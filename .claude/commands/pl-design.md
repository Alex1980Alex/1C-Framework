## Шаги

1. **Состояние и вход.** Прочитай состояние и артефакт планирования:
   ```
   .venv/Scripts/python.exe .claude/hooks/shared/pipeline_state.py status
   ```
   затем прочитай `pipeline/<CURRENT>/01-architecture.md`. Если Этап 1 не `done` — гейт мягкий:
   предупреди и продолжай (хук `pipeline-gate` тоже эмитит advisory, не блокирует).

2. **Спроектируй реализацию** (это инженерный дизайн, НЕ код):
   - **Точки модификации** — конкретные файлы (`path:line`), что меняется/добавляется.
   - **Контракты** — сигнатуры функций/классов, типы, схемы данных, API.
   - **Последовательность** — порядок изменений, зависимости между ними.
   - **Тест-стратегия** — что и как будет проверяться на Этапе 4.
   - **Соответствие плану** — как дизайн реализует рекомендацию из `01-architecture.md`.

3. **Запиши артефакт** `pipeline/<slug>/02-design.md` по структуре выше.

4. **Закрой этап:**
   ```
   .venv/Scripts/python.exe .claude/hooks/shared/pipeline_state.py done <slug> 2 02-design.md
   ```

5. **Передай дальше + ГЕЙТ.** Сообщи: «Этап 2 готов — отревьюй `02-design.md`. Кодирование (`/pl-code`)
   **заблокировано**, пока дизайн не одобрен человеком. Одобрить:
   ```
   .venv/Scripts/python.exe .claude/hooks/shared/pipeline_state.py approve <slug>
   ```
   затем `/pl-code`.» НЕ кодируй в этом запуске — одобрение дизайна = осознанный чекпоинт перед тратой на код.
