Запусти **Этап 1** generic 4-этапного пайплайна (ADR-017): архитектурное планирование задачи.
Вход: описание задачи. Выход: артефакт `pipeline/<slug>/01-architecture.md` (+ ADR при арх-решении).

> Это домен-агностичный пайплайн разработки фреймворка. НЕ путать с 1С-цепочкой
> (`/analyze-1c-task → /implement-1c-task → …`) — та отдельная, для задач 1С.

$ARGUMENTS

## Шаги

1. **Инициализируй пайплайн.** Выведи короткий `slug` из задачи (буквы/цифры/дефисы) и выполни:
   ```
   .venv/Scripts/python.exe .claude/hooks/shared/pipeline_state.py init <slug> --title "<краткий заголовок>"
   ```
   Это создаёт `pipeline/<slug>/` и указатель `pipeline/CURRENT` (дальше slug можно не передавать).

2. **Исследуй через Skill('architecture-research')** — пройди Фазы 0–6: кеш → `docs/documentation/` →
   web/GitHub best practices → синтез → атрибуция → (Фаза 6) ADR при архитектурном решении.

3. **Запиши артефакт** `pipeline/<slug>/01-architecture.md` по структуре:
   - **Проблема / Контекст** — что и зачем.
   - **Исследование** — факты с атрибуцией `[docs]/[web]/[exp]/[own]`.
   - **Варианты** (≥2) с trade-offs.
   - **Рекомендация** — выбранный подход + обоснование.
   - **Риски / Откат.**
   - **ADR** — ссылка, если решение архитектурное (создай по Фазе 6, следующий № из `adr/_index.json`).

4. **Закрой этап:**
   ```
   .venv/Scripts/python.exe .claude/hooks/shared/pipeline_state.py done <slug> 1 01-architecture.md
   ```

5. **Передай дальше.** Сообщи: «Этап 1 готов — отревьюй `pipeline/<slug>/01-architecture.md`, затем `/pl-design`».
   НЕ начинай дизайн в этом же запуске — между этапами стоит чекпоинт ревью артефакта.
