# 1c-solution-architecture — Архитектура 1С-решений (явный арх-шаг)

Применять на **Шаге 2 (Дизайн)** любой 1С-задачи: ПЕРЕД написанием BSL зафиксировать
архитектурное решение. Делает архитектурный шаг **явным**, а не неявным внутри анализа.
Эталон фактов: `1c-doc-research/cache/1c-architecture-methodology.md` (its.1c.ru приоритет 1).

## Когда использовать
- Любая доработка типовой (ERP/УТ/БП) — выбор «как менять код».
- Новый объект/механизм — проектирование объектной модели (какой регистр, проведение).
- Процесс с маршрутизацией/статусами — выбор модели бизнес-процесса.
- Перед `/implement-1c-task` — прогнать 4 чек-листа ниже, результат → в ANALYSIS-REPORT / ADR.

## 1. Decision-tree: расширение ↔ изменение типовой (ГЛАВНОЕ решение)
```
Доработка типовой конфигурации?
├─ Можно расширением? (новый функционал / перехват метода / +реквизит / +форма)
│   └─ ДА → РАСШИРЕНИЕ (&Вместо/&Перед/&После/&ИзменениеИКонтроль, заимствование объекта)
│           обновляемость сохранена; типовая не снята с поддержки
├─ Нужна глубокая правка алгоритма, невозможная расширением?
│   └─ ДА → изменение типовой (СНЯТИЕ С ПОДДЕРЖКИ) — крайняя мера;
│           цена = ручное сравнение/объединение при каждом обновлении
└─ Автономный модуль?
    └─ отдельная подсистема/конфигурация + обмен (РИБ/КД/RMQ)
```
Правило: **«сначала расширение, типовую трогать в последнюю очередь»**.
[its.1c.ru гл.34 «Расширение конфигурации»; its.1c.ru/db/pubextensions]

## 2. Матрица выбора регистра (объектная модель)
| Нужно | Регистр | Признак |
|---|---|---|
| Остатки / обороты (кол-во, сумма) | **Накопления** | склад, взаиморасчёты, движения |
| Значение атрибута на дату | **Сведений** (периодич.) | цены, курсы, статусы во времени |
| Бух.проводки (Дт/Кт) | **Бухгалтерии** | план счетов |
| Периодические расчёты (вид расчёта) | **Расчёта** | зарплата, начисления |
| Просто факт-событие | **Документ** + движения | первичка |
| НСИ / классификатор | **Справочник** | номенклатура, контрагенты |
Проверки: проведение **идемпотентно** (перепроведение не плодит/не ломает); периодический РС
подчинённый регистратору — НЕ «Месяц» (коллизия ключа → «По позиции регистратора»).

## 3. Моделирование бизнес-процесса
| Сложность | Модель | Объекты |
|---|---|---|
| Формализованный workflow с маршрутизацией/исполнителями | **штатный БП** | Бизнес-процесс + Карта маршрута + Задача |
| Лёгкая статусная модель | **состояния** | РС/реквизит состояния + переходы |
| Межсистемный процесс | **интеграция** | обмены РИБ/КД, RMQ, 1С:ДО |

## 4. Чек-лист стандартов (арх-гигиена, обязательно)
- [ ] БСП вместо велосипеда: `ОбщегоНазначения.*`, `ОбработкаОшибок.*`, права через **поставляемые профили**.
- [ ] Реквизит читать `ОбщегоНазначения.ЗначениеРеквизитаОбъекта` (не `Ссылка.Реквизит`, особ. в циклах).
- [ ] Запросы: не в цикле; без соединения с виртуальной таблицей (материализация во ВТ + индекс); без ГРУППИРОВАТЬ по строкам неогр. длины.
- [ ] Управляемые формы (8.3), зарезервированные имена; СтрШаблон вместо конкатенации.
- [ ] Изменённый/добавленный BSL → **SonarQube «1C BSL Way»** дельта = 0 BLOCKER/CRITICAL (ADR-037).

## Выход (артефакт арх-шага)
В ANALYSIS-REPORT (или ADR при значимом выборе): **(1)** способ изменения кода (расширение/типовая/обмен),
**(2)** объектная модель (какие объекты/регистры), **(3)** модель процесса (если есть), **(4)** отметка по чек-листу стандартов.
