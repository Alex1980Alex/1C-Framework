# ADR-003: ADR как структурный паттерн в Фабрике Триады

**Дата:** 2026-02-14
**Статус:** accepted
**Исследование:** [cache/knowledge-organization-patterns.md](../cache/knowledge-organization-patterns.md)

---

## Контекст

3-tier структура знаний (cache/ + adr/ + SKILL.md) была реализована только локально в `architecture-research`. Вопрос: является ли это переиспользуемым паттерном, который должен быть оформлен в Фабрике Триады (triad-factory)?

Паттерн — шаблон для решения типовых проблем, стандартизирующий процессы. Выделяют порождающие (creational), структурные (structural) и поведенческие (behavioral) паттерны.

## Решение

**Оформить ADR как структурный паттерн в Фабрике Триады** через Q6.

### Что изменено

1. **ШАГ 1 (Классификация)**: добавлен Q6 "Нужно ли фиксировать решения?" → ADR
2. **ШАГ 2 (Формула)**: новые комбинации с ADR + правило Q4/Q6
3. **ШАГ 3 (Генерация)**: секция "Если нужен ADR" — шаблон, жизненный цикл, критерий
4. **ШАГ 4 (Связывание)**: ADR в таблице подключений
5. **ШАГ 5 (Верификация)**: ADR в таблице тестов
6. **Справочник формул**: обновлён
7. **Чеклист домена**: обновлён

### Классификация паттерна

| Характеристика | Значение |
|---------------|----------|
| **Тип** | Структурный (организация знаний) |
| **Уровень** | Skill-level (внутри research-скилла) |
| **Условие** | Q6=Да (исследование приводит к выбору) |
| **Зависимость** | Q4=Да (ADR всегда основан на cache) |

### Правило применения Q6

- Q4=Да + Q6=Нет → `cache/` only (факты, переиспользуемые) — 1c-doc-research, tech-research
- Q4=Да + Q6=Да → `cache/` + `adr/` (факты отделены от решений) — architecture-research
- Q6=Да без Q4 → НЕ бывает (решение всегда основано на исследовании)

## Последствия

### Положительные
- Любой новый домен знаний проходит через Q6 — осознанный выбор нужен ли ADR
- Фабрика порождает полную структуру (cache + adr) автоматически
- Единообразие: все research-скиллы с решениями организованы одинаково
- Паттерн документирован на уровне процесса (не ad-hoc)

### Отрицательные
- Усложнение Фабрики (Q1-Q5 → Q1-Q6, +1 секция в ШАГ 3)
- Не все домены нуждаются в ADR (1c-doc-research — факты, не решения)

## Альтернативы

1. **Оставить только в architecture-research** — отклонён: нарушает принцип "каждое решение через Фабрику"
2. **Сделать ADR обязательным для всех research-скиллов** — отклонён: 1c-doc-research не принимает решений
3. **Отдельный skill для ADR** — отклонён: ADR — часть процесса исследования, не отдельная активность
