# ADR-004: Фабрика Триады как GoF-паттерн

**Дата:** 2026-02-14
**Статус:** accepted
**Исследование:** [cache/knowledge-organization-patterns.md](../cache/knowledge-organization-patterns.md)

---

## Контекст

`triad-factory/SKILL.md` содержал алгоритм создания компонентов (ШАГ 1-5, Q1-Q6), но не был оформлен как формальный паттерн проектирования. Отсутствовали стандартные секции GoF: Intent, Motivation, Applicability, Consequences, Related Patterns.

Паттерн — шаблон для решения типовых проблем, стандартизирующий процессы. Три категории: порождающие (creational), структурные (structural), поведенческие (behavioral).

## Решение

**Оформить triad-factory как порождающий GoF-паттерн (Abstract Factory + Builder)** с полным набором секций.

### Классификация

| Характеристика | Значение |
|---------------|----------|
| **Тип GoF** | Порождающий (Creational) |
| **Основной паттерн** | Abstract Factory — создаёт семейства компонентов по формуле |
| **Вспомогательный** | Builder — ШАГ 1-6 пошагово конструируют результат |
| **Подпаттерны** | Strategy (hooks), Chain of Responsibility (pipeline), Observer (events), Template Method (BaseHook) |

### Добавленные секции

| Секция GoF | Содержание |
|-----------|-----------|
| **Intent** | Создание семейств компонентов (Hook + Skill + MCP + Cache + ADR + Enforcer) без привязки к реализациям |
| **Motivation** | Проблема потери решений между сессиями → самоусиливающийся цикл артефактов |
| **Applicability** | Таблица: когда применять (новый домен, архитектурное решение) vs когда не применять (баг, однострочник) |
| **Structure** | Принцип триады + таблица участников (Hooks/Skills/MCP) |
| **Consequences** | 6 положительных + 5 отрицательных последствий |
| **Related Patterns** | 7 GoF-паттернов в составе + 4 подпаттерна триады + 5 антипаттернов |

## Последствия

### Положительные
- Формальная документация помогает новым участникам понять архитектуру
- Связь с GoF делает паттерн узнаваемым для разработчиков
- Consequences секция явно показывает trade-offs
- Related Patterns связывает с известными GoF-паттернами

### Отрицательные
- SKILL.md увеличился в размере (~500 строк)
- GoF-терминология может быть избыточной для процедурного скилла

## Альтернативы

1. **Оставить как процедурный алгоритм** — отклонён: не видны trade-offs, не связан с GoF, нет формальной мотивации
2. **Вынести в отдельный patterns.md** — отклонён: паттерн = скилл, разделение создаёт навигационную проблему
