# ADR-050: Обязательная live-верификация на реальных данных в Пайплайне 1С (анализ + тестирование) + главы отчётов

- **Статус:** accepted (мандат пользователя)
- **Дата:** 2026-07-13
- **Контекст-источник:** прямое указание пользователя 2026-07-13 («в Пайплайн 1С добавить использование 1c-debug-hmr/1c-debug: точки останова и на этапе анализа, и тестирования; проверка аналитики и тестирование на реальных данных; в отчётах отдельная глава - на каких данных тестировалось, какие результаты»); повторяет и закрепляет фидбэк 2026-05-11 ([[feedback-live-bp-trace-mandatory]], GKSTCPLK-2468), который был записан в память, но не проведён в методики.

## Контекст

Инфраструктура live-отладки уже была в пайплайне, но с opt-in активацией:

- `analyze-1c-task-v2` v4.2-v4.4: Фаза 2.5 Runtime Trace - **опциональная** (флаг `--trace` или self-decision «≥3 runtime-ветвлений»); глава §10 отчёта - «Верификация на реальных данных **(если проводилась)**».
- `implement-1c-task` v2.7-v2.8: Этап 5.x BP-verification обязателен в режиме Full, но требование «реальные данные» и консолидированная глава отчёта о данных/результатах отсутствовали (BP-результаты растворялись по секциям точек).
- Инцидент-обоснование (GKSTCPLK-2468): static-reading дал ошибочный вывод о runtime-типе → 2 итерации реализации; live `debug_evaluate` ДО реализации поймал бы за 1 шаг. Повтор класса ошибки - GKSTCPLK-2669/АРМ (2026-07-12): ручные параметры вместо функций вызывающего → 3021 строка вместо 114 (Шаблон 7 skill `1c-debug-hmr`).

## Решение

1. **Анализ (Фаза 2.5 Runtime Trace) - обязательная по умолчанию** (`analyze-1c-task-v2` v4.5.0) для каждой задачи с исполняемым BSL-кодом: BP на ключевых точках цепочки (`1c-debug-hmr`: `set_breakpoint`/`stack_trace`/`variables`/`evaluate`), триггер на **реальных данных** (кандидаты - `execute_query`, параметры - функциями вызывающего), сверка гипотез анализа ДО построения плана. `--trace` - форс; SKIP только по трём причинам (явный `--no-trace` / нет исполняемого алгоритма / debug env недоступен) с фиксацией в §10; прежний критерий «≥3 ветвлений» определяет глубину step-трассировки.
2. **Тестирование (Этапы 5.x/6 implement-1c-task) - на реальных данных** (v2.9.0): BP-триггеры и тест-план исполняются на существующих документах/записях живой базы; синтетика - только при пустой базе, с пометкой; идентификаторы данных фиксируются по ходу.
3. **Обязательные главы отчётов** («после работы указать, на каких данных было тестирование и какие результаты»):
   - `ANALYSIS-REPORT.md` §10 «Проверка на реальных данных» (Правило 7): база, таблица `Объект | Идентификатор | Дата | Роль`, сценарий/harness, инструменты, результаты + вердикты гипотез; при SKIP - причина + `[STATIC-ASSUMPTION]`.
   - `IMPLEMENTATION-PROGRESS.md` глава «Тестирование на реальных данных»: база, таблица данных, инструменты (BP модуль:строка/стек/значения, execute_*, YAxUnit/VA BDD), per-сценарий PASS/FAIL + итог.
4. **Enforcement - advisory** через существующий `scripts/lint_1c_artifacts.py` (+2 core-секции: analysis `реальн… данн|[STATIC-ASSUMPTION]`, implementation `реальн…|живы… данн` - lenient к историческому термину «живых данных»), поверхность - хук `pipeline-1c-advance`. Hard-блок НЕ вводится (осознанно): не каждая задача имеет live-сценарий (rename-only, роли), а advisory-канал уже встроен; эскалация до hard - отдельным решением после наблюдения (паттерн ADR-035 Фазы 2).

## Последствия

- Методики: `analyze-1c-task-v2` 4.4.0→4.5.0 (Фаза 2.5 default-ON, Правило 7, шаблон §10), `implement-1c-task` 2.8.1→2.9.0 (реальные данные 5.x/6, глава отчёта, чеклист).
- Команда `/analyze-1c-task`: `--trace` семантика «опция→форс», новый `--no-trace`.
- Линтер: `lint_1c_artifacts.py` +2 секции (12 unit-тестов, вкл. SKIP-вариант и lenient-алиас).
- Документация: гл. 43.1 (сквозной инвариант live-контура), 43.2 (обе команды).
- `/run-1c-task` наследует автоматически (делегирует методикам).
- Закрывается давний разрыв «память говорила mandatory, методика оставалась opt-in» - урок: мандаты из memory проводить в методики сразу.

## Альтернативы

- **Hard-гейт в `onec-task-completion-stop`** - отклонено на этом шаге: риск дедлоков на задачах без live-сценария; advisory-линт + обязательность в методике достаточны, эскалация возможна позже.
- **Оставить opt-in `--trace`** - отклонено мандатом пользователя (повторным).
- **Отдельный отчёт-файл о тестовых данных** - отклонено: глава в существующих артефактах дешевле и попадает в существующий lint/hook-контур.
