# 7 принципов AutoResearch v2

## 1. ONE change per iteration (атомарность)

Каждое изменение должно быть объяснимо в одном предложении.
Это обеспечивает чистый `git revert` и ясную причинно-следственную связь.

## 2. Measure BEFORE and AFTER (числовые метрики)

Только числовые метрики. "Стало лучше" — не метрика. "F1 = 0.72 → 0.75" — метрика.
Verify command должна выводить число: `METRIC: 0.75`.

## 3. REVERT on regression (без исключений)

Если метрика ухудшилась — revert. Без обсуждений.
Единственное исключение — verdict FIX (тесты упали, но идея хорошая → 1 попытка исправить).

## 4. Never retry Dead Ends

Dead ends отслеживаются в `autoresearch.md` секция `## Dead Ends`.
Executor ОБЯЗАН проверять этот список перед каждой итерацией.
Повторение dead end = потерянная итерация.

## 5. Separation of concerns

| Агент | Делает | НЕ делает |
|-------|--------|-----------|
| **Executor** | Пишет код, коммитит | Не тестирует, не оценивает |
| **Reviewer** | Тестирует, измеряет, решает | Не пишет код, не коммитит |
| **Comparator** | Слепое A/B сравнение | Не знает какая версия текущая |

## 6. Session persistence

`autoresearch.md` — живой документ. Содержит:
- Goal, Scope, Metric, Baseline, Current Best
- History table (все итерации)
- Dead Ends (не повторять)
- Next Ideas (очередь гипотез)
- Comparator Reviews (A/B результаты)

Новая сессия читает этот документ и продолжает с last iteration.

## 7. Idea-to-Recipe (уникальный рецепт)

Каждая идея анализируется и получает свой набор:
- **Инструменты**: MCP tools, CLI commands, тестовые фреймворки
- **Метрика**: конкретная команда, выводящая число
- **Подход**: по файлу, по категории, по объекту
- **Scope**: glob-паттерн файлов
- **Промпты**: уникальные для Executor и Reviewer
