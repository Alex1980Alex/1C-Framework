# Task Evaluation — классификация: Research vs Brainstorm vs Hybrid

## Обзор

Матрица решений для классификации входящих задач по трём типам:
- **Research** — найти существующие решения, документацию, best practices
- **Brainstorm** — сгенерировать новые идеи, спроектировать решение, выбрать подход
- **Hybrid** — сначала research (факты), потом brainstorm (идеи на основе фактов)

Используется хуком `research-task-detector.py` для автоматического роутинга.

---

## Быстрый справочник

| Тип | Ключевой вопрос | Результат | Маршрут |
|-----|----------------|-----------|---------|
| Research | "Что существует?" | Курированные факты | domain skill (1c/tech/architecture) |
| Brainstorm | "Что придумать?" | Решение + обоснование | Brainstorm workflow (5 фаз) |
| Hybrid | "Найди и предложи" | Факты + решение | Research-фазы → Brainstorm-фазы |

## Матрица классификации

### Сигналы Research (ищем существующее)

| Категория | Примеры |
|-----------|---------|
| Запрос фактов | "найди", "что есть", "какие варианты существуют" |
| Документация | "документация по", "как работает", "что такое" |
| Чужой опыт | "best practices", "как другие делают", "примеры реализации" |
| Обзор | "сделай обзор", "сравни", "расскажи про" |
| Инструкции | "как настроить", "как установить", "как подключить" |

**Индикатор:** ответ уже существует где-то (в документации, в чужом коде).

### Сигналы Brainstorm (генерируем новое)

| Категория | Примеры |
|-----------|---------|
| Генерация | "придумай", "предложи", "спроектируй", "разработай" |
| Выбор подхода | "какой подход выбрать", "какой вариант лучше" |
| Обсуждение | "давай обсудим варианты", "давай подумаем", "что думаешь о" |
| Творческий | "как бы ты", "нестандартный подход" |
| Архитектура | "предложи архитектуру", "предложи решение", "предложи дизайн" |

**Индикатор:** ответа пока не существует — нужно сгенерировать.

### Сигналы Hybrid (найди, потом предложи)

| Категория | Примеры |
|-----------|---------|
| Исследуй + предложи | "исследуй и предложи", "найди подходы и выбери лучший" |
| Улучши | "как улучшить", "как оптимизировать", "как ускорить" |
| Реши проблему | "как решить", "как исправить", "как обойти" |
| Сравни и выбери | "сравни подходы и выбери", "какие варианты и что лучше" |
| Слабые места | "что можно улучшить", "слабые места", "узкое место" |

**Индикатор:** нужны факты для обоснованного решения.

## Алгоритм классификации

```
ВХОД: prompt пользователя

ШАГ 1: Подсчёт сигналов
  research_signals  = count(RESEARCH_KEYWORDS in prompt)
  brainstorm_signals = count(BRAINSTORM_KEYWORDS in prompt)
  hybrid_signals    = count(HYBRID_KEYWORDS in prompt)

ШАГ 2: Определение типа
  IF hybrid_signals >= 1:
    → HYBRID
  ELIF brainstorm_signals >= 1 AND research_signals == 0:
    → BRAINSTORM
  ELIF brainstorm_signals >= 1 AND research_signals >= 1:
    → HYBRID
  ELIF research_signals >= 1:
    → RESEARCH
  ELSE:
    → PASS

ШАГ 3: Роутинг
  RESEARCH  → domain skill (определить домен: 1C / Tech / Architecture)
  BRAINSTORM → brainstorm workflow (5 фаз ниже)
  HYBRID    → research-фазы domain skill, затем brainstorm-фазы
```

**Критическое правило:** "Как улучшить X?" — это **HYBRID**, не Research.
Сначала research (какие подходы существуют), потом brainstorm (какой подход лучше для нас).

## Brainstorm Workflow (5 фаз)

### Фаза 1: Problem Framing

```markdown
## Проблема
- **Что решаем:** [конкретная формулировка]
- **Контекст:** [текущее состояние, ограничения]
- **Критерии успеха:** [как поймём что решено]
- **Ограничения:** [время, совместимость, зависимости]
```

### Фаза 2: Divergent Ideation (3-5 подходов)

Правила:
- Минимум 3, максимум 5 подходов
- Каждый — другая философия (не вариации одного)
- Включать консервативные и радикальные варианты
- Для каждого: название + суть в 1-2 предложениях

### Фаза 3: Evaluation Matrix

| Критерий | Подход A | Подход B | Подход C |
|----------|---------|---------|---------|
| Сложность реализации | Low/Med/High | | |
| Риски | Low/Med/High | | |
| Трудозатраты | часы/дни/недели | | |
| Совместимость с кодом | High/Med/Low | | |
| Масштабируемость | High/Med/Low | | |
| Обратимость | Да/Нет/Частично | | |

### Фаза 4: Recommendation

```markdown
## Рекомендация
**Выбран:** Подход [X]
**Почему:** [2-3 предложения — главные аргументы]
**Риски:** [что может пойти не так]
**План Б:** Подход [Y] если [условие отката]
```

### Фаза 5: Cache Decision

Сохранить в `architecture-research/adr/NNN-<название>.md`:
- `status: proposed` (до реализации) → `accepted` (после)
- `research:` ссылка на cache-файл (если был hybrid)

## Hybrid Workflow

```
[RESEARCH] domain skill фазы 0-5
  Phase 0: Cache check
  Phase 1: Local docs
  Phase 2: Web search
  Phase 3-5: Verify + Cache
        ↓
[BRAINSTORM] task-evaluation фазы 1-5
  Фаза 1: Problem framing (с учётом фактов)
  Фаза 2: Ideation (на основе research)
  Фаза 3: Evaluation matrix
  Фаза 4: Recommendation
  Фаза 5: ADR
```

## Антипаттерны

| Плохо | Почему | Правильно |
|-------|--------|-----------|
| "Как улучшить X?" = Research | Теряется генерация | Hybrid: research → brainstorm |
| Brainstorm без фактов | Решение на эмоциях | Если не уверен — hybrid |
| 1 подход вместо 3-5 | Нет выбора | Минимум 3 разных подхода |
| Без Evaluation Matrix | Нельзя сравнить | Обязательная таблица |
| Без ADR | Решение потеряется | Фаза 5: всегда ADR |
| Hybrid без research | Brainstorm на пустом месте | Research СНАЧАЛА |
