# VA BDD Testing — Vanessa Automation тестирование форм 1С

## Обзор

Скилл для написания и калибровки VA BDD сценариев (Gherkin .feature) для UI-тестирования форм 1С:Предприятие через Vanessa Automation v1.2.043+. Содержит паттерны заполнения полей, порядок калибровки, обходные пути для ограничений VA.

**Документация VA:** https://pr-mex.github.io/vanessa-automation/dev/
**Репозиторий:** https://github.com/Pr-Mex/vanessa-automation
**Runner:** `tools/vanessa/run-bdd.ps1`

## Триггеры

- 'vanessa automation', 'VA BDD', 'feature файл', 'gherkin 1С'
- 'тестирование формы', 'заполнение полей VA', 'калибровка VA'
- 'probe steps', 'создать документ через VA', 'UI тест 1С'

НЕ для YAxUnit (unit-тесты) — используй `auto-test-after-write`.
НЕ для анализа задач 1С — используй `analyze-1c-task-v2`.

## Быстрый справочник

| Задача | Действие |
|--------|----------|
| Запуск feature | `powershell -File tools\vanessa\run-bdd.ps1 -Feature "dir/file.feature"` |
| Увеличить таймаут | `-TimeoutSec 300` |
| Найти данные для полей | MCP `execute_query` по проведённым документам |
| Найти имя элемента формы | MCP `get_metadata_structure` → реквизит → синоним |
| Найти структуру формы | MCP `get_form_structure` |
| Проверить результат | MCP `execute_query` по последним документам |

---

## Алгоритм калибровки (Фаза 0)

```
1. ДАННЫЕ: MCP запрос к проведённым документам → реальные значения полей
2. МЕТАДАННЫЕ: get_metadata_structure → типы полей, синонимы, перечисления
3. PROBE: минимальный .feature → запуск → анализ ошибки → исправление
4. ИТЕРАЦИЯ: добавлять по одному полю, запускать, калибровать
5. ПРОВЕРКА: MCP запрос → документ записан? поля заполнены? проведён?
```

**Критерий завершения:** документ записан, все поля заполнены (проверено в базе), проведён.

## Паттерны заполнения полей

### 1. Малый справочник (< 1000 записей, без иерархии)

```gherkin
И я нажимаю кнопку выбора у поля с именем 'ТочкаМаршрута'
Тогда открылось окно "Точки маршрута"
И в таблице "Список" я перехожу к строке:
    | 'Наименование' |
    | 'ПЛК Светлый'  |
И в таблице "Список" я выбираю текущую строку
```

### 2. Большой иерархический справочник (1000+ записей)

```gherkin
И я нажимаю кнопку выбора у поля с именем '[ИМЯ_ПОЛЯ]'
Тогда открылось окно "[ЗАГОЛОВОК_ОКНА]"
И я нажимаю на кнопку с именем '*ИерархическийСписок'
И Пауза 1
И в таблице "Список" я активизирую дополнение формы с именем "СписокСтрокаПоиска"
И в таблице "Список" в дополнение формы с именем 'СписокСтрокаПоиска' я ввожу текст '[ПОИСКОВЫЙ_ТЕКСТ]'
И Пауза 5
И в таблице "Список" я выбираю текущую строку
```

**ВАЖНО:** `Пауза 5` обязательна — дополнение формы фильтрует динамический список асинхронно.

### 3. Большой плоский справочник (без иерархии, 1000+ записей)

```gherkin
И я нажимаю кнопку выбора у поля с именем '[ИМЯ_ПОЛЯ]'
Тогда открылось окно "[ЗАГОЛОВОК_ОКНА]"
И в таблице "Список" я активизирую дополнение формы с именем "СписокСтрокаПоиска"
И в таблице "Список" в дополнение формы с именем 'СписокСтрокаПоиска' я ввожу текст '[ПОИСКОВЫЙ_ТЕКСТ]'
И Пауза 5
И в таблице "Список" я выбираю текущую строку
```

Без `*ИерархическийСписок` — кнопка не существует на форме без иерархии.

### 4. Перечисление (выпадающий список)

```gherkin
И из выпадающего списка с именем '[ИМЯ_ПОЛЯ]' я выбираю по строке '[ЗНАЧЕНИЕ]'
```

### 5. Строковое поле

```gherkin
И в поле с именем '[ИМЯ_ПОЛЯ]' я ввожу текст '[ЗНАЧЕНИЕ]'
```

### 6. Числовое поле (ПолеВвода с типом Число)

```gherkin
И в поле с именем '[ИМЯ_ПОЛЯ]' я ввожу текст '[ЧИСЛО]'
```

Формат: запятая как десятичный разделитель (русская локаль): `'123,45'`, `'12 34,00'`

В табличной части:
```gherkin
И в таблице "[ТЧ]" в поле с именем '[ИМЯ]' я ввожу текст '111,00'
```

**ВАЖНО: Числовое ПолеВвода ≠ SpinEdit!**
- `ВидПоляФормы.ПолеВвода` с типом Число — `я ввожу текст` РАБОТАЕТ
- SpinEdit (поле с кнопками ±) — `я ввожу текст` НЕ РАБОТАЕТ → см. паттерн 11

### 7. CheckBox / Флаг

```gherkin
# Установить (idempotent → True)
И я устанавливаю флаг с именем '[ИМЯ_ПОЛЯ]'

# Снять (idempotent → False)
И я снимаю флаг с именем '[ИМЯ_ПОЛЯ]'

# Toggle (инвертировать — non-idempotent!)
И я изменяю флаг с именем '[ИМЯ_ПОЛЯ]'

# Проверить значение (Истина/Да/Ложь/Нет)
И флаг с именем '[ИМЯ_ПОЛЯ]' равен 'Истина'
```

В табличной части — сначала активизировать поле:
```gherkin
И в таблице "[ТЧ]" я активизирую поле с именем "[ТЧ_ИМЯ_ПОЛЯ]"
И в таблице "[ТЧ]" я изменяю флаг с именем '[ТЧ_ИМЯ_ПОЛЯ]'
И в таблице "[ТЧ]" я завершаю редактирование строки
```

### 8. RadioButton / Переключатель

```gherkin
# По значению
И я меняю значение переключателя с именем '[ИМЯ]' на '[ЗНАЧЕНИЕ]'

# По номеру (БЕЗ кавычек, с 0)
И я меняю значение переключателя с именем '[ИМЯ]' на 0

# По шаблону (wildcard, 8.3.12+)
И я меняю значение переключателя с именем '[ИМЯ]' на '[ЗНАЧЕНИЕ*]' по шаблону
```

НЕ поддерживает `устанавливаю флаг`/`снимаю флаг` — только `меняю значение`.
Баг #69: дубли заголовков → использовать `с именем`. Баг #1965: многострочные → `\n`.

### 9. Дата

```gherkin
И в поле с именем '[ИМЯ_ПОЛЯ]' я ввожу текст 'ДД.ММ.ГГГГ'
```

Дата-время: `'ДД.ММ.ГГГГ ЧЧ:ММ:СС'`. Формат ВСЕГДА русская локаль.

### 10. Составной тип (двухэтапный выбор)

```gherkin
И я нажимаю кнопку выбора у поля с именем '[ИМЯ_ПОЛЯ]'
Тогда открылось окно 'Выбор типа данных'
И в таблице "" я перехожу к строке:
    | ''             |
    | '[ТИП_ДАННЫХ]' |
И Пауза 1
И я нажимаю на кнопку 'ОК'
Тогда открылось окно '[ФОРМА_ВЫБОРА]'
# далее стандартный выбор из справочника
```

Таблица и колонка в "Выбор типа данных" имеют ПУСТЫЕ имена (`""` и `''`).

**Альтернатива (прямой ввод с автоподбором):** если поле поддерживает автоподбор:
```gherkin
И в поле с именем '[ИМЯ_ПОЛЯ]' я ввожу текст '[НАЧАЛО_НАИМЕНОВАНИЯ]'
И Пауза 2
```

### 11. SpinEdit — обходной путь через MCP

```
# VA ограничение: SpinEdit (число с кнопками ±) не принимает:
#   - "ввожу текст" по имени → "Неподходящий тип элемента управления"
#   - "ввожу текст" по заголовку → проходит бесшумно, НЕ заполняет
#
# ОБХОДНОЙ ПУТЬ: MCP execute_code после записи документа
```

```python
# После VA записи → MCP обновляет числовые поля и проводит:
mcp__1c-mcp-crud__execute_code(code="""
Запрос = Новый Запрос;
Запрос.Текст = "ВЫБРАТЬ ПЕРВЫЕ 1 Д.Ссылка ИЗ Документ.[ИМЯ_ДОКУМЕНТА] КАК Д
    ГДЕ Д.НомерДокументаПоставщика = &ТН УПОРЯДОЧИТЬ ПО Д.Дата УБЫВ";
Запрос.УстановитьПараметр("ТН", "[МАРКЕР]");
Выборка = Запрос.Выполнить().Выбрать();
Выборка.Следующий();
Док = Выборка.Ссылка.ПолучитьОбъект();
Док.ВесБрутто = 30000;
Док.ВесНетто = 30000;
Док.Записать(РежимЗаписиДокумента.Проведение);
""")
```

## Критические правила

### Порядок заполнения: СТРОГО СВЕРХУ ВНИЗ

```
ПРАВИЛО: Заполнять поля в порядке их расположения на форме (сверху → вниз).
ПРИЧИНА: Обработчики формы 1С при изменении вышестоящих полей СТИРАЮТ
         зависимые нижестоящие поля (каскадная очистка).
СЛЕДСТВИЕ: Транспорт/ТС заполнять ПОСЛЕДНИМ — он зависит от многих полей выше.
```

### Очистка состояния перед тестом

```gherkin
# ОБЯЗАТЕЛЬНО в начале сценария — иначе VA переиспользует старую форму
И Я закрыл все окна клиентского приложения
```

### Имена элементов vs заголовки

```
ПРАВИЛО: VA шаги 'с именем' используют ПРОГРАММНОЕ имя элемента формы.
         Это НЕ всегда совпадает с заголовком (label) на форме.

ПРИМЕР: Заголовок "Грузополучатель" → имя элемента 'Организация'
        Заголовок "Поставщик" → имя элемента 'Контрагент'
        Заголовок "Вес брутто" → имя элемента 'ВесБрутто'

КАК УЗНАТЬ: MCP get_metadata_structure → имя реквизита = имя элемента
            Синоним реквизита = заголовок на форме (обычно)
```

### Синонимы колонок в таблицах

```
ПРАВИЛО: В шаге "перехожу к строке" колонки указываются по СИНОНИМУ, не по имени.

ПРИМЕР: Справочник.ТранспортныеСредства → Наименование (синоним "Краткое наименование")
        → В таблице использовать: | 'Краткое наименование' |
```

### Фильтрация в формах выбора

```
ПРАВИЛО: Форма выбора справочника может фильтровать записи по реквизитам документа.

ПРИМЕР: Форма выбора ТС в документе РегистрацияНаПЛК показывает
        только ТС с ЭтоСправочникПЛК = Истина.
        Данные для теста ДОЛЖНЫ соответствовать фильтру.

КАК ПРОВЕРИТЬ: MCP execute_query по реквизитам + фильтрующему полю
```

## Алгоритм получения реальных данных

```
1. MCP execute_query — последние проведённые документы:
   ВЫБРАТЬ ПЕРВЫЕ 3 ПРЕДСТАВЛЕНИЕ(Д.Поле1) КАК Поле1, ...
   ИЗ Документ.[ИМЯ] КАК Д ГДЕ Д.Проведен УПОРЯДОЧИТЬ ПО Д.Дата УБЫВ

2. MCP get_metadata_structure — структура документа:
   → Типы полей (Справочник, Перечисление, Строка, Число)
   → Синонимы (для заголовков на форме)
   → Значения перечислений

3. MCP execute_query — данные справочников:
   ВЫБРАТЬ Н.Наименование ИЗ Справочник.[ИМЯ] КАК Н ГДЕ Н.Наименование ПОДОБНО "%текст%"

4. MCP get_form_structure — формы документа:
   → Имена форм (ФормаДокумента, ФормаСписка, ФормаВыбора)
```

## Диагностика ошибок VA

| Ошибка | Причина | Решение |
|--------|---------|---------|
| `Окно с заголовком <X> не найдено` | Кнопка выбора не открыла окно | Поле автозаполняется или скрыто, попробовать dropdown |
| `Элемента формы с именем <X> не найдено` | Неверное имя элемента | MCP get_metadata_structure → проверить реальное имя |
| `Не найдены колонки: X` | Колонка в таблице называется иначе | Использовать СИНОНИМ реквизита, не имя |
| `Не удалось перейти к нужной строке` | Запись в свёрнутой группе или на другой странице | Использовать дополнение формы + *ИерархическийСписок |
| `В таблице нет строк для выбора` | Поиск не нашёл (фильтр формы!) | Проверить ЭтоСправочникПЛК и другие фильтрующие реквизиты |
| `Неподходящий тип элемента управления` | SpinEdit не поддерживает ВвестиТекст | Обходной путь: MCP execute_code |
| `Не получилось выбрать из списка` | Элемент не является выпадающим списком | Попробовать кнопку выбора или прямой ввод |
| `Кнопка с именем <X> не найдена` | Форма не имеет этой кнопки | Проверить кнопки на скриншоте: Записать/Провести/ПровестиИЗакрыть |
| `Не найдена процедура для шага` | Шаг не существует в VA | VA ≠ ADD, проверить синтаксис в документации |
| Документ "(создание) *" после проведения | Проведение не прошло (валидация) | Проверить обязательные поля через скриншот/MCP |

## Кнопки документа

| Кнопка | Имя элемента | Для чего |
|--------|-------------|----------|
| Записать | `ФормаЗаписать` | Записать без проведения, окно остаётся |
| Записать и закрыть | `ФормаЗаписатьИЗакрыть` | Записать + закрыть (справочники) |
| Провести | `ФормаПровести` | Провести, окно остаётся (проверка) |
| Провести и закрыть | `ФормаПровестиИЗакрыть` | Провести + закрыть (документы) |

**ПРАВИЛО:** Справочники → `ФормаЗаписатьИЗакрыть`, Документы → `ФормаПровестиИЗакрыть`.

Паттерн проверки наличия кнопки (из дымовых тестов):
```gherkin
Если элемент формы с именем 'ФормаПровестиИЗакрыть' присутствует на форме Тогда
    И я нажимаю на кнопку с именем 'ФормаПровестиИЗакрыть'
```

## Проверки значений (assertions)

```gherkin
# Значение поля
И элемент формы с именем '[ИМЯ]' стал равен '[ЗНАЧЕНИЕ]'
И представление элемента с именем '[ИМЯ]' стало равно '[ЗНАЧЕНИЕ]'

# Флаг
И флаг с именем '[ИМЯ]' равен 'Истина'

# Видимость
И я вижу элемент с именем '[ИМЯ]'
И я не вижу элемент с именем '[ИМЯ]'
```

## Антипаттерны

| Плохо | Почему | Как правильно |
|-------|--------|---------------|
| Заполнять поля в произвольном порядке | Обработчики стирают зависимые поля | Строго сверху вниз, ТС последним |
| Использовать вымышленные данные (С001АА39) | Нет в справочнике → форма не примет | MCP запрос к реальным проведённым документам |
| `перехожу к строке` для больших справочников | Видит только загруженную страницу | Дополнение формы `СписокСтрокаПоиска` |
| `ввожу текст` для SpinEdit | "Неподходящий тип элемента" | Числовое ПолеВвода — OK, SpinEdit — MCP execute_code |
| `СписокСтрокаПоиска` как обычное поле | "Элемент не найден" | `дополнение формы с именем` (другой тип!) |
| `изменяю флаг` вместо `устанавливаю флаг` | Toggle не идемпотентен — зависит от текущего состояния | `устанавливаю флаг` (безусловно True) |
| Вводить дату как '2026-04-08' (ISO) | VA ожидает русскую локаль | Формат 'ДД.ММ.ГГГГ': '08.04.2026' |
| `устанавливаю флаг` для переключателя | RadioButton ≠ CheckBox | `я меняю значение переключателя` |
| Не проверять результат в базе | VA BuildStatus=0 не значит документ проведён | MCP execute_query после теста |
| Не закрывать окна перед тестом | VA переиспользует старую форму | `Я закрыл все окна клиентского приложения` |
| Предполагать имена элементов формы | "Грузополучатель" ≠ имя элемента | MCP get_metadata_structure → реальные имена |

Проверенный порядок заполнения (09.04.2026, обновлено по probe_steps.feature):

| # | Поле формы | Имя элемента | Паттерн | Значение |
|---|-----------|-------------|---------|----------|
| 1 | Пункт приёма | ТочкаМаршрута | малый справочник | ПЛК Светлый |
| 2 | Условие проезда | УсловиеПроезда | dropdown | DAP |
| 3 | Вид перевозки | ВидПеревозки | dropdown | Автомобиль |
| 4 | Грузополучатель | **Организация** | dropdown | СОДРУЖЕСТВО-СОЯ ЗАО |
| 5 | Номенклатура | Номенклатура | большой иерарх. | Пшеница 3 кл |
| 6 | Поставщик | Контрагент | большой плоский | ЯхимовщинаАгро |
| 7a | ТН номер | НомерДокументаПоставщика | строка | TEST-004 |
| 7b | ТН дата | ДатаДокументаПоставщика | дата (ДД.ММ.ГГГГ) | 08.04.2026 |
| 7c | Грузоотправитель | ОтправительПолучатель | большой плоский | ЯхимовщинаАгро |
| 7d | Внутригрупповой | Внутригрупповой | **checkbox** | Истина |
| 7e | Собственник | Собственник | **составной тип (автоподбор)** | Торговый дом Содружество |
| 8 | **Транспорт** | **ТранспортноеСредство** | **большой иерарх. (ПОСЛЕДНИЙ!)** | **М012УХ** |
| 9 | Вес брутто | **Вес** | числовое ПолеВвода | 15000 |
| 10 | Вес по документам | **ВесПоДокументам** | числовое ПолеВвода | 12000 |
| | | | `ФормаПровестиИЗакрыть` | |

**ВАЖНО:** Имя элемента формы для весов ≠ имя реквизита метаданных:
- `Вес` (элемент формы) → DataPath `Объект.ВесБрутто`
- `ВесПоДокументам` (элемент формы) → DataPath `Объект.ВесНетто`

Если `я ввожу текст` работает для этих полей — это числовое ПолеВвода, НЕ SpinEdit.
