# whisper — транскрипция аудио/видео (MCP)

## Обзор

MCP-сервер локальной транскрипции речи (Whisper / faster-whisper) — **аудио/видео → текст + субтитры**, офлайн, без внешних API. Инструменты **deferred** (грузятся `ToolSearch`). Нативной замены в проекте нет, поэтому единственный путь «речь в текст».

**Ниша:** расшифровка встреч/роликов, субтитры (SRT/VTT), пакетная обработка папки. **НЕ** раскадровка по сценам (это `scene-detect-mcp`).

## Каталог инструментов

| Инструмент | Назначение |
|---|---|
| `check_system` / `check_config` | Проверка окружения (GPU/CPU, ffmpeg) и текущей конфигурации ПЕРЕД работой |
| `list_models` / `download_model` / `switch_model` | Модели whisper (tiny…large-v3): список, скачать, переключить активную |
| `transcribe_audio` | Транскрипция ОДНОГО файла (аудио/видео) → текст (+ таймкоды) |
| `generate_subtitles` | Субтитры (SRT/VTT) из медиафайла |
| `analyze_media` | Инспекция медиа (длительность, дорожки, формат) до транскрипции |
| `start_batch` / `check_batch_progress` | Пакетная транскрипция папки (запуск + прогресс) |
| `check_progress` | Прогресс одиночной длительной транскрипции |
| `transcribe_batch` | Пакетная транскрипция набора файлов |

## Канонический workflow

```
check_system            # GPU/CPU + ffmpeg доступны?
list_models             # активная модель? если нужна точнее — download_model + switch_model
analyze_media(path)     # длительность/дорожки (оценить время)
transcribe_audio(path)  # или generate_subtitles(path, format="srt")
  # длинный файл → check_progress до готовности
# папка/много файлов:
start_batch(dir) → check_batch_progress (поллить до done)
```

## Транскрипт ПО ССЫЛКЕ (YouTube и др.) — два слоя, ADR-057

Правило: **сперва готовые субтитры, ASR только когда их нет или нужно качество.** Не транскрибировать
то, что уже существует текстом (канон экосистемы, [ADR-057](../architecture-research/adr/057-youtube-transcript-two-layer.md)).

```
1) mcp__youtube-transcript__get_transcript(url, lang)     # секунды, бесплатно, без GPU
   ├─ есть субтитры  → готово (get_timed_transcript — с таймкодами,
   │                   get_available_languages — какие языки есть, get_video_info — метаданные)
   └─ субтитров нет / RU-автосубтитры без пунктуации / нужна приватность
        v
2) yt-dlp -x --audio-format mp3 --no-playlist \
     -o "<dir>/%(id)s.%(ext)s" --print "after_move:filepath" "<URL>"   # .venv/Scripts/yt-dlp.exe
        v
   transcribe_audio(<полученный путь>, language="auto")   # whisper.cpp + Vulkan GPU, large-v3-turbo
```

| Слой | Когда он правильный |
|---|---|
| A `youtube-transcript` | англоязычные ролики с субтитрами, нужен быстрый текст/таймкоды, длинное видео (пагинация `next_cursor`) |
| B `yt-dlp` + `whisper` | субтитров нет · RU-речь (large-v3-turbo даёт пунктуацию, автосубтитры — нет) · чувствительный контент (аудио и текст не покидают машину) · не-YouTube источник |

⚠ **A выигрывает не только по скорости.** На живой сверке (19-сек ролик 2005 г., шумная дорожка)
ASR разошёлся с человеческими субтитрами в двух словах — расслышал «one of the elephants» вместо
«in front of the elephants» и «fronts» вместо «trunks». Вывод: при наличии ЧЕЛОВЕЧЕСКИХ субтитров
и плохом звуке слой A точнее; преимущество B — RU-речь, авто-субтитры без пунктуации, отсутствие
субтитров и приватность. Спорный фрагмент дешевле сверить обоими слоями, чем доверять одному.

**Операционные ноты**
- MCP `youtube-transcript` пинён на git-SHA: PyPI-релиз 0.3.5 отстал и даёт ОДИН инструмент, git-`main` (0.7.0) — четыре (проверено stdio-пробой). Правка `.mcp.json` действует после `/mcp reconnect`.
- Слой A ломается блокировкой YouTube по IP → в апстриме есть `--webshare-proxy-username/password` и `--http(s)-proxy`; добавлять в `args` при отказах.
- `yt-dlp` предупреждает `No supported JavaScript runtime` — часть форматов может быть недоступна; лечится установкой deno (`--js-runtimes`). При отказах извлечения первым делом `pip install -U yt-dlp` (YouTube ломает извлечение регулярно).
- Сервер whisper требует **явного подтверждения пользователя** перед возвратом текста в API; `privacy_mode=true` = транскрипт только в локальный файл (подтверждение всё равно спрашивается). Для несекретного контента снимается через `WHISPER_CONSENT_ACKNOWLEDGED=true` в env сервера.

## Выбор модели (баланс скорость/точность)

| Модель | Когда |
|---|---|
| `tiny`/`base` | черновая расшифровка, быстрый прогон, слабое железо |
| `small`/`medium` | рабочий баланс для русской речи |
| `large-v3` | максимум точности (медленно; нужен GPU) |

Русская речь — от `medium`; на CPU без GPU крупные модели медленны (оценивай по `analyze_media` длительности).

## Диагностика

| Симптом | Причина | Решение |
|---|---|---|
| tools не видны | deferred | `ToolSearch "select:mcp__whisper__transcribe_audio,..."` |
| «ffmpeg not found» | нет ffmpeg | установить ffmpeg, `check_system` перезапустить |
| очень медленно | CPU + крупная модель | `switch_model` на `small`/`medium` или включить GPU |
| пустой/обрывочный текст | тихая дорожка/шум/не тот язык | `analyze_media` (проверить дорожку), задать язык явно |
| батч «висит» | долгая обработка | `check_batch_progress` (не перезапускать) |

## Антипаттерны

| Плохо | Почему | Правильно |
|---|---|---|
| `transcribe_audio` без `check_system` | ffmpeg/GPU могут отсутствовать → падение | сначала `check_system`/`analyze_media` |
| `large-v3` на CPU для длинного видео | часы обработки | оценить `analyze_media` → выбрать модель по железу |
| whisper для «ключевых кадров»/склеек | не его задача | `scene-detect-mcp` |
| Перезапуск батча при «висит» | теряется прогресс | `check_batch_progress` |

## Связанные скиллы (НЕ дублировать)

- `scene-detect-mcp` — извлечение кадров по сменам сцен (видео → картинки), НЕ речь-в-текст.
- Для YouTube-метаданных/готовых транскриптов — отдельный путь (не whisper).
