# YAxUnit — полный справочник API (сверено с исходником v24.x)

> **Источник истины** — вендоренный исходник YAxUnit в `src/bsl/exts/YAXUNIT/CommonModules/`
> (BIA-Technologies, Apache-2.0). Каждый факт ниже сверен с Экспорт-сигнатурами модулей и с 3
> реальными задеплоенными тест-модулями в `src/bsl/exts/UnitTests/`. Официальные доки —
> [bia-technologies.github.io/yaxunit](https://bia-technologies.github.io/yaxunit/) (v25.12).
> При сомнении читать модуль: `mcp__edt-mcp__read_module_source(project, "YAXUNIT/CommonModules/<Модуль>/Module.bsl")`.
>
> ⚠ **Ловушка имён:** `ЮТест` (одна «Т») = фасад утверждений/API; `ЮТТесты` (две «Т») = регистратор
> тестов. Их постоянно путают — проверяй количество «Т».

## 1. Регистрация тестов — `ЮТТесты`

Точка входа тест-модуля — экспортная процедура `ИсполняемыеСценарии()` без параметров; в ней
регистрируются все тесты. Реальные сигнатуры (`ЮТТесты/Ext/Module.bsl`):

```bsl
ЮТТесты.ДобавитьСерверныйТест(ИмяТестовогоМетода, ПредставлениеТеста = "", ТегиСтрокой = "");
ЮТТесты.ДобавитьКлиентскийТест(ИмяТестовогоМетода, ПредставлениеТеста = "", Теги = "");   // редко
ЮТТесты.ДобавитьТест(ИмяТестовогоМетода, ПредставлениеТеста = "", ТегиСтрокой = "", Контексты = Неопределено);
ЮТТесты.ДобавитьТестовыйНабор(Имя, ТегиСтрокой = "");   // рекомендуется всегда, даже для 1 теста
```

- **`ПредставлениеТеста`** (2-й арг) — человекочитаемое описание; реальные тесты его ВСЕГДА дают.
  Имя процедуры в 1-м арге ДОЛЖНО посимвольно совпадать с объявленной `Процедура <Имя>() Экспорт`.
- **Флюент-модификаторы** (chain на результат `Добавить*`): `.ВТранзакции([=Истина])`,
  `.УдалениеТестовыхДанных([=Истина])`, `.Перед("Процедура")`, `.После("Процедура")`, `.Тег("тег")`,
  `.СПараметрами(...)` / `.СПараметрамиНаКлиенте(...)` / `.СПараметрамиНаСервере(...)`,
  `.Представление(...)`, `.ЗависитОт()`, `.НастройкаИсполнения(Имя, Значение)`, `.СвойствоОтчета(...)`.
- **`Контексты`** (4-й арг `ДобавитьТест`) — ОСЬ ИСПОЛНЕНИЯ (клиент/сервер), НЕ параметризация.
  `ДобавитьСерверныйТест`/`ДобавитьКлиентскийТест` = шорткаты пиннинга этой оси.

> ❌ **Нет метода `ДобавитьСерверныйТестСКонтекстом`** — это галлюцинация старых доков. Параметризация — через `.СПараметрами` / `ЮТест.Варианты` (§6).

## 2. Утверждения — `ЮТест.ОжидаетЧто(Значение [, Сообщение]).<Матчер>()`

`ЮТест.ОжидаетЧто(ПроверяемоеЗначение, Сообщение = "")` → `ЮТУтверждения` (chain). Полный каталог
матчеров (`ЮТУтверждения/Ext/Module.bsl`, все возвращают `ЮТУтверждения` для дальнейшего chain):

| Категория | Матчеры |
|---|---|
| Равенство/сравнение | `Равно` `НеРавно` `Больше` `БольшеИлиРавно` `Меньше` `МеньшеИлиРавно` |
| Диапазоны | `МеждуВключаяГраницы` `МеждуИсключаяГраницы` `МеждуВключаяНачалоГраницы` `МеждуВключаяОкончаниеГраницы` |
| Заполненность | `Заполнено` `НеЗаполнено` |
| Тип | `ИмеетТип` `НеИмеетТип` — принимают **`Строка \| Тип \| ОписаниеТипов`** |
| Булево | `ЭтоИстина` `ЭтоНеИстина` `ЭтоЛожь` `ЭтоНеЛожь` |
| Существование | `Существует` `НеСуществует` `ЭтоНеопределено` `ЭтоНеНеопределено` `ЭтоNull` `ЭтоНеNull` |
| Строки/коллекции | `Содержит` `НеСодержит` `СодержитСтрокуПоШаблону` `НеСодержитСтрокуПоШаблону` `НачинаетсяС` `ЗаканчиваетсяНа` `ВСписке` |
| Длина | `ИмеетДлину` `ИмеетДлинуБольше` `ИмеетДлинуМеньше` `НеИмеетДлину` |
| Свойства/элементы | `Свойство(Имя)` `НетСвойства` `ИмеетСвойство` `НеИмеетСвойства` `ИмеетСвойстваРавные` `Элемент(Индекс)` `Объект()` `ИмеющееПредставление` |
| Методы/исключения | `Метод(Имя, Параметры)` `ИмеетМетод` `ВыбрасываетИсключение([Ожид])` `НеВыбрасываетИсключение` |
| Предикаты коллекций | `СоответствуетПредикату` `КаждыйЭлементСоответствуетПредикату` `ЛюбойЭлементСоответствуетПредикату` `КаждыйЭлементСодержитСвойство[СоЗначением]` `ЛюбойЭлементСодержитСвойство[СоЗначением]` |

```bsl
// Тип — обе формы валидны (аргумент Строка|Тип|ОписаниеТипов):
ЮТест.ОжидаетЧто(Значение).ИмеетТип("Структура");
ЮТест.ОжидаетЧто(Значение).ИмеетТип(Тип("СправочникСсылка.Контрагенты"));

// Булево — идиоматично матчерами (не .Равно(Истина)):
ЮТест.ОжидаетЧто(Флаг).ЭтоИстина();
ЮТест.ОжидаетЧто(Флаг).ЭтоЛожь();
ЮТест.ОжидаетЧто(Значение).ЭтоНеопределено();

// Свойства объекта / коллекции:
ЮТест.ОжидаетЧто(Объект, "должен иметь код").Свойство("Код").Равно("А001");
ЮТест.ОжидаетЧто(Массив).ИмеетДлину(3);
ЮТест.ОжидаетЧто(Массив).Содержит(Элемент);

// Сообщение при падении (2-й арг ОжидаетЧто) — для диагностики:
ЮТест.ОжидаетЧто(Результат, "Должен вернуть ненулевую сумму").Больше(0);
```

**Исключения — правильные формы** (`ОжидаетВыброс` НЕ существует):
```bsl
// (а) через .Метод(...).ВыбрасываетИсключение() — вызов, ожидаемо падающий:
ЮТест.ОжидаетЧто(Объект, "Без прав — ошибка")
    .Метод("Записать", ЮТМетоды.МассивПараметров(РежимЗаписи.Запись))
    .ВыбрасываетИсключение();
// (б) прямой вызов в Попытке + проверка перехвата (когда вызов — статический код):
Поймано = Ложь;
Попытка
    гкс_Модуль.МетодКоторыйДолженУпасть(ПлохойАргумент);
Исключение
    Поймано = Истина;
КонецПопытки;
ЮТест.ОжидаетЧто(Поймано, "Ожидалось исключение").ЭтоИстина();
```

**Явный skip / fail** (`ЮТест/Ext/Module.bsl`):
```bsl
ЮТест.Пропустить("В базе нет данных для кейса");   // штатный SKIP (вместо ручного ОжидаетЧто(Истина).Равно(Истина); Возврат;)
ЮТест.Упал("Не должно достигать этой точки");       // явное падение
```

## 3. Утверждения по данным ИБ — `ЮТест.ОжидаетЧтоТаблицаБазы(...)`

`ЮТест.ОжидаетЧтоТаблицаБазы(ИмяТаблицы, Сообщение = "")` → `ЮТУтвержденияИБ`. Матчеры
(`ЮТУтвержденияИБ/Ext/Module.bsl`): `СодержитЗаписи(Предикат)` `НеСодержитЗаписи`
`СодержитЗаписиСНаименованием(Наим)` `СодержитЗаписиСКодом(Код)` `СодержитЗаписиСНомером(Номер)`
`СодержитТолькоОднуЗапись(Предикат)` `СодержитНесколькоЗаписей(N, Предикат)` (+ `Не*`-варианты).

```bsl
// ✅ реально: предикат через ЮТест.Предикат(...)
ЮТест.ОжидаетЧтоТаблицаБазы("РегистрНакопления.Остатки")
    .СодержитЗаписи(ЮТест.Предикат(Новый Структура("Номенклатура", Ссылка)));
ЮТест.ОжидаетЧтоТаблицаБазы("Справочник.Номенклатура").СодержитЗаписиСКодом("А001");
```
> ❌ `СодержитЗаписьСПолями(...)` — НЕ существует (галлюцинация старой главы). Используй `СодержитЗаписи(Предикат)`.

Это канонический способ проверить **движения регистров** после проведения документа (проводишь в тесте
→ проверяешь таблицу движений).

## 4. Изоляция данных

Два НЕЗАВИСИМЫХ механизма (оба — модификаторы регистрации, ставятся на модуль/набор/тест):

### `.ВТранзакции([Булево])` — откат транзакции
- Оборачивает **только серверный тест** (клиентский — игнор). В транзакцию входит тело теста +
  `ПередКаждымТестом`/`ПослеКаждогоТеста`; данные из `ПередВсемиТестами`/`ПередТестовымНабором` — **вне**,
  не откатываются (удалять руками).
- **НЕ спасает:** клиентский тест; тестируемый метод с ВЛОЖЕННЫМИ транзакциями (`НачатьТранзакцию` внутри);
  внешние эффекты вне СУБД-транзакции (HTTP, файлы, e-mail, фоновые задания, отдельные сессии, COM) — их мокировать.

### `.УдалениеТестовыхДанных([Булево])` — трекинг созданного (НЕ транзакция)
- Запоминает объекты/записи РС, созданные **через `ЮТест.Данные()`-API**, и удаляет по выходу из контекста.
  **Изменения существующих данных НЕ откатывает — только удаляет созданное.**
- **НЕ трекает:** созданное вне API (`Объект.Записать()` в своём коде); созданное ВНУТРИ тестируемого кода;
  клиент-данные через серверные callbacks.

### `ЮТест.Данные()` — фабрика фикстур (делает объекты «трекаемыми»)
```bsl
Конструктор = ЮТест.Данные().КонструкторОбъекта("Документы.ПриходТовара")
    .ФикцияРеквизитов("Поставщик, Склад")   // случайные значения реквизитов
    .ФикцияОбязательныхПолей()               // авто-заполнить обязательные
    .ТабличнаяЧасть("Товары");
Конструктор.ДобавитьСтроку().Фикция("Товар").Установить("Количество", 5);
Ссылка = Конструктор.Провести();             // или .Записать() → возвращает ссылку
// движения регистров: ЮТест.Данные().КонструкторДвижений(Документ, "ИмяРегистра")
```
⚠ `ЮТест.Данные().СлучайнаяДата()`/`СлучайноеПоложительноеЧисло(...)` повышают покрытие, но плодят
**флаки** (то падает, то нет; трудно воспроизвести). Для критичных кейсов — детерминированные данные.

> `ОбменДанными.Загрузка = Истина` при ручной записи фикстуры (в обход `ПроверкаЗаполнения`/`ПередЗаписью`)
> — общая 1С-практика (не YAxUnit-специфика); в экосистеме YAxUnit ту же роль закрывает `ФикцияОбязательныхПолей()`.

## 5. Мокирование — `Мокито` (+ `МокитоОбучение` / `МокитоПроверки`)

### ⚠ Требование обвязки — БЕЗ него мок не работает
Мокито НЕ патчит рантайм. Метод мокируется, ТОЛЬКО если он **заимствован в расширение** директивой
`&Вместо` и его тело делегирует в `МокитоПерехват.АнализВызова`. Канонический шаблон (`Мокито:29-47`,
[docs/mockito](https://bia-technologies.github.io/yaxunit/docs/features/mocking/mockito/)):
```bsl
&Вместо("ИмяМетода")
Функция Мок_ИмяМетода(Парам1)
    ПараметрыМетода = Мокито.МассивПараметров(Парам1);
    ПрерватьВыполнение = Ложь;
    Результат = МокитоПерехват.АнализВызова(<Объект>, "ИмяМетода", ПараметрыМетода, ПрерватьВыполнение);
    Если Не ПрерватьВыполнение Тогда
        Возврат ПродолжитьВызов(Парам1);   // мок не сработал → реальный метод
    Иначе
        Возврат Результат;                 // мок сработал → подменённое значение
    КонецЕсли;
КонецФункции
```
`<Объект>`: для **общего модуля** — ссылка на модуль (`ОбщегоНазначения`), **НЕ** `ЭтотОбъект`; для объекта —
`ЭтотОбъект`; для менеджера — `Справочники.Пользователи`. В EDT есть команды-помощники, генерящие обвязку.

### Три фазы: Обучение → Прогон → Проверить
```bsl
// 1. Обучение (arrange)
Мокито.Обучение(РаботаСHTTP)
    .Когда("ОтправитьОбъектНаСервер", Мокито.МассивПараметров(Источник, Данные))  // .Наблюдать = spy без подмены
        .Вернуть(2);                            // реакции: .Вернуть / .ВыброситьИсключение("текст") / .Пропустить() / .ВыполнитьМетод()
Мокито.Прогон();                                // ОБЯЗАТЕЛЬНО перед вызовом тестируемого кода
// 2. Act
Результат = РаботаСHTTP.ОтправитьОбъектНаСервер(Источник, Данные);
ЮТест.ОжидаетЧто(Результат).Равно(2);
// 3. Проверить (assert взаимодействий)
Мокито.Проверить(РаботаСHTTP).КоличествоВызовов("ОтправитьОбъектНаСервер").Равно(1);
```
- Формы `.Когда`: `.Когда("Метод", Мокито.МассивПараметров(...))` ИЛИ `.Когда(Объект.Метод(...))` (явный вызов).
- Маски параметров: `Мокито.ЛюбойПараметр()` `ЧисловойПараметр()` `СтроковыйПараметр()` `ТипизированныйПараметр(Тип)`
  `МассивПараметров(...)` (пропущенный параметр = `ЛюбойПараметр`).
- `Мокито.Проверить(Об)`: `.КоличествоВызовов("Метод"[, Параметры]).Равно(N)` (+ `.Больше .Меньше .Заполнено .Пусто`); `.Вызовы(...)`.
- Обучение через **менеджер** = мок для всех объектов типа; через **объект** = конкретный; через **ссылку** = для этой ссылки.
- ⚠ **danger:** в фазе `.Обучение()` вызовы обучаемого объекта возвращают инфо-о-вызове, НЕ делают полезной работы —
  не дёргай реальную логику до `.Прогон()`. Цепочку предикатов закрывать `.Получить()`.

### Что НЕЛЬЗЯ мокать (жёстко) и обходы
Нельзя: методы **платформы** (встроенные), методы **расширений**, методы **внешних обработок/отчётов**.
Обход для платформенных: обернуть вызов своей функцией и мокать обёртку:
```bsl
Функция ТекущаяДатаСеанса_МП() Экспорт  Возврат ТекущаяДатаСеанса();  КонецФункции  // мокаем эту обёртку
```
Готовые заглушки без Мокито: `ЮТест.Данные().HTTPСервисЗапрос()` / `HTTPОтвет` / `HTTPСоединение` /
`СообщениеСервисаИнтеграции` / `ADODB.RecordSet`.

> **Предпочитай DI мокам:** если зависимость передаётся ПАРАМЕТРОМ вызывающего — подсунуть тестовую реализацию
> проще и без обвязки (моки нужны, когда объект создаётся ВНУТРИ метода). Over-mocking → хрупкие тесты (§9).

## 6. Data-driven (параметризованные тесты)

**`.СПараметрами(...)` — предпочтительно** (до 10 арг; каждый набор = ИЗОЛИРОВАННЫЙ прогон + своя строка отчёта):
```bsl
Процедура ИсполняемыеСценарии() Экспорт
    ЮТТесты.ДобавитьТест("ЗначенияРавны")
        .СПараметрами(1, 1, Истина)
        .СПараметрами("1", 1, Ложь)
        .СПараметрами(Новый Структура("А", 1), Новый Структура("А", 1), Истина);
КонецПроцедуры
Процедура ЗначенияРавны(Значение1, Значение2, Ожидаемое) Экспорт
    ЮТест.ОжидаетЧто(Значение1 = Значение2).Равно(Ожидаемое);
КонецПроцедуры
```
**`ЮТест.Варианты(...)` — декартово произведение в одном тесте** (одна строка отчёта):
```bsl
Варианты = ЮТест.Варианты("ВидОперации, ВидКонтрагента").ДобавитьКомбинации(ВидыОпераций, ВидыКонтрагентов);
Для Каждого Вариант Из Варианты.СписокВариантов() Цикл
    Результат = ПроверитьДокумент(Вариант.ВидОперации, Вариант.ВидКонтрагента);
    ЮТест.ОжидаетЧто(Результат, "Вид: " + Вариант.ВидОперации).ЭтоИстина();
КонецЦикла;
```

## 7. События жизненного цикла (setup/teardown)

Обрабатываются **АВТО-детектом по имени**: положить в тест-модуль экспортную процедуру БЕЗ параметров с
зарезервированным именем. Опц. override — `.Перед("Проц")`/`.После("Проц")` при регистрации.

| Событие | Когда |
|---|---|
| `ПередВсемиТестами` | один раз перед всеми тестами модуля (вне per-test транзакции) |
| `ПередТестовымНабором` | перед набором (вне транзакции) |
| `ПередКаждымТестом` | перед каждым тестом (внутри транзакции при `.ВТранзакции()`) |
| `ПослеКаждогоТеста` | после каждого теста (внутри транзакции) |
| `ПослеТестовогоНабора` / `ПослеВсехТестов` | после набора / всех |

⚠ В клиент-серверных модулях хендлеры зовутся ДВАЖДЫ (клиент+сервер). Внутри — интроспекция:
`ЮТест.ОписаниеТекущегоТеста()`, `ЮТест.Контекст()` (мешок данных между тестами, скоупы
`КонтекстТеста/Набора/Модуля`).

## 8. Дискавери и деплой тест-модуля

**Дискавери (v24.x, сверено с `ЮТПодключаемыеМодулиСлужебный`): по СОДЕРЖИМОМУ ПОДСИСТЕМЫ.** Тест-модуль
находится, ТОЛЬКО если он добавлен в подсистему `ЮТТ_ЮТПодключаемыеМодули → Модульные`, `<Content>`:
```xml

<Content>
  <xr:Item xsi:type="xr:MDObjectRef">CommonModule.гкс_ОбщегоНазначенияТест</xr:Item>
```

- Имя модуля — **любое** (`гкс_…Тест` работает; `ЮТТ` — префикс ПОДСИСТЕМЫ, не модулей). Официальная схема

```powershell
1cv8.exe DESIGNER /IBConnectionString "<ONEC_TEST_CONN>" /UpdateDBCfg -Extension UnitTests
```

Версию платформы взять из установленной (локально 8.3.27.1936/2214), `<ONEC_TEST_CONN>` — из `.env`.

## 9. 🔒 Безопасный режим расширения — ОБЯЗАТЕЛЬНО снять

После загрузки расширения (UnitTests И YAXUNIT) в ИБ — **отключить «Безопасный режим» и «Защиту от опасных
действий»** ([docs/run](https://bia-technologies.github.io/yaxunit/docs/getting-started/run/)). Иначе:
перехваты Мокито (`МокитоПерехват`) не отрабатывают, движок не может прочитать `config.json`, файловые
операции и `closeAfterTests` блокируются → зависания/тихий сброс параметров. При CLI-создании расширения
(`LoadConfigFromFiles -Extension`) дефолт = безопасный режим ВКЛ.

## 10. Запуск и `config.json`

Нативный запуск — параметром `RunUnitTests` через `/C` (thin/thick/EDT). YAxUnit **НЕ** использует `/TESTMANAGER`
(это канал Vanessa/внешних тест-менеджеров):
```
1cv8c.exe ENTERPRISE /IBName MyBase /N Admin /C RunUnitTests=C:\tmp\test-config.json
```
Ключи `config.json` ([docs/run/configuration](https://bia-technologies.github.io/yaxunit/docs/getting-started/run/configuration)):

| Ключ | Значение |
|---|---|
| `filter` | `{extensions:["tests"], modules, tests, suites, tags, contexts}` |
| `reportFormat` | `"jUnit"` (деф) / `"JSON"` / `"allure"` (спеллинг — `jUnit`) |
| `reports` | `[{format, path}]` — несколько отчётов |
| `reportPath` | путь одиночного отчёта |
| `closeAfterTests` | закрыть 1С (деф `True`; для headless — обязательно `true`, иначе висит) |
| `showReport` | форма отчёта (деф `True`; для CI — `false`) |
| `exitCode` | путь к файлу `0`/`1` — гейт пайплайна |
| `logging` | `{file, enable, console, level: debug\|info\|warning\|error}` |

С 25.09 параметры можно переопределять в строке запуска (`/C"RunUnitTests=cfg.json;closeAfterTests=true"`;
приоритет дефолт < json < CLI). Пример headless-конфига CI:
```json
{ "filter": {"extensions": ["UnitTests"]}, "reportPath": "out/junit.xml", "reportFormat": "jUnit",
  "closeAfterTests": true, "showReport": false, "exitCode": "out/exit.txt",
  "logging": {"console": true, "level": "info"} }
```
В этом проекте прогон идёт через **`mcp-onec-test-runner`** (`run_module_tests`/`run_all_tests`), который
инкапсулирует native-launch + JUnit (см. §12).

## 11. `ЮТДымовыеТесты` (встроенный smoke) ≠ рек.3-«смоук»

YAxUnit-`ДымовыеТесты` — ФУНКЦИОНАЛЬНЫЙ smoke в RUNTIME по ВСЕЙ конфе (`ОткрытиеФорм`/`ПроведениеДокументов`/
`ПроверкаПрав`/`ЗаписьСправочников`), НЕ компиляция; реализация — отдельное незрелое расширение
[alexandr-yang/yaxunit-smoke](https://github.com/alexandr-yang/yaxunit-smoke) («not for production»). Тяжёлый
nightly whole-config прогон. Компиляция/метаданные-чек — ДРУГОЙ путь (syntax check: `check_syntax_designer_modules`/
`check_syntax_edt`). **рек.3-«смоук» ≠ ни то, ни другое** — это быстрый unit-прогон затронутого модуля (§13).

## 13. Связь с рек.3 (YAxUnit-смоук как advisory-петля)

Гейт `onec-task-completion-stop` рекомендует (advisory `•`, НИКОГДА не блок) прогнать YAxUnit-смоук, когда
правлен/добавлен **ЭКСПОРТНЫЙ серверный метод** (`onec_change_scope.edits_exported_method`) — экспортная
поверхность = тестируемый инвариант, POST-change комплемент impact-чека (кто сломается). Маршрут —
**ЕДИНСТВЕННЫЙ** `mcp-onec-test-runner` (`run_module_tests` затронутого модуля / `run_all_tests`), НЕ
`edt/codepilot run_yaxunit_tests`-дубли, НЕ BDD. Прогон пишет `.run-state.json` → авто-Этап-4
(`advance_test_done`), иначе — секция live-данных (ADR-050). Метрика — `onec_toolgate_validation.yaxunit_rate_on_applicable`.
