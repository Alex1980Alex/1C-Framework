# Аналитический отчет: GKSTCPLK-2262 — Заблокированные ТС

## 1. Обзор функционала

Функционал **"Заблокированные ТС"** реализует механизм усиленного контроля качества при приемке транспортных средств на ПЛК. Система автоматически блокирует регистрации ТС, если показатели качества по лабораторным анализам не соответствуют установленным правилам, и предоставляет интерфейс для управления блокировками в АРМе приемки транспорта.

**Функциональная опция:** `гкс_ИспользоватьУсиленныйКонтрольКачества`

## 3. Основные принципы формирования записей и проверок

### 3.1 Принцип формирования записей в РС `гкс_ЗаблокированныеРегистрацииУсиленныйКонтроль`

Записи формируются программно из общего модуля `гкс_ВходнойКонтрольКачества` при следующих условиях:

1. **Триггер:** Проведение документа `гкс_ЛабораторныйАнализ` или изменение состояния качества по регистрации.
2. **Алгоритм проверки:**
   - Для документа регистрации определяются применимые правила из РС `гкс_ПравилаУсиленногоКонтроляПоРегистрации`.
   - Фактические значения показателей берутся из РС `гкс_ПоказателиУсиленногоКонтроляПоРегистрации`.
   - Если показатель выходит за пределы (мин/макс) с учётом базиса, определяется состояние качества (отклонение).
   - При несоответствии создается запись блокировки с указанием блокирующей регистрации, группы ТС и показателя.

3. **Ключ записи (измерения):**
   - `ДокументРегистрации` — блокируемая регистрация
   - `Показатель` — показатель, вызвавший блокировку
   - `БлокирующаяРегистрация` — регистрация-источник отклонения
   - `БлокирующаяГруппаТС` — группа ТС

4. **Данные записи (ресурсы):**
   - `БлокирующееСостояниеКачества` — состояние качества, вызвавшее блокировку
   - `Разблокировано` (Boolean) — признак ручной разблокировки оператором

### 3.2 Принцип проверок

- Настройки проверок задаются в РС `гкс_НастройкиУсиленногоКонтроляКачества` с фильтрацией по: виду перевозки, точке маршрута, номенклатуре, показателю, ТС, пункту погрузки, поставщику, ЖД-станции.
- Каждое правило имеет `ИдентификаторПравила` (UUID), диапазон дат действия (`ДатаНачала`, `ДатаОкончания`), флаг `Активен`.
- Типы контроля (`ТипВходногоКонтроля`): определяет поведение — блокировка каждого ТС или блокировка группы после N ТС.
- Параметр `КоличествоТС` — сколько ТС должно быть проверено до применения блокировки.
- Флаг `ОтклонятьКачество` — определяет, отклоняется ли качество автоматически.

### Жизненный цикл записи:
1. **Создание** — при проведении лабораторного анализа, если показатели не соответствуют правилам
2. **Существование** — ТС заблокировано, отображается в АРМе как требующее внимания
3. **Разблокировка** — оператор в АРМе принимает решение (ресурс `Разблокировано = Истина`)
4. **Удаление** — при отмене проведения анализа или пересчете правил

## 5. Реализация в общем модуле `гкс_ВходнойКонтрольКачества`

### [REQ-4] Основные функции модуля:

| # | Метод (предполагаемый) | Назначение |
|---|----------------------|------------|
| 1 | Определение применимых правил | Выборка из РС `гкс_НастройкиУсиленногоКонтроляКачества` по параметрам регистрации (вид перевозки, точка маршрута, номенклатура и т.д.) |
| 2 | Запись правил по регистрации | Запись найденных правил в РС `гкс_ПравилаУсиленногоКонтроляПоРегистрации` |
| 3 | Расчет показателей | Получение фактических значений из лабораторных анализов, запись в РС `гкс_ПоказателиУсиленногоКонтроляПоРегистрации` |
| 4 | Проверка блокировок | Сравнение фактических показателей с пороговыми значениями правил |
| 5 | Формирование блокировок | Запись/удаление записей в РС `гкс_ЗаблокированныеРегистрацииУсиленныйКонтроль` |
| 6 | Разблокировка | Установка `Разблокировано = Истина` по указанным записям |

### Алгоритм работы:

```
1. ВХОД: Документ регистрации (гкс_РегистрацияНаПЛК)
2. Определить параметры фильтрации (вид перевозки, точка маршрута, номенклатура...)
3. ЗАПРОС: Получить активные правила из гкс_НастройкиУсиленногоКонтроляКачества
   WHERE Активен = TRUE
     AND ДатаНачала <= ТекущаяДата
     AND ДатаОкончания >= ТекущаяДата
     AND (фильтры по параметрам регистрации)
4. ЗАПИСАТЬ правила в гкс_ПравилаУсиленногоКонтроляПоРегистрации
5. ДЛЯ КАЖДОГО правила:
   5.1. Получить фактические значения показателя из ЛА
   5.2. ЗАПИСАТЬ в гкс_ПоказателиУсиленногоКонтроляПоРегистрации
   5.3. Проверить: ЗначениеФакт < ЗначениеМин ИЛИ ЗначениеФакт > ЗначениеМакс
   5.4. ЕСЛИ не в норме:
        - Определить блокирующую регистрацию и группу ТС
        - ЗАПИСАТЬ блокировку в гкс_ЗаблокированныеРегистрацииУсиленныйКонтроль
   5.5. ЕСЛИ в норме и была блокировка:
        - УДАЛИТЬ запись блокировки
6. ВЫХОД: Обновленные записи блокировок
```

## 6. Интерактивная работа в АРМе `гкс_ПриемкаТранспорта`

### [REQ-5] Взаимодействие пользователя с блокировками:

**Форма `ОсновнаяФорма`:**
- Отображение списка регистраций ТС с визуальным выделением заблокированных
- Просмотр причин блокировки (показатель, состояние качества, блокирующая регистрация)

**Форма `ГрупповоеНаправлениеНаРазгрузку`:**
- Групповое создание направлений на разгрузку для заблокированных ТС
- Возможность принять решение по нескольким ТС одновременно

**Форма `ИзменениеДопускаТранспорта`:**
- Изменение допуска заблокированного ТС
- Установка флага `Разблокировано = Истина` через серверный вызов

**Цепочка вызовов:**
```
АРМ (клиент) → гкс_ПриемкаТранспортаВызовСервера → гкс_ВходнойКонтрольКачества → РС
```

## 8. SQL-запросы для анализа данных

### 8.1 Текущие блокировки (активные)
```sql
SELECT
    Блок.ДокументРегистрации AS Регистрация,

```
