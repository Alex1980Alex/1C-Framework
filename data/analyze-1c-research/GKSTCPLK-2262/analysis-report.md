# Аналитический отчёт GKSTCPLK-2262: Функционал «Заблокированные ТС»

## 1. Общее описание функционала

Функционал **«Заблокированные ТС»** реализует механизм усиленного входного контроля качества транспортных средств (ТС) на приёмке. При поступлении ТС от поставщика система проверяет, требуется ли усиленный контроль по определённым показателям качества. Если первое ТС поставщика за сутки не прошло лабораторный анализ, последующие ТС этого поставщика **блокируются** до получения результатов.

### Ключевые бизнес-сценарии

| Сценарий | Описание |
|----------|----------|
| Регистрация ТС | При проведении `гкс_РегистрацияНаПЛК` записываются правила и показатели усиленного контроля |
| Блокировка при анализе | При завершении лабораторного анализа проверяется качество; при отклонении — создаются записи блокировки |
| Проверка при создании НнР | Перед созданием «Направления на разгрузку» проверяется наличие блокировки |
| Разблокировка | При принятии качества флаг `Разблокировано = Истина` снимает блокировку |
| Отображение в АРМ | В АРМ «Приёмка транспорта» отображается причина блокировки и ссылка на блокирующий ЛА |

## 2. Метаданные конфигурации

### 2.1. Функциональные опции и константы

| Объект | Тип | Назначение |
|--------|-----|------------|
| `гкс_ИспользоватьУсиленныйКонтрольКачества` | ФО + Константа (Boolean) | Включает/выключает весь функционал усиленного контроля |
| `гкс_ИспользоватьЗаблокированныеТС` | ФО + Константа (Boolean) | Включает/выключает блокировку ТС при усиленном контроле |
| `гкс_ИспользоватьОтключениеВходногоКонтроляКачества` | ФО + Константа (Boolean) | Отключение входного контроля качества |
| `гкс_ПередаватьКачествоВходногоКонтроля` | ФО + Константа (Boolean) | Передача качества входного контроля в силосную карту |

### 2.2. Перечисления [VERIFIED]

#### `гкс_ТипыУсиленногоКонтроляКачества` [VERIFIED]
| Значение | Синоним | Описание |
|----------|---------|----------|
| `КаждоеТС` | Каждое ТС | Контроль каждого ТС — блокировка не требуется |
| `ПервоеТС` | Первое ТС | Контроль по первому ТС поставщика за сутки, последующие блокируются |
| `ГруппыТС` | Группы ТС | Контроль группы ТС — блокируются ТС в следующей группе |

#### `гкс_ТипыКонтроляКачества` [VERIFIED]
| Значение | Синоним |
|----------|---------|
| `ВходнойКонтроль` | Входной контроль |

#### 2.3.5. `гкс_ЗаблокированныеРегистрацииУсиленныйКонтроль` — Записи блокировки ТС [VERIFIED, FIXED]

**Центральный регистр функционала.** Хранит записи о блокировке ТС с указанием блокирующей регистрации или группы ТС.

| Тип | Имя | Тип данных | Описание |
|-----|-----|-----------|----------|
| Измерение | ДокументРегистрации | ДокументСсылка.гкс_РегистрацияНаПЛК | Заблокированная регистрация |
| Измерение | Показатель | Справочник.гкс_ПоказателиАнализовНоменклатуры | Показатель качества |
| Измерение | БлокирующаяРегистрация | ДокументСсылка.гкс_РегистрацияНаПЛК | Первое ТС, результат которого ожидается |
| Измерение | БлокирующаяГруппаТС | Справочник.гкс_ГруппыТС | Группа ТС (при типе «Группы ТС») |
| Ресурс | БлокирующееСостояниеКачества | Перечисление.гкс_СостоянияКачества | Состояние первого ТС |
| Ресурс | Разблокировано | Булево | Признак разблокировки |

> **Исправлено при верификации:** измерение `ДокументРегистрации` НЕ является ведущим (Master=false в XML-метаданных). В отличие от регистров 2.3.2-2.3.4, данный регистр не имеет ведущих измерений.

## 3. Схема движения по регистрам сведений

### 3.1. Этап 1: Регистрация ТС (проведение `гкс_РегистрацияНаПЛК`) [VERIFIED]

```
[гкс_РегистрацияНаПЛК.ОбработкаПроведения]
  │ (ФО: гкс_ИспользоватьУсиленныйКонтрольКачества)
  ▼
[гкс_ВходнойКонтрольКачества.ЗарегистрироватьТранспортноеСредствоДляУсиленногоКонтроля()]
  │
  ├──► READ  гкс_ТранспортныеСредстваПоставщикаУсиленногоКонтроля
  │          (проверка: ТранспортноеСредствоЗарегистрировано)
  │
  ├──► READ  гкс_ТранспортныеСредстваПоставщикаУсиленногоКонтроля
  │          (поиск: ПерваяРегистрацияТСПоставщика — ЭтоПервоеТС?)
  │
  ├──► READ  гкс_НастройкиУсиленногоКонтроляКачества
  │          (подбор: НайтиПоказателиКачестваДляУсиленногоВходногоКонтроля)
  │
  ├──► WRITE гкс_ПоказателиУсиленногоКонтроляПоРегистрации
  │          (ЗаписатьДанныеПоУсиленномуКонтролюДляРегистрации)
  │
  ├──► WRITE гкс_ПравилаУсиленногоКонтроляПоРегистрации
  │          (ЗаписатьПравилаПоУсиленномуКонтролюДляРегистрации)
  │
  ├──► UPDATE гкс_НастройкиУсиленногоКонтроляКачества
  │           (УстановитьАктивность → Ложь для правил типа "ТС")
  │
  └──► WRITE гкс_ТранспортныеСредстваПоставщикаУсиленногоКонтроля
             (ЗаписатьДанныеПоМашинеПоставщика)
```

### 3.2. Этап 2: Завершение лабораторного анализа [VERIFIED]

```
[Завершение ЛА]
  │
  ▼
[гкс_ВходнойКонтрольКачества.ЗаполнитьЗаблокированныеРегистрацииУсиленныйКонтроль()]
  │
  ├──► READ  Пакетный запрос (ТекстЗапросаЗаблокированныхРегистрацийУК)
  │          Определяет: какие регистрации нужно заблокировать
  │
  ├──► READ  ПолучитьДанныеБлокировкиДляРегистраций (пакетная предзагрузка)
  │          гкс_ТранспортныеСредстваПоставщикаУсиленногоКонтроля
  │          гкс_ПоказателиУсиленногоКонтроляПоРегистрации
  │          гкс_ЗаблокированныеРегистрацииУсиленныйКонтроль
  │
  │ Для каждой регистрации:
  │
  ├──[Тип: ПервоеТС]──► WRITE гкс_ЗаблокированныеРегистрацииУсиленныйКонтроль
  │                            (ЗаписатьБлокировкуТС)
  │
  ├──[Тип: ГруппыТС]──► WRITE гкс_ЗаблокированныеРегистрацииУсиленныйКонтроль
  │                            (ЗаписатьБлокировкуГруппыТС)
  │
  └──► ОбновитьЗаблокированныеТСПриЗавершенииЛА
       │
       ├──► UPDATE гкс_ЗаблокированныеРегистрацииУсиленныйКонтроль
       │           (ОбновитьСостояниеБлокировки)
       │
       └──[Качество НЕ ПРИНЯТО]
            ├──► UPDATE гкс_ПоказателиУсиленногоКонтроляПоРегистрации
            │           (УстановитьПробыНеТребуютсяДляКомпозитных)
            └──► WRITE  гкс_ПоказателиУсиленногоКонтроляПоРегистрации
                        (ДобавитьПоказателиУКДляЗаблокированногоТС)
```

### 3.3. Этап 3: Интерактивная работа в АРМ [VERIFIED]

```
[АРМ гкс_ПриемкаТранспорта — ОсновнаяФорма]
  │
  ├──[ПриСозданииНаСервере]
  │   └──► СоздатьЭлементыБлокировкиНаСервере()
  │        (программное создание UI-элементов, если ФО включена)
  │
  ├──[Выбор регистрации]
  │   └──► ЗаполнитьИнформациюОБлокировке(ДокументРегистрации)
  │        │
  │        └──► READ гкс_ЗаблокированныеРегистрацииУсиленныйКонтроль
  │                  + гкс_ПоказателиУсиленногоКонтроляПоРегистрации
  │                  (ПолучитьПричинуБлокировкиДляДеталей)
  │                  → Отображает текст причины и ссылку на ЛА
  │
  └──[Команда «Направление на разгрузку»]
       └──► ПроверитьБлокировкуДляСозданияНнР(ДокументРегистрации)
            │
            ├──[ЕстьБлокировка = Истина] → Сообщение: «Создание НнР запрещено»
            ├──[ЕстьПредупреждение = Истина] → Диалог подтверждения
            └──[Нет блокировки] → Открытие формы НнР
```

### 3.4. Этап 4: Разблокировка [VERIFIED]

```
[гкс_НаправлениеНаРазгрузку.ОбработкаПроведения]
  │ (Если ПринятьКачество = Истина)
  ▼
[гкс_ВходнойКонтрольКачества.РазблокироватьТСПриПринятииКачества()]
  │ (ФО: гкс_ИспользоватьЗаблокированныеТС)
  │
  └──► UPDATE гкс_ЗаблокированныеРегистрацииУсиленныйКонтроль
              (Разблокировано = Истина для всех записей по регистрации)
```

### 4.3. Принципы формирования записей [VERIFIED]

1. **Однократная регистрация**: проверка `ТранспортноеСредствоЗарегистрировано()` предотвращает повторную запись
2. **Транзакционность**: вся запись выполняется в единой транзакции с `Попытка/Исключение`
3. **Привилегированный режим**: `УстановитьПривилегированныйРежим(Истина)` для обхода RLS
4. **Пакетная оптимизация**: `ПолучитьДанныеБлокировкиДляРегистраций()` выполняет один пакетный запрос вместо N отдельных
5. **Дедупликация обработки**: `ОбработанныеРегистрации = Новый Соответствие` — каждая регистрация обрабатывается однократно
6. **Функциональные опции**: все точки входа защищены проверкой `ПолучитьФункциональнуюОпцию()`

### 4.4. Принципы проверок (блокировки) [VERIFIED]

1. **Тип «КаждоеТС»** — пропускается (блокировка не нужна, каждое ТС проверяется само)
2. **Тип «ПервоеТС»** — блокировка создаётся, если:
   - Есть первое ТС от другой регистрации (`ЕстьПервоеТСДругойРегистрации`)
   - Анализ текущего ТС выполнен (`АнализТекущегоТСВыполнен`)
   - Состояние качества первого ТС: `ОтборПроб` или пустое
3. **Тип «ГруппыТС»** — блокировка по предыдущей группе, если:
   - Есть первое ТС от другой регистрации
   - Анализ текущего ТС выполнен
   - Учитывается состояние качества группы (`СостояниеКачестваГруппы`)

- При наличии блокировки показывает группу с текстом причины и ссылкой на ЛА

### 5.3. Причины блокировки (5 сценариев)

| # | Условие | Текст пользователю |
|---|---------|-------------------|
| 1 | Нет показателей входного контроля по ЛА | «Заблокировано: ждём результата по входному контролю» |
| 2 | Первое ТС — результат не готов | «Заблокировано: ждём результат по первому ТС» |
| 3 | Первое ТС — анализ не прошёл | «Заблокировано: анализ по первому ТС не прошёл, ждём результата проверки на усиленный контроль» |
| 4 | Группа ТС — промежуточный композит не готов | «Заблокировано: ждём результат на промежуточный композит предыдущей группы» |
| 5 | Группа ТС — промежуточный композит не прошёл | «Заблокировано: не прошёл анализ на промежуточный композит предыдущей группы, ждём результата проверки на усиленный контроль» |

### 5.4. Проверка при создании НнР [VERIFIED]

Метод `ПроверитьБлокировкуДляСозданияНнР()` возвращает структуру:
- `ЕстьБлокировка` — жёсткая блокировка (КачествоНеПринято без композита)
- `ЕстьПредупреждение` — мягкая блокировка (есть композит → можно продолжить с подтверждением)
- `ТекстСообщения` — текст для пользователя
