# GKSTCPLK-2262 — Описание функционала «Заблокированные ТС»

## 1. Общее описание

Функционал «Заблокированные ТС» реализует механизм блокировки транспортных средств (регистраций на ПЛК) в рамках усиленного входного контроля качества. Блокировка запрещает или ограничивает создание направления на разгрузку до получения результатов лабораторного анализа первого ТС поставщика (или группы ТС).

Управляется функциональной опцией `гкс_ИспользоватьЗаблокированныеТС`.

---

## 2. Метаданные и их назначение

### 2.1 Регистр сведений `гкс_ЗаблокированныеРегистрацииУсиленныйКонтроль`

**Назначение:** Хранит записи о заблокированных регистрациях ТС в рамках усиленного контроля качества.

| Тип       | Имя                         | Тип данных                                              | Описание |
|-----------|-----------------------------|---------------------------------------------------------|----------|
| Измерение | `ДокументРегистрации`       | `ДокументСсылка.гкс_РегистрацияНаПЛК`                  | Заблокированная регистрация (ТС, которое ждёт результатов) |
| Измерение | `Показатель`                | `СправочникСсылка.гкс_ПоказателиАнализовНоменклатуры`   | Показатель качества, по которому произошла блокировка |
| Измерение | `БлокирующаяРегистрация`    | `ДокументСсылка.гкс_РегистрацияНаПЛК`                  | Регистрация первого ТС, результаты которого ожидаются |
| Измерение | `БлокирующаяГруппаТС`       | `СправочникСсылка.гкс_ГруппыТС`                         | Группа ТС, результаты которой блокируют разгрузку |
| Ресурс    | `БлокирующееСостояниеКачества` | `ПеречислениеСсылка.гкс_СостоянияКачества`            | Состояние качества первого ТС / группы (обновляется при завершении ЛА) |
| Ресурс    | `Разблокировано`            | `Булево`                                                | Флаг разблокировки (Истина = блокировка снята) |

**Свойства:** Непериодический, независимый режим записи, управляемая блокировка данных.

### 2.2 Связанные регистры сведений

| Регистр | Назначение |
|---------|-----------|
| `гкс_ПоказателиУсиленногоКонтроляПоРегистрации` | Показатели качества для каждой регистрации: ЛА, состояние качества, тип пробы, назначение использования |
| `гкс_ПравилаУсиленногоКонтроляПоРегистрации` | Правила контроля: тип входного контроля (ПервоеТС / ГруппыТС / КаждоеТС), показатель |
| `гкс_ТранспортныеСредстваПоставщикаУсиленногоКонтроля` | Данные о ТС поставщика: контрагент, номенклатура, произв. сутки, признак «ЭтоПервоеТС» |
| `гкс_НастройкиУсиленногоКонтроляКачества` | Настройки и правила усиленного контроля для поиска показателей |
| `гкс_СоставГруппТранспорта` | Состав групп транспорта (привязка регистраций к группам ТС) |
| `гкс_СостоянияРегистрации` | Состояния регистрации для отображения в АРМе |
| `гкс_СопоставлениеФНПЛабАнализа` | Связь ФНП с лабораторными анализами |

### 2.3 Справочники и перечисления

| Объект | Назначение |
|--------|-----------|
| `Справочник.гкс_ГруппыТС` | Группы транспортных средств для группового контроля |
| `Перечисление.гкс_ТипыУсиленногоКонтроляКачества` | Типы контроля: `ПервоеТС`, `ГруппыТС`, `КаждоеТС` |
| `Перечисление.гкс_СостоянияКачества` | Состояния: `ОтборПроб`, `РезультатыПробПолучены`, `КачествоПринято`, `КачествоНеПринято` |
| `Перечисление.гкс_ТипыПроб` | Типы проб: `Единичная`, `Композитная` |
| `Перечисление.гкс_НазначенияИспользованияКачества` | Назначения: `Приемка`, `ПромежуточныйКомпозит` |

### 2.4 Общие модули

| Модуль | Контекст | Назначение |
|--------|----------|-----------|
| `гкс_ВходнойКонтрольКачества` | Сервер | Основная бизнес-логика: регистрация ТС, формирование/обновление блокировок, проверки, разблокировка |
| `гкс_ПриемкаТранспортаВызовСервера` | Сервер (ServerCall) | Обёртки с привилегированным режимом для вызова из клиента |
| `гкс_ПриемкаТранспорта` | Сервер | Вспомогательная логика АРМа приемки |

### 2.5 Обработка (АРМ)

| Объект | Назначение |
|--------|-----------|
| `Обработка.гкс_ПриемкаТранспорта` (ОсновнаяФорма) | Интерактивный АРМ приемки транспорта, в котором пользователь создаёт направления на разгрузку, видит блокировки |

## 3. Основные принципы формирования записей

### 3.1 Регистрация ТС для усиленного контроля

**Метод:** `гкс_ВходнойКонтрольКачества.ЗарегистрироватьТранспортноеСредствоДляУсиленногоКонтроля()` (строка 8)

Вызывается при регистрации ТС на ПЛК. Алгоритм:

1. Проверка однократности регистрации (`ТранспортноеСредствоЗарегистрировано`)
2. Получение реквизитов: Контрагент, Номенклатура
3. Определение первого ТС поставщика за произв. сутки (`ПерваяРегистрацияТСПоставщика`)
4. Получение показателей и правил контроля из настроек (`гкс_НастройкиУсиленногоКонтроляКачества`)
5. В транзакции:
   - Запись показателей в `гкс_ПоказателиУсиленногоКонтроляПоРегистрации`
   - Запись правил в `гкс_ПравилаУсиленногоКонтроляПоРегистрации`
   - Деактивация одноразовых правил контроля ТС
   - Для не-первого ТС: инициализация группы ТС (`ИнициализироватьГруппуТС`)
   - Запись данных поставщика в `гкс_ТранспортныеСредстваПоставщикаУсиленногоКонтроля`

### 3.2 Формирование записей блокировки

**Метод:** `гкс_ВходнойКонтрольКачества.ЗаполнитьЗаблокированныеРегистрацииУсиленныйКонтроль()` (строка 221)

Вызывается при завершении лабораторного анализа. Алгоритм:

1. Выполняется запрос `ТекстЗапросаЗаблокированныхРегистрацийУК()` — определяет все связанные регистрации с данными первого ТС, типом контроля, состоянием качества
2. Предзагрузка данных блокировки пакетным запросом (`ПолучитьДанныеБлокировкиДляРегистраций`)
3. Для каждой регистрации (кроме типа `КаждоеТС`):
   - **Правило «Первое ТС»:** если есть первое ТС другой регистрации, качество не принято и ЛА выполнен → `ЗаписатьБлокировкуТС()`
   - **Правило «Группа ТС»:** если есть первое ТС другой регистрации и ЛА выполнен → `ЗаписатьБлокировкуГруппыТС()`
4. Однократное обновление блокировок по уникальным регистрациям (`ОбновитьЗаблокированныеТСПриЗавершенииЛА`)

### 3.3 Обновление блокировок при завершении ЛА

**Метод:** `ОбновитьЗаблокированныеТСПриЗавершенииЛА()` (строка 1873)

Два сценария обновления:

| Сценарий | Условие | Действие |
|----------|---------|----------|
| **A — Качество ПРИНЯТО** | `СостояниеКачества = КачествоПринято` | Разблокировка: `ОбновитьСостояниеБлокировки()` с новым состоянием |
| **B — Качество НЕ ПРИНЯТО** | `СостояниеКачества = КачествоНеПринято` или `РезультатыПробПолучены` | Эскалация: обновление состояния + создание индивидуальных показателей для заблокированного ТС (`ДобавитьПоказателиУКДляЗаблокированногоТС`) |

### 3.4 Обновление блокировки текущей регистрации

**Метод:** `ОбновитьБлокировкуТекущейРегистрации()` (строка 2095)

При проведении индивидуального ЛА (ПромежуточныйКомпозит) по ранее заблокированному ТС: если качество принято — обновляет состояние всех записей блокировки для данной регистрации.

### 3.5 Разблокировка при принятии качества

**Метод:** `РазблокироватьТСПриПринятииКачества()` (строка 2690)

Устанавливает `Разблокировано = Истина` для всех неразблокированных записей по регистрации. Проверяет ФО `гкс_ИспользоватьЗаблокированныеТС`.

## 4. Схема проверок

### 4.1 Проверка при создании направления на разгрузку (НнР)

**Метод:** `гкс_ВходнойКонтрольКачества.ПроверитьБлокировкуДляСозданияНнР()` (строка 2581)

Пакетный запрос из 2 частей:
1. ВТ с показателями, по которым есть промежуточный композит ЛА
2. Соединение блокирующих записей с ВТ для определения наличия композита

**Три исхода:**

| Исход | Условие | Реакция |
|-------|---------|---------|
| **Жёсткая блокировка** | `КачествоНеПринято` + композит НЕ сделан | `ЕстьБлокировка = Истина`, ошибка пользователю, НнР запрещено |
| **Предупреждение** | `КачествоНеПринято` или `РезультатыПробПолучены` + композит сделан | `ЕстьПредупреждение = Истина`, вопрос пользователю Да/Нет |
| **Разрешено** | Нет блокирующих записей или все разблокированы | НнР создаётся без ограничений |

### 4.2 Прямая проверка блокировки

**Методы:**
- `ПроверитьБлокированиеТранспортногоСредстваДляРазгрузки()` (строка 2496) — SELECT ПЕРВЫЕ 1 из РС где `НЕ Разблокировано`
- `ПроверитьБлокированиеТранспортногоСредстваПоСтатусу()` (строка 2524) — аналогичная проверка

### 4.3 Определение необходимости блокировки

**Метод:** `ТребуетсяБлокировкаПервоеТС()` (строка 2480)

Блокировка требуется, если:
- Есть первое ТС другой регистрации (`ЕстьПервоеТСДругойРегистрации = Истина`)
- И состояние качества = `ОтборПроб` или пустое (результат ещё не получен)

### 4.4 Получение причины блокировки для деталей АРМ

**Метод:** `ПолучитьПричинуБлокировкиДляДеталей()` (строка 2144, GKSTCPLK-2206)

Пакетный запрос из 3 частей определяет одну из 5 причин:

| # | Причина | Текст |
|---|---------|-------|
| 1 | Нет показателей входного контроля | «Ждём результата по входному контролю» |
| 2 | Первое ТС: результат не готов | «Ждём результат по первому ТС» |
| 3 | Первое ТС: анализ не прошёл | «Анализ по первому ТС не прошёл, ждём результата проверки на УК» |
| 4 | Группа ТС: композит не готов | «Ждём результат на промежуточный композит предыдущей группы» |
| 5 | Группа ТС: композит не прошёл | «Не прошёл анализ на промежуточный композит, ждём УК» |

## 6. Интерактивная работа в АРМе `гкс_ПриемкаТранспорта`

### 6.1 Инициализация при открытии формы

**Форма:** `ОсновнаяФорма` > `ПриСозданииНаСервере` (строка 5)

Вызывается `СоздатьЭлементыБлокировкиНаСервере()` (строка 3906):
- Проверяет ФО `гкс_ИспользоватьЗаблокированныеТС`
- Программно создаёт реквизиты: `ТекстПричиныБлокировки` (Строка), `ЛАБлокировки` (ДокументСсылка)
- Создаёт элементы формы: группу `ГруппаИнформацияОБлокировке`, декорацию (красный текст), поле-гиперссылку на ЛА

### 6.2 Отображение деталей блокировки

**Метод:** `ЗаполнитьИнформациюОБлокировке()` (строка 3952)

Вызывается при выборе строки в списке регистраций:
1. Запрашивает `гкс_ВходнойКонтрольКачества.ПолучитьПричинуБлокировкиДляДеталей()`
2. При наличии блокировки:
   - Отображает красный текст причины
   - Показывает гиперссылку на блокирующий ЛА (если есть)
3. При отсутствии блокировки: скрывает группу

### 6.3 Создание направления на разгрузку

**Метод:** `РедактироватьНаправлениеНаРазгрузку()` (строка 375)

Пользователь нажимает «Направление на разгрузку»:
1. Вызов `гкс_ПриемкаТранспортаВызовСервера.ПроверитьБлокировкуДляСозданияНнР()` (строка 391)
2. Три ветки:
   - **`ЕстьБлокировка`** → сообщение об ошибке, возврат (строки 394-396)
   - **`ЕстьПредупреждение`** → диалог-вопрос Да/Нет, при «Да» продолжение (строки 397-406)
   - **Без блокировки** → открытие формы НнР (строка 409)

### 6.4 Переход к блокирующему ЛА

**Метод:** `Подключаемый_ЛАБлокировкиНажатие()` (строка 3991)

Пользователь нажимает гиперссылку ЛА → открывается форма блокирующего лабораторного анализа.

## 8. SQL-запросы для анализа данных

### 8.1 Все активные блокировки (неразблокированные записи)

```sql
ВЫБРАТЬ
    ЗаблокированныеТС.ДокументРегистрации,
    ЗаблокированныеТС.Показатель,
    ЗаблокированныеТС.БлокирующаяРегистрация,
    ЗаблокированныеТС.БлокирующаяГруппаТС,
    ЗаблокированныеТС.БлокирующееСостояниеКачества,
    ЗаблокированныеТС.Разблокировано
ИЗ
    РегистрСведений.гкс_ЗаблокированныеРегистрацииУсиленныйКонтроль КАК ЗаблокированныеТС
ГДЕ
    НЕ ЗаблокированныеТС.Разблокировано
```

### 8.2 Блокировки по конкретной регистрации

```sql
ВЫБРАТЬ
    ЗаблокированныеТС.Показатель.Наименование КАК ПоказательНаименование,
    ЗаблокированныеТС.БлокирующаяРегистрация,
    ЗаблокированныеТС.БлокирующаяГруппаТС,
    ЗаблокированныеТС.БлокирующееСостояниеКачества,
    ЗаблокированныеТС.Разблокировано
ИЗ
    РегистрСведений.гкс_ЗаблокированныеРегистрацииУсиленныйКонтроль КАК ЗаблокированныеТС
ГДЕ
    ЗаблокированныеТС.ДокументРегистрации = &ДокументРегистрации
```

### 8.3 Статистика блокировок за период

```sql
ВЫБРАТЬ
    ЗаблокированныеТС.БлокирующееСостояниеКачества КАК Состояние,
    КОЛИЧЕСТВО(РАЗЛИЧНЫЕ ЗаблокированныеТС.ДокументРегистрации) КАК КоличествоТС,
    СУММА(ВЫБОР КОГДА ЗаблокированныеТС.Разблокировано ТОГДА 1 ИНАЧЕ 0 КОНЕЦ) КАК Разблокировано,
    СУММА(ВЫБОР КОГДА НЕ ЗаблокированныеТС.Разблокировано ТОГДА 1 ИНАЧЕ 0 КОНЕЦ) КАК Заблокировано
ИЗ
    РегистрСведений.гкс_ЗаблокированныеРегистрацииУсиленныйКонтроль КАК ЗаблокированныеТС
СГРУППИРОВАТЬ ПО
    ЗаблокированныеТС.БлокирующееСостояниеКачества
```

### 8.4 Связь блокировок с показателями УК

```sql
ВЫБРАТЬ
    ЗаблокированныеТС.ДокументРегистрации,
    ЗаблокированныеТС.Показатель,
    ПоказателиУК.СостояниеКачества КАК СостояниеУК,
    ПоказателиУК.ЛабораторныйАнализ,
    ЗаблокированныеТС.БлокирующееСостояниеКачества
ИЗ
    РегистрСведений.гкс_ЗаблокированныеРегистрацииУсиленныйКонтроль КАК ЗаблокированныеТС
        ЛЕВОЕ СОЕДИНЕНИЕ РегистрСведений.гкс_ПоказателиУсиленногоКонтроляПоРегистрации КАК ПоказателиУК
        ПО ЗаблокированныеТС.ДокументРегистрации = ПоказателиУК.ДокументРегистрации
        И ЗаблокированныеТС.Показатель = ПоказателиУК.Показатель
ГДЕ
    НЕ ЗаблокированныеТС.Разблокировано
```
