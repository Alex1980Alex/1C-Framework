## 1. Общее описание функционала

Функционал **«Заблокированные ТС»** реализует механизм усиленного входного контроля качества транспортных средств (ТС) на приёмке. При поступлении ТС от поставщика система проверяет, требуется ли усиленный контроль по определённым показателям качества. Если первое ТС поставщика за сутки не прошло лабораторный анализ, последующие ТС этого поставщика **блокируются** до получения результатов.

### Ключевые бизнес-сценарии

| Сценарий | Описание |
|----------|----------|
| Регистрация ТС | При проведении `гкс_РегистрацияНаПЛК` записываются правила и показатели усиленного контроля |
| Блокировка при анализе | При завершении лабораторного анализа проверяется качество; при отклонении — создаются записи блокировки |
| Проверка при создании НнР | Перед созданием «Направления на разгрузку» проверяется наличие блокировки |
| Разблокировка | При принятии качества флаг `Разблокировано = Истина` снимает блокировку |
| Отображение в АРМ | В АРМ «Приёмка транспорта» отображается причина блокировки и ссылка на блокирующий ЛА |

## 2. Метаданные конфигурации [REQ-1]

### 2.1. Функциональные опции и константы

| Объект | Тип | Назначение |
|--------|-----|------------|
| `гкс_ИспользоватьУсиленныйКонтрольКачества` | ФО + Константа (Boolean) | Включает/выключает весь функционал усиленного контроля. Проверяется при проведении `гкс_РегистрацияНаПЛК` |
| `гкс_ИспользоватьЗаблокированныеТС` | ФО + Константа (Boolean) | Включает/выключает блокировку ТС при усиленном контроле. Проверяется при разблокировке в `РазблокироватьТСПриПринятииКачества` |
| `гкс_ИспользоватьОтключениеВходногоКонтроляКачества` | ФО + Константа (Boolean) | Отключение входного контроля качества |
| `гкс_ПередаватьКачествоВходногоКонтроля` | ФО + Константа (Boolean) | Передача качества входного контроля в силосную карту |

### 2.2. Перечисления

#### `гкс_ТипыУсиленногоКонтроляКачества`
| Значение | Синоним | Описание |
|----------|---------|----------|
| `КаждоеТС` | Каждое ТС | Контроль каждого ТС — блокировка не требуется |
| `ПервоеТС` | Первое ТС | Контроль по первому ТС поставщика за сутки, последующие блокируются до результатов первого |
| `ГруппыТС` | Группы ТС | Контроль группы ТС — блокируются ТС в следующей группе до результатов предыдущей |

#### `гкс_ТипыКонтроляКачества`
| Значение | Синоним |
|----------|---------|
| `ВходнойКонтроль` | Входной контроль |
| `УсиленныйКонтроль` | Усиленный контроль |

## 3. Схема движения по регистрам сведений [REQ-4]

### 3.1. Этап 1: Регистрация ТС (проведение `гкс_РегистрацияНаПЛК`)

```
[гкс_РегистрацияНаПЛК.ОбработкаПроведения]  (строка 106)
  │ (ФО: гкс_ИспользоватьУсиленныйКонтрольКачества)
  ▼
[гкс_ВходнойКонтрольКачества.ЗарегистрироватьТранспортноеСредствоДляУсиленногоКонтроля()]
  │                                                                       (строка 8)
  ├──► READ  гкс_ТранспортныеСредстваПоставщикаУсиленногоКонтроля
  │          (проверка: ТранспортноеСредствоЗарегистрировано — стр. 1498)
  │
  ├──► READ  гкс_ТранспортныеСредстваПоставщикаУсиленногоКонтроля
  │          (поиск: ПерваяРегистрацияТСПоставщика — стр. 355. ЭтоПервоеТС?)
  │
  ├──► READ  гкс_НастройкиУсиленногоКонтроляКачества
  │          (подбор: НайтиПоказателиКачестваДляУсиленногоВходногоКонтроля)
  │
  ├──► WRITE гкс_ПоказателиУсиленногоКонтроляПоРегистрации
  │          (ЗаписатьДанныеПоУсиленномуКонтролюДляРегистрации — стр. 1528)
  │
  ├──► WRITE гкс_ПравилаУсиленногоКонтроляПоРегистрации
  │          (ЗаписатьПравилаПоУсиленномуКонтролюДляРегистрации — стр. 1557)
  │
  ├──► UPDATE гкс_НастройкиУсиленногоКонтроляКачества
  │           (УстановитьАктивность → Ложь для правил типа "ТС")
  │
  └──► WRITE гкс_ТранспортныеСредстваПоставщикаУсиленногоКонтроля
             (ЗаписатьДанныеПоМашинеПоставщика — стр. 1537)
```

### 4.3. Принципы формирования записей [REQ-2]

1. **Однократная регистрация**: проверка `ТранспортноеСредствоЗарегистрировано()` (стр. 1498) предотвращает повторную запись — если ТС уже есть в `гкс_ТранспортныеСредстваПоставщикаУсиленногоКонтроля`, повторная регистрация не выполняется
2. **Транзакционность**: вся запись выполняется в единой транзакции с `Попытка/Исключение` — при ошибке в любом из 3 регистров откатываются все изменения
3. **Привилегированный режим**: `УстановитьПривилегированныйРежим(Истина)` для обхода RLS при записи в регистры
4. **Пакетная оптимизация**: `ПолучитьДанныеБлокировкиДляРегистраций()` (стр. 1598) выполняет один пакетный запрос к 3 регистрам вместо N отдельных запросов
5. **Дедупликация обработки**: `ОбработанныеРегистрации = Новый Соответствие` — каждая регистрация обрабатывается однократно в цикле
6. **Функциональные опции**: все точки входа защищены проверкой `ПолучитьФункциональнуюОпцию("гкс_ИспользоватьУсиленныйКонтрольКачества")`
7. **Условия создания блокировки**: запись в `гкс_ЗаблокированныеРегистрацииУсиленныйКонтроль` создаётся только при завершении ЛА (Этап 2), НЕ при регистрации ТС (Этап 1)
8. **Разблокировка**: устанавливается флаг `Разблокировано = Истина` (НЕ удаление записи) при проведении НнР с `ПринятьКачество = Истина`

### 4.4. Принципы проверок (блокировки) [REQ-3]

1. **Тип «КаждоеТС»** — пропускается (блокировка не нужна, каждое ТС проверяется индивидуально)
2. **Тип «ПервоеТС»** — блокировка создаётся, если:
   - Есть первое ТС от другой регистрации (`ЕстьПервоеТСДругойРегистрации`)
   - Анализ текущего ТС выполнен (`АнализТекущегоТСВыполнен`)
   - Состояние качества первого ТС: `ОтборПроб` или пустое (метод `ТребуетсяБлокировкаПервоеТС`, стр. 2480)
3. **Тип «ГруппыТС»** — блокировка по предыдущей группе, если:
   - Есть первое ТС от другой регистрации
   - Анализ текущего ТС выполнен
   - Учитывается состояние качества группы (`СостояниеКачестваГруппы`)
4. **Проверка при создании НнР** (стр. 2581):
   - `ЕстьБлокировка` (жёсткая) — КачествоНеПринято без промежуточного композита → создание НнР запрещено
   - `ЕстьПредупреждение` (мягкая) — есть промежуточный композит → можно продолжить с подтверждением пользователя
5. **Определение первого ТС** — запрос к `гкс_ТранспортныеСредстваПоставщикаУсиленногоКонтроля` с фильтром по поставщику, номенклатуре, производственным суткам и флагу `ЭтоПервоеТС`

## 7. SQL-запросы

### 7.1. Проверка регистрации ТС

```sql
ВЫБРАТЬ
    Т.ДокументРегистрации
ИЗ
    РегистрСведений.гкс_ТранспортныеСредстваПоставщикаУсиленногоКонтроля КАК Т
ГДЕ
    Т.ДокументРегистрации = &ДокументРегистрации
```

**Контекст:** Вызывается в `ТранспортноеСредствоЗарегистрировано()` (стр. 1498). Если запрос вернул результат — ТС уже зарегистрировано, повторная обработка не выполняется.

### 7.2. Поиск первого ТС поставщика за сутки

```sql
ВЫБРАТЬ РАЗРЕШЕННЫЕ ПЕРВЫЕ 1
    Т.ДокументРегистрации
ИЗ
    РегистрСведений.гкс_ТранспортныеСредстваПоставщикаУсиленногоКонтроля КАК Т
ГДЕ
    Т.ПроизводственныеСутки = &ПроизводственныеСутки
    И Т.Контрагент = &Контрагент
    И Т.Номенклатура = &Номенклатура
    И Т.ЭтоПервоеТС
```

**Контекст:** Вызывается в `ПерваяРегистрацияТСПоставщика()` (стр. 355). Определяет, было ли уже зарегистрировано первое ТС данного поставщика за текущие производственные сутки.

### 7.3. Получение заблокированных ТС по блокирующей регистрации

```sql
ВЫБРАТЬ
    З.ДокументРегистрации
ИЗ
    РегистрСведений.гкс_ЗаблокированныеРегистрацииУсиленныйКонтроль КАК З
ГДЕ
    З.БлокирующаяРегистрация = &ДокументРегистрации
    И З.Показатель В (&Показатели)
```

**Контекст:** Используется для получения списка ТС, заблокированных конкретной блокирующей регистрацией.

### 7.4. Проверка блокировки для создания НнР (пакетный)

```sql
-- Пакет 1: промежуточный композит по показателям
ВЫБРАТЬ РАЗЛИЧНЫЕ
    П.ДокументРегистрации, П.Показатель
ПОМЕСТИТЬ ВТ_КомпозитПоПоказателям
ИЗ
    РегистрСведений.гкс_ПоказателиУсиленногоКонтроляПоРегистрации КАК П
ГДЕ
    П.ДокументРегистрации = &ДокументРегистрации
    И П.НазначениеИспользования = ЗНАЧЕНИЕ(Перечисление.гкс_НазначенияИспользованияКачества.ПромежуточныйКомпозит)
    И П.ТипПробы = ЗНАЧЕНИЕ(Перечисление.гкс_ТипыПроб.Единичная)
    И П.СостояниеКачества В (&СостояниеКачестваПоказателяУК);

-- Пакет 2: неразблокированные записи с проверкой наличия композита
ВЫБРАТЬ РАЗЛИЧНЫЕ
    З.БлокирующееСостояниеКачества, З.Показатель,
    ВЫБОР КОГДА ВТ.ДокументРегистрации ЕСТЬ NULL ТОГДА ЛОЖЬ ИНАЧЕ ИСТИНА КОНЕЦ КАК КомпозитСделан
ИЗ
    РегистрСведений.гкс_ЗаблокированныеРегистрацииУсиленныйКонтроль КАК З
    ЛЕВОЕ СОЕДИНЕНИЕ ВТ_КомпозитПоПоказателям КАК ВТ
        ПО З.ДокументРегистрации = ВТ.ДокументРегистрации
        И З.Показатель = ВТ.Показатель
ГДЕ
    З.ДокументРегистрации = &ДокументРегистрации
    И НЕ З.Разблокировано
```

**Контекст:** Вызывается в `ПроверитьБлокировкуДляСозданияНнР()` (стр. 2581). Пакет 1 определяет наличие промежуточного композита (мягкая блокировка). Пакет 2 определяет неразблокированные записи и тип блокировки (жёсткая или мягкая).

### 7.6. Получение заблокированных групп ТС

```sql
ГДЕ
```

## 10. Заключение

Функционал «Заблокированные ТС» реализован как трёхуровневая архитектура:

1. **Слой данных (CRUD)** — ManagerModule регистров: `ЗаписатьБлокировкуТС`, `ЗаписатьБлокировкуГруппыТС`, `ОбновитьСостояниеБлокировки`, `ДобавитьПоказателиУКДляЗаблокированногоТС`
2. **Слой бизнес-логики** — Общий модуль `гкс_ВходнойКонтрольКачества`: оркестрация регистрации, блокировки, разблокировки, проверки (12 экспортных + 12 внутренних методов)
3. **Слой представления** — АРМ `гкс_ПриемкаТранспорта`: программное создание UI, отображение 5 сценариев причин блокировки, проверка при действиях пользователя (жёсткая/мягкая блокировка)

**Ключевые паттерны:**
- Функциональные опции для гейтинга всех точек входа
- Пакетная оптимизация запросов (один запрос к 3 регистрам вместо N отдельных)
- Транзакционная запись с Попытка/Исключение
- Однократная обработка через `Соответствие`
- Привилегированный режим для обхода RLS
- Разблокировка флагом (не удалением записей) для сохранения истории
