# Ralph Wiggum — автономные циклы для Claude Code

## Обзор

Ralph Wiggum — официальный плагин Claude Code, реализующий **автономные итеративные циклы**. Claude Code получает задачу и работает над ней в цикле, видя результаты своих предыдущих итераций через изменённую файловую систему и git-историю. Цикл продолжается до тех пор, пока задача не будет выполнена или не будет достигнут лимит итераций.

**Ключевой принцип:** неудачи — это данные. Каждая итерация уточняет решение на основе предыдущих попыток.

## Установка

### Предварительные требования

- **Claude Code CLI** установлен и настроен
- **Node.js** >= 18
- **jq** установлен (`sudo apt install jq` / `brew install jq`)
- **Git** — рабочая директория должна быть git-репозиторием
- Активная подписка с доступом к API (Max, Team, Enterprise или API-ключ)

### Шаги установки

```bash
# 1. Из сессии Claude Code — добавить маркетплейс

# 2. Установить плагин
/plugin install ralph-wiggum@claude-plugins-official

# 3. Проверить установку
/ralph-loop:help
```

### Альтернатива: ручной Ralph-цикл (без плагина)

Если плагин недоступен, можно использовать базовый bash-скрипт:

```bash
#!/bin/bash
# ralph.sh — минимальный Ralph-цикл
MAX_ITERATIONS=${1:-10}
PROMPT="$2"
ITERATION=0

while [ $ITERATION -lt $MAX_ITERATIONS ]; do
    ITERATION=$((ITERATION + 1))
    echo "=== Итерация $ITERATION из $MAX_ITERATIONS ==="

    # Запуск Claude Code с промптом
    # --dangerously-skip-permissions — только в изолированных средах!
    claude -p "$PROMPT Текущая итерация: $ITERATION из $MAX_ITERATIONS. \
    Если задача полностью завершена, включи в ответ строку RALPH_DONE. \
    Если нет — продолжай работу." \
    --dangerously-skip-permissions 2>&1 | tee /tmp/ralph_output.txt

    # Проверка маркера завершения
    if grep -q "RALPH_DONE" /tmp/ralph_output.txt; then
        echo "=== Задача завершена на итерации $ITERATION ==="
        exit 0
    fi

    echo "=== Итерация $ITERATION завершена, продолжаем... ==="
    sleep 2
done

echo "=== Достигнут лимит итераций ($MAX_ITERATIONS) ==="
```

Использование:

```bash
chmod +x ralph.sh
./ralph.sh 20 "Добавь JSDoc комментарии ко всем экспортируемым функциям в src/"
```

## Как работает плагин: механизм Stop Hook

### Архитектура

```
┌──────────────────────────────────────────────────────────┐
│                    RALPH-LOOP ЦИКЛ                       │
│                                                          │
│  ┌─────────┐    ┌──────────────┐    ┌────────────────┐  │
│  │ Промпт  │───>│  Claude Code  │───>│  Stop Hook     │  │
│  │ задачи  │    │  работает    │    │  скрипт        │  │
│  └─────────┘    └──────────────┘    └───────┬────────┘  │
│       ^                                      │           │
│       │         ┌──────────────┐             │           │
│       │    НЕТ  │ Найден       │   ДА        │           │
│       └─────────│ completion   │<────────────┘           │
│    (exit code 2)│ promise?     │                         │
│                 └──────┬───────┘                         │
│                        │ ДА (exit code 0)                │
│                        v                                 │
│                 ┌──────────────┐                         │
│                 │   СТОП       │                         │
│                 └──────────────┘                         │
└──────────────────────────────────────────────────────────┘
```

### Жизненный цикл итерации

1. **Запуск** — пользователь вызывает `/ralph-loop` с описанием задачи
2. **Работа** — Claude Code выполняет задачу, модифицирует файлы, делает коммиты
3. **Попытка остановки** — Claude Code решает, что закончил
4. **Перехват** — Stop Hook скрипт проверяет вывод:
   - Строка `completion-promise` **найдена** → exit 0 → цикл завершён
   - Строка **не найдена** И лимит итераций **не достигнут** → exit 2 → блокировка остановки, повторный ввод промпта
   - **Лимит достигнут** → exit 0 → принудительная остановка
5. **Следующая итерация** — Claude Code видит изменённую ФС и git-историю, продолжает работу

### Ключевые параметры

| Параметр | Описание | Рекомендация |
|----------|----------|-------------|
| `--max-iterations N` | Максимум итераций (предохранитель) | **Обязательно.** 10–50 в зависимости от задачи |
| `--completion-promise "СТРОКА"` | Маркер завершения в выводе Claude | Используй уникальную строку, например `TASK_COMPLETE_OK` |
| `--dangerously-skip-permissions` | Автоматическое одобрение всех операций | **Только в изолированных средах!** |

## Стратегии написания промптов

### Принципы эффективного Ralph-промпта

Промпт для Ralph-цикла кардинально отличается от обычного промпта. Ключевое требование — **чёткие, проверяемые критерии сходимости**.

### Структура промпта

```
ЗАДАЧА: [Что нужно сделать]

КОНТЕКСТ:
- [Технологии, фреймворки, ограничения]
- [Структура проекта]

КРИТЕРИИ ЗАВЕРШЕНИЯ (все должны быть выполнены):
1. [Конкретный проверяемый критерий]
2. [Конкретный проверяемый критерий]
3. [Конкретный проверяемый критерий]

ОГРАНИЧЕНИЯ:
- [Что НЕ делать]
- [Стилевые требования]

Когда ВСЕ критерии выполнены, включи в ответ: TASK_COMPLETE_OK
```

### Примеры хороших промптов

**Рефакторинг:**
```
ЗАДАЧА: Мигрировать все React компоненты с class-based на functional с hooks.

КОНТЕКСТ:
- Проект: src/components/
- React 18, TypeScript
- Используются: state, lifecycle methods, refs

КРИТЕРИИ ЗАВЕРШЕНИЯ:
1. Ни один файл в src/components/ не содержит "extends Component" или "extends React.Component"
2. Все тесты проходят: npm test -- --watchAll=false
3. Приложение собирается без ошибок: npm run build
4. Каждый мигрированный компонент использует useState/useEffect/useRef вместо this.state/componentDidMount/createRef

ОГРАНИЧЕНИЯ:
- Не менять публичный API компонентов (props)
- Сохранять имена файлов
- Коммитить каждый мигрированный компонент отдельно

Когда ВСЕ критерии выполнены: TASK_COMPLETE_OK
```

**Расширение тестов:**
```
ЗАДАЧА: Довести покрытие тестами до >= 80% для всех модулей в src/utils/.

КОНТЕКСТ:
- Jest + @testing-library/react
- Текущее покрытие ~45%

КРИТЕРИИ ЗАВЕРШЕНИЯ:
1. Запуск "npx jest --coverage --coverageDirectory=coverage" показывает >= 80% по branches и statements для каждого файла в src/utils/
2. Все тесты зелёные
3. Нет моков, которые маскируют реальные баги

Когда ВСЕ критерии выполнены: TASK_COMPLETE_OK
```

**Для 1С-разработки (BSL):**
```
ЗАДАЧА: Провести рефакторинг модуля "УправлениеТранспортом" — разделить монолитную процедуру ОбработкаЗаявокНаПеревозку на отдельные функции.

КОНТЕКСТ:
- Конфигурация 1С:Предприятие 8.3
- Модуль: ОбщиеМодули/УправлениеТранспортом
- Процедура > 500 строк, содержит бизнес-логику маршрутизации, валидации и документооборота

КРИТЕРИИ ЗАВЕРШЕНИЯ:
1. Процедура ОбработкаЗаявокНаПеревозку содержит <= 50 строк и делегирует логику подфункциям
2. Каждая подфункция имеет комментарий с описанием назначения и параметров
3. Все вызовы процедуры в других модулях работают без изменений (публичный API сохранён)
4. Модульные тесты (если есть) проходят

Когда ВСЕ критерии выполнены: TASK_COMPLETE_OK
```

### Антипаттерны (чего избегать)

| Плохо | Почему | Как исправить |
|-------|--------|---------------|
| «Улучши код» | Нет критериев сходимости — цикл бесконечен | Указать конкретные метрики: линтер без ошибок, тесты зелёные |
| «Сделай красивый UI» | Субъективный критерий | Конкретика: «все компоненты используют design system, нет inline styles» |
| «Исправь все баги» | Невозможно проверить «все» | Конкретный список: «исправь баги #123, #456, #789» |
| Без `--max-iterations` | Потенциально бесконечный цикл, огромные счета | Всегда ставить лимит |

## Управление затратами

### Примерная стоимость

| Сценарий | Итерации | Модель | Примерная стоимость |
|----------|----------|--------|-------------------|
| Малый рефакторинг | 5–10 | Sonnet 4.5 | $5–15 |
| Средняя миграция | 20–30 | Sonnet 4.5 | $20–50 |
| Крупная задача | 50+ | Sonnet 4.5 | $50–150+ |
| Крупная задача | 50+ | Opus | $150–500+ |

### Стратегии оптимизации

1. **Начинай с малого** — сначала 5 итераций, оцени прогресс, потом увеличивай
2. **Используй Sonnet для рутины** — Opus для сложных задач, Sonnet для механических
3. **Декомпозируй** — лучше 3 цикла по 10 итераций чем один на 50
4. **Git как чекпоинт** — после каждого успешного цикла коммить, чтобы не потерять прогресс
5. **Мониторь** — периодически проверяй вывод, не уходит ли Claude в бесполезный цикл

## Безопасность и изоляция

### КРИТИЧЕСКИ ВАЖНО

Флаг `--dangerously-skip-permissions` позволяет Claude Code выполнять **любые** команды без подтверждения. Это необходимо для автономной работы, но создаёт серьёзные риски.

### Рекомендуемые меры

| Мера | Как реализовать |
|------|----------------|
| **Одноразовая VM** | Запускай в Docker-контейнере или облачной VM (GitHub Codespaces, Gitpod) |
| **Git-репозиторий** | Всегда работай в git — возможность `git reset --hard` при проблемах |
| **Отдельная ветка** | `git checkout -b ralph-refactor` перед запуском |
| **Нет секретов** | Не храни API-ключи, пароли, токены в рабочей директории |
| **Ограниченная сеть** | По возможности блокируй исходящие соединения |
| **Мониторинг** | Проверяй вывод каждые 15–30 минут |

### Docker-обёртка для безопасного запуска

```dockerfile
FROM node:20-slim

RUN apt-get update && apt-get install -y git jq && rm -rf /var/lib/apt/lists/*
RUN npm install -g @anthropic-ai/claude-code

WORKDIR /workspace
# Копировать только нужные файлы проекта, БЕЗ секретов
COPY --chown=node:node . .

USER node
ENV ANTHROPIC_API_KEY=${ANTHROPIC_API_KEY}

# Запуск Ralph-цикла
CMD ["claude", "-p", "...ваш промпт...", "--dangerously-skip-permissions"]
```

```bash
docker build -t ralph-runner .
docker run --rm \
  -e ANTHROPIC_API_KEY="sk-ant-..." \
  --network=none \
  ralph-runner
```

## Лучшие задачи для Ralph

### Отлично подходит (чёткие критерии, верифицируемый результат)

- **Миграции фреймворков** — React class → hooks, Jest → Vitest, Express → Fastify
- **Пакетные обновления** — обновление зависимостей в сотнях файлов
- **Расширение покрытия тестами** — с 40% до 80%
- **Добавление документации** — JSDoc/TSDoc ко всем экспортам
- **Линтинг и форматирование** — устранение всех warnings/errors
- **Типизация** — добавление TypeScript типов к JS-коду
- **i18n** — вынос строк в файлы переводов
- **Greenfield scaffolding** — создание каркаса нового проекта за ночь
- **Механические рефакторинги** — переименование, разделение модулей

### Плохо подходит (субъективные решения)

- Дизайн UI/UX
- Архитектурные решения
- Выбор технологий
- Пограничные случаи бизнес-логики
- Оптимизация производительности (без чётких метрик)
- Ревью безопасности

## Интеграция с MCP-серверами

Ralph-циклы можно комбинировать с MCP-серверами для расширения возможностей Claude Code внутри цикла.

### Пример: Ralph + MCP для 1С-разработки

```json
// .claude/mcp.json
{
  "mcpServers": {
    "1c-metadata": {
      "command": "node",
      "args": ["./mcp-servers/1c-metadata/index.js"],
      "env": {
        "INFOBASE_PATH": "/path/to/infobase"
      }
    },
    "1c-docs": {
      "command": "node",
      "args": ["./mcp-servers/1c-docs/index.js"]
    }
  }
}
```

Внутри Ralph-цикла Claude Code автоматически получает доступ к MCP-инструментам и может:
- Читать метаданные конфигурации 1С
- Искать по документации
- Анализировать зависимости между объектами
- Проверять синтаксис BSL

## Диагностика проблем

### Частые проблемы

| Проблема | Причина | Решение |
|----------|---------|---------|
| Цикл не останавливается | `completion-promise` не совпадает точно | Используй `--max-iterations` как предохранитель. Упрости маркер до одного слова |
| Ошибка `jq: command not found` | jq не установлен | `sudo apt install jq` / `brew install jq` |
| Claude повторяет одни и те же действия | Недостаточный контекст между итерациями | Добавь в промпт: «Проверь git log и diff перед началом работы» |
| Слишком большие счета | Много итераций + дорогая модель | Начни с Sonnet, уменьши `--max-iterations`, декомпозируй задачу |
| Файлы повреждены | Конфликтующие изменения между итерациями | Всегда работай в git-ветке, делай `git stash` / `git reset` при проблемах |
| Не работает на Windows | bash-скрипты несовместимы | Используй `byigitt/ralph-wiggum-windows` (PowerShell) или WSL |
| Claude «застревает» в цикле ошибок | Ошибка невоспроизводима или требует человеческого решения | Добавь в промпт: «Если ошибка повторяется 3+ раз — пропусти и перейди к следующей задаче» |

### Отладка Stop Hook

```bash
# Проверить, что Stop Hook скрипт существует и исполняемый
ls -la .claude/plugins/ralph-wiggum/hooks/

# Ручной тест Stop Hook
echo "test output without marker" | .claude/plugins/ralph-wiggum/hooks/stop.sh
echo $?  # Должен быть 2 (продолжить)

echo "test output TASK_COMPLETE_OK" | .claude/plugins/ralph-wiggum/hooks/stop.sh
echo $?  # Должен быть 0 (остановить)
```

## Шаблоны промптов (копируй и адаптируй)

### Шаблон 1: Миграция / Рефакторинг

```
ЗАДАЧА: [Описание миграции]

КОНТЕКСТ:
- Проект: [путь к коду]
- Технологии: [фреймворк, язык, версии]
- Текущее состояние: [что есть сейчас]
- Целевое состояние: [что должно быть]

КРИТЕРИИ ЗАВЕРШЕНИЯ:
1. Ни один файл не содержит [старый паттерн]
2. Все тесты проходят: [команда запуска тестов]
3. Сборка успешна: [команда сборки]
4. [Дополнительные проверки]

ПОРЯДОК РАБОТЫ:
1. Сначала прочитай git log и текущий diff
2. Выбери следующий файл для миграции
3. Мигрируй, проверь тесты
4. Коммить с сообщением "[RALPH] Миграция: [имя файла]"

ОГРАНИЧЕНИЯ:
- [Что не менять]
- [Стилевые правила]

Когда ВСЕ критерии выполнены: TASK_COMPLETE_OK
```

### Шаблон 2: Расширение тестов
