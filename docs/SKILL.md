# Doc-to-Skill: конвертер документации в скиллы Claude Code

## Что это

Этот скилл превращает **любую сырую информацию** о технологии (статьи, документацию, README, результаты ресёрча, заметки) в **структурированный SKILL.md** — формат, который Claude Code CLI понимает и использует как руководство к действию.

## Зачем это нужно

Обычная документация написана для людей — она многословна, содержит историю, мотивацию, маркетинг. Claude Code нужно другое: **чёткие инструкции, команды, паттерны решений, критерии успеха и типичные ошибки**. Этот скилл выполняет трансформацию: из человеческой документации → в машинно-оптимальное руководство.

## Рабочий процесс

### Шаг 1: Сбор исходного материала

Определи что есть на входе. Это может быть:

| Тип входа | Действие |
|-----------|----------|
| URL на документацию | Загрузить и извлечь текст (`web_fetch`) |
| Загруженный файл (PDF, MD, TXT, HTML) | Прочитать содержимое |
| Результат deep research | Использовать текст из отчёта как есть |
| Устное описание от пользователя | Задать уточняющие вопросы, затем исследовать (`launch_extended_search_task`) |
| Несколько источников | Объединить, устранить дубликаты и противоречия |

Если информации недостаточно для полноценного скилла — **проведи исследование** через `web_search` или `launch_extended_search_task`, чтобы дополнить пробелы: установка, команды, API, типичные ошибки.

## Правила трансформации

При конвертации из сырого материала в SKILL.md следуй этим принципам:

### Что УБИРАТЬ из исходного материала

- **История и предыстория** — «Проект создан в 2019 году Иваном...» → убрать
- **Маркетинговые фразы** — «Революционный подход к...» → убрать
- **Философские рассуждения** — «Мы верим что будущее за...» → убрать
- **Сравнения с конкурентами** — «В отличие от X, наш Y...» → убрать (если нет прямой практической пользы)
- **Избыточные повторения** — одна мысль = одно место
- **Длинные абзацы прозы** → сжать в таблицы, списки, команды
- **Новостной контекст** — «На прошлой неделе вышла версия...» → только факты

### Что ДОБАВЛЯТЬ / УСИЛИВАТЬ

- **Копируемые команды** — каждая инструкция должна быть готова к `Ctrl+C → Ctrl+V`
- **Таблицы параметров** — вместо прозы «параметр X делает Y»
- **Диаграммы ASCII** — для архитектуры, потоков данных, жизненных циклов
- **Шаблоны с плейсхолдерами** — готовые к адаптации под конкретный проект
- **Таблицы диагностики** — проблема → причина → решение
- **Антипаттерны** — что НЕ делать и почему (Claude склонен повторять распространённые ошибки)
- **Интеграция с Claude Code** — как подключить к CLAUDE.md, MCP, хукам

### Стилистические правила

1. **Императив** — «Используй X» вместо «Можно использовать X»
2. **Конкретика** — `npm install -g docx` вместо «установите библиотеку»
3. **Объясняй "почему"** — не просто «делай так», а «делай так, потому что иначе Y»
4. **Без модальных "можешь"** — Claude должен понимать это как инструкцию, а не как опцию
5. **Русский язык** — если пользователь работает на русском, скилл на русском (команды и код на английском)
6. **Длина** — SKILL.md не более 500 строк. Если больше → выноси в `references/`

## Принятие решений о структуре

### Когда нужна секция «Архитектура / Основные концепции»

Включай если технология имеет нетривиальный внутренний механизм, который влияет на то, как Claude должен её использовать. Например: Ralph Wiggum → Stop Hook механизм определяет, как писать completion-promise. Пропускай если технология — простая CLI-утилита без скрытой логики.

### Когда выносить в references/

Если скилл получается > 500 строк, разбей так:

```
skill-name/
├── SKILL.md              ← Основной файл, ≤ 500 строк
│                           (обзор, быстрый справочник, установка,
│                            основные команды, диагностика, ссылки)
└── references/
    ├── advanced-usage.md  ← Расширенные сценарии
    ├── templates.md       ← Шаблоны
    ├── api-reference.md   ← Полный API
    └── migration-guide.md ← Гайд по миграции
```

В SKILL.md укажи:
```markdown
Для расширенных сценариев прочитай `references/advanced-usage.md`.
Для полного API прочитай `references/api-reference.md`.
```

### Когда добавлять скрипты

Если технология требует повторяющихся детерминированных операций (валидация, генерация конфигов, конвертация форматов), создай вспомогательные скрипты:

```
skill-name/
├── SKILL.md
└── scripts/
    ├── validate.sh    ← Проверка корректности настройки
    ├── init-config.sh ← Генерация начальной конфигурации
    └── cleanup.sh     ← Очистка артефактов
```

## Контроль качества

После генерации SKILL.md проверь:

| Критерий | Проверка |
|----------|----------|
| **Триггерность** | Description в frontmatter содержит ≥ 5 триггерных фраз? |
| **Копируемость** | Каждая команда готова к копированию без модификации? |
| **Полнота** | Есть: установка, основные команды, хотя бы 1 шаблон, диагностика? |
| **Actionability** | Claude может выполнить любую инструкцию без дополнительного поиска? |
| **Длина** | SKILL.md ≤ 500 строк? Если нет — вынесены ли лишние секции в references/? |
| **Антипаттерны** | Перечислены ≥ 3 распространённые ошибки? |
| **Интеграция** | Описано как подключить к CLAUDE.md / MCP / хукам (если применимо)? |
| **Без воды** | Нет истории, маркетинга, философии? |

### Пример: Вход → Выход

**ВХОД (сырая информация):**
> «Ralph Wiggum — это плагин, созданный Джеффри Хантли из Австралии. Он назвал его в честь
> персонажа Симпсонов. Идея в том что Claude Code запускается в цикле while true и работает
> пока не закончит задачу. Установить можно через /plugin install. Стоит $50-100 за 50 итераций.
> Есть баг с jq на Windows...»

**ВЫХОД (фрагмент SKILL.md):**
```markdown
## Быстрый справочник

| Задача | Команда |
|--------|---------|
| Установить | `/plugin install ralph-wiggum@claude-plugins-official` |
| Запустить цикл | `/ralph-loop "задача" --max-iterations 20` |
| Отменить | `/cancel-ralph` |

## Диагностика

| Проблема | Причина | Решение |
|----------|---------|---------|
| `jq: command not found` | jq не установлен | `sudo apt install jq` |
```

Обрати внимание: история про Австралию убрана, команды стали копируемыми, баг превратился в строку таблицы диагностики.

## Рабочий процесс Claude Code при использовании этого скилла

1. Пользователь предоставляет материал (URL, файл, текст, или просит исследовать тему)
2. **Если материала мало** → проведи исследование через `launch_extended_search_task` или `web_search`
3. **Извлеки знания** по категориям (см. «Шаг 2: Анализ и извлечение»)
4. **Собери SKILL.md** по шаблону, применяя правила трансформации
5. **Проверь качество** по чеклисту
6. **Сохрани файл** в `/mnt/user-data/outputs/<skill-name>/SKILL.md`
7. **Покажи пользователю** через `present_files`
8. **Предложи** куда положить в проекте: `.claude/skills/<name>/SKILL.md`
