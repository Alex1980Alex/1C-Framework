# Создание плагинов

> Создавайте пользовательские плагины для расширения Claude Code с помощью команд слэша, агентов, хуков, Skills и MCP серверов.

Плагины позволяют расширить Claude Code пользовательской функциональностью, которая может быть общей для проектов и команд. Это руководство охватывает создание собственных плагинов с командами слэша, агентами, Skills, хуками и MCP серверами.

Ищете установку существующих плагинов? Смотрите [Обнаружение и установка плагинов](/ru/discover-plugins). Для полных технических спецификаций смотрите [Справочник плагинов](/ru/plugins-reference).

## Когда использовать плагины в сравнении с автономной конфигурацией

Claude Code поддерживает два способа добавления пользовательских команд слэша, агентов и хуков:

| Подход                                                  | Имена команд слэша   | Лучше всего для                                                                                                     |
| :------------------------------------------------------ | :------------------- | :------------------------------------------------------------------------------------------------------------------ |
| **Автономная** (директория `.claude/`)                  | `/hello`             | Личные рабочие процессы, специфичные для проекта настройки, быстрые эксперименты                                    |
| **Плагины** (директории с `.claude-plugin/plugin.json`) | `/plugin-name:hello` | Совместное использование с коллегами, распространение в сообществе, версионные релизы, переиспользование в проектах |

**Используйте автономную конфигурацию когда**:

* Вы настраиваете Claude Code для одного проекта
* Конфигурация личная и не требует совместного использования
* Вы экспериментируете с командами слэша или хуками перед их упаковкой
* Вы хотите короткие имена команд слэша, такие как `/hello` или `/review`

**Используйте плагины когда**:

* Вы хотите поделиться функциональностью с вашей командой или сообществом
* Вам нужны одни и те же команды слэша/агенты в нескольких проектах
* Вы хотите контроль версий и легкие обновления для ваших расширений
* Вы распространяете через маркетплейс
* Вы согласны с пространством имён команд слэша, такими как `/my-plugin:hello` (пространство имён предотвращает конфликты между плагинами)

<Tip>
  Начните с автономной конфигурации в `.claude/` для быстрой итерации, затем [преобразуйте в плагин](#convert-existing-configurations-to-plugins) когда вы готовы поделиться.
</Tip>

## Быстрый старт

Этот быстрый старт проведёт вас через создание плагина с пользовательской командой слэша. Вы создадите манифест (файл конфигурации, который определяет ваш плагин), добавите команду слэша и протестируете её локально, используя флаг `--plugin-dir`.

### Предварительные требования

* Claude Code [установлен и аутентифицирован](/ru/quickstart#step-1-install-claude-code)
* Claude Code версия 1.0.33 или позже (запустите `claude --version` для проверки)

<Note>
  Если вы не видите команду `/plugin`, обновите Claude Code до последней версии. Смотрите [Устранение неполадок](/ru/troubleshooting) для инструкций по обновлению.
</Note>

### Создайте ваш первый плагин

<Steps>
  <Step title="Создайте директорию плагина">
    Каждый плагин находится в собственной директории, содержащей манифест и ваши пользовательские команды, агенты или хуки. Создайте один сейчас:

    ```bash  theme={null}
    mkdir my-first-plugin
    ```
  </Step>

  <Step title="Создайте манифест плагина">
    Файл манифеста в `.claude-plugin/plugin.json` определяет идентичность вашего плагина: его имя, описание и версию. Claude Code использует эти метаданные для отображения вашего плагина в менеджере плагинов.

    Создайте директорию `.claude-plugin` внутри папки вашего плагина:

    ```bash  theme={null}
    mkdir my-first-plugin/.claude-plugin
    ```

    Затем создайте `my-first-plugin/.claude-plugin/plugin.json` с этим содержимым:

    ```json my-first-plugin/.claude-plugin/plugin.json theme={null}
    {
    "name": "my-first-plugin",
    "description": "A greeting plugin to learn the basics",
    "version": "1.0.0",
    "author": {
    "name": "Your Name"
    }
    }
    ```

    | Поле          | Назначение                                                                                                                          |
    | :------------ | :---------------------------------------------------------------------------------------------------------------------------------- |
    | `name`        | Уникальный идентификатор и пространство имён команды слэша. Команды слэша имеют префикс этого (например, `/my-first-plugin:hello`). |
    | `description` | Показывается в менеджере плагинов при просмотре или установке плагинов.                                                             |
    | `version`     | Отслеживайте релизы, используя [семантическое версионирование](/ru/plugins-reference#version-management).                           |
    | `author`      | Опционально. Полезно для атрибуции.                                                                                                 |

    Для дополнительных полей, таких как `homepage`, `repository` и `license`, смотрите [полную схему манифеста](/ru/plugins-reference#plugin-manifest-schema).
  </Step>

  <Step title="Добавьте команду слэша">
    Команды слэша — это файлы Markdown в директории `commands/`. Имя файла становится именем команды слэша, с префиксом пространства имён плагина (`hello.md` в плагине с именем `my-first-plugin` создаёт `/my-first-plugin:hello`). Содержимое Markdown говорит Claude, как ответить, когда кто-то запустит команду слэша.

    Создайте директорию `commands` в папке вашего плагина:

    ```bash  theme={null}
    mkdir my-first-plugin/commands
    ```

    Затем создайте `my-first-plugin/commands/hello.md` с этим содержимым:

    ```markdown my-first-plugin/commands/hello.md theme={null}
    ---
    description: Greet the user with a friendly message
    ---

    # Hello Command

    Greet the user warmly and ask how you can help them today.
    ```
  </Step>

  <Step title="Протестируйте ваш плагин">
    Запустите Claude Code с флагом `--plugin-dir` для загрузки вашего плагина:

    ```bash  theme={null}
    claude --plugin-dir ./my-first-plugin
    ```

    Как только Claude Code запустится, попробуйте вашу новую команду:

    ```shell  theme={null}
    /my-first-plugin:hello
    ```

    Вы увидите, как Claude ответит приветствием. Запустите `/help` для просмотра вашей команды, указанной в пространстве имён плагина.

    <Note>
      **Почему пространство имён?** Команды слэша плагинов всегда имеют пространство имён (например, `/greet:hello`) для предотвращения конфликтов, когда несколько плагинов имеют команды с одинаковыми именами.

      Чтобы изменить префикс пространства имён, обновите поле `name` в `plugin.json`.
    </Note>
  </Step>

  <Step title="Добавьте аргументы команды слэша">
    Сделайте вашу команду слэша динамичной, принимая пользовательский ввод. Заполнитель `$ARGUMENTS` захватывает любой текст, который пользователь предоставляет после команды слэша.

    Обновите ваш файл `hello.md`:

    ```markdown my-first-plugin/commands/hello.md theme={null}
    ---
    description: Greet the user with a personalized message
    ---

    # Hello Command

    Greet the user named "$ARGUMENTS" warmly and ask how you can help them today. Make the greeting personal and encouraging.
    ```

    Перезагрузите Claude Code для применения изменений, затем попробуйте команду с вашим именем:

    ```shell  theme={null}
    /my-first-plugin:hello Alex
    ```

    Claude поприветствует вас по имени. Для дополнительных опций аргументов, таких как `$1`, `$2` для отдельных параметров, смотрите [Команды слэша](/ru/slash-commands).
  </Step>
</Steps>

Вы успешно создали и протестировали плагин с этими ключевыми компонентами:

* **Манифест плагина** (`.claude-plugin/plugin.json`): описывает метаданные вашего плагина
* **Директория команд** (`commands/`): содержит ваши пользовательские команды слэша
* **Аргументы команды** (`$ARGUMENTS`): захватывает пользовательский ввод для динамического поведения

<Tip>
  Флаг `--plugin-dir` полезен для разработки и тестирования. Когда вы готовы поделиться вашим плагином с другими, смотрите [Создание и распространение маркетплейса плагинов](/ru/plugin-marketplaces).
</Tip>

## Обзор структуры плагина

Вы создали плагин с командой слэша, но плагины могут включать намного больше: пользовательские агенты, Skills, хуки, MCP серверы и LSP серверы.

<Warning>
  **Распространённая ошибка**: Не помещайте `commands/`, `agents/`, `skills/` или `hooks/` внутри директории `.claude-plugin/`. Только `plugin.json` находится внутри `.claude-plugin/`. Все остальные директории должны быть на уровне корня плагина.
</Warning>

| Директория        | Местоположение | Назначение                                         |
| :---------------- | :------------- | :------------------------------------------------- |
| `.claude-plugin/` | Корень плагина | Содержит только манифест `plugin.json` (требуется) |
| `commands/`       | Корень плагина | Команды слэша как файлы Markdown                   |
| `agents/`         | Корень плагина | Определения пользовательских агентов               |
| `skills/`         | Корень плагина | Agent Skills с файлами `SKILL.md`                  |
| `hooks/`          | Корень плагина | Обработчики событий в `hooks.json`                 |
| `.mcp.json`       | Корень плагина | Конфигурации MCP сервера                           |
| `.lsp.json`       | Корень плагина | Конфигурации LSP сервера для интеллекта кода       |

<Note>
  **Следующие шаги**: Готовы добавить больше функций? Перейдите к [Разработка более сложных плагинов](#develop-more-complex-plugins) для добавления агентов, хуков, MCP серверов и LSP серверов. Для полных технических спецификаций всех компонентов плагина смотрите [Справочник плагинов](/ru/plugins-reference).
</Note>

## Разработка более сложных плагинов

Как только вы будете комфортны с базовыми плагинами, вы можете создавать более сложные расширения.

### Добавьте Skills в ваш плагин

Плагины могут включать [Agent Skills](/ru/skills) для расширения возможностей Claude. Skills вызываются моделью: Claude автоматически использует их на основе контекста задачи.

Добавьте директорию `skills/` в корень вашего плагина с папками Skills, содержащими файлы `SKILL.md`:

```
my-plugin/
├── .claude-plugin/
│   └── plugin.json
└── skills/
    └── code-review/
        └── SKILL.md
```

Каждый `SKILL.md` нуждается в frontmatter с полями `name` и `description`, за которыми следуют инструкции:

```yaml  theme={null}
---
name: code-review
description: Reviews code for best practices and potential issues. Use when reviewing code, checking PRs, or analyzing code quality.
---

When reviewing code, check for:
1. Code organization and structure
2. Error handling
3. Security concerns
4. Test coverage
```

После установки плагина перезагрузите Claude Code для загрузки Skills. Для полного руководства по авторству Skill, включая прогрессивное раскрытие и ограничения инструментов, смотрите [Agent Skills](/ru/skills).

### Добавьте LSP серверы в ваш плагин

<Tip>
  Для распространённых языков, таких как TypeScript, Python и Rust, установите предварительно построенные LSP плагины из официального маркетплейса. Создавайте пользовательские LSP плагины только когда вам нужна поддержка языков, которые ещё не охвачены.
</Tip>

LSP (Language Server Protocol) плагины дают Claude интеллект кода в реальном времени. Если вам нужна поддержка языка, который не имеет официального LSP плагина, вы можете создать свой собственный, добавив файл `.lsp.json` в ваш плагин:

```json .lsp.json theme={null}
{
  "go": {
    "command": "gopls",
    "args": ["serve"],
    "extensionToLanguage": {
      ".go": "go"
    }
  }
}
```

Пользователи, устанавливающие ваш плагин, должны иметь двоичный файл языкового сервера, установленный на их машине.

Для полных опций конфигурации LSP смотрите [LSP серверы](/ru/plugins-reference#lsp-servers).

### Организуйте сложные плагины

Для плагинов со многими компонентами организуйте структуру вашей директории по функциональности. Для полных макетов директорий и паттернов организации смотрите [Структура директории плагина](/ru/plugins-reference#plugin-directory-structure).

### Протестируйте ваши плагины локально

Используйте флаг `--plugin-dir` для тестирования плагинов во время разработки. Это загружает ваш плагин напрямую без необходимости установки.

```bash  theme={null}
claude --plugin-dir ./my-plugin
```

По мере внесения изменений в ваш плагин перезагрузите Claude Code для применения обновлений. Протестируйте компоненты вашего плагина:

* Попробуйте ваши команды с `/command-name`
* Проверьте, что агенты появляются в `/agents`
* Убедитесь, что хуки работают как ожидается

<Tip>
  Вы можете загружать несколько плагинов одновременно, указав флаг несколько раз:

  ```bash  theme={null}
  claude --plugin-dir ./plugin-one --plugin-dir ./plugin-two
  ```
</Tip>

### Отладка проблем плагина

Если ваш плагин не работает как ожидается:

1. **Проверьте структуру**: Убедитесь, что ваши директории находятся в корне плагина, а не внутри `.claude-plugin/`
2. **Протестируйте компоненты отдельно**: Проверьте каждую команду, агента и хук отдельно
3. **Используйте инструменты валидации и отладки**: Смотрите [Инструменты отладки и разработки](/ru/plugins-reference#debugging-and-development-tools) для команд CLI и методов устранения неполадок

### Поделитесь вашими плагинами

Когда ваш плагин готов к совместному использованию:

1. **Добавьте документацию**: Включите `README.md` с инструкциями по установке и использованию
2. **Версионируйте ваш плагин**: Используйте [семантическое версионирование](/ru/plugins-reference#version-management) в вашем `plugin.json`
3. **Создайте или используйте маркетплейс**: Распространяйте через [маркетплейсы плагинов](/ru/plugin-marketplaces) для установки
4. **Протестируйте с другими**: Попросите членов команды протестировать плагин перед более широким распространением

Как только ваш плагин находится в маркетплейсе, другие могут установить его, используя инструкции в [Обнаружение и установка плагинов](/ru/discover-plugins).

<Note>
  Для полных технических спецификаций, методов отладки и стратегий распространения смотрите [Справочник плагинов](/ru/plugins-reference).
</Note>

## Преобразование существующих конфигураций в плагины

Если у вас уже есть пользовательские команды, Skills или хуки в вашей директории `.claude/`, вы можете преобразовать их в плагин для более лёгкого совместного использования и распространения.

### Шаги миграции

<Steps>
  <Step title="Создайте структуру плагина">
    Создайте новую директорию плагина:

    ```bash  theme={null}
    mkdir -p my-plugin/.claude-plugin
    ```

    Создайте файл манифеста в `my-plugin/.claude-plugin/plugin.json`:

    ```json my-plugin/.claude-plugin/plugin.json theme={null}
    {
      "name": "my-plugin",
      "description": "Migrated from standalone configuration",
      "version": "1.0.0"
    }
    ```
  </Step>

  <Step title="Скопируйте ваши существующие файлы">
    Скопируйте ваши существующие конфигурации в директорию плагина:

    ```bash  theme={null}
    # Copy commands
    cp -r .claude/commands my-plugin/

    # Copy agents (if any)
    cp -r .claude/agents my-plugin/

    # Copy skills (if any)
    cp -r .claude/skills my-plugin/
    ```
  </Step>

  <Step title="Мигрируйте хуки">
    Если у вас есть хуки в ваших настройках, создайте директорию хуков:

    ```bash  theme={null}
    mkdir my-plugin/hooks
    ```

    Создайте `my-plugin/hooks/hooks.json` с конфигурацией ваших хуков. Скопируйте объект `hooks` из вашего `.claude/settings.json` или `settings.local.json` — формат одинаков:

    ```json my-plugin/hooks/hooks.json theme={null}
    {
      "hooks": {
        "PostToolUse": [
          {
            "matcher": "Write|Edit",
            "hooks": [{ "type": "command", "command": "npm run lint:fix $FILE" }]
          }
        ]
      }
    }
    ```
  </Step>

  <Step title="Протестируйте ваш мигрированный плагин">
    Загрузите ваш плагин для проверки, что всё работает:

    ```bash  theme={null}
    claude --plugin-dir ./my-plugin
    ```

    Протестируйте каждый компонент: запустите ваши команды, проверьте, что агенты появляются в `/agents`, и убедитесь, что хуки срабатывают правильно.
  </Step>
</Steps>

### Что изменяется при миграции

| Автономная (`.claude/`)                                       | Плагин                              |
| :------------------------------------------------------------ | :---------------------------------- |
| Доступна только в одном проекте                               | Может быть общей через маркетплейсы |
| Файлы в `.claude/commands/`                                   | Файлы в `plugin-name/commands/`     |
| Хуки в `settings.json`                                        | Хуки в `hooks/hooks.json`           |
| Должны быть скопированы вручную для совместного использования | Установите с `/plugin install`      |

<Note>
  После миграции вы можете удалить исходные файлы из `.claude/` для избежания дубликатов. Версия плагина будет иметь приоритет при загрузке.
</Note>
