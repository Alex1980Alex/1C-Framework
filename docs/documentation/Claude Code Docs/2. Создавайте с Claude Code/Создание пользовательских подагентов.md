# Создание пользовательских подагентов

> Создавайте и используйте специализированных AI подагентов в Claude Code для рабочих процессов, ориентированных на конкретные задачи, и улучшенного управления контекстом.

Подагенты — это специализированные AI помощники, которые обрабатывают определённые типы задач. Каждый подагент работает в собственном окне контекста с пользовательским системным приглашением, специфическим доступом к инструментам и независимыми разрешениями. Когда Claude встречает задачу, которая соответствует описанию подагента, он делегирует её этому подагенту, который работает независимо и возвращает результаты.

Подагенты помогают вам:

* **Сохранять контекст**, отделяя исследование и реализацию от основного разговора
* **Применять ограничения**, ограничивая доступ подагента к определённым инструментам
* **Переиспользовать конфигурации** в разных проектах с подагентами уровня пользователя
* **Специализировать поведение** с помощью сфокусированных системных приглашений для конкретных областей
* **Контролировать затраты**, маршрутизируя задачи на более быстрые и дешёвые модели, такие как Haiku

Claude использует описание каждого подагента, чтобы решить, когда делегировать задачи. Когда вы создаёте подагента, напишите чёткое описание, чтобы Claude знал, когда его использовать.

Claude Code включает несколько встроенных подагентов, таких как **Explore**, **Plan** и **general-purpose**. Вы также можете создавать пользовательские подагенты для обработки конкретных задач. На этой странице рассматриваются [встроенные подагенты](#built-in-subagents), [как создать свой собственный](#quickstart-create-your-first-subagent), [полные параметры конфигурации](#configure-subagents), [шаблоны работы с подагентами](#work-with-subagents) и [примеры подагентов](#example-subagents).

## Встроенные подагенты

Claude Code включает встроенные подагенты, которые Claude автоматически использует при необходимости. Каждый наследует разрешения родительского разговора с дополнительными ограничениями инструментов.

<Tabs>
  <Tab title="Explore">
    Быстрый агент, доступный только для чтения, оптимизированный для поиска и анализа кодовых баз.

    * **Модель**: Haiku (быстрая, низкая задержка)
    * **Инструменты**: Инструменты только для чтения (запрещён доступ к инструментам Write и Edit)
    * **Назначение**: Обнаружение файлов, поиск кода, исследование кодовой базы

    Claude делегирует Explore, когда ему нужно искать или понимать кодовую базу без внесения изменений. Это держит результаты исследования вне контекста основного разговора.

    При вызове Explore Claude указывает уровень тщательности: **quick** для целевых поисков, **medium** для сбалансированного исследования или **very thorough** для комплексного анализа.
  </Tab>

  <Tab title="Plan">
    Исследовательский агент, используемый во время [режима планирования](/ru/common-workflows#use-plan-mode-for-safe-code-analysis) для сбора контекста перед представлением плана.

    * **Модель**: Наследуется из основного разговора
    * **Инструменты**: Инструменты только для чтения (запрещён доступ к инструментам Write и Edit)
    * **Назначение**: Исследование кодовой базы для планирования

    Когда вы находитесь в режиме планирования и Claude нужно понять вашу кодовую базу, он делегирует исследование подагенту Plan. Это предотвращает бесконечное вложение (подагенты не могут порождать других подагентов) при этом собирая необходимый контекст.
  </Tab>

  <Tab title="General-purpose">
    Способный агент для сложных многошаговых задач, требующих как исследования, так и действия.

    * **Модель**: Наследуется из основного разговора
    * **Инструменты**: Все инструменты
    * **Назначение**: Сложное исследование, многошаговые операции, модификация кода

    Claude делегирует general-purpose, когда задача требует как исследования, так и модификации, сложного рассуждения для интерпретации результатов или нескольких зависимых шагов.
  </Tab>

  <Tab title="Other">
    Claude Code включает дополнительных вспомогательных агентов для конкретных задач. Они обычно вызываются автоматически, поэтому вам не нужно использовать их напрямую.

    | Агент             | Модель      | Когда Claude его использует                                      |
    | :---------------- | :---------- | :--------------------------------------------------------------- |
    | Bash              | Наследуется | Запуск команд терминала в отдельном контексте                    |
    | statusline-setup  | Sonnet      | Когда вы запускаете `/statusline` для настройки строки состояния |
    | Claude Code Guide | Haiku       | Когда вы задаёте вопросы о функциях Claude Code                  |
  </Tab>
</Tabs>

Помимо этих встроенных подагентов, вы можете создавать свои собственные с пользовательскими приглашениями, ограничениями инструментов, режимами разрешений, хуками и навыками. В следующих разделах показано, как начать работу и настроить подагентов.

## Быстрый старт: создайте свой первый подагент

Подагенты определяются в файлах Markdown с YAML frontmatter. Вы можете [создавать их вручную](#write-subagent-files) или использовать команду `/agents`.

Это пошаговое руководство проведёт вас через создание подагента уровня пользователя с помощью команды `/agent`. Подагент проверяет код и предлагает улучшения для кодовой базы.

<Steps>
  <Step title="Откройте интерфейс подагентов">
    В Claude Code запустите:

    ```
    /agents
    ```
  </Step>

  <Step title="Создайте нового агента уровня пользователя">
    Выберите **Create new agent**, затем выберите **User-level**. Это сохранит подагента в `~/.claude/agents/`, чтобы он был доступен во всех ваших проектах.
  </Step>

  <Step title="Генерируйте с помощью Claude">
    Выберите **Generate with Claude**. Когда будет предложено, опишите подагента:

    ```
    A code improvement agent that scans files and suggests improvements
    for readability, performance, and best practices. It should explain
    each issue, show the current code, and provide an improved version.
    ```

    Claude генерирует системное приглашение и конфигурацию. Нажмите `e`, чтобы открыть его в редакторе, если вы хотите его настроить.
  </Step>

  <Step title="Выберите инструменты">
    Для проверяющего, доступного только для чтения, отмените выбор всего, кроме **Read-only tools**. Если вы оставите все инструменты выбранными, подагент наследует все инструменты, доступные основному разговору.
  </Step>

  <Step title="Выберите модель">
    Выберите, какую модель использует подагент. Для этого примера агента выберите **Sonnet**, который балансирует возможности и скорость для анализа паттернов кода.
  </Step>

  <Step title="Выберите цвет">
    Выберите цвет фона для подагента. Это помогает вам определить, какой подагент работает в интерфейсе.
  </Step>

  <Step title="Сохраните и попробуйте">
    Сохраните подагента. Он доступен немедленно (перезагрузка не требуется). Попробуйте:

    ```
    Use the code-improver agent to suggest improvements in this project
    ```

    Claude делегирует вашему новому подагенту, который сканирует кодовую базу и возвращает предложения по улучшению.
  </Step>
</Steps>

Теперь у вас есть подагент, который вы можете использовать в любом проекте на вашей машине для анализа кодовых баз и предложения улучшений.

Вы также можете создавать подагентов вручную как файлы Markdown, определять их через флаги CLI или распространять их через плагины. В следующих разделах рассматриваются все параметры конфигурации.

## Настройка подагентов

### Используйте команду /agents

Команда `/agents` предоставляет интерактивный интерфейс для управления подагентами. Запустите `/agents`, чтобы:

* Просмотреть все доступные подагенты (встроенные, пользовательские, проектные и из плагинов)
* Создавать новых подагентов с помощью управляемой установки или генерации Claude
* Редактировать существующую конфигурацию подагента и доступ к инструментам
* Удалять пользовательских подагентов
* Видеть, какие подагенты активны при наличии дубликатов

Это рекомендуемый способ создания и управления подагентами. Для ручного создания или автоматизации вы также можете добавлять файлы подагентов напрямую.

### Выберите область подагента

Подагенты — это файлы Markdown с YAML frontmatter. Сохраняйте их в разных местах в зависимости от области. Когда несколько подагентов имеют одно и то же имя, выигрывает местоположение с более высоким приоритетом.

| Местоположение               | Область            | Приоритет      | Как создать                            |
| :--------------------------- | :----------------- | :------------- | :------------------------------------- |
| Флаг CLI `--agents`          | Текущая сессия     | 1 (наивысший)  | Передайте JSON при запуске Claude Code |
| `.claude/agents/`            | Текущий проект     | 2              | Интерактивно или вручную               |
| `~/.claude/agents/`          | Все ваши проекты   | 3              | Интерактивно или вручную               |
| Директория `agents/` плагина | Где плагин включён | 4 (наименьший) | Установлено с [плагинами](/ru/plugins) |

**Подагенты проекта** (`.claude/agents/`) идеальны для подагентов, специфичных для кодовой базы. Проверьте их в контроль версий, чтобы ваша команда могла использовать и улучшать их совместно.

**Подагенты пользователя** (`~/.claude/agents/`) — это личные подагенты, доступные во всех ваших проектах.

**Подагенты, определённые через CLI**, передаются как JSON при запуске Claude Code. Они существуют только для этой сессии и не сохраняются на диск, что делает их полезными для быстрого тестирования или скриптов автоматизации:

```bash  theme={null}
claude --agents '{
  "code-reviewer": {
    "description": "Expert code reviewer. Use proactively after code changes.",
    "prompt": "You are a senior code reviewer. Focus on code quality, security, and best practices.",
    "tools": ["Read", "Grep", "Glob", "Bash"],
    "model": "sonnet"
  }
}'
```

Флаг `--agents` принимает JSON с теми же полями, что и [frontmatter](#supported-frontmatter-fields). Используйте `prompt` для системного приглашения (эквивалент тела markdown в файловых подагентах). Полный формат JSON см. в [справочнике CLI](/ru/cli-reference#agents-flag-format).

**Подагенты плагина** поступают из [плагинов](/ru/plugins), которые вы установили. Они появляются в `/agents` рядом с вашими пользовательскими подагентами. Подробности о создании подагентов плагина см. в [справочнике компонентов плагина](/ru/plugins-reference#agents).

### Напишите файлы подагентов

Файлы подагентов используют YAML frontmatter для конфигурации, за которым следует системное приглашение в Markdown:

<Note>
  Подагенты загружаются при запуске сессии. Если вы создаёте подагента, вручную добавляя файл, перезагрузите сессию или используйте `/agents` для немедленной загрузки.
</Note>

```markdown  theme={null}
---
name: code-reviewer
description: Reviews code for quality and best practices
tools: Read, Glob, Grep
model: sonnet
---

You are a code reviewer. When invoked, analyze the code and provide
specific, actionable feedback on quality, security, and best practices.
```

Frontmatter определяет метаданные и конфигурацию подагента. Тело становится системным приглашением, которое направляет поведение подагента. Подагенты получают только это системное приглашение (плюс основные детали окружения, такие как рабочая директория), а не полное системное приглашение Claude Code.

#### Поддерживаемые поля frontmatter

Следующие поля можно использовать в YAML frontmatter. Требуются только `name` и `description`.

| Поле              | Требуется | Описание                                                                                                                                                                                                     |
| :---------------- | :-------- | :----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `name`            | Да        | Уникальный идентификатор, используя строчные буквы и дефисы                                                                                                                                                  |
| `description`     | Да        | Когда Claude должен делегировать этому подагенту                                                                                                                                                             |
| `tools`           | Нет       | [Инструменты](#available-tools), которые может использовать подагент. Наследует все инструменты, если опущено                                                                                                |
| `disallowedTools` | Нет       | Инструменты для запрета, удалённые из унаследованного или указанного списка                                                                                                                                  |
| `model`           | Нет       | [Модель](#choose-a-model) для использования: `sonnet`, `opus`, `haiku` или `inherit`. По умолчанию `sonnet`                                                                                                  |
| `permissionMode`  | Нет       | [Режим разрешений](#permission-modes): `default`, `acceptEdits`, `dontAsk`, `bypassPermissions` или `plan`                                                                                                   |
| `skills`          | Нет       | [Навыки](/ru/skills) для загрузки в контекст подагента при запуске. Полное содержимое навыка вводится, а не просто становится доступным для вызова. Подагенты не наследуют навыки из родительского разговора |
| `hooks`           | Нет       | [Хуки жизненного цикла](#define-hooks-for-subagents), ограниченные этим подагентом                                                                                                                           |

### Выберите модель

Поле `model` контролирует, какую [AI модель](/ru/model-config) использует подагент:

* **Псевдоним модели**: Используйте один из доступных псевдонимов: `sonnet`, `opus` или `haiku`
* **inherit**: Используйте ту же модель, что и основной разговор (полезно для согласованности)
* **Опущено**: Если не указано, использует модель по умолчанию, настроенную для подагентов (`sonnet`)

### Контролируйте возможности подагента

Вы можете контролировать, что могут делать подагенты, через доступ к инструментам, режимы разрешений и условные правила.

#### Доступные инструменты

Подагенты могут использовать любой из [внутренних инструментов](/ru/settings#tools-available-to-claude) Claude Code. По умолчанию подагенты наследуют все инструменты из основного разговора, включая инструменты MCP.

Чтобы ограничить инструменты, используйте поле `tools` (список разрешений) или поле `disallowedTools` (список запретов):

```yaml  theme={null}
---
name: safe-researcher
description: Research agent with restricted capabilities
tools: Read, Grep, Glob, Bash
disallowedTools: Write, Edit
---
```

#### Режимы разрешений

Поле `permissionMode` контролирует, как подагент обрабатывает запросы разрешений. Подагенты наследуют контекст разрешений из основного разговора, но могут переопределить режим.

| Режим               | Поведение                                                                                  |
| :------------------ | :----------------------------------------------------------------------------------------- |
| `default`           | Стандартная проверка разрешений с подсказками                                              |
| `acceptEdits`       | Автоматически принимать редактирование файлов                                              |
| `dontAsk`           | Автоматически отклонять запросы разрешений (явно разрешённые инструменты всё ещё работают) |
| `bypassPermissions` | Пропустить все проверки разрешений                                                         |
| `plan`              | Режим планирования (исследование только для чтения)                                        |

<Warning>
  Используйте `bypassPermissions` с осторожностью. Это пропускает все проверки разрешений, позволяя подагенту выполнять любую операцию без одобрения.
</Warning>

Если родитель использует `bypassPermissions`, это имеет приоритет и не может быть переопределено.

#### Предварительно загружайте навыки в подагентов

Используйте поле `skills` для внедрения содержимого навыка в контекст подагента при запуске. Это даёт подагенту знания в области без необходимости обнаруживать и загружать навыки во время выполнения.

```yaml  theme={null}
---
name: api-developer
description: Implement API endpoints following team conventions
skills:
  - api-conventions
  - error-handling-patterns
---

Implement API endpoints. Follow the conventions and patterns from the preloaded skills.
```

Полное содержимое каждого навыка вводится в контекст подагента, а не просто становится доступным для вызова. Подагенты не наследуют навыки из родительского разговора; вы должны перечислить их явно.

<Note>
  Это противоположно [запуску навыка в подагенте](/ru/skills#run-skills-in-a-subagent). С `skills` в подагенте подагент контролирует системное приглашение и загружает содержимое навыка. С `context: fork` в навыке содержимое навыка вводится в агента, который вы указываете. Оба используют одну и ту же базовую систему.
</Note>

#### Условные правила с хуками

Для более динамического контроля использования инструментов используйте хуки `PreToolUse` для проверки операций перед их выполнением. Это полезно, когда вам нужно разрешить некоторые операции инструмента, блокируя другие.

Этот пример создаёт подагента, который разрешает только запросы к базе данных только для чтения. Хук `PreToolUse` запускает скрипт, указанный в `command`, перед каждой командой Bash:

```yaml  theme={null}
---
name: db-reader
description: Execute read-only database queries
tools: Bash
hooks:
  PreToolUse:
    - matcher: "Bash"
      hooks:
        - type: command
          command: "./scripts/validate-readonly-query.sh"
---
```

Claude Code [передаёт входные данные хука как JSON](/ru/hooks#pretooluse-input) через stdin командам хука. Скрипт проверки читает этот JSON, извлекает команду Bash и [выходит с кодом 2](/ru/hooks#exit-code-2-behavior) для блокирования операций записи:

```bash  theme={null}
#!/bin/bash
# ./scripts/validate-readonly-query.sh

INPUT=$(cat)
COMMAND=$(echo "$INPUT" | jq -r '.tool_input.command // empty')

# Block SQL write operations (case-insensitive)
if echo "$COMMAND" | grep -iE '\b(INSERT|UPDATE|DELETE|DROP|CREATE|ALTER|TRUNCATE)\b' > /dev/null; then
  echo "Blocked: Only SELECT queries are allowed" >&2
  exit 2
fi

exit 0
```

Полную схему входных данных см. в [Hook input](/ru/hooks#pretooluse-input) и коды выхода см. в [exit codes](/ru/hooks#simple-exit-code) для того, как коды выхода влияют на поведение.

#### Отключите конкретные подагенты

Вы можете предотвратить использование Claude конкретных подагентов, добавив их в массив `deny` в ваших [параметрах](/ru/settings#permission-settings). Используйте формат `Task(subagent-name)`, где `subagent-name` соответствует полю name подагента.

```json  theme={null}
{
  "permissions": {
    "deny": ["Task(Explore)", "Task(my-custom-agent)"]
  }
}
```

Это работает как для встроенных, так и для пользовательских подагентов. Вы также можете использовать флаг CLI `--disallowedTools`:

```bash  theme={null}
claude --disallowedTools "Task(Explore)"
```

Подробнее см. в [документации IAM](/ru/iam#tool-specific-permission-rules).

### Определите хуки для подагентов

Подагенты могут определять [хуки](/ru/hooks), которые запускаются во время жизненного цикла подагента. Есть два способа настройки хуков:

1. **В frontmatter подагента**: Определите хуки, которые запускаются только во время активности этого подагента
2. **В `settings.json`**: Определите хуки, которые запускаются в основной сессии при запуске или остановке подагентов

#### Хуки в frontmatter подагента

Определите хуки непосредственно в файле markdown подагента. Эти хуки запускаются только во время активности этого конкретного подагента и очищаются при его завершении.

| Событие       | Входные данные Matcher | Когда это срабатывает                       |
| :------------ | :--------------------- | :------------------------------------------ |
| `PreToolUse`  | Имя инструмента        | Перед использованием подагентом инструмента |
| `PostToolUse` | Имя инструмента        | После использования подагентом инструмента  |
| `Stop`        | (нет)                  | Когда подагент завершает работу             |

Этот пример проверяет команды Bash с помощью хука `PreToolUse` и запускает линтер после редактирования файлов с помощью `PostToolUse`:

```yaml  theme={null}
---
name: code-reviewer
description: Review code changes with automatic linting
hooks:
  PreToolUse:
    - matcher: "Bash"
      hooks:
        - type: command
          command: "./scripts/validate-command.sh $TOOL_INPUT"
  PostToolUse:
    - matcher: "Edit|Write"
      hooks:
        - type: command
          command: "./scripts/run-linter.sh"
---
```

Хуки `Stop` в frontmatter автоматически преобразуются в события `SubagentStop`.

#### Хуки уровня проекта для событий подагента

Настройте хуки в `settings.json`, которые реагируют на события жизненного цикла подагента в основной сессии. Используйте поле `matcher` для нацеливания на конкретные типы агентов по имени.

| Событие         | Входные данные Matcher | Когда это срабатывает              |
| :-------------- | :--------------------- | :--------------------------------- |
| `SubagentStart` | Имя типа агента        | Когда подагент начинает выполнение |
| `SubagentStop`  | Имя типа агента        | Когда подагент завершает работу    |

Этот пример запускает скрипты установки и очистки только при запуске и остановке подагента `db-agent`:

```json  theme={null}
{
  "hooks": {
    "SubagentStart": [
      {
        "matcher": "db-agent",
        "hooks": [
          { "type": "command", "command": "./scripts/setup-db-connection.sh" }
        ]
      }
    ],
    "SubagentStop": [
      {
        "matcher": "db-agent",
        "hooks": [
          { "type": "command", "command": "./scripts/cleanup-db-connection.sh" }
        ]
      }
    ]
  }
}
```

Полный формат конфигурации хуков см. в [Hooks](/ru/hooks).

## Работа с подагентами

### Поймите автоматическую делегацию

Claude автоматически делегирует задачи на основе описания задачи в вашем запросе, поля `description` в конфигурациях подагентов и текущего контекста. Чтобы поощрить активную делегацию, включите фразы вроде "use proactively" в поле description вашего подагента.

Вы также можете явно запросить конкретного подагента:

```
Use the test-runner subagent to fix failing tests
Have the code-reviewer subagent look at my recent changes
```

### Запускайте подагентов на переднем плане или в фоне

Подагенты могут работать на переднем плане (блокирующий) или в фоне (одновременно):

* **Подагенты переднего плана** блокируют основной разговор до завершения. Запросы разрешений и уточняющие вопросы (такие как [`AskUserQuestion`](/ru/settings#tools-available-to-claude)) передаются вам.
* **Подагенты фона** работают одновременно, пока вы продолжаете работать. Они наследуют разрешения родителя и автоматически отклоняют всё, что не предварительно одобрено. Если подагент фона нуждается в разрешении, которого у него нет, или нужно задать уточняющие вопросы, вызов инструмента не удаётся, но подагент продолжает работу. Инструменты MCP недоступны в подагентах фона.

Если подагент фона не удаётся из-за отсутствия разрешений, вы можете [возобновить его](#resume-subagents) на переднем плане, чтобы повторить попытку с интерактивными подсказками.

Claude решает, запускать ли подагентов на переднем плане или в фоне, на основе задачи. Вы также можете:

* Попросить Claude "run this in the background"
* Нажать **Ctrl+B**, чтобы отправить работающую задачу в фон

Чтобы отключить всю функциональность фоновых задач, установите переменную окружения `CLAUDE_CODE_DISABLE_BACKGROUND_TASKS` на `1`. См. [Переменные окружения](/ru/settings#environment-variables).

### Общие шаблоны

#### Изолируйте высокообъёмные операции

Одно из наиболее эффективных применений подагентов — изоляция операций, которые производят большой объём выходных данных. Запуск тестов, получение документации или обработка файлов журналов может потребить значительный контекст. Делегируя эти операции подагенту, подробный выход остаётся в контексте подагента, в то время как только соответствующее резюме возвращается в основной разговор.

```
Use a subagent to run the test suite and report only the failing tests with their error messages
```

#### Запустите параллельное исследование

Для независимых исследований порождайте несколько подагентов для одновременной работы:

```
Research the authentication, database, and API modules in parallel using separate subagents
```

Каждый подагент исследует свою область независимо, затем Claude синтезирует результаты. Это работает лучше всего, когда пути исследования не зависят друг от друга.

<Warning>
  Когда подагенты завершают работу, их результаты возвращаются в основной разговор. Запуск многих подагентов, каждый из которых возвращает подробные результаты, может потребить значительный контекст.
</Warning>

#### Цепочка подагентов

Для многошаговых рабочих процессов попросите Claude использовать подагентов последовательно. Каждый подагент завершает свою задачу и возвращает результаты Claude, который затем передаёт соответствующий контекст следующему подагенту.

```
Use the code-reviewer subagent to find performance issues, then use the optimizer subagent to fix them
```

### Выберите между подагентами и основным разговором

Используйте **основной разговор**, когда:

* Задача требует частого взаимодействия или итеративного уточнения
* Несколько фаз имеют значительный общий контекст (планирование → реализация → тестирование)
* Вы вносите быстрое, целевое изменение
* Задержка имеет значение. Подагенты начинают с нуля и могут потребовать время для сбора контекста

Используйте **подагентов**, когда:

* Задача производит подробный выход, который вам не нужен в основном контексте
* Вы хотите применить конкретные ограничения инструментов или разрешений
* Работа самодостаточна и может вернуть резюме

Вместо этого рассмотрите [Skills](/ru/skills), когда вы хотите переиспользуемые приглашения или рабочие процессы, которые работают в контексте основного разговора, а не в изолированном контексте подагента.

<Note>
  Подагенты не могут порождать других подагентов. Если ваш рабочий процесс требует вложенной делегации, используйте [Skills](/ru/skills) или [цепочку подагентов](#chain-subagents) из основного разговора.
</Note>

### Управляйте контекстом подагента

#### Возобновите подагентов

Каждый вызов подагента создаёт новый экземпляр со свежим контекстом. Чтобы продолжить работу существующего подагента вместо начала заново, попросите Claude возобновить его.

Возобновленные подагенты сохраняют полную историю разговора, включая все предыдущие вызовы инструментов, результаты и рассуждения. Подагент продолжает ровно с того места, где остановился, а не начинает заново.

Когда подагент завершает работу, Claude получает его ID агента. Чтобы возобновить подагента, попросите Claude продолжить предыдущую работу:

```
Use the code-reviewer subagent to review the authentication module
[Agent completes]

Continue that code review and now analyze the authorization logic
[Claude resumes the subagent with full context from previous conversation]
```

Вы также можете попросить Claude ID агента, если хотите явно на него ссылаться, или найти ID в файлах транскрипта в `~/.claude/projects/{project}/{sessionId}/subagents/`. Каждый транскрипт сохраняется как `agent-{agentId}.jsonl`.

Транскрипты подагентов сохраняются независимо от основного разговора:

* **Компактирование основного разговора**: Когда основной разговор компактируется, транскрипты подагентов не затрагиваются. Они сохраняются в отдельных файлах.
* **Сохранение сессии**: Транскрипты подагентов сохраняются в пределах их сессии. Вы можете [возобновить подагента](#resume-subagents) после перезагрузки Claude Code, возобновив ту же сессию.
* **Автоматическая очистка**: Транскрипты очищаются на основе параметра `cleanupPeriodDays` (по умолчанию: 30 дней).

#### Автоматическое компактирование

Подагенты поддерживают автоматическое компактирование, используя ту же логику, что и основной разговор. По умолчанию автоматическое компактирование срабатывает при приблизительно 95% ёмкости. Чтобы срабатывание компактирования произошло раньше, установите `CLAUDE_AUTOCOMPACT_PCT_OVERRIDE` на более низкий процент (например, `50`). Подробнее см. в [переменных окружения](/ru/settings#environment-variables).

События компактирования регистрируются в файлах транскриптов подагентов:

```json  theme={null}
{
  "type": "system",
  "subtype": "compact_boundary",
  "compactMetadata": {
    "trigger": "auto",
    "preTokens": 167189
  }
}
```

Значение `preTokens` показывает, сколько токенов было использовано перед компактированием.

## Примеры подагентов

Эти примеры демонстрируют эффективные шаблоны для создания подагентов. Используйте их как отправные точки или генерируйте настроенную версию с Claude.

<Tip>
  **Лучшие практики:**

  * **Разработайте сфокусированные подагенты:** каждый подагент должен превосходить в одной конкретной задаче
  * **Напишите подробные описания:** Claude использует описание, чтобы решить, когда делегировать
  * **Ограничьте доступ к инструментам:** предоставьте только необходимые разрешения для безопасности и сфокусированности
  * **Проверьте в контроль версий:** поделитесь подагентами проекта с вашей командой
</Tip>

### Проверяющий код

Подагент, доступный только для чтения, который проверяет код без его модификации. Этот пример показывает, как разработать сфокусированный подагент с ограниченным доступом к инструментам (без Edit или Write) и подробным приглашением, которое точно указывает, что искать и как форматировать выход.

```markdown  theme={null}
---
name: code-reviewer
description: Expert code review specialist. Proactively reviews code for quality, security, and maintainability. Use immediately after writing or modifying code.
tools: Read, Grep, Glob, Bash
model: inherit
---

You are a senior code reviewer ensuring high standards of code quality and security.

When invoked:
1. Run git diff to see recent changes
2. Focus on modified files
3. Begin review immediately

Review checklist:
- Code is clear and readable
- Functions and variables are well-named
- No duplicated code
- Proper error handling
- No exposed secrets or API keys
- Input validation implemented
- Good test coverage
- Performance considerations addressed

Provide feedback organized by priority:
- Critical issues (must fix)
- Warnings (should fix)
- Suggestions (consider improving)

Include specific examples of how to fix issues.
```

### Отладчик

Подагент, который может как анализировать, так и исправлять проблемы. В отличие от проверяющего кода, этот включает Edit, потому что исправление ошибок требует модификации кода. Приглашение предоставляет чёткий рабочий процесс от диагностики к проверке.

```markdown  theme={null}
---
name: debugger
description: Debugging specialist for errors, test failures, and unexpected behavior. Use proactively when encountering any issues.
tools: Read, Edit, Bash, Grep, Glob
---

You are an expert debugger specializing in root cause analysis.

When invoked:
1. Capture error message and stack trace
2. Identify reproduction steps
3. Isolate the failure location
4. Implement minimal fix
5. Verify solution works

Debugging process:
- Analyze error messages and logs
- Check recent code changes
- Form and test hypotheses
- Add strategic debug logging
- Inspect variable states

For each issue, provide:
- Root cause explanation
- Evidence supporting the diagnosis
- Specific code fix
- Testing approach
- Prevention recommendations

Focus on fixing the underlying issue, not the symptoms.
```

### Специалист по данным

Специализированный подагент для работы анализа данных. Этот пример показывает, как создавать подагентов для специализированных рабочих процессов вне типичных задач кодирования. Он явно устанавливает `model: sonnet` для более способного анализа.

```markdown  theme={null}
---
name: data-scientist
description: Data analysis expert for SQL queries, BigQuery operations, and data insights. Use proactively for data analysis tasks and queries.
tools: Bash, Read, Write
model: sonnet
---

You are a data scientist specializing in SQL and BigQuery analysis.

When invoked:
1. Understand the data analysis requirement
2. Write efficient SQL queries
3. Use BigQuery command line tools (bq) when appropriate
4. Analyze and summarize results
5. Present findings clearly

Key practices:
- Write optimized SQL queries with proper filters
- Use appropriate aggregations and joins
- Include comments explaining complex logic
- Format results for readability
- Provide data-driven recommendations

For each analysis:
- Explain the query approach
- Document any assumptions
- Highlight key findings
- Suggest next steps based on data

Always ensure queries are efficient and cost-effective.
```

### Валидатор запросов к базе данных

Подагент, который разрешает доступ Bash, но проверяет команды, чтобы разрешить только запросы SQL только для чтения. Этот пример показывает, как использовать хуки `PreToolUse` для условной проверки, когда вам нужен более тонкий контроль, чем предоставляет поле `tools`.

```markdown  theme={null}
---
name: db-reader
description: Execute read-only database queries. Use when analyzing data or generating reports.
tools: Bash
hooks:
  PreToolUse:
    - matcher: "Bash"
      hooks:
        - type: command
          command: "./scripts/validate-readonly-query.sh"
---

You are a database analyst with read-only access. Execute SELECT queries to answer questions about the data.

When asked to analyze data:
1. Identify which tables contain the relevant data
2. Write efficient SELECT queries with appropriate filters
3. Present results clearly with context

You cannot modify data. If asked to INSERT, UPDATE, DELETE, or modify schema, explain that you only have read access.
```

Claude Code [передаёт входные данные хука как JSON](/ru/hooks#pretooluse-input) через stdin командам хука. Скрипт проверки читает этот JSON, извлекает выполняемую команду и проверяет её против списка операций записи SQL. Если обнаружена операция записи, скрипт [выходит с кодом 2](/ru/hooks#exit-code-2-behavior) для блокирования выполнения и возвращает сообщение об ошибке Claude через stderr.

Создайте скрипт проверки в любом месте вашего проекта. Путь должен соответствовать полю `command` в конфигурации хука:

```bash  theme={null}
#!/bin/bash
# Blocks SQL write operations, allows SELECT queries

# Read JSON input from stdin
INPUT=$(cat)

# Extract the command field from tool_input using jq
COMMAND=$(echo "$INPUT" | jq -r '.tool_input.command // empty')

if [ -z "$COMMAND" ]; then
  exit 0
fi

# Block write operations (case-insensitive)
if echo "$COMMAND" | grep -iE '\b(INSERT|UPDATE|DELETE|DROP|CREATE|ALTER|TRUNCATE|REPLACE|MERGE)\b' > /dev/null; then
  echo "Blocked: Write operations not allowed. Use SELECT queries only." >&2
  exit 2
fi

exit 0
```

Сделайте скрипт исполняемым:

```bash  theme={null}
chmod +x ./scripts/validate-readonly-query.sh
```

Хук получает JSON через stdin с командой Bash в `tool_input.command`. Код выхода 2 блокирует операцию и передаёт сообщение об ошибке обратно Claude. Подробнее см. в [Hooks](/ru/hooks#simple-exit-code) для кодов выхода и [Hook input](/ru/hooks#pretooluse-input) для полной схемы входных данных.
