# Управление идентификацией и доступом

> Узнайте, как настроить аутентификацию пользователей, авторизацию и элементы управления доступом для Claude Code в вашей организации.

## Методы аутентификации

Настройка Claude Code требует доступа к моделям Anthropic. Для команд вы можете настроить доступ к Claude Code одним из следующих способов:

* [Claude for Teams или Enterprise](/ru/setup#for-teams-and-organizations) (рекомендуется)
* [Claude Console с командным выставлением счетов](/ru/setup#for-teams-and-organizations)
* [Amazon Bedrock](/ru/amazon-bedrock)
* [Google Vertex AI](/ru/google-vertex-ai)
* [Microsoft Foundry](/ru/microsoft-foundry)

### Claude for Teams или Enterprise (рекомендуется)

[Claude for Teams](https://claude.com/pricing#team-&-enterprise) и [Claude for Enterprise](https://anthropic.com/contact-sales) обеспечивают лучший опыт для организаций, использующих Claude Code. Члены команды получают доступ как к Claude Code, так и к Claude в веб-версии с централизованным выставлением счетов и управлением командой.

* **Claude for Teams**: План самообслуживания с функциями сотрудничества, инструментами администратора и управлением выставлением счетов. Лучше всего подходит для небольших команд.
* **Claude for Enterprise**: Добавляет SSO, захват домена, разрешения на основе ролей, API соответствия и управляемые параметры политики для конфигураций Claude Code на уровне организации. Лучше всего подходит для крупных организаций с требованиями безопасности и соответствия.

**Для настройки доступа к Claude Code:**

1. Подпишитесь на [Claude for Teams](https://claude.com/pricing#team-&-enterprise) или свяжитесь с отделом продаж для [Claude for Enterprise](https://anthropic.com/contact-sales)
2. Пригласите членов команды из панели администратора
3. Члены команды устанавливают Claude Code и входят со своими учетными записями Claude.ai

### Аутентификация Claude Console

Для организаций, которые предпочитают выставление счетов на основе API, вы можете настроить доступ через Claude Console.

**Для настройки доступа к Claude Code для вашей команды через Claude Console:**

1. Используйте существующую учетную запись Claude Console или создайте новую учетную запись Claude Console
2. Вы можете добавлять пользователей одним из следующих способов:
   * Массовое приглашение пользователей из Console (Console -> Settings -> Members -> Invite)
   * [Настройка SSO](https://support.claude.com/en/articles/13132885-setting-up-single-sign-on-sso)
3. При приглашении пользователей им нужна одна из следующих ролей:
   * Роль "Claude Code" означает, что пользователи могут создавать только ключи API Claude Code
   * Роль "Developer" означает, что пользователи могут создавать любой вид ключа API
4. Каждый приглашенный пользователь должен выполнить следующие шаги:
   * Принять приглашение Console
   * [Проверить системные требования](/ru/setup#system-requirements)
   * [Установить Claude Code](/ru/setup#installation)
   * Войти с учетными данными учетной записи Console

### Аутентификация поставщика облачных услуг

**Для настройки доступа к Claude Code для вашей команды через Bedrock, Vertex или Azure:**

1. Следуйте [документации Bedrock](/ru/amazon-bedrock), [документации Vertex](/ru/google-vertex-ai) или [документации Microsoft Foundry](/ru/microsoft-foundry)
2. Распределите переменные окружения и инструкции по созданию учетных данных облака среди ваших пользователей. Узнайте больше о том, как [управлять конфигурацией здесь](/ru/settings).
3. Пользователи могут [установить Claude Code](/ru/setup#installation)

## Контроль доступа и разрешения

Мы поддерживаем детальные разрешения, чтобы вы могли точно указать, что агенту разрешено делать (например, запускать тесты, запускать линтер) и что ему не разрешено делать (например, обновлять облачную инфраструктуру). Эти параметры разрешений можно проверить в системе контроля версий и распределить среди всех разработчиков в вашей организации, а также настроить отдельными разработчиками.

### Система разрешений

Claude Code использует многоуровневую систему разрешений для балансирования мощности и безопасности:

| Тип инструмента  | Пример                       | Требуется одобрение | Поведение "Да, не спрашивать снова"              |
| :--------------- | :--------------------------- | :------------------ | :----------------------------------------------- |
| Только чтение    | Чтение файлов, Grep          | Нет                 | Н/Д                                              |
| Команды Bash     | Выполнение оболочки          | Да                  | Постоянно для каждого каталога проекта и команды |
| Изменение файлов | Редактирование/запись файлов | Да                  | До конца сеанса                                  |

### Настройка разрешений

Вы можете просматривать и управлять разрешениями инструментов Claude Code с помощью `/permissions`. Этот интерфейс отображает все правила разрешений и файл settings.json, из которого они получены.

* Правила **Allow** позволяют Claude Code использовать указанный инструмент без ручного одобрения.
* Правила **Ask** запрашивают подтверждение всякий раз, когда Claude Code пытается использовать указанный инструмент.
* Правила **Deny** предотвращают использование Claude Code указанного инструмента.

Правила оцениваются по порядку: **deny → ask → allow**. Первое совпадающее правило побеждает, поэтому правила deny всегда имеют приоритет.

* **Дополнительные каталоги** расширяют доступ Claude к файлам в каталогах за пределами исходного рабочего каталога.
* **Режим по умолчанию** управляет поведением разрешений Claude при возникновении новых запросов.

Правила разрешений используют формат: `Tool` или `Tool(optional-specifier)`

Правило, которое является просто названием инструмента, соответствует любому использованию этого инструмента. Например, добавление `Bash` в список разрешений позволяет Claude Code использовать инструмент Bash без требования одобрения пользователя. Обратите внимание, что `Bash(*)` **не** соответствует всем командам Bash. Используйте `Bash` без скобок, чтобы соответствовать всем использованиям.

<Note>
  Для быстрого справочника по синтаксису правил разрешений, включая подстановочные знаки, см. [Синтаксис правил разрешений](/ru/settings#permission-rule-syntax) в документации параметров.
</Note>

#### Режимы разрешений

Claude Code поддерживает несколько режимов разрешений, которые можно установить как `defaultMode` в [файлах параметров](/ru/settings#settings-files):

| Режим               | Описание                                                                                                                                                          |
| :------------------ | :---------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `default`           | Стандартное поведение - запрашивает разрешение при первом использовании каждого инструмента                                                                       |
| `acceptEdits`       | Автоматически принимает разрешения на редактирование файлов для сеанса                                                                                            |
| `plan`              | Режим плана - Claude может анализировать, но не изменять файлы или выполнять команды                                                                              |
| `dontAsk`           | Автоматически отклоняет инструменты, если они не предварительно одобрены через `/permissions` или правила [`permissions.allow`](/ru/settings#permission-settings) |
| `bypassPermissions` | Пропускает все запросы разрешений (требует безопасной среды - см. предупреждение ниже)                                                                            |

#### Рабочие каталоги

По умолчанию Claude имеет доступ к файлам в каталоге, в котором он был запущен. Вы можете расширить этот доступ:

* **При запуске**: используйте аргумент CLI `--add-dir <path>`
* **Во время сеанса**: используйте команду слэша `/add-dir`
* **Постоянная конфигурация**: добавьте в `additionalDirectories` в [файлах параметров](/ru/settings#settings-files)

Файлы в дополнительных каталогах следуют тем же правилам разрешений, что и исходный рабочий каталог - они становятся читаемыми без запросов, и разрешения на редактирование файлов следуют текущему режиму разрешений.

#### Правила разрешений для конкретных инструментов

Некоторые инструменты поддерживают более детальные элементы управления разрешениями:

**Bash**

Правила разрешений Bash поддерживают как сопоставление префиксов с `:*`, так и сопоставление подстановочных знаков с `*`:

* `Bash(npm run build)` Соответствует точной команде Bash `npm run build`
* `Bash(npm run test:*)` Соответствует командам Bash, начинающимся с `npm run test`
* `Bash(npm *)` Соответствует любой команде, начинающейся с `npm ` (например, `npm install`, `npm run build`)
* `Bash(* install)` Соответствует любой команде, заканчивающейся на ` install` (например, `npm install`, `yarn install`)
* `Bash(git * main)` Соответствует командам типа `git checkout main`, `git merge main`

<Tip>
  Claude Code осведомлен об операторах оболочки (таких как `&&`), поэтому правило сопоставления префиксов типа `Bash(safe-cmd:*)` не даст ему разрешение на выполнение команды `safe-cmd && other-cmd`
</Tip>

<Warning>
  Важные ограничения шаблонов разрешений Bash:

  1. Подстановочный знак `:*` работает только в конце шаблона для сопоставления префиксов
  2. Подстановочный знак `*` может появляться в любой позиции и соответствует любой последовательности символов
  3. Шаблоны типа `Bash(curl http://github.com/:*)` можно обойти многими способами:
     * Опции перед URL: `curl -X GET http://github.com/...` не будут соответствовать
     * Другой протокол: `curl https://github.com/...` не будет соответствовать
     * Перенаправления: `curl -L http://bit.ly/xyz` (перенаправляет на github)
     * Переменные: `URL=http://github.com && curl $URL` не будут соответствовать
     * Дополнительные пробелы: `curl  http://github.com` не будут соответствовать

  Для более надежной фильтрации URL рассмотрите:

  * **Ограничить сетевые инструменты Bash**: используйте правила deny для блокировки `curl`, `wget` и аналогичных команд, затем используйте инструмент WebFetch с разрешением `WebFetch(domain:github.com)` для разрешенных доменов
  * **Использовать крючки PreToolUse**: реализуйте крючок, который проверяет URL в командах Bash и блокирует запрещенные домены
  * Инструктирование Claude Code о ваших разрешенных шаблонах curl через CLAUDE.md

  Обратите внимание, что использование только WebFetch не предотвращает сетевой доступ. Если Bash разрешен, Claude все еще может использовать `curl`, `wget` или другие инструменты для доступа к любому URL.
</Warning>

**Read & Edit**

Правила `Edit` применяются ко всем встроенным инструментам, которые редактируют файлы. Claude приложит максимум усилий для применения правил `Read` ко всем встроенным инструментам, которые читают файлы, таким как Grep и Glob.

Правила Read & Edit оба следуют спецификации [gitignore](https://git-scm.com/docs/gitignore) с четырьмя различными типами шаблонов:

| Шаблон              | Значение                                      | Пример                           | Соответствует                      |
| ------------------- | --------------------------------------------- | -------------------------------- | ---------------------------------- |
| `//path`            | **Абсолютный** путь от корня файловой системы | `Read(//Users/alice/secrets/**)` | `/Users/alice/secrets/**`          |
| `~/path`            | Путь от **домашнего** каталога                | `Read(~/Documents/*.pdf)`        | `/Users/alice/Documents/*.pdf`     |
| `/path`             | Путь **относительно файла параметров**        | `Edit(/src/**/*.ts)`             | `<settings file path>/src/**/*.ts` |
| `path` или `./path` | Путь **относительно текущего каталога**       | `Read(*.env)`                    | `<cwd>/*.env`                      |

<Warning>
  Шаблон типа `/Users/alice/file` НЕ является абсолютным путем - он относителен к вашему файлу параметров! Используйте `//Users/alice/file` для абсолютных путей.
</Warning>

* `Edit(/docs/**)` - Редактирование в `<project>/docs/` (НЕ `/docs/`!)
* `Read(~/.zshrc)` - Чтение `.zshrc` вашего домашнего каталога
* `Edit(//tmp/scratch.txt)` - Редактирование абсолютного пути `/tmp/scratch.txt`
* `Read(src/**)` - Чтение из `<current-directory>/src/`

**WebFetch**

* `WebFetch(domain:example.com)` Соответствует запросам выборки к example.com

**MCP**

* `mcp__puppeteer` Соответствует любому инструменту, предоставленному сервером `puppeteer` (имя настроено в Claude Code)
* `mcp__puppeteer__*` Синтаксис подстановочных знаков, который также соответствует всем инструментам с сервера `puppeteer`
* `mcp__puppeteer__puppeteer_navigate` Соответствует инструменту `puppeteer_navigate`, предоставленному сервером `puppeteer`

**Task (Subagents)**

Используйте правила `Task(AgentName)` для управления тем, какие [подагенты](/ru/sub-agents) может использовать Claude:

* `Task(Explore)` Соответствует подагенту Explore
* `Task(Plan)` Соответствует подагенту Plan
* `Task(Verify)` Соответствует подагенту Verify

Добавьте эти правила в массив `deny` в ваших [параметрах](/ru/settings#permission-settings) или используйте флаг CLI `--disallowedTools` для отключения конкретных агентов. Например, чтобы отключить агента Explore:

```json  theme={null}
{
  "permissions": {
    "deny": ["Task(Explore)"]
  }
}
```

### Дополнительный контроль разрешений с помощью крючков

[Крючки Claude Code](/ru/hooks-guide) предоставляют способ регистрации пользовательских команд оболочки для выполнения оценки разрешений во время выполнения. Когда Claude Code выполняет вызов инструмента, крючки PreToolUse запускаются перед системой разрешений, и выходные данные крючка могут определить, одобрить или отклонить вызов инструмента вместо системы разрешений.

### Управляемые параметры

Для организаций, которым требуется централизованный контроль над конфигурацией Claude Code, администраторы могут развертывать файлы `managed-settings.json` в [системные каталоги](/ru/settings#settings-files). Эти файлы политики следуют тому же формату, что и обычные файлы параметров, и не могут быть переопределены пользовательскими или проектными параметрами.

### Приоритет параметров

Когда существуют несколько источников параметров, они применяются в следующем порядке (от наивысшего к наименьшему приоритету):

1. Управляемые параметры (`managed-settings.json`)
2. Аргументы командной строки
3. Локальные параметры проекта (`.claude/settings.local.json`)
4. Общие параметры проекта (`.claude/settings.json`)
5. Параметры пользователя (`~/.claude/settings.json`)

Эта иерархия гарантирует, что организационные политики всегда применяются, при этом обеспечивая гибкость на уровне проекта и пользователя, где это уместно.

## Управление учетными данными

Claude Code безопасно управляет вашими учетными данными аутентификации:

* **Место хранения**: На macOS ключи API, токены OAuth и другие учетные данные хранятся в зашифрованной цепочке ключей macOS.
* **Поддерживаемые типы аутентификации**: учетные данные Claude.ai, учетные данные API Claude, Azure Auth, Bedrock Auth и Vertex Auth.
* **Пользовательские скрипты учетных данных**: параметр [`apiKeyHelper`](/ru/settings#available-settings) можно настроить для запуска скрипта оболочки, который возвращает ключ API.
* **Интервалы обновления**: по умолчанию `apiKeyHelper` вызывается через 5 минут или при ответе HTTP 401. Установите переменную окружения `CLAUDE_CODE_API_KEY_HELPER_TTL_MS` для пользовательских интервалов обновления.
