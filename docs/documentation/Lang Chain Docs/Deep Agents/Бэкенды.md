# Бэкенды

> Выберите и настройте файловые системы для агентов Deep Agent. Вы можете указать маршруты к различным системам, реализовать виртуальные файловые системы и применять политики.

Глубокие агенты предоставляют агенту доступ к файловой системе через такие инструменты, как `ls`, `read_file`, `write_file`, `edit_file`, `glob` и `grep`. Эти инструменты работают через подключаемый бэкэнд.

```тема русалки={null}
график ТБ
    Инструменты[Инструменты файловой системы] --> Бэкенд[Бэкенд]

    Backend --> State[State]
    Backend --> Disk[Filesystem]
    Backend --> Store[Store]
    Backend --> Composite[Composite]
    Бэкенд --> Пользовательский[Пользовательский]

    Композитный --> Маршрутизатор{Маршруты}
    Состояние маршрутизатора
    Маршрутизатор --> Диск
    Маршрутизатор --> Магазин
```

На этой странице объясняется, как [выбрать бэкенд](#specify-a-backend), [направлять разные пути к разным бэкендам](#route-to-different-backends), [реализовать собственную виртуальную файловую систему](#use-a-virtual-filesystem) (например, S3 или Postgres), [добавить хуки политик](#add-policy-hooks) и [соответствовать протоколу бэкенда](#protocol-reference).

## Быстрый старт

Вот несколько готовых бэкэндов файловых систем, которые вы можете быстро использовать с вашим глубоким агентом:

| Встроенная серверная часть                                                       | Описание                                                                                                                                                                                                                                                                                                                           |
| -------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| [По умолчанию](#statebackend-ephemeral)                                          | `agent = create_deep_agent()` <br /> Временное состояние. Файловая система по умолчанию для агента хранится в состоянии `langgraph`. Обратите внимание, что эта файловая система сохраняется только *для одного потока*.                                                                                                           |
| [Сохранение доступа к локальной файловой системе](#filesystembackend-local-disk) | `agent = create_deep_agent(backend=FilesystemBackend(root_dir="/Users/nh/Desktop/"))` <br />Это предоставляет агенту глубокий доступ к файловой системе вашей локальной машины. Вы можете указать корневой каталог, к которому агент имеет доступ. Обратите внимание, что любой указанный `root_dir` должен быть абсолютным путем. |
| [Устойчивое хранилище (хранилище LangGraph)](#storebackend-langgraph-store)      | `agent = create_deep_agent(backend=lambda rt: StoreBackend(rt))` <br />Это дает агенту доступ к долговременному хранилищу, *сохраняющемуся между потоками*. Это отлично подходит для хранения долговременной памяти или инструкций, применимых к агенту в течение нескольких выполнений.                                           |
| [Composite](#compositebackend-router)                                            | По умолчанию временный, `/memories/` сохраняется. Бэкенд Composite максимально гибок. Вы можете указать разные маршруты в файловой системе, указывающие на разные бэкенды. См. пример маршрутизации Composite ниже.                                                                                                                |

## Встроенные бэкэнды

### StateBackend (временный)

```python theme={null}
# По умолчанию мы предоставляем StateBackend
agent = create_deep_agent()

# Под капотом, похоже,
from deepagents.backends import StateBackend

agent = create_deep_agent(
    backend=(lambda rt: StateBackend(rt)) # Обратите внимание, что инструменты получают доступ к State через runtime.state
)
```

**Как это работает:**

* Сохраняет файлы в состоянии агента LangGraph для текущего потока.
* Сохраняется при нескольких переключениях агентов в одном и том же потоке с помощью контрольных точек.

**Лучше всего подходит для:**

* Блокнот для записи промежуточных результатов агентом.
* Автоматическое удаление больших объемов выходных данных инструмента, которые агент затем может считывать по частям.

Обратите внимание, что эта серверная часть используется совместно агентом-супервизором и субагентами, и любые файлы, записанные субагентом, останутся в состоянии агента LangGraph.
Даже после завершения выполнения этого субагента, эти файлы останутся доступными для агента-супервайзера и других субагентов.

### Файловая система (локальный диск)

<Предупреждение>
  Эта серверная часть предоставляет агентам прямой доступ на чтение и запись в файловую систему.
  Использовать с осторожностью и только в соответствующих условиях.

  **Подходящие варианты использования:**

  * Локальные CLI для разработки (помощники в программировании, инструменты разработки)
  * Конвейеры CI/CD (см. вопросы безопасности ниже)

  **Неподходящие варианты использования:**

  * Для веб-серверов или HTTP API используйте `StateBackend`, `StoreBackend` или `SandboxBackend`.

  **Риски безопасности:**

  * Агенты могут читать любые доступные файлы, включая секреты (ключи API, учетные данные, файлы `.env`).
  * В сочетании с сетевыми инструментами, секретная информация может быть украдена посредством SSRF-атак.
  * Изменения в файле являются необратимыми и постоянными.

  **Рекомендуемые меры предосторожности:**

  1. Включите [промежуточное ПО для взаимодействия человека с системой обратной связи (HITL)](/oss/python/deepagents/human-in-the-loop) для проверки конфиденциальных операций.
  2. Исключите секретные данные из доступных путей файловой системы (особенно в системах CI/CD).
  3. Используйте `SandboxBackend` для производственных сред, требующих взаимодействия с файловой системой.
  4. **Всегда** используйте `virtual_mode=True` с `root_dir`, чтобы включить ограничения доступа на основе путей (блоки `..`, `~` и абсолютные пути за пределами корневого каталога).
     Обратите внимание, что значение по умолчанию (`virtual_mode=False`) не обеспечивает никакой безопасности, даже если задан параметр `root_dir`.
</Предупреждение>

```python theme={null}
from deepagents.backends import FilesystemBackend

agent = create_deep_agent(
    backend=FilesystemBackend(root_dir="."", virtual_mode=True)
)
```

**Как это работает:**

* Осуществляет чтение/запись реальных файлов в настраиваемом каталоге `root_dir`.
* При желании можно установить `virtual_mode=True`, чтобы изолировать и нормализовать пути в каталоге `root_dir`.
* Использует безопасное разрешение путей, предотвращает небезопасное перемещение символических ссылок, когда это возможно, может использовать ripgrep для быстрого поиска с помощью `grep`.

**Лучше всего подходит для:**

* Локальные проекты на вашем компьютере
* Песочницы CI
* Смонтированные постоянные тома

### StoreBackend (магазин LangGraph)

```python theme={null}
from langgraph.store.memory import InMemoryStore
from deepagents.backends import StoreBackend

agent = create_deep_agent(
    backend=(lambda rt: StoreBackend(rt)), # Обратите внимание, что инструменты обращаются к Store через runtime.store
    store=InMemoryStore()
)
```

**Как это работает:**

* Сохраняет файлы в хранилище LangGraph [`BaseStore`](https://reference.langchain.com/python/langgraph/store/#langgraph.store.base.BaseStore), предоставляемом средой выполнения, обеспечивая надежное хранение данных между потоками.

**Лучше всего подходит для:**

* Если вы уже используете настроенное хранилище LangGraph (например, Redis, Postgres или облачные реализации, работающие с [`BaseStore`](https://reference.langchain.com/python/langgraph/store/#langgraph.store.base.BaseStore)).
* При развертывании агента через LangSmith Deployment (хранилище автоматически создается для вашего агента).

### CompositeBackend (router)

```python theme={null}
from deepagents import create_deep_agent
from deepagents.backends import CompositeBackend, StateBackend, StoreBackend
from langgraph.store.memory import InMemoryStore

composite_backend = lambda rt: CompositeBackend(
    default=StateBackend(rt),
    маршруты={
        "/memories/": StoreBackend(rt),
    }
)

agent = create_deep_agent(
    backend=composite_backend,
    store=InMemoryStore() # Хранилище передается в create_deep_agent, а не в бэкенд
)
```

**Как это работает:**

* Направляет файловые операции в разные бэкэнды в зависимости от префикса пути.
* Сохраняет исходные префиксы путей в списках и результатах поиска.

**Лучше всего подходит для:**

* Если вы хотите предоставить своему агенту как временное, так и межпотоковое хранилище, `CompositeBackend` позволяет вам указать как `StateBackend`, так и `StoreBackend`.
* Когда у вас есть несколько источников информации, которые вы хотите предоставить своему агенту в рамках единой файловой системы.
  * Например, у вас есть долговременные воспоминания, хранящиеся в `/memories/` в одном хранилище, а также собственный бэкэнд, документация которого доступна по адресу `/docs/`.

## Укажите бэкэнд

* Передайте бэкенд в функцию `create_deep_agent(backend=...)`. Промежуточное ПО файловой системы использует его для всех инструментов.
* Вы можете сдать любой из следующих экзаменов:
  * Экземпляр, реализующий `BackendProtocol` (например, `FilesystemBackend(root_dir="."")`), или
  * Фабрика `BackendFactory = Callable[[ToolRuntime], BackendProtocol]` (для бэкендов, которым требуется среда выполнения, таких как `StateBackend` или `StoreBackend`).
* Если параметр опущен, по умолчанию используется `lambda rt: StateBackend(rt)`.

## Маршрутизация к различным бэкэндам

Перенаправляйте части пространства имен на разные бэкенды. Обычно используется для сохранения `/memories/*` и обеспечения временного хранения всего остального.

```python theme={null}
from deepagents import create_deep_agent
from deepagents.backends import CompositeBackend, StateBackend, FilesystemBackend

composite_backend = lambda rt: CompositeBackend(
    default=StateBackend(rt),
    маршруты={
        "/memories/": FilesystemBackend(root_dir="/deepagents/myagent", virtual_mode=True),
    },
)

agent = create_deep_agent(backend=composite_backend)
```

Поведение:

* `/workspace/plan.md` → `StateBackend` (временный)
* `/memories/agent.md` → `FilesystemBackend` в `/deepagents/myagent`
* Функции `ls`, `glob`, `grep` агрегируют результаты и отображают префиксы исходных путей.

Примечания:

* Более длинные префиксы имеют приоритет (например, маршрут `"/memories/projects/"` может переопределить `"/memories/"`).
* Для маршрутизации StoreBackend убедитесь, что среда выполнения агента предоставляет хранилище (`runtime.store`).

## Использование виртуальной файловой системы

Создайте собственную серверную часть для проецирования удаленной файловой системы или базы данных (например, S3 или Postgres) в пространство имен инструментов.

Рекомендации по дизайну:

* Пути являются абсолютными (`/x/y.txt`). Решите, как сопоставить их с ключами/строками вашего хранилища.
* Эффективно реализуйте функции `ls_info` и `glob_info` (список на стороне сервера, если доступен, в противном случае — локальный фильтр).
* Возвращает удобочитаемые для пользователя строки с ошибками для отсутствующих файлов или недопустимых шаблонов регулярных выражений.
* Для внешнего сохранения данных установите `files_update=None` в результатах; только бэкенды, находящиеся в состоянии, должны возвращать словарь `files_update`.

Схема в стиле S3:

```python theme={null}
from deepagents.backends.protocol import BackendProtocol, WriteResult, EditResult
from deepagents.backends.utils import FileInfo, GrepMatch

class S3Backend(BackendProtocol):
    def __init__(self, bucket: str, prefix: str = ""):
        self.bucket = bucket
        self.prefix = prefix.rstrip("/")

    def _key(self, path: str) -> str:
        return f"{self.prefix}{path}"

    def ls_info(self, path: str) -> list[FileInfo]:
        # Вывести список объектов по ключу _key(path); создать записи FileInfo (path, size, modified_at)
        ...

    def read(self, file_path: str, offset: int = 0, limit: int = 2000) -> str:
        # Получение объекта; возврат пронумерованного содержимого или строки ошибки.
        ...

    def grep_raw(self, pattern: str, path: str | None = None, glob: str | None = None) -> list[GrepMatch] | str:
        # При необходимости фильтрация на стороне сервера; в противном случае — вывод списка и сканирование содержимого.
        ...

    def glob_info(self, pattern: str, path: str = "/") -> list[FileInfo]:
        # Применить шаблон glob относительно пути ко всем ключам
        ...

    def write(self, file_path: str, content: str) -> WriteResult:
        # Обеспечить семантику только для создания файлов; return WriteResult(path=file_path, files_update=None)
        ...

    def edit(self, file_path: str, old_string: str, new_string: str, replace_all: bool = False) -> EditResult:
        # Чтение → замена (с соблюдением уникальности, в отличие от replace_all) → запись → возврат количества вхождений
        ...
```

Структура документа в стиле PostgreSQL:

* Таблица `files(path text primary key, content text, created_at timestamptz, modified_at timestamptz)`
* Сопоставьте операции инструмента с SQL:
  * `ls_info` использует `WHERE path LIKE $1 || '%'`
  * Фильтр `glob_info` в SQL или запрос с последующим применением шаблона в Python
  * Функция `grep_raw` может извлекать строки-кандидаты по расширению или времени последнего изменения, а затем сканировать строки.

## Добавить обработчики политик

Внедряйте корпоративные правила, создавая подклассы или обертки для бэкэнда.

Блоковая запись/редактирование под выбранными префиксами (подклассом):

```python theme={null}
from deepagents.backends.filesystem import FilesystemBackend
from deepagents.backends.protocol import WriteResult, EditResult

class GuardedBackend(FilesystemBackend):
    def __init__(self, *, deny_prefixes: list[str], **kwargs):
        super().__init__(**kwargs)
        self.deny_prefixes = [p if p.endswith("/") else p + "/" for p in deny_prefixes]

    def write(self, file_path: str, content: str) -> WriteResult:
        if any(file_path.startswith(p) for p in self.deny_prefixes):
            return WriteResult(error=f"Запись запрещена в пределах {file_path}")
        return super().write(file_path, content)

    def edit(self, file_path: str, old_string: str, new_string: str, replace_all: bool = False) -> EditResult:
        if any(file_path.startswith(p) for p in self.deny_prefixes):
            return EditResult(error="Редактирование запрещено в пределах {file_path}")
        return super().edit(file_path, old_string, new_string, replace_all)
```

Универсальная обертка (работает с любым бэкендом):

```python theme={null}
from deepagents.backends.protocol import BackendProtocol, WriteResult, EditResult
from deepagents.backends.utils import FileInfo, GrepMatch

class PolicyWrapper(BackendProtocol):
    def __init__(self, inner: BackendProtocol, deny_prefixes: list[str] | None = None):
        self.inner = inner
        self.deny_prefixes = [p if p.endswith("/") else p + "/" for p in (deny_prefixes or [])]

    def _deny(self, path: str) -> bool:
        return any(path.startswith(p) for p in self.deny_prefixes)

    def ls_info(self, path: str) -> list[FileInfo]:
        return self.inner.ls_info(path)
    def read(self, file_path: str, offset: int = 0, limit: int = 2000) -> str:
        return self.inner.read(file_path, offset=offset, limit=limit)
    def grep_raw(self, pattern: str, path: str | None = None, glob: str | None = None) -> list[GrepMatch] | str:
        return self.inner.grep_raw(pattern, path, glob)
    def glob_info(self, pattern: str, path: str = "/") -> list[FileInfo]:
        return self.inner.glob_info(pattern, path)
    def write(self, file_path: str, content: str) -> WriteResult:
        if self._deny(file_path):
            return WriteResult(error=f"Запись запрещена в пределах {file_path}")
        return self.inner.write(file_path, content)
    def edit(self, file_path: str, old_string: str, new_string: str, replace_all: bool = False) -> EditResult:
        if self._deny(file_path):
            return EditResult(error="Редактирование запрещено в пределах {file_path}")
        return self.inner.edit(file_path, old_string, new_string, replace_all)
```

## Справочник по протоколу

Бэкенды должны реализовывать протокол `BackendProtocol`.

Необходимые конечные точки:

* `ls_info(path: str) -> list[FileInfo]`
  * Возвращать записи, содержащие как минимум `path`. Включать `is_dir`, `size`, `modified_at`, если они доступны. Сортировать по `path` для получения детерминированного результата.
* `read(file_path: str, offset: int = 0, limit: int = 2000) -> str`
  * Возвращает пронумерованное содержимое. При отсутствии файла возвращает `"Ошибка: Файл '/x' не найден"".
* `grep_raw(pattern: str, path: Optional[str] = None, glob: Optional[str] = None) -> list[GrepMatch] | str`
  * Возвращает структурированные совпадения. В случае недопустимого регулярного выражения возвращает строку типа `"Недопустимый шаблон регулярного выражения: ..."` (не вызывает исключение).
* `glob_info(pattern: str, path: str = "/") -> list[FileInfo]`
  * Возвращает найденные файлы в виде записей `FileInfo` (пустой список, если файлов нет).
* `write(file_path: str, content: str) -> WriteResult`
  * Только для создания. В случае конфликта вернуть `WriteResult(error=...)`. В случае успеха установить `path`, а для бэкендов состояния установить `files_update={...}`; для внешних бэкендов следует использовать `files_update=None`.
* `edit(file_path: str, old_string: str, new_string: str, replace_all: bool = False) -> EditResult`
  * Обеспечивает уникальность `old_string`, если `replace_all=True`. Если строка не найдена, возвращает ошибку. В случае успеха включает `occurrences`.

Вспомогательные типы:

* `WriteResult(error, path, files_update)`
* `EditResult(error, path, files_update, occurrences)`
* `FileInfo` с полями: `path` (обязательно), опционально `is_dir`, `size`, `modified_at`.
* `GrepMatch` с полями: `path`, `line`, `text`.
