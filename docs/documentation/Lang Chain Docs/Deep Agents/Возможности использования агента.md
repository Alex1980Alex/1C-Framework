# Возможности использования агента

Мы рассматриваем `deepagents` как ["инструмент для работы с агентами"](/oss/python/concepts/products#agent-harnesses-like-the-deep-agents-sdk). Это тот же самый цикл вызова основных инструментов, что и в других фреймворках для работы с агентами, но со встроенными инструментами и возможностями.

```тема русалки={null}
график ТБ
    Агент[Глубокий агент] --> Инструменты[Инструменты файловой системы]
    Агент --> Список дел
    Агент --> Подсубъекты

    Инструменты --> Бэкенд [Бэкенд хранилища]
    Backend --> State[State]
    Backend --> Disk[Filesystem]
    Backend --> Store[Store]

    Подпрограмма --> |изолированная работа| Результат[Конечный результат]
    Результат --> Агент
```

На этой странице перечислены компоненты, из которых состоит жгут проводов агента.

## Доступ к файловой системе

Данный модуль предоставляет шесть инструментов для работы с файловой системой, делая файлы полноправными участниками среды агента:

| Инструмент   | Описание                                                                                                  |
| ------------ | --------------------------------------------------------------------------------------------------------- |
| `ls`         | Вывести список файлов в каталоге с метаданными (размер, время изменения)                                  |
| `read_file`  | Чтение содержимого файла с указанием номеров строк, поддержка смещения/ограничения для больших файлов     |
| `write_file` | Создать новые файлы                                                                                       |
| `edit_file`  | Выполнять точную замену строк в файлах (в глобальном режиме замены)                                       |
| `glob`       | Найти файлы, соответствующие шаблонам (например, `**/*.py`)                                               |
| `grep`       | Поиск содержимого файла с несколькими режимами вывода (только файлы, содержимое с контекстом или подсчет) |

## Вытеснение результатов использования крупных инструментов

[`FilesystemMiddleware`](/oss/python/deepagents/middleware) автоматически вытесняет результаты работы инструментов большого размера в файловую систему, когда они превышают пороговое значение, предотвращая насыщение контекстного окна.

**Как это работает:**

* Отслеживает размер результатов вызова инструмента (пороговое значение по умолчанию: 20 000 токенов, настраивается с помощью `tool_token_limit_before_evict`).
* При превышении лимита результат записывается с использованием настроенного бэкэнда.
* Заменяет результат работы инструмента усеченным предварительным просмотром и ссылкой на файл.
* Агент может при необходимости прочитать полный результат из файловой системы.

## Подключаемые бэкэнды для хранения данных

Данная система абстрагирует операции файловой системы за протоколом, позволяя использовать различные стратегии хранения данных для разных сценариев применения.

**Доступные бэкэнды:**

1. **`StateBackend`** — Временное хранилище данных в оперативной памяти.
   * Файлы хранятся в состоянии агента (контрольные точки сохраняются вместе с перепиской).
   * Сохраняется внутри одной ветки, но не между ветками.
   * Полезно для временных рабочих файлов

2. **`FilesystemBackend`** - Реальный доступ к файловой системе
   * Чтение/запись с фактического диска
   * Поддерживает виртуальный режим (в изолированной среде, доступной из корневого каталога)
   * Интегрируется с системными инструментами (ripgrep для grep)
   * Функции безопасности: проверка пути, ограничения размера, предотвращение создания символических ссылок.

3. **`StoreBackend`** — Постоянное хранилище данных для обмена данными между различными платформами.
   * Использует BaseStore из библиотеки LangGraph для обеспечения отказоустойчивости.
   * Пространство имен задано для `assistant_id`
   * Файлы сохраняются между разговорами
   * Полезно для долговременной памяти или формирования базы знаний.

4. **`CompositeBackend`** - Маршрутизация различных путей к различным бэкендам
   * Пример: `/` → StateBackend, `/memories/` → StoreBackend
   * Сопоставление по самому длинному префиксу для маршрутизации
   * Обеспечивает возможность использования гибридных стратегий хранения данных.

Подробности конфигурации и примеры см. в разделе [backends](/oss/python/deepagents/backends).

## Делегирование задач (субагентам)

Данная система позволяет главному агенту создавать временные «субагенты» для выполнения изолированных многоэтапных задач.

**Почему это полезно:**

* **Изоляция контекста** - Работа вспомогательного агента не засоряет контекст основного агента.
* **Параллельное выполнение** - Несколько подагентов могут работать одновременно.
* **Специализация** - Подгруппы агентов могут иметь различные инструменты/конфигурации.
* **Эффективность использования токенов** - Большой контекст подзадачи сжимается в один результат.

**Как это работает:**

* У главного агента есть инструмент «задача».
* При вызове создает новый экземпляр агента с собственным контекстом.
* Подпрограмма выполняет действия автономно до завершения.
* Возвращает главный агент единый итоговый отчет.
* Суб-агенты не имеют состояния (не могут отправлять несколько сообщений обратно).

**Субагент по умолчанию:**

* Автоматически доступен субагент "общего назначения"
* По умолчанию содержит инструменты файловой системы.
* Возможно расширение функционала за счет дополнительных инструментов/промежуточного программного обеспечения.

**Суб-агенты по индивидуальному заказу:**

* Определяйте специализированных субагентов с помощью специальных инструментов.
* Пример: рецензент кода, веб-исследователь, специалист по запуску тестов
* Настройка осуществляется с помощью параметра `subagents`

## Краткое изложение истории разговоров

Устройство автоматически сжимает историю старых переписок, когда использование токенов становится чрезмерным.

**Конфигурация:**

* Срабатывает при достижении 85% от `max_input_tokens` модели из ее [профиля модели](/oss/python/langchain/models#model-profiles)
* Сохраняет 10% токенов в качестве актуального контекста
* При недоступности профиля модели происходит переключение на триггер с 170 000 токенов / сохраняется 6 сообщений
* Более старые сообщения суммируются моделью.

**Почему это полезно:**

* Позволяет вести очень длинные диалоги, не достигая ограничений контекста.
* Сохраняет современный контекст, сжимая при этом древнюю историю.
* Прозрачно для агента (отображается как специальное системное сообщение)

## Ремонт болтающегося инструмента

Устройство исправляет историю сообщений, когда вызовы инструмента прерываются или отменяются до получения результатов.

**Проблема:**

* Агент запрашивает вызов инструмента: "Пожалуйста, запустите X"
* Вызов инструмента прерван (пользователь отменил запрос, произошла ошибка и т. д.)
* Агент видит `tool_call` в `AIMessage`, но не находит соответствующего `ToolMessage`.
* Это создаёт недопустимую последовательность сообщений.

**Решение:**

* Обнаруживает объекты `AIMessage` с `tool_calls`, для которых отсутствуют результаты.
* Создает синтетические ответы `ToolMessage`, указывающие на отмену вызова.
* Восстанавливает историю сообщений перед выполнением агента.

**Почему это полезно:**

* Предотвращает путаницу среди агентов из-за неполных цепочек сообщений.
* Корректно обрабатывает прерывания и ошибки
* Поддерживает связность разговора

## Отслеживание списка дел

Данная система предоставляет инструмент `write_todos`, который агенты могут использовать для ведения структурированного списка задач.

**Функции:**

* Отслеживайте выполнение нескольких задач по статусам (`'pending'`, `'in_progress'`, `'completed'`)
* Сохранялся в состоянии агента
* Помогает агенту организовать сложную многоэтапную работу
* Полезен для выполнения длительных задач и планирования.

## Человек в процессе

Система может приостанавливать выполнение агента при определенных вызовах инструментов, чтобы дать возможность человеку подтвердить или внести изменения. Эта функция активируется по желанию с помощью параметра `interrupt_on`.

**Конфигурация:**

* Передайте `interrupt_on` в `create_deep_agent`, указав соответствие имен инструментов конфигурациям прерываний.
* Пример: `interrupt_on={"edit_file": True}` приостанавливает редактирование перед каждым изменением
* Может предоставлять подтверждающие сообщения или изменять входные данные инструмента.

**Почему это полезно:**

* Защитные ворота для разрушительных операций
* Проверка пользователя перед выполнением ресурсоемких вызовов API
* Интерактивная отладка и руководство

## Кэширование с задержкой (антропическое)

Данная технология позволяет функции кэширования запросов Anthropic сократить избыточную обработку токенов.

**Как это работает:**

* Кэширует части подсказки, которые повторяются в разных ходах.
* Значительно снижает задержку и затраты при обработке длительных системных запросов.
* Автоматически пропускается для моделей, не относящихся к антропогенным.

**Почему это полезно:**

* Системные подсказки (особенно при работе с документацией по файловой системе) могут содержать более 5000 токенов.
* Эти действия повторяются каждый ход без кэширования.
* Кэширование обеспечивает примерно 10-кратное ускорение и снижение затрат.

## Потоковое вещание

В устройстве предусмотрена встроенная функция потоковой передачи данных для получения обновлений в реальном времени во время выполнения агента.

**Как это работает:**

* Использует потоковую систему LangGraph для отображения обновлений.
* Потоки данных как от основного агента, так и от субагентов.
* Запросы на использование инструментов, результаты работы инструментов и ответы LLM передаются в режиме реального времени.

**Почему это полезно:**

* Отображение вывода в прогрессивном режиме
* Проверка и отладка работы агентов и субагентов.
