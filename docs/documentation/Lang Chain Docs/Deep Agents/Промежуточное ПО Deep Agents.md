# Промежуточное ПО Deep Agents

> Разберитесь в промежуточном программном обеспечении, обеспечивающем работу агентов глубокого обучения.

Глубокие агенты построены на основе модульной архитектуры промежуточного программного обеспечения. Глубокие агенты имеют доступ к:

1. Инструмент планирования
2. Файловая система для хранения контекста и долговременной памяти.
3. Возможность создавать субагентов.

Каждая функция реализована как отдельное промежуточное ПО. При создании глубокого агента с помощью `create_deep_agent` мы автоматически подключаем к нему `TodoListMiddleware`, `FilesystemMiddleware` и `SubAgentMiddleware`.

```тема русалки={null}
график LR
    Agent[create_deep_agent] --> Todo[TodoList]
    Агент --> FS[Файловая система]
    Агент --> Суб[Субагент]

    Задачи --> Инструменты[Инструменты агента]
    FS --> Инструменты
    Подраздел --> Инструменты
```

Промежуточное ПО является компонуемым — вы можете добавить к агенту столько промежуточных программ, сколько необходимо. Вы можете использовать любое промежуточное ПО независимо.

В следующих разделах объясняется, что предоставляет каждое промежуточное программное обеспечение.

## Промежуточное ПО для списка дел

Планирование играет важнейшую роль в решении сложных проблем. Если вы недавно пользовались Claude Code, вы заметите, как он составляет список дел перед тем, как приступить к выполнению сложных, многоэтапных задач. Вы также заметите, как он может адаптировать и обновлять этот список дел на ходу по мере поступления новой информации.

`TodoListMiddleware` предоставляет вашему агенту инструмент, специально предназначенный для обновления этого списка дел. Перед выполнением многоэтапной задачи и во время её выполнения агенту предлагается использовать инструмент `write_todos`, чтобы отслеживать, что он делает и что ещё нужно сделать.

```python theme={null}
from langchain.agents import create_agent
from langchain.agents.middleware import TodoListMiddleware

# TodoListMiddleware включен по умолчанию в create_deep_agent
# Вы можете настроить это при создании собственного агента.
агент = create_agent(
    model="claude-sonnet-4-5-20250929",
    # Пользовательские инструкции по планированию можно добавить через промежуточное ПО.
    промежуточное ПО=[
        TodoListMiddleware(
            system_prompt="Используйте инструмент write_todos для..." # Необязательно: пользовательское дополнение к системной подсказке
        ),
    ],
)
```

## Промежуточное ПО для файловой системы

Разработка контекста — одна из главных задач при создании эффективных агентов. Это особенно сложно при использовании инструментов, возвращающих результаты переменной длины (например, `web_search` и RAG), поскольку длинные результаты инструментов могут быстро заполнить контекстное окно.

`FilesystemMiddleware` предоставляет четыре инструмента для взаимодействия как с кратковременной, так и с долговременной памятью:

* `ls`: Выводит список файлов в файловой системе
* `read_file`: Чтение всего файла или определенного количества строк из файла.
* `write_file`: Запись нового файла в файловую систему
* `edit_file`: Редактирование существующего файла в файловой системе

```python theme={null}
from langchain.agents import create_agent
from deepagents.middleware.filesystem import FilesystemMiddleware

# FilesystemMiddleware включен по умолчанию в create_deep_agent
# Вы можете настроить это при создании собственного агента.
агент = create_agent(
    model="claude-sonnet-4-5-20250929",
    промежуточное ПО=[
        FilesystemMiddleware(
            backend=None, # Необязательно: пользовательский бэкенд (по умолчанию StateBackend)
            system_prompt="Запись в файловую систему при...", # Дополнительное пользовательское дополнение к системной подсказке
            custom_tool_descriptions={
                "ls": "Используйте инструмент ls, когда...",
                "read_file": "Используйте инструмент read_file, чтобы..."
            } # Необязательно: Пользовательские описания для инструментов файловой системы
        ),
    ],
)
```

### Краткосрочная и долгосрочная файловая система

По умолчанию эти инструменты записывают данные в локальную файловую систему в состоянии вашего графа. Чтобы обеспечить постоянное хранение данных между потоками, настройте `CompositeBackend`, который направляет определенные пути (например, `/memories/`) в `StoreBackend`.

```python theme={null}
from langchain.agents import create_agent
from deepagents.middleware import FilesystemMiddleware
from deepagents.backends import CompositeBackend, StateBackend, StoreBackend
from langgraph.store.memory import InMemoryStore

store = InMemoryStore()

агент = create_agent(
    model="claude-sonnet-4-5-20250929",
    магазин=магазин,
    промежуточное ПО=[
        FilesystemMiddleware(
            backend=lambda rt: CompositeBackend(
                default=StateBackend(rt),
                routes={"/memories/": StoreBackend(rt)}
            ),
            custom_tool_descriptions={
                "ls": "Используйте инструмент ls, когда...",
                "read_file": "Используйте инструмент read_file, чтобы..."
            } # Необязательно: Пользовательские описания для инструментов файловой системы
        ),
    ],
)
```

При настройке `CompositeBackend` с `StoreBackend` для `/memories/`, все файлы с префиксом **/memories/** сохраняются в постоянном хранилище и остаются активными в разных потоках. Файлы без этого префикса остаются во временном хранилище состояния.

## Промежуточное ПО для субагентов

Передача задач субагентам изолирует контекст, сохраняя окно контекста основного (супервизорского) агента чистым, но при этом позволяя глубоко погрузиться в выполнение задачи.

Промежуточное программное обеспечение для субагентов позволяет назначать субагентов с помощью инструмента «задача».

```python theme={null}
from langchain.tools import tool
from langchain.agents import create_agent
from deepagents.middleware.subagents import SubAgentMiddleware


@инструмент
def get_weather(city: str) -> str:
    «Узнайте погоду в городе».
    return f"В городе {city} солнечная погода."

агент = create_agent(
    model="claude-sonnet-4-5-20250929",
    промежуточное ПО=[
        SubAgentMiddleware(
            default_model="claude-sonnet-4-5-20250929",
            default_tools=[],
            субагенты=[
                {
                    "имя": "погода",
                    «Описание»: «Этот субагент может получать информацию о погоде в городах».
                    "system_prompt": "Используйте инструмент get_weather, чтобы узнать погоду в городе."
                    "инструменты": [get_weather],
                    "model": "gpt-4.1",
                    "промежуточное ПО": [],
                }
            ],
        )
    ],
)
```

Вспомогательный агент определяется с помощью **имени**, **описания**, **системной подсказки** и **инструментов**. Вы также можете предоставить вспомогательному агенту пользовательскую **модель** или дополнительное **промежуточное ПО**. Это может быть особенно полезно, если вы хотите передать вспомогательному агенту дополнительный ключ состояния для совместного использования с основным агентом.

Для более сложных сценариев использования вы также можете предоставить собственный предварительно созданный граф LangGraph в качестве субагента.

```python theme={null}
from langchain.agents import create_agent
from deepagents.middleware.subagents import SubAgentMiddleware
from deepagents import CompiledSubAgent
from langgraph.graph import StateGraph

# Создание пользовательского графа LangGraph
def create_weather_graph():
    рабочий процесс = StateGraph(...)
    # Создайте свой собственный график
    return workflow.compile()

weather_graph = create_weather_graph()

# Оберните это в CompiledSubAgent
weather_subagent = CompiledSubAgent(
    name="погода",
    Описание: Этот субагент может получать информацию о погоде в городах.
    runnable=weather_graph
)

агент = create_agent(
    model="claude-sonnet-4-5-20250929",
    промежуточное ПО=[
        SubAgentMiddleware(
            default_model="claude-sonnet-4-5-20250929",
            default_tools=[],
            subagents=[weather_subagent],
        )
    ],
)
```

В дополнение к любым заданным пользователем субагентам, главный агент постоянно имеет доступ к «универсальному» субагенту. Этот субагент имеет те же инструкции, что и главный агент, и все инструменты, к которым он имеет доступ. Основная цель «универсального» субагента — изоляция контекста: главный агент может делегировать этому субагенту сложную задачу и получить в ответ лаконичный ответ без лишних вызовов промежуточных инструментов.
