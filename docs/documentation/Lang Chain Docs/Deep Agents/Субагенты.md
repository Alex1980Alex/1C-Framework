# Субагенты

> Узнайте, как использовать субагентов для делегирования работы и поддержания чистоты контекста.

Глубокие агенты могут создавать субагентов для делегирования работы. Вы можете указать пользовательских субагентов в параметре `subagents`. Субагенты полезны для [карантина контекста](https://www.dbreunig.com/2025/06/26/how-to-fix-your-context.html#context-quarantine) (поддержание чистоты контекста основного агента) и для предоставления специализированных инструкций.

```тема русалки={null}
график ТБ
    Главный [Главный агент] --> |инструмент задачи| Под [Подагент]

    Подраздел --> Исследование[Исследование]
    Подпрограмма --> Код[Код]
    Подраздел --> Генеральный[Генеральный]

    Исследование --> |изолированная работа| Результат [Окончательный результат]
    Код --> |изолированная работа| Результат
    Общий --> |изолированная работа| Результат

    Результат --> Главный
```

## Зачем использовать субагентов?

Вспомогательные агенты решают проблему **раздувания контекста**. Когда агенты используют инструменты с большими выходными данными (веб-поиск, чтение файлов, запросы к базам данных), контекстное окно быстро заполняется промежуточными результатами. Вспомогательные агенты изолируют эту детальную работу — основной агент получает только конечный результат, а не десятки вызовов инструментов, которые его создали.

**Когда следует использовать субагентов:**

* ✅ Многоэтапные задачи, которые могут загромоздить контекст основного агента.
* ✅ Специализированные области, требующие индивидуальных инструкций или инструментов
* ✅ Задачи, требующие различных возможностей модели
* ✅ Когда вы хотите, чтобы основной агент сосредоточился на координации высокого уровня

**Когда НЕ следует использовать субагентов:**

* ❌ Простые задачи, выполняемые в один шаг
* ❌ Когда необходимо поддерживать промежуточный контекст
* ❌ Когда накладные расходы превышают выгоды

## Конфигурация

`subagents` должен представлять собой список словарей или объектов `CompiledSubAgent`. Существует два типа:

### Субагент (на основе словаря)

В большинстве случаев субагентов следует определять как словари:

**Обязательные поля:**

<ParamField body="name" type="str" ​​required>
  Уникальный идентификатор субагента.
  Главный агент использует это имя при вызове инструмента `task()`.
  Имя субагента становится метаданными для `AIMessage` и для потоковой передачи, что помогает различать агентов.
</ParamField>

<ParamField body="description" type="str" ​​required>
  Чем занимается этот субагент. Будьте конкретны и ориентированы на действия. Главный агент использует это для принятия решения о том, когда делегировать задачи.
</ParamField>

<ParamField body="system_prompt" type="str" ​​required>
  Инструкции для субагента. Включите рекомендации по использованию инструмента и требования к формату вывода.
</ParamField>

<ParamField body="tools" type="list[Callable]" required>
  Инструменты, которые может использовать субагент. Ограничьтесь минимальным списком и включите только необходимое.
</ParamField>

**Необязательные поля:**

<ParamField body="model" type="str | BaseChatModel">
  Переопределите модель основного агента. Используйте формат `'provider:model-name'` (например, `'openai:gpt-4.1'`).
</ParamField>

<ParamField body="middleware" type="list[Middleware]">
  Дополнительное промежуточное ПО для настройки поведения, ведения журналов или ограничения скорости запросов.
</ParamField>

<ParamField body="interrupt_on" type="dict[str, bool]">
  Настройка участия человека в процессе разработки для конкретных инструментов. Требуется контрольная точка.
</ParamField>

### CompiledSubAgent

Для сложных рабочих процессов используйте предварительно созданный граф LangGraph:

<ParamField body="name" type="str" ​​required>
  Уникальный идентификатор субагента.
  Имя субагента становится метаданными для `AIMessage` и для потоковой передачи, что помогает различать агентов.
</ParamField>

<ParamField body="description" type="str" ​​required>
  Чем занимается этот субагент.
</ParamField>

<ParamField body="runnable" type="Runnable" required>
  Скомпилированный граф LangGraph (предварительно необходимо вызвать `.compile()`).
</ParamField>

## Использование субагента

```python theme={null}
импорт os
from typing import Literal
from tavily import TavilyClient
from deepagents import create_deep_agent

tavily_client = TavilyClient(api_key=os.environ["TAVILY_API_KEY"])

def internet_search(
    запрос: str,
    max_results: int = 5,
    тема: Буквальный ["общий", "новости", "финансы"] = "общий",
    include_raw_content: bool = False,
):
    """Выполнить поиск в интернете"""
    return tavily_client.search(
        запрос,
        max_results=max_results,
        include_raw_content=include_raw_content,
        тема=тема,
    )

research_subagent = {
    "имя": "научный сотрудник",
    «Описание»: «Используется для более глубокого изучения вопросов».
    "system_prompt": "Вы отличный исследователь",
    "инструменты": [поиск в интернете],
    "model": "openai:gpt-4.1", # Необязательное переопределение, по умолчанию используется основная модель агента
}
субагенты = [research_subagent]

agent = create_deep_agent(
    model="claude-sonnet-4-5-20250929",
    субагенты = субагенты
)
```

## Использование CompiledSubAgent

Для более сложных сценариев использования вы можете предоставить своих собственных субагентов.
Вы можете создать собственного субагента, используя функцию `create_agent` в LangChain, или создав собственный граф LangGraph с помощью [API для работы с графами](https://github.com/langchain-ai/docs/pull/).

Если вы создаете собственный граф LangGraph, убедитесь, что у графа есть [ключ состояния с именем `"messages"`](/oss/python/langgraph/quickstart#2-define-state):

```python theme={null}
from deepagents import create_deep_agent, CompiledSubAgent
from langchain.agents import create_agent

# Создание пользовательского графа агентов
custom_graph = create_agent(
    model=your_model,
    инструменты=специализированные_инструменты,
    prompt="Вы являетесь специалистом по анализу данных..."
)

# Используйте его в качестве пользовательского субагента
custom_subagent = CompiledSubAgent(
    name="data-analyzer",
    описание="Специализированный агент для решения сложных задач анализа данных"
    runnable=custom_graph
)

субагенты = [custom_subagent]

agent = create_deep_agent(
    model="claude-sonnet-4-5-20250929",
    инструменты=[поиск в интернете],
    system_prompt=research_instructions,
    субагенты = субагенты
)
```

## Потоковое вещание

При потоковой передаче информации о трассировке имена агентов доступны в метаданных как `lc_agent_name`.
При анализе информации, полученной в результате отслеживания, вы можете использовать эти метаданные, чтобы определить, от какого именно агента были получены данные.

В следующем примере создается подсистема агентов с именем `main-agent` и подсистема агентов с именем `research-agent`:

```python theme={null}
импорт os
from typing import Literal
from tavily import TavilyClient
from deepagents import create_deep_agent

tavily_client = TavilyClient(api_key=os.environ["TAVILY_API_KEY"])

def internet_search(
    запрос: str,
    max_results: int = 5,
    тема: Буквальный ["общий", "новости", "финансы"] = "общий",
    include_raw_content: bool = False,
):
    """Выполнить поиск в интернете"""
    return tavily_client.search(
        запрос,
        max_results=max_results,
        include_raw_content=include_raw_content,
        тема=тема,
    )

research_subagent = {
    "имя": "научный сотрудник",
    «Описание»: «Используется для более глубокого изучения вопросов».
    "system_prompt": "Вы отличный исследователь",
    "инструменты": [поиск в интернете],
    "model": "claude-sonnet-4-5-20250929", # Необязательное переопределение, по умолчанию используется основная модель агента
}
субагенты = [research_subagent]

agent = create_deep_agent(
    model="claude-sonnet-4-5-20250929",
    субагенты = субагенты,
    name="главный-агент"
)
```

При запуске ваших deepagents все запуски агентов, выполняемые subagent или deepagent, будут содержать имя агента в своих метаданных.
В этом случае субагент с именем «research-agent» будет иметь в метаданных любого связанного с ним запуска агента значение `{'lc_agent_name': 'research-agent'}`:

## Универсальный субагент

В дополнение к любым заданным пользователем субагентам, у глубинных агентов всегда есть доступ к субагенту «общего назначения». Этот субагент:

* Имеет ту же системную подсказку, что и основной агент.
* Имеет доступ ко всем тем же инструментам.
* Использует ту же модель (если не указано иное)

### Когда его использовать

Универсальный субагент идеально подходит для контекстной изоляции без необходимости специализации поведения. Основной агент может делегировать этому субагенту сложную многоэтапную задачу и получить в ответ лаконичный результат без лишних вызовов промежуточных инструментов.

<Card title="Example">
  Вместо того чтобы основной агент выполнял 10 веб-поисков и заполнял свой контекст результатами, он делегирует задачу универсальному субагенту: `task(name="general-purpose", task="Research quantum computing trends")`. Субагент выполняет все поиски внутри себя и возвращает только сводку.
</Карточка>

## Передовые методы

### Пишите понятные описания

Главный агент использует описания, чтобы решить, к какому субагенту обратиться. Будьте конкретны:

✅ **Хорошо:** «Анализирует финансовые данные и формирует инвестиционные прогнозы с указанием степени достоверности»

❌ **Плохо:** «Занимается финансами»

### Предоставляйте системным подсказкам подробную информацию

Включите конкретные указания по использованию инструментов и форматированию выходных данных:

```python theme={null}
research_subagent = {
    "имя": "научный сотрудник",
    «Описание»: «Проводит углубленное исследование с использованием веб-поиска и обобщает полученные результаты».
    "system_prompt": """Вы — дотошный исследователь. Ваша задача:

    1. Разбейте исследовательский вопрос на поисковые запросы.
    2. Используйте интернет-поиск для поиска соответствующей информации.
    3. Обобщить полученные результаты в исчерпывающем, но кратком резюме.
    4. При формулировании утверждений указывайте источники.

    Формат вывода:
    - Краткое содержание (2-3 абзаца)
    — Основные выводы (пункты)
    - Источники (с URL-адресами)

    Чтобы сохранить целостность контекста, ваш ответ должен содержать не более 500 слов.
    "инструменты": [поиск в интернете],
}
```

### Сокращение наборов инструментов

Предоставляйте субагентам только необходимые инструменты. Это повышает концентрацию внимания и безопасность:

```python theme={null}
# ✅ Плюсы: Целенаправленный набор инструментов
email_agent = {
    "имя": "отправитель электронного письма",
    "инструменты": [send_email, validate_email], # Только инструменты, связанные с электронной почтой
}

# ❌ Плохо: Слишком много инструментов
email_agent = {
    "имя": "отправитель электронного письма",
    "инструменты": [send_email, web_search, database_query, file_upload], # Нефокусированный
}
```

### Выбор моделей по задачам

Разные модели лучше справляются с разными задачами:

```python theme={null}
субагенты = [
    {
        "имя": "эксперт по контрактам",
        «Описание»: «Проверяет юридические документы и контракты».
        "system_prompt": "Вы являетесь экспертом в области юридической экспертизы...",
        "инструменты": [read_document, analyze_contract],
        "model": "claude-sonnet-4-5-20250929", # Большой контекст для длинных документов
    },
    {
        "имя": "финансовый аналитик",
        «Описание»: «Анализирует финансовые данные и рыночные тенденции».
        "system_prompt": "Вы — опытный финансовый аналитик...",
        "инструменты": [get_stock_price, analyze_fundamentals],
        "model": "openai:gpt-5", # Лучше для численного анализа
    },
]
```

### Возвращает краткие результаты

Поручите субагентам возвращать сводные данные, а не необработанные данные:

```python theme={null}
data_analyst = {
    "system_prompt": """Проанализировать данные и вернуть:
    1. Ключевые выводы (3-5 пунктов)
    2. Общий балл уверенности
    3. Рекомендуемые дальнейшие действия

    НЕ включать:
    - Исходные данные
    - Промежуточные вычисления
    - Подробные результаты работы инструмента

    Ответ должен быть объемом не более 300 слов.
}
```

## Распространенные шаблоны

### Множество специализированных субагентов

Создайте специализированных субагентов для различных областей:

```python theme={null}
from deepagents import create_deep_agent

субагенты = [
    {
        "name": "data-collector",
        "Описание": "Собирает необработанные данные из различных источников",
        "system_prompt": "Собрать исчерпывающие данные по теме",
        "инструменты": [web_search, api_call, database_query],
    },
    {
        "name": "data-analyzer",
        «Описание»: «Анализирует собранные данные для получения ценной информации».
        "system_prompt": "Анализ данных и извлечение ключевых выводов",
        "инструменты": [статистический_анализ],
    },
    {
        "имя": "составитель отчёта",
        «Описание»: «Составляет качественные отчеты на основе анализа».
        "system_prompt": "Создание профессиональных отчетов на основе аналитических данных",
        "инструменты": [формат_документа],
    },
]

agent = create_deep_agent(
    model="claude-sonnet-4-5-20250929",
    system_prompt="Вы координируете анализ данных и составление отчетов. Используйте субагентов для выполнения специализированных задач."
    субагенты = субагенты
)
```

**Рабочий процесс:**

1. Главный агент разрабатывает план высокого уровня.
2. Делегирует сбор данных сборщику данных.
3. Передает результаты анализатору данных.
4. Передает аналитические данные составителю отчета.
5. Формирует окончательный результат.

Каждый субагент работает в четком контексте, сосредоточенном исключительно на своей задаче.

## Поиск неисправностей

### Субагент не вызывается

**Проблема**: Главный агент пытается выполнить работу самостоятельно, вместо того чтобы делегировать её другим.

**Решения**:

1. **Уточните описания:**

   ```python theme={null}
   # ✅ Хорошо
   {"name": "специалист по исследованиям", "description": "Проводит углубленные исследования по конкретным темам с помощью веб-поиска. Используйте, когда вам нужна подробная информация, требующая нескольких поисковых запросов."}

   # ❌ Плохо
   {"name": "помощник", "description": "помогает с разными вещами"}
   ```

2. **Дать указание главному агенту делегировать:**

   ```python theme={null}
   agent = create_deep_agent(
       system_prompt="""...ваши инструкции...

       ВАЖНО: Для сложных задач делегируйте их своим субагентам, используя инструмент task().
       Это помогает поддерживать порядок в контексте и улучшает результаты."",
       субагенты=[...]
   )
   ```

### Контекст по-прежнему раздувается

**Проблема**: Контекст заполняется, несмотря на использование субагентов.

**Решения**:

1. **Дать указание субагенту предоставить краткие результаты:**

   ```python theme={null}
   system_prompt="""...

   ВАЖНО: Возвращайте только самое необходимое резюме.
   НЕ следует включать исходные данные, промежуточные результаты поиска или подробные выходные данные инструментов.
   Ваш ответ должен содержать менее 500 слов.
   ```

2. **Используйте файловую систему для больших объемов данных:**

   ```python theme={null}
   system_prompt="""Когда вы собираете большие объемы данных:
   1. Сохраните исходные данные в файл /data/raw_results.txt
   2. Обработка и анализ данных.
   3. Возвращать только сводку анализа.

   Это помогает сохранить контекст в чистоте."""
   ```

### Выбран не тот субагент

**Проблема**: Главный агент вызывает для выполнения задачи неподходящего субагента.

**Решение**: Четко разграничьте субагентов в описаниях:

```python theme={null}
субагенты = [
    {
        "имя": "быстрый исследователь",
        "Описание": "Для простых и быстрых исследовательских вопросов, требующих 1-2 поисковых запросов. Используйте, когда вам нужны основные факты или определения."
    },
    {
        "имя": "исследователь глубин",
        «Описание»: «Для сложных, углубленных исследований, требующих многократного поиска, синтеза и анализа. Используйте для составления исчерпывающих отчетов».
    }
]
```
