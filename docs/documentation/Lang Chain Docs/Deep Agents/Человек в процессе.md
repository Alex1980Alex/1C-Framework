# Человек в процессе

Узнайте, как настроить подтверждение доступа для выполнения операций с конфиденциальными инструментами.

Некоторые операции с инструментами могут быть конфиденциальными и требовать подтверждения пользователя перед выполнением. Глубокие агенты поддерживают рабочие процессы с участием человека благодаря возможностям прерывания LangGraph. Вы можете настроить, для каких инструментов требуется подтверждение, используя параметр `interrupt_on`.

```тема русалки={null}
график LR
    Агент[Агент] --> Проверка{Прерывание?}
    Проверить --> |нет| Выполнить[Выполнить]
    Проверить --> |да| Человек{Человек}

    Человек --> |одобрить| Выполнить
    Человек --> |редактировать| Выполнить
    Человек --> |отклонить| Отмена[Отмена]

    Выполнить --> Агент
    Отмена --> Агент
```

## Базовая конфигурация

Параметр `interrupt_on` принимает словарь, сопоставляющий имена инструментов с конфигурациями прерываний. Каждый инструмент может быть настроен следующим образом:

* **`True`**: Включить прерывания с поведением по умолчанию (разрешены одобрение, редактирование, отклонение)
* **`False`**: Отключить прерывания для этого инструмента
* **`{"allowed_decisions": [...]}`**: Пользовательская конфигурация с указанием конкретных разрешенных решений

```python theme={null}
from langchain.tools import tool
from deepagents import create_deep_agent
from langgraph.checkpoint.memory import MemorySaver

@инструмент
def delete_file(path: str) -> str:
    «Удалить файл из файловой системы».
    return f"Удаленный {путь}"

@инструмент
def read_file(path: str) -> str:
    «Чтение файла из файловой системы».
    return f"Содержимое {пути}"

@инструмент
def send_email(to: str, subject: str, body: str) -> str:
    «Отправить электронное письмо».
    return f"Отправлено электронное письмо на адрес {кому}"

# Для обеспечения участия человека в процессе необходима поддержка Checkpointer.
checkpointer = MemorySaver()

agent = create_deep_agent(
    model="claude-sonnet-4-5-20250929",
    tools=[delete_file, read_file, send_email],
    interrupt_on={
        "delete_file": True, # По умолчанию: одобрить, отредактировать, отклонить
        "read_file": False, # Прерывания не требуются
        "send_email": {"allowed_decisions": ["approve", "reject"]}, # Редактирование запрещено
    },
    checkpointer=checkpointer # Обязательно!
)
```

## Типы решений

Список `allowed_decisions` определяет, какие действия может предпринять человек при проверке вызова инструмента:

* **`"approve"`**: Запустить инструмент с исходными аргументами, предложенными агентом.
* **`"редактирование"`**: Измените аргументы инструмента перед выполнением
* **`"reject"`**: Полностью пропустить выполнение этого вызова инструмента

Вы можете настроить, какие решения будут доступны для каждого инструмента:

```python theme={null}
interrupt_on = {
    # Конфиденциальные операции: разрешить все параметры
    "delete_file": {"allowed_decisions": ["approve", "edit", "reject"]},

    # Умеренный риск: только одобрение или отклонение
    "write_file": {"allowed_decisions": ["approve", "reject"]},

    # Необходимо одобрить (отклонение не допускается)
    "critical_operation": {"allowed_decisions": ["approve"]},
}
```

## Обработка прерываний

При возникновении прерывания агент приостанавливает выполнение и возвращает управление. Проверьте наличие прерываний в результате и обработайте их соответствующим образом.

```python theme={null}
импорт uuid
from langgraph.types import Command

# Создание конфигурации с идентификатором потока для сохранения состояния
config = {"configurable": {"thread_id": str(uuid.uuid4())}}

# Вызов агента
результат = agent.invoke({
    "messages": [{"role": "user", "content": "Удалить файл temp.txt"}]
}, config=config)

# Проверка, было ли прервано выполнение
if result.get("__interrupt__"):
    # Извлечение информации о прерывании
    прерывания = результат["__interrupt__"][0].значение
    action_requests = interrupts["action_requests"]
    review_configs = interrupts["review_configs"]

    # Создать карту соответствия от имени инструмента к конфигурации проверки
    config_map = {cfg["action_name"]: cfg for cfg in review_configs}

    # Отобразить пользователю ожидающие действия
    для действия в action_requests:
        review_config = config_map[action["name"]]
        print(f"Инструмент: {action['name']}")
        print(f"Аргументы: {action['args']}")
        print(f"Разрешенные решения: {review_config['allowed_decisions']}")

    # Получение решений пользователя (одно на каждый запрос действия, по порядку)
    решения = [
        {"type": "approve"} # Пользователь одобрил удаление
    ]

    # Возобновить выполнение с принятыми решениями
    результат = agent.invoke(
        Команда(resume={"decisions": decisions}),
        config=config # Необходимо использовать один и тот же конфигурационный файл!
    )

# Обработка конечного результата
print(result["messages"][-1].content)
```

## Множественные вызовы инструментов

Когда агент вызывает несколько инструментов, требующих подтверждения, все прерывания объединяются в одно. Вам необходимо принять решение по каждому из них по порядку.

```python theme={null}
config = {"configurable": {"thread_id": str(uuid.uuid4())}}

результат = agent.invoke({
    "сообщения": [{
        "роль": "пользователь",
        "content": "Удалите файл temp.txt и отправьте электронное письмо на адрес admin@example.com"
    }]
}, config=config)

if result.get("__interrupt__"):
    прерывания = результат["__interrupt__"][0].значение
    action_requests = interrupts["action_requests"]

    # Двум инструментам требуется одобрение
    assert len(action_requests) == 2

    # Принимайте решения в том же порядке, что и запросы на действия.
    решения = [
        {"type": "approve"}, # Первый инструмент: delete_file
        {"type": "reject"} # Второй инструмент: send_email
    ]

    результат = agent.invoke(
        Команда(resume={"decisions": decisions}),
        config=config
    )
```

## Редактирование аргументов инструмента

Если параметр «редактирование» входит в число разрешенных, вы можете изменить аргументы инструмента перед его выполнением:

```python theme={null}
if result.get("__interrupt__"):
    прерывания = результат["__interrupt__"][0].значение
    action_request = interrupts["action_requests"][0]

    # Исходные аргументы от агента
    print(action_request["args"]) # {"to": "everyone@company.com", ...}

    # Пользователь решает изменить получателя
    решения = [{
        "type": "edit",
        "edited_action": {
            "name": action_request["name"], # Необходимо указать название инструмента
            "args": {"to": "team@company.com", "subject": "...", "body": "..."}
        }
    }]

    результат = agent.invoke(
        Команда(resume={"decisions": decisions}),
        config=config
    )
```

## Прерывания субагента

Каждый субагент может иметь собственную конфигурацию `interrupt_on`, которая переопределяет настройки основного агента:

```python theme={null}
agent = create_deep_agent(
    инструменты=[delete_file, read_file],
    interrupt_on={
        "delete_file": True,
        "read_file": False,
    },
    субагенты=[{
        "имя": "файловый менеджер",
        "Описание": "Управляет операциями с файлами",
        "system_prompt": "Вы являетесь помощником по управлению файлами."
        "инструменты": [удалить_файл, прочитать_файл],
        "interrupt_on": {
            # Переопределение: требуется подтверждение для чтения данных этим субагентом
            "delete_file": True,
            "read_file": True, # Отличается от основного агента!
        }
    }],
    контрольная точка=контрольная точка
)
```

Когда субагент инициирует прерывание, обработка происходит аналогично – проверяется наличие `__interrupt__` и возобновляется с помощью `Command`.

## Передовые методы

### Всегда используйте контрольную точку

Для обеспечения участия человека в процессе требуется контрольная точка для сохранения состояния агента между прерыванием и возобновлением работы:

```python theme={null}
from langgraph.checkpoint.memory import MemorySaver

checkpointer = MemorySaver()
agent = create_deep_agent(
    инструменты=[...],
    interrupt_on={...},
    checkpointer=checkpointer # Требуется для HITL
)
```

### Используйте тот же идентификатор потока

При возобновлении работы необходимо использовать ту же конфигурацию с тем же `thread_id`:

```python theme={null}
# Первый звонок
config = {"configurable": {"thread_id": "my-thread"}}
результат = agent.invoke(input, config=config)

# Возобновить (использовать ту же конфигурацию)
result = agent.invoke(Command(resume={...}), config=config)
```

### Сопоставьте порядок принятия решений с действиями

Список решений должен соответствовать порядку `action_requests`:

```python theme={null}
if result.get("__interrupt__"):
    прерывания = результат["__interrupt__"][0].значение
    action_requests = interrupts["action_requests"]

    # Принимайте одно решение для каждого действия, в указанном порядке
    решения = []
    для действия в action_requests:

    результат = agent.invoke(

```

### Настройка параметров в зависимости от риска

Настройте различные инструменты в зависимости от уровня риска:

```python theme={null}
interrupt_on = {
    # Высокий риск: полный контроль (утверждение, редактирование, отклонение)
    "delete_file": {"allowed_decisions": ["approve", "edit", "reject"]},
    "send_email": {"allowed_decisions": ["approve", "edit", "reject"]},

    # Средний уровень риска: редактирование запрещено
    "write_file": {"allowed_decisions": ["approve", "reject"]},

    # Низкий риск: без перерывов
    "read_file": False,
    "list_files": False,
}
```
