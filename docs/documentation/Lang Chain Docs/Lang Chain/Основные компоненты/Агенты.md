# Агенты

Агенты объединяют языковые модели с [инструментами](/oss/python/langchain/tools), чтобы создавать системы, способные анализировать задачи, выбирать подходящие инструменты и итеративно работать над поиском решений.

[`create_agent`](https://reference.langchain.com/python/langchain/agents/#langchain.agents.create_agent) предоставляет готовую к использованию в производственной среде реализацию агента.

[Агент LLM запускает инструменты в цикле для достижения цели](https://simonwillison.net/2025/Sep/18/agents/).
Агент работает до тех пор, пока не будет выполнено условие остановки, то есть когда модель выдаст окончательный результат или будет достигнут лимит итераций.


<Информация>
  [`create_agent`](https://reference.langchain.com/python/langchain/agents/#langchain.agents.create_agent) создает среду выполнения агента на основе **графа** с использованием [LangGraph](/oss/python/langgraph/overview). Граф состоит из узлов (шагов) и ребер (соединений), которые определяют, как ваш агент обрабатывает информацию. Агент перемещается по этому графу, выполняя такие узлы, как узел модели (который вызывает модель), узел инструментов (который выполняет инструменты) или промежуточное ПО.

  Узнайте больше об [Graph API](/oss/python/langgraph/graph-api).

## Основные компоненты

### Модель

Модель (/oss/python/langchain/models) — это механизм рассуждений вашего агента. Её можно задать несколькими способами, поддерживая как статический, так и динамический выбор модели.

#### Статическая модель

Статические модели настраиваются один раз при создании агента и остаются неизменными на протяжении всего выполнения. Это наиболее распространенный и простой подход.

Чтобы инициализировать статическую модель из строки идентификатора модели, содержащей <Tooltip tip="Строка, соответствующая формату `provider:model` (например, openai:gpt-5)" cta="См. сопоставления" href="https://reference.langchain.com/python/langchain/models/#langchain.chat_models.init_chat_model(model)">

```python wrap theme={null}
from langchain.agents import create_agent

agent = create_agent("openai:gpt-5", tools=tools)
```

<Совет>
  Строковые идентификаторы моделей поддерживают автоматическое определение (например, `"gpt-5"` будет интерпретировано как `"openai:gpt-5"`). Полный список сопоставлений строковых идентификаторов моделей см. в [справочнике](https://reference.langchain.com/python/langchain/models/#langchain.chat_models.init_chat_model\(model\)).
</Совет>

Для более полного контроля над конфигурацией модели инициализируйте экземпляр модели напрямую, используя пакет provider. В этом примере мы используем [`ChatOpenAI`](https://reference.langchain.com/python/integrations/langchain_openai/ChatOpenAI). См. [Модели чата](/oss/python/integrations/chat) для получения информации о других доступных классах моделей чата.

```python wrap theme={null}
from langchain.agents import create_agent
from langchain_openai import ChatOpenAI

модель = ChatOpenAI(
    model="gpt-5",
    температура = 0,1,
    max_tokens=1000,
    timeout=30
    # ... (другие параметры)
)
агент = create_agent(model, tools=tools)
```

Экземпляры моделей предоставляют полный контроль над конфигурацией. Используйте их, когда вам нужно установить определенные [параметры](/oss/python/langchain/models#parameters), такие как `temperature`, `max_tokens`, `timeouts`, `base_url` и другие параметры, специфичные для поставщика. Обратитесь к [справочнику](/oss/python/integrations/providers/all_providers), чтобы увидеть доступные параметры и методы вашей модели.

#### Динамическая модель

Динамические модели выбираются в среде выполнения вашего агента, содержащей неизменяемые конфигурационные и контекстные данные, сохраняющиеся на протяжении всего выполнения агента (например, идентификаторы пользователей, сведения о сеансе или конфигурация, специфичная для приложения) на основе текущего состояния и контекста. Это позволяет реализовать сложную логику маршрутизации и оптимизацию затрат.

Для использования динамической модели создайте промежуточное ПО с помощью декоратора [`@wrap_model_call`](https://reference.langchain.com/python/langchain/middleware/#langchain.agents.middleware.wrap_model_call), который изменяет модель в запросе:

```python theme={null}
from langchain_openai import ChatOpenAI
from langchain.agents import create_agent
from langchain.agents.middleware import wrap_model_call, ModelRequest, ModelResponse


basic_model = ChatOpenAI(model="gpt-4.1-mini")
advanced_model = ChatOpenAI(model="gpt-4.1")

@wrap_model_call
def dynamic_model_selection(request: ModelRequest, handler) -> ModelResponse:
    «Выбирайте модель в зависимости от сложности диалога».
    message_count = len(request.state["messages"])

    если message_count > 10:
        # Используйте расширенную модель для более длительных разговоров
        модель = advanced_model
    еще:
        модель = базовая_модель

    return handler(request.override(model=model))

агент = create_agent(
    model=basic_model, # Модель по умолчанию
    инструменты=инструменты,
    middleware=[dynamic_model_selection]
)
```

<Предупреждение>
  Предварительно связанные модели (модели, для которых уже вызывается [`bind_tools`](https://reference.langchain.com/python/langchain_core/language_models/#langchain_core.language_models.chat_models.BaseChatModel.bind_tools)) не поддерживаются при использовании структурированного вывода. Если вам необходим динамический выбор модели со структурированным выводом, убедитесь, что модели, передаваемые в промежуточное ПО, не являются предварительно связанными.
</Предупреждение>

<Совет>
  Подробную информацию о настройке модели см. в разделе [Модели](/oss/python/langchain/models). Описание шаблонов динамического выбора модели см. в разделе [Динамическая модель в промежуточном ПО](/oss/python/langchain/middleware#dynamic-model).
</Совет>

### Инструменты

Инструменты предоставляют агентам возможность совершать действия. Агенты выходят за рамки простой привязки инструментов только к модели, обеспечивая:

* Последовательный вызов нескольких инструментов (запускается одним запросом)
* Параллельные вызовы инструментов при необходимости
* Динамический выбор инструмента на основе предыдущих результатов
* Логика повторных попыток и обработка ошибок инструмента
* Сохранение состояния между вызовами инструментов

Для получения дополнительной информации см. [Инструменты](/oss/python/langchain/tools).

#### Определение инструментов

Передайте агенту список инструментов.

<Совет>
  Инструменты могут быть указаны как обычные функции Python или как корутины.

  [Декоратор инструментов](/oss/python/langchain/tools#create-tools) можно использовать для настройки имен инструментов, описаний, схем аргументов и других свойств.
</Совет>

```python wrap theme={null}
from langchain.tools import tool
from langchain.agents import create_agent


@инструмент
def search(query: str) -> str:
    «Поиск информации».
    return f"Результаты для: {запрос}"

@инструмент
def get_weather(location: str) -> str:
    «Получите информацию о погоде для определенного места».
    return "Погода в {местоположение}: Солнечно, 72°F"

agent = create_agent(model, tools=[search, get_weather])
```

Если предоставлен пустой список инструментов, агент будет состоять из одного узла LLM без возможности вызова инструментов.

#### Обработка ошибок инструмента

Чтобы настроить обработку ошибок инструментов, используйте декоратор [`@wrap_tool_call`](https://reference.langchain.com/python/langchain/middleware/#langchain.agents.middleware.wrap_tool_call) для создания промежуточного ПО:

```python wrap theme={null}
from langchain.agents import create_agent
from langchain.agents.middleware import wrap_tool_call
from langchain.messages import ToolMessage


@wrap_tool_call
def handle_tool_errors(request, handler):
    «Обработка ошибок выполнения инструментов с помощью пользовательских сообщений».
    пытаться:
        return handler(request)
    за исключением исключения как e:
        # Возвращает в модель пользовательское сообщение об ошибке
        return ToolMessage(
            content=f"Ошибка инструмента: Пожалуйста, проверьте введенные данные и попробуйте снова. ({str(e)})",
            tool_call_id=request.tool_call["id"]
        )

агент = create_agent(
    model="gpt-4.1",
    tools=[search, get_weather],
    middleware=[handle_tool_errors]
)
```

В случае сбоя инструмента агент вернет сообщение об ошибке в формате [`ToolMessage`](https://reference.langchain.com/python/langchain/messages/#langchain.messages.ToolMessage) с пользовательским сообщением об ошибке:

```python theme={null}
[
    ...
    ToolMessage(
        content="Ошибка инструмента: Пожалуйста, проверьте ввод и попробуйте снова. (деление на ноль)",
        tool_call_id="..."
    ),
    ...
]
```

#### Использование инструментов в цикле ReAct

Агенты следуют схеме ReAct («Рассуждение + Действие»), чередуя краткие этапы рассуждения с целенаправленными вызовами инструментов и используя полученные данные для принятия последующих решений, пока не смогут дать окончательный ответ.

<Accordion title="Пример цикла ReAct">
  **Задание:** Определите самые популярные на данный момент беспроводные наушники и проверьте их наличие.

  ```
  ================================ Сообщение от человека ==================================

  Найдите самые популярные беспроводные наушники прямо сейчас и проверьте, есть ли они в наличии.
  ```

  * **Обоснование**: «Популярность зависит от времени, мне необходимо использовать предоставленный инструмент поиска».
  * **Действующее действие**: Вызов `search_products("беспроводные наушники")`

  ```
  ================================ Сообщение Ai ================================
  Вызовы инструментов:
    search_products (call_abc123)
   Идентификатор вызова: call_abc123
    Аргументы:
      запрос: беспроводные наушники
  ```

  ```
  ================================= Сообщение инструмента =================================

  Найдено 5 товаров, соответствующих запросу "беспроводные наушники". Топ-5 результатов: WH-1000XM5, ...
  ```

  * **Обоснование**: «Мне необходимо подтвердить наличие товара, занимающего первое место в рейтинге, прежде чем отвечать».
  * **Действующее действие**: Вызов `check_inventory("WH-1000XM5")`

  ```
  ================================ Сообщение Ai ================================
  Вызовы инструментов:
    check_inventory (call_def456)
   Идентификатор вызова: call_def456
    Аргументы:
      product_id: WH-1000XM5
  ```

  ```
  ================================= Сообщение инструмента =================================

  Товар WH-1000XM5: в наличии 10 единиц.
  ```

  * **Обоснование**: «У меня есть самая популярная модель и информация о её наличии на складе. Теперь я могу ответить на вопрос пользователя».
  * **Актерская игра**: Подготовьте окончательный ответ

  ```
  ================================ Сообщение Ai ================================

  Я обнаружил беспроводные наушники (модель WH-1000XM5) в наличии 10 штук...
  ```
</Аккордеон>

#### Динамические инструменты

В некоторых сценариях необходимо изменить набор инструментов, доступных агенту во время выполнения, вместо того, чтобы определять их все заранее. Существует два подхода в зависимости от того, известны ли инструменты заранее:

<Вкладки>
  <Tab title="Фильтрация предварительно зарегистрированных инструментов">
    Когда все возможные инструменты известны на этапе создания агента, вы можете предварительно зарегистрировать их и динамически фильтровать, какие из них будут доступны модели, на основе состояния, разрешений или контекста.

    ```python theme={null}
    from langchain.agents import create_agent
    from langchain.agents.middleware import wrap_model_call, ModelRequest, ModelResponse
    from typing import Callable

    @wrap_model_call
    def filter_tools(
        запрос: ModelRequest,
        обработчик: Callable[[ModelRequest], ModelResponse],
    ) -> ModelResponse:
        «Фильтрация инструментов на основе прав доступа пользователя».
        user_role = request.runtime.context.user_role

        если user_role == "admin":
            # Администраторы получают все инструменты
            инструменты = запрос.инструменты
        еще:
            # Обычные пользователи получают инструменты только для чтения
            инструменты = [t for t in request.tools if t.name.startswith("read_")]

        return handler(request.override(tools=tools))

    агент = create_agent(
        model="gpt-4o",
        tools=[read_data, write_data, delete_data], # Все инструменты предварительно зарегистрированы
        middleware=[filter_tools],
    )
    ```

    Этот подход наиболее эффективен в следующих случаях:

    * Все возможные инструменты известны на этапе компиляции/запуска.
    * Вы хотите выполнить фильтрацию на основе разрешений, флагов функций или состояния беседы.
    * Инструменты статичны, но их доступность динамична.

    Дополнительные примеры см. в разделе [Динамический выбор инструментов](/oss/python/langchain/middleware/custom#dynamically-selecting-tools).
  </Tab>

  <Tab title="Регистрация инструментов среды выполнения">
    Когда инструменты обнаруживаются или создаются во время выполнения (например, загружаются с сервера MCP, генерируются на основе пользовательских данных или извлекаются из удаленного реестра), необходимо как зарегистрировать эти инструменты, так и динамически управлять их выполнением.

    Для этого требуется два промежуточных обработчика:

    1. `wrap_model_call` — Добавить динамические инструменты в запрос.
    2. `wrap_tool_call` — Обработка выполнения динамически добавляемых инструментов.

    ```python theme={null}
    from langchain.tools import tool
    from langchain.agents import create_agent
    из langchain.agents.middleware импортировать AgentMiddleware, ModelRequest
    from langchain.agents.middleware.types import ToolCallRequest

    # Инструмент, который будет добавляться динамически во время выполнения.
    @инструмент
    def calculate_tip(bill_amount: float, tip_percentage: float = 20.0) -> str:
        «Рассчитайте сумму чаевых к счету».
        чаевые = сумма счета * (процент чаевых / 100)
        return f"Чаевые: ${tip:.2f}, Итого: ${сумма_счета + чаевые:.2f}"

    класс DynamicToolMiddleware (AgentMiddleware):
        «Промежуточное программное обеспечение, которое регистрирует и обрабатывает динамические инструменты».

        def wrap_model_call(self, request: ModelRequest, handler):
            # Добавить динамический инструмент к запросу
            # Данные могут быть загружены с сервера MCP, базы данных и т. д.
            обновлено = request.override(tools=[*request.tools, calculate_tip])
            обработчик возврата (обновлено)

        def wrap_tool_call(self, request: ToolCallRequest, handler):
            # Обработка выполнения динамического инструмента
            if request.tool_call["name"] == "calculate_tip":
                return handler(request.override(tool=calculate_tip))
            return handler(request)

    агент = create_agent(
        model="gpt-4o",
        tools=[get_weather], # Здесь зарегистрированы только статические инструменты
        промежуточное ПО=[DynamicToolMiddleware()],
    )

    # Теперь агент может использовать как get_weather, так и calculate_tip
    результат = agent.invoke({
        "messages": [{"role": "user", "content": "Рассчитать чаевые в размере 20% от 85 долларов"}]
    })
    ```

    Этот подход наиболее эффективен в следующих случаях:

    * Инструменты обнаруживаются во время выполнения (например, на сервере MCP).
    * Инструменты генерируются динамически на основе пользовательских данных или конфигурации.
    * Вы интегрируетесь с внешними реестрами инструментов.

    <Примечание>
      Хук `wrap_tool_call` необходим для инструментов, зарегистрированных во время выполнения, поскольку агенту нужно знать, как запускать инструменты, которых не было в исходном списке инструментов. Без него агент не будет знать, как вызвать динамически добавленный инструмент.
    </Примечание>
  </Tab>
</Вкладки>

<Совет>
  Чтобы узнать больше об инструментах, см. [Tools](/oss/python/langchain/tools).
</Совет>

### Системная подсказка

Вы можете настроить подход вашего агента к выполнению задач, предоставив ему подсказку. Параметр [`system_prompt`](https://reference.langchain.com/python/langchain/agents/#langchain.agents.create_agent\(system_prompt\)) можно передать в виде строки:

```python wrap theme={null}
агент = create_agent(
    модель,
    инструменты,
    system_prompt="Вы полезный помощник. Будьте кратки и точны."
)
```

Если параметр [`system_prompt`](https://reference.langchain.com/python/langchain/agents/#langchain.agents.create_agent\(system_prompt\)) не указан, агент будет определять свою задачу непосредственно из сообщений.

Параметр [`system_prompt`](https://reference.langchain.com/python/langchain/agents/#langchain.agents.create_agent\(system_prompt\)) принимает либо строку (`str`), либо [`SystemMessage`](https://reference.langchain.com/python/langchain/messages/#langchain.messages.SystemMessage). Использование `SystemMessage` дает больше контроля над структурой подсказки, что полезно для функций, специфичных для конкретного поставщика, таких как [кэширование подсказок Anthropic](/oss/python/integrations/chat/anthropic#prompt-caching):

```python wrap theme={null}
from langchain.agents import create_agent
from langchain.messages import SystemMessage, HumanMessage

literary_agent = create_agent(
    model="anthropic:claude-sonnet-4-5",
    system_prompt=SystemMessage(
        контент=[
            {
                "type": "text",
                "текст": "Вы — ИИ-помощник, которому поручено анализировать литературные произведения."
            },
            {
                "type": "text",
                "текст": "<полное содержание романа «Гордость и предубеждение»>",
                "cache_control": {"type": "ephemeral"}
            }
        ]
    )
)

результат = literary_agent.invoke(
    {"messages": [HumanMessage("Проанализируйте основные темы романа «Гордость и предубеждение»."]}
)
```

Поле `cache_control` со значением `{"type": "ephemeral"}` указывает Anthropic кэшировать этот блок контента, уменьшая задержку и затраты при повторных запросах, использующих одну и ту же системную подсказку.

#### Динамическая системная подсказка

Для более сложных сценариев использования, когда необходимо изменять системную подсказку в зависимости от контекста выполнения или состояния агента, можно использовать [промежуточное ПО](/oss/python/langchain/middleware).

Декоратор [`@dynamic_prompt`](https://reference.langchain.com/python/langchain/middleware/#langchain.agents.middleware.dynamic_prompt) создает промежуточное ПО, которое генерирует системные подсказки на основе запроса модели:

```python wrap theme={null}
from typing import TypedDict

from langchain.agents import create_agent
from langchain.agents.middleware import dynamic_prompt, ModelRequest


class Context(TypedDict):
    роль пользователя: строка

@dynamic_prompt
def user_role_prompt(request: ModelRequest) -> str:
    «Сгенерировать системное приглашение в зависимости от роли пользователя».
    user_role = request.runtime.context.get("user_role", "user")
    base_prompt = "Вы полезный помощник."

    если user_role == "expert":
        return f"{base_prompt} Предоставьте подробные технические ответы."
    elif user_role == "beginner":
        return f"{base_prompt} Объясняйте понятия простым языком и избегайте профессионального жаргона."

    return base_prompt

агент = create_agent(
    model="gpt-4.1",
    инструменты=[web_search],
    middleware=[user_role_prompt],
    context_schema=Context
)

# Системная подсказка будет устанавливаться динамически в зависимости от контекста
результат = agent.invoke(
    {"messages": [{"role": "user", "content": "Explain machine learning"}]},
    контекст={"user_role": "expert"}
)
```

<Совет>
  Более подробную информацию о типах сообщений и их форматировании см. в разделе [Сообщения](/oss/python/langchain/messages). Подробную документацию по промежуточному программному обеспечению см. в разделе [Промежуточное программное обеспечение](/oss/python/langchain/middleware).
</Совет>

## Призыв

Вы можете вызвать агента, передав ему обновление в его [`State`](/oss/python/langgraph/graph-api#state). Все агенты включают [последовательность сообщений](/oss/python/langgraph/use-graph-api#messagesstate) в свое состояние; чтобы вызвать агента, передайте новое сообщение:

```python theme={null}
результат = agent.invoke(
    {"messages": [{"role": "user", "content": "Какая погода в Сан-Франциско?"}]}
)
```

Для потоковой передачи шагов и/или токенов от агента обратитесь к руководству по потоковой передаче.

В противном случае агент следует API графа LangGraph и поддерживает все связанные с ним методы, такие как `stream` и `invoke`.

## Расширенные концепции

### Структурированный вывод

В некоторых ситуациях может потребоваться, чтобы агент возвращал результат в определенном формате. LangChain предоставляет стратегии для структурированного вывода с помощью параметра [`response_format`](https://reference.langchain.com/python/langchain/agents/#langchain.agents.create_agent\(response_format\)).

#### Стратегия инструментов

`ToolStrategy` использует искусственный вызов инструментов для генерации структурированного вывода. Это работает с любой моделью, поддерживающей вызов инструментов. `ToolStrategy` следует использовать, когда собственный структурированный вывод поставщика (через [`ProviderStrategy`](#ProviderStrategy)) недоступен или ненадежен.

```python wrap theme={null}
from pydantic import BaseModel
from langchain.agents import create_agent
from langchain.agents.structured_output import ToolStrategy


class ContactInfo(BaseModel):
    имя: str
    электронная почта: str
    телефон: стр.

агент = create_agent(
    model="gpt-4.1-mini",
    инструменты=[search_tool],
    response_format=ToolStrategy(ContactInfo)
)

результат = agent.invoke({
    "сообщения": [{"роль": "пользователь", "содержание": "Извлечь контактную информацию от: Джон Доу, john@example.com, (555) 123-4567"}]
})

результат["структурированный_ответ"]
# ContactInfo(name='John Doe', email='john@example.com', phone='(555) 123-4567')
```

#### Стратегия поставщика

`ProviderStrategy` использует встроенную функцию генерации структурированного вывода поставщика модели. Это более надежный способ, но он работает только с поставщиками, поддерживающими встроенную генерацию структурированного вывода:

```python wrap theme={null}
from langchain.agents.structured_output import ProviderStrategy

агент = create_agent(
    model="gpt-4.1",
    response_format=ProviderStrategy(ContactInfo)
)
```

<Примечание>
  Начиная с версии `langchain 1.0`, простая передача схемы (например, `response_format=ContactInfo`) по умолчанию будет использовать `ProviderStrategy`, если модель поддерживает собственный структурированный вывод. В противном случае будет использоваться `ToolStrategy`.
</Примечание>

<Совет>
  Чтобы узнать больше о структурированном выводе, см. [Структурированный вывод](/oss/python/langchain/structured-output).
</Совет>

### Память

Агенты автоматически сохраняют историю разговоров в состоянии сообщений. Вы также можете настроить агента на использование пользовательской схемы состояния для запоминания дополнительной информации во время разговора.

Информацию, хранящуюся в состоянии, можно рассматривать как [кратковременную память](/oss/python/langchain/short-term-memory) агента:

Пользовательские схемы состояний должны расширять [`AgentState`](https://reference.langchain.com/python/langchain/agents/#langchain.agents.AgentState) как `TypedDict`.

Существует два способа определения пользовательского состояния:

1. Через [промежуточное ПО](/oss/python/langchain/middleware) (предпочтительный способ)
2. Через [`state_schema`](https://reference.langchain.com/python/langchain/middleware/#langchain.agents.middleware.AgentMiddleware.state_schema) в [`create_agent`](https://reference.langchain.com/python/langchain/agents/#langchain.agents.create_agent)

#### Определение состояния через промежуточное ПО

Используйте промежуточное ПО для определения пользовательского состояния, когда доступ к этому состоянию необходим для определенных обработчиков и инструментов промежуточного ПО, подключенных к данному промежуточному ПО.

```python theme={null}
from langchain.agents import AgentState
из langchain.agents.middleware импортировать AgentMiddleware
из набора текста импортировать Any


class CustomState(AgentState):
    user_preferences: dict

класс CustomMiddleware(AgentMiddleware):
    state_schema = CustomState
    инструменты = [инструмент1, инструмент2]

    def before_model(self, state: CustomState, runtime) -> dict[str, Any] | None:
        ...

агент = create_agent(
    модель,
    инструменты=инструменты,
    промежуточное ПО=[CustomMiddleware()]
)

# Теперь агент может отслеживать не только сообщения, но и другие состояния.
результат = agent.invoke({
    "messages": [{"role": "user", "content": "I prefer technical explanations"}],
    "user_preferences": {"style": "technical", "verbosity": "detailed"},
})
```

#### Определение состояния с помощью `state_schema`

Используйте параметр [`state_schema`](https://reference.langchain.com/python/langchain/middleware/#langchain.agents.middleware.AgentMiddleware.state_schema) в качестве сокращения для определения пользовательского состояния, которое используется только в инструментах.

```python theme={null}
from langchain.agents import AgentState


class CustomState(AgentState):
    user_preferences: dict

агент = create_agent(
    модель,
    инструменты=[инструмент1, инструмент2],
    state_schema=CustomState
)
# Теперь агент может отслеживать не только сообщения, но и другие состояния.
результат = agent.invoke({
    "messages": [{"role": "user", "content": "I prefer technical explanations"}],
    "user_preferences": {"style": "technical", "verbosity": "detailed"},
})
```

<Примечание>
  Начиная с версии `langchain 1.0`, пользовательские схемы состояний **должны** быть типами `TypedDict`. Модели и классы данных Pydantic больше не поддерживаются. Дополнительную информацию см. в [руководстве по миграции v1](/oss/python/migrate/langchain-v1#state-type-restrictions).
</Примечание>

<Примечание>
  Определение пользовательского состояния через промежуточное ПО предпочтительнее, чем определение его через [`state_schema`](https://reference.langchain.com/python/langchain/middleware/#langchain.agents.middleware.AgentMiddleware.state_schema) в [`create_agent`](https://reference.langchain.com/python/langchain/agents/#langchain.agents.create_agent), поскольку это позволяет сохранять концептуальную область действия расширений состояния в рамках соответствующего промежуточного ПО и инструментов.

  [`state_schema`](https://reference.langchain.com/python/langchain/middleware/#langchain.agents.middleware.AgentMiddleware.state_schema) по-прежнему поддерживается для обратной совместимости с [`create_agent`](https://reference.langchain.com/python/langchain/agents/#langchain.agents.create_agent).
</Примечание>

<Совет>
  Чтобы узнать больше о памяти, см. [Memory](/oss/python/concepts/memory). Информацию о реализации долговременной памяти, сохраняющейся между сессиями, см. [Long-term memory](/oss/python/langchain/long-term-memory).
</Совет>

### Стриминг

Мы видели, как можно вызвать агента с помощью команды `invoke` для получения окончательного ответа. Если агент выполняет несколько шагов, это может занять некоторое время. Чтобы показать промежуточный прогресс, мы можем передавать сообщения обратно по мере их поступления.

```python theme={null}
for chunk in agent.stream({
    "messages": [{"role": "user", "content": "Поиск новостей об ИИ и обобщение результатов"}]
}, stream_mode="values"):
    # Каждый фрагмент содержит полное состояние на данный момент
    latest_message = chunk["messages"][-1]
    если latest_message.content:
        print(f"Агент: {latest_message.content}")
    elif latest_message.tool_calls:
        print(f"Вызов инструментов: {[tc['name'] for tc in latest_message.tool_calls]}")
```

<Совет>
  Для получения более подробной информации о потоковой передаче данных см. [Streaming](/oss/python/langchain/streaming).
</Совет>

### Промежуточное ПО

[Промежуточное ПО](/oss/python/langchain/middleware) обеспечивает широкие возможности расширения для настройки поведения агента на разных этапах выполнения. Вы можете использовать промежуточное ПО для:

* Обработка состояния перед вызовом модели (например, обрезка сообщений, внедрение контекста)
* Изменить или проверить ответ модели (например, установить ограничители, фильтровать контент).
* Обработка ошибок выполнения инструмента с помощью пользовательской логики.
* Реализовать динамический выбор модели на основе состояния или контекста.
* Добавьте пользовательские функции ведения журналов, мониторинга или аналитики.

Промежуточное ПО органично интегрируется в работу агента, позволяя перехватывать и изменять поток данных в ключевых точках без изменения основной логики агента.

<Совет>
  Для получения исчерпывающей документации по промежуточному программному обеспечению, включая такие декораторы, как [`@before_model`](https://reference.langchain.com/python/langchain/middleware/#langchain.agents.middleware.before_model), [`@after_model`](https://reference.langchain.com/python/langchain/middleware/#langchain.agents.middleware.after_model) и [`@wrap_tool_call`](https://reference.langchain.com/python/langchain/middleware/#langchain.agents.middleware.wrap_tool_call), см. [Middleware](/oss/python/langchain/middleware).
</Совет>
