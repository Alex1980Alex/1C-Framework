# Инструменты

Инструменты расширяют возможности [агентов](/oss/python/langchain/agents), позволяя им получать данные в реальном времени, выполнять код, запрашивать данные из внешних баз данных и совершать действия в окружающем мире.

По сути, инструменты представляют собой вызываемые функции с четко определенными входными и выходными данными, которые передаются в [модель чата](/oss/python/langchain/models). Модель решает, когда вызывать инструмент, исходя из контекста разговора, и какие входные аргументы следует предоставить.

<Совет>
  Подробную информацию о том, как модели обрабатывают вызовы инструментов, см. в разделе [Вызов инструментов](/oss/python/langchain/models#tool-calling).
</Совет>

## Создание инструментов

### Базовое определение инструмента

Простейший способ создать инструмент — использовать декоратор [`@tool`](https://reference.langchain.com/python/langchain/tools/#langchain.tools.tool). По умолчанию строка документации функции становится описанием инструмента, которое помогает модели понять, когда его следует использовать:

```python theme={null}
from langchain.tools import tool

@инструмент
def search_database(query: str, limit: int = 10) -> str:
    Выполните поиск в базе данных клиентов записей, соответствующих запросу.

    Аргументы:
        Запрос: Поисковые запросы для поиска
        limit: Максимальное количество возвращаемых результатов
    """
    return "Найдено {limit} результатов для '{query}'"
```

Указания типов **обязательны**, поскольку они определяют схему ввода инструмента. Документация должна быть информативной и краткой, чтобы помочь модели понять назначение инструмента.

<Примечание>
  **Использование инструментов на стороне сервера**

  Некоторые модели чата (например, [OpenAI](/oss/python/integrations/chat/openai), [Anthropic](/oss/python/integrations/chat/anthropic) и [Gemini](/oss/python/integrations/chat/google_generative_ai)) имеют [встроенные инструменты](/oss/python/langchain/models#server-side-tool-use), которые выполняются на стороне сервера, такие как веб-поиск и интерпретаторы кода. Обратитесь к [обзору поставщика](/oss/python/integrations/providers/overview), чтобы узнать, как получить доступ к этим инструментам для вашей конкретной модели чата.
</Примечание>

### Настройка свойств инструмента

#### Пользовательское название инструмента

По умолчанию название инструмента берется из названия функции. Если вам нужно более описательное название, переопределите его:

```python theme={null}
@tool("web_search") # Пользовательское имя
def search(query: str) -> str:
    «Ищите информацию в интернете».
    return f"Результаты для: {запрос}"

print(search.name) # web_search
```

#### Описание пользовательского инструмента

Для более понятных указаний по работе с моделью измените автоматически сгенерированное описание инструмента:

```python theme={null}
@tool("calculator", description="Выполняет арифметические вычисления. Используйте это для решения любых математических задач.")
def calc(expression: str) -> str:
    «Вычисляйте значения математических выражений».
    return str(eval(expression))
```

### Расширенное определение схемы

Определяйте сложные входные данные с помощью моделей Pydantic или схем JSON:

<CodeGroup>
  ```python Pydantic model theme={null}
  from pydantic import BaseModel, Field
  from typing import Literal

  class WeatherInput(BaseModel):
      «Ввод данных для запросов о погоде».
      местоположение: str = Field(description="Название города или координаты")
      единицы измерения: Literal["celesius", "fahrenheit"] = Field(
          default="celsius",
          описание="Предпочтительная единица измерения температуры"
      )
      include_forecast: bool = Field(
          по умолчанию = False,
          описание="Включить прогноз на 5 дней"
      )

  @tool(args_schema=WeatherInput)
  def get_weather(location: str, units: str = "celsius", include_forecast: bool = False) -> str:
      «Получите текущую погоду и, при желании, прогноз».
      temp = 22 if units == "celsius" else 72
      результат = f"Текущая погода в {местоположение}: {температура} градусов {единицы[0].upper()}"
      если include_forecast:
          результат += "\nСледующие 5 дней: Солнечно"
      вернуть результат
  ```

  ```python JSON Schema theme={null}
  weather_schema = {
      "type": "object",
      "характеристики": {
          "location": {"type": "string"},
          "units": {"type": "string"},
          "include_forecast": {"type": "boolean"}
      },
      "required": ["location", "units", "include_forecast"]
  }

  @tool(args_schema=weather_schema)
  def get_weather(location: str, units: str = "celsius", include_forecast: bool = False) -> str:
      «Получите текущую погоду и, при желании, прогноз».
      temp = 22 if units == "celsius" else 72
      результат = f"Текущая погода в {местоположение}: {температура} градусов {единицы[0].upper()}"
      если include_forecast:
          результат += "\nСледующие 5 дней: Солнечно"
      вернуть результат
  ```
</CodeGroup>

### Зарезервированные имена аргументов

Следующие имена параметров зарезервированы и не могут использоваться в качестве аргументов инструмента. Использование этих имен приведет к ошибкам во время выполнения.

| Название параметра | Назначение                                                                             |
| ------------------ | -------------------------------------------------------------------------------------- |
| `config`           | Зарезервировано для передачи `RunnableConfig` инструментам внутри системы              |
| `runtime`          | Зарезервировано для параметра `ToolRuntime` (доступ к состоянию, контексту, хранилищу) |

Для доступа к информации о времени выполнения используйте параметр [`ToolRuntime`](https://reference.langchain.com/python/langchain/tools/#langchain.tools.ToolRuntime) вместо того, чтобы называть свои аргументы `config` или `runtime`.

## Доступ к контексту

<Информация>
  **Почему это важно:** Инструменты наиболее эффективны, когда они имеют доступ к состоянию агента, контексту выполнения и долговременной памяти. Это позволяет инструментам принимать решения с учетом контекста, персонализировать ответы и сохранять информацию в ходе диалогов.

  Контекст времени выполнения предоставляет способ внедрения зависимостей (таких как подключения к базе данных, идентификаторы пользователей или конфигурация) в ваши инструменты во время выполнения, что делает их более тестируемыми и пригодными для повторного использования.
</Info>

Инструменты могут получать доступ к информации о времени выполнения через параметр `ToolRuntime`, который предоставляет следующие данные:

* **Состояние** — Изменяемые данные, передаваемые в процессе выполнения (например, сообщения, счетчики, пользовательские поля).
* **Контекст** - Неизменяемая конфигурация, такая как идентификаторы пользователей, сведения о сеансе или конфигурация, специфичная для приложения.
* **Сохранение** — Устойчивая долговременная память, сохраняющаяся в ходе разговоров.
* **Stream Writer** - Потоковая передача пользовательских обновлений по мере выполнения инструментов.
* **Config** - `RunnableConfig` для выполнения
* **Идентификатор вызова инструмента** - ID текущего вызова инструмента

### `ToolRuntime`

Используйте `ToolRuntime` для доступа ко всей информации о времени выполнения в одном параметре. Просто добавьте `runtime: ToolRuntime` в сигнатуру вашего инструмента, и он будет автоматически внедрен без доступа к LLM.

<Информация>
  **`ToolRuntime`**: Единый параметр, предоставляющий инструментам доступ к состоянию, контексту, хранилищу, потоковой передаче, конфигурации и идентификатору вызова инструмента. Это заменяет старый подход, в котором использовались отдельные аннотации [`InjectedState`](https://reference.langchain.com/python/langgraph/agents/#langgraph.prebuilt.tool_node.InjectedState), [`InjectedStore`](https://reference.langchain.com/python/langgraph/agents/#langgraph.prebuilt.tool_node.InjectedStore), [`get_runtime`](https://reference.langchain.com/python/langgraph/runtime/#langgraph.runtime.get_runtime) и [`InjectedToolCallId`](https://reference.langchain.com/python/langchain/tools/#langchain.tools.InjectedToolCallId).

  Среда выполнения автоматически предоставляет эти возможности функциям вашего инструментария без необходимости явной передачи этих возможностей или использования глобального состояния.
</Info>

**Доступ к состоянию:**

Инструменты могут получить доступ к текущему состоянию графа с помощью `ToolRuntime`:

```python theme={null}
from langchain.tools import tool, ToolRuntime

# Доступ к текущему состоянию разговора
@инструмент
def summarize_conversation(
    среда выполнения: ToolRuntime
) -> str:
    «Подведите итоги разговора на данный момент».
    сообщения = runtime.state["сообщения"]

    human_msgs = sum(1 for m in messages if m.__class__.__name__ == "HumanMessage")
    ai_msgs = sum(1 for m in messages if m.__class__.__name__ == "AIMessage")
    tool_msgs = sum(1 for m in messages if m.__class__.__name__ == "ToolMessage")

    "В диалоге содержится {human_msgs} сообщений пользователя, {ai_msgs} ответов ИИ и {tool_msgs} результатов работы инструмента."

# Доступ к пользовательским полям состояния
@инструмент
def get_user_preference(
    pref_name: str,
    runtime: ToolRuntime # Параметр ToolRuntime не виден модели
) -> str:
    «Получить значение пользовательских предпочтений».
    preferences = runtime.state.get("user_preferences", {})
    return preferences.get(pref_name, "Не задано")
```

<Предупреждение>
  Параметр `runtime` скрыт от модели. В приведенном выше примере модель видит только `pref_name` в схеме инструмента — параметр `runtime` *не* включается в запрос.
</Предупреждение>

**Обновление состояния:**

Используйте [`Command`](https://reference.langchain.com/python/langgraph/types/#langgraph.types.Command), чтобы обновить состояние агента или управлять потоком выполнения графа:

```python theme={null}
from langgraph.types import Command
from langchain.messages import RemoveMessage
from langgraph.graph.message import REMOVE_ALL_MESSAGES
from langchain.tools import tool, ToolRuntime

# Обновить историю переписки, удалив все сообщения
@инструмент
def clear_conversation() -> Command:
    «Очистить историю переписки».

    return Command(
        обновление={
            "сообщения": [RemoveMessage(id=REMOVE_ALL_MESSAGES)],
        }
    )

# Обновите имя пользователя в состоянии агента
@инструмент
def update_user_name(
    новое_имя: str,
    среда выполнения: ToolRuntime
) -> Команда:
    «Обновить имя пользователя».
    return Command(update={"user_name": new_name})
```

#### Контекст

Доступ к неизменяемым конфигурационным и контекстным данным, таким как идентификаторы пользователей, сведения о сеансах или конфигурация, специфичная для приложения, осуществляется через `runtime.context`.

Инструменты могут получать доступ к контексту среды выполнения через `ToolRuntime`:

```python theme={null}
from dataclasses import dataclass
from langchain_openai import ChatOpenAI
from langchain.agents import create_agent
from langchain.tools import tool, ToolRuntime


USER_DATABASE = {
    "user123": {
        "имя": "Элис Джонсон",
        "account_type": "Premium",
        "баланс": 5000,
        "email": "alice@example.com"
    },
    "user456": {
        "имя": "Боб Смит",
        "account_type": "Standard",
        "баланс": 1200,
        "email": "bob@example.com"
    }
}

@dataclass
класс UserContext:
    user_id: str

@инструмент
def get_account_info(runtime: ToolRuntime[UserContext]) -> str:
    «Получить информацию об учетной записи текущего пользователя».
    user_id = runtime.context.user_id

    если user_id находится в базе данных пользователей:
        пользователь = USER_DATABASE[user_id]
        return f"Владелец счета: {user['name']}\nТип: {user['account_type']}\nБаланс: ${user['balance']}"
    вернуть "Пользователь не найден"

model = ChatOpenAI(model="gpt-4.1")
агент = create_agent(
    модель,
    tools=[get_account_info],
    context_schema=UserContext,
    system_prompt="Вы являетесь финансовым помощником."
)

результат = agent.invoke(
    {"messages": [{"role": "user", "content": "Какой у меня текущий баланс?"}]},
    context=UserContext(user_id="user123")
)
```

#### Память (хранилище)

Получайте доступ к постоянным данным между диалогами с помощью хранилища. Доступ к хранилищу осуществляется через `runtime.store` и позволяет сохранять и извлекать данные, специфичные для пользователя или приложения.

Инструменты могут получать доступ к хранилищу и обновлять его через `ToolRuntime`:

```python expandable theme={null}
из набора текста импортировать Any
from langgraph.store.memory import InMemoryStore
from langchain.agents import create_agent
from langchain.tools import tool, ToolRuntime


# Доступ к памяти
@инструмент
def get_user_info(user_id: str, runtime: ToolRuntime) -> str:
    «Поиск информации о пользователе».
    store = runtime.store
    user_info = store.get(("users",), user_id)
    return str(user_info.value) if user_info else "Неизвестный пользователь"

# Обновление памяти
@инструмент
def save_user_info(user_id: str, user_info: dict[str, Any], runtime: ToolRuntime) -> str:
    """Сохранить информацию о пользователе."""
    store = runtime.store
    store.put(("users",), user_id, user_info)
    return "Информация о пользователе успешно сохранена."

store = InMemoryStore()
агент = create_agent(
    модель,
    tools=[get_user_info, save_user_info],
    магазин=магазин
)

# Первая сессия: сохранение информации о пользователе
agent.invoke({
    "messages": [{"role": "user", "content": "Сохранить следующего пользователя: userid: abc123, name: Foo, age: 25, email: foo@langchain.dev"}]
})

# Вторая сессия: получение информации о пользователе
agent.invoke({
    "messages": [{"role": "user", "content": "Получить информацию о пользователе с идентификатором 'abc123'"}]
})
# Вот информация о пользователе с ID "abc123":
# - Имя: Фу
# - Возраст: 25
# - Электронная почта: foo@langchain.dev
```

#### Автор потока

Используйте `runtime.stream_writer` для потоковой передачи пользовательских обновлений из инструментов по мере их выполнения. Это полезно для предоставления пользователям обратной связи в реальном времени о том, что делает инструмент.

```python theme={null}
from langchain.tools import tool, ToolRuntime

@инструмент
def get_weather(city: str, runtime: ToolRuntime) -> str:
    «Получите информацию о погоде для конкретного города».
    writer = runtime.stream_writer

    # Передача пользовательских обновлений в потоке во время выполнения инструмента
    writer(f"Поиск данных для города: {city}")
    writer(f"Получены данные для города: {city}")

    return f"В {городе} всегда солнечно!"
```

<Примечание>
  Если вы используете `runtime.stream_writer` внутри своего инструмента, инструмент должен быть вызван в контексте выполнения LangGraph. Дополнительные сведения см. в разделе [Streaming](/oss/python/langchain/streaming).
</Примечание>
