# Кратковременная память

## Обзор

Память — это система, которая запоминает информацию о предыдущих взаимодействиях. Для агентов искусственного интеллекта память имеет решающее значение, поскольку позволяет им запоминать предыдущие взаимодействия, учиться на основе обратной связи и адаптироваться к предпочтениям пользователя. По мере того, как агенты решают более сложные задачи с многочисленными взаимодействиями с пользователем, эта способность становится важной как для эффективности, так и для удовлетворенности пользователя.

Кратковременная память позволяет вашему приложению запоминать предыдущие взаимодействия в рамках одной ветки обсуждения или диалога.

<Примечание>
  Ветка обсуждений организует множество взаимодействий в рамках одной сессии, подобно тому, как электронная почта группирует сообщения в одной переписке.
</Примечание>

История разговоров — наиболее распространенная форма кратковременной памяти. Длительные разговоры представляют собой проблему для современных программ долговременной памяти; полная история может не уместиться в контекстное окно программы, что приводит к потере контекста или ошибкам.

Даже если ваша модель поддерживает полную длину контекста, большинство моделей с длинной структурой контекста по-прежнему плохо работают с длинными контекстами. Они «отвлекаются» на устаревший или не относящийся к теме контент, при этом страдая от более медленного времени отклика и более высоких затрат.

Модели чата принимают контекст с помощью [сообщений](/oss/python/langchain/messages), которые включают инструкции (системное сообщение) и входные данные (сообщения от людей). В чат-приложениях сообщения чередуются между вводом от людей и ответами модели, в результате чего список сообщений со временем становится длиннее. Поскольку контекстные окна ограничены, многие приложения могут извлечь выгоду из использования методов удаления или «забывания» устаревшей информации.

## Использование

Для добавления кратковременной памяти (постоянства на уровне потоков) к агенту необходимо указать контрольную точку (checkpointer) при создании агента.

<Информация>
  Агент LangChain управляет кратковременной памятью как частью состояния вашего агента.

  Сохраняя эти данные в состоянии графа, агент может получить доступ к полному контексту конкретного разговора, сохраняя при этом разделение между различными потоками.

  Состояние сохраняется в базе данных (или в памяти) с помощью контрольной точки, поэтому поток можно возобновить в любой момент.

  Кратковременная память обновляется при вызове агента или завершении шага (например, вызова инструмента), а состояние считывается в начале каждого шага.
</Info>

```python theme={null}
from langchain.agents import create_agent
from langgraph.checkpoint.memory import InMemorySaver # [!code highlight]


агент = create_agent(
    "gpt-5",
    инструменты=[get_user_info],
    checkpointer=InMemorySaver(), # [!code highlight]
)

agent.invoke(
    {"messages": [{"role": "user", "content": "Привет! Меня зовут Боб."}]},
    {"configurable": {"thread_id": "1"}}, # [!code highlight]
)
```

## Настройка памяти агента

По умолчанию агенты используют [`AgentState`](https://reference.langchain.com/python/langchain/agents/#langchain.agents.AgentState) для управления кратковременной памятью, а именно историей разговоров, через ключ `messages`.

Вы можете расширить [`AgentState`](https://reference.langchain.com/python/langchain/agents/#langchain.agents.AgentState), чтобы добавить дополнительные поля. Пользовательские схемы состояний передаются в [`create_agent`](https://reference.langchain.com/python/langchain/agents/#langchain.agents.create_agent) с помощью параметра [`state_schema`](https://reference.langchain.com/python/langchain/middleware/#langchain.agents.middleware.AgentMiddleware.state_schema).

```python theme={null}
from langchain.agents import create_agent, AgentState
from langgraph.checkpoint.memory import InMemorySaver


class CustomAgentState(AgentState): # [!выделение кода]
    user_id: str # [!code highlight]
    Настройки: словарь # [!подсветка кода]

агент = create_agent(
    "gpt-5",
    инструменты=[get_user_info],
    state_schema=CustomAgentState, # [!code highlight]
    checkpointer=InMemorySaver(),
)

# Пользовательское состояние можно передать при вызове
результат = agent.invoke(
    {
        "messages": [{"role": "user", "content": "Hello"}],
        "user_id": "user_123", # [!code highlight]
        "preferences": {"theme": "dark"} # [!code highlight]
    },
    {"configurable": {"thread_id": "1"}})
```

### Удаление сообщений

Большинство LLM-модулей имеют максимальное поддерживаемое контекстное окно (выраженное в токенах).

Один из способов определить, когда следует обрезать сообщения, — это подсчитать количество токенов в истории сообщений и обрезать их всякий раз, когда они приближаются к этому пределу. Если вы используете LangChain, вы можете воспользоваться утилитой trim messages и указать количество токенов, которые следует сохранить из списка, а также стратегию (например, сохранить последние `max_tokens`), используемую для обработки границы.

Для обрезки истории сообщений в агенте используйте декоратор промежуточного ПО [`@before_model`](https://reference.langchain.com/python/langchain/middleware/#langchain.agents.middleware.before_model):

```python theme={null}
from langchain.messages import RemoveMessage
from langgraph.graph.message import REMOVE_ALL_MESSAGES
from langgraph.checkpoint.memory import InMemorySaver
from langchain.agents import create_agent, AgentState
from langchain.agents.middleware import before_model
from langgraph.runtime import Runtime
from langchain_core.runnables import RunnableConfig
из набора текста импортировать Any


@before_model
def trim_messages(state: AgentState, runtime: Runtime) -> dict[str, Any] | None:
    «Оставляйте только последние несколько сообщений, чтобы они помещались в контекстное окно».
    сообщения = состояние["сообщения"]

    если len(messages) <= 3:
        return None # Изменения не требуются

    first_msg = messages[0]
    recent_messages = messages[-3:] if len(messages) % 2 == 0 else messages[-4:]
    новые_сообщения = [первое_сообщение] + недавние_сообщения

    возвращаться {
        "сообщения": [
            RemoveMessage(id=REMOVE_ALL_MESSAGES),
            *новые_сообщения
        ]
    }

агент = create_agent(
    ваша_модель_здесь,
    tools=your_tools_here,
    middleware=[trim_messages],
    checkpointer=InMemorySaver(),
)

config: RunnableConfig = {"configurable": {"thread_id": "1"}}

agent.invoke({"messages": "привет, меня зовут Боб"}, config)
agent.invoke({"messages": "напишите короткое стихотворение о кошках"}, config)
agent.invoke({"messages": "теперь сделайте то же самое, но для собак"}, config)
final_response = agent.invoke({"messages": "Как меня зовут?"}, config)

final_response["messages"][-1].pretty_print()
"""
================================ Сообщение Ai ================================

Вас зовут Боб. Вы мне это сказали раньше.
Если вы хотите, чтобы я называл вас прозвищем или использовал другое имя, просто скажите это.
"""
```

### Удалить сообщения

Для управления историей сообщений можно удалять сообщения из состояния графа.

Это полезно, когда вы хотите удалить определенные сообщения или очистить всю историю сообщений.

Для удаления сообщений из состояния графа можно использовать функцию `RemoveMessage`.

Для работы функции `RemoveMessage` необходимо использовать ключ состояния с [`add_messages`](https://reference.langchain.com/python/langgraph/graphs/#langgraph.graph.message.add_messages) [reducer](/oss/python/langgraph/graph-api#reducers).

Это обеспечивается значением по умолчанию [`AgentState`](https://reference.langchain.com/python/langchain/agents/#langchain.agents.AgentState).

Чтобы удалить определенные сообщения:

```python theme={null}
from langchain.messages import RemoveMessage # [!code highlight]

def delete_messages(state):
    сообщения = состояние["сообщения"]
    если длина сообщений > 2:
        # удалить два самых ранних сообщения
        return {"messages": [RemoveMessage(id=m.id) for m in messages[:2]]} # [!code highlight]
```

Чтобы удалить **все** сообщения:

```python theme={null}
from langgraph.graph.message import REMOVE_ALL_MESSAGES # [!code highlight]

def delete_messages(state):
    return {"messages": [RemoveMessage(id=REMOVE_ALL_MESSAGES)]} # [!code highlight]
```

<Предупреждение>
  При удалении сообщений **убедитесь**, что полученная история сообщений является корректной. Проверьте ограничения используемого вами поставщика LLM. Например:

  * Некоторые провайдеры ожидают, что история сообщений будет начинаться с сообщения от пользователя.
  * Большинство поставщиков услуг требуют, чтобы сообщения `assistant`, содержащие вызовы инструментов, сопровождались соответствующими сообщениями с результатами выполнения команды `tool`.
</Предупреждение>

```python theme={null}

from langchain.agents import create_agent, AgentState

config: RunnableConfig = {"configurable": {"thread_id": "1"}}
```

### Сводка сообщений

Проблема с обрезкой или удалением сообщений, как показано выше, заключается в том, что вы можете потерять информацию в результате очистки очереди сообщений.
Поэтому в некоторых приложениях более эффективный подход заключается в обобщении истории сообщений с использованием модели чата.

Для суммирования истории сообщений в агенте используйте встроенную функцию [`SummarizationMiddleware`](/oss/python/langchain/middleware#summarization):

```python theme={null}
from langchain.agents import create_agent
from langchain.agents.middleware import SummarizationMiddleware
from langgraph.checkpoint.memory import InMemorySaver
from langchain_core.runnables import RunnableConfig


checkpointer = InMemorySaver()

агент = create_agent(
    model="gpt-4.1",
    инструменты=[],
    промежуточное ПО=[
        SummarizationMiddleware(
            model="gpt-4.1-mini",
            trigger=("tokens", 4000),
            keep=("messages", 20)
        )
    ],
    checkpointer=checkpointer,
)

config: RunnableConfig = {"configurable": {"thread_id": "1"}}
agent.invoke({"messages": "привет, меня зовут Боб"}, config)
agent.invoke({"messages": "напишите короткое стихотворение о кошках"}, config)
agent.invoke({"messages": "теперь сделайте то же самое, но для собак"}, config)
final_response = agent.invoke({"messages": "Как меня зовут?"}, config)

final_response["messages"][-1].pretty_print()
"""
================================ Сообщение Ai ================================

Вас зовут Боб!
"""
```

## Доступ к памяти

Доступ к кратковременной памяти (состоянию) агента и его изменение возможны несколькими способами:

### Инструменты

#### Чтение кратковременной памяти в инструменте

Для доступа к кратковременной памяти (состоянию) инструмента используйте параметр `runtime` (тип `ToolRuntime`).

Параметр `runtime` скрыт в сигнатуре инструмента (поэтому модель его не видит), но инструмент может получить доступ к состоянию через него.

```python theme={null}
from langchain.agents import create_agent, AgentState
from langchain.tools import tool, ToolRuntime


class CustomState(AgentState):
    user_id: str

@инструмент
def get_user_info(
    среда выполнения: ToolRuntime
) -> str:
    «Поиск информации о пользователе».
    user_id = runtime.state["user_id"]
    Если user_id == "user_123", вернуть "Пользователь - Джон Смит", иначе "Неизвестный пользователь".

агент = create_agent(
    model="gpt-5-nano",
    инструменты=[get_user_info],
    state_schema=CustomState,
)

результат = agent.invoke({
    "сообщения": "поиск информации о пользователе",
    "user_id": "user_123"
})
print(result["messages"][-1].content)
# > Пользователь — Джон Смит.
```

#### Запись данных из инструментов в кратковременную память

Для изменения кратковременной памяти (состояния) агента во время выполнения можно получать обновления состояния непосредственно из инструментов.

Это полезно для сохранения промежуточных результатов или обеспечения доступа к информации для последующих инструментов или запросов.

```python theme={null}
from langchain.tools import tool, ToolRuntime
from langchain_core.runnables import RunnableConfig
from langchain.messages import ToolMessage
from langchain.agents import create_agent, AgentState
from langgraph.types import Command
from pydantic import BaseModel


class CustomState(AgentState): # [!code highlight]
    имя_пользователя: строка

class CustomContext(BaseModel):
    user_id: str

@инструмент
def update_user_info(
    среда выполнения: ToolRuntime[CustomContext, CustomState],
) -> Команда:
    «Найдите и обновите информацию о пользователе».
    user_id = runtime.context.user_id
    name = "John Smith" if user_id == "user_123" else "Unknown user"
    return Command(update={ # [!code highlight]
        "user_name": имя,
        # Обновить историю сообщений
        "сообщения": [
            ToolMessage(
                "Информация о пользователе успешно найдена",
                tool_call_id=runtime.tool_call_id
            )
        ]
    })

@инструмент
def greet(
    среда выполнения: ToolRuntime[CustomContext, CustomState]
) -> str | Команда:
    """Используйте это для приветствия пользователя после того, как найдете его данные."""
    user_name = runtime.state.get("user_name", None)
    если user_name равно None:
       return Command(update={
            "сообщения": [
                ToolMessage(
                    "Пожалуйста, вызовите инструмент 'update_user_info', он получит и обновит имя пользователя."
                    tool_call_id=runtime.tool_call_id
                )
            ]
        })
    return f"Привет, {имя_пользователя}!"

агент = create_agent(
    model="gpt-5-nano",
    tools=[update_user_info, greet],
    state_schema=CustomState, # [!code highlight]
    context_schema=CustomContext,
)

agent.invoke(
    {"messages": [{"role": "user", "content": "greet the user"}]},
    context=CustomContext(user_id="user_123"),
)
```
