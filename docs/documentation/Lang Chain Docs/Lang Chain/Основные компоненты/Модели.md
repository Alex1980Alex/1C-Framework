# Модели

LLM-модели — это мощные инструменты искусственного интеллекта, способные интерпретировать и генерировать текст подобно людям. Они достаточно универсальны, чтобы создавать контент, переводить языки, делать обобщения и отвечать на вопросы, не требуя специального обучения для каждой задачи.

Помимо генерации текста, многие модели поддерживают:

* <Icon icon="hammer" size={16} /> [Вызов инструментов](#tool-calling) - вызов внешних инструментов (например, запросов к базам данных или вызовов API) и использование результатов в их ответах.
* <Icon icon="shapes" size={16} /> [Структурированный вывод](#structured-output) - где ответ модели ограничен определенным форматом.
* <Icon icon="image" size={16} /> [Мультимодальность](#multimodal) - обработка и возврат данных, отличных от текста, таких как изображения, аудио и видео.
* <Icon icon="brain" size={16} /> [Рассуждение](#рассуждение) - модели выполняют многоэтапное рассуждение, чтобы прийти к выводу.

Модели являются движущей силой рассуждений [агентов](/oss/python/langchain/agents). Они управляют процессом принятия решений агентом, определяя, какие инструменты использовать, как интерпретировать результаты и когда дать окончательный ответ.

Качество и возможности выбранной вами модели напрямую влияют на базовую надежность и производительность вашего агента. Разные модели лучше справляются с разными задачами — одни лучше выполняют сложные инструкции, другие лучше подходят для структурированного мышления, а третьи поддерживают более широкие контекстные окна для обработки большего объема информации.

Стандартные интерфейсы моделей LangChain предоставляют доступ ко множеству различных интеграций с поставщиками, что упрощает экспериментирование и переключение между моделями для поиска оптимального варианта для ваших задач.

<Информация>
  Для получения информации об интеграции и возможностях конкретного поставщика услуг, см. страницу [модели чата](/oss/python/integrations/chat) этого поставщика.
</Info>

## Основные правила использования

Модели можно использовать двумя способами:

1. **С агентами** - Модели могут быть динамически заданы при создании [агента](/oss/python/langchain/agents#model).
2. **Автономный режим** — Модели можно вызывать напрямую (вне цикла работы агента) для таких задач, как генерация текста, классификация или извлечение информации, без необходимости использования агентской платформы.

Один и тот же интерфейс модели работает в обоих контекстах, что дает вам гибкость для начала работы с простыми задачами и масштабирования до более сложных рабочих процессов на основе агентов по мере необходимости.

## Параметры

Модель чата принимает параметры, которые можно использовать для настройки её поведения. Полный набор поддерживаемых параметров различается в зависимости от модели и поставщика, но стандартные параметры включают:

<ParamField body="model" type="string" required>
  Имя или идентификатор конкретной модели, которую вы хотите использовать с поставщиком. Вы также можете указать как модель, так и ее поставщик в одном аргументе, используя формат '{model_provider}:{model}', например, 'openai:o1'.
</ParamField>

<ParamField body="api_key" type="string">
  Ключ, необходимый для аутентификации у поставщика модели. Обычно он выдается при регистрации для доступа к модели. Часто доступ к нему осуществляется путем установки переменной среды.
</ParamField>

<ParamField body="temperature" type="number">
  Управляет степенью случайности выходных данных модели. Большее значение делает ответы более креативными; меньшее — более детерминированными.
</ParamField>

<ParamField body="max_tokens" type="number">
  Ограничивает общее количество токенов <Tooltip tip="Базовая единица, которую модель считывает и генерирует. Поставщики могут определять их по-разному, но в общем случае они могут представлять целое слово или его часть." в ответе, фактически контролируя длину выходных данных.
</ParamField>

<ParamField body="timeout" type="number">
  Максимальное время (в секундах), в течение которого следует ожидать ответа от модели перед отменой запроса.
</ParamField>

<ParamField body="max_retries" type="number">
  Максимальное количество попыток, которые система предпримет для повторной отправки запроса в случае неудачи из-за таких проблем, как тайм-аут сети или ограничения скорости.
</ParamField>

Используя [`init_chat_model`](https://reference.langchain.com/python/langchain/models/#langchain.chat_models.init_chat_model), передайте эти параметры в виде встроенных <Tooltip tip="Произвольные аргументы ключевых слов" cta="Узнать больше" href="https://www.w3schools.com/python/python_args_kwargs.asp">`**kwargs`</Tooltip>:

```Инициализация Python с использованием параметров модели theme={null}
модель = init_chat_model(
    "claude-sonnet-4-5-20250929",
    # Аргументы, переданные модели:
    температура = 0,7,
    timeout=30,
    max_tokens=1000,
)
```

<Информация>
  Каждая интеграция модели чата может иметь дополнительные параметры, используемые для управления функциональностью, специфичной для конкретного поставщика услуг.

  Например, в [`ChatOpenAI`](https://reference.langchain.com/python/integrations/langchain_openai/ChatOpenAI) есть параметр `use_responses_api`, который определяет, следует ли использовать API ответов OpenAI или API завершения.

</Info>

## Призыв

Для генерации выходных данных необходимо вызвать модель чата. Существует три основных метода вызова, каждый из которых подходит для разных сценариев использования.

### Вызов

Самый простой способ вызвать модель — использовать [`invoke()`](https://reference.langchain.com/python/langchain_core/language_models/#langchain_core.language_models.chat_models.BaseChatModel.invoke) с одним сообщением или списком сообщений.

```python Тема одного сообщения={null}
response = model.invoke("Почему у попугаев такие разноцветные перья?")
print(response)
```

В модель чата можно передать список сообщений, представляющих историю переписки. Каждое сообщение имеет роль, которую модель использует для указания отправителя сообщения в ходе беседы.

Более подробную информацию о ролях, типах и содержимом см. в руководстве [messages](/oss/python/langchain/messages).

```python Dictionary format theme={null}
разговор = [
    {"role": "system", "content": "Вы — полезный помощник, который переводит с английского на французский."},
    {"role": "user", "content": "Translate: I love programming."},
    {"role": "ассистент", "content": "Я обожаю программирование."},
    {"role": "user", "content": "Translate: Я люблю создавать приложения."}
]

response = model.invoke(conversation)
print(response) # AIMessage("Я люблю создавать приложения.")
```

```python Message objects theme={null}
из langchain.messages импортируйте HumanMessage, AIMessage, SystemMessage

разговор = [
    SystemMessage("Вы — полезный помощник, который переводит с английского на французский."),
    HumanMessage("Перевод: Я люблю программирование."),
    AIMessage("Обожаю программирование."),
    HumanMessage("Перевод: Я люблю создавать приложения.")
]

response = model.invoke(conversation)
print(response) # AIMessage("Я люблю создавать приложения.")
```

<Информация>
  Если тип возвращаемого значения вашего вызова — строка, убедитесь, что вы используете модель чата, а не LLM. Устаревшие LLM с автодополнением текста возвращают строки напрямую. Модели чата LangChain имеют префикс "Chat", например, [`ChatOpenAI`](https://reference.langchain.com/python/integrations/langchain_openai/ChatOpenAI)(/oss/integrations/chat/openai).
</Info>

### Транслировать

Большинство моделей могут передавать свой выходной контент в режиме реального времени во время его генерации. Поэтапное отображение выходного контента значительно улучшает пользовательский опыт, особенно при обработке длинных ответов.

Вызов функции [`stream()`](https://reference.langchain.com/python/langchain_core/language_models/#langchain_core.language_models.chat_models.BaseChatModel.stream) возвращает итератор, который по мере создания выдает фрагменты данных. Для обработки каждого фрагмента в режиме реального времени можно использовать цикл:

<CodeGroup>
  ```python Basic text streaming theme={null}
  for chunk in model.stream("Почему у попугаев такие разноцветные перья?"):
      print(chunk.text, end="|", flush=True)
  ```

  ```Вызовы инструмента Stream в Python, обоснование и прочий контент theme={null}
  for chunk in model.stream("Какого цвета небо?"):
      for block in chunk.content_blocks:
          if block["type"] == "reasoning" and (reasoning := block.get("reasoning")):
              print(f"Рассуждение: {рассуждение}")
          elif block["type"] == "tool_call_chunk":
              print(f"Фрагмент вызова инструмента: {блок}")
          elif block["type"] == "text":
              print(block["text"])
          еще:
              ...
  ```
</CodeGroup>

В отличие от функции `invoke()` (#invoke), которая возвращает один объект `AIMessage` (https://reference.langchain.com/python/langchain/messages/#langchain.messages.AIMessage) после того, как модель завершила генерацию полного ответа, функция `stream()` возвращает несколько объектов `AIMessageChunk` (https://reference.langchain.com/python/langchain/messages/#langchain.messages.AIMessageChunk), каждый из которых содержит часть выходного текста. Важно отметить, что каждый фрагмент в потоке предназначен для объединения в полное сообщение путем суммирования:

```python Создать тему AIMessage={null}
полный = Нет # Нет | AIMessageChunk
for chunk in model.stream("Какого цвета небо?"):
    полный = фрагмент, если полный равен None, иначе полный + фрагмент
    print(full.text)

# The
# Небо
Небо
# Небо обычно
# Небо обычно голубое
# ...

print(full.content_blocks)
# [{"type": "text", "text": "Небо обычно голубое..."}]
```

Полученное сообщение можно обрабатывать так же, как и сообщение, сгенерированное с помощью [`invoke()`](#invoke) – например, его можно объединить в историю сообщений и передать обратно в модель в качестве контекста разговора.

<Предупреждение>
  Потоковая обработка работает только в том случае, если все этапы программы умеют обрабатывать поток фрагментов данных. Например, приложение, не поддерживающее потоковую обработку, должно хранить весь вывод в памяти до его обработки.
</Предупреждение>

    LangChain упрощает потоковую передачу данных из моделей чата, автоматически включая потоковый режим в определенных случаях, даже если вы явно не вызываете методы потоковой передачи. Это особенно полезно, когда вы используете метод вызова без потоковой передачи, но все же хотите передавать данные всего приложения, включая промежуточные результаты из модели чата.

    Например, в [агентах LangGraph](/oss/python/langchain/agents) вы можете вызывать `model.invoke()` внутри узлов, но LangChain автоматически будет делегировать вызов потоковой обработке, если работает в потоковом режиме.

    #### Как это работает

    При вызове функции `invoke()` модели чата LangChain автоматически переключится во внутренний потоковый режим, если обнаружит попытку потоковой передачи всего приложения. Результат вызова будет тем же с точки зрения кода, который использовал `invoke`; однако, пока модель чата передается в потоковом режиме, LangChain позаботится об вызове событий [`on_llm_new_token`](https://reference.langchain.com/python/langchain_core/callbacks/#langchain_core.callbacks.base.AsyncCallbackHandler.on_llm_new_token) в системе обратных вызовов LangChain.

    События обратного вызова позволяют функциям `stream()` и `astream_events()` в LangGraph отображать выходные данные модели чата в режиме реального времени.
  </Аккордеон>
</Аккордеон>

### Партия

Объединение набора независимых запросов к модели в пакеты может значительно повысить производительность и снизить затраты, поскольку обработка может выполняться параллельно:

```python Batch theme={null}
ответы = модель.пакет([
    «Почему у попугаев такие яркие перья?»
    «Как летают самолеты?»
    «Что такое квантовые вычисления?»
])
для ответа в ответах:
    print(response)
```

<Примечание>
  В этом разделе описывается метод модели чата [`batch()`](https://reference.langchain.com/python/langchain_core/language_models/#langchain_core.language_models.chat_models.BaseChatModel.batch), который распараллеливает вызовы модели на стороне клиента.

  Это **отличается** от пакетных API, поддерживаемых поставщиками услуг вывода, такими как [OpenAI](https://platform.openai.com/docs/guides/batch) или [Anthropic](https://platform.claude.com/docs/en/build-with-claude/batch-processing#message-batches-api).
</Примечание>

По умолчанию функция [`batch()`](https://reference.langchain.com/python/langchain_core/language_models/#langchain_core.language_models.chat_models.BaseChatModel.batch) возвращает только итоговый результат для всего пакета. Если вы хотите получать результат для каждого отдельного входного параметра по мере его генерации, вы можете передавать результаты потоком с помощью функции [`batch_as_completed()`](https://reference.langchain.com/python/langchain_core/language_models/#langchain_core.language_models.chat_models.BaseChatModel.batch_as_completed):

```python Выдавать пакетные ответы по завершении theme={null}
for response in model.batch_as_completed([
    «Почему у попугаев такие яркие перья?»
    «Как летают самолеты?»
    «Что такое квантовые вычисления?»
]):
    print(response)
```

<Примечание>
  При использовании функции [`batch_as_completed()`](https://reference.langchain.com/python/langchain_core/language_models/#langchain_core.language_models.chat_models.BaseChatModel.batch_as_completed) результаты могут поступать в неправильном порядке. Каждый результат включает входной индекс для сопоставления, чтобы восстановить исходный порядок по мере необходимости.
</Примечание>

<Совет>
  При обработке большого количества входных данных с помощью функций [`batch()`](https://reference.langchain.com/python/langchain_core/language_models/#langchain_core.language_models.chat_models.BaseChatModel.batch) или [`batch_as_completed()`](https://reference.langchain.com/python/langchain_core/language_models/#langchain_core.language_models.chat_models.BaseChatModel.batch_as_completed) может потребоваться ограничить максимальное количество параллельных вызовов. Это можно сделать, установив атрибут [`max_concurrency`](https://reference.langchain.com/python/langchain_core/runnables/#langchain_core.runnables.RunnableConfig.max_concurrency) в словаре [`RunnableConfig`](https://reference.langchain.com/python/langchain_core/runnables/#langchain_core.runnables.RunnableConfig).

  ```Пакетная обработка Python с максимальным количеством параллельных вызовов theme={null}
  model.batch(
      список_входов,
      config={
          'max_concurrency': 5, # Ограничение до 5 параллельных вызовов
      }
  )
  ```

  Полный список поддерживаемых атрибутов см. в справочнике [`RunnableConfig`](https://reference.langchain.com/python/langchain_core/runnables/#langchain_core.runnables.RunnableConfig).
</Совет>

Для получения более подробной информации о пакетной обработке см. [справочник](https://reference.langchain.com/python/langchain_core/language_models/#langchain_core.language_models.chat_models.BaseChatModel.batch).

## Вызов инструмента

Модели могут запрашивать вызов инструментов, выполняющих такие задачи, как получение данных из базы данных, поиск в интернете или выполнение кода. Инструменты представляют собой пары:

1. Схема, включающая название инструмента, описание и/или определения аргументов (часто это JSON-схема).
2. Функция или сопрограмма для выполнения.

<Примечание>
  Вы можете услышать термин «вызов функции». Мы используем его как синоним термина «вызов инструмента».
</Примечание>

Вот базовая схема взаимодействия между пользователем и моделью при вызове инструментов:

```тема русалки={null}
диаграмма последовательности
    участник U как пользователь
    участник М как модель
    участник Т как Инструменты

    U->>M: "Какая погода в Сан-Франциско и Нью-Йорке?"
    M->>M: Проанализировать запрос и определить необходимые инструменты.

    par Параллельные вызовы инструментов
        M->>T: get_weather("Сан-Франциско")
        M->>T: get_weather("Нью-Йорк")
    конец

    par Выполнение инструмента
        T-->>M: Данные о погоде в Сан-Франциско
        T-->>M: Данные о погоде в Нью-Йорке
    конец

    M->>M: Обработка результатов и формирование ответа
    M->>U: "Сан-Франциско: 72°F солнечно, Нью-Йорк: 68°F облачно"
```

Чтобы сделать инструменты, определенные вами, доступными для использования моделью, необходимо связать их с помощью [`bind_tools`](https://reference.langchain.com/python/langchain_core/language_models/#langchain_core.language_models.chat_models.BaseChatModel.bind_tools). При последующих вызовах модель сможет вызывать любые из связанных инструментов по мере необходимости.

Некоторые поставщики моделей предлагают встроенные инструменты, которые можно включить с помощью параметров модели или вызова (например, [`ChatOpenAI`](/oss/python/integrations/chat/openai), [`ChatAnthropic`](/oss/python/integrations/chat/anthropic)). Для получения подробной информации см. соответствующий [справочник поставщика](/oss/python/integrations/providers/overview).

<Совет>
  Подробности и другие параметры создания инструментов см. в [руководстве по инструментам](/oss/python/langchain/tools).
</Совет>

```python Binding user tools theme={null}
from langchain.tools import tool

@инструмент
def get_weather(location: str) -> str:
    «Узнайте прогноз погоды в выбранном месте».
    return f"В {местоположение} солнечно."


model_with_tools = model.bind_tools([get_weather]) # [!code highlight]

response = model_with_tools.invoke("Какая погода в Бостоне?")
for tool_call in response.tool_calls:
    # Вызовы инструмента просмотра, выполняемые моделью
    print(f"Инструмент: {tool_call['name']}")
    print(f"Аргументы: {tool_call['args']}")
```

При привязке пользовательских инструментов ответ модели включает **запрос** на выполнение инструмента. При использовании модели отдельно от [агента](/oss/python/langchain/agents) вам необходимо выполнить запрошенный инструмент и вернуть результат модели для использования в последующих рассуждениях. При использовании [агента](/oss/python/langchain/agents) цикл агента будет обрабатывать цикл выполнения инструмента за вас.

Ниже мы покажем несколько распространенных способов использования вызова инструментов.

<AccordionGroup>
  <Заголовок аккордеона="Цикл выполнения инструмента" значок="стрелка-поворот-вправо">
    Когда модель возвращает вызовы инструментов, необходимо выполнить эти инструменты и передать результаты обратно модели. Это создает цикл взаимодействия, в котором модель может использовать результаты выполнения инструментов для генерации своего окончательного ответа. LangChain включает в себя абстракции [agent](/oss/python/langchain/agents), которые управляют этим процессом.

    Вот простой пример того, как это сделать:

    ```python Tool execution loop theme={null}
    # Привязка (возможно, нескольких) инструментов к модели
    model_with_tools = model.bind_tools([get_weather])

    # Шаг 1: Модель генерирует вызовы инструментов
    сообщения = [{"role": "user", "content": "Какая погода в Бостоне?"}]
    ai_msg = model_with_tools.invoke(messages)
    messages.append(ai_msg)

    # Шаг 2: Запустите инструменты и соберите результаты
    for tool_call in ai_msg.tool_calls:
        # Запустите инструмент с сгенерированными аргументами
        tool_result = get_weather.invoke(tool_call)
        messages.append(tool_result)

    # Шаг 3: Передайте результаты обратно в модель для получения окончательного ответа
    final_response = model_with_tools.invoke(messages)
    print(final_response.text)
    # "В Бостоне сейчас 72°F (22°C) и солнечно."
    ```

    Каждый [`ToolMessage`](https://reference.langchain.com/python/langchain/messages/#langchain.messages.ToolMessage), возвращаемый инструментом, содержит `tool_call_id`, соответствующий исходному вызову инструмента, что помогает модели сопоставлять результаты с запросами.
  </Аккордеон>

  <Заголовок аккордеона="Принудительные вызовы инструментов" значок="звездочка">
    По умолчанию модель имеет возможность выбирать, какой из связанных инструментов использовать, на основе ввода пользователя. Однако вы можете захотеть принудительно выбрать инструмент, гарантируя, что модель будет использовать либо определенный инструмент, либо **любой** инструмент из заданного списка:

    <CodeGroup>
      ```python Принудительное использование любой темы инструментов={null}
      model_with_tools = model.bind_tools([tool_1], tool_choice="any")
      ```

      ```python Принудительное использование определенных инструментов theme={null}
      model_with_tools = model.bind_tools([tool_1], tool_choice="tool_1")
      ```
    </CodeGroup>
  </Аккордеон>

  <Заголовок аккордеона="Параллельные вызовы инструментов" icon="группа слоев">
    Многие модели поддерживают параллельный вызов нескольких инструментов, когда это необходимо. Это позволяет модели одновременно собирать информацию из разных источников.

    ```python Parallel tool calls theme={null}
    model_with_tools = model.bind_tools([get_weather])

    response = model_with_tools.invoke(
        "Какая погода в Бостоне и Токио?"
    )


    # Модель может генерировать несколько вызовов инструментов
    print(response.tool_calls)
    # [
    # {'name': 'get_weather', 'args': {'location': 'Boston'}, 'id': 'call_1'},
    # {'name': 'get_weather', 'args': {'location': 'Tokyo'}, 'id': 'call_2'},
    # ]


    # Выполнить все инструменты (можно сделать параллельно с помощью асинхронного режима)
    результаты = []
    for tool_call in response.tool_calls:
        если tool_call['name'] == 'get_weather':
            result = get_weather.invoke(tool_call)
        ...
        results.append(result)
    ```

    Модель интеллектуально определяет целесообразность параллельного выполнения, исходя из независимости запрашиваемых операций.

    <Совет>
      Большинство моделей, поддерживающих вызов инструментов, по умолчанию включают параллельные вызовы инструментов. Некоторые (включая [OpenAI](/oss/python/integrations/chat/openai) и [Anthropic](/oss/python/integrations/chat/anthropic)) позволяют отключить эту функцию. Для этого установите `parallel_tool_calls=False`:

      ```python theme={null}
      model.bind_tools([get_weather], parallel_tool_calls=False)
      ```
    </Совет>
  </Аккордеон>

  <Заголовок аккордеона="Вызовы потокового инструмента" icon="rss">
    При потоковой передаче ответов вызовы инструментов формируются постепенно с помощью [`ToolCallChunk`](https://reference.langchain.com/python/langchain/messages/#langchain.messages.ToolCallChunk). Это позволяет видеть вызовы инструментов по мере их генерации, а не ждать полного ответа.

    ```Инструмент потоковой передачи Python вызывает тему={null}

        # Фрагменты вызовов инструментов поступают постепенно
        for tool_chunk in chunk.tool_call_chunks:
            if name := tool_chunk.get("name"):

            if id_ := tool_chunk.get("id"):

            if args := tool_chunk.get("args"):
                print(f"Аргументы: {args}")

    # Выход:
    # Инструмент: get_weather
    # ID: call_SvMlU1TVIZugrFLckFE2ceRE

    # Аргументы: catio
    # Аргументы: n": "B
    # Аргументы: osto
    # Аргументы: n"}
    # Инструмент: get_weather
    # ID: call_QMZdy6qInx13oWKE7KhuhOLR
    # Аргументы: {"lo
    # Аргументы: catio
    # Аргументы: n": "T
    # Аргументы: okyo
    # Аргументы: "}
    ```

## Структурированный вывод

Модели могут запрашивать ответ в формате, соответствующем заданной схеме. Это полезно для обеспечения возможности легкого анализа и использования выходных данных в последующей обработке. LangChain поддерживает несколько типов схем и методов для обеспечения структурированного вывода.

<Совет>
  Чтобы узнать больше о структурированном выводе, см. [Структурированный вывод](/oss/python/langchain/structured-output).
</Совет>

<Вкладки>
  <Tab title="Pydantic">
    Модели Pydantic (https://docs.pydantic.dev/latest/concepts/models/#basic-model-usage) предоставляют самый богатый набор функций, включая проверку полей, описания и вложенные структуры.

    ```python theme={null}
    from pydantic import BaseModel, Field

    class Movie(BaseModel):
        «Фильм, полный деталей».
        заголовок: str = Field(..., description="Название фильма")
        год: int = Field(..., description="Год выхода фильма")
        режиссер: str = Field(..., description="Режиссер фильма")
        рейтинг: float = Field(..., description="Рейтинг фильма по 10-балльной шкале")

    model_with_structure = model.with_structured_output(Movie)
    response = model_with_structure.invoke("Предоставьте подробную информацию о фильме «Начало»)
    print(response) # Movie(title="Начало", year=2010, director="Кристофер Нолан", rating=8.8)
    ```
  </Tab>

  <Tab title="TypedDict">
    Python-библиотека `TypedDict` предоставляет более простую альтернативу моделям Pydantic, идеально подходящую в тех случаях, когда проверка данных во время выполнения не требуется.

    ```python theme={null}
    from typing_extensions import TypedDict, Annotated

    class MovieDict(TypedDict):
        «Фильм, полный деталей».
        title: Annotated[str, ..., "Название фильма"]
        год: Annotated[int, ..., "Год выхода фильма"]
        Режиссер: Аннотированный[str, ..., "Режиссер фильма"]
        рейтинг: Аннотированный[float, ..., "Рейтинг фильма по 10-балльной шкале"]

    model_with_structure = model.with_structured_output(MovieDict)
    response = model_with_structure.invoke("Предоставьте подробную информацию о фильме «Начало»)
    print(response) # {'title': 'Начало', 'year': 2010, 'director': 'Кристофер Нолан', 'rating': 8.8}
    ```
  </Tab>

  <Tab title="JSON Schema">
    Для обеспечения максимального контроля и совместимости предоставьте схему JSON (https://json-schema.org/understanding-json-schema/about).

    ```python theme={null}
    импорт json

    json_schema = {
        "Название": "Фильм",
        «Описание»: «Фильм с подробностями».
        "type": "object",
        "характеристики": {
            "заголовок": {
                "type": "string",
                "описание": "Название фильма"
            },
            "год": {
                "type": "integer",
                «Описание»: «Год выхода фильма»
            },
            "директор": {
                "type": "string",
                «Описание»: «Режиссер фильма»
            },
            "рейтинг": {
                "тип": "номер",
                «Описание»: «Рейтинг фильма по 10-балльной шкале»
            }
        },
        "обязательно": ["название", "год", "режиссер", "рейтинг"]
    }

    model_with_structure = model.with_structured_output(
        json_schema,
        метод="json_schema",
    )
    response = model_with_structure.invoke("Предоставьте подробную информацию о фильме «Начало»)
    print(response) # {'title': 'Начало', 'year': 2010, ...}
    ```
  </Tab>
</Вкладки>

<Примечание>
  **Ключевые моменты, которые следует учитывать при структурировании выходных данных**

  * **Параметр метода**: Некоторые поставщики поддерживают различные методы для структурированного вывода:
    * `'json_schema'`: Использует специальные функции структурированного вывода, предоставляемые поставщиком.
    * `'function_calling'`: Формирует структурированный вывод, принудительно вызывая [инструмент](#tool-calling), соответствующий заданной схеме.
    * `'json_mode'`: Предшественница `'json_schema'`, предлагаемая некоторыми поставщиками. Генерирует корректный JSON, но схема должна быть описана в подсказке.
  * **Включить необработанные данные**: Установите `include_raw=True`, чтобы получить как обработанный вывод, так и необработанное сообщение ИИ.
  * **Проверка**: Модели Pydantic обеспечивают автоматическую проверку. Для `TypedDict` и JSON Schema требуется ручная проверка.

  Информацию о поддерживаемых методах и параметрах конфигурации см. на странице интеграции вашего [провайдера](/oss/python/integrations/providers/overview).
</Примечание>

<Заголовок аккордеона="Пример: вывод сообщения вместе с проанализированной структурой">
  Может быть полезно возвращать исходный объект [`AIMessage`](https://reference.langchain.com/python/langchain/messages/#langchain.messages.AIMessage) вместе с разобранным представлением для доступа к метаданным ответа, таким как [количество токенов](#token-usage). Для этого установите [`include_raw=True`](https://reference.langchain.com/python/langchain_core/language_models/#langchain_core.language_models.chat_models.BaseChatModel.with_structured_output\(include_raw\)) при вызове [`with_structured_output`](https://reference.langchain.com/python/langchain_core/language_models/#langchain_core.language_models.chat_models.BaseChatModel.with_structured_output):

  ```python theme={null}
  from pydantic import BaseModel, Field

  class Movie(BaseModel):
      «Фильм, полный деталей».
      заголовок: str = Field(..., description="Название фильма")
      год: int = Field(..., description="Год выхода фильма")
      режиссер: str = Field(..., description="Режиссер фильма")
      рейтинг: float = Field(..., description="Рейтинг фильма по 10-балльной шкале")

  model_with_structure = model.with_structured_output(Movie, include_raw=True) # [!code highlight]
  response = model_with_structure.invoke("Предоставьте подробную информацию о фильме «Начало»)
  ответ
  # {
  # "raw": AIMessage(...),
  # "parsed": Movie(title=..., year=..., ...),
  # "parsing_error": None,
  # }
  ```
</Аккордеон>

  <CodeGroup>

### Профили моделей

<Информация>
  Для создания профилей моделей требуется `langchain>=1.1`.
</Info>

Модели чата LangChain могут предоставлять словарь поддерживаемых функций и возможностей через атрибут `.profile`:

```python theme={null}
модель.профиль
# {
# "max_input_tokens": 400000,
# "image_inputs": True,
# "reasoning_output": True,
# "tool_calling": True,
# ...
# }
```

Полный набор полей см. в [справочнике API](https://reference.langchain.com/python/langchain_core/language_models/#langchain_core.language_models.BaseChatModel.profile).

Большая часть данных профиля модели основана на проекте [models.dev](https://github.com/sst/models.dev), инициативе с открытым исходным кодом, которая предоставляет данные о возможностях модели. Эти данные дополняются дополнительными полями для использования с LangChain. Эти дополнения постоянно согласуются с исходным проектом по мере его развития.

Данные профиля модели позволяют приложениям динамически обходить ограничения модели. Например:

1. [Промежуточное ПО для суммирования](/oss/python/langchain/middleware/built-in#summarization) может запускать суммирование на основе размера контекстного окна модели.
2. Стратегии [структурированного вывода](/oss/python/langchain/structured-output) в `create_agent` могут быть определены автоматически (например, путем проверки поддержки собственных функций структурированного вывода).
3. Входные данные модели могут быть ограничены в зависимости от поддерживаемых [модальностей](#мультимодальных) и максимального количества входных токенов.

<Заголовок аккордеона="Обновление или перезапись данных профиля">
  Данные профиля модели могут быть изменены, если они отсутствуют, устарели или некорректны.

  **Вариант 1 (быстрое решение)**

  Вы можете создать экземпляр модели чата с любым допустимым профилем:

  ```python theme={null}
  custom_profile = {
      "max_input_tokens": 100_000,
      "tool_calling": True,
      "structured_output": True,
      # ...
  }
  model = init_chat_model("...", profile=custom_profile)
  ```

  `profile` также представляет собой обычный `dict` и может быть обновлен на месте. Если экземпляр модели является общим, рекомендуется использовать `model_copy`, чтобы избежать изменения общего состояния.

  ```python theme={null}
  new_profile = model.profile | {"key": "value"}
  model.model_copy(update={"profile": new_profile})
  ```

  **Вариант 2 (исправление данных в вышестоящем источнике)**

  Основным источником данных является проект [models.dev](https://models.dev/). Эти данные объединяются с дополнительными полями и переопределениями в пакетах интеграции LangChain [/oss/python/integrations/providers/overview] и поставляются вместе с этими пакетами.

  Обновление данных профиля модели может осуществляться следующим образом:

  1. (При необходимости) обновите исходные данные на [models.dev](https://models.dev/) с помощью запроса на слияние в [репозиторий на GitHub](https://github.com/sst/models.dev).
  2. (При необходимости) обновите дополнительные поля и переопределения в файле `langchain_<package>/data/profile_augmentations.toml`, отправив запрос на слияние в пакет интеграции LangChain (/oss/python/integrations/providers/overview).
  3. Используйте инструмент командной строки [`langchain-model-profiles`](https://pypi.org/project/langchain-model-profiles/), чтобы получить последние данные с [models.dev](https://models.dev/), объединить аугментации и обновить данные профиля:

  ```bash theme={null}
  pip install langchain-model-profiles
  ```

  ```bash theme={null}
  langchain-profiles refresh --provider <provider> --data-dir <data_dir>
  ```

  Эта команда:

  * Загружает последние данные для `<provider>` с models.dev
  * Объединяет аугментации из `profile_augmentations.toml` в `<data_dir>`
  * Записывает объединенные профили в файл `profiles.py` в каталог `<data_dir>`

  Например: из [`libs/partners/anthropic`](https://github.com/langchain-ai/langchain/tree/master/libs/partners/anthropic) в [монорепозитории LangChain](https://github.com/langchain-ai/langchain):

  ```bash theme={null}
  uv run --with langchain-model-profiles --provider anthropic --data-dir langchain_anthropic/data
  ```
</Аккордеон>

<Предупреждение>
  Профили моделей находятся в стадии бета-тестирования. Формат профиля может быть изменен.
</Предупреждение>

### Мультимодальный

Некоторые модели могут обрабатывать и возвращать нетекстовые данные, такие как изображения, аудио и видео. Вы можете передавать нетекстовые данные модели, предоставляя [блоки контента](/oss/python/langchain/messages#message-content).

<Совет>
  Все модели чата LangChain с поддержкой мультимодальных возможностей поддерживают:

  1. Данные в стандартном формате для всех поставщиков (см. [наше руководство по сообщениям](/oss/python/langchain/messages))
  2. Формат автодополнения чата OpenAI [https://platform.openai.com/docs/api-reference/chat](https://platform.openai.com/docs/api-reference/chat)
  3. Любой формат, являющийся родным для данного поставщика (например, модели Anthropic принимают собственный формат Anthropic).
</Совет>

Подробности см. в разделе [мультимодальные сообщения](/oss/python/langchain/messages#multimodal) руководства по сообщениям.

<Tooltip tip="Не все LLM одинаковы!" cta="См. ссылку" href="https://models.dev/">Некоторые модели</Tooltip> могут возвращать мультимодальные данные в качестве части своего ответа. Если вызвать эту функцию, результирующее [`AIMessage`](https://reference.langchain.com/python/langchain/messages/#langchain.messages.AIMessage) будет содержать блоки контента с мультимодальными типами.

```python Multimodal output theme={null}
response = model.invoke("Создать изображение кошки")
print(response.content_blocks)
# [
# {"type": "text", "text": "Вот фотография кошки"},
# {"type": "image", "base64": "...", "mime_type": "image/jpeg"},
# ]
```

Подробную информацию о конкретных поставщиках см. на странице [интеграций](/oss/python/integrations/providers/overview).

### Рассуждения

Многие модели способны выполнять многоэтапное рассуждение для достижения вывода. Это включает в себя разбиение сложных проблем на более мелкие, более управляемые этапы.

**Если это подтверждается базовой моделью,** вы можете отобразить этот процесс рассуждений, чтобы лучше понять, как модель пришла к своему окончательному ответу.

<CodeGroup>
  ```python Stream reasoning output theme={null}
  for chunk in model.stream("Почему у попугаев такие разноцветные перья?"):
      reasoning_steps = [r for r in chunk.content_blocks if r["type"] == "reasoning"]
      print(reasoning_steps if reasoning_steps else chunk.text)
  ```

  ```python Complete reasoning output theme={null}
  response = model.invoke("Почему у попугаев такие разноцветные перья?")
  reasoning_steps = [b for b in response.content_blocks if b["type"] == "reasoning"]
  print(" ".join(step["reasoning"] for step in reasoning_steps))
  ```
</CodeGroup>

В зависимости от модели, иногда можно указать уровень усилий, которые она должна вложить в рассуждения. Аналогично, можно запросить полное отключение рассуждений моделью. Это может принимать форму категориальных «уровней» рассуждений (например, «низкий» или «высокий») или целочисленных бюджетов токенов.

Для получения более подробной информации см. страницу [интеграций](/oss/python/integrations/providers/overview) или [справочник](https://reference.langchain.com/python/integrations/) для вашей соответствующей модели чата.

### Локальные модели

LangChain поддерживает запуск моделей локально на вашем собственном оборудовании. Это полезно в ситуациях, когда критически важна конфиденциальность данных, вы хотите использовать собственную модель или хотите избежать затрат, связанных с использованием облачной модели.

[Ollama](/oss/python/integrations/chat/ollama) — один из самых простых способов запуска чата и моделей встраивания локально.

### Кэширование подсказок

Многие провайдеры предлагают функции оперативного кэширования для уменьшения задержки и затрат при повторной обработке одних и тех же токенов. Эти функции могут быть **неявными** или **явными**:

* **Неявное кэширование запросов:** поставщики автоматически передают экономию средств, если запрос попадает в кэш. Примеры: [OpenAI](/oss/python/integrations/chat/openai) и [Gemini](/oss/python/integrations/chat/google_generative_ai).
* **Явное кэширование:** провайдеры позволяют вручную указывать точки кэширования для большего контроля или для гарантированной экономии средств. Примеры:
  * [`ChatOpenAI`](https://reference.langchain.com/python/integrations/langchain_openai/ChatOpenAI) (через `prompt_cache_key`)
  * Anthropic's [`AnthropicPromptCachingMiddleware`](/oss/python/integrations/chat/anthropic#prompt-caching)
  * [Gemini](https://reference.langchain.com/python/integrations/langchain_google_genai/).
  * [AWS Bedrock](/oss/python/integrations/chat/bedrock#prompt-caching)

<Предупреждение>
  Кэширование подсказок часто включается только при превышении минимального порогового значения входного токена. Подробнее см. на страницах [провайдера](/oss/python/integrations/chat).
</Предупреждение>

Использование кэша будет отражено в [метаданных использования](/oss/python/langchain/messages#token-usage) ответа модели.

### Использование серверных инструментов

Некоторые поставщики поддерживают циклы вызова инструментов на стороне сервера: модели могут взаимодействовать с веб-поиском, интерпретаторами кода и другими инструментами и анализировать результаты в рамках одного диалога.

```python Вызов с помощью серверного инструмента use theme={null}
model = init_chat_model("gpt-4.1-mini")

model_with_tools = model.bind_tools([tool])
```

### Ограничение скорости

Многие провайдеры чат-моделей устанавливают ограничение на количество запросов, которые можно отправить за определенный период времени. Если вы превысите лимит запросов, вы, как правило, получите сообщение об ошибке от провайдера и вам придется подождать, прежде чем отправлять новые запросы.

Для управления ограничениями скорости запросов интеграции с чат-моделями принимают параметр `rate_limiter`, который можно указать во время инициализации для контроля скорости отправки запросов.

<Accordion title="Инициализация и использование ограничителя скорости" icon="gauge-high">
  LangChain поставляется с (опциональным) встроенным ограничителем скорости передачи данных [`InMemoryRateLimiter`](https://reference.langchain.com/python/langchain_core/rate_limiters/#langchain_core.rate_limiters.InMemoryRateLimiter). Этот ограничитель потокобезопасен и может использоваться несколькими потоками в одном процессе.

  ```python Определить ограничитель скорости theme={null}
  from langchain_core.rate_limiters import InMemoryRateLimiter

  rate_limiter = InMemoryRateLimiter(
      requests_per_second=0.1, # 1 запрос каждые 10 секунд
      check_every_n_seconds=0.1, # Проверяем каждые 100 мс, разрешено ли отправлять запрос
      max_bucket_size=10, # Управляет максимальным размером пакета данных.
  )

  модель = init_chat_model(
      model="gpt-5",
      model_provider="openai",
      rate_limiter=rate_limiter # [!code highlight]
  )
  ```

  <Предупреждение>
    Предоставленный ограничитель скорости может ограничивать только количество запросов в единицу времени. Он не поможет, если вам также необходимо ограничить скорость в зависимости от размера запросов.
  </Предупреждение>
</Аккордеон>

### Базовый URL или прокси

Для многих интеграций с моделями чата можно настроить базовый URL-адрес для запросов API, что позволяет использовать поставщиков моделей, имеющих API, совместимые с OpenAI, или использовать прокси-сервер.

<Accordion title="Базовый URL" icon="link">
  Многие поставщики моделей предлагают API, совместимые с OpenAI (например, [Together AI](https://www.together.ai/), [vLLM](https://github.com/vllm-project/vllm)). Вы можете использовать [`init_chat_model`](https://reference.langchain.com/python/langchain/models/#langchain.chat_models.init_chat_model) с этими поставщиками, указав соответствующий параметр `base_url`:

  ```python theme={null}
  модель = init_chat_model(
      model="MODEL_NAME",
      model_provider="openai",
      base_url="BASE_URL",
      api_key="ВАШ_API_КЛЮЧ",
  )
  ```

  <Примечание>
    При использовании создания экземпляра класса модели прямого чата имя параметра может различаться в зависимости от поставщика. Для получения более подробной информации см. соответствующий [справочник](/oss/python/integrations/providers/overview).
  </Примечание>
</Аккордеон>

<Accordion title="Конфигурация прокси" icon="щит">
  Для развертываний, требующих HTTP-прокси, некоторые интеграции моделей поддерживают настройку прокси:

  ```python theme={null}
  from langchain_openai import ChatOpenAI

  модель = ChatOpenAI(
      model="gpt-4.1",
      openai_proxy="http://proxy.example.com:8080"
  )
  ```

  <Примечание>
    Поддержка прокси-сервера зависит от интеграции. Параметры настройки прокси-сервера можно найти в документации конкретного поставщика модели [reference](/oss/python/integrations/providers/overview).
  </Примечание>
</Аккордеон>

### Логарифмические вероятности

Некоторые модели можно настроить таким образом, чтобы они возвращали логарифмические вероятности на уровне токенов, представляющие вероятность существования данного токена, путем установки параметра `logprobs` при инициализации модели:

```python theme={null}
модель = init_chat_model(
    model="gpt-4.1",
    model_provider="openai"
).bind(logprobs=True)

response = model.invoke("Почему попугаи разговаривают?")
print(response.response_metadata["logprobs"])
```

### Использование токенов

Ряд поставщиков моделей возвращают информацию об использовании токенов в составе ответа на вызов. Если эта информация доступна, она будет включена в объекты [`AIMessage`](https://reference.langchain.com/python/langchain/messages/#langchain.messages.AIMessage), создаваемые соответствующей моделью. Для получения более подробной информации см. руководство [messages](/oss/python/langchain/messages).

<Примечание>
  Некоторые API поставщиков услуг, в частности OpenAI и Azure OpenAI для автозавершения чатов, требуют согласия пользователей на получение данных об использовании токенов в потоковом режиме. Подробности см. в разделе [метаданные об использовании потокового режима](/oss/python/integrations/chat/openai#streaming-usage-metadata) руководства по интеграции.
</Примечание>

### Конфигурация вызова

При вызове модели вы можете передать дополнительную конфигурацию через параметр `config`, используя словарь [`RunnableConfig`](https://reference.langchain.com/python/langchain_core/runnables/#langchain_core.runnables.RunnableConfig). Это обеспечивает управление поведением выполнения, обратными вызовами и отслеживанием метаданных во время выполнения.

К числу распространенных параметров конфигурации относятся:

```Вызов Python с конфигурацией theme={null}
response = model.invoke(
    "Расскажи мне анекдот",
    config={
        "run_name": "joke_generation", # Пользовательское имя для этого запуска
        "теги": ["юмор", "демо"], # Теги для категоризации
        "метаданные": {"user_id": "123"}, # Пользовательские метаданные
        "callbacks": [my_callback_handler], # Обработчики обратных вызовов
    }
)
```

Эти параметры конфигурации особенно полезны в следующих случаях:

* Отладка с помощью трассировки [LangSmith](https://docs.langchain.com/langsmith/home).
* Внедрение пользовательских систем логирования или мониторинга
* Контроль использования ресурсов в производстве
* Отслеживание вызовов в сложных конвейерах обработки данных

<Заголовок аккордеона="Ключевые атрибуты конфигурации">
  <ParamField body="run_name" type="string">
    Идентифицирует этот конкретный вызов в журналах и трассировках. Не наследуется дочерними вызовами.
  </ParamField>

  <ParamField body="tags" type="string[]">
    Метки, наследуемые всеми подвызовами, используются для фильтрации и организации в инструментах отладки.
  </ParamField>

  <ParamField body="metadata" type="object">
    Пользовательские пары ключ-значение для отслеживания дополнительного контекста, наследуемые всеми подвызовами.
  </ParamField>

  <ParamField body="max_concurrency" type="number">
    Управляет максимальным количеством параллельных вызовов при использовании [`batch()`](https://reference.langchain.com/python/langchain_core/language_models/#langchain_core.language_models.chat_models.BaseChatModel.batch) или [`batch_as_completed()`](https://reference.langchain.com/python/langchain_core/language_models/#langchain_core.language_models.chat_models.BaseChatModel.batch_as_completed).
  </ParamField>

  <ParamField body="callbacks" type="array">
    Обработчики для мониторинга событий и реагирования на них во время выполнения.
  </ParamField>

  <ParamField body="recursion_limit" type="number">
    Максимальная глубина рекурсии для цепочек, предотвращающая бесконечные циклы в сложных конвейерах обработки данных.
  </ParamField>
</Аккордеон>

<Совет>
  Полный справочник по [`RunnableConfig`](https://reference.langchain.com/python/langchain_core/runnables/#langchain_core.runnables.RunnableConfig) содержит информацию обо всех поддерживаемых атрибутах.
</Совет>

### Настраиваемые модели

Вы также можете создать модель, настраиваемую во время выполнения, указав [`configurable_fields`](https://reference.langchain.com/python/langchain_core/language_models/#langchain_core.language_models.chat_models.BaseChatModel.configurable_fields). Если вы не укажете значение модели, то `'model'` и `'model_provider'` будут настраиваемыми по умолчанию.

```python theme={null}
from langchain.chat_models import init_chat_model

configurable_model = init_chat_model(temperature=0)

configurable_model.invoke(
    "как тебя зовут",
    config={"configurable": {"model": "gpt-5-nano"}}, # Запуск с GPT-5-Nano
)
configurable_model.invoke(
    "как тебя зовут",
    config={"configurable": {"model": "claude-sonnet-4-5-20250929"}}, # Запуск с Клодом
)
```

<Заголовок аккордеона: "Настраиваемая модель со значениями по умолчанию">
  Мы можем создать настраиваемую модель со значениями модели по умолчанию, указать, какие параметры являются настраиваемыми, и добавить префиксы к настраиваемым параметрам:

  ```python theme={null}
  first_model = init_chat_model(
          model="gpt-4.1-mini",
          температура = 0,
          configurable_fields=("model", "model_provider", "temperature", "max_tokens"),
          config_prefix="first", # Полезно, если у вас есть цепочка с несколькими моделями
  )

  first_model.invoke("Как тебя зовут")
  ```

  ```python theme={null}
  first_model.invoke(
      "как тебя зовут",
      config={
          "настраиваемый": {
              "first_model": "claude-sonnet-4-5-20250929",
              "first_temperature": 0.5,
              "first_max_tokens": 100,
          }
      },
  )
  ```

  Для получения более подробной информации о параметрах `configurable_fields` и `config_prefix` см. справочник [`init_chat_model`](https://reference.langchain.com/python/langchain/models/#langchain.chat_models.init_chat_model).
</Аккордеон>

<Заголовок аккордеона="Использование декларативно настраиваемой модели">
