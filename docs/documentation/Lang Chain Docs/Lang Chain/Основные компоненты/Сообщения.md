# Сообщения

Сообщения являются основной единицей контекста для моделей в LangChain. Они представляют собой входные и выходные данные моделей, неся как контент, так и метаданные, необходимые для представления состояния разговора при взаимодействии с LLM.

Сообщения — это объекты, содержащие:

* <Icon icon="user" size={16} /> [**Роль**](#message-types) - Определяет тип сообщения (например, `system`, `user`)
* <Icon icon="folder-closed" size={16} /> [**Содержание**](#message-content) - Представляет фактическое содержимое сообщения (например, текст, изображения, аудио, документы и т. д.)
* <Icon icon="tag" size={16} /> [**Метаданные**](#message-metadata) - Необязательные поля, такие как информация об ответе, идентификаторы сообщений и использование токенов

LangChain предоставляет стандартный тип сообщений, который работает со всеми поставщиками моделей, обеспечивая согласованное поведение независимо от вызываемой модели.

## Основные правила использования

Простейший способ использования сообщений — это создание объектов сообщений и передача их модели при вызове [/oss/python/langchain/models#invocation].

```python theme={null}
from langchain.chat_models import init_chat_model
из langchain.messages импортируйте HumanMessage, AIMessage, SystemMessage

model = init_chat_model("gpt-5-nano")

system_msg = SystemMessage("Вы — полезный помощник.")
human_msg = HumanMessage("Здравствуйте, как дела?")

# Использовать с моделями чата
сообщения = [system_msg, human_msg]
response = model.invoke(messages) # Возвращает AIMessage
```

### Текстовые подсказки

Текстовые подсказки представляют собой строки — идеально подходят для простых задач генерации, где не требуется сохранять историю переписки.

```python theme={null}
response = model.invoke("Напишите хайку о весне")
```

**Используйте текстовые подсказки в следующих случаях:**

* У вас один, отдельный запрос
* История переписки не требуется
* Вам нужна минимальная сложность кода

### Подсказки сообщений

В качестве альтернативы, вы можете передать в модель список сообщений, предоставив список объектов сообщений.

```python theme={null}
из langchain.messages импортировать SystemMessage, HumanMessage, AIMessage

сообщения = [
    SystemMessage("Вы — эксперт в поэзии"),
    HumanMessage("Напишите хайку о весне"),
    AIMessage("Цветущая сакура...")
]
response = model.invoke(messages)
```

**Используйте подсказки сообщений в следующих случаях:**

* Управление многоэтапными переговорами
* Работа с мультимодальным контентом (изображения, аудио, файлы)
* Включая системные инструкции

### Формат словаря

Вы также можете указывать сообщения непосредственно в формате автозавершения чата OpenAI.

```python theme={null}
сообщения = [
    {"role": "system", "content": "You are poetry expert"},
    {"role": "user", "content": "Напишите хайку о весне"},
    {"role": "assistant", "content": "Цветущая вишня..."}
]
response = model.invoke(messages)
```

## Типы сообщений

* <Icon icon="gear" size={16} /> [Системное сообщение](#system-message) - Указывает модели, как себя вести, и предоставляет контекст для взаимодействий
* <Icon icon="user" size={16} /> [Сообщение от пользователя](#human-message) - Представляет ввод пользователя и его взаимодействие с моделью
* <Icon icon="robot" size={16} /> [Сообщение ИИ](#ai-message) - Ответы, сгенерированные моделью, включая текстовое содержимое, вызовы инструментов и метаданные
* <Icon icon="wrench" size={16} /> [Сообщение инструмента](#tool-message) - Представляет собой результаты [вызовов инструментов](/oss/python/langchain/models#tool-calling)

### Системное сообщение

Системное сообщение (SystemMessage) представляет собой начальный набор инструкций, которые подготавливают поведение модели. Вы можете использовать системное сообщение, чтобы задать тон, определить роль модели и установить правила для ответов.

```Базовые инструкции Python theme={null}
system_msg = SystemMessage("Вы — полезный помощник в программировании.")

сообщения = [
    системное сообщение,
    HumanMessage("Как создать REST API?")
]
response = model.invoke(messages)
```

```python Detailed persona theme={null}
from langchain.messages import SystemMessage, HumanMessage

system_msg = SystemMessage("""
Вы — опытный Python-разработчик с экспертными знаниями в области веб-фреймворков.
Всегда приводите примеры кода и объясняйте свои рассуждения.
Будьте краткими, но исчерпывающими в своих объяснениях.
""")

сообщения = [
    системное сообщение,
    HumanMessage("Как создать REST API?")
]
response = model.invoke(messages)
```

### Человеческое сообщение

Объект [`HumanMessage`](https://reference.langchain.com/python/langchain/messages/#langchain.messages.HumanMessage) представляет собой пользовательский ввод и взаимодействие. Он может содержать текст, изображения, аудио, файлы и любое другое количество мультимодального [контента](#message-content).

#### Текстовое содержимое

<CodeGroup>
  ```python Message object theme={null}
  response = model.invoke([
    HumanMessage("Что такое машинное обучение?")
  ])
  ```

  ```python Строковый ярлык theme={null}
  # Использование строки — это сокращенный способ отправки одного сообщения HumanMessage.
  response = model.invoke("Что такое машинное обучение?")
  ```
</CodeGroup>

#### Метаданные сообщения

```python Добавить метаданные theme={null}
human_msg = HumanMessage(
    content="Привет!",
    name="alice", # Необязательно: идентификация разных пользователей
    id="msg_123", # Необязательно: уникальный идентификатор для трассировки
)
```

<Примечание>
  Поведение поля `name` различается в зависимости от поставщика — некоторые используют его для идентификации пользователя, другие игнорируют. Для проверки обратитесь к [справочнику](https://reference.langchain.com/python/integrations/) поставщика модели.
</Примечание>

### Сообщение ИИ

Объект [`AIMessage`](https://reference.langchain.com/python/langchain/messages/#langchain.messages.AIMessage) представляет собой результат вызова модели. Он может включать мультимодальные данные, вызовы инструментов и метаданные, специфичные для поставщика, к которым можно получить доступ позже.

```python theme={null}
response = model.invoke("Explain AI")
print(type(response)) # <class 'langchain.messages.AIMessage'>
```

При вызове модели ей возвращаются объекты [`AIMessage`](https://reference.langchain.com/python/langchain/messages/#langchain.messages.AIMessage), содержащие все связанные метаданные в ответе.

Поставщики по-разному оценивают/контекстуализируют типы сообщений, поэтому иногда бывает полезно вручную создать новый объект [`AIMessage`](https://reference.langchain.com/python/langchain/messages/#langchain.messages.AIMessage) и вставить его в историю сообщений так, как если бы он поступил от модели.

```python theme={null}
из langchain.messages импортируйте AIMessage, SystemMessage, HumanMessage

# Создание сообщения для ИИ вручную (например, для истории переписки)
ai_msg = AIMessage("Я с удовольствием помогу вам с этим вопросом!")

# Добавить в историю переписки
сообщения = [
    SystemMessage("Вы — полезный помощник"),
    HumanMessage("Можете мне помочь?"),
    ai_msg, # Вставить так, как если бы сообщение поступило из модели
    HumanMessage("Отлично! А сколько будет 2+2?")
]

response = model.invoke(messages)
```

<Accordion title="Attributes">
  <ParamField path="text" type="string">
    Текстовое содержание сообщения.
  </ParamField>

  <ParamField path="content" type="string | dict[]">
    Исходное содержание сообщения.
  </ParamField>

  <ParamField path="content_blocks" type="ContentBlock[]">
    Стандартизированные [блоки содержимого](#message-content) сообщения.
  </ParamField>

  <ParamField path="tool_calls" type="dict[] | None">
    Вызовы инструментов, выполняемые моделью.

    Пусто, если не вызывались никакие инструменты.
  </ParamField>

  <ParamField path="id" type="string">
    Уникальный идентификатор сообщения (либо автоматически сгенерированный LangChain, либо возвращенный в ответе поставщика).
  </ParamField>

  <ParamField path="usage_metadata" type="dict | None">
    Метаданные об использовании сообщения, которые могут содержать количество токенов, если таковые имеются.
  </ParamField>

  <ParamField path="response_metadata" type="ResponseMetadata | None">
    Метаданные ответа сообщения.
  </ParamField>
</Аккордеон>

#### Вызовы инструментов

Когда модели выполняют [вызовы инструментов](/oss/python/langchain/models#tool-calling), они включаются в [`AIMessage`](https://reference.langchain.com/python/langchain/messages/#langchain.messages.AIMessage):

```python theme={null}
from langchain.chat_models import init_chat_model

model = init_chat_model("gpt-5-nano")

def get_weather(location: str) -> str:
    «Узнайте прогноз погоды в выбранном месте».
    ...

model_with_tools = model.bind_tools([get_weather])
response = model_with_tools.invoke("Какая погода в Париже?")

for tool_call in response.tool_calls:
    print(f"Инструмент: {tool_call['name']}")
    print(f"Аргументы: {tool_call['args']}")
    print(f"ID: {tool_call['id']}")
```

В сообщении [content](/oss/python/langchain/messages#message-content) также могут содержаться другие структурированные данные, такие как обоснование или ссылки на источники.

#### Использование токенов

Объект [`AIMessage`](https://reference.langchain.com/python/langchain/messages/#langchain.messages.AIMessage) может содержать количество токенов и другие метаданные об использовании в поле [`usage_metadata`](https://reference.langchain.com/python/langchain/messages/#langchain.messages.UsageMetadata):

```python theme={null}
from langchain.chat_models import init_chat_model

model = init_chat_model("gpt-5-nano")

response = model.invoke("Привет!")
response.usage_metadata
```

```
{'input_tokens': 8,
 'output_tokens': 304,
 'total_tokens': 312,
 'input_token_details': {'audio': 0, 'cache_read': 0},
 'output_token_details': {'audio': 0, 'reasoning': 256}}
```

Подробности см. в [`UsageMetadata`](https://reference.langchain.com/python/langchain/messages/#langchain.messages.UsageMetadata).

#### Потоковая передача и фрагменты

В процессе потоковой передачи вы будете получать объекты [`AIMessageChunk`](https://reference.langchain.com/python/langchain/messages/#langchain.messages.AIMessageChunk), которые можно объединить в полный объект сообщения:

```python theme={null}
фрагменты = []
full_message = None
for chunk in model.stream("Hi"):
    chunks.append(chunk)
    print(chunk.text)
    full_message = chunk, если full_message равно None, иначе full_message + chunk
```

### Сообщение инструмента

Для моделей, поддерживающих [вызов инструментов](/oss/python/langchain/models#tool-calling), сообщения ИИ могут содержать вызовы инструментов. Сообщения инструментов используются для передачи результатов выполнения одного инструмента обратно в модель.

[Инструменты](/oss/python/langchain/tools) могут напрямую генерировать объекты [`ToolMessage`](https://reference.langchain.com/python/langchain/messages/#langchain.messages.ToolMessage). Ниже приведен простой пример. Подробнее см. в [руководстве по инструментам](/oss/python/langchain/tools).

```python theme={null}
из langchain.messages импортировать AIMessage
from langchain.messages import ToolMessage

# После того, как модель вызывает инструмент
(Здесь для краткости мы демонстрируем создание сообщений вручную)
ai_message = AIMessage(
    контент=[],
    tool_calls=[{
        "name": "get_weather",
        "args": {"location": "Сан-Франциско"},
        "id": "call_123"
    }]
)

# Запустить инструмент и создать сообщение с результатом
weather_result = "Солнечно, 72°F"
tool_message = ToolMessage(
    content=weather_result,
    tool_call_id="call_123" # Должен совпадать с идентификатором вызова
)

# Продолжить разговор
сообщения = [
    HumanMessage("Какая погода в Сан-Франциско?"),
    ai_message, # Вызов инструмента модели
    tool_message, # Результат выполнения инструмента
]
response = model.invoke(messages) # Модель обрабатывает результат
```

<Accordion title="Attributes">
  <ParamField path="content" type="string" required>
    Строковый вывод вызова инструмента.
  </ParamField>

  <ParamField path="tool_call_id" type="string" required>
    Идентификатор вызова инструмента, на который отвечает это сообщение. Должен совпадать с идентификатором вызова инструмента в [`AIMessage`](https://reference.langchain.com/python/langchain/messages/#langchain.messages.AIMessage).
  </ParamField>

  <ParamField path="name" type="string" required>
    Название вызванного инструмента.
  </ParamField>

  <ParamField path="artifact" type="dict">
    Дополнительные данные не передаются в модель, но к ним можно получить доступ программным способом.
  </ParamField>
</Аккордеон>

<Примечание>
  Поле `artifact` хранит дополнительные данные, которые не будут отправлены в модель, но к которым можно получить доступ программно. Это полезно для хранения необработанных результатов, отладочной информации или данных для последующей обработки без загромождения контекста модели.

  <Заголовок аккордеона="Пример: Использование артефакта для получения метаданных">
    Например, инструмент [retrieval](/oss/python/langchain/retrieval) может извлечь фрагмент текста из документа для использования моделью в качестве ссылки. Если сообщение `content` содержит текст, на который будет ссылаться модель, то `artifact` может содержать идентификаторы документа или другие метаданные, которые может использовать приложение (например, для отображения страницы). См. пример ниже:

    ```python theme={null}
    from langchain.messages import ToolMessage

    # Отправлено модели
    message_content = "Это было лучшее время, это было худшее время."

    # Артефакт доступен ниже по потоку
    артефакт = {"document_id": "doc_123", "page": 0}

    tool_message = ToolMessage(
        content=message_content,
        tool_call_id="call_123",
        name="search_books",
        артефакт=артефакт,
    )
    ```

    См. [учебное пособие по RAG](/oss/python/langchain/rag) для получения полного примера создания агентов поиска [информации](/oss/python/langchain/agents) с помощью LangChain.
  </Аккордеон>
</Примечание>

## Содержание сообщения

Содержимое сообщения можно рассматривать как полезную нагрузку данных, отправляемых в модель. Сообщения имеют атрибут `content`, который имеет свободную типизацию и поддерживает строки и списки нетипизированных объектов (например, словари). Это позволяет напрямую использовать в моделях чата LangChain структуры, созданные самим поставщиком, такие как [мультимодальное](#мультимодальное) содержимое и другие данные.

Отдельно LangChain предоставляет специальные типы контента для текста, рассуждений, цитат, мультимодальных данных, вызовов серверных инструментов и другого содержимого сообщений. См. [блоки контента](#standard-content-blocks) ниже.

Модели чата LangChain принимают содержимое сообщений в атрибуте `content`.

Это может содержать либо:

1. Строка
2. Список блоков контента в формате, разработанном самим поставщиком.
3. Список стандартных блоков контента [LangChain](#standard-content-blocks)

Ниже приведён пример использования [мультимодальных](#мультимодальных) входных данных:

```python theme={null}
from langchain.messages import HumanMessage

# Содержимое строки
human_message = HumanMessage("Здравствуйте, как дела?")

# Формат, разработанный поставщиком (например, OpenAI)
human_message = HumanMessage(content=[
    {"type": "text", "text": "Здравствуйте, как дела?"},
    {"type": "image_url", "image_url": {"url": "https://example.com/image.jpg"}}
])

# Список стандартных блоков контента
human_message = HumanMessage(content_blocks=[
    {"type": "text", "text": "Здравствуйте, как дела?"},
    {"type": "image", "url": "https://example.com/image.jpg"},
])
```

<Совет>
  Указание параметра `content_blocks` при инициализации сообщения всё равно приведёт к его заполнению.
  `content`, но предоставляет типобезопасный интерфейс для этого.
</Совет>

### Стандартные блоки контента

LangChain предоставляет стандартное представление содержимого сообщений, которое работает у разных поставщиков услуг.

Объекты сообщений реализуют свойство `content_blocks`, которое будет лениво преобразовывать атрибут `content` в стандартное, типобезопасное представление. Например, сообщения, сгенерированные из [`ChatAnthropic`](/oss/python/integrations/chat/anthropic) или [`ChatOpenAI`](/oss/python/integrations/chat/openai), будут содержать блоки `thinking` или `reasoning` в формате соответствующего поставщика, но могут быть лениво преобразованы в согласованное представление [`ReasoningContentBlock`](#content-block-reference):

<Примечание>
  **Сериализация стандартного контента**

  Если приложению, не использующему LangChain, необходим доступ к стандартному блоку контента,
  В целях наглядности вы можете включить возможность хранения блоков контента в содержимом сообщения.

  Для этого можно установить переменную среды `LC_OUTPUT_VERSION` в значение `v1`. Или же...
  инициализируйте любую модель чата значением `output_version="v1"`:

  ```python theme={null}

  model = init_chat_model("gpt-5-nano", output_version="v1")
  ```
</Примечание>

## Использовать с моделями чата

Модели чата принимают на вход последовательность объектов сообщений и возвращают на выходе объект [`AIMessage`](https://reference.langchain.com/python/langchain/messages/#langchain.messages.AIMessage). Взаимодействия часто не имеют состояния, поэтому простой цикл диалога включает в себя вызов модели с постоянно пополняющимся списком сообщений.

Для получения более подробной информации обратитесь к приведенным ниже руководствам:

* Встроенные функции для [сохранения и управления историей разговоров](/oss/python/langchain/short-term-memory)
* Стратегии управления контекстными окнами, включая [обрезку и суммирование сообщений](/oss/python/langchain/short-term-memory#common-patterns)
