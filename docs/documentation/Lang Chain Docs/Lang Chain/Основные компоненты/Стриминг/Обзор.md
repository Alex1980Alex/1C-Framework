# Обзор

> Передача обновлений в реальном времени из запусков агентов

LangChain использует потоковую систему для отображения обновлений в реальном времени.

Потоковая передача данных имеет решающее значение для повышения быстродействия приложений, построенных на основе LLM. Благодаря постепенному отображению выходных данных, даже до того, как будет готов полный ответ, потоковая передача значительно улучшает пользовательский опыт (UX), особенно при работе с задержкой, характерной для LLM.

## Обзор

Система потоковой передачи данных LangChain позволяет отображать в вашем приложении обратную связь в режиме реального времени от работы агентов.

Что возможно с помощью потоковой передачи данных LangChain:

* <Icon icon="brain" size={16} /> [**Потоковое отображение прогресса агента**](#agent-progress) — получать обновления состояния после каждого шага агента.
* <Icon icon="square-binary" size={16} /> [**Потоковая передача токенов LLM**](#llm-tokens) — потоковая передача токенов языковой модели по мере их генерации.
* <Icon icon="table" size={16} /> [**Потоковые пользовательские обновления**](#custom-updates) — отправка определяемых пользователем сигналов (например, `"Получено 10/100 записей"`).
* <Icon icon="layer-plus" size={16} /> [**Многорежимная потоковая передача**](#stream-multiple-modes) — выберите один из режимов: `updates` (прогресс агента), `messages` (токены LLM + метаданные) или `custom` (произвольные пользовательские данные).

Дополнительные примеры комплексного решения см. в разделе [общие шаблоны](#common-patterns) ниже.

## Поддерживаемые режимы потоковой передачи

Передайте один или несколько из следующих режимов потока в виде списка методам [`stream`](https://reference.langchain.com/python/langgraph/graphs/#langgraph.graph.state.CompiledStateGraph.stream) или [`astream`](https://reference.langchain.com/python/langgraph/graphs/#langgraph.graph.state.CompiledStateGraph.astream):

| Режим      | Описание                                                                                                                                                                                          |
| ---------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `updates`  | Передает обновления состояния после каждого шага агента. Если в одном и том же шаге выполняется несколько обновлений (например, запускается несколько узлов), эти обновления передаются отдельно. |
| `messages` | Поставляет кортежи `(токен, метаданные)` из любых узлов графа, где вызывается LLM.                                                                                                                |
| `custom`   | Передает пользовательские данные из узлов графа с помощью средства записи потока.                                                                                                                 |

## Прогресс агента

Для потоковой передачи прогресса агента используйте методы [`stream`](https://reference.langchain.com/python/langgraph/graphs/#langgraph.graph.state.CompiledStateGraph.stream) или [`astream`](https://reference.langchain.com/python/langgraph/graphs/#langgraph.graph.state.CompiledStateGraph.astream) с параметром `stream_mode="updates"`. Это будет генерировать событие после каждого шага агента.

Например, если ваш агент вызывает инструмент всего один раз, вы должны увидеть следующие обновления:

* **Узел LLM**: [`AIMessage`](https://reference.langchain.com/python/langchain/messages/#langchain.messages.AIMessage) с запросами на вызов инструментов
* **Узел инструмента**: [`ToolMessage`](https://reference.langchain.com/python/langchain/messages/#langchain.messages.ToolMessage) с результатом выполнения
* **Узел LLM**: Окончательный ответ ИИ

```python title="Прогресс агента потоковой передачи" theme={null}
from langchain.agents import create_agent


def get_weather(city: str) -> str:
    «Получите информацию о погоде для конкретного города».

    return f"В {городе} всегда солнечно!"

агент = create_agent(
    model="gpt-5-nano",
    инструменты=[get_weather],
)
for chunk in agent.stream( # [!code highlight]
    {"messages": [{"role": "user", "content": "Какая погода в Сан-Франциско?"}]},
    stream_mode="updates",
):
    for step, data in chunk.items():
        print(f"шаг: {шаг}")
        print(f"content: {data['messages'][-1].content_blocks}")
```

## Пользовательские обновления

Для потоковой передачи обновлений от инструментов по мере их выполнения можно использовать [`get_stream_writer`](https://reference.langchain.com/python/langgraph/config/#langgraph.config.get_stream_writer).

```python title="Потоковая передача пользовательских обновлений" theme={null}
from langchain.agents import create_agent
from langgraph.config import get_stream_writer # [!code highlight]


def get_weather(city: str) -> str:
    «Получите информацию о погоде для конкретного города».
    writer = get_stream_writer() # [!подсветка кода]
    # передавать любые произвольные данные
    writer(f"Поиск данных для города: {city}")
    writer(f"Получены данные для города: {city}")
    return f"В {городе} всегда солнечно!"

агент = create_agent(
    model="claude-sonnet-4-5-20250929",
    инструменты=[get_weather],
)

for chunk in agent.stream(
    {"messages": [{"role": "user", "content": "Какая погода в Сан-Франциско?"}]},
    stream_mode="custom" # [!code highlight]
):
    print(chunk)
```

```shell title="Output" theme={null}
Поиск данных по городу: Сан-Франциско
Получены данные по городу: Сан-Франциско
```

<Примечание>
  Если вы добавите [`get_stream_writer`](https://reference.langchain.com/python/langgraph/config/#langgraph.config.get_stream_writer) в свой инструмент, вы не сможете вызвать его вне контекста выполнения LangGraph.
</Примечание>

## Потоковая передача в нескольких режимах

Вы можете указать несколько режимов потоковой передачи, передав режим потоковой передачи в виде списка: `stream_mode=["updates", "custom"]`.

Выходные потоки будут представлять собой кортежи `(mode, chunk)`, где `mode` — это название режима потоковой передачи, а `chunk` — это данные, передаваемые этим режимом.

```python title="Streaming multiple modes" theme={null}
from langchain.agents import create_agent
from langgraph.config import get_stream_writer


def get_weather(city: str) -> str:
    «Получите информацию о погоде для конкретного города».
    writer = get_stream_writer()
    writer(f"Поиск данных для города: {city}")
    writer(f"Получены данные для города: {city}")
    return f"В {городе} всегда солнечно!"

агент = create_agent(
    model="gpt-5-nano",
    инструменты=[get_weather],
)

для stream_mode, фрагмент в agent.stream( # [!подсветка кода]
    {"messages": [{"role": "user", "content": "Какая погода в Сан-Франциско?"}]},
    stream_mode=["updates", "custom"]
):
    print(f"stream_mode: {stream_mode}")
    print(f"content: {chunk}")
    print("\n")
```

## Распространенные шаблоны

Ниже приведены примеры, демонстрирующие распространенные сценарии использования потоковой передачи данных.

### Вызовы инструментов потоковой передачи

Возможно, вам захочется посмотреть оба варианта онлайн:

1. Сгенерирован частичный JSON в виде [вызовов инструментов](/oss/python/langchain/models#tool-calling).
2. Завершенные, проанализированные вызовы инструментов, которые выполняются.

Указание [`stream_mode="messages"`](#llm-tokens) позволит передавать инкрементальные [фрагменты сообщений](/oss/python/langchain/messages#streaming-and-chunks), генерируемые всеми вызовами LLM в агенте. Для доступа к завершенным сообщениям с помощью разобранных вызовов инструментов:

1. Если эти сообщения отслеживаются в [state](/oss/python/langchain/agents#memory) (как в узле модели [`create_agent`](/oss/python/langchain/agents)), используйте `stream_mode=["messages", "updates"]` для доступа к завершенным сообщениям через [state updates](#agent-progress) (показано ниже).
2. Если эти сообщения не отслеживаются в состоянии, используйте [пользовательские обновления](#custom-updates) или агрегируйте фрагменты во время цикла потоковой передачи ([следующий раздел](#accessing-completed-messages)).

<Примечание>
  Если ваш агент включает несколько LLM-ов, обратитесь к разделу ниже, посвященному [потоковой передаче данных от суб-агентов](#streaming-from-sub-agents).
</Примечание>

#### Доступ к завершенным сообщениям

<Примечание>
  Если завершенные сообщения отслеживаются в [состоянии](/oss/python/langchain/agents#memory) агента, вы можете использовать `stream_mode=["messages", "updates"]`, как показано [выше](#streaming-tool-calls), для доступа к завершенным сообщениям во время потоковой передачи.
</Примечание>

В некоторых случаях завершенные сообщения не отображаются в [обновлениях состояния](#agent-progress). Если у вас есть доступ к внутренним механизмам агента, вы можете использовать [пользовательские обновления](#custom-updates) для доступа к этим сообщениям во время потоковой передачи. В противном случае вы можете объединять фрагменты сообщений в цикле потоковой передачи (см. ниже).

Рассмотрим приведенный ниже пример, где мы интегрируем [потоковый писатель](#custom-updates) в упрощенное [промежуточное ПО Guardrail](/oss/python/langchain/guardrails#after-agent-guardrails). Это промежуточное ПО демонстрирует вызов инструмента для генерации структурированной оценки «безопасно/небезопасно» (для этого также можно использовать [структурированные выходные данные](/oss/python/langchain/models#structured-output):

```python theme={null}
from typing import Any, Literal

from langchain.agents.middleware import after_agent, AgentState
from langgraph.runtime import Runtime
из langchain.messages импортировать AIMessage
from langchain.chat_models import init_chat_model
from langgraph.config import get_stream_writer # [!code highlight]
from pydantic import BaseModel


class ResponseSafety(BaseModel):
    «Оцените ответ как безопасный или небезопасный».
    оценка: Буквально ["безопасный", "небезопасный"]


Safety_model = init_chat_model("openai:gpt-5.2")

@after_agent(can_jump_to=["end"])
def safety_guardrail(state: AgentState, runtime: Runtime) -> dict[str, Any] | None:
    «Ограничительные меры на основе моделей: используйте модель LLM для оценки безопасности реагирования».
    stream_writer = get_stream_writer() # [!выделение кода]
    # Получение ответа модели
    если не state["messages"]:
        вернуть None

    last_message = state["messages"][-1]
    if not isinstance(last_message, AIMessage):
        вернуть None

    # Используйте другую модель для оценки безопасности
    model_with_tools = safety_model.bind_tools([ResponseSafety], tool_choice="any")
    результат = model_with_tools.invoke(
        [
            {
                "роль": "система",
                «Содержание»: «Оцените ответ ИИ как в целом безопасный или небезопасный».
            },
            {
                "роль": "пользователь",
                "content": f"Ответ ИИ: {last_message.text}"
            }
        ]
    )
    stream_writer(result) # [!code highlight]

    tool_call = result.tool_calls[0]
    if tool_call["args"]["evaluation"] == "unsafe":
        last_message.content = "Я не могу предоставить этот ответ. Пожалуйста, переформулируйте свой запрос."

    вернуть None
```

Затем мы можем интегрировать это промежуточное ПО в наш агент и включить в него пользовательские потоковые события:

```python theme={null}
из набора текста импортировать Any

from langchain.agents import create_agent
from langchain.messages import AIMessageChunk, AIMessage, AnyMessage


def get_weather(city: str) -> str:
    «Получите информацию о погоде для конкретного города».

    return f"В {городе} всегда солнечно!"


агент = create_agent(
    model="openai:gpt-5.2",
    инструменты=[get_weather],
```

### Потоковая передача с участием человека

Для обработки прерываний с участием человека мы используем [пример выше](#streaming-tool-calls):

2. Мы собираем прерывания, генерируемые в режиме потоковой передачи «обновлений».

### Трансляция от субагентов

Когда в агенте одновременно присутствует несколько LLM-модулей, часто возникает необходимость определить источник сообщений по мере их генерации.

Для этого передайте каждому агенту [`name`](https://reference.langchain.com/python/langchain/agents/#langchain.agents.create_agent\(name\)) при его создании. Это имя затем будет доступно в метаданных через ключ `lc_agent_name` при потоковой передаче в режиме «сообщений».

Ниже мы обновляем пример [вызовов инструментов потоковой передачи](#streaming-tool-calls):

1. Мы заменяем наш инструмент инструментом `call_weather_agent`, который вызывает агента внутри системы.
2. Мы добавляем `имя` к каждому агенту.
3. При создании потока мы указываем [`subgraphs=True`](/oss/python/langgraph/use-subgraphs#stream-subgraph-outputs).
4. Обработка потока данных осталась прежней, но мы добавили логику для отслеживания активности агента с помощью параметра `name` функции `create_agent`.

<Совет>
  Когда вы задаёте `имя` для агента, это имя также прикрепляется ко всем `AIMessage`, генерируемым этим агентом.
</Совет>

Сначала мы создаём агента:

## Отключить потоковую передачу

В некоторых приложениях может потребоваться отключить потоковую передачу отдельных токенов для данной модели. Это полезно в следующих случаях:

* Работа с многоагентными системами (/oss/python/langchain/multi-agent) для управления тем, какие агенты передают свой вывод в потоковом режиме.
* Смешивание моделей, поддерживающих потоковую передачу, с моделями, которые её не поддерживают.
* Развертываем приложение в [LangSmith](/langsmith/home) и хотим предотвратить потоковую передачу определенных выходных данных модели клиенту.

При инициализации модели установите параметр `streaming=False`.

```python theme={null}
from langchain_openai import ChatOpenAI

модель = ChatOpenAI(
    model="gpt-4.1",
    streaming=False # [!code highlight]
)
```

<Совет>
  При развертывании в LangSmith установите параметр `streaming=False` для всех моделей, выходные данные которых вы не хотите передавать клиенту в потоковом режиме. Это настраивается в коде вашего графа до развертывания.
</Совет>

<Примечание>
  Не все интеграции с моделями чата поддерживают параметр `streaming`. Если ваша модель его не поддерживает, используйте вместо него `disable_streaming=True`. Этот параметр доступен для всех моделей чата через базовый класс.
</Примечание>

Более подробную информацию см. в [руководстве по потоковой передаче LangGraph](/oss/python/langgraph/streaming#disable-streaming-for-specific-chat-models).
