# Встроенное промежуточное ПО

> Готовые промежуточные программы для распространенных сценариев использования агентов

LangChain предоставляет готовые промежуточные программные продукты для распространенных сценариев использования. Каждый из этих продуктов готов к внедрению в производство и может быть настроен в соответствии с вашими конкретными потребностями.

### Подведение итогов

Автоматическое составление краткого изложения истории переписки при приближении к лимиту токенов, с сохранением последних сообщений и сжатием более старого контекста. Функция суммирования полезна в следующих случаях:

* Длительные разговоры, выходящие за рамки контекстного окна.
* Многоэтапные диалоги с подробным историческим контекстом.
* Приложения, где важно сохранить полный контекст разговора.

**Справочник по API:** [`SummarizationMiddleware`](https://reference.langchain.com/python/langchain/middleware/#langchain.agents.middleware.SummarizationMiddleware)

```python theme={null}
from langchain.agents import create_agent
from langchain.agents.middleware import SummarizationMiddleware

агент = create_agent(
    model="gpt-4.1",
    tools=[your_weather_tool, your_calculator_tool],
    промежуточное ПО=[
        SummarizationMiddleware(
            model="gpt-4.1-mini",
            trigger=("tokens", 4000),
            keep=("messages", 20),
        ),
    ],
)
```

<Заголовок аккордеона="Параметры конфигурации">
  <Совет>
    Условия `fraction` для `trigger` и `keep` (показаны ниже) зависят от [данных профиля](/oss/python/langchain/models#model-profiles) модели чата, если используется `langchain>=1.1`. Если данные недоступны, используйте другое условие или укажите их вручную:

    ```python theme={null}
    from langchain.chat_models import init_chat_model

    custom_profile = {
        "max_input_tokens": 100_000,
        # ...
    }
    model = init_chat_model("gpt-4.1", profile=custom_profile)
    ```
  </Совет>

  <ParamField body="model" type="string | BaseChatModel" required>
    Модель для генерации сводок. Может быть строковым идентификатором модели (например, `'openai:gpt-4.1-mini'`) или экземпляром `BaseChatModel`. Дополнительную информацию см. в [`init_chat_model`](https://reference.langchain.com/python/langchain/models/#langchain.chat_models.init_chat_model\(model\)).
  </ParamField>

  <ParamField body="trigger" type="ContextSize | list[ContextSize] | None">
    Условие(я) запуска суммирования. Может быть:

    * Один кортеж [`ContextSize`](https://reference.langchain.com/python/langchain/middleware/#langchain.agents.middleware.summarization.ContextSize) (должно выполняться указанное условие)
    * Список кортежей [`ContextSize`](https://reference.langchain.com/python/langchain/middleware/#langchain.agents.middleware.summarization.ContextSize) (должно выполняться любое условие - логика ИЛИ)

    Условие должно соответствовать одному из следующих вариантов:

    * `fraction` (float): Доля размера контекста модели (0-1)
    * `tokens` (int): Абсолютное количество токенов
    * `messages` (int): Количество сообщений

    Необходимо указать хотя бы одно условие. Если оно не указано, автоматическое суммирование не запустится.

    Дополнительную информацию о параметре [`ContextSize`](https://reference.langchain.com/python/langchain/middleware/#langchain.agents.middleware.summarization.ContextSize) см. в справочнике API.
  </ParamField>

  <ParamField body="keep" type="ContextSize" default="('messages', 20)">
    Сколько контекстной информации следует сохранить после суммирования. Укажите ровно один из следующих вариантов:

    * `fraction` (float): Доля размера контекста модели, которую необходимо сохранить (0-1)
    * `tokens` (int): Абсолютное количество токенов для хранения
    * `messages` (int): Количество последних сообщений, которые нужно сохранить

    Дополнительную информацию о параметре [`ContextSize`](https://reference.langchain.com/python/langchain/middleware/#langchain.agents.middleware.summarization.ContextSize) см. в справочнике API.
  </ParamField>

  <ParamField body="token_counter" type="function">
    Настраиваемая функция подсчета токенов. По умолчанию используется подсчет по символам.
  </ParamField>

  <ParamField body="summary_prompt" type="string">
    Пользовательский шаблон запроса для суммирования. Использует встроенный шаблон, если не указан. Шаблон должен включать заполнитель `{messages}`, куда будет вставлена ​​история переписки.
  </ParamField>

  <ParamField body="trim_tokens_to_summarize" type="number" default="4000">
    Максимальное количество токенов, которые можно включить при создании сводки. Сообщения будут обрезаны до этого предела перед составлением сводки.
  </ParamField>

  <ParamField body="summary_prefix" type="string" deprecated>
    **Устарело:** Используйте `summary_prompt` для отображения полного запроса.
  </ParamField>

  <ParamField body="max_tokens_before_summary" type="number" deprecated>
    **Устарело:** Используйте `trigger: ("tokens", value)` вместо этого. Пороговое значение токенов для запуска суммирования.
  </ParamField>

  <ParamField body="messages_to_keep" type="number" deprecated>
    **Устарело:** Используйте `keep: ("messages", value)` вместо этого. Последние сообщения для сохранения.
  </ParamField>
</Аккордеон>

<Заголовок аккордеона="Полный пример">
  Промежуточное программное обеспечение для суммирования отслеживает количество токенов сообщений и автоматически суммирует более старые сообщения при достижении пороговых значений.

  Условия запуска** определяют, когда начинается суммирование:

  * Объект, выполняющий единственное условие (указанное условие должно быть выполнено)
  * Массив условий (любое условие должно быть выполнено - логическая операция ИЛИ)
  * Для каждого условия можно использовать `fraction` (от размера контекста модели), `tokens` (абсолютное количество) или `messages` (количество сообщений).

  **Условие сохранения** определяет, какой объем контекста следует сохранить (укажите ровно один):

  * `fraction` — Доля размера контекста модели, которую необходимо сохранить.
  * `токены` - абсолютное количество токенов для хранения
  * `messages` — Количество последних сообщений, которые следует сохранить.

  ```python theme={null}
  from langchain.agents import create_agent
  from langchain.agents.middleware import SummarizationMiddleware


  # Единственное условие: срабатывает, если количество токенов >= 4000
  агент = create_agent(
      model="gpt-4.1",
      tools=[your_weather_tool, your_calculator_tool],
      промежуточное ПО=[
          SummarizationMiddleware(
              model="gpt-4.1-mini",
              trigger=("tokens", 4000),
              keep=("messages", 20),
          ),
      ],
  )

  # Несколько условий: срабатывает, если количество токенов >= 3000 ИЛИ количество сообщений >= 6
  agent2 = create_agent(
      model="gpt-4.1",
      tools=[your_weather_tool, your_calculator_tool],
      промежуточное ПО=[
          SummarizationMiddleware(
              model="gpt-4.1-mini",
              триггер=[
                  ("токены", 3000),
                  ("сообщения", 6),
              ],
              keep=("messages", 20),
          ),
      ],
  )

  # Использование дробных пределов
  agent3 = create_agent(
      model="gpt-4.1",
      tools=[your_weather_tool, your_calculator_tool],
      промежуточное ПО=[
          SummarizationMiddleware(
              model="gpt-4.1-mini",
              trigger=("fraction", 0.8),
              keep=("fraction", 0.3),
          ),
      ],
  )
  ```
</Аккордеон>

### Человек в процессе

Приостановка выполнения агента для подтверждения, редактирования или отклонения вызовов инструментов человеком перед их выполнением. [Human-in-the-loop](/oss/python/langchain/human-in-the-loop) полезен в следующих случаях:

* Операции с высокими ставками, требующие одобрения человека (например, запись в базу данных, финансовые транзакции).
* Рабочие процессы обеспечения соответствия требованиям, в которых необходим человеческий контроль.
* Длительные диалоги, в которых обратная связь от человека направляет работу агента.

**Справочник по API:** [`HumanInTheLoopMiddleware`](https://reference.langchain.com/python/langchain/middleware/#langchain.agents.middleware.HumanInTheLoopMiddleware)

<Предупреждение>
  Для обеспечения взаимодействия человека с системой управления требуется [контрольная точка](/oss/python/langgraph/persistence#checkpoints) для поддержания состояния при прерываниях.
</Предупреждение>

```python theme={null}
from langchain.agents import create_agent
from langchain.agents.middleware import HumanInTheLoopMiddleware
from langgraph.checkpoint.memory import InMemorySaver


def read_email_tool(email_id: str) -> str:
    «Функция, имитирующая чтение электронного письма по его идентификатору».
    return f"Содержание электронного письма для ID: {email_id}"

def send_email_tool(recipient: str, subject: str, body: str) -> str:
    «Функция имитации отправки электронного письма».
    return f"Электронное письмо отправлено получателю {recipient} с темой '{subject}'"

агент = create_agent(
    model="gpt-4.1",
    tools=[your_read_email_tool, your_send_email_tool],
    checkpointer=InMemorySaver(),
    промежуточное ПО=[
        HumanInTheLoopMiddleware(
            interrupt_on={
                "your_send_email_tool": {
                    "allowed_decisions": ["approve", "edit", "reject"],
                },
                "your_read_email_tool": False,
            }
        ),
    ],
)
```

<Совет>
  Полные примеры, параметры конфигурации и шаблоны интеграции см. в документации по механизму "человек в цикле" (Human-in-the-loop).
</Совет>

### Ограничение на количество вызовов модели

Ограничьте количество вызовов модели, чтобы предотвратить бесконечные циклы или чрезмерные затраты. Ограничение количества вызовов модели полезно в следующих случаях:

* Предотвращение чрезмерного количества вызовов API со стороны агентов, вышедших из-под контроля.
* Обеспечение контроля затрат при развертывании в производственной среде.
* Тестирование поведения операторов в рамках заданных бюджетов звонков.

**Справочник по API:** [`ModelCallLimitMiddleware`](https://reference.langchain.com/python/langchain/middleware/#langchain.agents.middleware.ModelCallLimitMiddleware)

```python theme={null}
from langchain.agents import create_agent
from langchain.agents.middleware import ModelCallLimitMiddleware
from langgraph.checkpoint.memory import InMemorySaver

агент = create_agent(
    model="gpt-4.1",
    checkpointer=InMemorySaver(), # Требуется для ограничения количества потоков
    инструменты=[],
    промежуточное ПО=[
        ModelCallLimitMiddleware(
            thread_limit=10,
            run_limit=5,
            exit_behavior="end",
        ),
    ],
)
```

<Заголовок аккордеона="Параметры конфигурации">
  <ParamField body="thread_limit" type="number">
    Максимальное количество вызовов модели за все запуски в потоке. По умолчанию ограничение отсутствует.
  </ParamField>

  <ParamField body="run_limit" type="number">
    Максимальное количество вызовов модели за один запуск. По умолчанию ограничений нет.
  </ParamField>

  <ParamField body="exit_behavior" type="string" default="end">
    Поведение при достижении лимита. Варианты: `'end'` (корректное завершение) или `'error'` (вызов исключения).
  </ParamField>
</Аккордеон>

### Лимит вызовов инструмента

Управляйте выполнением агента, ограничивая количество вызовов инструментов либо глобально для всех инструментов, либо для конкретных инструментов. Ограничения на количество вызовов инструментов полезны в следующих случаях:

* Предотвращение чрезмерного количества обращений к дорогостоящим внешним API.
* Ограничение веб-поиска или запросов к базам данных.
* Введение ограничений на количество использований определенных инструментов.
* Защита от неконтролируемых циклов работы агентов.

**Справочник по API:** [`ToolCallLimitMiddleware`](https://reference.langchain.com/python/langchain/middleware/#langchain.agents.middleware.ToolCallLimitMiddleware)

```python theme={null}
from langchain.agents import create_agent
from langchain.agents.middleware import ToolCallLimitMiddleware

агент = create_agent(
    model="gpt-4.1",
    tools=[search_tool, database_tool],
    промежуточное ПО=[
        # Глобальный лимит
        ToolCallLimitMiddleware(thread_limit=20, run_limit=10),
        # Ограничение, специфичное для инструмента
        ToolCallLimitMiddleware(
            tool_name="search",
            thread_limit=5,
            run_limit=3,
        ),
    ],
)
```

  Посмотрите это [видеоруководство](https://www.youtube.com/watch?v=6gYlaJJ8t0w), демонстрирующее работу промежуточного ПО Tool Call Limit.
</Callout>

<Заголовок аккордеона="Параметры конфигурации">
  <ParamField body="tool_name" type="string">
    Название конкретного инструмента, для которого необходимо установить ограничения. Если это не указано, ограничения применяются ко **всем инструментам в глобальном масштабе**.
  </ParamField>

  <ParamField body="thread_limit" type="number">
    Максимальное количество вызовов инструмента за все запуски в потоке (диалоге). Сохраняется при многократных вызовах с одним и тем же идентификатором потока. Для поддержания состояния требуется контрольная точка. `None` означает отсутствие ограничения на количество потоков.
  </ParamField>

  <ParamField body="run_limit" type="number">
    Максимальное количество вызовов инструмента за один цикл (одно сообщение пользователя → цикл ответа). Сбрасывается с каждым новым сообщением пользователя. `None` означает отсутствие ограничения на количество запусков.

    **Примечание:** Необходимо указать хотя бы один из параметров `thread_limit` или `run_limit`.
  </ParamField>

  <ParamField body="exit_behavior" type="string" default="continue">
    Поведение при достижении лимита:

    * `'продолжить'` (по умолчанию) - Блокировать превышение количества вызовов инструментов с сообщениями об ошибках, позволяя другим инструментам и модели продолжать работу. Модель сама решает, когда завершить работу, на основе сообщений об ошибках.
    * `'error'` — Вызывает исключение `ToolCallLimitExceededError`, немедленно останавливая выполнение.
    * `'end'` — Немедленно останавливает выполнение с сообщением `ToolMessage` и сообщением AI о превышении количества вызовов инструмента. Работает только при ограничении одного инструмента; вызывает `NotImplementedError`, если у других инструментов есть ожидающие вызовы.
  </ParamField>
</Аккордеон>

<Заголовок аккордеона="Полный пример">
  Укажите ограничения с помощью:

  * **Ограничение на количество потоков** - Максимальное количество вызовов за все сеансы в рамках диалога (требуется Checkpointer)
  * **Ограничение на количество запусков** - Максимальное количество вызовов за один цикл (сбрасывается каждый ход)

  Выходные действия:

  * `'продолжить'` (по умолчанию) - Заблокировано более вызовов с сообщениями об ошибках, агент продолжает работу
  * `'error'` - Немедленно вызвать исключение
  * `'end'` - Остановка с помощью сообщения ToolMessage + сообщения AI (только в сценариях с одним инструментом)

  ```python theme={null}
  from langchain.agents import create_agent
  from langchain.agents.middleware import ToolCallLimitMiddleware


  global_limiter = ToolCallLimitMiddleware(thread_limit=20, run_limit=10)
  search_limiter = ToolCallLimitMiddleware(tool_name="search", thread_limit=5, run_limit=3)
  database_limiter = ToolCallLimitMiddleware(tool_name="query_database", thread_limit=10)
  strict_limiter = ToolCallLimitMiddleware(tool_name="scrape_webpage", run_limit=2, exit_behavior="error")

  агент = create_agent(
      model="gpt-4.1",
      tools=[search_tool, database_tool, scraper_tool],
      middleware=[global_limiter, search_limiter, database_limiter, strict_limiter],
  )
  ```
</Аккордеон>

### Резервный вариант модели

Автоматическое переключение на альтернативные модели при сбое основной модели. Переключение на альтернативные модели полезно в следующих случаях:

* Создание отказоустойчивых агентов, способных справляться с перебоями в работе модели.

### Выбор инструмента LLM

Используйте LLM для интеллектуального выбора соответствующих инструментов перед вызовом основной модели. Инструменты выбора LLM полезны в следующих случаях:

* Агенты, использующие множество инструментов (более 10), большинство из которых неактуальны для конкретного запроса.
* Сокращение использования токенов путем фильтрации нерелевантных инструментов.
* Повышение точности и сфокусированности модели.

Это промежуточное программное обеспечение использует структурированный вывод для запроса к LLM о том, какие инструменты наиболее актуальны для текущего запроса. Схема структурированного вывода определяет доступные названия и описания инструментов. Поставщики моделей часто добавляют эту информацию из структурированного вывода в системную подсказку в фоновом режиме.

**Справочник по API:** [`LLMToolSelectorMiddleware`](https://reference.langchain.com/python/langchain/middleware/#langchain.agents.middleware.LLMToolSelectorMiddleware)

```python theme={null}
from langchain.agents import create_agent

агент = create_agent(

    промежуточное ПО=[
        LLMToolSelectorMiddleware(
            model="gpt-4.1-mini",

            always_include=["search"],

```

### Повторная попытка использования инструмента

Автоматическое повторение неудачных вызовов инструментов с настраиваемой экспоненциальной задержкой. Повторные попытки использования инструментов полезны в следующих случаях:

* Обработка временных сбоев при вызовах внешнего API.
* Повышение надежности сетевых инструментов.
* Создание отказоустойчивых агентов, которые корректно обрабатывают временные ошибки.

**Справочник по API:** [`ToolRetryMiddleware`](https://reference.langchain.com/python/langchain/middleware/#langchain.agents.middleware.ToolRetryMiddleware)

```python theme={null}
from langchain.agents import create_agent

агент = create_agent(
    model="gpt-4.1",
    tools=[search_tool, database_tool],
    промежуточное ПО=[
        ToolRetryMiddleware(
            max_retries=3,
            backoff_factor=2.0,
            initial_delay=1.0,
        ),
    ],
)
```

<Заголовок аккордеона="Параметры конфигурации">
  <ParamField body="max_retries" type="number" default="2">
    Максимальное количество повторных попыток после первого вызова (всего 3 попытки, по умолчанию)

  </ParamField>

  <ParamField body="retry_on" type="tuple[type[Exception], ...] | callable" default="(Exception,)">
    Либо кортеж типов исключений для повторной попытки, либо вызываемая функция, которая принимает исключение и возвращает `True`, если требуется повторная попытка.
  </ParamField>

  <ParamField body="on_failure" type="string | callable" default="return_message">
    Поведение при исчерпании всех попыток повтора. Варианты:

    * `'return_message'` - Возвращает объект `ToolMessage` с подробными сведениями об ошибке (позволяет LLM обрабатывать сбои)
    * `'raise'` — Повторно инициирует исключение (останавливает выполнение агента)
    * Пользовательская вызываемая функция — функция, которая принимает исключение и возвращает строку с содержимым `ToolMessage`.
  </ParamField>

  <ParamField body="backoff_factor" type="number" default="2.0">

  </ParamField>

  <ParamField body="max_delay" type="number" default="60.0">

  </ParamField>

  <ParamField body="jitter" type="boolean" default="true">
    Стоит ли добавлять случайные колебания (±25%) к задержке, чтобы избежать грохочущего стада?
  </ParamField>
</Аккордеон>

### Эмулятор инструмента LLM

Для целей тестирования можно эмулировать выполнение инструментов с помощью LLM, заменяя фактические вызовы инструментов ответами, сгенерированными ИИ. Эмуляторы инструментов на основе LLM полезны в следующих случаях:

* Тестирование поведения агента без запуска реальных инструментов.
* Разработка агентов в случаях, когда внешние инструменты недоступны или дороги.
* Разработка прототипов рабочих процессов агентов перед внедрением реальных инструментов.

**Справочник по API:** [`LLMToolEmulator`](https://reference.langchain.com/python/langchain/middleware/#langchain.agents.middleware.LLMToolEmulator)

```python theme={null}
from langchain.agents import create_agent
from langchain.agents.middleware import LLMToolEmulator

агент = create_agent(
    model="gpt-4.1",
    tools=[get_weather, search_database, send_email],
    промежуточное ПО=[
        LLMToolEmulator(), # Эмуляция всех инструментов
    ],
)
```

<Заголовок аккордеона="Параметры конфигурации">
  <ParamField body="tools" type="list[str | BaseTool]">
    Список названий инструментов (строка) или экземпляров BaseTool для эмуляции. Если `None` (по умолчанию), будут эмулированы ВСЕ инструменты. Если список `[]` пуст, эмулироваться не будут никакие инструменты. Если список содержит названия/экземпляры инструментов, будут эмулироваться только эти инструменты.
  </ParamField>

  <ParamField body="model" type="string | BaseChatModel">
    Модель, используемая для генерации эмулированных ответов инструмента. Может быть строкой идентификатора модели (например, `'anthropic:claude-sonnet-4-5-20250929'`) или экземпляром `BaseChatModel`. По умолчанию используется модель агента, если не указана. Дополнительную информацию см. в [`init_chat_model`](https://reference.langchain.com/python/langchain/models/#langchain.chat_models.init_chat_model\(model\)).
  </ParamField>
</Аккордеон>

<Заголовок аккордеона="Полный пример">
  Промежуточное программное обеспечение использует LLM для генерации правдоподобных ответов на вызовы инструментов вместо выполнения самих инструментов.

### Редактирование контекста

Управляйте контекстом разговора, очищая старые результаты вызовов инструментов при достижении лимита токенов, сохраняя при этом последние результаты. Это помогает поддерживать управляемость контекстных окон в длительных разговорах с большим количеством вызовов инструментов. Редактирование контекста полезно в следующих случаях:

* Длительные диалоги с множеством вызовов инструментов, превышающие лимиты токенов.
* Снижение стоимости токенов за счет удаления устаревших результатов работы инструментов, которые больше не актуальны.
* Сохранение в контексте только самых последних результатов работы инструмента N.

**Справочник по API:** [`ContextEditingMiddleware`](https://reference.langchain.com/python/langchain/middleware/#langchain.agents.middleware.ContextEditingMiddleware), [`ClearToolUsesEdit`](https://reference.langchain.com/python/langchain/middleware/#langchain.agents.middleware.ClearToolUsesEdit)

```python theme={null}
from langchain.agents import create_agent
from langchain.agents.middleware import ContextEditingMiddleware, ClearToolUsesEdit

агент = create_agent(
    model="gpt-4.1",
    инструменты=[],
    промежуточное ПО=[
        ContextEditingMiddleware(
            edits=[
                ClearToolUsesEdit(
                    trigger=100000,
                    keep=3,
                ),
            ],
        ),
    ],
)
```

<Заголовок аккордеона="Параметры конфигурации">
  <ParamField body="edits" type="list[ContextEdit]" default="[ClearToolUsesEdit()]">
    Список стратегий [`ContextEdit`](https://reference.langchain.com/python/langchain/middleware/#langchain.agents.middleware.ContextEdit), которые можно применить.
  </ParamField>

  <ParamField body="token_count_method" type="string" default="approximate">
    Метод подсчета токенов. Варианты: `'приблизительный'` или `'модель'`.
  </ParamField>

  **[`ClearToolUsesEdit`](https://reference.langchain.com/python/langchain/middleware/#langchain.agents.middleware.ClearToolUsesEdit) options:**

  <ParamField body="trigger" type="number" default="100000">
    Количество токенов, запускающих редактирование. Когда количество токенов в беседе превысит это значение, старые результаты работы инструмента будут удалены.
  </ParamField>

  <ParamField body="clear_at_least" type="number" default="0">
    Минимальное количество токенов, которое необходимо освободить при редактировании. Если установлено значение 0, освобождается столько токенов, сколько необходимо.
  </ParamField>

  <ParamField body="keep" type="number" default="3">
    Количество последних результатов работы инструмента, которые необходимо сохранить. Эти данные никогда не будут удалены.
  </ParamField>

  <ParamField body="clear_tool_inputs" type="boolean" default="False">
    Следует ли очищать параметры вызова инструмента, инициировавшего сообщение ИИ. Если `True`, аргументы вызова инструмента заменяются пустыми объектами.
  </ParamField>

  <ParamField body="exclude_tools" type="list[string]" default="()">
    Список названий инструментов, которые следует исключить из процесса очистки. Результаты работы этих инструментов никогда не будут очищены.
  </ParamField>

  <ParamField body="placeholder" type="string" default="[cleared]">
    Вставлен текст-заполнитель для очищенных результатов работы инструмента. Он заменяет исходное содержимое сообщения инструмента.
  </ParamField>
</Аккордеон>

<Заголовок аккордеона="Полный пример">
  Промежуточное ПО применяет стратегии редактирования контекста при достижении лимита токенов. Наиболее распространенная стратегия — `ClearToolUsesEdit`, которая удаляет старые результаты использования инструментов, сохраняя при этом последние.

  **Как это работает:**

  1. Отслеживайте количество токенов в разговоре.
  2. При достижении порогового значения удалите старые выходные данные инструмента.
  3. Сохраняйте самые последние результаты работы инструмента N.
  4. При желании можно сохранить аргументы вызова инструмента для контекста.

  ```python theme={null}
  from langchain.agents import create_agent
  from langchain.agents.middleware import ContextEditingMiddleware, ClearToolUsesEdit


  агент = create_agent(
      model="gpt-4.1",
      tools=[search_tool, your_calculator_tool, database_tool],
      промежуточное ПО=[
          ContextEditingMiddleware(
              edits=[
                  ClearToolUsesEdit(
                      trigger=2000,
                      keep=3,
                      clear_tool_inputs=False,
                      exclude_tools=[],
                      placeholder="[cleared]",
                  ),
              ],
          ),
      ],
  )
  ```
</Аккордеон>

### Инструмент командной оболочки

Предоставьте агентам постоянный доступ к сеансу командной оболочки для выполнения команд. Промежуточное программное обеспечение для работы с командной оболочкой полезно в следующих случаях:

* Агенты, которым необходимо выполнять системные команды
* Задачи автоматизации разработки и развертывания
* Рабочие процессы тестирования и проверки
* Операции с файловой системой и выполнение скриптов

<Предупреждение>
  **Вопросы безопасности**: Используйте соответствующие политики выполнения (`HostExecutionPolicy`, `DockerExecutionPolicy` или `CodexSandboxExecutionPolicy`), чтобы соответствовать требованиям безопасности вашего развертывания.
</Предупреждение>

<Примечание>
  **Ограничение**: В настоящее время постоянные сеансы командной оболочки не работают с прерываниями (с участием человека). Мы планируем добавить поддержку этой функции в будущем.
</Примечание>

**Справочник по API:** [`ShellToolMiddleware`](https://reference.langchain.com/python/langchain/middleware/#langchain.agents.middleware.ShellToolMiddleware)

```python theme={null}
from langchain.agents import create_agent
from langchain.agents.middleware import (
    ShellToolMiddleware,
    HostExecutionPolicy,
)

агент = create_agent(
    model="gpt-4.1",
    инструменты=[search_tool],
    промежуточное ПО=[
        ShellToolMiddleware(
            workspace_root="/workspace",
            execution_policy=HostExecutionPolicy(),
        ),
    ],
)
```

<Заголовок аккордеона="Параметры конфигурации">
  <ParamField body="workspace_root" type="str | Path | None">
    Базовый каталог для сеанса командной оболочки. Если этот параметр опущен, при запуске агента создается временный каталог, который удаляется при его завершении.
  </ParamField>

  <ParamField body="startup_commands" type="tuple[str, ...] | list[str] | str | None">
    Дополнительные команды выполняются последовательно после начала сессии.
  </ParamField>

  <ParamField body="shutdown_commands" type="tuple[str, ...] | list[str] | str | None">
    Дополнительные команды, выполняемые перед завершением сессии.
  </ParamField>

  <ParamField body="execution_policy" type="BaseExecutionPolicy | None">
    Политика выполнения, контролирующая тайм-ауты, ограничения на вывод и конфигурацию ресурсов. Параметры:

    * `HostExecutionPolicy` — Полный доступ к хосту (по умолчанию); лучше всего подходит для доверенных сред, где агент уже работает внутри контейнера или виртуальной машины.
    * `DockerExecutionPolicy` — запускает отдельный контейнер Docker для каждого запуска агента, обеспечивая более надежную изоляцию.
    * `CodexSandboxExecutionPolicy` — повторно использует песочницу Codex CLI для дополнительных ограничений системных вызовов/файловой системы.
  </ParamField>

  <ParamField body="redaction_rules" type="tuple[RedactionRule, ...] | list[RedactionRule] | None">
    Дополнительные правила редактирования для очистки выходных данных команды перед их возвратом в модель.

    <Предупреждение>
      Правила маскировки применяются после выполнения и не предотвращают утечку секретов или конфиденциальных данных при использовании `HostExecutionPolicy`.
    </Предупреждение>
  </ParamField>

  <ParamField body="tool_description" type="str | None">
    Дополнительное поле для изменения описания зарегистрированного инструмента оболочки (необязательно).
  </ParamField>

  <ParamField body="shell_command" type="Sequence[str] | str | None">
    Необязательный исполняемый файл оболочки (строка) или последовательность аргументов, используемых для запуска постоянной сессии. По умолчанию используется `/bin/bash`.
  </ParamField>

  <ParamField body="env" type="Mapping[str, Any] | None">
    Необязательные переменные окружения, которые передаются в сессию оболочки. Значения преобразуются в строки перед выполнением команды.
  </ParamField>
</Аккордеон>

<Заголовок аккордеона="Полный пример">

### Поиск файлов

Предоставьте инструменты поиска Glob и Grep по файловой системе. Промежуточное программное обеспечение для поиска файлов полезно в следующих случаях:

* Исследование и анализ кода
* Поиск файлов по шаблонам имен
* Поиск содержимого кода с помощью регулярных выражений
* Большие кодовые базы, где требуется обнаружение файлов

**Справочник по API:** [`FilesystemFileSearchMiddleware`](https://reference.langchain.com/python/langchain/middleware/#langchain.agents.middleware.FilesystemFileSearchMiddleware)

```python theme={null}
from langchain.agents import create_agent
from langchain.agents.middleware import FilesystemFileSearchMiddleware

агент = create_agent(
    model="gpt-4.1",
    инструменты=[],
    промежуточное ПО=[
        FilesystemFileSearchMiddleware(
            root_path="/workspace",
            use_ripgrep=True,
        ),
    ],
)
```

<Заголовок аккордеона="Параметры конфигурации">
  <ParamField body="root_path" type="str" ​​required>
    Корневой каталог для поиска. Все операции с файлами выполняются относительно этого пути.
  </ParamField>

  <ParamField body="use_ripgrep" type="bool" default="True">
    Использовать ли ripgrep для поиска. В случае недоступности ripgrep используется регулярное выражение Python.
  </ParamField>

  <ParamField body="max_file_size_mb" type="int" default="10">
    Максимальный размер файла для поиска указан в МБ. Файлы большего размера будут пропущены.
  </ParamField>
</Аккордеон>

<Заголовок аккордеона="Полный пример">
  Промежуточное программное обеспечение добавляет агентам два инструмента поиска:

  **Инструмент Glob** - Быстрое сопоставление шаблонов файлов:

  * Поддерживает шаблоны типа `**/*.py`, `src/**/*.ts`
  * Возвращает соответствующие пути к файлам, отсортированные по времени изменения.

  **Инструмент Grep** - Поиск контента с использованием регулярных выражений:

  * Полная поддержка синтаксиса регулярных выражений
  * Фильтрация по шаблонам файлов с помощью параметра `include`
  * Три режима вывода: `files_with_matches`, `content`, `count`

  ```python theme={null}
  from langchain.agents import create_agent
  from langchain.agents.middleware import FilesystemFileSearchMiddleware
  from langchain.messages import HumanMessage


  агент = create_agent(
      model="gpt-4.1",
      инструменты=[],
      промежуточное ПО=[
          FilesystemFileSearchMiddleware(
              root_path="/workspace",
              use_ripgrep=True,
              max_file_size_mb=10,
          ),
      ],
  )

  # Теперь агент может использовать инструменты glob_search и grep_search
  результат = agent.invoke({
      "messages": [HumanMessage("Найти все файлы Python, содержащие 'async def'")]
  })

  # Агент будет использовать:
  # 1. glob_search(pattern="**/*.py") для поиска файлов Python
  # 2. grep_search(pattern="async def", include="*.py") для поиска асинхронных функций
  ```
</Аккордеон>
