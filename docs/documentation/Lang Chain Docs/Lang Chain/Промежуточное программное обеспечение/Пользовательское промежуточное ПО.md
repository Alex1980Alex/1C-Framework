# Пользовательское промежуточное ПО

Создавайте собственное промежуточное ПО, реализуя обработчики событий, которые запускаются в определенных точках процесса выполнения агента.

Промежуточное ПО предоставляет два типа перехватчиков для перехвата выполнения агентов:

### Хуки в стиле узлов

Выполнять последовательно в определенных точках выполнения. Использовать для логирования, проверки и обновления состояния.

**Доступные крючки:**

* `before_agent` - Перед запуском агента (один раз за вызов)
* `before_model` - Перед каждым вызовом модели
* `after_model` - После каждого ответа модели
* `after_agent` - После завершения работы агента (один раз за вызов)

**Пример:**

<Вкладки>

    ```python theme={null}
    из langchain.messages импортировать AIMessage
    from langgraph.runtime import Runtime
    из набора текста импортировать Any


    @before_model(can_jump_to=["end"])
    def check_message_limit(state: AgentState, runtime: Runtime) -> dict[str, Any] | None:
        if len(state["messages"]) >= 50:
            возвращаться {
                "messages": [AIMessage("Достигнут лимит разговоров."),
                "jump_to": "end"

    @after_model
    def log_response(state: AgentState, runtime: Runtime) -> dict[str, Any] | None:
        print(f"Возвращенная модель: {state['messages'][-1].content}")
    ```

### Крючки обхватывающего типа

Перехватывать выполнение и управлять процессом при вызове обработчика. Использовать для повторных попыток, кэширования и преобразования.

Вы сами решаете, будет ли обработчик вызываться ноль раз (короткое замыкание), один раз (нормальный поток) или несколько раз (логика повторных попыток).

**Доступные крючки:**

* `wrap_model_call` - Оборачивает каждый вызов модели
* `wrap_tool_call` — Обёртывает каждый вызов инструмента

**Пример:**

<Вкладки>
  <Tab title="Декоратор">
    ```python theme={null}
    from langchain.agents.middleware import wrap_model_call, ModelRequest, ModelResponse
    from typing import Callable


    @wrap_model_call
    def retry_model(
        запрос: ModelRequest,
        обработчик: Callable[[ModelRequest], ModelResponse],
    ) -> ModelResponse:
        для попытки в диапазоне(3):
            пытаться:
                return handler(request)
            за исключением исключения как e:
                если попытка == 2:
                    поднимать
                print(f"Повторить попытку {попытка + 1}/3 после ошибки: {e}")
    ```
  </Tab>

  <Tab title="Class">
    ```python theme={null}
    from langchain.agents.middleware import AgentMiddleware, ModelRequest, ModelResponse
    from typing import Callable

    класс RetryMiddleware(AgentMiddleware):
        def __init__(self, max_retries: int = 3):
            super().__init__()
            self.max_retries = max_retries

        def wrap_model_call(
            себя,
            запрос: ModelRequest,
            обработчик: Callable[[ModelRequest], ModelResponse],
        ) -> ModelResponse:
            for attempt in range(self.max_retries):
                пытаться:
                    return handler(request)
                за исключением исключения как e:
                    если attempt == self.max_retries - 1:
                        поднимать
                    print(f"Повторить попытку {attempt + 1}/{self.max_retries} после ошибки: {e}")
    ```

</Вкладки>

### Промежуточное ПО на основе декораторов

Быстрое и простое решение для промежуточного ПО с одним хуком. Используйте декораторы для обертывания отдельных функций.

**Доступные декораторы:**

**Стиль узла:**

* [`@before_agent`](https://reference.langchain.com/python/langchain/middleware/#langchain.agents.middleware.before_agent) - Выполняется перед запуском агента (один раз за вызов)
* [`@before_model`](https://reference.langchain.com/python/langchain/middleware/#langchain.agents.middleware.before_model) - Выполняется перед каждым вызовом модели
* [`@after_model`](https://reference.langchain.com/python/langchain/middleware/#langchain.agents.middleware.after_model) - Выполняется после каждого ответа модели
* [`@after_agent`](https://reference.langchain.com/python/langchain/middleware/#langchain.agents.middleware.after_agent) - Запускается после завершения работы агента (один раз за вызов)

**В стиле "обмотка":**

* [`@wrap_model_call`](https://reference.langchain.com/python/langchain/middleware/#langchain.agents.middleware.wrap_model_call) - Оборачивает каждый вызов модели пользовательской логикой
* [`@wrap_tool_call`](https://reference.langchain.com/python/langchain/middleware/#langchain.agents.middleware.wrap_tool_call) - Оборачивает каждый вызов инструмента пользовательской логикой

**Удобство:**

* [`@dynamic_prompt`](https://reference.langchain.com/python/langchain/middleware/#langchain.agents.middleware.dynamic_prompt) - Генерирует динамические системные подсказки

**Пример:**

```python theme={null}
from langchain.agents.middleware import (
    before_model,
    wrap_model_call,
    AgentState,
    ModelRequest,
    МодельОтвет,
)
from langchain.agents import create_agent
from langgraph.runtime import Runtime
from typing import Any, Callable


@before_model
def log_before_model(state: AgentState, runtime: Runtime) -> dict[str, Any] | None:
    print(f"Собираемся вызвать модель с {len(state['messages'])} сообщениями")
    вернуть None

@wrap_model_call
def retry_model(
    запрос: ModelRequest,
    обработчик: Callable[[ModelRequest], ModelResponse],
) -> ModelResponse:
    для попытки в диапазоне(3):
        пытаться:
            return handler(request)
        за исключением исключения как e:
            если попытка == 2:
                поднимать
            print(f"Повторить попытку {попытка + 1}/3 после ошибки: {e}")

агент = create_agent(
    model="gpt-4.1",
    middleware=[log_before_model, retry_model],
    инструменты=[...],
)
```

**Когда следует привлекать декораторов:**

* Требуется один крючок
* Без сложной конфигурации
* Быстрое прототипирование

### Промежуточное ПО на основе классов

Более мощный инструмент для сложных промежуточных обработчиков с множеством хуков или конфигураций. Используйте классы, когда вам нужно определить как синхронные, так и асинхронные реализации для одного и того же хука, или когда вы хотите объединить несколько хуков в одном промежуточном обработчике.

**Пример:**

```python theme={null}
from langchain.agents.middleware import (
    AgentMiddleware,
    AgentState,
    ModelRequest,
    МодельОтвет,
)
from langgraph.runtime import Runtime
from typing import Any, Callable

класс LoggingMiddleware(AgentMiddleware):
    def before_model(self, state: AgentState, runtime: Runtime) -> dict[str, Any] | None:
        print(f"Собираемся вызвать модель с {len(state['messages'])} сообщениями")
        вернуть None

    def after_model(self, state: AgentState, runtime: Runtime) -> dict[str, Any] | None:
        print(f"Возвращенная модель: {state['messages'][-1].content}")
        вернуть None

агент = create_agent(
    model="gpt-4.1",
    промежуточное ПО=[LoggingMiddleware()],
    инструменты=[...],
)
```

**Когда использовать классы:**

* Определение синхронной и асинхронной реализаций для одного и того же хука.
* В одном промежуточном ПО требуется несколько хуков.
* Требуется сложная настройка (например, настраиваемые пороговые значения, пользовательские модели)
* Повторное использование в разных проектах с конфигурацией на этапе инициализации

## Пользовательская схема состояния

Промежуточное ПО может расширять состояние агента с помощью пользовательских свойств. Это позволяет промежуточному ПО:

* **Отслеживание состояния на протяжении всего выполнения**: Поддержание счетчиков, флагов или других значений, которые сохраняются на протяжении всего жизненного цикла выполнения агента.

* **Обмен данными между хуками**: Передача информации из `before_model` в `after_model` или между различными экземплярами промежуточного ПО.

* **Реализация сквозных задач**: добавление таких функций, как ограничение скорости запросов, отслеживание использования, контекст пользователя или ведение журнала аудита, без изменения основной логики агента.

* **Принимайте решения в зависимости от условий**: используйте накопленное состояние, чтобы определить, следует ли продолжать выполнение, переходить к другим узлам или динамически изменять поведение.

## Порядок исполнения

При использовании нескольких промежуточных программ необходимо понимать, как они выполняются:

```python theme={null}
агент = create_agent(
    model="gpt-4.1",
    middleware=[middleware1, middleware2, middleware3],
    инструменты=[...],
)
```

<Заголовок аккордеона="Последовательность выполнения">
  **Перед началом последовательности заброса крючков:**

  1. `middleware1.before_agent()`
  2. `middleware2.before_agent()`
  3. `middleware3.before_agent()`

  **Запуск агентского цикла**

  4. `middleware1.before_model()`
  5. `middleware2.before_model()`
  6. `middleware3.before_model()`

  **Обёртки для хуков вложены в вызовы функций:**

  7. `middleware1.wrap_model_call()` → `middleware2.wrap_model_call()` → `middleware3.wrap_model_call()` → модель

  **После выполнения забросов крючков в обратном порядке:**

  8. `middleware3.after_model()`
  9. `middleware2.after_model()`
  10. `middleware1.after_model()`

  **Завершение работы агентского цикла**

  11. `middleware3.after_agent()`
  12. `middleware2.after_agent()`
  13. `middleware1.after_agent()`
</Аккордеон>

**Основные правила:**

* Хуки `before_*`: от первого до последнего
* `after_*` hooks: Last to first (reverse)
* Хуки `wrap_*`: Вложенные (первый промежуточный обработчик оборачивает все остальные)

## Агент прыгает

Для досрочного выхода из промежуточного ПО верните словарь с параметром `jump_to`:

**Доступные цели для прыжка:**

* `'end'`: Переход к концу выполнения агента (или к первому хуку `after_agent`)
* `'инструменты'`: Переход к узлу инструментов
* `'model'`: Переход к узлу модели (или к первому хуку `before_model`)

## Передовые методы

1. Сосредоточьтесь на одном направлении в промежуточном ПО — каждое из них должно хорошо выполнять одну задачу.
2. Обрабатывайте ошибки корректно — не допускайте сбоев агента из-за ошибок промежуточного ПО.
3. **Используйте крючки соответствующего типа**:
   * Стиль узлов для последовательной логики (логирование, проверка данных)
   * Использование обертки для управления потоком выполнения (повторная попытка, резервный вариант, кэширование)
4. Четко задокументируйте все пользовательские свойства состояния.
5. Перед интеграцией проведите независимое модульное тестирование промежуточного программного обеспечения.
6. Учитывайте порядок выполнения — разместите критически важное промежуточное ПО первым в списке.
7. По возможности используйте встроенное промежуточное программное обеспечение.

    ```python theme={null}
        ) -> ToolMessage | Command:
            print(f"Выполняется инструмент: {request.tool_call['name']}")
            print(f"Аргументы: {request.tool_call['args']}")
            пытаться:
                результат = обработчик(запрос)
                print(f"Инструмент успешно завершен")
                вернуть результат
            за исключением исключения как e:
                print(f"Инструмент не сработал: {e}")
                поднимать
    ```
  </Tab>
</Вкладки>

### Динамический выбор инструментов

Для повышения производительности и точности выбирайте соответствующие инструменты во время выполнения. В этом разделе рассматривается фильтрация предварительно зарегистрированных инструментов. Для регистрации инструментов, обнаруженных во время выполнения (например, на серверах MCP), см. [Регистрация инструментов во время выполнения](/oss/python/langchain/agents#dynamic-tools).

**Преимущества:**

* **Более короткие подсказки** — Снижаем сложность, отображая только необходимые инструменты.
* **Повышенная точность** - Модели правильно выбирают из меньшего количества вариантов.
* **Контроль прав доступа** - Динамическая фильтрация инструментов на основе прав доступа пользователя.

<Вкладки>
  <Tab title="Декоратор">
    ```python theme={null}
    from langchain.agents import create_agent
    from langchain.agents.middleware import wrap_model_call, ModelRequest, ModelResponse
    from typing import Callable


    @wrap_model_call
    def select_tools(
        запрос: ModelRequest,
        обработчик: Callable[[ModelRequest], ModelResponse],
    ) -> ModelResponse:
        «Промежуточное программное обеспечение для выбора соответствующих инструментов в зависимости от состояния/контекста».
        # Выберите небольшое, подходящее подмножество инструментов на основе состояния/контекста
        relevant_tools = select_relevant_tools(request.state, request.runtime)
        return handler(request.override(tools=relevant_tools))

    агент = create_agent(
        model="gpt-4.1",
        tools=all_tools, # Все доступные инструменты необходимо зарегистрировать заранее
        middleware=[select_tools],
    )
    ```

### Работа с системными сообщениями

Изменяйте системные сообщения в промежуточном ПО, используя поле `system_message` в `ModelRequest`. Поле `system_message` содержит объект [`SystemMessage`](https://reference.langchain.com/python/langchain/messages/#langchain.messages.SystemMessage) (даже если агент был создан со строкой `system_prompt`).

**Пример: Добавление контекста к системному сообщению**

<Вкладки>
  <Tab title="Декоратор">
    ```python theme={null}
    from langchain.agents.middleware import wrap_model_call, ModelRequest, ModelResponse
    from langchain.messages import SystemMessage
    from typing import Callable


    @wrap_model_call
    def add_context(
        запрос: ModelRequest,
        обработчик: Callable[[ModelRequest], ModelResponse],
    ) -> ModelResponse:
        # Всегда работайте с блоками контента
        new_content = list(request.system_message.content_blocks) + [
            {"type": "text", "text": "Дополнительный контекст."}
        ]
        new_system_message = SystemMessage(content=new_content)
        return handler(request.override(system_message=new_system_message))
    ```
  </Tab>

  <Tab title="Class">

**Пример: Работа с управлением кэшем (антропный режим)**

При работе с антропными моделями можно использовать блоки структурированного контента с директивами управления кэшированием для кэширования больших системных запросов:

<Вкладки>
  <Tab title="Декоратор">
    ```python theme={null}
    from langchain.agents.middleware import wrap_model_call, ModelRequest, ModelResponse
    from langchain.messages import SystemMessage
    from typing import Callable


    @wrap_model_call
    def add_cached_context(
        запрос: ModelRequest,
        обработчик: Callable[[ModelRequest], ModelResponse],
    ) -> ModelResponse:
        # Всегда работайте с блоками контента
        new_content = list(request.system_message.content_blocks) + [
            {
                "type": "text",
                "текст": "Вот большой документ для анализа:\n\n<документ>...</документ>",
                # Контент до этого момента кэшируется
                "cache_control": {"type": "ephemeral"}
            }
        ]

        new_system_message = SystemMessage(content=new_content)
        return handler(request.override(system_message=new_system_message))
    ```
  </Tab>

  <Tab title="Class">

**Примечания:**

* `ModelRequest.system_message` всегда является объектом типа [`SystemMessage`](https://reference.langchain.com/python/langchain/messages/#langchain.messages.SystemMessage), даже если агент был создан с параметром `system_prompt="string"`.
* Используйте `SystemMessage.content_blocks` для доступа к содержимому в виде списка блоков, независимо от того, было ли исходное содержимое строкой или списком.
* При изменении системных сообщений используйте `content_blocks` и добавляйте новые блоки, чтобы сохранить существующую структуру.
* Для расширенных сценариев использования, таких как управление кэшированием, вы можете передавать объекты [`SystemMessage`](https://reference.langchain.com/python/langchain/messages/#langchain.messages.SystemMessage) непосредственно параметру `system_prompt` функции `create_agent`.
