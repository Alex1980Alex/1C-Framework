# Тест

Приложения, использующие агентные модели, позволяют LLM самостоятельно определять дальнейшие шаги для решения проблемы. Эта гибкость является мощным инструментом, но «черноящичная» природа модели затрудняет прогнозирование того, как изменение одной части агента повлияет на остальную. Для создания готовых к использованию в производстве агентов необходимо тщательное тестирование.

Существует несколько подходов к тестированию ваших агентов:

* [Модульные тесты](#unit-testing) проверяют небольшие, детерминированные части вашего агента изолированно, используя поддельные данные в памяти, чтобы вы могли быстро и детерминированно подтвердить точное поведение.

* [Интеграционные тесты](#integration-testing) проверяют работу агента с использованием реальных сетевых вызовов, чтобы подтвердить, что компоненты работают вместе, учетные данные и схемы совпадают, а задержка приемлема.

В агентных приложениях, как правило, больше внимания уделяется интеграции, поскольку они объединяют множество компонентов и должны учитывать нестабильность, обусловленную недетерминированным характером линейных моделей поведения.

## Модульное тестирование

### Имитация модели чата

Для логики, не требующей вызовов API, можно использовать заглушку в оперативной памяти для имитации ответов.

LangChain предоставляет [`GenericFakeChatModel`](https://python.langchain.com/api_reference/core/language_models/langchain_core.language_models.fake_chat_models.GenericFakeChatModel.html) для имитации текстовых ответов. Он принимает итератор ответов (AIMessages или строк) и возвращает один итератор за каждый вызов. Поддерживается как обычное, так и потоковое использование.

```python theme={null}
from langchain_core.language_models.fake_chat_models import GenericFakeChatModel

модель = GenericFakeChatModel(messages=iter([
    AIMessage(content="", tool_calls=[ToolCall(name="foo", args={"bar": "baz"}, id="call_1")]),
    "бар"
]))

model.invoke("hello")
# AIMessage(content='', ..., tool_calls=[{'name': 'foo', 'args': {'bar': 'baz'}, 'id': 'call_1', 'type': 'tool_call'}])
```

Если мы снова вызовем модель, она вернет следующий элемент в итераторе:

```python theme={null}
model.invoke("Привет, снова!")
# AIMessage(content='bar', ...)
```

### Контрольная точка InMemorySaver

Для обеспечения сохранения данных во время тестирования можно использовать контрольную точку [`InMemorySaver`](https://reference.langchain.com/python/langgraph/checkpoints/#langgraph.checkpoint.memory.InMemorySaver). Это позволяет имитировать несколько итераций для проверки поведения, зависящего от состояния:

```python theme={null}
from langgraph.checkpoint.memory import InMemorySaver

агент = create_agent(
    модель,
    инструменты=[],
    checkpointer=InMemorySaver()
)

# Первое заклинание
agent.invoke(
    {"messages": [HumanMessage(content="Я живу в Сиднее, Австралия")]},
    config={"configurable": {"thread_id": "session-1"}}
)

# Второй вызов: первое сообщение сохраняется (местоположение в Сиднее), поэтому модель возвращает время GMT+10.
agent.invoke(
    {"messages": [HumanMessage(content="Какое у меня местное время?")]},
    config={"configurable": {"thread_id": "session-1"}}
)
```

## Интеграционное тестирование

Многие особенности поведения агентов проявляются только при использовании реальной модели LLM, например, какой инструмент агент решает вызвать, как он форматирует ответы или влияет ли изменение подсказки на всю траекторию выполнения. Пакет [`agentevals`](https://github.com/langchain-ai/agentevals) от LangChain предоставляет инструменты оценки, специально разработанные для тестирования траекторий агентов с помощью реальных моделей.

AgentEvals позволяет легко оценить траекторию вашего агента (точную последовательность сообщений, включая вызовы инструментов), выполнив **сопоставление траектории** или используя **судью LLM**:

<Card title="Trajectory match" icon="equals" arrow="true" href="#trajectory-match-evaluator">
  Задайте эталонную траекторию в заданном коде и проверьте правильность выполнения с помощью пошагового сравнения.

  Идеально подходит для тестирования четко определенных рабочих процессов, где известно ожидаемое поведение. Используйте, когда у вас есть конкретные ожидания относительно того, какие инструменты должны быть вызваны и в каком порядке. Этот подход является детерминированным, быстрым и экономически эффективным, поскольку не требует дополнительных вызовов LLM.
</Карточка>

<Card title="LLM-as-judge" icon="gavel" arrow="true" href="#llm-as-judge-evaluator">
  Используйте LLM для качественной проверки траектории выполнения действий вашим агентом. «Судья» LLM оценивает решения агента по критериям, приведенным в подсказке (которая может включать эталонную траекторию).

  Более гибкий и позволяющий оценивать тонкие аспекты, такие как эффективность и целесообразность, но требует вызова LLM и менее детерминирован. Используется, когда необходимо оценить общее качество и обоснованность траектории агента без строгих требований к вызову инструмента или порядку действий.
</Карточка>

### Оценщик соответствия траектории

AgentEvals предлагает функцию `create_trajectory_match_evaluator` для сопоставления траектории вашего агента с эталонной траекторией. Доступны четыре режима:

| Режим       | Описание                                                                       | Вариант использования                                                                   |
| ----------- | ------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------- |
| `strict`    | Точное совпадение сообщений и вызовов инструментов в одном и том же порядке    | Проверка определенных последовательностей (например, поиск политики перед авторизацией) |
| `unordered` | Разрешены вызовы одного и того же инструмента в любом порядке                  | Проверка получения информации, когда порядок не имеет значения                          |
| `subset`    | Агент вызывает только инструменты из ссылки (без дополнительных)               | Гарантия того, что агент не выходит за рамки ожидаемой области действия                 |
| `superset`  | Агент вызывает как минимум справочные инструменты (допускаются дополнительные) | Проверка выполнения минимально необходимых действий                                     |

<Accordion title="Строгое соответствие">
  Режим «строгий» гарантирует, что траектории содержат идентичные сообщения в одном и том же порядке с одними и теми же вызовами инструментов, хотя и допускает различия в содержимом сообщений. Это полезно, когда необходимо обеспечить соблюдение определенной последовательности операций, например, потребовать проверки политики перед авторизацией действия.

  ```python theme={null}
  from langchain.agents import create_agent
  from langchain.tools import tool
  from langchain.messages import HumanMessage, AIMessage, ToolMessage
  from agentevals.trajectory.match import create_trajectory_match_evaluator


  @инструмент
  def get_weather(city: str):
      «Получите информацию о погоде в городе».
      return f"В городе 75 градусов и солнечно."

  agent = create_agent("gpt-4.1", tools=[get_weather])

  evaluator = create_trajectory_match_evaluator( # [!code highlight]
      trajectory_match_mode="strict", # [!code highlight]
  ) # [!подсветка кода]

  def test_weather_tool_called_strict():
      результат = agent.invoke({
          "messages": [HumanMessage(content="Какая погода в Сан-Франциско?")]
      })

      reference_trajectory = [
          HumanMessage(content="Какая погода в Сан-Франциско?"),
          AIMessage(content="", tool_calls=[
              {"id": "call_1", "name": "get_weather", "args": {"city": "Сан-Франциско"}}
          ]),
          ToolMessage(content="В Сан-Франциско 75 градусов и солнечно."", tool_call_id="call_1"),
          AIMessage(content="Погода в Сан-Франциско 75 градусов и солнечно."),
      ]

      оценка = оценщик(
          outputs=result["messages"],
          reference_outputs=reference_trajectory
      )
      # {
      # 'key': 'trajectory_strict_match',
      # 'score': True,
      # 'комментарий': Нет,
      # }
      assert evaluation["score"] is True
  ```
</Аккордеон>

<Accordion title="Unordered match">
  Режим «без порядка» позволяет вызывать одни и те же инструменты в любом порядке, что полезно, когда нужно убедиться, что конкретная информация была получена, но последовательность не имеет значения. Например, агенту может потребоваться проверить и погоду, и события для города, но порядок не имеет значения.

  ```python theme={null}
  from langchain.agents import create_agent
  from langchain.tools import tool
  from langchain.messages import HumanMessage, AIMessage, ToolMessage
  from agentevals.trajectory.match import create_trajectory_match_evaluator


  @инструмент
  def get_weather(city: str):
      «Получите информацию о погоде в городе».
      return f"В городе 75 градусов и солнечно."

  @инструмент
  def get_events(city: str):
      «Организуйте мероприятия в городе».
      Концерт в парке в {городе} сегодня вечером."

  agent = create_agent("gpt-4.1", tools=[get_weather, get_events])

  evaluator = create_trajectory_match_evaluator( # [!code highlight]
      trajectory_match_mode="unordered", # [!code highlight]
  ) # [!подсветка кода]

  def test_multiple_tools_any_order():
      результат = agent.invoke({
          "messages": [HumanMessage(content="Что сегодня происходит в Сан-Франциско?")]
      })

      # В справке показаны инструменты, вызываемые в порядке, отличном от фактического выполнения.
      reference_trajectory = [
          HumanMessage(content="Что сегодня происходит в Сан-Франциско?"),
          AIMessage(content="", tool_calls=[
              {"id": "call_1", "name": "get_events", "args": {"city": "SF"}},
              {"id": "call_2", "name": "get_weather", "args": {"city": "SF"}},
          ]),
          ToolMessage(content="Концерт в парке в Сан-Франциско сегодня вечером."", tool_call_id="call_1"),
          ToolMessage(content="В Сан-Франциско 75 градусов и солнечно."", tool_call_id="call_2"),
          AIMessage(content="Сегодня в Сан-Франциско: 75 градусов и солнечно, вечером концерт в парке."),
      ]

      оценка = оценщик(
          outputs=result["messages"],
          reference_outputs=reference_trajectory,
      )
      # {
      # 'key': 'trajectory_unordered_match',
      # 'score': True,
      # }
      assert evaluation["score"] is True
  ```
</Аккордеон>

<Заголовок аккордеона="Совпадение подмножества и надмножества">
  Режимы `superset` и `subset` соответствуют частичным траекториям. Режим `superset` проверяет, что агент вызвал как минимум инструменты из эталонной траектории, допуская дополнительные вызовы инструментов. Режим `subset` гарантирует, что агент не вызывал никаких инструментов, кроме тех, что указаны в эталонной траектории.

  ```python theme={null}
  from langchain.agents import create_agent
  from langchain.tools import tool
  from langchain.messages import HumanMessage, AIMessage, ToolMessage
  from agentevals.trajectory.match import create_trajectory_match_evaluator


  @инструмент
  def get_weather(city: str):
      «Получите информацию о погоде в городе».
      return f"В городе 75 градусов и солнечно."

  @инструмент
  def get_detailed_forecast(city: str):
      «Получите подробный прогноз погоды для города».
      "Подробный прогноз погоды для города {city}: солнечно всю неделю."

  agent = create_agent("gpt-4.1", tools=[get_weather, get_detailed_forecast])

  evaluator = create_trajectory_match_evaluator( # [!code highlight]
      trajectory_match_mode="superset", # [!code highlight]
  ) # [!подсветка кода]

  def test_agent_calls_required_tools_plus_extra():
      результат = agent.invoke({
          "messages": [HumanMessage(content="Какая погода в Бостоне?")]
      })

      # Для работы требуется только get_weather, но агент может использовать дополнительные инструменты.
      reference_trajectory = [
          HumanMessage(content="Какая погода в Бостоне?"),
          AIMessage(content="", tool_calls=[
              {"id": "call_1", "name": "get_weather", "args": {"city": "Boston"}},
          ]),
          ToolMessage(content="В Бостоне 75 градусов и солнечно."", tool_call_id="call_1"),
          AIMessage(content="Погода в Бостоне 75 градусов и солнечно."),
      ]

      оценка = оценщик(
          outputs=result["messages"],
          reference_outputs=reference_trajectory,
      )
      # {
      # 'key': 'trajectory_superset_match',
      # 'score': True,
      # 'комментарий': Нет,
      # }
      assert evaluation["score"] is True
  ```
</Аккордеон>

<Информация>
  Вы также можете установить свойство `tool_args_match_mode` и/или `tool_args_match_overrides`, чтобы настроить, как оценщик учитывает равенство между вызовами инструментов в фактической траектории и эталонной. По умолчанию равными считаются только вызовы инструментов с одинаковыми аргументами для одного и того же инструмента. Для получения более подробной информации посетите [репозиторий](https://github.com/langchain-ai/agentevals?tab=readme-ov-file#tool-args-match-modes).
</Info>

### Эксперт по оценке в качестве судьи (LLM-as-Judge)

Также можно использовать LLM для оценки пути выполнения агента с помощью функции `create_trajectory_llm_as_judge`. В отличие от оценщиков соответствия траектории, он не требует эталонной траектории, но ее можно предоставить, если она доступна.

<Заголовок аккордеона="Без опорной траектории">
  ```python theme={null}
  from langchain.agents import create_agent
  from langchain.tools import tool
  from langchain.messages import HumanMessage, AIMessage, ToolMessage
  from agentevals.trajectory.llm import create_trajectory_llm_as_judge, TRAJECTORY_ACCURACY_PROMPT


  @инструмент
  def get_weather(city: str):
      «Получите информацию о погоде в городе».
      return f"В городе 75 градусов и солнечно."

  agent = create_agent("gpt-4.1", tools=[get_weather])

  evaluator = create_trajectory_llm_as_judge( # [!code highlight]
      model="openai:o3-mini", # [!code highlight]
      prompt=TRAJECTORY_ACCURACY_PROMPT, # [!code highlight]
  ) # [!подсветка кода]

  def test_trajectory_quality():
      результат = agent.invoke({
          "messages": [HumanMessage(content="Какая погода в Сиэтле?")]
      })

      оценка = оценщик(
          outputs=result["messages"],
      )
      # {
      # 'key': 'trajectory_accuracy',
      # 'score': True,
      # 'comment': 'Предоставленная траектория движения агента является разумной...'
      # }
      assert evaluation["score"] is True
  ```
</Аккордеон>

<Accordion title="С эталонной траекторией">
  Если у вас есть опорная траектория, вы можете добавить дополнительную переменную в свою подсказку и передать в нее опорную траекторию. Ниже мы используем встроенную подсказку `TRAJECTORY_ACCURACY_PROMPT_WITH_REFERENCE` и настраиваем переменную `reference_outputs`:

  ```python theme={null}
  evaluator = create_trajectory_llm_as_judge(
      model="openai:o3-mini",
      prompt=TRAJECTORY_ACCURACY_PROMPT_WITH_REFERENCE,
  )
  оценка = оценщик(
      outputs=result["messages"],
      reference_outputs=reference_trajectory,
  )
  ```
</Аккордеон>

<Информация>
  Для более гибкой настройки способа оценки траектории с помощью LLM посетите [репозиторий](https://github.com/langchain-ai/agentevals?tab=readme-ov-file#trajectory-llm-as-judge).
</Info>

### Поддержка асинхронного режима

Все оценщики `agentevals` поддерживают Python asyncio. Для оценщиков, использующих фабричные функции, асинхронные версии доступны путем добавления `async` после `create_` в имени функции.

<Accordion title="Пример асинхронного судьи и оценщика">
  ```python theme={null}
  from agentevals.trajectory.llm import create_async_trajectory_llm_as_judge, TRAJECTORY_ACCURACY_PROMPT
  from agentevals.trajectory.match import create_async_trajectory_match_evaluator

  async_judge = create_async_trajectory_llm_as_judge(
      model="openai:o3-mini",
      prompt=TRAJECTORY_ACCURACY_PROMPT,
  )

  async_evaluator = create_async_trajectory_match_evaluator(
      trajectory_match_mode="strict",
  )

  async def test_async_evaluation():
      результат = await agent.ainvoke({
          "messages": [HumanMessage(content="Какая погода?")]
      })

      evaluation = await async_judge(outputs=result["messages"])
      assert evaluation["score"] is True
  ```
</Аккордеон>

## Интеграция с LangSmith

Для отслеживания экспериментов во времени вы можете записывать результаты оценки в [LangSmith](https://smith.langchain.com/), платформу для создания приложений LLM производственного уровня, которая включает инструменты для трассировки, оценки и экспериментирования.

Сначала настройте LangSmith, установив необходимые переменные среды:

```bash theme={null}
export LANGSMITH_API_KEY="your_langsmith_api_key"
export LANGSMITH_TRACING="true"
```

LangSmith предлагает два основных подхода к выполнению оценок: интеграция с [pytest](/langsmith/pytest) и функция `evaluate`.

<Accordion title="Использование интеграции pytest">
  ```python theme={null}
  импортировать pytest
  из langsmith импорт тестирование как t
  from agentevals.trajectory.llm import create_trajectory_llm_as_judge, TRAJECTORY_ACCURACY_PROMPT

  trajectory_evaluator = create_trajectory_llm_as_judge(
      model="openai:o3-mini",
      prompt=TRAJECTORY_ACCURACY_PROMPT,
  )

  @pytest.mark.langsmith
  def test_trajectory_accuracy():
      результат = agent.invoke({
          "messages": [HumanMessage(content="Какая погода в Сан-Франциско?")]
      })

      reference_trajectory = [
          HumanMessage(content="Какая погода в Сан-Франциско?"),
          AIMessage(content="", tool_calls=[
              {"id": "call_1", "name": "get_weather", "args": {"city": "SF"}},
          ]),
          ToolMessage(content="В Сан-Франциско 75 градусов и солнечно."", tool_call_id="call_1"),
          AIMessage(content="В Сан-Франциско 75 градусов и солнечно."),
      ]

      # Запись входных, выходных и эталонных выходных данных в LangSmith
      t.log_inputs({})
      t.log_outputs({"messages": result["messages"]})
      t.log_reference_outputs({"messages": reference_trajectory})

      trajectory_evaluator(
          outputs=result["messages"],
          reference_outputs=reference_trajectory
      )
  ```

  Выполните оценку с помощью pytest:

  ```bash theme={null}
  pytest test_trajectory.py --langsmith-output
  ```

  Результаты будут автоматически зарегистрированы в LangSmith.
</Аккордеон>

<Заголовок аккордеона="Использование функции evaluate">
  В качестве альтернативы вы можете создать набор данных в LangSmith и использовать функцию `evaluate`:

  ```python theme={null}
  from langsmith import Client
  from agentevals.trajectory.llm import create_trajectory_llm_as_judge, TRAJECTORY_ACCURACY_PROMPT

  клиент = Клиент()

  trajectory_evaluator = create_trajectory_llm_as_judge(
      model="openai:o3-mini",

      «Функция вашего агента, которая возвращает сообщения о траектории».
  ```

## Запись и воспроизведение HTTP-запросов

Интеграционные тесты, вызывающие реальные API LLM, могут быть медленными и ресурсоемкими, особенно при частом запуске в конвейерах CI/CD. Мы рекомендуем использовать библиотеку для записи HTTP-запросов и ответов, а затем воспроизводить их в последующих запусках без выполнения реальных сетевых запросов.

Для этого можно использовать [`vcrpy`](https://pypi.org/project/vcrpy/1.5.2/). Если вы используете `pytest`, [`pytest-recording` plugin](https://pypi.org/project/pytest-recording/) предоставляет простой способ включить эту функцию с минимальной конфигурацией. Запросы/ответы записываются в кассеты, которые затем используются для имитации реальных сетевых вызовов в последующих запусках.

Настройте файл `conftest.py` таким образом, чтобы он отфильтровывал конфиденциальную информацию с кассет:

```py conftest.py theme={null}
импортировать pytest

@pytest.fixture(scope="session")
def vcr_config():
    возвращаться {
        "filter_headers": [
            ("авторизация", "XXXX"),
            ("x-api-key", "XXXX"),
            # ... другие заголовки, которые вы хотите скрыть
        ],
        "filter_query_parameters": [
            ("api_key", "XXXX"),
            ("ключ", "XXXX"),
        ],
    }
```

Затем настройте свой проект так, чтобы он распознавал маркер `vcr`:

<CodeGroup>
  ```ini pytest.ini theme={null}
  [pytest]
  маркеры =
      vcr: запись/воспроизведение по HTTP через VCR
  addopts = --record-mode=once
  ```

  ```toml pyproject.toml theme={null}
  [tool.pytest.ini_options]
  маркеры = [
    "vcr: запись/воспроизведение по HTTP через видеомагнитофон"
  ]
  addopts = "--record-mode=once"
  ```
</CodeGroup>

<Информация>
  Опция `--record-mode=once` записывает HTTP-взаимодействия при первом запуске и воспроизводит их при последующих запусках.
</Info>

Теперь просто добавьте к своим тестам маркер `vcr`:

```python theme={null}
@pytest.mark.vcr()
def test_agent_trajectory():
    # ...
```

При первом запуске этого теста ваш агент будет совершать реальные сетевые вызовы, и pytest сгенерирует файл-кассету `test_agent_trajectory.yaml` в каталоге `tests/cassettes`. При последующих запусках эта кассета будет использоваться для имитации реальных сетевых вызовов, при условии, что запросы агента не изменятся по сравнению с предыдущим запуском. Если же они изменятся, тест завершится неудачей, и вам потребуется удалить кассету и запустить тест заново, чтобы записать новые взаимодействия.

<Предупреждение>
  При изменении подсказок, добавлении новых инструментов или изменении ожидаемых траекторий ваши сохраненные файлы устареют, и существующие тесты **завершится неудачей**. Вам следует удалить соответствующие файлы и повторно запустить тесты, чтобы записать новые взаимодействия.
</Предупреждение>
