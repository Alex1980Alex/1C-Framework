# Контекстная инженерия в агентах

## Обзор

Самая сложная часть создания агентов (или любого другого приложения LLM) — это обеспечение их достаточной надежности. Хотя они могут работать в прототипе, в реальных условиях эксплуатации они часто дают сбой.

### Почему агенты терпят неудачу?

Когда агенты дают сбой, это обычно происходит из-за того, что внутри агента произошел неправильный звонок LLM / он не выполнил то, что мы ожидали. Сбои LLM происходят по одной из двух причин:

1. Базовая модель LLM недостаточно функциональна.
2. «Правильный» контекст не был передан в программу магистратуры по праву.

Чаще всего именно вторая причина делает агентов ненадежными.

**Разработка контекста** — это предоставление нужной информации и инструментов в нужном формате, чтобы LLM мог выполнить задачу. Это первостепенная задача инженеров в области ИИ. Отсутствие «правильного» контекста является главной проблемой для создания более надежных агентов, и абстракции агентов LangChain специально разработаны для облегчения разработки контекста.

<Совет>
  Новичок в проектировании контекста? Начните с [концептуального обзора](/oss/python/concepts/context), чтобы понять различные типы контекста и когда их использовать.
</Совет>

### Цикл агента

Типичный цикл работы агента состоит из двух основных этапов:

1. **Вызов модели** — вызывает LLM с подсказкой и доступными инструментами, возвращает либо ответ, либо запрос на выполнение инструментов.
2. **Выполнение инструментов** - выполняет инструменты, запрошенные LLM, и возвращает результаты выполнения инструментов.

### Что вы можете контролировать

Для создания надежных агентов необходимо контролировать все процессы на каждом этапе цикла работы агента, а также то, что происходит между этапами.

| Тип контекста                                               | Что вы контролируете                                                                                                                     | Временный или постоянный |
| ----------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------- | ------------------------ |
| **[Контекст модели](#model-context)**                       | Что входит в вызовы модели (инструкции, история сообщений, инструменты, формат ответа)                                                   | Временный                |
| **[Контекст инструмента](#tool-context)**                   | К каким инструментам можно получить доступ и что они могут создавать (чтение/запись в состояние, хранилище, контекст времени выполнения) | Постоянное               |
| **[Контекст жизненного цикла](#контекст жизненного цикла)** | Что происходит между вызовами модели и инструмента (суммирование, ограничения, логирование и т. д.)                                      | Постоянное               |

### Источники данных

В ходе этого процесса ваш агент получает доступ (читает/записывает) к различным источникам данных:

| Источник данных         | Также известен как       | Область применения        | Примеры                                                                                       |
| ----------------------- | ------------------------ | ------------------------- | --------------------------------------------------------------------------------------------- |
| **Контекст выполнения** | Статическая конфигурация | В рамках диалога          | Идентификатор пользователя, ключи API, подключения к базе данных, разрешения, настройки среды |
| **Состояние**           | Кратковременная память   | В рамках беседы           | Текущие сообщения, загруженные файлы, статус аутентификации, результаты работы инструмента    |
| **Магазин**             | Долговременная память    | Межсетевое взаимодействие | Пользовательские предпочтения, извлеченные данные, воспоминания, исторические данные          |

### Как это работает

LangChain [middleware](/oss/python/langchain/middleware) — это внутренний механизм, который делает разработку контекста практичной для разработчиков, использующих LangChain.

Промежуточное ПО позволяет подключаться к любому этапу жизненного цикла агента и:

* Обновить контекст
* Перейти к другому этапу жизненного цикла агента

В этом руководстве вы часто будете встречать API промежуточного ПО как средство для решения задачи проектирования контекста.

### Системная подсказка

Системные подсказки определяют поведение и возможности LLM. Разные пользователи, контексты или этапы разговора требуют разных инструкций. Успешные агенты используют память, предпочтения и конфигурацию для предоставления правильных инструкций в зависимости от текущего состояния разговора.

### Сообщения

Сообщения составляют запрос, который отправляется в магистратуру.
Крайне важно управлять содержанием сообщений, чтобы гарантировать, что у магистра права есть вся необходимая информация для эффективного ответа.

    ```python theme={null}
        # Чтение из состояния: получение метаданных загруженных файлов
        uploaded_files = request.state.get("uploaded_files", []) # [!code highlight]

            # Внедрить контекст файла перед последними сообщениями
            сообщения = [ # [!подсветка кода]

                {"role": "user", "content": file_context},
            ]
            request = request.override(messages=messages) # [!выделение кода]
    ```

<Примечание>
  **Временные и постоянные обновления сообщений:**

  В приведенных выше примерах используется `wrap_model_call` для выполнения **временных** обновлений — изменения того, какие сообщения отправляются модели для одного вызова, без изменения того, что сохранено в состоянии.

  Для **постоянных** обновлений, изменяющих состояние (как в примере с суммированием в [Контекст жизненного цикла](#summarization)), используйте хуки жизненного цикла, такие как `before_model` или `after_model`, чтобы навсегда обновить историю разговора. ### Инструменты

Инструменты позволяют модели взаимодействовать с базами данных, API и внешними системами. То, как вы определяете и выбираете инструменты, напрямую влияет на то, сможет ли модель эффективно выполнять задачи.

#### Определение инструментов

Каждому инструменту необходимы четкое название, описание, названия аргументов и описания аргументов. Это не просто метаданные — они определяют, когда и как использовать инструмент, на основе рассуждений модели.

```python theme={null}
from langchain.tools import tool

@tool(parse_docstring=True)
def search_orders(
    user_id: str,
    статус: строка,
    limit: int = 10
) -> str:
    """Поиск заказов пользователей по статусу."

    Используйте это, когда пользователь спрашивает об истории заказов или хочет проверить
    Статус заказа. Всегда фильтруйте по указанному статусу.

    Аргументы:
        user_id: Уникальный идентификатор пользователя
        Статус: Статус заказа: «ожидание», «отправлено» или «доставлено»
        limit: Максимальное количество возвращаемых результатов
    """
    # Реализация здесь
    проходить
```

#### Выбор инструментов

Не каждый инструмент подходит для каждой ситуации. Слишком много инструментов может перегрузить модель (перегрузить контекст) и увеличить количество ошибок; слишком мало ограничивает возможности. Динамический выбор инструментов адаптирует доступный набор инструментов в зависимости от состояния аутентификации, прав пользователя, флагов функций или этапа диалога.

### Формат ответа

Структурированный вывод преобразует неструктурированный текст в проверенные структурированные данные. При извлечении определенных полей или возврате данных для последующих систем, свободного текста недостаточно.

**Как это работает:** Если вы указываете схему в качестве формата ответа, гарантируется, что окончательный ответ модели будет соответствовать этой схеме. Агент запускает цикл вызова модели/инструмента до тех пор, пока модель не завершит вызов инструментов, после чего окончательный ответ преобразуется в предоставленный формат.

#### Определение форматов

Определения схемы определяют модель. Названия полей, типы и описания точно указывают, какому формату должен соответствовать вывод.

```python theme={null}
from pydantic import BaseModel, Field

class CustomerSupportTicket(BaseModel):
    «Структурированная информация о заявке, извлеченная из сообщения клиента».

    категория: str = Field(
        description="Категория проблемы: 'выставление счетов', 'техническая проблема', 'учетная запись' или 'продукт'"
    )
    приоритет: str = Field(
        description="Уровень срочности: низкий, средний, высокий или критический"
    )
    сводка: str = Field(
        описание="Краткое изложение проблемы клиента в одном предложении"
    )
    customer_sentiment: str = Field(
        description="Эмоциональный тон клиента: 'разочарованный', 'нейтральный' или 'удовлетворенный'"
    )
```

## Контекст инструмента

Инструменты уникальны тем, что они одновременно считывают и записывают контекст.

В самом простом случае, когда инструмент запускается, он получает параметры запроса от LLM и возвращает сообщение инструмента. Инструмент выполняет свою работу и выдает результат.

Инструменты также могут получать важную информацию для модели, которая позволяет ей выполнять и завершать задачи.

### Чтения

Большинству реальных инструментов требуется больше, чем просто параметры LLM. Им нужны идентификаторы пользователей для запросов к базе данных, ключи API для внешних сервисов или текущее состояние сессии для принятия решений. Инструменты считывают эту информацию из состояния, хранилища и контекста выполнения.

    ```python theme={null}
        api_key = runtime.context.api_key
        db_connection = runtime.context.db_connection

        # Используйте конфигурацию для получения данных
        results = perform_database_query(db_connection, query, api_key)

        return f"Найдено {len(results)} результатов для пользователя {user_id}"

    агент = create_agent(
        model="gpt-4.1",
        tools=[fetch_user_data],
        context_schema=Context
    )

    # Вызов с учетом контекста выполнения
    результат = agent.invoke(
        {"messages": [{"role": "user", "content": "Получить мои данные"}]},
        контекст=Контекст(
            user_id="user_123",
            api_key="sk-...",
            db_connection="postgresql://..."
        )
    )
    ```

</Вкладки>

и обновить память агента, чтобы сделать важный контекст доступным для будущих шагов.

    ```python theme={null}
    from dataclasses import dataclass
    from langchain.tools import tool, ToolRuntime
    from langchain.agents import create_agent
    from langgraph.store.memory import InMemoryStore

    @dataclass
    Контекст класса:
        user_id: str

    @инструмент
    def save_preference(
        preference_key: str,
        preference_value: str,
        среда выполнения: ToolRuntime[Context]
    ) -> str:
        """Сохранить настройки пользователя в магазине."""
        user_id = runtime.context.user_id

        # Прочитать существующие настройки
        store = runtime.store
        existing_prefs = store.get(("preferences",), user_id)

        # Объединить с новыми настройками
        prefs = existing_prefs.value if existing_prefs else {}
        prefs[preference_key] = preference_value

        # Запись в хранилище: сохранение обновленных настроек
        store.put(("preferences",), user_id, prefs)

        return f"Сохраненная настройка: {preference_key} = {preference_value}"

    агент = create_agent(
        model="gpt-4.1",
        инструменты=[save_preference],
        context_schema=Context,
        store=InMemoryStore()
    )
    ```

## Контекст жизненного цикла

Контролируйте то, что происходит **между** основными этапами работы агента — перехватывайте поток данных для реализации сквозных задач, таких как суммирование, ограничения и ведение журналов.

Как вы уже видели в [Контекст модели](#model-context) и [Контекст инструмента](#tool-context), [промежуточное ПО](/oss/python/langchain/middleware) — это механизм, который делает проектирование контекста практичным. Промежуточное ПО позволяет подключаться к любому этапу жизненного цикла агента и либо:

1. **Обновить контекст** — Изменить состояние и сохранить изменения, обновить историю переписки или сохранить аналитические данные.
2. **Переход на новый этап жизненного цикла** — Переход к различным этапам цикла агента в зависимости от контекста (например, пропуск выполнения инструмента, если условие выполнено, повторный вызов модели с измененным контекстом).

### Пример: Подведение итогов

Один из наиболее распространенных шаблонов жизненного цикла — автоматическое сокращение истории переписки, когда она становится слишком длинной. В отличие от временного сокращения сообщений, показанного в [Контекст модели](#сообщения), суммирование **постоянно обновляет состояние** — навсегда заменяя старые сообщения кратким изложением, которое сохраняется для всех будущих ходов.

LangChain предлагает для этого встроенное промежуточное программное обеспечение:

```python theme={null}
from langchain.agents import create_agent
from langchain.agents.middleware import SummarizationMiddleware

агент = create_agent(
    model="gpt-4.1",
    инструменты=[...],
    промежуточное ПО=[
        SummarizationMiddleware(
            model="gpt-4.1-mini",
            trigger={"tokens": 4000},
            keep={"messages": 20},
        ),
    ],
)
```

Когда в ходе беседы превышается лимит токенов, `SummarizationMiddleware` автоматически выполняет следующие действия:

1. Обобщает старые сообщения с помощью отдельного вызова LLM.
2. Заменяет их сводным сообщением в разделе «Состояние» (навсегда).
3. Сохраняет недавние сообщения в неизменном виде для контекста.

Краткая история переписки обновляется постоянно — в последующих раундах вместо исходных сообщений будет отображаться только краткое содержание.

## Передовые методы

1. **Начните с простого** — начните со статических подсказок и инструментов, добавляйте динамику только при необходимости.
2. **Тестируйте поэтапно** — добавляйте по одной функции контекстной инженерии за раз.
3. **Мониторинг производительности** - Отслеживание вызовов модели, использования токенов и задержки.
4. **Используйте встроенное промежуточное ПО** - Задействуйте [`SummarizationMiddleware`](/oss/python/langchain/middleware#summarization), [`LLMToolSelectorMiddleware`](/oss/python/langchain/middleware#llm-tool-selector) и т. д.
5. **Задокументируйте свою стратегию использования контекста** — Четко укажите, какой контекст передается и зачем.
6. **Разберитесь в различиях между временными и постоянными изменениями**: Изменения контекста модели являются временными (для каждого вызова), в то время как изменения контекста в течение жизненного цикла сохраняются до состояния.
