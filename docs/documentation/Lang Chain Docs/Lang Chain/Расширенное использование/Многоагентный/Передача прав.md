# Передача полномочий

В архитектуре **handoffs** поведение динамически изменяется в зависимости от состояния. Основной механизм: [инструменты](/oss/python/langchain/tools) обновляют переменную состояния (например, `current_step` или `active_agent`), которая сохраняется между ходами, и система считывает эту переменную для корректировки поведения — либо применяя другую конфигурацию (подсказка системы, инструменты), либо перенаправляя на другого [агента](/oss/python/langchain/agents). Этот шаблон поддерживает как передачу управления между различными агентами, так и динамические изменения конфигурации внутри одного агента.

<Совет>
  Термин **handoffs** был придуман [OpenAI](https://openai.github.io/openai-agents-python/handoffs/) для обозначения использования вызовов инструментов (например, `transfer_to_sales_agent`) для передачи управления между агентами или состояниями.
</Совет>

## Ключевые характеристики

* Поведение, определяемое состоянием: Изменения поведения на основе переменной состояния (например, `current_step` или `active_agent`)
* Переходы на основе инструментов: Инструменты обновляют переменную состояния для перехода между состояниями.
* Прямое взаимодействие с пользователем: конфигурация каждого штата обрабатывает сообщения пользователя напрямую.
* Устойчивое состояние: состояние сохраняется на протяжении всего диалога.

## Когда использовать

Используйте шаблон «передача управления», когда необходимо соблюдать последовательные ограничения (разблокировать возможности только после выполнения предварительных условий), когда агенту необходимо напрямую общаться с пользователем на разных этапах или когда вы строите многоэтапные диалоговые потоки. Этот шаблон особенно полезен в сценариях поддержки клиентов, где необходимо собирать информацию в определенной последовательности — например, собирать идентификатор гарантии перед обработкой возврата средств.

## Базовая реализация

Основной механизм — это [инструмент](/oss/python/langchain/tools), который возвращает [`Команду`](/oss/python/langgraph/graph-api#command) для обновления состояния, запускающего переход к новому шагу или агенту:

```python theme={null}
from langchain.tools import tool
from langchain.messages import ToolMessage
from langgraph.types import Command

@инструмент
def transfer_to_specialist(runtime) -> Command:
    «Перевод агенту-специалисту».
    return Command(
        обновление={
            "сообщения": [
                ToolMessage( # [!подсветка кода]
                    content="Передано специалисту",
                    tool_call_id=runtime.tool_call_id # [!code highlight]
                )
            ],
            "current_step": "specialist" # Запускает изменение поведения
        }
    )
```

<Примечание>
  **Зачем включать `ToolMessage`?** Когда LLM вызывает инструмент, он ожидает ответа. `ToolMessage` с соответствующим `tool_call_id` завершает этот цикл запрос-ответ — без него история разговора становится некорректной. Это необходимо всякий раз, когда ваш инструмент передачи обновляет сообщения.
</Примечание>

Полную версию инструкции см. в руководстве ниже.

## Подходы к реализации

Существует два способа реализации передачи управления: **[один агент с промежуточным ПО](#single-agent-with-middleware)** (один агент с динамической конфигурацией) или **[несколько подграфов агентов](#multiple-agent-subgraphs)** (различные агенты в качестве узлов графа).

### Один агент с промежуточным ПО

Поведение отдельного агента изменяется в зависимости от состояния. Промежуточное ПО перехватывает каждый вызов модели и динамически корректирует системную подсказку и доступные инструменты. Инструменты обновляют переменную состояния для запуска переходов:

```python theme={null}
from langchain.tools import ToolRuntime, tool
from langchain.messages import ToolMessage
from langgraph.types import Command

@инструмент
def record_warranty_status(
    статус: строка,
    runtime: ToolRuntime[None, SupportState]
) -> Команда:
    «Зафиксируйте статус гарантии и перейдите к следующему шагу».
    return Command(
        обновление={
            "сообщения": [
                ToolMessage(
                    content="Зарегистрирован статус гарантии: {status}",
                    tool_call_id=runtime.tool_call_id
                )
            ],
            "warranty_status": статус,
            "current_step": "specialist" # Обновите состояние, чтобы запустить переход
        }
    )
```

### Подграфы с несколькими агентами

В графе существует несколько различных агентов, представленных отдельными узлами. Инструменты передачи управления позволяют перемещаться между узлами агентов, используя `Command.PARENT` для указания того, какой узел следует выполнить следующим.

<Предупреждение>
  Передача сообщений между подграфами требует тщательной **[контекстной инженерии](/oss/python/langchain/context-engineering)**. В отличие от промежуточного ПО с одним агентом (где история сообщений передается естественным образом), вы должны явно определить, какие сообщения передаются между агентами. Если вы допустите ошибку, агенты получат некорректную историю разговора или избыточный контекст. См. [Контекстная инженерия](#context-engineering) ниже.
</Предупреждение>

```python theme={null}
from langchain.messages import AIMessage, ToolMessage
from langchain.tools import tool, ToolRuntime
from langgraph.types import Command

@инструмент
def transfer_to_sales(
    среда выполнения: ToolRuntime,
) -> Команда:
    «Передать агенту по продажам».
    last_ai_message = next( # [!code highlight]
        msg for msg in reversed(runtime.state["messages"]) if isinstance(msg, AIMessage) # [!code highlight]
    ) # [!подсветка кода]
    transfer_message = ToolMessage( # [!code highlight]
        content="Передано торговому агенту", # [!code highlight]
        tool_call_id=runtime.tool_call_id, # [!code highlight]
    ) # [!подсветка кода]
    return Command(
        goto="sales_agent",
        обновление={
            "active_agent": "sales_agent",
            "messages": [last_ai_message, transfer_message], # [!code highlight]
        },
        graph=Command.PARENT
    )
```

  from langchain.agents import AgentState, create_agent
  from langchain.messages import AIMessage, ToolMessage
  from langchain.tools import tool, ToolRuntime

  @инструмент
  def transfer_to_sales(
      среда выполнения: ToolRuntime,
  ) -> Команда:

              "active_agent": "sales_agent",
              "messages": [last_ai_message, transfer_message], # [!code highlight]
          },

      )


  @инструмент
  def transfer_to_support(
      среда выполнения: ToolRuntime,

      last_ai_message = next( # [!code highlight]
          msg for msg in reversed(runtime.state["messages"]) if isinstance(msg, AIMessage) # [!code highlight]

          tool_call_id=runtime.tool_call_id, # [!code highlight]
      ) # [!подсветка кода]
      return Command(
          goto="support_agent",
          обновление={
              "active_agent": "support_agent",
              "messages": [last_ai_message, transfer_message], # [!code highlight]
          },
          graph=Command.PARENT,
      )


  # 3. Создание агентов с инструментами для передачи задач.
  sales_agent = create_agent(
      model="anthropic:claude-sonnet-4-20250514",
      инструменты=[transfer_to_support],
      system_prompt="Вы являетесь торговым представителем. Помогите с вопросами, касающимися продаж. Если у вас возникли вопросы по техническим проблемам или поддержке, перенаправьте их специалисту службы поддержки."

  )

  def call_sales_agent(state: MultiAgentState) -> Command:
      «Примечание, которое нужно отправить торговому агенту».
      response = sales_agent.invoke(state)
      вернуть ответ

      «Примечание, которое свяжется с агентом службы поддержки».
      response = support_agent.invoke(state)
      вернуть ответ

  def route_after_agent(
      состояние: MultiAgentState,
  ) -> Literal["sales_agent", "support_agent", "__end__"]:

      сообщения = state.get("сообщения", [])

      # Проверяем последнее сообщение — если это AIMessage без вызовов инструментов, то работа завершена.
      если сообщения:
          last_msg = messages[-1]

              return "__end__" # [!code highlight]

      active = state.get("active_agent", "sales_agent")
      Возвращать активный, если активен, иначе "sales_agent"


  def route_initial(
      состояние: MultiAgentState,
  ) -> Literal["sales_agent", "support_agent"]:
      «Переадресация вызова активного агента в зависимости от штата, по умолчанию — агент по продажам».
      return state.get("active_agent") or "sales_agent"


  # 6. Постройте график
  builder = StateGraph(MultiAgentState)
  builder.add_node("sales_agent", call_sales_agent)

  builder.add_conditional_edges(
      "sales_agent", route_after_agent, ["sales_agent", "support_agent", END]
  )
  builder.add_conditional_edges(
      "support_agent", route_after_agent, ["sales_agent", "support_agent", END]
  )

  graph = builder.compile()
  результат = graph.invoke(

          ]
      }
  )

#### Контекстная инженерия

При использовании механизма передачи данных между подграфами вы точно контролируете, какие сообщения передаются между агентами. Эта точность необходима для поддержания достоверной истории разговоров и предотвращения раздувания контекста, которое может запутать последующих агентов. Подробнее об этом см. [контекстная инженерия](/oss/python/langchain/context-engineering).

**Обработка контекста при передаче информации**

При передаче управления между агентами необходимо убедиться, что история разговора остается достоверной. LLM-ы ожидают, что вызовы инструментов будут связаны с их ответами, поэтому при использовании `Command.PARENT` для передачи управления другому агенту необходимо указать и то, и другое:

1. **Сообщение `AIMessage`, содержащее вызов инструмента** (сообщение, инициировавшее передачу управления)
2. **Сообщение от инструмента (ToolMessage), подтверждающее передачу управления** (искусственный ответ на вызов инструмента).

Без этого сопряжения принимающий агент увидит неполный диалог, что может привести к ошибкам или неожиданному поведению.

В приведенном ниже примере предполагается, что был вызван только инструмент передачи управления (без параллельных вызовов инструментов):

```python theme={null}
@инструмент
def transfer_to_sales(runtime: ToolRuntime) -> Command:
    # Получить сообщение от ИИ, которое инициировало эту передачу управления
    last_ai_message = runtime.state["messages"][-1]

    # Создайте искусственный инструмент для завершения пары
    transfer_message = ToolMessage(
        content="Передано торговому агенту",
        tool_call_id=runtime.tool_call_id,
    )

    return Command(
        goto="sales_agent",
        обновление={
            "active_agent": "sales_agent",
            # Передавайте только эти два сообщения, а не всю историю субагента.
            "messages": [last_ai_message, transfer_message],
        },
        graph=Command.PARENT,
    )
```

<Примечание>
  **Почему бы не передавать все сообщения от субагентов?** Хотя вы могли бы включить полный диалог субагента в передачу, это часто создает проблемы. Принимающий агент может запутаться в нерелевантных внутренних рассуждениях, а затраты токенов неоправданно возрастут. Передавая только пару «передача», вы сохраняете контекст родительского графа сосредоточенным на координации высокого уровня. Если принимающему агенту нужен дополнительный контекст, рассмотрите возможность суммирования работы субагента в содержимом ToolMessage вместо передачи необработанной истории сообщений.
</Примечание>

**Возвращение управления пользователю**

При возвращении управления пользователю (завершении хода агента) убедитесь, что последнее сообщение имеет тип `AIMessage`. Это позволит сохранить корректную историю диалога и сигнализировать пользовательскому интерфейсу о завершении работы агента.

## Вопросы реализации

При проектировании многоагентной системы учитывайте следующее:

* **Стратегия фильтрации контекста**: Будет ли каждый агент получать полную историю разговора, отфильтрованные фрагменты или сводки? Разным агентам может потребоваться разный контекст в зависимости от их роли.
* **Семантика инструментов**: Уточните, обновляют ли инструменты передачи только состояние маршрутизации или также выполняют побочные эффекты. Например, должен ли метод `transfer_to_sales()` также создавать заявку в службу поддержки, или это должно быть отдельным действием?
* **Эффективность использования токенов**: Сбалансируйте полноту контекста и стоимость токенов. По мере увеличения длины диалога, суммирование и выборочная передача контекста становятся всё более важными.
