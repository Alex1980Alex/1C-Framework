# Человек в процессе

Промежуточное ПО Human-in-the-Loop (HITL) позволяет добавить человеческий контроль к вызовам инструментов агентов.
Когда модель предлагает действие, которое может потребовать проверки — например, запись в файл или выполнение SQL-запроса, — промежуточное программное обеспечение может приостановить выполнение и дождаться решения.

Это достигается путем проверки каждого вызова инструмента на соответствие настраиваемой политике. Если требуется вмешательство, промежуточное ПО инициирует прерывание, которое останавливает выполнение. Состояние графа сохраняется с помощью слоя персистентности LangGraph, поэтому выполнение может быть безопасно приостановлено и возобновлено позже.

Затем решение человека определяет дальнейшие действия: действие может быть одобрено в текущем виде («approve»), изменено перед выполнением («edit») или отклонено с обратной связью («reject»).

## Типы решений о прерывании

[Промежуточное ПО](/oss/python/langchain/middleware/built-in#human-in-the-loop) определяет три встроенных способа реагирования человека на прерывание:

| Тип решения   | Описание                                                                        | Пример использования                                                   |
| ------------- | ------------------------------------------------------------------------------- | ---------------------------------------------------------------------- |
| ✅ `одобрить`  | Действие одобрено в текущем виде и выполнено без изменений.                     | Отправить черновик электронного письма точно так, как он написан       |
| ✏️ `edit`      | Вызов инструмента выполняется с изменениями.                                    | Измените получателя перед отправкой электронного письма                |
| ❌ `отклонить` | Запрос на использование инструмента отклонен, объяснение добавлено в переписку. | Отклонить черновик электронного письма и объяснить, как его переписать |

Доступные типы решений для каждого инструмента зависят от политики, которую вы настраиваете в параметре `interrupt_on`.
Когда одновременно приостановлено несколько вызовов инструментов, для каждого действия требуется отдельное решение.
Решения должны быть предоставлены в том же порядке, в котором действия указаны в запросе на прерывание.

<Совет>
  При **редактировании** аргументов инструмента вносите изменения осторожно. Значительные изменения исходных аргументов могут привести к тому, что модель пересмотрит свой подход и потенциально сможет выполнить инструмент несколько раз или предпринять неожиданные действия.
</Совет>

## Настройка прерываний

Для использования HITL добавьте [промежуточное ПО](/oss/python/langchain/middleware/built-in#human-in-the-loop) в список `промежуточного ПО` агента при его создании.

Вы настраиваете его, сопоставляя действия инструмента с типами решений, разрешенными для каждого действия. Промежуточное ПО прервет выполнение, когда вызов инструмента совпадет с действием в сопоставлении.

```python theme={null}
from langchain.agents import create_agent
from langchain.agents.middleware import HumanInTheLoopMiddleware # [!code highlight]
from langgraph.checkpoint.memory import InMemorySaver # [!code highlight]


агент = create_agent(
    model="gpt-4.1",
    tools=[write_file_tool, execute_sql_tool, read_data_tool],
    промежуточное ПО=[
        HumanInTheLoopMiddleware( # [!code highlight]
            interrupt_on={
                "write_file": True, # Разрешены все решения (одобрить, отредактировать, отклонить).
                "execute_sql": {"allowed_decisions": ["approve", "reject"]}, # Редактирование запрещено
                # Безопасная эксплуатация, не требуется никаких разрешений
                "read_data": False,
            },
            # Префикс для сообщений о прерываниях — объединяется с именем инструмента и аргументами для формирования полного сообщения.
            # Например, "Выполнение инструмента ожидает подтверждения: execute_sql с запросом='DELETE FROM...'"
            # Отдельные инструменты могут переопределить это, указав "описание" в конфигурации прерывания.
            description_prefix="Выполнение инструмента ожидает подтверждения",
        ),
    ],
    # Для обработки прерываний при участии человека требуется создание контрольных точек.
    # В производственной среде используйте постоянный контрольный указатель, например AsyncPostgresSaver.
    checkpointer=InMemorySaver(), # [!code highlight]
)
```

<Информация>
  Необходимо настроить контрольную точку для сохранения состояния графа при прерываниях.
  В производственной среде используйте постоянный контрольный указатель, например [`AsyncPostgresSaver`](https://reference.langchain.com/python/langgraph/checkpoints/#langgraph.checkpoint.postgres.aio.AsyncPostgresSaver). Для тестирования или прототипирования используйте [`InMemorySaver`](https://reference.langchain.com/python/langgraph/checkpoints/#langgraph.checkpoint.memory.InMemorySaver).

  При запуске агента передайте файл `config`, содержащий **идентификатор потока**, чтобы связать выполнение с потоком диалога.
  Подробности см. в документации по прерываниям LangGraph (/oss/python/langgraph/interrupts).
</Info>

<Заголовок аккордеона="Параметры конфигурации">
  <ParamField body="interrupt_on" type="dict" required>
    Сопоставление названий инструментов с конфигурациями подтверждения. Значения могут быть `True` (прерывание с конфигурацией по умолчанию), `False` (автоматическое подтверждение) или объектом `InterruptOnConfig`.
  </ParamField>

  <ParamField body="description_prefix" type="string" default="Для выполнения инструмента требуется подтверждение">
    Префикс для описания запросов на действия
  </ParamField>

  **Параметры `InterruptOnConfig`:**

  <ParamField body="allowed_decisions" type="list[string]">
    Список допустимых решений: «одобрить», «редактировать» или «отклонить».
  </ParamField>

  <ParamField body="description" type="string | callable">
    Статическая строка или вызываемая функция для пользовательского описания
  </ParamField>
</Аккордеон>

## Реагирование на прерывания

При запуске агента он работает до завершения или до возникновения прерывания. Прерывание срабатывает, когда вызов инструмента соответствует политике, настроенной в параметре `interrupt_on`. В этом случае результат вызова будет включать поле `__interrupt__` с действиями, требующими проверки. Затем вы можете представить эти действия проверяющему и возобновить выполнение после получения решений.

```python theme={null}
from langgraph.types import Command

# Модель "человек в контуре управления" использует слой сохранения данных LangGraph.
# Для привязки выполнения к ветке обсуждения необходимо указать идентификатор потока.
# чтобы разговор можно было приостанавливать и возобновлять (что необходимо для проверки человеком).
config = {"configurable": {"thread_id": "some_id"}} # [!code highlight]
# Запускайте график до тех пор, пока не будет срабатывать прерывание.
результат = agent.invoke(
    {
        "сообщения": [
            {
                "роль": "пользователь",
                "content": "Удалить старые записи из базы данных",
            }
        ]
    },
    config=config # [!выделение кода]
)

# Прерывание содержит полный запрос HITL с параметрами action_requests и review_configs.
print(result['__interrupt__'])
# > [
# > Прерывание(
# > значение={
# > 'action_requests': [
# > {
# > 'name': 'execute_sql',
# > 'arguments': {'query': 'DELETE FROM records WHERE created_at < NOW() - INTERVAL \'30 days\';'},
# > 'description': 'Выполнение инструмента ожидает подтверждения\n\nИнструмент: execute_sql\nАргументы: {...}'
# > }
# > ],
# > 'review_configs': [
# > {
# > 'action_name': 'execute_sql',
# > 'allowed_decisions': ['approve', 'reject']
# > }
# > ]
# > }
# > )
# > ]


# Резюме с решением об утверждении
agent.invoke(
    Команда( # [!подсветка кода]
        resume={"decisions": [{"type": "approve"}]} # или "reject" [!code highlight]
    ), # [!выделение кода]
    config=config # Тот же идентификатор потока для возобновления приостановленного разговора
)
```

## Потоковая передача с участием человека

Вместо `invoke()` можно использовать `stream()` для получения обновлений в реальном времени, пока агент работает и обрабатывает прерывания. Используйте `stream_mode=['updates', 'messages']` для потоковой передачи как информации о ходе выполнения агента, так и токенов LLM.

```python theme={null}
from langgraph.types import Command

config = {"configurable": {"thread_id": "some_id"}}

# Отслеживание прогресса агента потока и токенов LLM до прерывания
для режима, фрагмент в agent.stream(
    {"messages": [{"role": "user", "content": "Удалить старые записи из базы данных"}]},
    config=config,
    stream_mode=["updates", "messages"], # [!code highlight]
):
    если режим == "сообщения":
        # Токен LLM
        токен, метаданные = фрагмент
        если token.content:
            print(token.content, end="", flush=True)
    elif mode == "updates":
        # Проверка на наличие прерывания
        если "__interrupt__" в блоке:
            print(f"\n\nПрерывание: {chunk['__interrupt__']}")

# Возобновление потоковой передачи после принятия решения человеком
для режима, фрагмент в agent.stream(
    Command(resume={"decisions": [{"type": "approve"}]}),
    config=config,
    stream_mode=["updates", "messages"],
):
    если режим == "сообщения":
        токен, метаданные = фрагмент
        если token.content:
            print(token.content, end="", flush=True)
```

Более подробную информацию о режимах потоковой передачи см. в руководстве [Streaming](/oss/python/langchain/streaming).

## Жизненный цикл выполнения

Промежуточное ПО определяет хук `after_model`, который запускается после того, как модель сгенерирует ответ, но до выполнения каких-либо вызовов инструментов:

1. Агент вызывает модель для генерации ответа.
2. Промежуточное программное обеспечение проверяет ответ на наличие вызовов инструментов.
3. Если какие-либо вызовы требуют ввода данных от человека, промежуточное ПО формирует объект `HITLRequest` с параметрами `action_requests` и `review_configs` и вызывает функцию [interrupt](https://reference.langchain.com/python/langgraph/types/#langgraph.types.interrupt).
4. Агент ожидает решений человека.
5. На основе решений `HITLResponse` промежуточное ПО выполняет одобренные или отредактированные вызовы, синтезирует сообщения [ToolMessage](https://reference.langchain.com/python/langchain/messages/#langchain.messages.ToolMessage) для отклоненных вызовов и возобновляет выполнение.
