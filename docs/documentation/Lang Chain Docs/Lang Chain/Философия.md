# Философия

LangChain создан для того, чтобы стать самым простым местом для начала разработки приложений с использованием LLM-программ, обеспечивая при этом гибкость и готовность к внедрению в производство.

В основе деятельности LangChain лежат несколько ключевых принципов:

* Большие языковые модели (LLM) — это замечательная, мощная новая технология.
* Модели LLM становятся еще эффективнее, если их сочетать с внешними источниками данных.
* Магистратуры в области прикладных наук изменят представление о том, как будут выглядеть приложения будущего. В частности, приложения будущего будут все больше и больше ориентироваться на действия субъектов.
* Этот процесс трансформации находится еще на самой ранней стадии.
* Хотя создать прототип таких агентных приложений несложно, разработать агентов, достаточно надежных для внедрения в производство, по-прежнему очень трудно.

В LangChain мы уделяем два основных внимания:

<Шаги>
  <Заголовок шага: Мы хотим дать разработчикам возможность создавать приложения с использованием лучших моделей.">
    Разные поставщики предоставляют разные API с разными параметрами модели и разными форматами сообщений.
    Стандартизация входных и выходных данных модели является ключевым приоритетом, что позволяет разработчикам легко переключаться на самую последнюю, передовую модель и избегать зависимости от неё.
  </Шаг>

  <Заголовок шага: «Мы хотим упростить использование моделей для организации более сложных потоков, взаимодействующих с другими данными и вычислениями».>
    Модели следует использовать не только для *генерации текста*, но и для организации более сложных процессов, взаимодействующих с другими данными. LangChain упрощает определение [инструментов](/oss/python/langchain/tools), которые LLM-ы могут использовать динамически, а также помогает в разборе и доступе к неструктурированным данным.
  </Шаг>
</Шаги>

## История

Учитывая постоянные изменения в этой области, LangChain также эволюционировал с течением времени. Ниже представлена ​​краткая хронология изменений LangChain за эти годы, отражающая эволюцию в контексте развития технологий с использованием магистерских программ:

<Update label="2022-10-24" description="v0.0.1">
  За месяц до запуска ChatGPT был выпущен **пакет LangChain для Python**. Он состоял из двух основных компонентов:

  * Абстракции LLM
  * «Цепочки» или заранее определенные этапы вычислений для выполнения в типичных сценариях использования. Например, RAG: выполнить этап извлечения, затем выполнить этап генерации.

  Название LangChain происходит от слов «язык» (например, языковые модели) и «цепочки».
</Обновление>

<Update label="2022-12">
  В LangChain были добавлены первые агенты общего назначения.

  Эти универсальные агенты были созданы на основе статьи [ReAct](https://arxiv.org/abs/2210.03629) (ReAct расшифровывается как «Рассуждение и действие»). Они использовали LLM для генерации JSON-объектов, представляющих вызовы инструментов, а затем анализировали этот JSON, чтобы определить, какие инструменты следует вызвать.
</Обновление>

<Update label="2023-01">
  Компания OpenAI выпустила API для завершения чата.

  Ранее модели принимали строки и возвращали строку. В API ChatCompletions они эволюционировали и теперь принимают список сообщений и возвращают сообщение. Другие поставщики моделей последовали их примеру, и LangChain обновился, чтобы работать со списками сообщений.
</Обновление>

<Update label="2023-01">
  LangChain выпустила версию для JavaScript.

  LLM-ы и агенты изменят подход к разработке приложений, а JavaScript станет языком разработчиков приложений.
</Обновление>

<Update label="2023-02">
  Компания LangChain Inc. была создана на основе проекта с открытым исходным кодом LangChain.

  Главная цель заключалась в том, чтобы «сделать интеллектуальных агентов повсеместными». Команда понимала, что, хотя LangChain был ключевым компонентом (LangChain упростил начало работы с LLM), существовала также потребность в других компонентах.
</Обновление>

<Update label="2023-03">
  OpenAI добавила функцию вызова функций в свой API.

  Это позволило API явно генерировать полезные данные, представляющие вызовы инструментов. Другие поставщики моделей последовали этому примеру, и LangChain был обновлен, чтобы использовать этот метод в качестве предпочтительного для вызова инструментов (вместо анализа JSON).
</Обновление>

<Update label="2023-06">
  **LangSmith выпущен** как платформа с закрытым исходным кодом от LangChain Inc., обеспечивающая возможность мониторинга и оценки.

  Главная проблема при создании агентов — это обеспечение их надёжности, и LangSmith, предоставляющий возможности мониторинга и оценки, был разработан для решения этой задачи. LangChain был обновлён для бесшовной интеграции с LangSmith.
</Обновление>

<Update label="2024-01" description="v0.1.0">
  **LangChain выпускает версию 0.1.0**, свою первую версию, отличную от 0.0.x.

  Отрасль прошла путь от прототипов до серийного производства, и в связи с этим LangChain усилила акцент на стабильность.
</Обновление>

<Update label="2024-02">
  **LangGraph выпущен** как библиотека с открытым исходным кодом.

  Первоначальная версия LangChain имела две основные направленности: абстракции LLM и высокоуровневые интерфейсы для начала работы с распространенными приложениями; однако ей не хватало низкоуровневого уровня оркестровки, который позволял бы разработчикам контролировать точный поток работы своего агента. И тут на сцену выходит LangGraph.

  При создании LangGraph мы учли опыт разработки LangChain и добавили функциональность, которая, как мы обнаружили, была необходима: потоковая обработка, устойчивое выполнение, кратковременная память, участие человека и многое другое.
</Обновление>

<Update label="2024-06">
  **LangChain имеет более 700 интеграций.**

  Интеграции были выделены из основного пакета LangChain и либо перенесены в отдельные автономные пакеты (для основных интеграций), либо в пакет `langchain-community`.
</Обновление>

<Update label="2024-10">
  LangGraph становится предпочтительным способом создания любых приложений искусственного интеллекта, которые представляют собой нечто большее, чем просто один вызов LLM.

  Разработчикам, стремящимся повысить надежность своих приложений, требовался больший контроль, чем обеспечивали высокоуровневые интерфейсы. LangGraph предоставлял эту низкоуровневую гибкость. Большинство цепочек и агентов были помечены как устаревшие в LangChain, и были предоставлены руководства по их миграции в LangGraph. В LangGraph по-прежнему существует одна высокоуровневая абстракция: абстракция агента. Она построена на основе низкоуровневого LangGraph и имеет тот же интерфейс, что и агенты ReAct из LangChain.
</Обновление>

<Update label="2025-04">
  API моделей становятся все более многомодальными.

  Модели начали принимать файлы, изображения, видео и многое другое. Мы обновили формат сообщений `langchain-core`, чтобы разработчики могли стандартным образом указывать эти мультимодальные входные данные.
</Обновление>

<Update label="2025-10-20" description="v1.0.0">
  **LangChain выпускает версию 1.0** с двумя основными изменениями:

  1. Полная переработка всех цепочек и агентов в `langchain`. Все цепочки и агенты теперь заменены одной высокоуровневой абстракцией: абстракцией агента, построенной на основе LangGraph. Это была высокоуровневая абстракция, первоначально созданная в LangGraph, но перенесенная в LangChain.

     Для пользователей, которые все еще используют старые цепочки/агенты LangChain и НЕ хотят обновляться (примечание: мы рекомендуем это сделать), вы можете продолжить использовать старую версию LangChain, установив пакет `langchain-classic`.

  2. Стандартный формат содержимого сообщений: API моделей эволюционировали от возврата сообщений с простой строкой содержимого к более сложным типам вывода — блокам рассуждений, цитатам, вызовам серверных инструментов и т. д. LangChain развил свои форматы сообщений для стандартизации этих форматов среди различных поставщиков.
</Обновление>
