# Память

Приложениям ИИ требуется [память](/oss/python/concepts/memory) для совместного использования контекста при множественных взаимодействиях. В LangGraph можно добавить два типа памяти:

* [Добавьте кратковременную память](#add-short-term-memory) в качестве части [состояния](/oss/python/langgraph/graph-api#state) вашего агента, чтобы включить многоходовые диалоги.
* [Добавить долговременную память](#add-long-term-memory) для хранения данных, специфичных для пользователя или приложения, между сессиями.

## Добавить кратковременную память

Кратковременная память (на уровне потоков [постоянство](/oss/python/langgraph/persistence)) позволяет агентам отслеживать многоходовые диалоги. Чтобы добавить кратковременную память:

```python theme={null}
from langgraph.checkpoint.memory import InMemorySaver # [!code highlight]
from langgraph.graph import StateGraph

checkpointer = InMemorySaver() # [!подсветка кода]

builder = StateGraph(...)
graph = builder.compile(checkpointer=checkpointer) # [!code highlight]

graph.invoke(
    {"messages": [{"role": "user", "content": "hi! i am Bob"}]},
    {"configurable": {"thread_id": "1"}}, # [!code highlight]
)
```

### Использовать в подграфах

Если ваш граф содержит [подграфы](/oss/python/langgraph/use-subgraphs), вам нужно указать контрольную точку только при компиляции родительского графа. LangGraph автоматически передаст контрольную точку дочерним подграфам.

```python theme={null}
from langgraph.graph import START, StateGraph
from langgraph.checkpoint.memory import InMemorySaver
from typing import TypedDict

class State(TypedDict):
    foo: str

# Подграф

def subgraph_node_1(state: State):
    return {"foo": state["foo"] + "bar"}

subgraph_builder = StateGraph(State)
subgraph_builder.add_node(subgraph_node_1)
subgraph_builder.add_edge(START, "subgraph_node_1")
subgraph = subgraph_builder.compile() # [!выделение кода]

# Родительский график

builder = StateGraph(State)
builder.add_node("node_1", subgraph) # [!code highlight]
builder.add_edge(START, "node_1")

checkpointer = InMemorySaver()
graph = builder.compile(checkpointer=checkpointer) # [!code highlight]
```

Если вы хотите, чтобы подграф имел собственную память, вы можете скомпилировать его с соответствующей опцией контрольных точек. Это полезно в многоагентных системах, если вы хотите, чтобы агенты отслеживали свою внутреннюю историю сообщений.

```python theme={null}
subgraph_builder = StateGraph(...)
subgraph = subgraph_builder.compile(checkpointer=True) # [!code highlight]
```

## Добавить долговременную память

Используйте долговременную память для хранения данных, специфичных для пользователя или приложения, в рамках различных диалогов.

```python theme={null}
from langgraph.store.memory import InMemoryStore # [!code highlight]
from langgraph.graph import StateGraph

store = InMemoryStore() # [!подсветка кода]

builder = StateGraph(...)
graph = builder.compile(store=store) # [!code highlight]
```

### Использование в производстве

В производственной среде используйте хранилище данных, поддерживаемое базой данных:

```python theme={null}
from langgraph.store.postgres import PostgresStore

DB_URI = "postgresql://postgres:postgres@localhost:5442/postgres?sslmode=disable"
with PostgresStore.from_conn_string(DB_URI) as store: # [!code highlight]
    builder = StateGraph(...)
    graph = builder.compile(store=store) # [!code highlight]
```

## Управление кратковременной памятью

При включенной функции кратковременной памяти (#add-short-term-memory) длительные диалоги могут выходить за рамки контекстного окна LLM. Распространенные решения:

* [Удаление сообщений](#trim-messages): Удалить первые или последние N сообщений (перед вызовом LLM)
* [Удалить сообщения](#delete-messages) из состояния LangGraph навсегда
* [Сводка сообщений](#summarize-messages): Сводка предыдущих сообщений в истории и замена их сводкой.
* [Управление контрольными точками](#manage-checkpoints) для хранения и извлечения истории сообщений
* Пользовательские стратегии (например, фильтрация сообщений и т. д.)

Это позволяет агенту отслеживать ход разговора, не выходя за пределы контекстного окна LLM.

### Удаление сообщений

Большинство LLM имеют максимальное поддерживаемое контекстное окно (выраженное в токенах). Один из способов определить, когда следует обрезать сообщения, — это подсчитать количество токенов в истории сообщений и обрезать их всякий раз, когда они приближаются к этому пределу. Если вы используете LangChain, вы можете воспользоваться утилитой trim messages и указать количество токенов, которые следует сохранить из списка, а также стратегию (например, сохранить последние `max_tokens`), используемую для обработки границы.

Для обрезки истории сообщений используйте функцию [`trim_messages`](https://python.langchain.com/api_reference/core/messages/langchain_core.messages.utils.trim_messages.html):

builder = StateGraph(MessagesState)

### Удалить сообщения

Вы можете удалять сообщения из состояния графа, чтобы управлять историей сообщений. Это полезно, когда вы хотите удалить определенные сообщения или очистить всю историю сообщений.

Для удаления сообщений из состояния графа можно использовать `RemoveMessage`. Для работы `RemoveMessage` необходимо использовать ключ состояния с [`add_messages`](https://reference.langchain.com/python/langgraph/graphs/#langgraph.graph.message.add_messages) [reducer](/oss/python/langgraph/graph-api#reducers), например [`MessagesState`](/oss/python/langgraph/graph-api#messagesstate).

Чтобы удалить определенные сообщения:

```python theme={null}
from langchain.messages import RemoveMessage # [!code highlight]

def delete_messages(state):
    сообщения = состояние["сообщения"]
    если длина сообщений > 2:
        # удалить два самых ранних сообщения
        return {"messages": [RemoveMessage(id=m.id) for m in messages[:2]]} # [!code highlight]
```

Чтобы удалить **все** сообщения:

```python theme={null}
from langgraph.graph.message import REMOVE_ALL_MESSAGES # [!code highlight]

def delete_messages(state):
    return {"messages": [RemoveMessage(id=REMOVE_ALL_MESSAGES)]} # [!code highlight]
```

<Предупреждение>
  При удалении сообщений **убедитесь**, что полученная история сообщений является корректной. Проверьте ограничения используемого вами поставщика LLM. Например:

  * Некоторые провайдеры ожидают, что история сообщений будет начинаться с сообщения от пользователя.
  * Большинство поставщиков услуг требуют, чтобы сообщения `assistant`, содержащие вызовы инструментов, сопровождались соответствующими сообщениями с результатами выполнения команды `tool`.
</Предупреждение>

Для обобщения истории сообщений можно использовать логику запросов и управления. Например, в LangGraph можно расширить [`MessagesState`](/oss/python/langgraph/graph-api#working-with-messages-in-graph-state), добавив ключ `summary`:

```python theme={null}
from langgraph.graph import MessagesState
class State(MessagesState):
    резюме: стр.
```

Затем вы можете сгенерировать сводку истории чата, используя любую существующую сводку в качестве контекста для следующей сводки. Этот узел `summarize_conversation` можно вызвать после того, как в ключе состояния `messages` накопится определенное количество сообщений.

```python theme={null}
def summarize_conversation(state: State):

    # Сначала мы получаем любую существующую сводку
    summary = state.get("summary", "")

    # Создание подсказки для суммирования
    если краткое содержание:

        # Сводка уже существует
        summary_message = (
            «Это краткое изложение состоявшейся на данный момент беседы: {краткое содержание}\n\n»
            «Расширьте резюме, приняв во внимание новые сообщения, указанные выше:»
        )

    еще:
        summary_message = "Создать краткое изложение приведенной выше беседы:"

    # Добавить подсказку в нашу историю
    messages = state["messages"] + [HumanMessage(content=summary_message)]
    response = model.invoke(messages)

    # Удалить все сообщения, кроме двух последних
    delete_messages = [RemoveMessage(id=m.id) for m in state["messages"][:-2]]
    return {"summary": response.content, "messages": delete_messages}
```

## Управление базами данных

Если вы используете какую-либо реализацию хранения данных на основе баз данных (например, Postgres или Redis) для краткосрочного и/или долговременного хранения, вам потребуется выполнить миграции для настройки необходимой схемы, прежде чем вы сможете использовать ее с вашей базой данных.

По общепринятой практике, большинство библиотек, специфичных для баз данных, определяют метод `setup()` в экземпляре контрольной точки или хранилища, который запускает необходимые миграции. Однако вам следует уточнить точное название и использование метода в вашей конкретной реализации [`BaseCheckpointSaver`](https://reference.langchain.com/python/langgraph/checkpoints/#langgraph.checkpoint.base.BaseCheckpointSaver) или [`BaseStore`](https://reference.langchain.com/python/langgraph/store/#langgraph.store.base.BaseStore).

Мы рекомендуем выполнять миграции как отдельный этап развертывания, или же вы можете обеспечить их выполнение в рамках запуска сервера.
