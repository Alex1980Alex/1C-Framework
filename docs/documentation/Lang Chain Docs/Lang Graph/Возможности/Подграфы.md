# Подграфы

В этом руководстве объясняется механика использования подграфов. Подграф — это [граф](/oss/python/langgraph/graph-api#graphs), который используется в качестве [узла](/oss/python/langgraph/graph-api#nodes) в другом графе.

Подграфы полезны для:

* Создание [многоагентных систем](/oss/python/langchain/multi-agent)
* Повторное использование набора узлов в нескольких графах
* Распределенная разработка: если вы хотите, чтобы разные команды работали над разными частями графа независимо друг от друга, вы можете определить каждую часть как подграф, и, если соблюдается интерфейс подграфа (входные и выходные схемы), родительский граф может быть построен без знания каких-либо деталей подграфа.

При добавлении подграфов необходимо определить, как родительский граф и подграф взаимодействуют:

* [Вызов графа из узла](#invoke-a-graph-from-a-node) — подграфы вызываются изнутри узла в родительском графе
* [Добавление графа в качестве узла](#add-a-graph-as-a-node) — подграф добавляется непосредственно в качестве узла в родительский объект и **разделяет [ключи состояния](/oss/python/langgraph/graph-api#state)** с родительским объектом.

## Вызов графа из узла

Простой способ реализовать подграф — это вызвать граф изнутри узла другого графа. В этом случае подграфы могут иметь **совершенно другие схемы** по сравнению с родительским графом (без общих ключей). Например, вы можете захотеть хранить историю личных сообщений для каждого из агентов в многоагентной системе.

Если это относится к вашему приложению, вам необходимо определить функцию узла, **которая вызывает подграф**. Эта функция должна преобразовать входное (родительское) состояние в состояние подграфа перед вызовом подграфа и преобразовать результаты обратно в родительское состояние перед возвратом обновления состояния от узла.

```python theme={null}
from typing_extensions import TypedDict
from langgraph.graph.state import StateGraph, START

class SubgraphState(TypedDict):
    бар: стр

# Подграф

def subgraph_node_1(state: SubgraphState):
    return {"bar": "привет!" + state["bar"]}

subgraph_builder = StateGraph(SubgraphState)
subgraph_builder.add_node(subgraph_node_1)
subgraph_builder.add_edge(START, "subgraph_node_1")
subgraph = subgraph_builder.compile()

# Родительский график

class State(TypedDict):
    foo: str

def call_subgraph(state: State):
    # Преобразовать состояние в состояние подграфа
    subgraph_output = subgraph.invoke({"bar": state["foo"]}) # [!code highlight]
    # Преобразовать ответ обратно в родительское состояние
    return {"foo": subgraph_output["bar"]}

builder = StateGraph(State)
builder.add_node("node_1", call_subgraph)
builder.add_edge(START, "node_1")
graph = builder.compile()
```

  # График внука
  from typing_extensions import TypedDict
  from langgraph.graph.state import StateGraph, START, END

  class GrandChildState(TypedDict):
      my_granchild_key: str

  def grandchild_1(state: GrandChildState) -> GrandChildState:

      return {"my_grandchild_key": state["my_grandchild_key"] + ", how are you"}

  grandchild.add_node("granchild_1", grandchild_1)

  grandchild_graph = grandchild.compile()

  # Дочерний график
  class ChildState(TypedDict):
      my_child_key: str

  def call_grandchild_graph(state: ChildState) -> ChildState:

      grandchild_graph_input = {"my_grandchild_key": state["my_child_key"]}
      grandchild_graph_output = grandchild_graph.invoke(granchild_graph_input)

  # Здесь мы передаем функцию вместо просто скомпилированного графа (`grandchild_graph`)
  child.add_node("child_1", call_granchild_graph)
  child.add_edge(START, "child_1")
  child.add_edge("child_1", END)
  child_graph = child.compile()

  # Родительский график
  class ParentState(TypedDict):
      мой_ключ: str

  def parent_1(state: ParentState) -> ParentState:
      # ПРИМЕЧАНИЕ: ключи для детей или внуков здесь недоступны.
      return {"my_key": "hi" + state["my_key"]}

  def parent_2(state: ParentState) -> ParentState:
      return {"my_key": state["my_key"] + " пока!"}

  def call_child_graph(state: ParentState) -> ParentState:
      child_graph_input = {"my_child_key": state["my_key"]}
      child_graph_output = child_graph.invoke(child_graph_input)
      return {"my_key": child_graph_output["my_child_key"]}

  parent = StateGraph(ParentState)
  parent.add_node("parent_1", parent_1)

  parent.add_edge("parent_1", "child")

## Добавить граф в качестве узла

Когда родительский граф и подграф могут обмениваться данными по общему ключу состояния (каналу) в [схеме](/oss/python/langgraph/graph-api#state), вы можете добавить граф в качестве [узла](/oss/python/langgraph/graph-api#nodes) в другой граф. Например, в многоагентных системах (/oss/python/langchain/multi-agent) агенты часто обмениваются данными по общему ключу [messages](/oss/python/langgraph/graph-api#why-use-messages).

Если ваш подграф имеет общие ключи состояния с родительским графом, вы можете добавить его в свой граф, выполнив следующие действия:

1. Определите рабочий процесс подграфа (`subgraph_builder` в приведенном ниже примере) и скомпилируйте его.
2. Передайте скомпилированный подграф методу [`add_node`](https://reference.langchain.com/python/langgraph/graphs/#langgraph.graph.state.StateGraph.add_node) при определении рабочего процесса родительского графа.

```python theme={null}
from typing_extensions import TypedDict
from langgraph.graph.state import StateGraph, START

class State(TypedDict):
    foo: str

# Подграф

def subgraph_node_1(state: State):
    return {"foo": "привет!" + state["foo"]}

subgraph_builder = StateGraph(State)
subgraph_builder.add_node(subgraph_node_1)
subgraph_builder.add_edge(START, "subgraph_node_1")
subgraph = subgraph_builder.compile()

# Родительский график

builder = StateGraph(State)
builder.add_node("node_1", subgraph) # [!code highlight]
builder.add_edge(START, "node_1")
graph = builder.compile()
```

<Accordion title="Полный пример: схемы общего состояния">

      return {"foo": state["foo"] + state["bar"]}

  subgraph_builder.add_node(subgraph_node_2)

## Добавить сохранение состояния

Контрольную точку нужно **указывать только при компиляции родительского графа**. LangGraph автоматически передаст контрольную точку дочерним подграфам.

```python theme={null}
from langgraph.graph import START, StateGraph
from langgraph.checkpoint.memory import MemorySaver
from typing_extensions import TypedDict

class State(TypedDict):
    foo: str

# Подграф

def subgraph_node_1(state: State):
    return {"foo": state["foo"] + "bar"}

subgraph_builder = StateGraph(State)
subgraph_builder.add_node(subgraph_node_1)
subgraph_builder.add_edge(START, "subgraph_node_1")
subgraph = subgraph_builder.compile()

# Родительский график

builder = StateGraph(State)
builder.add_node("node_1", subgraph)
builder.add_edge(START, "node_1")

checkpointer = MemorySaver()
graph = builder.compile(checkpointer=checkpointer)
```

Если вы хотите, чтобы подграф **имел собственную память**, вы можете скомпилировать его с соответствующей опцией контрольных точек. Это полезно в многоагентных системах, если вы хотите, чтобы агенты отслеживали свою внутреннюю историю сообщений:

```python theme={null}
subgraph_builder = StateGraph(...)
subgraph = subgraph_builder.compile(checkpointer=True)
```

## Просмотр состояния подграфа

При включении [персистентности](/oss/python/langgraph/persistence) вы можете [проверить состояние графа](/oss/python/langgraph/persistence#checkpoints) (checkpoint) соответствующим способом. Для просмотра состояния подграфа можно использовать опцию subgraphs.

Вы можете проверить состояние графа с помощью `graph.get_state(config)`. Чтобы просмотреть состояние подграфа, вы можете использовать `graph.get_state(config, subgraphs=True)`.

<Предупреждение>
  **Доступно **только** при прерывании**
  Состояние подграфа можно просмотреть только **при прерывании работы подграфа**. После возобновления работы графа доступ к состоянию подграфа будет невозможен.
</Предупреждение>

<Заголовок аккордеона="Просмотр прерванного состояния подграфа">

  graph.invoke(Command(resume="bar"), config)

## Выходы подграфа потока

Чтобы включить выходные данные из подграфов в потоковые выходные данные, можно задать параметр `subgraphs` в методе `stream` родительского графа. Это позволит передавать потоковые выходные данные как из родительского графа, так и из любых подграфов.

```python theme={null}
for chunk in graph.stream(
    {"foo": "foo"},
    subgraphs=True, # [!подсветка кода]
    stream_mode="updates",
):
    print(chunk)
```
