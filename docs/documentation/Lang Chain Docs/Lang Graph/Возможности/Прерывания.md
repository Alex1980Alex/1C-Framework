# Прерывания

Прерывания позволяют приостанавливать выполнение графа в определенных точках и ждать внешнего ввода перед продолжением. Это позволяет реализовать модели с участием человека, когда для продолжения работы необходим внешний ввод. При срабатывании прерывания LangGraph сохраняет состояние графа, используя свой слой [persistence](/oss/python/langgraph/persistence), и ожидает неограниченное время, пока вы не возобновите выполнение.

Прерывания работают путем вызова функции `interrupt()` в любой точке узлов графа. Функция принимает любое значение, сериализуемое в формате JSON, которое отображается вызывающей стороне. Когда вы будете готовы продолжить, вы возобновляете выполнение, повторно вызывая граф с помощью `Command`, который затем становится возвращаемым значением вызова `interrupt()` изнутри узла.

В отличие от статических точек останова (которые приостанавливают выполнение до или после определенных узлов), прерывания являются **динамическими** — их можно разместить в любом месте кода, и они могут быть условными в зависимости от логики вашего приложения.

* **Сохранение контрольных точек позволяет сохранить текущее состояние:** программа создания контрольных точек записывает точное состояние графа, чтобы вы могли продолжить работу позже, даже если произошла ошибка.
* **`thread_id` — это ваш указатель:** установите `config={"configurable": {"thread_id": ...}}`, чтобы указать контрольной точке, какое состояние следует загрузить.
* **Полезные нагрузки прерываний отображаются как `__interrupt__`:** значения, которые вы передаете в `interrupt()`, возвращаются вызывающей стороне в поле `__interrupt__`, чтобы вы знали, чего ожидает граф.

Выбранный вами `thread_id` фактически является вашим постоянным курсором. Повторное использование этого значения возобновляет работу с той же контрольной точки; использование нового значения запускает совершенно новый поток с пустым состоянием.

## Пауза с помощью `interrupt`

Функция [`interrupt`](https://reference.langchain.com/python/langgraph/types/#langgraph.types.interrupt) приостанавливает выполнение графа и возвращает значение вызывающей стороне. При вызове функции [`interrupt`](https://reference.langchain.com/python/langgraph/types/#langgraph.types.interrupt) внутри узла LangGraph сохраняет текущее состояние графа и ожидает возобновления выполнения с вводом данных.

Для использования функции [`interrupt`](https://reference.langchain.com/python/langgraph/types/#langgraph.types.interrupt) вам потребуется:

1. **Контрольный указатель** для сохранения состояния графа (в производственной среде используйте надежный контрольный указатель).
2. Укажите **идентификатор потока** в конфигурации, чтобы среда выполнения знала, из какого состояния следует возобновить работу.
3. Чтобы вызвать `interrupt()` в том месте, где вы хотите приостановить выполнение (полезная нагрузка должна быть сериализуемой в формате JSON),

```python theme={null}
from langgraph.types import interrupt

def approval_node(state: State):
    # Сделайте паузу и запросите одобрение
    approved = interrupt("Вы одобряете это действие?")

    # При возобновлении работы команда Command(resume=...) возвращает это значение здесь.
    return {"approved": approved}
```

Вот что происходит, когда вы вызываете [`interrupt`](https://reference.langchain.com/python/langgraph/types/#langgraph.types.interrupt):

1. **Выполнение графа приостанавливается** в тот самый момент, когда вызывается метод [`interrupt`](https://reference.langchain.com/python/langgraph/types/#langgraph.types.interrupt).
2. **Состояние сохраняется** с помощью контрольной точки, чтобы выполнение можно было возобновить позже. В производственной среде это должна быть постоянная контрольная точка (например, с резервным копированием из базы данных).
3. **Значение возвращается** вызывающей стороне в обработчике `__interrupt__`; это может быть любое значение, сериализуемое в формате JSON (строка, объект, массив и т. д.).
4. **Граф будет ждать неопределенное время**, пока вы не возобновите выполнение с ответом.
5. **Ответ передается обратно** в узел при возобновлении работы, становясь возвращаемым значением вызова `interrupt()`.

## Возобновление прерываний

После прерывания, приостанавливающего выполнение, вы возобновляете работу графа, вызывая его снова с помощью команды, содержащей значение возобновления. Значение возобновления передается обратно в вызов прерывания, позволяя узлу продолжить выполнение с внешним входом.

```python theme={null}
from langgraph.types import Command

# Первый запуск - срабатывает прерывание и происходит пауза
# thread_id — это постоянный указатель (хранит стабильный идентификатор в рабочей среде)
config = {"configurable": {"thread_id": "thread-1"}}
result = graph.invoke({"input": "data"}, config=config)

# Проверьте, что было прервано
# __interrupt__ содержит полезную нагрузку, переданную в функцию interrupt().
print(result["__interrupt__"])
# > [Interrupt(value='Вы одобряете это действие?')]

# Возобновить работу с ответом пользователя
# Возобновляемая полезная нагрузка становится возвращаемым значением функции interrupt() внутри узла.
graph.invoke(Command(resume=True), config=config)
```

**Ключевые моменты, касающиеся возобновления работы:**

* При возобновлении работы необходимо использовать **тот же идентификатор потока**, который использовался в момент возникновения прерывания.
* Значение, переданное в `Command(resume=...)`, становится возвращаемым значением вызова [`interrupt`](https://reference.langchain.com/python/langgraph/types/#langgraph.types.interrupt)
* При возобновлении работы узел перезапускается с того места, где был вызван [`interrupt`](https://reference.langchain.com/python/langgraph/types/#langgraph.types.interrupt), поэтому любой код до вызова [`interrupt`](https://reference.langchain.com/python/langgraph/types/#langgraph.types.interrupt) выполняется снова.
* В качестве значения параметра resume можно передать любое значение, сериализуемое в формате JSON.

### Потоковая передача с прерываниями, включающими участие человека (HITL)

При создании интерактивных агентов с рабочими процессами, предполагающими участие человека, можно одновременно передавать фрагменты сообщений и обновления узлов для обеспечения обратной связи в реальном времени и обработки прерываний.

Используйте несколько режимов потоковой передачи («сообщения» и «обновления») с параметром `subgraphs=True` (если присутствуют подграфы), чтобы:

* Транслируйте ответы ИИ в режиме реального времени по мере их генерации.
* Определяет момент возникновения прерывания в графике.
* Обеспечивает бесперебойную обработку пользовательского ввода и возобновление выполнения.

```python theme={null}
async для метаданных, режима, фрагмента в graph.astream(

):

            interrupt_info = chunk["__interrupt__"][0].value
            
            # Обработка пользовательского ввода
            user_response = get_user_input(interrupt_info)
            
            # Возобновление работы графа с обновленными входными данными

            перерыв
        
        еще:

            current_node = list(chunk.keys())[0]
```

* **`stream_mode=["messages", "updates"]`**: Включает двойную потоковую передачу как фрагментов сообщений, так и обновлений состояния графа.
* **`subgraphs=True`**: Требуется для обнаружения прерываний во вложенных графах
* **Обнаружение прерываний**: сигнализирует о необходимости ввода данных человеком.
* **`Команда(resume=...)`**: Возобновляет выполнение графа с использованием предоставленных пользователем данных.

### Одобрить или отклонить

Одно из наиболее распространенных применений прерываний — это приостановка выполнения критически важного действия для запроса подтверждения. Например, вам может потребоваться запросить у человека подтверждение вызова API, изменения в базе данных или любого другого важного решения.

```python theme={null}
from typing import Literal
from langgraph.types import interrupt, Command

def approval_node(state: State) -> Command[Literal["proceed", "cancel"]]:
    # Приостановить выполнение; полезная нагрузка отображается в result["__interrupt__"]
    is_approved = interrupt({
        «Вопрос»: «Вы хотите продолжить это действие?»
        "details": state["action_details"]
    })

    # Маршрутизация на основе ответа
    если is_approved:
        return Command(goto="proceed") # Выполняется после предоставления полезной нагрузки для возобновления работы
    еще:
        return Command(goto="cancel")
```

При возобновлении работы графа передайте `true` для одобрения или `false` для отклонения:

```python theme={null}
# Для утверждения
graph.invoke(Command(resume=True), config=config)

# Отклонить
graph.invoke(Command(resume=False), config=config)
```

### Проверка и редактирование состояния

Иногда перед продолжением работы необходимо, чтобы специалист проверил и отредактировал часть состояния графика. Это полезно для исправления LLM-моделей, добавления недостающей информации или внесения корректировок.

```python theme={null}
from langgraph.types import interrupt

def review_node(state: State):
    # Приостановить и показать текущее содержимое для просмотра (отображается в result["__interrupt__"])
    edited_content = interrupt({
        «Инструкция»: «Просмотрите и отредактируйте этот контент».
        "content": state["generated_text"]
    })

    # Обновить состояние, указав отредактированную версию
    return {"generated_text": edited_content}
```

При возобновлении работы укажите отредактированный контент:

```python theme={null}
graph.invoke(
    Command(resume="The edited and improved text"), # Значение становится возвращаемым значением функции interrupt()
    config=config
)
```

### Прерывания в инструментах

Также можно размещать прерывания непосредственно внутри функций инструмента. Это заставляет сам инструмент приостанавливать работу для подтверждения при каждом вызове, что позволяет человеку проверить и отредактировать вызов инструмента перед его выполнением.

Сначала определите инструмент, использующий [`interrupt`](https://reference.langchain.com/python/langgraph/types/#langgraph.types.interrupt):

```python theme={null}
from langchain.tools import tool
from langgraph.types import interrupt

@инструмент
def send_email(to: str, subject: str, body: str):
    «Отправить электронное письмо получателю».

    # Пауза перед отправкой; полезная нагрузка отображается в result["__interrupt__"]
    ответ = прерывание({
        "действие": "отправить_электронное_письмо",
        "к": к,
        "субъект": субъект,
        "тело": тело,
        "сообщение": "Одобрить отправку этого письма?"
    })

    if response.get("action") == "approve":
        # Значение параметра Resume может переопределять входные данные перед выполнением.
        final_to = response.get("to", to)
        final_subject = response.get("subject", subject)
        final_body = response.get("body", body)
        "Электронное письмо отправлено на адрес {final_to} с темой '{final_subject}'"
    return "Электронное письмо отменено пользователем"
```

Этот подход полезен, когда вам нужно, чтобы логика утверждения была интегрирована в сам инструмент, что позволяет использовать её в разных частях графа. LLM может вызывать инструмент естественным образом, а прерывание будет приостанавливать выполнение всякий раз, когда инструмент вызывается, позволяя вам утвердить, отредактировать или отменить действие.

### Проверка ввода данных человеком

Иногда необходимо проверить ввод данных от людей и повторно спросить, не является ли он недействительным. Это можно сделать с помощью нескольких вызовов функции прерывания (`interrupt`) в цикле.

```python theme={null}

    Запрос: "Сколько вам лет?"

    пока истинно:
        ответ = прерывание(подсказка) # полезная нагрузка отображается в result["__interrupt__"]

        # Проверка входных данных
        Если isinstance(answer, int) и answer > 0:
            # Допустимый ввод - продолжить
            перерыв
        еще:
```

## Правила прерываний

При вызове функции [`interrupt`](https://reference.langchain.com/python/langgraph/types/#langgraph.types.interrupt) внутри узла LangGraph приостанавливает выполнение, генерируя исключение, которое сигнализирует среде выполнения о необходимости приостановки. Это исключение распространяется вверх по стеку вызовов и перехватывается средой выполнения, которая уведомляет граф о необходимости сохранить текущее состояние и ожидать внешнего ввода.

Когда выполнение возобновляется (после предоставления запрошенных входных данных), среда выполнения перезапускает весь узел с самого начала — она не возобновляет выполнение с той самой строки, где был вызван [`interrupt`](https://reference.langchain.com/python/langgraph/types/#langgraph.types.interrupt). Это означает, что любой код, который выполнялся до вызова [`interrupt`](https://reference.langchain.com/python/langgraph/types/#langgraph.types.interrupt), будет выполнен снова. Поэтому при работе с прерываниями необходимо соблюдать несколько важных правил, чтобы гарантировать их корректное поведение.

### Не оборачивайте вызовы `interrupt` в блоки try/except

Метод `interrupt` (https://reference.langchain.com/python/langgraph/types/#langgraph.types.interrupt) приостанавливает выполнение в точке вызова, генерируя специальное исключение. Если обернуть вызов `interrupt` в блок `try/except`, то это исключение будет перехвачено, и прерывание не будет передано обратно в граф.

* ✅ Отделите вызовы [`interrupt`](https://reference.langchain.com/python/langgraph/types/#langgraph.types.interrupt) от кода, подверженного ошибкам.
* ✅ Используйте определенные типы исключений в блоках try/except

<CodeGroup>
  ```python Разделение логической темы={null}
  def node_a(state: State):
      # ✅ Хорошо: сначала прервать, а затем обработать.
      # условия ошибок отдельно
      прерывание("Как тебя зовут?")
      пытаться:
          fetch_data() # Это может привести к ошибке
      за исключением исключения как e:
          print(e)
      состояние возврата
  ```

  ```python Явная обработка исключений theme={null}
  def node_a(state: State):
      # ✅ Хорошо: перехват определенных типов исключений
      # не будет перехвачено исключение прерывания
      пытаться:
          name = interrupt("Как тебя зовут?")
          fetch_data() # Это может привести к ошибке
      except NetworkException as e:
          print(e)
      состояние возврата
  ```
</CodeGroup>

* 🔴 Не оборачивайте вызовы [`interrupt`](https://reference.langchain.com/python/langgraph/types/#langgraph.types.interrupt) в простые блоки try/except

### Не изменяйте порядок вызовов `interrupt` внутри узла

В одном узле часто используется несколько прерываний, однако при неосторожном обращении это может привести к непредсказуемому поведению.

Когда узел содержит несколько вызовов прерываний, LangGraph хранит список значений возобновления, специфичных для задачи, выполняющей этот узел. При каждом возобновлении выполнения оно начинается с начала узла. Для каждого обнаруженного прерывания LangGraph проверяет, существует ли соответствующее значение в списке возобновления задачи. Сопоставление осуществляется **строго по индексу**, поэтому порядок вызовов прерываний внутри узла имеет значение.

* ✅ Обеспечьте согласованность вызовов [`interrupt`](https://reference.langchain.com/python/langgraph/types/#langgraph.types.interrupt) между запусками узлов

```python theme={null}
def node_a(state: State):
    # ✅ Хорошо: вызовы прерываний всегда происходят в одном и том же порядке.
    name = interrupt("Как тебя зовут?")
    возраст = прерывание("Какой у тебя возраст?")
    город = interrupt("Какой у вас город?")

    возвращаться {
        "имя": имя,
        "возраст": возраст,
        "город": город
    }
```

* 🔴 Не пропускайте условно вызовы [`interrupt`](https://reference.langchain.com/python/langgraph/types/#langgraph.types.interrupt) внутри узла
* 🔴 Не используйте циклы вызовов [`interrupt`](https://reference.langchain.com/python/langgraph/types/#langgraph.types.interrupt), используя логику, которая не является детерминированной при каждом выполнении.

<CodeGroup>

### Побочные эффекты, вызываемые перед `interrupt`, должны быть идемпотентными.

Поскольку прерывания работают путем повторного запуска узлов, из которых они были вызваны, побочные эффекты, вызываемые перед [`interrupt`](https://reference.langchain.com/python/langgraph/types/#langgraph.types.interrupt), должны (в идеале) быть идемпотентными. Для контекста, идемпотентность означает, что одна и та же операция может быть применена несколько раз без изменения результата после первоначального выполнения.

Например, у вас может быть вызов API для обновления записи внутри узла. Если после этого вызова вызывается [`interrupt`](https://reference.langchain.com/python/langgraph/types/#langgraph.types.interrupt), он будет повторно запущен несколько раз при возобновлении работы узла, потенциально перезаписывая первоначальное обновление или создавая дубликаты записей.

* ✅ Используйте идемпотентные операции перед [`interrupt`](https://reference.langchain.com/python/langgraph/types/#langgraph.types.interrupt)
* ✅ Размещайте побочные эффекты после вызовов [`interrupt`](https://reference.langchain.com/python/langgraph/types/#langgraph.types.interrupt)
* ✅ По возможности разделяйте побочные эффекты на отдельные узлы.

<CodeGroup>
  ```python Идемпотентные операции theme={null}
  def node_a(state: State):
      # ✅ Хорошо: используется операция upsert, которая является идемпотентной.
      # Многократное выполнение даст тот же результат
      db.upsert_user(
          user_id=state["user_id"],
          статус="ожидание_одобрения"
      )

      approved = interrupt("Утвердить это изменение?")

      return {"approved": approved}
  ```

  ```Побочные эффекты Python после прерывания theme={null}

      approved = interrupt("Утвердить это изменение?")
  ```

## Использование с подграфами, называемыми функциями

При вызове подграфа внутри узла родительский граф возобновит выполнение с **начала узла**, где был вызван подграф и сработало прерывание (`interrupt`](https://reference.langchain.com/python/langgraph/types/#langgraph.types.interrupt). Аналогично, **подграф** также возобновит выполнение с начала узла, где было вызвано прерывание (`interrupt`](https://reference.langchain.com/python/langgraph/types/#langgraph.types.interrupt).

```python theme={null}
    # ...
```

## Отладка с использованием прерываний

Для отладки и тестирования графа можно использовать статические прерывания в качестве точек останова, чтобы пошагово выполнять граф, обрабатывая каждый узел по отдельности. Статические прерывания срабатывают в определенных точках либо до, либо после выполнения узла. Эти точки можно задать, указав параметры `interrupt_before` и `interrupt_after` при компиляции графа.

<Примечание>
  Статические прерывания **не** рекомендуются для рабочих процессов с участием человека. Вместо них используйте функцию [`interrupt`](https://reference.langchain.com/python/langgraph/types/#langgraph.types.interrupt).
</Примечание>

<Вкладки>
  <Tab title="Во время компиляции">
    ```python theme={null}
    graph = builder.compile(
        interrupt_before=["node_a"], # [!code highlight]
        interrupt_after=["node_b", "node_c"], # [!code highlight]
        checkpointer=checkpointer,
    )

    # Передайте идентификатор потока в граф
    config = {
        "настраиваемый": {
            "thread_id": "some_thread"
        }
    }

    # Запустите график до точки перегиба
    graph.invoke(inputs, config=config) # [!code highlight]

    # Возобновить построение графика
    graph.invoke(None, config=config) # [!code highlight]
    ```

    1. Точки останова устанавливаются во время компиляции.
    2. Параметр `interrupt_before` указывает узлы, выполнение которых должно быть приостановлено перед запуском узла.
    3. Параметр `interrupt_after` указывает узлы, выполнение которых должно быть приостановлено после завершения работы узла.
    4. Для активации точек останова необходим контрольный указатель.
    5. График строится до тех пор, пока не будет достигнута первая точка перегиба.
    6. Возобновление работы графа осуществляется путем передачи значения `None` в качестве входных данных. Это позволит продолжать работу графа до достижения следующей точки останова.
  </Tab>

  <Tab title="Во время выполнения">
