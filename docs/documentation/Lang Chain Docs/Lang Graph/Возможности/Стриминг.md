# Стриминг

LangGraph использует потоковую систему для отображения обновлений в реальном времени. Потоковая передача данных имеет решающее значение для повышения быстродействия приложений, построенных на основе LLM. Благодаря постепенному отображению выходных данных, даже до получения полного ответа, потоковая передача значительно улучшает пользовательский опыт (UX), особенно при работе с задержками в LLM.

Возможности потоковой передачи данных LangGraph:

* <Icon icon="share-nodes" size={16} /> [**Состояние графа потока**](#stream-graph-state) — получать обновления состояния / значения с режимами `updates` и `values`.
* <Icon icon="square-poll-horizontal" size={16} /> [**Выходы подграфа потока**](#stream-subgraph-outputs) — включают выходы как родительского графа, так и любых вложенных подграфов.
* <Icon icon="square-binary" size={16} /> [**Потоковые LLM-токены**](#messages) — захватывать потоки токенов из любого места: внутри узлов, подграфов или инструментов.
* <Icon icon="table" size={16} /> [**Потоковая передача пользовательских данных**](#stream-custom-data) — отправка пользовательских обновлений или сигналов о ходе выполнения непосредственно из функций инструмента.
* <Icon icon="layer-plus" size={16} /> [**Используйте несколько режимов потоковой передачи**](#stream-multiple-modes) — выберите один из вариантов: `values` (полное состояние), `updates` (изменения состояния), `messages` (токены LLM + метаданные), `custom` (произвольные данные пользователя) или `debug` (подробная трассировка).

## Поддерживаемые режимы потоковой передачи

Передайте один или несколько из следующих режимов потока в виде списка методам [`stream`](https://reference.langchain.com/python/langgraph/graphs/#langgraph.graph.state.CompiledStateGraph.stream) или [`astream`](https://reference.langchain.com/python/langgraph/graphs/#langgraph.graph.state.CompiledStateGraph.astream):

| Режим      | Описание                                                                                                                                                                                         |
| ---------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `values`   | Передает полное значение состояния после каждого шага графа.                                                                                                                                     |
| `updates`  | Передает обновления состояния потоком после каждого шага графа. Если на одном шаге выполняется несколько обновлений (например, запускается несколько узлов), эти обновления передаются отдельно. |
| `custom`   | Передает пользовательские данные из узлов вашего графа.                                                                                                                                          |
| `messages` | Передает потоки из двух кортежей (токен LLM, метаданные) из любых узлов графа, где вызывается LLM.                                                                                               |
| `debug`    | Передает максимально возможное количество информации на протяжении всего выполнения графа.                                                                                                       |

## Базовый пример использования

Графы LangGraph предоставляют доступ к методам [`stream`](https://reference.langchain.com/python/langgraph/pregel/#langgraph.pregel.Pregel.stream) (синхронный) и [`astream`](https://reference.langchain.com/python/langgraph/pregel/#langgraph.pregel.Pregel.astream) (асинхронный) для получения потоковых выходных данных в виде итераторов.

```python theme={null}
for chunk in graph.stream(inputs, stream_mode="updates"):
    print(chunk)
```

## Потоковая передача в нескольких режимах

В качестве параметра `stream_mode` можно передать список, чтобы одновременно транслировать несколько режимов.

Выходные потоки будут представлять собой кортежи типа `(mode, chunk)`, где `mode` — это название режима потоковой передачи, а `chunk` — это данные, передаваемые в этом режиме.

```python theme={null}
для режима, фрагмент в graph.stream(inputs, stream_mode=["updates", "custom"]):
    print(chunk)
```

## Состояние графа потока

Используйте режимы потоковой передачи `updates` и `values` для потоковой передачи состояния графа по мере его выполнения.

* Функция `updates` передает **обновления** в состояние после каждого шага графа.
* Функция `values` передает **полное значение** состояния после каждого шага графа.

```python theme={null}
from typing import TypedDict
from langgraph.graph import StateGraph, START, END


class State(TypedDict):
  тема: строка
  шутка: стр


def refine_topic(state: State):
    return {"topic": state["topic"] + " and cats"}


def generate_joke(state: State):
    return {"joke": f"Это шутка о {state['topic']}"}

график = (
  StateGraph(State)
  .add_node(refine_topic)
  .add_node(generate_joke)
  .add_edge(START, "refine_topic")
  .add_edge("refine_topic", "generate_joke")
  .add_edge("generate_joke", END)
  .compile()
)
```

<Вкладки>
  <Tab title="updates">

    ```python theme={null}

        {"тема": "мороженое"},

    ):
        print(chunk)
    ```

## Выходы подграфа потока

Чтобы включить выходные данные из [подграфов](/oss/python/langgraph/use-subgraphs) в потоковые выходные данные, вы можете установить `subgraphs=True` в методе `.stream()` родительского графа. Это позволит передавать потоковые данные как из родительского графа, так и из любых подграфов.

Выходные данные будут передаваться в виде кортежей `(namespace, data)`, где `namespace` — это кортеж с путем к узлу, где вызывается подграф, например, `("parent_node:<task_id>", "child_node:<task_id>")`.

```python theme={null}
for chunk in graph.stream(
    {"foo": "foo"},
    # Установите subgraphs=True, чтобы передавать выходные данные из подграфов потоком.
    subgraphs=True, # [!подсветка кода]
    stream_mode="updates",
):
    print(chunk)
```

<Заголовок аккордеона="Расширенный пример: потоковая передача данных из подграфов">
  ```python theme={null}
  from langgraph.graph import START, StateGraph
  from typing import TypedDict

  # Определить подграф
  class SubgraphState(TypedDict):
      foo: str # Обратите внимание, что этот ключ используется совместно с состоянием родительского графа.
      бар: стр

  def subgraph_node_1(state: SubgraphState):
      return {"bar": "bar"}

  def subgraph_node_2(state: SubgraphState):
      return {"foo": state["foo"] + state["bar"]}

  subgraph_builder = StateGraph(SubgraphState)
  subgraph_builder.add_node(subgraph_node_1)
  subgraph_builder.add_node(subgraph_node_2)
  subgraph_builder.add_edge(START, "subgraph_node_1")
  subgraph_builder.add_edge("subgraph_node_1", "subgraph_node_2")
  subgraph = subgraph_builder.compile()

  # Определение родительского графа
  class ParentState(TypedDict):
      foo: str

  def node_1(state: ParentState):
      return {"foo": "привет!" + state["foo"]}

  builder = StateGraph(ParentState)
  builder.add_node("node_1", node_1)
  builder.add_node("node_2", subgraph)
  builder.add_edge(START, "node_1")
  builder.add_edge("node_1", "node_2")
  graph = builder.compile()

  for chunk in graph.stream(
      {"foo": "foo"},
      stream_mode="updates",
      # Установите subgraphs=True, чтобы передавать выходные данные из подграфов потоком.
      subgraphs=True, # [!подсветка кода]
  ):
      print(chunk)
  ```

  ```
  ((), {'node_1': {'foo': 'hi! foo'}})
  (('node_2:dfddc4ba-c3c5-6887-5012-a243b5b377c2',), {'subgraph_node_1': {'bar': 'bar'}})
  (('node_2:dfddc4ba-c3c5-6887-5012-a243b5b377c2',), {'subgraph_node_2': {'foo': 'hi! foobar'}})
  ((), {'node_2': {'foo': 'привет! foobar'}})
  ```

  Обратите внимание, что мы получаем не только обновления узлов, но и пространства имен, которые указывают, из какого графа (или подграфа) мы получаем потоковые данные.

## Токены LLM

Используйте потоковый режим `messages` для потоковой передачи выходных данных модели Large Language Model (LLM) **токен за токеном** из любой части вашего графа, включая узлы, инструменты, подграфы или задачи.

Потоковая передача данных из режима [`messages`](#supported-stream-modes) представляет собой кортеж `(message_chunk, metadata)`, где:

* `message_chunk`: токен или сегмент сообщения из LLM.
* `metadata`: словарь, содержащий подробную информацию об узле графа и вызове LLM.

Если ваш LLM недоступен для интеграции с LangChain, вы можете передавать его выходные данные в режиме `custom`. Подробнее см. [использовать с любым LLM](#use-with-any-llm).

<Предупреждение>
  **Для асинхронных операций в Python < 3.11 требуется ручная настройка**
  При использовании Python < 3.11 с асинхронным кодом необходимо явно передать [`RunnableConfig`](https://reference.langchain.com/python/langchain_core/runnables/#langchain_core.runnables.RunnableConfig) в `ainvoke()` для корректной потоковой передачи. См. [Асинхронные операции с Python < 3.11](#async) для получения подробной информации или обновите Python до версии 3.11+.
</Предупреждение>

```python theme={null}
from dataclasses import dataclass

from langchain.chat_models import init_chat_model
from langgraph.graph import StateGraph, START


@dataclass
класс MyState:
    тема: строка
    шутка: str = ""


model = init_chat_model(model="gpt-4.1-mini")

def call_model(state: MyState):
    «Позвоните в магистратуру, чтобы придумать шутку на какую-нибудь тему»
    # Обратите внимание, что события сообщений генерируются даже при запуске LLM с использованием метода .invoke вместо .stream.
    model_response = model.invoke( # [!code highlight]
        [
            {"role": "user", "content": f"Сгенерировать шутку о {state.topic}"}
        ]
    )
    return {"joke": model_response.content}

график = (
    StateGraph(MyState)
    .add_node(call_model)
    .add_edge(START, "call_model")
    .compile()
)

# Режим потоковой передачи "messages" возвращает итератор кортежей (message_chunk, metadata)
# где message_chunk — это токен, передаваемый потоком LLM, а metadata — это словарь.
# с информацией об узле графа, где был вызван LLM, и другой информацией.
for message_chunk, metadata in graph.stream(
    {"тема": "мороженое"},
    stream_mode="messages", # [!code highlight]
):
    если message_chunk.content:
        print(message_chunk.content, end="|", flush=True)
```

#### Фильтрация по узлу

Чтобы передавать токены только с определенных узлов, используйте `stream_mode="messages"` и отфильтруйте выходные данные по полю `langgraph_node` в передаваемых метаданных:

```python theme={null}
# с информацией об узле графа, где был вызван LLM, и другой информацией.
для сообщения, метаданных в graph.stream(
    входные данные,
    stream_mode="messages", # [!code highlight]
):
    # Фильтрация потоковых токенов по полю langgraph_node в метаданных
    # Чтобы включить только токены из указанного узла

        ...
```

## Потоковая передача пользовательских данных

Чтобы отправить **пользовательские данные** из узла или инструмента LangGraph, выполните следующие действия:

1. Используйте [`get_stream_writer`](https://reference.langchain.com/python/langgraph/config/#langgraph.config.get_stream_writer) для доступа к потоку записи и генерации пользовательских данных.
2. Установите `stream_mode="custom"` при вызове `.stream()` или `.astream()`, чтобы получить пользовательские данные в потоке. Вы можете комбинировать несколько режимов (например, `["updates", "custom"]`), но как минимум один из них должен быть `"custom"`.

<Предупреждение>
  **В асинхронном режиме Python < 3.11 функция [`get_stream_writer`](https://reference.langchain.com/python/langgraph/config/#langgraph.config.get_stream_writer) недоступна.**
  В асинхронном коде, работающем на Python < 3.11, функция [`get_stream_writer`](https://reference.langchain.com/python/langgraph/config/#langgraph.config.get_stream_writer) работать не будет.
  Вместо этого добавьте параметр `writer` к вашему узлу или инструменту и передавайте его вручную.
  Примеры использования см. в разделе [Асинхронные операции в Python < 3.11](#async).
</Предупреждение>

## Использовать с любым LLM

Вы можете использовать `stream_mode="custom"` для потоковой передачи данных из **любого API LLM** — даже если этот API **не** реализует интерфейс модели чата LangChain.

Это позволяет интегрировать как обычные LLM-клиенты, так и внешние сервисы, предоставляющие собственные потоковые интерфейсы, что делает LangGraph очень гибким для пользовательских настроек.

```python theme={null}
from langgraph.config import get_stream_writer

def call_arbitrary_model(state):
    «Пример узла, который вызывает произвольную модель и передает выходные данные потоком».
    # Настройте потоковое записывающее устройство на отправку пользовательских данных
    writer = get_stream_writer() # [!подсветка кода]
    # Предположим, у вас есть потоковый клиент, который выдает фрагменты данных.
    # Сгенерируйте токены LLM, используя свой собственный потоковый клиент
    for chunk in your_custom_streaming_client(state["topic"]):
        # Используйте модуль записи для отправки пользовательских данных в поток
        writer({"custom_llm_chunk": chunk}) # [!code highlight]
    return {"result": "completed"}

график = (
    StateGraph(State)
    .add_node(call_arbitrary_model)
    # Добавьте другие узлы и ребра по мере необходимости
    .compile()
)
# Установите параметр stream_mode="custom", чтобы получать пользовательские данные в потоке.
for chunk in graph.stream(
    {"тема": "кошки"},
    stream_mode="custom", # [!code highlight]

):
    # Этот фрагмент будет содержать пользовательские данные, передаваемые из LLM.
    print(chunk)
```

## Отключить потоковую передачу для определенных моделей чата

Если в вашем приложении используются модели, поддерживающие потоковую передачу данных, а также модели, не поддерживающие её, вам может потребоваться явно отключить потоковую передачу данных для некоторых из них.
модели, которые его не поддерживают.

При инициализации модели установите параметр `streaming=False`.

### Асинхронные операции с Python < 3.11

В версиях Python < 3.11 задачи asyncio (https://docs.python.org/3/library/asyncio-task.html#asyncio.create_task) не поддерживают параметр `context`.
Это ограничивает возможности LangGraph по автоматическому распространению контекста и влияет на механизмы потоковой обработки данных LangGraph двумя ключевыми способами:

1. Необходимо явно передавать [`RunnableConfig`](https://python.langchain.com/docs/concepts/runnables/#runnableconfig) в асинхронные вызовы LLM (например, `ainvoke()`), поскольку коллбэки не передаются автоматически.
2. Вы **не можете** использовать [`get_stream_writer`](https://reference.langchain.com/python/langgraph/config/#langgraph.config.get_stream_writer) в асинхронных узлах или инструментах — необходимо передавать аргумент `writer` напрямую.
