# Рабочие процессы и агенты

В этом руководстве рассматриваются распространенные схемы рабочих процессов и поведения агентов.

* Рабочие процессы имеют заранее определенные пути выполнения кода и предназначены для работы в определенной последовательности.
* Агенты динамичны и определяют собственные процессы и использование инструментов.

## Последовательность подсказок

Последовательность вызовов — это когда каждый вызов LLM обрабатывает результат предыдущего вызова. Она часто используется для выполнения четко определенных задач, которые можно разбить на более мелкие, проверяемые шаги. Некоторые примеры:

* Перевод документов на разные языки
* Проверка сгенерированного контента на соответствие

## Параллелизация

При распараллеливании программируемые логические модули (LLM) работают над задачей одновременно. Это достигается либо путем одновременного выполнения нескольких независимых подзадач, либо путем многократного выполнения одной и той же задачи для проверки различных результатов. Распараллеливание обычно используется для:

* Разделите подзадачи и выполняйте их параллельно, что повысит скорость.
* Запускайте задачи несколько раз, чтобы проверить различные результаты, что повышает уверенность в правильности решения.

В качестве примеров можно привести следующие:

* Выполняется одна подзадача, которая обрабатывает документ на наличие ключевых слов, и вторая подзадача для проверки на ошибки форматирования.
* Многократное выполнение задачи, которая оценивает документ на точность на основе различных критериев, таких как количество цитирований, количество использованных источников и качество источников.

Рабочие процессы маршрутизации обрабатывают входные данные, а затем направляют их к задачам, специфичным для конкретного контекста. Это позволяет определять специализированные потоки для сложных задач. Например, рабочий процесс, созданный для ответа на вопросы, связанные с продуктом, может сначала обработать вопрос такого типа, а затем направить запрос к конкретным процессам, связанным с ценообразованием, возвратом средств, обменом товаров и т. д.

## Оркестратор-работник

В конфигурации «оркестратор-работник» оркестратор:

* Разбивает задачи на подзадачи
* Делегирует подзадачи работникам
* Обобщает результаты работы сотрудников в конечный результат.

### Создание рабочих процессов в LangGraph

Рабочие процессы «оркестратор-работник» распространены, и LangGraph имеет встроенную поддержку для них. API `Send` позволяет динамически создавать узлы-работники и отправлять им определенные входные данные. Каждый работник имеет собственное состояние, и все выходные данные работников записываются в общий ключ состояния, доступный графу оркестратора. Это дает оркестратору доступ ко всем выходным данным работников и позволяет ему синтезировать их в конечный результат. В приведенном ниже примере выполняется итерация по списку разделов и используется API `Send` для отправки раздела каждому работнику.

```python theme={null}
from langgraph.types import Send


# Состояние графа
class State(TypedDict):
    тема: str # Сообщить о теме
    sections: list[Section] # Список разделов отчета
    completed_sections: Annotated[
        список, оператор.добавить
    ] # Все рабочие процессы записывают данные по этому ключу параллельно
    final_report: str # Итоговый отчет


# Рабочее государство
class WorkerState(TypedDict):
    раздел: Раздел
    completed_sections: Annotated[list, operator.add]


# Узлы
Def orchestrator(state: State):
    «Оркестратор, который формирует план отчета»

    # Генерация запросов
    report_sections = planner.invoke(
        [
            SystemMessage(content="Сгенерируйте план для отчета."),
            HumanMessage(content=f"Вот тема отчета: {state['topic']}"),
        ]
    )

    return {"sections": report_sections.sections}


def llm_call(state: WorkerState):
    «Работник пишет раздел отчета»

    # Сгенерировать раздел
    section = llm.invoke(
        [
            SystemMessage(
                content="Напишите раздел отчета, следуя указанному названию и описанию. Не включайте преамбулу для каждого раздела. Используйте форматирование Markdown."
            ),
            HumanMessage(
                content="Здесь указано название раздела: {state['section'].name} и описание: {state['section'].description}"
            ),
        ]
    )

    # Записать обновленный раздел в уже заполненные разделы
    return {"completed_sections": [section.content]}


def synthesizer(state: State):
    «Составьте полный отчет по разделам»

    # Список завершенных разделов
    completed_sections = state["completed_sections"]

    # Форматируйте завершенный раздел в строку, чтобы использовать его в качестве контекста для заключительных разделов.
    completed_report_sections = "\n\n---\n\n".join(completed_sections)

    return {"final_report": completed_report_sections}


# Функция условного ребра для создания рабочих процессов llm_call, каждый из которых записывает раздел отчета.
def assign_workers(state: State):
    «Назначьте работника на каждый раздел плана»

    # Запуск параллельной записи раздела с помощью API Send()
    return [Send("llm_call", {"section": s}) for s in state["sections"]]


# Создание рабочего процесса
orchestrator_worker_builder = StateGraph(State)

# Добавить узлы
orchestrator_worker_builder.add_node("orchestrator", orchestrator)
orchestrator_worker_builder.add_node("llm_call", llm_call)
orchestrator_worker_builder.add_node("synthesizer", synthesizer)

# Добавить ребра для соединения узлов
orchestrator_worker_builder.add_edge(START, "orchestrator")
orchestrator_worker_builder.add_conditional_edges(
    "оркестратор", assign_workers, ["llm_call"]
)
orchestrator_worker_builder.add_edge("llm_call", "synthesizer")
orchestrator_worker_builder.add_edge("synthesizer", END)

# Компиляция рабочего процесса
orchestrator_worker = orchestrator_worker_builder.compile()

# Отображение рабочего процесса
display(Image(orchestrator_worker.get_graph().draw_mermaid_png())

# Вызов
state = orchestrator_worker.invoke({"topic": "Создать отчет о законах масштабирования LLM"})

from IPython.display import Markdown
Markdown(state["final_report"])
```

## Оценщик-оптимизатор

В рабочих процессах «оценщик-оптимизатор» один вызов LLM создает ответ, а другой оценивает этот ответ. Если оценщик или [человек в цикле](/oss/python/langgraph/interrupts) определяет, что ответ нуждается в доработке, предоставляется обратная связь, и ответ создается заново. Этот цикл продолжается до тех пор, пока не будет сгенерирован приемлемый ответ.

Рабочие процессы «оценщик-оптимизатор» обычно используются, когда для выполнения задачи существуют определенные критерии успеха, но для их достижения требуется итерация. Например, при переводе текста между двумя языками не всегда достигается идеальное совпадение. Может потребоваться несколько итераций, чтобы получить перевод с одинаковым смыслом на обоих языках.

  ```python Graph API theme={null}
  evaluator = llm.with_structured_output(Feedback)


  # Узлы
  def llm_call_generator(state: State):
      «LLM порождает шутку»

      if state.get("feedback"):
          msg = llm.invoke(
              f"Напишите шутку на тему {state['topic']}, но учтите обратную связь: {state['feedback']}"
          )
      еще:
          msg = llm.invoke(f"Напишите шутку о {state['topic']}")
      return {"joke": msg.content}


  def llm_call_evaluator(state: State):
      «LLM оценивает шутку»

      grade = evaluator.invoke(f"Оцените шутку {state['joke']}")
      return {"funny_or_not": grade.grade, "feedback": grade.feedback}


  # Функция условного перехода для возврата к генератору шуток или к конечной точке в зависимости от обратной связи от оценщика
  def route_joke(state: State):
      «Вернуться к генератору шуток или завершить процесс на основе отзывов оценщика»

      if state["funny_or_not"] == "funny":
          вернуть "Принято"
      elif state["funny_or_not"] == "not funny":
          return "Rejected + Feedback"


  # Создание рабочего процесса
  optimizer_builder = StateGraph(State)

  # Добавить узлы
  optimizer_builder.add_node("llm_call_generator", llm_call_generator)
  optimizer_builder.add_node("llm_call_evaluator", llm_call_evaluator)

  # Добавить ребра для соединения узлов
  optimizer_builder.add_edge(START, "llm_call_generator")
  optimizer_builder.add_edge("llm_call_generator", "llm_call_evaluator")
  optimizer_builder.add_conditional_edges(
      "llm_call_evaluator",
      route_joke,
      { # Имя, возвращаемое функцией route_joke: Имя следующего узла для посещения
          "Принято": КОНЕЦ,
          "Отклонено + Обратная связь": "llm_call_generator",
      },
  )

  # Компиляция рабочего процесса
  optimizer_workflow = optimizer_builder.compile()

  # Отображение рабочего процесса
  display(Image(optimizer_workflow.get_graph().draw_mermaid_png())

  # Вызов
  state = optimizer_workflow.invoke({"topic": "Cats"})
  print(state["joke"])
  ```

## Агенты

Агенты обычно реализуются как LLM, выполняющие действия с использованием [инструментов](/oss/python/langchain/tools). Они работают в непрерывных циклах обратной связи и используются в ситуациях, когда проблемы и решения непредсказуемы. Агенты обладают большей автономией, чем рабочие процессы, и могут принимать решения об используемых инструментах и ​​способах решения проблем. При этом вы можете определить доступный набор инструментов и правила поведения агентов.

  ```python Functional API theme={null}
  from langchain.messages import (
      Системное сообщение,
      HumanMessage,
      ToolCall,
  )
  from langchain_core.messages import BaseMessage


  @задача
  def call_llm(messages: list[BaseMessage]):
      «LLM решает, называть ли инструмент или нет»
      return llm_with_tools.invoke(
          [
              SystemMessage(
                  content="Вы — полезный помощник, которому поручено выполнять арифметические операции над набором входных данных."
              )
          ]
          + сообщения
      )


  @задача
  def call_tool(tool_call: ToolCall):
      """Выполняет вызов инструмента"""
      инструмент = tools_by_name[tool_call["name"]]
      return tool.invoke(tool_call)


  @entrypoint()
  def agent(messages: list[BaseMessage]):
      llm_response = call_llm(messages).result()

      пока истинно:
          if not llm_response.tool_calls:
              перерыв

          # Выполнение инструментов
          tool_result_futures = [
              call_tool(tool_call) for tool_call in llm_response.tool_calls
          ]
          tool_results = [fut.result() for fut in tool_result_futures]
          messages = add_messages(messages, [llm_response, *tool_results])
          llm_response = call_llm(messages).result()

      messages = add_messages(messages, llm_response)
      возвращать сообщения

  # Вызов
  сообщения = [HumanMessage(content="Добавьте 3 и 4.")]
  for chunk in agent.stream(messages, stream_mode="updates"):

      print("\n")
  ```
