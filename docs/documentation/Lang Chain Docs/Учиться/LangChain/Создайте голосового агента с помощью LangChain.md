# Создание голосового агента с помощью LangChain

## Обзор

Чат-интерфейсы доминировали в том, как мы взаимодействуем с ИИ, но недавние прорывы в области мультимодального ИИ открывают захватывающие новые возможности. Высококачественные генеративные модели и выразительные системы преобразования текста в речь (TTS) теперь позволяют создавать агентов, которые воспринимаются не столько как инструменты, сколько как собеседники.

Голосовые агенты — один из примеров этого. Вместо того чтобы полагаться на клавиатуру и мышь для ввода данных в агента, вы можете использовать голосовое управление для взаимодействия с ним. Это может быть более естественным и увлекательным способом взаимодействия с ИИ, и он может быть особенно полезен в определенных контекстах.

### Что такое голосовые агенты?

Голосовые агенты — это [агенты](/oss/python/langchain/agents), способные вести естественные разговоры с пользователями. Эти агенты сочетают в себе распознавание речи, обработку естественного языка, генеративный ИИ и технологии преобразования текста в речь для создания плавных и естественных диалогов.

Они подходят для самых разных задач, в том числе:

* Поддержка клиентов
* Персональные помощники
* Интерфейсы с поддержкой бесконтактного управления
* Коучинг и обучение

### Как работают голосовые агенты?

В общих чертах, каждый голосовой агент должен выполнять три задачи:

1. **Прослушайте** — запишите аудио и расшифруйте его.
2. **Подумайте** — интерпретируйте намерение, причину, план.
3. **Speak** — генерация аудиосигнала и его передача пользователю.

Разница заключается в последовательности и взаимосвязи этих шагов. На практике производственные агенты следуют одной из двух основных архитектур:

#### 1. Архитектура STT > Агент > TTS («Сэндвич»)

Архитектура Sandwich состоит из трех отдельных компонентов: преобразования речи в текст (STT), текстового агента LangChain и преобразования текста в речь (TTS).

```тема русалки={null}
блок-схема LR
    A[Аудио пользователя] --> B[Преобразование речи в текст]
    B --> C[LangChain Agent]
    C --> D [Преобразование текста в речь]
    D --> E [Аудиовыход]
```

**Плюсы:**

* Полный контроль над каждым компонентом (при необходимости можно менять поставщиков STT/TTS)
* Доступ к новейшим возможностям современных моделей текстовой модальности
* Прозрачное поведение с четкими границами между компонентами.

**Недостатки:**

* Требуется координация работы нескольких сервисов
* Дополнительная сложность в управлении конвейером
* При преобразовании речи в текст происходит потеря информации (например, тона, эмоций).

#### 2. Архитектура преобразования речи в речь (S2S)

Технология преобразования речи в речь использует многомодальную модель, которая обрабатывает аудиовход и генерирует аудиовыход в исходном виде.

```тема русалки={null}
блок-схема LR
    A[Пользовательский звук] --> B[Мультимодальная модель]
    B --> C [Аудиовыход]
```

**Плюсы:**

* Более простая архитектура с меньшим количеством движущихся частей
* Как правило, более низкая задержка для простых взаимодействий.
* Прямая обработка звука улавливает тон и другие нюансы речи.

**Недостатки:**

* Ограниченный выбор моделей, повышенный риск привязки к конкретному поставщику услуг.
* Функционал может отставать от моделей, работающих с текстовым режимом отображения.
* Меньшая прозрачность в обработке звука
* Ограниченные возможности управления и настройки

В этом руководстве демонстрируется **сэндвич-архитектура**, позволяющая сбалансировать производительность, управляемость и доступ к современным возможностям моделей. Сэндвич-архитектура может обеспечить задержку менее 700 мс при работе с некоторыми поставщиками STT и TTS, сохраняя при этом контроль над модульными компонентами.

### Обзор демонстрационного приложения

Мы рассмотрим создание голосового агента с использованием архитектуры «сэндвич». Агент будет управлять заказами в сэндвич-кафе. Приложение продемонстрирует все три компонента архитектуры «сэндвич», используя [AssemblyAI](https://www.assemblyai.com/) для синтеза речи и [Cartesia](https://cartesia.ai/) для преобразования текста в речь (хотя адаптеры можно создать для большинства провайдеров).

Полноценное тестовое приложение доступно в репозитории [voice-sandwich-demo](https://github.com/langchain-ai/voice-sandwich-demo). Здесь мы рассмотрим это приложение.

В демонстрационной версии используются WebSockets для двусторонней связи в реальном времени между браузером и сервером. Та же архитектура может быть адаптирована для других протоколов, таких как телефонные системы (Twilio, Vonage) или соединения WebRTC.

### Архитектура

В демонстрационном примере реализован потоковый конвейер обработки данных, где на каждом этапе данные обрабатываются асинхронно:

**Клиент (браузер)**

* Захватывает звук с микрофона и кодирует его в формате PCM.
* Устанавливает соединение WebSocket с бэкэнд-сервером.
* Передает аудиофрагменты на сервер в режиме реального времени.
* Принимает и воспроизводит синтезированную речь.

**Сервер (Python)**

* Принимает соединения WebSocket от клиентов

* Организует трехэтапный процесс:
  * [Преобразование речи в текст (STT)](#1-преобразование речи в текст): Пересылает аудиопоток поставщику STT (например, AssemblyAI), получает события транскрипции.
  * [Агент](#2-langchain-agent): Обрабатывает транскрипты с помощью агента LangChain, передает токены ответа потоком.
  * [Преобразование текста в речь (TTS)](#3-text-to-speech): Отправляет ответы агента поставщику TTS (например, Cartesia), получает аудиофрагменты

* Возвращает синтезированный звук клиенту для воспроизведения.

Конвейер обработки данных использует асинхронные генераторы для обеспечения потоковой передачи на каждом этапе. Это позволяет компонентам, расположенным ниже по потоку, начинать обработку до завершения обработки на вышестоящих этапах, минимизируя сквозную задержку.

## 1. Преобразование речи в текст

Этап STT преобразует входящий аудиопоток в текстовые расшифровки. В реализации используется схема «производитель-потребитель» для одновременной обработки потоковой передачи аудио и приема расшифровок.

### Ключевые понятия

**Схема «производитель-потребитель»**: аудиофрагменты отправляются в службу STT одновременно с получением событий транскрипции. Это позволяет начать транскрипцию до того, как будет получен весь аудиоконтент.

**Типы мероприятий**:

* `stt_chunk`: Частичные расшифровки предоставляются по мере обработки аудиоданных сервисом STT.
* `stt_output`: Итоговые отформатированные стенограммы, запускающие обработку агентом.

**WebSocket-соединение**: Поддерживает постоянное соединение с API STT в реальном времени от AssemblyAI, настроенным для воспроизведения PCM-аудио с частотой 16 кГц и автоматическим форматированием треков.

### Выполнение

```python theme={null}
from typing import AsyncIterator
import asyncio
from assemblyai_stt import AssemblyAISTT
from events import VoiceAgentEvent

async def stt_stream(
    audio_stream: AsyncIterator[bytes],
) -> AsyncIterator[VoiceAgentEvent]:
    """
    Преобразование потока: Аудио (байты) → Голосовые события (VoiceAgentEvent)

    Использует модель «производитель-потребитель», в которой:
    - Продюсер: считывает аудиофрагменты и отправляет их в AssemblyAI.
    - Потребитель: получает события транскрипции от AssemblyAI
    """
    stt = AssemblyAISTT(sample_rate=16000)

    async def send_audio():
        «Фоновая задача, которая передает аудиофрагменты в AssemblyAI».
        пытаться:
            async for audio_chunk in audio_stream:
                await stt.send_audio(audio_chunk)
        окончательно:
            # Сигнализация завершения по окончании аудиопотока
            await stt.close()

    # Запуск отправки аудио в фоновом режиме
    send_task = asyncio.create_task(send_audio())

    пытаться:
        # Принимать и передавать события транскрипции по мере их поступления
        async for event in stt.receive_events():
            событие уплаты налогов
    окончательно:
        # Уборка
        with contextlib.suppress(asyncio.CancelledError):
            send_task.cancel()
            await send_task
        await stt.close()
```

## 2. Агент LangChain

На этапе обработки агентом текстовые расшифровки передаются через LangChain [agent](/oss/python/langchain/agents), а токены ответа передаются потоком. В данном случае мы передаем потоком все [блоки текстового содержимого](/oss/python/langchain/messages#textcontentblock), сгенерированные агентом.

### Ключевые понятия

**Потоковая передача ответов**: Агент использует [`stream_mode="messages"`](/oss/python/langchain/streaming#llm-tokens) для отправки токенов ответа по мере их генерации, а не ожидая полного ответа. Это позволяет этапу синтеза речи начать синтез немедленно.

**Память диалога**: [контрольная точка](/oss/python/langchain/short-term-memory) поддерживает состояние диалога между ходами, используя уникальный идентификатор потока. Это позволяет агенту ссылаться на предыдущие обмены репликами в диалоге.

### Выполнение

## 3. Преобразование текста в речь

Этап синтеза речи (TTS) преобразует текстовые ответы агента в аудиопоток и передает его обратно клиенту. Как и этап синтеза речи (STT), он использует схему «производитель-потребитель» для одновременной отправки текста и приема аудио.

### Ключевые понятия

**Параллельная обработка**: Данная реализация объединяет два асинхронных потока:

* **Обработка на вышестоящем уровне**: Пропускает все события и отправляет фрагменты текста от агента поставщику TTS.
* **Приём аудио**: Принимает синтезированные аудиофрагменты от поставщика TTS.

**Потоковая передача текста в речь**: Некоторые провайдеры (например, [Cartesia](https://cartesia.ai/)) начинают синтезировать звук сразу после получения текста, что позволяет начать воспроизведение аудио до того, как агент завершит генерацию полного ответа.

**Сквозная передача событий**: Все события, поступающие из вышестоящих источников, проходят без изменений, что позволяет клиенту или другим наблюдателям отслеживать полное состояние конвейера.

### Выполнение

```python theme={null}
from cartesia_tts import CartesiaTTS
from utils import merge_async_iters

async def tts_stream(
    event_stream: AsyncIterator[VoiceAgentEvent],
) -> AsyncIterator[VoiceAgentEvent]:
    """
    Преобразование потока: Голосовые события → Голосовые события (с аудио)

    Объединяет два параллельных потока:
    1. process_upstream(): передает события и отправляет текст в Cartesia.
    2. tts.receive_events(): возвращает аудиофрагменты из Cartesia.
    """
    tts = CartesiaTTS()

    async def process_upstream() -> AsyncIterator[VoiceAgentEvent]:
        «Обработать события, поступающие от источника, и отправить текст агента в Cartesia».
        async for event in event_stream:
            # Пройти через все события
            событие уплаты налогов
            # Отправить текст агента в Cartesia для синтеза
            if event.type == "agent_chunk":
                await tts.send_text(event.text)

    пытаться:
        # Объединение исходящих событий с аудиособытиями TTS
        # Оба потока работают одновременно
        async for event in merge_async_iters(
            process_upstream(),
            tts.receive_events()
        ):
            событие уплаты налогов
    окончательно:
        await tts.close()
```

## Собираем всё воедино

Полный конвейер объединяет три этапа в единую цепь:

```python theme={null}
from langchain_core.runnables import RunnableGenerator

конвейер = (
    RunnableGenerator(stt_stream) # Аудио → STT события
    | RunnableGenerator(agent_stream) # События STT → События агента
    | RunnableGenerator(tts_stream) # События агента → Аудио TTS
)

# Использовать в конечной точке WebSocket
@app.websocket("/ws")
async def websocket_endpoint(websocket: WebSocket):
    await websocket.accept()

    async def websocket_audio_stream():
        «Передача аудиобайтов через WebSocket».
        пока истинно:
            data = await websocket.receive_bytes()
            данные о урожайности

    # Преобразование звука через конвейер
    output_stream = pipeline.atransform(websocket_audio_stream())

    # Отправить аудио TTS обратно клиенту
    async for event in output_stream:
        if event.type == "tts_chunk":
            await websocket.send_bytes(event.audio)
```

Для компоновки каждого шага конвейера мы используем [RunnableGenerators](https://reference.langchain.com/python/langchain_core/runnables/#langchain_core.runnables.base.RunnableGenerator). Это абстракция, которую LangChain использует внутри для управления [потоковой передачей данных между компонентами](https://reference.langchain.com/python/langchain_core/runnables/).

Каждый этап обрабатывает события независимо и параллельно: расшифровка аудио начинается сразу после поступления аудиоданных, агент начинает рассуждения, как только становится доступна расшифровка, а синтез речи начинается сразу после генерации текста агентом. Такая архитектура позволяет достичь задержки менее 700 мс, что обеспечивает естественную разговорную речь.
