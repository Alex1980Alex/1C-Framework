# Обзор контекста

**Контекстная инженерия** — это практика создания динамических систем, которые предоставляют необходимую информацию и инструменты в нужном формате, чтобы приложение искусственного интеллекта могло выполнить задачу. Контекст можно охарактеризовать по двум ключевым параметрам:

1. По признаку **изменчивости**:

* **Статический контекст**: Неизменяемые данные, которые не меняются во время выполнения (например, метаданные пользователя, подключения к базе данных, инструменты).
* **Динамический контекст**: Изменяемые данные, которые меняются по мере работы приложения (например, история разговоров, промежуточные результаты, наблюдения за вызовами инструментов).

2. По продолжительности жизни:

* **Контекст выполнения**: Данные, относящиеся к одному запуску или обращению
* **Контекст между разговорами**: Данные, сохраняющиеся в нескольких разговорах или сессиях.

<Совет>
  Контекст времени выполнения относится к локальному контексту: данным и зависимостям, необходимым вашему коду для работы. Он **не** относится к:

  * Контекст LLM, то есть данные, передаваемые в подсказку LLM.
  * "Контекстное окно", которое представляет собой максимальное количество токенов, которые могут быть переданы в LLM.

  Контекст времени выполнения — это форма внедрения зависимостей, которую можно использовать для оптимизации контекста LLM. Он позволяет предоставлять зависимости (например, подключения к базе данных, идентификаторы пользователей или клиенты API) вашим инструментам и узлам во время выполнения, а не прописывать их жестко. Например, вы можете использовать метаданные пользователя в контексте времени выполнения для получения пользовательских настроек и передачи их в контекстное окно.
</Совет>

LangGraph предоставляет три способа управления контекстом, объединяющие измерения изменчивости и времени жизни:

| Тип контекста | Описание | Изменчивость | Время жизни | Способ доступа |
| ------------------------------------------------------------------------------------------- | ------------------------------------------------------ | ---------- | ------------------ | --------------------------------------- |
| [**Статический контекст выполнения**](#static-runtime-context) | Метаданные пользователя, инструменты, подключения к базе данных передаются при запуске | Статический | Однократное выполнение | Аргумент `context` для `invoke`/`stream` |
| [**Динамический контекст выполнения (состояние)**](#dynamic-runtime-context-state) | Изменяемые данные, которые меняются в течение одного запуска | Динамический | Один запуск | Объект состояния LangGraph |
| [**Динамическое хранилище контекста между диалогами**](#dynamic-cross-conversation-context-store) | Постоянные данные, передаваемые между диалогами | Динамическое | Междиалоговое | Хранилище LangGraph |

## Статический контекст выполнения

**Статический контекст выполнения** представляет собой неизменяемые данные, такие как метаданные пользователя, инструменты и подключения к базе данных, которые передаются приложению в начале выполнения через аргумент `context` в функциях `invoke`/`stream`. Эти данные не изменяются во время выполнения.

```python theme={null}
@dataclass
class ContextScheme:
    имя_пользователя: строка

graph.invoke(
    {"messages": [{"role": "user", "content": "hi!"}]},
    context={"user_name": "John Smith"} # [!code highlight]
)
```

<Вкладки>
  <Tab title="Подсказка агента">

    ```python theme={null}
    @dynamic_prompt # [!подсветка кода]
    def personalized_prompt(request: ModelRequest) -> str: # [!code highlight]
        user_name = request.runtime.context.user_name
        return f"Вы полезный помощник. Обращайтесь к пользователю как {user_name}."

    агент = create_agent(
        model="claude-sonnet-4-5-20250929",
        инструменты=[get_weather],
        middleware=[personalized_prompt],
        context_schema=ContextSchema
    )

    agent.invoke(
        {"messages": [{"role": "user", "content": "what is the weather in sf"}]},
        context=ContextSchema(user_name="John Smith") # [!code highlight]
    )
    ```

## Динамический контекст выполнения

**Динамический контекст выполнения** представляет собой изменяемые данные, которые могут меняться в течение одного запуска и управляются с помощью объекта состояния LangGraph. Сюда входят история разговоров, промежуточные результаты и значения, полученные от инструментов или выходных данных LLM. В LangGraph объект состояния выступает в роли [кратковременной памяти](/oss/python/concepts/memory) во время выполнения.

<Вкладки>
  <Tab title="В агенте">
    В примере показано, как включить состояние в **подсказку** агента.

    Состояние также может быть доступно **инструментам** агента, которые могут считывать или обновлять состояние по мере необходимости. Подробнее см. [руководство по вызову инструментов](/oss/python/langchain/tools#short-term-memory).

    ```python theme={null}
    from langchain.agents import create_agent
    from langchain.agents.middleware import dynamic_prompt, ModelRequest
    from langchain.agents import AgentState


    class CustomState(AgentState): # [!code highlight]
        имя_пользователя: строка

    @dynamic_prompt # [!подсветка кода]
    def personalized_prompt(request: ModelRequest) -> str: # [!code highlight]
        user_name = request.state.get("user_name", "User")
        return f"Вы полезный помощник. Имя пользователя: {user_name}"

    агент = create_agent(
        model="claude-sonnet-4-5-20250929",
        инструменты=[...],
        state_schema=CustomState, # [!code highlight]
        middleware=[personalized_prompt], # [!code highlight]
    )

    agent.invoke({
        "сообщения": "привет!",
        "user_name": "John Smith"
    })
    ```
  </Tab>

  <Tab title="В рабочем процессе">
    ```python theme={null}
    from typing_extensions import TypedDict
    from langchain.messages import AnyMessage
    from langgraph.graph import StateGraph

    class CustomState(TypedDict): # [!code highlight]
        сообщения: список[AnyMessage]
        extra_field: int

    def node(state: CustomState): # [!code highlight]
        сообщения = состояние["сообщения"]
        ...
        return { # [!выделение кода]
            "extra_field": state["extra_field"] + 1 # [!code highlight]
        }

    builder = StateGraph(State)
    builder.add_node(node)
    builder.set_entry_point("node")
    graph = builder.compile()
    ```
  </Tab>
</Вкладки>

<Совет>
  **Включение памяти**
  Для получения более подробной информации о включении памяти см. [руководство по памяти](/oss/python/langgraph/add-memory). Это мощная функция, позволяющая сохранять состояние агента между несколькими запусками. В противном случае состояние будет ограничено только одним запуском.
</Совет>

## Динамический контекст междиалогового взаимодействия

**Динамический контекст межсобытийного взаимодействия** представляет собой постоянные, изменяемые данные, охватывающие несколько разговоров или сессий и управляемые через хранилище LangGraph. Сюда входят профили пользователей, предпочтения и история взаимодействий. Хранилище LangGraph выступает в качестве [долговременной памяти](/oss/python/concepts/memory#long-term-memory) в течение нескольких запусков. Это можно использовать для чтения или обновления постоянных данных (например, профилей пользователей, предпочтений, предыдущих взаимодействий).
