# Обзор памяти

Память — это система, которая запоминает информацию о предыдущих взаимодействиях. Для агентов ИИ память имеет решающее значение, поскольку позволяет им запоминать предыдущие взаимодействия, учиться на основе обратной связи и адаптироваться к предпочтениям пользователя. По мере того, как агенты решают более сложные задачи с многочисленными взаимодействиями с пользователем, эта возможность становится важной как для эффективности, так и для удовлетворенности пользователя.

В этом концептуальном руководстве рассматриваются два типа памяти в зависимости от объема воспроизводимых ею данных:

* Кратковременная память (или память, ограниченная потоком) отслеживает текущий диалог, сохраняя историю сообщений в рамках сессии. LangGraph управляет кратковременной памятью как частью состояния вашего агента. Состояние сохраняется в базе данных с помощью контрольной точки, поэтому поток можно возобновить в любое время. Кратковременная память обновляется при вызове графа или завершении шага, а состояние считывается в начале каждого шага.
* Долговременная память (Long-term-memory) хранит данные, специфичные для пользователя или приложения, в разных сессиях и используется *между* потоками диалога. Ее можно вызвать *в любое время* и *в любом потоке*. Память ограничена любым пользовательским пространством имен, а не только идентификатором одного потока. LangGraph предоставляет хранилища (stores) (/oss/python/langgraph/persistence#memory-store) ([reference doc](https://langchain-ai.github.io/langgraph/reference/store/#langgraph.store.base.BaseStore)), позволяющие сохранять и вызывать долговременную память.

## Кратковременная память

Кратковременная память позволяет вашему приложению запоминать предыдущие взаимодействия в рамках одного потока или диалога. Поток организует несколько взаимодействий в рамках одной сессии, подобно тому, как электронная почта группирует сообщения в одном диалоге.

LangGraph управляет кратковременной памятью как частью состояния агента, сохраняя данные с помощью контрольных точек, привязанных к конкретному потоку. Это состояние обычно включает историю разговоров, а также другие данные, сохраняющие состояние, такие как загруженные файлы, полученные документы или сгенерированные артефакты. Сохраняя эти данные в состоянии графа, бот может получить доступ к полному контексту данного разговора, сохраняя при этом разделение между различными потоками.

### Управление кратковременной памятью

История разговоров — наиболее распространенная форма кратковременной памяти, и длительные разговоры представляют собой проблему для современных LLM (Learning Memory Model). Полная история может не поместиться в контекстное окно LLM, что приведет к неисправимой ошибке. Даже если ваша LLM поддерживает полную длину контекста, большинство LLM все равно плохо работают с длинными контекстами. Они «отвлекаются» на устаревший или не относящийся к теме контент, при этом страдая от более медленного времени отклика и более высоких затрат.

Модели чата принимают контекст с помощью сообщений, которые включают инструкции, предоставленные разработчиком (системное сообщение), и ввод пользователя (сообщения от человека). В чат-приложениях сообщения чередуются между вводом от человека и ответами модели, в результате чего список сообщений со временем становится длиннее. Поскольку контекстные окна ограничены, а списки сообщений, содержащие большое количество токенов, могут быть дорогостоящими, многие приложения могут извлечь выгоду из использования методов ручного удаления или игнорирования устаревшей информации.

## Долговременная память

Долговременная память в LangGraph позволяет системам сохранять информацию между различными диалогами или сессиями. В отличие от кратковременной памяти, которая ограничена определенным потоком, долговременная память сохраняется в пользовательских «пространствах имен».

Долговременная память — сложная задача, для которой нет универсального решения. Однако следующие вопросы помогут вам разобраться в различных методах:

* Что такое тип памяти? Люди используют память для запоминания фактов (семантическая память), опыта (эпизодическая память) и правил (процедурная память). Агенты ИИ могут использовать память аналогичным образом. Например, агенты ИИ могут использовать память для запоминания конкретных фактов о пользователе, чтобы выполнить задачу.
* [Когда вы хотите обновить воспоминания?](#writing-memories) Обновление памяти может происходить в рамках логики приложения агента (например, «на горячем пути»). В этом случае агент обычно решает запомнить факты, прежде чем ответить пользователю. В качестве альтернативы, обновление памяти может происходить в фоновом режиме (логика, которая работает в фоновом режиме / асинхронно и генерирует воспоминания). Мы объясняем компромиссы между этими подходами в [разделе ниже](#writing-memories).

Различные приложения требуют разных типов памяти. Хотя аналогия не совсем точна, изучение [типов человеческой памяти](https://www.psychologytoday.com/us/basics/memory/types-of-memory?ref=blog.langchain.dev) может быть весьма полезным. Некоторые исследования (например, [статья CoALA](https://arxiv.org/pdf/2309.02427)) даже сопоставили эти типы человеческой памяти с теми, которые используются в агентах искусственного интеллекта.

| Тип памяти | Что хранится | Пример с человеком | Пример с агентом |
| -------------------------------- | -------------- | -------------------------- | ------------------- |
| [Семантическая](#семантическая-память) | Факты | То, чему я научился в школе | Факты о пользователе |
| [Эпизодическая](#эпизодическая-память) | Опыт | Что я делал | Действия агента в прошлом |
| [Процедурная](#процедурная-память) | Инструкции | Инстинкты или двигательные навыки | Подсказка системы агента |

### Семантическая память

Семантическая память, как у людей, так и у агентов искусственного интеллекта, включает в себя сохранение конкретных фактов и понятий. У людей она может включать информацию, полученную в школе, а также понимание понятий и их взаимосвязей. Для агентов искусственного интеллекта семантическая память часто используется для персонализации приложений путем запоминания фактов или понятий из прошлых взаимодействий.

<Примечание>
  Семантическая память отличается от «семантического поиска», который представляет собой метод поиска похожего контента с использованием «смысла» (обычно в виде векторных представлений). Семантическая память — это термин из психологии, обозначающий хранение фактов и знаний, тогда как семантический поиск — это метод извлечения информации на основе смысла, а не точного совпадения.
</Примечание>

Семантическая память может управляться различными способами:

#### Профиль

Воспоминания могут представлять собой единый, постоянно обновляемый «профиль», содержащий четко определенную информацию о пользователе, организации или другом объекте (включая самого агента). Профиль, как правило, представляет собой просто JSON-документ с различными парами «ключ-значение», которые вы выбрали для представления вашей предметной области.

При запоминании профиля необходимо убедиться, что он **обновляется** каждый раз. Поэтому следует передавать предыдущий профиль и [запрашивать у модели генерацию нового профиля](https://github.com/langchain-ai/memory-template) (или использовать какой-либо [JSON-патч](https://github.com/hinthornw/trustcall) для применения к старому профилю). По мере увеличения размера профиля это может привести к ошибкам, поэтому может быть полезно разделить профиль на несколько документов или использовать **строгое** декодирование при генерации документов, чтобы гарантировать корректность схем памяти.

#### Коллекция

В качестве альтернативы, воспоминания могут представлять собой набор документов, которые постоянно обновляются и расширяются с течением времени. Каждое отдельное воспоминание может быть более узкоспециализированным и его легче генерировать, что означает меньшую вероятность **потери** информации с течением времени. Для LLM проще создавать *новые* объекты для новой информации, чем согласовывать новую информацию с существующим профилем. В результате, набор документов, как правило, приводит к [более высокой полноте воспроизведения](https://en.wikipedia.org/wiki/Precision_and_recall).

Однако это несколько усложняет процесс обновления памяти. Теперь модели необходимо *удалять* или *обновлять* существующие элементы в списке, что может быть непросто. Кроме того, некоторые модели могут по умолчанию чрезмерно вставлять элементы, а другие — чрезмерно обновлять. См. пакет [Trustcall](https://github.com/hinthornw/trustcall) для одного из способов управления этим процессом и рассмотрите возможность оценки (например, с помощью такого инструмента, как [LangSmith](https://docs.langchain.com/langsmith/evaluation)), чтобы помочь вам настроить поведение.

Работа с коллекциями документов также переносит сложность на поиск в памяти по списку. В настоящее время `Store` поддерживает как [семантический поиск](https://langchain-ai.github.io/langgraph/reference/store/#langgraph.store.base.SearchOp.query), так и [фильтрацию по содержимому](https://langchain-ai.github.io/langgraph/reference/store/#langgraph.store.base.SearchOp.filter).

Наконец, использование набора воспоминаний может затруднить предоставление всестороннего контекста модели. Хотя отдельные воспоминания могут следовать определенной схеме, эта структура может не отражать полный контекст или взаимосвязи между воспоминаниями. В результате, при использовании этих воспоминаний для генерации ответов, модели может не хватать важной контекстной информации, которая была бы более доступна при использовании единого профилирующего подхода.

### Эпизодическая память

Эпизодическая память, как у людей, так и у агентов ИИ, включает в себя воспоминания о прошлых событиях или действиях. В статье CoALA хорошо это иллюстрируется: факты можно записывать в семантическую память, тогда как *опыт* можно записывать в эпизодическую память. Для агентов ИИ эпизодическая память часто используется, чтобы помочь агенту вспомнить, как выполнить задачу.

На практике эпизодическая память часто реализуется с помощью подсказок на основе небольшого количества примеров, где агенты учатся на прошлых последовательностях, чтобы правильно выполнять задачи. Иногда проще «показать», чем «рассказать», и LLM хорошо обучаются на примерах. Обучение на основе небольшого количества примеров позволяет [«программировать»](https://x.com/karpathy/status/1627366413840322562) вашу LLM, обновляя подсказку примерами ввода-вывода для иллюстрации предполагаемого поведения. Хотя для генерации примеров на основе небольшого количества примеров можно использовать различные лучшие практики, часто проблема заключается в выборе наиболее релевантных примеров на основе пользовательского ввода.

Обратите внимание, что хранилище данных в памяти (memory store) — это лишь один из способов хранения данных в виде примеров для небольшого количества заданий. Если вы хотите привлечь больше разработчиков или более тесно связать примеры для небольшого количества заданий с вашей оценочной средой, вы также можете использовать набор данных LangSmith (LangSmith Dataset) для хранения ваших данных. Затем для достижения той же цели можно использовать динамические селекторы примеров для небольшого количества заданий. LangSmith проиндексирует набор данных и позволит извлекать примеры для небольшого количества заданий, наиболее релевантные пользовательскому вводу, на основе сходства ключевых слов (используя алгоритм, подобный BM25, для сходства ключевых слов).

Посмотрите это видеоинструкцию [https://www.youtube.com/watch?v=37VaU7e7t5o] для примера использования динамического выбора примеров с малым количеством примеров в LangSmith. Также посмотрите эту [статью в блоге](https://blog.langchain.dev/few-shot-prompting-to-improve-tool-calling-performance/), демонстрирующую использование подсказок с малым количеством примеров для повышения производительности вызова инструментов, и эту [статью в блоге](https://blog.langchain.dev/aligning-llm-as-a-judge-with-human-preferences/), в которой пример с малым количеством примеров используется для согласования LLM с предпочтениями человека.

### Процедурная память

Процедурная память, как у людей, так и у агентов ИИ, включает в себя запоминание правил, используемых для выполнения задач. У людей процедурная память подобна усвоенным знаниям о том, как выполнять задачи, например, ездить на велосипеде, используя базовые двигательные навыки и чувство равновесия. Эпизодическая память, с другой стороны, включает в себя воспоминания о конкретных событиях, таких как первая успешная поездка на велосипеде без дополнительных колес или запоминающаяся велосипедная прогулка по живописному маршруту. Для агентов ИИ процедурная память представляет собой комбинацию весов модели, кода агента и подсказок агента, которые в совокупности определяют функциональность агента.

На практике агенты довольно редко изменяют веса своей модели или переписывают свой код. Однако гораздо чаще агенты изменяют свои собственные подсказки.

Один из эффективных подходов к уточнению инструкций агента — это ["рефлексия"](https://blog.langchain.dev/reflection-agents/) или мета-подсказка. Это включает в себя предоставление агенту текущих инструкций (например, системной подсказки) вместе с недавними разговорами или явной обратной связью от пользователя. Затем агент уточняет свои собственные инструкции на основе этих данных. Этот метод особенно полезен для задач, где инструкции сложно указать заранее, поскольку он позволяет агенту учиться и адаптироваться на основе своих взаимодействий.

Например, мы создали [генератор твитов](https://www.youtube.com/watch?v=Vn8A3BxfplE), используя внешнюю обратную связь и переписывание подсказок, чтобы создавать высококачественные бумажные резюме для Twitter. В этом случае конкретную подсказку для составления резюме было сложно задать *заранее*, но пользователю было довольно легко критиковать сгенерированные твиты и давать рекомендации по улучшению процесса составления резюме.

Приведённый ниже псевдокод показывает, как это можно реализовать с помощью хранилища памяти LangGraph (/oss/python/langgraph/persistence#memory-store), используя хранилище для сохранения приглашения ввода, узел `update_instructions` для получения текущего приглашения (а также обратной связи от диалога с пользователем, захваченной в `state["messages"]`), обновления приглашения и сохранения нового приглашения обратно в хранилище. Затем `call_model` получает обновлённое приглашение из хранилища и использует его для генерации ответа.

```python theme={null}
# Узел, который *использует* инструкции
def call_model(state: State, store: BaseStore):
    namespace = ("agent_instructions", )
    инструкции = store.get(namespace, key="agent_a")[0]
    # Логика приложения
    prompt = prompt_template.format(instructions=instructions.value["instructions"])
    ...

# Узел, обновляющий инструкции
def update_instructions(state: State, store: BaseStore):
    пространство имен = ("инструкции",)
    инструкции = магазин.поиск(пространство имен)[0]
    # Логика памяти
    prompt = prompt_template.format(instructions=instructions.value["instructions"], conversation=state["messages"])
    output = llm.invoke(prompt)
    new_instructions = output['new_instructions']
    store.put(("agent_instructions", "agent_a", {"instructions": new_instructions})
    ...
```

#### На раскаленном пути

Создание воспоминаний во время выполнения программы имеет как преимущества, так и недостатки. С положительной стороны, такой подход позволяет обновлять информацию в режиме реального времени, делая новые воспоминания немедленно доступными для использования в последующих взаимодействиях. Он также обеспечивает прозрачность, поскольку пользователи могут получать уведомления о создании и сохранении воспоминаний.

Однако этот метод также сопряжен с трудностями. Он может увеличить сложность, если агенту потребуется новый инструмент для принятия решения о том, что следует сохранить в памяти. Кроме того, процесс рассуждений о том, что следует сохранить в памяти, может повлиять на задержку агента. Наконец, агенту приходится одновременно создавать память и выполнять другие свои обязанности, что потенциально может повлиять на количество и качество создаваемой памяти.

Например, ChatGPT использует инструмент [save_memories](https://openai.com/index/memory-and-new-controls-for-chatgpt/) для обновления и добавления воспоминаний в виде строкового содержимого, определяя, следует ли и как использовать этот инструмент для каждого сообщения пользователя. В качестве примера реализации можно использовать наш шаблон [memory-agent](https://github.com/langchain-ai/memory-agent).

#### На заднем плане

Создание памяти в качестве отдельной фоновой задачи имеет ряд преимуществ. Это устраняет задержки в основном приложении, отделяет логику приложения от управления памятью и позволяет агенту более целенаправленно выполнять задачи. Такой подход также обеспечивает гибкость во времени создания памяти, чтобы избежать дублирования работы.

Однако этот метод имеет свои сложности. Определение частоты записи в память становится критически важным, поскольку нечастые обновления могут оставить другие потоки без нового контекста. Также важно решить, когда запускать процесс формирования памяти. Распространенные стратегии включают планирование через заданный промежуток времени (с перепланированием при возникновении новых событий), использование расписания cron или разрешение ручного запуска пользователями или логикой приложения.

В качестве примера реализации можно использовать наш шаблон [memory-service](https://github.com/langchain-ai/memory-template).

### Хранение данных в памяти

LangGraph хранит долговременные воспоминания в виде JSON-документов в хранилище (/oss/python/langgraph/persistence#memory-store). Каждое воспоминание организовано в рамках пользовательского пространства имен (аналогично папке) и имеет уникальный ключ (подобный имени файла). Пространства имен часто содержат идентификаторы пользователей или организаций, а также другие метки, что упрощает организацию информации. Такая структура обеспечивает иерархическую организацию воспоминаний. Поиск между пространствами имен поддерживается с помощью фильтров содержимого.

```python theme={null}
from langgraph.store.memory import InMemoryStore


def embed(texts: list[str]) -> list[list[float]]:
    # Замените на фактическую функцию встраивания или объект встраивания LangChain
    return [[1.0, 2.0] * len(texts)]


# InMemoryStore сохраняет данные во встроенный в память словарь. В производственной среде используйте хранилище на основе базы данных.
store = InMemoryStore(index={"embed": embed, "dims": 2})
user_id = "my-user"
application_context = "chitchat"
namespace = (user_id, application_context)
store.put(
    пространство имён,
    "память",
    {
        "правила": [
            «Пользователям нравится короткий и прямой язык».
            Пользователь владеет только английским языком и языком Python.
        ],
        "my-key": "my-value",
    },
)
# получить "память" по идентификатору
item = store.get(namespace, "a-memory")
# Поиск "воспоминаний" в этом пространстве имен с фильтрацией по эквивалентности контента, отсортированный по сходству векторов.
items = store.search(
    namespace, filter={"my-key": "my-value"}, query="language preferences"
)
```

Для получения дополнительной информации о хранилище в памяти см. руководство [Persistence](/oss/python/langgraph/persistence#memory-store).
