# Создание системы поддержки клиентов с помощью передачи информации между сотрудниками

Паттерн [конечный автомат](/oss/python/langchain/multi-agent/handoffs) описывает рабочие процессы, в которых поведение агента изменяется по мере прохождения им различных состояний задачи. В этом руководстве показано, как реализовать конечный автомат, используя вызовы инструментов для динамического изменения конфигурации одного агента — обновления доступных инструментов и инструкций на основе текущего состояния. Состояние может определяться из нескольких источников: прошлых действий агента (вызовы инструментов), внешнего состояния (например, результатов вызовов API) или даже первоначального ввода пользователя (например, путем запуска классификатора для определения намерений пользователя).

В этом руководстве вы создадите агента службы поддержки клиентов, который будет выполнять следующие действия:

* Перед продолжением запрашивает информацию о гарантии.
* Классифицирует проблемы как аппаратные или программные.
* Предлагает решения или передает вопрос специалисту службы поддержки.
* Сохраняет состояние диалога на протяжении нескольких ходов.

В отличие от паттерна [субагентов](/oss/python/langchain/multi-agent/subagents-personal-assistant), где субагенты вызываются как инструменты, в паттерне **конечный автомат** используется один агент, конфигурация которого изменяется в зависимости от хода выполнения рабочего процесса. Каждый «шаг» — это просто другая конфигурация (системная подсказка + инструменты) одного и того же базового агента, выбираемая динамически в зависимости от состояния.

## 1. Определение пользовательского состояния

Сначала определите пользовательскую схему состояния, которая отслеживает, какой шаг в данный момент активен:

```python theme={null}
from langchain.agents import AgentState
from typing_extensions import NotRequired
from typing import Literal

# Определите возможные этапы рабочего процесса
SupportStep = Literal["warranty_collector", "issue_classifier", "resolution_specialist"] # [!code highlight]

class SupportState(AgentState): # [!code highlight]
    «Состояние рабочего процесса службы поддержки клиентов».
    current_step: NotRequired[SupportStep # [!code highlight]
    warranty_status: NotRequired[Literal["in_warranty", "out_of_warranty"]]
    issue_type: NotRequired[Literal["hardware", "software"]]
```

Поле `current_step` является ядром паттерна конечного автомата — оно определяет, какая конфигурация (подсказка + инструменты) загружается на каждом этапе.

## 2. Создайте инструменты для управления состоянием рабочего процесса.

Создайте инструменты, которые обновляют состояние рабочего процесса. Эти инструменты позволяют агенту записывать информацию и переходить к следующему шагу.

Ключевым моментом является использование команды `Command` для обновления состояния, включая поле `current_step`:

```python theme={null}
from langchain.tools import tool, ToolRuntime
from langchain.messages import ToolMessage
from langgraph.types import Command

@инструмент
def record_warranty_status(
    статус: Буквально ["в_гарантии", "вне_гарантии"],
    среда выполнения: ToolRuntime[None, SupportState],
) -> Команда: # [!подсветка кода]
    «Зафиксируйте гарантийный статус клиента и перейдите к классификации проблемы».
    return Command( # [!выделение кода]
        обновление={ # [!подсветка кода]
            "сообщения": [
                ToolMessage(
                    "Статус гарантии указан как: {status}",
                    tool_call_id=runtime.tool_call_id,
                )
            ],
            "warranty_status": статус,
            "current_step": "issue_classifier", # [!code highlight]
        }
    )


@инструмент
def record_issue_type(
    issue_type: Literal["hardware", "software"],
    среда выполнения: ToolRuntime[None, SupportState],
) -> Команда: # [!подсветка кода]
    «Зафиксируйте тип проблемы и передайте дело специалисту по ее решению».
    return Command( # [!выделение кода]
        обновление={ # [!подсветка кода]
            "сообщения": [
                ToolMessage(
                    content=f"Тип проблемы указан как: {issue_type}",
                    tool_call_id=runtime.tool_call_id,
                )
            ],
            "issue_type": issue_type,
            "current_step": "resolution_specialist", # [!code highlight]
        }
    )


@инструмент
def escalate_to_human(reason: str) -> str:
    «Передайте дело специалисту службы поддержки».
    В реальной системе это привело бы к созданию заявки, уведомлению персонала и т. д.
    return f"Передача вопроса в службу поддержки. Причина: {reason}"


@инструмент
def provide_solution(solution: str) -> str:
    «Предложить решение проблемы клиента».
    return f"Предоставлено решение: {решение}"
```

Обратите внимание, как `record_warranty_status` и `record_issue_type` возвращают объекты `Command`, которые обновляют как данные (`warranty_status`, `issue_type`), так и `current_step`. Именно так работает конечный автомат — инструменты управляют ходом выполнения рабочего процесса.

## 4. Создайте промежуточное ПО на основе шагов.

Создайте промежуточное ПО, которое считывает `current_step` из состояния и применяет соответствующую конфигурацию. Для более чистой реализации мы будем использовать декоратор `@wrap_model_call`:

```python theme={null}
from langchain.agents.middleware import wrap_model_call, ModelRequest, ModelResponse
from typing import Callable


@wrap_model_call # [!code highlight]
def apply_step_config(
    запрос: ModelRequest,
    обработчик: Callable[[ModelRequest], ModelResponse],
) -> ModelResponse:
    """Настройте поведение агента в зависимости от текущего шага."""
    # Получить текущий шаг (по умолчанию — warranty_collector для первого взаимодействия)
    current_step = request.state.get("current_step", "warranty_collector") # [!code highlight]

    # Поиск конфигурации шага
    stage_config = STEP_CONFIG[current_step] # [!code highlight]

    # Проверка наличия необходимого состояния
    for key in stage_config["requires"]:
        если request.state.get(key) равно None:
            raise ValueError(f"{key} должен быть установлен до достижения {current_step}")

    # Форматирование запроса с указанием значений состояния (поддерживает {warranty_status}, {issue_type} и т. д.)
    system_prompt = stage_config["prompt"].format(**request.state)

    # Внедрение системных подсказок и инструментов, специфичных для каждого шага.
    request = request.override( # [!выделение кода]
        system_prompt=system_prompt, # [!code highlight]
        tools=stage_config["tools"], # [!code highlight]
    )

    return handler(request)
```

Это промежуточное программное обеспечение:

1. **Считывает текущий шаг**: Получает `current_step` из состояния (по умолчанию — "warranty\_collector").
2. **Выполняет поиск конфигурации**: Находит соответствующую запись в `STEP_CONFIG`.
3. **Проверяет зависимости**: Гарантирует наличие необходимых полей состояния.
4. **Форматирует приглашение**: Вставляет значения состояния в шаблон приглашения.
5. **Применяет конфигурацию**: Переопределяет системное приглашение и доступные инструменты.

Метод `request.override()` имеет ключевое значение — он позволяет динамически изменять поведение агента в зависимости от состояния без создания отдельных экземпляров агента.

## 5. Создайте агента

Теперь создайте агента с пошаговым промежуточным ПО и контрольной точкой для сохранения состояния:

```python theme={null}
from langchain.agents import create_agent
from langgraph.checkpoint.memory import InMemorySaver

# Собрать все инструменты из всех конфигураций шагов
все_инструменты = [
    record_warranty_status,
    тип_выпуска_записи,
    provide_solution,
    escalate_to_human,
]

# Создание агента с пошаговой конфигурацией
агент = create_agent(
    модель,
    tools=all_tools,
    state_schema=SupportState, # [!code highlight]
    middleware=[apply_step_config], # [!code highlight]
    checkpointer=InMemorySaver(), # [!code highlight]
)
```

<Примечание>
  **Зачем нужен контрольный пункт?** Контрольный пункт сохраняет состояние между ходами разговора. Без него состояние `current_step` будет потеряно между сообщениями пользователя, что нарушит рабочий процесс.
</Примечание>

## 7. Понимание переходов состояний

Давайте проследим, что происходит на каждом этапе:

### Ход 1: Начальное сообщение

```python theme={null}
{
    "messages": [HumanMessage("Привет, у меня треснул экран телефона")],
    "current_step": "warranty_collector" # Значение по умолчанию
}
```

Применяется промежуточное ПО:

* Системная подсказка: `WARRANTY_COLLECTOR_PROMPT`
* Инструменты: `[record_warranty_status]`

### Шаг 2: После регистрации гарантийного случая

Вызов инструмента `record_warranty_status("in_warranty")` возвращает:

```python theme={null}
Команда(обновление={
    "warranty_status": "in_warranty",
    "current_step": "issue_classifier" # Переход состояния!
})
```

На следующем ходу применяется промежуточное ПО:

* Системная подсказка: `ISSUE_CLASSIFIER_PROMPT` (отформатирована с параметром `warranty_status="in_warranty"`)
* Инструменты: `[record_issue_type]`

### Ход 3: После классификации вопроса

Вызов инструмента `record_issue_type("hardware")` возвращает:

```python theme={null}
Команда(обновление={
    "issue_type": "hardware",
    "current_step": "resolution_specialist" # Переход состояния!
})
```

На следующем ходу применяется промежуточное ПО:

* Системное приглашение: `RESOLUTION_SPECIALIST_PROMPT` (отформатировано с использованием `warranty_status` и `issue_type`)
* Инструменты: `[provide_solution, escalate_to_human]`

Ключевая идея: **Инструменты управляют рабочим процессом**, обновляя `current_step`, а **промежуточное ПО реагирует**, применяя соответствующую конфигурацию на следующем этапе.

## 8. Управление историей сообщений

По мере прохождения агентом этапов история сообщений увеличивается. Используйте [промежуточное ПО для суммирования](/oss/python/langchain/short-term-memory#summarize-messages), чтобы сжать более ранние сообщения, сохраняя при этом контекст разговора:

```python theme={null}
from langchain.agents import create_agent
from langchain.agents.middleware import SummarizationMiddleware # [!code highlight]
from langgraph.checkpoint.memory import InMemorySaver

агент = create_agent(
    модель,
    tools=all_tools,
    state_schema=SupportState,
    промежуточное ПО=[
        apply_step_config,
        SummarizationMiddleware( # [!code highlight]
            model="gpt-4.1-mini",
            trigger=("tokens", 4000),
            keep=("messages", 10)
        )
    ],
    checkpointer=InMemorySaver(),
)
```

Другие методы управления памятью описаны в [руководстве по кратковременной памяти](/oss/python/langchain/short-term-memory).

## 9. Добавьте гибкости: Вернитесь назад

В некоторых рабочих процессах пользователям необходимо иметь возможность вернуться к предыдущим шагам для исправления информации (например, изменения статуса гарантии или классификации проблемы). Однако не все переходы целесообразны — например, обычно нельзя вернуться назад после обработки возврата средств. Для этого рабочего процесса поддержки мы добавим инструменты для возврата к шагам проверки гарантии и классификации проблемы.

<Совет>
  Если ваш рабочий процесс требует произвольных переходов между большинством шагов, подумайте, нужен ли вам вообще структурированный рабочий процесс. Такая схема работает лучше всего, когда шаги следуют четкой последовательной последовательности с occasional обратными переходами для внесения исправлений.
</Совет>

Добавьте инструменты «вернуться назад» на этап решения проблемы:

```python theme={null}
@инструмент
def go_back_to_warranty() -> Команда: # [!подсветка кода]
    «Вернитесь к этапу проверки гарантии».
    return Command(update={"current_step": "warranty_collector"}) # [!code highlight]


@инструмент
def go_back_to_classification() -> Команда: # [!подсветка кода]
    «Вернитесь к этапу классификации проблемы».
    return Command(update={"current_step": "issue_classifier"}) # [!code highlight]


# Обновите конфигурацию resolution_specialist, чтобы включить эти инструменты.
STEP_CONFIG["resolution_specialist"]["tools"].extend([
    вернуться к гарантии,
    вернуться к классификации
])
```

Обновите подсказку специалиста по разрешению проблем, упомянув следующие инструменты:

```python theme={null}
RESOLUTION_SPECIALIST_PROMPT = """Вы являетесь агентом службы поддержки клиентов и помогаете с проблемами устройств."

ТЕКУЩИЙ ЭТАП: Разрешение
ИНФОРМАЦИЯ О КЛИЕНТЕ: Статус гарантии: {warranty_status}, тип проблемы: {issue_type}

На этом этапе вам необходимо:
1. По вопросам, связанным с программным обеспечением: предоставьте шаги по устранению неполадок, используя функцию provide_solution.
2. По вопросам, касающимся оборудования:
   - Если товар находится на гарантии: опишите процесс гарантийного ремонта, используя функцию provide_solution.
   - Если гарантия истекла: обратитесь к специалисту для получения информации о платных вариантах ремонта.

Если клиент укажет на неверность предоставленной информации, используйте:
- go_back_to_warranty для исправления статуса гарантии
- go_back_to_classification для исправления типа проблемы

Будьте конкретны и полезны в своих решениях.""
```

Теперь агент может вносить исправления:

```python theme={null}
результат = agent.invoke(
    {"messages": [HumanMessage("На самом деле я допустил ошибку — гарантия на мое устройство истекла")]},
    конфигурация
)
# Агент вызовет функцию go_back_to_warranty и перезапустит этап проверки гарантии.
```

## Полный пример

Вот всё вместе в виде исполняемого скрипта:

<Expandable title="Полный код" defaultOpen={false}>
  ```python theme={null}
  """
  Пример конечного автомата поддержки клиентов

  Этот пример демонстрирует шаблон проектирования «конечный автомат».
  Поведение отдельного агента динамически изменяется в зависимости от состояния current_step.
  создание конечного автомата для последовательного сбора информации.
  """

  импорт uuid

  from langgraph.checkpoint.memory import InMemorySaver
  from langgraph.types import Command
  from typing import Callable, Literal
  from typing_extensions import NotRequired

  from langchain.agents import AgentState, create_agent
  from langchain.agents.middleware import wrap_model_call, ModelRequest, ModelResponse, SummarizationMiddleware
  from langchain.chat_models import init_chat_model
  from langchain.messages import HumanMessage, ToolMessage
  from langchain.tools import tool, ToolRuntime

  model = init_chat_model("anthropic:claude-3-5-sonnet-latest")


  # Определите возможные этапы рабочего процесса
  SupportStep = Literal["warranty_collector", "issue_classifier", "resolution_specialist"]


  class SupportState(AgentState):
      «Состояние рабочего процесса службы поддержки клиентов».

      current_step: NotRequired[SupportStep]
      warranty_status: NotRequired[Literal["in_warranty", "out_of_warranty"]]
      issue_type: NotRequired[Literal["hardware", "software"]]


  @инструмент
  def record_warranty_status(
      статус: Буквально ["в_гарантии", "вне_гарантии"],
      среда выполнения: ToolRuntime[None, SupportState],
  ) -> Команда:
      «Зафиксируйте гарантийный статус клиента и перейдите к классификации проблемы».
      return Command(
          обновление={
              "сообщения": [
                  ToolMessage(
                      "Статус гарантии указан как: {status}",
                      tool_call_id=runtime.tool_call_id,
                  )
              ],
              "warranty_status": статус,
              "current_step": "issue_classifier",
          }
      )


  @инструмент
  def record_issue_type(
      issue_type: Literal["hardware", "software"],
      среда выполнения: ToolRuntime[None, SupportState],
  ) -> Команда:
      «Зафиксируйте тип проблемы и передайте дело специалисту по ее решению».
      return Command(
          обновление={
              "сообщения": [
                  ToolMessage(
                      content=f"Тип проблемы указан как: {issue_type}",
                      tool_call_id=runtime.tool_call_id,
                  )
              ],
              "issue_type": issue_type,
              "текущий_шаг": "специалист_по_разрешению",
          }
      )


  @инструмент
  def escalate_to_human(reason: str) -> str:
      «Передайте дело специалисту службы поддержки».
      В реальной системе это привело бы к созданию заявки, уведомлению персонала и т. д.
      return f"Передача вопроса в службу поддержки. Причина: {reason}"


  @инструмент
  def provide_solution(solution: str) -> str:
      «Предложить решение проблемы клиента».
      return f"Предоставлено решение: {решение}"


  # Определяем подсказки как константы
  WARRANTY_COLLECTOR_PROMPT = """Вы являетесь агентом службы поддержки клиентов и помогаете с проблемами устройства."

  ТЕКУЩИЙ ЭТАП: Проверка гарантии

  На этом этапе вам необходимо:
  1. Тепло поприветствуйте клиента.
  2. Спросите, распространяется ли гарантия на их устройство.
  3. Используйте функцию record_warranty_status для записи их ответа и перейдите к следующему шагу.

  Будьте разговорчивы и дружелюбны. Не задавайте несколько вопросов одновременно.

  ISSUE_CLASSIFIER_PROMPT = """Вы являетесь агентом службы поддержки клиентов и помогаете с проблемами устройств."

  ТЕКУЩИЙ ЭТАП: Классификация проблемы
  ИНФОРМАЦИЯ О КЛИЕНТЕ: Гарантийный статус: {warranty_status}

  На этом этапе вам необходимо:
  1. Попросите клиента описать свою проблему.
  2. Определите, является ли проблема аппаратной (физические повреждения, поломка деталей) или программной (сбои в работе приложений, проблемы с производительностью).
  3. Используйте record_issue_type для записи классификации и перейдите к следующему шагу.

  Если что-то непонятно, задайте уточняющие вопросы, прежде чем классифицировать.

  RESOLUTION_SPECIALIST_PROMPT = """Вы являетесь агентом службы поддержки клиентов и помогаете с проблемами устройств."

  ТЕКУЩИЙ ШАГ: Разрешение
  ИНФОРМАЦИЯ О КЛИЕНТЕ: Статус гарантии: {warranty_status}, тип проблемы: {issue_type}

  На этом этапе вам необходимо:
  1. По вопросам, связанным с программным обеспечением: предоставьте шаги по устранению неполадок, используя функцию provide_solution.
  2. По вопросам, касающимся оборудования:
     - Если товар находится на гарантии: опишите процесс гарантийного ремонта, используя функцию provide_solution.
     - Если гарантия истекла: обратитесь к специалисту для получения информации о платных вариантах ремонта.

  Будьте конкретны и полезны в своих решениях."""


  # Настройка шага: сопоставляет имя шага с (prompt, tools, required_state)
  STEP_CONFIG = {
      "warranty_collector": {
          "prompt": WARRANTY_COLLECTOR_PROMPT,
          "инструменты": [record_warranty_status],
          "требует": [],
      },
      "issue_classifier": {
          "prompt": ISSUE_CLASSIFIER_PROMPT,
          "инструменты": [record_issue_type],
          "требуется": ["статус_гарантии"],
      },
      "resolution_specialist": {
          "prompt": RESOLUTION_SPECIALIST_PROMPT,
          "инструменты": [предоставить_решение, передать_вопрос_человеку],
          "требуется": ["статус_гарантии", "тип_выпуска"],
      },
  }


  @wrap_model_call
  def apply_step_config(
      запрос: ModelRequest,
      обработчик: Callable[[ModelRequest], ModelResponse],
  ) -> ModelResponse:
      """Настройте поведение агента в зависимости от текущего шага."""
      # Получить текущий шаг (по умолчанию — warranty_collector для первого взаимодействия)
      current_step = request.state.get("current_step", "warranty_collector")

      # Поиск конфигурации шага
      step_config = STEP_CONFIG[current_step]

      # Проверка наличия необходимого состояния
      for key in step_config["requires"]:
          если request.state.get(key) равно None:
              raise ValueError(f"{key} должен быть установлен до достижения {current_step}")

      # Форматирование запроса с указанием значений состояния
      system_prompt = step_config["prompt"].format(**request.state)

      # Внедрение системных подсказок и инструментов, специфичных для каждого шага.
      request = request.override(
          system_prompt=system_prompt,
          tools=step_config["tools"],
      )

      return handler(request)


  # Собрать все инструменты из всех конфигураций шагов
  все_инструменты = [
      record_warranty_status,
      тип_выпуска_записи,
      provide_solution,
      escalate_to_human,
  ]

  # Создание агента с пошаговой конфигурацией и суммированием
  агент = create_agent(
      модель,
      tools=all_tools,
      state_schema=SupportState,
      промежуточное ПО=[
          apply_step_config,
          SummarizationMiddleware(
              model="gpt-4.1-mini",
              trigger=("tokens", 4000),
              keep=("messages", 10)
          )
      ],
      checkpointer=InMemorySaver(),
  )


  # ============================================================================
  # Тестирование рабочего процесса
  # ============================================================================

  если __name__ == "__main__":
      thread_id = str(uuid.uuid4())
      config = {"configurable": {"thread_id": thread_id}}

      результат = agent.invoke(
          {"messages": [HumanMessage("Привет, у меня треснул экран телефона")]},
          конфигурация
      )

      результат = agent.invoke(
          {"messages": [HumanMessage("Да, гарантия еще действует")]},
          конфигурация
      )

      результат = agent.invoke(
          {"messages": [HumanMessage("Экран треснул из-за падения")]},
          конфигурация
      )

      результат = agent.invoke(
          {"messages": [HumanMessage("Что мне делать?")]},
          конфигурация
      )
      for msg in result['messages']:
          msg.pretty_print()
  ```
