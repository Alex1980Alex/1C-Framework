# Создание личного помощника с субагентами

## Обзор

Паттерн **супервизора** — это многоагентная архитектура, в которой центральный агент-супервизор координирует работу специализированных агентов-работников. Этот подход особенно эффективен, когда задачи требуют различных видов экспертизы. Вместо создания одного агента, управляющего выбором инструментов в разных областях, вы создаете узкоспециализированных специалистов, координируемых супервизором, который понимает общий рабочий процесс.

В этом уроке вы создадите систему персонального помощника, которая продемонстрирует эти преимущества на примере реалистичного рабочего процесса. Система будет координировать работу двух специалистов с принципиально разными обязанностями:

* **Агент календаря**, который занимается составлением расписаний, проверкой доступности и организацией мероприятий.
* **Агент электронной почты**, который управляет коммуникацией, составляет сообщения и отправляет уведомления.

Мы также добавим функцию [проверки с участием человека](/oss/python/langchain/human-in-the-loop), которая позволит пользователям утверждать, редактировать и отклонять действия (например, исходящие электронные письма) по своему усмотрению.

### Зачем нужен супервайзер?

Многоагентные архитектуры позволяют распределять инструменты между рабочими процессами, каждый из которых имеет свои собственные подсказки или инструкции. Рассмотрим агента с прямым доступом ко всем API календаря и электронной почты: он должен выбирать из множества похожих инструментов, понимать точные форматы каждого API и обрабатывать несколько доменов одновременно. Если производительность снижается, может быть полезно разделить связанные инструменты и соответствующие подсказки на логические группы (частично для управления итеративными улучшениями).

## 1. Определение инструментов

Начните с определения инструментов, требующих структурированных входных данных. В реальных приложениях они будут вызывать реальные API (Google Calendar, SendGrid и т. д.). В этом руководстве вы будете использовать заглушки для демонстрации этого шаблона.

```python theme={null}
from langchain.tools import tool

@инструмент
def create_calendar_event(
    заголовок: строка,
    start_time: str, # ISO format: "2024-01-15T14:00:00"
    end_time: str, # ISO format: "2024-01-15T15:00:00"
    участники: список[str], # адресов электронной почты
    местоположение: str = ""
) -> str:
    «Создать событие в календаре. Требуется точный формат даты и времени ISO».
    # Заготовка: На практике это будет вызывать API Google Календаря, API Outlook и т. д.
    return f"Событие создано: {title} с {start_time} по {end_time} с {len(attendees)} участниками"


@инструмент
def send_email(
    кому: список[str], # адреса электронной почты
    Тема: строка,
    тело: str,
    cc: list[str] = []
) -> str:
    «Отправка электронных писем через API электронной почты. Требуются правильно отформатированные адреса».
    # Заготовка: На практике это будет вызывать SendGrid, API Gmail и т. д.
    return f"Электронное письмо отправлено на адрес {', '.join(to)} - Тема: {subject}"


@инструмент
def get_available_time_slots(
    участники: список[str],
    дата: строка, # Формат ISO: "2024-01-15"
    duration_minutes: int
) -> список[str]:
    «Проверьте доступность участников в календаре на конкретную дату».
    # Заготовка: На практике это будет запрашивать API календаря.
    return ["09:00", "14:00", "16:00"]
```

## 2. Создание специализированных субагентов

Далее мы создадим специализированных субагентов, которые будут заниматься каждой областью.

### Создание агента календаря

Календарный агент понимает запросы на планирование на естественном языке и преобразует их в точные вызовы API. Он обрабатывает анализ дат, проверку доступности и создание событий.

```python theme={null}
from langchain.agents import create_agent


CALENDAR_AGENT_PROMPT = (
    «Вы — помощник по составлению расписания».
    "Анализ запросов на планирование на естественном языке (например, 'следующий вторник в 14:00')"
    «в надлежащие форматы даты и времени ISO».
    Используйте функцию get_available_time_slots для проверки доступности временных интервалов при необходимости.
    Используйте функцию create_calendar_event для планирования событий.
    «В своем окончательном ответе всегда уточняйте, что было запланировано».
)

calendar_agent = create_agent(
    модель,
    tools=[create_calendar_event, get_available_time_slots],
    system_prompt=CALENDAR_AGENT_PROMPT,
)
```

Протестируйте календарный агент, чтобы посмотреть, как он обрабатывает планирование на естественном языке:

### Создать агент электронной почты

Агент электронной почты отвечает за составление и отправку сообщений. Он занимается извлечением информации о получателе, созданием подходящих тем и текста сообщений, а также управлением электронной перепиской.

```python theme={null}
EMAIL_AGENT_PROMPT = (
    «Вы — помощник по работе с электронной почтой».
    «Составляйте профессиональные электронные письма, основываясь на запросах, заданных на естественном языке».
    «Извлеките информацию о получателе и составьте соответствующие заголовки и основной текст».
    Используйте функцию send_email для отправки сообщения.
    «В своем окончательном ответе всегда уточняйте, что именно было отправлено».
)

email_agent = create_agent(
    модель,
    инструменты=[отправить_электронную почту],
    system_prompt=EMAIL_AGENT_PROMPT,
)
```

## 3. Используйте суб-агентов в качестве инструментов

Теперь оберните каждый субагент в инструмент, который может вызвать супервизор. Это ключевой архитектурный шаг, создающий многоуровневую систему. Супервизор будет видеть инструменты высокого уровня, такие как "schedule_event", а не инструменты низкого уровня, такие как "create_calendar_event".

```python theme={null}
@инструмент
def schedule_event(request: str) -> str:
    «Планируйте события в календаре, используя естественный язык».

    Используйте эту функцию, когда пользователь хочет создать, изменить или проверить события в календаре.
    Обрабатывает данные о дате и времени, проверяет доступность и создает события.

    Входные данные: Запрос на планирование на естественном языке (например, «встреча с командой дизайнеров»).
    в следующий вторник в 14:00)
    """
    результат = calendar_agent.invoke({
        "сообщения": [{"роль": "пользователь", "контент": запрос}]
    })
    return result["messages"][-1].text


@инструмент
def manage_email(request: str) -> str:
    Отправляйте электронные письма, используя естественный язык.

    Используйте это, когда пользователь хочет отправить уведомления, напоминания или любое другое электронное письмо.
    Коммуникация. Обработка данных о получателях, формирование тем писем и подготовка электронных сообщений.
    композиция.

    Входные данные: Запрос на отправку электронного письма на естественном языке (например, «отправить им напоминание о…»).
    встреча')
    """
    результат = email_agent.invoke({
        "сообщения": [{"роль": "пользователь", "контент": запрос}]
    })
    return result["messages"][-1].text
```

Описания инструментов помогают руководителю решить, когда использовать каждый из них, поэтому делайте их ясными и конкретными. Мы возвращаем только окончательный ответ суб-агента, поскольку руководителю не нужно видеть промежуточные рассуждения или вызовы инструментов.

## 4. Создайте агента-супервайзера

Теперь создайте супервизора, который будет координировать работу субагентов. Супервизор видит только инструменты высокого уровня и принимает решения о маршрутизации на уровне домена, а не на уровне отдельных API.

```python theme={null}
SUPERVISOR_PROMPT = (
    «Вы — полезный личный помощник».
    «Вы можете планировать события в календаре и отправлять электронные письма».
    «Разбивайте запросы пользователей на соответствующие вызовы инструментов и координируйте результаты».
    «Когда запрос включает в себя несколько действий, используйте несколько инструментов последовательно».
)

    модель,

### Понимание архитектуры

Ваша система состоит из трех уровней. Нижний уровень содержит инструменты API с жесткими требованиями к форматам. Средний уровень содержит суб-агенты, которые принимают естественный язык, преобразуют его в структурированные вызовы API и возвращают подтверждения на естественном языке. Верхний уровень содержит супервизор, который направляет запросы к высокоуровневым функциям и синтезирует результаты.

Такое разделение задач обеспечивает ряд преимуществ: каждый слой имеет свою узкую специализацию, можно добавлять новые области, не затрагивая существующие, а также тестировать и дорабатывать каждый слой независимо.

## 6. Добавьте проверку с участием человека

Целесообразно включить [проверку с участием человека](/oss/python/langchain/human-in-the-loop) конфиденциальных действий. - Ваша встреча с командой дизайнеров назначена на следующий вторник, 18 июня, с 14:00 до 15:00.
- Команде дизайнеров отправлено электронное напоминание о необходимости ознакомиться с новыми макетами перед встречей.

```

Запуск продолжается с учетом наших действий.

## 7. Расширенные возможности: Управление потоком информации

По умолчанию суб-агенты получают от супервизора только строку запроса. Возможно, вам потребуется передать дополнительный контекст, например, историю переписки или пользовательские настройки.

### Передача дополнительного контекста разговора субагентам

```python theme={null}
from langchain.tools import tool, ToolRuntime

@инструмент
def schedule_event(
    запрос: str,
    среда выполнения: ToolRuntime
) -> str:
    «Планируйте события в календаре, используя естественный язык».
    # Настройка контекста, получаемого субагентом
    original_user_message = next(
        сообщение для сообщения в runtime.state["messages"]
        если message.type == "human"
    )
    подсказка = (
        «Вы оказываете помощь в обработке следующего запроса пользователя:\n\n»
        f"{original_user_message.text}\n\n"
        «Вам поручено выполнить следующее дополнительное задание:\n\n»
        f"{request}"
    )
    результат = calendar_agent.invoke({
        "сообщения": [{"роль": "пользователь", "содержание": подсказка}],
    })
    return result["messages"][-1].text
```

Это позволяет суб-агентам видеть полный контекст разговора, что может быть полезно для разрешения неоднозначностей, таких как «запланируйте это на то же время завтра» (ссылаясь на предыдущий разговор).

<Совет>
  Полный контекст, полученный суб-агентом, можно увидеть в вызове модели чата ([chat model call](https://smith.langchain.com/public/c7d54882-afb8-4039-9c5a-4112d0f458b0/r/6803571e-af78-4c68-904a-ecf55771084d)) трассировки LangSmith.
</Совет>

## 8. Основные выводы

Паттерн "супервизор" создает уровни абстракции, где каждый уровень имеет четко определенную ответственность. При проектировании системы супервизора начните с четких границ предметной области и предоставьте каждому суб-агенту специализированные инструменты и подсказки. Напишите четкие описания инструментов для супервизора, протестируйте каждый уровень независимо перед интеграцией и управляйте потоком информации в соответствии с вашими конкретными потребностями.

<Совет>
  **Когда следует использовать модель "супервайзер"?**

  Используйте шаблон супервизора, если у вас несколько отдельных доменов (календарь, электронная почта, CRM, база данных), каждый домен имеет несколько инструментов или сложную логику, вам нужен централизованный контроль рабочих процессов, и суб-агентам не нужно напрямую общаться с пользователями.

  В более простых случаях с небольшим количеством инструментов используйте одного агента. Когда агентам необходимо вести диалог с пользователями, используйте [handoffs](/oss/python/langchain/multi-agent/handoffs) вместо этого. Для взаимодействия между агентами по принципу «точка-точка» рассмотрите другие шаблоны работы с несколькими агентами.
</Совет>
