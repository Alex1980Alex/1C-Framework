## 1. Базовый протокол

### 1.1. JSON-RPC 2.0

LSP использует JSON-RPC 2.0 для обмена сообщениями между клиентом (IDE) и сервером.

**Три типа сообщений:**

| Тип | Поля | Ответ ожидается? |
|-----|------|:----------------:|
| **Request** | `jsonrpc`, `id`, `method`, `params` | Да |
| **Response** | `jsonrpc`, `id`, `result` \| `error` | — |
| **Notification** | `jsonrpc`, `method`, `params` | Нет |

### 1.2. Формат сообщений

Каждое сообщение состоит из header и content, разделённых `\r\n\r\n`:

```
Content-Length: 123\r\n
Content-Type: application/vscode-jsonrpc; charset=utf-8\r\n
\r\n
{"jsonrpc":"2.0","id":1,"method":"textDocument/completion","params":{...}}
```

- `Content-Length` — обязательный, размер content в байтах
- `Content-Type` — опциональный, по умолчанию `application/vscode-jsonrpc; charset=utf-8`

### 1.3. Error Codes

| Диапазон | Назначение |
|----------|-----------|
| `-32700` | Parse error (невалидный JSON) |
| `-32600` | Invalid Request |
| `-32601` | Method not found |
| `-32602` | Invalid params |
| `-32603` | Internal error |
| `-32800` | `RequestCancelled` — запрос отменён через `$/cancelRequest` |
| `-32801` | `ContentModified` — контент изменился, результат невалиден |
| `-32802` | `ServerCancelled` — сервер отменил запрос |
| `-32803` | `RequestFailed` — запрос не может быть выполнен |

### 1.4. Базовые типы данных

```typescript
// URI документа (string)
DocumentUri = "file:///path/to/file.env"

// Позиция в документе (0-based)
Position { line: uint, character: uint }

// Диапазон
Range { start: Position, end: Position }

// Расположение
Location { uri: DocumentUri, range: Range }

// LocationLink (расширенный)
LocationLink {
    originSelectionRange?: Range,   // исходный выделенный диапазон
    targetUri: DocumentUri,          // целевой файл
    targetRange: Range,              // полный диапазон цели
    targetSelectionRange: Range      // точный диапазон определения
}

// Текстовое изменение
TextEdit { range: Range, newText: string }

// Идентификатор документа
TextDocumentIdentifier { uri: DocumentUri }
TextDocumentItem { uri, languageId, version, text }

// Позиция в документе
TextDocumentPositionParams {
    textDocument: TextDocumentIdentifier,
    position: Position
}
```

## 2. Жизненный цикл

8 методов управления соединением между клиентом и сервером.

### 2.1. `initialize` — Инициализация

| Свойство | Значение |
|----------|----------|
| Тип | Request |
| Направление | Client → Server |
| Params | `InitializeParams` |
| Result | `InitializeResult` |

Первый запрос при подключении. Клиент и сервер обмениваются **capabilities** — списком поддерживаемых функций.

**InitializeParams (основные поля)**:
```typescript
{
    processId: number | null,        // PID клиента
    rootUri: DocumentUri | null,     // корень workspace
    capabilities: ClientCapabilities, // что умеет клиент
    workspaceFolders: WorkspaceFolder[] | null,
    initializationOptions?: any      // пользовательские опции
}
```

**InitializeResult**:
```typescript
{
    capabilities: ServerCapabilities, // что умеет сервер
    serverInfo?: { name: string, version?: string }
}
```

**Пример**:
```json
// Request
{
    "jsonrpc": "2.0",
    "id": 1,
    "method": "initialize",
    "params": {
        "processId": 12345,
        "rootUri": "file:///d%3A/project",
        "capabilities": {
            "textDocument": {
                "completion": { "completionItem": { "snippetSupport": true } },
                "hover": { "contentFormat": ["markdown", "plaintext"] },
                "publishDiagnostics": { "relatedInformation": true }
            }
        }
    }
}

// Response
{
    "jsonrpc": "2.0",
    "id": 1,
    "result": {
        "capabilities": {
            "completionProvider": { "triggerCharacters": ["=", "_"] },
            "hoverProvider": true,
            "textDocumentSync": 1,
            "diagnosticProvider": { "interFileDependencies": true }
        },
        "serverInfo": { "name": "pdf-framework-lsp", "version": "0.1.0" }
    }
}
```

### 2.2. `initialized` — Готовность

| Свойство | Значение |
|----------|----------|
| Тип | Notification |
| Направление | Client → Server |
| Params | `{}` (пустой объект) |

Клиент подтверждает получение результата `initialize`. После этого сервер может отправлять notifications.

### 2.3. `shutdown` — Подготовка к завершению

| Свойство | Значение |
|----------|----------|
| Тип | Request |
| Направление | Client → Server |
| Result | `null` |

Сервер освобождает ресурсы. После `shutdown` сервер отвечает на запросы ошибкой `InvalidRequest`.

### 2.4. `exit` — Завершение процесса

| Свойство | Значение |
|----------|----------|
| Тип | Notification |
| Направление | Client → Server |

Сервер завершает процесс. Exit code: `0` если `shutdown` был вызван, `1` если нет.

### 2.5. `$/cancelRequest` — Отмена запроса

| Свойство | Значение |
|----------|----------|
| Тип | Notification |
| Направление | Двусторонний |
| Params | `{ id: integer \| string }` |

Отменяет запрос по его `id`. Сервер отвечает ошибкой `RequestCancelled` (-32800).

### 2.6. `$/progress` — Отчёт о прогрессе

| Свойство | Значение |
|----------|----------|
| Тип | Notification |
| Направление | Двусторонний |
| Params | `{ token: ProgressToken, value: WorkDoneProgressBegin \| Report \| End }` |

```typescript
WorkDoneProgressBegin {
    kind: "begin",
    title: string,        // "Validating .env..."
    cancellable?: boolean,
    message?: string,
    percentage?: number   // 0-100
}
WorkDoneProgressReport {
    kind: "report",
    message?: string,     // "Checking dependencies..."
    percentage?: number
}
WorkDoneProgressEnd {
    kind: "end",
    message?: string      // "Validation complete: 3 errors"
}
```

### 2.7. `$/logTrace` — Трассировка

| Свойство | Значение |
|----------|----------|
| Тип | Notification |
| Направление | Server → Client |
| Params | `{ message: string, verbose?: string }` |

### 2.8. `$/setTrace` — Установка уровня трассировки

| Свойство | Значение |
|----------|----------|
| Тип | Notification |
| Направление | Client → Server |
| Params | `{ value: TraceValue }` |

`TraceValue`: `"off"` | `"messages"` | `"verbose"`

## 3. Синхронизация документов

10 методов для синхронизации содержимого документов между клиентом и сервером.

### 3.1. Текстовые документы

#### `textDocument/didOpen` — Документ открыт

| Тип | Notification | Client → Server |
|-----|-------------|-----------------|

```typescript
DidOpenTextDocumentParams {
    textDocument: TextDocumentItem {
        uri: DocumentUri,
        languageId: string,   // "env", "yaml", "json"
        version: integer,     // 0 при открытии
        text: string          // полное содержимое
    }
}
```

Сервер начинает отслеживать документ. Содержимое теперь в памяти, а не в файловой системе.

#### `textDocument/didChange` — Документ изменён

| Тип | Notification | Client → Server |
|-----|-------------|-----------------|

```typescript
DidChangeTextDocumentParams {
    textDocument: VersionedTextDocumentIdentifier { uri, version },
    contentChanges: TextDocumentContentChangeEvent[]
}
```

**Режимы синхронизации** (`TextDocumentSyncKind`):
| Значение | Режим | Описание |
|----------|-------|----------|
| 0 | None | Синхронизация отключена |
| 1 | Full | Клиент отправляет полный текст при каждом изменении |
| 2 | Incremental | Клиент отправляет только дельту изменений |

**Incremental change event**:
```json
{
    "range": { "start": {"line": 5, "character": 0}, "end": {"line": 5, "character": 15} },
    "text": "EMBEDDING__PROVIDER=voyage"
}
```

#### `textDocument/willSave` — Перед сохранением

| Тип | Notification | Client → Server |
|-----|-------------|-----------------|

```typescript
WillSaveTextDocumentParams {
    textDocument: TextDocumentIdentifier,
    reason: TextDocumentSaveReason  // 1=Manual, 2=AfterDelay, 3=FocusOut
}
```

#### `textDocument/willSaveWaitUntil` — Правки перед сохранением

| Тип | Request | Client → Server |
|-----|---------|-----------------|
| Result | `TextEdit[]` |

Сервер может вернуть правки, которые будут применены ДО сохранения (auto-format, auto-fix).

#### `textDocument/didSave` — Документ сохранён

| Тип | Notification | Client → Server |
|-----|-------------|-----------------|

```typescript
DidSaveTextDocumentParams {
    textDocument: TextDocumentIdentifier,
    text?: string  // полный текст (если includeText=true в capabilities)
}
```

#### `textDocument/didClose` — Документ закрыт

| Тип | Notification | Client → Server |
|-----|-------------|-----------------|

Документ больше не в памяти клиента. Содержимое актуально в файловой системе.

## 4. Навигация

6 методов для перемещения по коду.

### 4.1. `textDocument/declaration` — Перейти к объявлению

| Тип | Request | Client → Server |
|-----|---------|-----------------|
| Params | `DeclarationParams` (TextDocumentPositionParams) |
| Result | `Location \| Location[] \| LocationLink[] \| null` |

Объявление (declaration) — forward declaration. Отличается от definition для языков с раздельными объявлениями и определениями (C/C++ header vs implementation).

### 4.2. `textDocument/definition` — Перейти к определению

| Тип | Request | Client → Server |
|-----|---------|-----------------|
| Params | `DefinitionParams` (TextDocumentPositionParams) |
| Result | `Location \| Location[] \| LocationLink[] \| null` |

**Пример**: Ctrl+Click на `EMBEDDING__PROVIDER` → переход к `config/embedding.py:12`

```json
// Request
{
    "jsonrpc": "2.0", "id": 1,
    "method": "textDocument/definition",
    "params": {
        "textDocument": { "uri": "file:///project/.env" },
        "position": { "line": 10, "character": 5 }
    }
}

// Response
{
    "jsonrpc": "2.0", "id": 1,
    "result": {
        "uri": "file:///project/src/pdf_framework/config/embedding.py",
        "range": {
            "start": { "line": 11, "character": 4 },
            "end": { "line": 11, "character": 53 }
        }
    }
}
```

### 4.3. `textDocument/typeDefinition` — Перейти к определению типа

| Тип | Request | Client → Server |
|-----|---------|-----------------|
| Result | `Location \| Location[] \| LocationLink[] \| null` |

Переход к определению типа переменной (не самой переменной).

### 4.4. `textDocument/implementation` — Перейти к реализации

| Тип | Request | Client → Server |
|-----|---------|-----------------|

Переход от интерфейса/абстрактного класса к конкретной реализации.

### 4.5. `textDocument/references` — Найти все ссылки

| Тип | Request | Client → Server |
|-----|---------|-----------------|
| Params | `ReferenceParams` |
| Result | `Location[] \| null` |

```typescript
ReferenceParams {
    textDocument: TextDocumentIdentifier,
    position: Position,
    context: ReferenceContext { includeDeclaration: boolean }
}
```

**Пример**: Find References для `EMBEDDING__PROVIDER` → все файлы где используется `settings.embedding.provider`.

### 4.6. `textDocument/documentHighlight` — Подсветить вхождения

| Тип | Request | Client → Server |
|-----|---------|-----------------|
| Result | `DocumentHighlight[] \| null` |

```typescript
DocumentHighlight {
    range: Range,
    kind?: DocumentHighlightKind  // 1=Text, 2=Read, 3=Write
}
```

Подсвечивает все вхождения символа в текущем документе (без перехода в другие файлы).

```typescript
    tags?: DiagnosticTag[],
    relatedInformation?: DiagnosticRelatedInformation[],
    data?: any

```

**DiagnosticSeverity**:

| Значение | Название | Иконка | Описание |
|----------|----------|--------|----------|
| 1 | Error | 🔴 | Критическая ошибка |
| 2 | Warning | 🟡 | Предупреждение |
| 3 | Information | 🔵 | Информация |
| 4 | Hint | 💡 | Подсказка |

**DiagnosticTag**:

| Значение | Название | Визуал | Описание |
|----------|----------|--------|----------|
| 1 | Unnecessary | Затемнённый текст | Неиспользуемый код |
| 2 | Deprecated | ~~Зачёркнутый~~ | Устаревший код |

**Пример**:
```json

                "range": { "start": {"line": 12, "character": 0}, "end": {"line": 12, "character": 14} },
                "severity": 4,
                "code": "default-value",
```
