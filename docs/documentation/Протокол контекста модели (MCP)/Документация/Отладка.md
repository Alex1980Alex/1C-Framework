# Отладка

> Подробное руководство по отладке интеграций протокола контекста модели (MCP)

Эффективная отладка имеет важное значение при разработке серверов MCP или их интеграции с приложениями. В этом руководстве рассматриваются инструменты и подходы к отладке, доступные в экосистеме MCP.

<Информация>
  Это руководство предназначено для macOS. Руководства для других платформ появятся в ближайшее время.
</Info>

## Обзор инструментов отладки

MCP предоставляет несколько инструментов для отладки на разных уровнях:

1. **Инспектор MCP**
   * Интерактивный интерфейс отладки
   * Прямое тестирование сервера
   * Подробности см. в [руководстве по инспектору](/docs/tools/inspector).

2. **Инструменты разработчика Claude Desktop**
   * Интеграционное тестирование
   * Сбор бревен
   * Интеграция с инструментами разработчика Chrome

3. **Ведение журналов сервера**
   * Пользовательские реализации логирования
   * Отслеживание ошибок
   * Мониторинг производительности

### Просмотр журналов

Просмотрите подробные журналы MCP из Claude Desktop:

```bash theme={null}
# Отслеживание логов в режиме реального времени
tail -n 20 -F ~/Library/Logs/Claude/mcp*.log
```

В логах зафиксировано:

* События подключения к серверу
* Проблемы с конфигурацией
* Ошибки во время выполнения
* Обмен сообщениями

### Использование инструментов разработчика Chrome

Воспользуйтесь инструментами разработчика Chrome в Claude Desktop, чтобы исследовать ошибки на стороне клиента:

1. Создайте файл `developer_settings.json`, установив для параметра `allowDevTools` значение true:

```bash theme={null}
echo '{"allowDevTools": true}' > ~/Library/Application\ Support/Claude/developer_settings.json
```

2. Откройте инструменты разработчика: `Command-Option-Shift-i`

Примечание: Вы увидите два окна инструментов разработчика:

* Главное окно содержимого
* Окно заголовка приложения

Используйте панель «Консоль» для проверки ошибок на стороне клиента.

Для проверки используйте панель «Сеть»:

* Содержимое сообщений
* Время подключения

## Распространенные проблемы

### Рабочий каталог

При использовании серверов MCP с Claude Desktop:

* Рабочий каталог для серверов, запускаемых через `claude_desktop_config.json`, может быть неопределенным (например, `/` в macOS), поскольку Claude Desktop можно запустить из любого места.
* Для обеспечения надежной работы всегда используйте абсолютные пути в файлах конфигурации и `.env`.
* Для тестирования серверов непосредственно через командную строку рабочий каталог будет соответствовать тому, куда вы запускаете команду.

Например, в файле `claude_desktop_config.json` используйте:

```json theme={null}
{
  "команда": "npx",
  "args": [
    "-y",
    "@modelcontextprotocol/server-filesystem",
    "/Users/username/data"
  ]
}
```

Вместо относительных путей, таких как `./data`

### Переменные среды

Серверы MCP автоматически наследуют лишь часть переменных окружения, таких как `USER`, `HOME` и `PATH`.

Чтобы переопределить переменные по умолчанию или указать свои собственные, вы можете указать ключ `env` в файле `claude_desktop_config.json`:

```json theme={null}
{
  "мой сервер": {
    "команда": "mcp-server-myapp",
    "env": {
      "MYAPP_API_KEY": "some_key"
    }
  }
}
```

### Инициализация сервера

Распространенные проблемы инициализации:

1. **Проблемы с маршрутизацией**
   * Неверный путь к исполняемому файлу сервера
   * Отсутствуют необходимые файлы
   * Проблемы с правами доступа
   * Попробуйте использовать абсолютный путь для `command`

2. **Ошибки конфигурации**
   * Недопустимый синтаксис JSON
   * Отсутствуют обязательные поля
   * Несоответствия типов

3. **Экологические проблемы**
   * Отсутствуют переменные среды
   * Неверные значения переменных
   * Ограничения доступа

### Проблемы с подключением

Когда серверы не могут подключиться:

1. Проверьте журналы Claude Desktop.
2. Убедитесь, что серверный процесс запущен.
3. Протестируйте автономно с помощью [Инспектора](/docs/tools/inspector)
4. Проверьте совместимость протокола.

## Реализация логирования

### Ведение журналов на стороне сервера

При создании сервера, использующего локальный stdio [транспорт](/legacy/concepts/transports), все сообщения, записываемые в stderr (стандартный поток ошибок), будут автоматически перехватываться хост-приложением (например, Claude Desktop).

<Предупреждение>
  Локальные MCP-серверы не должны выводить сообщения в стандартный поток вывода (stdout), так как это будет мешать работе протокола.
</Предупреждение>

Для всех [транспортных систем](/legacy/concepts/transports) вы также можете предоставлять клиенту возможность вести логирование, отправляя уведомление в виде лог-сообщения:

<CodeGroup>
  ```python Python theme={null}
  server.request_context.session.send_log_message(
    level="info",
    data="Сервер успешно запущен",
  )
  ```

  ```typescript TypeScript theme={null}
  server.sendLoggingMessage({
    уровень: "информация",
    данные: "Сервер успешно запущен",
  });
  ```
</CodeGroup>

Важные события для регистрации:

* Этапы инициализации
* Доступ к ресурсам
* Выполнение инструмента
* Условия возникновения ошибок
* Показатели производительности

### Логирование на стороне клиента

В клиентских приложениях:

1. Включите отладочное логирование.
2. Мониторинг сетевого трафика
3. Отслеживание обмена сообщениями.
4. Состояния ошибок записи

## Процесс отладки

### Цикл разработки

1. Начальная разработка
   * Используйте [Инспектор](/legacy/tools/inspector) для базового тестирования
   * Реализовать основную функциональность
   * Добавить точки регистрации

2. Интеграционное тестирование
   * Тестирование в Claude Desktop
   * Журналы мониторинга
   * Проверка обработки ошибок

### Изменения в тестировании

Для эффективного тестирования изменений:

* **Изменения конфигурации**: Перезапустите рабочий стол Клода.
* **Изменения в коде сервера**: Используйте Command-R для перезагрузки.
* **Быстрая итерация**: Используйте [Инспектор](/legacy/tools/inspector) во время разработки

## Передовые методы

### Стратегия ведения журнала

1. **Структурированная регистрация данных**
   * Используйте единообразные форматы

   * Добавить временные метки
   * Отслеживание идентификаторов запросов

2. **Обработка ошибок**
   * Запись трассировки стека
   * Включить контекст ошибки
   * Отслеживание шаблонов ошибок
   * Мониторинг восстановления

3. **Отслеживание производительности**
   * Время выполнения операции регистрации
   * Мониторинг использования ресурсов
   * Отслеживание размеров сообщений
   * Измерение задержки

### Вопросы безопасности

При отладке:

1. **Конфиденциальные данные**
   * Очистка журналов

   * Скрыть личную информацию

2. **Контроль доступа**
   * Проверьте права доступа
   * Проверка подлинности
   * Мониторинг шаблонов доступа
