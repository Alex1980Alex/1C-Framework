# Понимание работы серверов MCP

Серверы MCP — это программы, которые предоставляют приложениям искусственного интеллекта доступ к определенным возможностям через стандартизированные протокольные интерфейсы.

В качестве распространенных примеров можно привести файловые серверы для доступа к документам, серверы баз данных для запросов к данным, серверы GitHub для управления кодом, серверы Slack для командного общения и календарные серверы для планирования.

## Основные функции сервера

Серверы обеспечивают функциональность посредством трех основных компонентов:

| Функция         | Объяснение                                                                                                                                                                                                                              | Примеры                                                                               | Кто контролирует это |
| --------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------- | -------------------- |
| **Инструменты** | Функции, которые ваш LLM может активно вызывать и решать, когда их использовать, на основе запросов пользователей. Инструменты могут записывать данные в базы данных, вызывать внешние API, изменять файлы или запускать другую логику. | Поиск рейсов<br />Отправка сообщений<br />Создание событий календаря                  | Модель               |
| **Ресурсы**     | Пассивные источники данных, предоставляющие доступ только для чтения к информации для контекста, такой как содержимое файлов, схемы баз данных или документация API.                                                                    | Получение документов<br />Доступ к базам знаний<br />Чтение календарей                | Приложение           |
| **Подсказки**   | Готовые шаблоны инструкций, указывающие модели, как работать с конкретными инструментами и ресурсами.                                                                                                                                   | Спланировать отпуск<br />Подвести итоги моих встреч<br />Составить электронное письмо | Пользователь         |

Мы используем гипотетический сценарий, чтобы продемонстрировать роль каждой из этих функций и показать, как они могут взаимодействовать друг с другом.

### Инструменты

Инструменты позволяют моделям ИИ выполнять действия. Каждый инструмент определяет конкретную операцию с типизированными входными и выходными данными. Модель запрашивает выполнение инструмента в зависимости от контекста.

#### Как работают инструменты

Инструменты представляют собой интерфейсы, определенные в схеме, которые могут вызывать LLM-модели. MCP использует JSON Schema для проверки. Каждый инструмент выполняет одну операцию с четко определенными входными и выходными данными. Инструменты могут требовать согласия пользователя перед выполнением, что помогает гарантировать, что пользователи сохраняют контроль над действиями, выполняемыми моделью.

**Операции по протоколу:**

| Метод        | Назначение                      | Возвраты                                   |
| ------------ | ------------------------------- | ------------------------------------------ |
| `tools/list` | Найти доступные инструменты     | Массив определений инструментов со схемами |
| `tools/call` | Выполнить конкретный инструмент | Результат выполнения инструмента           |

**Пример определения инструмента:**

```typescript theme={null}
{
  имя: "searchFlights",
  описание: "Поиск доступных рейсов",
  inputSchema: {
    тип: "объект",
    характеристики: {
      origin: { type: "string", description: "Город отправления" },
      destination: { type: "string", description: "Город прибытия" },
      дата: { тип: "строка", формат: "дата", описание: "Дата поездки" }
    },
    обязательный параметр: ["origin", "destination", "date"]
  }
}
```

#### Пример: Бронирование поездки

Инструменты позволяют приложениям на основе ИИ выполнять действия от имени пользователей. В сценарии планирования поездки приложение на основе ИИ может использовать несколько инструментов, чтобы помочь забронировать отпуск:

**Поиск рейсов**

```
searchFlights(origin: "NYC", destination: "Barcelona", date: "2024-06-15")
```

Выполняет запрос к нескольким авиакомпаниям и возвращает структурированные варианты перелетов.

**Блокировка календаря**

```
createCalendarEvent(title: "Поездка в Барселону", startDate: "15.06.2024", endDate: "22.06.2024")
```

Отмечает даты поездки в календаре пользователя.

**Уведомление по электронной почте**

```
sendEmail(to: "team@work.com", subject: "Out of Office", body: "...")
```

Отправляет коллегам автоматическое сообщение об отсутствии на рабочем месте.

#### Модель взаимодействия с пользователем

Инструменты управляются моделями, то есть модели ИИ могут обнаруживать и вызывать их автоматически. Однако MCP делает упор на человеческий контроль посредством нескольких механизмов.

В целях обеспечения доверия и безопасности приложения могут реализовывать пользовательский контроль с помощью различных механизмов, таких как:

* Отображение доступных инструментов в пользовательском интерфейсе, позволяющее пользователям определять, должен ли тот или иной инструмент быть доступен в конкретных взаимодействиях.
* Диалоги подтверждения для выполнения отдельных инструментов
* Настройки разрешений для предварительного одобрения определенных безопасных операций
* Журналы активности, отображающие все выполнения инструментов с указанием результатов.

### Ресурсы

Ресурсы обеспечивают структурированный доступ к информации, которую приложение искусственного интеллекта может получать и предоставлять моделям в качестве контекста.

#### Как работают ресурсы

Ресурсы предоставляют доступ к данным из файлов, API, баз данных или любых других источников, необходимых ИИ для понимания контекста. Приложения могут получать доступ к этой информации напрямую и решать, как ее использовать — будь то выбор релевантных фрагментов, поиск с использованием эмбеддингов или передача всей информации модели.

Каждый ресурс имеет уникальный URI (например, `file:///path/to/document.md`) и указывает свой MIME-тип для соответствующей обработки содержимого.

Ресурсы поддерживают два типа поиска:

* **Прямые ресурсы** — фиксированные URI, указывающие на конкретные данные. Пример: `calendar://events/2024` — возвращает информацию о доступности календаря на 2024 год.
* **Шаблоны ресурсов** — динамические URI с параметрами для гибких запросов. Пример:
  * `travel://activities/{city}/{category}` - возвращает информацию о мероприятиях по городу и категории.
  * `travel://activities/barcelona/museums` - выводит список всех музеев Барселоны

Шаблоны ресурсов содержат метаданные, такие как заголовок, описание и ожидаемый MIME-тип, что делает их легкодоступными и самодокументируемыми.

**Операции по протоколу:**

| Метод                      | Назначение                       | Возвраты                             |
| -------------------------- | -------------------------------- | ------------------------------------ |
| `resources/list`           | Список доступных прямых ресурсов | Массив дескрипторов ресурсов         |
| `resources/templates/list` | Найти шаблоны ресурсов           | Массив определений шаблонов ресурсов |
| `resources/read`           | Получение содержимого ресурса    | Данные ресурса с метаданными         |
| `resources/subscribe`      | Отслеживание изменений ресурсов  | Подтверждение подписки               |

#### Пример: Получение контекста планирования поездки

Продолжая пример с планированием поездки, следует отметить, что ресурсы предоставляют приложению искусственного интеллекта доступ к соответствующей информации:

* **Данные календаря** (`calendar://events/2024`) - Проверяет доступность пользователя
* **Проездные документы** (`file:///Documents/Travel/passport.pdf`) - Доступ к важным документам
* **Предыдущие маршруты** (`trips://history/barcelona-2023`) - Ссылки на прошлые поездки и предпочтения

Приложение искусственного интеллекта извлекает эти ресурсы и решает, как их обрабатывать: выбирает ли подмножество данных с помощью эмбеддингов или поиска по ключевым словам, или передает необработанные данные непосредственно модели.

В данном случае, она предоставляет модели календарные данные, информацию о погоде и предпочтения в поездках, позволяя ей проверять наличие мест, анализировать погодные условия и учитывать прошлые предпочтения в поездках.

**Примеры шаблонов ресурсов:**

```json theme={null}
{
  "uriTemplate": "weather://forecast/{city}/{date}",
  "name": "weather-forecast",
  «Заголовок»: «Прогноз погоды»,
  "Описание": "Получите прогноз погоды для любого города и даты",
  "mimeType": "application/json"
}

{
  "uriTemplate": "travel://flights/{origin}/{destination}",
  "name": "flight-search",
  «Заголовок»: «Поиск рейса»,
  "Описание": "Поиск доступных рейсов между городами",
  "mimeType": "application/json"
}
```

Эти шаблоны обеспечивают гибкость запросов. Для получения данных о погоде пользователи могут получить доступ к прогнозам для любой комбинации города и даты. Для поиска рейсов они могут искать маршруты между любыми двумя аэропортами. Если пользователь ввел «NYC» в качестве аэропорта отправления и начинает вводить «Bar» в качестве аэропорта назначения, система может предложить «Барселона (BCN)» или «Барбадос (BGI)».

#### Автодополнение параметров

Динамические ресурсы поддерживают автодополнение параметров. Например:

* При вводе "Par" в качестве параметра для `weather://forecast/{city}` может отобразиться "Paris" или "Park City".
* При вводе "JFK" в запросе `flights://search/{airport}` может появиться запрос "JFK - Международный аэропорт имени Джона Ф. Кеннеди".

Система помогает обнаруживать допустимые значения, не требуя точного знания формата.

#### Модель взаимодействия с пользователем

Ресурсы ориентированы на конкретное приложение, что обеспечивает им гибкость в способах получения, обработки и представления доступного контекста. Типичные модели взаимодействия включают:

* Древовидное или списочное представление для просмотра ресурсов в привычных папочных структурах.
* Интерфейсы поиска и фильтрации для нахождения конкретных ресурсов
* Автоматическое включение контекста или интеллектуальные подсказки на основе эвристических методов или выбора с помощью ИИ.
* Интерфейсы ручного или пакетного выбора для включения отдельных или нескольких ресурсов.

Приложения могут реализовать поиск ресурсов с помощью любого интерфейса, соответствующего их потребностям. Протокол не предписывает использование конкретных шаблонов пользовательского интерфейса, что позволяет создавать средства выбора ресурсов с возможностью предварительного просмотра, интеллектуальные подсказки на основе текущего контекста разговора, осуществлять массовый выбор нескольких ресурсов, а также интегрироваться с существующими файловыми браузерами и средствами просмотра данных.

### Подсказки

Подсказки предоставляют многократно используемые шаблоны. Они позволяют разработчикам MCP-серверов создавать параметризованные подсказки для домена или демонстрировать наилучшие способы использования MCP-сервера.

#### Как работают подсказки

Подсказки представляют собой структурированные шаблоны, определяющие ожидаемые входные данные и схемы взаимодействия. Они управляются пользователем и требуют явного вызова, а не автоматического запуска. Подсказки могут учитывать контекст, ссылаясь на доступные ресурсы и инструменты для создания комплексных рабочих процессов. Подобно ресурсам, подсказки поддерживают автодополнение параметров, помогая пользователям находить допустимые значения аргументов.

**Операции по протоколу:**

| Метод          | Назначение                     | Возвраты                                   |
| -------------- | ------------------------------ | ------------------------------------------ |
| `prompts/list` | Найти доступные подсказки      | Массив описаний подсказок                  |
| `prompts/get`  | Получение сведений о подсказке | Полное определение подсказки с аргументами |

#### Пример: Оптимизированные рабочие процессы

Подсказки предоставляют структурированные шаблоны для выполнения типовых задач. В контексте планирования поездок:

**Задание для "Планирования отпуска":**

```json theme={null}
{
  "имя": "план-отпуск",
  «Заголовок»: «Спланируйте отпуск»,
  «Описание»: «Руководство по планированию отпуска».
  "аргументы": [
    { "name": "destination", "type": "string", "required": true },
    { "name": "duration", "type": "number", "description": "days" },
    { "name": "budget", "type": "number", "required": false },
    { "name": "interests", "type": "array", "items": { "type": "string" } }
  ]
}
```

Вместо неструктурированного ввода естественного языка система подсказок позволяет:

1. Выбор шаблона «Планирование отпуска».
2. Структурированный ввод: Барселона, 7 дней, 3000 долларов, ["пляжи", "архитектура", "еда"]
3. Последовательное выполнение рабочего процесса на основе шаблона.

#### Модель взаимодействия с пользователем

Запросы управляются пользователем и требуют явного вызова. Протокол предоставляет разработчикам свободу в проектировании интерфейсов, которые органично вписываются в их приложение. Ключевые принципы включают:

* Легкий поиск доступных подсказок
* Четкое описание того, что делает каждый запрос.
* Естественный ввод аргументов с проверкой
* Прозрачное отображение базового шаблона запроса

Приложения обычно отображают подсказки с помощью различных элементов пользовательского интерфейса, таких как:

* Команды со слэшем (наберите "/", чтобы увидеть доступные подсказки, например, /plan-vacation)
* Палитры команд для поиска
* Специальные кнопки пользовательского интерфейса для часто используемых подсказок
* Контекстные меню, предлагающие соответствующие подсказки.

## Объединение серверов

Реальная мощь MCP проявляется, когда несколько серверов работают вместе, объединяя свои специализированные возможности через единый интерфейс.

### Пример: Многосерверное планирование поездок

Рассмотрим персонализированное приложение для планирования путешествий на основе искусственного интеллекта, использующее три подключенных сервера:

* **Служба бронирования поездок** - занимается бронированием авиабилетов, отелей и составлением маршрутов.
* **Сервер погоды** - Предоставляет климатические данные и прогнозы.
* **Сервер календаря/почты** - Управляет расписаниями и коммуникациями.

#### Полный поток

1. **Пользователь отправляет приглашение ввода с параметрами:**

   ```json theme={null}
   {
     "prompt": "plan-vacation",
     "аргументы": {
       "пункт назначения": "Барселона",
       "departure_date": "2024-06-15",
       "return_date": "2024-06-22",
       "бюджет": 3000,
       "путешественники": 2
     }
   }
   ```

2. **Пользователь выбирает ресурсы для включения:**
   * `calendar://my-calendar/June-2024` (с календарного сервера)
   * `travel://preferences/europe` (из Travel Server)
   * `travel://past-trips/Spain-2023` (с Travel Server)

3. **Искусственный интеллект обрабатывает запрос с помощью инструментов:**

   Сначала ИИ анализирует все выбранные ресурсы, чтобы собрать контекст: определяет доступные даты в календаре, изучает предпочтительные авиакомпании и типы отелей на основе туристических предпочтений, а также обнаруживает места, которые ранее посещались в ходе предыдущих поездок.

   Используя этот контекст, ИИ затем выполняет ряд действий:

   * `searchFlights()` — Запрашивает у авиакомпаний рейсы из Нью-Йорка в Барселону.
   * `checkWeather()` — Получает прогноз погоды на даты поездок.

   Затем ИИ использует эту информацию для создания бронирования и последующих шагов, запрашивая подтверждение у пользователя, если это необходимо:

   * `bookHotel()` — Находит отели в пределах указанного бюджета.
   * `createCalendarEvent()` — Добавляет поездку в календарь пользователя.
   * `sendEmail()` - Отправляет подтверждение с подробной информацией о поездке

**Результат:** Используя несколько серверов MCP, пользователь нашел и забронировал поездку в Барселону, соответствующую его расписанию. Подсказка «Спланировать отпуск» помогла ИИ объединить ресурсы (доступность календаря и историю поездок) с инструментами (поиск авиабилетов, бронирование отелей, обновление календарей) на разных серверах — собирая контекст и выполняя бронирование. Задача, которая могла бы занять часы, была выполнена за минуты с помощью MCP.
