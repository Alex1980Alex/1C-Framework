## Возможности

Серверы, отправляющие уведомления в виде лог-сообщений, **ОБЯЗАТЕЛЬНО** должны объявить о наличии возможности `logging`:

```json theme={null}
{
  "возможности": {
    "logging": {}
  }
}
```

## Уровни логарифма

Протокол соответствует стандартным уровням серьезности syslog, указанным в
[RFC 5424](https://datatracker.ietf.org/doc/html/rfc5424#section-6.2.1):

| Уровень            | Описание                           | Пример использования             |
| ------------------ | ---------------------------------- | -------------------------------- |
| отладка            | Подробная отладочная информация    | Точки входа/выхода из функций    |
| информация         | Общие информационные сообщения     | Обновления о ходе операции       |
| уведомление        | Обычные, но важные события         | Изменения конфигурации           |
| предупреждение     | Условия предупреждения             | Использование устаревших функций |
| ошибка             | Условия ошибки                     | Сбои в работе                    |
| критические        | Критические условия                | Отказы компонентов системы       |
| Предупреждение     | Необходимо немедленно принять меры | Обнаружено повреждение данных    |
| Аварийная ситуация | Система неработоспособна           | Полный отказ системы             |

## Протокольные сообщения

### Настройка уровня логирования

Для настройки минимального уровня логирования клиенты **МОГУТ** отправить запрос `logging/setLevel`:

**Запрос:**

```json theme={null}
{
  "jsonrpc": "2.0",
  "id": 1,
  "метод": "logging/setLevel",
  "параметры": {
    "уровень": "информация"
  }
}
```

### Уведомления о сообщениях в журнале

Серверы отправляют сообщения в журнал с помощью уведомлений `notifications/message`:

```json theme={null}
{
  "jsonrpc": "2.0",
  "метод": "уведомления/сообщение",
  "параметры": {
    "уровень": "ошибка",
    "logger": "database",
    "данные": {
      "ошибка": "Сбой подключения",
      "подробности": {
        "host": "localhost",
        "порт": 5432
      }
    }
  }
}
```

    Примечание по серверу: отправляются только сообщения об ошибках уровня <br/> и выше.

## Обработка ошибок

Серверы **ДОЛЖНЫ** возвращать стандартные ошибки JSON-RPC в типичных случаях сбоев:

* Недопустимый уровень логирования: `-32602` (Недопустимые параметры)
* Ошибки конфигурации: `-32603` (Внутренняя ошибка)

## Вопросы реализации

1. Серверы **ДОЛЖНЫ**:
   * Сообщения журнала об ограничении скорости
   * Включите соответствующий контекст в поле данных.
   * Используйте согласованные имена регистраторов.
   * Удалите конфиденциальную информацию

2. Клиенты **МОГУТ**:
   * Отображение сообщений журнала в пользовательском интерфейсе
   * Реализовать фильтрацию/поиск в логах
   * Визуальное отображение степени тяжести
   * Сохранять сообщения журнала

## Безопасность

1. Сообщения журнала **НЕ ДОЛЖНЫ** содержать:
   * Учетные данные или секреты
   * Персональные идентификационные данные
   * Внутренние системные детали, которые могут способствовать атакам

2. Реализация **ДОЛЖНА**:
   * Сообщения об ограничении скорости
   * Проверить все поля данных
   * Управление доступом к журналам
   * Отслеживайте наличие контента, представляющего личный интерес
