# Пинг

<div id="enable-section-numbers" />

<Информация>**Ревизия протокола**: 2025-11-25</Информация>

Протокол контекста модели включает в себя дополнительный механизм проверки доступности (ping), позволяющий любой из сторон
чтобы убедиться, что их контрагент по-прежнему отвечает и соединение активно.

## Обзор

Функция пинга реализована с помощью простой схемы запрос/ответ. Либо
Клиент или сервер могут инициировать пинг, отправив запрос `ping`.

## Формат сообщения

Запрос ping — это стандартный JSON-RPC запрос без параметров:

```json theme={null}
{
  "jsonrpc": "2.0",
  "id": "123",
  "метод": "пинг"
}
```

## Требования к поведению

1. Получатель **ОБЯЗАН** незамедлительно ответить пустым сообщением:

```json theme={null}
{
  "jsonrpc": "2.0",
  "id": "123",
  "результат": {}
}
```

2. Если в течение разумного периода времени не получен ответ, отправитель **МОЖЕТ**:
   * Считайте соединение устаревшим
   * Разорвать соединение
   * Попробуйте выполнить процедуры повторного подключения

## Шаблоны использования

```тема русалки={null}
диаграмма последовательности
    участник Отправитель
    участник Получатель

    Отправитель->>Получатель: запрос ping
    Получатель->>Отправитель: пустой ответ
```

## Вопросы реализации

* Реализации **ДОЛЖНЫ** периодически отправлять пинги для проверки состояния соединения.
* Частота пингов **ДОЛЖНА** быть настраиваемой.
* Время ожидания **ДОЛЖНО** соответствовать сетевой среде.
* Следует избегать чрезмерного количества пингов, чтобы снизить нагрузку на сеть.

## Обработка ошибок

* Тайм-ауты **СЛЕДУЕТ** рассматривать как сбои соединения.
* Многократные неудачные попытки пинга **МОГУТ** привести к сбросу соединения.
* Реализации **ДОЛЖНЫ** регистрировать сбои ping для диагностики.
