# Прогресс

<div id="enable-section-numbers" />

<Информация>**Ревизия протокола**: 2025-11-25</Информация>

Протокол контекста модели (MCP) поддерживает опциональное отслеживание прогресса для длительных процессов.
Операции осуществляются посредством уведомлений. Любая из сторон может отправлять уведомления о ходе выполнения.
Предоставлять обновления о состоянии работы.

## Ход выполнения

Когда сторона хочет *получать* обновления о ходе выполнения запроса, она включает в него следующее:
`progressToken` в метаданных запроса.

* Токены прогресса **ОБЯЗАТЕЛЬНО** должны быть строковым или целочисленным значением.
* Отправитель может выбрать токены прогресса любым способом, но они **ОБЯЗАТЕЛЬНО** должны быть уникальными.
  по всем активным запросам.

```json theme={null}
{
  "jsonrpc": "2.0",
  "id": 1,
  "метод": "некоторый_метод",
  "параметры": {
    "_мета": {
      "progressToken": "abc123"
    }
  }
}
```

Получатель **МОЖЕТ** затем отправлять уведомления о ходе выполнения, содержащие:

* Оригинальный токен прогресса
* Текущее значение прогресса на данный момент
* Необязательное значение "итого"
* Необязательное значение "сообщения"

```json theme={null}
{
  "jsonrpc": "2.0",
  "метод": "уведомления/прогресс",
  "параметры": {
    "progressToken": "abc123",
    "прогресс": 50,
    "Итого": 100,
    "сообщение": "Сетчатые сплайны..."
  }
}
```

* Значение `progress` **ОБЯЗАТЕЛЬНО** должно увеличиваться с каждым уведомлением, даже если общее значение равно
  неизвестный.
* Значения `progress` и `total` **МОГУТ** быть числами с плавающей запятой.
* Поле `message` **ДОЛЖНО** содержать удобочитаемую информацию о ходе выполнения.

## Требования к поведению

1. Уведомления о ходе выполнения **ОБЯЗАТЕЛЬНО** должны ссылаться только на токены, которые:
   * Были предоставлены в рамках активного запроса
   * Связаны с текущей операцией

2. Получатели запросов о ходе выполнения **МОЖЕТ**:
   * Выберите вариант не отправлять уведомления о ходе выполнения.
   * Отправлять уведомления с той частотой, которую они сочтут целесообразной.
   * Если общая сумма неизвестна, ее следует опустить.

3. Для запросов с расширением задачи (./tasks) предоставленный в исходном запросе `progressToken` **ДОЛЖЕН** продолжать использоваться для уведомлений о ходе выполнения задачи на протяжении всего ее жизненного цикла, даже после того, как `CreateTaskResult` будет возвращен. Токен прогресса остается действительным и связанным с задачей до тех пор, пока задача не достигнет конечного состояния.
   * Для уведомлений о ходе выполнения задач **ОБЯЗАТЕЛЬНО** следует использовать тот же `progressToken`, который был предоставлен в первоначальном запросе на добавление данных к задаче.
   * Уведомления о ходе выполнения задач **ДОЛЖНЫ** прекращаться после того, как задача достигнет конечного состояния («завершено», «неудачно» или «отменено»).

```тема русалки={null}
диаграмма последовательности
    участник Отправитель
    участник Получатель

    Примечание к отправителю и получателю: Запрос с токеном прогресса.
    Отправитель->>Получатель: Запрос метода с использованием progressToken

    Примечание к отправителю и получателю: обновления о ходе выполнения.
    Получатель --> Отправитель: Уведомление о ходе выполнения (0.2/1.0)
    Получатель --> Отправитель: Уведомление о ходе выполнения (0.6/1.0)
    Получатель --> Отправитель: Уведомление о ходе выполнения (1.0/1.0)

    Примечание для отправителя и получателя: Операция завершена.
    Получатель->>Отправитель: Ответ метода
```

## Примечания по реализации

* Отправители и получатели **ДОЛЖНЫ** отслеживать активные токены прогресса
* Обе стороны **должны** ввести ограничение скорости запросов, чтобы предотвратить перегрузку сети.
* Уведомления о ходе выполнения **ОБЯЗАТЕЛЬНО** должны прекратиться после завершения.
