## Обзор

MCP предоставляет стандартизированный способ для приложений:

* Передавайте контекстную информацию языковым моделям.
* Предоставить доступ к инструментам и возможностям системам искусственного интеллекта.
* Создавайте компонуемые интеграции и рабочие процессы.

Протокол использует сообщения [JSON-RPC](https://www.jsonrpc.org/) 2.0 для установления соединения.
коммуникация между:

* **Хосты**: приложения LLM, инициирующие соединения
* **Клиенты**: Коннекторы внутри основного приложения
* **Серверы**: Сервисы, предоставляющие контекст и возможности.

MCP черпает вдохновение из
[Протокол языкового сервера](https://microsoft.github.io/language-server-protocol/), который
стандартизирует порядок добавления поддержки языков программирования во всей экосистеме.
инструменты разработки. Аналогичным образом, MCP стандартизирует способы интеграции дополнительного контекста.
и инструментов в экосистеме приложений искусственного интеллекта.

## Ключевые детали

### Базовый протокол

* Формат сообщения [JSON-RPC](https://www.jsonrpc.org/)
* Соединения с сохранением состояния
* Согласование возможностей сервера и клиента

### Функции

Серверы предоставляют клиентам любую из следующих функций:

* **Ресурсы**: Контекст и данные для использования пользователем или моделью ИИ.
* **Подсказки**: Шаблонные сообщения и рабочие процессы для пользователей
* **Инструменты**: Функции, которые должна выполнять модель ИИ.

Клиенты могут предлагать серверам следующие функции:

* **Выборка**: Инициируемые сервером действия агентов и рекурсивные взаимодействия LLM
* **Корневые каталоги**: Запросы, инициированные сервером, к границам URI или файловой системы для работы в
* **Запрос информации**: Инициированные сервером запросы дополнительной информации от пользователей.

### Дополнительные утилиты

* Конфигурация
* Отслеживание прогресса
* Отмена
* Сообщение об ошибках
* Ведение журнала

## Безопасность и доверие

Протокол контекста модели обеспечивает широкие возможности благодаря произвольному доступу к данным.
и пути выполнения кода. Эта возможность обеспечивает важную безопасность и доверие.
факторы, которые все разработчики должны тщательно учитывать.

### Ключевые принципы

1. **Согласие пользователя и контроль**
   * Пользователи должны явно дать согласие на весь доступ к данным и понимать все операции, связанные с ними.
   * Пользователи должны сохранять контроль над тем, какие данные передаются и какие действия предпринимаются.
   * Разработчики должны предоставлять понятные пользовательские интерфейсы для проверки и авторизации действий.

2. **Защита данных**
   * Хостинговые компании должны получить явное согласие пользователя, прежде чем передавать его данные на серверы.
   * Хосты не должны передавать данные ресурсов в другие места без согласия пользователя.
   * Данные пользователей должны быть защищены с помощью соответствующих средств контроля доступа.

3. **Безопасность при работе с инструментом**
   * Инструменты обеспечивают выполнение произвольного кода и должны обрабатываться соответствующим образом.
     осторожность.
     * В частности, описания поведения инструмента, такие как аннотации, должны быть
       Считается ненадежной информацией, если она не получена с надежного сервера.
   * Хостинг-провайдеры должны получить явное согласие пользователя перед использованием любого инструмента.
   * Перед тем как разрешить использование каждого инструмента, пользователи должны понимать, для чего он предназначен.

4. **Контрольные образцы LLM**
   * Пользователи должны явно одобрить любые запросы на отбор образцов LLM.
   * Пользователи должны контролировать:
     * Проводится ли вообще отбор проб
     * Фактическое сообщение, которое будет отправлено
     * Какие результаты может увидеть сервер
   * Протокол намеренно ограничивает видимость сервером подсказок.

### Руководство по внедрению

Хотя сам MCP не может обеспечить соблюдение этих принципов безопасности на уровне протокола,
Разработчикам следует:

1. Внедрить в их приложения надежные механизмы получения согласия и авторизации.
2. Предоставьте четкую документацию, описывающую последствия для безопасности.
3. Внедрить соответствующие средства контроля доступа и защиты данных.
4. При интеграции следуйте передовым методам обеспечения безопасности.
5. При разработке функций учитывайте вопросы конфиденциальности.
