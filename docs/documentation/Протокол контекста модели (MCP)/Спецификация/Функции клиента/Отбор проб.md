# Выборка

<div id="enable-section-numbers" />

<Информация>**Ревизия протокола**: 2025-11-25</Информация>

Протокол контекста модели (MCP) предоставляет стандартизированный способ запроса LLM серверами.
Выборка («завершение» или «поколение») из языковых моделей через клиентов. Этот процесс
позволяет клиентам сохранять контроль над доступом к модели, ее выбором и правами доступа, в то время как
Это позволяет серверам использовать возможности искусственного интеллекта без необходимости использования API-ключей сервера.
Серверы могут запрашивать взаимодействие на основе текста, аудио или изображений, а также, при необходимости, включать в него другие элементы.
Контекст поступает с серверов MCP в их подсказках.

## Модель взаимодействия с пользователем

Функция выборки в MCP позволяет серверам реализовывать агентное поведение, обеспечивая возможность вызова LLM для
происходят *вложенными* внутри других функций сервера MCP.

Реализации могут предоставлять возможность выборки данных через любой подходящий для них интерфейс.
их потребности — сам протокол не предписывает какого-либо конкретного взаимодействия с пользователем.
модель.

<Предупреждение>
  Для обеспечения доверия, безопасности и защищенности **ДОЛЖНО** всегда
  быть человеком, участвующим в процессе, и иметь возможность отклонять запросы на отбор проб.

  Приложения **должны**:

  * Предоставить пользовательский интерфейс, который упростит и сделает более интуитивно понятным просмотр запросов на отбор проб.
  * Предоставьте пользователям возможность просматривать и редактировать подсказки перед отправкой.
  * Предоставьте сгенерированные ответы для проверки перед отправкой.
</Предупреждение>

## Инструменты выборки

Серверы могут запрашивать у LLM клиента использование инструментов во время выборки, предоставляя массив `tools` и необязательную конфигурацию `toolChoice` в своих запросах на выборку. Это позволяет серверам реализовывать агентное поведение, при котором LLM может вызывать инструменты, получать результаты и продолжать диалог — всё в рамках одного потока запроса на выборку.

Клиенты **ОБЯЗАТЕЛЬНО** должны указать поддержку использования инструмента через параметр `sampling.tools`, чтобы получать запросы на выборку с поддержкой инструмента. Серверы **НЕ ДОЛЖНЫ** отправлять запросы на выборку с поддержкой инструмента клиентам, которые не указали поддержку использования инструмента через параметр `sampling.tools`.

## Возможности

Клиенты, поддерживающие отбор проб, **ОБЯЗАТЕЛЬНО** должны указать наличие возможности отбора проб во время процесса.
[инициализация](/specification/2025-11-25/basic/lifecycle#initialization):

**Базовая выборка:**

```json theme={null}
{
  "возможности": {
    "выборка": {}
  }
}
```

**С поддержкой использования инструментов:**

```json theme={null}
{
  "возможности": {
    "выборка": {
      "инструменты": {}
    }
  }
}
```

**С поддержкой включения контекста (условно устаревшая):**

```json theme={null}
{
  "возможности": {
    "выборка": {
      "контекст": {}
    }
  }
}
```

<Примечание>
  Значения параметра `includeContext` `"thisServer"` и `"allServers"` следующие:
  Устарело. Серверам **СЛЕДУЕТ** избегать использования этих значений (например, можно просто...).
  опустите `includeContext`, поскольку по умолчанию он равен `"none"`), и **НЕ СЛЕДУЕТ** использовать
  их, если клиент не укажет возможность `sampling.context`. Эти значения
  Возможно, будет удалено в будущих версиях спецификации.
</Примечание>

## Протокольные сообщения

### Создание сообщений

Для запроса на генерацию языковой модели серверы отправляют запрос `sampling/createMessage`:

**Запрос:**

```json theme={null}
{
  "jsonrpc": "2.0",
  "id": 1,
  "метод": "sampling/createMessage",
  "параметры": {
    "сообщения": [
      {
        "роль": "пользователь",
        "содержание": {
          "type": "text",
          "текст": "Какова столица Франции?"
        }
      }
    ],
    "modelPreferences": {
      "подсказки": [
        {
          "имя": "сонет Клода-3"
        }
      ],
      "Приоритет интеллекта": 0.8,
      "speedPriority": 0.5
    },
    "systemPrompt": "Вы полезный помощник."
    "maxTokens": 100
  }
}
```

**Ответ:**

```json theme={null}
{
  "jsonrpc": "2.0",
  "id": 1,
  "результат": {
    "роль": "ассистент",
    "содержание": {
      "type": "text",
      "текст": "Столица Франции — Париж."
    },
    "model": "claude-3-sonnet-20240307",
    "stopReason": "endTurn"
  }
}
```

### Сэмплирование с помощью инструментов

На следующей диаграмме показан полный процесс отбора проб с использованием инструментов, включая многооборотный контур инструмента:

```тема русалки={null}
диаграмма последовательности
    участник Сервер
    участник Клиент
    участник Пользователь
    участник LLM

    Примечание по Server, Client: Первоначальный запрос с использованием инструментов.
    Сервер->>Клиент: sampling/createMessage<br/>(сообщения + инструменты)

    Примечание по поводу взаимодействия клиента и пользователя: проверка с участием человека.
    Клиент->>Пользователь: Предъявите запрос на утверждение.
    Пользователь-->>Клиент: Утвердить/изменить

    Клиент->>LLM: Пересылка запроса с использованием инструментов
    LLM-->>Клиент: Ответ с tool_use<br/>(stopReason: "toolUse")

    Клиент->>Пользователь: Представить запросы на использование инструмента для проверки
    Пользователь-->>Клиент: Подтверждение вызовов инструментов
    Клиент-->>Сервер: Возвращает ответ tool_use

    Примечание на сервере: Запустите инструмент(ы)
    Сервер->>Сервер: Запустить get_weather("Париж")<br/>Запустить get_weather("Лондон")

    Примечание по Server, Client: Продолжить просмотр результатов работы инструмента.
    Сервер->>Клиент: sampling/createMessage<br/>(history + tool_results + tools)

    Клиент->>Пользователь: Продолжение настоящего сообщения
    Пользователь-->>Клиент: Подтвердить

    Клиент->>LLM: Переслать результаты работы инструмента.
    LLM-->>Клиент: Окончательный текстовый ответ<br/>(stopReason: "endTurn")

    Клиент->>Пользователь: Предоставить ответ
    Пользователь-->>Клиент: Подтвердить
    Клиент-->>Сервер: Возвращает окончательный ответ

    Примечание от сервера: Сервер обрабатывает результат (может продолжить разговор...).
```

Для запроса генерации LLM с возможностью использования инструментов серверы включают в запрос параметр `tools` и, при необходимости, `toolChoice`:

**Запрос (Сервер -> Клиент):**

```json theme={null}
{
  "jsonrpc": "2.0",
  "id": 1,
  "метод": "sampling/createMessage",
  "параметры": {
    "сообщения": [
      {
        "роль": "пользователь",
        "содержание": {
          "type": "text",
          "текст": "Какая погода в Париже и Лондоне?"
        }
      }
    ],
    "инструменты": [
      {
        "name": "get_weather",
        "описание": "Получите текущую погоду для города",
        "inputSchema": {
          "type": "object",
          "характеристики": {
            "город": {
              "type": "string",
              "описание": "Название города"
            }
          },
          "обязательно": ["город"]
        }
      }
    ],
    "toolChoice": {
      "режим": "авто"
    },
    "maxTokens": 1000
  }
}
```

**Ответ (клиент -> сервер):**

```json theme={null}
{
  "jsonrpc": "2.0",
  "id": 1,
  "результат": {
    "роль": "ассистент",
    "содержание": [
      {
        "type": "tool_use",
        "id": "call_abc123",
        "name": "get_weather",
        "вход": {
          «город»: «Париж»
        }
      },
      {
        "type": "tool_use",
        "id": "call_def456",
        "name": "get_weather",
        "вход": {
          "город": "Лондон"
        }
      }
    ],
    "model": "claude-3-sonnet-20240307",
    "stopReason": "toolUse"
  }
}
```

### Многооборотный инструментальный цикл

После получения запросов на использование инструментов от LLM сервер обычно выполняет следующие действия:

1. Выполняет запрошенные действия с инструментом.
2. Отправляет новый запрос на отбор проб с добавлением результатов работы инструмента.
3. Получает ответ от магистра права (который может содержать информацию о новых способах использования инструмента).
4. Повторяется столько раз, сколько необходимо (сервер может ограничить максимальное количество итераций и, например, передать `toolChoice: {mode: "none"}` на последней итерации, чтобы принудительно получить окончательный результат).

**Запрос на последующее отслеживание (сервер -> клиент) с результатами работы инструмента:**


## Ограничения содержимого сообщений

### Сообщения о результатах работы инструмента

Если сообщение пользователя содержит результаты работы инструмента (тип: "tool\_result"), оно **ОБЯЗАТЕЛЬНО** должно содержать ТОЛЬКО результаты работы инструмента. Смешивание результатов работы инструмента с другими типами контента (текст, изображение, аудио) в одном сообщении не допускается.

Это ограничение обеспечивает совместимость с API поставщиков, которые используют выделенные роли для результатов работы инструментов (например, роль «инструмент» в OpenAI, роль «функция» в Gemini).

**Действительный результат — результат использования одного инструмента:**

```json theme={null}
{
  "роль": "пользователь",
  "содержание": {
    "type": "tool_result",
    "toolUseId": "call_123",
    "content": [{ "type": "text", "text": "Result data" }]
  }
}
```

**Достоверные результаты — получены с помощью нескольких инструментов:**

```json theme={null}
{
  "роль": "пользователь",
  "содержание": [
    {
      "type": "tool_result",
      "toolUseId": "call_123",
      "content": [{ "type": "text", "text": "Result 1" }]
    },
    {
      "type": "tool_result",
      "toolUseId": "call_456",
      "content": [{ "type": "text", "text": "Result 2" }]
    }
  ]
}
```

**Неверно - смешанное содержимое:**

```json theme={null}
{
  "роль": "пользователь",
  "содержание": [
    {
      "type": "text",
      "текст": "Вот результаты:"
    },
    {
      "type": "tool_result",
      "toolUseId": "call_123",
      "content": [{ "type": "text", "text": "Result data" }]
    }
  ]
}
```

### Баланс между использованием инструментов и результатами

При использовании данных об использовании инструментов в процессе выборки каждое сообщение помощника, содержащее блоки `ToolUseContent`, **ДОЛЖНО** сопровождаться сообщением пользователя, полностью состоящим из блоков `ToolResultContent`, при этом каждое использование инструмента (например, с `id: $id`) должно соответствовать результату использования инструмента (с `toolUseId: $id`) перед любым другим сообщением.

Это требование обеспечивает:

* Вопросы использования инструментов всегда решаются до продолжения разговора.
* API-интерфейсы поставщиков могут одновременно обрабатывать несколько запросов к инструментам и получать их результаты параллельно.
* В ходе разговора сохраняется последовательная модель «запрос-ответ».

**Пример допустимой последовательности:**

1. Сообщение пользователя: "Какая погода в Париже и Лондоне?"
2. Сообщение помощника: `ToolUseContent` (`id: "call_abc123", name: "get_weather", input: {city: "Paris"}`) + `ToolUseContent` (`id: "call_def456", name: "get_weather", input: {city: "London"}`)
3. Сообщение пользователя: `ToolResultContent` (`toolUseId: "call_abc123", content: "18°C, частично облачно"`) + `ToolResultContent` (`toolUseId: "call_def456", content: "15°C, дождливо"`)
4. Сообщение от помощника: текстовый ответ со сравнением погоды в обоих городах.

**Неверная последовательность — отсутствует результат работы инструмента:**

1. Сообщение пользователя: "Какая погода в Париже и Лондоне?"
2. Сообщение помощника: `ToolUseContent` (`id: "call_abc123", name: "get_weather", input: {city: "Paris"}`) + `ToolUseContent` (`id: "call_def456", name: "get_weather", input: {city: "London"}`)
3. Сообщение пользователя: `ToolResultContent` (`toolUseId: "call_abc123", content: "18°C, частично облачно"`) ← Отсутствует результат для вызова\_def456
4. Сообщение от помощника: Текстовый ответ (недействительный - не все варианты использования инструмента были решены)

## Совместимость между различными API

Спецификация выборки разработана для работы с различными API-интерфейсами поставщиков LLM (Claude, OpenAI, Gemini и др.). Ключевые проектные решения для обеспечения совместимости:

### Роли сообщений

В MCP используются две роли: «пользователь» и «помощник».

Запросы на использование инструмента отправляются в объекте CreateMessageResult с ролью "ассистент".
Результаты работы инструмента отправляются обратно в сообщениях с указанием роли "пользователь".
Сообщения с результатами работы инструмента не могут содержать другой контент.

### Режимы выбора инструмента

Параметр `CreateMessageRequest.params.toolChoice` управляет возможностью использования инструмента моделью:

* `{mode: "auto"}`: Модель определяет, использовать ли инструменты (по умолчанию)
* `{mode: "required"}`: Модель ДОЛЖНА использовать хотя бы один инструмент перед завершением.
* `{mode: "none"}`: Модель НЕ ДОЛЖНА использовать никакие инструменты

### Параллельное использование инструментов

MCP позволяет моделям отправлять несколько запросов на использование инструментов параллельно (возвращая массив `ToolUseContent`). Все основные API поставщиков поддерживают эту функцию:

* **Клод**: Поддерживает параллельное использование инструментов изначально.
* **OpenAI**: Поддерживает параллельные вызовы инструментов (можно отключить с помощью `parallel_tool_calls: false`)
* **Gemini**: Поддерживает параллельные вызовы функций нативно.

Реализации, использующие провайдеры, поддерживающие отключение параллельного использования инструментов, МОГУТ предоставлять эту возможность в качестве расширения, но она не является частью основной спецификации MCP.

## Типы данных

### Сообщения

Образцы сообщений могут содержать:

#### Текстовое содержимое

```json theme={null}
{
  "type": "text",
  "текст": "Содержание сообщения"
```

### Настройки модели

Выбор модели в MCP требует тщательной абстракции, поскольку серверы и клиенты могут использовать
Различные поставщики ИИ предлагают разные модели. Сервер не может просто запросить
Укажите конкретную модель по названию, поскольку у клиента может не быть доступа именно к этой модели.
предпочтительнее использовать аналогичную модель другого поставщика.

Для решения этой проблемы MCP внедряет систему предпочтений, которая объединяет абстрактные возможности.
Приоритеты с необязательными подсказками модели:

#### Приоритеты возможностей

Серверы выражают свои потребности с помощью трех нормализованных значений приоритета (0-1):

* `costPriority`: Насколько важна минимизация затрат? Более высокие значения отдают предпочтение более дешевым моделям.
* `speedPriority`: Насколько важна низкая задержка? Более высокие значения предпочтительны для более быстрых моделей.
* `Приоритет интеллекта`: Насколько важны передовые возможности? Предпочтение отдается более высоким значениям.
  более функциональные модели.

#### Подсказки по модели

В то время как приоритеты помогают выбирать модели на основе характеристик, «подсказки» позволяют серверам...
Предложите конкретные модели или семейства моделей:

* Подсказки рассматриваются как подстроки, которые могут гибко сопоставляться с названиями моделей.
* Несколько подсказок оцениваются в порядке предпочтения.
* Клиенты **МОГУТ** сопоставлять подсказки с эквивалентными моделями от разных поставщиков.
* Подсказки носят рекомендательный характер — окончательный выбор модели осуществляет клиент.

Например:

```json theme={null}
{
  "подсказки": [
    { "name": "claude-3-sonnet" }, // Предпочтительнее использовать модели класса Sonnet
    { "name": "claude" } // В случае необходимости можно использовать любую модель Клода
  ],
  "costPriority": 0.3, // Стоимость менее важна
  "speedPriority": 0.8, // Скорость очень важна
  "Приоритет интеллекта": 0.5 // Умеренные потребности в возможностях
}
```

Клиент обрабатывает эти предпочтения, чтобы выбрать подходящую модель из имеющихся в наличии.
варианты. Например, если у клиента нет доступа к моделям Клода, но есть Gemini,
Возможно, это позволит сопоставить подсказку сонета с `gemini-1.5-pro` на основе аналогичных возможностей.

## Обработка ошибок

Клиенты **ДОЛЖНЫ** возвращать ошибки в типичных случаях сбоев:

* Пользователь отклонил запрос на выборку: `-1`
* В запросе отсутствует результат работы инструмента: `-32602` (Недопустимые параметры)
* Результаты работы инструмента содержат смешанный контент: `-32602` (Недопустимые параметры)

Примеры ошибок:

```json theme={null}
{
  "jsonrpc": "2.0",
  "id": 3,
  "ошибка": {
    "код": -1,
    "message": "Пользователь отклонил запрос на отбор проб"
  }
}
```

```json theme={null}
{
  "jsonrpc": "2.0",
  "id": 4,
  "ошибка": {
    "код": -32602,
    "message": "Результат работы инструмента отсутствует в запросе"
  }
}
```

## Вопросы безопасности

1. Клиенты **ДОЛЖНЫ** внедрить механизмы контроля за подтверждением действий пользователей.
2. Обе стороны **должны** проверить содержание сообщения.
3. Клиенты **СЛЕДУЕТ** уважать подсказки о предпочтениях модели.
4. Клиентам **СЛЕДУЕТ** внедрять ограничение скорости запросов.
5. Обе стороны **ОБЯЗАНЫ** надлежащим образом обращаться с конфиденциальными данными.

При использовании инструментов для отбора проб необходимо учитывать дополнительные аспекты безопасности:

6. Серверы **ОБЯЗАТЕЛЬНО** должны гарантировать, что при ответе на `stopReason: "toolUse"` каждый элемент `ToolUseContent` будет сопровождаться элементом `ToolResultContent` с соответствующим `toolUseId`, и что сообщение пользователя будет содержать только результаты работы инструментов (никаких других типов контента).
7. Обе стороны **должны** установить ограничения на количество итераций для циклов обработки данных.
