# Инструменты

<div id="enable-section-numbers" />

<Информация>**Ревизия протокола**: 2025-11-25</Информация>

Протокол контекста модели (MCP) позволяет серверам предоставлять доступ к инструментам, которые могут быть вызваны сервером.
языковые модели. Инструменты позволяют моделям взаимодействовать с внешними системами, например, для выполнения запросов.
базы данных, вызов API или выполнение вычислений. Каждый инструмент имеет уникальный идентификатор.
имя и включает метаданные, описывающие его схему.

## Модель взаимодействия с пользователем

Инструменты в MCP разработаны для **управления на основе модели**, что означает, что языковая модель может
Автоматическое обнаружение и вызов инструментов на основе контекстного понимания и
Подсказки пользователя.

Однако разработчики могут свободно предоставлять доступ к инструментам через любой шаблон интерфейса.
соответствует их потребностям — сам протокол не предписывает какого-либо конкретного пользователя.
модель взаимодействия.

<Предупреждение>
  Для обеспечения доверия, безопасности и защищенности **ДОЛЖНО** всегда
  быть человеком, участвующим в процессе, с возможностью отклонять вызовы инструментов.

  Приложения **должны**:

  * Предоставить пользовательский интерфейс, который четко показывает, какие инструменты доступны для модели ИИ.
  * Вставляйте четкие визуальные индикаторы при вызове инструментов.
  * Отображать у пользователя запросы на подтверждение выполнения операций, чтобы убедиться, что на экране находится человек.
    петля
</Предупреждение>

## Возможности

Серверы, поддерживающие инструменты, **ОБЯЗАТЕЛЬНО** должны объявить о наличии возможности `tools`:

```json theme={null}
{
  "возможности": {
    "инструменты": {
      "listChanged": true
    }
  }
}
```

`listChanged` указывает, будет ли сервер отправлять уведомления, когда список изменится.
Доступные инструменты изменились.

## Протокольные сообщения

### Инструменты для размещения объявлений

Для получения информации о доступных инструментах клиенты отправляют запрос `tools/list`. Эта операция поддерживает
[пагинация](/specification/2025-11-25/server/utilities/pagination).

**Запрос:**

```json theme={null}
{
  "jsonrpc": "2.0",
  "id": 1,
  "метод": "инструменты/список",
  "параметры": {
    "cursor": "optional-cursor-value"
  }
}
```

**Ответ:**

```json theme={null}
{
  "jsonrpc": "2.0",
  "id": 1,
  "результат": {
    "инструменты": [
      {
        "name": "get_weather",
        «Заголовок»: «Поставщик метеорологической информации»,
        "Описание": "Получить актуальную информацию о погоде для указанного места",
        "inputSchema": {
          "type": "object",
          "характеристики": {
            "расположение": {
              "type": "string",
              "описание": "Название города или почтовый индекс"
            }
          },
          "обязательно": ["местоположение"]
        },
        "иконки": [
          {
            "src": "https://example.com/weather-icon.png",
            "mimeType": "image/png",
            "Размеры": ["48x48"]
          }
        ]
      }
    ],
    "nextCursor": "next-page-cursor"
  }
}
```

### Инструменты вызова

Для вызова инструмента клиенты отправляют запрос `tools/call`:

**Запрос:**

```json theme={null}
{
  "jsonrpc": "2.0",
  "id": 2,
  "метод": "инструменты/вызов",
  "параметры": {
    "name": "get_weather",
    "аргументы": {
      «Местоположение»: «Нью-Йорк»
    }
  }
}
```

**Ответ:**

```json theme={null}
{
  "jsonrpc": "2.0",
  "id": 2,
  "результат": {
    "содержание": [
      {
        "type": "text",
        "текст": "Текущая погода в Нью-Йорке:\nТемпература: 72°F\nУсловия: Переменная облачность"
      }
    ],
    "isError": false
  }
}
```

### Уведомление об изменении списка

Когда список доступных инструментов изменяется, серверы, объявившие `listChanged`,
Данная функция **ДОЛЖНА** отправлять уведомление:

```json theme={null}
{
  "jsonrpc": "2.0",
  "метод": "уведомления/инструменты/список_измененных"
}
```

## Типы данных

### Инструмент

Определение инструмента включает в себя:

* `name`: Уникальный идентификатор инструмента
* `title`: Необязательное удобочитаемое название инструмента для отображения.
* `description`: Удобочитаемое описание функциональности
* `icons`: Необязательный массив значков для отображения в пользовательских интерфейсах
* `inputSchema`: JSON-схема, определяющая ожидаемые параметры
  * Соответствует [рекомендациям по использованию JSON Schema](/specification/2025-11-25/basic#json-schema-usage)
  * Если поле `$schema` отсутствует, по умолчанию используется значение 2020-12.
  * **ОБЯЗАТЕЛЬНО** должен быть допустимым объектом JSON Schema (не `null`)
  * Для инструментов без параметров используйте один из следующих допустимых подходов:
    * `{ "type": "object", "additionalProperties": false }` - **Рекомендуется**: явно принимает только пустые объекты
    * `{ "type": "object" }` - принимает любой объект (включая объекты со свойствами)
* `outputSchema`: Необязательная JSON-схема, определяющая ожидаемую структуру выходных данных.
  * Соответствует [рекомендациям по использованию JSON Schema](/specification/2025-11-25/basic#json-schema-usage)
  * Если поле `$schema` отсутствует, по умолчанию используется значение 2020-12.
* `annotations`: Необязательные свойства, описывающие поведение инструмента

<Предупреждение>
  В целях обеспечения доверия, безопасности и защиты данных клиенты **ОБЯЗАТЕЛЬНО** должны учитывать возможность добавления аннотаций к инструментам.
  Эти данные не заслуживают доверия, если они не поступают с доверенных серверов.
</Предупреждение>

#### Названия инструментов

* Названия инструментов **ДОЛЖНЫ** содержать от 1 до 128 символов (включительно).
* Названия инструментов **СЛЕДУЕТ** учитывать регистр символов.
* Следующие символы **ДОЛЖНЫ** быть единственными допустимыми символами: прописные и строчные буквы ASCII (AZ, az), цифры.
  (0-9), нижнее подчеркивание (\_), дефис (-) и точка (.)
* Названия инструментов **НЕ ДОЛЖНЫ** содержать пробелы, запятые или другие специальные символы.
* Названия инструментов **ДОЛЖНЫ** быть уникальными в пределах одного сервера.
* Примеры допустимых названий инструментов:
  * getUser
  * DATA\_EXPORT\_v2
  * admin.tools.list

### Результат работы инструмента

Результаты работы инструмента могут содержать [**структурированный**](#структурированный-контент) или **неструктурированный** контент.

В поле `content` результата возвращается **неструктурированный** контент, который может содержать несколько элементов контента разных типов:

<Примечание>
  Все типы контента (текст, изображения, аудио, ссылки на ресурсы и встроенные ресурсы)
  поддержка опциональная
  [аннотации](/specification/2025-11-25/server/resources#annotations), которые
  Предоставляются метаданные об аудитории, приоритете и времени внесения изменений. Это
  Тот же формат аннотаций используется для ресурсов и подсказок.
</Примечание>

#### Текстовое содержимое

```json theme={null}
{
  "type": "text",
  "текст": "Текст результата работы инструмента"
}
```

#### Содержимое изображения

```json theme={null}
{
  "type": "image",
  "данные": "данные, закодированные в base64",
  "mimeType": "image/png",
  "аннотации": {
    "аудитория": ["пользователь"],
    "приоритет": 0.9
  }
}
```

#### Аудиоконтент

```json theme={null}
{
  "тип": "аудио",
  "data": "base64-encoded-audio-data",
  "mimeType": "audio/wav"
}
```

#### Ссылки на ресурсы

Инструмент **МОЖЕТ** возвращать ссылки на [Ресурсы](/specification/2025-11-25/server/resources), чтобы предоставить дополнительный контекст.
или данные. В этом случае инструмент вернет URI, на который клиент может подписаться или получить доступ:

```json theme={null}
{
  "type"""resource_link",
  "uri": "file:///project/src/main.rs",
  "name": "main.rs",
  "описание": "Основная точка входа в приложение",
  "mimeType": "text/x-rust"
}
```

Ссылки на ресурсы поддерживают те же [аннотации ресурсов](/specification/2025-11-25/server/resources#annotations), что и обычные ресурсы, чтобы помочь клиентам понять, как их использовать.

<Информация>
  Ссылки на ресурсы, возвращаемые инструментами, не гарантируют их отображение в результатах поиска.
  Запроса `resources/list`.
</Info>

#### Встроенные ресурсы

[Ресурсы](/specification/2025-11-25/server/resources) **МОЖЕТ** быть встроены для предоставления дополнительного контекста.
или данные с использованием подходящей [URI-схемы](./resources#common-uri-schemes). Серверы, использующие встроенные ресурсы, **ДОЛЖНЫ** реализовать возможность `resources`:

```json theme={null}
{
  "type": "resource",
  "ресурс": {
    "uri": "file:///project/src/main.rs",
    "mimeType": "text/x-rust",
    "текст": "fn main() {\n println!(\"Hello world!\");\n}",
    "аннотации": {
      "аудитория": ["пользователь", "помощник"],
      "приоритет": 0,7,
      "lastModified": "2025-05-03T14:30:00Z"
    }
  }
}
```

Встроенные ресурсы поддерживают те же [аннотации ресурсов](/specification/2025-11-25/server/resources#annotations), что и обычные ресурсы, чтобы помочь клиентам понять, как их использовать.

#### Структурированный контент

**Структурированный** контент возвращается в виде объекта JSON в поле `structuredContent` результата.

Для обеспечения обратной совместимости инструмент, возвращающий структурированное содержимое, ДОЛЖЕН также возвращать сериализованный JSON в блоке TextContent.

#### Схема вывода

Инструменты также могут предоставлять схему выходных данных для проверки структурированных результатов.
Если предоставлена ​​схема вывода:

* Серверы **ОБЯЗАТЕЛЬНО** должны предоставлять структурированные результаты, соответствующие данной схеме.
* Клиенты **ДОЛЖНЫ** проверять структурированные результаты на соответствие этой схеме.

Пример инструмента со схемой вывода:

```json theme={null}
{
  "name": "get_weather_data",
  «title»: «Средство для получения данных о погоде»,
  "Описание": "Получить актуальные данные о погоде для указанного местоположения",
  "inputSchema": {
    "type": "object",
    "характеристики": {
      "расположение": {
        "type": "string",
        "описание": "Название города или почтовый индекс"
      }
    },
    "обязательно": ["местоположение"]
  },
  "outputSchema": {
    "type": "object",
    "характеристики": {
      "температура": {
        "тип": "номер",
        "Описание": "Температура в градусах Цельсия"
      },
      "условия": {
        "type": "string",
        "описание": "Описание погодных условий"
      },
      "влажность": {
        "тип": "номер",
        "описание": "Процент влажности"
      }
    },
    "требуется": ["температура", "условия", "влажность"]
  }
}
```

Пример корректного ответа для этого инструмента:

```json theme={null}
{
  "jsonrpc": "2.0",
  "id": 5,
  "результат": {
    "содержание": [
      {
        "type": "text",
        "текст": "{\"температура\": 22,5, \"условия\": \"частичная облачность\", \"влажность\": 65}"
      }
    ],
    "structuredContent": {
      "температура": 22,5,
      «Условия»: «Частичная облачность».
      «влажность»: 65

  }
}
```

Предоставление схемы выходных данных помогает клиентам и магистрам права понимать и правильно обрабатывать структурированные выходные данные инструментов, а именно:

* Включение строгой проверки схемы ответов
* Предоставление информации о типах для лучшей интеграции с языками программирования.
* Оказание помощи клиентам и магистрам права в правильном анализе и использовании полученных данных.
* Поддержка улучшения документации и удобства работы разработчиков.

## Обработка ошибок

Инструменты используют два механизма сообщения об ошибках:

1. **Протокольные ошибки**: Стандартные ошибки JSON-RPC, связанные с такими проблемами, как:
   * Неизвестные инструменты
   * Некорректные запросы (запросы, не удовлетворяющие [схеме CallToolRequest](/specification/2025-11-25/schema#calltoolrequest))
   * Ошибки сервера

2. **Ошибки выполнения инструмента**: В результатах выполнения инструмента отображается `isError: true`:
   * Сбои API
   * Ошибки проверки входных данных (например, дата в неправильном формате, значение вне допустимого диапазона)
   * Ошибки бизнес-логики

**Ошибки выполнения инструмента** содержат полезную обратную связь, которую языковые модели могут использовать для самокоррекции и повторной попытки с измененными параметрами.
**Протокольные ошибки** указывают на проблемы в самой структуре запроса, которые модели с меньшей вероятностью смогут исправить.
Клиенты **СЛЕДУЕТ** предоставлять языковым моделям информацию об ошибках выполнения инструмента для обеспечения возможности самокоррекции.
Клиенты **МОГУТ** передавать языковым моделям ошибки протокола, хотя вероятность успешного восстановления таких ошибок невелика.

Пример ошибки протокола:

```json theme={null}
{
  "jsonrpc": "2.0",
  "id": 3,
  "ошибка": {
    "код": -32602,
    "message": "Неизвестный инструмент: invalid_tool_name"
  }
}
```

Пример ошибки выполнения инструмента (проверка входных данных):

```json theme={null}
{
  "jsonrpc": "2.0",
  "id": 4,
  "результат": {
    "содержание": [
      {
        "type": "text",
        "текст": "Неверная дата отправления: должна быть в будущем. Текущая дата — 08.08.2025."
      }
    ],
    "isError": true
  }
}
```

## Вопросы безопасности

1. Серверы **ОБЯЗАТЕЛЬНО**:
   * Проверьте правильность ввода всех данных инструмента.
   * Внедрить надлежащие средства контроля доступа
   * Вызовы инструмента ограничения скорости
   * Очистка выходных данных инструмента

2. Клиенты **должны**:
   * Запрашивает подтверждение пользователя при выполнении конфиденциальных операций.
   * Перед обращением к серверу отображайте пользователю вводимые с инструмента данные, чтобы избежать вредоносных действий или...
     случайная утечка данных
   * Перед передачей в LLM проверьте результаты работы инструмента.
   * Внедрить тайм-ауты для вызовов инструментов.
   * Регистрируйте использование инструмента в целях аудита.
