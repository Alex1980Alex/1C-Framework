## Возможности

Серверы, поддерживающие запросы подсказок, **ОБЯЗАТЕЛЬНО** должны объявить о наличии возможности `prompts` во время выполнения запроса.
[инициализация](/specification/2025-11-25/basic/lifecycle#initialization):

```json theme={null}
{
  "возможности": {
    "подсказки": {
      "listChanged": true
    }
  }
}
```

`listChanged` указывает, будет ли сервер отправлять уведомления, когда список изменится.
Доступные подсказки изменяются.

## Протокольные сообщения

### Подсказки для размещения объявлений

Для получения доступных подсказок клиенты отправляют запрос `prompts/list`. Эта операция
поддерживает [пагинацию](/specification/2025-11-25/server/utilities/pagination).

**Запрос:**

```json theme={null}
{
  "jsonrpc": "2.0",
  "id": 1,
  "метод": "подсказки/список",
  "параметры": {
    "cursor": "optional-cursor-value"
  }
}
```

**Ответ:**

```json theme={null}
{
  "jsonrpc": "2.0",
  "id": 1,
  "результат": {
    "подсказки": [
      {
        "name": "code_review",
        "title": "Запрос на проверку кода",
        «Описание»: «Просит магистра права проанализировать качество кода и предложить улучшения».
        "аргументы": [
          {
            "имя": "код",
            "описание": "Код для проверки",
            "обязательно": true
          }
        ],
        "иконки": [
          {
            "src": "https://example.com/review-icon.svg",
            "mimeType": "image/svg+xml",
            "размеры": ["любые"]
          }
        ]
      }
    ],
    "nextCursor": "next-page-cursor"
  }
}
```

### Получение подсказки

Для получения конкретного запроса клиенты отправляют запрос `prompts/get`. В качестве аргументов могут использоваться следующие параметры:
Автоматическое завершение через [API завершения](/specification/2025-11-25/server/utilities/completion).

**Запрос:**

```json theme={null}
{
  "jsonrpc": "2.0",
  "id": 2,
  "метод": "prompts/get",
  "параметры": {
    "name": "code_review",
    "аргументы": {
      "code": "def hello():\n print('world')"
    }
  }
}
```

**Ответ:**

```json theme={null}
{
  "jsonrpc": "2.0",
  "id": 2,
  "результат": {
    "описание": "Подсказка для проверки кода",
    "сообщения": [
      {
        "роль": "пользователь",
        "содержание": {
          "type": "text",
          "text": "Пожалуйста, проверьте этот код на Python:\ndef hello():\n print('world')"
        }
      }
    ]
  }
}
```

```json theme={null}
}
```

## Типы данных

### Быстрый

Определение подсказки включает в себя:

* `name`: Уникальный идентификатор для приглашения командной строки
* `title`: Необязательное удобочитаемое имя подсказки для отображения.
* `description`: Необязательное описание, читаемое человеком
* `icons`: Необязательный массив значков для отображения в пользовательских интерфейсах
* `arguments`: Необязательный список аргументов для настройки

### PromptMessage

Сообщения в командной строке могут содержать:

* `role`: либо "user", либо "assistant" для обозначения говорящего
* `content`: Один из следующих типов контента:

<Примечание>
  Все типы содержимого в сообщениях-запросах поддерживают необязательные параметры.
  [аннотации](./resources#annotations) для метаданных об аудитории, приоритете,
  и время внесения изменений.
</Примечание>

#### Текстовое содержимое

Текстовое содержимое представляет собой обычные текстовые сообщения:

```json theme={null}
{
  "type": "text",
  "текст": "Текстовое содержимое сообщения"
}
```

Это наиболее распространенный тип контента, используемый для взаимодействия на естественном языке.

#### Содержимое изображения

Графическое содержимое позволяет включать визуальную информацию в сообщения:

```json theme={null}
{
  "type": "image",
  "данные": "данные изображения, закодированные в base64",
  "mimeType": "image/png"
}
```

Данные изображения **ОБЯЗАТЕЛЬНО** должны быть закодированы в base64 и содержать допустимый MIME-тип. Это позволяет
Мультимодальные взаимодействия, в которых важен визуальный контекст.

#### Аудиоконтент

Аудиоконтент позволяет включать аудиоинформацию в сообщения:

```json theme={null}
{
  "тип": "аудио",
  "data": "base64-encoded-audio-data",
  "mimeType": "audio/wav"
}
```

Аудиоданные ДОЛЖНЫ быть закодированы в формате base64 и содержать допустимый MIME-тип. Это позволяет
Мультимодальные взаимодействия, в которых важен звуковой контекст.

#### Встроенные ресурсы

Встроенные ресурсы позволяют напрямую ссылаться на ресурсы на стороне сервера в сообщениях:

```json theme={null}
{
  "type": "resource",
  "ресурс": {
    "uri": "resource://example",
    "mimeType": "text/plain",
    "текст": "Содержание ресурса"
  }
}
```

Ресурсы могут содержать как текстовые, так и двоичные (блоковые) данные и **ОБЯЗАТЕЛЬНО** должны включать:

* Действительный URI ресурса
* Соответствующий MIME-тип
* Либо текстовое содержимое, либо данные в формате blob, закодированные в base64.

Встроенные ресурсы позволяют запросам автоматически интегрировать контент, управляемый сервером, например...

## Обработка ошибок

Серверы **ДОЛЖНЫ** возвращать стандартные ошибки JSON-RPC в типичных случаях сбоев:

* Недопустимое имя приглашения: `-32602` (Недопустимые параметры)
* Отсутствуют обязательные аргументы: `-32602` (Недопустимые параметры)
* Внутренние ошибки: `-32603` (Внутренняя ошибка)

## Вопросы реализации

1. Серверы **ДОЛЖНЫ** проверять аргументы запроса перед обработкой.
2. Клиенты **СЛЕДУЕТ** самостоятельно обрабатывать постраничную навигацию для больших списков подсказок.
3. Обе стороны **должны** уважать переговоры о возможностях.

## Безопасность

Внедрение **ОБЯЗАТЕЛЬНО** должно тщательно проверять все входные и выходные данные подсказок, чтобы предотвратить
Внедрение вредоносных программ или несанкционированный доступ к ресурсам.
