# Ресурсы

<div id="enable-section-numbers" />

<Информация>**Ревизия протокола**: 2025-11-25</Информация>

Протокол контекста модели (MCP) предоставляет стандартизированный способ для серверов предоставлять доступ к информации.
Ресурсы для клиентов. Ресурсы позволяют серверам обмениваться данными, которые обеспечивают контекст для
языковые модели, такие как файлы, схемы баз данных или информация, специфичная для конкретного приложения.
Каждый ресурс однозначно идентифицируется по...
[URI](https://datatracker.ietf.org/doc/html/rfc3986).

## Модель взаимодействия с пользователем

Ресурсы в MCP спроектированы как **ориентированные на приложения**, с хост-приложениями.
определение того, как учитывать контекст, исходя из их потребностей.

Например, приложения могли бы:

* Предоставляйте доступ к ресурсам через элементы пользовательского интерфейса для явного выбора в виде дерева или списка.
* Предоставить пользователю возможность поиска и фильтрации доступных ресурсов.
* Реализовать автоматическое включение контекста на основе эвристических методов или выбора модели ИИ.

## Возможности

Серверы, поддерживающие ресурсы, **ОБЯЗАТЕЛЬНО** должны объявить о наличии возможности `resources`:

```json theme={null}
{
  "возможности": {
    "ресурсы": {
      "подписаться": true,
      "listChanged": true
    }
  }
}
```

Данная функция поддерживает две дополнительные опции:

* `subscribe`: позволяет ли клиент подписаться на уведомления об изменениях в данных отдельных пользователей.
  ресурсы.
* `listChanged`: будет ли сервер отправлять уведомления, когда список доступных
  изменения в ресурсах.

И `subscribe`, и `listChanged` являются необязательными — серверы не поддерживают ни один из них.
один или оба:

```json theme={null}
{
  "возможности": {
    "ресурсы": {} // Ни одна из функций не поддерживается
  }
}
```

```json theme={null}
{
  "возможности": {
    "ресурсы": {
      "subscribe": true // Поддерживаются только подписки
    }
  }
}
```

```json theme={null}
{
  "возможности": {
    "ресурсы": {
      "listChanged": true // Поддерживаются только уведомления об изменении списка
    }
  }
}
```

## Протокольные сообщения

### Ресурсы для размещения объявлений

Для получения информации о доступных ресурсах клиенты отправляют запрос `resources/list`. Эта операция
поддерживает [пагинацию](/specification/2025-11-25/server/utilities/pagination).

**Запрос:**

```json theme={null}
{
  "jsonrpc": "2.0",
  "id": 1,
  "метод": "ресурсы/список",
  "параметры": {
    "cursor": "optional-cursor-value"
  }
}
```

**Ответ:**

```json theme={null}
{
  "jsonrpc": "2.0",
  "id": 1,
  "результат": {
    "ресурсы": [
      {
        "uri": "file:///project/src/main.rs",
        "name": "main.rs",
        "title": "Основной файл программного приложения на Rust",
        "описание": "Основная точка входа в приложение",
        "mimeType": "text/x-rust",
        "иконки": [
          {
            "src": "https://example.com/rust-file-icon.png",
            "mimeType": "image/png",
            "Размеры": ["48x48"]
          }
        ]
      }
    ],
    "nextCursor": "next-page-cursor"
  }
}
```

### Ресурсы для чтения

Для получения содержимого ресурсов клиенты отправляют запрос `resources/read`:

**Запрос:**

```json theme={null}
{
  "jsonrpc": "2.0",
  "id": 2,
  "метод": "ресурсы/чтение",
  "параметры": {
    "uri": "file:///project/src/main.rs"
  }
}
```

**Ответ:**

```json theme={null}
{
  "jsonrpc": "2.0",
  "id": 2,
  "результат": {
    "содержание": [
      {
        "uri": "file:///project/src/main.rs",
        "mimeType": "text/x-rust",
        "text": "fn main() {\n println!(\"Hello world!\");\n}"
      }
    ]
  }
}
```

### Шаблоны ресурсов

Шаблоны ресурсов позволяют серверам предоставлять доступ к параметризованным ресурсам с помощью
[URI-шаблоны](https://datatracker.ietf.org/doc/html/rfc6570). Аргументы могут быть
Автоматическое завершение через [API завершения](/specification/2025-11-25/server/utilities/completion).

**Запрос:**

```json theme={null}
{
  "jsonrpc": "2.0",
  "id": 3,
  "метод": "ресурсы/шаблоны/список"
}
```

**Ответ:**

```json theme={null}
{
  "jsonrpc": "2.0",
  "id": 3,
  "результат": {
    "resourceTemplates": [
      {
        "uriTemplate": "file:///{path}",
        "имя": "Файлы проекта",
        "title": "📁 Файлы проекта",
        "description": "Доступ к файлам в каталоге проекта",
        "mimeType": "application/octet-stream",
        "иконки": [
          {
            "src": "https://example.com/folder-icon.png",
            "mimeType": "image/png",
            "Размеры": ["48x48"]
          }
        ]
      }
    ]
  }
}
```

### Уведомление об изменении списка

Когда список доступных ресурсов изменяется, серверы, объявившие событие `listChanged`,
Данная функция **ДОЛЖНА** отправлять уведомление:

```json theme={null}
{
  "jsonrpc": "2.0",
  "метод": "уведомления/ресурсы/список_изменений"
}
```

### Подписки

Протокол поддерживает необязательную подписку на изменения ресурсов. Клиенты могут подписаться.
Получайте уведомления об изменениях в определенных ресурсах:

**Запрос на подписку:**

```json theme={null}
{
  "jsonrpc": "2.0",
  "id": 4,
  "метод": "ресурсы/подписка",
  "параметры": {
    "uri": "file:///project/src/main.rs"
  }
}
```

**Уведомление об обновлении:**

```json theme={null}
{
  "jsonrpc": "2.0",
  "метод": "уведомления/ресурсы/обновлено",
  "параметры": {
    "uri": "file:///project/src/main.rs"
  }
}
```

## Типы данных

### Ресурс

Определение ресурса включает в себя:

* `uri`: Уникальный идентификатор ресурса
* `name`: Название ресурса.
* `title`: Необязательное удобочитаемое название ресурса для отображения.
* `description`: Необязательное описание
* `icons`: Необязательный массив значков для отображения в пользовательских интерфейсах
* `mimeType`: Необязательный тип MIME
* `size`: Необязательный размер в байтах

### Содержание ресурса

Ресурсы могут содержать как текстовые, так и двоичные данные:

#### Текстовое содержимое

```json theme={null}
{
  "uri": "file:///example.txt",
  "mimeType": "text/plain",
  "текст": "Содержание ресурса"
}
```

#### Двоичное содержимое

```json theme={null}
{
  "uri": "file:///example.png",
  "mimeType": "image/png",
  "blob": "base64-encoded-data"
}
```

### Аннотации

Ресурсы, шаблоны ресурсов и блоки контента поддерживают необязательные аннотации, которые предоставляют клиентам подсказки о том, как использовать или отображать ресурс:

* **`audience`**: Массив, указывающий на целевую аудиторию (аудиторию) для данного ресурса. Допустимые значения: `"user"` и `"assistant"`. Например, `["user", "assistant"]` указывает на контент, полезный для обеих групп пользователей.
* **`Приоритет`**: Число от 0,0 до 1,0, указывающее на важность данного ресурса. Значение 1 означает «наиболее важный» (фактически обязательный), а 0 — «наименее важный» (полностью необязательный).
* **`lastModified`**: метка времени в формате ISO 8601, указывающая, когда ресурс был последний раз изменен (например, `"2025-01-12T15:00:58Z"`).

Пример ресурса с аннотациями:

```json theme={null}
{
  "uri": "file:///project/README.md",
  "name": "README.md",
  «Заголовок»: «Проектная документация»,
  "mimeType": "text/markdown",
  "аннотации": {
    "аудитория": ["пользователь"],
    "приоритет": 0,8,
    "lastModified": "2025-01-12T15:00:58Z"
  }
}
```

Клиенты могут использовать эти аннотации для:

* Фильтруйте ресурсы в зависимости от их целевой аудитории.
* Определите приоритетность ресурсов для включения в контекст.
* Отображение времени внесения изменений или сортировка по давности.

## Общие схемы URI

Протокол определяет несколько стандартных схем URI. Этот список не включает в себя:
исчерпывающий перечень — реализации всегда могут свободно использовать дополнительные, пользовательские схемы URI.

### https\://

Используется для обозначения ресурса, доступного в интернете.

Серверы **ДОЛЖНЫ** использовать эту схему только тогда, когда клиент может получить и загрузить данные.
Ресурс загружается непосредственно из интернета самостоятельно — то есть, ему не нужно его читать.
через сервер MCP.

В других случаях серверам **следует** отдавать предпочтение использованию другой схемы URI или определять собственную схему.
пользовательский, даже если сам сервер будет загружать содержимое ресурсов через
интернет.

### файл://

Используется для идентификации ресурсов, которые ведут себя как файловая система. Однако эти ресурсы таковыми не являются.
Необходимо сопоставить с реальной физической файловой системой.

Серверы MCP **МОГУТ** идентифицировать ресурсы file:// с помощью
[Тип MIME XDG](https://specifications.freedesktop.org/shared-mime-info-spec/0.14/ar01s02.html#id-1.3.14),
подобно `inode/directory`, используется для обозначения нестандартных файлов (таких как каталоги), которые не соответствуют определенным критериям.
в противном случае используйте стандартный MIME-тип.

### git://

Интеграция с системой контроля версий Git.

### Пользовательские схемы URI

Пользовательские схемы URI **ДОЛЖНЫ** соответствовать [RFC3986](https://datatracker.ietf.org/doc/html/rfc3986),
с учетом вышеизложенных рекомендаций.

## Обработка ошибок

Серверы **ДОЛЖНЫ** возвращать стандартные ошибки JSON-RPC в типичных случаях сбоев:

* Ресурс не найден: `-32002`
* Внутренние ошибки: `-32603`

Пример ошибки:

```json theme={null}
{
  "jsonrpc": "2.0",
  "id": 5,
  "ошибка": {
    "код": -32002,
    "сообщение": "Ресурс не найден",
    "данные": {
      "uri": "file:///nonexistent.txt"
    }
  }
}
```

## Вопросы безопасности

1. Серверы **ОБЯЗАТЕЛЬНО** должны проверять все URI ресурсов.
2. Для доступа к конфиденциальным ресурсам **следует** внедрить механизмы контроля доступа.
3. Двоичные данные **ОБЯЗАТЕЛЬНО** должны быть правильно закодированы.
4. Перед началом работы **необходимо** проверить права доступа к ресурсам.
