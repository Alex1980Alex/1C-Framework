# 03.1 Загрузка PDF

## Hybrid Loader — 4-уровневая загрузка

Framework использует гибридную стратегию загрузки PDF для гарантии 100% покрытия страниц:

```
Level 1: PyMuPDF4LLM    → основной markdown текст
Level 2: fitz tables     → извлечение таблиц
Level 3: Docling         → структурные таблицы (fallback)
Level 4: Vision OCR      → сканированные страницы (Claude Vision)
```

### Как работает

1. **PyMuPDF4LLM** (основной) — конвертирует PDF в Markdown с `page_chunks=True`.
   ⚠ **Совместимость версий (2026-06-12, roadmap 260612 pdf-docs P1/A1):** pymupdf4llm ≥1.0
   (PyMuPDF-aligned versioning, в проекте 1.27.2.3) переименовал metadata-ключ
   `page` → `page_number` — оба loader'а (`pymupdf4llm_loader.py`, `hybrid_loader.py`)
   читают толерантно (`meta["page"] if "page" in meta else meta["page_number"]`);
   отсутствие обоих ключей = честный KeyError, не глотается
2. **fitz tables** — извлекает таблицы через `page.find_tables()`, дедупликация с основным текстом
3. **Docling** — парсит структурные таблицы как fallback для сложных layout
4. **Vision OCR** — автоопределение сканированных страниц (<50 символов + наличие изображений) → Claude Vision описание

## CLI команды

```bash
# Базовая индексация одного файла
python -m src.cli.main index "path/to/document.pdf"

# Рекурсивная индексация директории
python -m src.cli.main index "path/to/docs/" --recursive

# Полная индексация со всеми фичами
python -m src.cli.main index "path/to/document.pdf" \
    --graph --communities --parent-child --raptor \
    --summarize --layout-aware --extract-images

# Индексация для конкретного тенанта
python -m src.cli.main index "path/to/document.pdf" --tenant company-a
```

## Python API

```python
from src.api.dependencies.components import Components

async def index_document():
    components = Components()
    await components.initialize()

    # Загрузка
    document = await components.loader.load("path/to/document.pdf")

    # Обработка (splitting, metadata, enrichment)
    chunks = components.pipeline.process(document)

    # Индексация
    result = await components.indexer.index_chunks(
        chunks,
        document_id=document.id,
        source_path=document.source_path,
    )

    print(f"Indexed: {result.chunks_stored} chunks")
```

> **Регистрация документа (D7, 2026-06-12):** успешный `index_chunks` финальным
> шагом best-effort регистрирует документ в `document_registry.db`
> (`chunk_count`, `page_count` = max страница из metadata чанков) — поэтому
> MCP `list_documents` отражает индексацию из любой точки входа (CLI/MCP/API),
> а не только REST-роутов. Ошибка реестра логируется warning'ом и не роняет
> индексацию. Детали и backfill — глава [34.1 Knowledge Base](../34_KNOWLEDGE_BASE/34.1_Обзор.md).

## Pipeline обработки

После загрузки PDF текст проходит через pipeline:

```
Raw Text
  → RecursiveCharacterTextSplitter (500-800 символов)
    → Header Propagation (заголовки разделов в metadata)
      → Section Prefix ("Раздел: H1 > H2 > H3\n\n{content}")
        → Metadata Enrichment (language, doc_type, version)
          → Page Number Assignment (bisect mapping)
            → Embedding (E5-large, 1024d)
              → Storage (Qdrant + FTS5 + Graph)
```

### Metadata каждого чанка

| Поле | Описание | Пример |
|------|----------|--------|
| `document_id` | ID документа | `"doc_abc123"` |
| `source` | Путь к файлу | `"data/pdfs/chapter5.pdf"` |
| `page_number` | Номер страницы | `42` |
| `section_title` | Заголовок раздела | `"5.8 Справочники"` |
| `breadcrumb` | Путь в структуре | `"Глава 5 > 5.8 Справочники > 5.8.1 Формы"` |
| `language` | Язык | `"ru"` |
| `document_type` | Тип документа | `"documentation"` |
| `heading_level` | Уровень заголовка | `"h2"` |
| `chunk_index` | Порядковый номер | `156` |
