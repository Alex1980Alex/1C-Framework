# 03.2 Опции индексации

## Все флаги индексации

| Флаг | Описание | По умолчанию |
|------|----------|-------------|
| `--graph` | Извлечь сущности и связи для графа знаний | Выкл |
| `--communities` | Детекция communities (Leiden algorithm) | Выкл |
| `--parent-child` | Создать parent-child иерархию чанков | Выкл |
| `--raptor` | Построить RAPTOR tree (иерархическая суммаризация) | Выкл |
| `--summarize` | Создать суммаризации для Summary Index | Выкл |
| `--layout-aware` | Layout-aware парсинг (Docling) | Вкл |
| `--extract-images` | Извлечь изображения и описать через Vision | Вкл |
| `--extract-tables` | Извлечь таблицы | Вкл |
| `--contextual` | Contextual Retrieval (добавить контекст документа) | Выкл |
| `--recursive` | Рекурсивная индексация директории | Выкл |
| `--full-reindex` | Полная переиндексация (игнорировать delta) | Выкл |
| `--tenant ID` | Tenant для multi-tenancy | `default` |

## Рекомендуемые комбинации

### Быстрая индексация

```bash
python -m src.cli.main index "document.pdf"
```

Минимум: текст + embeddings + BM25. Время: 1-3 минуты на 200 страниц.

### Стандартная индексация (рекомендуется)

```bash
python -m src.cli.main index "document.pdf" --graph
```

Текст + embeddings + BM25 + граф знаний. Время: 5-15 минут на 200 страниц.

### Полная индексация (максимальное качество)

```bash
python -m src.cli.main index "document.pdf" \
    --graph --communities --parent-child --raptor \
    --summarize --contextual
```

Все фичи. Время: 30-60 минут на 200 страниц (зависит от количества LLM-вызовов).

### Batch индексация директории

```bash
python -m src.cli.main index "path/to/docs/" --recursive --graph
```

## Что создаёт каждая опция

### `--graph` — Граф знаний

Извлекает сущности (entities) и связи (relations) из текста:

```
"Конфигуратор позволяет редактировать объекты конфигурации"
  → Entity: "Конфигуратор" (type: tool)
  → Entity: "объекты конфигурации" (type: concept)
  → Relation: "Конфигуратор" → "позволяет редактировать" → "объекты конфигурации"
```

Подробнее: [03.3 Граф знаний](03.3_Граф_знаний.md)

### `--communities` — Community Detection

Кластеризация сущностей графа (Leiden algorithm):
- Группирует связанные сущности в communities
- Генерирует LLM-суммаризации для каждой community
- Используется в GraphRAG (Local и Global search)

### `--parent-child` — Иерархия чанков

Создаёт двухуровневую структуру:
- **Parent chunk** (~2000 символов) — полный контекст
- **Child chunks** (~400 символов) — точный поиск

При поиске: находим child → возвращаем parent (полный контекст).

### `--raptor` — RAPTOR Tree

Иерархическая кластеризация чанков:
- Level 0: оригинальные чанки
- Level 1+: кластеры → LLM суммаризации → новые чанки
- Полезно для высокоуровневых запросов ("общая архитектура")

### `--contextual` — Contextual Retrieval

При индексации добавляет контекст всего документа к каждому чанку:

```
Before: "Регистр имеет измерения и ресурсы."
After:  "В контексте документации 1С:Предприятие 8.3.26, в разделе о регистрах
         накопления: Регистр имеет измерения и ресурсы."
```

### `--extract-images` — Image Understanding

1. PyMuPDF извлекает изображения (min 50x50 px)
2. Claude Vision описывает каждое изображение
3. Описания → отдельные чанки с `page_number`

Подробнее: [03.5 Изображения и таблицы](03.5_Изображения_и_таблицы.md)

## Удаление документов

```bash
# Через API — каскадное удаление из всех хранилищ
curl -X DELETE http://localhost:8000/documents/{document_id}
```

Каскадное удаление очищает 9 слоёв:
1. Vector Store (Qdrant)
2. BM25 Store (FTS5)
3. Parent Store
4. Graph Store
5. Entity Embeddings
6. Semantic Cache
7. Document Registry
8. Collections
9. Version Manager

## LLM Rotation (дешёвый LLM)

Context generator, entity extractor, section summary и community summarizer поддерживают CheapLLM fallback через LLM Rotation Service (Category 2, opt-in). Конфигурация: `LLM_ROTATION_COMPONENTS` в `.env`. Подробнее: skill `llm-rotation`.
