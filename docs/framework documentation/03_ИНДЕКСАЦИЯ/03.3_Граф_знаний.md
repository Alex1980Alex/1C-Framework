# 03.3 Граф знаний

## Обзор

Граф знаний автоматически извлекает из PDF-документов сущности (entities) и связи (relations), формируя структурированное представление содержимого документа.

## Как строится граф

### Entity Extraction

Из текста каждого чанка LLM извлекает:

- **Сущности** — именованные объекты (термины, компоненты, понятия)
- **Связи** — отношения между сущностями (действия, свойства, зависимости)

```
Текст: "Регистр накопления предназначен для учёта числовых показателей.
        Он содержит измерения и ресурсы."

Сущности:
  - Регистр накопления (type: object)
  - числовые показатели (type: concept)
  - измерения (type: property)
  - ресурсы (type: property)

Связи:
  - Регистр накопления → предназначен для → числовые показатели
  - Регистр накопления → содержит → измерения
  - Регистр накопления → содержит → ресурсы
```

### Community Detection

При использовании `--communities`:
1. **Leiden Algorithm** кластеризует связанные сущности в communities
2. Для каждой community генерируется **LLM-суммаризация** (2-3 предложения)
3. Communities используются в GraphRAG (Local и Global search)

## Индексация с графом

```bash
# Базовый граф (entities + relations)
python -m src.cli.main index "document.pdf" --graph

# С community detection
python -m src.cli.main index "document.pdf" --graph --communities

# Batch mode (пакетная обработка)
python -m src.cli.main index "docs/" --recursive --graph --communities
```

## Статистика графа

```bash
# Через API
curl http://localhost:8000/graph/stats
```

## Провайдеры графа

### NetworkX (по умолчанию)

- **In-memory** — быстрый, не требует внешних зависимостей
- Хранение: JSON-файл на диске (`data/graph_store.json`)
- Подходит для: одного документа, разработки

### Neo4j (production)

- **Серверный** — масштабируемый, для больших графов
- Cypher-запросы, визуализация в Neo4j Browser

```env
# Настройка Neo4j
# В docker-compose порт маппится как 17687:7687 (чтобы не конфликтовать с 1c-neo4j)
GRAPH_STORE__PROVIDER=neo4j
GRAPH_STORE__NEO4J_URI=bolt://localhost:17687
GRAPH_STORE__NEO4J_USER=neo4j
GRAPH_STORE__NEO4J_PASSWORD=password
```

## Визуализация графа

### Web UI

На вкладке **Graph** в Web UI можно:
- Просматривать сущности и связи
- Фильтровать по типу сущности
- Визуализировать подграфы

### API

```bash
# Получить entities
curl http://localhost:8000/graph/entities?limit=50

# Получить связи для entity
curl http://localhost:8000/graph/entity/{entity_name}/relations

# Поиск entity
curl "http://localhost:8000/graph/entities/search?query=конфигуратор"
```

## Entity Embeddings

Помимо текстового графа, для сущностей генерируются embeddings:
- Каждая entity → embedding (E5-large, 1024d)
- Хранятся в отдельной Qdrant коллекции
- Используются в GraphRAG Local Search для семантического поиска по entities

## Wiki Export — фильтр noise-entities (2026-05-13)

При экспорте сущностей графа в `docs/wiki/entities/*.md` через `WikiExporter`
([src/pdf_framework/indexing/wiki_exporter.py](../../../src/pdf_framework/indexing/wiki_exporter.py))
применяется regex-фильтр `_is_noise_entity_name()`, отбрасывающий false-positive NER:
даты (`01012009`), timestamps (`13042023-111027`), bare numbers, single chars,
long hex hashes (≥16 chars), years-only (`2026`).

**Важно:** версионные строки (`8.3.27`, `v1.2.3`, `Python 3.11`) НЕ считаются noise —
это валидные доменные entities для 1С и библиотек.

Для очистки уже созданных stub-файлов:
```bash
python scripts/wiki_cleanup_noise_entities.py --dry-run    # отчёт
python scripts/wiki_cleanup_noise_entities.py --archive    # → docs/wiki/archive/YYYY-MM/noise-entities/
```

Companion-скрипты:
- `scripts/wiki_backlink_walker.py` — bidirectional `related:` backfill
- `scripts/wiki_confidence_status_sync.py` — отчёт нарушений confidence<0.8+status=active
