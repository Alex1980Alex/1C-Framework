# 03.4 Инкрементальная индексация

## Обзор

Инкрементальная индексация обновляет только изменённые документы и чанки, экономя время и ресурсы.

## Как работает

### Document Versioning

Каждый документ отслеживается через SHA-256 content hash:

```
document.pdf → SHA-256 hash → сравнение с предыдущим hash
  → hash совпадает? → пропуск (не изменился)
  → hash отличается? → delta indexing
```

### Delta Detection

При изменении документа:

1. Новые чанки → добавляются в индекс
2. Изменённые чанки → обновляются (старые удаляются, новые добавляются)
3. Удалённые чанки → удаляются из индекса

## CLI команды

```bash
# Инкрементальная индексация (по умолчанию)
python -m src.cli.main index "document.pdf"
# → Обрабатывает только изменённые чанки

# Полная переиндексация (игнорировать delta)
python -m src.cli.main index "document.pdf" --full-reindex
```

## File Watcher

Автоматический мониторинг директории на изменения:

```bash
# Запуск file watcher
python -m src.cli.main watch "data/pdfs/"
```

При изменении или добавлении PDF файла в указанной директории — автоматическая переиндексация.

### Настройка

```env
INDEXING__INCREMENTAL=true
INDEXING__WATCH_ENABLED=false       # true для автоматического мониторинга
INDEXING__WATCH_DIR=data/pdfs
```

## Python API

```python
from src.pdf_framework.processing.versioning import DocumentVersioning

versioning = DocumentVersioning()

# Проверить, изменился ли документ
is_changed = await versioning.has_changed(
    document_id="doc_123",
    content_hash="sha256:abc...",
)

if is_changed:
    # Delta indexing
    await indexer.index_delta(new_chunks, document_id="doc_123")
```

## Что обновляется при переиндексации

При инкрементальной переиндексации обновляются все слои:

| Слой | Действие |
|------|---------|
| Vector Store (Qdrant) | Обновление/удаление изменённых чанков |
| BM25 Store (FTS5) | Пересборка для изменённого документа |
| Graph Store | Обновление entities и relations |
| Semantic Cache | Инвалидация кэша для документа |
| Document Registry | Обновление content hash и metadata |
| Wiki Pages | Переэкспорт только affected entities (via EventBus) |

## Инкрементальный Graph → Wiki Sync (Phase 3.10)

При инкрементальном обновлении графа (через `IncrementalGraphUpdater`) события публикуются в `EventBus` и автоматически запускают переэкспорт wiki-страниц:

```
IncrementalGraphUpdater.update(entities, relations)
  → EventBus.publish("graph.entity_created/updated", ...)
  → IncrementalWikiSync._listen_loop() receives event
  → ForwardSyncService.sync_entity() → WikiExporter.export_entity()
```

Это обеспечивает переэкспорт **только** изменённых entities (80-95% экономия CPU).

### Конфигурация

```python
from src.memory.infrastructure.event_bus import EventBus
from src.pdf_framework.graph_store.incremental import IncrementalGraphUpdater
from src.pdf_framework.indexing.wiki_exporter import IncrementalWikiSync

bus = EventBus()
await bus.start()

updater = IncrementalGraphUpdater(graph_store, event_bus=bus)
inc_sync = IncrementalWikiSync(forward_sync, exporter, event_bus=bus)
await inc_sync.start()
```

### Retry Policy

| Attempt | Delay | On Exhaustion |
|---------|-------|---------------|
| 1 | 1s | Retry |
| 2 | 5s | Retry |
| 3 | 30s | Write to DLQ (`docs/wiki/_failed_events.jsonl`) |

### Metrics

| Metric | Type | Description |
|--------|------|-------------|
| `wiki_sync_events_total` | counter | Total events processed |
| `wiki_sync_failures_total` | counter | Events that exhausted retries |
| `wiki_sync_dlq_size` | gauge | Current dead letter queue size |
