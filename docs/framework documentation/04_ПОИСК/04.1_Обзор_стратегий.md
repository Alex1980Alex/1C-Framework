## Генерация ответа (`/search/ask`)

После retrieval ответ синтезирует **`RetrievalQAChain`** ([`chains/qa/retrieval_qa.py`](../../../src/pdf_framework/chains/qa/retrieval_qa.py)) из найденных чанков. Синтез идёт на **free-LLM** (llm_rotation, компонент `qa_answer`, Cat-1) — без платного Anthropic (ADR-040): при отсутствии баланса/ключа `self._llm=None` или `is_cheap_llm_enabled("qa_answer")` → генерация через бесплатные провайдеры. Чистый retrieve **без** LLM — `POST /search/` (для research эталона 8.3.27 достаточно его). Skill: `search-pipeline-debug`.

## Когда какую использовать

### Для быстрого поиска конкретного термина

```bash
python -m src.cli.main search "модуль внешнего соединения" --strategy bm25
# 5-14 мс, точное совпадение слов
```

### Для лучшего качества (рекомендуется)

```bash
python -m src.cli.main search "роли и права доступа" --strategy hybrid
# Vector + BM25 + Graph, RRF fusion
```

### Для поиска в конкретном разделе

```bash
python -m src.cli.main search "справочники" --strategy section_first
# BM25 → определение раздела → scoped hybrid
```

### Для концептуальных вопросов

```bash
python -m src.cli.main search "архитектура платформы 1С" --strategy graphrag_global
# Map-reduce по всем communities
```

### Для сложных исследовательских вопросов

```bash
python -m src.cli.main search "сравните типы регистров" --strategy adaptive
# Автоматически выберет decomposition + multi-step
```

### Для разнообразия результатов

```bash
python -m src.cli.main search "настройка сервера" --strategy mmr --diversity 0.5
# Устранение дубликатов
```

## Turbo Pipeline

Framework автоматически оптимизирует скорость через Turbo Pipeline:

```
Запрос → Rule-based Classifier (0 мс)
  → simple (90% запросов):  BM25 early termination → 125 мс
  → moderate:               Hybrid + Reranking → 3-5 с
  → complex:                Decomposition + Multi-step → 10-30 с
```

Результат: **31x ускорение** для простых запросов (125 мс вместо 3878 мс).

## Observability

`SearchManager.search()` инструментирован Langfuse span'ом (roadmap §5c.5, 2026-05-15): для каждого вызова эмитится observation `search.manager.search` с input `{query_len, strategy, k, rerank, expand_query, filter_keys}` и output `{status, results, duration_ms}` (status: `cache-hit` для semantic-cache-hit пути, `ok` для прохождения через стратегию + rerank). Spans отправляются с `flush=False` — Langfuse SDK background thread обрабатывает queue без блокировки event loop. Подробности и полная таблица всех wired call sites — [09.4.1 Langfuse → Wired call sites](../09_АДМИНИСТРИРОВАНИЕ/09.4.1_Langfuse.md#wired-call-sites-full-5c4--5c5-closure-2026-05-15).
