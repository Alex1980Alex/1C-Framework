# 04.7 Расширенный поиск

## MMR (Maximal Marginal Relevance)

Обеспечивает разнообразие результатов, устраняя дубликаты и слишком похожие фрагменты.

```bash
# MMR с дефолтным разнообразием (0.3)
python -m src.cli.main search "настройка сервера 1С" --strategy mmr

# Увеличить разнообразие
python -m src.cli.main search "настройка сервера 1С" --strategy mmr --diversity 0.7
```

```python
response = await components.search_manager.search(
    query="настройка сервера 1С",
    strategy="mmr",
    k=10,
    diversity=0.5,  # 0.0 = только релевантность, 1.0 = макс. разнообразие
)
```

## RAPTOR — иерархический поиск

RAPTOR строит дерево суммаризаций:
- Level 0: оригинальные чанки
- Level 1+: кластеры → LLM суммаризации

Лучше всего для высокоуровневых запросов.

```bash
# RAPTOR поиск
python -m src.cli.main search "общая концепция" --strategy raptor --top-k 5
```

Требует индексации с `--raptor`:
```bash
python -m src.cli.main index "document.pdf" --raptor
```

## HyDE (Hypothetical Document Embeddings)

Генерирует гипотетический документ-ответ, затем ищет по его embedding:

```bash
python -m src.cli.main search "как создать форму" --expand-query --verbose
```

Verbose вывод:
```
[HyDE] Generating hypothetical document...
[HyDE] Hypothetical: "Для создания формы в 1С:Предприятие..."
[HyDE] Using hypothetical document for search
```

## Two-Stage Pipeline

Двухэтапный поиск: быстрый recall → точный reranking.

```bash
python -m src.cli.main search "работа с транзакциями" --strategy two_stage
```

**Алгоритм:**
1. Stage 1: Извлечь top-50 кандидатов (быстрый recall)
2. Stage 2: FlashRank reranking → top-k лучших

```env
TWO_STAGE__ENABLED=true
TWO_STAGE__FIRST_STAGE_K=50
TWO_STAGE__RERANKER=flashrank
```

## Auto-Merge (Parent-Child)

Поиск по мелким child-чанкам (~400 символов), возврат полных parent-чанков (~2000 символов).

```bash
python -m src.cli.main search "объекты конфигурации" --strategy auto_merge
```

**Алгоритм:**
1. Поиск по child chunks (точные совпадения)
2. Для каждого child → определение parent
3. Если 3+ child из одного parent → auto-merge
4. Возврат parent chunks (полный контекст)

Требует индексации с `--parent-child`:
```bash
python -m src.cli.main index "document.pdf" --parent-child
```

## Query Expansion

Автоматическое расширение запроса синонимами и перефразировками:

```bash
python -m src.cli.main search "установка базы данных" --expand-query

# Комбинация с hybrid
python -m src.cli.main search "настройка PostgreSQL" --strategy hybrid --expand-query
```

## Adaptive RAG

Автоматически классифицирует запрос и выбирает оптимальную стратегию:

```bash
python -m src.cli.main search "Что такое модуль?" --strategy adaptive --verbose
```

Verbose вывод:
```
[CLASSIFY] Query type: factual
[CLASSIFY] Complexity: simple
[ROUTE] Selected strategy: vector
```

Для сложных запросов автоматически decompose:
```bash
python -m src.cli.main search "Сравните конфигуратор и пользовательский режим" \
    --strategy adaptive --verbose
```

```
[DECOMPOSE] Sub-questions:
  1. Что такое конфигуратор?
  2. Что такое пользовательский режим?
  3. В чем различия между ними?
```

## Force Route

Принудительный выбор стратегии в Adaptive RAG:

```bash
python -m src.cli.main search "архитектура" \
    --strategy adaptive \
    --force-route graphrag_global
```
