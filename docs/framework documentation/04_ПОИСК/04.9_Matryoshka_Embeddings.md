# 04.9 Matryoshka Embeddings — Storage/Latency Trade-off

> **Source:** roadmap [260509 §4.1](../../roadmap/260509_ROADMAP_CONSOLIDATED_BACKLOG.md), closed 2026-05-16. Bench results in [`data/eval/matryoshka_report.json`](../../../data/eval/matryoshka_report.json).

## Что такое Matryoshka Representation Learning (MRL)

Qwen3-Embedding-8B обучена с MRL loss — **первые N измерений вектора уже несут осмысленный сигнал**. Прямая truncation `vec[:N]` + L2-renormalize даёт workable embedding на меньшем dim **без переобучения**.

```
Native 4096d:    [v_0, v_1, ..., v_1023, v_1024, ..., v_4095]
MRL 1024 truncate: [v_0, v_1, ..., v_1023]                      (нужна L2-renormalize)
MRL  512 truncate: [v_0, v_1, ...,  v_511]                      (нужна L2-renormalize)
```

Cosine distance в Qdrant требует unit-normalized inputs. После truncation норма падает (`‖v‖ < 1`), поэтому **обязательная L2-renormalize** на client side. Без неё similarity scores дрейфуют — bug, который сложно поймать.

## Acceptance criterion (§4.1.3)

| delta_rel (vs 4096d baseline) | Recommendation |
|---|---|
| ≥ -5% (включая улучшение) | **MIGRATE** — production swap safe |
| -5% ≤ delta < -10% | **OPT_IN** — keep 4096d primary, MRL опционально |
| < -10% degradation | **REJECT** — close experiment |

Logic в [`scripts/matryoshka_bench.py`](../../../scripts/matryoshka_bench.py) `compare_results()` — асимметричная (улучшение не блокирует migration; только degradation).

## Bench results (2026-05-16, pdf_documents 830 pts)

| Dim | recall@10 | p50 ms | p95 ms | delta_rel | latency speedup p95 | storage factor | Recommendation |
|---|---|---|---|---|---|---|---|
| 4096 (baseline) | 0.0563 | 20.6 | 29.2 | — | 1.0× | 1.0× | — |
| **1024 (MRL)** | **0.0563** | 19.5 | 26.5 | **+0.0%** | 1.1× | **4.0×** | **✅ MIGRATE** |
| 512 (MRL) | 0.0625 | 16.9 | 22.5 | +11.0% | 1.3× | 8.0× | MIGRATE (asymmetric — improvement noise at n=40) |

**Per-difficulty breakdown** (mean keyword_recall):

| Difficulty | 4096d | 1024d | 512d |
|---|---|---|---|
| easy | 0.1875 | 0.1875 | 0.1875 |
| medium | 0.0441 | 0.0441 | 0.0588 |
| hard | 0.0 | 0.0 | 0.0 |

## Interpretation

**Key finding**: 1024d MRL преобразование `pdf_documents` даёт **strictly identical retrieval** к 4096d baseline (delta=0.0% per query, identical per-difficulty). Это сильное эмпирическое подтверждение что Qwen3-Embedding-8B MRL-trained embeddings preserve full rank ordering в первых 1024 dims.

**Storage win unconditional**:
- `pdf_documents` 830 pts: 13 MB → 3.3 MB (-75%)
- `framework_code_v1` 21,242 pts: ~340 MB → ~85 MB (-75%)
- `bsl_code_v4_late` 24,455 pts: ~390 MB → ~98 MB (-75%)

**Latency speedup модест** (1.1-1.3×) на dataset из 830 pts — HNSW graph traversal `O(log N)` доминирует над per-vector ops при таком N. На production-scale collections (24k+ pts) speedup ожидается ближе к 1.5-2×, не 4× как могло бы показаться из dim ratio.

**512d delta +11%** — статистический noise на baseline=0.056, n=40. CI на recall ~5% означает что результаты в пределах ±10% interchangeable. Cannot conclude 512d "лучше" 4096d.

## Caveats метода

1. **Keyword recall@10 вместо NDCG@10**: `golden_v1.expected_chunk_ids` empty pending §7.5 v2.0 grounding. Keyword recall — proxy метрика по `expected_keywords` (40/40 populated). Methodologically valid для A/B comparison, но absolute numbers не сопоставимы с production retrieval.
2. **Low baseline recall (0.056)**: `golden_v1` спроектирован против `framework_code_v1` keywords (Qwen3, FastAPI, MCP, RRF), а индексирован `pdf_documents` (1С Глава 5). Many queries don't have keyword hits in this corpus → keyword_recall approaches noise floor.
3. **n=40 queries**: confidence intervals широкие. Delta < 5% considered noise, > 10% considered signal.
4. **Single corpus tested**: production migration `framework_code_v1` SHOULD re-run bench with appropriate golden subset before swap.

**Production bench results (NDCG@10, 46 items, 2026-05-16)**:

| Dim | NDCG@10 | p95 ms | Delta vs 4096d | Verdict |
|---|---|---|---|---|
| 4096 (baseline) | **0.5645** | 124.5 | — | — |
| **1024 (MRL)** | **0.5506** | 110.6 | **−2.5%** | ✅ **MIGRATE** |
| 512 (MRL) | 0.5034 | 110.5 | −10.8% | ❌ REJECT |

**Storage + latency win при 1024d migration** (`framework_code_v1`):
- 24,481 chunks × 4096d × 4 bytes = **~390 MB**
- 24,481 chunks × 1024d × 4 bytes = **~98 MB**
- **Saving: ~75% (292 MB)**, p95 latency **−11%** (124ms → 111ms)

## Запуск bench локально

```bash
# Один прогон end-to-end (re-embed + evaluate):
python scripts/matryoshka_bench.py --full --report data/eval/matryoshka_report.json

# Только evaluate на уже существующих MRL collections:
python scripts/matryoshka_bench.py --evaluate

# Custom batch (если OOM на меньшем GPU):
python scripts/matryoshka_bench.py --full --batch-size 4
```

Required: CUDA GPU с ≥16 GB VRAM для Qwen3-Embedding-8B bf16 (на RTX 3090 ~5 мин wall-clock).
