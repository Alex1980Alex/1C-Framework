# 06.4 MCP Server

## Обзор

MCP (Model Context Protocol) Server предоставляет 24 инструментов для интеграции с Claude Code и другими MCP-совместимыми клиентами.

## Запуск

```bash
# Запуск MCP сервера
python -m src.mcp_server.server
```

## Примеры использования

### Поиск

```
search_documents(
    query="конфигуратор",
    strategy="hybrid",
    k=5,
    language="ru"
)
```

### RAG ответ

```
ask_question(
    query="Что такое конфигуратор?",
    strategy="hybrid"

```

### Индексация

```
index_pdf(
    path="data/pdfs/document.pdf",
    graph=true,
    communities=true
)
```

```json
{
    "mcpServers": {

            "command": "python",
            "args": ["-m", "src.mcp_server.server"],
            "cwd": "/path/to/1C-Framework"
        }
    }
}
```

## Производительность холодного старта

`pdf-vector-graph` использует **lazy import** контейнера зависимостей `Components` ([src/mcp_server/server.py](../../../src/mcp_server/server.py)) — тяжёлая цепочка LangChain загружается только при первом вызове tool'а, не на module import. Это нужно чтобы успеть ответить на JSON-RPC `initialize` до MCP handshake timeout клиента.

`_get_components()` защищён `asyncio.Lock` (создаётся ленивонo внутри корутины), и присваивание глобального `_components` выполняется **только** после успешного `initialize()` — через локальную `instance`. При `asyncio.CancelledError` (клиент отменил tool-call по таймауту) или любом другом исключении `_components` остаётся `None`, и следующий вызов запустит init с нуля. Без этой защиты cancel оставлял зомби-состояние: объект создан, но `initialize()` не закончен — последующие tool-call'ы возвращали полу-инициализированный контейнер.

| Метрика | Значение |
|---|---|
| Cold start handshake (после lazy import, 2026-05-19) | ~0.5 с |
| Cold start handshake (до lazy import) | ~24 с |
| Первый вызов tool'а (загрузка LangChain) | +20-25 с однократно |
| Последующие вызовы | штатные latencies |

### Если MCP-сервер показывает `✘ failed`

1. **Проверить cold start** — запустить вручную с `initialize` и замерить:
   ```powershell
   $start=Get-Date
   '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2024-11-05","capabilities":{},"clientInfo":{"name":"probe","version":"1"}}}' | .venv\Scripts\python.exe -m src.mcp_server.server 2>$null | Out-Null
   "Cold start: $(((Get-Date)-$start).TotalSeconds) s"
   ```
   Ожидание: ~0.5-2 с.

2. **Поднять MCP handshake timeout** (страховка для других тяжёлых серверов):
   ```powershell
   [System.Environment]::SetEnvironmentVariable('MCP_TIMEOUT', '60000', 'User')
   ```
   Применяется после перезапуска Claude Code.

3. **Если cold start всё ещё медленный** — проверить eager imports в [server.py](../../../src/mcp_server/server.py) (любой `from src.*` на верхнем уровне модуля, который тянет LangChain/Pydantic/embeddings, должен быть в `TYPE_CHECKING` блоке или внутри `_get_components()`).

4. **Persistent log сервера** — [`data/mcp-pdf-vector-graph.log`](../../../data/mcp-pdf-vector-graph.log) (RotatingFileHandler, 2 MB × 3 backups, UTF-8). Пишется через именованный логгер `pdf-vector-graph` с `propagate=False` (не загрязняет root и stdio JSON-RPC канал). Тот же `file_handler` дополнительно прицеплен к **root logger** — это пропускает в файл записи внутренних модулей (`httpx`, `src.pdf_framework.*`, `pymorphy3.opencorpora_dict.wrapper` и т.д.), что позволяет видеть на каком конкретно под-этапе застрял `Components.initialize()`. К root прицеплен **только** file-handler (не stderr), чтобы не зашумлять Claude Code MCP-лог. Содержит: `MCP server pdf-vector-graph: starting stdio transport` при старте процесса, `Lazy-init Components: starting` / `Lazy-init Components: ready in Ns` вокруг первого tool-call'а, и внутреннюю трассировку между ними (`[QDRANT] Initialized`, `[BM25] Initialized`, `Loading dictionaries from …` и т.д.). При отсутствии стартовой строки в логе — процесс не запустился вовсе (проверить `tasklist | findstr python`); при отсутствии «ready in Ns» — сервер завис в `Components.initialize()`, последняя записанная внутренним модулем строка указывает на стадию-виновника.

### Granular Components timing (2026-05-19)

Чтобы локализовать стадию-виновника без догадок, [`src/api/dependencies/components.py`](../../../src/api/dependencies/components.py) теперь инструментирован пошагово через локальный `_step()` helper в `__init__` и `_astep()` в `async initialize()`. Каждый блок выдаёт строку формата:

```
[Components] <step name>                  X.XXs (cum  Y.YYs)
[Components.init] <step name>             X.XXs (cum  Y.YYs)
```

`__init__` покрывает **16 unconditional + до 10 conditional подшагов** (всего 26 точек логирования; conditional gated на флаги `bm25_enabled`, `parent_child.enabled`, `light_rag.enabled`, `adaptive.routing_enabled`, `two_stage.enabled`, `optimization.enabled`, `external.web_search_enabled`, `hierarchical.summary_enabled`, `raptor.enabled`, `feedback.enabled`). Покрытые сущности: get_settings, get_loader, ProcessingPipeline, get_embedding_engine, get_vector_store, get_graph_store, ImageExtractor, SearchManager, ConversationMemory, + по одному `_step` на каждую Phase 30/38/7/8/3.3/34/32/37/36/40/18/19/22/30/13.2. `initialize()` покрывает 13 async-вызовов (vector_store, graph_store, parent_store, bm25_store, semantic_cache, version_manager, feedback_store, section_summary, collection_store, document_registry, research_session_store, query_tracker, audit_logger). Финальные строки — `[Components] __init__ DONE in X.XXs` и `[Components.init] DONE in X.XXs`.

Изолированный замер 2026-05-19 на холодном venv (вне MCP stdio): `__init__` 0.46 с, `initialize()` 0.67 с, общая Lazy-init фаза ≈ 1.1 с. Когда в production видишь "Lazy-init: starting" → "ready in" задержку >5 с — `grep "\[Components" data/mcp-pdf-vector-graph.log | tail -30` укажет конкретный подшаг с расхождением. Если ни один подшаг не выделяется аномально, а суммарное cum близко к 1 с — тормоз не в `Components`, а во внешнем contention (см. [`feedback_pdf_mcp_init_duration`](file:///C:/Users/Tech.%20Boutique/.claude/projects/C--1--Framework/memory/feedback_pdf_mcp_init_duration.md): MCP cold-start storm при reconnect, disk I/O на параллельных venv-загрузках).

### Alias-aware Qdrant initialize (2026-05-19)

После Phase 8 MIGRATE-3 (см. [04.9 §4.1.6-15](../04_ПОИСК/04.9_Matryoshka_Embeddings.md)) `pdf_documents`, `framework_code_v1`, `wiki_pages_v1` существуют как **alias'ы** на физические `*_mrl_1024`. `QdrantVectorStore.initialize()` дополняет `get_collections()` обходом через `get_aliases()` и проверяет существование через union обоих set'ов — иначе alias-имя из конфига попадает в "не существует" ветку, вызывается `create_collection()` и Qdrant возвращает HTTP 400. Подробности с кодом — [04.9 §4.1.16](../04_ПОИСК/04.9_Matryoshka_Embeddings.md#41916-init-pitfall-alias-aware-existence-check-2026-05-19).
