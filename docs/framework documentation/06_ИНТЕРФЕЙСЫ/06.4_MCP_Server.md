# 06.4 MCP Server

## Обзор

MCP (Model Context Protocol) Server предоставляет 24 инструментов для интеграции с Claude Code и другими MCP-совместимыми клиентами.

## Запуск

```bash
# Запуск MCP сервера
python -m src.mcp_server.server
```

## Примеры использования

### Поиск

```
search_documents(
    query="конфигуратор",
    strategy="hybrid",
    k=5,
    language="ru"
)
```

### RAG ответ

```
ask_question(
    query="Что такое конфигуратор?",
    strategy="hybrid"
)
```

### Индексация

```
index_pdf(
    path="data/pdfs/document.pdf",
    graph=true,
    communities=true
)
```

## Настройка в Claude Code

Добавить в `.claude/settings.local.json`:

```json
{
    "mcpServers": {
        "pdf-framework": {
            "command": "python",
            "args": ["-m", "src.mcp_server.server"],
            "cwd": "/path/to/1C-Framework"
        }
    }
}
```

## MCP Resources и Prompts

Сервер **bsl-semantic-search** поддерживает Resources и Prompts помимо Tools:

### Ресурсы

| URI | Описание |
|-----|----------|
| `config://bsl-structure` | JSON структура типов метаданных 1С (Справочники, Документы, Регистры и др.) |
| `standards://coding-1c` | Стандарты кодирования 1С: именование, структура модулей, обработка ошибок |
| `templates://module-skeleton` | Шаблон BSL модуля со стандартными регионами |

### Промпты

| Prompt | Параметры | Описание |
|--------|-----------|----------|
| `generate_handler` | object_type, object_name, event_name | Генерация обработчика события BSL |
| `refactor_module` | module_path, goal | Рефакторинг BSL модуля |
| `review_code` | code_snippet, review_focus | Code review BSL кода |

**Реализация:** `src/bsl/semantic_search/mcp_resources.py`, регистрация через `register_resources_and_prompts(mcp)`.

## Производительность холодного старта

`pdf-vector-graph` использует **lazy import** контейнера зависимостей `Components` ([src/mcp_server/server.py](../../../src/mcp_server/server.py)) — тяжёлая цепочка LangChain загружается только при первом вызове tool'а, не на module import. Это нужно чтобы успеть ответить на JSON-RPC `initialize` до MCP handshake timeout клиента.

| Метрика | Значение |
|---|---|
| Cold start handshake (после lazy import, 2026-05-19) | ~0.5 с |
| Cold start handshake (до lazy import) | ~24 с |
| Первый вызов tool'а (загрузка LangChain) | +20-25 с однократно |
| Последующие вызовы | штатные latencies |

### Если MCP-сервер показывает `✘ failed`

1. **Проверить cold start** — запустить вручную с `initialize` и замерить:
   ```powershell
   $start=Get-Date
   '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2024-11-05","capabilities":{},"clientInfo":{"name":"probe","version":"1"}}}' | .venv\Scripts\python.exe -m src.mcp_server.server 2>$null | Out-Null
   "Cold start: $(((Get-Date)-$start).TotalSeconds) s"
   ```
   Ожидание: ~0.5-2 с.

2. **Поднять MCP handshake timeout** (страховка для других тяжёлых серверов):
   ```powershell
   [System.Environment]::SetEnvironmentVariable('MCP_TIMEOUT', '60000', 'User')
   ```
   Применяется после перезапуска Claude Code.

3. **Если cold start всё ещё медленный** — проверить eager imports в [server.py](../../../src/mcp_server/server.py) (любой `from src.*` на верхнем уровне модуля, который тянет LangChain/Pydantic/embeddings, должен быть в `TYPE_CHECKING` блоке или внутри `_get_components()`).

4. **Persistent log сервера** — [`data/mcp-pdf-vector-graph.log`](../../../data/mcp-pdf-vector-graph.log) (RotatingFileHandler, 2 MB × 3 backups, UTF-8). Пишется через именованный логгер `pdf-vector-graph` с `propagate=False` (не загрязняет root и stdio JSON-RPC канал). Содержит: `MCP server pdf-vector-graph: starting stdio transport` при старте процесса, `Lazy-init Components: starting` / `Lazy-init Components: ready in Ns` вокруг первого tool-call'а. При отсутствии стартовой строки в логе — процесс не запустился вовсе (проверить `tasklist | findstr python`); при отсутствии «ready in Ns» — сервер завис в `Components.initialize()` (cold start не дотерпел до handshake).
