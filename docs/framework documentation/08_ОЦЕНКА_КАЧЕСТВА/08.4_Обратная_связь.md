# 08.4 Обратная связь (Self-Learning Feedback)

## Обзор

Система обратной связи позволяет пользователям оценивать ответы. Положительные оценки используются для улучшения качества.

## Как работает

```
Пользователь оценивает ответ (1-5 stars)
  → Feedback Store (SQLite)
    → Few-Shot: лучшие примеры (5 stars) → в промпты
    → Score Boost: документы с позитивным фидбеком → boost при поиске
    → Strategy Tuning: статистика → адаптация параметров
```

## Три компонента

| Компонент | Назначение |
|-----------|-----------|
| **Feedback Store** | Хранение оценок пользователей (1-5 stars) |
| **Few-Shot Provider** | Лучшие примеры (5 stars) как few-shot в промптах |
| **Score Booster** | Boost score документов с позитивным фидбеком |

## Отправка feedback

### Через API

```bash
curl -X POST http://localhost:8000/feedback/ \
    -H "Content-Type: application/json" \
    -d '{
        "query": "конфигуратор",
        "result_id": "chunk_123",
        "score": 5,
        "comment": "Точный ответ"
    }'
```

### Через Web UI

На вкладке Chat — кнопки thumbs up / thumbs down под каждым ответом.

### Python API

```python
from src.pdf_framework.feedback.store import FeedbackStore

store = FeedbackStore()

await store.add(
    query="конфигуратор",
    chunk_id="chunk_123",
    score=5,
    comment="Отличный ответ",
)

# Получить лучшие примеры для few-shot
examples = await store.get_best_examples(query="конфигуратор", top_k=3)
```

## Backup & Recovery (Dual-Write)

> Roadmap reference: [260509_ROADMAP_CONSOLIDATED_BACKLOG.md §3.5](../../../docs/roadmap/260509_ROADMAP_CONSOLIDATED_BACKLOG.md). Closed 2026-05-09.

`FeedbackCollector` параллельно с записью в SQLite пишет каждый feedback entry в JSONL backup — защита от corruption single-point-of-failure.

### Как работает

```
add_feedback(entry)
  ├─ INSERT INTO feedback (...)  ← primary write, durable on commit
  └─ _write_jsonl_backup(entry, row_id)  ← fail-soft append
       └─ data/feedback/backups/backup_YYYY-MM-DD.jsonl
```

**Гарантии:**

1. JSONL backup пишется **после** SQLite commit — backup никогда не содержит row, которая не была durably записана в primary.
2. Backup write — **fail-soft**: любая I/O ошибка логируется как warning, но не propagate. SQLite остаётся primary store.
3. Daily rotation: один файл на UTC-дату, append-only, по одной JSON-записи на строку.

### Формат записи

```json
{"id": 42, "written_at": "2026-05-09T10:30:00+00:00", "entry": {"query": "...", "answer": "...", "feedback": "positive", "strategy": "hybrid", "score": 0.85, "sources": [...], "timestamp": 1715246400.0, "user_comment": "", "metadata": {...}}}
```

### Конфигурация

```python
# По умолчанию backup включён, директория = data_dir/feedback/backups
collector = FeedbackCollector()

# Кастомный путь
collector = FeedbackCollector(backup_dir="/var/backups/feedback")

# Отключить (например, для тестов)
collector = FeedbackCollector(backup_enabled=False)
```

### Recovery: replay из JSONL → SQLite

При corruption primary SQLite или миграции на новый instance:

```bash
# Восстановить всё в новую БД
python scripts/replay_feedback_backup.py --target-db data/feedback_restored.db

# Только записи с 2026-05-01 по 2026-05-09
python scripts/replay_feedback_backup.py \
    --since 2026-05-01 --until 2026-05-09

# Идемпотентный replay (skip существующих записей по (query, timestamp))
python scripts/replay_feedback_backup.py --dedupe

# Dry-run — посчитать без записи
python scripts/replay_feedback_backup.py --dry-run
```

Replay создаёт записи с **новыми** auto-increment ID. Original backup ID сохраняется в `metadata.backup_origin_id`, исходный файл — в `metadata.backup_source_file` (traceability).

### Diagnostics

| Симптом | Причина | Решение |
|---|---|---|
| `[FEEDBACK] Backup dir unavailable` warning | Read-only filesystem или нет permissions | Проверить права `data/feedback/backups/`; либо `backup_enabled=False` для read-only deploy |
| `[FEEDBACK] JSONL backup write failed (non-fatal)` | Дисковое место / IO error | Не блокирует пользовательский flow, но требует attention. Проверить `df -h`, `data/feedback/backups/` |
| Replay `seen=N inserted=0 skipped=N` (с `--dedupe`) | Все записи уже есть в target | Норма для повторного запуска; используй другой `--target-db` для свежего impor'а |
| Replay `seen>inserted skipped>0` (без dedupe) | Bad JSON в backup или Pydantic validation fail | Проверить логи, посмотреть конкретные строки в `backup_*.jsonl` |
| Backup file пустой после `add_feedback` | `backup_enabled=False` или write race | Проверить settings; убедиться что `add_feedback()` действительно вернул rid |

### Когда расширить

- **Hourly rotation**: при >100 feedback/hour замедлится JSON parse в replay → перейти на `backup_YYYY-MM-DD-HH.jsonl`.
- **Compression**: при >1GB суточного объёма — `gzip` daily files (replay умеет читать gzip через standard lib, добавить в `_enumerate_backup_files`).
- **Remote backup**: добавить S3/GCS sync через cron — JSONL append-only friendly для object storage.
