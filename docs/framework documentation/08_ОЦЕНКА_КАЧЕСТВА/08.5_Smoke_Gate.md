# 08.5 Smoke Gate — CI-защита retrieval-качества

> Roadmap reference: [260509_ROADMAP_CONSOLIDATED_BACKLOG.md §2.1](../../../docs/roadmap/260509_ROADMAP_CONSOLIDATED_BACKLOG.md). Closed (initial scope) 2026-05-09.
> Architectural decision: [ADR-008 — DSPy Migration Verdict (Accepted)](../../../docs/architecture/ADR-008-dspy-migration-verdict.md) — verdict PASS, grader +2pp, hallucination p95 latency -6.6s (2026-04-21 eval, status updated 2026-05-15).

## Назначение

Smoke gate — это CI-проверка, которая **блокирует merge**, если retrieval-качество фреймворка деградирует ниже зафиксированного порога. Защищает от случайных регрессий при изменениях в:

- embedding pipeline (модель, prefix, dimensions)
- retrieval-стратегиях (Hybrid, BM25, vector, RRF weights)
- chunking / splitting логике
- reranker конфигурации

## Двухуровневая модель

| Уровень | Когда срабатывает | Что проверяет | Стоимость |
|---|---|---|---|
| **Schema gate** | Каждый PR (всегда) | `data/eval/golden_v1.json` загружается, schema валидна, ≥1 item, нет дубликатов id, корректные значения difficulty/category | ~30 мс, 0 внешних сервисов |
| **Quality gate** | Когда golden_v1 имеет ≥50 items с `expected_chunk_ids` И Qdrant + embedding service доступны | NDCG@10 поверх hybrid search ≥ threshold (см. ниже) | ~30-90 сек, нужен Qdrant + TEI |

При размере dataset'а <50 items quality gate **gracefully skipped** — это явное состояние пока golden_v1 в seed-фазе (10 items на 2026-05-09).

## Threshold rationale (NDCG@10 ≥ 0.55)

**Текущий placeholder threshold = 0.55**, прозрачно ниже E5 baseline (0.45 + buffer for Qwen3 lift). Окончательный калиброванный порог зафиксируется отдельным ADR после v2.0 dataset'а с реальными `expected_chunk_ids` и измерения базового NDCG на production retrieval pipeline (`pdf_documents` коллекция, hybrid strategy).

> Когда v2.0 dataset готов, обновить `NDCG_THRESHOLD` в `tests/eval/test_smoke_gate.py` и записать calibration measurement в новый ADR.

## Как пополнять golden dataset

### Ручное добавление (рекомендовано для критических queries)

1. Открыть [`data/eval/golden_v1.json`](../../../data/eval/golden_v1.json).
2. В массив `items` добавить новый объект со схемой:
   ```json
   {
     "id": "gv1-NNN",
     "query": "...",
     "expected_chunk_ids": ["chunk-id-1", "chunk-id-2"],
     "expected_keywords": ["keyword1", "keyword2"],
     "expected_answer_summary": "...",
     "difficulty": "easy|medium|hard",
     "category": "factual|conceptual|procedural|analytical|comparative",
     "domain": "rag-framework|1c|embeddings|infra"
   }
   ```
3. Обновить `stats.count` и `stats.by_difficulty/by_domain`.
4. Записать запись в [`data/eval/CHANGELOG.md`](../../../data/eval/CHANGELOG.md).
5. Коммит — schema gate валидирует schema на CI.

### Synthetic expansion через DSPy

```bash
pip install dspy-ai
export ANTHROPIC_API_KEY=...
python scripts/gen_golden_dataset.py --count 30 --difficulty medium
```

> На 2026-05-09 скрипт = scaffold (выходит с error если deps не установлены). Реализация генерации pending v2.0.

## Diagnostics

| Симптом | Причина | Решение |
|---|---|---|
| `Golden dataset not found` skip | `data/eval/golden_v1.json` отсутствует | Проверь `git status` — файл должен быть в репо |
| Schema gate FAIL | invalid difficulty/category или missing field | Проверить error message → исправить item |
| Quality gate skip "< 50 items" | Dataset в seed-фазе | Ожидаемо — пополнить до ≥50 для активации quality gate |
| Quality gate FAIL "NDCG < threshold" | Реальная регрессия retrieval | Investigate: какие queries деградировали? bisect через `git log` ↔ benchmark |
