# 09.11 Async Workers — Фоновая обработка (ARQ)

Phase 59. ARQ-based очередь фоновых задач на Redis. Позволяет запускать долгие операции (индексация, перестройка графа, RAGAS-оценка) асинхронно, не блокируя API.

## Архитектура

```
API / CLI → Redis queue → ARQ Worker process → tasks (indexing, graph, eval)
                ↑                ↓
         enqueue_job()    Redis hash job:{id} (progress 0→100)
```

Worker — отдельный процесс. Использует ту же базу кода (`src/`), но запускается независимо. Подключается к Redis по `QUEUE__REDIS_URL`.

## 5 зарегистрированных задач

| Задача | Модуль | Сигнатура | Описание |
|--------|--------|-----------|----------|
| `index_document` | `tasks.indexing` | `(file_path, document_id=None, tenant_id="default", options={})` | Индексировать PDF |
| `rebuild_bm25` | `tasks.indexing` | `(collection)` | Перестроить BM25-индекс |
| `rebuild_embeddings` | `tasks.indexing` | `(collection)` | Переиндексировать эмбеддинги |
| `rebuild_graph` | `tasks.graph` | `(filters={})` | Перестроить граф сущностей |
| `run_evaluation` | `tasks.evaluation` | `(dataset, strategy)` | Запустить RAGAS-оценку |

## Отслеживание прогресса

Задача `index_document` обновляет Redis hash `job:{job_id}`:

| Прогресс | Статус | Этап |
|----------|--------|------|
| 0% | `loading` | Чтение файла |
| 10% | `chunking` | Разбивка на чанки |
| 30% | `indexing` | Запись в vector store |
| 70% | `embeddings` | Генерация эмбеддингов |
| 90% | `graph` | Обновление графа |
| 100% | `done` | Завершено |

```python
# Получить статус задачи
import redis.asyncio as aioredis
r = await aioredis.from_url("redis://localhost:6379")
status = await r.hgetall(f"job:{job_id}")
# {b"progress": b"70", b"status": b"embeddings"}
```

## Конфигурация

| Переменная | По умолчанию | Описание |
|-----------|-------------|----------|
| `QUEUE__ENABLED` | `false` | Включить очередь |
| `QUEUE__REDIS_URL` | `redis://localhost:6379` | URL Redis |
| `QUEUE__QUEUE_NAME` | `pdf_framework` | Имя очереди ARQ |
| `QUEUE__MAX_JOBS` | `10` | Макс. параллельных задач |
| `QUEUE__JOB_TIMEOUT` | `3600` | Таймаут задачи (секунды) |
| `QUEUE__RETRY_ATTEMPTS` | `3` | Попыток при сбое |
| `QUEUE__RETRY_DELAY_SECONDS` | `60` | Задержка между попытками |
| `QUEUE__HEALTH_CHECK_INTERVAL` | `60` | Интервал health check (сек) |

## Запуск воркера

```bash
# Стандартный запуск через ARQ CLI
arq src.workers.worker.WorkerSettings

# Проверить состояние воркера
python -m arq.cli src.workers.worker.WorkerSettings --check

# Через модуль (если нет arq в PATH)
python -c "import asyncio; from src.workers.worker import main; asyncio.run(main())"
```

Требования: `QUEUE__ENABLED=true` в `.env`, Redis запущен.

## Постановка задач в очередь

```python
import asyncio
from arq import create_pool
from arq.connections import RedisSettings

async def enqueue():
    redis = await create_pool(RedisSettings.from_dsn("redis://localhost:6379"))

    # Индексация PDF
    job = await redis.enqueue_job(
        "index_document",
        file_path="/data/docs/manual.pdf",
        tenant_id="acme",
        options={"chunk_size": 512, "overlap": 64},
    )
    print(f"Job ID: {job.job_id}")

    # Перестройка BM25
    await redis.enqueue_job("rebuild_bm25", collection="pdf_documents")

    # RAGAS-оценка
    await redis.enqueue_job("run_evaluation", dataset="eval_set_v1", strategy="hybrid")

asyncio.run(enqueue())
```

## Мониторинг

```bash
# Статистика очереди через Redis CLI
redis-cli llen pdf_framework           # задачи в ожидании
redis-cli hgetall "job:<job_id>"       # прогресс конкретной задачи

# Логи воркера (stdout)
# [WORKER] Starting ARQ worker...
# [INDEX] Starting: /data/docs/manual.pdf
# [WORKER] Health check passed
```

Worker логирует через стандартный `logging`. Уровень задаётся через `LOG_LEVEL` в `.env`.

## Docker Compose

```yaml
# docker-compose.yml
worker:
  build: .
  command: arq src.workers.worker.WorkerSettings
  environment:
    - QUEUE__ENABLED=true
    - QUEUE__REDIS_URL=redis://redis:6379
  depends_on:
    - redis
  restart: unless-stopped
```
