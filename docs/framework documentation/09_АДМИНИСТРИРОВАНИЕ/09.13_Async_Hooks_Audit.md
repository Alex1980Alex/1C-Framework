# 09.13 Async Hooks Audit

> Roadmap reference: [260509_ROADMAP_CONSOLIDATED_BACKLOG.md §4.9](../../../docs/roadmap/260509_ROADMAP_CONSOLIDATED_BACKLOG.md). Closed 2026-05-09.

§4.9 запрашивал async refactor для PostToolUse hooks с >2s latency. Real audit показал: **большинство slow hooks — `Stop` events, не PostToolUse**. Реальные refactor candidates ограничены, выбраны для отдельной итерации.

## Findings

### Outlier: SlashCommandTracker Stop (250s avg)

`SlashCommandTracker` на Stop event имеет **avg 250s** — это явный outlier и требует root-cause analysis отдельным taскom (не §4.9 scope). Likely причина: tracker ждёт завершения subagent chains в некоторых slash-command runs. Размер выборки маленький (16 invocations), возможно несколько extreme outliers искажают статистику. **Не candidate для async refactor — нужен RCA.**

### Real refactor candidates

| Hook | Slow rate | Recommendation |
|---|---|---|
| `MemoryFirstHook` Stop | 14% (29/210) | **Best candidate** — significant slow rate, Stop event подходит для fire-and-forget |
| `SessionMemorySave` Stop | 1.6% (8/488) | Borderline — large volume, occasionally crosses 2s |

### Не candidates

`AutoGitSave`, `git-commit-enforcer`, `task-enforcer`, `docs-change-enforcer` — все avg ≤1s, max <2s, slow rate = 0%. Текущая sync execution acceptable.

`PostToolUseAutoGitSave` — единственный PostToolUse в slow set, но avg 0.66s, max 1.93s, 0 slow runs. Не требует refactor.

## Async/fire-and-forget pattern (для будущих refactor'ов)

Claude Code hooks API не предоставляет `"async": true` flag (по 2026-05-09). Fire-and-forget achievable через два паттерна:

### Pattern 1: subprocess.Popen detached (Python hook)

```python
# В Stop hook — quick check + spawn detached worker
import subprocess
import sys
from pathlib import Path

def execute(self, inp: HookInput) -> HookOutput | None:
    # Critical synchronous part (cheap checks)
    if not self._should_save(inp):
        return None

    # Heavy work — fire-and-forget detached subprocess
    worker = Path(__file__).parent / "memory_save_worker.py"
    subprocess.Popen(
        [sys.executable, str(worker), inp.session_id],
        stdout=subprocess.DEVNULL,
        stderr=subprocess.DEVNULL,
        creationflags=subprocess.DETACHED_PROCESS if sys.platform == "win32" else 0,
    )
    return HookOutput().system_message("[MEMORY] save dispatched async")
```

### Pattern 2: asyncio task (если hook event-loop'у)

```python
# Только если hook сам async (не текущий case)
async def execute(self, inp):
    asyncio.create_task(self._save_async(inp))  # fire-and-forget
    return HookOutput().system_message("dispatched")
```

### Trade-offs

| Approach | Pros | Cons |
|---|---|---|
| Sync (current) | Simple, deterministic, errors visible | Slow tail blocks Stop event |
| Fire-and-forget | Fast Stop, async heavy work | Errors silent; no completion guarantee |
| Defer to PostToolUse чейн | Spread cost across multiple hook calls | Сложнее debugging |

**Choosing fire-and-forget — обязательно**:
1. Logging в `data/hook-invocations.jsonl` ДО dispatch — fail-soft trace
2. Worker pid saved to `.claude/cache/memory-save-pids.json` для cleanup
3. Health check: post-hook pid liveness (orphan worker detection)
4. Idempotent worker: same session_id processed twice = no-op

## Decision (2026-05-09)

**Defer actual refactor of MemoryFirstHook + SessionMemorySave** до отдельного focused task с:
- Reproducer test (controlled slow input)
- Worker isolation harness
- Rollback plan (revert flag в settings.json)

§4.9 closes как **audit + pattern documentation**. Sole concrete change — выявление SlashCommandTracker outlier для RCA отдельной задачей.
