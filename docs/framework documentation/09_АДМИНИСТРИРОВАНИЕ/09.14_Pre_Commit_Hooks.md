# 09.14 Pre-Commit Hooks

> **Audience:** developers, CI operators.
> **Scope:** [`.pre-commit-config.yaml`](../../../.pre-commit-config.yaml) hook chain — what each step does, why, and where to fix when one fails.

## Контекст

В репо настроена цепочка [pre-commit](https://pre-commit.com/) хуков, защищающая `main` от регрессий стиля/секретов/wiki-формата. Большая часть хуков — стандартные (ruff, mypy, gitleaks, markdownlint). Этот документ описывает **нестандартные** хуки, требующие contextual знания для дебага.

## kb-lint wiki KB validation

| | |
|---|---|
| **Hook id** | `kb-lint` |
| **Entry** | `python scripts/kb_lint_ci.py` |
| **Triggers on** | `^docs/wiki/.*\.md$` |
| **Mode** | `--ci` (read-only check, no `--fix` in CI) |
| **Pass condition** | exit 0 = 0 ERROR-severity issues per `<wiki_path>/.kblintrc.yml` config |

### Зачем wrapper `scripts/kb_lint_ci.py`, а не прямой `kb-lint --ci`

Wrapper закрывает **два бага** kb-lint 0.1.1 на Windows / Cyrillic-heavy KB:

1. **UTF-8 stdout reconfigure.** Upstream `rich.Console` падает с
   `UnicodeEncodeError '↔' ... cp1251` при попытке вывести таблицу
   результатов в Windows-консоль с charmap-encoding. Wrapper зовёт
   `sys.stdout.reconfigure(encoding='utf-8', errors='replace')` до импорта
   `kb_lint.cli` — Console при создании читает encoding из stdout и работает
   корректно.

2. **Cyrillic-safety monkey-patch** для `kb_lint.fixer.fix_filename_casing`.
   Upstream использует `re.sub(r"[^a-z0-9]+", "-", stem.lower())` —
   ASCII-only character class **уничтожает** кириллицу и любые non-ASCII
   символы при `--fix`. Реальный инцидент (2026-05-13): один запуск
   `kb-lint --fix docs/wiki/` переименовал/удалил 1131 файл и создал
   `docs/wiki/entities/.md` с пустым именем (stem `точек` → `.md`).
   Wrapper подменяет функцию на вариант с `stem.isascii()` guard'ом —
   не-ASCII stems пропускаются с warning в stderr; ASCII fall through к
   оригиналу без изменений.

   Production hook зовёт только `--ci`, который НЕ дёргает `apply_fixes`,
   поэтому monkey-patch — защита от ручного `python scripts/kb_lint_ci.py
   --fix` запуска. См. roadmap
   [`260513_KB_LINT_UPSTREAM_PATCH_CYRILLIC_SAFETY.md`](../../roadmap/260513_KB_LINT_UPSTREAM_PATCH_CYRILLIC_SAFETY.md)
   — после merge upstream PR можно будет удалить monkey-patch.

### Config location

kb-lint 0.1.1 читает config из **`<wiki_path>/.kblintrc.yml`** или
`<wiki_path>/pyproject.toml [tool.kb-lint]` — НЕ из project-root.
Канонический конфиг: [`docs/wiki/.kblintrc.yml`](../../../docs/wiki/.kblintrc.yml)
(см. также `kb_lint/config.py:60-78`).

### Diagnostics: hook fails — что делать

```bash
# Запустить вручную, увидеть полную таблицу
python scripts/kb_lint_ci.py

# Auto-fix safe issues (frontmatter, ascii filenames)
python scripts/kb_lint_ci.py --fix docs/wiki
```

| Symptom | Cause | Fix |
|---|---|---|
| `Executable kb-lint not found` | Не установлен в `.venv` | `pip install kb-lint>=0.1.1` (уже в `pyproject.toml [project.optional-dependencies].dev`) |
| `UnicodeEncodeError '↔'` | Wrapper не вызван (прямой `kb-lint --ci`) | Использовать `python scripts/kb_lint_ci.py`, а не `kb-lint` напрямую |
| `yaml.constructor.ConstructorError 'found unhashable key'` | `{{placeholder}}` Mustache syntax в `templates/**.md` | Добавить `templates/**` в `ignore_patterns` в `.kblintrc.yml` |
| `Empty required field: unified_id` | Wiki page без `unified_id` в frontmatter | Сгенерировать UUID v7 (`scripts/patterns_fill_frontmatter.py` — пример) |
| `Broken wiki-link: [[target]]` | `[[target]].md` не существует | Создать stub-страницу ИЛИ удалить ref ИЛИ `<!-- kb-lint-disable-next-line links -->` |

### Workaround для auto-save commits

[`.claude/hooks/posttooluse-auto-git-save.py:110`](../../../.claude/hooks/posttooluse-auto-git-save.py) использует `git commit --no-verify` чтобы auto-save'ы не падали на временных wiki-issues. Это **намеренный** bypass для machine-generated commits; ручные commits должны проходить полный hook chain.

## mypy temporary exclude (2026-05-14, sanitized 2026-05-16)

В [`.pre-commit-config.yaml`](../../../.pre-commit-config.yaml) `mypy` hook исключает только `src/pdf_framework/quick.py` (после un-exclude `src/api/auth/` 2026-05-16):

```yaml
- id: mypy
  ...
  exclude: ^(tests/|docs/|scripts/|src/pdf_framework/quick\.py$)
```

**История.** На 2026-05-14 в exclude были и `quick.py`, и весь `src/api/auth/` — 421 pre-existing mypy-ошибок в 96 файлах блокировали **любой** structured commit через этот hook, каждый normal commit вынужден был идти через `--no-verify` bypass (инцидент 2026-05-14, sandbox skeleton коммиты `9b392c465` + `11a1d1852` сорвались на unrelated mypy-фейлах). 2026-05-16: 9 ошибок в `src/api/auth/` закрыты ([`rbac.py`](../../../src/api/auth/rbac.py) — `Callable[[DecoratedAsync], DecoratedAsync]` type alias для декораторов `require_role`/`require_permission` + `RBACManager.__init__(self) -> None`; [`jwt_handler.py`](../../../src/api/auth/jwt_handler.py) — `get_jwt_handler(**kwargs: Any) -> JWTHandler`), путь убран из exclude.

**Cleanup tracking:** [`docs/roadmap/260514_ROADMAP_MYPY_CLEANUP.md`](../../roadmap/260514_ROADMAP_MYPY_CLEANUP.md) — un-exclude по мере фиксов. **НЕ расширять `exclude` дальше** без записи в roadmap.

**Phase 0 ratchet gate (2026-05-15)** — отдельный CI job `mypy-baseline` в [`.github/workflows/ci.yml`](../../../.github/workflows/ci.yml) сравнивает `mypy src/` с зафиксированным [`mypy-baseline.txt`](../../../mypy-baseline.txt), падает при `new > 0`. SessionStart баннер [`session-mypy-banner.py`](../../../.claude/hooks/session-mypy-banner.py) показывает текущий error count + delta vs `origin/main`.

**Verification:**

```bash
.venv/Scripts/python -m mypy --ignore-missing-imports src/pdf_framework src/api 2>&1 | tail -5
```

— должен показывать ошибки только в `quick.py` (это и есть приоритетный backlog).
