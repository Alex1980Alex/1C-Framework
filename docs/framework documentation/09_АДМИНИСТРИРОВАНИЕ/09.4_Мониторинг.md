## Langfuse

Полноценный LLM observability:
- Traces всех LLM-вызовов
- Стоимость (tokens, cost)
- Latency по шагам
- Качество (scores)

### Установка

```bash
pip install -e ".[langfuse]"
```

`[langfuse]` extra включает `langfuse>=2.0`. Без установки система работает в no-op режиме (handler автоматически выключается с warning в логе).

### Конфигурация

```env
# Pydantic-settings (nested delimiter __ через OBSERVABILITY__)
OBSERVABILITY__LANGFUSE_ENABLED=true
OBSERVABILITY__LANGFUSE_PUBLIC_KEY=pk-lf-...
OBSERVABILITY__LANGFUSE_SECRET_KEY=sk-lf-...
OBSERVABILITY__LANGFUSE_HOST=https://cloud.langfuse.com
OBSERVABILITY__LANGFUSE_PROJECT_NAME=pdf-framework
```

> Legacy fallback: `LANGFUSE_PUBLIC_KEY`/`LANGFUSE_SECRET_KEY`/`LANGFUSE_HOST` (single underscore) поддерживаются как fallback в `LangfuseCallbackHandler._resolve_credentials`. Резолвинг: explicit kwargs → pydantic-settings → os.environ → disabled с warning. Обновлено roadmap §3.1, см. [`langfuse_callback.py`](../../../src/pdf_framework/callbacks/langfuse/langfuse_callback.py).
>
> **Onboarding (2026-05-15, roadmap §3.4-ter):** placeholder env vars теперь зафиксированы в [`.env.example`](../../../.env.example) с `OBSERVABILITY__LANGFUSE_ENABLED=false` по умолчанию — fresh clone получает корректный reference set без необходимости читать roadmap для discovery нужных переменных. Активация Phase B — [ADR-010](../../../docs/architecture/) + roadmap §5c.

### Использование

**Через middleware (рекомендуется):**

```python
from src.pdf_framework.agents.rag.middleware import with_middleware

llm_traced = with_middleware(
    llm,
    enable_langfuse=True,
    user_id="user-123",
    session_id="session-abc",
)
```

**Через central setup helper** (для не-middleware кода):

```python
from src.pdf_framework.observability.langfuse_setup import (
    is_langfuse_enabled, build_langfuse_callback,
)

if is_langfuse_enabled():
    handler = build_langfuse_callback(user_id="u-1", session_id="s-1")
    if handler is not None:
        llm.callbacks = (llm.callbacks or []) + [handler]
```

`build_langfuse_callback()` возвращает `None` если: (1) `langfuse_enabled=False` в settings, (2) `langfuse` package не установлен, (3) credentials отсутствуют. Никогда не raise.

**Через `emit_observation()` для standalone хуков (2026-05-15, roadmap §5c.4):**

Для Python-хуков Claude Code (memory-first-hook, session-memory-save, memory-sync), которые **не используют LangChain runtime**, добавлен второй entry point — прямая эмиссия одной observation через `langfuse.start_observation()` + `flush()`:

```python
from src.pdf_framework.observability.langfuse_setup import emit_observation

emit_observation(
    name="memory-first-recall",
    input={"prompt_len": len(prompt)},
    output={"layers": 4, "results": n_results, "latency_ms": dt_ms},
    session_id=event.get("session_id"),
    metadata={"hook": "memory-first", "event": "UserPromptSubmit"},
)
```

Pattern source: `doneyli/claude-code-langfuse-template` (Claude Code Stop hook reference impl), research cached в [`langfuse-standalone-spans-2026.md`](../../../.claude/skills/architecture-research/cache/langfuse-standalone-spans-2026.md). Graceful: try/except оборачивает всё; ImportError / network / cred errors → debug log + return (никогда не raise). Opt-out: env `MEMORY_HOOK_NO_LANGFUSE=1`. Currently wired в `.claude/hooks/session-memory-save.py` (proof-of-concept).

### Что трекается

`LangfuseCallbackHandler` подписан на LangChain BaseCallbackHandler events:

| Event | Что записывается |
|---|---|
| `on_llm_start` | Generation: prompts, user_id, session_id |
| `on_llm_end` | Generation: output_text, token usage (prompt/completion/total), model |
| `on_llm_error` | Generation с error metadata |
| `ignore_chain/agent/retriever` | False — все callback'и активны |

### Diagnostics

| Симптом | Причина | Решение |
|---|---|---|
| `[LANGFUSE] langfuse not installed` warning | extra `[langfuse]` не установлен | `pip install -e ".[langfuse]"` |
| `[LANGFUSE] Missing credentials, disabling callback` | settings + env пусты | Проверить `.env` (см. Конфигурация выше) |
| Traces не появляются в Langfuse Cloud | `langfuse_enabled=False` или ключи неверны | Проверить `is_langfuse_enabled()` returns True; проверить ключи в Langfuse dashboard |
| `[LANGFUSE] Failed to start LLM trace: ...` | Network / Langfuse Cloud недоступен | Handler не падает (graceful), traces теряются. Проверить host/firewall |

## Быстрый доступ к дашборду

Команда `dashboard` автоматически проверяет, запущен ли сервер, стартует его при необходимости и открывает браузер:

```bash
# Открыть HTML Dashboard (автозапуск сервера)
python -m src.cli.main dashboard

# На другом порту
python -m src.cli.main dashboard --port 9000

# Без открытия браузера (только запуск сервера)
python -m src.cli.main dashboard --no-browser
```

### Ручной запуск API-сервера

Если нужен только сервер без открытия браузера:

```bash
# Через CLI
python -m src.cli.main server --port 8000

# Через uvicorn напрямую
python -m uvicorn src.api.app:create_app --factory --host 0.0.0.0 --port 8000
```

### Перезапуск сервера

Команда `restart` находит процесс на порту, останавливает его и запускает новый экземпляр в фоне:

```bash
# Перезапуск на порту по умолчанию (8000)
python -m src.cli.main restart

# Перезапуск на другом порту
python -m src.cli.main restart --port 9000

# Принудительное завершение (без graceful shutdown)
python -m src.cli.main restart --force
```

| Опция | Описание | Default |
|-------|----------|---------|
| `--host` | Хост сервера | `127.0.0.1` |
| `--port` | Порт сервера | `8000` |
| `--force`, `-f` | Завершить без ожидания graceful shutdown | `false` |

После запуска все `/metrics/*` эндпоинты доступны по адресу `http://localhost:8000`.

**Degraded mode:** Если Qdrant/Neo4j недоступны, сервер стартует в ограниченном режиме — метрики и health работают, search/index/chat вернут 500. Подробнее: [10.1 Частые ошибки](../10_УСТРАНЕНИЕ_НЕПОЛАДОК/10.1_Частые_ошибки.md#qdrant-не-доступен).

**Файлы:** `src/api/app.py` (фабрика `create_app`, degraded mode), `src/api/routes/metrics.py` (эндпоинты), `src/cli/main.py` (команда `dashboard`)

## HTML Dashboard

Визуальный дашборд системных метрик в браузере с автообновлением каждые 30 секунд.

**URL:** `http://localhost:8000/metrics/html`

### Секции дашборда

| Секция | Содержимое |
|--------|-----------|
| **Key Metrics** | 6 карточек: Total Queries, Queries Today, Avg Latency, P95 Latency, Cache Hit Rate, Error Rate |
| **Cache Statistics** | Таблица: Embedding Cache, LLM Response Cache, Document Cache (hits, misses, hit rate с progress bar) |
| **Search Strategy Usage** | Таблица стратегий поиска с долей использования (%) |
| **Hook Invocations** | Таблица хуков: Count, Avg/P95 ms, Blocks, Errors |
| **Skill Activations** | Карточки: Activation Rate, Recommended, Activated, Prompt Detection, PostToolUse. Таблица скиллов с колонкой Source (цветные теги по источнику) |
| **Enforcement & Errors** | Total Blocks, Block Rate, последние ошибки |
| **Try It** | Интерактивный поиск/RAG-запрос прямо из дашборда |

### Как работает

1. `GET /metrics/html` вызывает `get_metrics()` — сбор метрик из 4 источников:
   - `MetricsCollector` — общие метрики (queries, latency, errors)
   - `EmbeddingCache` — кеш эмбеддингов (hits/misses)
   - `LLMCache` — кеш LLM-ответов (hits/misses)
   - `DocumentCache` — кеш документов (hits/stale)
2. Значения подставляются в HTML-шаблон через `string.Template`
3. JavaScript автоматически перезагружает страницу каждые 30 секунд

### Цветовая индикация

| Метрика | Зелёный | Жёлтый | Красный |
|---------|---------|--------|---------|
| Cache Hit Rate | > 50% | 20-50% | < 20% |
| Error Rate | < 1% | 1-5% | > 5% |

## Hook Observability

Мониторинг хуков Claude Code (invocations, skill activations, latency):

### Hook Metrics DB

SQLite pipeline для инжеста JSONL-логов хуков в базу данных:

```python
from src.pdf_framework.observability.hook_metrics_db import HookMetricsDB

db = HookMetricsDB()
db.ingest_from_logs()

recent = db.get_recent_invocations(limit=100)
metrics = db.get_hook_metrics(hours=24)
skills = db.get_skill_metrics(hours=24)
# skills содержит: total_recommended, total_activated, activation_rate,
# by_source: {"prompt-detection": N, "post-tool-use": N},
# per_skill: {name: {recommended, activated, rate, sources: {source: count}}}
```

Таблицы `skill_activations` и `skill_accuracy` содержат колонку `source TEXT` для различения источников активаций (`prompt-detection` vs `post-tool-use`). Auto-migration добавляет колонку при обновлении.

**Файл:** `src/pdf_framework/observability/hook_metrics_db.py`

#### Cross-hook correlation (roadmap §3.3, 2026-05-09)

`invocations` schema расширена тремя полями: `run_id` (UUID slash-command run), `category` (hook / mcp_call / slash_run), `agent_id` (subagent monitoring). Поля приходят из JSONL уже с Phase 8 — auto-migration добавляет соответствующие колонки в существующих БД и индекс `idx_invocations_run_id` для быстрых cross-hook trace queries.

```python
# Полная цепочка хуков для одного slash-command run
trace = db.get_run_trace(run_id="abc123-...")
# → [{ts, hook, event, elapsed_ms, category, ...}, ...] в chronological order

# Топ дорогих/застрявших runs за последние 24 часа
expensive = db.get_run_summary(hours=24, min_invocations=2)
# → [{run_id, hook_count, total_ms, first_ts, last_ts}, ...] sorted by total_ms desc
```

**Откуда берётся run_id:** [`slash-command-tracker.py`](../../../.claude/hooks/slash-command-tracker.py) (UPS hook) генерирует UUID при запуске `/cmd`, складывает в [`data/.current-runs.json`](../../../data/.current-runs.json) через [`shared/run_context.py`](../../../.claude/hooks/shared/run_context.py). Все последующие hook-invocations в той же session подхватывают `run_id` через `shared.invocation_logger.log_invocation(run_id=...)`. MCP-логгер ([`mcp-invocation-logger.py`](../../../.claude/hooks/mcp-invocation-logger.py)) автоматически прицепляет тот же `run_id` к каждой записи MCP-вызова — даёт полный цепочный трейс slash-run → MCP calls → Stop.

## Retry Policy (resilience)

> Roadmap reference: [260509_ROADMAP_CONSOLIDATED_BACKLOG.md §3.7](../../../docs/roadmap/260509_ROADMAP_CONSOLIDATED_BACKLOG.md). Closed 2026-05-09.

Транзиентные I/O сбои (LLM rate limits, network blips, Qdrant temporary unavailability) обрабатываются через единый wrapper [`src/pdf_framework/utils/retry.py`](../../../src/pdf_framework/utils/retry.py) на базе `tenacity`. Этот же модуль предоставляет 4 pre-configured декоратора:

| Декоратор | Сценарий | Параметры |
|---|---|---|
| `@retry_llm_call` | LLM API (Anthropic/OpenAI) | 5 attempts / 120s, exp jitter, retries on Timeout/Connection/OS |
| `@retry_embedding` | Embedding service (TEI/OpenAI) | 5 attempts / 90s, exp jitter, +RuntimeError (CUDA/model load) |
| `@retry_db_operation` | Qdrant/SQLite write | 3 attempts, fixed 0.5s |
| `@retry_network` | HTTP запросы | 4 attempts / 60s, exp jitter |
| `create_retry(...)` | Кастомные параметры | factory с `max_attempts`, `max_delay`, `initial_wait`, `jitter`, `retry_on` |

**Ralph Wiggum loops vs transient retry**: в codebase есть `for attempt in range(...)` циклы которые **НЕ** являются transient retry — это semantic correction loops (LLM feedback injection, length/language/refusal validation per attempt). Они intentional и не должны мигрироваться на tenacity. Документация о таких exceptions находится в docstring [`utils/retry.py`](../../../src/pdf_framework/utils/retry.py).

**Тесты**: 16 unit-тестов в [`tests/test_retry.py`](../../../tests/test_retry.py) покрывают sync/async × LLM/DB/embedding/network/custom configs.
