# 09.6 Auto Git Save — автоматический коммит

> Система автоматического коммита изменений из хуков Claude Code.
> При каждом Write/Edit отслеживаемого файла — мгновенный `git add` + `git commit`.

---

## Обзор

Auto Git Save — sync-commit система, которая автоматически коммитит изменения в git при редактировании файлов через Claude Code. Хук `auto-git-save.py` срабатывает на каждый PostToolUse (Write/Edit/Bash) и при достижении порога файлов выполняет `git add` + `git commit` прямо из хука.

**Текущая конфигурация:** порог = 1 файл (каждое изменение = мгновенный коммит).

---

## Полный цикл работы

### Write/Edit отслеживаемого файла

```
Write/Edit файл → auto-git-save.py (PostToolUse)
                  │
                  ├─ should_track_file()? ─ НЕТ → выход
                  │   Проверяет:
                  │   - расширение (.py, .md, .json, ...)
                  │   - путь (src/, docs/, .claude/skills/, ...)
                  │   - не в ignore (cache/, __pycache__, ...)
                  │
                  ├─ sync_pending_tasks_with_git()     ← zombie prevention
                  │   Проверяет на каждый вызов:
                  │   - есть pending задачи от auto-git-save?
                  │   - файлы задачи уже закоммичены в git?
                  │   - если да → задача completed (zombie cleanup)
                  │   - учитывает untracked directories ("?? dir/")
                  │
                  ├─ file_count >= порог (1)? ─ ВСЕГДА ДА
                  │                             │
                  │                             └─ perform_sync_commit()
                  │                                ├─ git add -- <файл>
                  │                                ├─ git commit -m "chore: auto-commit 1 file(s)"
                  │                                ├─ complete_task_by_hook()
                  │                                └─ → [AUTO-GIT-SAVE OK] hash: abc1234
                  │
                  └─ commit failed?
                     └─ создать mandatory pending задачу для ручного коммита
                        └─ task-enforcer заблокирует Stop пока не закоммитишь
```

### Bash "git commit" (ручной коммит)

```
Bash "git commit" → auto-git-save.py (PostToolUse)
                    │
                    ├─ validate_cache()
                    │   └─ git diff --quiet -- <каждый файл>
                    │
                    ├─ все закоммичены? → complete_task_by_hook()
                    │                    → [GIT COMMIT COMPLETED]
                    │
                    └─ ещё есть? → ничего (задача остаётся)
```

## 3-уровневая защита

Система обеспечивает **три уровня** гарантий, что изменения не будут потеряны:

```
┌─────────────────────────────────────────────────────────┐
│  Уровень 1: СОЗДАНИЕ                                   │
│  auto-git-save.py → PostToolUse (Write|Edit|Bash)       │
│  Трекинг файлов → автокоммит или pending задача         │
├─────────────────────────────────────────────────────────┤
│  Уровень 2: НАПОМИНАНИЕ                                │
│  todo-sync.py → UserPromptSubmit                        │
│  hook-todos.json → systemMessage → TodoWrite            │
│  (на каждое сообщение пользователя проверяет pending)   │
├─────────────────────────────────────────────────────────┤
│  Уровень 3: БЛОКИРОВКА                                 │
│  task-enforcer.py → Stop                                │
│  sync_git_tasks_with_status() → block если pending      │
│                                                         │
│  git-commit-enforcer.py → Stop                          │
│  git status → block если dirty в watched paths          │
└─────────────────────────────────────────────────────────┘
```

### Уровень 1: Создание (auto-git-save.py)

**Событие:** PostToolUse (Write|Edit|Bash)
**Timeout:** 15 секунд

При каждом Write/Edit отслеживаемого файла:
1. Проверяет расширение и путь файла
2. Запускает zombie prevention (sync с git status)
3. Если порог достигнут — выполняет sync commit
4. Если коммит не удался — создаёт mandatory pending задачу

При Bash с `git commit`:
1. Проверяет какие файлы из кеша ещё не закоммичены
2. Если все закоммичены — завершает pending задачу

### Уровень 2: Напоминание (todo-sync.py)

**Событие:** UserPromptSubmit (каждое сообщение пользователя)
**Timeout:** 3 секунды

Читает `hook-todos.json` и если есть pending задачи от mandatory hooks — отправляет systemMessage с инструкцией добавить их в TodoWrite. Это обеспечивает видимость незавершённых задач в UI.

### Уровень 3: Блокировка (task-enforcer.py + git-commit-enforcer.py)

**Событие:** Stop (попытка завершения сессии)

**task-enforcer.py** (timeout 10s):
1. Запускает `sync_git_tasks_with_status()` — если git чистый, auto-complete задачи
2. Проверяет pending задачи от mandatory hooks
3. Если есть — блокирует Stop (exit code 2)

**git-commit-enforcer.py** (timeout 5s):
1. Проверяет `git status --porcelain`
2. Фильтрует по watched paths
3. Если есть незакоммиченные изменения — блокирует Stop

## Механизмы

### Sync Commit

При достижении порога выполняет коммит синхронно из хука:

1. `git status --porcelain` — проверка что есть изменения
2. `git add -- <файл>` — stage каждого отслеженного файла
3. `git commit -m "chore: auto-commit N file(s) changed"` — коммит
4. `complete_task_by_hook()` — завершение pending задачи
5. systemMessage `[AUTO-GIT-SAVE OK]` — уведомление Claude

### Zombie Task Prevention

Вызывается на **каждый** PostToolUse. Предотвращает ситуацию когда pending задача остаётся после того как файлы уже закоммичены (вручную или другим инструментом).

Алгоритм:
1. Получить uncommitted файлы из `git status --porcelain`
2. Отдельно трекать untracked directories (`?? dir/`)
3. Для каждой pending задачи проверить:
   - файл в uncommitted set? → uncommitted
   - файл внутри untracked directory? → uncommitted
4. Если ВСЕ файлы задачи уже закоммичены → задача completed

### Validate Cache

При ручном `git commit` через Bash:
1. Проверяет каждый файл из кеша через `git diff --quiet`
2. Если все закоммичены → `complete_task_by_hook()` + clear cache
3. Детектирует коммиты сделанные вне хука

### Adaptive Timeout

Timeout коммита масштабируется по количеству файлов:
- Формула: `max(15, min(base + files * per_file, 120))`
- Минимум: 15 секунд
- Максимум: 120 секунд

### Adaptive Cooldown

После завершения задачи — cooldown перед созданием новой (anti-spam):
- Формула: `max(COOLDOWN_BASE, 6 - file_count)` минут
- 1 файл → 5 минут cooldown
- 3 файла → 3 минуты
- 5+ файлов → 2 минуты

### Task Metadata

Файлы хранятся в metadata задачи (single source of truth):

```json
{
  "content": "Закоммитить незакоммиченные изменения - file1.py, file2.md",
  "metadata": {
    "files": ["src/main.py", "docs/README.md"],
    "first_change": "2026-02-21T14:00:00",
    "last_change": "2026-02-21T14:05:00"
  }
}
```

## Конфигурация

Все параметры настраиваются через переменные окружения:

| Переменная | Default | Описание |
|-----------|---------|----------|
| `CLAUDE_COMMIT_THRESHOLD` | **1** | Количество файлов до автокоммита |
| `CLAUDE_COMMIT_TIMEOUT_BASE` | 5 | Базовый timeout коммита (секунды) |
| `CLAUDE_COMMIT_TIMEOUT_PER_FILE` | 1 | Дополнительный timeout за каждый файл (секунды) |
| `CLAUDE_COMMIT_COOLDOWN_BASE` | 2 | Базовый cooldown после коммита (минуты) |

### Примеры конфигурации

**Мгновенный коммит** (текущая настройка):
```bash
CLAUDE_COMMIT_THRESHOLD=1  # каждое изменение = коммит
```

**Батчевый коммит** (накопление):
```bash
CLAUDE_COMMIT_THRESHOLD=5  # коммит каждые 5 файлов
```

## task_master.py API

Все задачи хранятся в `.claude/cache/hook-todos.json` (отдельно от TodoWrite). API обеспечивает атомарные операции с file locking.

| Функция | Описание |
|---------|----------|
| `add_task(title, priority, created_by)` | Создать pending задачу (с dedup check) |
| `complete_task(title, created_by)` | Завершить конкретную задачу по title |
| `complete_task_by_hook(hook_id)` | Завершить ВСЕ pending задачи хука |
| `get_pending_tasks(created_by)` | Получить pending задачи (опционально по creator) |
| `get_task_with_metadata(hook_id)` | Получить задачу с metadata |
| `update_task_metadata(hook_id, data)` | Обновить metadata задачи (merge или replace) |
| `has_recent_completion(hook_id, minutes)` | Cooldown check (anti-spam) |
| `cleanup_old_completed(max_age_hours, max_count)` | Удалить старые completed задачи (>24h) |
| `auto_validate_git_tasks()` | Sync git tasks при старте сессии |
| `session_start_cleanup()` | Полная очистка: cleanup + validate |

### Особенности реализации

- **Atomic writes** — temp file + rename (предотвращает corruption)
- **Cross-platform file locking** — msvcrt (Windows) + fcntl (Unix)
- **Stats self-validation** — автокоррекция при race conditions
- **STRICT MODE** — задачи помечаются completed, НЕ удаляются (audit trail)
- **Duplicate check** — одинаковые title + creator + pending не дублируются

## Типичные сценарии

### Сценарий 1: Нормальная работа

```
1. Claude редактирует src/main.py
2. auto-git-save.py срабатывает (PostToolUse: Edit)
3. Порог = 1 → sync commit
4. git add src/main.py && git commit
5. → [AUTO-GIT-SAVE OK] hash: abc1234
6. Работа продолжается
```

### Сценарий 2: Коммит не удался

```
1. Claude редактирует файл
2. auto-git-save.py → perform_sync_commit() → FAIL (pre-commit hook, конфликт, ...)
3. Создаётся mandatory pending задача
4. todo-sync.py покажет задачу при следующем сообщении пользователя
5. При попытке Stop → task-enforcer заблокирует
6. Claude должен закоммитить вручную
```

### Сценарий 3: Ручной коммит через Bash

```
1. Claude или пользователь: git commit -m "..."
2. auto-git-save.py срабатывает (PostToolUse: Bash, содержит "git commit")
3. validate_cache() проверяет файлы
4. Все закоммичены → complete_task_by_hook()
5. → [GIT COMMIT COMPLETED]
```

### Сценарий 4: Попытка завершить сессию

```
1. Пользователь завершает сессию
2. git-commit-enforcer.py: git status → есть dirty files?
   ├─ НЕТ → allow stop
   └─ ДА → block stop + инструкция закоммитить
3. task-enforcer.py: есть pending mandatory tasks?
   ├─ sync_git_tasks_with_status() → git clean? → auto-complete
   ├─ НЕТ pending → allow stop
   └─ ДА pending → block stop + список задач
```

## Troubleshooting

### Автокоммит не срабатывает

1. **Файл не в watched paths** — проверь что путь начинается с `src/`, `docs/`, `tests/`, `.claude/skills/`, `.claude/hooks/`
2. **Расширение не отслеживается** — проверь что расширение в списке tracked extensions
3. **Cooldown активен** — после коммита есть cooldown 2-5 минут
4. **Timeout хука** — если коммит занимает больше 15 секунд, хук прерывается

### Zombie задачи

Задача остаётся pending хотя файлы уже закоммичены:
- Zombie prevention запускается на каждый PostToolUse
- Если проблема сохраняется — `session_start_cleanup()` очистит при следующем запуске

### Stop заблокирован

```
[TASK-ENFORCER] N mandatory task(s) pending!
```

Решение:
1. Проверить `git status`
2. Закоммитить незакоммиченные файлы
3. Повторить попытку завершения
