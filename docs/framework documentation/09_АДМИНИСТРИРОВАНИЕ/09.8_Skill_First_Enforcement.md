# 09.8 Skill-First Enforcement

> Система принудительной опоры на скиллы: Claude обязан активировать скилл
> перед написанием кода, проверить результат после, и сохранить знания для будущих сессий.
>
> **Полная документация:** [11. Система скиллов](../11_СИСТЕМА_СКИЛЛОВ/11.1_Обзор.md) — архитектура, все 6 уровней A-F, каталог 57 скиллов, мониторинг и roadmap.

---

## Принцип

```
Прежде чем Claude что-то делает — проверь скилл-кеш.
После того как сделал — проверь результат против скилла.
Если скилла не было — создай его из полученного опыта.
```

Три фазы замкнутого цикла: **PRE** (проверь до) -> **POST** (проверь после) -> **LEARN** (сохрани знания).

---

## Как это работает

### Полная карта enforcement

```
Этап работы Claude           Фаза   Уровень  Действие             Принуд.
───────────────────────────────────────────────────────────────────────────
Пользователь пишет промпт  → PRE    router   Рекомендация          Советует
Claude пишет файл в dir/   → PRE    B        BLOCK                 100%
Claude пишет код с pattern  → PRE    A        BLOCK                 100%
Claude пишет код без skill  → PRE    fallback Research + Context7   Советует
Claude запускает Bash       → PRE    C        BLOCK                 100%
Claude ищет в интернете     → PRE    D        "Проверь кеш"         Советует
                                      │
                              ════════╪════════ действие выполнено
                                      │
Claude записал код          → POST   E        Verify vs skill       Task→Stop
Claude исследовал           → POST   F        LEARN: создать скилл  Task→Stop
Claude останавливается      → STOP   enforcer BLOCK если tasks      100%
                                      │
                              ════════╪════════ следующая сессия
                                      │
Тот же паттерн              → PRE    A        BLOCK (быстрый путь)  100%
```

## 6 уровней enforcement (A-F)

### Уровень A: Content Patterns (PRE)

Анализирует содержимое Write/Edit. Если код содержит паттерн, привязанный к скиллу — блокирует без активации.

**Примеры паттернов:**

| Паттерн (regex) | Скилл | Пример кода |
|-----------------|-------|-------------|
| `StateGraph\|add_node\|add_edge` | `langgraph-core` | `graph = StateGraph(...)` |
| `QdrantClient\|qdrant_client` | `tech-research` | `from qdrant_client import QdrantClient` |
| `BaseHook\|HookInput\|HookOutput` | `create-hook` | `class MyHook(BaseHook):` |
| `ВЫБРАТЬ.*ИЗ\|ОбработкаПроведения` | `1c-doc-research` | `ВЫБРАТЬ Номенклатура ИЗ` |
| `Dockerfile\|docker-compose` | `tech-research` | `FROM python:3.11` |
| `@pytest.fixture\|conftest` | `tech-research` | `@pytest.fixture` |

**Поведение:**
```
Write("from langgraph.graph import StateGraph")
  → Паттерн: StateGraph → Скилл: langgraph-core
  → Скилл активирован? НЕТ
  → EXIT 2 (BLOCK)
  → "Активируй скилл langgraph-core через Skill('langgraph-core')"
```

**Минимальная длина контента:** 20 символов (короче — пропускается).

### Уровень B: Directory Rules (PRE)

Проверяет путь файла. Запись в определённые директории требует соответствующего скилла.

| Директория | Требуемый скилл |
|-----------|-----------------|
| `.claude/hooks/` | `create-hook` |
| `.claude/skills/` | `doc-to-skill` |
| `src/mcp_server/` | `hooks-skills-mcp-triad` |
| `src/pdf_framework/agents/` | `langgraph-core` |
| `src/pdf_framework/search/` | `tech-research` |

**Приоритет:** Directory rules проверяются ПЕРЕД content patterns.

### Уровень C: Bash Rules (PRE)

Проверяет команды Bash. Определённые команды требуют скиллов.

| Команда | Требуемый скилл |
|---------|-----------------|
| `docker compose` | `tech-research` |
| `kubectl` | `tech-research` |
| `pytest` | `tech-research` |
| `streamlit run` | `framework-cli` |

**Поведение:**
```
Bash("docker compose up -d")
  → Паттерн: docker compose → Скилл: tech-research
  → EXIT 2 (BLOCK)
```

### Уровень D: Research Enforcement (POST)

После WebSearch/WebFetch проверяет, есть ли кеш по теме.

| Запрос | Кеш-путь |
|--------|---------|
| `qdrant collection` | `.claude/skills/tech-research/cache/` |
| `langchain agent` | `.claude/skills/langchain-core/cache/` |

**Поведение:** advisory systemMessage "Проверь кеш перед использованием результатов".

### Уровень E: Post-Verification (POST)

После Write/Edit проверяет, соответствует ли результат требованиям активированного скилла.

**Правила проверки:**

| Файл | Активный скилл | must_contain | must_not_contain |
|------|----------------|-------------|------------------|
| `agents/*.py` | `langgraph-core` | `StateGraph` | `AgentExecutor` |
| `.claude/hooks/*.py` | `create-hook` | `BaseHook` | — |

**Поведение:** если must_contain отсутствует или must_not_contain найден — advisory systemMessage + mandatory task.

### Уровень F: LEARN (POST)

Если на этапе PRE скилла не нашлось (Research Protocol), после Write/Edit создаёт задачи на обучение:

1. **Создать скилл** — `doc-to-skill` для оформления полученных знаний
2. **Зарегистрировать** — добавить в `skill-router-config.json`
3. **Мигрировать паттерн** — перенести из `research_protocol` в `patterns`

**Anti-spam:** cooldown 10 минут между LEARN-задачами.

## Research Protocol (fallback)

Когда паттерн найден, но скилла для него нет — вместо блокировки Claude получает протокол исследования.

### Для tech-домена (Python/ML/RAG)

```
Порядок исследования:
1. Context7 MCP → resolve-library-id → get-library-docs
2. StackOverflow → поиск по теме
3. GitHub → поиск по репозиториям
4. Применить Trust Scale к результатам
```

### Для 1С-домена

```
Порядок исследования:
1. infostart.ru → рейтинг, скачивания
2. GitHub → 1С-репозитории
3. its.1c.ru → официальная документация
4. Применить Trust Scale к результатам
```

## Trust Scorer — оценка доверия источников

Каждый источник информации оценивается по rubric (0.0 — 1.0):

### Context7 MCP

| Критерий | Вес | Значение |
|----------|-----|----------|
| Официальная документация | 1.0 | Всегда trust = 1.0 |

### GitHub

| Критерий | Вес | Порог |
|----------|-----|-------|
| Stars | 0.30 | >= 100 |
| Last commit | 0.25 | < 90 дней |
| Documentation | 0.25 | Есть README + docs/ |
| License | 0.20 | MIT / Apache / BSD |

### StackOverflow

| Критерий | Вес | Порог |
|----------|-----|-------|
| Accepted answer | 0.40 | Да / Нет |
| Votes | 0.30 | >= 10 |
| Recency | 0.30 | < 365 дней |

### Infostart.ru

| Критерий | Вес | Порог |
|----------|-----|-------|
| Rating | 0.35 | >= 4.0 |
| Downloads | 0.35 | >= 100 |
| Recency | 0.30 | < 365 дней |

**Использование:**
```python
from shared.trust_scorer import compute_score, format_trust_rubric

score = compute_score("github", {
    "stars": 500,
    "last_commit_days": 30,
    "has_docs": True,
    "license": "MIT"
})
# → 0.85

rubric = format_trust_rubric("github")
# → текстовое описание критериев для systemMessage
```

**Файл:** `.claude/hooks/shared/trust_scorer.py`

Context7 всегда первый в research protocol для tech-домена (trust = 1.0).

## code-skill-patterns.json

Конфигурационный файл с 7 секциями:

```json
{
  "version": "2.0",
  "patterns": [
    {
      "regex": "StateGraph|add_node|add_edge",
      "skill": "langgraph-core",
      "description": "LangGraph граф"
    }
  ],
  "directory_rules": [
    {
      "path": ".claude/hooks/",
      "skill": "create-hook"
    }
  ],
  "bash_rules": [
    {
      "regex": "docker\\s+compose",
      "skill": "tech-research"
    }
  ],
  "research_rules": [
    {
      "regex": "qdrant",
      "cache_path": "tech-research/cache/"
    }
  ],
  "research_protocol": [
    {
      "regex": "fastapi|FastAPI",
      "domain": "tech",
      "label": "FastAPI"
    }
  ],
  "post_verification": [
    {
      "file_pattern": "agents/",
      "skill": "langgraph-core",
      "must_contain": ["StateGraph"],
      "must_not_contain": ["AgentExecutor"]
    }
  ],
  "metadata": {
    "migration_history": []
  }
}
```

**Статистика:** 22 content patterns, 9 directory rules, 7 bash rules, 4 research rules, 3 research protocol, 7 post verification.

**Файл:** `.claude/hooks/shared/code-skill-patterns.json`

## Замкнутый цикл обучения

```
  Паттерн найден в коде
       │
       ├─ Скилл ЕСТЬ → [PRE] BLOCK → активируй скилл
       │                                    │
       │                              Claude пишет код
       │                                    │
       │                              [POST] проверь результат → OK
       │
       └─ Скилла НЕТ → [PRE] Research Protocol
                              │
                              ├─ Context7 / SO / GitHub / infostart
                              ├─ Claude применил знания (написал код)
                              ├─ [POST] проверил результат
                              │
                              └─ [LEARN]
                                    │
                                    ├─ 1. doc-to-skill → создать SKILL.md
                                    ├─ 2. Зарегистрировать в skill-router
                                    ├─ 3. Мигрировать: research → patterns
                                    │
                                    └─ Следующая сессия:
                                       Паттерн → скилл ЕСТЬ → быстрый путь
```

## Конфигурация

### Регистрация хука

`code-skill-enforcer.py` регистрируется на 3 события в `.claude/settings.json`:

```json
{
  "hooks": {
    "PreToolUse": [{
      "matcher": "Write|Edit|Bash",
      "hooks": [{
        "type": "command",
        "command": "python .claude/hooks/code-skill-enforcer.py",
        "timeout": 3
      }]
    }],
    "PostToolUse": [
      {
        "matcher": "Write|Edit",
        "hooks": [{
          "type": "command",
          "command": "python .claude/hooks/code-skill-enforcer.py",
          "timeout": 3
        }]
      },
      {
        "matcher": "WebSearch|WebFetch",
        "hooks": [{
          "type": "command",
          "command": "python .claude/hooks/code-skill-enforcer.py",
          "timeout": 3
        }]
      }
    ]
  }
}
```

### Интеграция с task-enforcer

`code-skill-enforcer` зарегистрирован в `MANDATORY_HOOKS` обоих enforcer-ов:
- `task-enforcer.py` — блокирует Stop при pending задачах от enforcer
- `task_master.py` — отслеживает задачи от enforcer

## Troubleshooting

### Claude заблокирован при написании кода

```
BLOCKED: Код содержит StateGraph. Сначала активируй скилл 'langgraph-core'.
```

**Решение:** Claude должен вызвать `Skill('langgraph-core')` и повторить попытку.

### Ложное срабатывание (false positive)

Если паттерн срабатывает на код, который не относится к скиллу:

1. Проверить `exclude_files` в `code-skill-patterns.json`
2. Если файл — часть самого enforcer, он исключён автоматически
3. Для нового исключения — добавить путь в `exclude_files` паттерна

### LEARN-задачи не создаются

Возможные причины:
- **Cooldown активен** — 10 минут после последнего LEARN
- **pending_learn пуст** — Research Protocol не был вызван
- **Скилл уже активирован** — LEARN не нужен

### Latency хука

Ожидаемая задержка: 50-100ms (avg=74ms, p95=79ms).
Если больше — проверить:
- Размер `code-skill-patterns.json` (regex-ы компилируются при первом вызове)
- Чтение `session_state.py` (диск I/O)
