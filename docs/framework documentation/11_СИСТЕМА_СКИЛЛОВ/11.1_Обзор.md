# 11.1 Обзор системы скиллов

> Система скиллов — замкнутый цикл PRE → POST → LEARN, который обеспечивает
> использование накопленных знаний при каждом действии Claude Code.

---

## Проблема

Claude Code по умолчанию начинает каждую задачу с нуля. Даже если в проекте уже есть
документированные паттерны, архитектурные решения и проверенные подходы — Claude не знает
о них, пока явно не получит этот контекст. Результат:

- Код противоречит принятым в проекте конвенциям
- Одни и те же ошибки повторяются из сессии в сессию
- Архитектурные решения (ADR) игнорируются
- Знания, накопленные в предыдущих сессиях, теряются

## Решение: замкнутый цикл PRE → POST → LEARN

Система скиллов решает эту проблему через три фазы:

```
┌─────────────────────────────────────────────────────────────────┐
│                    ЗАМКНУТЫЙ ЦИКЛ СКИЛЛОВ                       │
│                                                                 │
│   ┌──────────┐     ┌──────────┐     ┌──────────┐               │
│   │   PRE    │────>│   POST   │────>│  LEARN   │──┐            │
│   │          │     │          │     │          │  │            │
│   │ Проверь  │     │ Проверь  │     │ Сохрани  │  │            │
│   │ скилл    │     │ результат│     │ знания   │  │            │
│   │ ДО кода  │     │ ПОСЛЕ    │     │ для      │  │            │
│   │          │     │ кода     │     │ будущего  │  │            │
│   └──────────┘     └──────────┘     └──────────┘  │            │
│        ^                                          │            │
│        └──────────────────────────────────────────┘            │
│                   Новый скилл доступен                          │
└─────────────────────────────────────────────────────────────────┘
```

| Фаза | Что происходит | Компонент |
|------|---------------|-----------|
| **PRE** | Рекомендация и принуждение к использованию скиллов ДО написания кода | skill-router + code-skill-enforcer + task-protocol-enforcer |
| **POST** | Верификация написанного кода ПОСЛЕ выполнения (must_contain / must_not_contain) | code-skill-enforcer (Level E) |
| **LEARN** | Создание нового скилла через Skill('learning-loop'), если подходящего не нашлось | code-skill-enforcer (Level A.1 BLOCK + Level F advisory) |

## Три ключевых компонента

### 1. Skill Router (`skill-router.py`)

**Событие:** UserPromptSubmit (каждый промпт пользователя)

Маршрутизатор анализирует текст промпта и рекомендует релевантные скиллы.
Использует 4 слоя матчинга: phrase matching, fuzzy matching, TF-IDF semantic, intent classification.

Вывод в stdout (100% injection rate):
```
[SKILL-ROUTER] Bundles: langchain-core, langchain-infra
Рекомендованные скиллы: langchain-core, langgraph-core
Опционально (по контексту): langchain-multiagent

ACTIVATE SKILLS [HIGH]: Skill('langchain-core'), Skill('langgraph-core')
You MUST call Skill('langchain-core'), Skill('langgraph-core') BEFORE writing any code.
```

### 2. Code Skill Enforcer (`code-skill-enforcer.py`)

**Событие:** PreToolUse (Write, Edit, Bash) и PostToolUse (Write, Edit, WebSearch, WebFetch)

Принуждает к использованию скиллов через 6 уровней (A–F):
- **PRE-уровни (A, B, C):** блокируют Write/Edit/Bash, пока скилл не активирован
- **POST-уровни (D, E, F):** advisory — проверка результатов, напоминания, создание задач

### 3. Task Protocol Enforcer (`task-protocol-enforcer.py`)

**Событие:** PreToolUse (Write, Edit)

Гарантирует выполнение полного алгоритма задачи:
```
idle → classified → decomposed → skill_checked → [ALLOW Write/Edit]
```

Только фаза `skill_checked` (после вызова `Skill()`) разрешает запись кода.

## Как скилл попадает в контекст Claude

1. Пользователь отправляет промпт
2. `skill-router.py` анализирует текст → выводит рекомендацию в stdout
3. Claude видит рекомендацию как часть контекста
4. Claude вызывает `Skill('skill-name')` — инструмент Claude Code
5. Claude Code читает файл `.claude/skills/<skill-name>/SKILL.md`
6. Содержимое SKILL.md инжектится как промпт в контекст Claude
7. Claude действует с учётом знаний из скилла

```
Промпт пользователя
        │
        ▼
┌─────────────────┐
│  skill-router   │  UserPromptSubmit
│  (4 слоя)       │  stdout → рекомендация
└────────┬────────┘
         │
         ▼
┌─────────────────┐
│  Claude видит:  │  "ACTIVATE SKILLS [HIGH]: Skill('X')"
│  рекомендацию   │
└────────┬────────┘
         │
         ▼
┌─────────────────┐
│  Skill('X')     │  Claude Code Tool
│  → читает       │  .claude/skills/X/SKILL.md
│  → инжектит     │  → как промпт в контекст
└────────┬────────┘
         │
         ▼
┌─────────────────┐
│  Claude пишет   │  С учётом знаний из скилла
│  код            │  task-protocol-enforcer: phase=skill_checked → ALLOW
└────────┬────────┘
         │
         ▼
┌─────────────────┐
│  code-skill-    │  PostToolUse → Level E/F
│  enforcer       │  Верификация + LEARN
└─────────────────┘
```

## SessionState — центральное хранилище

Все компоненты координируются через `SessionState` (файл `data/session-skills.json`):

| Поле | Назначение |
|------|-----------|
| `activated_skills` | Список активированных скиллов в текущей сессии |
| `recommended_skills` | Список рекомендованных скиллов (для dedup) |
| `pending_learn` | Данные для LEARN-фазы (label, domain, pattern) |
| `task_protocol.phase` | Текущая фаза протокола: idle/classified/decomposed/skill_checked |
| `router_fired_at` | Метка времени последней рекомендации (для dedup) |
| `current_prompt_id` | ID для корреляции recommend ↔ activate |
