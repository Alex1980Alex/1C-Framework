## BaseHook протокол

Все хуки наследуются от `BaseHook` ([base/protocol.py](../../../.claude/hooks/base/protocol.py)):

```python
class BaseHook(ABC):
    @abstractmethod
    def execute(self, inp: HookInput) -> Optional[HookOutput]:
        ...

    def run(self) -> None:
        # 1. Читает stdin → HookInput
        # 2. Вызывает execute()
        # 3. Если результат — emit stdout JSON
        # 4. Логирует invocation (always)
        # 5. При ошибке — sys.exit(0) (graceful degradation)
```

### HookInput (stdin JSON → объект)

```python
class HookInput:
    prompt: str          # UserPromptSubmit: текст промпта
    tool_name: str       # PreToolUse/PostToolUse: имя инструмента
    tool_input: dict     # Параметры инструмента
    tool_result: str     # PostToolUse: результат
    transcript: str      # Stop: транскрипт сессии
    session_id: str      # Идентификатор сессии

    @property
    def detected_event(self) -> str:
        # Авто-определение: PreToolUse | PostToolUse | UserPromptSubmit | Stop
```

### HookOutput (builder → stdout JSON)

```python
class HookOutput:
    def allow(self) -> HookOutput            # Разрешить (по умолчанию)
    def block(self, reason: str) -> HookOutput  # Заблокировать (exit code 2)
    def system_message(self, msg: str) -> HookOutput  # Инжектировать сообщение
    def modified_input(self, new_input) -> HookOutput  # Модифицировать ввод
    def claude_fallback(self, hook_name, prompt, priority) -> HookOutput  # Запрос fallback-действия
```

**Протокол блокировки:**
- `block()` устанавливает `{"continue": false, "decision": "block", "reason": "..."}`
- После `emit()` хук возвращает exit code 2
- Claude видит причину блокировки и может исправить действие

## SessionState — центральное хранилище

Файл: `data/session-skills.json`

```json
{
  "activated_skills": ["langchain-core", "langgraph-core"],
  "recommended_skills": ["langchain-core", "langgraph-core", "langchain-multiagent"],
  "pending_learn": null,
  "session_id": "a1b2c3d4e5f67890",
  "created_at": "2026-03-03T10:00:00",
  "last_updated": "2026-03-03T10:15:00",
  "task_protocol": {
    "phase": "skill_checked",
    "complexity": "medium",
    "subtask_count": 3,
    "decomposed_at": "2026-03-03T10:05:00",
    "skill_checked_at": "2026-03-03T10:10:00"
  },
  "router_fired_at": "2026-03-03T10:01:00",
  "current_prompt_id": "abc12345"
}
```

### Фазы task_protocol

```
idle ──────> classified ──────> decomposed ──────> skill_checked
  │              │                   │                   │
  │  UserPrompt  │   TaskCreate()    │    Skill()        │
  │  Submit      │   hook:observer   │    hook:observer   │
  │              │                   │                    │
  │              └───────────────────┴──> Только эта ─────┘
  │                                      фаза разрешает
  └──> BLOCK Write/Edit                  Write/Edit
```

| Фаза | Кто устанавливает | Что разрешено |
|------|------------------|---------------|
| `idle` | Начало промпта (reset) | Ничего (Read, Glob, Grep — не блокируются) |
| `classified` | `skill-eval-enforcer-shell.py` | Ничего (Write/Edit заблокированы) |
| `decomposed` | `task-protocol-observer.py` при TaskCreate | Ничего (Write/Edit заблокированы) |
| `skill_checked` | `task-protocol-observer.py` при Skill() | **Write/Edit разрешены** |

## Координация хуков

### Порядок на UserPromptSubmit

1. `skill-router.py` — рекомендует скиллы → устанавливает `router_fired_at`
2. `skill-eval-enforcer-shell.py` — классифицирует задачу → проверяет `router_fired_at` для dedup

### Порядок на PreToolUse:Write

1. `task-protocol-enforcer.py` — проверяет `phase == skill_checked`
2. `code-skill-enforcer.py` — проверяет уровни B → A → A.1 → C

Если первый хук блокирует — второй не выполняется (Claude видит ошибку и корректирует).

### Session Dedup (TIER 3)

Router отслеживает `recommended_skills` в SessionState. Если скилл уже рекомендовался
в текущей сессии — он не рекомендуется повторно. Это предотвращает спам одинаковыми
рекомендациями при серии связанных промптов.

### Router-Enforcer координация

`router_fired_at` позволяет enforcer'у пропустить дублирующие рекомендации:
если router уже сработал менее 10 секунд назад — enforcer не добавляет
свои рекомендации поверх.

## Файлы-исключения

Task Protocol Enforcer не блокирует запись в:

| Категория | Примеры |
|-----------|---------|
| Каталоги | `.claude/`, `docs/`, `data/`, `.github/` |
| Расширения | `.json`, `.toml`, `.yml`, `.yaml`, `.env`, `.cfg`, `.ini` |
| Не-код | `.md`, `.txt`, `.csv`, `.log`, `.rst` |
| Dotfiles | Файлы начинающиеся с `.` |

Это позволяет свободно редактировать конфигурацию, документацию и данные без прохождения
полного протокола задач.

## Graceful Degradation

Каждый компонент следует принципу "никогда не блокируй на внутренней ошибке":

```python
except Exception as e:
    # Логировать ошибку
    sys.exit(0)  # ALLOW — не блокировать Claude
```

- Если `session_state.py` недоступен → enforcer пропускает проверку
- Если `fuzzy_match` или `tfidf_scorer` не установлены → router работает без этих слоёв
- Если `code-skill-patterns.json` повреждён → enforcer загружает пустую конфигурацию
- Переменная `SKILL_ROUTER_NO_TFIDF` отключает Layer C для ablation testing
