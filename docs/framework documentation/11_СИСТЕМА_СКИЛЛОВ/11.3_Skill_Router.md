# 11.3 Skill Router

> Маршрутизатор скиллов: 4 слоя матчинга, конфигурация бандлов, affinities,
> session dedup, workflow detection, intent classification.

---

## Обзор

Skill Router ([skill-router.py](../../../.claude/hooks/skill-router.py)) — хук на событие
`UserPromptSubmit`, который анализирует каждый промпт пользователя и рекомендует
релевантные скиллы. Это первая линия системы: определяет, какие знания нужны Claude.

**Характеристики:**
- Событие: UserPromptSubmit
- Timeout: 5 секунд
- Конфигурация: [skill-router-config.json](../../../.claude/skills/skill-router-config.json) (v8)
- Вывод: stdout (100% injection rate)

---

## 4 слоя матчинга

Router последовательно применяет 4 слоя для определения релевантных бандлов:

```
┌─────────────────────────────────────────────────────────────┐
│  Промпт пользователя                                        │
│      │                                                       │
│      ├──> Layer A: Phrase Matching (exact substring)          │
│      │    keywords: +1, weighted_keywords: +N                │
│      │                                                       │
│      ├──> Layer B: Fuzzy Matching (pymorphy3 + RapidFuzz)    │
│      │    threshold: 78%, single words only, +1              │
│      │                                                       │
│      ├──> Layer C: TF-IDF Semantic (char n-grams, cosine)    │
│      │    top_k: 2, strong: +1, moderate: +1                 │
│      │                                                       │
│      └──> Layer D: Intent Classification                     │
│           system → skip | informational → raise threshold    │
│                                                              │
│  Итоговый score = сумма A + B + C                            │
│  Фильтр: score >= min_score (2)                              │
│  Ранжирование: top max_bundles (2)                           │
└─────────────────────────────────────────────────────────────┘
```

### Layer A: Phrase Matching

Точное вхождение подстроки в prompt (lowercase).

**Standard keywords** (вес 1):
```json
"keywords": ["langchain agent", "multi-agent", "handoff"]
```
Каждое совпадение добавляет +1 к score бандла.

**Weighted keywords** (вес N):
```json
"weighted_keywords": {
  "create_agent": 5,
  "@tool": 4,
  "StateGraph": 5
}
```
Совпадение добавляет указанный вес. Это позволяет высокоспецифичным терминам
давать больший вклад в score.

**Предобработка промпта:**
- Приведение к lowercase
- Удаление файловых путей (regex `[a-zA-Z]:\\[^\s>]*|/[^\s>]*\.\w+`) — предотвращает
  ложные срабатывания на путях вроде `D:\1С-Framework\` (ключевое слово "1с")

### Layer B: Fuzzy Matching

Нечёткий матчинг для обработки опечаток и морфологических вариаций.

**Зависимости:**
- `pymorphy3` — лемматизация русского/английского текста
- `rapidfuzz` — нечёткое сравнение строк (алгоритм Levenshtein)

**Параметры:**
- Threshold: 78% similarity
- Только single-word keywords (multi-word фразы — через Layer A)
- Каждое нечёткое совпадение: +1 к score бандла
- Не добавляет +1, если Layer A уже нашёл это ключевое слово (dedup)

**Graceful degradation:** если зависимости не установлены → Layer B пропускается.

### Layer C: TF-IDF Semantic

Семантический матчинг через предвычисленные TF-IDF векторы.

**Артефакты** (каталог `data/route-tfidf/`):
- `vocabulary.json` — словарь char n-grams (2-4 символа)
- `idf.npy` — IDF веса
- `centroids.json` — центроиды бандлов (средний TF-IDF вектор utterances)

**Алгоритм:**
1. Промпт → char n-grams (2-4) → TF-IDF вектор
2. Cosine similarity с центроидами каждого бандла
3. Top-K фильтр (top_k=2)
4. Similarity → bonus score через thresholds

**Thresholds** (из config):
```json
"tfidf_thresholds": {
  "strong": 0.40,      "strong_bonus": 1,
  "moderate": 0.25,    "moderate_bonus": 1,
  "weak": 0.99,        "weak_bonus": 0,
  "top_k": 2
}
```

| Similarity | Bonus |
|-----------|-------|
| >= 0.40 (strong) | +1 |
| >= 0.25 (moderate) | +1 |
| >= 0.99 (weak) | +0 (фактически отключен) |
| < 0.25 | 0 |

**Пересборка артефактов:**
```bash
python scripts/build-route-embeddings.py
```

**Graceful degradation:**
- Переменная `SKILL_ROUTER_NO_TFIDF` → Layer C отключен
- numpy не установлен → Layer C пропускается
- Артефакты не собраны → Layer C пропускается

### Layer D: Intent Classification

Классификация намерения промпта для корректировки порогов.

```python
_INFO_MARKERS = [
    "что такое", "как работает", "объясни", "расскажи",
    "what is", "how does", "explain", "describe", ...
]
_SYSTEM_PREFIXES = ("/", "!!", "git ", "cd ")
```

| Intent | Правило | Действие |
|--------|---------|----------|
| `system` | Начинается с `/`, `!!`, `git `, `cd ` | **Skip** — рекомендации не выдаются |
| `informational` | Содержит маркеры "что такое", "explain" и т.д. | Порог поднимается до **6** |
| `action` | По умолчанию | Стандартный порог (min_score=2) |

Повышенный порог для informational предотвращает ложные рекомендации на вопросы
"что такое LangChain?" — нужны и keyword-матч И semantic-матч одновременно.

```json
{
  "version": 8,

  "min_score": 2,
  "max_bundles": 2,
  "min_score_gap": 2
```

| Параметр | Значение | Описание |

## Scoring: как считается итоговый score

```
score(bundle) = Σ(Layer A keywords × 1)
              + Σ(Layer A weighted_keywords × weight)
              + Σ(Layer B fuzzy matches × 1)
              + Σ(Layer C TF-IDF bonus for top-K)
```

**Пример:**
```
Промпт: "создай langchain agent с StateGraph"

Layer A: "langchain agent" in keywords → +1
         "langchain" in weighted_keywords (2) → +2
         "StateGraph" in weighted_keywords (5) → +5
Layer B: (нет новых fuzzy матчей)
Layer C: cosine sim=0.35 (moderate) → +1

Итого: score = 1 + 2 + 5 + 1 = 9
```

### Confidence levels

Определяются по top score первого бандла:

| Top Score | Confidence | Значение |
|-----------|-----------|----------|
| >= 4 | HIGH | Высокая уверенность, обязательно активировать |
| >= 3 | MEDIUM | Средняя уверенность |
| < 3 | LOW | Низкая уверенность (но score >= min_score) |

## Session Dedup (TIER 3)

Router отслеживает уже рекомендованные скиллы через `SessionState.recommended_skills`:

1. При каждом промпте: загрузить `recommended_skills` из session state
2. Отфильтровать скиллы, которые уже рекомендовались
3. Если все скиллы уже рекомендовались → `return None` (пропустить)
4. Записать новые рекомендации в session state

Это предотвращает повторные рекомендации одних и тех же скиллов в рамках одной сессии.

## Workflow Detection (TIER 4)

Бандлы могут указывать `"workflow": "research|brainstorm|hybrid"`.

Если matched бандл имеет workflow — Router добавляет инструкцию по workflow:

| Workflow | Инструкция |
|----------|-----------|
| `research` | Определи домен → используй `1c-doc-research` / `tech-research` / `architecture-research` |
| `brainstorm` | task-evaluation Brainstorm Workflow: 5 шагов от проблемы до ADR |
| `hybrid` | Research + Brainstorm: domain skill (фазы 0-5) + task-evaluation (фазы 1-5) |

Router выводит в stdout (не systemMessage — 100% injection rate vs 55%):

```

Рекомендованные скиллы: langchain-core, langgraph-core
Опционально (по контексту): langchain-multiagent, langchain-streaming
Аффинные скиллы (связанные): langchain-tutorials

[WORKFLOW: RESEARCH] Задача на исследование...

You MUST call Skill('langchain-core'), Skill('langgraph-core') BEFORE writing any code.
Do NOT skip — these skills contain critical project-specific knowledge.
```

## Prompt ID и Accuracy Tracking

Для каждой рекомендации генерируется `prompt_id` (MD5 hash timestamp + prompt[:80]):

1. Router генерирует `prompt_id` → сохраняет в `SessionState.current_prompt_id`
2. Router пишет `{"type": "recommend", "prompt_id": "abc12345", "skills": [...]}` в `data/skill-accuracy.jsonl`
3. При активации скилла (detect через `<command-name>` tags) → пишет `{"type": "activate", "prompt_id": "abc12345"}`
4. Correlation: recommend → activate по prompt_id показывает конверсию рекомендаций

## Фильтрация IDE-событий

Router пропускает промпты, которые являются IDE-метаданными (не пользовательским вводом):

```python
if prompt_stripped.startswith(("<ide_", "<file_", "<selection", "<cursor")):
    return None
if prompt_stripped.count("<") > len(prompt_stripped) / 10:
    return None  # Слишком много XML тегов — IDE dump
```
