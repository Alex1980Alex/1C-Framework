# 11.5 Формат и создание скиллов

> Структура SKILL.md, YAML frontmatter, cache/, конвенции именования,
> как Skill() загружает файл, workflow создания.

---

## Структура каталога скилла

```
.claude/skills/<skill-name>/
├── SKILL.md           # Главный файл (YAML frontmatter + markdown)
├── cache/             # Накопленные знания (опционально)
│   ├── topic-a.md
│   └── topic-b.md
└── adr/               # Архитектурные решения (опционально)
    └── 001-choice.md
```

| Файл/каталог | Назначение | Обязательный |
|-------------|-----------|-------------|
| `SKILL.md` | Основное содержимое скилла (инжектится в контекст Claude) | Да |
| `cache/` | Накопленные знания, результаты исследований, проверенные факты | Нет |
| `adr/` | Architecture Decision Records — зафиксированные решения | Нет |

## Формат SKILL.md

### YAML Frontmatter

```yaml
---
name: langgraph-core
description: |
  LangGraph ядро: StateGraph, Functional API, nodes, edges, state.
  Триггеры: 'langgraph', 'StateGraph', 'add_node', 'add_edge',
  'conditional_edges', 'entrypoint', '@task', 'Command'.
---
```

| Поле | Тип | Описание |
|------|-----|----------|
| `name` | string | Уникальное имя скилла (kebab-case) |
| `description` | string | Описание + триггеры для Skill Router. Триггеры в формате `'keyword1', 'keyword2'` |

Поле `description` служит двойную цель:
1. Описывает содержимое скилла для человека
2. Перечисляет триггеры — ключевые слова, по которым Skill Router рекомендует этот скилл

### Markdown содержимое

После frontmatter — стандартный markdown:

```markdown
# Название скилла

> Краткое описание (1-2 предложения)

---

## Секция 1: Концепты
...

## Секция 2: API Reference
...

## Секция 3: Примеры
```python
# Код с примерами
```

## Секция 4: Чеклист
- [ ] Проверить X
- [ ] Убедиться в Y

## Секция 5: Anti-patterns
- НЕ делать Z
```

### Рекомендуемая структура секций

| Секция | Содержимое |
|--------|-----------|
| Заголовок (H1) | Название + краткое описание |
| Концепты | Ключевые понятия, определения |
| API / Синтаксис | Ссылки на API, параметры, типы |
| Паттерны / Шаблоны | Готовые code snippets |
| Примеры | Реальные примеры из проекта |
| Чеклист | Обязательные проверки |
| Anti-patterns | Что НЕ делать |
| Cache | Ссылки на cache/ файлы |

## Конвенции именования

| Правило | Пример |
|---------|--------|
| kebab-case для имён | `langgraph-core`, `1c-doc-research` |
| Домен как префикс (опционально) | `claude-code-settings`, `1c-query-language` |
| Каталог = имя скилла | `.claude/skills/langgraph-core/` |
| SKILL.md — всегда uppercase | `.claude/skills/langgraph-core/SKILL.md` |
| Cache файлы — kebab-case | `cache/qdrant-api-reference.md` |

## Как Skill() загружает файл

Когда Claude вызывает `Skill('skill-name')`:

```
1. Claude Code получает вызов Skill('langgraph-core')
2. Ищет файл: .claude/skills/langgraph-core/SKILL.md
3. Читает содержимое SKILL.md
4. Инжектит содержимое в контекст Claude как промпт
5. Claude видит полный текст скилла — все инструкции, паттерны, примеры
6. Все последующие действия Claude учитывают эти знания
```

**Что видит Claude после Skill():**
```
<command-name>langgraph-core</command-name>
[Полное содержимое SKILL.md]
```

Тег `<command-name>` используется для:
- Отображения, что скилл активирован
- Детекции активации в `skill-router.py` → `_detect_skill_activations()`
- Записи в `SessionState.activated_skills`

## Cache: накопленные знания

Каталог `cache/` содержит результаты исследований, проверенные факты, API-ссылки:

```
.claude/skills/tech-research/cache/
├── qdrant-api-reference.md
├── langchain-tools-api.md
├── sentence-transformers-models.md
└── colbert-reranking.md
```

**Когда использовать cache:**
- Результаты WebSearch/WebFetch — сохранять для будущих сессий
- API-документация — стабильные ссылки и параметры
- Проверенные паттерны — рабочие code snippets

**Формат cache-файла:**
```markdown
# Topic Name

> Source: URL or reference
> Date: 2026-03-03
> Trust: 0.95 (Context7)

## Содержимое
...
```

## Workflow создания скиллов

### Вариант 1: doc-to-skill (автоматический)

Скилл `doc-to-skill` конвертирует существующую документацию:

```
Skill('doc-to-skill')
→ Указать исходный файл (MD/TXT)
→ Скилл автоматически:
  - Создаёт YAML frontmatter
  - Структурирует секции
  - Добавляет триггеры
  - Создаёт SKILL.md
```

### Вариант 2: triad-factory (через фабрику)

Скилл `triad-factory` создаёт полный компонент триады (Hook + Skill + MCP tool):

```
Skill('triad-factory')
→ Ответить на вопросы Q1-Q5
→ Фабрика создаёт:
  - .claude/skills/<name>/SKILL.md
  - .claude/hooks/<name>.py (если нужен hook)
  - Регистрацию в config
```

### Вариант 3: Вручную

1. Создать каталог: `.claude/skills/<name>/`
2. Создать `SKILL.md` с YAML frontmatter
3. Написать содержимое
4. Зарегистрировать в `skill-router-config.json`

---

## Регистрация в skill-router-config.json

После создания скилла его нужно зарегистрировать для маршрутизации:

### Шаг 1: Определить домен

Выбрать из 6 доменов: `1c`, `framework`, `claude-code`, `langchain`, `research`, `tools`

### Шаг 2: Найти или создать бандл

Если существующий бандл подходит — добавить скилл в `skills` или `optional`.
Если нет — создать новый бандл.

### Шаг 3: Добавить бандл в config

```json
"my-new-bundle": {
  "keywords": ["keyword1", "keyword2"],
  "weighted_keywords": {
    "specific-term": 4
  },
  "utterances": [
    "example prompt that should trigger this bundle",
    "пример промпта на русском"
  ],
  "skills": ["my-new-skill"],
  "optional": []
}
```

### Шаг 4: Добавить в domains

```json
"domains": {
  "framework": [..., "my-new-bundle"]
}
```

### Шаг 5: Пересобрать TF-IDF артефакты

```bash
python scripts/build-route-embeddings.py
```

### Шаг 6: Протестировать

```bash
python scripts/eval-skill-router.py --verbose
```

```
.claude/skills/tenacity-retry/
├── SKILL.md
└── cache/
    └── tenacity-patterns.md
```

```yaml

name: tenacity-retry

  Retry с tenacity: декораторы, backoff, jitter, async.

  'jitter', 'retry decorator', 'повторные попытки'.
  НЕ для LangGraph RetryPolicy — используй langgraph-core.

```

# Tenacity Retry Patterns

> Готовые паттерны retry для проекта с exponential backoff и jitter.

## Базовый паттерн
\```python
from tenacity import retry, stop_after_attempt, wait_exponential

@retry(stop=stop_after_attempt(3), wait=wait_exponential(multiplier=1, max=10))
def call_api():
    ...
\```

## Async-паттерн
...

## Чеклист
- [ ] Всегда указывать stop condition
- [ ] Использовать exponential backoff для API
- [ ] Добавить jitter для конкурентных запросов
```
