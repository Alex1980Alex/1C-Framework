## Фазы развития

### Phase 14 (DONE): TF-IDF Layer C

Что реализовано:
- TF-IDF scorer на char 2-4 n-grams
- Предвычисленные артефакты в `data/route-tfidf/`
- Top-K фильтр (top_k=2)
- Configurable thresholds (strong/moderate/weak)
- Ablation: `SKILL_ROUTER_NO_TFIDF` переменная

### Phase 15 (PLANNED): LEARN — Auto-Correction

**Цель:** автоматическая коррекция маршрутизации из логов.

Планируемые фичи:
- Анализ `skill-accuracy.jsonl`: recommend без activate → possible false positive
- Анализ `hook-invocations.jsonl`: block events → what skills are missing
- Автоматическое предложение новых keywords/weighted_keywords
- Feedback loop: если пользователь игнорирует рекомендацию N раз → снизить вес

Реализация:
```
1. Скрипт scripts/learn-from-logs.py
2. Чтение skill-accuracy.jsonl за последние 7 дней
3. Выявление паттернов: low activation rate per bundle
4. Генерация предложений: add/remove keywords
5. Вывод как PR или как TaskCreate задачи
```

### Phase 16 (PLANNED): SCALE — Hierarchical Routing

**Цель:** масштабирование до 50-100+ скиллов.

Проблема: при 50+ бандлах линейный перебор всех keywords становится медленным,
а TF-IDF центроиды — менее дискриминативными.

Планируемое решение:
- Двухуровневая маршрутизация: Domain → Bundle
- Сначала определить домен (1c/framework/claude-code/langchain/research/tools)
- Затем маршрутизировать только в бандлах этого домена
- Threshold адаптация per-domain (1С-домен может требовать другие пороги)

### Phase 17 (PLANNED): OBSERVE — Production Observability

**Цель:** полноценная наблюдаемость в production.

Планируемые фичи:
- OTEL traces для всей цепочки recommend → activate → write → verify
- Grafana dashboard с real-time метриками
- Alerting: activation rate падает ниже порога → уведомление
- A/B testing: сравнение config versions через evaluation

## Как добавить новый бандл

Пошаговая инструкция:

### Шаг 1: Определить потребность

- Есть промпты, на которые Router не реагирует?
- Есть скиллы, которые не маршрутизируются?
- Evaluation показывает false negatives для определённой темы?

### Шаг 2: Создать скилл (если нет)

```bash
mkdir -p .claude/skills/my-new-skill
# Создать SKILL.md с YAML frontmatter + содержимое
```

### Шаг 3: Добавить бандл в config

Редактировать `.claude/skills/skill-router-config.json`:

```json
"my-new-bundle": {
  "keywords": [
    "keyword1",
    "keyword2 phrase"
  ],
  "weighted_keywords": {
    "very-specific-term": 5,
    "moderately-specific": 3
  },
  "utterances": [
    "natural language prompt example in english",
    "пример промпта на русском языке",
    "another variation of the same intent",
    "ещё одна вариация того же намерения"
  ],
  "skills": ["my-new-skill"],
  "optional": ["related-skill"],
  "workflow": null
}
```

**Рекомендации:**
- 5-10 keywords (mix single words + phrases)
- 3-5 weighted_keywords (самые специфичные термины, вес 3-5)
- 8-12 utterances (по 4-6 на каждом языке)
- `skills` — обязательные скиллы для этой темы
- `optional` — скиллы, которые могут пригодиться

### Шаг 4: Зарегистрировать в domains

```json
"domains": {
  "framework": [..., "my-new-bundle"]
}
```

### Шаг 5: Добавить affinities (опционально)

```json
"affinities": {
  "my-new-skill": ["related-skill-1", "related-skill-2"]
}
```

### Шаг 6: Добавить ground truth

Добавить в `data/skill-router-ground-truth.jsonl`:
```json
{"prompt": "example prompt that should trigger this bundle", "expected_skills": ["my-new-skill"], "expected_bundles": ["my-new-bundle"]}
```

### Шаг 7: Пересобрать TF-IDF

```bash
python scripts/build-route-embeddings.py
```

### Шаг 8: Запустить evaluation

```bash
python scripts/eval-skill-router.py --verbose
```

Убедиться что:
- F1 не упал (или улучшился)
- Новый бандл корректно матчится на ground truth промпты
- Нет новых false positives

## Как добавить новый паттерн enforcement

### Content Pattern (Level A)

Редактировать `.claude/hooks/shared/code-skill-patterns.json` → `patterns.mappings`:

```json
{
  "pattern": "MyNewClass|my_new_function",
  "skill": "my-new-skill",
  "label": "My New Feature",
  "domain": "tech"
}
```

### Directory Rule (Level B)

```json
{
  "directory_prefix": "src/my_module/",
  "skill": "my-new-skill",
  "label": "My Module Development",
  "domain": "framework"
}
```

### Bash Rule (Level C)

```json
{
  "pattern": "my-tool\\s+(init|build|deploy)",
  "skill": "my-tool-skill",
  "label": "My Tool Operations",
  "domain": "devops"
}
```

### Post-verification Rule (Level E)

```json
{
  "name": "my-new-skill",
  "file_pattern": "src/my_module/.*\\.py",
  "must_contain": ["from my_module", "class\\s+\\w+"],
  "must_not_contain": ["import \\*", "TODO"],
  "error_message": "Missing required patterns for My Module."
}
```

### Обновить metadata.stats

После добавления — обновить счётчики в `metadata.stats`.

## Как запустить evaluation

### Full Evaluation

```bash
python scripts/eval-skill-router.py
```

Вывод:
```
=== Skill Router Evaluation ===
Ground truth: 64 prompts
Precision: 0.847
Recall:    0.781
F1:        0.813

Per-bundle breakdown:
  langchain-core:  P=0.90 R=0.85 F1=0.87
  research-1c:     P=0.80 R=0.90 F1=0.85
  ...
```

### Verbose mode

```bash
python scripts/eval-skill-router.py --verbose
```

Показывает каждый промпт:
```
[OK] "создай agent с StateGraph" → langgraph-core (expected: langgraph-core)
[FP] "что такое 1С" → 1c-doc-research (expected: none)
[FN] "помоги с redis кешем" → none (expected: tech-research)
```

### JSON для CI

```bash
python scripts/eval-skill-router.py --json > eval-results.json
```

```json
{
  "precision": 0.847,
  "recall": 0.781,
  "f1": 0.813,
  "total": 64,
  "correct": 52,
  "false_positives": 5,
  "false_negatives": 7
}
```

### Интерпретация результатов

| Ситуация | Причина | Действие |
|----------|---------|----------|
| Low Precision (много FP) | Keywords слишком общие | Повысить weighted_keywords, убрать общие keywords |
| Low Recall (много FN) | Keywords не покрывают тему | Добавить keywords, utterances |
| Bundle A забирает от B | Пересечение keywords | Разделить keywords, поднять min_score_gap |
| Informational промпты FP | intent threshold слишком низкий | Поднять effective_min_score для informational |

## build-route-embeddings.py

Скрипт пересборки TF-IDF артефактов:

```bash
python scripts/build-route-embeddings.py
```

**Что делает:**
1. Читает `skill-router-config.json`
2. Для каждого бандла: собирает keywords + weighted_keywords + utterances
3. Строит TF-IDF матрицу (char 2-4 n-grams)
4. Вычисляет IDF веса
5. Для каждого бандла: вычисляет центроид (средний TF-IDF вектор)
6. Сохраняет артефакты в `data/route-tfidf/`:
   - `vocabulary.json` — словарь
   - `idf.npy` — IDF веса
   - `centroids.json` — центроиды бандлов

**Когда пересобирать:**
- После добавления нового бандла
- После изменения utterances
- После изменения keywords (для consistency)
- Перед evaluation (для актуальности)
