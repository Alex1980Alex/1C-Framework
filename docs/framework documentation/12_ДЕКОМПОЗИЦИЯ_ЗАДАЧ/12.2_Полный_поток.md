# 12.2 Полный поток декомпозиции

> Пошаговый разбор: что происходит от момента ввода промпта пользователем
> до разрешения Write/Edit. Каждый шаг с указанием файлов и кода.

---

## Шаг 1: UserPromptSubmit — классификация и инструктирование

При каждом новом промпте пользователя срабатывают два хука в порядке:

### 1.1 skill-router.py (рекомендация скиллов)

Файл: [skill-router.py](../../../.claude/hooks/skill-router.py)

Анализирует текст промпта через 4 слоя матчинга (phrase, fuzzy, TF-IDF, intent)
и выводит в stdout рекомендацию конкретных скиллов для активации.

Также устанавливает `router_fired_at` в SessionState для координации с enforcer.

### 1.2 skill-eval-enforcer-shell.py (reset + классификация)

Файл: [skill-eval-enforcer-shell.py](../../../.claude/hooks/skill-eval-enforcer-shell.py)

Выполняет три действия:

**1. Reset protocol** — сбрасывает фазовый автомат в `idle`:
```python
SessionState.reset_task_protocol()
```

**2. Auto-classify** — определяет сложность промпта:
```python
complexity = _classify_complexity(prompt_stripped)
SessionState.set_task_classified(complexity)
```

**3. Инструкция** — выводит в stdout (100% injection rate):
```
INSTRUCTION: TASK PROTOCOL (MANDATORY)
1. CLASSIFY: trivial (<1 file) | medium (1-3 files) | complex (4+)
   Auto-classified as: medium
2. IF NOT trivial: DECOMPOSE via TaskCreate
3. SKILL CHECK (ALL tasks including trivial!):
   Search skills → activate or use learning-loop
   Write/Edit is BLOCKED until skill activated.
4. Execute → TaskUpdate completed
5. VERIFY: code-verify after code changes
```

**Dedup**: если `skill-router` уже дал конкретные рекомендации (проверка
`was_router_fired_recently(10)`), enforcer пропускает generic инструкцию.

## Шаг 2: Claude принимает решения

Claude видит рекомендации и инструкцию и **сам решает** что делать.
Хуки не принимают решений за Claude — они только инструктируют и наблюдают.

### Для trivial задач

Claude пропускает TaskCreate и сразу активирует скилл:
```
Claude: активирует скилл        ← PostToolUse → phase=skill_checked
Claude: Write(file_path=...) ← PreToolUse → phase OK → ALLOW
```

### Для medium/complex задач

Claude сначала декомпозирует, потом проверяет скиллы:
```
Claude: TaskCreate("Add validation")    ← PostToolUse → phase=decomposed
Claude: TaskCreate("Update endpoint")   ← PostToolUse → subtask_count++
Claude: активирует скилл                ← PostToolUse → phase=skill_checked
Claude: Write(file_path=..., ...)       ← PreToolUse → phase OK → ALLOW
```

## Шаг 3: PostToolUse — наблюдение за фазами

### task-protocol-observer.py

Файл: [task-protocol-observer.py](../../../.claude/hooks/task-protocol-observer.py)

Молчаливый наблюдатель (никогда не блокирует, никогда не выводит в stdout).
Реагирует на два инструмента:

| Инструмент | Действие | Метод SessionState |
|------------|----------|-------------------|
| TaskCreate | phase = decomposed, subtask_count++ | `record_decomposition()` |
| Skill (tool) | phase = skill_checked | `record_skill_checked()` |

```python
class TaskProtocolObserver(BaseHook):
    def execute(self, inp):
        if inp.tool_name == "TaskCreate":
            SessionState.record_decomposition()
        elif inp.tool_name == "Skill":
            SessionState.record_skill_checked()
        return None  # Silent — no output to Claude
```

### Важно: фазы идут только вперёд

Порядок:
```
idle → classified → decomposed → skill_checked
```

`set_task_classified` не даунгрейдит фазу:
```python
# Don't downgrade from 'decomposed'
if protocol.get("phase") != "decomposed":
    protocol["phase"] = "classified"
```

## Шаг 4: PreToolUse — блокировка Write/Edit

### 4.1 task-protocol-enforcer.py (Слой 1)

Файл: [task-protocol-enforcer.py](../../../.claude/hooks/task-protocol-enforcer.py)

Проверяет фазу протокола. Блокирует если `phase != "skill_checked"`:

```python
phase = protocol.get("phase", "idle")
if phase == "skill_checked":
    return None  # ALLOW

# Контекстная подсказка в зависимости от текущей фазы
if phase == "idle":
    hint = "1. CLASSIFY ... 2. Search skills ..."
elif phase == "classified":
    hint = "Skills not checked yet! ..."
elif phase == "decomposed":
    hint = "Decomposed but skills not checked! ..."
return HookOutput().block(...)
```

Claude видит причину блокировки и конкретные шаги для разблокировки.

### 4.2 code-skill-enforcer.py (Слой 2)

Файл: [code-skill-enforcer.py](../../../.claude/hooks/code-skill-enforcer.py)

Если Слой 1 пропустил (фаза OK), проверяет содержимое кода на паттерны:

| Level | Что проверяет | Пример |
|-------|--------------|--------|
| B | Путь файла по директории | `.claude/hooks/` → create-hook |
| A | Содержимое кода по паттерну | Граф-паттерны → langgraph-core |
| A.1 | Research protocol → BLOCK + learning-loop | Библиотеки без скилла |
| C | Bash команды по паттерну | `docker compose` → deployment |

## Шаг 5: PostToolUse — пост-проверка

После успешного Write/Edit срабатывает `code-skill-enforcer` в POST mode
(advisory, никогда не блокирует):

| Level | Действие |
|-------|----------|
| F | LEARN: advisory напоминание вызвать learning-loop (если pending_learn) |
| E | Verification: must_contain / must_not_contain проверки |
| D | Cache reminder: напоминание использовать кэш скилла |

## SessionState — центральное хранилище

Все хуки координируются через `SessionState`
([session_state.py](../../../.claude/hooks/shared/session_state.py)),
который хранит состояние в `data/session-skills.json`:

```json
{
  "task_protocol": {
    "phase": "skill_checked",
    "complexity": "medium",
    "subtask_count": 3,
    "decomposed_at": "2026-03-03T10:05:00",
    "skill_checked_at": "2026-03-03T10:10:00"
  }
}
```

### API task_protocol

| Метод | Хук | Действие |
|-------|-----|----------|
| `reset_task_protocol()` | skill-eval-enforcer-shell | Сброс в idle (новый промпт) |
| `set_task_classified(complexity)` | skill-eval-enforcer-shell | phase=classified |
| `record_decomposition()` | task-protocol-observer | phase=decomposed, subtask_count++ |
| `record_skill_checked()` | task-protocol-observer | phase=skill_checked |
| `get_task_protocol()` | task-protocol-enforcer | Чтение текущей фазы |

## Файлы-исключения

`task-protocol-enforcer` **не блокирует** запись в определённые файлы,
позволяя свободно работать с конфигурацией и документацией:

| Категория | Примеры |
|-----------|---------|
| Каталоги | `.claude/`, `docs/`, `data/`, `.github/` |
| Конфигурация | `.json`, `.toml`, `.yml`, `.yaml`, `.env`, `.cfg`, `.ini` |
| Не-код | `.md`, `.txt`, `.csv`, `.log`, `.rst` |
| Dotfiles | Файлы начинающиеся с `.` |

`code-skill-enforcer` имеет **свою** логику: проверяет содержимое кода
на паттерны, не учитывая путь файла для Level A. Поэтому документация,
содержащая код-примеры, может триггерить Level A.

## Graceful Degradation

Каждый компонент следует принципу **"никогда не блокируй на внутренней ошибке"**:

```python
except Exception:
    sys.exit(0)  # ALLOW — не блокировать Claude
```

Если SessionState недоступен, файлы повреждены, или модуль не импортируется —
хук пропускает проверку и разрешает действие. Это гарантирует что внутренние
ошибки фреймворка не парализуют работу Claude Code.
