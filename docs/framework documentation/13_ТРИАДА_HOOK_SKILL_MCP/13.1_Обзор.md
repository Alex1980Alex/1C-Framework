# 13.1 Обзор триады Hook + Skill + MCP

> Три слоя автоматизации, которые превращают решения из чата в долговечные
> артефакты: Hook определяет КОГДА действовать, Skill — КАК, MCP Tool — ЧЕМ.

---

## Проблема

Claude Code начинает каждую сессию с нуля. Решения, принятые в предыдущих сессиях,
не передаются в следующие. Результат:

```
Сессия 1: "Какой фреймворк использовать?" → ответ в чате → потеряно
Сессия 2: "Какой фреймворк использовать?" → тот же вопрос заново
Сессия 3: "Обработай 1С-вопрос" → забыли использовать скилл → неполный ответ
```

**Ключевое правило:** если в разговоре принято решение — оно ДОЛЖНО стать артефактом
(файлом). Если решение осталось только в чате — оно потеряно.

## Решение: три слоя

```
HOOKS  (событийная автоматизация)     ← КОГДА делать     (3-5 сек)
   ↓  systemMessage
SKILLS (оркестрация + знания)         ← КАК делать       (persistent cache)
   ↓  tool calls
MCP TOOLS (исполнение)                ← ЧЕМ делать       (stateless JSON-RPC)
```

Каждый слой решает одну задачу. Ни один не заменяет другой.

| Слой | Роль | Формат | Время жизни |
|------|------|--------|-------------|
| **Hook** | Реакция на события Claude Code | Python `.py` | 3-5 сек (timeout) |
| **Skill** | Процедурное знание, инструкции | Markdown `SKILL.md` | Между сессиями (persistent) |
| **MCP Tool** | Исполнение тяжёлых операций | JSON-RPC сервер | Stateless (каждый вызов) |

## Что может каждый слой

| Возможность | Hook | Skill | MCP |
|-------------|:----:|:-----:|:---:|
| Event triggers (UserPromptSubmit, Stop) | + | — | — |
| Блокировка действия / выхода | + | — | — |
| Рекомендация через systemMessage | + | — | — |
| Persistent cache (знания между сессиями) | — | + | — |
| Domain knowledge (процедуры, шаблоны) | — | + | — |
| 5-фазный research workflow | — | + | — |
| Tool execution (search, index, RAG) | — | — | + |
| Тяжёлые вычисления (embeddings, NLP) | — | — | + |
| Workflow enforcement (принуждение) | + | — | — |

## Каналы коммуникации

Слои общаются через три канала — и только через них:

```
Hook <──> Hook:      hook-todos.json (файл, file lock)
Hook  ──> Skill:     systemMessage ("используй skill X")
Skill ──> MCP:       tool call (search_documents, ask_question)
Hook  ──> MCP:       нет прямой связи
```

Диаграмма потока:

```
┌──────────────────────────────────────────────────────────────┐
│                    Claude Code Session                        │
│                                                              │
│  UserPromptSubmit ──> [Hook: skill-router]                   │
│                           │ systemMessage                    │
│                           ▼                                  │
│                       [Skill: SKILL.md]                      │
│                           │ tool call                        │
│                           ▼                                  │
│                       [MCP: search_documents]                │
│                           │ результат                        │
│                           ▼                                  │
│  PostToolUse ──> [Hook: cache-reminder]                      │
│                           │ add_task()                        │
│                           ▼                                  │
│                    hook-todos.json                            │
│                           │                                  │
│  Stop ──> [Hook: task-enforcer]                              │
│                    │ pending? → BLOCK                         │
│                    │ empty?   → ALLOW                         │
└──────────────────────────────────────────────────────────────┘
```

## С паттерном vs без

| Без триады | С триадой |
|------------|-----------|
| Решение в чате → потеряно | Решение → артефакт (файл) |
| Каждая сессия с нуля | Hook автоматически роутит на скилл |
| Ручная активация скиллов | Skill Router рекомендует при каждом промпте |
| Забыл сохранить в кеш | Enforcer блокирует выход без сохранения |
| Одни и те же ошибки | Cache хранит исследованные темы |
