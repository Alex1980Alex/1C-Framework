# 13.2 Hooks — событийная автоматизация (КОГДА)

> Хуки — лёгкие Python-скрипты, которые реагируют на события Claude Code:
> ввод пользователя, вызов инструмента, остановку сессии.
> Хуки не выполняют поиск, не вызывают LLM, не модифицируют файлы.

---

## Протокол

Все хуки работают по одному протоколу: stdin JSON → логика → stdout JSON.

```
Claude Code Event  →  stdin (JSON)  →  Hook (.py)  →  stdout (JSON)
                                                        │
                                          ┌─────────────┤
                                          │             │
                                    allow/pass     block (exit 2)
```

**Вход (stdin):**
```json
{
  "session_id": "abc123",
  "prompt": "текст промпта",
  "tool_name": "Read",
  "tool_input": {"file_path": "..."},
  "tool_result": "..."
}
```

**Выход (stdout) — два варианта:**

Подсказка (не блокирует):
```json
{"continue": true, "systemMessage": "Информация для Claude"}
```

Блокировка:
```json
{"continue": false, "decision": "block", "reason": "причина блокировки"}
```

**Timeout:** 3-5 секунд. Хуки должны быть лёгкими — keyword matching, file read,
проверка условий. Тяжёлые вычисления — в MCP.

## BaseHook — абстрактная база

Все хуки наследуют `BaseHook` из [`.claude/hooks/base/protocol.py`](../../../.claude/hooks/base/protocol.py).

```
BaseHook (ABC)
├── __init__()        — запускает таймер
├── run()             — entry point: read stdin → execute() → emit → log
├── execute(inp)      — абстрактный метод (реализуется в подклассах)
└── elapsed_ms        — миллисекунды с начала
```

Три класса протокола:

| Класс | Назначение | Ключевые методы |
|-------|-----------|-----------------|
| `HookInput` | Парсинг stdin JSON | `.prompt`, `.tool_name`, `.tool_input`, `.tool_result`, `.detected_event` |
| `HookOutput` | Построение stdout JSON | `.allow()`, `.block(reason)`, `.system_message(msg)`, `.emit()` |
| `BaseHook` | Абстрактная база | `.run()`, `.execute(inp)`, `.elapsed_ms` |

**Graceful degradation:** при любом исключении в `execute()` хук молча завершается
с `exit(0)` — никогда не блокирует workflow из-за внутренней ошибки. Ошибки
логируются в `.claude/cache/hook-errors.log`.

## 4 основных события

| Событие | Когда | Может блокировать | stdin содержит |
|---------|-------|:-----------------:|---------------|
| **UserPromptSubmit** | Пользователь отправил сообщение | Да | `prompt` |
| **PreToolUse** | До вызова инструмента | Да | `tool_name`, `tool_input` |
| **PostToolUse** | После вызова инструмента | Нет | `tool_name`, `tool_input`, `tool_result` |
| **Stop** | Claude завершает работу | Да (exit 2) | `transcript`, `reason` |

Дополнительные события (редко используемые):

| Событие | Назначение |
|---------|-----------|
| `Notification` | Уведомление |
| `SessionStart` / `SessionEnd` | Начало/конец сессии |
| `PreCompact` | Перед компактификацией контекста |
| `SubagentStop` | Субагент завершился |
| `PermissionRequest` | Запрос разрешений |

## Каталог хуков

### Level 1 — UserPromptSubmit (5 хуков)

Срабатывают при каждом промпте пользователя. Роутинг и классификация.

| Хук | Назначение |
|-----|-----------|
| `skill-router.py` | Config-driven маршрутизация: Layer A (keyword) + B (fuzzy) + C (TF-IDF) → рекомендация скиллов (28 бандлов, 6 доменов) |
| `skill-eval-enforcer-shell.py` | Task protocol + activation enforcement |
| `research-task-detector.py` | Детекция ВОПРОСОВ → роутинг: Architecture, 1С, Tech |
| `decision-to-triad.py` | Детекция РЕШЕНИЙ/ИДЕЙ → Фабрика (`triad-factory`, Q1-Q6) |
| `document-persistence.py` | Детекция roadmap/analysis/plan → сохранение в `docs/` |

### Level 2 — PreToolUse (3 хука)

Срабатывают ДО вызова инструмента. Валидация и блокировка.

| Хук | Matcher | Назначение |
|-----|---------|-----------|
| `code-skill-enforcer.py` | `Write\|Edit` | Skill-First: BLOCK если скилл не активирован (уровни A-C) |
| `task-protocol-enforcer.py` | `Write\|Edit` | BLOCK если task protocol не пройден (phase machine) |
| `root-clutter-guard.py` | `Write` | Блокировка ad-hoc файлов в корне (`test_*`, `debug_*`) |

### Level 2 — PostToolUse (7 хуков)

Срабатывают ПОСЛЕ вызова инструмента. Напоминания и контроль.

| Хук | Matcher | Назначение |
|-----|---------|-----------|
| `code-skill-enforcer.py` | `WebSearch\|WebFetch` | Research cache reminder (уровень D) |
| `code-skill-enforcer.py` | `Write\|Edit` | Post-verification + LEARN phase (уровни E-F) |
| `task-protocol-observer.py` | `TaskCreate` | Фиксирует decomposition в session state |
| `knowledge-cache-reminder.py` | `WebSearch\|WebFetch` | Напоминание сохранить в кеш: 1С, Tech, Architecture |
| `factory-enforcer.py` | `Write` | Контроль ШАГ 4-5 Фабрики: регистрация + верификация |
| `code-verify-reminder.py` | `Write\|Edit` | Advisory напоминание запустить code-verify |
| `auto-git-save.py` | `Write\|Edit\|Bash` | Mandatory task на коммит при пороге файлов |

### Level 3 — Stop (4 хука)

Срабатывают при попытке Claude завершить работу. Блокировка через `exit(2)`.

| Хук | Назначение |
|-----|-----------|
| `task-enforcer.py` | Блокировка без выполнения mandatory задач из hook-todos.json |
| `git-commit-enforcer.py` | Блокировка без коммита изменений в `.claude/` |
| `docs-change-enforcer.py` | Блокировка если код изменён без обновления документации |
| `ralph_wiggum_stop.py` | Контроль итеративного цикла Ralph Wiggum |

## Регистрация в settings.json

Хуки регистрируются в [`.claude/settings.json`](../../../.claude/settings.json)
в секции `hooks`:

```json
{
  "hooks": {
    "UserPromptSubmit": [
      {
        "hooks": [
          {
            "type": "command",
            "command": "D:\\1С-Framework\\.venv\\Scripts\\python.exe D:\\1С-Framework\\.claude\\hooks\\skill-router.py",
            "timeout": 5
          }
        ]
      }
    ],
    "PreToolUse": [
      {
        "matcher": "Write|Edit",
        "hooks": [
          {
            "type": "command",
            "command": "D:\\...\\python.exe D:\\...\\code-skill-enforcer.py",
            "timeout": 3
          }
        ]
      }
    ]
  }
}
```

**Matcher паттерны:**

| Паттерн | Описание |
|---------|----------|
| `"Write"` | Конкретный инструмент |
| `"Read\|Write\|Glob"` | Несколько через `\|` |
| `"mcp__serena__.*"` | Regex для MCP |
| `""` или отсутствие | Все инструменты |

**Абсолютные пути обязательны** — bash на Windows съедает обратные слеши
в относительных путях (подробнее: skill `windows-hooks-paths`).

## Graceful degradation

Принцип: **хуки никогда не ломают workflow**.

```
execute() → исключение → catch в BaseHook.run()
                              │
                              ├── log в hook-errors.log
                              └── sys.exit(0) → allow (pass through)
```

Если хук упал — Claude продолжает работу, как будто хука нет. Ошибка
записывается в `.claude/cache/hook-errors.log` для отладки.
