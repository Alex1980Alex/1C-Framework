# 13.4 MCP Tools — исполнение (ЧЕМ)

> MCP (Model Context Protocol) — стандартный протокол для инструментов Claude Code.
> MCP-сервер предоставляет 15 stateless инструментов: индексация, поиск, RAG, аналитика.
> Тяжёлые вычисления выполняются здесь, а не в хуках.

---

## Протокол MCP

**JSON-RPC** через `stdio` (по умолчанию) или `SSE` (для удалённого доступа).

```
Claude Code  ──JSON-RPC──>  MCP Server  ──>  Components
                                                  │
                                          ┌───────┼───────┐
                                          │       │       │
                                       Loader  Search  Vector
                                               Manager  Store
```

Характеристики:

| Параметр | Значение |
|----------|---------|
| Транспорт | stdio (default), SSE |
| Протокол | JSON-RPC 2.0 |
| Стейтфулность | Stateless (каждый вызов независим) |
| Инициализация | Lazy (Components создаются при первом вызове) |
| Сервер | `pdf-vector-graph` |

## 15 инструментов

### Core (4)

| Инструмент | Назначение | Ключевые параметры |
|-----------|-----------|-------------------|
| `index_pdf` | Загрузка, разбиение, embedding, индексация PDF | `file_path` |
| `search_documents` | Семантический поиск по проиндексированным документам | `query`, `strategy`, `k`, `section` |
| `ask_question` | RAG Q&A — ответ на вопрос с цитатами | `question`, `strategy` |
| `graph_query` | Запрос к графу знаний (entities, relations) | `query`, `entity_type`, `depth` |

### Analytical (2)

| Инструмент | Назначение | Ключевые параметры |
|-----------|-----------|-------------------|
| `analyze` | Аналитический RAG: multi-round evidence gathering, comparison tables | `question`, `max_rounds` |
| `research` | Deep research v2: plan-execute-verify, evidence graph, structured reports | `question`, `max_rounds` |

### Web (2)

| Инструмент | Назначение | Ключевые параметры |
|-----------|-----------|-------------------|
| `web_search` | Поиск в интернете (Tavily/SerpAPI/DuckDuckGo) | `query`, `k` |
| `search_with_fallback` | Локальный поиск + веб, если low confidence, с RRF fusion | `query`, `strategy`, `k` |

### Visual (2)

| Инструмент | Назначение | Ключевые параметры |
|-----------|-----------|-------------------|
| `visual_search` | Поиск по визуальным страницам (таблицы, диаграммы, charts) | `query`, `k`, `document_id` |
| `visual_hybrid_search` | Гибридный visual + text поиск с RRF fusion | `query`, `k`, `visual_weight`, `text_weight` |

### Agent (1)

| Инструмент | Назначение | Ключевые параметры |
|-----------|-----------|-------------------|
| `plan_execute` | Plan-Execute agent: разбиение сложных запросов на шаги | `query`, `max_iterations` |

### Utility (4)

| Инструмент | Назначение | Ключевые параметры |
|-----------|-----------|-------------------|
| `list_collections` | Список коллекций документов | — |
| `list_documents` | Список проиндексированных документов с метаданными | — |
| `get_toc` | Оглавление конкретного документа | `document_id` |
| `get_stats` | Статистика индекса и графа знаний | — |

### Стратегии поиска

`search_documents` поддерживает 7 стратегий:

| Стратегия | Описание |
|-----------|---------|
| `hybrid` | Vector + BM25 + Graph с RRF fusion (default) |
| `vector` | Только vector similarity (cosine) |
| `bm25` | Только лексический поиск (FTS5) |
| `graph` | Только по графу знаний |
| `section_first` | Секционный поиск по ToC + vector |
| `graphrag_local` | Microsoft GraphRAG — local search |
| `graphrag_light` | LightRAG — лёгкий graph search |

## Архитектура Components

MCP-сервер использует `Components` ([`src/api/dependencies/components.py`](../../../src/api/dependencies/components.py))
— единую точку доступа ко всем подсистемам:

```
Components (lazy init, singleton)
├── loader          ← HybridLoader (PyMuPDF + Docling + Vision)
├── pipeline        ← ProcessingPipeline (splitting, cleaning, metadata)
├── indexer         ← IndexingPipeline (embeddings → vector store)
├── search_manager  ← SearchManager (7 стратегий, reranking)
├── graph_store     ← GraphStore (NetworkX / Neo4j)
├── vector_store    ← VectorStore (Qdrant / ChromaDB / FAISS)
└── embedding       ← EmbeddingProvider (E5 / GigaChat / BGE-M3)
```

**Lazy init:** компоненты создаются при первом вызове `_get_components()`.
Повторные вызовы используют singleton.

## Конфигурация

### settings.json (Claude Code)

MCP-серверы регистрируются в `.claude/settings.json` → `mcpServers`:

```json
{
  "mcpServers": {
    "pdf-vector-graph": {
      "command": "D:\\1С-Framework\\.venv\\Scripts\\python.exe",
      "args": ["-m", "src.mcp_server.server"],
      "cwd": "D:\\1С-Framework",
      "env": {
        "PYTHONPATH": "D:\\1С-Framework"
      }
    }
  }
}
```

### .env (Framework)

Параметры MCP-сервера задаются через `.env`:

| Параметр | Описание | Default |
|----------|---------|---------|
| `MCP_TRANSPORT` | Транспорт: `stdio` или `sse` | `stdio` |
| `MCP_SSE_PORT` | Порт для SSE-транспорта | `8765` |
| `EMBEDDING_MODEL` | Модель эмбеддингов | `intfloat/multilingual-e5-large` |
| `VECTOR_STORE_TYPE` | Тип vector store | `qdrant` |
| `GRAPH_STORE_TYPE` | Тип graph store | `networkx` |

Подробнее: [02.2 Конфигурация](../02_БЫСТРЫЙ_СТАРТ/02.2_Конфигурация.md)

## Интеграция с LangChain

MCP-инструменты можно использовать в LangChain-агентах через
`langchain-mcp-adapters`:

```python
from langchain_mcp_adapters.client import MultiServerMCPClient

async with MultiServerMCPClient({
    "pdf-vector-graph": {
        "command": "python",
        "args": ["-m", "src.mcp_server.server"],
    }
}) as client:
    tools = client.get_tools()
    # tools: [search_documents, ask_question, ...]
```

Подробнее: skill `langchain-mcp-tools`
