# 14.1 Обзор Ralph Wiggum

> Ralph Wiggum — двойная система, которая не даёт Claude остановиться на полпути
> (автономный цикл) и заставляет LLM-вызовы учиться на своих ошибках (self-correcting retry).

---

## Проблема

Claude Code по умолчанию останавливается после первого разумного результата.
На простых задачах это нормально. На сложных — катастрофа:

```
Задача: "Создай новый hook + тесты + регистрация + MEMORY.md"

Без Ralph:
  Claude создаёт hook → останавливается → тесты не написаны,
  settings.json не обновлён, MEMORY.md забыт.

С Ralph:
  Claude создаёт hook → пытается остановиться → БЛОК →
  пишет тесты → БЛОК → обновляет settings.json → БЛОК →
  пишет MEMORY.md → RALPH_DONE → выход разрешён.
```

Параллельно, при каждом LLM-вызове (grading, rewriting, entity extraction) ответ
модели может быть невалидным. Слепой retry не помогает — нужна обратная связь.

## Два аспекта Ralph Wiggum

Ralph Wiggum — это **одно имя для двух разных механизмов**:

| Аспект | Что делает | Где живёт | Когда работает |
|--------|-----------|-----------|----------------|
| **Автономный цикл** | Не даёт Claude остановиться, пока задача не завершена | Hooks: `ralph_activator.py`, `ralph_wiggum_stop.py` | Сложные задачи (factory, research, phase) |
| **Self-Correcting Retry** | Передаёт причину ошибки в следующую попытку LLM | Паттерн в 10 файлах `src/pdf_framework/` | Каждый LLM-вызов |

Общая философия: **"Failures are data"** — информация о неудаче кормит следующую итерацию вместо слепого повтора.

## Lifecycle автономного цикла

```
User prompt: "Создай hook для валидации коммитов"
    │
    ▼
[ralph_activator.py] ── UserPromptSubmit
    │  Детектирует "создай hook" → Factory tier
    │  Создаёт .ralph_active + .ralph_criteria.json
    │  Инжектирует системное сообщение с критериями
    ▼
Claude работает (несколько итераций)
    │
    ▼
Claude пытается остановиться
    │
    ▼
[ralph_wiggum_stop.py] ── Stop event
    │  9-шаговый каскад проверок
    │
    ├── Критерии выполнены? ──да──> deactivate → выход разрешён
    │
    └── Нет ──> BLOCK (exit 2) → Claude продолжает работу
                    │
                    ▼
              Повтор до выполнения всех критериев
                    или достижения max_iterations
```

## Связь с триадой

Ralph Wiggum — это **Hook-слой** в контексте автономных задач:

```
Триада:  Hook ──> Skill ──> MCP Tool
                    │
Ralph:   ralph_activator (Hook)
         ralph_wiggum_stop (Hook)
         ralph_state (shared state)
```

Ralph не заменяет триаду, а усиливает её: пока триада обеспечивает
*правильность* (делаем нужное), Ralph обеспечивает *полноту* (доделываем до конца).

Подробности о триаде — [Глава 13. Триада Hook + Skill + MCP](../13_ТРИАДА_HOOK_SKILL_MCP/13.1_Обзор.md).
