# 14.2 Автономный цикл

> Внешний скрипт запускает Claude Code в цикле: каждая итерация проверяет критерии,
> и если задача не завершена — Claude продолжает работу автоматически.

---

## Скрипты

Ralph предоставляет два скрипта для запуска автономного цикла:

| Скрипт | Платформа | Путь |
|--------|-----------|------|
| `ralph.sh` | Linux / macOS / WSL | [`scripts/ralph.sh`](../../../scripts/ralph.sh) |
| `ralph.bat` | Windows (cmd) | [`scripts/ralph.bat`](../../../scripts/ralph.bat) |

Оба делают одно и то же:

1. Активируют Ralph mode (создают `.claude/hooks/.ralph_active`)
2. Запускают `claude -p` в цикле до `MAX_ITERATIONS`
3. После каждой итерации проверяют маркер `RALPH_DONE` в выводе
4. Логируют вывод в `data/ralph_log_<timestamp>.txt`
5. Очищают `.ralph_active` при завершении (trap/cleanup)

## Параметры запуска

```bash
# Прямой запуск с промптом
./scripts/ralph.sh <max-iterations> "<prompt>"
./scripts/ralph.sh 10 "Добавь тесты для всех модулей в src/pdf_framework/search/"

# Запуск с шаблоном
./scripts/ralph.sh --template reindex
./scripts/ralph.sh --template test-coverage --max-iterations 15

# Windows
scripts\ralph.bat --template lint
scripts\ralph.bat 8 "Исправь все ошибки линтера"
```

| Параметр | Описание | По умолчанию |
|----------|---------|--------------|
| `<max-iterations>` | Максимум итераций | 10 |
| `"<prompt>"` | Текст задачи для Claude | — (обязательный) |
| `--template <name>` | Использовать встроенный шаблон | — |
| `--max-iterations N` | Переопределить максимум итераций | 10 |

## 5 встроенных шаблонов

| Шаблон | Описание | Критерии завершения |
|--------|---------|---------------------|
| `reindex` | Проверка полного пайплайна индексации PDF | API 200, метаданные чанков, BM25 синхронизирован, поиск работает |
| `test-coverage` | Увеличение покрытия тестами до 80%+ | Все тесты проходят, покрытие >= 80%, реальные проверки |
| `evaluation` | Запуск RAGAS-оценки качества | 10+ вопросов, faithfulness >= 0.8, relevancy >= 0.7 |
| `documentation` | Добавление docstrings к публичному API | Все public функции с docstring, Google-style, без заглушек |
| `lint` | Исправление всех предупреждений линтера | ruff = 0 ошибок, импорты отсортированы, код отформатирован |

Каждый шаблон содержит:
- **ЗАДАЧА** — описание цели
- **КОНТЕКСТ** — пути, инструменты, зависимости
- **КРИТЕРИИ ЗАВЕРШЕНИЯ** — пронумерованный список (все должны быть выполнены)
- **ПОРЯДОК РАБОТЫ** — рекомендуемая последовательность шагов

## Маркер завершения

Claude должен включить строку `RALPH_DONE` в свой ответ, когда все критерии выполнены.
Скрипт ищет маркер через `grep` (Linux) или `findstr` (Windows) в выводе каждой итерации.

```
# В ответе Claude:
Все тесты проходят, покрытие 84%. RALPH_DONE
```

Альтернативные маркеры (распознаются stop-хуком, но не скриптом):
`TASK_COMPLETE_OK`, `ALL_DONE`.

## Логирование

Весь вывод каждой итерации сохраняется в лог-файл:

```
data/ralph_log_20260304_143022.txt
```

Формат внутри лога:

```
=== Iteration 1 / 10 [2026-03-04 14:30:22] ===
<вывод Claude>
=== Iteration 1 done, continuing... ===
=== Iteration 2 / 10 [2026-03-04 14:31:45] ===
...
=== Task completed at iteration 4 ===
```

## Файл активации

Скрипт создаёт файл `.claude/hooks/.ralph_active` при старте и удаляет при завершении.
Этот файл — сигнал для `ralph_wiggum_stop.py`: если файл есть — блокировать
преждевременный выход Claude.

```
.claude/hooks/
├── .ralph_active           ← существование = Ralph активен
├── .ralph_criteria.json    ← критерии (создаёт activator hook)
└── .ralph_wiggum_count     ← счётчик итераций
```

## Правила из CLAUDE.md

При работе в автономном цикле Claude обязан:

1. В начале итерации: `git log --oneline -5` + `git diff --stat`
2. Коммиты с префиксом `[RALPH]`, по одному на логическое изменение
3. После 3 неудачных попыток — объяснить почему, не зацикливаться
4. Не изменять файлы вне scope задачи
5. Не удалять `data/` без инструкции
