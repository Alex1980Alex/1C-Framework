# 14.3 Хуки и состояние

> Три компонента обеспечивают автономный цикл: Activator определяет сложность задачи,
> Stop Hook блокирует преждевременный выход, а ralph_state управляет атомарным состоянием.

---

## Компоненты

| Компонент | Файл | Событие | Роль |
|-----------|------|---------|------|
| **Activator** | [`ralph_activator.py`](../../../.claude/hooks/ralph_activator.py) | `UserPromptSubmit` | Детектирует сложную задачу, активирует Ralph |
| **Stop Hook** | [`ralph_wiggum_stop.py`](../../../.claude/hooks/ralph_wiggum_stop.py) | `Stop` | Блокирует выход, если критерии не выполнены |
| **State** | [`shared/ralph_state.py`](../../../.claude/hooks/shared/ralph_state.py) | — (библиотека) | Атомарное чтение/запись состояния |

## ralph_activator.py — детекция сложных задач

### Negative-first подход

Хук сначала отсеивает простые задачи, потом проверяет сложные:

```
User prompt
    │
    ▼
Prompt < 15 символов? ──да──> пропустить
    │ нет
    ▼
Ralph уже активен? ──да──> stale? ──да──> deactivate
    │ нет                      │ нет
    ▼                          └──> пропустить
SIMPLE_SIGNALS (2+ совпадений)? ──да──> пропустить (tier 0)
    │ нет
    ▼
Factory signals? ──да──> активация (tier 1)
    │ нет
    ▼
Phase signals? ──да──> активация (tier 2)
    │ нет
    ▼
Brainstorm signals? ──да──> активация (tier 2.5)
    │ нет
    ▼
Research signals? ──да──> активация (tier 3)
    │ нет
    ▼
Multi-step (3+ пунктов)? ──да──> активация (tier 4)
    │ нет
    ▼
Fuzzy match (2+ глагола)? ──да──> активация (tier 5)
    │ нет
    ▼
Пропустить (Ralph не нужен)
```

### 7 Tier-ов

| Tier | Тип | Max iter | Критерии завершения | Сигналы-триггеры |
|------|-----|----------|---------------------|------------------|
| 0 | Simple | — (skip) | — | `fix`, `typo`, `покажи`, `git status`, `объясни` |
| 1 | Factory | 12 | settings.json updated, MEMORY.md updated, test passed | `новый хук`, `фабрика`, `триада`, `mcp tool` |
| 2 | Phase | 15 | all files created, tests pass, MEMORY.md updated | `новая фаза`, `implement phase`, `новый pipeline` |
| 2.5 | Brainstorm | 10 | comparison table created, recommendation given | `придумай`, `предложи`, `какой подход выбрать` |
| 3 | Research | 8 | cache saved, _index.json updated | `исследуй`, `сравни подходы`, `обзор по` |
| 4 | Multi-step | 10 | all listed items completed | Нумерованный список (3+), `а также`, `после этого` |
| 5 | Fuzzy | 10 | all tasks completed | pymorphy3 лемматизация + rapidfuzz (threshold 78) |

**Порядок детекции**: Simple(skip) → Factory → Phase → Brainstorm → Research → Multi-step → Fuzzy.

### Fuzzy Fallback (tier 5)

Когда ни одна фраза не совпала, `FuzzyMatcher` использует лемматизацию (pymorphy3)
и нечёткое сравнение (rapidfuzz) для обнаружения сложных глаголов:

```python
keywords = [
    "исследовать", "проанализировать", "реализовать",
    "автоматизировать", "интегрировать", "рефакторить",
    "мигрировать", "оптимизировать",
]
threshold = 78   # rapidfuzz score
required = 2     # нужно 2+ совпадения
```

### Активационное сообщение

При активации хук инжектирует `systemMessage`:

```
[RALPH-ACTIVATED] Autonomous mode ON (type=factory, max 12 iterations).

Ralph Wiggum автономный цикл активирован.
Claude НЕ остановится пока все критерии не выполнены:
  - settings.json updated
  - MEMORY.md updated
  - test passed

Когда ВСЕ критерии выполнены, включи маркер: RALPH_DONE
```

## ralph_wiggum_stop.py — контроль выхода

### 9-шаговый каскад решений

```
Claude пытается остановиться (Stop event)
    │
    ▼
1. Ralph не активен?               → разрешить (exit 0)
    │
2. Stale (>2 часов)?               → deactivate → разрешить (exit 0)
    │
3. Max iterations достигнут?        → deactivate → разрешить (exit 0)
    │
4. RALPH_DONE в выводе?            → deactivate → разрешить (exit 0)
    │
5. 2+ completion signals?          → deactivate → разрешить (exit 0)
    │
6. Все структурные критерии?       → deactivate → разрешить (exit 0)
    │
7. Pending mandatory tasks?         → BLOCK (exit 2)
    │
8. Incomplete signals найдены?      → BLOCK (exit 2)
    │
9. Ранние итерации (<=3)?          → BLOCK (exit 2)
    │
10. Поздние итерации, нет сигналов → разрешить (exit 0)
```

### Маркеры завершения

```python
COMPLETION_MARKERS = ["RALPH_DONE", "TASK_COMPLETE_OK", "ALL_DONE"]
```

Claude включает любой из этих маркеров в свой ответ для сигнализации о завершении.

### Criteria → Signal Mapping

Stop hook ищет в транскрипте доказательства выполнения каждого критерия:

| Критерий | Поисковые сигналы |
|----------|------------------|
| `cache saved` | cache, saved, кеш, сохранен, cached |
| `_index.json updated` | _index.json, index updated, индекс обновлен |
| `settings.json updated` | settings.json |
| `MEMORY.md updated` | memory.md, memory updated |
| `test passed` | test pass, tests pass, тест пройден, verified |
| `all files created` | created, написан, создан |
| `comparison table created` | comparison, таблица, matrix, pros, cons |
| `recommendation given` | recommendation, рекомендация, выбран, chosen |

### Incomplete Signals (блокируют выход)

Если в выводе найдены сигналы незавершённой работы — выход блокируется:

```python
INCOMPLETE_SIGNALS = [
    "todo", "fixme", "need to", "will implement", "next step",
    "pending", "will continue", "need to register",
    "need to test", "need to save", "need to update",
]
```

### Mandatory Tasks

Stop hook проверяет `hook-todos.json` на наличие невыполненных задач
от обязательных хуков:

```python
MANDATORY_HOOKS = {
    "knowledge-cache-reminder-hook",
    "factory-enforcer-hook",
}
```

Если есть pending задачи от этих хуков → выход блокируется с напоминанием.

## ralph_state.py — управление состоянием

### 3 файла состояния

Все файлы хранятся в `.claude/hooks/` (project-level):

| Файл | Тип | Назначение |
|------|-----|-----------|
| `.ralph_active` | Flag (существование = активен) | Главный переключатель |
| `.ralph_criteria.json` | JSON | Критерии, тип задачи, timestamp |
| `.ralph_wiggum_count` | Текст (число) | Счётчик итераций |

### Формат .ralph_criteria.json

```json
{
  "task_type": "factory",
  "activated_at": "2026-03-04T14:30:00.123456+00:00",
  "prompt_excerpt": "первые 200 символов промпта...",
  "completion_criteria": ["settings.json updated", "test passed"],
  "max_iterations": 12
}
```

### API

```python
from shared.ralph_state import (
    activate, deactivate, is_active, is_stale,
    increment_iteration, get_max_iterations, get_criteria,
    set_stop_running, clear_stop_running, is_stop_running,
)

# Активация
activate(task_type, prompt_excerpt, criteria, max_iterations)

# Деактивация (удаляет все 3 файла)
deactivate()

# Проверки
is_active() -> bool          # .ralph_active существует?
is_stale() -> bool           # activated_at > 2 часов назад?
is_stop_running() -> bool    # stop hook сейчас выполняется?

# Итерации
increment_iteration() -> int  # +1, вернуть новое значение
get_max_iterations() -> int   # из criteria или DEFAULT (15)

# Критерии
get_criteria() -> dict | None # прочитать .ralph_criteria.json
```

### Константы

```python
DEFAULT_MAX_ITERATIONS = 15   # если не задано в criteria
STALE_HOURS = 2               # авто-деактивация через 2 часа
```

### Атомарная запись

Все файловые операции используют паттерн temp + rename для защиты от крэшей:

```python
fd, tmp = tempfile.mkstemp(dir=path.parent, suffix=".tmp", prefix=".ralph_")
with os.fdopen(fd, "w") as f:
    json.dump(data, f)
os.replace(tmp, path)  # Атомарно на Windows и Unix
```

### Stop-lock

Механизм предотвращения каскадов: когда stop hook выполняется,
другие хуки (auto-git-save, git-commit-enforcer) не должны создавать
новые задачи, которые заблокируют тот же stop.

```python
set_stop_running()    # Создаёт .ralph_stop_lock с PID
is_stop_running()     # True если lock существует и < 30 сек
clear_stop_running()  # Удаляет lock
```

## Типичный lifecycle

```
1. User: "Создай новый hook для валидации коммитов"

2. ralph_activator.py → Factory tier
   Создаёт .ralph_active, .ralph_criteria.json (max 12)
   Инжектирует критерии: settings.json, test passed, MEMORY.md

3. Claude создаёт hook, пишет в settings.json
   factory-enforcer.py → mandatory task в hook-todos.json

4. Claude пытается остановиться (итерация 2)
   ralph_wiggum_stop.py:
     criteria: settings.json ✓  test passed ✗  MEMORY.md ✗
     mandatory task от factory-enforcer ✓
     → BLOCK: "Need to run tests"

5. Claude запускает тесты — проходят

6. Claude обновляет MEMORY.md, пишет RALPH_DONE
   ralph_wiggum_stop.py:
     RALPH_DONE найден → deactivate → exit 0
```
