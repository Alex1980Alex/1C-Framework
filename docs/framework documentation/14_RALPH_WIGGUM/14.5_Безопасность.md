# 14.5 Безопасность

> 7 механизмов защиты предотвращают зависание, бесконечные циклы и повреждение данных
> при работе Ralph Wiggum в автономном режиме.

---

## 7 механизмов защиты

| # | Механизм | Что предотвращает | Где реализован |
|---|----------|------------------|----------------|
| 1 | **2-hour staleness** | Забытая сессия зависает навечно | [`ralph_state.py`](../../../.claude/hooks/shared/ralph_state.py): `is_stale()` |
| 2 | **Max iterations** | Бесконечный цикл на невозможной задаче | `ralph_activator.py`: 8-15 по tier |
| 3 | **RALPH_DONE marker** | Claude не может завершить обычным путём | `ralph_wiggum_stop.py`: шаг 4 каскада |
| 4 | **Negative-first detection** | False positive на простых задачах | `ralph_activator.py`: SIMPLE_SIGNALS |
| 5 | **Atomic state files** | Повреждение состояния при крэше | `ralph_state.py`: temp + `os.replace()` |
| 6 | **Mandatory task check** | Критические шаги пропущены | `ralph_wiggum_stop.py`: hook-todos.json |
| 7 | **Stop-lock** | Каскадная блокировка (stop → git → stop) | `ralph_state.py`: `.ralph_stop_lock` |

## Правила из CLAUDE.md

При работе в автономном цикле (`scripts/ralph.bat` / `ralph.sh`):

1. **В начале итерации** — `git log --oneline -5` + `git diff --stat` для контекста
2. **Коммиты** — с префиксом `[RALPH]`, по одному на логическое изменение
3. **3 неудачных попытки** — объяснить почему, не зацикливаться
4. **Маркер завершения** — `RALPH_DONE` (только когда ВСЕ критерии выполнены)
5. **Scope** — не изменять файлы вне scope задачи, не удалять `data/`

## Антипаттерны

| Плохо | Почему | Правильно |
|-------|--------|-----------|
| `RALPH_DONE` после первого файла | Критерии не выполнены, задача не завершена | Проверить все критерии перед маркером |
| Бесконечный retry без RALPH_DONE | Max iterations потрачены впустую | После 3 неудач — `RALPH_DONE` с объяснением |
| Ручное удаление `.ralph_active` | Состояние рассинхронизировано с criteria | Использовать `deactivate()` через ralph_state |
| Активация Ralph на `git status` | Ресурсы потрачены на тривиальную задачу | Negative-first фильтр отсекает simple задачи |
| Коммит без `[RALPH]` префикса | Невозможно отличить ручные коммиты от автономных | Всегда `[RALPH] Описание изменения` |
| Изменение файлов вне scope | Побочные эффекты вне задачи | Только файлы, связанные с задачей |

## Troubleshooting

| Проблема | Причина | Решение |
|----------|---------|---------|
| Ralph не активируется на сложную задачу | Промпт содержит 2+ SIMPLE_SIGNALS | Переформулировать без simple-слов или добавить сигнал в нужный tier |
| Ralph блокирует выход, хотя всё готово | Incomplete signals в выводе (`todo`, `need to`) | Убрать слова-триггеры или включить `RALPH_DONE` |
| Stale activation (Ralph активен после закрытия) | Процесс завершился без cleanup | Подождать 2 часа (авто-деактивация) или удалить `.ralph_active` вручную |
| Каскадная блокировка (stop → commit → stop) | Stop-lock не работает | Проверить `.ralph_stop_lock`, перезапустить |
| Max iterations без результата | Задача слишком сложная для одного tier | Увеличить `--max-iterations` или разбить задачу |
| Criteria check не видит прогресс | Сигналы не совпадают с CRITERIA_SIGNAL_MAP | Убедиться, что вывод содержит ключевые слова из mapping |
| `.ralph_criteria.json` повреждён | Крэш во время записи | Удалить файл — будет использовано DEFAULT_MAX_ITERATIONS |

## Потоки данных безопасности

```
Активация:
  User prompt → negative filter → tier detection → atomic write → systemMessage

Блокировка:
  Stop event → set_stop_running() → 9-step cascade → clear_stop_running()
       │                                    │
       │                              block (exit 2)
       │                                    │
       └── lock предотвращает ──────────────┘
           каскадные вызовы
           от других хуков

Деактивация:
  criteria met │ stale │ max_iter │ RALPH_DONE
       └───────┴───────┴──────────┘
                    │
                    ▼
              deactivate()
              удаляет .ralph_active
              удаляет .ralph_criteria.json
              удаляет .ralph_wiggum_count
```

## Path Resolution

Все файлы состояния используют [`shared/core_paths.py`](../../../.claude/hooks/shared/core_paths.py)
для определения путей:

| Path | Разрешается в | Назначение |
|------|--------------|-----------|
| `get_state_dir()` | `.claude/hooks/` (project-level) | Файлы состояния Ralph |
| `get_cache_dir()` | `.claude/cache/` (project-level) | hook-todos.json |
| `get_core_dir()` | `~/.claude/hooks/` (user-level) | Исходный код хуков Ralph |

Файлы состояния **всегда project-level** — каждый проект имеет свою Ralph-сессию.
