# 15.2 Z.AI Delegation Protocol

> Протокол делегирования генерации контента на дешёвые LLM через LLM Rotation.
> 4 уровня делегирования, Orchestrator Mode для пакетных задач.

---

## Уровни делегирования

```
Задача
  │
  ├─ Bulk/formatting (10+ элементов, шаблонные) ──→ SOFT (без ревью)
  │
  ├─ Docs/decomposition/tests (1-5 файлов) ──────→ MEDIUM (Opus review)
  │
  ├─ Code/refactoring/analysis (продакшен) ───────→ HARD (Opus thorough review)
  │
  └─ Architecture/security/debugging ─────────────→ NEVER (только Opus)
```

| Сигнал | Уровень | Примеры |
|--------|---------|---------|
| 10+ однотипных элементов | Soft | Форматирование, переименование |
| Генерация docs, тестов, декомпозиция | Medium | "сгенерируй readme", "напиши тесты", "разбей на файлы" |
| Написание кода, рефакторинг | Hard | "напиши код", "рефакторинг", "создай модуль" |
| Архитектура, безопасность, отладка | Never | "как лучше сделать", "debug", "безопасность" |
| Ожидаемый output < 30 строк | Never | Overhead делегирования выше пользы |

## Детекция сигналов (Hook)

Хук `z-ai-delegation-enforcer.py` анализирует каждый промпт пользователя:

```
UserPromptSubmit
  │
  ├─ prompt.length < 40 символов? → пропуск
  │
  ├─ Never signals ("архитектур", "debug", "безопасност")? → пропуск (тишина)
  │
  ├─ Orchestrator signals ("каждый файл", "batch", 3+ файлов)?
  │   └─ systemMessage: ORCHESTRATOR (MEDIUM или HARD)
  │
  ├─ Hard signals ("напиши код", "рефакторинг")?
  │   └─ systemMessage: HARD — Draft → Thorough Review
  │
  └─ Medium signals ≥ 2 ("сгенерируй", "декомпозиция")?
      └─ systemMessage: MEDIUM — Draft → Review
```

**Приоритет:** Never > Bandit (если уверен) > Orchestrator > Hard > Medium. Never всегда побеждает.

### Bandit Routing (AUTONOMOUS)

Параллельно с rule-based детекцией работает contextual bandit — `DelegationBandit` (LinUCB, 4 arms: Soft/Medium/Hard/Never) из [src/shared/delegation_bandit.py](../../../src/shared/delegation_bandit.py). Source: паттерн TensorZero online-learning.

**Warm-up режимы** (по количеству обученных outcomes в `data/delegation-bandit.pkl`):

| Outcomes | Режим | Поведение enforcer |
|----------|-------|-------------------|
| < 20 | Rule-based | Bandit игнорируется, работают keyword-сигналы |
| 20-50 | Hybrid | Rules + bandit suggestion (только если уверен) |
| > 50 | AUTONOMOUS | Bandit-решение побеждает Hard/Medium (но не Never) |

**Online update** — [delegation-outcome-tracker.py](../../../.claude/hooks/delegation-outcome-tracker.py) после каждого Write-события вызывает `bandit.update(context_features, classification, reward)`. Reward: 1.0 если делегировано, 0.5 если нет.

**AUTONOMOUS routing** в [z-ai-delegation-enforcer.py](../../../.claude/hooks/z-ai-delegation-enforcer.py): когда `bandit_level != "Never"` и модель уверена, возвращается systemMessage уровня из bandit'а (Hard/Medium/Soft) с протоколом делегирования. Rule-based сигналы в этом режиме подавляются.

**CLI dashboard:**

```bash
python -m src.shared.delegation_bandit dashboard
# accuracy, delegation rate, classification distribution
```

### Сигналы детекции

**Orchestrator** (пакетные):
- EN: "each file", "for every", "batch", "multiple files"
- RU: "каждый файл", "для каждого", "все файлы", "пакетно", "каждая фаза"
- Regex: `\b([3-9]|[1-9]\d+)\s*(файл|file|модул|module|фаз|phase)`

**Medium** (docs/тесты):
- EN: "documentation", "decompos", "generate tests", "boilerplate"
- RU: "разбей", "декомпозиция", "сгенерируй", "напиши тесты", "по шаблону"

**Hard** (код):
- EN: "write code", "implement", "refactor", "rewrite"
- RU: "напиши код", "реализуй", "рефакторинг", "перепиши", "написать функцию"

**Never** (только Opus):
- EN: "architecture", "security", "debug", "investigate"
- RU: "архитектур", "безопасност", "отладка", "почему не работает"

## Orchestrator Mode

Для задач с 3+ выходными файлами. Opus = мозг, Z.AI = руки.

```
Step 1: DECOMPOSE (Opus, 0 tokens Z.AI)
  └─ Разбей задачу на подзадачи
  └─ Для каждой: уровень (Soft/Medium/Hard/Never)
  └─ Never-подзадачи → Opus делает сам

Step 2: PREPARE PROMPTS (Opus, 0 tokens Z.AI)
  └─ Для каждой делегируемой подзадачи:
     a) ЗАДАЧА — что сгенерировать
     b) КОНТЕКСТ — сниппеты из проекта
     c) ФОРМАТ — структура, стиль, язык
     d) ОГРАНИЧЕНИЯ — naming, паттерны

Step 3: DELEGATE (Z.AI tokens)
  └─ mcp__llm-rotation__llm_complete() для каждой подзадачи
  └─ Независимые — параллельно, зависимые — последовательно

Step 4: REVIEW (Opus, минимум tokens)
  └─ Medium: accuracy + completeness + format
  └─ Hard: + logic + edge cases + security
  └─ Fix inline. При > 50% переписывания → Never

Step 5: ASSEMBLE + WRITE (Opus)
  └─ Собрать финал из всех подзадач
  └─ Write() файлы. Один проход — не возвращаться к Z.AI
```

### Пример: 10 файлов roadmap

```
Подзадача        Уровень   Промпт для Z.AI                     Review
INDEX.md         Medium    "Create index with table..."        Format check
PHASE_58.md      Medium    "Expand phase 58: eval dataset..."  Accuracy check
PHASE_59.md      Medium    "Expand phase 59: AST parser..."    Accuracy check
... (повторить для каждой фазы)

Opus: decompose + prompts + review ≈ 6 мин
Z.AI: 10 × llm_complete = 10 файлов
Экономия Opus: ~85% output tokens
```

## Single Task: Draft → Review

Для одиночных задач (не пакетных):

```
mcp__llm-rotation__llm_complete(
  prompt="[задача + контекст + формат + ограничения]",
  max_tokens=4096
)
```

### Review по уровням

**Medium — проверь и поправь:**
- Фактическая точность (имена, API, ссылки)
- Полнота (ничего не пропущено?)
- Формат (соответствует стилю проекта?)

**Hard — всё из Medium ПЛЮС:**
- Логическая корректность (будет работать?)
- Edge cases обработаны?
- Консистентность с паттернами кодовой базы?
- Нет security-проблем?
- При > 50% переписывания — переклассифицируй в Never

## Шаблоны промптов

### Генерация документации

```
Generate documentation for the following feature.

Context:
[ОПИСАНИЕ/КОД]

Requirements:
- Language: Russian
- Format: Markdown, headers, tables
- Include: purpose, tasks, deliverables, acceptance criteria
- Style: concise, technical, actionable

Output the complete document.
```

### Генерация кода

```
Write [LANGUAGE] code for the following:

Task: [ЧТО РЕАЛИЗОВАТЬ]

Context:
[СУЩЕСТВУЮЩИЕ ПАТТЕРНЫ, ИНТЕРФЕЙСЫ, ТИПЫ]

Constraints:
- Follow these patterns: [ПАТТЕРНЫ]
- Naming: [КОНВЕНЦИИ]

Output only the code with minimal comments.
```

### Генерация тестов

```
Generate tests for this code:

Code:
[КОД ФУНКЦИИ/КЛАССА]

Requirements:
- Framework: pytest
- Cover: happy path, edge cases, error cases
- Mock external dependencies

Output complete test file.
```
