## Token Economics

### Экономия по типам задач

| Сценарий | Без делегирования | С делегированием | Экономия Opus |
|----------|-------------------|------------------|---------------|
| 10 файлов docs | ~15K Opus output | ~2K Opus + 15K Z.AI | **~85%** |
| 50 тест-кейсов | ~8K Opus output | ~1K Opus + 8K Z.AI | **~87%** |
| 500 строк кода | ~3K Opus output | ~0.5K Opus + 3K Z.AI | **~83%** |
| Архитектура | ~2K Opus output | N/A (never delegate) | 0% |

### Распределение токенов Opus при делегировании

```
Orchestrator (10 файлов):
  ├─ DECOMPOSE     ~200 tokens  (классификация подзадач)
  ├─ PREPARE       ~800 tokens  (10 промптов × ~80 tokens)
  ├─ REVIEW        ~1000 tokens (10 ревью × ~100 tokens)
  └─ ASSEMBLE      ~200 tokens  (финальная сборка)
  ─────────────────────────────
  Итого Opus:      ~2200 tokens
  Z.AI:            ~15000 tokens (10 × ~1500)
  Экономия:        ~85%

Single Draft → Review (1 файл кода):
  ├─ PROMPT        ~150 tokens  (контекст + задача)
  ├─ REVIEW        ~300 tokens  (thorough check)
  └─ FIX           ~100 tokens  (inline правки)
  ─────────────────────────────
  Итого Opus:      ~550 tokens
  Z.AI:            ~3000 tokens
  Экономия:        ~83%
```

## Когда НЕ делегировать

| Ситуация | Почему | Что делать |
|----------|--------|------------|
| Output < 30 строк | Overhead делегирования > экономии | Opus пишет сам |
| Архитектурное решение | Нужен полный контекст проекта | Never — только Opus |
| Отладка / debug | Интерактивный процесс | Never — только Opus |
| Безопасность / секреты | Критичность + контекст | Never — только Opus |
| Z.AI вернул > 50% мусора | Задача слишком сложная | Переклассифицировать в Never |

## Антипаттерны

| Плохо | Почему | Как правильно |
|-------|--------|---------------|
| Делегировать всё подряд | Overhead на мелких задачах | Только при output > 30 строк |
| Сырой Z.AI ответ без ревью | Ошибки в именах, логике, API | Medium/Hard — всегда ревью Opus |
| Промпт без контекста проекта | Галлюцинации (несуществующие API) | Вставлять сниппеты кода в промпт |
| Делегировать архитектуру | Z.AI не знает проект | Never — только Opus |
| Повтор при плохом результате | Тот же промпт = тот же результат | Улучшить промпт или сделать самому |
| Пропустить Code Review | Ошибки накапливаются | Enforcer не даёт пропустить |
| Игнорировать THOROUGH чеклист | Security/edge case пропущен | Все 5 пунктов обязательны |

## Диагностика

| Проблема | Причина | Решение |
|----------|---------|---------|
| Пустой ответ Z.AI | Провайдер в cooldown | `mcp__llm-rotation__llm_list_providers` — проверить статус |
| "All providers failed" | Все провайдеры недоступны | Opus пишет сам (fallback to Never) |
| Низкое качество черновика | Промпт без контекста | Добавить сниппеты кода/доков в промпт |
| > 50% переписывания | Задача слишком сложная для Z.AI | Переклассифицировать в Never |
| Timeout при llm_complete | max_tokens слишком большой | Разбить на 2-3 вызова по 4096 |
| Код из Z.AI не работает | Z.AI не знает проект | Добавить интерфейсы/типы в промпт |
| Hook не срабатывает | Промпт < 40 символов | Нормальное поведение (короткие пропускаются) |
| THOROUGH для тестов | Тест лежит в `src/` | Нормально — всё в src/ = production |
| Review не появляется | Файл .md/.json (не код) | Нормально — non-code пропускается |

## Мониторинг

### Логи хуков

Оба хука логируют вызовы через `InvocationTimer` в `data/hook-invocations.jsonl`:

```json
{"hook": "z-ai-delegation-enforcer", "event": "UserPromptSubmit", "outcome": "orchestrator-medium", "ts": "..."}
{"hook": "code-review-enforcer", "event": "PostToolUse", "outcome": "thorough", "file": "parser.py", "ts": "..."}
```

### Проверка провайдеров

```
mcp__llm-rotation__llm_list_providers  — статус всех провайдеров
mcp__llm-rotation__llm_get_stats       — статистика использования
mcp__llm-rotation__llm_test_providers  — тест доступности
mcp__llm-rotation__llm_reset_provider  — сброс cooldown
```
