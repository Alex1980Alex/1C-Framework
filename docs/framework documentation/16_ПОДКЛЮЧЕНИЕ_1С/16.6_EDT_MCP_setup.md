### Карта среды

| Компонент | Порт | Состояние, в котором pipeline работает |
|---|---|---|
| `edt-mcp` HTTP-bridge (EDT IDE плагин) | `localhost:8765` | LISTENING |
| 1С debug agent (`ragent.exe -debug`) | `localhost:1550` | LISTENING (опционально для Этапа 4) |
| Qdrant | `localhost:6333` | LISTENING (нужен для bsl-semantic-search) |
| 1С HTTP-сервис `MCP_Сервер` | `localhost/<base>/hs/mcp/rpc` | HTTP 401 без auth (значит сервис опубликован) |

Быстрая проверка из PowerShell:

```powershell
@(8765,1550,6333) | ForEach-Object {
    $port = $_
    $r = Test-NetConnection -ComputerName localhost -Port $port -InformationLevel Quiet -WarningAction SilentlyContinue
    Write-Output "port $port : $r"
}
```

Для smoke-теста всего pipeline целиком:

```powershell
python scripts/smoke_test_implement_1c_task.py
```

Скрипт парсит [`.mcp.json`](../../../.mcp.json), TCP-проверяет ключевые порты и возвращает exit-code:
- `0` — режим **Full** (все этапы работают)
- `1` — режим деградации (`Code-only` / `Read-only verify` / `Read-only research`)
- `2` — режим **unusable** (запуск pipeline бессмыслен)

### EDT-MCP — основной инструмент Этапа 1, 3, 5

EDT-MCP — это HTTP-плагин внутри 1C:Enterprise Development Tools (Eclipse-based IDE), отдающий MCP-инструменты `list_projects`, `read_method_source`, `write_module_source`, `validate_query`, `find_references`, `get_project_errors` и др. Без него Этапы 2/3/5 SKILL.md уходят в hard-stop.

#### Конфигурация в `.mcp.json`

```json
"edt-mcp": {
  "command": "npx",
  "args": ["-y", "mcp-remote", "http://localhost:8765/mcp"],
  "timeout": 60000
}
```

`mcp-remote` — клиент для удалённых MCP-серверов через HTTP. Stdio-обёртку поднимает `npx`, реальный сервер работает внутри EDT.

#### Запуск EDT IDE

1. Запустить EDT (`<EDT_HOME>/edt.exe` или ярлык «1C:EDT»).
2. Открыть workspace, в котором лежат проекты конфигурации (типичный путь — `C:\Users\<user>\edt-workspace\`).
3. Дождаться полной индексации проекта (статус-бар внизу: «Building workspace… 100%»).
4. Активировать MCP-плагин:
   - **Window → Preferences → 1C:EDT → MCP Server** (либо аналогичный пункт в зависимости от версии EDT-плагина).
   - Включить чекбокс **Enable MCP Server**, указать порт `8765`.
   - Применить, при необходимости перезапустить EDT.
5. Проверить порт:
   ```powershell
   Test-NetConnection -ComputerName localhost -Port 8765 -InformationLevel Quiet
   ```
   Ожидание — `True`.
6. В Claude Code выполнить `/mcp` → `Reconnect edt-mcp`. После reconnect должны появиться тулы `mcp__edt-mcp__list_projects`, `mcp__edt-mcp__read_method_source` и т. д.

#### Если порт 8765 занят

```powershell
Get-NetTCPConnection -LocalPort 8765 | Select-Object OwningProcess, State
Get-Process -Id <PID>
```

Варианты:
- Старый процесс EDT не завершился — `Stop-Process -Id <PID>`.
- Порт занят другим приложением — сменить порт в настройках EDT (см. шаг 4) и в `.mcp.json` (`http://localhost:<новый порт>/mcp`).

#### Smoke-test EDT-MCP

```
ToolSearch select:mcp__edt-mcp__list_projects
mcp__edt-mcp__list_projects
```

Должен вернуть массив проектов EDT с именами вида `УправлениеТранспортомНаПЛК` / `TransportManagement` / etc.

### 1С debug agent — runtime-отладка Этапа 4 (опционально)

`bsl-debug-server` (порт `:1551` через прокси) использует runtime-отладку 1С на стандартном порту `:1550`. Без агента работают только статический `bsl_analyze` и OneScript-исполнение `bsl_execute` — для большинства задач этого достаточно. Полноценный `bsl_debug_start` / `bsl_debug_step` / `bsl_debug_variables` требует поднятого агента.

#### Запуск

**Вариант A — через `Конфигуратор`:**

1. Открыть конфигурацию через 1С:Предприятие (Конфигуратор).
2. **Сервис → Параметры → Запуск 1С:Предприятия → Отладка** → включить «Отладка разрешена», порт по умолчанию `1550`.
3. Проверить: `Test-NetConnection -ComputerName localhost -Port 1550 -InformationLevel Quiet` → `True`.

**Вариант B — `ragent.exe -debug` для серверной базы:**

```powershell
& "C:\Program Files\1cv8\<version>\bin\ragent.exe" -debug -port 1550
```

Используется только когда отладка идёт по серверной базе через сервер 1С (rphost). Для файловой базы достаточно Варианта A.

#### Smoke-test debug agent

```
mcp__1c-debug__debug_targets
```

Должен вернуть список доступных targets (хотя бы один — текущий рабочий процесс 1С). Пустой массив означает, что агент не поднят.

### Универсальная диагностика среды

Если `/implement-1c-task` ушёл в режим **Read-only research** или **Read-only verify** — пройтись по чеклисту:

- [ ] `Test-NetConnection 8765` → `True`. Если `False` → запустить EDT IDE и активировать MCP-плагин.
- [ ] `Test-NetConnection 1550` → `True` (опционально). Если `False` и нужен runtime-debug → поднять Конфигуратор / `ragent.exe -debug`.
- [ ] `curl http://localhost/<base>/transport/hs/mcp/health` → `401 Unauthorized` (значит публикация HTTP-сервиса в порядке) либо `200`/`404`. Если `502`/`504` → IIS/Apache не отвечает.
- [ ] `python scripts/mcp_health_monitor.py` → `1c-mcp-crud`, `edt-mcp`, `bsl-debugger`, `bsl-semantic-search` в статусе `OK`.
- [ ] `ToolSearch select:mcp__edt-mcp__list_projects` и `select:mcp__1c-mcp-crud__get_metadata` возвращают schema, не `No matching deferred tools`.
- [ ] `python scripts/smoke_test_implement_1c_task.py` exit-code `0`.

При сбое — переходить к разделам выше по соответствующему компоненту.

### Известные проблемы

**1С user locked out.** При нескольких неверных попытках входа в `mcp_APIBackend` (например, пустой пароль в `.mcp.json` → стартовый probe) 1С блокирует учётку на 5 минут. Сообщение:
```
Превышено допустимое количество ошибок при вводе имени и пароля.
Вход для данного пользователя заблокирован до <время>.
```
Решение: дождаться разблокировки либо снять флаг блокировки в Конфигураторе (Администрирование → Пользователи).

**EDT-MCP плагин не находит порт.** EDT кеширует workspace metadata — при смене порта в Preferences иногда требуется `File → Restart` либо удалить `<workspace>/.metadata/.plugins/<plugin>` и перезапустить.

**`mcp-remote` ругается на SSL.** EDT публикует `http://`, а не `https://`. Если в `.mcp.json` случайно написано `https://localhost:8765/mcp` — `mcp-remote` будет падать. Должно быть строго `http://`.
