# 17.1 Автоматизация тестирования 1С:Предприятие — Обзор

## Назначение

Автоматизированное тестирование в экосистеме 1С:Предприятие предназначено для обеспечения регрессионной стабильности конфигураций и верификации бизнес-логики. Внедрение автоматизации позволяет:

*   Сократить время на проведение регрессионных тестирований при выпуске новых релизов.
*   Исключить человеческий фактор при проверке рутинных сценариев (смок-тесты, ввод документов).
*   Интегрировать проверку качества в конвейер CI/CD для раннего обнаружения ошибок.
*   Формировать формализованные отчеты о покрытии кода и статусе сборки.

## Инструменты тестирования

В рамках фреймворка используется стек инструментов для покрытия различных уровней тестирования (от модульных до сценарных).

| Инструмент | Тип / Назначение | Версия | Характеристики |
| :--- | :--- | :--- | :--- |
| **YAxUnit** | Unit-тестирование | v25.12 | 690+ тестов, Pass rate 80%. Интеграция через `vrunner`. Предназначен для проверки алгоритмов и бизнес-логики без участия пользователя. |
| **Vanessa Automation** | BDD / UI-тестирование | v1.2.043.1 | Сценарное тестирование на языке Gherkin (RU). Управление через TestManager/TestClient. Позволяет записывать и воспроизводить действия пользователя. |
| **vanessa-runner** | CLI-обертка | v2.6.0 | Инструмент командной строки (OneScript). Обеспечивает запуск тестов в среде CI, управление информационными базами и загрузку расширений. |

## Архитектура

Взаимодействие компонентов при запуске сценарного тестирования (BDD) реализовано через PowerShell-оркестрацию. Схема процесса запуска:

```text
PowerShell Script (run-bdd.ps1)
    |
    +-- Sync features -> D:\va-test (Latin path)
    |
    +-- Start 1cv8c.exe ENTERPRISE
    |       |
    |       +-- /TESTMANAGER -> VA .epf загружается
    |       |       |
    |       |       +-- StartFeaturePlayer (авто-запуск)
    |       |       +-- VAParams.json (полная конфигурация)
    |       |
    |       +-- TestClient (порт 1538)
    |               |
    |               +-- Выполнение Gherkin-сценариев
    |               +-- BuildStatus.log (0=ok, 1=fail)
    |               +-- JUnit XML отчеты
    |
    +-- Copy results <- D:\va-test\build\reports
```

**Принцип работы:**
1.  Скрипт синхронизирует файлы сценариев (`.feature`) в рабочий каталог с латинским путем.
2.  Запускается клиент 1С в специальном режиме тестирования.
3.  Загружается обработка Vanessa Automation, которая инициализирует TestManager.
4.  TestManager подключается к TestClient, выполняет сценарии и генерирует отчеты.
5.  Результаты копируются в директорию артефактов сборки.

## Критические ограничения платформы

При настройке CI/CD для 1С необходимо учитывать следующие особенности и баги платформы 1С:Предприятие и инструментов тестирования:

| Проблема | Описание | Решение / Workaround |
| :--- | :--- | :--- |
| **Баг платформы 8.3.27** | Параметр запуска `-TPort` с нестандартным портом ломает взаимодействие с TestClient. | Жесткое использование порта **1538**. |
| **Кириллица в путях** | Кириллический путь (например, `D:\1С-Framework`) вызывает ошибки кодировки при передаче через параметр `/C`. | Использование латинского пути `D:\va-test` для конфигурационных файлов VA. |
| **First Run Helper** | При использовании `StartFeaturePlayer` VA ожидает закрытия помощника первого запуска, что приводит к зависанию процесса на 10+ минут. | Установка `DisableFirstRunHelper` в настройках VA или конфигурации. |
| **Конфигурация VA** | Vanessa Automation игнорирует минимальные конфигурационные файлы. | Использование полного шаблона `VAParams.json` (300+ строк) с явно заданными параметрами. |

## Быстрый старт

Для запуска тестов используйте один из следующих способов — от высокоуровневых slash-команд
Claude Code до прямого вызова раннеров.

### Slash-команды Claude Code (рекомендуемый путь для задач 1С)

Полный pipeline от анализа требований до прогона тестов реализован через 4 команды:

```
/analyze-1c-task <ТЗ>                            → ANALYSIS-REPORT
/implement-1c-task <ANALYSIS-REPORT>              → BSL/XML код
/write-1c-tests <TEST-PLAN>                       → features/<task-slug>/*.feature
/run-1c-tests <features/<task-slug>/>             → цепочный прогон с resume
```

Подробности каждой команды, модель цепочки с возобновлением, pre-scenario TestDB check
(Stage 4a), новые параметры `run-bdd.ps1` — см. [17.5 Команды 1С Pipeline](17.5_КОМАНДЫ_ПАЙПЛАЙНА.md).

### Прямой запуск `run-bdd.ps1` (низкоуровневый путь)

**Запуск одного сценария (BDD):**
```powershell
powershell -File tools/vanessa/run-bdd.ps1 -Feature "smoke_testclient.feature"
```

**Запуск всех BDD-сценариев:**
```powershell
powershell -File tools/vanessa/run-bdd.ps1
```

**Запуск с структурированным JSON-результатом** (для интеграции с `/run-1c-tests`):
```powershell
powershell -File tools/vanessa/run-bdd.ps1 `
    -Feature "gkstcplk2256/06_arm_workflow.feature" `
    -RunId "gkstcplk2256-20260411-143000" `
    -TimeoutSec 300
# → build/reports/runs/gkstcplk2256-20260411-143000/result.json
```

**Запуск Unit-тестов (YAxUnit):**
```bash
oscript vrunner xunit ...
```

## Файлы и конфигурация

Основные файлы конфигурации и исполняемые модули, используемые в проекте:

| Путь | Описание |
| :--- | :--- |
| `tools/vanessa/run-bdd.ps1` | Основной скрипт оркестрации запуска BDD тестов. |
| `tools/vanessa/vanessa-automation-single.epf` | Дистрибутив обработки Vanessa Automation (v1.2.043.1). |
| `tools/vanessa/vanessa.json` | Настройки для `vrunner` (устарело/не используется из-за бага с кириллицей). |
| `D:\va-test\VAParams.json` | Рабочий файл полной конфигурации Vanessa Automation. |
| `D:\va-test\va.epf` | Копия обработки VA в рабочем каталоге. |
| `features/*.feature` | Исходные файлы сценариев на Gherkin (синхронизируются скриптом). |
| `build/reports/` | Каталог для генерации отчетов в формате JUnit XML. |
