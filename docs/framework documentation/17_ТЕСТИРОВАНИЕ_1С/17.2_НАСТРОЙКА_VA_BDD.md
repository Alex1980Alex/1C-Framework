# 17.2 Настройка Vanessa Automation BDD

В данном разделе описана процедура настройки окружения для запуска BDD-тестов с использованием Vanessa Automation (VA). Особое внимание уделено специфике работы с платформой 8.3.27 и обработке известных проблем запуска TestClient.

## Предварительные требования

Перед началом настройки убедитесь, что окружение соответствует следующим требованиям:

*   **Платформа 1С:Предприятие:** Версия 8.3.27.1859 (64-bit).
*   **OneScript:** Версия 2.0.0.
    *   Исполняемый файл: `C:\Tools\OneScript\bin\oscript.exe`
*   **vanessa-runner:** Версия 2.6.0.
    *   Путь установки: `C:\Tools\OneScript\lib\vanessa-runner\`
*   **База данных:**
    *   Сервер 1С: `Srvr="KOMPUTER"`
    *   Имя базы: `Ref="TestDB"`
*   **Пользователь запуска:**
    *   Должен обладать ролями: `ПолныеПрава`, `АдминистраторСистемы`, `ИнтерактивноеОткрытиеВнешнихОтчетовИОбработок`.

> **Актуализация окружения (2026-06-04):** dev-стенд мигрировал. Машина `KOMPUTER` → `DESKTOP-TNU600C`, база `TestDB` ретайрнута. Текущая рабочая ИБ — `localhost:1541\ИБTransportManagementDevelop` (логин `a.terletskiy@sodru.com`). Установленная платформа — **8.3.27.1936** (1859 из требований выше не стоит → старый раннер `tools/vanessa/run-bdd.ps1`, прибитый к 1859, падает). Примеры ниже с `KOMPUTER`/`TestDB`/`TestUser` — обобщённые плейсхолдеры; подставляйте актуальные значения. Роль `ИнтерактивноеОткрытиеВнешнихОтчетовИОбработок` критична и для отладочного прогона (см. финальную секцию) — её нет даже у `ПолныеПрава`.

## Порт TestClient (Критическая ошибка 8.3.27)

В версии платформы 1С 8.3.27 выявлен критический баг, влияющий на работу TestClient через Vanessa Automation.

**Суть проблемы:**
При указании параметра `-TPort` с любым значением порта, отличным от `1538`, TestClient запускается как обычный интерактивный сеанс. Процесс `1cv8c.exe` появляется в диспетчере задач, но **TCP-порт не открывается**. В результате VA не может подключиться к клиенту тестирования, и выполнение сценария зависает.

**Результаты тестирования:**
*   Запуск с портами `48010`, `48050`: Процесс активен, порт закрыт (Listen state отсутствует).
*   Запуск с портом `1538` или без параметра `-TPort`: Порт открывается корректно в течение 10 секунд.

**Решение:**
Необходимо жестко зафиксировать использование порта 1538 в настройках Vanessa Automation. Использование динамических диапазонов портов в данной версии платформы невозможно.

## Конфигурация VAParams.json

Файл `VAParams.json` является основным файлом конфигурации для запуска тестов. Ниже приведены критически важные параметры.

### Ключевые параметры

*   **КаталогФич** — Путь к каталогу, содержащему `.feature` файлы с описанием сценариев.
*   **ДиапазонПортовTestclient** — Строка задания диапазона портов. В связи с багом платформы (см. выше), должно быть значение `"1538-1538"`.
*   **ДополнительныеПараметрыЗапускаКлиентаТестирования** — Строка параметров командной строки для 1С. Обязательно должна содержать учетные данные и флаги подавления диалогов: `/N"user" /P"pass" /DisableStartupMessages /DisableStartupDialogs`.
*   **ДанныеКлиентовТестирования** — Массив описаний клиентов. Содержит поля: `Имя`, `ПутьКИнфобазе`, `ПортЗапускаТестКлиента` (должен быть `1538`), `ДопПараметры`, `ТипКлиента` (обычно "Тонкий").
*   **ИмяПодключения** — Имя клиента тестирования из массива `ДанныеКлиентовТестирования`, которое VA должна использовать для текущего запуска.

### Пример конфигурации

```json
{
  "КаталогФич": "D:\\va-test\\features",
  "ДиапазонПортовTestclient": "1538-1538",
  "ДополнительныеПараметрыЗапускаКлиентаТестирования": "/N\"TestUser\" /P\"SecurePass123\" /DisableStartupMessages /DisableStartupDialogs",
  "ДанныеКлиентовТестирования": [
    {
      "Имя": "TestDB",
      "ПутьКИнфобазе": "Srvr=\"KOMPUTER\";Ref=\"TestDB\";",
      "ТипКлиента": "Тонкий",
      "ПортЗапускаТестКлиента": 1538,
      "ДопПараметры": ""
    }
  ],
  "ИмяПодключения": "TestDB",
  "EpfДляИнициализацииБазы": ""
}
```

> **Важно:** Минимальный JSON (~30 строк) приводит к зависанию VA. Необходимо использовать полный шаблон `VAParams.json` (300+ строк) с явно заданными всеми параметрами. Рабочий полный файл находится в `D:\va-test\VAParams.json`.

## Параметры командной строки /C

Для корректной автоматической работы Vanessa Automation необходимо передать специальные параметры через ключ `/C` строки запуска. Эти параметры управляют поведением VA при старте.

### Описание параметров

*   `StartFeaturePlayer` — Запускает выполнение тестов сразу после старта VA (автостарт).
*   `DisableFirstRunHelper` — **ОБЯЗАТЕЛЬНЫЙ ПАРАМЕТР**. Отключает диалоги "первого запуска" и обучающие мастера. Без этого параметра VA зависнет в ожидании реакции пользователя на приветственное окно.
*   `DisableLoadConfig` — Запрещает загрузку пользовательских настроек из хранилища, гарантируя использование настроек из `VAParams.json`.
*   `ClearStepsCache` — Очищает кэш шагов перед запуском. Полезно при разработке новых шагов.
*   `VAParams=путь` — Указывает путь к файлу конфигурации JSON.

### Пример строки запуска

```text
/C"StartFeaturePlayer;DisableFirstRunHelper;DisableLoadConfig;ClearStepsCache;VAParams=D:\va-test\VAParams.json"
```

### Настройка через переменные окружения

Некоторые параметры можно задать через переменные окружения. Они имеют максимальный приоритет.

```text
VANESSA_DisableFirstRunHelper=true
```

## Авто-логин TestClient

При настройке подключения TestClient часто возникает проблема с автоматическим входом в базу.

**Проблема:**
При использовании профиля клиента "Этот клиент" (копирование настроек от менеджера тестов), Vanessa Automation копирует имя пользователя, но **не копирует пароль**. В результате при запуске TestClient появляется диалог "Вход в программу" с пустым полем пароля. Так как интерактивный ввод в режиме тестирования невозможен, TestClient зависает.

**Решение:**
Необходимо явно указать параметры авторизации в поле `ДополнительныеПараметрыЗапускаКлиентаТестирования` в `VAParams.json`. Эти параметры будут добавлены к командной строке запуска TestClient.

**Важное замечание:**
Использование флагов `/DisableStartupMessages` и `/DisableStartupDialogs` без указания `/N` и `/P` приведет к "тихому" зависанию. Диалог входа будет подавлен системой, но так как учетные данные не переданы, сеанс не будет инициализирован, и VA не сможет подключиться к окну.

**Корректный набор параметров:**
```text
/N"user" /P"pass" /DisableStartupMessages /DisableStartupDialogs
```

## Паттерны окон

При работе с TestClient платформа 1С модифицирует заголовки окон, добавляя служебные префиксы и суффиксы. Это необходимо учитывать при написании шагов, проверяющих открытие окон.

**Особенность формирования заголовка:**
TestClient добавляет префикс `[КОПИЯ]` и суффикс темы оформления, например, `(Светлый) /`.

**Пример:**
Если в конфигурации окно называется "Управление транспортом", то в сеансе TestClient заголовок будет выглядеть примерно так:
`[КОПИЯ] Управление транспортом (Светлый) /`

**Проблема:**
Шаг `Тогда открылось окно 'Управление транспортом'` завершится ошибкой, так как точное совпадение строки не будет найдено.

**Решение:**
Использовать маски (wildcards) с символом `*`.

**Правильный вариант шага:**
```gherkin
Тогда открылось окно '*правление транспорто*'
```

**Подсказки VA:**
В сообщении об ошибке неудачного поиска окна Vanessa Automation часто выводит подсказку вида: `Возможная строка шаблона <*правление транспорто*>`. Рекомендуется использовать предложенный шаблон.

## Debug-attached прогон — поймать серверный BP через VA

Отдельный сценарий (не обычный TCP-TestClient BDD-прогон): VA используется как **драйвер UI**, чтобы спровоцировать выполнение **серверного** кода (запись документа / набора записей), на котором стоит breakpoint в [1c-debug-hmr](../36_AUTONOMOUS_DEBUG_CONTROL/36.7_HMR_Subprocess_Wrapper.md). Харнесс воскрешён 2026-06-04 после длительного простоя.

### Отличия от обычного BDD-прогона

| Аспект | Обычный BDD (секции выше) | Debug-attached |
|---|---|---|
| Режим запуска VA | `/TESTCLIENT` + менеджер | `/TESTMANAGER` + `/Execute"va.epf"` |
| Канал к клиенту | TCP-порт 1538 | не нужен (сценарий крутится в самом менеджере) |
| Отладка | нет | TestClient стартует с `/Debug -http /DebuggerURL` |
| Цель | проверить UI-логику | спровоцировать серверный BP fire + чтение переменных |

### Рабочая конфигурация (2026-06-04)

- **Воркспейс:** `D:\va-test\`. Движок `va.epf` = **vanessa-automation-single** `1.2.043.23` (релиз с github `Pr-Mex/vanessa-automation`, в zip `vanessa-automation-single.<ver>.zip`).
- **Платформа:** `C:\Program Files (x86)\1cv8\8.3.27.1936\bin\1cv8c.exe`.
- **ИБ:** `/Slocalhost:1541\ИБTransportManagementDevelop`, логин `a.terletskiy@sodru.com`.
- **Право (КРИТИЧНО):** запускающему пользователю нужна роль `ИнтерактивноеОткрытиеВнешнихОтчетовИОбработок` — без неё VA падает модалкой **«Нарушение прав доступа!»**. Её нет даже у `ПолныеПрава`. Под это создан сервисный пользователь `CiBotForVA`.

### Инжекция /Debug в TestClient (НЕ через `testclientdebug`)

VA-параметр `testclientdebug` шлёт TestClient'у `/debug` **без** `-http` → платформа поднимает TCP-отладку, конфликтующую с HTTP-отладчиком `dbgs.exe :1550` (RC3 protocol mismatch). Вместо этого флаги отладки инжектятся в `AdditionalParametersForLaunchingTheTestingClient` (`ДополнительныеПараметрыЗапускаКлиентаТестирования`):

```text
/P"<pwd>" /Debug -http /DebuggerURL=http://localhost:1550
```

> `/DebuggerURL` — именно `http://`, не `tcp://` (порт 1550 = HTTP-порт ragent, запущенного с `-debug -http`). См. memory `feedback_1c_debug_url_protocol`.

### Команда запуска (одной строкой)

```text
1cv8c.exe ENTERPRISE /Slocalhost:1541\ИБTransportManagementDevelop /N"a.terletskiy@sodru.com" /P"<pwd>" /DisableStartupMessages /DisableStartupDialogs /TESTMANAGER /Execute"D:\va-test\va.epf" /C"StartFeaturePlayer;DisableFirstRunHelper;VAParams=D:\va-test\VAParams.json" /out"D:\va-test\va-out.txt"
```

### Как поймать серверный BP

1. `debug_connect` + `debug_capture_mode` (break-on-next), BP на серверной строке модуля.
2. Запись TestClient'а уходит в **тёплый pre-existing rphost** (он не attached к сессии) → BP не стреляет. Решение: **убить** этот rphost (нужен admin) — запись пойдёт в свежий attached rphost. Полный разбор warm-pool ceiling — [36.6 Диагностика](../36_AUTONOMOUS_DEBUG_CONTROL/36.6_Диагностика.md), автономный JOB-обход — [36.8 §10.1](../36_AUTONOMOUS_DEBUG_CONTROL/36.8_Advanced_Debug_Features.md).
3. Halt на BP записи РС **транзиентный (~сек)** → читать переменные через **logpoint** ([`debug_set_logpoint`](../36_AUTONOMOUS_DEBUG_CONTROL/36.8_Advanced_Debug_Features.md#3-p0b--logpoints-tracepoints)), а не async `debug_evaluate` — последний не успевает в окно halt'а.

### Подводные камни сценария

- **Артефакт «BP не стреляет»:** запись через `Выполнить(СтрокаКода)` атрибутирует halt кадру оператора `Выполнить`, а не register-строке. Нужен статический триггер: форма / TestClient / именованный метод в `ФоновыеЗадания.Выполнить("ОбщийМодуль.Метод")`.
- **Заполнение формы записи РС:** все обязательные поля верного типа (`НомерУдостоверения` = Число, даты `dd.mm.yyyy`), иначе модалка «некорректные данные». Брать регистрацию без уже существующего удостоверения (иначе дубль ключа РС).
