# 18.1 Обзор AutoResearch

## Паттерн

AutoResearch — универсальный движок итеративных улучшений с измеримыми метриками.

```
measure → change → verify → keep/revert → repeat
```

**Ключевое:** это не разовые действия. Это непрерывный цикл, встроенный в систему. Скиллы деградируют (модели обновляются, код меняется, появляются новые паттерны). Улучшение должно быть автоматическим и постоянным.

## Архитектура

```
                ┌─────────────────────────┐
                │     /autoresearch       │
                │   (универсальный движок) │
                └────────────┬────────────┘
                             │
          ┌──────────────────┼──────────────────┐
          │                  │                  │
          ▼                  ▼                  ▼
 ┌────────────────┐ ┌────────────────┐ ┌────────────────┐
 │  Domain: Code  │ │ Domain: Skills │ │ Domain: 1C     │
 │ metric: errors │ │ metric: F1     │ │ metric: cover% │
 │ tools: ruff    │ │ tools: eval.py │ │ tools: MCP     │
 │ scope: src/    │ │ scope: .claude/│ │ scope: cache/  │
 └────────────────┘ └────────────────┘ └────────────────┘
          │                  │                  │
          ▼                  ▼                  ▼
 ┌────────────────────────────────────────────────────┐
 │              ОДИНАКОВЫЙ ЦИКЛ:                      │
 │  Executor → Reviewer → Comparator → Log → Repeat   │
 └────────────────────────────────────────────────────┘
```

**Один движок. Разные домены. Одинаковый цикл.**

## 10 фаз алгоритма

| Фаза | Действие | Описание |
|------|----------|----------|
| 1 | IDEA | Сформулировать гипотезу улучшения |
| 2 | ANALYZE | ultrathink: глубокий анализ проблемы и подходов |
| 3 | BASELINE | Зафиксировать текущую метрику (git commit) |
| 4 | RECIPE | Выбрать рецепт домена (метрика + tools + verify) |
| 5 | EXECUTE | Executor вносит ОДНО изменение |
| 6 | REVIEW | Reviewer запускает verify, фиксирует метрику |
| 7 | COMPARE | Comparator: слепое A/B каждые 5 итераций |
| 8 | LOG | Записать в autoresearch.jsonl |
| 9 | DECIDE | metric↑ → KEEP (commit) / metric↓ → REVERT |
| 10 | REPEAT | Следующая итерация или стоп |

## 3 агента

| Агент | Роль | Правило |
|-------|------|---------|
| **Executor** | Вносит ОДНО изменение по рецепту | Не оценивает результат — только выполняет |
| **Reviewer** | Запускает verify, сравнивает метрику | Беспристрастен: только цифры → verdict |
| **Comparator** | Слепое A/B каждые 5 итераций | Финальный арбитр при спорных дельтах |

## Домены и рецепты

| Домен | Метрика | Verify Command | Scope | Приоритет |
|-------|---------|----------------|-------|-----------|
| Скиллы | F1 (eval-skill-router.py) | `python scripts/eval-skill-router.py` | `.claude/skills/` | P0 |
| Хуки | eval-hooks accuracy | `python scripts/eval-hooks.py` | `.claude/hooks/` | P0 |
| Python | ruff + mypy errors | `ruff check src/ --output-format json` | `src/` | P1 |
| BSL | bsl_analyze errors | `bsl_analyze --json` | `src/bsl/` | P1 |
| 1С конфиг | coverage % | `python scripts/1c_coverage.py` | `cache/` | P1 |
| Документация | audit-docs score | `Skill('audit-docs')` | `docs/` | P2 |
| API | response time ms | `pytest-benchmark` | `src/api/` | P2 |
| Безопасность | findings count | `bandit -r src/ -f json` | `src/` | P2 |
| Промпты | quality score | LLM-graded eval | prompts | P3 |
| Мета | keep rate | iterations to target | autoresearch | P3 |

## Persistence между сессиями

**autoresearch.md** — живой документ с состоянием цикла:
```markdown
# AutoResearch: [задача]
Домен: skills | Метрика: F1 | Baseline: 0.6049
Итерация: 7 | Текущая: 0.72 | Тренд: ↑ +0.12
```

**autoresearch.jsonl** — лог экспериментов:
```jsonl
{"ts":"...","iter":1,"metric":0.6049,"delta":0,"action":"baseline"}
{"ts":"...","iter":2,"metric":0.6651,"delta":0.0602,"action":"keep","desc":"YAML+config fix"}
```

## Стоп-условия

- Достигнут целевой порог метрики
- 5 итераций подряд без улучшений (плато)
- Превышен лимит итераций (max_iterations)
- Критическая ошибка (тесты сломаны, код не компилируется)
- Маркер `RALPH_DONE` (при работе через ralph.bat)
