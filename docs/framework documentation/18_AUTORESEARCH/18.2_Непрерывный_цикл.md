# 18.2 Непрерывный цикл

## Три уровня мониторинга

AutoResearch работает не как разовая задача, а как непрерывная система на трёх уровнях:

```
Уровень 1 (хуки)           Уровень 2 (ночной)         Уровень 3 (ручной)
────────────────            ──────────────────          ─────────────────
Каждый промпт              Раз в неделю                По запросу
Пассивный сбор             Автономное исправление      Целенаправленная работа
ДАТЧИК                     АВТОПИЛОТ                   РУЧНОЕ УПРАВЛЕНИЕ
```

**Аналогия:**
- Уровень 1 = **приборная панель** (показывает температуру двигателя)
- Уровень 2 = **автоматический термостат** (температура высокая → охлаждает)
- Уровень 3 = **механик** (разобрал двигатель, нашёл причину, починил)

## Уровень 1: Автоматический (хуки — каждый промпт)

Хуки работают на каждом промпте, молча собирают данные и ловят деградацию.

| Хук | Событие | Что делает |
|-----|---------|-----------|
| `skill-quality-monitor.py` | UserPromptSubmit | Логирует: рекомендованные скиллы, активированные, ручные вызовы |
| `task-protocol-observer.py` | PostToolUse:Skill | Записывает: какой скилл активирован |

**Данные** сохраняются в `data/skill-accuracy.jsonl`. Два типа событий:
```json
{"ts": "2026-03-15T10:23:00", "type": "recommend", "prompt_id": "abc123_5", "skills": ["pdf-knowledge", "search-pipeline-debug"]}
{"ts": "2026-03-15T10:23:01", "type": "activate",  "prompt_id": "abc123_5", "skill": "pdf-knowledge"}
```

**Принцип:** только логирование, без блокировок. Если хук упал — молча, без влияния на работу.

## Уровень 2: Периодический (ночной AutoResearch цикл)

Раз в неделю (или по расписанию) — автономный цикл улучшений.

```
1. Прочитать data/skill-accuracy.jsonl
   → Какие скиллы с высоким waste rate? (recommend без activate)
   → Какие скиллы не вызывались > 30 дней? (мёртвые)
   → Какие скиллы вызывались вручную? (activate без recommend = router miss)

2. Для каждого проблемного скилла:
   AutoResearch цикл (Executor → Reviewer):
   - Executor: переписывает description (pushy стиль)
   - Reviewer: eval-skill-router.py → F1 вырос?
   - Keep / Revert

3. Обновить data/skill-health-report.md

Запуск:
  scripts\ralph.bat --template skill-health --max-iterations 15
  powershell -File scripts\autoresearch.ps1 -Domain skill-health
```

## Уровень 3: Ручной (/autoresearch — по запросу)

Пользователь видит конкретную проблему и запускает целенаправленный цикл:

```
> /autoresearch
> bsl-development скилл срабатывает на запросы про Python, почини
```

## Взаимодействие уровней по доменам

| Домен | Уровень 1 (хук-датчик) | Уровень 2 (ночной цикл) | Уровень 3 (ручной) |
|-------|------------------------|--------------------------|---------------------|
| Скиллы | skill-quality-monitor | `ralph --template skill-health` | `/autoresearch` |
| Хуки | hook-invocation-logger | `ralph --template hook-quality` | `/autoresearch` |
| Python | code-review-enforcer | `ralph --template quality` | `/autoresearch` |
| BSL | bsl-tool-router | `ralph --template bsl` | `/autoresearch` |
| 1С знания | knowledge-cache-reminder | `ralph --template 1c-study` | `/autoresearch` |
| Документация | docs-change-enforcer | `ralph --template docs` | `/autoresearch` |

## Жизненный цикл скилла

```
Создание                  Жизнь                          Смерть
────────                  ─────                          ──────

  doc-to-skill     →    Хуки мониторят usage        →   Comparator: "скилл
  или вручную      →    Eval проверяет triggers     →   не приносит пользы"
                   →    Ночной цикл правит desc     →   → архивация
                   │    Модель обновилась?           │
                   │      → re-eval автоматически    │
                   │    Код изменился?               │
                   │      → docs-change-enforcer     │
                   │    Пользователь вызвал вручную? │
                   │      → плохой trigger,          │
                   │        ночной цикл починит      │
                   └─────────────────────────────────┘
                         НЕПРЕРЫВНО
```

Архивированные скиллы перемещаются в `.claude/skills/_archived/` с записью в таблице причин и метрик.
