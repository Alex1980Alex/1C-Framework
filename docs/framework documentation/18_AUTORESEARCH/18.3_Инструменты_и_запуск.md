# 18.3 Инструменты и запуск

## Быстрый старт

```powershell
# Базовый запуск: домен + лимит итераций
.\scripts\autoresearch.ps1 -Domain skill-health -MaxIterations 5

# С целевой метрикой (остановка при достижении)
.\scripts\autoresearch.ps1 -Domain skills -MaxIterations 20 -Target 0.85

# Через ralph.bat (шаблонный запуск)
scripts\ralph.bat --template skill-health --max-iterations 15
```

Оба скрипта запускают Claude Code в headless-режиме (`claude -p ... --dangerously-skip-permissions`) — все операции выполняются без подтверждений.

---

## Параметры autoresearch.ps1

```powershell
.\scripts\autoresearch.ps1
  -Domain <string>        # ОБЯЗАТЕЛЬНЫЙ — выбор рецепта (см. таблицу ниже)
  -MaxIterations <int>    # макс итераций (по умолчанию 10)
  -Target <string>        # целевая метрика — стоп при достижении
```

## Когда какой домен запускать

### Таблица решений

| Ситуация | Домен | Пример команды |
|----------|-------|----------------|
| Skill Router рекомендует не те скиллы | `skill-health` | `-Domain skill-health -MaxIterations 10` |
| Хочу повысить F1 роутера точечно | `skills` | `-Domain skills -MaxIterations 15 -Target 0.85` |
| ruff/mypy ругаются на Python код | `python-quality` | `-Domain python-quality -Target 0` |
| Хуки срабатывают неточно | `hooks` | `-Domain hooks -MaxIterations 10` |
| bandit нашёл уязвимости | `security` | `-Domain security -MaxIterations 15` |
| Покрытие тестами низкое | `tests` | `-Domain tests -MaxIterations 10` |
| Нет документации к модулям | `docs` | `-Domain docs -MaxIterations 10` |
| BSL код с ошибками | `bsl` | `-Domain bsl -MaxIterations 10` |

### Блок-схема выбора

```
Что нужно улучшить?
│
├── Скиллы / Skill Router
│   ├── Видишь waste=1.00 в health report   → skill-health
│   ├── Видишь ROUTER MISS                  → skill-health
│   ├── Хочешь повысить F1 конкретного      → skills
│   └── Первый запуск, не знаешь что        → skill-health (диагностика)
│
├── Качество кода
│   ├── Python (ruff/mypy ошибки)           → python-quality
│   ├── BSL (bsl_analyze ошибки)            → bsl
│   └── Уязвимости (bandit findings)        → security
│
├── Покрытие
│   ├── Тесты (pytest coverage)             → tests
│   └── Документация (docstrings)           → docs
│
└── Инфраструктура
    └── Хуки (eval-hooks accuracy)          → hooks
```

## 8 доменов — подробное описание

### 1. skill-health — здоровье Skill Router

**Когда:** Skill Router рекомендует ненужные скиллы (HIGH WASTE), пропускает нужные (ROUTER MISS), или скиллы никогда не используются (NEVER USED).

**Что делает за 1 итерацию:**
1. Запускает `skill-health-analyzer.py --no-eval` — читает `data/skill-accuracy.jsonl`, строит health report
2. Находит ОДИН проблемный скилл (по приоритету: HIGH WASTE > ROUTER MISS > NEVER USED)
3. Вносит ОДНО изменение:
   - HIGH WASTE → сужает description в SKILL.md (убирает generic слова, добавляет "НЕ для")
   - ROUTER MISS → добавляет keywords/utterances в skill-router-config.json
   - NEVER USED → архивирует в `.claude/skills/_archived/`
4. `git commit` + `eval-skill-router.py` → F1
5. KEEP если F1 не упал, REVERT если упал

**Verify:** `python scripts/eval-skill-router.py`

**Типичный запуск:**
```powershell
.\scripts\autoresearch.ps1 -Domain skill-health -MaxIterations 10
```

**Пример вывода одной итерации:**
```
=== Iteration 3 / 10 [2026-03-16T21:03:06] ===
  Запуск Claude...

Выполнено:
1. Запущен skill-health-analyzer.py --no-eval
2. Найден ROUTER MISS: create-hook (5 manual activations)
3. Добавлены 8 weighted_keywords в bundle "creation"
4. Config version: 8 → 9
5. Verify: F1 = 0.7224 (стабильный)
6. VERDICT: KEEP

  KEEP: metric=0.7224 delta=0.0035
```

**Когда НЕ использовать:**
- Если `data/skill-accuracy.jsonl` пустой или < 100 записей — недостаточно данных
- Если нужно улучшить конкретный скилл — используй `skills`

### 2. skills — точечное улучшение description

**Когда:** Хочешь повысить F1 конкретного скилла через pushy description (триггеры + негативные маркеры).

**Что делает за 1 итерацию:**
1. Claude сам выбирает скилл со слабым description
2. Переписывает description в YAML frontmatter SKILL.md
3. `git commit` + `eval-skill-router.py` → F1
4. KEEP/REVERT по результату

**Verify:** `python scripts/eval-skill-router.py`

**Типичный запуск:**
```powershell
# Улучшать пока F1 не дойдёт до 0.85
.\scripts\autoresearch.ps1 -Domain skills -MaxIterations 20 -Target 0.85

# Просто 5 итераций
.\scripts\autoresearch.ps1 -Domain skills -MaxIterations 5
```

**Разница с skill-health:**
- `skills` — Claude сам выбирает скилл, правит только description
- `skill-health` — анализирует health report, правит description ИЛИ config ИЛИ архивирует

### 3. python-quality — исправление ошибок ruff

**Когда:** В Python коде (src/) есть ошибки линтера. Цель — довести до 0.

**Что делает за 1 итерацию:**
1. `ruff check src/` — находит самую частую категорию ошибок
2. Исправляет ВСЕ файлы с этой категорией
3. `git commit` + `ruff check src/ --output-format json` → количество ошибок
4. KEEP/REVERT

**Verify:** `ruff check src/ --output-format json`

**Типичный запуск:**
```powershell
# Цель: 0 ошибок
.\scripts\autoresearch.ps1 -Domain python-quality -Target 0

# Или просто N итераций
.\scripts\autoresearch.ps1 -Domain python-quality -MaxIterations 15
```

**Пример:** если самая частая ошибка — `F401 unused import`, Claude найдёт все файлы с F401 и удалит неиспользуемые импорты за одну итерацию. Следующая итерация — следующая категория.

### 4. hooks — улучшение хуков

**Когда:** Хуки срабатывают неточно (ложные срабатывания или пропуски).

**Что делает за 1 итерацию:**
1. `eval-hooks.py` — находит хук с наихудшей accuracy
2. Правит signals/threshold/matcher в хуке
3. `git commit` + `eval-hooks.py` → accuracy
4. KEEP/REVERT

**Verify:** `python scripts/eval-hooks.py`

**Типичный запуск:**
```powershell
.\scripts\autoresearch.ps1 -Domain hooks -MaxIterations 10
```

### 5. security — исправление уязвимостей

**Когда:** `bandit -r src/` находит уязвимости. Исправляет безопасность, НЕ меняет бизнес-логику.

**Что делает за 1 итерацию:**
1. `bandit -r src/` — находит одну уязвимость
2. Исправляет (только безопасность)
3. `git commit` + `bandit -r src/ -f json` → количество findings
4. KEEP/REVERT

**Verify:** `bandit -r src/ -f json`

**Типичный запуск:**
```powershell
.\scripts\autoresearch.ps1 -Domain security -MaxIterations 15
```

### 6. tests — написание тестов

**Когда:** Покрытие тестами низкое. Claude пишет unit-тесты для одного непокрытого модуля за итерацию.

**Что делает за 1 итерацию:**
1. `pytest --cov` — находит непокрытый модуль
2. Пишет unit-тесты
3. `git commit` + `pytest --cov=src -q` → coverage %
4. KEEP/REVERT

**Verify:** `pytest --cov=src -q`

**Типичный запуск:**
```powershell
.\scripts\autoresearch.ps1 -Domain tests -MaxIterations 10
```

### 7. docs — документирование

**Verify:** `echo METRIC: 0` (метрика-заглушка, verify вручную)

## Детальный поток итерации

Каждая итерация — один вызов `claude -p` с полным протоколом:

```
┌─────────────────────────────────────────────────────────────┐
│  autoresearch.ps1 формирует промпт:                        │
│                                                            │
│  "AutoResearch итерация {i} из {max}. Домен: {domain}.    │
│                                                            │
│   ЗАДАЧА: {recipe.Prompt}                                  │
│                                                            │
│   ПРОТОКОЛ:                                                │
│   1. git log --oneline -3 (контекст)                       │
│   2. Внеси ОДНО изменение                                  │
│   3. git commit -m '[AR] {domain} iter {i}: описание'      │
│   4. Запусти verify: {recipe.Verify}                       │
│   5. Выведи: METRIC: число                                 │
│   6. Сравни → VERDICT: KEEP или VERDICT: REVERT            │
│   7. Если REVERT → git revert HEAD --no-edit               │
│   8. Если всё завершено → AUTORESEARCH_DONE"               │
└──────────────────────────┬──────────────────────────────────┘
                           │
                           ▼
              claude -p "промпт" --dangerously-skip-permissions
                           │
                           ▼
┌─────────────────────────────────────────────────────────────┐
│  autoresearch.ps1 парсит вывод Claude:                     │
│                                                            │
│  1. METRIC:\s*([\d.]+)  → метрика (число)                  │
│     fallback: F1[\s:=]+([\d.]+) → для случаев F1: 0.72    │
│                                                            │
│  2. VERDICT:\s*KEEP     → action = "keep"                  │
│     VERDICT:\s*REVERT   → action = "revert"                │
│                                                            │
│  3. AUTORESEARCH_DONE   → полная остановка цикла           │
│                                                            │
│  4. Обновляет bestMetric, plateauCount                     │
│  5. Записывает в data/autoresearch.jsonl                   │
│  6. Сохраняет состояние в data/autoresearch.md             │
└─────────────────────────────────────────────────────────────┘
```

### Стоп-условия

| Условие | Описание |
|---------|----------|
| `AUTORESEARCH_DONE` | Claude решил что задача полностью завершена |
| Target достигнут | `bestMetric >= Target` (если задан `-Target`) |
| Плато | 5 итераций подряд без улучшения метрики |
| MaxIterations | Лимит исчерпан |

## Практические сценарии

### Сценарий 1: Первый запуск — диагностика скиллов

Не знаешь с чего начать? Запусти skill-health на 3 итерации:

```powershell
.\scripts\autoresearch.ps1 -Domain skill-health -MaxIterations 3
```

Результат: health report в `data/skill-health-report.md` покажет:
- HIGH WASTE — какие скиллы шумят
- ROUTER MISS — какие скиллы роутер не находит
- NEVER USED — кандидаты на архивацию

### Сценарий 2: Довести F1 до целевого значения

```powershell
.\scripts\autoresearch.ps1 -Domain skills -MaxIterations 30 -Target 0.85
```

Claude будет итеративно улучшать description скиллов пока F1 не достигнет 0.85 или не упрётся в плато.

### Сценарий 3: Вычистить все ошибки ruff

```powershell
.\scripts\autoresearch.ps1 -Domain python-quality -Target 0
```

За каждую итерацию Claude исправит одну категорию ошибок (F401, E501, W291...). При `-Target 0` остановится когда ошибок не останется.

### Сценарий 4: Ночной цикл безопасности

```powershell
.\scripts\autoresearch.ps1 -Domain security -MaxIterations 20
```

Автономно исправляет уязвимости по одной. Каждое исправление в отдельном коммите — легко review и откат.

### Сценарий 5: Продолжение прерванного цикла

autoresearch.ps1 сохраняет состояние в `data/autoresearch.md`:

```markdown
# AutoResearch Session
Domain: skill-health
Iteration: 7
BestMetric: 0.73
Plateau: 1
Target:
Updated: 2026-03-16T22:30:00
```

При повторном запуске с тем же доменом продолжит с итерации 8:

```powershell
# Продолжит с итерации 8
.\scripts\autoresearch.ps1 -Domain skill-health -MaxIterations 15
```

### Сценарий 6: Разовая задача через ralph.bat

```batch
rem Произвольный промпт — 10 итераций
scripts\ralph.bat 10 "Исправь все ошибки ruff в src/"

rem Шаблон — skill-health
scripts\ralph.bat --template skill-health --max-iterations 15
```

## Инструменты анализа

### skill-health-analyzer.py

Читает `data/skill-accuracy.jsonl` (реальные события recommend/activate от skill-router.py), строит health report.

```bash
# Полный анализ за 30 дней + F1 eval
python scripts/skill-health-analyzer.py

# Без eval (быстрее), за 7 дней, порог 2 записи
python scripts/skill-health-analyzer.py --no-eval --days 7 --min-samples 2

# В кастомный файл
python scripts/skill-health-analyzer.py --output reports/health.md
```

**Источник данных:** `data/skill-accuracy.jsonl` — JSONL с двумя типами событий:

```json
{"type": "recommend", "prompt_id": "e19e4ee5", "skills": ["create-hook", "triad-factory"], "ts": "..."}
{"type": "activate",  "prompt_id": "e19e4ee5", "skill": "create-hook", "ts": "..."}
```

Записи пишутся хуками `skill-router.py` (recommend) и `skill-usage-metrics.py` (activate).

**Метрики per-skill:**
- **Precision** = activated / recommended (роутер попал?)
- **Waste** = (recommended - activated) / recommended (бесполезные рекомендации)
- **Manual** = activated but NOT recommended (роутер пропустил)

**Пример вывода:**
```
# Skill Router Health Report

**Total prompts:** 4367
**Unique skills:** 67

| Skill | Recs | Acts | Manual | Precision | Waste |
|-------|------|------|--------|-----------|-------|
| langchain-core | 589 | 0 | 1 | 0.00 | 1.00 |
| bsl-development | 7 | 3 | 18 | 0.43 | 0.57 |
| 1c-mcp-toolkit | 1 | 1 | 1 | 1.00 | 0.00 |

## Action Items
### HIGH WASTE — langchain-core: waste=1.00 (589 recs, 0 acts)
### ROUTER MISS — bsl-development: 18 manual activations
```

### eval-skill-router.py

Ground truth eval с 73 промптами. Выводит F1, precision, recall.

```bash
python scripts/eval-skill-router.py
```

**Пример вывода:**
```
Loaded 73 ground truth samples

Skill Metrics — Required Only:
  Precision: 0.8242
  Recall:    0.7648
  F1:        0.7224
  TP=62 FP=21 FN=27

Bundle Metrics:
  F1:        0.7443

Top False Positives (5):
  "Настрой REST API endpoint" -> extra: ['framework-mcp-ui', 'indexing-pipeline']

Top False Negatives (5):
  "Как подключить MCP сервер" -> missed: ['langchain-mcp-tools']
```

### audit-skill-freshness.py

Сканирует YAML frontmatter, находит скиллы без `last_verified` или с устаревшей датой.

```bash
python scripts/audit-skill-freshness.py
python scripts/audit-skill-freshness.py --days 60
```

## Разница autoresearch.ps1 vs ralph.bat

| | autoresearch.ps1 | ralph.bat |
|---|---|---|
| **Домены** | 8 встроенных рецептов | 8 шаблонов + произвольный промпт |
| **Persistence** | Да (`data/autoresearch.md`) | Нет |
| **Парсинг метрики** | `METRIC:` + `F1:` + `VERDICT:` | `RALPH_DONE` маркер |
| **Плато-детекция** | 5 итераций без улучшений → стоп | Нет |
| **Target** | `-Target 0.85` → стоп при достижении | Нет |
| **JSONL лог** | `data/autoresearch.jsonl` | Нет |
| **Когда** | Длинные циклы с метрикой | Разовые задачи |

## Архив скиллов

Бесполезные скиллы перемещаются в `.claude/skills/_archived/`:

```
.claude/skills/_archived/
  <skill-name>/
    SKILL.md
```

**Критерии архивации:**
- NEVER USED: recommended 10+ раз, activated 0
- Ручное решение пользователя

**Восстановление:** переместить обратно в `.claude/skills/` и добавить в `skill-router-config.json`.

## Troubleshooting

### Метрика всегда null в autoresearch.jsonl

**Причина:** Claude выводит метрику в формате `F1: 0.72` вместо `METRIC: 0.72`.

**Решение:** Исправлено в v9 — скрипт парсит оба формата: `METRIC:\s*([\d.]+)` и fallback `F1[\s:=]+([\d.]+)`.

### skill-health-analyzer.py показывает 0 промптов

**Причина (до v9):** Analyzer читал из несуществующего `skill-quality-metrics.jsonl`.

**Решение:** Исправлено в v9 — analyzer читает из `data/skill-accuracy.jsonl` (реальные данные от skill-router.py).

### Claude галлюцинирует результаты

**Симптом:** AutoResearch отчитывается об изменениях, которых нет в git.

**Причина:** `--dangerously-skip-permissions` + длинная сессия → Claude теряет контекст.

**Решение:** Проверяй `git log --oneline -5` после каждого прогона. Используй меньше итераций (5-10 вместо 20+).

### Плато после 2-3 итераций

**Причина:** Все "лёгкие" улучшения уже сделаны, оставшиеся требуют глубоких изменений.

**Решение:** Переключись на другой домен или запусти ручной `/autoresearch` в интерактиве для точечной работы.
