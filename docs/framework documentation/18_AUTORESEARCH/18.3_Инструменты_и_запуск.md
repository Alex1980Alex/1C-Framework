# 18.3 Инструменты и запуск

## Быстрый старт: как запустить

### Принудительный режим (автономный — без подтверждений)

Оба скрипта (`ralph.bat` и `autoresearch.ps1`) запускают Claude Code в headless-режиме с флагом `--dangerously-skip-permissions` — Claude выполняет все операции (Read, Write, Edit, Bash, git) без запроса подтверждения пользователя.

```powershell
# PowerShell — полная автономия
.\scripts\autoresearch.ps1 -Domain skill-health -MaxIterations 15

# Batch — через шаблон
scripts\ralph.bat --template skill-health --max-iterations 15

# Batch — произвольный промпт
scripts\ralph.bat 10 "Исправь все ошибки ruff в src/"
```

**Что происходит под капотом:**
1. Скрипт вызывает `claude -p "<prompt>" --dangerously-skip-permissions`
2. Устанавливает `RALPH_ENABLED=1` (env) — guard от ложной активации ralph_activator в интерактиве
3. Claude выполняет одну итерацию: изменение → verify → METRIC/VERDICT
4. Скрипт парсит вывод: `VERDICT: KEEP` или `VERDICT: REVERT`
5. Повторяет до стоп-условия (target / плато / max iterations / `RALPH_DONE`)

**Предосторожности:**
- Все изменения через git — можно откатить (`git revert`, `git log`)
- autoresearch.ps1 сохраняет состояние в `data/autoresearch.md` (возобновляемость)
- Лог каждой итерации: `data/autoresearch_<domain>_<date>.log`
- ralph.bat пишет лог в `data/ralph_log_<date>.txt`

### Интерактивный режим (с подтверждениями)

Для ручного контроля используй `/autoresearch` в чате Claude Code:

```
> /autoresearch
> Улучши F1 skill router до 0.85
```

Claude анализирует, создаёт рецепт, выполняет по шагам с подтверждением каждого действия.

## Детальный поток итерации (на примере `skill-health`)

Каждая итерация — это один вызов `claude -p` с полным протоколом. Claude получает промпт и выполняет 6 шагов автономно.

### Шаг 1: ЗАМЕР — запуск диагностики

Claude запускает два скрипта:

```bash
python scripts/skill-health-analyzer.py --no-eval   # → data/skill-health-report.md
python scripts/eval-skill-router.py                  # → F1 score (например 0.72)
```

`skill-health-analyzer.py` читает пассивные метрики из `data/skill-quality-metrics.jsonl` (собираются хуком `skill-quality-monitor.py` на каждый промпт), вычисляет per-skill статистику и генерирует отчёт с тремя категориями проблем.

### Шаг 2: АНАЛИЗ — поиск проблемного скилла

Claude читает `data/skill-health-report.md` и находит **один** проблемный скилл:

| Категория       | Критерий в коде                       | Что значит                                                                            | Что Claude делает                                                                                              |
| --------------- | ------------------------------------- | ------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------- |
| **HIGH WASTE**  | `recommended > 5` и `waste > 80%`     | Роутер рекомендует скилл, но пользователь его не активирует — trigger слишком широкий | Редактирует `SKILL.md` — **сужает description** (убирает общие слова, добавляет негативные маркеры "НЕ для X") |
| **ROUTER MISS** | `manual_count > 2`                    | Пользователь вызывает скилл вручную — роутер не подобрал                              | Редактирует `skill-router-config.json` — **добавляет keywords/utterances** в бандл скилла                      |
| **NEVER USED**  | `recommended > 10` и `activated == 0` | Рекомендуется часто, но никто не использует — бесполезен                              | **Перемещает** в `.claude/skills/_archived/`                                                                   |

### Шаг 3: ИЗМЕНЕНИЕ — ровно одно действие

Claude вносит **одно** изменение к **одному** скиллу. Примеры:

**HIGH WASTE** — сужение description:
```
БЫЛО:  "Embedding models — работа с моделями эмбеддингов"
СТАЛО: "Embedding Models — выбор, настройка и отладка моделей эмбеддингов.
        ИСПОЛЬЗУЙ когда выбираешь модель (E5, BGE, Jina), настраиваешь ONNX,
        исправляешь dimension mismatch. Триггеры: 'embedding', 'E5', 'dimension'.
        НЕ для общих вопросов про ML — используй tech-research."
```

**ROUTER MISS** — добавление keywords в config:
```json
// skill-router-config.json → бандл скилла
{
  "skills": ["graph-operations"],
  "keywords": ["граф", "graph", "entity", "связи", "LightRAG"],
  "utterances": ["построй граф знаний", "найди связи между"]
}
```

**NEVER USED** — архивация:
```bash
mv .claude/skills/unused-skill/ .claude/skills/_archived/unused-skill/
# + удаление из skill-router-config.json
```

### Шаг 4: КОММИТ + VERIFY

```bash
git commit -m "[AR] skill-health iter 3: narrow embedding-models description"
python scripts/eval-skill-router.py   # → F1 = 0.73
```

### Шаг 5: РЕШЕНИЕ

Claude сравнивает F1 с предыдущим значением и выводит вердикт:

| Результат              | Вердикт                      | Действие                                               |
| ---------------------- | ---------------------------- | ------------------------------------------------------ |
| F1 вырос (0.73 > 0.72) | `VERDICT: KEEP`              | Коммит остаётся                                        |
| F1 упал (0.71 < 0.72)  | `VERDICT: REVERT`            | `git revert HEAD --no-edit`                            |
| F1 не изменился        | `VERDICT: KEEP` или `REVERT` | На усмотрение Claude (обычно KEEP если нет деградации) |

### Шаг 6: СЛЕДУЮЩАЯ ИТЕРАЦИЯ

Скрипт записывает результат в `data/autoresearch.jsonl`:
```json
{"ts":"2026-03-15T22:30:00","iter":3,"domain":"skill-health","metric":0.73,"delta":0.01,"action":"keep"}
```

Обновляет `data/autoresearch.md` (живой документ — Domain, Iteration, BestMetric, Plateau) и переходит к итерации 4 — Claude **снова** запускает health analyzer, находит **следующий** проблемный скилл, повторяет.

### Стоп — скрипт останавливается когда

1. **Target достигнут** — например `F1 >= 0.85`
2. **Плато 5 итераций** — 5 подряд без улучшения metric (всё REVERT или delta=0)
3. **Max iterations** — лимит исчерпан
4. **`AUTORESEARCH_DONE`** — Claude решил что всё сделано (нет проблем в health report)

## Что конкретно делает каждый домен за 1 итерацию

| Домен            | Шаг 1: Диагностика                                | Шаг 2-3: Изменение                                                             | Шаг 4: Verify                                  |
| ---------------- | ------------------------------------------------- | ------------------------------------------------------------------------------ | ---------------------------------------------- |
| `skill-health`   | `skill-health-analyzer.py` → health report        | Правка description ИЛИ config ИЛИ архивация (по категории проблемы)            | `eval-skill-router.py` → F1                    |
| `skills`         | Claude сам выбирает скилл со слабым description   | Переписывает description в pushy-стиле (триггеры + негативные маркеры)         | `eval-skill-router.py` → F1                    |
| `python-quality` | `ruff check src/` → самая частая категория ошибок | Исправляет ВСЕ файлы с этой категорией                                         | `ruff check src/ --output-format json` → count |
| `hooks`          | `eval-hooks.py` → хук с worst accuracy            | Правит signals/threshold в хуке                                                | `eval-hooks.py` → accuracy                     |
| `security`       | `bandit -r src/` → одна уязвимость                | Исправляет уязвимость (только безопасность, не логику)                         | `bandit -r src/ -f json` → count               |
| `tests`          | `pytest --cov` → непокрытый модуль                | Пишет unit-тесты для модуля                                                    | `pytest --cov=src -q` → coverage %             |
| `1c-study`       | `get_metadata` → первый неизученный объект        | 6 фаз: метаданные → код → гипотеза → проверка на базе → граничные случаи → кэш | Файл cache создан, `_index.json` обновлён      |
| `bsl`            | `bsl_analyze` → категория ошибок                  | Исправляет BSL-код                                                             | `bsl_analyze --json` → count                   |
| `docs`           | `audit-docs` → непокрытый модуль                  | Дописывает документацию к модулю                                               | coverage score                                 |

## Скрипты AutoResearch

### autoresearch.ps1 — PowerShell движок

Универсальный скрипт для автономного запуска AutoResearch с доменными рецептами.

```powershell
# Использование
.\scripts\autoresearch.ps1 -Domain skills -MaxIterations 15
.\scripts\autoresearch.ps1 -Domain python-quality -Target 0
.\scripts\autoresearch.ps1 -Domain skill-health -MaxIterations 20 -Target 0.85
```

**Поддерживаемые домены:** `skills`, `skill-health`, `python-quality`, `bsl`, `docs`, `hooks`, `security`, `tests`.

Каждый домен содержит рецепт из 3 полей:

| Поле     | Описание                                         |
| -------- | ------------------------------------------------ |
| `Verify` | Команда для измерения метрики                    |
| `Metric` | Что измеряем (human-readable)                    |
| `Prompt` | Инструкция для Claude (что делать за 1 итерацию) |

**Persistence между сессиями:** скрипт сохраняет состояние в `data/autoresearch.md` (Domain, Iteration, BestMetric, Plateau). При повторном запуске с тем же доменом продолжает с последней итерации.

### ralph.bat / ralph.sh — шаблоны

Ralph Wiggum запускает AutoResearch через предустановленные шаблоны:

```bash
# Windows
scripts\ralph.bat --template skill-health --max-iterations 15
scripts\ralph.bat --template quality --max-iterations 20

# Linux/macOS
scripts/ralph.sh --template skill-health --max-iterations 15
```

**Шаблоны:**

| Шаблон          | Домен     | Цель                                                         |
| --------------- | --------- | ------------------------------------------------------------ |
| `skill-health`  | Скиллы    | Улучшение F1 через health-report → правка description/config |
| `quality`       | Python    | 0 ruff/mypy errors через итеративное исправление             |
| `1c-study`      | 1С конфиг | Изучение объектов конфигурации (6-фазный цикл)               |
| `reindex`       | Pipeline  | Проверка полного пайплайна индексации                        |
| `test-coverage` | Тесты     | Увеличение покрытия до 80%+                                  |
| `evaluation`    | RAG       | RAGAS-оценка и исправление деградаций                        |
| `documentation` | Docs      | Добавление docstrings к публичным API                        |
| `lint`          | Python    | 0 linter warnings, форматирование, импорты                   |

### Разница между autoresearch.ps1 и ralph.bat

|                        | autoresearch.ps1                                 | ralph.bat                                           |
| ---------------------- | ------------------------------------------------ | --------------------------------------------------- |
| **Домены**             | 8 встроенных рецептов                            | 8 шаблонов + произвольный промпт                    |
| **Persistence**        | Да (`data/autoresearch.md`)                      | Нет (каждый запуск с нуля)                          |
| **Парсинг метрики**    | `METRIC:` + `VERDICT:` из stdout                 | `RALPH_DONE` маркер завершения                      |
| **Плато-детекция**     | 5 итераций без улучшений → стоп                  | Нет (только max iterations)                         |
| **Target**             | `-Target 0.85` — стоп при достижении             | Нет                                                 |
| **JSONL лог**          | `data/autoresearch.jsonl`                        | Нет (только текстовый лог)                          |
| **Когда использовать** | Длинные циклы с метрикой (skill-health, quality) | Разовые задачи (reindex, lint, произвольный промпт) |

## Инструменты анализа

### skill-health-analyzer.py — анализ здоровья скиллов

Читает пассивные данные `data/skill-quality-metrics.jsonl`, вычисляет per-skill статистику, генерирует отчёт.

```bash
python scripts/skill-health-analyzer.py
python scripts/skill-health-analyzer.py --days 7 --min-samples 2
python scripts/skill-health-analyzer.py --output data/custom-report.md --no-eval
```

**Метрики:**
- **Precision** = activated / recommended (попал ли роутер)
- **Waste Rate** = (recommended - activated) / recommended (бесполезные рекомендации)

**Особенности реализации:**
- Session dedup: берёт только последнюю запись per session_id (данные кумулятивные)
- Фильтрует `learn:*` префиксы из manual_activations (динамические learning-loop записи)
- Опционально запускает `eval-skill-router.py` для F1 score (флаг `--no-eval` отключает)

### audit-skill-freshness.py — аудит свежести скиллов

Сканирует YAML frontmatter reference-скиллов, находит устаревшие (last_verified > N дней).

```bash
python scripts/audit-skill-freshness.py
python scripts/audit-skill-freshness.py --days 60
python scripts/audit-skill-freshness.py --output data/skill-freshness-report.md
```

**Отчёт содержит:**
- Stale Skills (need review) — старше порога
- Skills Without Date — нет last_verified/updated полей
- Fresh Skills — в норме

### eval-skill-router.py — оценка Skill Router

Ground truth eval с 64 промптами. Метрики: F1, precision, recall по required и optional скиллам.

```bash
python scripts/eval-skill-router.py

Через ralph.bat          scripts\ralph.bat --template skill-health --max-iterations 1 (запустит eval внутри)

 Через autoresearch.ps1  .\scripts\autoresearch.ps1 -Domain skill-health -MaxIterations 1  
```

## Архив скиллов

Бесполезные скиллы перемещаются в `.claude/skills/_archived/`:

```
.claude/skills/_archived/
  README.md           # Критерии архивации, процедура восстановления
  <skill-name>/       # Архивированные скиллы с оригинальной структурой
    SKILL.md
```

**Критерии архивации:**
- NEVER USED: recommended 10+ раз, activated 0
- HIGH WASTE: waste_rate > 80%
- Manual: пользователь явно решил архивировать

**Восстановление:** переместить директорию обратно в `.claude/skills/` и добавить в `skill-router-config.json`.
