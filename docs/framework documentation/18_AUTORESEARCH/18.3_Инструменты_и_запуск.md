# 18.3 Инструменты и запуск

## Быстрый старт: как запустить

### Принудительный режим (автономный — без подтверждений)

Оба скрипта (`ralph.bat` и `autoresearch.ps1`) запускают Claude Code в headless-режиме с флагом `--dangerously-skip-permissions` — Claude выполняет все операции (Read, Write, Edit, Bash, git) без запроса подтверждения пользователя.

```powershell
# PowerShell — полная автономия
.\scripts\autoresearch.ps1 -Domain skill-health -MaxIterations 15

# Batch — через шаблон
scripts\ralph.bat --template skill-health --max-iterations 15

# Batch — произвольный промпт
scripts\ralph.bat 10 "Исправь все ошибки ruff в src/"
```

**Что происходит под капотом:**
1. Скрипт вызывает `claude -p "<prompt>" --dangerously-skip-permissions`
2. Устанавливает `RALPH_ENABLED=1` (env) — guard от ложной активации ralph_activator в интерактиве
3. Claude выполняет одну итерацию: изменение → verify → METRIC/VERDICT
4. Скрипт парсит вывод: `VERDICT: KEEP` или `VERDICT: REVERT`
5. Повторяет до стоп-условия (target / плато / max iterations / `RALPH_DONE`)

**Предосторожности:**
- Все изменения через git — можно откатить (`git revert`, `git log`)
- autoresearch.ps1 сохраняет состояние в `data/autoresearch.md` (возобновляемость)
- Лог каждой итерации: `data/autoresearch_<domain>_<date>.log`
- ralph.bat пишет лог в `data/ralph_log_<date>.txt`

### Интерактивный режим (с подтверждениями)

Для ручного контроля используй `/autoresearch` в чате Claude Code:

```
> /autoresearch
> Улучши F1 skill router до 0.85
```

Claude анализирует, создаёт рецепт, выполняет по шагам с подтверждением каждого действия.

## Скрипты AutoResearch

### autoresearch.ps1 — PowerShell движок

Универсальный скрипт для автономного запуска AutoResearch с доменными рецептами.

```powershell
# Использование
.\scripts\autoresearch.ps1 -Domain skills -MaxIterations 15
.\scripts\autoresearch.ps1 -Domain python-quality -Target 0
.\scripts\autoresearch.ps1 -Domain skill-health -MaxIterations 20 -Target 0.85
```

**Поддерживаемые домены:** `skills`, `skill-health`, `python-quality`, `bsl`, `docs`, `hooks`, `security`, `tests`.

Каждый домен содержит рецепт из 3 полей:

| Поле | Описание |
|------|----------|
| `Verify` | Команда для измерения метрики |
| `Metric` | Что измеряем (human-readable) |
| `Prompt` | Инструкция для Claude (что делать за 1 итерацию) |

**Протокол итерации:**
1. Проверить `git log --oneline -3` для контекста
2. Внести ОДНО изменение
3. `git commit -m "[AR] domain iter N: описание"`
4. Запустить verify-команду
5. Вывести `METRIC: число`
6. Сравнить с предыдущим → `VERDICT: KEEP` или `VERDICT: REVERT`
7. Если REVERT → `git revert HEAD --no-edit`

**Стоп-условия скрипта:**
- Достигнут Target
- 5 итераций без улучшений (плато)
- Превышен MaxIterations
- Маркер `AUTORESEARCH_DONE` в выводе Claude

### ralph.bat / ralph.sh — шаблоны

Ralph Wiggum запускает AutoResearch через предустановленные шаблоны:

```bash
# Windows
scripts\ralph.bat --template skill-health --max-iterations 15
scripts\ralph.bat --template quality --max-iterations 20

# Linux/macOS
scripts/ralph.sh --template skill-health --max-iterations 15
```

**Шаблоны:**

| Шаблон | Домен | Цель |
|--------|-------|------|
| `skill-health` | Скиллы | Улучшение F1 через health-report → правка description/config |
| `quality` | Python | 0 ruff/mypy errors через итеративное исправление |
| `1c-study` | 1С конфиг | Изучение объектов конфигурации (6-фазный цикл) |
| `reindex` | Pipeline | Проверка полного пайплайна индексации |
| `test-coverage` | Тесты | Увеличение покрытия до 80%+ |
| `evaluation` | RAG | RAGAS-оценка и исправление деградаций |
| `documentation` | Docs | Добавление docstrings к публичным API |
| `lint` | Python | 0 linter warnings, форматирование, импорты |

## Инструменты анализа

### skill-health-analyzer.py — анализ здоровья скиллов

Читает пассивные данные `data/skill-quality-metrics.jsonl`, вычисляет per-skill статистику, генерирует отчёт.

```bash
python scripts/skill-health-analyzer.py
python scripts/skill-health-analyzer.py --days 7 --min-samples 2
python scripts/skill-health-analyzer.py --output data/custom-report.md --no-eval
```

**Метрики:**
- **Precision** = activated / recommended (попал ли роутер)
- **Waste Rate** = (recommended - activated) / recommended (бесполезные рекомендации)

**Проблемные категории:**

| Категория | Критерий | Действие |
|-----------|----------|----------|
| HIGH WASTE | >5 рекомендаций, waste >80% | Сузить description (слишком широкий trigger) |
| ROUTER MISS | >2 ручных вызовов | Добавить keywords в skill-router-config.json |
| NEVER USED | >10 рекомендаций, 0 активаций | Переместить в `_archived/` |

**Особенности реализации:**
- Session dedup: берёт только последнюю запись per session_id (данные кумулятивные)
- Фильтрует `learn:*` префиксы из manual_activations (динамические learning-loop записи)
- Опционально запускает `eval-skill-router.py` для F1 score

### audit-skill-freshness.py — аудит свежести скиллов

Сканирует YAML frontmatter reference-скиллов, находит устаревшие (last_verified > N дней).

```bash
python scripts/audit-skill-freshness.py
python scripts/audit-skill-freshness.py --days 60
python scripts/audit-skill-freshness.py --output data/skill-freshness-report.md
```

**Отчёт содержит:**
- Stale Skills (need review) — старше порога
- Skills Without Date — нет last_verified/updated полей
- Fresh Skills — в норме

### eval-skill-router.py — оценка Skill Router

Ground truth eval с 64 промптами. Метрики: F1, precision, recall по required и optional скиллам.

```bash
python scripts/eval-skill-router.py
```

## Архив скиллов

Бесполезные скиллы перемещаются в `.claude/skills/_archived/`:

```
.claude/skills/_archived/
  README.md           # Критерии архивации, процедура восстановления
  <skill-name>/       # Архивированные скиллы с оригинальной структурой
    SKILL.md
```

**Критерии архивации:**
- NEVER USED: recommended 10+ раз, activated 0
- HIGH WASTE: waste_rate > 80%
- Manual: пользователь явно решил архивировать

**Восстановление:** переместить директорию обратно в `.claude/skills/` и добавить в `skill-router-config.json`.
