# 19.4 Компоненты системы индексации

## smart_index_bsl.py -- Multi-Language индексатор

**Путь:** `scripts/docs-mcp/smart_index_bsl.py`
**Вызывается из:** `index-folder.bat` (этап 1), `reindex_bsl.bat` (фаза 1)

### Поддерживаемые языки

| Расширение | Тип | Метод индексации |
|---|---|---|
| `.bsl` | BSL | `index_bsl_file` (AST-парсинг процедур) |
| `.js` | JavaScript | `index_javascript_file` |
| `.ts` | TypeScript | `index_javascript_file` |
| `.py` | Python | `index_document` (чанкинг по секциям) |
| `.md` | Markdown | `index_document` (чанкинг по заголовкам) |

### Режимы чанкинга

| Режим | Описание | Когда |
|---|---|---|
| `smart` (default) | По процедурам для BSL, по секциям для MD | Рекомендуется |
| `procedures` | Каждая процедура/функция -- отдельный чанк | Для BSL |
| `full` | Весь файл -- один чанк | Для мелких файлов |

### Инкрементальность

При повторном запуске скрипт:
1. Вычисляет MD5 hash содержимого файла
2. Сравнивает с hash в БД
3. Пропускает неизменённые файлы

Флаг `--force` отключает проверку hash.

### Пропуск файлов

Автоматически пропускаются:
- `node_modules/`, `__pycache__/`, `.venv/`, `.git/`
- BSL: `CommonModules/БСП`, `СтандартныеПодсистемы` (библиотечные модули)
- JS: `.min.js`, `dist/`, `build/`

### CLI

```
python smart_index_bsl.py --help

  --list, -l            Список проектов
  --project, -p PROJECT Имя проекта
  --path PATH           Полный путь к проекту
  --framework           Индексировать фреймворк
  --languages LANGUAGES Языки (bsl,javascript,python,markdown,typescript)
  --chunk-mode          full | procedures | smart
  --delay DELAY         Задержка между файлами (сек)
  --full, -f            Полная индексация
  --force               Принудительная переиндексация
  --ast                 AST-based symbol-level indexing для BSL
```

## bsl_indexer_async.py -- BSL эмбеддинги через Ollama

**Путь:** `D:\1C-Enterprise_Framework\bsl-semantic-search\scripts\indexing\bsl_indexer_async.py`
**Вызывается из:** `index-folder.bat` (этап 2)

### Архитектура

```
BSLParser                        EmbeddingService
  |                                |
  v                                v
Парсинг .bsl файла              Ollama API
  - module_type                   - nomic-embed-text:latest
  - functions[]                   - 768 dimensions
  - variables[]                   - Circuit breaker
  - searchable_text               - Auto-restart
  |                                |
  └──────────────┬─────────────────┘
                 v
          IndexedFile
            - file_path
            - module_type
            - functions_count
            - variables_count
            - searchable_text
            - embedding[768]
            - processing_time_ms
                 |
                 v
          bsl_index_full.json
```

### Параметры

| Параметр | Default | Описание |
|---|---|---|
| `--output` | `bsl-semantic-search/data/index` | Директория для индекса |
| `--batch-size` | 10 | Файлов в batch (параллельно) |
| `--max-workers` | 4 | Worker threads |
| `--retry-attempts` | 3 | Попытки при ошибке |
| `--max-files` | все | Ограничить количество файлов |

### Resilience

- **Retry Logic:** 3 попытки с экспоненциальной задержкой
- **Circuit Breaker:** после 5 ошибок Ollama -- открытие breaker на 60 сек
- **Auto-restart:** OllamaManager перезапускает Ollama при persistent failures
- **Graceful Degradation:** если эмбеддинг не создан -- файл индексируется без вектора

## BSLParser -- парсер BSL кода

**Путь:** `D:\1C-Enterprise_Framework\bsl-semantic-search\utils\bsl_parser.py`

Извлекает из BSL файла:

| Поле | Описание | Пример |
|---|---|---|
| `module_type` | Тип модуля | `ObjectModule`, `ManagerModule`, `FormModule` |
| `functions[]` | Процедуры и функции | `ОбработкаПроведения`, `ПриСоздании` |
| `variables[]` | Переменные модуля | `Перем ТекущийДокумент` |
| `searchable_text` | Текст для эмбеддинга | Конкатенация имён + комментариев |

## EmbeddingService -- сервис эмбеддингов

**Путь:** `D:\1C-Enterprise_Framework\bsl-semantic-search\services\embedding_service.py`

Обёртка над Ollama API с resilience-паттернами:

```python
service = EmbeddingService(
    ollama_host="http://localhost:11434",
    model="nomic-embed-text:latest",
    cache_embeddings=True,       # Кеш в памяти
    timeout=90,                  # Таймаут запроса
    request_delay=0.1,           # Rate limiting
    wait_for_recovery=True,      # Ждать восстановления Ollama
    max_recovery_wait=120,       # Макс. время ожидания
    auto_restart=True,           # Авто-перезапуск Ollama
)

embedding = service.create_embedding("Процедура ОбработкаПроведения")
# -> [0.123, -0.456, ...] (768 float)
```

## hybrid_search.db -- SQLite БД 1c-docs-rag

**Путь:** `cache/docs-mcp/hybrid_search.db`

Содержит:
- **FTS5 таблица** -- полнотекстовый поиск по содержимому
- **Векторы** -- эмбеддинги MiniLM (384d)
- **Метаданные** -- путь, язык, hash, дата индексации

Используется MCP-сервером `1c-docs-rag` для:
- `search_docs(query)` -- семантический поиск
- `search_docs_with_facets(query, doc_type, source)` -- поиск с фильтрами
