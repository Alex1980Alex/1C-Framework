# 12.3 Классификация задач

> Авто-классификация промптов на trivial/medium/complex.
> Определяет нужна ли декомпозиция через TaskCreate.

---

## Три уровня сложности

| Сложность | Критерии | Действие |
|-----------|----------|----------|
| **trivial** | < 30 слов, нет multi-file маркеров | Активация скилла → Write/Edit |
| **medium** | 30-100 слов, 1-3 файла | TaskCreate → Активация → Write/Edit |
| **complex** | > 100 слов или 4+ файлов | Полная декомпозиция → Активация → Write/Edit |

## Алгоритм классификации

Реализован в `skill-eval-enforcer-shell.py`, функция `_classify_complexity()`:

```python
def _classify_complexity(prompt: str) -> str:
    word_count = len(prompt.split())

    # Multi-file markers always force non-trivial
    if _MULTI_FILE_MARKERS.search(prompt):
        return "complex" if word_count > 100 else "medium"

    if word_count < 30:
        return "trivial"
    elif word_count < 100:
        return "medium"
    else:
        return "complex"
```

### Два фактора

**1. Число слов** — базовый фактор:

```
< 30 слов   → trivial
30-100 слов → medium
> 100 слов  → complex
```

**2. Multi-file маркеры** — повышающий фактор:

Если в промпте есть маркеры работы с несколькими файлами, классификация
повышается как минимум до `medium`:

```python
_MULTI_FILE_MARKERS = re.compile(
    r"и также|а также|плюс|additionally|across|multiple files|"
    r"refactor|все файлы|each file|several|несколько файлов|"
    r"во всех|all files|every file",
    re.IGNORECASE,
)
```

| Маркер (рус) | Маркер (eng) | Что означает |
|--------------|-------------|--------------|
| и также, а также | additionally | Дополнительные файлы |
| все файлы, во всех | all files, every file | Массовое изменение |
| несколько файлов | multiple files, several | Множественность |
| — | refactor | Рефакторинг = много файлов |
| — | across | Кросс-файловое изменение |
| плюс | — | Добавление к списку |

## Примеры классификации

### trivial (< 30 слов, нет маркеров)

```
"Fix typo in README"
→ 4 слова, нет маркеров → trivial

"Добавь валидацию email в форму"
→ 5 слов, нет маркеров → trivial

"Rename variable from x to count"
→ 6 слов, нет маркеров → trivial
```

### medium (30-100 слов или маркеры)

```
"Добавь валидацию в поле email и также обнови тесты"
→ 8 слов, но маркер "и также" → medium

"Add input validation to the search endpoint. The validation should
check that the query is not empty, the page number is positive, and
the limit is between 1 and 100."
→ 32 слова → medium
```

### complex (> 100 слов или маркеры + > 100 слов)

```
"Implement multi-tenant support for vector store. This requires
changes across multiple files: the base store class, all provider
implementations, the configuration module, the API endpoints,
and the authentication middleware..."
→ маркер "across multiple files" + маркер "all" → medium (без 100+ слов)
  (повысился бы до complex при > 100 словах)
```

## Что происходит после классификации

### trivial — минимальный путь

```
UserPromptSubmit
  └─> phase = classified (complexity=trivial)
       │
       ▼
  Claude ищет скилл → активирует
       │
       ▼
  phase = skill_checked
       │
       ▼
  Write/Edit → ALLOWED
```

TaskCreate **не требуется** для trivial. Claude может сразу активировать скилл
и приступить к Write/Edit.

### medium — TaskCreate + скилл

```
UserPromptSubmit
  └─> phase = classified (complexity=medium)
       │
       ▼
  Claude: TaskCreate("Subtask 1")  → phase = decomposed
  Claude: TaskCreate("Subtask 2")  → subtask_count++
       │
       ▼
  Claude: активирует скилл → phase = skill_checked
       │
       ▼
  FOR EACH subtask:
    Claude: TaskUpdate(in_progress)
    Claude: Write/Edit → ALLOWED
    Claude: TaskUpdate(completed)
```

### complex — полная декомпозиция

```
UserPromptSubmit
  └─> phase = classified (complexity=complex)
       │
       ▼
  Claude: TaskCreate("Subtask 1")  → phase = decomposed
  Claude: TaskCreate("Subtask 2")  → subtask_count++
  Claude: TaskCreate("Subtask 3")  → subtask_count++
  Claude: TaskCreate("Subtask 4")  → subtask_count++
       │
       ▼
  Claude: активирует скилл → phase = skill_checked
       │
       ▼
  FOR EACH subtask:
    Claude: TaskUpdate(in_progress)
    Claude: Write/Edit → ALLOWED
    Claude: TaskUpdate(completed)
       │
       ▼
  Claude: верификация кода
```

## Связь с enforcement

Классификация — **advisory**. Enforcer не проверяет соответствие:
если Claude решил декомпозировать trivial задачу — это допустимо.
Если Claude не декомпозировал complex — enforcer не блокирует на этом.

Enforcer блокирует **только** на отсутствии skill_checked фазы.
Классификация — подсказка Claude, какой путь выбрать.

| Что контролируется | Как |
|-------------------|-----|
| Классификация (trivial/medium/complex) | Advisory (stdout инструкция) |
| Декомпозиция (TaskCreate) | Advisory (инструкция) + наблюдение (observer) |
| Проверка скиллов (skill activation) | **БЛОКИРОВКА** (enforcer, exit code 2) |

---

## Ограничения

1. **Word count — грубая эвристика**: промпт из 25 коротких слов может быть сложнее,
   чем из 35 длинных. Это компромисс ради скорости (< 1ms).

2. **Multi-file маркеры — неполные**: промпт "измени все модели" не триггерит маркер
   (нет "все файлы"). Список постепенно расширяется.

3. **Язык**: маркеры покрывают русский и английский. Другие языки не поддержаны.

4. **Нет анализа контекста**: классификатор не знает какие файлы затронуты.
   Это задача Claude — уточнить при необходимости.
