# 20.3 Домены и шаблоны

## Обзор доменов

AutoResearch v2 поддерживает 8 встроенных доменов. Каждый домен представляет собой готовый рецепт с предустановленной метрикой, verify-командой, scope, direction и подсказкой для Executor. Это позволяет запускать исследования одной командой без ручной настройки.

| Домен | Метрика | Direction | Verify Command | Scope | Приоритет |
|-------|---------|-----------|----------------|-------|-----------|
| skills | F1 score | higher | python scripts/eval-skill-router.py | .claude/skills/ | P0 |
| skill-health | F1 + health report | higher | python scripts/eval-skill-router.py | .claude/skills/, skill-router-config.json | P0 |
| python-quality | ruff errors count | lower | ruff check src/ --output-format json | src/**/*.py | P1 |
| hooks | eval-hooks accuracy | higher | python scripts/eval-hooks.py | .claude/hooks/ | P1 |
| security | findings count | higher (READ-ONLY) | bandit -r src/ -f json | src/**/*.py | P2 |
| tests | coverage % | higher | pytest --cov=src --cov-report=json | tests/**/*.py | P2 |
| docs | documented % | higher | AST-based verify | src/**/*.py | P2 |
| bsl | bsl_analyze errors | lower | bsl_analyze | src/bsl/**/*.bsl | P1 |

---

## Блок-схема выбора домена

```
Что нужно улучшить?
├── Скиллы / Skill Router
│   ├── Много waste в health report → skill-health
│   ├── ROUTER MISS → skill-health
│   ├── F1 конкретного скилла → skills
│   └── Не знаешь с чего начать → skill-health
├── Качество кода
│   ├── Python (ruff/mypy) → python-quality
│   ├── BSL ошибки → bsl
│   └── Уязвимости → security
├── Покрытие
│   ├── Тесты → tests
│   └── Документация → docs
└── Инфраструктура
    └── Хуки → hooks
```

## Подробное описание каждого домена

### 1. skills — точечное улучшение description

**Когда применять:** Необходимо повысить F1 конкретного скилла через улучшение description в pushy-стиле.

**Что делает:** Claude анализирует метрики всех скиллов, выбирает один со слабым description и переписывает его YAML frontmatter. Изменения направлены на повышение точности маршрутизации через добавление триггеров и негативных маркеров.

**Verify:** `python scripts/eval-skill-router.py` возвращает F1 score для оценки улучшения.

**Пример запуска:**
```powershell
.\scripts\autoresearch.ps1 -Domain skills -MaxIterations 20 -Target 0.85
```

**ExecutorHint:** "Улучши description ОДНОГО скилла для повышения F1. Pushy стиль с триггерами и негативными маркерами."

---

### 2. skill-health — здоровье Skill Router

**Когда применять:** Много waste (recommend без activate), частые ROUTER MISS, наличие NEVER USED скиллов в health report.

**Что делает:** Анализирует отчёт skill-health-analyzer.py, принимает решение о правке description, конфигурации skill-router-config.json или архивации неиспользуемого скилла. Работает комплексно над всей экосистемой роутера.

**Отличие от skills:** skill-health анализирует health report и принимает системные решения, skills — Claude сам выбирает скилл для точечного улучшения description.

**Пример запуска:**
```powershell
.\scripts\autoresearch.ps1 -Domain skill-health -MaxIterations 10
```

---

### 3. python-quality — ruff ошибки

**Direction:** lower is better (цель — 0 ошибок).

**Что делает:** Находит самую частую категорию ошибок (F401 — unused imports, E501 — line too long и т.д.), исправляет ВСЕ файлы с этой категорией за одну итерацию. Это обеспечивает системный подход к устранению технического долга.

**Verify:** `ruff check src/ --output-format json` возвращает количество ошибок.

**Пример запуска:**
```powershell
.\scripts\autoresearch.ps1 -Domain python-quality -Target 0
```

**Пример:** если самая частая ошибка — `F401 unused import`, Claude найдёт все файлы с F401 и удалит неиспользуемые импорты за одну итерацию. Следующая итерация — следующая категория.

---

### 4. hooks — улучшение хуков

**Когда применять:** Низкая accuracy хуков, ложные срабатывания или пропуски событий.

**Что делает:** eval-hooks.py находит хук с наихудшей accuracy, анализирует паттерны срабатываний и корректирует signals/threshold в конфигурации хука для повышения точности.

**Scope:** `.claude/hooks/` — все файлы конфигурации хуков.

**Пример запуска:**
```powershell
.\scripts\autoresearch.ps1 -Domain hooks -MaxIterations 10
```

---

### 5. security — STRIDE аудит (READ-ONLY)

**ВАЖНО:** Домен НЕ модифицирует код. Только анализ и отчётность.

**Что делает:** bandit находит уязвимости в коде, Claude анализирует их по STRIDE модели (Spoofing, Tampering, Repudiation, Information Disclosure, Denial of Service, Elevation of Privilege). Каждая итерация фокусируется на отдельном attack vector.

**Direction:** higher (READ-ONLY) — метрика отражает количество проанализированных уязвимостей, а не исправлений.

**Пример запуска:**
```powershell
.\scripts\autoresearch.ps1 -Domain security -MaxIterations 15
```

---

### 6. tests — написание тестов

**Когда применять:** Низкое покрытие кода тестами, необходимость unit-тестов для новых модулей.

**Что делает:** pytest --cov находит модуль с минимальным покрытием, Claude пишет unit-тесты для ОДНОГО модуля за итерацию. Тесты размещаются в `tests/` с сохранением структуры директорий.

**Verify:** `pytest --cov=src --cov-report=json` возвращает процент покрытия.

**Пример запуска:**
```powershell
.\scripts\autoresearch.ps1 -Domain tests -MaxIterations 10
```

---

### 7. docs — документирование

**Когда применять:** Недостаточная документированность кода, отсутствие docstrings в публичных функциях.

**Что делает:** Находит модуль с наименьшим процентом документированных функций, дописывает docstrings в Google или NumPy формате. Сохраняется стиль существующей документации в проекте.

**Scope:** `src/**/*.py` — весь Python-код проекта.

**Пример запуска:**
```powershell
.\scripts\autoresearch.ps1 -Domain docs -MaxIterations 10
```

---

### 8. bsl — анализ BSL кода

**Когда применять:** Ошибки линтера в коде 1С:Предприятие, необходимость соответствия стандартам BSL.

**Что делает:** bsl_analyze ищет ошибки в BSL-файлах, Claude исправляет ОДНУ категорию ошибок за итерацию (например, именование переменных, структура модулей). Поддерживаются стандартные правила линтера BSL LS.

**Scope:** `src/bsl/**/*.bsl` — все BSL-файлы проекта.

**Пример запуска:**
```powershell
.\scripts\autoresearch.ps1 -Domain bsl -MaxIterations 10
```

## Custom домены через /autoresearch:plan

Если ни один встроенный домен не подходит под задачу, wizard `/autoresearch:plan` создаёт custom рецепт на основе 5 вопросов (gates).

**Результат работы wizard:**
```
data/autoresearch/{idea-name}-{date}/
├── autoresearch.md          # Живой документ с планом
├── executor-prompt.md       # Промпт для Executor агента
├── reviewer-prompt.md       # Промпт для Reviewer агента
└── run.bat                  # Команда запуска
```

**Запуск custom исследования:**
```powershell
.\scripts\autoresearch.ps1 -IdeaDir data/autoresearch/api-speed-20260320
```

Скрипт прочитает `autoresearch.md` из указанной директории и использует описанные в нём метрику, scope и verify command вместо встроенного рецепта.

## Шаблоны в .claude/skills/autoresearch/templates/

Каждый домен имеет детальный шаблон с инструкциями для Claude. Шаблоны содержат примеры кода, типичные паттерны исправлений и специфику verify-команд.

| Шаблон | Описание |
|--------|----------|
| python-quality.md | Правила ruff, примеры исправлений типичных ошибок |
| python-performance.md | Профилирование, оптимизация узких мест |
| bsl-quality.md | Стандарты BSL, типичные нарушения |
| 1c-study.md | Изучение API 1С:Предприятие, 6 фаз на объект |
| test-coverage.md | Паттерны unit-тестов, mock-объекты |
| documentation.md | Форматы docstrings, AST-based verify скрипт |
| security-audit.md | STRIDE модель, чеклисты безопасности |

Шаблоны автоматически подгружаются при выборе соответствующего домена и расширяют контекст для Executor.
