# 21.3 Backoff и Rate Limiting

> Защита от перегрузки провайдеров: экспоненциальный backoff с jitter и проактивный Token Bucket rate limiter.

---

## Exponential Backoff

Модуль `src/shared/llm_rotation/backoff.py` реализует стратегию экспоненциальной задержки с джиттером.

### Класс BackoffStrategy

| Параметр | Тип | Default | Описание |
|----------|-----|---------|----------|
| base_delay | float | 1.0 | Начальная задержка (сек) |
| max_delay | float | 30.0 | Максимальная задержка (сек) |
| jitter | float | 1.0 | Диапазон случайной добавки |
| multiplier | float | 2.0 | Множитель экспоненты |

**Формула:**

```
delay = min(base_delay * multiplier^attempt, max_delay) + uniform(0, jitter)
```

При наличии заголовка `Retry-After` (HTTP 429) используется значение из заголовка:

```
delay = retry_after + uniform(0, jitter)
```

**Метод:**

```python
def compute_delay(self, attempt: int, retry_after: float | None = None) -> float
```

**Пример расчёта (дефолтные параметры):**

| attempt | base * multiplier^attempt | delay (с jitter) |
|---------|---------------------------|------------------|
| 0 | 1.0 | 1.0 + [0..1.0] |
| 1 | 2.0 | 2.0 + [0..1.0] |
| 2 | 4.0 | 4.0 + [0..1.0] |
| 3 | 8.0 | 8.0 + [0..1.0] |

## RateLimitError

Специальное исключение для обработки HTTP 429.

```python
class RateLimitError(RuntimeError):
    def __init__(self, message: str, retry_after: float | None = None):
        super().__init__(message)
        self.retry_after = retry_after
```

- Создаётся при получении HTTP 429
- Парсит заголовок `Retry-After` (числовое значение в секундах)
- Поле `retry_after` используется BackoffStrategy для расчёта задержки

## Token Bucket Rate Limiter

Модуль `src/shared/llm_rotation/rate_limiter.py` реализует проактивное ограничение запросов **до** отправки (не после получения 429).

### Класс TokenBucket

| Параметр | Описание |
|----------|----------|
| rate | Скорость пополнения (tokens/sec = rpm / 60) |
| capacity | Максимальный размер бакета (burst size = rpm) |

**Методы:**

| Метод | Описание |
|-------|----------|
| `consume() -> bool` | Пытается взять один токен. `True` если разрешено. |
| `wait_time() -> float` | Секунды до появления следующего токена. |
| `available` (property) | Текущее количество доступных токенов. |
| `reset()` | Заполняет бакет до capacity. |

### Класс ProviderRateLimiter

Управляет набором TokenBucket для всех провайдеров.

| Метод | Описание |
|-------|----------|
| `register(name, rpm)` | Регистрирует провайдер с RPM-лимитом. |
| `can_request(name) -> bool` | Проверяет и потребляет токен. |
| `wait_time(name) -> float` | Время ожидания до следующего запроса. |
| `get_stats(name) -> dict` | Статистика бакета: rpm, available, capacity. |

Провайдеры без `rate_limit_rpm` всегда возвращают `can_request() = True`.

---

## Как работает в связке

Поток обработки запроса:

1. **Перед запросом:** `ProviderRateLimiter.wait_time(name)` -- если > 0, `await sleep(wait_time)`
2. **Проверка:** `ProviderRateLimiter.can_request(name)` -- если False, пропустить провайдер
3. **Выполнение:** запрос отправляется
4. **При ошибке:** `BackoffStrategy.compute_delay(attempt)` -- `await sleep(delay)` перед retry
5. **При HTTP 429:** создаётся `RateLimitError` с `retry_after` -- CircuitBreaker переходит в `force_open(rate_limit_cooldown=60)`

## Конфигурация

| Параметр | Env | Default | Описание |
|----------|-----|---------|----------|
| backoff_base_delay | `LLM_ROTATION_BACKOFF_BASE_DELAY` | 1.0 | Начальная задержка (сек) |
| backoff_max_delay | `LLM_ROTATION_BACKOFF_MAX_DELAY` | 30.0 | Максимальная задержка (сек) |
| backoff_jitter | `LLM_ROTATION_BACKOFF_JITTER` | 1.0 | Случайная добавка [0..jitter] |
| backoff_multiplier | `LLM_ROTATION_BACKOFF_MULTIPLIER` | 2.0 | Множитель экспоненты |
| rate_limiting_enabled | `LLM_ROTATION_RATE_LIMITING_ENABLED` | true | Включить rate limiting |
| rate_limit_cooldown | `LLM_ROTATION_RATE_LIMIT_COOLDOWN` | 60 | Cooldown при 429 (сек) |

RPM-лимит задаётся индивидуально в `ProviderConfig.rate_limit_rpm`.
