## Установка и инициализация

```bash
# Установка
npm install -g @fission-ai/openspec

# Инициализация для Claude Code
openspec init --tools claude

# Для Claude Code + Cursor
openspec init --tools claude,cursor
```

**Результат инициализации для Claude Code:**

```
.claude/
└── skills/
    ├── opsx-propose/
    │   └── SKILL.md
    ├── opsx-apply/
    │   └── SKILL.md
    ├── opsx-explore/
    │   └── SKILL.md
    ├── opsx-approve/
    │   └── SKILL.md
    └── opsx-archive/

├── changes/         # Активные изменения (в каждом change: proposal.md / tasks.md / design.md / specs/ delta)
│   └── archive/     # Завершённые изменения
├── specs/           # Source-of-Truth спеки — МАТЕРИАЛИЗУЕТСЯ при archive (merge delta-specs); до первого merge каталога нет
├── critiques/       # Результаты openspec_critique_proposal
├── profiles/        # Профили валидации
├── project.md       # Контекст проекта (openspec_get_project_context)
├── config.yaml      # Конфигурация проекта (1С: delta_markers / delta_specs)
└── AGENTS.md        # Инструкции для AI-агентов
```

## Команды OpenSpec

### Базовые команды (4)

| Команда | Назначение | Синтаксис Claude Code |
|---------|-----------|----------------------|
| **Explore** | Разведка: исследование кодовой базы | `/opsx:explore` |
| **Propose** | Создание папки изменения + все 4 артефакта | `/opsx:propose {name}` |
| **Apply** | AI реализует задачи по чек-листу | `/opsx:apply` |
| **Archive** | Документы в архив, рабочее пространство чистое | `/opsx:archive` |

### Расширенные команды

| Команда | Назначение |
|---------|-----------|
| `/opsx:ff` | Fast-forward: генерация всех артефактов за один проход |
| `/opsx:verify` | Валидация реализации относительно спецификации |
| `/opsx:onboard` | Интерактивный туториал (~15-20 минут) |
| `/opsx:new` | Создание папки изменения без генерации артефактов |
| `/opsx:approve` | Ревью и утверждение артефактов (Approval Gate) |

## Конфигурация для 1С (`openspec/config.yaml`)

```yaml
tech_stack:
  language: bsl
  platform: "1C:Enterprise 8.3"
  format: xml

rules:
  proposal:
    required: [problem, solution, impact]
  specs:
    required: [metadata, constraints, scenarios]
    keywords: [MUST, SHALL, SHOULD, MAY]  # RFC 2119
  design:
    required: [files_changed, architecture, risks]
    delta_markers: [ADDED, MODIFIED]
  tasks:
    format: checklist

conventions:
  naming: CamelCase_ru
  prefix: гкс_
  modules: [ObjectModule, FormModule, ManagerModule]

delta_specs:
  markers: [ADDED, MODIFIED]
  format: "## {MARKER} Requirements"
  verification: get_metadata
  anti_patterns:
    - duplicate_typical_logic
    - create_new_register_when_exists
```

## Рабочий цикл Claude Code + OpenSpec

```
1. claude                          # Запускаем Claude Code CLI
2. /opsx:explore                   # Исследуем конфигурацию
   → Claude сканирует файлы, анализирует структуру
3. /opsx:propose add-print-form    # Создаём изменение
   → Генерируются proposal.md, specs/, design.md, tasks.md
4. [Проверяем и корректируем артефакты]
5. /opsx:approve                   # Утверждаем спецификацию
   → Статус меняется на approved
6. /opsx:apply                     # AI реализует задачи по чек-листу
   → Claude вносит изменения в файлы конфигурации
7. brownfield-validate             # Валидация в существующей конфигурации
8. /opsx:archive                   # Архивируем, чистим контекст
```

## OpenSpec MCP Server (опционально)

Помимо базовой интеграции через Skills, существует MCP-сервер для OpenSpec:

```json
{
  "mcpServers": {
    "openspec": {
      "command": "npx",
      "args": ["-y", "openspec-mcp", "--with-dashboard"]
    }
  }
}
```

**Добавляет:**
- Полный CLI OpenSpec как MCP-инструменты
- Трекинг задач с парсингом tasks.md в реальном времени
- Workflow одобрения (request → approve → reject)
- Веб-дашборд с WebSocket для live-обновлений

## Кроссплатформенность артефактов

Артефакты — обычные Markdown-файлы, что обеспечивает:
- `/opsx:propose` в Claude Code, `/opsx:apply` — в Cursor/Copilot/RooCode
- Артефакты коммитятся в Git, доступны всей команде
- Смена AI-инструмента не требует переписывания спецификаций

## Сравнение SDD-фреймворков

| Критерий | OpenSpec | cc-sdd | GSD | Spec Kit |
|----------|----------|--------|-----|----------|
| Brownfield (доработка 1С) | Идеален | Ограничен | Ограничен | Greenfield |
| Русский язык | Через AI | `--lang ru` | Нет | Нет |
| Сложность | Низкая | Средняя | Высокая | Высокая |
| Артефактов на задачу | 4 файла | 3 файла | Много | 8+ файлов |
| Claude Code интеграция | Нативная | Нативная | Нативная | Нативная |

**Вывод:** OpenSpec — оптимальный выбор для 1С благодаря brownfield-first подходу и дельта-спецификациям.
