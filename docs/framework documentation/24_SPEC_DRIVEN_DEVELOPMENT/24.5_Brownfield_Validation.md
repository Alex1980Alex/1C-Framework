# 24.5 Brownfield Validation Suite — валидация существующего кода

> **Версия:** 1.0 | **Дата:** 2026-04-02 | **Статус:** ACTIVE

---

## Проблема

Существующий `code-verify` работает post-factum — обнаруживает ошибки после написания кода. Экосистема SDD перешла к **превентивной валидации** — проверке до фактической выгрузки конфигурации.

## Решение: Brownfield Validation Suite

Трехуровневая система проверки дрифта между спецификацией и реальным кодом.

### Архитектура

```
┌─────────────────────────────────────────────────┐
│              brownfield-validate                 │
├─────────────────┬───────────────┬───────────────┤
│  Gap Validator  │ Design Val.   │  Impl Val.    │
│  (полнота)      │ (архитектура) │  (код)        │
├─────────────────┼───────────────┼───────────────┤
│ MUST/SHALL из   │ design.md vs  │ METR + naming │
│ specs vs код    │ код           │ + test cover  │
└─────────────────┴───────────────┴───────────────┘
                      │
              Consolidated Report
```

---

## 3 валидатора

### 1. Gap Validator (полнота покрытия)

**Что проверяет:** Все ли требования из specs покрыты в коде.

**Механизм:**
1. Парсит ключевые слова MUST/SHALL/SHOULD из `specs/`
2. Проверяет наличие соответствующего кода для каждого требования
3. Формирует список uncovered gaps

**Пример:**
```
[MUST] ДатаОкончания > ДатаНачала          → COVERED (строка 142)
[SHALL] Организация — СправочникСсылка      → COVERED (строка 15)
[MUST] Сообщение при ошибке                 → GAP NOT FOUND
```

### 2. Design Validator (архитектурная целостность)

**Что проверяет:** Соответствие кода утверждённому design.md.

**Механизм:**
1. Читает `design.md` — список файлов, модулей, SQL-паттернов
2. Сверяет с фактически изменёнными файлами
3. Проверяет сигнатуры функций, SQL-структуру, паттерны

**Пример:**
```
[DESIGN] ObjectModule.bsl: LEFT JOIN to РегистрНакопления    → MATCH
[DESIGN] Form.xml: 3 new elements                             → MATCH (3/3)
[DESIGN] Module.bsl: function ВалидацияДат()                  → NOT FOUND
```

### 3. Impl Validator (стандарты кодирования)

**Что проверяет:** Синтаксис, naming conventions, тестовое покрытие.

**Механизм:**
1. METR — синтаксическая проверка BSL
2. Coding standards — CamelCase_ru, `гкс_` prefix, `СтрШаблон()` вместо конкатенации
3. Тестовое покрытие — наличие тестов для критичных функций

**Graceful degradation:** Если MCP-серверы недоступны → SKIP (не FAIL), валидация продолжается.

## Консолидированный отчёт

```
=== Brownfield Validation Report ===
Change: gkstcplk-2256-exclude-registered-vehicles
Date: 2026-04-02

Gap Validation:    4/5 COVERED, 1 GAP
Design Validation: 3/3 MATCH
Impl Validation:   PASSED (METR OK, naming OK)

Verdict: NEEDS FIX
Action: Устранить GAP "Сообщение при ошибке" в specs/tasks
```

---

## Интеграция с конвейером

```
/opsx:apply → brownfield-validate → /opsx:archive
                   │
                   ├─ PASS → продолжить архивацию
                   └─ FAIL → вернуться к /opsx:propose для исправления
```

**Дополняет `code-verify`:**
- `code-verify` — качество кода (дублирование, сложность, стиль)
- `brownfield-validate` — соответствие спецификации (полнота, архитектура, стандарты)
