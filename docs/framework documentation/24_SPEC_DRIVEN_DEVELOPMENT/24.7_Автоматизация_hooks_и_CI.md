## L1 — approval-gate.py (PreToolUse, блокирующий)

Подробно описан в [24.4 Approval Gate](24.4_Approval_Gate.md). Здесь — краткая роль в общей картине.

**Файл:** [`.claude/hooks/approval-gate.py`](../../../.claude/hooks/approval-gate.py)
**Event:** `PreToolUse:Skill`
**Триггер:** `Skill('implement-1c-task')` или `Skill('opsx:apply')`
**Логика:** читает `openspec/changes/<change>/.openspec.yaml`, поле `approval.status`. Если `≠ approved` — `block()` с инструкцией запустить `/opsx:approve`.
**Регистрация:** [.claude/settings.json](../../../.claude/settings.json) → `PreToolUse` chain.

Это **единственный hook блокирующего класса** в OpenSpec-автоматизации. Все остальные — информационные (`system_message`), не прерывают workflow.

## L2 — openspec-change-coverage.py (PostToolUse, info)

**Файл:** [`.claude/hooks/openspec-change-coverage.py`](../../../.claude/hooks/openspec-change-coverage.py)
**Event:** `PostToolUse` с matcher `Edit|Write|NotebookEdit`
**Что делает:** при правке файла в `ИБTransportManagementDevelop/Конфигурация/src/**` ищет JIRA-токен `GKSTCPLK-NNNN` в пути → проверяет, есть ли active change в `openspec/changes/*/`, упоминающий этот токен (в `.openspec.yaml`/`proposal.md`/`tasks.md`). Если нет — эмитит `systemMessage` с рекомендацией создать change через `/opsx:propose`.
