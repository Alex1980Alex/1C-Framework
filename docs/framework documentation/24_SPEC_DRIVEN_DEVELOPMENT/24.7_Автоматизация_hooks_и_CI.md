## Обзор

Глава описывает четыре уровня автоматизации OpenSpec в фреймворке: hooks (4 шт), CI workflow, pre-commit lint, smoke-preflight. Все компоненты введены в sprint 2026-05-20 ([roadmap §B/C/D/E/F/Q](../../roadmap/260520_ROADMAP_OPENSPEC_INTEGRATION_V2.md)).

```

│  Слои автоматизации OpenSpec в 1С-Framework                      │
└──────────────────────────────────────────────────────────────────┘

  ┌─────────────────────────────────────────────────────────────┐
  │ L1 — PreToolUse hook (live, блокирующий)                    │
  │   approval-gate.py                                          │
  │   • Skill('implement-1c-task') без approved → BLOCK         │
  │   • Skill('opsx:apply') без approved → BLOCK                │

                               │
  ┌────────────────────────────▼────────────────────────────────┐

  │   • Edit/Write в Конфигурация/ с JIRA-токеном в пути        │

  └────────────────────────────┬────────────────────────────────┘
                               │
  ┌────────────────────────────▼────────────────────────────────┐

  ┌────────────────────────────▼────────────────────────────────┐
  │ L4 — CI/PR gate (remote)                                    │
  │   .github/workflows/openspec.yml                            │
  │   • PR → scripts/openspec_lint_ci.py --mode structural      │

  │   • Comment summary на PR                                   │
```

## L1 — approval-gate.py (PreToolUse, блокирующий)

Подробно описан в [24.4 Approval Gate](24.4_Approval_Gate.md). Здесь — краткая роль в общей картине.

**Файл:** [`.claude/hooks/approval-gate.py`](../../../.claude/hooks/approval-gate.py)
**Event:** `PreToolUse:Skill`
**Триггер:** `Skill('implement-1c-task')` или `Skill('opsx:apply')`
**Логика:** читает `openspec/changes/<change>/.openspec.yaml`, поле `approval.status`. Если `≠ approved` — `block()` с инструкцией запустить `/opsx:approve`.
**Регистрация:** [.claude/settings.json](../../../.claude/settings.json) → `PreToolUse` chain.

Это **единственный hook блокирующего класса** в OpenSpec-автоматизации. Все остальные — информационные (`system_message`), не прерывают workflow.

## L2 — openspec-change-coverage.py (PostToolUse, info)

**Файл:** [`.claude/hooks/openspec-change-coverage.py`](../../../.claude/hooks/openspec-change-coverage.py)
**Event:** `PostToolUse` с matcher `Edit|Write|NotebookEdit`
**Что делает:** при правке файла в `ИБTransportManagementDevelop/Конфигурация/src/**` ищет JIRA-токен `GKSTCPLK-NNNN` в пути → проверяет, есть ли active change в `openspec/changes/*/`, упоминающий этот токен (в `.openspec.yaml`/`proposal.md`/`tasks.md`). Если нет — эмитит `systemMessage` с рекомендацией создать change через `/opsx:propose`.

**Поведение:**

| Сценарий | Результат |
|---|---|
| Edit с JIRA-токеном + есть active change | silent (match found) |
| Edit с JIRA-токеном + НЕТ active change | `systemMessage` warning |
| Edit без JIRA в пути | silent (связь не определима — не шумим) |
| Edit в openspec/ или .claude/ или scripts/ | silent (это инфра) |
| Cooldown 15 минут per (session × jira × file) | silent (анти-флуд) |

**SKIP_PATTERNS:** `openspec/`, `.claude/`, `.github/`, `scripts/`, `/docs/`, `tests/`, `tools/` — нет смысла warnить на правки инфраструктуры.

**Cache:** `.claude/cache/openspec-change-coverage-sessions.json` — boot 100 entries, FIFO.

## L3-a — opsx-apply-postvalidate.py (Stop, info)

**Файл:** [`.claude/hooks/opsx-apply-postvalidate.py`](../../../.claude/hooks/opsx-apply-postvalidate.py)
**Event:** `Stop`
**Что делает:** в конце сессии читает tail `data/hook-invocations.jsonl` (512 KB, ~24h окно). Ищет `slash_run start` для `slash:opsx-apply` / `slash:opsx:apply` / `slash:openspec-apply`. Если найден И в этом же окне нет последующего упоминания `brownfield-validate` — эмитит `systemMessage` с инструкцией запустить `brownfield-validate` для проверки соответствия реализации спецификации.

**Анти-флуд:** per-session cookie в `.claude/cache/opsx-apply-postvalidate-sessions.json` (boot 50). Один раз на сессию.

**Why не auto-spawn:** brownfield-validate — это **skill**, а не CLI; запустить его автоматически из subprocess'а нельзя. Hook эмитит подсказку Claude, который вызывает `Skill('brownfield-validate')` на следующей итерации.

## L3-b — openspec-task-progress.py (Stop, info)

**Файл:** [`.claude/hooks/openspec-task-progress.py`](../../../.claude/hooks/openspec-task-progress.py)
**Event:** `Stop`
**Что делает:** читает `git diff --name-only HEAD~10..HEAD` + `git log --format=%B HEAD~10..HEAD`. Извлекает JIRA-токены из diff/commits. Для каждой JIRA, упомянутой в active change'е, парсит `tasks.md` (паттерн `- [ ] **N.M** <description>`) и выявляет «кандидатов на completed»: задачи, у которых ключевые слова из текста (≥8 символов) встречаются в git diff. Эмитит `systemMessage` со списком кандидатов и шаблоном вызова `mcp__openspec-mcp__openspec_batch_update_tasks`.

**Heuristic-based, не auto-update.** Это подсказка Claude, который должен **вручную** оценить достоверность и пометить задачи. False-positives ожидаемы (ключевое слово в diff'е ≠ задача реально сделана).

**Cache:** `.claude/cache/openspec-task-progress-sessions.json`, per-session, boot 50.

**Известное ограничение:** одна сессия может затрагивать **несколько** JIRA (например, основная задача + параллельный рефакторинг под другой JIRA) — все попадут в кандидаты. Финальное решение за Claude.

## L4 — CI workflow

**Файл:** [`.github/workflows/openspec.yml`](../../../.github/workflows/openspec.yml)

**Триггеры:**
- PR (paths: `openspec/**`, `ИБTransportManagementDevelop/Конфигурация/src/**`, сам workflow)
- push на `master` / `dev-master` (paths: `openspec/**`)

**Шаги:**

1. `openspec_lint_ci.py --mode structural --fail-on-error` — проверка структуры active changes (proposal/tasks/.openspec.yaml обязательны, design/specs/sections рекомендованы)
2. *(только PR)* `openspec_lint_ci.py --mode coverage --base <base_sha> --head <head_sha> --warn-only` — проверка соответствия code-edit'ов в `ИБTransportManagementDevelop/` и JIRA-токенов в commit messages с active change'ами
3. *(только PR)* PR-comment через `actions/github-script@v7` с содержимым `openspec-lint-report.md`

**Permissions:** `contents: read`, `pull-requests: write` (для comment).

**Fail-mode:** структурная проверка `--fail-on-error` падает CI при отсутствии обязательных файлов. Coverage — `--warn-only` (не блокирует merge, только информирует).

## Pre-commit / local lint

**Файл:** [`scripts/openspec_lint_ci.py`](../../../scripts/openspec_lint_ci.py)

Local-frendly CLI с тремя режимами:

| Режим | Что проверяет |
|---|---|
| `structural` | Каждый active change: наличие `proposal.md` / `tasks.md` / `.openspec.yaml` (errors), `design.md` / `specs/<cap>/spec.md` / sections в proposal (warnings) |
| `coverage` | PR-проверка: edit-файлы в Конфигурации с JIRA в commits → есть ли соответствующий active change |
| `all` | structural + coverage |

**Опции:** `--fail-on-error` (exit 1 при errors), `--warn-only` (всегда exit 0), `--base/--head` (SHA для coverage).

**Output:** stdout + `openspec-lint-report.md` (markdown report для PR-comment, в `.gitignore`).

**Использование локально перед коммитом:**

```bash
python scripts/openspec_lint_ci.py --mode structural --fail-on-error
```

## Smoke-preflight

**Файл:** [`scripts/smoke_test_openspec.py`](../../../scripts/smoke_test_openspec.py)

Аналог [`smoke_test_implement_1c_task.py`](../../../scripts/smoke_test_implement_1c_task.py). Проверяет:

1. `openspec/AGENTS.md` + `project.md` + `config.yaml` + `changes/` + `profiles/` присутствуют
2. Каждый active change имеет `proposal.md` + `tasks.md` + `.openspec.yaml`
3. `openspec_lint_ci.py --mode structural` exit 0

**Output:** JSON со статусом `mode = OK | Warn | Fatal`, список active changes, lint exit.

**Использование:** перед `/opsx:propose` / `/opsx:apply` чтобы убедиться что среда консистентна.

```bash
python scripts/smoke_test_openspec.py
# exit 0 = OK, 1 = Warn, 2 = Fatal
```

## Регистрация hooks в settings.json

```json
{
  "hooks": {
    "PreToolUse": [
      { "matcher": "Skill",
        "hooks": [{ "command": "...approval-gate.py", "timeout": 5 }]}
    ],
    "PostToolUse": [
      { "matcher": "Write|Edit",
        "hooks": [
          { "command": "...openspec-change-coverage.py", "timeout": 5 }
        ]}
    ],
    "Stop": [
      { "matcher": "",
        "hooks": [
          { "command": "...opsx-apply-postvalidate.py", "timeout": 5 },
          { "command": "...openspec-task-progress.py", "timeout": 8 }
        ]}
    ]
  }
}
```

Полная регистрация — [.claude/settings.json](../../../.claude/settings.json).
