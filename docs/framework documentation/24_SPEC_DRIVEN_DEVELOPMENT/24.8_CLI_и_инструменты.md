## CLI `openspec` (v1.3.1)

**Пакет:** `openspec-extensions@1.3.4` (NPM, MIT)

**Установка:**

```bash
npm install -g openspec-extensions@1.3.4
```

После установки три бинаря: `openspec`, `openspec-ex`, `openspec-extensions`.

### Зачем нужен

`mcp__openspec-mcp__openspec_validate_change` под капотом вызывает CLI через shell (`execAsync('openspec validate <id>')`). Без установленного CLI tool всегда возвращал `Invalid 0 errors`. После установки (sprint 2026-05-20) валидация работает корректно.

### Основные команды

| Команда | Назначение |
|---|---|
| `openspec list [--json]` | Список active + archived changes |
| `openspec validate <id> [--json] [--strict]` | Валидация change по схеме |
| `openspec validate --all` | Все changes + specs |
| `openspec change show <id> [--json]` | Просмотр change |
| `openspec spec validate <id>` | Валидация отдельного spec |

## Интеграция с инфраструктурой

### A) Memory bridge

Skill `openspec-archive-change` step 6 вызывает `mcp__memory-orchestrator__route_and_save` с metadata `{category: openspec-archived, change_id, jira}` — позволяет позже семантически искать аналогичные завершённые changes.

### B) Semantic search — `framework_code_v1` включает `openspec/`

[src/framework_search/config.py:20-21](../../../src/framework_search/config.py) добавил `openspec` в `DEFAULT_INDEX_ROOTS`. Auto-reindex на git commit через `scripts/git_hooks/post-commit`.

Поиск:
```python
mcp__framework-search__search_code(query="...", path_glob="openspec/changes/**", k=5)
```
