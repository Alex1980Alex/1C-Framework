# 25.3 Архитектура субагента

## Конфигурация

```yaml
# .claude/agents/learning-loop.md (frontmatter)
name: learning-loop
model: opus
tools: [Read, Write, Edit, Grep, Glob, Bash, WebSearch, WebFetch]
skills: [learning-loop]   # SKILL.md автоинжектируется в контекст
```

**Важно:** `Task` tool **исключён** из списка — платформа всё равно блокирует вложенные вызовы.

## Ограничение вложенности

Субагенты **не могут** порождать суб-субагенты. Это намеренное архитектурное решение платформы Claude Code (hub-and-spoke).

```
Main Claude ──┬── Agent(learning-loop)  ✅  глубина 1
              ├── Agent(Explore)         ✅  глубина 1
              │
              └── Внутри Agent(learning-loop):
                    └── Agent(code-verify) ❌  ЗАПРЕЩЕНО
```

**Подтверждено:** GitHub issues [#4182](https://github.com/anthropics/claude-code/issues/4182), [#23506](https://github.com/anthropics/claude-code/issues/23506), [#31977](https://github.com/anthropics/claude-code/issues/31977), [#32731](https://github.com/anthropics/claude-code/issues/32731).

**Следствие:** VERIFY выполняется inline (Grep + self-review), а не через делегирование code-verify субагенту.

## Изоляция контекста

Главная ценность субагента — **изоляция**:
- WebSearch результаты (5-10K токенов) остаются в контексте субагента
- Основной разговор получает только краткий summary
- KB не засоряет основной контекст

## Token Cost

| Подход | Токены |
|--------|--------|
| Один learning-loop субагент | ~1x (базовый) |
| Цепочка 4 субагентов (SEARCH+FETCH+EXECUTE+VERIFY) | ~4x (дороже) |
| Agent Teams | ~15x (экспериментально) |
