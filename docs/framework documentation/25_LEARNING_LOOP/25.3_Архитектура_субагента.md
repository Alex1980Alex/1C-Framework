# 25.3 Архитектура субагента

Субагент Learning Loop — изолированный контекст с Opus model для пайплайна FETCH → EXECUTE → VERIFY. CREATE-фаза выполняется главным Claude (host) после возврата субагента, чтобы skill попал в файловую систему пользователя без race conditions.

## Конфигурация

```yaml
# .claude/agents/learning-loop.md (frontmatter)
name: learning-loop
model: opus
tools: [Read, Write, Edit, Grep, Glob, Bash, WebSearch, WebFetch]
skills: [learning-loop]   # SKILL.md автоинжектируется в контекст
```

### Выбор инструментов

| Tool | Зачем |
|---|---|
| `Read` / `Grep` / `Glob` | SEARCH-фаза: проверка существующих skills + cache/ |
| `WebSearch` / `WebFetch` | FETCH-фаза: сбор knowledge_block из tech-python / 1c доменов |
| `Bash` | EXECUTE-фаза: запуск тестов / verify (через pytest, AST checks) |
| `Write` / `Edit` | EXECUTE-фаза: написание production кода |

### Что **исключено** и почему

```yaml
tools: [Read, Write, Edit, Grep, Glob, Bash, WebSearch, WebFetch]
       # ← БЕЗ Task (запрет рекурсии)
```

`Task` tool **намеренно исключён** — платформа Claude Code блокирует вложенные Subagent вызовы (hub-and-spoke architecture). Если оставить Task в списке, разработчик может случайно попытаться делегировать code-verify внутри learning-loop → silent failure.

**Подтверждено:** GitHub issues [#4182](https://github.com/anthropics/claude-code/issues/4182), [#23506](https://github.com/anthropics/claude-code/issues/23506), [#31977](https://github.com/anthropics/claude-code/issues/31977), [#32731](https://github.com/anthropics/claude-code/issues/32731).

## Ограничение вложенности (hub-and-spoke)

```
Main Claude ──┬── Agent(learning-loop)  ✅  глубина 1
              ├── Agent(Explore)         ✅  глубина 1
              │
              └── Внутри Agent(learning-loop):
                    └── Agent(code-verify) ❌  ЗАПРЕЩЕНО
```

**Следствие для VERIFY-фазы:** проверка соответствия KB выполняется **inline** через Grep + self-review, а не через Subagent(code-verify). Маркерные паттерны из knowledge_block grep'аются непосредственно в EXECUTE-output. Если автоматическая grep-проверка PARTIAL/FAIL → субагент Ralph Wiggum-ит самостоятельно (макс 3 итерации).

После возврата субагента **главный Claude** запускает `Skill('code-verify')` в режиме `knowledge-compliance` — это *второй уровень* проверки уже в host context.

## Изоляция контекста

Главная ценность субагента — **изоляция большого контекста**, который не должен попадать в основной разговор:

| Что остаётся в субагенте | Что возвращается в основной разговор |
|---|---|
| WebSearch результаты (5-10K токенов) | Краткое summary (~200 токенов) |
| WebFetch full-page docs (часто 20K+) | Извлечённые actionable paragraphs |
| Итерации Ralph Wiggum при FAIL | Итог: PASS/FAIL + final code |
| KB Markdown полный (8-15K токенов) | Reference на путь cache/{topic}.md |

**Без изоляции** main context превышает 100K токенов после 2-3 Learning Loop циклов и нужен `/clear`.

## Token cost

| Подход | Относительная стоимость | Когда использовать |
|---|---|---|
| Один learning-loop субагент | **1×** (базовый) | Default — оптимальный trade-off |
| Цепочка 4 субагентов (SEARCH+FETCH+EXECUTE+VERIFY) | ~4× | Очень сложные домены, требующие fresh context на каждой фазе |
| Agent Teams (multi-agent supervisor) | ~15× | Экспериментально — не рекомендуется в production |

**Решение для PDF Framework:** один субагент. Изоляция контекста + Ralph Wiggum loop достаточны для 95% случаев.

## Промпт-инжекция через skill

При запуске `Subagent(learning-loop)` платформа автоматически инжектирует содержимое [`SKILL.md`](../../../.claude/skills/learning-loop/SKILL.md) в начало system prompt субагента. Это значит:

```
[Subagent system prompt]
=== Skill: learning-loop ===
{полный SKILL.md ~250 строк с шаблонами, антипаттернами, чеклистами}
=== End skill ===
{user task: "Изучи tenacity и напиши retry для api.py"}
```

Субагент получает строгий 5-фазный алгоритм без необходимости host'у его передавать руками. SKILL.md обновляется через CREATE-фазу самого Learning Loop — система сама улучшает свой "agent prompt".

## Сравнение с альтернативными архитектурами

| Архитектура | Pros | Cons | Когда подходит |
|---|---|---|---|
| **Inline в host** (без субагента) | Нулевой overhead | Контекст загрязнён 10K+ токенов FETCH | Простые тех. вопросы (1-2 источника) |
| **Скил без субагента** (Skill в host) | Дёшево | Нет fresh context per task | Уже изученные темы (после CREATE) |
| **Single subagent** (текущий выбор) | Изоляция + 1× cost | Нет per-phase fresh context | **Default** для PDF Framework |
| **Multi-agent chain** (4 субагента) | Per-phase isolation, parallel FETCH | 4× cost, сложная оркестрация | Domain research projects |
| **Agent Teams** (supervisor + workers) | Параллелизм | 15× cost, экспериментально | Не используется |
