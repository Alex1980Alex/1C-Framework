# 25.6 Диагностика

## Частые проблемы

| Проблема | Причина | Решение |
|---|---|---|
| Таймаут субагента | FETCH собирает слишком много источников | Ограничить до 3 источников, уменьшить объём KB |
| Низкое качество FETCH | Источники с низким trust score | Проверить `trust_scorer.py` веса, приоритизировать official docs |
| `VERIFY FAIL` 3× подряд | Marker patterns не найдены в коде | Проверить соответствие KB и EXECUTE, уточнить маркеры |
| Skill не зарегистрирован | Ошибка в CREATE фазе | Проверить `skill-router-config.json` на валидность JSON |
| `WebSearch` заблокирован | Сетевые ограничения или rate limit | Использовать pre-cached KB из `skills/*/cache/` |
| Skill превышает 500 строк | Избыточное содержание KB | Извлечь только actionable знания, убрать raw docs |
| Вложенный Subagent FAIL | Платформенный лимит (hub-and-spoke) | VERIFY делать inline через Grep, не через Task |
| Race condition при CREATE | Два параллельных Learning Loop пишут один skill | CREATE выполняется в host, не в субагенте |
| `FETCH` зацикливается на StackOverflow | trust_scorer не отфильтровал closed/duplicate Q | Поднять threshold answer_score >= 5 |
| Subagent игнорирует SKILL.md | Skill не registered в `.claude/skills/skill-router-config.json` | Добавить bundle в config + restart session |

## Когда Learning Loop НЕ нужен

| Ситуация | Почему | Что делать |
|---|---|---|
| Skill уже существует | SEARCH найдёт его | Пайплайн прерывается на фазе 1 |
| Задача в домене Opus | Architecture, debugging, security = Never delegate | Claude делает сам, без субагента |
| Одноразовый скрипт | Overhead на создание skill не оправдан | Claude пишет напрямую |
| Код < 30 строк | Token overhead субагента > экономии | Claude пишет напрямую |
| Уже знакомая стандартная библиотека | Embedded знания достаточно | Claude использует напрямую |
| Domain-specific business logic | Не имеет смысла как universal skill | Inline implementation |

### Ralph Wiggum трассировка (VERIFY FAIL → retry)

При FAIL в VERIFY-фазе субагент логирует попытки в свой контекст:

```
[VERIFY] iteration 1: PARTIAL — missing markers: ['wait_exponential_jitter', 'reraise=True']
[FIX]    итеративно: добавить эти маркеры в код
[VERIFY] iteration 2: PASS — все маркеры найдены
```

Если 3 итерации — все FAIL → субагент возвращает code with `requires manual review` и summary проблем. Главный Claude видит summary и решает: применить вручную, отбросить, или продолжить с placeholder.

### Pending cache tasks

После FETCH результаты складываются в hook-todos как pending CREATE tasks:

```bash
python -c "
import sys
sys.path.insert(0, '.claude/hooks')
from shared.task_master import get_pending_tasks
tasks = get_pending_tasks(created_by='knowledge-cache-reminder-hook')
print(f'pending cache tasks: {len(tasks)}')
for t in tasks: print(' -', t.get('description', '')[:80])
"
```

Если pending > 0 после успешного завершения Learning Loop — вероятно CREATE-фаза не была завершена (subagent timeout или host crash). Resolution: запустить CREATE вручную через `Skill('doc-to-skill')`.

## Мониторинг

| Метрика | Источник | Что показывает |
|---|---|---|
| Triggered count | `data/skill-router.log` | Сколько раз code-skill-enforcer Level A заблокировал |
| Resolution rate | `data/skill-accuracy.jsonl` | % случаев когда LL действительно создал работающий skill |
| Average FETCH cost | `data/hook-invocations.jsonl` (elapsed_ms на learning-loop subagent) | Время на FETCH+EXECUTE+VERIFY |
| Cross-hook trace | `db.get_run_trace(run_id)` (см. [09.4](../09_АДМИНИСТРИРОВАНИЕ/09.4_Мониторинг.md)) | Полная цепочка вызовов в одном LL run |
| Skill creation rate | `git log --diff-filter=A --since='1 week ago' .claude/skills/` | Сколько новых skills создано за неделю |
