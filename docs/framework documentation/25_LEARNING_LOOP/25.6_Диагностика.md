# 25.6 Диагностика

## Частые проблемы

| Проблема | Причина | Решение |
|----------|---------|---------|
| Таймаут субагента | FETCH собирает слишком много источников | Ограничить до 3 источников, уменьшить объём KB |
| Низкое качество FETCH | Источники с низким trust score | Проверить `trust_scorer.py` веса, приоритизировать official docs |
| `VERIFY FAIL` | Marker patterns не найдены в коде | Проверить соответствие KB и EXECUTE, уточнить маркеры |
| Skill не зарегистрирован | Ошибка в CREATE фазе | Проверить `skill-router-config.json` на валидность JSON |
| `WebSearch` заблокирован | Сетевые ограничения или rate limit | Использовать pre-cached KB из `skills/*/cache/` |
| Skill превышает 500 строк | Избыточное содержание KB | Извлечь только actionable знания, убрать raw docs |

## Когда Learning Loop НЕ нужен

| Ситуация | Почему | Что делать |
|----------|--------|-----------|
| Skill уже существует | SEARCH фаза его найдёт | Пайплайн прерывается автоматически |
| Задача в домене Opus | Architecture, debugging, security = Never | Claude делает сам, без субагента |
| Одноразовый скрипт | Overhead на создание skill не оправдан | Claude пишет напрямую |
| Код < 30 строк | Token overhead субагента > экономии | Claude пишет напрямую |

## Мониторинг

Метрики Learning Loop отслеживаются через существующую инфраструктуру:
- `data/skill-router.log` — рекомендации learning-loop
- `data/skill-accuracy.jsonl` — корреляция recommend → activate
- `data/hook-invocations.jsonl` — вызовы code-skill-enforcer Level A.1
- `.claude/cache/hook-todos.json` — pending cache tasks
