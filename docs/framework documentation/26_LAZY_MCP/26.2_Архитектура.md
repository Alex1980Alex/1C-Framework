# 26.2. Lazy-MCP — Архитектура

## Общая схема

```
┌─────────────────────────────────────────────────────────────────────┐
│                         Claude Code                                  │
│                                                                      │
│   Видит только 3 мета-инструмента (~5k токенов):                    │
│   • recommend_tools(task_description)                               │
│   • get_tools_in_category(path)                                     │
│   • execute_tool(tool_path, arguments)                              │
└───────────────────────────┬─────────────────────────────────────────┘
                            │ JSON-RPC 2.0 over stdio
                            ▼
┌─────────────────────────────────────────────────────────────────────┐
│                       Lazy-MCP Server                                │
│                                                                      │
│  ┌──────────────┐  ┌──────────────┐  ┌────────────────────────────┐ │
│  │   Registry   │  │    Loader    │  │    LRU Pool (max 5)       │ │
│  │  (YAML→RAM)  │  │  (spawn)    │  │    OrderedDict[srv→proc]  │ │
│  └──────────────┘  └──────────────┘  └────────────────────────────┘ │
│                                                                      │
│  ┌──────────────┐  ┌──────────────────────────────────────────────┐ │
│  │   Tool       │  │   Server Types:                              │ │
│  │  Interceptor │  │   native  → subprocess (Python/Java/Node)   │ │
│  │  (A/B/C)     │  │   npx     → npx -y <pkg>                    │ │
│  └──────────────┘  │   docker  → docker-mcp-gateway (singleton)  │ │
│                     │   bridge  → HTTP/MCPO proxy                 │ │
│                     └──────────────────────────────────────────────┘ │
└───────────────────────────┬─────────────────────────────────────────┘
                            │
          ┌─────────────────┼─────────────────┐
          ▼                 ▼                 ▼
   ┌────────────┐   ┌────────────┐   ┌────────────┐
   │  ast-grep  │   │ 1c-docs-   │   │  serena    │  ...
   │    -mcp    │   │    rag     │   │            │
   │ (native)   │   │ (native)   │   │ (native)   │
   └────────────┘   └────────────┘   └────────────┘
```

## Компоненты

### 1. Registry (`src/registry.py`)

Загружает конфигурацию из `config/registry.yaml` и строит иерархическую навигацию.

**Ключевые классы:**
- `ServerConfig` — dataclass с параметрами сервера (command, args, env, timeout, type)
- `ToolInfo` — информация об инструменте (name, description, server, category, inputSchema)
- `Registry` — основной класс с методами навигации

**API Registry:**
```python
class Registry:
    get_categories(path="/") -> list[str]       # Список категорий/серверов
    get_server_config(name) -> ServerConfig     # Конфиг сервера
    find_server_by_path(path) -> (cat, srv, tl) # Парсинг пути
    get_category_info(path) -> dict             # Информация о пути
    cache_tools(server, tools)                  # Кеширование инструментов
```

**Навигация по уровням:**
| Путь | Результат |
|---|---|
| `/` | Список категорий: `[1c-development, documentation, ...]` |
| `/1c-development` | Список серверов: `[ast-grep-mcp, bsl-platform-context, ...]` |
| `/1c-development/ast-grep-mcp` | Список инструментов с inputSchema |

### 2. Loader (`src/loader.py`)

Динамический загрузчик с LRU-пулом и поддержкой 4 типов серверов.

**Ключевые классы:**
- `ActiveServer` — активный сервер с процессом, инструментами и stderr-потоком
- `BridgeServer` — HTTP-мост (MCPO)
- `ServerLoader` — основной загрузчик с LRU-кешем

**Жизненный цикл сервера:**
```
get_server(name)
    │
    ├─ Есть в пуле и жив? → move_to_end() → вернуть
    │
    ├─ Пул полон (5/5)? → LRU evict oldest → shutdown
    │
    └─ Запуск нового:
        ├─ native/npx → subprocess.Popen() + stderr drain
        ├─ docker-mcp → singleton gateway + mcp-add
        └─ bridge → HTTP health check + register
```

**Критичные фиксы для Windows:**

| Проблема | Решение | Файл |
|---|---|---|
| Stdout буферизация | `PYTHONUNBUFFERED=1` + `-u` флаг | `loader.py:149-161` |
| Stderr блокирует stdout | Daemon thread `drain_stderr()` | `loader.py:194-211` |
| `CREATE_NO_WINDOW` ломает stdio | `CREATE_NEW_PROCESS_GROUP` | `loader.py:29` |
| `cmd /c` вместо `shell=True` | PATH resolution без промежуточного cmd | `loader.py:169-173` |
| `notifications/initialized` | MCP lifecycle protocol | `loader.py:996-1003` |

### 3. Server (`src/server.py`)

Точка входа MCP-сервера на FastMCP.

**Инициализация:**
```python
def setup():
    registry = Registry(config_path)      # Загрузка YAML
    loader = ServerLoader(registry, max_active=5)  # LRU pool
    mcp_app.run(transport="stdio")        # Запуск
```

**Мета-инструменты:**

| Инструмент | Параметры | Возвращает |
|---|---|---|
| `recommend_tools` | `task_description: str` | Рекомендации категорий + quick_action |
| `get_tools_in_category` | `path: str = "/"` | Иерархия категорий/серверов/инструментов |
| `execute_tool` | `tool_path: str, arguments: dict` | Результат выполнения + routing metadata |

### 4. Tool Interceptor (`src/tool_interceptor.py`)

Автоматическая маршрутизация вызовов через Z.AI с классификацией A/B/C.

## Типы серверов

### Native (subprocess)
Стандартный запуск через `subprocess.Popen` с stdio-транспортом.

```yaml
ast-grep-mcp:
  command: "D:/path/to/python.exe"
  args: ["main.py"]
  env: { PYTHONIOENCODING: "utf-8" }
  timeout: 60000
```

### NPX (npm-пакеты)
Запуск через `npx -y <package>` с автоматической загрузкой при первом вызове.

```yaml
ripgrep:
  command: "npx"
  args: ["-y", "mcp-ripgrep"]
  type: "npx"
```

### Docker-MCP (через Gateway)
Singleton Docker MCP Gateway для контейнерных серверов.

```yaml
brave:
  type: "docker-mcp"
  docker_image: "mcp/brave-search"
  docker_server: "brave"
```

**Архитектура Docker-MCP:**
```
Lazy-MCP → docker-mcp-gateway (singleton) → mcp-exec → Docker Container
```

Gateway запускается один раз (retry 3 попытки), все docker-серверы маршрутизируются через него.

### Bridge (HTTP/MCPO)
HTTP-мост для серверов, доступных через REST API.

```yaml
mcpo:
  type: "bridge"
  endpoints:
    base_url: "http://localhost:8765"
    filesystem: "/filesystem"
    ripgrep: "/ripgrep"
```

Выполнение через HTTP POST вместо subprocess.

## Протокол взаимодействия

Lazy-MCP использует стандартный MCP-протокол (JSON-RPC 2.0):

```
┌─────────┐                           ┌─────────┐
│ Claude  │                           │ Lazy-MCP│
│  Code   │                           │  Server │
└────┬────┘                           └────┬────┘
     │                                     │
     │  initialize (protocolVersion)       │
     │─────────────────────────────────────>│
     │                                     │
     │  initialize response (capabilities) │
     │<─────────────────────────────────────│
     │                                     │
     │  notifications/initialized          │
     │─────────────────────────────────────>│
     │                                     │
     │  tools/list                         │
     │─────────────────────────────────────>│
     │                                     │
     │  [3 meta-tools schemas]             │
     │<─────────────────────────────────────│
     │                                     │
     │  tools/call: recommend_tools(...)   │
     │─────────────────────────────────────>│
     │                                     │
     │  JSON with recommendations          │
     │<─────────────────────────────────────│
     │                                     │
     │  tools/call: execute_tool(...)      │
     │─────────────────────────────────────>│
     │     ┌────────────────────────┐      │
     │     │ Loader starts server   │      │
     │     │ → JSON-RPC initialize  │      │
     │     │ → tools/list           │      │
     │     │ → tools/call           │      │
     │     └────────────────────────┘      │
     │                                     │
     │  Tool result                        │
     │<─────────────────────────────────────│
```

## Поток выполнения `execute_tool`

```
execute_tool("/1c-development/ast-grep-mcp/ast_grep", {pattern: "..."})
    │
    ▼
registry.find_server_by_path() → (category, server_name, tool_name)
    │
    ▼
tool_interceptor.classify_tool(server_name, tool_name) → ToolCategory
    │
    ├─ Category A → Z.AI (или direct fallback)
    ├─ Category B → Z.AI + валидация Claude
    └─ Category C → прямое выполнение
    │
    ▼
loader.get_server(server_name) → ActiveServer (start if needed)
    │
    ▼
_send_request(tools/call) → JSON-RPC response
    │
    ▼
Result → safe_serialize → return to Claude
```
