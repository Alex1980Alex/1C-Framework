# 26.6. Lazy-MCP — Устранение неполадок

## Известные проблемы и решения

### 1. Сервер не отвечает (timeout)

**Симптом:** `execute_tool` возвращает ошибку timeout через 30-180 секунд.

**Причины и решения:**

| Причина | Решение |
|---|---|
| Stderr буфер заполнен → блокирует stdout | Daemon thread `drain_stderr()` (v1.2.0) |
| Python буферизация stdout | `-u` флаг + `PYTHONUNBUFFERED=1` |
| `CREATE_NO_WINDOW` на Windows | Заменён на `CREATE_NEW_PROCESS_GROUP` |
| Сервер не получил `notifications/initialized` | Отправляется после initialize (v1.1.0) |
| Тяжёлый сервер долго стартует | `init_delay` 3.0s для unified-memory, bsl-platform-context |

**Отладка:**

```bash
# Проверить логи stderr
cat infra/lazy-mcp/lazy-err.log

# Запустить вручную с отладкой
cd infra/lazy-mcp
.venv/Scripts/python.exe src/server_wrapper.py
# → claude-startup.log с подробной диагностикой
```

### 2. Z.AI Routing Error

**Симптом:** Tool Interceptor не может направить вызов через Z.AI.

**Решения:**

| Причина | Решение |
|---|---|
| `ZAI_API_KEY` не установлен | Установить env-переменную |
| Z.AI API недоступен | Автоматический fallback на direct execution |
| Circuit breaker открыт | Вызвать `llm_reset_provider("zai-glm5")` |

**Fallback-цепочка:**
```
Z.AI primary → Z.AI fallback provider → Direct subprocess execution
```

### 3. JSON serialization error

**Симптом:** `TypeError: Object of type ZaiResponse is not JSON serializable`.

**Решение:** Функция `safe_serialize()` (v1.3.1) рекурсивно обрабатывает:
- `dataclass` → `dict` через `__dataclass_fields__`
- Обычные объекты → `dict` через `vars()`
- `bytes` → `str` через UTF-8 decode

### 4. NPX-сервер не запускается

**Симптом:** NPX-пакет скачивается, но сервер не отвечает.

**Решения:**

| Причина | Решение |
|---|---|
| NPX кеширует старую версию | `npx clear-npx-cache` |
| Нет internet для первого запуска | Предварительно `npx -y <pkg>` вручную |
| PATH не содержит npx | Используется `cmd /c npx` wrapper |

### 5. Windows-специфичные проблемы

| Проблема | Решение |
|---|---|
| `ProactorEventLoop` зависает | `asyncio.WindowsSelectorEventLoopPolicy()` |
| `readline()` блокирует на Windows | Byte-by-byte `read(1)` цикл |
| cmd.exe съедает кавычки | `cmd /c command arg1 arg2` без shell=True |
| cp1251 кодировка | `PYTHONIOENCODING=utf-8`, `sys.stdin.buffer.read().decode("utf-8")` |

### 6. Docker MCP Gateway не стартует

**Симптом:** Docker-серверы недоступны, gateway timeout.

**Решения:**

| Причина | Решение |
|---|---|
| Docker daemon не запущен | Запустить Docker Desktop |
| Gateway timeout (каталог 311+ серверов) | Увеличен timeout до 15 секунд |
| Порт занят | Проверить `docker ps`, перезапустить |

**Debug:**
```bash
# Проверить Docker
docker ps

# Ручной запуск gateway
docker run -i --rm mcp/gateway
```

## Сравнение подходов

| Метрика | Все серверы загружены | Lazy-MCP |
|---|---|---|
| Токены в контексте | ~100k | ~5k |
| Экономия | — | **95%** |
| Первый вызов | Мгновенно | 1-3 секунды |
| Последующие вызовы | Мгновенно | <500мс |
| Активных процессов | 20+ | max 5 |
| RAM потребление | Высокое | Низкое |
| Автовыбор инструмента | Нет | Да (`recommend_tools`) |
| Z.AI маршрутизация | Нет | Да (A/B/C) |
