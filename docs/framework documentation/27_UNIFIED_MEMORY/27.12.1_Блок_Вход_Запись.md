# 27.12.1 Блок «ВХОД (запись)» — точки записи в память

> Детализация блока **«ВХОД (запись)»** мастер-схемы [27.12 §10](27.12_Memory_Systems_Map.md): все пути, которыми данные физически попадают в store'ы Unified Memory — от «умного» `route_and_save` до Stop-харвестеров. Все факты — из кода `src/memory/` и `.claude/hooks/`.

```text
  ВХОД (запись)                                  куда пишет физически
  ┌──────────────────────────┐
  │ route_and_save           │──► 1..3 store'а (Router, пороги 0.80/0.50/0.30)
  │ save_pattern             │──► Qdrant learned_patterns (prior 0.70)
  │ save_important_message   │──► SQLite memory_ai.db
  │ capture_pattern          │──► JSONL pending_patterns.jsonl (default)
  │ Stop: session-memory-save│──► SQLite (category=session_summary)
  │ Stop: patterns-harvester │──► Qdrant learned_patterns (UUID5(content_hash))
  │ Stop: skills-harvester   │──► Qdrant skill_library (incremental)
  └──────────────────────────┘
```

---

## 1. `route_and_save` — умная запись через роутер

**Сигнатура** ([memory_orchestrator.py](../../../src/memory/orchestrator/memory_orchestrator.py), `MemoryOrchestrator.route_and_save`): `route_and_save(content: str, metadata: dict | None, auto_propagate: bool = False)`.

Шаги (по коду):

1. **Роутинг** — `MemoryRouter.route(content, metadata)` ([memory_router.py](../../../src/memory/orchestrator/memory_router.py)), 4-фазная классификация:
   - **Phase 0** `ContentClassifier` (regex-сигналы FACT/PREFERENCE/RULE/SKILL/CODE; каждый match `+0.3`, нормализация `score/3.0`). При `confidence ≥ 0.6` — сразу единственный target из `CONTENT_TYPE_TARGETS` (FACT/PREFERENCE/OBSERVATION → `memory-ai`, RULE/CODE → `vector-memory`, SKILL → `skill-learning`, WIKI → `wiki`).
   - **Phase 1** — детерминированные правила: `EXPLICIT_KEYWORDS` (категория → `CATEGORY_TARGETS`: patterns/code→`vector-memory`, facts→`memory-ai`, skills→`skill-learning`, wiki→`wiki`) с conf `1.0`; `INTENT_PATTERNS` («запомнить это», «создать паттерн», «promote to wiki»…) с conf `0.95`; type-detection (code-блоки `0.85`, config-файлы `0.7`).
   - **Phase 2** — keyword scoring (TF-IDF-like, веса `patterns 1.5 / facts 1.2 / skills 1.3`).
   - **Phase 3** `_phase3_select_targets` — **пороги количества store'ов** из `RouterConfig`: top-score `≥ 0.80` → 1 target; второй score `≥ 0.50` → 2 targets; третий `≥ 0.30` → 3 targets; иначе fallback top-1. Финальный fallback всей цепочки — `{"memory-ai": 0.3}`.
   - Контент длиннее `max_content_length=10000` усекается до `truncate_length=2000` ещё до классификации.
2. **Лог решения** — `write_trace("memory-routing.log", "route", targets/method/confidences)` (§27 P1 D1.1, fail-soft, opt-out `MEMORY_ROUTING_LOG_DISABLE=1`).
3. **Запись в каждый target** — `_save_to_target(target, content, metadata)`: на каждый target генерируется **новый `uuid4`** entity_id:
   - `memory-ai` — прямой SQLite `INSERT INTO important_messages` (`data/memory_ai.db`), importance из metadata (default `0.7`), category default `general`;
   - `vector-memory` — прямой `client.upsert` в `learned_patterns` (минуя handler `save_pattern`!), payload с `confidence` из metadata (default `0.7`), `pattern_type` default `code-convention`;
   - `skill-learning` — append в `data/skill_learning/patterns.jsonl` (**сразу в confirmed-файл, минуя pending**), `pattern_type` default `workflow-pattern`;
   - `wiki` — `MemoryCube.to_wiki_page()` → файл `docs/wiki/drafts/{slug}.md`.
4. **Cross-links** — при `saved_entities > 1` цепочка `LinkRegistry.create_link(..., SESSION_CONTEXT, strength=0.7)`.
5. **Событие + аудит** — `_emit_event("memory.save", …)` (EventBus/EventStore) и `_audit(AuditAction.CREATE, …)` → `data/services/audit.jsonl`.

**Идемпотентность: НЕТ.** ⚠ Расхождение с контрактом §26 (27.12 §11.2): `_save_to_target` не вычисляет `content_hash`, не делает skip-on-exists и не зовёт `record_ingest` — повторный вызов с тем же контентом создаёт дубликаты с новыми `uuid4`. Fail-soft: исключение в одном target логируется (`logger.error`) и даёт `None` — остальные targets записываются.

## 2. `save_pattern` — прямая запись паттерна (vector-memory MCP)

**Handler** `handle_save_pattern` ([server.py](../../../src/memory/vector_memory/server.py)). Schema: `pattern_type` (enum `PatternType`), `name`, `content` — required; `description`, `confidence`, `tags`, `evidence_sources` — optional.

Что реально делает:

1. `pattern_id = uuid4()` — **каждый вызов = новая точка** (дедупа нет).
2. **Advisory `confidence` ИГНОРИРУЕТСЯ** (§22.9.1): ставится `derive_confidence(0.0, 0.0)` = **0.70** (среднее Beta(7,3) prior), `succ=0`, `fail=0`, `last_decay_at=now`. Доверие растёт только через `apply_pattern`.
3. Embed текста `"{name}: {content}"` через `_get_embedding` (проектный провайдер `pdf_framework.embeddings`; при недоступности — `RuntimeError`, hash-fallback только при opt-in `MEMORY_VECTOR_ALLOW_HASH_FALLBACK=1`).
4. `client.upsert` в `COLLECTION_NAME` (`learned_patterns`, env `LEARNING_COLLECTION_NAME`, 4096d cosine, env `LEARNING_VECTOR_SIZE`).
5. `_bump_epoch()` — §24 инвалидация surfacing-кэша; `_log_lifecycle("save", pattern_id, confidence)` → §22 lifecycle-лог ([lifecycle_log.py](../../../src/memory/vector_memory/lifecycle_log.py), fail-soft).

⚠ Расхождение с 27.12 §11.2 («ключ дедупа = `content_hash` (payload)»): `handle_save_pattern` **не проставляет `content_hash` и не дедупит** — в payload его кладут только харвестеры (§6) и `MemoryCube.to_vector_memory_payload()`. `record_ingest` тоже не вызывается (вызывают только харвестеры).

## 3. `save_important_message` — прямая запись в memory-ai

**Handler** `save_important_message` ([ai_memory/server.py](../../../src/memory/ai_memory/server.py)). Параметры: `content` (required), `importance` (default `0.7`), `category` (default `"general"`), `tags`.

Шаги: `msg_id = uuid4()` → `INSERT INTO important_messages (id, content, importance, category, tags, created_at, updated_at, metadata)` в `data/memory_ai.db` (`DB_PATH`). Tags сериализуются JSON'ом, `metadata = {}`. Логируется только `logger.info` (stderr MCP-сервера); ни `content_hash`, ни `record_ingest`, ни дедупа в коде нет — идемпотентность не обеспечивается (повторный вызов = вторая строка).

## 4. `capture_pattern` / `batch_capture` — захват в skill-learning

**Handler** `handle_capture_pattern` ([skill_learning/server.py](../../../src/memory/skill_learning/server.py)). Параметры: `pattern_type`, `name`, `content` (required); `description`, `confidence` (default `0.7`), `tags`, `evidence_sources`, `metadata`, `require_confirmation` (default `true`).

- `pattern_id = uuid4()`, запись с нулевыми счётчиками (`application_count/success_count/failure_count = 0`, `version=1`, `archived=false`).
- `require_confirmation=true` (default) → append в **`data/skill_learning/pending_patterns.jsonl`** (`PENDING_FILE`), статус `pending`; `false` → сразу в `patterns.jsonl` (`SAVED_FILE`) + обновление `learning_stats.json`.
- `confirm_pattern` переносит запись pending → `patterns.jsonl`; `reject_pattern` → `rejected_patterns.jsonl`.
- `batch_capture(patterns, require_confirmation)` — простой цикл по `handle_capture_pattern` с общим флагом.
- Дедупа по `content_hash` нет; зато подтверждённые записи `patterns.jsonl` дальше **подхватывает patterns-harvester** (§26 P2 D2.2, источник `skill_learning` в `harvest()`) и идемпотентно прокачивает в `learned_patterns`.

## 5. Stop-хук `session-memory-save` — авто-сохранение сессии

[session-memory-save.py](../../../.claude/hooks/session-memory-save.py), Event: Stop, timeout 5s, advisory (всегда exit 0).

1. `collect_context()` — `session-skills.json` (session_id, активированные skills), git (`diff`/`diff --cached`/`status --porcelain` + `log --since="8 hours ago"`, до 5 коммитов), завершённые задачи из `hook-todos.json`.
2. Гейт значимости `is_meaningful`: **`MIN_FILES=2` или `MIN_COMMITS=1` или `MIN_SKILLS=1`** — иначе skip.
3. **Дедуп `already_saved`** — по `session_id` в `metadata` (SQL `LIKE`), fallback — не более 1 сводки в день (`session_date`). Ключ дедупа — session_id/дата, **не `content_hash`**.
4. `save_to_sqlite` — `INSERT` в `important_messages`, `category="session_summary"`, importance авто-расчёт **0.5–0.95** (`+0.02/файл cap 0.2, +0.05/коммит cap 0.15, +0.03/skill cap 0.1, +0.03/задачу cap 0.1`), авто-теги по префиксам путей (`src/memory/`→`memory`, `.claude/hooks/`→`hooks`, …).
5. `reinforce_session(session_id, detect_session_success(ctx))` — мостик §22 reinforce (fail-soft try/except).

⚠ Расхождение с 27.12 §4/§10 («Stop-hook → SQLite + `docs/wiki/log.md`»): в коде `save_to_wiki_log()` и `try_promote_patterns()` — **заглушки** (`return False/None`, «full impl deferred», пост-PR#2 регрессия). Реально хук пишет **только в SQLite**; запись в `docs/wiki/log.md` сейчас не выполняется. `_emit_langfuse_span` — тоже stub.

## 6. `patterns-harvester.py` — Stop-ingestion в learned_patterns (§26 P1 D1.1)

Хук [patterns-harvester.py](../../../.claude/hooks/patterns-harvester.py) (timeout 8s, opt-out `PATTERNS_HARVEST_DISABLE=1`, cap `PATTERNS_HARVEST_CAP`, default 5) делегирует в [shared/pattern_harvest.py](../../../.claude/hooks/shared/pattern_harvest.py) `harvest()`. Три источника-кандидата:

| Источник | Откуда | Фильтр качества |
|---|---|---|
| confirmed feedback-drafts | `data/memory_drafts/*.md` | frontmatter `metadata.status ∈ {confirmed, approved}`, поле «Правило» ≥ 25 симв., без `<placeholder>` |
| session-lessons | `data/lifecycle/*.md` (≤ 48h) | bullets секции «Lessons», noise-фильтр авто-задач (`_LESSON_NOISE_RE`) |
| confirmed skill-learning | `data/skill_learning/patterns.jsonl` | не `archived`, content ≥ 25 симв. (§26 P2 D2.2) |

Ядро `ingest_items()` — **эталонная реализация контракта писателя §26**:

1. In-run дедуп кандидатов по `content_hash`;
2. **point id = `UUID5(фикс. namespace, content_hash)`** — детерминированный: re-harvest того же контента находит существующую точку через дешёвый `client.retrieve` (без траты embedding) → `skipped_dup`;
3. per-run cap → `skipped_cap`;
4. TEI passage-embed (`/embed`, без query-инструкции, truncate 8000);
5. payload зеркалит `_pattern_to_payload` **+ `content_hash`**, `confidence = 0.70` (Beta(7,3) prior, как `save_pattern`), `tags += harvested`, `metadata.harvest_source`;
6. `_emit_ingest_stats` → `record_ingest("learned_patterns", saved|dup, content_hash=…, pattern_id=…, harvester="patterns")` per item; cap/error — счётные события `skipped(reason="cap")`/`error`.

Полностью fail-soft (Qdrant/TEI down → `errors` в stats, stop не блокируется). Хук репортит `[PATTERNS-HARVEST] +N pattern(s) → learned_patterns (dup=…, cap=…, err=…)`.

## 7. `skills-harvester.py` — инкрементальная индексация skill_library (§26 P1 D1.2)

Хук [skills-harvester.py](../../../.claude/hooks/skills-harvester.py) (timeout 8s, opt-out `SKILLS_HARVEST_DISABLE=1`, cap `SKILLS_HARVEST_CAP`, default 10) → [shared/skills_harvest.py](../../../.claude/hooks/shared/skills_harvest.py) `harvest_skills()`:

- сканирует `.claude/skills/*/SKILL.md`; идемпотентность — `sha256(SKILL.md)[:16]` в state-файле `.claude/cache/skills-harvest-state.json` (atomic `os.replace`): unchanged → skip;
- **cold-start seed**: первый запуск записывает хэши **без embedding** (коллекция уже наполнена batch-индексатором — защита от шторма ~80 embed'ов внутри Stop);
- changed/new → TEI passage-embed `description\ntriggers` → upsert в Qdrant `skill_library`, point id = `uuid5(NAMESPACE_URL, skill_name)` (та же схема, что у batch-индексатора → инкремент обновляет те же точки);
- **stale-cleanup**: skill исчез с диска → `client.delete` его точки.

В отличие от patterns-harvester, `record_ingest` здесь **не вызывается** (store — `skill_library`, не `learned_patterns`); наблюдаемость — через systemMessage `[SKILLS-HARVEST]` и stats.

## 8. Контракт писателя §26 — `content_hash` + `record_ingest`

- **Ключ**: [content_hash.py](../../../src/memory/orchestrator/content_hash.py) — `hash_content(text) = sha256(content)[:16]` (`HASH_WIDTH=16`, `errors="replace"`, не менять без миграции); `content_key(payload)` берёт `content`, fallback `description`. Единственная реализация — `scripts/dedupe_learned_patterns.py` делегирует сюда.
- **Метрики**: [ingest_metrics.py](../../../src/memory/orchestrator/ingest_metrics.py) — `record_ingest(store, action, content_hash=, reason=, harvester=)` пишет в 2 sink'а: JSONL `.claude/cache/memory-ingestion.log` (cross-process, ротация при 2 MB — atomic, оставляет новую половину; путь переопределяется `CLAUDE_CACHE_DIR`) + best-effort счётчики `MetricsCollector` (`ingest_{action}`, `ingest_{store}_{action}`). Словарь действий `ACTIONS = saved / dup / skipped / error`. Metadata-only (тела не пишутся), полностью fail-soft, opt-out `MEMORY_INGEST_LOG_DISABLE=1`. Плюс `record_store_size(store, size)` — gauge размера store.
- **Фактическое покрытие контракта (по коду):** полный контракт (hash-дедуп + `record_ingest`) реализуют **только харвестеры** (`ingest_items`). MCP-писатели `save_pattern` / `save_important_message` / `capture_pattern` и `_save_to_target` оркестратора пишут «слепым upsert'ом» без hash-гейта — это разрыв между описанным в 27.12 §11.2 контрактом и текущим кодом прямых писателей.

## 9. Сводка писателей

| Точка входа | Триггер | Store (физически) | Ключ дедупа | Лог |
|---|---|---|---|---|
| `route_and_save` | MCP (orchestrator) | 1–3 из: `memory_ai.db` / `learned_patterns` / `patterns.jsonl` / `docs/wiki/drafts/` | **нет** (uuid4 каждый раз) | `memory-routing.log` + event `memory.save` + `audit.jsonl` |
| `save_pattern` | MCP (vector-memory) | Qdrant `learned_patterns` | **нет** (uuid4) | §22 lifecycle-лог (`save`) + epoch bump |
| `save_important_message` | MCP (memory-ai) | SQLite `important_messages` | **нет** | только logger stderr |
| `capture_pattern` | MCP (skill-learning) | `pending_patterns.jsonl` (default) / `patterns.jsonl` | **нет** | `learning_stats.json` (при сразу-save) |
| `session-memory-save` | Stop-хук | SQLite, `category=session_summary` | `session_id` / 1-в-день | (wiki-log — stub) |
| `patterns-harvester` | Stop-хук | Qdrant `learned_patterns` | `UUID5(content_hash)` ✅ | `memory-ingestion.log` (`record_ingest`) |
| `skills-harvester` | Stop-хук | Qdrant `skill_library` | hash SKILL.md в state-файле ✅ | systemMessage + stats |

## 10. Типичные сбои и диагностика

| Симптом | Причина в коде | Диагностика / opt-out |
|---|---|---|
| Дубликаты в `learned_patterns` | прямые писатели (`save_pattern`, `route_and_save`) без hash-дедупа | `scripts/dedupe_learned_patterns.py`; `--view dup-rate` по `memory-ingestion.log` |
| `route_and_save` «сохранил», но entity нет | `_save_to_target` fail-soft: exception → `logger.error` → target пропущен, `saved_entities` короче `targets` | сверить `routing.targets` vs `saved_entities` в ответе |
| `save_pattern` падает с `RuntimeError` | embedding-провайдер не поднялся (умышленно: hash-fallback давал случайный поиск) | TEI/провайдер up; opt-in `MEMORY_VECTOR_ALLOW_HASH_FALLBACK=1` (только smoke) |
| confidence сохранённого паттерна «не тот, что передали» | advisory `confidence` игнорируется — всегда prior 0.70 | это by design (§22.9.1), растить через `apply_pattern` |
| Харвест молчит (0 created) | всё dup (идемпотентность), либо качество-фильтры (placeholder/`< 25` симв./noise), либо Qdrant/TEI down (`errors`) | `tail .claude/cache/memory-ingestion.log`; `PATTERNS_HARVEST_DISABLE=1` / `SKILLS_HARVEST_DISABLE=1` |
| Сессия не сохранилась | `is_meaningful` не прошёл (< 2 файлов, 0 коммитов, 0 skills) или дедуп `already_saved` | `sqlite3 data/memory_ai.db "select * from important_messages where category='session_summary'"` |
| Нет записей в `docs/wiki/log.md` | `save_to_wiki_log` — заглушка (deferred) | известное расхождение, см. §5 |
| Пустой `memory-ingestion.log` | `MEMORY_INGEST_LOG_DISABLE=1`, либо пишут только харвестеры (MCP-писатели не логируют) | проверить env; событие есть только у harvest-путей |
| Свежий паттерн не всплывает в surfacing | мутации без `_bump_epoch` нет только у харвестеров — они epoch не бампают (bump есть в `save_pattern`/`apply`/`delete`/`decay`) | подождать TTL кэша surfacing или любую MCP-мутацию |
