# 27.12.4 Блок «ВЫХОД (чтение)» — unified_search vs surfacing

> Зум на блок **«ВЫХОД (чтение)»** мастер-схемы [27.12 §10](27.12_Memory_Systems_Map.md): два независимых пути, которыми данные достаются из памяти — явный federated-поиск `unified_search` (через оркестратор) и авто-surfacing `memory-first-hook` (мимо оркестратора, hot-path). Глава сравнивает их стадия-в-стадию с точными константами из кода. Детали каждого пути по отдельности — [27.3 Memory-First Hook](27.3_Memory_First_Hook.md) и [27.5 Поиск и сервисы](27.5_Поиск_и_сервисы.md); качество surfacing (§24/§25) — [27.10](27.10_Memory_Surfacing_Quality.md). Все факты — из [unified_search.py](../../../src/memory/orchestrator/unified_search.py) и [memory-first-hook.py](../../../.claude/hooks/memory-first-hook.py).

## Фрагмент мастер-схемы

```text
                 КООРДИНАЦИЯ                        ВЫХОД (чтение)
        ┌──────────────────────┐      ┌────────────────────────────────────┐
        │  Memory Orchestrator │◄─────│ unified_search                     │
        │  Search(adapters →   │      │ adapters ∥ → RRF(k=60, 60/40)      │
        │   RRF→dedup→rerank→  │      │ → min_score 0.3 → MD5-dedup        │
        │   links)             │      │ → diversity ≤3 → LinkEnricher      │
        └──────────┬───────────┘      └────────────────────────────────────┘
                   │  МИМО оркестратора (hot-path):
                   │                  ┌────────────────────────────────────┐
   [stores: memory-ai · vector-      ◄│ memory-first-hook (UserPromptSubmit)│
    memory · skill-learning ·         │ cache(epoch) → tei → 3 arms → gate │
    pdf-docs · .md-слой]              │ → RRF(k=60) → top-5 → stdout inject│
                                      └────────────────────────────────────┘
```

Оба пути сходятся на одних и тех же store'ах и на одной валюте ранжирования (§22 confidence), но идут к ним разными маршрутами: `unified_search` — через слой адаптеров оркестратора (универсальность), хук — прямыми клиентскими вызовами (латентность).

## Путь 1 — `unified_search` (федеративный, через оркестратор)

`UnifiedSearchEngine.search()` ([unified_search.py](../../../src/memory/orchestrator/unified_search.py)) — пайплайн `Dispatch ∥ → RRF → Filter → Dedup → Rerank → Enrich → Limit → Trace`.

### Стадии и константы

| # | Стадия | Класс/код | Точные константы |
|---|---|---|---|
| 1 | **Parallel dispatch** | `asyncio.create_task` + `wait_for` per adapter | per-adapter timeout = `timeout_ms/1000` (default **5000 ms**); общий hard ceiling `asyncio.timeout(timeout_ms × 1.5)` — защита от event-loop starvation в долгоживущей MCP-сессии. Упавший/просроченный адаптер → `SourceError` в `sources_failed`, остальные живут |
| 2 | **Filter by memory_type** | до фьюжна, per-source | `memory_types` сужает результаты каждого источника |
| 3 | **RRF fusion** | `RRFMerger(k=60)` | `score(d) = Σ weight_S / (k + rank_S)`, rank с 1 (`k + rank + 1` при enumerate с 0); per-source веса из `options.rrf_source_weights` (default 1.0); RRF-сумма нормализуется на `max_rrf = Σ w/(k+1)` |
| 4 | **Blend 60/40** | там же | `final_score = 0.6 × base_rrf + 0.4 × boost`, где boost = `ScoreNormalizer.normalize()`: clamp raw в [0,1], затем **×1.2** если запись моложе 24 ч, **×1.1** если моложе 7 дней, **×1.15** если `raw_score > 0.8`, итог clamp ≤1.0 |
| 5 | **min_score filter** | `search()` | default **0.3** по `final_score` |
| 6 | **Dedup** | `Deduplicator` | **MD5** от `content.strip().lower()`; дубликат не выбрасывается бесследно — его источник дописывается в `duplicate_sources` победителя |
| 7 | **Diversity rerank** | `Reranker` | sort по `final_score` desc, затем **≤3 результата с одного источника** в верхних позициях (ограничение снимается после 10 выданных) |
| 8 | **Link enrichment** | `LinkEnricher` | `LinkRegistry.get_all_links(min_strength=0.5)` (default `max_link_depth=1`) → `linked_entities` (outgoing+incoming); fail-soft per item |
| 9 | **Limit + trace** | `search()` | срез `[:limit]` (default **20**); запись JSONL в `memory-read.log` через `infrastructure/trace_log.py` — metadata-only (`query_len`, per-source `arm_hits`, `sources_failed`, `latency_ms`; текст запроса НЕ логируется; opt-out `MEMORY_READ_LOG_DISABLE`) |

Fallback: при `rrf_enabled=False` — плоский merge + `ScoreNormalizer` без RRF (`metadata.fusion = "normalize"`). Адаптеры — `BaseSearchAdapter` (`search()` + `source_name()`), регистрируются в engine; сам движок store'ов не знает (подробно про адаптеры и hybrid-сервисы — [27.5](27.5_Поиск_и_сервисы.md)).

## Путь 2 — `memory-first-hook` (auto-surfacing, мимо оркестратора)

[memory-first-hook.py](../../../.claude/hooks/memory-first-hook.py), event `UserPromptSubmit`, advisory (exit 0 всегда). Бьёт по SQLite/Qdrant/`.md` **напрямую** (никакого импорта `orchestrator/`) — каждый промпт спавнит свежий процесс, бюджет жёсткий. Пайплайн: `skip → cache → [tei → arms → gate → rrf] → layer-RRF → (rerank) → inject`.

### Стадии и пороги

1. **Skip-фильтры**: промпт < `MIN_PROMPT_LEN=20` символов, начинается с `/`, односложный, либо cooldown < `COOLDOWN_SECONDS=30` → выход без поиска.
2. **Tokenize**: lowercase + русский суффиксный стеммер (29 суффиксов).
3. **Execution-cache (§24)**: ключ = `sha256(f"{epoch!r}|{sorted(query_tokens)}")[:32]`, файл `.claude/cache/memory-first-surfacing-cache.json`, TTL `MEMORY_SURFACE_CACHE_TTL=300s`, FIFO-cap **200** ключей, atomic write (mkstemp + `os.replace`). **Hit** пропускает весь пайплайн (~2 s экономии: TEI+Qdrant+RRF+rerank), но **реплеит `record_surfaced`** по сохранённым `pids` — петля §22 P1 не рвётся. Кешируется и пустой результат (`cached-empty`).
4. **Слои поиска** (последовательно, каждый под `time.monotonic() < deadline`; `TOTAL_BUDGET=3.0s`, hard-kill хука в settings.json — 5 s):
   - `sqlite` (200 ms): top-200 `important_messages` по importance, token-overlap `|overlap|/|query|` + tag-boost `+0.2`, порог `SCORE_THRESHOLD=0.3`;
   - `qdrant` (2.0 s): **3 плеча** → свой RRF, см. ниже;
   - `md` (500 ms): `memory/*.md`, weighted overlap `name×3 / desc×2 / body×1`, score `0.7·coverage + 0.3·density`, порог 0.3;
   - `wiki` (200 ms): **stub, возвращает `[]`** (full impl deferred).
5. **Внутренний hybrid RRF в `search_qdrant`** — `rrf_merge(arms, SURFACE_RRF_WEIGHTS, k=SURFACE_RRF_K=60)`:

   | Плечо | Источник | Вес |
   |---|---|---|
   | `skill` | `skill_library` semantic (TEI Qwen3 4096d, top-5) | 0.5 |
   | `pattern_dense` | `learned_patterns` semantic (gated) | 0.3 |
   | `pattern_lexical` | `learned_patterns` token-overlap (scroll 100 точек) — **ALWAYS-ON**, не fallback | 0.7 |

   TEI down → dense-плечи пусты, lexical живёт (graceful degradation в lexical-only). Дедуп внутри RRF — `sha1(content)[:16]`; паттерн в двух плечах фьюзится → boosted rank.
6. **Confidence-gating (§24 ADR-D6)** — `_pattern_score_gate`, применяется к обоим pattern-плечам: `expired_at` set → **hard-exclude** (override `MEMORY_INCLUDE_ARCHIVED=1`); `effective_confidence < MIN_SURFACE_CONF=0.15` → drop (noise floor); иначе `score × max(CONF_FLOOR=0.30, eff)` (floored-multiply: новый паттерн с prior 0.70 не давится, discredited 0.1 → подавлен).
7. **Слойный RRF**: `rrf_merge` по 4 слоям с `LAYER_WEIGHTS = {sqlite: 0.30, qdrant: 0.35, md: 0.15, wiki: 0.20}`, k=60, формула `w × 1/(k+rank)` → top-`MAX_RESULTS=5`.
8. **Опциональный LLM-rerank (§24 P2)**: OFF by default (`MEMORY_RERANK=1`), Ollama `qwen2.5-coder:7b`, минимум 3 кандидата, бюджет = остаток до 5s hard-kill минус 0.5s safety (< 0.8s → skip); любой fail → fused-порядок.
9. **Inject**: `_emit_stdout` — UTF-8 **байтами** через `sys.stdout.buffer` (не `print()`: кириллица на cp1251-pipe молча роняла инъекцию), формат `[MEMORY CONTEXT] Top N ...`.

Константы 5–7 — **самотюнящиеся** (§25): `_load_surfacing_tuning()` при импорте оверлеит `data/memory/surfacing_tuning.json` (clamped; opt-out `MEMORY_SURFACE_TUNING_DISABLE=1`; env `MEMORY_SURFACE_CACHE_TTL` побеждает файл). Подробно — [27.10 §25](27.10_Memory_Surfacing_Quality.md).

> ⚠ **Расхождение с 27.3:** там до сих пор веса `0.35/0.40/0.25` и бюджет 4.0s — это состояние P5.2 v3. В коде: 4 слоя `0.30/0.35/0.15/0.20`, `TOTAL_BUDGET=3.0`, `QDRANT_TIMEOUT=2.0`. Аналогично таблица arm'ов в 27.10 §P1 ещё перечисляет `experience`/`conversation` — эти плечи **удалены 2026-06-03** (§26 Q1 ADR) вместе с коллекциями; в коде `SEMANTIC_COLLECTIONS` = только `skill_library` + `learned_patterns`, arm'ов три. Шапка-docstring самого хука («Timeout 2s, budget 1.5s») тоже отстала от констант.

## Сравнительная таблица двух путей

| Аспект | `unified_search` | `memory-first-hook` |
|---|---|---|
| **Кто вызывает** | агент явно (MCP tool `unified_search`) или код через `federated_search()` | Claude Code автоматически на каждый `UserPromptSubmit` |
| **Через что идёт** | оркестратор → `BaseSearchAdapter`-слой (store'ы инкапсулированы) | **напрямую** в store'ы: `sqlite3`, `QdrantClient(127.0.0.1:6333)`, файлы `.md` |
| **Источники** | все зарегистрированные адаптеры (memory-ai, vector-memory, skill-learning, pdf-docs, …) | SQLite `important_messages` + Qdrant `skill_library`/`learned_patterns` + `memory/*.md` + wiki-stub |
| **Latency-бюджет** | 5 s per adapter, hard ceiling 7.5 s (×1.5) | 3.0 s total (5 s hard-kill хука); per-layer 0.2/2.0/0.5/0.2 s |
| **Ранжирование** | RRF k=60 → blend `0.6·rrf + 0.4·boost` (24h ×1.2, week ×1.1, conf>0.8 ×1.15) → min_score 0.3 | двухуровневый RRF k=60 (arms 0.5/0.3/0.7 → layers 0.30/0.35/0.15/0.20), порог 0.3 на входе слоёв |
| **Роль §22 confidence** | boost ×1.15 по `raw_score` (адаптеры могут отдавать effective) | полноценный gate: `payload_effective_confidence` (decayed Beta(7,3)) — drop <0.15, `×max(0.30, eff)`, archived excluded |
| **Dedup** | MD5 полного content + `duplicate_sources` | sha1(content)[:16] внутри RRF (фьюжн, не выброс) |
| **Diversity** | ≤3 на источник в топе | нет (top-5 как есть) |
| **Кеш** | нет (каждый вызов живой) | disk execution-cache, TTL 300 s, FIFO 200 |
| **Инвалидация** | не нужна | **epoch в cache-key**: любая мутация confidence → `bump()` → instant miss |
| **Связи** | `LinkEnricher` → `linked_entities` из LinkRegistry | нет (links — не hot-path) |
| **Лимит выдачи** | 20 | 5 (`MAX_RESULTS`) |
| **Наблюдаемость** | `memory-read.log` (trace_log, §27 D1.2) | `memory-first-surfacing.log` + Langfuse span |
| **Деградация** | per-adapter `SourceError`, частичный результат | fail-soft везде (`except: pass`), TEI-down → lexical-only |

**Почему два пути, а не один:** хук не может позволить себе импорт оркестратора и async-машинерию адаптеров на каждый промпт — его контракт это <3 s в свежем процессе. Цена — дублирование RRF-логики (`rrf_merge` в хуке ≠ `RRFMerger` в оркестраторе) и собственный механизм консистентности (epoch вместо живого чтения).

## Epoch — мост консистентности между путями

`unified_search` всегда видит актуальное состояние store'ов. Хук — нет: его кеш на 300 s заморозил бы паттерн, заархивированный или дискредитированный mid-TTL. Решение — [epoch.py](../../../src/memory/vector_memory/epoch.py): каждый мутатор confidence/archive зовёт `bump()` → атомарная запись `repr(time.time())` в `.claude/cache/confidence-epoch.txt`; хук читает `read()` (локальный файл, **без Qdrant-roundtrip**, fail-soft → 0.0) и вшивает значение в cache-key → мутация = другой ключ = instant miss = recompute. Timestamp вместо счётчика — race-tolerant (last-writer-wins, ключ всё равно меняется). При недоступном файле система деградирует к legacy TTL-only поведению.

## Контракт read → cascade: чтение — участник петли обратной связи

Чтение в этой системе **не read-only**. Surfacing-путь регистрирует, *что именно* было показано модели:

```text
search_qdrant → pids = [(id, score) for hits из learned_patterns]
             → shared.pattern_reinforce.record_surfaced(session_id, pids)
             → (Stop-hook) reinforce_session → apply → §22 confidence ↑/↓ → epoch.bump()
             → следующий read видит пере-ранжирование   ⟲
```

Ключевые свойства контракта (из кода `execute()`):
- `record_surfaced` вызывается **и на cache-hit** (replay сохранённых `pids` из envelope) — иначе кешированные показы не учитывались бы в reinforcement;
- считаются только хиты с `_collection == "learned_patterns"` — skill'ы и `.md` в петле не участвуют;
- вызов fail-soft: его падение не ломает inject, но **молча размыкает петлю** — confidence «замерзает» на prior 0.70 (именно так выглядел import-collision `shared.pattern_reinforce`, починен 2026-06-05, см. [[feedback-hook-src-shared-collision]] и [27.12 §10.2](27.12_Memory_Systems_Map.md)).

`unified_search` в этой петле НЕ участвует (нет аналога `record_surfaced` в `search()`) — reinforcement по явному пути идёт только через явный `apply_pattern`. Полная механика петли и cascade — [27.12 §10.2](27.12_Memory_Systems_Map.md), математика §22 — [27.9](27.9_Confidence_Lifecycle.md)/[27.11](27.11_Pattern_Lifecycle.md).

## Типичные сбои и диагностика

Первый инструмент — `.claude/cache/memory-first-surfacing.log` (JSONL, по записи на инвокацию, ротация 2 MB tail-keep; opt-out `MEMORY_SURFACE_LOG_DISABLE=1`). Поля: `cache` (hit/miss), `tei` (ok/down/no_embedding) + `tei_error`, `arms` (hit-counts по 3 плечам), `gate` `{archived, below_floor, passed}`, `layers`, `rrf_fused`, `rerank`, `reinforced_pids`, `duration_ms`, `outcome` (`injected` / `injected-cached` / `no-results` / `cached-empty`).

| Симптом | Лог-сигнатура | Причина / действие |
|---|---|---|
| Surfacing «отупел», только точные совпадения | `"tei":"down"`, `arms.skill=0`, `arms.pattern_dense=0`, `pattern_lexical>0` | TEI-контейнер `pdf-rag-tei` лежит → dense-плечи пусты, работает lexical-only. Поднять Docker; классический корень — `ModuleNotFoundError: shared.semantic_search` из-за `insert(0)` вместо `append` ([[feedback-hook-src-shared-collision]]), смотреть `tei_error` |
| Всплывает заархивированный/протухший паттерн | `"cache":"hit"` при свежей мутации | Epoch не бампнулся: мутатор без `bump()`, либо мутация ушла через **stale MCP-процесс** (server.py-код до `/mcp reconnect` — [[feedback-mcp-stale-code-reconnect]]). Проверить mtime `confidence-epoch.txt`; форс — удалить `memory-first-surfacing-cache.json` или `MEMORY_SURFACE_CACHE_DISABLE=1` |
| Паттерны есть, но ничего не инжектится | `outcome:"no-results"`, `gate.below_floor`/`gate.archived` высокие, `gate.passed=0` | Gate отбросил всё: confidence просел < 0.15 (decay) или массовый archive. Проверить `eff` через `list_patterns`; временная диагностика `MEMORY_INCLUDE_ARCHIVED=1`; пороги мог сдвинуть §25-тюнинг — смотреть `data/memory/surfacing_tuning.json` (удалить файл = defaults) |
| Инъекция «исчезает» при exit 0 | лог пишется, stdout пуст у потребителя | cp1251-pipe + кириллица: только `_emit_stdout` (UTF-8 bytes), не `print()` ([[feedback-windows-hook-stdout-cp1251]]) |
| Хук «молчит» на повторных промптах | `skipped-cooldown` (Langfuse) / отсутствие записи | Нормально: cooldown 30 s, skip коротких/`/`-промптов |
| `unified_search` отдаёт частичный результат | `memory-read.log`: `sources_failed:["..."]`, `error:"timeout"`/`"hard_timeout"` | Адаптер упал/просрочил 5 s — движок продолжает на остальных; hard_timeout 7.5 s = подозрение на event-loop starvation MCP-процесса |
| `rerank` никогда не `applied` | `"rerank":"skipped_no_budget"` | `MEMORY_RERANK=1` без поднятия hook-timeout ≥10 s в settings.json — cold Ollama не влезает в 5 s hard-kill (есть one-shot stderr warning) |

Сквозная сверка одного паттерна по всем sink'ам: `python scripts/memory_observability_query.py --view fact-trace --key <pattern_id>` (§27, см. [27.12 §10.1](27.12_Memory_Systems_Map.md)).
