# 27.12.7 Блок «ПОТОКИ» — write / read / cascade / migrate по шагам

> Пошаговая трассировка четырёх сквозных потоков мастер-схемы Unified Memory System через код: каждый шаг = «вызов → файл:функция → константы → лог-sink». Уровень — «инженер дебажит поток с открытым кодом». **Взаимосвязь потоков (3 рельса + петля обратной связи) — в [27.12 §10.2](27.12_Memory_Systems_Map.md); здесь — только внутренность каждого потока.** Все факты — из кода `src/memory/`, хуков и `scripts/`.

```text
  ПОТОКИ:
   write : вход → Router.classify → 1..3 store'а → cross-link(0.7) → event
   read  : query → adapters(parallel) → normalize → RRF(k=60) → dedup → rerank → link-enrich
   cascade: apply → Propagation(BFS, time×dist decay) → confidence соседей
   migrate: memory-ai → learned_patterns(light) → normalize(full) → wiki(promoter)
```

## 1. WRITE — `route_and_save` по шагам

Код: [memory_orchestrator.py](../../../src/memory/orchestrator/memory_orchestrator.py) (`route_and_save`, `_save_to_target`, `_emit_event`, `_audit`) + [memory_router.py](../../../src/memory/orchestrator/memory_router.py).

| # | Шаг | Код | Константы | Sink |
|---|---|---|---|---|
| 1 | Вход | MCP `route_and_save(content, metadata)` → `MemoryOrchestrator.route_and_save()` | — | — |
| 2 | Truncate | `MemoryRouter._validate_content` | `max_content_length=10000` → срез до `truncate_length=2000` | — |
| 3 | Phase 0: auto-classify | `ContentClassifier.classify` (regex-сигналы FACT/PREFERENCE/RULE/SKILL/CODE) | каждый match `+0.3`, `metadata_hint` `+1.0`, `confidence = min(score/3.0, 1.0)`; **гейт `>=0.6`** → 1 target по `CONTENT_TYPE_TARGETS` | — |
| 4 | Phase 1: rule-based | `_phase1_rule_classification` | `EXPLICIT_KEYWORDS`→conf `1.0`, `INTENT_PATTERNS`→`0.95`, code-block regex→`vector-memory 0.85`, config-regex→`0.7` | — |
| 5 | Phase 2: keyword scoring | `_phase2_keyword_scoring` | `score = match_count/len(keywords) × weight` (patterns `1.5`, facts `1.2`, skills `1.3`) | — |
| 6 | Phase 3: выбор targets | `_phase3_select_targets` | пороги **0.80 → 1 / 0.50 → 2 / 0.30 → 3** store'а; нет сигналов → fallback `memory-ai` conf 0.3 | — |
| 7 | Трейс решения | `route_and_save` → `write_trace("memory-routing.log","route",…)` | targets/method/confidences; opt-out `MEMORY_ROUTING_LOG_DISABLE=1` | `.claude/cache/memory-routing.log` |
| 8 | Запись в store'ы | `_save_to_target(target, content, metadata)` per target | `entity_id = uuid4()` | см. ниже |
| 9 | Cross-links | `link_registry.create_link(…, LinkType.SESSION_CONTEXT, strength=0.7)` цепочкой `i→i+1`, только если `saved_entities > 1` и `enable_link_creation` | strength **0.7** | `data/link_registry.db` |
| 10 | Событие | `_emit_event("memory.save", {targets, entity_count})` → `EventBus.publish` + `EventStore.append` (fire-and-forget) | source=`orchestrator` | `data/events.jsonl` (hot) + `data/events.db` (cold) |
| 11 | Аудит | `_audit(AuditAction.CREATE, "memory", …)` — fail-soft, буферизуется, flush на `stop()` | metadata-only | `data/services/audit.jsonl` |

**Шаг 8 в разрезе store'ов (`_save_to_target`):**

- `memory-ai` → `INSERT INTO important_messages` в `data/memory_ai.db` (defaults: `importance=0.7`, `category="general"`).
- `vector-memory` → `_get_embedding(content)` ([vector_memory/server.py](../../../src/memory/vector_memory/server.py)) → `client.upsert("learned_patterns", PointStruct(id=entity_id, …))`; payload defaults: `confidence=0.7`, `decay_rate=0.05`, `application_count=0`, `version=1`.
- `skill-learning` → append-строка в `data/skill_learning/patterns.jsonl`.
- `wiki` → `MemoryCube(content_type=WIKI).to_wiki_page()` → `docs/wiki/drafts/<slug>.md`.

**⚠ Расхождения кода с ожиданиями:**
1. `_save_to_target` — `except Exception → return None`: упавший target **молча выпадает** из `saved_entities`, а ответ всё равно `{"success": true}`. Диагноз: route в `memory-routing.log` есть, а `saved_entities` пуст.
2. Этот путь даёт `id = uuid4()` и **не проставляет `content_hash`** в payload — в отличие от harvester-пути (§10.1: `pattern_id = UUID5(content_hash)`, sink `memory-ingestion.log`). Записи `route_and_save` невидимы для cross-store-дедупа §26 (см. поток migrate, `build_index` дропает пустые хэши).

**Жив ли поток:** `tail -3 .claude/cache/memory-routing.log` (есть свежие `"event":"route"`), затем `memory_event_history(event_type="memory.save")` через MCP `memory-orchestrator`, и `python scripts/memory_observability_query.py --view recent`.

## 2. READ — `unified_search` по шагам

Код: [unified_search.py](../../../src/memory/orchestrator/unified_search.py) (`UnifiedSearchEngine.search`) + адаптеры в [memory_orchestrator.py](../../../src/memory/orchestrator/memory_orchestrator.py).

1. **Вход** — MCP `unified_search(query, include/exclude, min_score=0.3, limit=20)` → фильтрация адаптеров по `SourceServer`.
2. **Parallel dispatch** — `asyncio.create_task(wait_for(adapter.search(...), timeout_ms/1000))`; default `timeout_ms=5000`. Поверх — **hard ceiling** `asyncio.timeout(timeout_ms×1.5)` = 7.5 s (защита от деградации wait_for в долгоживущей MCP-сессии); упавшие/просроченные адаптеры → `sources_failed[]` (`timeout` / `hard_timeout` / текст исключения), поток продолжает на выживших.
3. **Адаптеры** (каждый инкапсулирует свой store):
   - `AiMemorySearchAdapter` — SQLite: токены `len>=3`, OR-`LIKE` по `content`+`tags`, fetch `max(limit×3, 30)`, Python-rerank `0.5·match_ratio + 0.5·importance`.
   - `VectorMemorySearchAdapter` — `_get_embedding(query)` → `client.query_points("learned_patterns", filter confidence>=0.3)`; `raw_score = similarity × pattern.confidence`. Любая ошибка → `logger.warning` + пустой список (fail-soft).
   - `SkillLearningSearchAdapter` — `patterns.jsonl`, keyword-overlap `|q∩doc| / |q|`.
4. **Фильтр по `memory_types`** — per-source, до fusion.
5. **RRF** — `RRFMerger.fuse` при `rrf_enabled=True` (default): per-source rank по `raw_score` desc, `rrf = weight/(k + rank + 1)` с **k=60**; нормализация на `max_rrf`; затем бленд `final_score = 0.6·base_rrf + 0.4·boost`, где boost = `ScoreNormalizer` (clamp [0,1], `×1.2` если <24 h, `×1.1` если <7 d, `×1.15` если `raw_score>0.8`, cap 1.0).
6. **min_score** — отсев `final_score < 0.3`.
7. **Dedup** — `Deduplicator`: ключ `md5(content.strip().lower())`; дубль не выбрасывается бесследно — его источник дописывается в `duplicate_sources` победителя.
8. **Rerank diversity** — `Reranker`: максимум **3 результата одного источника** в топе (ослабляется после позиции 10).
9. **Link-enrich** — `LinkEnricher.enrich`: `link_registry.get_all_links(uid, min_strength=0.5)` → `linked_entities[]` (outgoing+incoming); per-item fail-soft warning.
10. **Trace** — `write_trace("memory-read.log","search", query_len, arm_hits, sources_failed, final, latency_ms)`; текст запроса **не** логируется; opt-out `MEMORY_READ_LOG_DISABLE=1`.

**Второй путь чтения** — surfacing `memory-first-hook` (мимо оркестратора, см. [27.12 §5](27.12_Memory_Systems_Map.md) и [27.12.4](27.12.4_Блок_Выход_Чтение.md)). Для этой главы важен его единственный контракт с другими потоками: на inject он вызывает `record_surfaced()` — мост `read → cascade` (см. ниже, шаг C1).

**Жив ли поток:** `tail -3 .claude/cache/memory-read.log` — поле `arm_hits` показывает, какое плечо пустое; `sources_failed != []` = адаптер деградировал. Срезы: `python scripts/memory_observability_query.py --view by-source` и `--view latency`.

## 3. CASCADE — apply → confidence соседей

Каскад в коде — **два контура** (важно не перепутать при отладке):

### 3.1 Автономный контур (production): surfaced → reinforce → cascade-on-apply

| # | Шаг | Код | Константы | Sink |
|---|---|---|---|---|
| C1 | Фиксация surfaced | `memory-first-hook.py` → `record_surfaced(session_id, [(pid, score)])` ([pattern_reinforce.py](../../../.claude/hooks/shared/pattern_reinforce.py)) | max-score per pid, atomic write | `.claude/cache/surfaced-patterns-<sid>.json` |
| C2 | Stop-хук | **`pattern-reinforce-stop.py`** (выделен из session-memory-save 2026-06-09, roadmap 260609 P0.1 — старое место за early-return'ами дедупа не срабатывало НИКОГДА) → `_detect_success()` (commit ≤8h **или** completed_task) → `reinforce_session(sid, success, cap=REINFORCE_CAP)` | opt-out `P1_REINFORCE_DISABLE=1`; timeout 15s async; cap **10** (`REINFORCE_CAP`); idempotency per-session; `SCORE_THRESHOLD=0.3`, cooldown **6 h**/pattern, sentinel FIFO 500 | `.claude/cache/p1-reinforcement-state.json`; событие `session` → `confidence-lifecycle.log` |
| C3 | Мутация Beta | `reinforce_pattern(pid, success)` ([reinforce.py](../../../src/memory/vector_memory/reinforce.py)): `retrieve` → `apply_to_payload` (математика §22 в `confidence.py`) → `set_payload` | Qdrant `127.0.0.1:6333`, timeout 2 s | событие `reinforce` (old/new confidence, succ/fail) → `.claude/cache/confidence-lifecycle.log` |
| C4 | Инвалидация read-кэша | `epoch.bump()` ([epoch.py](../../../src/memory/vector_memory/epoch.py)) — атомарная запись `time.time()` | fail-soft; хук читает через `epoch.read()` в cache-key | `.claude/cache/confidence-epoch.txt` |
| C5 | Каскад на соседей | MCP `apply_pattern` → `handle_apply_pattern` ([server.py](../../../src/memory/vector_memory/server.py)) → после собственного apply зовёт `_cascade_confidence` | см. ниже | `apply` → `confidence-lifecycle.log`; `propagate` → `memory-propagation.log` |

`_cascade_confidence` (синхронный, depth-1, same-store): gate `MEMORY_APPLY_CASCADE_DISABLE=1` → `LinkRegistry().get_links_from(pattern_id, [SUPPORTS, EXTENDS, BASED_ON, DERIVES_FROM])` (CONTRADICTS исключён — инверсная семантика) → для каждого соседа `delta = 1.0 × link.strength × 0.5 × max(0.5, 1 − days/365)`; отсев `delta < 0.001`; rate-limit `_APPLY_CASCADE_MAX=10`; нудж `succ/fail` (при отсутствии — `seed_counts_from_legacy`) → `derive_confidence` → `set_payload` → `bump()` если кого-то обновили. **No-op пока в `link_registry` нет реальных pattern↔pattern связей** (сегодня — тест-фикстуры; реальные рёбра появляются из reflect/`DERIVES_FROM`, cross-link write, `MIRRORS`/`PROMOTED_TO` миграции).

### 3.2 Оркестраторный контур: `propagate_update` → PropagationEngine

Код: [propagation_engine.py](../../../src/memory/orchestrator/propagation_engine.py).

1. MCP `propagate_update(entity_id, delta=0.1, success)` → lazy-init `PropagationEngine(link_registry, update_handlers=_build_propagation_handlers())` + `start()` (2 background-воркера, очередь 1000). `success` сворачивается в знак: `base_delta = ±|delta|` (boost/penalty).
2. `propagate()` → `PropagationEvent(uuid4)`; дедуп по `entity_id` (`_recent_events`, очистка при >1000); при включённом background событие уходит в очередь, а caller сразу получает `reason="queued_for_background_processing"` (результат — асинхронно, смотреть лог).
3. `_process_propagation` — BFS `deque` от entity: `max_depth=3`, на каждом ребре `get_links_from`; фильтр `_can_receive_propagation` — только `RECEIVER_TYPES = {(vector-memory, semantic), (memory-ai, episodic)}`, `STATIC_TYPES` не трогаются.
4. `_calculate_delta`: `base × strength × time_decay(max(0.5, 1 − days/365)) × dist_decay(max(0.3, 0.5^depth))`; отсев `< min_delta_threshold=0.001`; rate-limit `max_entities_per_event=10`.
5. `_apply_update` — через `update_handlers[source]`. **⚠ Расхождение с интуицией из §6/§10.2:** оркестратор создаёт движок **без** `update_handlers` → ветка «No handler — simulate success»: BFS/decay/лог реальны, но confidence в этом контуре фактически **не мутируется**. Реальная мутация соседей сегодня — только server-side `_cascade_confidence` (3.1/C5).
6. Защита — `CircuitBreaker("propagation_engine", failure_threshold=5, reset_timeout=60s)`: OPEN → `reason="circuit_breaker_open"`.
7. Sink — `write_trace("memory-propagation.log","propagate", source, entities_updated, cascades_prevented, final_depth, latency_ms)` + `_audit(PROPAGATE)`.

**Жив ли поток:** `tail -5 .claude/cache/confidence-lifecycle.log` (чередование `reinforce`/`apply`/`session`), `tail -3 .claude/cache/memory-propagation.log`, `cat .claude/cache/confidence-epoch.txt` (timestamp бампается после каждого apply). Полный тред одного факта: `python scripts/memory_observability_query.py --view fact-trace --key <pattern_id>`.

## 4. MIGRATE — консолидация по cadence

Оркестратор cadence — [memory_maintenance.py](../../../scripts/memory_maintenance.py): **dry-run по умолчанию**, `--apply` пробрасывается sub-job'ам, `--skip job1,job2` — opt-out; каждый job fail-soft (rc=-1 в дашборде вместо аборта). Последовательность:

| # | Job | Код | Гейты/константы | Выход |
|---|---|---|---|---|
| M1 | `reflect` (episodic→semantic) | subprocess [reflect_memory.py](../../../scripts/reflect_memory.py) → `shared/reflection.reflect()` | кластеры из `memory_ai.db`: Jaccard `--sim 0.5`, `--min-cluster 3` (или `--theta` по сумме importance), `--cap 10`/run; дедуп по `content_hash` | upsert в `learned_patterns` + рёбра **`DERIVES_FROM`** на эпизоды-источники (link_fn только при `--apply`) |
| M2 | `sync` (cross-store dedup) | subprocess `scripts/cross_store_sync.py --no-report`; ядро: [cross_store_index.py](../../../src/memory/orchestrator/cross_store_index.py) + [cross_store_sync.py](../../../src/memory/orchestrator/cross_store_sync.py) | `build_index` по `content_hash` (`sha256[:16]`, пустые дропаются) → `find_cross_store_dups` (≥2 store'а) → `choose_canonical` через `ConflictResolver(SOURCE_PRIORITY)`: **wiki > learned_patterns > skill_learning > memory_ai** | рёбра **`MIRRORS`** (`mirror → canonical`) в `link_registry` (идемпотентно, аддитивно) + conflict-audit отчёт |
| M3 | `promote` (semantic→wiki) | subprocess `-m scripts.export_graph_to_wiki promote-patterns` → [wiki_promoter.py](../../../src/memory/librarian/wiki_promoter.py) `scan_and_promote()`; **apply-only** (в dry-run пропускается) | scroll-фильтр `confidence>=0.8 AND application_count>=5`; пост-гейт `payload_effective_confidence>=0.8` (lazy-decay); skip `expired_at` (архив); дедуп `similarity>=0.85` против уже промоченных | `MemoryCube.to_wiki_page()` → `docs/wiki/drafts/<slug>.md` + append `docs/wiki/log.md`; ребро **`PROMOTED_TO`**; событие `wiki.draft.created` |
| M4 | `forget` (inline) | `run_forget`: `plan_forget(points, now)` → при `--apply` `set_payload({"expired_at": now})` per-point | критерии §22 P3 (eff<0.40 / idle) | `log_event("forget", source="memory_maintenance")` → `confidence-lifecycle.log` + `epoch.bump()` |
| M5 | Dashboard | `build_dashboard`/`render_dashboard` (`memory.maintenance.dashboard`) | store sizes, `cross_store_dup_rate`, ingest/dup rates из `memory-ingestion.log`, forget summary, link stats | `data/reports/memory/memory_maintenance_*.md` |

**Schema-нормализация light-записей** — отдельный одноразовый инструмент [normalize_light_patterns.py](../../../scripts/normalize_light_patterns.py) (не в cadence): LIGHT-shape (`original_id` есть, `pattern_id` нет — наследие исторической миграции memory-ai→Qdrant) переписывается в full `LearnedPattern`: `pattern_type` по `CATEGORY_MAP` (8 категорий; `session_summary` и прочие непаттерны — SKIP), `confidence ← importance`, честный seed `succ/fail = (0,0)` (синтетика — только явный `--seed-importance N`), provenance в metadata, vector без изменений. Dry-run default; vector-inclusive backup в `data/memory/backups/` (restore — `dedupe_learned_patterns.py --restore`).

**⚠ Уточнение к строке мастер-схемы** `memory-ai → learned_patterns(light) → normalize(full) → wiki(promoter)`: «light → normalize» — это **исторический one-shot** (хвост старой миграции); действующий регулярный канал episodic→semantic — `reflect` (M1, сразу full-schema + `DERIVES_FROM`). Остальная цепочка (→ wiki через promoter) — действующая, по cadence.

**Жив ли поток:** `python scripts/memory_maintenance.py` (dry-run печатает план каждого job) → свежий `data/reports/memory/memory_maintenance_*.md`; рёбра миграции: `sqlite3 data/link_registry.db "SELECT link_type, COUNT(*) FROM entity_links GROUP BY link_type"` (ждём `derives_from`/`mirrors`/`promoted_to`); промоты: `ls docs/wiki/drafts/` + `tail docs/wiki/log.md`.

## 5. Точки разрыва потоков

| Поток | Где рвётся | Почему (из кода) | Как видно |
|---|---|---|---|
| write | `_save_to_target` | fail-soft `return None`: упавший store молча выпадает, ответ всё равно `success:true` | route есть в `memory-routing.log`, но `saved_entities` короче `targets`; `memory-ingestion.log` молчит |
| write | дедуп-инфраструктура | путь `route_and_save` не проставляет `content_hash` → записи невидимы для M2-sync | строки без `content_hash` в payload; `build_index` их дропает |
| read | адаптер vector-memory | TEI/Qdrant down → `except → []` (warning), плечо пустое; таймаут 5 s / hard 7.5 s | `sources_failed` в ответе и в `memory-read.log`; `arm_hits["vector-memory"]=0` |
| cascade | мост `record_surfaced → reinforce_session` | исторически рвался дважды: import-collision `shared.*` (починено 2026-06-05) и **позиция вызова за early-return'ами `already_saved` + 5s-бюджет session-memory-save** (за всю историю 0 production-reinforce; вынесено в отдельный хук `pattern-reinforce-stop.py` 2026-06-09, roadmap 260609 P0.1) | нет файлов `surfaced-patterns-*.json`; в `confidence-lifecycle.log` нет `reinforce`/`session` при живом surfacing |
| cascade | stale MCP-код | `_cascade_confidence` живёт в vector-memory **MCP-сервере** — правки требуют `/mcp reconnect` ([[feedback-mcp-stale-code-reconnect]]) | в ответе `apply_pattern` нет поля `cascaded` |
| cascade | пустой граф / no handlers | C5 — no-op без pattern↔pattern рёбер; контур 3.2 — «simulate success» без `update_handlers` | `memory-propagation.log`: `entities_updated=0`; circuit OPEN → `memory_circuit_status` |
| migrate | dry-run default | без `--apply` ничего не пишется; `promote` вообще apply-only; `.venv/Scripts/python.exe` обязателен ([[feedback-venv-python-windows]]) | в отчёте `dry-run (no links written)`; job tail `skipped (apply-only)` / `python.exe missing` |

Сквозная проверка всех мостов разом — `--view fact-trace` (один `pattern_id`/`content_hash` через все sink'и) и сводка `python scripts/memory_observability_report.py`.
