# 27.12 Карта систем памяти и потоки данных (глубокий разбор + схемы)

> Полная архитектурная карта Unified Memory System: **оркестратор + 4 подсистемы-хранилища +
> курируемый `.md`-слой + хуки**, и как данные **пишутся, читаются, связываются, мигрируют и
> затухают** между ними. Зум-аут к «большой картине» поверх per-подсистемных глав
> ([27.2 Оркестратор](27.2_Оркестратор.md), [27.5 Поиск](27.5_Поиск_и_сервисы.md),
> [27.11 Pattern Lifecycle](27.11_Pattern_Lifecycle.md)). Все факты — из кода `src/memory/`.

---

## 1. Большая картина — кто есть кто

Память — это **НЕ одно хранилище**, а федерация из нескольких независимых store'ов, объединённых оркестратором на уровне записи/поиска/связей. Плюс отдельный курируемый `.md`-слой и хуки, которые всё это «всплывают».

```mermaid
flowchart TB
  subgraph CLIENT["Точки входа"]
    HOOK["memory-first-hook (UserPromptSubmit)<br/>auto-surfacing"]
    STOP["session-memory-save (Stop)<br/>auto-save сессии"]
    MCP["MCP-инструменты (4 сервера, 52+ tools)"]
  end

  subgraph ORCH["Memory Orchestrator (orchestrator/, SQLite link_registry.db)"]
    ROUTER["MemoryRouter<br/>classify → route"]
    SEARCH["UnifiedSearchEngine<br/>federated + RRF"]
    LINKS["LinkRegistry<br/>граф связей"]
    PROP["PropagationEngine<br/>каскад доверия"]
    MEMCUBE["MemCube<br/>единый контейнер"]
  end

  subgraph STORES["Подсистемы-хранилища"]
    AI["memory-ai (EPISODIC)<br/>SQLite data/memory_ai.db<br/>important_messages"]
    VEC["vector-memory (SEMANTIC)<br/>Qdrant learned_patterns 4096d<br/>= ПАТТЕРНЫ"]
    SKILL["skill-learning (LEARNING)<br/>JSONL data/skill_learning/<br/>pending/saved/rejected"]
    DOCS["pdf-docs (DOCUMENTATION)<br/>Qdrant framework collections"]
  end

  subgraph CURATED["Курируемый слой (НЕ через оркестратор)"]
    MD["MEMORY.md + memory/*.md<br/>файлы, ручная запись"]
  end

  HOOK --> SEARCH
  HOOK -.-> MD
  HOOK -.-> AI
  HOOK -.-> VEC
  STOP --> AI
  MCP --> ROUTER
  MCP --> SEARCH
  ROUTER --> AI & VEC & SKILL
  SEARCH --> AI & VEC & SKILL & DOCS
  ROUTER --> LINKS
  SEARCH --> LINKS
  PROP --> VEC & AI
  MEMCUBE -.конвертация.-> AI & VEC & SKILL & MD
```

**Ключевой принцип:** подсистемы **не знают друг о друге** — координацию (роутинг, federated-поиск, связи, каскад) делает оркестратор. Курируемый `.md`-слой живёт **в стороне** (его читает только `memory-first-hook`, не оркестратор).

## 2. Хранилища — физическая карта (где что лежит)

| Подсистема | MemoryType | Backend | Физический путь | Что хранит | `.md`? |
|---|---|---|---|---|---|
| **memory-ai** | `episodic` | SQLite | `data/memory_ai.db` (таблица `important_messages`) | сообщения/факты сессий + importance | ❌ |
| **vector-memory** | `semantic` | Qdrant | `localhost:6333`, коллекция `learned_patterns` (4096d cosine) | **паттерны** (LearnedPattern) | ❌ (поле `content`) |
| **skill-learning** | `learning` | JSONL | `data/skill_learning/` (`pending/saved/rejected_patterns.jsonl`) | паттерны навыков на подтверждение | ❌ |
| **pdf-docs** | `docs` | Qdrant | framework-коллекции | документация (RAG) | ❌ |
| **Link Registry** | — | SQLite | `data/link_registry.db` (`entity_links`/`link_history`/`link_stats`) | связи между сущностями | ❌ |
| **Event Store** | — | JSONL+SQLite | `data/events.jsonl` (hot) + `data/events.db` (cold) | события шины | ❌ |
| **Курируемая память** | — | файлы | `~/.claude/projects/<...>/memory/*.md` + `MEMORY.md` | ручные заметки/feedback | ✅ **да** |

> Подытог по частому вопросу: **паттерн (`learned_patterns`) — это запись в Qdrant, НЕ `.md`.** `.md` есть только у курируемого слоя — это **отдельная система**.

## 3. UnifiedID — общий «адрес» сущности

```mermaid
flowchart LR
  ID["{memory_type} : {source} : {identifier}"]
  ID --> EX["episodic:memory-ai:550e8400-...<br/>semantic:vector-memory:660f...<br/>learning:skill-learning:770g...<br/>docs:pdf-docs:a1b2c3..."]
  REG["IDRegistry<br/>_unified_to_original / _original_to_unified / _metadata<br/>register / resolve / get_or_create"]
  ID --> REG
```

- **MemoryType (6):** `episodic` · `semantic` · `learning` · `docs` · `wiki` · `graph`.
- **SourceServer (7):** `memory-ai` · `vector-memory` · `skill-learning` · `pdf-docs` · `orchestrator` · `obsidian-vault` · `lightrag`.
- `identifier` валидируется regex `^[a-zA-Z0-9_:\-]+$`. `IDRegistry` хранит двунаправленный маппинг unified↔original (источниковый id паттерна/сообщения) + метаданные.

## 4. WRITE — как данные ПОПАДАЮТ в память

```mermaid
flowchart TD
  IN["route_and_save(content, metadata)"] --> CLS["ContentClassifier (regex)<br/>→ ClassificationResult (confidence, signals)"]
  CLS --> RULE["MemoryRouter:<br/>0) auto-classify (≥0.60)<br/>1) EXPLICIT_KEYWORDS / INTENT_PATTERNS<br/>2) keyword scoring (TF-IDF-like)<br/>3) target selection по порогам"]
  RULE --> TGT{"confidence → targets"}
  TGT -->|"≥0.80"| ONE["1 target"]
  TGT -->|"≥0.50"| TWO["2 targets"]
  TGT -->|"≥0.30"| THREE["3 targets"]
  ONE --> SAVE["_save_to_target() в каждую подсистему"]
  TWO --> SAVE
  THREE --> SAVE
  SAVE --> XL["cross-links: SESSION_CONTEXT, strength 0.7<br/>между сохранёнными сущностями"]
  XL --> EV["emit event memory.save → EventBus/EventStore"]
```

**ContentType (7):** `FACT` · `PREFERENCE` · `RULE` · `SKILL` · `CODE` · `OBSERVATION` · `WIKI`.
**CATEGORY_TARGETS** маппит категорию → подсистему(ы). Уверенность определяет, в **сколько** хранилищ уйдёт запись (1/2/3). Прямые пути записи (минуя роутер): `save_pattern` (→ Qdrant), `save_important_message` (→ SQLite), `capture_pattern` (→ JSONL), Stop-хук `session-memory-save` (→ SQLite + `docs/wiki/log.md`).

## 5. READ — federated search (как данные ЧИТАЮТСЯ обратно)

```mermaid
flowchart TD
  Q["unified_search(query, sources, options)"] --> DISP["параллельный dispatch адаптеров (timeout×1.5)"]
  DISP --> A1["AiMemoryAdapter<br/>SQLite token-OR LIKE<br/>rerank 0.5·match + 0.5·importance"]
  DISP --> A2["VectorMemoryAdapter<br/>Qdrant semantic (cosine) + min_confidence"]
  DISP --> A3["SkillLearningAdapter<br/>JSONL keyword-overlap"]
  A1 --> NORM["ScoreNormalizer<br/>boosts: 24h ×1.2 · week ×1.1 · high-conf ×1.15"]
  A2 --> NORM
  A3 --> NORM
  NORM --> RRF["RRFMerger (k=60)<br/>score = Σ weight/(k+rank)<br/>blend 60% RRF + 40% quality"]
  RRF --> DD["Deduplicator (MD5 content-hash)"]
  DD --> RR["Reranker (diversity: ≤3 на источник в топе)"]
  RR --> LE["LinkEnricher → get_all_links() → linked_entities"]
  LE --> OUT["UnifiedSearchResult[] (final_score, duplicate_sources, linked_entities)"]
```

**Адаптеры — паттерн «один интерфейс на подсистему»:** оркестратор не лезет в БД напрямую, каждый `BaseSearchAdapter` инкапсулирует свой store. Это позволяет добавлять/убирать подсистемы без изменения движка.

> Второй путь чтения — **surfacing** (`memory-first-hook`, §3.4 [27.11](27.11_Pattern_Lifecycle.md)): свой облегчённый RRF (k=60, плечи skill/exp/conv/pattern_dense/pattern_lexical) + confidence-gating + execution-cache. Он бьёт по store'ам напрямую (не через оркестратор) ради hot-path-латентности (<3s).

## 6. Граф связей и каскад доверия

```mermaid
flowchart TD
  subgraph LR2["LinkRegistry (data/link_registry.db)"]
    EL["EntityLink: source_id → target_id<br/>link_type · strength(0-1) · bidirectional · expires_at"]
    TBL["таблицы: entity_links · link_history · link_stats"]
  end
  GR["get_related (BFS)<br/>max_depth=2 · min_strength=0.5 · direction both/in/out<br/>effective_strength = strength × 0.9^(depth-1)"]
  EL --> GR
  subgraph PE["PropagationEngine — каскад при apply"]
    direction TB
    EV2["PropagationEvent (entity, base_delta, success)"] --> CALC["delta = base·link_strength<br/>× time_decay max(0.5, 1−days/365)<br/>× dist_decay max(0.3, 0.5^depth)"]
    CALC --> APPLY["обновить confidence соседей<br/>(receiver: vector-memory, memory-ai)<br/>STATIC (docs/conv) — не трогаются"]
  end
  GR -.граф для каскада.-> PE
```

**LinkType (10):** `based_on` · `supports` · `contradicts` · `extends` · `derives_from` · `session_context` · `promoted_to` · `superseded_by` · `mirrors` · `graph_node`.
Каскад ограничен: `max_depth=3`, `max_entities_per_event=10`, `min_delta_threshold=0.001`, дедуп событий + Circuit Breaker (защита от лавины). Связь со страхом самовозбуждения — двойной decay (время + расстояние).

## 7. MemCube — единый контейнер (мост между форматами)

```mermaid
flowchart LR
  CUBE["MemCube<br/>cube_id · content · content_type · memory_type · source<br/>confidence · importance · tags · metadata<br/>engram: what/why/where/learned<br/>created/updated/expires · version"]
  CUBE --> R1["to_ai_memory_row() → SQLite"]
  CUBE --> R2["to_vector_memory_payload() → Qdrant"]
  CUBE --> R3["to_skill_learning_record() → JSONL"]
  CUBE --> R4["to_wiki_page() ↔ from_wiki_page()<br/>Markdown + YAML frontmatter"]
```

MemCube — это «эсперанто» памяти: одна сущность, которую можно сериализовать в формат любой подсистемы (или в wiki-`.md` с секциями `## What/Why/Where/Learned`). Через него идёт миграция между store'ами. `touch()` бампает версию + timestamp; `is_expired()` — TTL.

## 8. Governance — жизненный цикл и защита (P4-сервисы)

```mermaid
flowchart TB
  subgraph GOV["Сервисы управления (infrastructure/ + */services/)"]
    TTL["TTL Service<br/>never/short1h/med24h/long7d/ext30d<br/>cleanup background"]
    VER["Versioning<br/>history (versions.jsonl) · rollback · diff"]
    FG["ForgetGate<br/>strategies: confidence_decay/access/surprise/composite<br/>actions: ARCHIVE/DECAY/DELETE/KEEP"]
    CB["CircuitBreaker<br/>CLOSED→OPEN→HALF_OPEN<br/>fail_threshold 5 · reset 60s"]
    AUD["Audit (audit.jsonl)<br/>create/read/update/delete/search/link/propagate/..."]
    MET["Metrics (counters/gauges/durations)"]
    BUS["EventBus + EventStore<br/>hot events.jsonl + cold events.db<br/>pub/sub + replay"]
  end
  FG -.->|ARCHIVE| VECNOTE["vector-memory: expired_at (§22 P3)"]
  CB -.guards.-> PROPNOTE["PropagationEngine (анти-лавина)"]
```

§22 confidence-lifecycle ([27.9](27.9_Confidence_Lifecycle.md)) — это *частный* случай governance, встроенный прямо в vector-memory (Beta-posterior, decay-on-read, forget/revive). ForgetGate — более общий механизм с 4 стратегиями и 4 действиями.

## 9. Миграция и связь с курируемым `.md`-слоем

```mermaid
flowchart LR
  AI2["memory-ai (SQLite)<br/>session_summary, preferences, ..."] -->|"мигрировано как LIGHT-записи"| VEC2["vector-memory<br/>learned_patterns (original_id schema)"]
  VEC2 -->|"normalize_light_patterns.py"| VEC3["full LearnedPattern (pattern_id schema)"]
  VEC2 -->|"WikiPromoter (§L5)"| WIKI["docs/wiki/*.md (export_graph_to_wiki)"]
  STOP2["session-memory-save (Stop)"] --> AI2
  STOP2 --> LOG["docs/wiki/log.md"]
  MAN["вручную (человек)"] --> MD2["MEMORY.md + memory/*.md<br/>(курируемый слой — НЕ авто)"]
  MD2 -.читается.-> HOOK2["memory-first-hook (layer 'md')"]
```

**Три разных «памяти» — не путать:**
1. **vector-memory `learned_patterns`** (Qdrant) — авто-выученные паттерны, §22 confidence.
2. **Курируемая `MEMORY.md` + `memory/*.md`** (файлы) — **ручной** слой, пишется человеком/подтверждением; авто-захват только в *черновики* `data/memory_drafts/`.
3. **memory-ai** (SQLite) — эпизодические сессии (авто, Stop-хук).
Данные **перетекают** (memory-ai → learned_patterns light → normalize → full; learned_patterns → wiki через WikiPromoter), но системы остаются разными.
