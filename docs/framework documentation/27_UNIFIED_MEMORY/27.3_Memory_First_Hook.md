# 27.3 Memory-First Hook — автоконтекст памяти

## Проблема

MCP-серверы памяти (memory-ai, vector-memory, skill-learning) — это инструменты, которые Claude вызывает **по своему решению**. Нет гарантии, что перед ответом он проверит память проекта. Результат: повторные объяснения, потеря контекста, игнорирование ранее принятых решений.

## Решение

Фаза **P0.5** добавляет `UserPromptSubmit` hook, который перехватывает каждый промпт пользователя и автоматически ищет релевантные записи в памяти **до** начала ответа. Найденный контекст печатается в `stdout` (Claude Code инжектирует plain-text stdout UserPromptSubmit-хуков в контекст модели), и Claude получает его до генерации.

> **Fix 2026-04-05:** раньше использовался `systemMessage` — это *user-facing warning*, Claude его не видит. Реальная reach rate была ~55%. После перехода на `print(stdout)` — 100%. См. [архитектурный кеш](.claude/skills/architecture-research/cache/userpromptsubmit-hook-output-formats.md).

**Эволюция:**
- **P0.5 (2026-04-04):** single-layer `.md` поиск с Russian stemming
- **P5.2 (2026-04-05):** 3-layer federated recall (SQLite + Qdrant + `.md`) с RRF merge
- **P5.2 v3 (2026-04-09):** Layer 2 → semantic search (Ollama nomic-embed-text 768d + 3 Qdrant коллекции). IPv4 fix. Companion hook `session-context-enforcer.py`

**Файл:** [`.claude/hooks/memory-first-hook.py`](.claude/hooks/memory-first-hook.py)
**Событие:** `UserPromptSubmit`
**Тесты:** 41 PASS (`scripts/claude-backend/tests/test_memory_first_hook.py`)

## Архитектура (P5.2 — 3-layer federated)

```
User prompt (stdin JSON)
        |
        v
+-------+------------------+
| Skip checks              |
|  - prompt length < 20    |
|  - starts with '/'       |
|  - single-word query     |
|  - cooldown active (30s) |
+-------+------------------+
        | (pass)
        v
+-------+------------------+
| Tokenize + Russian stem  |
|  (query_tokens)          |
+-------+------------------+
        |
        v (deadline = now + 4.0s)
+-------+-----------+-----------+----------+
|                   |           |          |
v                   v           v          v
search_sqlite   search_qdrant search_md    (skipped if over deadline)
 (weight 0.35)   (weight 0.40) (weight 0.25)
 200ms budget    3500ms budget 500ms budget
 top-200 by      SEMANTIC:      glob *.md
 importance      embed(Ollama)  name×3/desc×2/body×1
                 →query 3 colls
                 fallback:token
        |           |           |
        v           v           v
+-------+-----------+-----------+
| rrf_merge (k=60, dedup sha1)  |
|   score += w × 1/(k+rank)     |
+-------+-----------------------+
        |
        v
+-------+----------------+
| Format stdout text     |
|  top-5 (MAX_RESULTS)   |
|  with source labels    |
+-------+----------------+
        |
        v
Claude receives prompt + [MEMORY CONTEXT]
```

### Layer details

| Layer | Источник | Weight | Timeout | Опционально |
|---|---|---|---|---|
| **Layer 1** | SQLite `important_messages` (top-200 by importance, token overlap + tag boost) | 0.35 | 200ms | Всегда работает |
| **Layer 2** | Qdrant **semantic search** (Ollama nomic-embed-text 768d → query 3 коллекций). Fallback: token overlap на `learned_patterns` | 0.40 | 3500ms | По умолчанию ON. Отключить: `MEMORY_HOOK_NO_SEMANTIC=1` |
| **Layer 3** | `.md` файлы из `CLAUDE_MEMORY_DIR` (weighted name×3/desc×2/body×1) | 0.25 | 500ms | Всегда работает |

**Layer 2 коллекции (v3):**

| Коллекция | Точек | Dims | Что содержит |
|---|---|---|---|
| `skill_library` | 75 | 768d | Skills: name, description, triggers |
| `experience_embeddings` | 61 | 768d | Experiences: task_type, tool_preference, reason |
| `conversation_memory` | 372 | 768d | Session history: content_preview, role |

**Deadline enforcement:** каждый вызов layer обёрнут в `time.monotonic() < deadline` — если общий budget 4.0s исчерпан, оставшиеся layers возвращают пустой список.

## Алгоритм scoring

### Layer 3 (.md) — весовая модель токенов

| Поле `.md` | Вес | Обоснование |
|---|---|---|
| `name` (YAML frontmatter `name`) | ×3 | Самый сильный сигнал |
| `description` (YAML frontmatter `description`) | ×2 | Краткая характеристика |
| body (содержимое файла) | ×1 | Дополнительный контекст |

Формула layer-score (.md):

```
score = 0.7 × query_coverage + 0.3 × memory_density
threshold = 0.3
```

### Layer 1 (SQLite) и Layer 2 (Qdrant) — token overlap

```
score = |overlap| / |query_tokens|
+ 0.2 если какой-то query_token присутствует в tags (SQLite)
threshold = 0.3
```

### RRF merge (Reciprocal Rank Fusion)

```
fused_score(item) = Σ_layer [ weight_layer × 1 / (k + rank_layer) ]   k=60

дедуп: sha1(content[:200])[:16] — если hash совпадает, RRF scores суммируются
```

Результаты сортируются по `fused_score DESC`, возвращаются top-5 (`MAX_RESULTS`).

### Логика

1. Токенизация промпта (lowercase, split по не-буквенным символам)
2. Стемминг каждого токена кириллицы (см. Russian Stemming ниже)
3. Для каждой памяти: токенизация + стемминг полей name/description/body
4. Подсчёт пересечения стеммов с весами по полям
5. Вычисление coverage и density, комбинация в `score`
6. Отсечение по threshold, сортировка по убыванию score
7. Топ-5 печатается в stdout (plain text, Claude Code инжектирует его в контекст)

## Russian Stemming (v1.1)

Лёгкий суффиксный стриппер без морфологии (не pymorphy3 — для скорости). Работает только с кириллицей, минимальная длина стема — 3 символа.

### Таблица правил

29 суффиксов обрабатываются в порядке убывания длины (3-char → 2-char → 1-char):

| Длина | Суффиксы |
|---|---|
| 3-char | ами, ями, ова, ева, его, ого, ему, ому, ыми, ими, ыми |
| 2-char | ам, ям, ом, ем, ей, ий, ый, ой, ая, яя, ое, ие, ые, ую, юю, ов |
| 1-char | а, я, о, е, у, ю, ы, и, ь |

### Примеры

| Словоформа | Стем | Удалённый суффикс |
|---|---|---|
| агенты | агент | -ы |
| агентов | агент | -ов |
| агентам | агент | -ам |
| агентами | агент | -ами |
| документации | документаци | -и |
| документацию | документаци | -ю |
| конфигурации | конфигураци | -и |
| хуков | хук | -ов |
| настройка | настройк | -а |

### Ограничения

- Английские токены не стеммируются (работают хорошо и так)
- Минимальная длина стема — 3 символа (защита от избыточного обрезания)
- Обрабатывается только кириллица
- Без морфологии: "конфигурация" → "конфигураци" (не идеально, но достаточно)
- Транслитерация cyr↔lat не выполняется

## Оптимизации

| Параметр | Значение | Назначение |
|---|---|---|
| Min prompt length | 20 символов | Пропуск приветствий и коротких команд |
| Cooldown | 30 секунд | Файл `cache/memory-first-cooldown.json` |
| Timeout | 5 секунд (budget 4s) | Ollama embed ~2s + Qdrant ~0.1s + imports ~1.2s |
| Score threshold | 0.3 | Отсечение низкорелевантного шума |
| Skip patterns | `/command`, однословные | Служебные запросы |
| Embedding model | nomic-embed-text (768d) | Ollama localhost:11434 |
| Embed timeout | 2.5 секунды | Fallback на token overlap если Ollama недоступен |

### Graceful degradation

При любой ошибке hook возвращает `{"continue": true}` и логирует в `cache/hooks-error.log`. Пользователь не видит сбоев, Claude продолжает работу без контекста памяти.

## Формат stdout (P5.2, fixed 2026-04-05)

При успешном поиске инжектируется блок с **source attribution**:

```
[MEMORY CONTEXT] Top 5 results across 3 source(s):
1. [SQLite|0.012] session_summary: "Session 2026-04-04. Skills: memory-unified. Changed 8 files..."
2. [.md|0.008]    feedback: "Opus=Planner, Z.AI=Coder. Never write code yourself..."
3. [Qdrant|0.007] pattern: "BSL validation pattern with graceful degradation..."
4. [SQLite|0.006] preference: "Qdrant для production вместо ChromaDB..."
5. [.md|0.004]    project: "Unified Memory Migration P0-P5.4 COMPLETE..."

Use this context to inform your response. If memory conflicts with current code, trust current code.
```

Labels: `SQLite` (Layer 1), `Qdrant` (Layer 2), `.md` (Layer 3). Число после `|` — `fused_score` из RRF.

## Эволюция реализации

| Версия | Дата | Архитектура | Зависимости |
|---|---|---|---|
| P0.5 v1 | 2026-04-04 | Single-layer `.md` | Только файловая система |
| P5.2 v2 | 2026-04-05 | 3-layer federated (SQLite + Qdrant token overlap + .md) | SQLite + опционально Qdrant HTTP |
| **P5.2 v3** | **2026-04-09** | **3-layer: SQLite + Qdrant SEMANTIC (3 коллекции) + .md** | **SQLite + Ollama + Qdrant. IPv4 fix** |

Прямой доступ к бэкендам **без MCP** — для скорости и независимости от запущенных серверов:

| Бэкенд | Путь | Способ доступа |
|---|---|---|
| SQLite | `data/memory_ai.db` | `sqlite3.connect()` (timeout 0.5s) |
| Qdrant | `http://127.0.0.1:6333` | `search_qdrant_semantic()` via `shared/semantic_search.py` |
| Ollama | `http://localhost:11434` | `embed_query_ollama()` via `shared/semantic_search.py` |
| `.md` | `~/.claude/projects/D--1--Framework/memory/` | `Path.glob("*.md")` + `parse_frontmatter()` |

> **IPv4 fix (2026-04-09):** Qdrant Docker не слушает IPv6 (`::1`). `localhost` на Windows резолвится в `::1` → timeout 10s. Замена на `127.0.0.1` → **24ms**. Исправлено в `memory-first-hook.py` и `shared/semantic_search.py`.

## Связь с P5.3 / P5.4

- **P5.3 Deferred Qdrant Indexing** ([`scripts/deferred_qdrant_indexing.py`](scripts/deferred_qdrant_indexing.py)) — пакетно embeds записи `important_messages` через E5-large (1024d) и апсертит в `learned_patterns` с детерминированными uuid5 ID. Контролируется флагом `indexed_in_qdrant` в схеме SQLite.
- **P5.4 Migration .md → DB** ([`scripts/migrate_memory_md_to_db.py`](scripts/migrate_memory_md_to_db.py)) — одноразовый idempotent импорт `.md` memory файлов в `important_messages` через SHA-256 `content_hash` в metadata. Importance по типу: feedback=0.8, user=0.7, project=0.6, reference=0.5.

Подробности всех подфаз P5 — [27.8 Session Memory Bridge](27.8_Session_Memory_Bridge.md).
