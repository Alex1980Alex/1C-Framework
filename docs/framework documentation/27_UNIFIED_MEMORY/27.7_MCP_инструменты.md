# 27.7 MCP инструменты

Unified Memory System предоставляет **4 MCP-сервера** с суммарно 52+ инструментами. Все серверы зарегистрированы в [`.mcp.json`](.mcp.json).

| Сервер | Tools | Назначение |
|---|---|---|
| `memory-ai` | 5 | Эпизодические сообщения, факты, категории (SQLite) |
| `vector-memory` | 7 | Семантические паттерны с confidence (Qdrant) |
| `skill-learning` | 7 | Захваченные паттерны навыков (JSONL) |
| `memory-orchestrator` | 33 | Координация, federated search, граф, сервисы |

---

| `delete_message` | `message_id` | Статус удаления |
| `get_categories` | — | Список категорий + статистика (count per category) |

## vector-memory (7 tools)

Семантические паттерны в Qdrant коллекции `learned_patterns` (1024d E5).

| Tool | Аргументы | Возвращает |
|---|---|---|
| `save_pattern` | `pattern`, `confidence`, `metadata`, `tags` | `pattern_id`, статус |
| `search_patterns` | `query`, `confidence_min`, `limit`, `tags` | Массив паттернов с score |
| `apply_pattern` | `pattern_id`, `context`, `success` | Обновлённый `confidence`, счётчик применений |
| `get_pattern` | `pattern_id` | Полное описание паттерна |
| `delete_pattern` | `pattern_id` | Статус удаления |
| `decay_confidence` | `decay_rate`, `older_than_hours` | Количество обновлённых записей |
| `health_check` | — | Статус Qdrant, размер коллекции |

**Confidence system:** 0.0–1.0. Формула: `confidence × exp(-0.05 × days/30)`. Паттерны ниже 0.3 автоудаляются.

**Embedding fallback policy (roadmap 260509 §4.3, 2026-05-16):** все 7 инструментов требуют рабочий embedding provider (`pdf_framework.embeddings.get_embedding_engine`). При init failure `_get_embedding` **raises RuntimeError** по умолчанию — silent hash-based fallback (SHA-512 pseudo-vectors) более не активен, поскольку семантический поиск становился effectively random. Для offline/CI окружений где Qdrant + embedding model недоступны можно явно опт-инить legacy fallback через env `MEMORY_VECTOR_ALLOW_HASH_FALLBACK=1` — каждый embedding-вызов в этом режиме эмитит `[HASH-FALLBACK] ...` WARN log. Production deployments должны оставлять env пустым.

## memory-orchestrator (33 tools)

Центральный сервер, разделён на 4 фазовых группы.

### Core P0 (8 tools)

Базовые операции чтения/записи и навигации по графу.

| Tool | Аргументы | Возвращает |
|---|---|---|
| `unified_search` | `query`, `sources[]`, `limit`, `rrf_enabled` | Federated результаты с RRF scoring |
| `route_and_save` | `content`, `content_type?`, `metadata` | Целевой backend + `record_id` |
| `get_full_context` | `entity_id`, `depth` | Сущность + связи до depth через BFS |
| `create_link` | `source_id`, `target_id`, `relation_type`, `metadata` | `link_id` |
| `get_related` | `entity_id`, `relation_types[]`, `depth` | Массив связанных сущностей |
| `propagate_update` | `entity_id`, `delta`, `max_depth` | Число затронутых записей |
| `get_system_stats` | — | Агрегаты по всем подсистемам |
| `health_check` | — | Статус всех компонентов |

### Realtime P3 (8 tools)

Pub/sub шина для координации агентов.

| Tool | Аргументы | Возвращает |
|---|---|---|
| `memory_subscribe` | `pattern`, `client_id` | `subscription_id` |
| `memory_unsubscribe` | `subscription_id` | Статус отписки |
| `memory_publish` | `event_type`, `payload` | Число получателей |
| `memory_get_events` | `subscription_id`, `limit` | Массив событий |
| `memory_replay` | `event_type`, `from_ts`, `to_ts` | События за период |
| `memory_event_history` | `event_type`, `limit` | История событий |
| `memory_event_stats` | — | bus/store/subscription stats |
| `memory_subscription_health` | — | Heartbeat/list активных подписок |

### Extended P3 (4 tools)

Анализ и операции над памятью.

| Tool | Аргументы | Возвращает |
|---|---|---|
| `memory_research` | `topic`, `analysis_type` (relationships/anomalies/clusters/timeline/summary) | Структурированный отчёт |
| `memory_id_management` | `action` (generate/resolve/conflict/batch), `id_type` | UUIDv7 или результат операции |
| `memory_surprise` | `content`, `threshold` | Novelty score, связанные аномалии |
| `memory_warmup` | `strategy` (frequent/recent/important/pattern) | Статус загрузки в кэш |

| `memory_circuit_status` | — | Состояние CB по подсистемам |

| `memory_ttl_check` | `entity_ids[]` | Оставшиеся TTL |

## Типовые сценарии

### 1. Federated search по всем подсистемам

```python
result = await mcp.call("memory-orchestrator", "unified_search", {
    "query": "настройка circuit breaker",
    "sources": ["ai_memory", "vector_memory", "skill_learning"],
    "limit": 10,
    "rrf_enabled": True
})
# result: агрегированные записи с source_backend и unified score
```

### 2. Сохранить факт с auto-classify

```python
result = await mcp.call("memory-orchestrator", "route_and_save", {
    "content": "Пользователь предпочитает PostgreSQL для production",
    "metadata": {"importance": 0.8, "session_id": "sess_001"}
})
# classifier определит PREFERENCE → маршрутизирует в ai_memory
```

### 3. Откатить версию записи

```python
# 1) история
history = await mcp.call("memory-orchestrator", "memory_version_history", {
    "entity_id": "mem_20260404_001", "limit": 5
})

# 2) diff между версиями 3 и 4
diff = await mcp.call("memory-orchestrator", "memory_version_compare", {
    "entity_id": "mem_20260404_001", "v1": 3, "v2": 4
})

# 3) откат
await mcp.call("memory-orchestrator", "memory_version_rollback", {
    "entity_id": "mem_20260404_001", "version": 3
})
```

### 4. Анализ графа связей

```python
# Контекст с соседями до depth=3
context = await mcp.call("memory-orchestrator", "get_full_context", {
    "entity_id": "skill:bsl-development", "depth": 3
})

# PageRank / communities для всего графа
analysis = await mcp.call("memory-orchestrator", "memory_graph_analyze", {
    "algorithm": "pagerank", "params": {"damping": 0.85, "iterations": 100}
})
```

### 5. Сессионный event replay

```python
# Подписка
sub = await mcp.call("memory-orchestrator", "memory_subscribe", {
    "pattern": "memory.**", "client_id": "agent_1"
})

# Забор накопленных событий
events = await mcp.call("memory-orchestrator", "memory_get_events", {
    "subscription_id": sub["subscription_id"], "limit": 50
})

# Replay за период
history = await mcp.call("memory-orchestrator", "memory_replay", {
    "event_type": "memory.saved",
    "from_ts": "2026-04-01T00:00:00Z",
    "to_ts":   "2026-04-04T23:59:59Z"
})
```
