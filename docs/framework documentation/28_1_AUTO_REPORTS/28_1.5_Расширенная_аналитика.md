# 38.5 Расширенная аналитика (T0-T2)

Доработка [38.1-38.4](28_1.1_Обзор.md) — 9 модулей закрывают аналитический loop:
ловят больше сигналов, ранжируют действия, сохраняют историю аномалий, дают visual representation.

## Что добавлено (2026-05-22)

### Closed analytical loop

[`scripts/analyzers/anomaly_tracker.py`](../../../scripts/analyzers/anomaly_tracker.py) — persistent registry `data/reports/anomalies.jsonl`:

- **Stable fingerprint** через sha1(`subject` + numeric-normalized message). «32 154 dangling» и «5 340 dangling» → одинаковый fingerprint, recurrence_count бампается.
- **Auto-resolution**: anomaly не surfac'нулась в новом ране — статус автоматически становится `resolved`.
- **Chronic detection**: recurrence_count ≥ 3 → попадает в "chronic" список отдельной секции отчёта.
- **GitHub issue auto-create** (opt-in): задать `ANALYZER_GH_REPO=owner/repo`, `gh` CLI должен быть в PATH. Создаётся 1 issue на каждую новую WARN/FAIL анomaly; URL сохраняется в registry.
- **Severity classification** по keyword tokens — FAIL / WARN / INFO.

Закрывает loop: detect → track → resolve / chronic surface → roadmap entry.

### Verdict gauge + auto action items

[`scripts/analyzers/verdict.py`](../../../scripts/analyzers/verdict.py) — rule-based gauge **PASS / WARN / FAIL**:

- Aggregate severity counts → один verdict.
- **Top wins** (≤3): из summary/probes (recall@1≥0.95, dim match, zero errors, full effective rank).
- **Top issues** (≤3): sorted by severity, FAIL first.
- **Action items**: для каждой anomaly подбирается suggested fix с skill/file pointer из `_ACTION_RULES` (12 правил, extensible).

Рендерится в **первой** секции отчёта (insert(0)), сразу под заголовком — для быстрой триажной оценки.

### Extended embedding quality probes

[`scripts/analyzers/indexing.py:_embedding_quality_metrics`](../../../scripts/analyzers/indexing.py):

| Метрика | Что показывает | Anomaly threshold |
|---------|----------------|-------------------|
| L2 norm outliers (>3σ) | broken vectors | count > 0 logged |
| **Effective rank** | sum(σ²)·exp(entropy) — fraction of dimensions actually used | ratio < 30% → anomaly |
| **Anisotropy mean cos** | средняя cos similarity случайных пар vectors | > 0.5 → anomaly (collapsed cone) |

Реальный пример surface'нутый на `framework_code_v1` (MRL 1024d + SQ): **effective rank 19/100 (19%) + anisotropy 0.44 + recall@1 0.90** — три независимых сигнала указывают на degradation MRL truncation. Это новая ценная информация, которая раньше была невидима.

### Chunk-level metrics

[`scripts/analyzers/chunk_metrics.py`](../../../scripts/analyzers/chunk_metrics.py) — на отдельном scroll с `with_payload=True`:

- Char/token length распределение (mean, median, p95, max).
- Lexical diversity (unique tokens / total) — `<0.3` boilerplate, `>0.7` high entropy.
- Empty/near-empty chunks count — > 10% от sample → anomaly.
- **Near-duplicate detection** через shingled jaccard (k=5, threshold ≥0.85), sample 500 pairs из топ-200 chunks.
- Language detection (если установлен `langdetect`).

### ASCII charts

[`scripts/analyzers/charts.py`](../../../scripts/analyzers/charts.py) — pure-stdlib, никаких deps:

- `histogram(values, bins, width)` — горизонтальный bar chart.
- `boxplot(values)` — single-line Q1/median/Q3 representation.
- `waterfall(stages)` — chronological cumulative timing chart.
- `distribution_table(dist, top)` — top-N с % bars.
- `degree_distribution_loglog(degrees)` — log-log bins + naive power-law γ exponent + R² goodness-of-fit.

### Graph topology metrics

[`scripts/analyzers/graph.py:_analyze_neo4j`](../../../scripts/analyzers/graph.py):

- **Power-law γ** на degree distribution из 1000-node sample (`MATCH (n:Symbol) WITH n, rand() ORDER BY r LIMIT 1000`). Healthy scale-free network: γ ∈ [2, 3]. Outside [1.5, 3.5] → anomaly. На текущем BSL call graph: **γ=0.429, R²=0.193 (weak fit)** — НЕ scale-free, центрировано на BSL stdlib hubs.
- **Local clustering coefficient** на 50-node sample: `2T(v) / (deg(v)·(deg(v)-1))`. На текущем графе **0.0240** — star-shaped (hubs доминируют).
- **Modularity proxy**: процент CALLS edges intra-community vs total (если есть Community nodes от Leiden).

### Resource telemetry daemon

[`scripts/_progress.py:_telemetry_loop`](../../../scripts/_progress.py) — opt-in daemon thread:

- Sample RSS / CPU% через `psutil` каждые `max(5s, hb*0.5)`.
- GPU VRAM (best-effort через `nvidia-smi --query-gpu=memory.used`).
- Эмитит `category=telemetry` events в `data/indexing-progress.jsonl`.
- Opt-out: `INDEXING_NO_TELEMETRY=1` (для tests/CI).
- Analyzer aggregates → peak/mean RSS+CPU+GPU в новой секции "Resource telemetry". Peak RSS > 8 GB → anomaly.

### Schema regression test

[`tests/integration/test_analyze_run.py::test_analyzer_indexing_schema_regression`](../../../tests/integration/test_analyze_run.py):

- Snapshot fixed set of required top-level JSON keys (`REQUIRED_INDEXING_KEYS`).
- Snapshot verdict sub-schema.
- Anomalies must be `list[str]`.
- Verdict gauge ∈ {PASS, WARN, FAIL}.
- При добавлении key — он сам добавляется (forward-compat). При удалении — CI fail.

Плюс unit-тесты на `AnomalyTracker` (dedup + auto-resolution + fingerprint stability) и `Verdict` (gauge classification edge cases).

## Output integration

Все добавки автоматически попадают в стандартный `data/reports/{indexing,graph}/<subject>_*.md`:

1. **Verdict** — секция №1 (top of report)
2. **Anomaly history** — секция перед summary (persistent state)
3. **Resource telemetry** — после Heartbeat gaps (если есть psutil events)
4. **Chunk-level metrics** — после Quality probes
5. **Chunk char-length histogram** — ASCII chart inline
6. **Stage timing waterfall** — встроен в Stages & timing
7. **Graph topology** — после Top-15 nodes by degree (только для neo4j source)
8. **Effective rank + Anisotropy** — встроены в Quality probes
