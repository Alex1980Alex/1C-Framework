## Назначение

BSL Semantic Search — MCP-сервер для семантического поиска по исходному коду 1С:Предприятие (BSL). Позволяет Claude Code находить процедуры, функции, объекты метаданных и зависимости по смыслу запроса, а не только по точному совпадению текста.

### Ключевые возможности

- **Семантический поиск** — поиск по смыслу: "контроль остатков при проведении" → находит все модули с этой логикой
- **Полнотекстовый поиск** — поиск по точному вхождению: `ОбработкаПроведения` → точные совпадения
- **Граф зависимостей** — кто вызывает модуль, кого вызывает он, кластеры связанных модулей
- **RRF-fusion метаданных** — поиск объектов по техническому имени, синониму и описанию одновременно
- **6 инструментов** через MCP протокол
- **Автозапуск зависимостей** — Docker, Qdrant, Neo4j, Ollama запускаются автоматически при необходимости
- **Graceful degradation** — 5 режимов работы: от полного до offline

### Место в фреймворке

```
Claude Code
    │
    ├── analyze-1c-task-v2     → использует intelligent_search, analyze_graph
    ├── implement-1c-task      → использует search_bsl_code, analyze_graph
    ├── code-analysis-pipeline → использует intelligent_search (Step 1.0)
    │
    └── bsl-semantic-search (lazy-mcp, on-demand)
            │
            ├── Qdrant (Docker: 1c-qdrant) — векторное хранилище
            ├── Ollama (localhost:11434)    — генерация эмбеддингов
            └── Neo4j (Docker: 1c-neo4j)   — граф зависимостей
```

## Архитектура

### Компоненты

| Компонент | Назначение | Технология |
|-----------|-----------|------------|
| **MCP Server** | Точка входа, JSON-RPC протокол | Python, FastMCP |
| **BSL Search Service** | Координация поиска, кеширование | Python |
| **Qdrant Vector Store** | Хранение и поиск эмбеддингов | Qdrant (Docker) |
| **TEI Embedding Service** (production, Phase 8) | Генерация эмбеддингов | TEI Docker `pdf-rag-tei` + Qwen3-Embedding-8B 4096d. Legacy: Ollama nomic 768d (dropped 2026-04-30) |
| **Ollama LLM Service** (legacy fallback) | Реранкинг через LLM, опционально | Ollama + deepseek-coder 6.7b |
| **Neo4j Graph** | Граф зависимостей между модулями | Neo4j (Docker) |
| **Hybrid Search Engine** | Объединение vector + graph | RRF fusion |
| **Graph Analytics** | Centrality, communities, dependencies | Python + Neo4j |
| **Resilience Layer** | Circuit breakers, auto-recovery | pybreaker + OllamaManager |

### Поток данных

```
Запрос пользователя
    ↓
MCP Server (FastMCP)
    ↓
_ensure_services() → проверка/автозапуск зависимостей
    ↓
BSL Search Service
    ├── mode=semantic  → Ollama (эмбеддинг) → Qdrant (vector search)
    ├── mode=fulltext  → Qdrant (BM25/text search)
    ├── mode=graph     → Neo4j (graph traversal)
    ├── mode=hybrid    → Qdrant + Neo4j → RRF fusion
    └── mode=intelligent → автовыбор стратегии
    ↓
Результаты → кеш (TTL 5 мин) → MCP ответ
```

## Режимы работы (Graceful Degradation)

Сервер автоматически определяет доступные зависимости и выбирает режим:

| Mode | Qdrant | Ollama | Neo4j | Доступные функции |
|------|:------:|:------:|:-----:|------------------|
| `full` | + | + | + | Всё: semantic, fulltext, graph, hybrid, intelligent |
| `semantic` | + | + | - | Semantic + fulltext (нет graph/dependencies) |
| `fulltext+graph` | + | - | + | Fulltext + graph (нет semantic) |
| `fulltext-only` | + | - | - | Только полнотекстовый поиск |
| `offline` | - | ? | ? | Ничего (нет Qdrant = нет индекса) |

### Автодаунгрейд запросов

Если пользователь запрашивает `mode="semantic"`, а Ollama недоступна:

```
Запрос: mode="semantic"
Ollama: DOWN
→ Автодаунгрейд: mode="fulltext" + warning в логах
→ Результат менее точный, но сервер НЕ зависает
```

Аналогично: `mode="graph"` без Neo4j → `mode="fulltext"`, `mode="hybrid"` → `mode="semantic"` или `mode="fulltext"`.
