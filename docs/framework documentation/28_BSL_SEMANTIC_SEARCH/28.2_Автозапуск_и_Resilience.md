# 28.2 Автозапуск и Resilience

> **Версия:** 3.0 | **Дата:** 2026-05-04 | **Тестирование:** 44/44 OK (исторический результат v2.0; после Phase 8 базовый сценарий «TEI недоступен» проверяется отдельным smoke-набором)

---

## Проблема

До v2.0 `bsl-semantic-search` при запуске пытался инициализировать все сервисы (Qdrant, embedder, Neo4j) как один неделимый блок. Если один сервис не отвечал — сервер зависал на таймауте (30-180 секунд) и падал.

**Типичный сценарий (Phase 8):** TEI Docker контейнер `pdf-rag-tei` остановлен → сервер пытается получить эмбеддинг запроса → таймаут HTTP → ошибка → все semantic/hybrid/intelligent инструменты недоступны.

## Решение: 4-уровневая система восстановления

### Уровень 1: Быстрая проверка (TCP/HTTP, 3 сек)

Перед инициализацией каждого сервиса — быстрая проверка доступности:

```python
# TCP check (Qdrant, Neo4j)
socket.connect_ex((host, port))  # timeout=3 сек
# Если порт закрыт → не пытаемся подключиться → нет зависания

# HTTP check (TEI :8080, Ollama :11434)
urllib.request.urlopen(url, timeout=3)
# Если TEI не отвечает → degraded → автодаунгрейд semantic→fulltext
# Если Ollama не отвечает → отключаем только LLM-реранкинг
```

### Уровень 2: Автозапуск Docker

Если Docker-контейнер остановлен:

```
1. _ensure_docker_running()
   ├── docker info → OK? → продолжить
   └── Docker Desktop не запущен:
       └── "C:\Program Files\Docker\Docker\Docker Desktop.exe"
           → ждать до 60 сек пока daemon ready
           → docker info каждую секунду

2. _start_docker_container(service)
   ├── docker inspect → status?
   │   ├── "running" или "restarting" → OK
   │   ├── "exited" / "created" / "paused" → docker start
   │   └── not found → пропустить
   └── Пробует имена:
       ├── Qdrant: 1c-qdrant, qdrant, pdf_framework-qdrant-1
       ├── TEI:    pdf-rag-tei, tei
       └── Neo4j:  1c-neo4j, neo4j, pdf-rag-neo4j
```

### Уровень 3: Автозапуск Ollama (опционально, для LLM-реранкинга)

Эта ветка активна только когда включён LLM rerank — для эмбеддингов Ollama более не нужна (Phase 8 → TEI).

```
_start_ollama()
├── Попытка 1: OllamaManager.api_restart()
│   └── Уровни восстановления менеджера:
│       ├── Soft: перезагрузка модели
│       ├── API: перезапуск сервера
│       └── Full: полный перезапуск приложения
│
└── Попытка 2: Прямой запуск ollama.exe serve
    ├── %LOCALAPPDATA%\Programs\Ollama\ollama.exe
    └── C:\Program Files\Ollama\ollama.exe
```

### Уровень 4: Периодическое восстановление

```
Каждые 60 секунд → _try_recover_services()
├── Для каждого degraded сервиса:
│   ├── TCP/HTTP check → если UP:
│   │   ├── Реинициализировать сервис
│   │   ├── Пересобрать composite сервисы (Hybrid, Graph)
│   │   └── Убрать из degraded
│   └── Если DOWN → оставить в degraded, попробовать через 60 сек
```

## Полный алгоритм запуска

```
BSL Semantic Search → _ensure_services()
│
├─ 1. Qdrant: TCP check (localhost:6333, 3s)
│   ├─ UP → init QdrantVectorStore → OK
│   └─ DOWN:
│       ├─ _ensure_docker_running() → запуск Docker Desktop если нужно
│       ├─ _start_docker_container("qdrant") → docker start 1c-qdrant
│       ├─ wait max 15 sec
│       ├─ TCP check → UP → init → OK
│       └─ TCP check → DOWN → mode="offline"
│
├─ 2. TEI: HTTP check (localhost:8080/health, 3s)
│   ├─ UP → init FrameworkTEIEmbedder → OK
│   └─ DOWN:
│       ├─ _start_docker_container("pdf-rag-tei") → docker start
│       ├─ wait max 30 sec (модель Qwen3-8B грузится в GPU дольше Qdrant)
│       ├─ HTTP check → UP → init → OK
│       └─ HTTP check → DOWN → degraded (semantic/hybrid → fulltext)
│
├─ 2b. Ollama (опц., только если включён LLM rerank): HTTP check :11434
│   ├─ UP → init LLM Service → OK
│   └─ DOWN → отключить LLM rerank, остальное работает
│
├─ 3. Neo4j: TCP check (localhost:7687, 3s)
│   ├─ UP → init Neo4jService → OK
│   └─ DOWN:
│       ├─ _ensure_docker_running() → уже запущен
│       ├─ _start_docker_container("neo4j") → docker start 1c-neo4j
│       ├─ wait max 15 sec
│       ├─ TCP check → UP → init → OK
│       └─ TCP check → DOWN → degraded (нет graph)
│
├─ 4. Composite сервисы:
│   ├─ Qdrant + Neo4j → HybridSearchEngine + GraphAnalytics
│   ├─ Qdrant (любой) → BSLSearchService
│   └─ LLM + Search → ContextManager
│
└─ 5. Каждые 60s → _try_recover_services()
```

## Docker-контейнеры

### Имена контейнеров

| Сервис | Основное имя | Fallback имена |
|--------|-------------|----------------|
| Qdrant | `1c-qdrant` | `qdrant`, `pdf_framework-qdrant-1` |
| Neo4j | `1c-neo4j` | `neo4j`, `pdf-rag-neo4j` |

### Порты

| Контейнер | Порт | Протокол | Health check |
|-----------|------|----------|-------------|
| `1c-qdrant` | 6333 | HTTP REST | `GET /healthz` |
| `1c-qdrant` | 6334 | gRPC | — |
| `1c-neo4j` | 7687 | Bolt (основной) | TCP connect |
| `1c-neo4j` | 7474 | HTTP (browser) | `GET /` |

**Важно:** Neo4j Bolt (7687) готов раньше HTTP (7474). Сервер подключается через Bolt. HTTP-порт используется только для браузерного доступа.

### Docker Desktop

Путь: `C:\Program Files\Docker\Docker\Docker Desktop.exe`

Автозапуск: если `docker info` не отвечает → запуск Docker Desktop → ожидание до 60 сек → `docker info` каждую секунду.

## Circuit Breaker

Реализован в `resilience/circuit_breakers.py` (pybreaker):

| Breaker | Max failures | Reset timeout | Что защищает |
|---------|:-----------:|:-------------:|-------------|
| Ollama | 5 | 60 сек | Эмбеддинги, реранкинг |
| Qdrant | 3 | 30 сек | Vector search |

**Состояния:**
- `CLOSED` — работает нормально
- `OPEN` — сервис упал, запросы блокируются мгновенно (fail-fast)
- `HALF-OPEN` — проверка: один запрос проходит, если OK → CLOSED

**Structured logging при переходах:**
```json
{"event": "circuit_breaker_opened", "breaker_name": "ollama", "fail_count": 5}
{"event": "circuit_breaker_closed", "breaker_name": "ollama"}
```

## OllamaManager

Реализован в `resilience/ollama_manager.py`:

| Уровень | Действие | Когда |
|---------|---------|-------|
| **Soft** | Перезагрузка модели | Модель не отвечает, API работает |
| **API** | `ollama pull model` | API работает, модель потеряна |
| **Full** | `ollama.exe serve` | Ollama не запущена |

Автоматический поиск ollama.exe:
1. `where ollama` (PATH)
2. `%LOCALAPPDATA%\Programs\Ollama\ollama.exe`
3. `C:\Program Files\Ollama\ollama.exe`
