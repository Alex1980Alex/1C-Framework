## 1. bsl_search — базовый поиск (бывший `search_bsl_code`)

Основной инструмент поиска по индексированному BSL коду.

### Параметры

| Параметр | Тип | Default | Обязательный | Описание |
|----------|-----|---------|:------------:|----------|
| `query` | string | — | да | Поисковый запрос (русский/английский) |
| `limit` | number | 10 | нет | Максимум результатов (max 50) |
| `mode` | string | "semantic" | нет | Режим поиска |
| `module_types` | array | null | нет | Фильтр по типам модулей |

### Режимы поиска (mode)

| Mode | Что делает | Зависимости | Когда использовать |
|------|-----------|-------------|-------------------|
| `semantic` | Qwen3 query-эмбеддинг (с `is_query=True`) → vector similarity в `bsl_code_v4_late` | Qdrant + TEI | Поиск по смыслу: "контроль остатков" |
| `fulltext` | BM25 / текстовый поиск | Qdrant | Точное вхождение: `ОбработкаПроведения` |
| `graph` | Обход графа зависимостей | Qdrant + Neo4j | Кто вызывает модуль, связи |
| `hybrid` | Vector + Graph → RRF fusion | Qdrant + TEI + Neo4j | Максимальный охват |
| `intelligent` | Автоматический выбор стратегии | Все | Когда не знаешь какой mode нужен |

### Пример

```json
{
  "query": "ОбработкаПроведения регистр накопления движения",
  "limit": 5,
  "mode": "semantic",
  "module_types": ["ObjectModule"]
}
```

### Автодаунгрейд

- `mode="semantic"` без TEI → автоматически `mode="fulltext"`
- `mode="graph"` без Neo4j → автоматически `mode="fulltext"`
- `mode="hybrid"` без TEI/Neo4j → `mode="semantic"` или `mode="fulltext"`

### Пример вывода (после fix 2026-05-04)

```
### Результат 1 (релевантность: 0.515)
**Файл**: C:\1С-Framework\...\src\Documents\гкс_ЛабораторныйАнализ\Ext\ObjectModule.bsl
**Тип модуля**: ObjectModule
**Источник**: semantic
**Описание**:
// Object: Document.гкс_ЛабораторныйАнализ
Процедура СформироватьНаправленияНаРазгрузкуДляРазблокированныхТС(...)
...
```

До 2026-05-04 поле `**Файл**` было пустым: код читал устаревшие ключи payload `file_path`/`searchable_text`, а Phase 8 индексер пишет `module_path`/`content`. Фикс — [`src/bsl/semantic_search/services/search.py:316`](../../../src/bsl/semantic_search/services/search.py).

## 2. bsl_hybrid_search / bsl_context — многомерный поиск (бывший `intelligent_search`)

Расширенный поиск с учётом контекста задачи. Автоматически выбирает стратегию (vector + BM25 + graph через RRF fusion).

### Параметры

| Параметр | Тип | Default | Обязательный | Описание |
|----------|-----|---------|:------------:|----------|
| `query` | string | — | да | Поисковый запрос |
| `context_type` | string | "code_search" | нет | Тип контекста задачи |
| `limit` | number | 10 | нет | Максимум результатов |

### Типы контекста (context_type)

| context_type | Стратегия | Когда использовать |
|-------------|-----------|-------------------|
| `code_search` | Прямой поиск по имени/паттерну | Найти конкретную функцию |
| `code_understanding` | Глубокий анализ: как работает, зачем | Понять алгоритм |
| `debugging` | Поиск причины ошибки | Где может ломаться |
| `documentation` | Поиск по документации | Найти описание API |
| `examples` | Примеры аналогичных реализаций | Как делали похожее |
| `refactoring` | Дублирование, кандидаты на рефакторинг | Оптимизация кода |

### Пример

```json
{
  "query": "контроль остатков при проведении реализации товаров",
  "context_type": "code_understanding",
  "limit": 10
}
```

## 3. bsl_call_graph / bsl_impact_analysis / bsl_dead_code — анализ графа зависимостей (бывший `analyze_graph`)

Анализ связей между модулями через Neo4j: входящие/исходящие вызовы, влияние изменений (impact), мёртвый код.

### Параметры

| Параметр | Тип | Default | Обязательный | Описание |
|----------|-----|---------|:------------:|----------|
| `file_path` | string | null | нет | Путь к файлу (null = весь проект) |
| `analysis_type` | string | "dependencies" | нет | Тип анализа |

### Типы анализа

| analysis_type | Что показывает | Применение |
|--------------|---------------|-----------|
| `dependencies` | Кто вызывает модуль + кого вызывает он | Побочные эффекты изменений |
| `centrality` | Самые связанные модули (узлы риска) | Оценка рисков рефакторинга |
| `communities` | Кластеры связанных модулей | Выявление подсистем |
| `full` | Всё вместе | Полный обзор архитектуры |

### Пример

```json
{
  "file_path": "src/Documents/гкс_Взвешивание/Ext/ObjectModule.bsl",
  "analysis_type": "dependencies"
}
```

**Требует Neo4j.** Если Neo4j недоступен → ответ `{"status": "degraded", "message": "Neo4j unavailable"}`.

## 4. bsl_object_info — семантический поиск по метаданным (бывший `search_metadata_rrf`)

Поиск объектов метаданных конфигурации с мультивекторным ранжированием (Reciprocal Rank Fusion).

### Параметры

| Параметр | Тип | Default | Обязательный | Описание |
|----------|-----|---------|:------------:|----------|
| `query` | string | — | да | Поисковый запрос |
| `limit` | number | 10 | нет | Максимум результатов |

### Как работает RRF

Для каждого объекта метаданных строятся 3 вектора:
1. **object_name** — техническое имя (например `гкс_Взвешивание`)
2. **friendly_name** — синоним (например `Взвешивание`)
3. **description** — описание и контекст

Результаты трёх поисков объединяются через Reciprocal Rank Fusion:

```
RRF_score(object) = Σ 1 / (k + rank_i)
```

### Когда использовать вместо `bsl_search`

- Ищете **объект метаданных** (справочник, документ, регистр), а не код
- Знаете **русское название** но не знаете техническое имя
- Нужен **fuzzy-поиск** по метаданным (опечатки, синонимы)

### Пример

```json
{
  "query": "контрагент организация договор поставки",
  "limit": 10
}
```

## 5. bsl_stats — статистика индекса

Возвращает состояние BSL Qdrant-индекса: имя коллекции, количество точек, размерность, embedder URL.

### Пример ответа (после fix 2026-05-04)

```
## Статистика BSL индекса (Qdrant)

**Коллекция**: bsl_code_v4_late
**Векторная размерность**: 4096
**Модель embeddings**: qwen3-embedding

**Количество точек**: 54752
**Статус**: green

**Qdrant**: localhost:6333
**Embedder**: TEI (FrameworkTEIEmbedder) http://localhost:8080
```

До 2026-05-04 строка `Embedder` показывала legacy-текст про Ollama, хотя реально вызовы шли через TEI HTTP. Фикс — [`src/bsl/semantic_search/mcp.py:398`](../../../src/bsl/semantic_search/mcp.py).
