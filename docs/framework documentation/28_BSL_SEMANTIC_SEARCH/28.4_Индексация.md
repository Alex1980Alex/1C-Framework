## 1. Архитектура pipeline

BSL Semantic Search опирается на **3 параллельных артефакта**, каждый строится отдельным скриптом:

| Артефакт | Скрипт | Время | Что хранит |
|----------|--------|-------|------------|
| **Semantic chunks** | [`scripts/reindex_bsl_qwen3.py`](../../../scripts/reindex_bsl_qwen3.py) | 30-60 мин | Qdrant `bsl_code_v4_late` — 4096d векторы процедур/функций |
| **Call graph (SQLite)** | [`scripts/build_call_graph.py`](../../../scripts/build_call_graph.py) | ~20 сек | `cache/bsl_call_graph.db` — symbols + calls + modules |
| **Property graph (Neo4j)** | [`scripts/load_graph_to_neo4j.py`](../../../scripts/load_graph_to_neo4j.py) | ~12 сек | Neo4j bolt:7687 — Module/Symbol/Object + CALLS edges |
| **Graph embeddings** | [`scripts/build_graph_embeddings.py`](../../../scripts/build_graph_embeddings.py) | 60-90 мин | Qdrant `graph_embeddings` — vector view графа |

Зависимость артефактов:
```
build_call_graph → cache/bsl_call_graph.db
                    │
                    ├─→ load_graph_to_neo4j → Neo4j
                    └─→ build_graph_embeddings → Qdrant graph_embeddings

reindex_bsl_qwen3 (читает bsl_call_graph.db для context-enrichment payload)
                    └─→ Qdrant bsl_code_v4_late
```

**Полный flow для нового проекта**:
1. `build_call_graph.py --project <root> --clear`
2. `load_graph_to_neo4j.py`
3. `reindex_bsl_qwen3.py --project <root> --embedder qwen3-tei --batch-size 32`
4. `build_graph_embeddings.py --embedder qwen3-tei --batch-size 32 --recreate`

Stop event после завершения → [`post-indexing-analyzer`](../../../.claude/hooks/post-indexing-analyzer.py) хук автоматически генерит отчёты в `data/reports/`. См. [28_1 Auto-Reports](../28_1_AUTO_REPORTS/28_1.1_Обзор.md).

## 2. Payload schema (Phase 8, актуально 2026-05-22)

### `bsl_code_v4_late` (production)

| Поле | Содержимое | Источник |
|------|-----------|----------|
| `module_path` | Полный путь к BSL-файлу | парсер `BSLChunker` |
| `module_name`, `module_type` | `CommonModule` / `ObjectModule` / `FormModule` / `ManagerModule` / `RecordSetModule` | парсер |
| `content` | Текст процедуры/функции + контекст | chunker + `BSLContextEnricher` |
| `chunk_id` | Stable UUID5 от (`module_path`, `name`, `line_start`) | `_to_qdrant_id` |
| `name` | Имя процедуры/функции | парсер |
| `chunk_type` | `function` / `procedure` / `region` / `module_header` | chunker |
| `symbol_type` | `Function` / `Procedure` / `Variable` | `BSLSymbol` |
| `is_export` | `true` если объявление с `Экспорт` | парсер |
| `params` | Список параметров | парсер |
| `calls` | Список вызываемых символов (из call_graph join) | `BSLContextEnricher` |
| `signature` | Полная сигнатура объявления | парсер |
| `region` | Имя `Область` (если внутри `#Область ...`) | парсер |
| `line_start`, `line_end` | Диапазон строк в файле | парсер |
| `object_type`, `object_name` | Например `Document`, `РасходнаяНакладная` | `module_metadata` |
| `caller_count` | Кто-сколько раз вызывает этот символ (из graph) | `BSLContextEnricher` |

**Важно после Phase 8 (2026-05-01)**: поля переименованы с `file_path` → `module_path` и `searchable_text` → `content`. Bug-fix 2026-05-04 в [`src/bsl/semantic_search/services/search.py`](../../../src/bsl/semantic_search/services/search.py) приводит читателей в соответствие.

### `graph_embeddings` (production)

| Поле | Содержимое |
|------|-----------|
| `id` | UUID5 от `kind` + ключ |
| `kind` | `Module` / `Symbol` / `Object` |
| `name` | Имя сущности |
| `module_path` | Для Symbol — путь, для Object — empty |
| `module_type`, `object_type`, `object_name`, `subsystem` | Метаданные |
| `is_export` | Symbol only |
| `symbol_type` | Symbol only — Function/Procedure/Variable |
| `text` | Композитный текст для эмбеддинга («Symbol: имя \| Export \| in Object.X \| params=…») |

## 3. Backend choice — реальность 2026-05-22

### Decision flowchart

```
Что делаешь?
├── Изменил 1-N .bsl файлов (commit/PR)
│   → INCREMENTAL: reindex_bsl_qwen3.py --paths <files> --embedder qwen3-tei --batch-size 32
│     TEI остаётся up; ~секунды; auto-detect project root через walk
│     до configuration/<X>/. Auto-trigger через git post-commit hook
│     (если `git config core.hooksPath scripts/git_hooks`).
│
├── Full project reindex (новый проект / breaking change)
│   → reindex_bsl_qwen3.py --project <root> --embedder qwen3-tei --batch-size 32 [--recreate]
│     TEI остаётся up; ~30-60 мин на 2000+ файлов;
│     `--recreate` дропает ВСЮ коллекцию всех проектов!
│
└── Build graph artefacts (после reindex или standalone)
    ├── build_call_graph.py --project <root> --clear  (~20 сек)
    ├── load_graph_to_neo4j.py  (~12 сек)
    └── build_graph_embeddings.py --embedder qwen3-tei --batch-size 32 --recreate  (~60-90 мин)
```

### qwen3-tei vs qwen3-st — реальный статус

| Backend | Статус 2026-05-22 | Use case |
|---------|-------------------|----------|
| **`qwen3-tei`** (TEI HTTP) | ✅ Production-stable | **ВСЕ операции** — incremental + full + graph_embeddings |
| `qwen3-st` (sentence-transformers local) | ❌ Segfault на model_load (exit 139) | Документировано в memory как Phase 5 default, **на практике не работает** в текущем env |
| `e5` (legacy multilingual-e5-large) | DEPRECATED 2026-04-30 | Не использовать |

**История изменений**:
- 2026-04-30: Phase 8.12 — Qwen3 production switchover (Late Chunking variant)
- 2026-05-20: Phase 5 alias swap — `bsl_code_v4_late` → physical `bsl_code_v4_late_v2` (std pooling + FA2, +30pp recall vs Late)
- 2026-05-22: qwen3-st сегфолтит на текущем env — workaround = qwen3-tei (HTTP backend стабилен, использует Docker `pdf-rag-tei`)

## 5. Build graph pipeline — детально

### 5.1 Call graph (SQLite)

`scripts/build_call_graph.py --project <root> --clear`:

```
Parse BSL files (BSLASTParser + BSLChunker)
  → CallGraphStore (SQLite cache/bsl_call_graph.db)
  → 3 таблицы:
     - module_metadata (path, module_type, subsystem, object_type, object_name)
     - symbols (id, name, type, module_path, is_export, params, doc_comment)
     - calls (caller_id, callee_name, call_type)
```

Last full build (этот сессии):
- 2082 files / 33 783 symbols / 80 013 calls / 0 errors / 20 сек

### 5.2 Neo4j load

`scripts/load_graph_to_neo4j.py`:

```
Read cache/bsl_call_graph.db
  → 4 batched UNWIND queries:
     1. MERGE (m:Module) ... → 2097 Module nodes
     2. MERGE (s:Symbol) ... → 33 970 Symbol nodes
     3. MERGE (o:Object) ... → 833 Object nodes
     4. MATCH ... MERGE (caller)-[:CALLS]->(callee) → 293 835 CALLS edges
  + BELONGS_TO (Symbol → Module), DECLARES (Module → Symbol), CONTAINS (Object → Module)
```

Default credentials: `neo4j` / `bsl-graph-2026` (из `scripts/load_graph_to_neo4j.py:21`). Override через env `NEO4J_URI`/`NEO4J_USER`/`NEO4J_PASSWORD`.

### 5.3 Graph embeddings (Qdrant)

`scripts/build_graph_embeddings.py --embedder qwen3-tei --batch-size 32 --recreate`:

```
Read cache/bsl_call_graph.db
  → Iter Module/Symbol/Object nodes
  → Build composite text per node (e.g. "Function: name | Export | in Document.X | params=...")
  → Embed via TEI HTTP (Qwen3 4096d)
  → Upsert into Qdrant graph_embeddings
```

**2026-05-22 patch**: до этого скрипт жёстко использовал `sentence_transformers.SentenceTransformer("Qwen/Qwen3-Embedding-8B")` локально и сегфолтил на model_load. Добавлен `--embedder qwen3-tei` (commit `2ba493d3b`), переиспользует `Qwen3TEIEmbedder` класс из `reindex_bsl_qwen3.py:769`.

## 6. Context enrichment

`BSLContextEnricher` (читает `bsl_call_graph.db`) обогащает payload каждого chunk'а:

- `calls` — список символов, которые вызывает данная процедура
- `caller_count` — сколько раз эта процедура вызывается (in-degree из graph)

Это даёт +20-30% recall в seman search для запросов вроде «найди всё что вызывает `ОбработкаПроведения`» — поиск идёт по самой логике, плюс boost для часто-вызываемых.

**ВАЖНО**: если `build_call_graph.py` НЕ запущен перед `reindex_bsl_qwen3.py` → `calls` / `caller_count` пустые в payload. Поэтому правильный порядок:

```bash
python scripts/build_call_graph.py --project <root> --clear  # ПЕРЕД
python scripts/reindex_bsl_qwen3.py --project <root> ...     # ПОТОМ
```

Auto-reindex BSL post-commit (`scripts/git_hooks`) делает оба в одном потоке.

## 7. Типичные ошибки (помни!)

1. **`qwen3-tei` для FULL reindex** — раньше считалось анти-паттерном (mixed pooling), сейчас (2026-05-22) единственный стабильный вариант, std pooling вс late chunking больше не различимы после Phase 5 swap.
2. **`qwen3-st` БЕЗ остановки TEI** → CUDA OOM (две копии 8B FP16 = 32GB на 24GB GPU). Сейчас qwen3-st сегфолтит и при остановленном TEI — env issue, обходить через qwen3-tei.
3. **`--enable-fa2` на огромных проектах** — Phase 5 рекомендует FA2, но текущий env сегфолтит и с FA2 и без. Defer до root-cause investigation.
4. **`build_call_graph.py` не запущен ПЕРЕД reindex** → пустой `calls`/`caller_count` в payload → меньше recall.
5. **Matryoshka truncation на BSL** → -12% до -20% recall (Cyrillic identifiers не сжимаются). SQ int8 — да, MRL — нет. Memory `feedback_mrl_content_matters`.
6. **`--recreate` для добавления проекта** → дроп ВСЕЙ коллекции (всех конфигураций). Без `--recreate`, новые chunks доupsert'ятся.
7. **build_graph_embeddings.py БЕЗ `--embedder qwen3-tei`** — default `qwen3-st` сегфолтит. Всегда передавать `--embedder qwen3-tei` пока env не починен.

## 8. Auto-reports после индексации

Stop event Claude Code после любого reindex/graph-build триггерит [`post-indexing-analyzer.py`](../../../.claude/hooks/post-indexing-analyzer.py), который:

1. Читает tail `data/indexing-progress.jsonl`
2. Находит новые `category=run_end` события (через FIFO state dedup)
3. Спавнит [`scripts/analyze_run.py`](../../../scripts/analyze_run.py) detached subprocess для каждого
4. Через 10-30 сек в `data/reports/{indexing,graph}/` появляются deep markdown-отчёты:
   - Quality probes (L2 norm, effective rank, anisotropy, recall@1 SQ-aware)
   - Chunk metrics (length, dedup, lexical diversity)
   - Verdict gauge (PASS/WARN/FAIL) + auto action items
   - Anomaly history (persistent через `anomalies.jsonl`)

**Manual trigger** (графовый mode):
```bash
python scripts/analyze_run.py --mode graph --source sqlite        # call graph SQLite
python scripts/analyze_run.py --mode graph --source neo4j         # Neo4j
python scripts/analyze_run.py --mode graph --source qdrant_graph  # graph_embeddings collection
```

**Полная справка**: [28_1 Auto-Reports](../28_1_AUTO_REPORTS/28_1.1_Обзор.md) (sister chapter — намеренно рядом в TOC для discoverability).

## 12. LLM Reranker integration (v4.1, 2026-05-22)

После investigation цикла (vector-only baseline → hybrid → reranker A/B, 20 queries) — LLM reranker дал единственный **measured positive gain** (+5-10pp top-1 relevance). Integration committed в `_intelligent_search`.

### Архитектура

```
SearchMode.INTELLIGENT (default mode)
  ↓
  hybrid_search(limit=request.limit × 4)  # fetch wider pool
  ↓
  if request.use_llm_reranking and len(results) > 1:
    → _llm_rerank(query, results, top_k=request.limit)
        ↓
        POST http://localhost:11434/api/generate
        model: qwen2.5-coder:7b
        prompt: "Rank N candidates by relevance to query, output comma-separated indices"
        timeout: 15s, temperature: 0.0, num_predict: 100
        ↓
        Parse "3,7,1,5,2,..." → reorder results
        ↓
        Mark each as reranked=True, decay score 1.0/0.99/0.98/...
        Preserve r.original_score = vec_score for audit
  else:
    → results[:top_k]  # vector-only fallback
```

### Graceful fallback chain

| Failure | Behavior |
|---------|----------|
| `use_llm_reranking=False` в request | Vector-only, no rerank call |
| `len(results) <= 1` | Nothing to rerank, return as-is |
| Ollama HTTP timeout/connect error | `logger.warning` + return vector order |
| Empty/malformed LLM response | `logger.warning` + return vector order |
| LLM returns invalid indices | Filter to valid range, append non-ranked at end |

### Evidence (investigation 2026-05-22)

- **20-query semantic search eval**:
  - Vector-only top-1 relevance: **45-65%** (subjective)
  - + LLM rerank top-1 relevance: **50-75%** (+5-10pp)
  - Tight clustering (top-1 vs top-5 spread <0.05): 18/20 queries → reranker breaks ties
- **Latency**: +1.5s per query (acceptable trade-off vs vector-only)
- **Tested alternatives**:
  - Naive RRF hybrid (Vector + Qdrant MatchText): **HURT 7/8 changes** (boolean keyword matching not BM25) — dropped
  - SentenceTransformers cross-encoder (BGE-reranker): **segfault** на local model load (same env issue как qwen3-st)
  - Anthropic Claude `LLMReranker` (existing in framework): requires API key, не использовал
  - **Local Ollama qwen2.5-coder:7b**: stable, 1.5s/query, 0 failures on 20-query A/B → **chosen**

### Configuration

`SearchRequest.use_llm_reranking: bool = True` (default — opt-out, не opt-in).

Чтобы выключить:
```python
req = SearchRequest(query=..., mode=SearchMode.INTELLIGENT, use_llm_reranking=False)
```

Глобальный flag: `BSLSearchSettings.use_llm_reranking` в `src/bsl/semantic_search/config.py:64` (default `True`).

### Зависимости

- **Ollama localhost:11434** — must be running с моделью `qwen2.5-coder:7b`
- Если Ollama down → graceful fallback на vector order, warning в логе

### Что НЕ решено reranker'ом

Reranker фиксит **ranking ambiguity** (anisotropy-induced tied scores), но не лечит:
- **Effective rank 6/200** — embedding collapse remains
- **Anisotropy 0.59** — vectors в узком конусе
- **Score absolute low** (~0.4-0.6) — embedder не "уверен" в matches

Это **system-level** properties BSL embeddings (Cyrillic identifiers + repetitive syntax) — для radical улучшения нужны: A1 chunker tuning, C1 whitening transform, или сменa embedder model. Defer до evidence of pain (current reranker delivers).

### Real fixes на будущее (deferred, см. roadmap)

- **A1**: chunker `MAX_CHARS` 500→2000 — больше context per chunk (speculation, F2 evidence не подтверждает)
- **C1**: whitening transform (Mu & Viswanath 2018) — direct fix anisotropy (~6ч implementation)
- **Native Qdrant BM25 sparse**: enable sparse_vectors_config + reindex (~2ч reindex)
