## Зачем глава

Документирует подсистему **engagement-aware ранжирования** и **on-demand скана экосистемы** —
результат оценки open-source инструмента [`last30days-skill`](https://github.com/mvanhorn/last30days-skill)
(46k★, MIT, Claude Code skill). По [ADR-039](../../../../.claude/skills/architecture-research/adr/039-last30days-skill-adopt-evaluation.md)
полный инструмент **НЕ принят** (доменный промах 1С/RU + дублирование research-механик + секрет-риск
public-репо + платные зависимости), но его **полезное ядро** — ранжирование по реальному engagement,
а не по SEO — извлечено в безопасный переиспользуемый модуль без скрапинга/cookies/платных API.

## Что это (одним абзацем)

Поисковые механики фреймворка (research-скиллы, prework-хуки) исторически ранжировали кандидатов
**только по релевантности** (rapidfuzz/embeddings). «Самый релевантный» ≠ «самый ценный»: репозиторий
с 5 000★ и проект-однодневка с 1★ при одинаковом совпадении названия были неразличимы. Engagement-aware
ранжирование добавляет второй сигнал — **популярность** (stars / upvotes / points) — и сливает его с
релевантностью, поднимая по-настоящему значимые результаты.

## Quick reference

```bash
# V2: on-demand скан «что в экосистеме за N дней» (free public API, без ключей)
python scripts/ecosystem_scan.py "RAG embeddings reranking 2026" --days 30 --top 10
python scripts/ecosystem_scan.py "claude code mcp" --out data/reports/ecosystem/mcp.md
python scripts/ecosystem_scan.py "langgraph" --json     # машинный вывод
```

```python
# Общий приём (V1 и V2): слить релевантность с популярностью
from shared.engagement_rank import rank_items   # из .claude/hooks
ranked = rank_items(items, relevance_key="relevance", engagement_key="engagement")
#         blended = 0.7 * relevance + 0.3 * log-norm(engagement)
```

## Принципы дизайна

1. **Релевантность доминирует** (вес 0.7), популярность — корректирующий вклад (0.3): один «звёздный»
   но нерелевантный элемент не вытесняет точные совпадения.
2. **Free-only**: только публичные API (HN Algolia, StackExchange, GitHub search) — без cookies, скрапинга,
   ScrapeCreators/Perplexity/Brave (отличие от full last30days; согласуется с cost-conscious-политикой).
3. **Stdlib-only ядро**: `engagement_rank` без внешних зависимостей → чистые функции, юнит-тестируемы.
4. **Graceful**: сеть изолирована; источник упал → пропущен, остальные работают; CLI не падает стектрейсом.
5. **Reuse > duplication**: один модуль на обоих потребителей.

## Где применяется

- **V1** — авто-всплытие GitHub best-practices перед задачей (§14 Pre-Work pipeline), теперь
  ранжированное по engagement.
- **V2** — ускоритель **Фазы 2** `architecture-research`/`tech-research` (web/GitHub best-practices) +
  discovery-половина tooling-adoption (ADR-012..015): «какие новые MCP/RAG/Claude-Code инструменты
  поднялись за 30 дней».
