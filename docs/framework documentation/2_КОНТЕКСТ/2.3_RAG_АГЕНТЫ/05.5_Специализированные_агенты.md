# 05.5 Специализированные агенты

## Агенты фреймворка

Помимо базовых RAG-агентов, framework включает специализированные агенты:

| Агент | Назначение | Когда использовать |
|-------|-----------|-------------------|
| **Analytical** | Сбор фактов, сравнение, выводы | "Чем X отличается от Y?" |
| **Plan-Execute** | Планирование задач + пошаговое выполнение | Сложные многошаговые задачи |
| **Multi-Agent** | Оркестрация нескольких агентов | Задачи, требующие разных специализаций |
| **Routing** | Маршрутизация к оптимальному агенту | Автоматический выбор |
| **Research v2** | Улучшенный Deep Research | Глубокие исследования |

## Analytical Agent

Реализует цикл **Think → Act → Observe → Re-Think**:

1. **Analytical Planner** — планирует: какие аспекты изучить, что сравнить
2. **Multi-Source Retriever** — параллельный поиск из всех источников
3. **Evidence Collector** — сбор фактов + источник + уверенность
4. **Comparator** — таблица различий, общие черты, противоречия
5. **Conclusion Generator** — генерация выводов (анализ, не копипаст)

```
Вопрос: "Чем регистр накопления отличается от регистра сведений?"

Агент ДУМАЕТ:
  → Найти: определение регистра накопления + регистра сведений
  → Сравнить: назначение, структура, типы движений
  → Проверить: примеры использования

Агент ДЕЙСТВУЕТ (3 витка):
  Виток 1: search("регистр накопления") → 5 фактов
  Виток 2: search("регистр сведений") → 4 факта
  Виток 3: search("сравнение регистров") → дополнительный контекст

Агент АНАЛИЗИРУЕТ:
  → Таблица: 8 критериев × 2 типа регистра
  → Вывод: "Регистр накопления предназначен для..."
```

## Plan-Execute Agent

Для сложных задач с чётким планом:

1. **Planner** — LLM создаёт план из 3-7 шагов
2. **Executor** — выполняет каждый шаг (поиск, анализ, генерация)
3. **Re-Planner** — корректирует план по результатам выполнения

## Multi-Agent Orchestration

Оркестрация нескольких агентов для комплексных задач:

```
Вопрос: "Проведите полный анализ архитектуры платформы"

Orchestrator:
  → Research Agent: собрать факты об архитектуре
  → Analytical Agent: провести анализ и сравнение
  → Summary Agent: подготовить структурированный отчёт
```

## Routing Agent

Автоматически направляет запрос к наиболее подходящему агенту:

| Тип запроса | Агент |
|-------------|-------|
| Простой факт | Self-RAG |
| Сравнение | Analytical |
| Исследование | Deep Research |
| Многошаговая задача | Plan-Execute |
| Комплексный анализ | Multi-Agent |


## Plan Execute Agent

**Исходный файл:** `src\pdf_framework\agents\plan_execute\agent.py`

Граф LangGraph `planner → executor → replanner → (executor | synthesizer)` ([agent.py:80-101](../../../../src/pdf_framework/agents/plan_execute/agent.py)):

1. **Planner** ([`nodes/planner.py`](../../../../src/pdf_framework/agents/plan_execute/nodes/planner.py)) — LLM генерирует JSON-план из 2-5 шагов (`PLANNER_PROMPT`), каждый шаг — `PlanStep(tool, query, depends_on)`. При ошибке разбора JSON — fallback: один шаг `search` с исходным запросом целиком.
2. **Executor** (`nodes/executor.py`) — выполняет очередной шаг выбранным инструментом (`search`/`graph_query`/`calculate`/`web_search`, передаются в `tools: dict[str, Any]` при создании агента).
3. **Replanner** (`nodes/replanner.py`) — после каждого шага решает: продолжить (`"execute"`), завершить (`"synthesize"`) или остановиться по ошибке/лимиту итераций (`should_continue`, [agent.py:28-52]).
4. **Synthesizer** (`nodes/synthesizer.py`) — собирает результаты всех шагов в финальный ответ (`final_answer`).

**Ключевые параметры** (`create_plan_execute_agent`, [agent.py:55-60]):

| Параметр | Дефолт | Назначение |
|---|---|---|
| `llm: ChatAnthropic` | — | модель для планирования и синтеза |
| `search_manager: Any` | — | поисковый менеджер, доступный executor'у |
| `tools: dict[str, Any]` | — | набор доступных инструментов |
| `max_iterations: int` | `5` | максимум циклов replanning (`PlanExecuteState.max_iterations`, [state.py:58]) |

**Когда использовать:** запрос требует явного линейного плана шагов с промежуточными результатами и возможностью скорректировать план по ходу (в отличие от **Analytical** — там фиксированный 5-шаговый цикл сравнения; от **Research v2** — там дерево задач + evidence graph + quality gates, здесь — плоский список шагов без графа доказательств).

**Пример вызова** ([agent.py:72-74](../../../../src/pdf_framework/agents/plan_execute/agent.py)):

```python
agent = create_plan_execute_agent(llm, search_manager, tools)
result = await agent.ainvoke({"query": "Compare X and Y"})
```

Либо через обёртку `run_plan_execute(query, agent, search_manager, max_iterations=5)` ([agent.py:111-159]) — возвращает `{"query", "answer", "steps", "iterations", "results", "error"}` и перехватывает исключения агента в поле `error` вместо raise.

> **Bugfix 2026-06-08 (roadmap 260608):** граф агента не компилировался — рёбра ссылались на
> узел `"execute"`, тогда как узел зарегистрирован как `"executor"`, поэтому
> `StateGraph.compile()` падал (агент был неработоспособен с момента создания). Исправлена
> разводка рёбер (`planner → executor → replanner`, условное ребро `"execute" → "executor"`).
> Дополнительно: планировщик падал на `PLANNER_PROMPT.format(query=...)` из-за литеральных
> JSON-скобок в промпте — подстановка заменена на `.replace("{query}", …)`
> (`nodes/planner.py`). Публичная сигнатура `create_plan_execute_agent(...)` не изменилась;
> поведенческие unit-тесты теперь компилируют реальный граф и проверяют подстановку запроса.


## Research V2 Agent

**Исходный файл:** `src\pdf_framework\agents\research_v2\agent.py`

Граф LangGraph Plan-Execute-Verify (Phase 36): `plan → execute → evidence → quality → (execute | report)` ([agent.py:583-604](../../../../src/pdf_framework/agents/research_v2/agent.py)).

1. **Plan** — `fast_llm` строит дерево задач `ResearchPlanTree` (3-8 задач, `parent_id` для зависимостей, `strategy` ∈ {hybrid, bm25, section_first, graphrag_local, vector}); при ошибке парсинга JSON — fallback-план из 3 фиксированных задач ([agent.py:88-169]).
2. **Execute** — параллельно (`asyncio.gather`, максимум 4 задачи за раунд, [agent.py:207]) выполняет "готовые" задачи плана (`plan.get_ready_tasks()`) через `search_manager.search(...)` или `search_manager.search_section_first(...)`, дедуплицирует чанки по `chunk_id` ([agent.py:172-253]).
3. **Evidence** — `fast_llm` извлекает факты (`EvidenceFact`, максимум 15 с `confidence > 0.5`) и связи (`supports`/`contradicts`/`refines`) в `EvidenceGraph` ([agent.py:256-364]).
4. **Quality Gate** — считает `coverage` (доля задач плана с фактами) и `groundedness` (доля фактов с `confidence >= 0.7`); проходит при `coverage >= 0.80` и `groundedness >= 0.90` либо по достижении `max_rounds`, иначе `recommendation="continue"` → ещё раунд execute ([agent.py:367-436]).
5. **Report** — генерирует структурированный отчёт (резюме, выводы, сравнительная таблица, противоречия, заключение) на основе `eg.strongest_facts(top_k=20)` и найденных противоречий ([agent.py:439-569]).

**Ключевые параметры** (`create_research_agent_v2`, [agent.py:44-49]):

| Параметр | Дефолт | Назначение |
|---|---|---|
| `search_manager: SearchManager` | — | многостратегийный поиск |
| `settings: AgentSettings \| None` | `None` → `AgentSettings()` | модель/температура/`max_tokens` основного LLM |
| `api_key: str` | `""` | Anthropic API key |
| `fast_model: str` | `"claude-sonnet-4-5-20250929"` | модель планирования и извлечения фактов (temperature=0.0) |
| `_MAX_ROUNDS` | `5` | верхняя граница `max_rounds` ([agent.py:39]) |
| `_COVERAGE_GATE` | `0.80` | порог coverage-гейта ([agent.py:40]) |
| `_GROUNDEDNESS_GATE` | `0.90` | порог groundedness-гейта ([agent.py:41]) |

**Когда использовать:** запрос требует глубокого многораундового исследования с явным контролем качества (coverage/groundedness) и построением графа доказательств с детекцией противоречий — в отличие от базового **Research Agent** (`research_agent.py` — декомпозиция + multi-step retrieval + синтез без quality gates и evidence graph) и от **Plan-Execute** (плоский план шагов без итеративного улучшения покрытия).

**Пример вызова** (эндпойнт `POST /research`, [`api/routes/search.py:397-414`](../../../../src/api/routes/search.py)):

```python
agent = create_research_agent_v2(
    search_manager=components.search_manager,
    settings=components.settings.agent,
    api_key=components.settings.anthropic_api_key,
    fast_model=components.settings.self_rag.grading_model,
)
result = await agent.ainvoke({"question": request.question, "max_rounds": request.max_rounds})
```
