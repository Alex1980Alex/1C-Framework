## Назначение

BSL Semantic Search — MCP-сервер для семантического поиска по исходному коду 1С:Предприятие (BSL). Позволяет Claude Code находить процедуры, функции, объекты метаданных и зависимости по смыслу запроса, а не только по точному совпадению текста.

### Ключевые возможности

- **Семантический поиск** — поиск по смыслу: "контроль остатков при проведении" → находит все модули с этой логикой
- **Полнотекстовый поиск** — поиск по точному вхождению: `ОбработкаПроведения` → точные совпадения
- **Граф зависимостей** — кто вызывает модуль, кого вызывает он, кластеры связанных модулей
- **RRF-fusion метаданных** — поиск объектов по техническому имени, синониму и описанию одновременно
- **7 инструментов** через MCP протокол
- **Автозапуск зависимостей** — Docker, Qdrant, Neo4j, TEI запускаются автоматически при необходимости (Ollama — опционально, только для LLM-реранкинга)
- **Graceful degradation** — 5 режимов работы: от полного до offline

### Место в фреймворке

```
Claude Code
    │
    ├── analyze-1c-task-v2     → использует bsl_hybrid_search, bsl_call_graph
    ├── implement-1c-task      → использует bsl_search, bsl_impact_analysis
    ├── code-analysis-pipeline → использует bsl_hybrid_search (Step 1.0)
    │
    └── bsl-semantic-search (lazy-mcp, on-demand)
            │
            ├── Qdrant (Docker: 1c-qdrant)        — векторное хранилище
            ├── TEI (Docker: pdf-rag-tei :8080)   — Qwen3-Embedding-8B 4096d
            ├── Neo4j (Docker: 1c-neo4j)          — граф зависимостей
            └── Ollama (localhost:11434, опц.)    — LLM-реранкинг (deepseek-coder)
```

## Архитектура

### Компоненты

| Компонент | Назначение | Технология |
|-----------|-----------|------------|
| **MCP Server** | Точка входа, JSON-RPC протокол | Python, FastMCP |
| **BSL Search Service** | Координация поиска, кеширование | Python (`src/bsl/semantic_search/services/search.py`) |
| **Qdrant Vector Store** | Хранение и поиск эмбеддингов | Qdrant (Docker `1c-qdrant`, 6333) |
| **TEI Embedding Service** (production) | Генерация эмбеддингов | TEI Docker `pdf-rag-tei` + Qwen3-Embedding-8B 4096d, обёртка `FrameworkTEIEmbedder` |
| **Ollama LLM Service** (опционально) | Реранкинг через LLM | Ollama + `deepseek-coder:6.7b` (только если включён LLM rerank) |
| **Neo4j Graph** | Граф зависимостей между модулями | Neo4j (Docker `1c-neo4j`, 7687) |
| **Hybrid Search Engine** | Объединение vector + graph | RRF fusion |
| **Graph Analytics** | Centrality, communities, dependencies | Python + Neo4j |
| **Resilience Layer** | Circuit breakers, auto-recovery | pybreaker + OllamaManager (для LLM-сервиса) |

### Поток данных

```
Запрос пользователя
    ↓
MCP Server (FastMCP)
    ↓
_ensure_services() → проверка/автозапуск зависимостей
    ↓
BSL Search Service
    ├── mode=semantic  → TEI (Qwen3 query embedding с префиксом is_query=True) → Qdrant (vector search в bsl_code_v4_late)
    ├── mode=fulltext  → Qdrant (BM25/text search)
    ├── mode=graph     → Neo4j (graph traversal)
    ├── mode=hybrid    → TEI + Qdrant + Neo4j → RRF fusion
    └── mode=intelligent → автовыбор стратегии
    ↓
Payload → форматтер (`module_path` + `content`, схема Phase 8) → кеш (TTL 5 мин) → MCP ответ
```

### Обязательные

| Сервис | Docker-контейнер | Порт | Без него |
|--------|-----------------|------|----------|
| **Qdrant** | `1c-qdrant` | 6333 | `offline` — ничего не работает |
| **TEI (Qwen3-Embedding-8B)** | `pdf-rag-tei` | 8080 | `fulltext-only` — нет semantic / hybrid / intelligent |

### Опциональные

| Сервис | Установка | Порт | Без него |
|--------|----------|------|----------|
| **Neo4j** | Docker `1c-neo4j` | 7687 | Нет graph — нет анализа зависимостей |
| **Ollama** (LLM, не embedder) | `%LOCALAPPDATA%\Programs\Ollama\ollama.exe` | 11434 | Не работает только LLM-реранкинг (опциональный слой) |

### Embedding модель (production, Phase 8)

| Модель | Размер | Dim | Backend | Назначение |
|--------|--------|-----|---------|-----------|
| **`Qwen/Qwen3-Embedding-8B`** | ~16GB GPU | 4096 | TEI Docker `pdf-rag-tei` (port 8080), MAX_CLIENT_BATCH_SIZE=32 | **PRODUCTION** — все коллекции BSL/framework/wiki/graph/skills |

Префиксы запросов: при `is_query=True` BSL Search Service добавляет инструкцию для query-варианта Qwen3 (асимметричный embedder), при индексации — passage-вариант. Подробности и ablation: [chapter 31, §21.10](../2.8_QWEN3_RETRIEVAL_PRODUCTION/31.1_Обзор.md).

### Deprecated (2026-04-30)

| Модель | Dim | Статус |
|--------|-----|--------|
| `nomic-embed-text:latest` | 768 | Deprecated — коллекция `bsl_code_v2` удалена |
| `intfloat/multilingual-e5-large` | 1024 | Deprecated — коллекция `bsl_code_v3` удалена |
| `all-minilm:l6-v2`, `mxbai-embed-large:latest` | 384 / 1024 | Не использовались в production |

Ollama-модели остаются только для опционального LLM-реранкинга (`deepseek-coder:6.7b`, путь `D:\ollama-models`). Для эмбеддингов Ollama **не используется** — все embedding-вызовы идут через TEI HTTP, см. [`src/pdf_framework/embeddings/framework_tei_embedder.py`](../../../../src/pdf_framework/embeddings/providers/tei.py).

## Режимы работы (Graceful Degradation)

Сервер автоматически определяет доступные зависимости и выбирает режим:

| Mode | Qdrant | TEI | Neo4j | Доступные функции |
|------|:------:|:---:|:-----:|------------------|
| `full` | + | + | + | Всё: semantic, fulltext, graph, hybrid, intelligent |
| `semantic` | + | + | − | Semantic + fulltext (нет graph/dependencies) |
| `fulltext+graph` | + | − | + | Fulltext + graph (нет semantic) |
| `fulltext-only` | + | − | − | Только полнотекстовый поиск |
| `offline` | − | ? | ? | Ничего (нет Qdrant = нет индекса) |

### Автодаунгрейд запросов

Если пользователь запрашивает `mode="semantic"`, а TEI недоступен:

```
Запрос: mode="semantic"
TEI: DOWN (нет ответа на http://localhost:8080/embed)
→ Автодаунгрейд: mode="fulltext" + warning в логах
→ Результат менее точный, но сервер НЕ зависает
```

Аналогично: `mode="graph"` без Neo4j → `mode="fulltext"`, `mode="hybrid"` → `mode="semantic"` или `mode="fulltext"`.
