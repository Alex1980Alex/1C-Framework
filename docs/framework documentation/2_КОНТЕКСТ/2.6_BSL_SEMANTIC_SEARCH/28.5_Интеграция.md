## analyze-1c-task-v2 (v6.0)

BSL Semantic Search используется в трёх фазах анализа задачи:

### Фаза 2 — Поиск объектов конфигурации

```python
# Семантический поиск объектов по ключевым словам из ТЗ
bsl_hybrid_search(query="ключевое слово из ТЗ", context_type="code_search", limit=10)
# → находит модули и функции, связанные с задачей

# Поиск объектов метаданных по смыслу
bsl_object_info(query="объект из ТЗ", limit=10)
# → находит справочники/документы/регистры по синониму

# Граф зависимостей для понимания связей
bsl_call_graph(file_path="найденный модуль", analysis_type="dependencies")
# → кто вызывает, кого вызывает → полная карта связей
```

### Фаза 3 — Анализ механизма

```python
# Понять как работает найденный код
bsl_hybrid_search(query="функция из кода", context_type="code_understanding")

# Найти точное совпадение по имени
bsl_search(query="ТекстЗапросаДанныеАРМ", mode="fulltext")
```

### Фаза 5 — Верификация

```python
# Проверить побочные эффекты
bsl_call_graph(file_path="изменяемый модуль", analysis_type="dependencies")
# → все модули, которые могут быть затронуты
```

## code-analysis-pipeline (v3.0)

BSL Semantic Search — **первый шаг** (Step 1.0) в конвейере анализа кода:

```
Step 1.0 (FIRST, required):
  bsl_hybrid_search(query=extracted_terms, context_type="code_search")
  → семантический поиск (Qwen3 query embedding через TEI) с динамически извлечёнными терминами

Step 1.1 (required):
  ast_grep → структурный AST поиск

Step 1.2 (fallback):
  ripgrep → текстовый поиск

Step 1.3 (required):
  1c-docs-rag → документация
```

## Комбинация с MCP_Сервер

BSL Semantic Search ищет по **статическим файлам** (индексированный код). MCP_Сервер работает с **live базой данных**. Вместе они дают полную картину:

| Задача | BSL Semantic Search | MCP_Сервер |
|--------|-------------------|------------|
| Найти модуль с нужной логикой | `bsl_hybrid_search` / `bsl_search` | — |
| Узнать точные реквизиты | — | `get_metadata(filter=FQN)` |
| Проверить SQL на live данных | — | `execute_query` |
| Найти зависимости модуля | `bsl_call_graph` / `bsl_impact_analysis` | `find_references_to_object` |
| Найти объект по синониму | `bsl_object_info` | `search_code` |
| Проверить права | — | `get_access_rights` |
| Сводка состояния BSL индекса | `bsl_stats` | — |

### Типичная цепочка

```
1. bsl_object_info("контрагент договор")    → находит объекты по смыслу
2. get_metadata(filter="Справочник.Контрагенты") → точные имена реквизитов
3. bsl_hybrid_search("ОбработкаПроведения контрагент") → код работы с ними
4. execute_query("ВЫБРАТЬ ПЕРВЫЕ 5 ...")         → проверка на live данных
5. bsl_call_graph(file_path="ObjectModule.bsl")    → побочные эффекты
```
