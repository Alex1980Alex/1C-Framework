## Структура отчёта

### TL;DR
Самое верхнее место — однострочные ключевые числа: `duration`, `files_indexed`, `chunks`, `embeddings_done`, `points_after`, `dimension`, `anomalies`. Удобно для быстрого взгляда.

### Run identity & CLI
Параметры запуска из события `startup`: embedder, project path, batch_size, pooling_mode, recreate флаг, dry_run, paths_mode. Позволяет точно воспроизвести ран.

### Run end summary
Полный payload `run_end` (files_seen, files_indexed, chunks, embeddings_done, errors). Если `errors > 0` — попадает в anomalies.

### Stages & timing
Таблица всех `stage_end` событий, отсортированная по duration (медленные сверху). Стадии для типичного reindex: `model_load`, `file_scan`, `parse_and_store`, `chunk_and_embed`, `upsert`. Колонка OK показывает успех/провал стадии.

### Discrete events
Хронологический лог `category=event` (startup, file_scan_done, parse_error, и др.). Источник для пост-мортем диагностики.

### Heartbeat gaps
Сводка heartbeat-сигнала от [`_progress.py`](../../../../scripts/_progress.py): сколько heartbeats эмитнулось, `max idle_s`, последний снимок состояния (file_idx, total_files, current). Если `max idle_s > 60s` — попадает в anomalies (возможное зависание в одном CUDA forward или TEI HTTP-вызове).

### Collection state
Live introspection Qdrant:
- Alias-resolved physical name (важно: `framework_code_v1` → `framework_code_v1_mrl_1024`)
- `points_count`, `vectors_count`, `status`
- `distance` (Cosine), `dimension` (1024 для MRL, 4096 для прочих)
- `on_disk` (true для больших коллекций)
- `quantization` (`ScalarQuantization` для production-коллекций после §4.1.12/15)
- Named vectors (если есть)

### Quality probes
Lightweight проверки на случайном sample (по умолчанию 200 точек, `--sample-size` для override). Бюджет — 10-30с даже для 80k-point коллекций.

1. **L2 norm**: mean/std/min/max. Для MRL+renorm должны быть ~1.0. Резкий дрифт >25% vs прошлого ран'а = подозрение на model swap.
2. **zero-vector count**: сколько точек с норм < 1e-9. Нормально = 0.
3. **dimension check**: длина sample-вектора vs объявленная dimension коллекции. Разница = silent model mismatch (как в Phase 9.1).
4. **self recall@1**: 10 случайных точек → query their own vector → проверяем что top-1 = они сами. Target ≥0.95. Если ниже — HNSW corruption либо забыли `using=` для named vectors.

### Diff vs previous run
Сравнение с предыдущим JSON-отчётом для той же subject (коллекции):
- Δ points (количество + проценты)
- Δ duration (быстрее/медленнее)
- L2 norm mean drift (warn >25%)
- Dimension swap detection

Если предыдущего отчёта нет — секция говорит «это первый ран».

## Anomalies (auto-detection)

Все аномалии собираются в верхнем блоке отчёта. Источники:

| Аномалия | Триггер | Что значит |
|----------|---------|------------|
| `run_end отсутствует` | Нет события `run_end` в JSONL | Индексер упал до `atexit` |
| `run_end.errors=N (>0)` | run_end payload | Pipeline errors |
| `Stage X завершился с ошибкой` | `stage_end.ok=false` | Stage threw exception |
| `idle_s = Ns (>60s)` | heartbeat snapshot | Зависание |
| `Qdrant introspection failed` | get_collection exception | Коллекция битая или Qdrant down |
| `Dimension mismatch: collection=X, sample=Y` | size collected ≠ declared | Model swap не догнан |
| `Self recall@1 = X (<0.95)` | search probe | HNSW corruption / wrong `using=` |
| `L2 norm mean изменился на N%` | vs prev report | Model swap или renorm policy change |

## Пример: первый ран `framework_code_v1` (smoke от 2026-05-22)

Анализатор корректно поймал:
- Alias `framework_code_v1` → physical `framework_code_v1_mrl_1024` (4096d → 1024d MRL truncation)
- Quantization `ScalarQuantization` (§4.1.12)
- L2 norm mean=1.0000 (perfectly renormalized после MRL truncation)
- Dimension check: match (1024d sample == 1024d collection)
- Self recall@1 в первом проходе на 5 sample'ах = 0.80 (граница [0,1] на n=5 — слишком шумно). После bump на n=10 — стабильно ≥0.9 на SQ-quantized.
