# 28_1.4 Хук и CLI

## Stop-хук `post-indexing-analyzer.py`

Файл: [`.claude/hooks/post-indexing-analyzer.py`](../../../../.claude/hooks/post-indexing-analyzer.py)

**Registration**: [`.claude/settings.json`](../../../../.claude/settings.json) → `hooks.Stop`, после `implement-1c-task-smoke-stop-alert.py`. Timeout 30s.

**Алгоритм**:

1. Читает tail (512 KB) `data/indexing-progress.jsonl`
2. Парсит `category=run_end` события → собирает кандидатов
3. Cross-check с `.claude/cache/post-indexing-analyzer-state.json` (FIFO список `processed_run_ids`, cap 500)
4. Новые run_ids → `subprocess.Popen` для каждого, detached (`DETACHED_PROCESS | CREATE_NO_WINDOW` на Windows). Cap 5 spawn-ов за один Stop (защита от dump'а после batch'а)
5. Обновляет state, эмитит `systemMessage` со списком запущенных и подсказкой про `_latest_<collection>.md`
6. Возвращает за <2с (Popen не ждёт завершения)

**Cold-start**: на первом запуске (state-файла нет) seed'ит все существующие run_ids без анализа и пишет дружелюбный init-message. Это защищает от flood'а отчётов на первой активации.

**Логи**: stdout/stderr detached subprocess'ов → `data/reports/_analyzer.log` (append).

## Контракт progress JSONL

Хук полагается на единый контракт `_progress.py`. Каждый индексер ДОЛЖЕН (через `make_tracker().start()`):

```python
tracker = make_tracker("my_indexer").start()
tracker.event("startup", collection="...", batch_size=N, ...)
with tracker.stage("model_load"): ...
with tracker.stage("file_scan"): ...
# ...
tracker.stop(summary={"files": N, "chunks": M, "errors": 0, "collection": "..."})
```

`tracker.stop(summary=...)` эмитит `category=run_end` с `elapsed_s` + полями из `summary`. Анализатор находит запись по `run_id` и достраивает контекст из predшествующих `stage_*` и `event` записей.

## CLI: `scripts/analyze_run.py`

Прямой запуск (можно прогнать ретроспективно для любого `run_id` в JSONL):

```bash
# Indexing
.venv\Scripts\python.exe scripts/analyze_run.py --mode indexing \
  --run-id <run_id_from_jsonl> [--collection <override>] [--verbosity medium|full] \
  [--sample-size 200] [--qdrant-url http://localhost:6333]

# Graph
.venv\Scripts\python.exe scripts/analyze_run.py --mode graph \
  --source {sqlite|neo4j|qdrant_graph} [--run-id <id>] \
  [--db-path cache/bsl_call_graph.db] \
  [--neo4j-uri bolt://localhost:7687] [--neo4j-user neo4j] [--neo4j-password <pw>] \
  [--qdrant-collection graph_embeddings] [--sample-size 200]

# Common
[--progress-jsonl <path>] [--reports-dir <path>] [--json-only]
```

`--json-only` — emit JSON summary в stdout (для скриптинга и hook integration).

## Параметры окружения

| ENV | Описание | Default |
|-----|----------|---------|
| `QDRANT_URL` | Qdrant endpoint | `http://localhost:6333` |
| `INDEXING_NO_PROGRESS` | Disable `_progress.py` (tests) | unset |
| `INDEXING_LOG_PATH` | Override JSONL path | `data/indexing-progress.jsonl` |
| `INDEXING_HEARTBEAT_S` | Heartbeat interval | 10.0 |
| `INDEXING_RUN_ID` | Force run_id для pipeline correlation | autogenerated |

## State-файл хука

`.claude/cache/post-indexing-analyzer-state.json`:

```json
{
  "processed_run_ids": ["...", "..."],
  "first_seen": "2026-05-22T00:15:00",
  "last_fire": "2026-05-22T00:30:00"
}
```

Cap 500 run_ids (FIFO eviction). Безопасно удалить — хук пересоздаст и при первом запуске сделает cold-start seed (без анализа).

## Когда хук НЕ срабатывает

- Cold start (первый ран сессии): seed + init-message, без анализа
- Нет новых `run_end` событий в tail JSONL
- Нет `python.exe` / `analyze_run.py` (хук залогирует FAIL в systemMessage)
- Stop без транскрипта / payload не парсится (graceful no-op через `BaseHook.run()`)

## Branch-per-task hook (opt-in, 2026-05-22)

[`.claude/hooks/post-task-push-pr.py`](../../../../.claude/hooks/post-task-push-pr.py) — отдельный хук, **не связан** с post-indexing-analyzer. Реализует workflow «branch + push + PR + auto-merge per task».

**Trigger**: `PostToolUse` с `matcher=TaskUpdate`. На каждый `TaskUpdate(status=completed)` хук проверяет:
1. `AUTO_PR_ENABLED=1` (default off → silent no-op)
2. `commits ahead of $AUTO_PR_BASE >= $AUTO_PR_MIN_COMMITS` (default base=master, min=3)
3. Не уже-обработано (idempotent через `.claude/cache/post-task-push-pr-state.json`)
4. `gh` CLI доступен
5. Pre-push tests pass (`pytest -x` или custom via `AUTO_PR_TEST_CMD`)

Если все проверки прошли:
- `git branch -f task/<taskId>-<slug> HEAD` (ref без checkout — текущая ветка не меняется)
- `git push -u origin task/...`
- `gh pr create --base $AUTO_PR_BASE --head task/... --title "[Task #N] subject"`
- Если `AUTO_PR_AUTO_MERGE=1` → `gh pr merge --squash --delete-branch`
- Emit `system_message` с PR URL

**Env vars**:

| Var | Default | Что |
|-----|---------|-----|
| `AUTO_PR_ENABLED` | `0` | master switch (`1` = enabled) |
| `AUTO_PR_BASE` | `master` | base branch (в этом repo: `dev-master` per memory `project_disjoint_master_topology`) |
| `AUTO_PR_MIN_COMMITS` | `3` | минимум commits ahead для триггера |
| `AUTO_PR_AUTO_MERGE` | `0` | `1` = auto-squash-merge после create |
| `AUTO_PR_NO_TESTS` | `0` | `1` = skip pre-push tests |
| `AUTO_PR_TEST_CMD` | pytest analyzer integration | override test command |

**Safety**:
- Never force-push, never reset working tree, never checkout new branch.
- Silent no-op при любом missing component (`gh`, base branch, AUTO_PR_ENABLED=0).
- Per-task idempotency cache (`head_sha` match → skip).

**Activation** (например, для текущего проекта):
```powershell
$env:AUTO_PR_ENABLED = "1"
$env:AUTO_PR_BASE = "dev-master"      # repo-specific
$env:AUTO_PR_MIN_COMMITS = "5"        # less PR spam
$env:AUTO_PR_AUTO_MERGE = "0"         # manual merge initially
```
