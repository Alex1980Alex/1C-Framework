## TEI Backend (Text Embeddings Inference)

### Конфигурация Docker

Сервис `tei` определён в [`docker/docker-compose.gpu.yml`](../../docker/docker-compose.gpu.yml) под opt-in profile `tei`:

```yaml
tei:
  image: ghcr.io/huggingface/text-embeddings-inference:1.7.2  # Ampere build
  command:
    - --model-id=/models/Qwen3-Embedding-8B
    - --max-input-length=4096        # token cap (matches qwen3-st)
    - --dtype=float16                # bfloat16 невалиден; fallback float32 для ORT FP16-bug #675
  volumes:
    - ${QWEN3_MODEL_DIR:-D:/hf-manual/Qwen3-Embedding-8B}:/models/Qwen3-Embedding-8B:ro
    - tei_data:/data
  ports: ["8080:80"]
  deploy:
    resources:
      reservations:
        devices:
          - driver: nvidia
            count: 1
            capabilities: [gpu]
  healthcheck:
    test: ["CMD-SHELL", "exec 3<>/dev/tcp/localhost/80; echo -e 'GET /health HTTP/1.0\\r\\n\\r\\n' >&3; head -1 <&3 | grep 200"]
    start_period: 5m

volumes:
  tei_data: {}
```

**Запуск:**

```bash
docker compose -f docker/docker-compose.yml \
  -f docker/docker-compose.gpu.yml --profile tei up -d tei
```

### API endpoints

| Endpoint | Назначение |
|----------|-----------|
| `POST /embed` | Эмбеддинг батча текстов (`{"inputs": [...], "normalize": true, "truncate": true, "truncation_direction": "Right"}`) |
| `GET /health` | Liveness probe |
| `GET /info` | Загруженная модель и конфиг |

### Server cap: `MAX_CLIENT_BATCH_SIZE = 32`

TEI 1.7.2 enforce-ит cap на размер batch'а в одном POST request. Клиент **обязан** разбивать буфер на под-батчи размера ≤ 32 — иначе **413 Payload Too Large**.

Реализация (фрагмент `scripts/reindex_bsl_qwen3.py:Qwen3TEIEmbedder._post_embed_sub`):

```python
def embed_batch(self, texts: list[str], ...) -> list[list[float]]:
    out = []
    bs = self.client_batch_size  # default 32
    for s in range(0, len(inputs), bs):
        out.extend(self._post_embed_sub(inputs[s : s + bs]))
    return out
```

### TEI vs qwen3-st (sentence-transformers) — когда что

| Use case | Backend | Почему |
|----------|---------|--------|
| Bulk reindex, std pooling | **TEI** | ~3-5× быстрее на 8B моделях, continuous batching |
| Late Chunking pooling | **qwen3-st** | TEI отдаёт pooled vectors only — token-level hidden states недоступны |
| Production query-time | **TEI** | Низкий latency, разделяемый GPU process |
| Memory hooks | **TEI** | Phase 9.1 alignment, единый стек |

**Single-GPU constraint:** Qwen3-Embedding-8B FP16 = ~16 GB VRAM. На RTX 3090 24 GB две независимые копии (TEI + qwen3-st одновременно) **НЕ помещаются**.

> **upd 2026-06-24:** прежнее «incremental → quality drift, т.к. Late Chunking требует qwen3-st» **устарело**. Late Chunking в production не используется (см. §«Реестр коллекций»), а incremental BSL reindex идёт через TEI std-pool — тем же backend, что и full reindex production-индекса → drift между свежеправленными символами и остальной коллекцией закрыт. Re-alignment manual full reindex более не обязателен для incremental-правок (см. [31.3 Pipeline](31.3_Pipeline_индексации.md), [31.6 §4.5 resilient reindex / ADR-038](31.6_Варианты_индексации_и_типичные_ошибки.md)).

## Qdrant — структура коллекций

### Layout коллекций (три варианта)

> **upd 2026-06-24:** прежнее утверждение «все коллекции = один dense 4096d, sparse BM25 НЕ используется» — **SUPERSEDED**. Hybrid sparse+dense внедрён в production 2026-05-22. Layout различается по коллекциям:

| Layout | Коллекции | Структура |
|--------|-----------|-----------|
| **Hybrid** (named dense + sparse bm25) | `bsl_code_v4_late_v3` (alias `bsl_code_v4_late`), `bsl_code_erp_ref` | `{"dense": 4096d cosine}` + sparse `{"bm25": IDF}` |
| **Single dense 4096d** | `bsl_code_v4`, `reference_1c_code`, `graph_embeddings`, `skill_library`, `learned_patterns` | один unnamed dense 4096d cosine |
| **MRL 1024d** | `framework_code_v1`, `wiki_pages_v1`, `pdf_documents` (алиасы → `*_mrl_1024`) | один dense 1024d cosine (Matryoshka-truncated) |

Создание hybrid-коллекции (production BSL):

```python
client.create_collection(
    collection_name="bsl_code_v4_late_v3",
    vectors_config={"dense": models.VectorParams(size=4096, distance=models.Distance.COSINE)},
    sparse_vectors_config={"bm25": models.SparseVectorParams(modifier=models.Modifier.IDF)},
)
```

Создание single-dense коллекции (legacy / reference):

```python
client.create_collection(
    collection_name="<name>",
    vectors_config=models.VectorParams(size=4096, distance=models.Distance.COSINE),
)
```

**Hybrid retrieval** теперь = native Qdrant `dense + bm25` с **DBSF fusion** (RRF fallback) — детали fusion-стратегии, query mode и бенчмарки в [31.7 BSL Hybrid Sparse BM25](31.7_BSL_Hybrid_Sparse_BM25.md). SQLite FTS5 (`cache/docs-mcp/hybrid_search.db`) остаётся отдельным lexical-индексом для docs-MCP, не для BSL retrieval.

## Идемпотентность через UUID5

Все индексаторы используют **deterministic UUID5** для chunk_id:

```python
chunk_id = str(uuid.uuid5(NAMESPACE, f"{path}:{line_start}:{sha1[:12]}"))
```

Эффект:
- Re-run на неизменном файле → тот же point_id → upsert no-op (idempotent)
- Edit файла (контент или позиция) → новый sha1 → новый UUID5 → новая точка
- Stale chunks (от удалённых/переименованных функций) убираются через `delete_stale_paths` — фильтр по `module_path` + `must_not HasIdCondition(has_id=keep_set)`

## Query path

### С TEI prefix-инструкцией (для query-side)

```python
QUERY_INSTRUCTION = (
    "Instruct: Given a web search query, retrieve relevant passages "
    "that answer the query\nQuery: "
)

# Embed query
qv = embedder.embed_batch([query], is_query=True)[0]
# is_query=True добавит QUERY_INSTRUCTION на client side

# Search (dense-only path — для single-dense коллекций ИЛИ fallback при TEI/BM25 down)
results = client.query_points(
    collection_name="bsl_code_v4_late",
    query=qv,
    limit=10,
    with_payload=True,
).points
```

**Passages индексируются БЕЗ префикса** (Qwen3 convention).

> **upd 2026-06-24 — production query path = hybrid.** Для hybrid-коллекции (`bsl_code_v4_late_v3`) plain `query_points` с одним вектором = **только dense-плечо** (fallback). Production-путь — `Prefetch` dense + `Prefetch` sparse bm25 → `FusionQuery` (**DBSF** дефолт, RRF fallback). Реализация: `src/bsl/semantic_search/services/search.py:439-554` (`_detect_collection_layout` → `hybrid`/`dense_only`). Дефолт query mode = **hybrid**; dense здоров (recall@10 ~0.72 lexical / ~0.42 semantic), прежнее «dense 18% / collapse» = harness artifact, **СУПЕРСЕДНУТО 2026-06-20**. Детали fusion/бенчмарки — [31.7 BSL Hybrid Sparse BM25](31.7_BSL_Hybrid_Sparse_BM25.md).

### Альтернативный backend (Ollama qwen3-embedding:8b GGUF)

`Qwen3TEIQueryService` (в `src/bsl/semantic_search/services/qwen3_embedding.py`) реализует γ-fallback Ollama → TEI: при недоступности Ollama автоматически переключается на TEI. **Caveat:** Ollama Q4 GGUF и TEI FP16 — разные векторные пространства (cosine drift = 0.52 vs ожидаемых 0.95+). Поэтому Ollama-backend **не используется** для `bsl_code_v4_late` (индекс построен через TEI). Сервис оставлен для возможного отдельного индекса `bsl_code_v4_late_ollama` (defer).
