## Lessons learned (10 наблюдений)

### 1. Декларативный план vs реальная имплементация

Phase 8 acceptance criterion §2 был «все 11 коллекций пересозданы», но фактически в первой итерации мигрирована только 1. Остальные 9 обнаружились через 4 дня при ручном `curl /collections | python -m json.tool`.

**Урок:** acceptance criterion со словом «все» нужен прогресс-чекер. Добавить в шаблон Phase plans «scroll all collections, verify dim ≥ target».

### 2. Silent bugs из dim mismatch

`memory-first-hook.py` вызывал Ollama 768d, коллекции были 1024d. Hook возвращал 0 результатов из Qdrant и фолбэчился на token overlap. Бы существовал месяцами без detection.

**Урок:** smoke test «collection dim == hook dim» на CI или session-start hook.

### 3. Path C inversion — pilot результаты обманчивы

14q pilot Qwen3+Late vs E5: E5 побеждал (recall 0.500 vs 0.321). Decision: «остаться на E5». Path C — расширение до 50q с pre-resolution фильтром: Qwen3+Late выигрывает (+26% recall).

**Урок:** малая выборка (n=14) с высоким skip-rate (53%) — статистически незначима. Decision-gate на n ≥ 30 + skip-rate < 20%.

### 4. GPU contention — single-GPU constraint реален

RTX 3090 24 GB не вмещает две независимые копии Qwen3-Embedding-8B FP16. Auto-reindex BSL incremental вынужден использовать TEI std pooling вместо qwen3-st Late.

**Урок:** документировать «working set VRAM» в каждом ADR. Перед выбором модели — оценивать footprint в paire с другими live-процессами.

### 5. «Future work» секции часто реализуются раньше плана

§24 был proposal «Framework self-search NOT scheduled — defer until production-сигнала». В тот же вечер §24 → §25 → реализован полностью.

**Урок:** «defer»-метки не снимают возможности немедленной имплементации. Добавлять «kill-switch criteria» (что должно случиться чтобы НЕ делать).

### 6. Backup manifest без verification

`260426_PHASE_8_PRE_QWEN3_BACKUP_MANIFEST.json` декларировал backup в `E:/Transfer folder/`. На момент cleanup — папки **не было**. Backup существует только в Qdrant snapshot volume.

**Урок:** при создании manifest'а проверять `Test-Path` физического артефакта PRE-commit. Manifest без verification = ложное чувство безопасности.

### 7. Phantom hooks tasks — context waste

Хуки `task-enforcer`, `code-verify-reminder`, `docs-change-tracker` срабатывали 8+ раз на phantom задачи (уже сделано, hook не знает). Каждый round-trip: 2-5 минут.

**Урок:** task-tracker hooks должны делать happy-path detection (если recent commits матчат паттерн — auto-close phantom).

### 8. «100%» migration — маркетинговая метрика

«10 коллекций × 4096d Qwen3, 100% migration» звучит впечатляюще. Реально: 8 с данными, 2 пустые «ready for auto-populate» (но pipelines TBD).

**Урок:** различать «schema migration» и «data migration» в roadmap'ах. 100% schema ≠ 100% data flow.

### 9. Late Chunking + TEI несовместимость

8.12.6 проектировался с предположением «TEI обслуживает все embedder use-cases». На 8.12.9 выяснилось — TEI отдаёт только pooled vectors.

**Урок:** для каждого embedder backend'а явно проверять каждый pooling-режим перед commit'ом архитектуры.

### 10. Что работает хорошо — паттерны для повтора

- **Idempotent UUID5 chunk_id** (`uuid5(NS, f"{path}:{line}:{sha1[:12]}")`) — re-run на неизменном файле = no-op upsert
- **Detached subprocess для git hooks** — commit не блокируется, log в отдельный файл
- **Re-embed без regen** через `scripts/reembed_collection.py` — 9 767 точек wiki+graph за 2 минуты вместо часов rechunk'а
- **3-уровневое резервирование актуальности** (file watcher + MCP lazy-check + git post-commit) — graceful degradation если один уровень падает

## Production checklist при возврате к работе

```bash
# 1. Состояние коллекций
curl -s http://localhost:6333/collections | python -m json.tool | grep '"name"'

# 2. TEI healthy
docker ps --filter "name=pdf-rag-tei"

# 3. Свежесть кода
.venv/Scripts/python.exe -c "from src.framework_search.indexer import run_index; print('imports OK')"

# 4. Smoke search BSL
# ⚠ alias bsl_code_v4_late → bsl_code_v4_late_v3 = named-vector коллекция {dense:4096d, bm25:sparse}.
#   Голый query=<vector> СЛОМАЕТСЯ (Qdrant требует имя вектора) — указывай using="dense"
#   для dense-fallback-проверки. Production-дефолт = DBSF hybrid (dense+bm25), быстрее всего
#   гонять через MCP `bsl_search` / `bsl_hybrid_search`, которые сами строят FusionQuery.
python -c "
import sys; sys.path.insert(0, '.')
from qdrant_client import QdrantClient
from src.framework_search.embedder import FrameworkTEIEmbedder
client = QdrantClient(url='http://localhost:6333')
with FrameworkTEIEmbedder() as e:
    qv = e.embed_batch(['обработка проведения документа'], is_query=True)[0]
results = client.query_points(collection_name='bsl_code_v4_late', query=qv, using='dense', limit=3, with_payload=True).points
for r in results:
    print(f'{r.score:.3f} {r.payload[\"name\"]}')
"

# 5. core.hooksPath set (auto-reindex on commit активен)
git config core.hooksPath
# Expected: scripts/git_hooks
```
