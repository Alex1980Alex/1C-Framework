# 34.1 Knowledge Base — Управление коллекциями документов

Phase 32. Управление документами на уровне выше vector store: именованные коллекции, реестр метаданных, статусы индексации.

## Назначение

Vector store хранит **чанки** (фрагменты текста с эмбеддингами). Knowledge Base хранит **документы** — богатые метаданные уровня файла и логические группы.

| Уровень | Хранилище | Единица | Назначение |
|---------|-----------|---------|-----------|
| Чанки | Qdrant / ChromaDB | chunk (текст + вектор) | Семантический поиск |
| Документы | Knowledge Base (SQLite) | DocumentRecord | Метаданные, статус, теги |
| Коллекции | Knowledge Base (SQLite) | Collection | Группировка по проекту/теме |

## Архитектура

```
src/pdf_framework/knowledge_base/
├── __init__.py          # exports: CollectionStore, DocumentRegistry
├── collection_store.py  # группы документов (Phase 32)
└── document_registry.py # метаданные документов (Phase 32)
```

Оба компонента инициализируются в `src/api/dependencies/components.py` и доступны через `components.collection_store` / `components.document_registry`.

## CollectionStore

SQLite-база (`data/collections.db`). Коллекция — именованная группа документов.

**Модель Collection:**
```python
class Collection(BaseModel):
    id: str
    name: str
    description: str = ""
    created_at: float
    updated_at: float
    document_count: int
    tags: list[str]
```

**API** (реальные сигнатуры — [`collection_store.py`](../../../../src/pdf_framework/knowledge_base/collection_store.py)):

| Метод | Описание |
|-------|----------|
| `await store.initialize()` | Создать таблицы (идемпотентно), L54 |
| `await store.create(name, description="", tags=None) -> Collection` | Создать коллекцию; `id` = первые 12 hex `sha256(name+timestamp)`, L91 |
| `await store.get(collection_id) -> Collection \| None` | Получить по ID (+ live-подсчёт `document_count`), L139 |
| `await store.get_by_name(name) -> Collection \| None` | Получить по уникальному имени, L169 |
| `await store.list_all() -> list[Collection]` | Все коллекции, отсортированы по `updated_at DESC`, L198 |
| `await store.update(collection_id, name=None, description=None, tags=None)` | Частичное обновление; `ValueError` при занятом имени, L225 |
| `await store.delete(collection_id) -> bool` | Удалить (CASCADE на `collection_documents`), L257 |
| `await store.add_document(collection_id, document_id) -> bool` | Привязать документ; `False`, если уже привязан (PK-конфликт), L273 |
| `await store.remove_document(collection_id, document_id) -> bool` | Отвязать документ, L295 |
| `await store.get_document_ids(collection_id) -> list[str]` | ID документов коллекции, L312 |
| `await store.get_collections_for_document(document_id) -> list[str]` | Обратный индекс: коллекции документа, L326 |

Имена методов короче, чем можно ожидать (`create`/`get`/`delete`, не `create_collection`/`get_collection`) — так называется публичный API класса в коде.

**Пример** (сигнатуры проверены по коду):
```python
from src.pdf_framework.knowledge_base import CollectionStore

store = CollectionStore(db_path="data/collections.db")
await store.initialize()

col = await store.create(
    name="1С Документация",
    description="Руководства по платформе 8.3",
    tags=["1c", "documentation"],
)

await store.add_document(col.id, document_id="doc-abc123")
doc_ids = await store.get_document_ids(col.id)
```

## DocumentRegistry

SQLite-база (`data/document_registry.db`). Реестр метаданных уровня файла.

**Писатели реестра (D7-проводка, 2026-06-12, roadmap 260612 pdf-docs):**
изначально реестр заполняли только REST-роуты (`src/api/routes/documents.py`),
из-за чего production-индексация (CLI/MCP/скрипты) оставляла его пустым, а
MCP `list_documents` молча отдавал `[]`. Теперь регистрация проведена на общий
низ пайплайна — `DocumentIndexer.index_chunks` (шаг 7, best-effort: ошибка
реестра никогда не роняет индексацию; `Components` подключает реестр к
индексатору после создания), плюс `scripts/reindex_pdf_documents.py` зеркалит
upsert самостоятельно. Исторический разрыв закрыт одноразовым идемпотентным
скриптом [`scripts/backfill_document_registry.py`](../../../../scripts/backfill_document_registry.py)
(`--dry-run`; толерантен к payload-диалектам `page`/`page_number`).
Регресс закреплён `tests/unit/test_indexer_registry_wiring.py`.

**Модель DocumentRecord** (Pydantic `BaseModel`, [`document_registry.py:19-34`](../../../../src/pdf_framework/knowledge_base/document_registry.py#L19-L34), процитировано дословно):
```python
class DocumentRecord(BaseModel):
    """Registered document with rich metadata."""

    document_id: str
    source_path: str
    filename: str = ""
    title: str = ""
    description: str = ""
    tags: list[str] = Field(default_factory=list)
    chunk_count: int = 0
    page_count: int = 0
    file_size_bytes: int = 0
    indexed_at: float = 0.0
    updated_at: float = 0.0
    status: str = "indexed"  # indexed | indexing | failed
    extra: dict[str, Any] = Field(default_factory=dict)
```
Модель — не `src.pdf_framework.schemas.DocumentRecord`, а определена локально в `document_registry.py` (нет отдельного модуля схем для KB).

**API** (реальные сигнатуры — [`document_registry.py`](../../../../src/pdf_framework/knowledge_base/document_registry.py)):

| Метод | Описание |
|-------|----------|
| `await registry.initialize()` | Создать таблицы (+ индексы по `source_path`/`status`), L50 |
| `await registry.register(document_id, source_path, chunk_count=0, page_count=0, title="", description="", tags=None, status="indexed") -> DocumentRecord` | `INSERT OR REPLACE`; при повторной регистрации сохраняет ранее заданные `title`/`description`/`tags`, если новые не переданы (L89-170) |
| `await registry.get(document_id) -> DocumentRecord \| None` | По ID, L172 |
| `await registry.get_by_source(source_path) -> DocumentRecord \| None` | По исходному пути файла, L188 |
| `await registry.list_all(status=None) -> list[DocumentRecord]` | Список, опц. фильтр по статусу, сортировка `updated_at DESC`, L204 (фильтра по `tags` в коде нет) |
| `await registry.update_metadata(document_id, title=None, description=None, tags=None)` | Частичное обновление пользовательских полей, L221 |
| `await registry.update_status(document_id, status)` | Обновить статус (`indexed`/`indexing`/`failed`), L250 |
| `await registry.update_chunk_count(document_id, chunk_count)` | Обновить счётчик чанков после индексации, L261 |
| `await registry.delete(document_id) -> bool` | Удалить запись, L272 |
| `await registry.count(status=None) -> int` | Подсчёт документов, опц. по статусу, L281 |

Метод называется `register`, не `register_document`; `get`/`delete`, не `get_document`/`delete_document`; фильтрации по `tags` в `list_all` нет (только `status`).

**Пример** (сигнатуры проверены по коду):
```python
from src.pdf_framework.knowledge_base import DocumentRegistry

registry = DocumentRegistry()
await registry.initialize()

# Регистрация/обновление документа после индексации —
# register() сам выставляет indexed_at/updated_at и filename/file_size_bytes
record = await registry.register(
    document_id="doc-abc123",
    source_path="/data/docs/manual.pdf",
    title="Руководство пользователя 8.3.27",
    chunk_count=342,
    page_count=95,
    status="indexed",
)

# Смена статуса без полной перезаписи записи
await registry.update_status("doc-abc123", "failed")
```

## Конфигурация

Отдельных `KB__*` настроек в `pydantic-settings` нет — пути к БД задаются в момент конструирования, привязаны к общему `settings.data_dir` ([`components.py:298-312`](../../../../src/api/dependencies/components.py#L298-L312)):

```python
self.collection_store = CollectionStore(db_path=self.settings.data_dir / "collections.db")
self.document_registry = DocumentRegistry(db_path=self.settings.data_dir / "document_registry.db")
```

| Параметр | Источник | По умолчанию |
|----------|----------|-------------|
| Путь к БД коллекций | `settings.data_dir / "collections.db"` | `data/collections.db` (`data_dir` = `PROJECT_ROOT / "data"`, [`_base.py:111`](../../../../src/pdf_framework/config/_base.py#L111)) |
| Путь к реестру документов | `settings.data_dir / "document_registry.db"` | `data/document_registry.db` |

Оба класса также принимают `db_path` напрямую в конструкторе (см. примеры выше) — для тестов/скриптов не нужно поднимать полный `Components`.

## REST API

**Коллекции** — [`src/api/routes/collections.py`](../../../../src/api/routes/collections.py), префикс `/collections`:

| Метод | Эндпоинт | Описание |
|-------|----------|----------|
| `POST` | `/collections/` | Создать коллекцию → 409 при дубле имени |
| `GET` | `/collections/` | Список коллекций с `document_count` |
| `GET` | `/collections/{collection_id}` | Коллекция + вложенные документы (обогащены из `document_registry`) |
| `PATCH` | `/collections/{collection_id}` | Частичное обновление name/description/tags |
| `DELETE` | `/collections/{collection_id}` | Удалить коллекцию (документы остаются проиндексированы) |
| `POST` | `/collections/{collection_id}/documents` | Добавить документы (batch `document_ids`) → `{added, already_in_collection}` |
| `DELETE` | `/collections/{collection_id}/documents/{document_id}` | Отвязать документ |
| `GET` | `/collections/{collection_id}/documents` | Документы коллекции с метаданными реестра |

**Реестр документов** — [`src/api/routes/documents.py`](../../../../src/api/routes/documents.py):

| Метод | Эндпоинт | Описание |
|-------|----------|----------|
| `GET` | `/documents/registry` | Список из `DocumentRegistry` (title/description/tags/chunk_count/…), опц. `?status=` (L770) |
| `PATCH` | `/documents/registry/{document_id}` | Обновить title/description/tags через `update_metadata` (L791) |

Отдельного `GET /documents/{id}`, отдающего запись реестра напрямую, нет — `GET /documents/` (без параметра) возвращает документы **из vector store** (сгруппированные чанки, `components.vector_store.count()`/`scroll()`), это другой источник данных, не `DocumentRegistry`.

## Связь с другими подсистемами

Импортёры `src/pdf_framework/knowledge_base/*` (по `Grep` на `from ... knowledge_base import` / `knowledge_base\.`):

- [`src/api/dependencies/components.py:299-312`](../../../../src/api/dependencies/components.py#L299-L312) — конструирует `CollectionStore`/`DocumentRegistry` и прикрепляет реестр к индексатору (`self.indexer.document_registry = self.document_registry`).
- [`src/pdf_framework/vector_store/indexing/indexer.py:21`](../../../../src/pdf_framework/vector_store/indexing/indexer.py) — `DocumentIndexer.index_chunks` регистрирует документ в реестре как шаг индексации (best-effort, не роняет индексацию при ошибке реестра — см. D7-проводку выше).
- [`src/api/routes/documents.py`](../../../../src/api/routes/documents.py) — REST-эндпоинты `/documents/registry*`.
- [`src/api/routes/collections.py`](../../../../src/api/routes/collections.py) — REST CRUD коллекций, обогащает ответы данными из `document_registry`.
- [`src/api/routes/search.py:74-91`](../../../../src/api/routes/search.py#L74-L91) — `collection_id` в поисковом запросе резолвится через `coll_store.get_document_ids()` в `search_filter["document_id"]` (scoped-поиск внутри коллекции); пустая коллекция даёт `search_type="collection_empty"` без обращения к vector store.
