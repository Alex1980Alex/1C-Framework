## Назначение

Главa описывает **production-конфигурацию retrieval**, реализованную в Phase 8 + 9.1: переход всей семантики фреймворка с E5/Ollama-nomic на **единую модель Qwen3-Embedding-8B 4096d** через TEI HTTP backend.

После закрытия Phase 8 + 9.1 (2026-04-30):

- 10 Qdrant-коллекций мигрированы на 4096d Qwen3 (8 с данными, 2 готовы к auto-populate)
- 80 908 векторных точек в production
- Memory subsystem aligned (silent bug 768d hooks vs 1024d collections исправлен)
- Auto-reindex на git commit активен (framework + BSL)
- 0 коллекций на legacy эмбеддерах в активном use-case (visual_grounding 768d nomic был дроплен)

## Зачем Qwen3-Embedding-8B

| Метрика | E5-large (до Phase 8) | Qwen3-8B (production) |
|---------|----------------------|----------------------|
| Dim | 1024 | **4096** (native, 32K context) |
| MTEB-Code | ~57 | **80.68** |
| MTEB-Multilingual | ~67 | **70.58** |
| Recall@10 на 50q BSL golden-set | 0.450 | **0.567** (+26%) |
| NDCG@10 на BSL | 0.291 | **0.414** (+43%) |
| Late Chunking support | ✅ (Jina v3) | ✅ через `qwen3-st` backend |
| Backend в production | sentence-transformers | TEI HTTP Docker |

Qwen3 выбран после expanded pilot (50 запросов, см. roadmap §21.10). Promotion решение принято на основе reproducible delta измеренного на synthetic golden-set, построенном по [Chroma generative-benchmarking](https://github.com/chroma-core/generative-benchmarking).

## Граничные условия и ограничения

- **Single-GPU constraint** (RTX 3090 24 GB): TEI занимает ~16 GB FP16. Параллельный qwen3-st (вторая копия модели) НЕ помещается → `qwen3-st` (Late Chunking) и TEI mutually-exclusive
- **TEI MAX_CLIENT_BATCH_SIZE=32** (server cap): клиенты должны sub-batch'ить буферы — см. `Qwen3TEIEmbedder.client_batch_size` в `scripts/reindex_bsl_qwen3.py`
- **TEI отдаёт только pooled vectors** — Late Chunking невозможен через TEI; для Late нужен `qwen3-st` через sentence-transformers
- **Qwen3 query instruction обязателен**: префикс `"Instruct: Given a web search query, retrieve relevant passages that answer the query\nQuery: "` для query-side. Любые отклонения ломают alignment (см. roadmap §21.10 H1 ablation, custom prompts давали -100% recall)

## Quick reference

**Pre-flight check (production retrieval жив?):**

```bash
# 1. TEI healthy
docker ps --filter "name=pdf-rag-tei"
curl -s http://localhost:8080/health

# 2. Qdrant healthy
curl -s http://localhost:6333/collections | python -m json.tool | grep '"name"'

# 3. Smoke search BSL
python -c "
import sys; sys.path.insert(0, '.')
from qdrant_client import QdrantClient
from src.framework_search.embedder import FrameworkTEIEmbedder
client = QdrantClient(url='http://localhost:6333')
with FrameworkTEIEmbedder() as e:
    qv = e.embed_batch(['обработка проведения документа'], is_query=True)[0]
results = client.query_points(collection_name='bsl_code_v4_late', query=qv, limit=3, with_payload=True).points
for r in results:
    print(f'{r.score:.3f} {r.payload[\"name\"]}')
"
```
