## TEI Backend (Text Embeddings Inference)

### Конфигурация Docker

Сервис `tei` определён в [`docker/docker-compose.gpu.yml`](../../docker/docker-compose.gpu.yml) под opt-in profile `tei`:

```yaml
tei:
  image: ghcr.io/huggingface/text-embeddings-inference:1.7.2  # Ampere build
  command:
    - --model-id=/models/Qwen3-Embedding-8B
    - --max-input-length=4096        # token cap (matches qwen3-st)
    - --dtype=float16                # bfloat16 невалиден; fallback float32 для ORT FP16-bug #675
  volumes:
    - ${QWEN3_MODEL_DIR:-D:/hf-manual/Qwen3-Embedding-8B}:/models/Qwen3-Embedding-8B:ro
    - tei_data:/data
  ports: ["8080:80"]
  deploy:
    resources:
      reservations:
        devices:
          - driver: nvidia
            count: 1
            capabilities: [gpu]
  healthcheck:
    test: ["CMD-SHELL", "exec 3<>/dev/tcp/localhost/80; echo -e 'GET /health HTTP/1.0\\r\\n\\r\\n' >&3; head -1 <&3 | grep 200"]
    start_period: 5m

volumes:
  tei_data: {}
```

**Запуск:**

```bash
docker compose -f docker/docker-compose.yml \
  -f docker/docker-compose.gpu.yml --profile tei up -d tei
```

### Server cap: `MAX_CLIENT_BATCH_SIZE = 32`

TEI 1.7.2 enforce-ит cap на размер batch'а в одном POST request. Клиент **обязан** разбивать буфер на под-батчи размера ≤ 32 — иначе **413 Payload Too Large**.

Реализация (фрагмент `scripts/reindex_bsl_qwen3.py:Qwen3TEIEmbedder._post_embed_sub`):

```python
def embed_batch(self, texts: list[str], ...) -> list[list[float]]:
    out = []
    bs = self.client_batch_size  # default 32
    for s in range(0, len(inputs), bs):
        out.extend(self._post_embed_sub(inputs[s : s + bs]))
    return out
```

### TEI vs qwen3-st (sentence-transformers) — когда что

| Use case | Backend | Почему |
|----------|---------|--------|
| Bulk reindex, std pooling | **TEI** | ~3-5× быстрее на 8B моделях, continuous batching |
| Late Chunking pooling | **qwen3-st** | TEI отдаёт pooled vectors only — token-level hidden states недоступны |
| Production query-time | **TEI** | Низкий latency, разделяемый GPU process |
| Memory hooks | **TEI** | Phase 9.1 alignment, единый стек |

**Single-GPU constraint:** Qwen3-Embedding-8B FP16 = ~16 GB VRAM. На RTX 3090 24 GB две независимые копии (TEI + qwen3-st одновременно) **НЕ помещаются**. Для incremental BSL auto-reindex используется TEI (std pooling) → quality drift на свежеправленных символах относительно остальной коллекции. Re-alignment через manual full reindex (см. [31.3 Pipeline](31.3_Pipeline_индексации.md)).

## Qdrant — структура коллекций

### Layout: single dense vector

Все 10 коллекций используют **один dense vector 4096d**, distance=cosine, без named vectors и sparse layer:

```python
client.create_collection(
    collection_name="<name>",
    vectors_config=models.VectorParams(size=4096, distance=models.Distance.COSINE),
)
```

**Sparse BM25 НЕ используется** на текущий момент. Для hybrid retrieval — fallback на SQLite FTS5 (`cache/docs-mcp/hybrid_search.db`, 12 983 docs). Phase 9.3 (см. [roadmap §32.3](../../roadmap/260426_ROADMAP_PHASE_8_QWEN3_EMBEDDING_REINDEX.md#323-phase-93--hybrid-sparsedense-2-4-часа)) запланирован переход на Qdrant native named vectors `dense + bm25` с RRF fusion.

## Идемпотентность через UUID5

Все индексаторы используют **deterministic UUID5** для chunk_id:

```python
chunk_id = str(uuid.uuid5(NAMESPACE, f"{path}:{line_start}:{sha1[:12]}"))
```

Эффект:
- Re-run на неизменном файле → тот же point_id → upsert no-op (idempotent)
- Edit файла (контент или позиция) → новый sha1 → новый UUID5 → новая точка
- Stale chunks (от удалённых/переименованных функций) убираются через `delete_stale_paths` — фильтр по `module_path` + `must_not HasIdCondition(has_id=keep_set)`

## Query path

### С TEI prefix-инструкцией (для query-side)

```python
QUERY_INSTRUCTION = (
    "Instruct: Given a web search query, retrieve relevant passages "
    "that answer the query\nQuery: "
)

# Embed query
qv = embedder.embed_batch([query], is_query=True)[0]
# is_query=True добавит QUERY_INSTRUCTION на client side

# Search
results = client.query_points(
    collection_name="bsl_code_v4_late",
    query=qv,
    limit=10,
    with_payload=True,
).points
```

**Passages индексируются БЕЗ префикса** (Qwen3 convention).

### Альтернативный backend (Ollama qwen3-embedding:8b GGUF)

`Qwen3TEIQueryService` (в `src/bsl/semantic_search/services/qwen3_embedding.py`) реализует γ-fallback Ollama → TEI: при недоступности Ollama автоматически переключается на TEI. **Caveat:** Ollama Q4 GGUF и TEI FP16 — разные векторные пространства (cosine drift = 0.52 vs ожидаемых 0.95+). Поэтому Ollama-backend **не используется** для `bsl_code_v4_late` (индекс построен через TEI). Сервис оставлен для возможного отдельного индекса `bsl_code_v4_late_ollama` (defer).
