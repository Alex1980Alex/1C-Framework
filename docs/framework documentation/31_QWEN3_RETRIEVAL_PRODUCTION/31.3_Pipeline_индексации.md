# 31.3 Pipeline индексации — operating procedures для каждой коллекции

> **Версия:** 1.0 | **Дата:** 2026-04-30 | **Статус:** ACTIVE

---

## Назначение

Главa описывает **production-команды для (ре)индексации** каждой из 10 Qdrant-коллекций. Используется при:
- Добавлении нового 1С-проекта (BSL)
- Добавлении новых PDF документов
- Регенерации wiki entities
- Добавлении новых skills в `.claude/skills/`
- Periodic full re-alignment (после долгой работы auto-reindex on commit с std pooling)

## Pre-flight checks

Все pipeline'ы требуют:

```bash
# 1. TEI healthy
docker ps --filter "name=pdf-rag-tei"
curl -s http://localhost:8080/health

# 2. Qdrant healthy
curl -s http://localhost:6333/collections | python -c "import json,sys; d=json.load(sys.stdin); print('collections:', len(d['result']['collections']))"

# 3. GPU свободен (для qwen3-st use-cases — но НЕ при работе TEI!)
nvidia-smi --query-gpu=memory.used,memory.free --format=csv
```

## BSL pipeline

### Production: per-project full reindex (Late Chunking)

```bash
python scripts/reindex_bsl_qwen3.py \
  --project "src/projects/configuration/<имя_проекта>" \
  --embedder qwen3-st \
  --pooling-mode late-chunking \
  --collection bsl_code_v4_late \
  --batch-size 32 \
  --buffer-size 512
```

**Время:** ~60-90 минут на проект с ~25k символов на RTX 3090.

**ВАЖНО:** требует **остановить TEI Docker** перед запуском (single-GPU constraint, qwen3-st = вторая копия Qwen3-8B 16 GB → OOM с TEI):

```bash
docker stop pdf-rag-tei  # FREE GPU memory
python scripts/reindex_bsl_qwen3.py --project ... --embedder qwen3-st ...
docker start pdf-rag-tei  # restore production
```

Альтернативно — индексировать через TEI (std pooling, без Late Chunking):

```bash
python scripts/reindex_bsl_qwen3.py \
  --project "src/projects/configuration/<имя_проекта>" \
  --embedder qwen3-tei \
  --collection bsl_code_v4 \
  --batch-size 32
```

Quality drop ~64% recall vs Late на BSL pilot (см. roadmap §21.10), не для production retrieval.

### Incremental: per-file (`--paths`)

Используется git hook'ом и для ручных incremental updates:

```bash
python scripts/reindex_bsl_qwen3.py \
  --paths "<bsl-file-1>" "<bsl-file-2>" ... \
  --embedder qwen3-tei \
  --collection bsl_code_v4_late \
  --batch-size 32
```

**Note:** через `qwen3-tei` (std pooling), не Late — quality drift ~5-10% на свежих символах. Periodic re-alignment через full reindex (production команда выше).

**Auto-detect project root** из path: walk до `src/projects/configuration/<X>/`.

**Delete-stale:** после upsert удаляет chunks с тем же `module_path` но другим `chunk_id` — ловит удалённые/переименованные BSL функции. Cap: один-к-одному per file.

### Граф вызовов (опционально)

Если коллекция участвует в Phase 8.12.8 quality eval pipeline или `bsl_call_graph` features:

```bash
python scripts/build_call_graph.py --project "src/projects/configuration/<X>" --clear
# ~17 секунд, артефакт cache/bsl_call_graph.db (33630 symbols / 79709 calls на текущий снапшот)
```

## Framework self-search pipeline

### Full reindex

```bash
python scripts/index_framework.py --recreate
```

**Время:** ~15-20 минут на 24 481 chunks (после scope tuning исключающего vendored projects).

**Что включается:** `src/`, `scripts/`, `.claude/hooks/`, `.claude/skills/`, `tools/` (без vendored), `tests/`, `docs/{architecture,framework documentation,roadmap}/`, `.mcp/`, root configs.

**SKIP_PATTERNS** в [`src/framework_search/config.py`](../../../src/framework_search/config.py) исключают:
- `__pycache__/`, `.venv/`, `node_modules/`, кэши, дисты
- `tools/serena/`, `tools/multilspy-fork/`, `tools/sonar-scanner` (vendored)
- `src/projects/configuration/` (BSL — отдельный pipeline)
- `docs/documentation/Lang Chain Docs/`, `Claude Code Docs/`, `Протокол контекста модели/`, `Language Server Protocol/` (импортированная сторонняя документация)

### Incremental (per-file)

```bash
python scripts/index_framework.py --paths "src/foo.py" "docs/bar.md"
```

**Delete-stale через chunk_id keep-set:** `module_path` файла → удалить всё что не в `keep_ids`.

### Pre-flight (без embed/upsert)

```bash
python scripts/index_framework.py --dry-run
# Покажет распределение chunks по language без изменения коллекции
```

### Smoke test (50 chunks)

```bash
python scripts/index_framework.py --limit 50 --recreate
```

## PDF pipeline

### Reindex `pdf_documents` (Qwen3 4096d)

```bash
python scripts/reindex_pdf_documents.py --recreate
```

**Что делает:**
- Сканирует `data/pdfs/*.pdf`
- Извлекает текст через `pymupdf` (218 страниц на 6.9 MB PDF)
- Sliding window 1000 chars / 200 overlap
- Эмбеддит через TEI batch=16
- Recreate коллекцию на 4096d cosine

**Время:** ~62 секунды на 830 chunks из одного PDF.

**Caveat:** PDF Framework нативно использует `src/pdf_framework/embeddings/providers/local.py` (sentence-transformers) — TEI provider пока не реализован (см. [roadmap §32.6.3](../../roadmap/260426_ROADMAP_PHASE_8_QWEN3_EMBEDDING_REINDEX.md#326-long-term-deferred)). Текущий script — одноразовая обвязка через `FrameworkTEIEmbedder` из `src/framework_search/`.

## Wiki / Graph / Learned-patterns — re-embed без regen

Универсальный script `scripts/reembed_collection.py` для миграции коллекций где payload уже содержит `text` или `content`:

```bash
# Wiki entities
python scripts/reembed_collection.py --collection wiki_pages_v1
# Default --text-field "text", --target-dim 4096

# Graph entities (тот же шаблон)
python scripts/reembed_collection.py --collection graph_embeddings

# Learned patterns (поле "content" вместо "text")
python scripts/reembed_collection.py --collection learned_patterns --text-field content
```

**Что делает:**
- Scrolls source collection, captures (id, payload, text)
- Drops + recreates на 4096d cosine
- Re-embed через TEI с **сохранением original ids** (UUID5 preservation)
- Truncate >8000 chars (TEI MAX_INPUT_LENGTH=4096 tokens ≈ 16k chars)

**Время:** ~78 секунд на 3073 wiki entities, ~85 секунд на 6694 graph entities, ~2 секунды на 44 learned_patterns.

## Skills pipeline

### Recreate + populate `skill_library`

```bash
SKILL_INDEX_RECREATE=1 python scripts/index-skills-to-qdrant.py
```

**Что делает:**
- Glob `.claude/skills/*/SKILL.md` (82 файла на 2026-04-30)
- Парсит YAML frontmatter (name, description, triggers)
- Embed через TEI 4096d
- Drop + recreate `skill_library` collection если `SKILL_INDEX_RECREATE=1`
- Без env var — append (idempotent UUID5 на skill_name)

**Время:** ~15 секунд на 80 skills (2 пропущены из-за empty body).

**Защита от dim mismatch:** скрипт abort'ит если existing collection dim ≠ `VECTOR_SIZE` без `SKILL_INDEX_RECREATE=1` env.

## Verify post-reindex

После любого reindex'а — проверка что данные легли:

```bash
# Number of points in collection
.venv/Scripts/python.exe -c "
from qdrant_client import QdrantClient
client = QdrantClient(url='http://localhost:6333')
info = client.get_collection('<коллекция>')
print(f'points={info.points_count} dims={info.config.params.vectors.size} status={info.status}')
"

# Smoke search
python -c "
import sys; sys.path.insert(0, '.')
from qdrant_client import QdrantClient
from src.framework_search.embedder import FrameworkTEIEmbedder
client = QdrantClient(url='http://localhost:6333')
with FrameworkTEIEmbedder() as e:
    qv = e.embed_batch(['<смысловой запрос>'], is_query=True)[0]
results = client.query_points(collection_name='<коллекция>', query=qv, limit=3, with_payload=True).points
for r in results:
    print(f'{r.score:.3f} {list(r.payload.keys())[:5]}')
"
```

## Common pitfalls

| Симптом | Причина | Решение |
|---------|---------|---------|
| `OOM` на 25-30% прогресса BSL reindex | XXL chunks (>4096 токенов) переполняют GPU | Sliding-window split в `BSLChunker` (Phase 8.12.5: window=1024 / overlap=256). Обычно уже включён по умолчанию |
| 0 chunks в коллекции после `--recreate` | Парсер не нашёл `.bsl` или EXT_TO_LANGUAGE пропустил | Проверить путь `--project`; убедиться что `.bsl` именно в этом дереве, а не в `bin/` / `node_modules/` (skip patterns) |
| `413 Payload Too Large` на TEI | Размер batch > server cap (32) | Использовать `Qwen3TEIEmbedder.client_batch_size=32` (default) — sub-batch автоматически |
| `AttributeError: 'QdrantClient' has no attribute 'search'` | qdrant-client ≥1.13 deprecated | `client.query_points(query=qv, with_payload=True).points` |
| `--paths` BSL даёт ERROR "spans multiple projects" | Файлы из разных `src/projects/configuration/<X>/` | Группировать по project root, делать отдельные spawn'ы (как в `git_post_commit_reindex.py`) |
| Dim mismatch (попытка upsert 4096d в 1024d коллекцию) | Старая legacy collection | Recreate target collection на 4096d перед upsert (`--recreate` флаг или `client.recreate_collection`) |
