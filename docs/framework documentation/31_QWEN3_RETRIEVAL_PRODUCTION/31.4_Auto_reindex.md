# 31.4 Auto-reindex on git commit — 3-уровневое резервирование актуальности

> **Версия:** 1.0 | **Дата:** 2026-04-30 | **Статус:** ACTIVE

---

## Назначение

Описывает **автоматическую инкрементальную индексацию** при `git commit` / `git merge`. Без этого механизма после каждой правки кода нужно было бы вручную дёргать `index_framework.py --paths ...` или ждать MCP lazy-check (~30 сек throttle).

**3 уровня резервирования** обеспечивают актуальность Qdrant:

```
  [git commit]                ← Level 1: post-commit hook
       │                          (git_post_commit_reindex.py, detached)
       ▼
  [Stage 3 file watcher]      ← Level 2: polling 5s (если daemon запущен)
       │                          (scripts/watch_framework.py)
       ▼
  [Stage 2 MCP lazy-check]    ← Level 3: on-demand при search_code
       │                          (throttle 30s, cap 50 files)
       ▼
  [Qdrant framework_code_v1]
       ▲
  [Manual fallback]           ← Level 4: всегда работает
       (python scripts/index_framework.py --paths X)
```

## Активация (один раз на клон репозитория)

```bash
git config core.hooksPath scripts/git_hooks
```

Это перенаправляет git hooks из `.git/hooks/` (per-clone) в версионируемый `scripts/git_hooks/` (всем clone'ам). Сохраняет git-lfs hooks (каждый wrapper делегирует `git lfs <event>` первым делом).

**Отключить:** `git config --unset core.hooksPath` восстанавливает `.git/hooks/`.

## Поток исполнения post-commit

```
git commit -m "..."
   │
   ▼
scripts/git_hooks/post-commit
   │
   ├── git lfs post-commit "$@"         ← preserve LFS behavior
   │
   └── python scripts/git_post_commit_reindex.py --since-ref HEAD~1
           │
           ▼
       _split_bsl_and_framework(diff)
           │
           ├──> framework_paths[]: .py .md .json .ts .toml ... cap 512KB
           │       │
           │       └─> spawn detached: scripts/index_framework.py --paths ...
           │           ↓ log: cache/framework_search_reindex.log
           │           ↓ result: framework_code_v1 updated (~5 sec for 5 files)
           │
           └──> bsl_groups[{project, files[]}]: .bsl in src/projects/configuration/, cap 4MB
                   │
                   └─> spawn detached PER project root:
                       scripts/reindex_bsl_qwen3.py --paths ... --embedder qwen3-tei \
                         --collection bsl_code_v4_late --batch-size 32
                       ↓ log: cache/bsl_reindex.log
                       ↓ result: bsl_code_v4_late updated (~1.5 sec per file)
```

**Detached spawn:** Windows `creationflags=DETACHED_PROCESS|CREATE_NEW_PROCESS_GROUP`, POSIX `start_new_session=True`. Commit завершается мгновенно, reindex идёт в фоне.

## Логика split

| Тип файла | Условие | Pipeline | Cap |
|-----------|---------|----------|-----|
| `.py .md .json .js .ts .toml .yaml .ini` | НЕ в `src/projects/configuration/` | framework_search → `framework_code_v1` | 512 KB |
| `.bsl` | В `src/projects/configuration/<X>/` | BSL → `bsl_code_v4_late` | 4 MB |
| Прочее | — | Skip (нет EXT_TO_LANGUAGE match) | — |

**Vendored эксклюды** (через `_matches_skip` в `src/framework_search/file_walker.py`):
- `tools/serena/`, `tools/multilspy-fork/`, `tools/sonar-scanner`, `tools/coverage41c/`
- `__pycache__/`, `.venv/`, `node_modules/`, кэши, дисты

**Bulk operation guard:** если в diff > 200 файлов (initial commit, branch switch с большим diff) — skip auto-reindex, лог в `cache/framework_search_reindex.log`. MCP lazy-check (Level 3) подберёт stale при следующем `search_code`.

## BSL incremental — backend trade-off

Auto-reindex BSL использует `--embedder qwen3-tei` (std pooling) вместо `qwen3-st` (Late Chunking). Причина — single-GPU constraint:

```
TEI Docker: ~16 GB VRAM (всегда занят)
qwen3-st: ~16 GB VRAM (если запустить)
RTX 3090: 24 GB total → не помещается
```

**Trade-off:**
- ✅ Auto-reindex быстрый и не блокирует production retrieval
- ⚠️ Свежие incremental chunks с std pooling vs остальная коллекция с Late Chunking
- ⚠️ Quality drop ~5-10% recall на свежеправленных символах (см. roadmap §28.2.5)

**Re-alignment:** periodic manual full reindex bsl_code_v4_late через qwen3-st (см. [31.3](31.3_Pipeline_индексации.md) production команда). Рекомендация — раз в 1-2 недели или после крупных рефакторингов.

## Конфигурация helper'а

`scripts/git_post_commit_reindex.py` принимает env-параметры:

| CLI flag / env | Default | Назначение |
|----------------|---------|-----------|
| `--since-ref` | `HEAD~1` | Diff base (`ORIG_HEAD` для post-merge) |
| `--max-files` | `200` | Skip если diff больше |

Edge cases:
- `HEAD~1` не существует (initial commit) → silent exit 0
- 0 файлов после фильтра → silent exit 0
- TEI down → spawn проходит, reindex script упадёт на embed; ошибка в `cache/*_reindex.log`

## MRL truncation на upsert (после §4.1.6 swap, 2026-05-17)

После production swap `framework_code_v1` → 1024d MRL alias (см. [04.9_Matryoshka_Embeddings.md](../04_ПОИСК/04.9_Matryoshka_Embeddings.md)) `framework_code_v1` физически указывает на `framework_code_v1_mrl_1024` (1024d). TEI продолжает возвращать 4096d, поэтому indexer обязан truncate'нуть на upsert.

Реализация в [`src/framework_search/indexer.py`](../../../src/framework_search/indexer.py):

```python
target_dim = resolve_collection_dim(client, collection)  # 1024 для аliased framework_code_v1
truncate = target_dim is not None and target_dim < dims  # True при mismatch
...
if truncate:
    vectors = maybe_truncate_vectors(vectors, target_dim)  # truncate + L2-renorm
```

Лог при активном пути: `indexer: MRL truncation 4096d -> 1024d active`.

**Замечание про `--recreate` (2026-05-17, M1+M2 fix):** `ensure_collection(recreate=True)` теперь полностью alias-aware:

1. `resolve_physical_collection(client, "framework_code_v1")` → `"framework_code_v1_mrl_1024"`
2. `delete_collection("framework_code_v1_mrl_1024")` — удаляет physical (заодно убирает alias)
3. `create_collection("framework_code_v1_mrl_1024", …)` — создаёт под physical именем
4. `update_collection_aliases(CreateAliasOperation(create_alias=CreateAlias(collection_name="framework_code_v1_mrl_1024", alias_name="framework_code_v1")))` — восстанавливает alias

Старый баг (до 2026-05-17): шаг 3 создавал новую standalone-коллекцию под именем алиаса (`"framework_code_v1"`), шаг 4 пропускался — MRL-сетап уничтожался, retrieval ломался до ручного восстановления. Покрыто 3 unit-тестами в [`tests/test_framework_search/test_indexer_mrl.py`](../../../tests/test_framework_search/test_indexer_mrl.py) + smoke на реальном Qdrant. Тот же паттерн применён в `scripts/reembed_collection.py` и `scripts/reindex_pdf_documents.py`.

BSL коллекция (`bsl_code_v4_late`) пока 4096d — truncate no-op (на момент 2026-05-17). При прохождении §4.1.7 (BSL migration) тот же механизм автоматически активируется.

## File watcher (Stage 3) — опциональный second layer

Если хочется real-time актуальность без ожидания commit'а:

```bash
# Foreground (Ctrl+C to stop)
python scripts/watch_framework.py

# Опции
python scripts/watch_framework.py --poll-interval 10 --debounce 3.0 --max-files-per-batch 50

# Daemon-style
python scripts/watch_framework.py --quiet > cache/watcher.log 2>&1 &
```

**Polling-based** (zero extra deps, кроссплатформенно): каждые 5 секунд сканирует mtimes файлов, сравнивает с in-memory snapshot indexed paths, реиндексирует diff. Debounce 2s (skip ещё-редактируемых файлов), cap 100 files/iter.

**Дополняет post-commit hook:** работает между коммитами; отключаемый. Подходит для активной разработки.

## MCP lazy-check (Stage 2) — fallback layer

В Stage 2 MCP server (`tools/framework-search-mcp/server.py`) каждый `search_code` call делает throttled mtime check:

- Throttle: не чаще 1× в 30 сек (`LAZY_CHECK_MIN_INTERVAL_SEC`)
- Cap: 50 файлов за проход
- Idempotent: если все mtimes совпадают — no-op

Это safety-net для случая когда watcher упал и hook не сработал.
