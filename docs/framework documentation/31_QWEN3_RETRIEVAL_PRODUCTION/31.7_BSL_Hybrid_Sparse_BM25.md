# 31.7 BSL Hybrid Sparse BM25 (Native Qdrant)

> **Status:** PRODUCTION since 2026-05-22. Alias `bsl_code_v4_late` resolves to `bsl_code_v4_late_hybrid` (named-vector `{dense:4096d, bm25:sparse IDF}`, 37,668 pts). **Default mode: pure BM25** (RRF deprecated после realistic eval, см. ниже).

## Проблема: dense Qwen3 коллапсирует на BSL

### Realistic golden eval (final, decides production default)

`scripts/bench_bsl_realistic_eval.py` — 50 hand-authored queries из `data/bsl_golden_set.json`, scope=CommonModules:

| Mode | Recall@10 | NDCG@10 | MRR | P@5 |
|---|---|---|---|---|
| Qwen3 dense | 18.0% | 0.135 | 0.120 | 0.036 |
| **BM25 sparse (production default)** | **76.0%** | **0.571** | **0.511** | **0.128** |
| Hybrid RRF | 70.0% | 0.502 | 0.438 | 0.128 |

**Pure BM25 strictly dominates RRF на ВСЕХ метриках.** dMRR +7.3pp, dRecall@10 +6.0pp, dNDCG +6.9pp. RRF degrades top-K ordering без вклада в recall.

### Synthetic anchor benchmarks (history; biased)

`scripts/bench_bsl_sparse_production.py` — 30 verbatim-fragment queries:

| Mode | MRR@10 | Hit@1 | Hit@3 | Hit@10 |
|---|---|---|---|---|
| Qwen3 dense alone | 0.113 | 10.00% | 10.00% | 16.67% |
| FastEmbed BM25 sparse | 0.526 | 40.00% | 63.33% | 73.33% |
| Hybrid RRF | 0.423 | 26.67% | 50.00% | 76.67% |

Anchor использует verbatim fragments → favours BM25 unfairly. Realistic golden eval подтвердил BM25 dominance independently. Dense не находит даже verbatim fragment собственного chunk в 83% случаев — корень BSL embedding collapse (детали в memory `feedback_bsl_embedding_collapse`, [chapter 31.6](./31.6_Варианты_индексации_и_типичные_ошибки.md)).

## Решение: native Qdrant sparse BM25 (dense kept as fallback)

### Layout

```
Named vectors:
  - dense:  4096d cosine  (Qwen3-Embedding-8B, Late Chunking std pooling)
Sparse vectors:
  - bm25:   IDF modifier  (FastEmbed Qdrant/bm25)
```

Один point хранит ОБА вектора. Sparse computed client-side из `payload.content`.

**Query path (production default):** pure BM25 — `client.query_points(query=SparseVector(...), using="bm25", ...)`. Dense vectors остаются на диске, доступны через `using="dense"` или Prefetch+RRF (для будущих экспериментов или corpus где dense работает), но НЕ в default path.

**Why RRF проигрывает BM25 alone:** RRF reciprocal-rank fusion даёт каждому Prefetch вес 1/(k+rank). Когда dense возвращает мусор в top-50, его 1/(60+rank) суммируется со scores BM25's top-50 — мусорные dense-кандидаты получают bonus и вытесняют точные BM25-хиты с MRR=1.

### CamelCase нормализация (obligatory)

BSL identifiers — `ОбработкаПроведения`, `НоменклатураКонтрагент` — BM25 без preprocessing видит как один opaque token. Query `обработка проведения` тогда не матчит. Решение — split на index AND query:

```python
import re
_CAMELCASE_RE = re.compile(r"[А-ЯЁ][а-яё]*|[A-Z][a-z]*|[а-яё]+|[a-z]+|\d+")

def normalize_camelcase(text: str) -> str:
    parts = _CAMELCASE_RE.findall(text)
    return " ".join(parts).lower() if parts else text.lower()
```

Одинаковый regex в трёх местах (если расходятся — index/query desync ломает retrieval):
- [`scripts/migrate_bsl_to_hybrid.py`](../../../scripts/migrate_bsl_to_hybrid.py)
- [`scripts/reindex_bsl_qwen3.py`](../../../scripts/reindex_bsl_qwen3.py) `_normalize_camelcase_for_bm25`
- [`src/bsl/semantic_search/services/search.py`](../../../src/bsl/semantic_search/services/search.py) `BSLSearchService._normalize_camelcase_for_bm25`

Existing dense vectors переиспользуются (no re-embed Qwen3). BM25 sparse compute on-the-fly через `fastembed.SparseTextEmbedding(model_name="Qdrant/bm25")`. Idempotent — повторный запуск skip'нет уже загруженное.

## Query path (production)

`src/bsl/semantic_search/services/search.py:_call_qdrant_search` auto-detects layout:

```python
layout = self._detect_collection_layout(collection_name)  # cached
if layout == "hybrid" and bm25_encoder:
    # Pure BM25 sparse — production default after 2026-05-22 realistic eval
    client.query_points(query=SparseVector(...), using="bm25", limit=k, ...)
else:
    # Legacy single-vector dense query_points OR fallback if FastEmbed unavailable
```

FastEmbed BM25 model lazy-init на первом hybrid-вызове (~2-3s, кэш в memory). Если FastEmbed недоступен — graceful degrade на dense через `using="dense"`. Dense path хуже BM25 (18% recall@10 vs 76%), но лучше отказа.

**Latency win:** pure BM25 не требует TEI dense embed (~150-300ms saved per query). BM25 sparse compute через FastEmbed CPU-only ~5ms.

## Incremental reindex (git post-commit)

`scripts/reindex_bsl_qwen3.py` теперь auto-detect'ит hybrid layout через `detect_collection_layout()` и инициализирует sparse encoder без флагов. Git post-commit hook (через `git_post_commit_reindex.py`) работает без изменений — alias `bsl_code_v4_late` теперь резолвится в hybrid, indexer видит layout и пишет sparse сам.

Для создания НОВОЙ hybrid коллекции (вне alias) — флаг `--enable-sparse`:

```bash
.venv\Scripts\python.exe scripts\reindex_bsl_qwen3.py \
    --project path/to/1c --embedder qwen3-tei --enable-sparse \
    --collection my_new_bsl_collection
```

## Известные nuances

- **Pure BM25 winning не generalize automatically.** BM25 dominance подтверждён ТОЛЬКО на BSL (identifier-rich Cyrillic). Для PDF/wiki/Python corpus (richer paraphrase space, English text) RRF или pure dense может быть лучше. Per-corpus eval mandatory ПЕРЕД применением паттерна.
- **Dense vectors остаются индексированными.** 37k × 4096d storage ~600MB RAM. Можно сэкономить через `PATCH /collections/.../vectors {"dense": null}` — но dense нужен как fallback when FastEmbed unavailable, plus future eval может показать что dense pulls weight на другом query distribution.
- **MCP server restart.** Long-running BSL MCP processes имеют кэшированный layout `dense_only`. После swap нужен restart процесса MCP (Claude Code spawns per-session, так что новые сессии видят hybrid сразу).
