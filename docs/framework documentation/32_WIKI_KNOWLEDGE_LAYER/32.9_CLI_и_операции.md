# 32.9 CLI и операции

Все wiki операции доступны через единый CLI [`scripts/export_graph_to_wiki.py`](../../../scripts/export_graph_to_wiki.py) — **8 subcommand'ов** (6 базовых + `decay-confidence` + `archive-stale` добавлены 2026-05-14). Реализация — Python typer/argparse, использует те же сервисы что и production daemon. Этот файл — operator reference.

## Запуск

```bash
.venv/Scripts/python -m scripts.export_graph_to_wiki <subcommand> [options]
```

Обязательно через `python -m` (а не прямой `python scripts/export_graph_to_wiki.py`) — необходимо чтобы Python нашёл `src/` через PYTHONPATH-инжекцию из script header.

## Subcommands

### 1. `export-all` — batch export всего графа

```bash
.venv/Scripts/python -m scripts.export_graph_to_wiki export-all \
    --output-dir docs/wiki/entities \
    --batch-size 50 \
    [--dry-run] \
    [--overwrite] \
    [--verbose]
```

| Опция | Default | Назначение |
|---|---|---|
| `--output-dir` | `docs/wiki/entities` | Куда писать markdown файлы |
| `--batch-size` | 50 | Сколько entities обрабатывать за раз |
| `--dry-run` | False | Логировать что было бы записано, ничего не писать |
| `--overwrite` | False | Перезаписать существующие файлы даже если hash совпал |
| `--verbose` / `-v` | False | DEBUG-level logging |

**Use cases:**
- Initial export после первой индексации PDF
- Migration после смены embedding model (см. [chapter 32.7](32.7_Search_интеграция.md) §Reindex)
- Recovery после удаления `docs/wiki/entities/`

**Exit codes:**
- `0` — все entities exported (или skipped как idempotent)
- `1` — partial failure (some entities raised, остальные exported)
- `2` — total failure (graph_store недоступен)

**Output sample:**

```
2026-05-14 10:30:00 [INFO] WikiExporter: Starting export of 2,822 entities
2026-05-14 10:30:01 [INFO] WikiExporter: Batch 1/57 (50 entities)
...
2026-05-14 10:33:45 [INFO] WikiExporter: Done. Exported 2,815, skipped (unchanged) 7, failed 0
```

### 2. `export-entity` — экспорт одной entity

```bash
.venv/Scripts/python -m scripts.export_graph_to_wiki export-entity <ENTITY_ID> \
    --output-dir docs/wiki/entities \
    [--dry-run] \
    [--verbose]
```

**Use cases:**
- Debug single entity export
- Manual re-sync после ручного edit'а entity в graph
- Smoke-test export pipeline

**Exit codes:**
- `0` — exported
- `1` — entity не найдена в graph

### 3. `sync-incremental` — production daemon

```bash
.venv/Scripts/python -m scripts.export_graph_to_wiki sync-incremental [--verbose]
```

Запускает long-running daemon, который подписывается на EventBus `graph.*` events. Блокирует терминал; Ctrl+C для graceful shutdown.

**Production deployment** (systemd unit):

```ini
[Unit]
Description=PDF Framework Wiki Sync Daemon
After=network.target qdrant.service

[Service]
Type=simple
User=pdf-framework
WorkingDirectory=/opt/pdf-framework
ExecStart=/opt/pdf-framework/.venv/bin/python -m scripts.export_graph_to_wiki sync-incremental
Restart=on-failure
RestartSec=10
StandardOutput=journal
StandardError=journal

[Install]
WantedBy=multi-user.target
```

**Docker variant:**

```dockerfile
CMD ["python", "-m", "scripts.export_graph_to_wiki", "sync-incremental", "--verbose"]
```

В obstetric состоянии команда не выйдет — она блокирует на `asyncio.Event().wait()`. Завершение — только через SIGINT (KeyboardInterrupt) или SIGTERM.

### 4. `index-search` — индексация в wiki_pages_v1

```bash
.venv/Scripts/python -m scripts.export_graph_to_wiki index-search \
    --wiki-dir docs/wiki/entities \
    [--verbose]
```

Эмбеддит все `.md` файлы в `wiki_dir` через TEI Qwen3 + upsert в Qdrant `wiki_pages_v1`. См. [chapter 32.7](32.7_Search_интеграция.md) для деталей.

**Когда запускать:**
- После full `export-all` (чтобы новые pages были searchable)
- После batch ручного edit'а wiki pages
- После смены embedding model

**Auto-reindex on commit** для wiki — НЕ настроен (в отличие от `framework_code_v1` и `bsl_code_v4*`). Wiki меняется реже, manual cadence acceptable.

### 5. `verify` — консистентность wiki ↔ граф

```bash
.venv/Scripts/python -m scripts.export_graph_to_wiki verify \
    --output-dir docs/wiki/entities \
    [--verbose]
```

Два check'а:

**Check 1: Every entity → has wiki page**

```python
entity_ids = [nid for nid, data in graph.nodes(data=True)
              if data.get("node_type") != "COMMUNITY" and data.get("name")]

for eid in entity_ids:
    name = graph.nodes[eid].get("name", eid)
    fname = WikiExporter._sanitize_filename(name)
    if not (output_dir / f"{fname}.md").exists():
        print(f"  MISSING wiki: {name} → {wp}")
        inconsistencies += 1
```

**Check 2: Every wiki page → has entity in graph**

```python
graph_names = {WikiExporter._sanitize_filename(data.get("name", nid))
               for nid, data in graph.nodes(data=True)}

for wp in output_dir.glob("*.md"):
    if wp.stem not in graph_names:
        print(f"  ORPHAN wiki: {wp.name} (no entity in graph)")
        inconsistencies += 1
```

**Exit codes:**
- `0` — no inconsistencies (или 0 entities в graph)
- `1` — есть inconsistencies (missing or orphan)
- `2` — graph_store недоступен

**Use cases:**
- CI/CD job для регулярной валидации
- Post-migration cleanup (после смены embedding model или graph schema)
- Pre-deploy sanity check

### 6. `promote-patterns` — L2 → L5 promotion (добавлено 2026-05-14)

```bash
.venv/Scripts/python -m scripts.export_graph_to_wiki promote-patterns \
    [--min-confidence 0.8] \
    [--min-usage 5] \
    [--similarity-threshold 0.85] \
    [--drafts-dir docs/wiki/drafts] \
    [--qdrant-url http://localhost:6333] \
    [--qdrant-api-key ...] \
    [--verbose]
```

| Опция | Default | Назначение |
|---|---|---|
| `--min-confidence` | 0.8 | Threshold для `confidence` field в `learned_patterns` |
| `--min-usage` | 5 | Threshold для `application_count` field |
| `--similarity-threshold` | 0.85 | Cosine threshold для dedup проверки |
| `--drafts-dir` | `docs/wiki/drafts` | Куда писать draft files |
| `--qdrant-url` | `http://localhost:6333` | Qdrant endpoint |
| `--qdrant-api-key` | `$QDRANT__API_KEY` env | Auth (для staging/cloud Qdrant) |

Реализация — [`WikiPromoter.scan_and_promote()`](../../../src/memory/librarian/wiki_promoter.py). См. [chapter 32.6](32.6_L2_L5_Promotion.md).

**Auto-invocation**: этот CLI вызывается из `.claude/hooks/session-memory-save.py:try_promote_patterns()` на каждый Stop event. Ручной вызов — для testing или manual promotion sweep.

**Exit codes:**
- `0` — successful run (с любым counter'ом promoted, включая 0)
- `1` — total failure (Qdrant unreachable)
- `2` — bad arguments

«Promoted 0» = informational success, message routed в stderr.

### 7. `decay-confidence` — time-based L3 decay (added 2026-05-14)

```bash
.venv/Scripts/python -m scripts.export_graph_to_wiki decay-confidence \
    [--min-confidence 0.0] \
    [--batch-size 100] \
    [--qdrant-url http://localhost:6333] \
    [--qdrant-api-key ...] \
    [--dry-run] \
    [--verbose]
```

Применяет monthly-linear decay (`decay_rate * days_idle / 30`) к `confidence` field в `learned_patterns`. Counter-balance к asymmetric `apply_pattern` update. См. [chapter 32.6 §Decay](32.6_L2_L5_Promotion.md#decay-counter-balance). Output: `Decay — total=N, decayed=N, skipped=N`. **Cadence:** monthly cron или manual; НЕ wired в Stop hook.

### 8. `archive-stale` — move low-confidence stale entities (added 2026-05-14)

```bash
.venv/Scripts/python -m scripts.export_graph_to_wiki archive-stale \
    [--wiki-dir docs/wiki/entities] \
    [--archive-dir docs/wiki/archive] \
    [--max-age-days 365] \
    [--min-confidence 0.3] \
    [--dry-run] \
    [--verbose]
```

Сканирует `docs/wiki/entities/*.md`, перемещает в `archive/YYYY-MM/` если `status != "archived"` AND `confidence < min_confidence` AND `updated_at < cutoff`. Uniqueness suffix `.HHMMSS` при collision target. Idempotent, dry-run safe. **Cadence:** manual (можно cron'ом раз в квартал/год).

## Common operator tasks

### Initial deployment

```bash
# 1. Initial PDF indexing (chapter 03)
.venv/Scripts/python -m src.cli ingest /path/to/pdfs

# 2. Verify graph populated
.venv/Scripts/python -c "
import asyncio
from src.pdf_framework.graph_store import get_graph_store
async def main():
    s = get_graph_store(); await s.initialize()
    print('Entities:', len([n for n in s._graph.nodes()]))
asyncio.run(main())
"
# → "Entities: 2,822"

# 3. Export to wiki
.venv/Scripts/python -m scripts.export_graph_to_wiki export-all --verbose

# 4. Index wiki в search
.venv/Scripts/python -m scripts.export_graph_to_wiki index-search

# 5. Start incremental daemon
.venv/Scripts/python -m scripts.export_graph_to_wiki sync-incremental
```

### Post-migration recovery

После dim/model change или DB corruption:

```bash
# 1. Drop wiki_pages_v1 collection
curl -X DELETE http://localhost:6333/collections/wiki_pages_v1

# 2. Full export (idempotent — skip unchanged)
.venv/Scripts/python -m scripts.export_graph_to_wiki export-all --overwrite

# 3. Reindex
.venv/Scripts/python -m scripts.export_graph_to_wiki index-search

# 4. Verify
.venv/Scripts/python -m scripts.export_graph_to_wiki verify
```

### Health check

```bash
# Quick consistency check (no graph changes)
.venv/Scripts/python -m scripts.export_graph_to_wiki verify

# Counts
ls docs/wiki/entities/ | wc -l
curl -s http://localhost:6333/collections/wiki_pages_v1 | \
    jq '.result.points_count'

# DLQ state (если daemon бежит)
wc -l data/wiki_sync_dlq.jsonl 2>/dev/null || echo "(no DLQ)"

# Latest wiki edits
ls -lt docs/wiki/entities/ | head -5

# Latest promotions
head -30 docs/wiki/log.md
```

### Force-rerun promotion

Если синхронизация L2→L5 в Stop-hook пропустила event (timeout, hook disabled):

```bash
# Manual run с verbose
.venv/Scripts/python -m scripts.export_graph_to_wiki promote-patterns --verbose

# С lowered thresholds (для testing на cold corpus)
.venv/Scripts/python -m scripts.export_graph_to_wiki promote-patterns \
    --min-confidence 0.7 \
    --min-usage 0
```

### Cleanup orphan wiki pages

`verify` обнаруживает orphans, но не удаляет. Cleanup:

```bash
# 1. Dump orphan list
.venv/Scripts/python -m scripts.export_graph_to_wiki verify 2>&1 | \
    grep "ORPHAN wiki:" | awk '{print $4}' > /tmp/orphans.txt

# 2. Manual review (опасно — может быть legitimate)
cat /tmp/orphans.txt

# 3. Move в archive (НЕ delete)
mkdir -p docs/wiki/archive/$(date +%Y-%m)/
while read fname; do
    git mv "docs/wiki/entities/$fname" \
           "docs/wiki/archive/$(date +%Y-%m)/$fname"
done < /tmp/orphans.txt

# 4. Commit
git commit -m "chore(wiki): archive $(wc -l < /tmp/orphans.txt) orphan entities"
```

Auto-cleanup (без manual review) — НЕ implemented. Slug может не совпадать с entity name (e.g., entity renamed в graph, но wiki файл остался под старым slug) — ручная проверка обязательна.

## Environment variables

| Variable | Effect |
|---|---|
| `QDRANT__API_KEY` | Picked up by `promote-patterns` если `--qdrant-api-key` не указан |
| `SESSION_MEMORY_NO_PROMOTE=1` | Disable `try_promote_patterns()` в Stop hook (CI / dev без Qdrant) |
| `PYTHONIOENCODING=utf-8` | Force UTF-8 output (используется в pre-commit для `kb_lint_ci.py`) |
| `MEMORY_HOOK_NO_SEMANTIC=1` | Disable semantic retrieval в `memory-first-hook` (включая L3 wiki search) |

## Логи

| Source | Location | Format |
|---|---|---|
| `WikiExporter` | Python logger `pdf_framework.indexing.wiki_exporter` | Standard logging (INFO / WARNING / ERROR) |
| `IncrementalWikiSync` | Python logger, `[INC-SYNC]` prefix | Same |
| `ReverseSyncService` | Python logger, `[REV-SYNC]` prefix | Same |
| `WikiPromoter` | Python logger `pdf_framework.memory.librarian.wiki_promoter` | Same |
| DLQ | `data/wiki_sync_dlq.jsonl` | One JSON object per line: `{entity_id, reason, timestamp}` |
| Promotion log | `docs/wiki/log.md` | Markdown, trimmed to 500 lines |
| MCP audit (если запускается через MCP) | `data/hook-invocations.jsonl` | One JSON per event, `category="mcp_call"` |
