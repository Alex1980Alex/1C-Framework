# 36.1 Autonomous Debug Control — Обзор

## Назначение

Трёхуровневая система автоматизации отладки 1С через wrapper [`tools/bsl-debug-server/mcp_debug_server.py`](../../../tools/bsl-debug-server/mcp_debug_server.py). Цель — **полный контроль результатов работы без ручной синхронизации среды**: Claude Code или CI запускает ОДНУ команду и получает готовое заключение «ready / not ready», «BPs fired / failed», «session metrics» в structured формате.

Система реализована 2026-05-10 как §12 roadmap'а [`260508_ROADMAP_BSL_DEBUG_WRAPPER_POST_BP_HANDSHAKE.md`](../../roadmap/260508_ROADMAP_BSL_DEBUG_WRAPPER_POST_BP_HANDSHAKE.md) после серии live-validations выявивших 5+ implementation gap'ов в RDBG-протоколе на 8.3.27.1936.

## 1. Три уровня контроля

| Level | Цель | API |
|---|---|---|
| **L1** Preflight health-check | «Готова ли среда к debug?» | MCP-tool `debug_health_check(mode, actions?)` |
| **L2** Autonomous E2E runner | «Прогнать сценарий end-to-end без user input» | CLI `python scripts/autonomous_debug_test.py <scenario>` |
| **L3** Post-mortem session summary | «Что произошло в сессии? Регрессии?» | MCP-tool `debug_session_summary(format)` + `debug_session_diff(prev_id)` |

Все 3 уровня **взаимозависимы**: L2 внутри использует L1 (auto-prepare) и L3 (вывод markdown в конце прогона). При этом каждый уровень полезен и **standalone** — L1 для ad-hoc проверки, L3 для аудит-trail в PR-описаниях.

## 3. Что было до vs после

| Аспект | До (manual workflow) | После (autonomous control) |
|---|---|---|
| Проверка готовности среды | 5-7 ручных вопросов user'у (dbgs up? `-debug`? rphost'ы?) | Одна команда `debug_health_check`, ответ за <1с |
| Подготовка среды | User вручную: kill rphost / restart service / set env | `mode=prepare` + whitelist actions, безопасный auto-fix |
| Запуск тестового сценария | Manual: connect → set BP → ask user "Провести" → wait | `python autonomous_debug_test.py <scenario>` — exit code = вердикт |
| Аудит результатов | Свободный пересказ в чате | Structured JSON + готовый Markdown в PR |
| Regression detection | Сравнивать вручную, помнить baseline | `debug_session_diff(prev_id)` — `verdict: REGRESSION/NO_REGRESSION` |
| Воспроизводимость | Требует точных шагов user'a | Scenario JSON в репе → бесконечно повторяется |
