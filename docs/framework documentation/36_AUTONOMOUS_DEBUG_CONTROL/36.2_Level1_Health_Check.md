# 36.2 Level 1 — `debug_health_check`

## Назначение

MCP-tool, выполняющий **8 probes за <1с** и возвращающий K8s-style readiness JSON со статусом каждой проверки + recommended workflow path. Защищает от silent failure: вместо «BP не сработал, разбирайтесь» — заранее говорит «pre-existing rphost есть, recommended: force-recycle» с конкретным `fix:` token'ом для каждой warn'ы.

> **Связано:** [36.1 Обзор](36.1_Обзор.md), [36.6 Диагностика](36.6_Диагностика.md), [16.6 EDT-MCP setup](../16_ПОДКЛЮЧЕНИЕ_1С/16.6_EDT_MCP_setup.md)

---

## 1. API tool

```
mcp__1c-debug__debug_health_check(
    mode: str = "probe",          # "probe" (read-only) | "prepare" (auto-fix)
    actions: list[str] = None,    # required для mode=prepare
) -> str (JSON)
```

### Mode: `probe` (default, безопасный)
Только collects probes, ничего не меняет. Идемпотентный, можно вызывать сколько угодно.

### Mode: `prepare` (требует whitelist actions)
Выполняет **только** actions из whitelist:
- `kill-stale-rphosts` — recycle pre-existing rphost'ов через `_recycle_via_rac` (см. 36.6)
- `restart-ragent` — bounce 1С Server Agent service (требует SDDL grant)

**Никогда автоматически:** modify SDDL / set env vars / install rac.exe — security boundary.

---

## 2. JSON shape (K8s readiness pattern)

```json
{
  "ready": true,
  "version": "mcp_debug_server@2026-05-10",
  "mode": "probe",
  "checks": {
    "dbgs_port_1550": {"status": "pass", "detail": "listening on localhost:1550"},
    "rac_exe_path":   {"status": "pass", "detail": "rac.exe + cluster fb88a5c5…"},
    "ragent_debug_flag": {"status": "pass", "detail": "ragent has -debug -http"},
    "rphost_count_baseline": {
      "status": "warn",
      "detail": "1 pre-existing rphost(s): [39460]",
      "fix": "kill-stale-rphosts (auto-prepare action)"
    },
    "cluster_load":   {"status": "pass", "detail": "all rphost'ы ≤10 connections"},
    "env_vars":       {"status": "pass", "detail": "env: {RAC_CLUSTER_USER:False, ...}"},
    "sddl_au_grant":  {
      "status": "warn",
      "detail": "AU ACE not found — service.restart требует admin",
      "fix": "scripts/grant-1c-debug-permissions.ps1 (run as admin once)"
    },
    "active_session": {"status": "pass", "detail": "no active debug session"}
  },
  "auto_prepare_available": ["kill-stale-rphosts"],
  "recommended_workflow": "force-recycle",
  "elapsed_ms": 627
}
```

`status` enum: `pass | warn | fail`. `fail` блокирует ready=true; `warn` не блокирует, но снижает recommendation.

## 3. 8 probes — что проверяет каждая

| Probe ID | Что | Cost | Результаты |
|---|---|---|---|
| **dbgs_port_1550** | TCP-connect к `localhost:1550` (50ms timeout) | минимальная | `pass` если port listening, `fail` иначе |
| **rac_exe_path** | `_find_rac_exe()` ищет в стандартных путях `1cv8/<version>/bin/rac.exe`; если найден — `rac cluster list` для проверки reachability | низкая | `pass` если rac + cluster, `warn` иначе |
| **ragent_debug_flag** | `Get-CimInstance Win32_Service` parsит `PathName` сервиса «1C:Enterprise 8.3 Server Agent» на `-debug` + `-http` flags | средняя (PowerShell) | `fail` если flags missing → `fix: scripts/enable-1c-server-debug-http.cmd` |
| **rphost_count_baseline** | `tasklist /FI "imagename eq rphost.exe"` count + PIDs | минимальная | `pass` если 0 rphost'ов, `warn` если есть pre-existing (см. 36.6 «pre-existing rphost gap») |
| **cluster_load** | `rac process list` парсит connections-field. Threshold default 10, configurable env `BSL_DEBUG_CONN_THRESHOLD` | средняя | `warn` если есть rphost с >threshold connections (debug может тормозить prod-нагрузку) |
| **env_vars** | Читает `RAC_CLUSTER_USER`, `RAC_CLUSTER_PWD`, `BSL_DEBUG_ALLOW_SERVICE_RESTART` из os.environ. Возвращает `_extras` для использования в `_hc_recommend_workflow` | минимальная | всегда `pass` (информационная) |
| **sddl_au_grant** | `sc.exe sdshow "1C:Enterprise 8.3 Server Agent"` → grep `(A;;LCSWRPWPCR;;;AU)` | средняя | `warn` если AU ACE не выдан → `fix: scripts/grant-1c-debug-permissions.ps1` |
| **active_session** | wrapper-side check: `_client._attached`. Информационный | минимальная | `pass` всегда; в detail — info про текущую session |

## 4. Recommended workflow logic

`_hc_recommend_workflow()` выбирает один из 4 paths на основе probe-results:

```
if dbgs_port_1550.status == "fail":
    → "read-only"               # дeбug невозможен в принципе

elif rphost_count_baseline.status != "warn":
    → "thin-client"             # чистая среда — любой path работает

elif rac_exe_path.status == "pass":
    → "force-recycle"           # Solution A (rac.turn-off, no admin)

elif env_vars[BSL_DEBUG_ALLOW_SERVICE_RESTART] AND sddl_au_grant.status == "pass":
    → "service-restart"         # Solution A2 (Fix #4, кill all rphosts)

else:
    → "thin-client"             # fallback: trigger ТОЛЬКО через UI пользователя
```

## 5. Auto-prepare actions (whitelist)

### `kill-stale-rphosts`

Workflow:
1. `detect_pre_existing_rphosts()` → list of PIDs
2. Если список не пуст — `force_recycle_rphost_processes(pids)` → пробует rac → fallback taskkill
3. Result содержит `method: "rac.turn_off" | "taskkill" | "noop"` для tracing

Результат action добавляется в response `actions_executed: [{action, result}]`.

### `restart-ragent`

Workflow:
1. `_recycle_via_service([])` → PowerShell `Restart-Service "1C:Enterprise 8.3 Server Agent" -Force`
2. Требует либо admin elevation, либо one-time SDDL grant (см. [`scripts/grant-1c-debug-permissions.ps1`](../../../scripts/grant-1c-debug-permissions.ps1))
3. Kills ALL rphosts (invasive — обрывает чужие user sessions)

## 6. Примеры использования

### Из Claude Code (MCP)

```
mcp__1c-debug__debug_health_check
```

### Standalone (Python)

```python
import asyncio, sys, json
sys.path.insert(0, "tools/bsl-debug-server")
import mcp_debug_server as m

raw = asyncio.run(m.debug_health_check())
result = json.loads(raw)
if not result["ready"]:
    print(f"NOT READY. Workflow: {result['recommended_workflow']}")
    for cid, c in result["checks"].items():
        if c["status"] == "fail":
            print(f"  FAIL {cid}: {c['detail']}")
            if "fix" in c:
                print(f"    fix: {c['fix']}")
```

### Auto-prepare workflow

```python
# Probe → если warn'ы есть и доступны auto-prepare actions → execute them
raw = await m.debug_health_check()
result = json.loads(raw)
if result.get("auto_prepare_available"):
    raw = await m.debug_health_check(
        mode="prepare",
        actions=result["auto_prepare_available"],
    )
    # Re-probe automatically inside, returns updated checks + actions_executed
```

## 7. Расширение probes

Чтобы добавить новый probe:

1. Создать функцию `_hc_probe_<name>(...)` → возвращает `dict` с ключами `status`, `detail`, опционально `fix`, `_extras` (для recommend logic)
2. Добавить в `_hc_collect_checks()` новую запись `"<name>": _hc_probe_<name>(...)`
3. (Опционально) обновить `_hc_recommend_workflow()` если probe влияет на workflow recommendation
4. Написать unit-test в `TestHealthCheckProbes` (`tests/test_mcp_debug_server.py`)

## 8. Производительность

| Конфигурация | elapsed_ms (typical) |
|---|---|
| Default 8 probes на dev-машине | 500-800ms |
| Без `cluster_load` (rac unavailable) | 200-400ms |
| `mode=prepare` + `kill-stale-rphosts` (rac path) | +1-2с (turn-off + 3s wait) |
| `mode=prepare` + `restart-ragent` | +5-10с (service restart) |

`probe` mode безопасно вызывать перед каждой debug-операцией — overhead приемлемый для interactive workflow.
