# 36.4 Level 3 — `debug_session_summary` + `debug_session_diff`

## Назначение

Два MCP-tools'а для post-mortem анализа debug-сессии:
- `debug_session_summary(format)` — текущая сессия в JSON, Markdown (готов для PR) или ZIP-артефактный bundle (P1.B)
- `debug_session_diff(prev_session_id, curr_session_id?)` — cross-session diff для regression detection

Tracking pattern (Sentry breadcrumbs / OpenTelemetry spans): append-only счётчики в `RDBGClient.__init__()`, инкрементятся в hook'ах существующих методов (`callStackFormed`, `eval_expression`, `_ui_plus_recover_and_retry`, `debug_connect.force_recycle`). Auto-mirror в `data/debug_sessions/<id>.json` при каждом вызове summary.

> **Связано:** [36.3 Level 2 Autonomous Runner](36.3_Level2_Autonomous_Runner.md), [36.5 Workflows](36.5_Workflows.md)

---

## 1. `debug_session_summary` API

```
mcp__1c-debug__debug_session_summary(
    format: str = "json",           # "json" | "markdown" | "artifacts"
) -> str
```

При отсутствии активной session — `{"status": "no_session"}`.

### JSON формат

```json

  "session_id": "72995821-…",
  "started_at": "2026-05-10T17:25:11.123456",
  "infobase_alias": "ИБTransportManagementDevelop",
  "attached": true,
  "breakpoints": {
    "set_count": 3,
    "fire_count": 3,
    "by_location": {
      "9c496dda-…:141": 1,
      "9c496dda-…:145": 1,
      "0d22c470-…:208": 1
    },
    "fire_rate": 1.0
  },
  "evaluations": {
    "count": 4,
    "failures": 0,
    "errors": []
  },
  "ui_plus_retries": 0,
  "recycle": {
    "force_invoked": true,
    "method_used": "rac.turn_off"
  },
  "stop_events": [
    {"ts": "…", "target_id": "7242abf0-…", "lineNo": "141", "reason": "breakpoint"},
    {"ts": "…", "target_id": "7242abf0-…", "lineNo": "145", "reason": "breakpoint"},
    {"ts": "…", "target_id": "7242abf0-…", "lineNo": "208", "reason": "breakpoint"}
  ],
  "rphosts_seen": ["7242abf0-…"]

```

### Markdown формат (для PR-описаний)

```markdown

- Infobase: **ИБTransportManagementDevelop**
- BPs: **3 set, 3 fired** (100% fire rate)
```

Копируется в комментарий PR/issue/baga — дает фактологию без пересказа.

## 2. Что трекается (поля в `RDBGClient.__init__`)

| Поле | Где инкрементится | Зачем |
|---|---|---|
| `_session_started_at` | `__init__` (datetime.now) | Session timestamp |
| `_bp_set_count` | Derived от `_set_breakpoints_cache` (len of all lines) | Total BPs зарегистрировано |
| `_bp_fire_count` | `_handle_command` callStackFormed когда `stopByBP=true` | Сколько раз stop по BP |
| `_bp_by_location` | Same handler, key = `f"{obj_id}:{lineNo}"` | Карта fire-distribution |
| `_eval_count` | `eval_expression` entry | Total eval-вызовов |
| `_eval_failures` | (зарезервировано — пока не инкрементится; future) | Eval'ы вернувшие withErrors |
| `_eval_errors` | (зарезервировано) | Last 10 error strings |
| `_ui_plus_retry_count` | `_ui_plus_recover_and_retry` start | Сколько раз UI+ контекст revoke'нулся |
| `_recycle_method_used` | `debug_connect` force_recycle path → `kill_result.method` | "rac.turn_off" / "taskkill" / "service.restart" / None |
| `_force_recycle_invoked` | `debug_connect` когда `force_recycle_rphost=True` + есть pre-existing | Флаг что recycle path был использован |
| `_stop_events` | `_handle_command` callStackFormed (append всегда) | Полный таймлайн stop-events с timestamps |
| `_rphosts_seen` | Same handler (set, додобавляет target_id) | Уникальные target'ы в session |

## 3. File mirror — `data/debug_sessions/<id>.json`

При каждом вызове `debug_session_summary` — JSON-snapshot пишется в `data/debug_sessions/<session_id>.json` (auto-create dir). Это нужно для:
- Cross-session diff (`debug_session_diff` загружает по ID)
- Постмортем анализа после wrapper restart (counters в process — теряются)
- CI artifact'ы: один файл на каждый прогон, можно diff между ними

`_persist_session_summary(summary)` graceful: возвращает `None` при OSError, не блокирует summary call.

## 4. `debug_session_diff` API

```
mcp__1c-debug__debug_session_diff(
    prev_session_id: str,                    # baseline UUID
    curr_session_id: str = None,             # comparison (default: current active)
) -> str
```

Диагностика: `prev` — «эталонная» session (например saved CI baseline), `curr` — новая (после правок). Сравнивает counters → возвращает `verdict: REGRESSION | NO_REGRESSION` + конкретные deltas.

### Output

```json
{
  "prev_session": "abc12345-…",
  "curr_session": "def67890-…",
  "regression_indicators": [
    "BP fire_count regressed: -1",
    "eval failures increased: +2"
  ],
  "deltas": {
    "bp_set_count": 0,
    "bp_fire_count": -1,
    "eval_count": 3,
    "eval_failures": 2,
    "ui_plus_retries": 0,
    "stop_events_count": -1
  },
  "verdict": "REGRESSION"
}
```

### Triggers для `REGRESSION` verdict

| Условие | Indicator |
|---|---|
| `bp_fire_count` уменьшился | `BP fire_count regressed: -N` |
| `eval_failures` увеличились | `eval failures increased: +N` |
| `ui_plus_retries` увеличились | `UI+ retries increased: +N` |

`bp_set_count` delta не считается регрессией — может вырасти из-за добавления BPs в новых тестах.

## 5. Workflow: regression hunt с `debug_session_diff`

```bash
# Step 1 — baseline на main branch
git checkout main
python scripts/autonomous_debug_test.py scripts/scenarios/post_lab_doc.json
# → копируем session_id из output (Phase 5 markdown)
BASELINE_ID=72995821-…

# Step 2 — переключаемся на feature branch
git checkout feature/my-changes
python scripts/autonomous_debug_test.py scripts/scenarios/post_lab_doc.json
# → автоматически persistит data/debug_sessions/<new_id>.json
NEW_ID=def67890-…

# Step 3 — diff (через MCP-tool из Claude Code)
# mcp__1c-debug__debug_session_diff(prev_session_id=BASELINE_ID, curr_session_id=NEW_ID)
# → если verdict=REGRESSION — точное указание что именно деградировало
```
