# 36.6 Диагностика и известные ограничения

## Назначение

Каталог типичных ошибок при использовании autonomous debug control + sanctioned обходные пути. Разбит по уровням (L1/L2/L3) и категориям (env / RDBG protocol / wrapper).

> **Связано:** [36.5 Workflows](36.5_Workflows.md), [16.6 EDT-MCP setup](../16_ПОДКЛЮЧЕНИЕ_1С/16.6_EDT_MCP_setup.md), [Roadmap §10/§11/§12](../../roadmap/260508_ROADMAP_BSL_DEBUG_WRAPPER_POST_BP_HANDSHAKE.md)

## 1. L1 — `debug_health_check` ошибки

| Probe fails / warns | Причина | Решение |
|---|---|---|
| `dbgs_port_1550 fail` | dbgs.exe не запущен или ragent без `-debug -http` | `scripts/enable-1c-server-debug-http.cmd` (admin) — добавляет flags + restart service |
| `ragent_debug_flag fail` | binPath сервиса без `-debug` или `-http` | То же — `enable-1c-server-debug-http.cmd` |
| `rphost_count_baseline warn` | Есть pre-existing rphost'ы alive до `debug_connect` | Auto-prepare action `kill-stale-rphosts` ИЛИ scenario с `force_recycle: true` |
| `rac_exe_path warn` | rac.exe не найден в стандартных путях | Установить полную платформу 1С (rac.exe идёт в комплекте); пути в `_RAC_BIN_CANDIDATES` |
| `cluster_load warn` | Один rphost обрабатывает >10 connections | Увеличить threshold через `BSL_DEBUG_CONN_THRESHOLD=20` ИЛИ дождаться low-load окна (debug снизит throughput) |
| `sddl_au_grant warn` | `Restart-Service` требует admin (нет AU ACE) | One-time admin: `.\scripts\grant-1c-debug-permissions.ps1` (выдаёт current user право Start/Stop без UAC) |
| `mode=prepare` без actions → error | Защита от accidental auto-fix | Всегда передавать `actions=[...]` явно (whitelist: `kill-stale-rphosts`, `restart-ragent`) |
| `mode=prepare` action=что-то-другое → "rejected" | Action не в whitelist | Только 2 разрешённых: `kill-stale-rphosts`, `restart-ragent` |

## 2. L2 — `autonomous_debug_test.py` exit codes

| Exit | Причина | Что делать |
|---|---|---|
| **0** OK | Все BPs fired + inspections passed | Можно мержить |
| **2** | Scenario file не найден | Проверить путь |
| **9** EXIT_SCHEMA_INVALID | JSON не прошёл validator | Stderr содержит список errors с путями (`$.iis.url is required`); поправить |
| **10** EXIT_HEALTH_FAILED | После health_check + auto-prepare ready=false | Прочитать checks → найти `fail` probe → manual fix |
| **11** EXIT_CONNECT_FAILED | `debug_connect` вернул не "connected" (например `ibInDebug` — другой debugger держит UI) | Закрыть EDT debug session или другой Claude debug; retry |
| **12** EXIT_BP_TIMEOUT | BP не fired в `stop_timeout_sec` | См. §3 ниже — самый частый случай |
| **13** EXIT_INSPECTION_FAILED | BPs fired но какая-то inspection не прошла assertion | Прочитать stdout — конкретная expr + detail; поправить scenario или код |
| **14** EXIT_BSL_TRIGGER_FAILED | IIS POST вернул не-200 | Проверить env vars `MCP_ONEC_USERNAME`/`MCP_ONEC_PASSWORD`; URL в scenario |

## 3. EXIT_BP_TIMEOUT — частые причины

> **Roadmap 260511 update (2026-05-11):** добавлен **`no_fire_diagnostics`** auto-surface в `debug_ping` после 3 consecutive empty pings (§P0.6). Wrapper автоматически детектит RC1 (alias mismatch) + RC2 (rphost не attached) + suggests конкретные fix paths. До §P0.6 это требовало 5+ ручных проверок. Пример output ниже в §3.0.

### 3.0 `no_fire_diagnostics` — auto-detect output (§P0.6)

После 3 consecutive `debug_ping` с `events: []` — wrapper автоматически добавляет в response блок `no_fire_diagnostics`:

```json
{
  "events": [],
  "count": 0,
  "no_fire_diagnostics": {
    "consecutive_empty_pings": 3,
    "infobase_alias": "TestDB",
    "session_id": "...",
    "targets_attached": 0,
    "infobase_validation": {
      "status": "invalid",
      "available": ["ИБTransportManagementDevelop", "260507_DEV_ATERLETSKIY_53196"]
    },
    "active_rphost_pids": [57724],
    "suggestions": [
      "RC1: infobase_alias 'TestDB' NOT in cluster. Available: [...]. Reconnect with valid alias.",
      "RC2: rphost'ы запущены но НЕ attached к debug session. Try: reconnect с recycle_strategy='all_rphosts_of_ib' или debug_launch_thin_client после connect (Solution C)."
    ]
  }
}
```

| Симптом suggestion | Что делать |
|---|---|
| `RC1: infobase_alias '<X>' NOT in cluster` | Использовать имя из `available[]` или env mapping `DEBUG_INFOBASE_ALIASES="Short:Long"` (§P0.7) |
| `RC2: rphost'ы запущены но НЕ attached` | `debug_disconnect` + `debug_connect(recycle_strategy="all_rphosts_of_ib")` (§P0.2) или `debug_launch_thin_client` (§P0.5) для UI-trigger Solution C |
| `No rphosts running — trigger BSL via execute_code` | Spawn'нуть rphost: либо `execute_code` через `1c-mcp-crud`, либо UI action в thin client |

### 3.1 Pre-existing rphost invisible (Roadmap §10 gap)

**Симптом:** `force_recycle: false`, IIS-trigger через 1c-mcp-crud, BP timeout.

**Причина:** rphost обслуживающий IIS-сервис уже работает ДО `debug_connect`. RDBG не может retroactively attach его. `setAutoAttachSettings` filter применяется только к **новым** rphost'ам, регистрирующимся после.

**Solutions:**
| Path | Когда |
|---|---|
| **A: force_recycle через rac** | dev-окружение; передать `"force_recycle": true` в scenario; auto pre_trigger_wait=5s |
| **B: thin-client trigger** | если есть запущенный 1cv8c.exe — попросить user'а сделать действие в UI |
| **C: service restart** | `scripts/grant-1c-debug-permissions.ps1` (one-time) + env `BSL_DEBUG_ALLOW_SERVICE_RESTART=true` + `mode=prepare actions=[restart-ragent]` |

### 3.2 Fix #1 regression — auto-attach filter rejected

**Симптом:** `setAutoAttachSettings` HTTP 400 «Несоответствие свойства targetType», все BPs не fire.

**Причина (исторически):** ранее default filter содержал значения `[HTTPService, WebService, BackgroundJob]` которые НЕ valid в RDBG XSD на 8.3.27.1936.

**Решение:** Fix откатан 2026-05-10 — default снова `[Server, ManagedClient]`. Если видите эту ошибку — `pull` свежий wrapper.

### 3.3 Multi-BP cache replace (Fix #5)

**Симптом:** Поставил 3 BPs, fired только последний.

**Причина:** RDBG `setBreakpoints` REPLACES workspace для (module, property) пары при каждом вызове. До Fix #5 wrapper отправлял single-BP per call → перезапись.

**Решение:** Fix #5 уже применён — wrapper aggregate'ит cache. Проверь что `debug_get_breakpoints` возвращает entries с merged lines (например `lines: [141, 145]` для одного модуля), а НЕ 3 separate entries с одной line каждый.

### 3.4 Timing race после force_recycle

**Симптом:** `force_recycle: true` + `pre_trigger_wait_sec: 0`, BP timeout.

**Причина:** trigger пришёл ДО того как fresh rphost'ы зарегистрировались с dbgs (race window).

**Решение:**
- Default `pre_trigger_wait_sec: null` → auto = 5s если force_recycle. Не переопределять в 0 без причины.
- Если 5s мало — увеличить до 10s в scenario JSON.

### 3.6 Conditional BP не fire'ит / fire'ит без остановки

**Симптом:** `debug_set_breakpoint(condition="Сумма > 1000")` — BP зарегистрирован, execution проходит через строку, но `callStackFormed` не приходит.

**Причины и решения:**

| Причина | Диагностика | Решение |
|---|---|---|
| Синтаксическая ошибка BSL в `condition` | RDBG тихо игнорирует invalid condition → BP fire'ит на каждой итерации | Проверить condition через `debug_evaluate(condition_expr)` в момент другого останова; исправить синтаксис |
| Переменная не в scope на данной строке | `condition` ссылается на переменную, объявленную ниже или в другом контексте | Использовать `debug_variables` перед постановкой BP — убедиться что переменная видна на выбранной строке |
| `condition` и `hit_condition` перепутаны | `hit_condition=">5"` проверяет счётчик срабатываний wrapper'ом; `condition` — RDBG-native BSL-выражение | `condition` — строка BSL (eval в 1С); `hit_condition` — DAP синтаксис (`>N`, `%N`, `=N`) |
| `hit_condition` counter сбрасывается при HMR-restart | Python wrapper теряет `_bp_hit_counters` при перезапуске | После HMR-reload поставить BP заново; counter начнётся с 0 |
| Conditional BP на pre-existing rphost | RDBG не attach'ит pre-existing rphost — condition даже не вычисляется | `force_recycle_rphost=True` или JOB-based execution (Шаблон 6) |

**Быстрая диагностика:**
```
# Временно убрать condition — проверить что BP вообще fire'ит
debug_set_breakpoint(object_id=..., line=42)   # без condition
# Если fire'ит → condition содержит ошибку или переменная не в scope
# Если не fire'ит → проблема в attach, не в condition (см. §3.1/§3.2)
```

**`hit_condition` trace:** логируется в `data/debug_logs/<session>.jsonl` с `hit_count` полем — можно посмотреть сколько раз BP действительно fire'ил до выполнения условия.

### 3.5 IIS routing на «не тот» rphost

**Симптом:** force_recycle сработал, fresh rphost'ы есть, но IIS-trigger всё равно не попадает на attached target.

**Причина:** IIS-сервис может маршрутизироваться на OTHER rphost (не тот, что мы attached'или). RDBG-протокол не предоставляет способа предсказать routing.

**Workaround:** использовать thin-client trigger (Solution C) — там session bound к конкретному rphost'у; ИЛИ kill ВСЕ rphost'ы (через `restart-ragent`) и убедиться что после restart есть только один rphost обслуживающий ВСЁ.

## 4. RDBG protocol — известные ограничения

| Limitation | Source | Impact |
|---|---|---|
| Только один Debug UI на инфобазу | kb.1ci.com §32.2.2 | Закрыть EDT debug ПЕРЕД `debug_connect`; иначе `ibInDebug` (read-only) |
| `setAutoAttachSettings` filter применяется на регистрации rphost'a | Reverse-engineered yukon39 + ITS edtdoc/t000068 | Pre-existing rphost'ы invisible — нужен force_recycle |
| `setBreakOnNextStatement` работает только для attached targets | Live test 2026-05-10 | НЕ catches pre-existing rphost'ы (`debug_break_on_next` MCP tool ограничен) |
| `setBreakpoints` REPLACES workspace per (module, prop) | Live test 2026-05-10 | Wrapper aggregate'ит cache (Fix #5); НЕ ставить BPs через прямой RDBG client'ом без aggregation |
| `targetType` XSD enum ограничен `[Server, ManagedClient, ...]` | Live test 2026-05-10 | НЕ передавать HTTPService/WebService/BackgroundJob в `target_types` |
| `getDbgAllTargetStates` без targetID → HTTP 400 | Live test 2026-05-09 | Wrapper делает session-state локально (см. `debug_target_state` impl) |
| UI+ context может revoke между операциями | Live test 2026-05-10 | Wrapper auto-retry с re-handshake (`_ui_plus_recover_and_retry`); session_summary tracking `ui_plus_retries` count |
| **HTTPService warm-pool rphost BP-fire** (vendor ceiling) | RDBG XSD analysis + yukon39 confirmation + [1c-dn forum Vladimir Gurov, 1С](https://1c-dn.com/forum/forum1/topic2025/) | Pre-existing rphost handling `1c-mcp-crud:execute_code` invisible — нет `attach-by-PID` в RDBG protocol. Workarounds: `force_recycle_rphost=True` (kills user sessions), `debug_launch_thin_client` (UI), `iisreset` (admin), либо JOB-based execution proposal (см. [36.8 §10](36.8_Advanced_Debug_Features.md#10-known-limit--httpservice-warm-pool-bp-fire)). Vendor planning fix in future EDT release. |

## 5. Wrapper-специфичные ошибки

### 5.1 `Z.AI WRITE GUARD` блокирует edit

**Симптом:** при работе с большими (>15 строк) Edit'ами на Python-файле hook блокирует.

**Решение:** разбить на несколько меньших Edit'ов; либо делегировать через `mcp__llm-rotation__llm_complete`.

### 5.2 `RuntimeError: Event loop is closed`

**Симптом:** при попытке нескольких `asyncio.run()` подряд в одном Python-процессе.

**Причина:** httpx закрывает connections async, но event loop уже закрыт.

**Решение:** одна `asyncio.run()` per process; внутри — `async def` с многими `await`.

### 5.3 Кракозябры в выводе (cp866 / cp1251)

**Симптом:** русский текст в RDBG-ошибках выводится как `﻿<?xml...` или non-printable.

**Причина:** `subprocess.run(text=True)` использует system locale; в Windows often cp866.

**Решение:** wrapper уже использует utf-8 для RDBG body parsing. Для PowerShell subprocess в helpers — phantom warning, не функциональная проблема.

## 6. Performance / overhead

| Operation | Typical latency | Note |
|---|---|---|
| `debug_health_check` (probe) | 500-800ms | 8 probes; cluster_load занимает ~200ms |
| `debug_health_check` (prepare + kill-stale) | +1-2s | rac turn-off + 3s wait |
| `debug_health_check` (prepare + restart-ragent) | +5-10s | service restart |
| `debug_connect` | 300-500ms | + handshake (initSettings, clearBreakOnNextStatement, setAutoAttachSettings) |
| `debug_set_breakpoint` | 50-100ms | per call (wrapper aggregates internally) |
| `debug_evaluate` (sync result) | 100-300ms | depends on expression complexity |
| `debug_evaluate` (async via exprEvaluated event) | up to 10s timeout | для сложных типов |
| `debug_session_summary` | <50ms | + ~10ms persist to JSON file |
| `debug_session_diff` | <100ms | загрузка 2 JSON + сравнение |
| L2 full scenario (3 BPs) | 30-60s | + force_recycle adds 5-10s |

## 8. Когда позвать человека (escalation criteria)

| Symptom | Что сделать |
|---|---|
| L1 ready=false и ВСЕ probes fail (даже dbgs_port) | dbgs.exe не запущен в принципе; нужен manual restart 1С Server Agent + проверка Windows Services |
| L2 exit 11 (ibInDebug) | другой Debug UI держит инфобазу; manual: закрыть EDT/Конфигуратор debug-сессию |
| `force_recycle` сработал но fresh rphost'ы НЕ появляются | Cluster может быть в degraded state; рестарт 1С Server Agent service полностью |
| `cluster_load warn` с десятками connections на rphost | Production-нагрузка; debug отложить; либо использовать read-only `debug_target_state` без BPs |
| Reproducible regression в `debug_session_diff` | Разобрать root cause через manual debug; обновить scenario с дополнительными inspections |
