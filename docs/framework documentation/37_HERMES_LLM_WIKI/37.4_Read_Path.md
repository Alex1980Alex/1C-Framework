# 37.4 Read Path — как происходит чтение через 5 слоёв

> При каждом UserPromptSubmit фреймворк параллельно ищет в L1-L4 и сливает результаты через RRF. L0 не читается напрямую (raw layer для re-indexing only).

## Pipeline целиком

```
User → "найди как работает hybrid search"
           │
           ▼
.claude/hooks/memory-first-hook.py (UserPromptSubmit)
           │
           ├─[parallel fetch]─►  L1: SQLite memory_ai.db
           │                      mcp__memory-ai__search_messages(query, limit=10)
           │                      → episodic context (last 30-90 days)
           │
           ├─[parallel fetch]─►  L2: Qdrant learned_patterns
           │                      mcp__vector-memory__search_patterns(query, limit=20)
           │                      → semantic patterns (confidence-weighted)
           │
           ├─[parallel fetch]─►  L3: docs/wiki/drafts/ + docs/wiki/entities/
           │                      search_wiki(query_tokens, limit=10)
           │                      → token-overlap + opt-in semantic
           │
           ├─[parallel fetch]─►  L4: Qdrant multi-collection
           │                      mcp__memory-orchestrator__unified_search(query, limit=20)
           │                      → wiki_pages_v1 / framework_code_v1 / bsl_code_v4_late
           │                      → graph_embeddings (LightRAG entities)
           │
           ▼
RRF fusion (k=60, weights L1=0.30, L2=0.35, L3=0.15, L4=0.20)
           │
           ▼
top-10 items → systemMessage context injection
           │
           ▼
Claude получает обогащённый prompt и отвечает
```

## memory-first-hook.py — детально

[`.claude/hooks/memory-first-hook.py`](../../../.claude/hooks/memory-first-hook.py) — UserPromptSubmit hook регистрируется в [`.claude/settings.json`](../../../.claude/settings.json) с timeout 30s.

### Логика hook'а

```python
# .claude/hooks/memory-first-hook.py (упрощённо)

WIKI_DIR = PROJECT_ROOT / "docs" / "wiki"
SEARCH_LIMIT_PER_LAYER = 10
RRF_K = 60
WEIGHTS = {"L1": 0.30, "L2": 0.35, "L3": 0.15, "L4": 0.20}


async def execute(stdin: dict) -> dict:
    user_prompt = stdin["prompt"]
    query_tokens = set(tokenize(user_prompt))

    # Параллельный fetch
    results = await asyncio.gather(
        search_episodic(user_prompt),       # L1
        search_patterns(user_prompt),        # L2
        search_wiki(query_tokens),           # L3
        search_md(user_prompt),              # L4 (через unified_search)
        return_exceptions=True,
    )
    l1, l2, l3, l4 = results

    # RRF fusion
    fused = rrf_fuse(
        layers={"L1": l1, "L2": l2, "L3": l3, "L4": l4},
        weights=WEIGHTS,
        k=RRF_K,
    )

    # systemMessage injection
    if fused:
        return {
            "hookSpecificOutput": {
                "hookEventName": "UserPromptSubmit",
                "additionalContext": format_context(fused[:10]),
            }
        }
    return {}


def rrf_fuse(layers: dict[str, list], weights: dict[str, float], k: int) -> list:
    scores = defaultdict(float)
    for layer_name, items in layers.items():
        if isinstance(items, Exception):
            continue  # Graceful degradation
        weight = weights[layer_name]
        for rank, item in enumerate(items, start=1):
            scores[item.id] += weight / (k + rank)
    return sorted(scores.items(), key=lambda x: -x[1])
```

### L3 search_wiki()

```python
def search_wiki(query_tokens: set[str], limit: int = 10) -> list[WikiHit]:
    """Token-overlap search across docs/wiki/drafts/ + entities/."""
    hits = []
    for md_path in WIKI_DIR.rglob("*.md"):
        # Skip templates, log, schema
        if md_path.name in {"SCHEMA.md", "log.md", "_index.md"}:
            continue
        if "templates" in md_path.parts:
            continue

        content = md_path.read_text(encoding="utf-8", errors="replace").lower()
        content_tokens = set(tokenize(content))
        overlap = query_tokens & content_tokens

        if overlap:
            score = len(overlap) / len(query_tokens)
            hits.append(WikiHit(path=md_path, score=score, overlap=overlap))

    return sorted(hits, key=lambda h: -h.score)[:limit]
```

**Semantic fallback** (через obsidian-mcp + Qdrant `wiki_pages_v1`) — opt-in через переменную окружения, не используется по умолчанию (slower, требует obsidian server running).

## Graceful degradation

Если **любой слой падает** (Qdrant down, SQLite locked, MCP server unreachable):
- `asyncio.gather(..., return_exceptions=True)` ловит исключение
- RRF skip'ает упавший layer (его веса фактически перераспределяются на остальные)
- Hook возвращает результаты из доступных слоёв

**Полная failure mode** (все 4 слоя упали) — hook возвращает пустой context, Claude работает без обогащения (zero context от memory layers, но прочая context-машинерия — CLAUDE.md, MEMORY.md — продолжает работать).

## Latency budget

| Слой | Typical latency | Max budget | Backend |
|---|---|---|---|
| L1 SQLite | 5-15ms | 50ms | Local file, mcp__memory-ai |
| L2 Qdrant patterns | 30-80ms | 200ms | Local Qdrant Docker |
| L3 Wiki token-overlap | 10-100ms | 300ms | Filesystem scan, opt-cached |
| L4 Qdrant multi-collection | 100-300ms | 500ms | TEI embedding + 3-5 collection search |
| **RRF fusion** | < 5ms | 10ms | In-process |
| **Total parallel** | 100-300ms | **< 1s** | (max-budget driven by slowest) |

Hook timeout в settings.json — 30s, реально работает в 100-300ms на warm cache.

## RRF weights — обоснование

| Layer | Weight | Почему |
|---|---|---|
| **L1 episodic** | 0.30 | Recent context критичен (что user'обсуждали в этой сессии). Volatile, но точный |
| **L2 patterns** | **0.35** | Доминирующий — это место где живут learned facts, confidence-weighted, наиболее accurate |
| **L3 wiki** | 0.15 | Narrow but high-precision; пока wiki молодая, мало entries (3 073 точки); вес может расти |
| **L4 indexes** | 0.20 | Wide recall — много коллекций (code, BSL, PDF), но meta-level (`framework_code_v1` показывает где код, не сами решения) |

Веса в `.claude/hooks/memory-first-hook.py` — не хардкод, можно тюнить через env: `MEMORY_HOOK_WEIGHTS_L1=0.25 ...` (опционально, default — code constant).

## Tools для запроса напрямую

Если нужно обойти hook (debugging, exploratory):

```python
# L1
mcp__memory-ai__search_messages(query="...", limit=10)
mcp__memory-ai__get_important_messages(limit=5)

# L2
mcp__vector-memory__search_patterns(query="...", limit=20)
mcp__vector-memory__get_pattern(pattern_id="...")

# L3 (через obsidian-mcp когда server running)
mcp__obsidian-mcp__obsidian_simple_search(query="...")
mcp__obsidian-mcp__obsidian_complex_search(filters=...)

# L4
mcp__memory-orchestrator__unified_search(query="...", targets=["wiki","graph","patterns"])
mcp__memory-orchestrator__get_related(unified_id="...", depth=2)
```

## Antipatterns

| Плохо | Почему | Как правильно |
|---|---|---|
| Запрашивать только L4 для контекста сессии | L1 episodic покрывает recent, не нужен embedding | Используй memory-first-hook (он сам все слои опросит) |
| Игнорировать L3 wiki в production lookup | L3 = canonical, должен иметь preference over L2 при тех же score | RRF weights уже учитывают; не override руками |
| RRF k=10 вместо 60 | Слишком жёсткий cutoff long-tail | k=60 (industry default, well-tested) |
| Запрашивать каждый слой sequentially | 4× latency vs parallel | `asyncio.gather` (уже в hook'е) |
