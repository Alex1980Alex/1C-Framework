# 37.5 Write Path и Promotion — как знания попадают в L3

> При каждом Stop event происходит capture L1+L2, а periodic'но (после каждой N сессий) — L2 → L3 промоция. Reverse sync обеспечивает что edits в wiki синхронизируются с graph.

## Полный pipeline

```
Session ends → Stop hook fires
       │
       ├──► session-memory-save.py
       │       │
       │       ├──► save_session_to_sqlite(L1)
       │       │       └─ data/memory_ai.db
       │       │
       │       ├──► capture_patterns_to_qdrant(L2)
       │       │       └─ mcp__skill-learning__capture_pattern
       │       │       └─ Qdrant learned_patterns
       │       │
       │       └──► try_promote_patterns()        ←─── L2 → L3 trigger
       │               │ subprocess timeout 4s
       │               │ opt-out SESSION_MEMORY_NO_PROMOTE=1
       │               │
       │               └──► python -m scripts.export_graph_to_wiki promote-patterns
       │                       │
       │                       └──► WikiPromoter.scan_and_promote()
       │                               │
       │                               ├──► filter: confidence>=0.8, application_count>=5
       │                               ├──► unified_search: cosine>=0.85 → ConflictResolver
       │                               ├──► MemoryCube.to_wiki_page()
       │                               ├──► write docs/wiki/drafts/<slug>.md
       │                               ├──► link_registry.create_link(PROMOTED_TO)
       │                               └──► event_bus.publish("wiki.promoted")
       │
       └──► docs-change-tracker.py (PostToolUse on new .md в wiki)
               │
               └──► kb-lint validation + auto-index to Qdrant wiki_pages_v1
```

## L2 capture (autonomous)

**Trigger:** при каждом успешном применении skill / решении задачи.

**Mechanism:**

```python
# В skill-learning MCP server / Stop hook
await mcp__skill-learning__capture_pattern(
    title="OAuth wrapper async migration",
    content="...",
    confidence=0.5,           # initial moderate confidence
    tags=["oauth", "async", "refactor"],
    source="session-2026-05-15-hermes-sprint",
)
```

После каждого successful apply:
```python
await mcp__vector-memory__apply_pattern(pattern_id="...", success=True)
# Internally: confidence += 0.02 (clamp [0, 1]); application_count += 1
```

После каждого failed apply:
```python
await mcp__vector-memory__apply_pattern(pattern_id="...", success=False)
# Internally: confidence -= 0.01; application_count += 1
```

**Decay**: `mcp__vector-memory__decay_confidence` запускается периодически (cron) — паттерны, давно не применявшиеся, теряют 0.05 confidence per week.

## L2 → L3 promotion (auto-librarian)

### Trigger

`session-memory-save.py:try_promote_patterns()` — subprocess вызов с timeout 4s, swallow errors, opt-out через `SESSION_MEMORY_NO_PROMOTE=1`.

```python
def try_promote_patterns(session_id: str) -> None:
    """Best-effort L2→L3 promotion after session save. Never blocks Stop."""
    if os.getenv("SESSION_MEMORY_NO_PROMOTE") == "1":
        return
    try:
        subprocess.run(
            [sys.executable, "-m", "scripts.export_graph_to_wiki", "promote-patterns"],
            timeout=4.0,
            check=False,  # swallow errors
            cwd=PROJECT_ROOT,
        )
    except subprocess.TimeoutExpired:
        pass  # Acceptable — promotion is best-effort
    except Exception:
        pass  # Audit-only logging if needed
```

### Promotion logic ([wiki_promoter.py](../../../src/memory/librarian/wiki_promoter.py))

```python
class WikiPromoter:
    """Thin wrapper над существующими memory компонентами."""

    async def scan_and_promote(
        self,
        confidence_threshold: float = 0.8,
        usage_threshold: int = 5,
    ) -> PromotionResult:
        # Step 1: Query candidates from L2
        candidates = await self.vector_memory.search_patterns(
            filter={
                "confidence__gte": confidence_threshold,
                "application_count__gte": usage_threshold,
            },
            limit=50,
        )

        promoted = []
        conflicts = []

        for pattern in candidates:
            # Step 2: Deduplication check
            existing = await self.orchestrator.unified_search(
                query=pattern.content,
                targets=["wiki"],
                limit=3,
            )

            if existing and existing[0].similarity >= 0.85:
                # Step 3: Conflict resolution
                resolved = await self.conflict_resolver.resolve(
                    existing=existing[0],
                    incoming=pattern,
                    strategy=ConflictStrategy.SOURCE_PRIORITY,
                )

                if resolved.action == "supersede":
                    await self.link_registry.create_link(
                        from_id=pattern.id,
                        to_id=existing[0].id,
                        link_type=LinkType.SUPERSEDED_BY,
                    )
                    conflicts.append(pattern.id)
                    continue

            # Step 4: Promote — pattern → MemoryCube → markdown
            cube = MemoryCube.from_pattern(pattern)
            cube.content_type = ContentType.WIKI
            slug = slugify(pattern.title, max_len=50)
            draft_path = WIKI_DIR / "drafts" / f"{slug}.md"

            markdown = cube.to_wiki_page()
            draft_path.write_text(markdown, encoding="utf-8")

            # Step 5: Link tracking
            await self.link_registry.create_link(
                from_id=pattern.id,
                to_id=f"wiki:{draft_path.relative_to(PROJECT_ROOT)}",
                link_type=LinkType.PROMOTED_TO,
            )

            # Step 6: Event for downstream
            await self.event_bus.publish("wiki.promoted", {
                "pattern_id": pattern.id,
                "draft_path": str(draft_path),
                "confidence": pattern.confidence,
                "application_count": pattern.application_count,
            })

            promoted.append(pattern.id)

        return PromotionResult(promoted=promoted, conflicts=conflicts)
```

### Conflict resolution strategies

[`ConflictResolver`](../../../src/memory/orchestrator/infrastructure/conflict_resolver.py) поддерживает:

- **SOURCE_PRIORITY** (default для wiki) — wiki entries trumps patterns (entries уже promoted earlier, считаются canonical)
- **HIGHEST_CONFIDENCE** — выигрывает более уверенный
- **NEWEST** — выигрывает по timestamp
- **MERGE** — комбинирует content (используется редко, требует LLM merge call)

### Schema validation (kb-lint)

После создания draft в `docs/wiki/drafts/<slug>.md` срабатывает pre-commit hook (или [`docs-change-tracker.py`](../../../.claude/hooks/docs-change-tracker.py) PostToolUse):

```bash
# Запускается автоматом
python scripts/kb_lint_ci.py docs/wiki/drafts/<slug>.md
```

Проверяет:
- YAML frontmatter присутствует и валиден (`unified_id`, `source`, `created_at`, `tags`)
- Filename Cyrillic-safe (есть monkey-patch для `kb_lint.fixer.fix_filename_casing`)
- `[[wiki-link]]` targets существуют
- Markdown lint правила (MD013 line length disabled, MD012 multiple blank lines)

Если invalid → draft помечается `status: needs_review` в frontmatter и не индексируется в Qdrant до исправления.

if file_path.startswith("docs/wiki/") and file_path.endswith(".md"):

## Wiki → Graph reverse sync

### Назначение

Если пользователь редактирует `docs/wiki/entities/<id>.md` (через Obsidian, IDE, или `Edit` tool), эти изменения должны отразиться в LightRAG entity graph.

### Mechanism ([`ReverseSyncService`](../../../src/pdf_framework/indexing/wiki_exporter.py))

```python
class ReverseSyncService:
    """Watchdog для docs/wiki/entities/ → graph sync."""

    def __init__(self, graph_store, dlq_path: Path):
        self._observer = Observer()
        self._graph = graph_store
        self._dlq = dlq_path  # dead-letter queue for failed parses

    def start(self):
        handler = FileSystemEventHandler()
        handler.on_modified = self._on_modified
        self._observer.schedule(handler, "docs/wiki/entities/", recursive=False)
        self._observer.start()

    async def _on_modified(self, event):
        if not event.src_path.endswith(".md"):
            return

        try:
            md = Path(event.src_path).read_text(encoding="utf-8")
            cube = MemoryCube.from_wiki_page(md)

            # Diff with current graph state
            current = await self._graph.get_entity(cube.unified_id)
            if current and current.content_hash == cube.content_hash:
                return  # No-op — same content

            # Apply update
            await self._graph.upsert_entity(cube.to_graph_node())

        except Exception as e:
            # Dead-letter
            self._dlq.append({
                "path": event.src_path,
                "error": str(e),
                "ts": datetime.now().isoformat(),
            })
```

### Запуск

```bash
# Standalone daemon
python scripts/export_graph_to_wiki.py reverse-sync --watch docs/wiki/entities/

# Или интегрировано в основной сервис при `MCP_OAUTH_ENABLED=true` deployment
```

### DLQ inspection

```bash
cat data/wiki_reverse_sync_dlq.jsonl | jq '.error' | sort | uniq -c

```

## Draft promotion (L5 → L3)

Drafts в `docs/wiki/drafts/` — pending review. Когда human (или auto-promotion logic) считает draft canonical, перемещение:

```bash
# Manual
git mv docs/wiki/drafts/oauth-pkce-wrapper-pattern.md docs/wiki/entities/

# Auto: после N applications draft → entity (TODO Phase 2.x)
```

После перемещения:
- `docs-change-tracker` детектит rename → re-index Qdrant с new path
- Old draft links через `link_registry` сохраняют traceability

## Antipatterns

| Плохо | Почему | Как правильно |
|---|---|---|
| Прямой Write в `docs/wiki/entities/` без frontmatter | kb-lint падает, файл не индексируется | Используй template или `MemoryCube.to_wiki_page()` |
| `confidence_threshold=0.5` для промоции | Слишком много low-quality drafts в wiki | Default 0.8 — keep it |
| Игнорировать `wiki.promoted` events | Downstream consumers (indexer, audit) пропускают новые drafts | Subscribe через `event_bus.subscribe()` |
| Удалить draft без `SUPERSEDED_BY` link | Теряется audit trail откуда пришёл | Создать link через `link_registry` или mark deprecated |
