## 16.5 MCP-серверы для 1С

Раздел описывает интеграцию фреймворка с AI-агентами посредством протокола MCP. В экосистему проекта входят четыре специализированных MCP-сервера, обеспечивающих взаимодействие AI с платформой 1С, поиск по исходному коду и получение справочной информации.

> **Операционная настройка среды** (запуск EDT IDE с MCP-плагином, runtime debug agent, диагностика `/implement-1c-task` pipeline) вынесена в [16.6 EDT-MCP setup](16.6_EDT_MCP_setup.md). Smoke-test всей среды: `python scripts/smoke_test_implement_1c_task.py`.

### Обзор MCP-интеграции

**MCP (Model Context Protocol)** — открытый стандарт протокола прикладного уровня, предназначенный для обеспечения стандартизированного взаимодействия между языковыми моделями (LLM) и внешними системами. Использование MCP позволяет AI-агентам выполнять запросы к информационным базам 1С, анализировать метаданные и работать с исходным кодом в автоматическом режиме.

В рамках проекта реализованы и поддерживаются следующие 4 MCP-сервера:
*   `1c-mcp-server` — расширение MCP_Сервер: выполнение кода, запросов, работа с метаданными, навигация по объектам, администрирование. Автоподключение к базам 1С.
*   `bsl-code-search` — структурный семантический поиск по исходному коду на языке BSL.
*   `bsl-platform-context` — предоставление контекста и справочной информации по API платформы 1С:Предприятие.
*   `METR` (mcp-yaxunit-runner) — автоматическая сборка, синтаксическая проверка и запуск тестов YaXUnit.

---

### 1c-mcp-server (расширение MCP_Сервер)

Основной сервер для прямого взаимодействия AI-агента с информационной базой 1С:Предприятие. Реализован как расширение конфигурации `MCP_Сервер` с HTTP-сервисом и stdio-прокси с автоподключением.

> **Примечание:** Расширение MCPToolkit, ранее использовавшееся для этих целей, полностью заменено расширением MCP_Сервер. Все 13 инструментов MCPToolkit перенесены в MCP_Сервер, добавлены 2 новых инструмента, поддержка ресурсов (resources) и промптов (prompts) по протоколу MCP 2025-03-26.

#### Назначение и инструменты

Сервер предоставляет **15 инструментов** (MCP tools) для полнофункционального доступа к данным и структуре 1С:

**Работа с данными:**
*   `execute_query` — выполнение произвольных запросов на языке запросов 1С с параметрами и схемой колонок.
*   `execute_code` — выполнение встроенного кода на языке BSL (результат через переменную `Результат`).
*   `validate_query` — проверка синтаксиса запроса без выполнения.

> **Известные ограничения** (workaround'ы — в [implement-1c-task SKILL.md §«Известные ограничения 1c-mcp-crud»](../../../../.claude/skills/implement-1c-task/SKILL.md#известные-ограничения-1c-mcp-crud)):
> 1. `get_metadata` для регистра сведений возвращает пустой `attributes:[]` — обходить через `execute_query` или EDT-MCP `get_metadata_details`.
> 2. `execute_query` падает на сериализации композитных ссылочных типов — оборачивать ссылочные поля в `ПРЕДСТАВЛЕНИЕ()`.
> 3. `execute_code` запрещает `Возврат` вне процедуры/функции (фрагмент оборачивается в анонимный top-level блок) — переписывать ранние выходы через ветвление `Если/Иначе` с присваиванием `Результат` в каждой ветке.

**Метаданные и структура:**
*   `get_metadata` — чтение структуры метаданных конфигурации (сводка / список по типу / детали объекта).
*   `get_metadata_tree` — компактное дерево всех метаданных (18 коллекций) с подсчётом объектов.
*   `get_form_structure` — структура форм объекта метаданных (список форм, реквизиты и команды основной формы).
*   `search_code` — поиск по метаданным конфигурации: имена объектов, синонимы, реквизиты, табличные части.
*   `list_metadata_objects` — список объектов заданного типа метаданных с фильтрацией по маске имени.
*   `get_metadata_structure` — детальная структура объекта метаданных (реквизиты, табличные части, измерения, ресурсы с типами и синонимами).

**Навигация по объектам:**
*   `get_object_by_link` — получение полных данных объекта 1С по навигационной ссылке.
*   `get_link_of_object` — генерация навигационной ссылки из описания объекта.
*   `find_references_to_object` — поиск всех ссылок на объект в документах, справочниках и регистрах.

**Администрирование:**
*   `get_event_log` — чтение журнала регистрации с фильтрацией по дате, уровню, событиям и пользователям.
*   `get_access_rights` — получение прав доступа к объектам метаданных по ролям или конкретному пользователю.
*   `get_bsl_syntax_help` — справочник по встроенному языку BSL (30+ функций с синтаксисом и примерами).

#### Автоподключение (auto-discovery)

Stdio-прокси `proxy.py` автоматически находит доступные базы 1С с расширением MCP_Сервер при запуске:

1.  Перебирает комбинации `серверы × базы × пути × учётные данные`.
2.  Отправляет `tools/list` к каждому кандидату.
3.  Первая база, вернувшая список инструментов — подключается.
4.  Если ни одна база не найдена — offline mode (пустой список tools, Claude Code не падает).
5.  При ошибке вызова — автоматический rediscovery.
6.  При `tools/list` в offline-режиме — повторная попытка подключения.

**Настройки прокси** (в начале `scripts/claude-backend/mcp-1c-proxy/proxy.py`):

```python
PROBE_SERVERS   = ["KOMPUTER", "localhost"]   # серверы для поиска
PROBE_DATABASES = ["TestDB"]                   # базы данных
PROBE_CREDENTIALS = [("ОселедькоВС", "")]      # учётные данные
PROBE_PATHS = ["/hs/mcp/rpc"]                  # путь HTTP-сервиса MCP_Сервер
PROBE_TIMEOUT = 4  # секунд на попытку
```

**Переопределение через переменные окружения** (в `mcp-servers.json` поле `env`):

| Переменная | Описание |
| :--- | :--- |
| `MCP_1C_URL` | Явный URL (пропускает discovery) |
| `MCP_1C_USER` | Имя пользователя 1С |
| `MCP_1C_PASSWORD` | Пароль пользователя 1С |
| `MCP_1C_SERVERS` | Серверы через запятую |
| `MCP_1C_DATABASES` | Базы через запятую |

#### Установка расширения

1.  Добавьте расширение `MCP_Сервер` в конфигураторе: Конфигурация → Расширения конфигурации → Добавить.
2.  Загрузите из XML: Конфигурация → Загрузить конфигурацию из файлов → путь к `src/external/1c_mcp/src/1c_ext/`.
3.  Обновите конфигурацию БД (F7).
4.  Опубликуйте базу с HTTP-сервисами расширений: Администрирование → Публикация на веб-сервере → вкладка «HTTP сервисы» → галочка «Публиковать HTTP сервисы расширений по умолчанию» → Опубликовать.

#### Конфигурация Claude Code

В файле `.claude/mcp-servers.json`:

```json
{
  "mcpServers": {
    "1c-mcp-server": {
      "command": "python",
      "args": ["scripts/claude-backend/mcp-1c-proxy/proxy.py"],
      "cwd": "D:\\1C-Enterprise_Framework",
      "description": "1C MCP Server (MCP_Сервер extension) - auto-discovers and connects to 1C:Enterprise databases. 15 tools."
    }
  }
}
```

Пример с явным URL через env:

```json
{
  "mcpServers": {
    "1c-mcp-server": {
      "command": "python",
      "args": ["scripts/claude-backend/mcp-1c-proxy/proxy.py"],
      "cwd": "D:\\1C-Enterprise_Framework",
      "env": {
        "MCP_1C_URL": "http://prod-server/ProdDB/hs/mcp/rpc",
        "MCP_1C_USER": "APIUser",
        "MCP_1C_PASSWORD": "secret"
      }
    }
  }
}
```

**URL HTTP-сервиса:** `http://<сервер>/<публикация>/hs/mcp/rpc`

**Аутентификация:** Basic Auth через заголовок `Authorization`. IIS ISAPI-расширение 1С обрабатывает авторизацию — `curl` с `-u`/`--ntlm` не работает, используется Python `urllib` с явным заголовком.

### bsl-code-search

Сервер для статического анализа и поиска по исходному коду модулей 1С без необходимости подключения к информационной базе.

#### Назначение и инструменты

Обеспечивает структурный поиск по коду с использованием синтаксического дерева. Включает 3 инструмента:
*   `search_symbols` — поиск символов (функций, процедур, переменных) по кодовой базе.
*   `find_callers` — поиск мест вызова конкретной функции или процедуры.
*   `get_module_ast` — получение абстрактного синтаксического дерева (AST) указанного модуля.

#### Технические детали

Парсинг кода выполняется с использованием библиотеки `tree-sitter-bsl` версии 0.1.6. Скорость построения AST составляет от 1 до 23 мс на файл, что позволяет обрабатывать крупные проекты в режиме реального времени.

#### Расположение

Исходный код сервера находится в директории: `tools/bsl-code-search/`.

### bsl-platform-context

Сервер контекстной справки, предоставляющий AI-агентам актуальную документацию по методам платформы 1С:Предприятие.

#### Назначение и инструменты

Содержит актуальную документацию по API платформы версии 1С:8.3.27. Позволяет AI избегать галлюцинаций при генерации кода за счет точного знания сигнатур методов и их поведения.

Доступные инструменты:
*   `search` — полнотекстовый поиск по справке.
*   `getMembers` — получение списка членов объекта (методов, свойств).
*   `getMember` — получение детального описания конкретного метода или свойства.
*   `getConstructors` — получение информации о конструкторах объекта.
*   `info` — получение общей информации о системе справки.
