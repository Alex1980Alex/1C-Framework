# 26.3. Lazy-MCP — Реестр серверов

## Конфигурация

Реестр серверов определяется в `config/registry.yaml` (283 строки). Содержит иерархию категорий и параметры запуска каждого сервера.

## Категории и серверы

Инструменты для разработки на платформе 1С:Предприятие — анализ BSL-кода, API платформы, семантический поиск, отладка.

| Сервер | Тип | Описание | Таймаут |
|---|---|---|---|
| `ast-grep-mcp` | native | AST-анализ BSL кода (100% надёжность) | 60s |
| `bsl-platform-context` | native | API платформы 1С — типы, методы, свойства | 30s |
| `bsl-semantic-search` | native | Семантический поиск по BSL коду конфигураций | 60s |
| `bsl-debugger` | native | Отладка BSL кода — 10 инструментов | 60s |
| `bsl-semantic-diff` | native | Семантическое сравнение BSL кода | 30s |

## Локальные инструменты вне lazy-реестра

Не все MCP-серверы репозитория идут через `config/registry.yaml` — часть подключена напрямую в корневом
`.mcp.json`, часть используется как jar-бэкенд для уже перечисленных выше серверов.

| Инструмент | Что это | Расположение | Подключение |
|---|---|---|---|
| `framework-search-mcp` | Semantic-поиск по коду фреймворка (коллекция `framework_code_v1`, TEI+Qdrant) | `tools/framework-search-mcp/` | напрямую в `.mcp.json` (`framework-search`), НЕ через lazy-реестр |
| `mcp-jars` | jar-артефакты Java-based MCP: `mcp-bsl-context-0.3.1.jar` (см. `bsl-platform-context` выше) + `mcp-yaxunit-runner-0.5.1.jar` (mcp-onec-test-runner) | `tools/mcp-jars/` | первый запускается через lazy-реестр (`java -jar`), второй — напрямую в `.mcp.json` через `scripts/onec_test_runner_launch.py` |
| `task-master-ai` | вендоренная Node.js task-management система (`claude-task-master`, PRD→tasks) | `infra/task-master/` | напрямую в `.mcp.json` (`task-master-ai`, `npx --package=task-master-ai`), НЕ через lazy-реестр |
| `mcp-reasoner` (fork) | Beam Search / MCTS reasoning-сервер | `tools/mcp-reasoner/` | фактически уже подключён через lazy-реестр как `reasoner` (см. категорию `reasoning` выше) — упомянут здесь для полноты сверки |

## Добавление нового сервера

Для добавления сервера в реестр отредактируйте `config/registry.yaml`:

```yaml
categories:
  my-category:
    description: "Описание категории"
    servers:
      my-server:
        command: "python"                    # Команда запуска
        args: ["path/to/server.py"]          # Аргументы
        env:                                  # Переменные окружения
          PYTHONIOENCODING: "utf-8"
        description: "Описание сервера"
        timeout: 60000                        # Таймаут в мс
        type: "native"                        # native | npx | docker-mcp | bridge
```

Для NPX-серверов:

```yaml
my-npx-server:
  command: "npx"
  args: ["-y", "@scope/mcp-server-package"]
  description: "Описание"
  type: "npx"
```

Для Bridge-серверов (MCPO):

```yaml
mcpo:
  type: "bridge"
  endpoints:
    base_url: "http://localhost:8765"
    filesystem: "/filesystem"
    ripgrep: "/ripgrep"
```

После изменения конфигурации перезапустите Lazy-MCP (или он перечитает при следующем вызове).
