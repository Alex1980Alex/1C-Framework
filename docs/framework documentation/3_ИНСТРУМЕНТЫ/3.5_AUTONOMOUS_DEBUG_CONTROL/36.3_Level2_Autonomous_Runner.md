# 36.3 Level 2 — `autonomous_debug_test.py`

## Назначение

Standalone CLI-runner который прогоняет полный E2E debug-сценарий **без user interaction**: validates JSON, health-checks, optionally auto-prepares, connects, sets BPs, triggers BSL via IIS, captures stop events, runs inspections, выводит summary, exit code = вердикт. Подходит как для CI, так и для headless validation новой логики.

> **Связано:** [36.1 Обзор](36.1_Обзор.md), [36.2 Level 1 Health Check](36.2_Level1_Health_Check.md), [36.4 Level 3 Session Summary](36.4_Level3_Session_Summary.md)

---

## 1. CLI

```bash
python scripts/autonomous_debug_test.py <scenario.json>
```

Sample: [`scripts/scenarios/post_lab_doc.json`](../../../../scripts/scenarios/post_lab_doc.json) — повторяет multi-BP live тест 2026-05-10 (3 BPs across 2 modules + 4 inspections).

### Обязательные env vars (для IIS-trigger)

```bash
MCP_ONEC_USERNAME=<user@domain>     # IIS Basic auth user
MCP_ONEC_PASSWORD=<password>        # IIS Basic auth password
```

### Опциональные env vars

```bash
RAC_CLUSTER_USER=<admin>            # для cluster security-level≠0

BSL_DEBUG_ALLOW_SERVICE_RESTART=true  # включает service-restart auto-prepare path

```

## 2. Scenario JSON schema

```jsonc
{
  // ОБЯЗАТЕЛЬНЫЕ
  "alias": "ИБTransportManagementDevelop",      // имя инфобазы в кластере 1С
  "bsl_trigger": "Документы.X.НайтиПоНомеру(\"Y\").ПолучитьОбъект().Записать(...);",
  "breakpoints": [
    {
      "object_id": "9c496dda-a7d1-463a-945d-1916088f7b61",  // UUID метаданных
      "line": 141,
      "module_type": "ObjectModule",            // ObjectModule | CommonModule | ManagerModule | FormModule | RecordSetModule | CommandModule
      "inspections": [
        {"expr": "ТипЗнч(ДопПараметры).ПолноеИмя()",
         "expect_substring": "Структура"}       // optional substring assertion
      ]
    }
  ],

  // ОПЦИОНАЛЬНЫЕ
  "iis": {
    "url": "http://localhost/transport/hs/mcp/rpc",
    "auth_user_env": "MCP_ONEC_USERNAME",       // env var name (не value!)
    "auth_pwd_env": "MCP_ONEC_PASSWORD"
  },
  "force_recycle": false,                       // true → kill pre-existing rphost'ы
  "stop_timeout_sec": 15,                       // per-BP wait timeout (default 15)
  "pre_trigger_wait_sec": null                  // null → auto: 5 если force_recycle, else 0
}
```

### Schema validation (fail-fast)

`validate_scenario(scenario)` → `list[str]` errors. При **non-empty** результате — exit 9 (`EXIT_SCHEMA_INVALID`) с понятным сообщением.

Проверки:
- Required fields: `alias`, `bsl_trigger`, `breakpoints`
- Type-checks: `force_recycle` bool, `line` int, `stop_timeout_sec`/`pre_trigger_wait_sec` numeric
- Nested: `iis.url` required если `iis` present; `breakpoints[].object_id` + `line` required; `inspections[].expr` required

## 3. Workflow (5 фаз)

```
┌──────────────────────────────────────────────────────────────┐
│ Phase 1 — Health check                                       │
│ ─ debug_health_check (probe)                                 │
│ ─ if not ready AND auto_prepare_available → prepare          │
│ ─ if not ready после prepare → exit 10 (EXIT_HEALTH_FAILED)  │
└──────────────────────────────────────────────────────────────┘
                            ↓
┌──────────────────────────────────────────────────────────────┐
│ Phase 2 — Connect debug                                      │
│ ─ debug_connect(infobase_alias, force_recycle_rphost=...)    │
│ ─ if status != "connected" → exit 11 (EXIT_CONNECT_FAILED)   │
└──────────────────────────────────────────────────────────────┘
                            ↓
┌──────────────────────────────────────────────────────────────┐
│ Phase 3 — Set breakpoints                                    │
│ ─ for bp in scenario.breakpoints: debug_set_breakpoint(...)  │
│ ─ wrapper aggregate'ит cache (Fix #5) → 1 setBreakpoints HTTP│
└──────────────────────────────────────────────────────────────┘
                            ↓
┌──────────────────────────────────────────────────────────────┐
│ Phase 4 — Trigger BSL + capture stops                        │
│ ─ pre_trigger_wait (5s если force_recycle) — warm-up         │
│ ─ asyncio.create_task(_trigger_bsl_via_iis)                  │
│ ─ for each expected BP:                                      │
│     ─ poll debug_targets until stopped_target appears        │
│       (timeout = stop_timeout_sec, default 15s)              │
│     ─ if timeout → exit 12 (EXIT_BP_TIMEOUT)                 │
│     ─ stack_trace + inspections + Continue                   │
│ ─ если inspection failed → exit 13 (EXIT_INSPECTION_FAILED)  │
└──────────────────────────────────────────────────────────────┘
                            ↓
┌──────────────────────────────────────────────────────────────┐
│ Phase 5 — Session summary + disconnect                       │
│ ─ debug_session_summary(format="markdown") → stdout          │
│ ─ debug_disconnect                                           │
│ ─ exit 0 если все BPs fired + все inspections passed         │
└──────────────────────────────────────────────────────────────┘
```

## 4. Exit codes

| Code | Constant | Когда |
|---|---|---|
| **0** | `EXIT_OK` | Все 3 acceptance: BPs fired, inspections passed, BSL trigger OK |
| **2** | (argparse) | Scenario file не найден |
| **9** | `EXIT_SCHEMA_INVALID` | Scenario JSON не прошёл schema validation |
| **10** | `EXIT_HEALTH_FAILED` | health_check ready=false и auto-prepare не помог |
| **11** | `EXIT_CONNECT_FAILED` | debug_connect вернул status != "connected" (например ibInDebug) |
| **12** | `EXIT_BP_TIMEOUT` | Один из BPs не fired в течение `stop_timeout_sec` |
| **13** | `EXIT_INSPECTION_FAILED` | Все BPs fired но какая-то inspection не прошла assertion |
| **14** | `EXIT_BSL_TRIGGER_FAILED` | IIS POST вернул не-200 или exception |

CI hook: `assert subprocess_returncode == 0`. Вердикт ясен без чтения логов.

## 5. BSL trigger через IIS

`_trigger_bsl_via_iis(scenario)` делает POST запрос:
```
POST {scenario.iis.url}
Headers: Content-Type: application/json
Auth: HTTP Basic ({user_env}, {pwd_env})
Body: {"jsonrpc": "2.0", "id": 1, "method": "execute_code",
       "params": {"code": "<scenario.bsl_trigger>"}}
```

Запускается как `asyncio.create_task` параллельно с polling for stops — рассчитан что BSL execution блокируется на BP, и trigger task ждёт пока user (или autonomous loop) не Continue'нет.

### RC2 warm-pool gap — JOB-based trigger (2026-05-12)

IIS-trigger имеет timing race: warm-pool rphost уже запущен до `debug_connect`, поэтому `DBGUIExtCmdInfoStarted` event уже прошёл и auto-attach его не поймал. BP fires только при совпадении — если нужен 100% гарантированный attach, используйте **JOB-based execution** (Шаблон 6 в [SKILL.md](../../../../.claude/skills/1c-debug-hmr/SKILL.md)):

```jsonc
{
  "alias": "ИБTransportManagementDevelop",
  // JOB-trigger: bsl_trigger запускается через ФоновыеЗадания.Выполнить
  // → спаунит НОВЫЙ JOB rphost → DBGUIExtCmdInfoStarted → auto-attach guaranteed
  "bsl_trigger": "П = Новый Массив; П.Добавить(\"<ваш код>\"); ФоновыеЗадания.Выполнить(\"гкс_ОтладкаВыполненияКода.ВыполнитьКод\", П);",
  "breakpoints": [...],
  "force_recycle": false     // НЕ нужен при JOB-pattern — новый rphost всегда clean
}
```

Требует `гкс_ОтладкаВыполненияКода` CommonModule в БД (задеплоен в ИБTransportManagementDevelop 2026-05-12, см. [§36.8 §10.1](36.8_Advanced_Debug_Features.md)).

### Альтернативные источники trigger'а

Сейчас scripts поддерживает только IIS. Расширения можно сделать:
- **JOB-based** — `ФоновыеЗадания.Выполнить` через IIS/execute_code (см. выше, рекомендован при RC2 gap)
- `subprocess` 1cv8c.exe `/Execute <epf>` (для thick-client сценариев)
- COM `V83.COMConnector` (для server-side prod scenarios)
- Direct запуск ScheduledJob через `rac job run`

## 6. Inspection matchers

Каждый BP может содержать массив `inspections`. Каждая inspection:

```json
{
  "expr": "Документ.Метаданные().ПолноеИмя()",
  "expect_substring": "Лабораторный"
}
```

Logic:
1. `debug_evaluate(expression=expr, target_id=...)` → response с `valueString`/`valueDecimal`/`valueBoolean`/`presentation`
2. `_format_inspection_result()` строит human-readable detail string (type + value + presentation b64-prefix)
3. Если `expect_substring` указан и НЕ найден в detail — inspection failed

### Будущие расширения matchers

- `expect_equals: <value>` (точное равенство)
- `expect_regex: <pattern>` (regex match)
- `expect_type: "Структура"` (assertion на typeName)
- `assert_no_error: true` (просто eval'нуть без сравнения, fail если evalResultState=withErrors)

## 7. Pre-trigger wait (Fix для post-recycle race)

Когда `force_recycle: true` — после kill rphost'ов и до trigger нужно дать ragent время spawn'ить fresh worker'ов И wrapper'у поймать `DBGUIExtCmdInfoStarted` event'ы (auto-attach через `setAutoAttachSettings` filter).

Logic:
```python
pre_wait = scenario.get("pre_trigger_wait_sec")
if pre_wait is None:
    pre_wait = 5 if scenario.get("force_recycle") else 0
if pre_wait > 0:
    await asyncio.sleep(pre_wait)
    # Re-query targets — wrapper уже мог auto-attach новые rphost'ы
```

Без этого wait — race window: trigger приходит до того как fresh rphost'ы зарегистрировались, BPs не fire.

## 9. CI integration (пример)

```yaml
# .github/workflows/debug-smoke.yml (sketch)
- name: Autonomous debug E2E
  run: |
    python scripts/autonomous_debug_test.py scripts/scenarios/post_lab_doc.json
  env:
    MCP_ONEC_USERNAME: ${{ secrets.ONEC_USER }}
    MCP_ONEC_PASSWORD: ${{ secrets.ONEC_PWD }}
```

CI step падает при non-zero exit. Markdown summary можно artifact'ом сохранить:
```bash
python scripts/autonomous_debug_test.py scenario.json | tee artifacts/debug-summary.md
```
