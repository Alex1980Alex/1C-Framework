## 15 best practices (synthesis)

### 1. Branch protection FIRST

Required status checks + reviews — auto-merge waits на них. Без branch protection любой бот может pushить в main → катастрофа.

### 2. Label-driven activation

PR с label `automerge` / `ready-to-merge` → bot acts. Default off для всех PRs.

```yaml
# pascalgn/automerge-action — default config
MERGE_LABELS: "automerge"
```

### 3. Start with low-risk PRs

Dependency updates (Dependabot/Renovate) → docs → код. Расширять confidence по мере роста CI.

### 4. Squash by default

Clean linear history, easy revert (1 commit per feature).

```yaml
MERGE_METHOD: "squash"
```

### 5. Delete-branch on merge

`gh pr merge --delete-branch` — automate cleanup. Иначе stale branches накапливаются.

### 6. Status check filter (только REQUIRED)

Bot ждёт ТОЛЬКО required checks (configured в branch protection). Optional checks не блокируют merge.

### 7. Dismiss stale approvals on push

GitHub branch protection rule "Dismiss stale pull request approvals when new commits are pushed". Prevents post-approval sneak-in.

### 8. Merge queue для concurrent PRs

Mergify merge queue: batch-test against latest base. Avoids "green-when-pushed-but-broken-after-merge".

### 9. Conflict auto-resolution

Bot updates branch with base before merge (Kodiak, Mergify). Reduces manual rebases.

### 10. Notifications channel

Slack / email на merge events. Visibility для команды.

### 11. Audit log

Bot actions logged для post-mortem. Crucial для compliance.

### 12. Dry-run mode

Test rules без actually merging. Особенно при rollout новых правил.

### 13. Idempotency

Re-running automerge должно быть safe. Pattern: state-file with PR ID → skip if already processed (наш `post-task-push-pr-state.json` соответствует).

### 14. Never force-push

`--force` уничтожает history. Use `squash-merge` вместо.

### 15. Test before merge, not after

Pre-push tests catch regressions раньше CI. Наш `AUTO_PR_TEST_CMD` запускает `pytest -x` локально перед push.

## Антипаттерны (что НЕ делать)

| Bad | Why | Fix |
|-----|-----|-----|
| Auto-merge без required reviews | Bypasses code review | Always require ≥1 approval (branch protection) |
| Force-push by bots | Destroys history | Use squash-merge |
| No branch protection | Anyone can push to main | Set required checks rule |
| Merge on green even если base moved | Stale CI = false confidence | Use merge queue |
| Auto-merge ALL PRs unconditionally | Bypass intentional reviews | Label-gated activation |
| Pre-commit gates только в PR CI | Slow feedback | Run locally too (наш .pre-commit-config) |
| Commit before lint | Dirty commits в history | Pre-commit runs ON commit, not post |

## Сравнение решений

| Tool | Type | Strengths | Weaknesses |
|------|------|-----------|------------|
| **GitHub native auto-merge** | UI checkbox | Free, simple, official | Needs branch protection, no rich logic |
| **Mergify** | SaaS bot | Merge queue, DSL, conflict resolution | Paid (free tier limited) |
| **Kodiak** | OSS bot | Updates branch + merges, label-driven | Maintenance reduced (last release 2024) |
| **Bulldozer (Palantir)** | OSS bot | Self-host, no SaaS dependency | Less active dev |
| **pascalgn/automerge-action** | Action | Lightweight, label-driven | Limited to single PRs |
| **peter-evans/enable-pr-automerge** | Action | Wraps native API | Needs branch protection |
| **Dependabot/Renovate** | Bot | Dependency-specific | Только для deps |
| **Graphite** | SaaS | Stacked PR workflow | Paid + CLI adoption |
| **GitHub App custom** | Probot | Full control | Build + maintain |
| **PDF Framework `post-task-push-pr.py`** | Self-hosted hook | Workflow integration, per-task PR | Manual maintenance, single user |
