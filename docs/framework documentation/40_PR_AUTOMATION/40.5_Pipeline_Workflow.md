# 40.5 PR Automation — полный workflow

> Sister-документ к [40.1 Обзор](40.1_Обзор.md) — здесь полная картина pipeline по таймлайну сессии с диаграммой потока, env-флагами и end-to-end примером.

## Концепция

**Три временных уровня** в жизненном цикле сессии Claude Code, каждый со своим хук-набором. Цель: пользователь и Claude **не теряют работу**, история остаётся **чистой**, PR **создаются автоматически**.

| Уровень | Когда срабатывает | Главный артефакт |
|---|---|---|
| **Edit-time** | После каждого `Write`/`Edit`/`Bash` | sync commit `chore: auto-save *.py` каждые N файлов |
| **Task-time** | На `TaskUpdate(status=completed)` | branch `task/<id>-<slug>` + push + PR + опц. merge |
| **Stop-time** | Когда Claude пытается завершить сессию | BLOCK или systemMessage если есть uncommitted / drift docs / pending tasks |

После сессии — отдельные операторские скрипты: post-merge CI watcher, dashboard, orphan cleanup.

## Диаграмма потока — Edit-time

```
   user prompt → Claude → Write/Edit/Bash
                           │
                           ▼  PostToolUse:Write|Edit|Bash
       ┌───── auto-git-save.py ──────────────────────────┐
       │  +1 файл в .claude/cache/auto-git-save.json     │
       │  counter ≥ 3 ?                                  │
       │   YES → git add + git commit                    │
       │         pre-commit gates                        │
       │         (ruff/mypy/gitleaks/markdownlint/kb-lint)│
       │         commit «chore: auto-save *.py»          │
       │   NO  → mandatory task в hook-todos.json        │
       └─────────────────────────────────────────────────┘
       параллельно: docs-change-tracker.py отмечает какие
       doc-области требуют обновления (для Stop-enforcer)
```

## Диаграмма потока — Task-time (opt-in)

Срабатывает на `TaskUpdate(completed)` только если включён `AUTO_PR_ENABLED=1`.

```
       TaskUpdate(status=in_progress)
            └─► save start_sha в state-file (per-task SHA, P2.1)

       TaskUpdate(status=completed)
            ├─ gate: AUTO_PR_ENABLED=1?
            ├─ gate: метка `auto-pr` (если REQUIRE_LABEL)?
            ├─ gate: commits_ahead(base) ≥ MIN_COMMITS (def 3)?
            │
            ▼
       drift-проверка: HEAD vs origin/base
           если behind > 0 → warn (опц. auto-rebase)
       pre-push gate: `pre-commit run --all-files`
       dry-run отсечка (если AUTO_PR_DRY_RUN=1)
            │
            ▼
       branch model:
           AUTO_PR_CHERRY_PICK=1 → worktree + cherry-pick
           иначе → git branch -f task/<id>-<slug> HEAD
            │
            ▼
       push с conflict-aware retry
            │
            ▼
       detect existing PR (gh pr list --head):
           OPEN  → gh pr comment «updated to <sha>»
           none  → gh pr create
            │
            ▼
       reviewers: CODEOWNERS → fallback AUTO_PR_REVIEWERS
       blocked-by labels (cross-PR deps)
            │
            ▼
       если AUTO_PR_AUTO_MERGE=1:
           WAIT_FOR_CHECKS=1 → poll gh pr checks
           MERGE_QUEUE=1     → gh pr merge --merge-queue
           иначе             → gh pr merge --squash --delete-branch
            │
            ▼
       SMTP notify (если AUTO_PR_SMTP_HOST задан)
```

## Диаграмма потока — Stop-time

Stop-chain хуки. Любой может остановить завершение через `exit 2`.

```
   Claude пытается Stop
        │
        ▼
   1. git-commit-enforcer.py
      если uncommitted в src/docs/tests/.claude/{skills,hooks}/
         → BLOCK + список файлов
        │
        ▼
   2. docs-change-enforcer.py
      git log --invert-grep '^chore: auto-save'
                    '^chore: rollup auto-format*'
      если code changed без docs update
         → systemMessage «обнови docs/N_DOMAIN/»
        │
        ▼
   3. task-enforcer.py
      если pending mandatory tasks
         → BLOCK + список tasks
        │
        ▼
   Stop разрешён → сессия завершена
```

## Post-session (операторские скрипты)

После завершения сессии — три независимых скрипта запускаются вручную или по cron.

### Post-merge CI watcher (P3.4)

`scripts/pr_check_post_merge.py`:

```
   for merged PR in state-file (за N часов):
       gh pr view → mergeCommit
       gh run list --commit <sha> → status
       если failure:
           создать revert PR через temp worktree
           email-notify
```

### Daily dashboard (P1.5)

`scripts/pr_automation_dashboard.py`:

```
   читает data/hook-invocations.jsonl + state-file
   агрегирует:
     - daily breakdown (total, ok, error, block, median ms)
     - top failure reasons (counter)
     - stale open PRs (>7 дней с момента completed_ts)
   пишет data/reports/pr_automation/_latest.md (markdown)
```

### Orphan branch cleanup (P2.4)

`scripts/cleanup_orphan_branches.py`:

```
   local: git for-each-ref refs/heads/task/*
          если merged в base + age ≥ 30d → git branch -D
   remote: gh pr list для каждой origin/task/*
          MERGED/CLOSED → git push origin --delete <branch>
```

## Шаги по таймлайну

| # | Шаг | Хук / скрипт | Когда | Артефакт |
|:--:|---|---|---|---|
| 1 | User отправляет prompt | `UserPromptSubmit` chain (skill-router, memory-first, …) | каждое сообщение | контекст для Claude |
| 2 | Claude правит файл | `auto-git-save.py` | каждый Write/Edit | counter в `.claude/cache/auto-git-save.json` |
| 2a | Threshold 3 файла | `auto-git-save.py` | при counter=3 | git commit «chore: auto-save *.py» |
| 2b | Pre-commit gates | hooks `.pre-commit-config.yaml` | при auto-save commit | ruff/mypy/gitleaks/markdownlint/kb-lint |
| 3 | TaskUpdate(in_progress) | `post-task-push-pr.py` | начало задачи | `start_sha` в state-file (per-task SHA, P2.1) |
| 3' | TaskUpdate(completed) | `post-task-push-pr.py` | завершение задачи | branch + push + PR + опц. merge |
| 4 | Claude пытается Stop | Stop-chain enforcers | конец сессии | BLOCK или systemMessage |
| 5 | Stop разрешён | — | — | сессия завершена |
| 6 | Post-merge CI check | `pr_check_post_merge.py` | cron / вручную | revert PR при провале CI |
| 7 | Daily roll-up | `pr_automation_dashboard.py` | вручную | `data/reports/pr_automation/_latest.md` |
| 8 | Orphan cleanup | `cleanup_orphan_branches.py` | cron | удаление merged task/* веток |

## Env-флаги и матрица режимов

```
AUTO_PR_ENABLED=1                ← master switch task-time pipeline
├── AUTO_PR_REQUIRE_LABEL=auto-pr ← label gate (P0.1)
├── AUTO_PR_BASE=master           ← base ветка
├── AUTO_PR_MIN_COMMITS=3
├── AUTO_PR_TEST_CMD              ← дефолт «pre-commit run --all-files» (P0.4)
├── AUTO_PR_NO_TESTS=1            ← skip pre-push gate
├── AUTO_PR_AUTO_REBASE=1         ← P1.3 — rebase HEAD на origin/base при behind > 0
├── AUTO_PR_REVIEWERS=user1,...   ← fallback к CODEOWNERS (P2.3)
├── AUTO_PR_AUTO_MERGE=1
├── AUTO_PR_MERGE_QUEUE=1         ← gh pr merge --merge-queue (P3.3 alt)
├── AUTO_PR_WAIT_FOR_CHECKS=1     ← poll gh pr checks перед merge (P1.2)
├── AUTO_PR_CHECKS_TIMEOUT=300
├── AUTO_PR_CHERRY_PICK=1         ← worktree-based clean diff (P3.2)
├── AUTO_PR_DRY_RUN=1             ← все checks, без push/PR/merge (P1.4)
├── AUTO_PR_SMTP_HOST, _PORT, _USER, _PASS, _TLS, _NOTIFY_FROM, _NOTIFY_TO
│                                  ← email уведомления (P1.1)
└── GITHUB_WEBHOOK_SECRET         ← для webhook receiver (P3.1)
```

Полный env reference + smoke checks — в [40.4 Дорожная карта](40.4_Дорожная_карта.md) §«Реализация 2026-05-22».

## Конкретный end-to-end пример

**Сценарий:** «Исправить опечатку в `bsl-development/SKILL.md`».

1. **User prompt:** «исправь опечатку 'каонфигурация' → 'конфигурация' в bsl-development»
2. **Claude:** Read → Edit одного файла
3. **`auto-git-save.py`** (PostToolUse:Edit): counter=1, threshold=3 → НЕ коммитит, создаёт mandatory task «Закоммитить незавершённые правки»
4. **Claude:** TaskCreate(«опечатка») + Edit ещё одного файла → counter=2
5. **Claude:** Edit третьего файла → counter=3 → **auto-git-save срабатывает**:
   - `git add bsl-development/SKILL.md ...`
   - pre-commit gates → markdownlint, kb-lint pass
   - `git commit -m "chore: auto-save SKILL.md, ..."`
6. **Claude:** TaskUpdate(status=completed)
7. **`post-task-push-pr.py`** (PostToolUse:TaskUpdate):
   - `AUTO_PR_ENABLED=1` ✓
   - commits_ahead(master) = 1, MIN_COMMITS=3 → **SKIP push/PR** с сообщением «1 commit ahead < threshold»
8. **Claude пытается Stop.**
   - `git-commit-enforcer.py` → uncommitted = 0 → PASS
   - `docs-change-enforcer.py` → правка в `.claude/skills/` не маппится на `docs/framework documentation/N_DOMAIN/` → PASS (skill = self-contained)
   - `task-enforcer.py` → mandatory task «Закоммитить» уже закрылась через auto-save → PASS
9. **Stop разрешён** → сессия завершена

**Если бы было 3+ коммитов с осмысленным TaskUpdate:**

7'. **`post-task-push-pr.py`** срабатывает полностью:
   - pre-push gate: `pre-commit run --all-files` → PASS
   - `git branch -f task/42-typo-fix HEAD`
   - `git push -u origin task/42-typo-fix`
   - `gh pr list --head task/42-typo-fix` → пусто → `gh pr create`
   - CODEOWNERS lookup → reviewer назначен
   - если `AUTO_PR_AUTO_MERGE=1` → poll checks → squash-merge → delete branch
   - SMTP email «[PR Merged] Task #42»
