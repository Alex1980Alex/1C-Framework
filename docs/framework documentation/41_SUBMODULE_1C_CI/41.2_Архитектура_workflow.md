# 41.2 Архитектура workflow

Детальный walkthrough файла `.github/workflows/ci.yml` в submodule репозитории.

## Триггеры

```yaml
on:
  push:
    branches: [master, main, develop]
  pull_request:
    branches: [master, main, develop]
  workflow_dispatch:
```

- **`push`** — runs on direct commits to main branches (когда PR не используется)
- **`pull_request`** — runs on PR open/sync/reopen
- **`workflow_dispatch`** — manual trigger из GitHub UI (Actions tab → Run workflow)

Триггер срабатывает **только на изменения внутри submodule репозитория**, не на изменения parent `1C-Framework` repo.

## Job 1: bsl-static (GitHub-hosted Linux)

```yaml
bsl-static:
  name: BSL Static Analysis
  runs-on: ubuntu-latest
  steps:
    - name: Checkout
      uses: actions/checkout@v4

    - name: Set up JDK 17
      uses: actions/setup-java@v4
      with:
        distribution: temurin
        java-version: "17"

    - name: Cache BSL Language Server
      id: cache-bsl-ls
      uses: actions/cache@v4
      with:
        path: ~/bsl-ls
        key: bsl-ls-0.24.0

    - name: Download BSL Language Server
      if: steps.cache-bsl-ls.outputs.cache-hit != 'true'
      run: |
        mkdir -p ~/bsl-ls
        curl -L -o ~/bsl-ls/bsl-language-server.jar \
          https://github.com/1c-syntax/bsl-language-server/releases/download/v0.24.0/bsl-language-server-0.24.0.jar
```

**Ключевые моменты:**

- `ubuntu-latest` — **GitHub-hosted runner**, free tier 2000 min/month
- `setup-java@v4` с `temurin` JDK 17 — нужен для BSL LS JAR
- `actions/cache@v4` — кэширует JAR между runs (downloaded once, reused)
- `bsl-language-server.jar` v0.24.0 — статический анализатор от `1c-syntax/bsl-language-server`

**Analysis шаг:**

```yaml
    - name: Run BSL Language Server
      run: |
        mkdir -p build/bsl-report
        java -jar ~/bsl-ls/bsl-language-server.jar \
          --analyze \
          --srcDir src \
          --reporter json \
          --reporter generic \
          --outputDir build/bsl-report || true
```

- `--srcDir src` — анализирует всю `src/` директорию submodule
- `--reporter json` + `generic` — два формата для разных downstream (artifact + console)
- `|| true` — non-blocking (отчёт есть, но CI не падает на diagnostics)
- Когда baseline стабилизирован — можно убрать `|| true` и сделать blocking

**Artifact upload:**

```yaml
    - name: Upload BSL Report
      if: always()
      uses: actions/upload-artifact@v4
      with:
        name: bsl-report
        path: build/bsl-report/
        retention-days: 14
```

Отчёт хранится 14 дней в GitHub Artifacts, доступен для скачивания из PR/run page.

## Job 2: yaxunit-tests (self-hosted Windows)

```yaml
yaxunit-tests:
  name: YAxUnit Tests
  runs-on: [self-hosted, windows-11, "1c"]
  env:
    VRUNNER_PATH: 'C:\Tools\OneScript\bin\vrunner.bat'
    TOOLS_PATH: 'D:\1C-FW\tools'
    IB_CONNECTION: '/SKOMPUTER\testdb1c'
```

- `runs-on: [self-hosted, windows-11, "1c"]` — runner labels (требует match все 3)
- Env vars hard-coded paths для runner machine
- `IB_CONNECTION` — путь к test infobase в формате `/SQLSERVER\dbname`

**Запуск тестов:**

```yaml
    - name: Run YAxUnit
      shell: pwsh
      env:
        USER_1C: ${{ secrets.USER_1C_LOGIN }}
        PASS_1C: ${{ secrets.USER_1C_PASS }}
      run: |
        [Console]::OutputEncoding = [Text.Encoding]::UTF8
        New-Item -ItemType Directory -Force -Path "build\reports" | Out-Null
        & "${{ env.VRUNNER_PATH }}" `
          run `
          --ibconnection "${{ env.IB_CONNECTION }}" `
          --db-user "$env:USER_1C" `
          --db-pwd "$env:PASS_1C" `
          --command "RunUnitTests" `
          --execute "${{ env.TOOLS_PATH }}\vanessa\YAxUnit-25.12.cfe" `
          --settings "${{ env.TOOLS_PATH }}\yaxunit.json"
```

- `shell: pwsh` — PowerShell Core (поддерживает UTF-8)
- `[Console]::OutputEncoding = UTF8` — обязательно для cyrillic output
- Credentials из GitHub secrets (см. [41.4](41.4_Secrets_и_безопасность.md))
- `vrunner` запускает 1С платформу в server mode с YAxUnit framework
- Output: `build/reports/junit.xml` (JUnit формат)

## Job 3: bdd-tests (self-hosted Windows, continue-on-error)

```yaml
bdd-tests:
  name: BDD Tests
  runs-on: [self-hosted, windows-11, "1c"]
  continue-on-error: true
```

**`continue-on-error: true`** — BDD UI tests менее стабильны (GUI dependent), их failure не блокирует общий CI verdict. Но результаты всё равно reported в PR comment.

```yaml
    - name: Run BDD Tests
      shell: pwsh
      env:
        USER_1C: ${{ secrets.USER_1C_LOGIN }}
        PASS_1C: ${{ secrets.USER_1C_PASS }}
      run: |
        [Console]::OutputEncoding = [Text.Encoding]::UTF8
        powershell -File "${{ env.TOOLS_PATH }}\vanessa\run-bdd.ps1"
```

Реальный runner script — `tools/vanessa/run-bdd.ps1` в main repo D:\1C-FW\. Скрипт запускает VanessaAutomation с подходящими параметрами.

## Job 4: pr-summary (aggregated comment)

```yaml
pr-summary:
  name: PR Summary
  runs-on: ubuntu-latest
  needs: [bsl-static, yaxunit-tests, bdd-tests]
  if: always() && github.event_name == 'pull_request'
  steps:
    - name: Comment PR
      uses: actions/github-script@v9
      with:
        script: |
          const results = {
            'BSL Static Analysis': '${{ needs.bsl-static.result }}',
            'YAxUnit Tests': '${{ needs.yaxunit-tests.result }}',
            'BDD Tests': '${{ needs.bdd-tests.result }}'
          };
```

- `needs: [...]` — runs ПОСЛЕ остальных 3 jobs
- `if: always()` — runs даже если какие-то из needs failed
- `github-script@v9` — добавляет markdown comment в PR с результатами

**Пример comment в PR:**

```markdown
## CI 1C:Enterprise Results

| Check | Result |
|-------|--------|
| BSL Static Analysis | ✅ success |
| YAxUnit Tests | ❌ failure |
| BDD Tests | ⚠️ skipped |

*BSL Static runs on GitHub-hosted Linux (always available).
YAxUnit/BDD require self-hosted Windows runner с 1С:Предприятие.*
```

## Дерево зависимостей jobs

```
              [push/PR/manual]
                     │
        ┌────────────┼────────────┐
        ▼            ▼            ▼
  bsl-static   yaxunit-tests  bdd-tests
  (Linux)      (Win self-h)   (Win self-h, soft)
        │            │            │
        └────────────┼────────────┘
                     ▼
                pr-summary
                (Linux, PR only)
```

3 main jobs **параллельные** (не зависят друг от друга). `pr-summary` ждёт всех и постит comment.

## Поведение при offline runner

Если self-hosted runner offline:

- ✅ **bsl-static** — runs nornally (cloud Linux)
- ⏳ **yaxunit-tests** — sits в `QUEUED` indefinitely
- ⏳ **bdd-tests** — sits в `QUEUED` indefinitely
- ⏳ **pr-summary** — sits в `QUEUED` (waits для needs)

GitHub Actions queue timeout — 1 час по умолчанию для self-hosted. После — job будет CANCELLED.

**Workaround:** запустить runner → jobs автоматически pick up из очереди.
