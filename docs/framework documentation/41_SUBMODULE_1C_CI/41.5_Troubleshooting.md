# 41.5 Troubleshooting

Диагностика типичных проблем submodule 1С CI workflow.

## Quick decision tree

| Симптом | Вероятная причина | Раздел |
|---------|-------------------|--------|
| bsl-static fails (404 BSL LS download) | URL устарел | BSL LS URL changed |
| yaxunit-tests QUEUED >5 min | Self-hosted runner offline | Runner Offline |
| yaxunit-tests "vrunner not found" | Tool path wrong | Tool Paths |
| yaxunit-tests "Cannot connect to infobase" | Test ИБ unavailable | Infobase Connection |
| yaxunit-tests "Authentication failed" | Secrets missing | Secrets Missing |
| yaxunit-tests "0 tests collected" | YAxUnit settings wrong | Tests Not Found |
| bdd-tests failed | UI assertion | BDD UI Issues (continue-on-error) |
| pr-summary not posted | Permissions | PR Comment Missing |

## Issue: Runner Offline (QUEUED indefinitely)

**Symptom:** yaxunit-tests и bdd-tests показаны QUEUED >5 минут.

**Diagnosis:**

```bash
gh api /repos/Alex1980Alex/IBTransportManagementDevelop-Configuration/actions/runners --jq ".runners[] | {name, status, busy}"
```

Output "status": "offline" → runner не доступен.

**Fix:**

| Cause | Fix |
|-------|-----|
| Service stopped | Start-Service "actions.runner.*" в PowerShell |
| ПК выключен | Включить + проверить service auto-start |
| Network blocked | Firewall: allow outbound HTTPS to github.com |
| Token expired | Re-register: config.cmd remove + config.cmd с новым token |
| Wrong labels | Verify .runner file: labels должны быть windows-11, 1c |

**Workaround:** Trigger workflow manually когда runner online:

```bash
gh workflow run ci.yml --repo Alex1980Alex/IBTransportManagementDevelop-Configuration --ref master
```

## Issue: Tool Paths (vrunner not found)

**Symptom:**

```
The term "C:\Tools\OneScriptinrunner.bat" is not recognized
```

**Diagnosis:**

```powershell
Test-Path "C:\Tools\OneScriptinrunner.bat"
opm list | Select-String vrunner
```

**Fix:** Установить OneScript + vrunner (см. [41.3](41.3_Self_hosted_runner.md)) ИЛИ обновить env VRUNNER_PATH в workflow если установлен в другом месте.

## Issue: Infobase Connection

**Symptom:**

```
Не удалось подключиться к информационной базе
Connection string: /SKOMPUTER	estdb1c
```

**Diagnosis:**

```powershell
sqlcmd -S SKOMPUTER -E -Q "SELECT name FROM sys.databases WHERE name=testdb1c"
```

**Fix:**

| Issue | Fix |
|-------|-----|
| SQL Server down | Start-Service MSSQLSERVER |
| Database name mismatch | Update IB_CONNECTION env в ci.yml |
| Network unreachable | nslookup SKOMPUTER |
| Permission denied | Verify 1С user via SQL Server Management Studio |

## Issue: Secrets Missing

**Symptom:**

```
ERROR: --db-user value is empty
ERROR: --db-pwd value is empty
```

**Diagnosis:**

```bash
gh secret list --repo Alex1980Alex/IBTransportManagementDevelop-Configuration
```

Должны быть USER_1C_LOGIN и USER_1C_PASS. Если отсутствуют — см. [41.4 Secrets setup](41.4_Secrets_и_безопасность.md).

**Note:** GitHub маскирует *** в логах — это нормально, не означает что value пусто.

## Issue: Tests Not Found

**Symptom:**

```
YAxUnit: 0 tests collected
ERROR: No test modules matched filter
```

**Causes:**

1. Test modules не помечены // @unit-test декоратором
2. YAxUnit settings (yaxunit.json) указывает на wrong subsystem
3. Test infobase не имеет загруженной конфигурации с тестами

**Diagnosis:**

```powershell
Select-String -Path "src\CommonModules\*\Module.bsl" -Pattern "@unit-test" | Select-Object -First 5
Get-Content "D:C-FW	ools\yaxunit.json"
```

**Fix** yaxunit.json:

```json
{
  "subsystems": ["ПодсистемаТестов"],
  "modules": ["ОбщийМодуль_Тесты"],
  "tags": ["unit", "smoke"]
}
```

## Issue: BDD UI Issues

**Symptom:** BDD tests fail с screenshot отличающимся от expected.

**Common causes:**

| Issue | Fix |
|-------|-----|
| Screen resolution | Set resolution на runner: cscript reschange.vbs 1920 1080 32 |
| 1С update changed UI | Update step definitions в .feature файлах |
| Slow PC = timeout | Increase в yaxunit.json: "timeout": 120 |
| Cyrillic encoding | Workflow ставит [Console]::OutputEncoding = UTF8 |

**Workaround:** continue-on-error: true — BDD failure НЕ блокирует merge.

## Issue: PR Comment Missing

**Symptom:** Workflow runs OK, но PR не получает summary comment.

**Diagnosis:**

```bash
gh run view RUN_ID --log | grep "pr-summary"
```

**Fix:** В workflow добавить permissions в pr-summary job:

```yaml
jobs:
  pr-summary:
    permissions:
      pull-requests: write
      contents: read
```

Также Settings → Actions → Workflow permissions → Read/Write.

## Issue: BSL Language Server URL changed

**Symptom:**

```
curl: (22) The requested URL returned error: 404
```

URL hardcoded на v0.24.0 может стать неактуальным.

**Fix:**

1. Найти latest release: https://github.com/1c-syntax/bsl-language-server/releases
2. Update workflow .github/workflows/ci.yml:
   - cache key: bsl-ls-X.Y.Z
   - curl URL: bsl-language-server-X.Y.Z.jar

## Diagnostic commands cheatsheet

```bash
# Status последнего CI run
gh run list --branch master --limit 3

# Detailed log конкретного job
gh run view RUN_ID --log

# Failed jobs only
gh run view RUN_ID --log-failed

# Re-run failed jobs
gh run rerun RUN_ID --failed

# Cancel queued run
gh run cancel RUN_ID

# Verify secrets exist
gh secret list

# Check runner status
gh api /repos/owner/repo/actions/runners

# Trigger workflow manually
gh workflow run ci.yml --ref master
```

## When all else fails

1. Try fresh run: gh run rerun RUN_ID
2. Manual trigger через UI: Actions → Run workflow
3. Local reproduction: запустить vrunner с тем же command локально без CI
4. Check GitHub Actions status: https://www.githubstatus.com/
5. Open issue в submodule repo с full logs
