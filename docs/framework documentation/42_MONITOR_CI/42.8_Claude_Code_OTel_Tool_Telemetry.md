# 42.8 Claude Code OTel — точная телеметрия инструментов (opt-in, ADR-022 P2)

> **Статус: opt-in, default OFF.** P0/P1 ([ADR-022](../../../.claude/skills/architecture-research/adr/022-tool-call-observability-effectiveness.md))
> дают лёгкий JSONL hot-path (calls / errors / **реальная латентность MCP** / retry / abandonment).
> **P2** — нативный OpenTelemetry самого Claude Code: точные спаны **всех** инструментов (включая
> нативные Read/Write/Bash), cost-per-tool, цепочки субагентов, online LLM-judge. JSONL остаётся;
> OTel — для глубокого анализа по требованию. Факты: [cache/tool-call-observability-effectiveness-2026.md](../../../.claude/skills/architecture-research/cache/tool-call-observability-effectiveness-2026.md).

## Что даёт P2 (чего НЕТ в JSONL P0/P1)

| Сигнал | OTel-имя | Закрывает пробел P0/P1 |
|---|---|---|
| Реальная длительность **любого** тула (вкл. нативные) | `claude_code.tool.execution.duration_ms` | JSONL меряет латентность только MCP (Pre/Post-пара); нативные — нет |
| Split «ожидание разрешения» vs «исполнение» | `claude_code.tool.blocked_on_user` / `.execution` | в JSONL не разделено |
| success / error_type / размеры per вызов | событие `claude_code.tool_result` | JSONL: success/error_type есть только у MCP |
| **Cost / токены с атрибуцией на тул/скилл/сервер** | `claude_code.cost.usage` (`mcp_tool.name`/`skill.name`) | в JSONL cost вообще нет |
| Цепочки субагентов в одном трейсе | `tool_use_id` (= `gen_ai.tool.call.id`) | в JSONL `agent_id` пустой |

## Шаг 1 — включить нативный OTel в `console` (zero-infra, проверка эмиссии)

```powershell
.venv\Scripts\python.exe scripts\otel\enable_claude_otel.py --console
```

Пишет в `.claude/settings.local.json` (gitignored, per-user — team `settings.json` НЕ трогается) env:
`CLAUDE_CODE_ENABLE_TELEMETRY=1`, `CLAUDE_CODE_ENHANCED_TELEMETRY_BETA=1` (traces),
`OTEL_{METRICS,LOGS,TRACES}_EXPORTER=console`. **Перезапустить `claude`** (env читается при старте) →
спаны `claude_code.tool.*` польются в console/stderr. Контент (промпты/args/result) **OFF по умолчанию**
(PII/секреты); включить — флаг `--content` (осознанно).

## Шаг 2 — OTLP-бэкенд

### 2а — лёгкий верифицированный sink (otel-collector, в репо) ✅

Один контейнер: OTLP-приёмник (`:4318` http / `:4317` grpc) → debug-логи спанов. Идеально для проверки,
что эмиссия реально летит.

```bash
docker compose -f docker/docker-compose.otel-collector.yml up -d
.venv\Scripts\python.exe scripts\otel\enable_claude_otel.py --otlp http://localhost:4318
# перезапустить claude → docker logs -f claude-otel-collector → спаны claude_code.tool.execution
docker compose -f docker/docker-compose.otel-collector.yml down   # стоп
```

**Приём-путь верифицирован (2026-06-17):** синтетический спан `claude_code.tool.execution`
(`tool_name` / `duration_ms` / `success`) → `POST /v1/traces` = `200` → принят и залогирован коллектором
(точная форма, которую эмитит Claude Code). Остаётся эмиссия самого `claude` (включить + перезапустить —
за пользователем; из скрипта/хука не наблюдаема).

### 2б — полные дашборды (Langfuse self-host, официальный compose)

Langfuse (MIT, дашборды + cost + LLM-judge) тяжёлый (postgres/clickhouse/redis/minio) — **НЕ вендорим**,
поднимается официально:

```bash
git clone https://github.com/langfuse/langfuse && cd langfuse && docker compose up -d
# UI localhost:3000 → создать проект → public/secret ключи; OTLP на http://localhost:3000/api/public/otel
```

Переключить экспортеры (Basic-auth Langfuse подставится в `OTEL_EXPORTER_OTLP_HEADERS`):

```powershell
.venv\Scripts\python.exe scripts\otel\enable_claude_otel.py `
    --otlp http://localhost:3000/api/public/otel --public-key pk-... --secret-key sk-...
```

Ставит `OTEL_*_EXPORTER=otlp`, `OTEL_EXPORTER_OTLP_PROTOCOL=http/protobuf`, endpoint + `Authorization=Basic`.
Для SigNoz — `--otlp <endpoint>` (+ `--headers "k=v"` при необходимости), без ключей Langfuse.

## Реверс / opt-out

```powershell
.venv\Scripts\python.exe scripts\otel\enable_claude_otel.py --disable   # убирает РОВНО OTel-ключи
.venv\Scripts\python.exe scripts\otel\enable_claude_otel.py --status    # текущее состояние
```

`--disable` чистит только OTel-env (чужой `env`/`permissions` целы; перед мутацией пишется `.bak`).
Бэкенд — `docker compose down`. Поскольку всё в gitignored `settings.local.json`, на других машинах/в
CI телеметрия не включается без явного opt-in.

## Связь с P0/P1 и мост `otel_exporter.py`

JSONL (`hook-invocations.jsonl`, P0/P1) — лёгкий **hot-path**, всегда; OTel (P2) — **глубокий анализ** по
требованию. Поля JSONL названы OTel-совместимо (`tool_call_id` = `gen_ai.tool.call.id`, `error_type`,
`success`) — апгрейд = переименование, не переписывание. Если нужно слать ещё и hook-события в тот же
бэкенд — [`shared/otel_exporter.py`](../../../.claude/hooks/shared/otel_exporter.py) (`HookTracerAdapter`)
готов как мост (подключается отдельно; нативная эмиссия Claude Code богаче и не требует моста).

## ⚠ Граница верификации

Сквозная эмиссия OTel требует **запущенного `claude` + opt-in** и не верифицируется из хука/скрипта —
проверено только: корректность env-конфига (имена по [monitoring docs](https://code.claude.com/docs/en/monitoring-usage)),
идемпотентность/реверс тоггла, сохранность чужого `env`. После opt-in проверить вручную: в `console`
появились спаны `claude_code.tool.execution`; в Langfuse UI — traces.
