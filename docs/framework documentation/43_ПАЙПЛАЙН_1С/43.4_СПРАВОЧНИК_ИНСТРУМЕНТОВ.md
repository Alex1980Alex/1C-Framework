# 43.4 Справочник инструментов 1С по этапам (основа TOOL-PLAN)

> Полный перечень инструментов, используемых при решении задач 1С, разложенный по 4 этапам пайплайна.
> Это **основа для `TOOL-PLAN.md`** (см. [43.3 Шаг 1](43.3_МАРШРУТИЗАЦИЯ_ХУКИ_ИНСТРУМЕНТИРОВАНИЕ.md)) —
> копируй нужные строки в артефакт задачи. **Не все инструменты нужны в каждой задаче** — бери только
> необходимые (методики analyze/implement/va-bdd сами решают, что применять). Перечень заземлён на
> `allowed-tools` команд `/analyze-1c-task`, `/implement-1c-task` и методику `va-bdd-testing`.

## Сквозные (любой этап)

| Инструмент | Назначение |
|---|---|
| `Read` / `Glob` / `Grep` | Чтение файлов, поиск по исходникам/ТЗ/артефактам |
| `Write` / `Edit` | Запись артефактов (ANALYSIS-REPORT, отчёты, `.feature`); правка BSL — **предпочтительно через EDT-MCP**, не прямой Edit |
| `Skill(...)` | Активация методики этапа (analyze-1c-task-v2 / implement-1c-task / va-bdd-testing / code-verify) |
| `TodoWrite` / `Task` | Оркестрация, декомпозиция, субагенты |
| `pipeline_state.py` | Состояние 4 этапов (`init` / `done` / `approve` / `status`) |
| `tool_usage_report.py` | Оценка эффективности инструментов (W) → `TOOL-USAGE-REPORT.md` |
| `mcp__memory-orchestrator__route_and_save` / `unified_search` | Запись/поиск в памяти проекта |
| `mcp__llm-rotation__llm_complete` | Делегирование Hard/Medium-подзадач (Token Economy) |

## Этап 1-2 — Планирование + Дизайн (`/analyze-1c-task`, skill `analyze-1c-task-v2`)

**Основной инструмент анализа конфигурации — `1c-mcp-crud`** (живая база, по умолчанию).

| Группа | Инструменты | Назначение |
|---|---|---|
| **1c-mcp-crud** ⭐ | `get_metadata`, `get_metadata_structure`, `get_metadata_tree`, `list_metadata_objects`, `get_form_structure`, `execute_query`, `validate_query`, `find_references_to_object`, `get_access_rights`, `get_object_by_link`, `search_code`, `get_bsl_syntax_help`, `get_event_log` | Метаданные, формы, запросы на живых данных, ссылки, права, журнал |
| **edt-mcp** | `list_projects`, `list_modules`, `get_module_structure`, `read_method_source`, `read_module_source`, `get_metadata_details`, `find_references`, `get_method_call_hierarchy`, `search_in_code`, `go_to_definition`, `get_symbol_info`, `get_form_screenshot`, `get_project_errors` | Чтение кода/метаданных из EDT, граф вызовов, скриншот формы |
| **bsl-semantic-search** | `bsl_search`, `bsl_hybrid_search`, `bsl_call_graph`, `bsl_impact_analysis`, `bsl_object_info`, `bsl_coding_context`, `bsl_similar`, `bsl_dead_code` | Семантический/гибридный поиск по BSL, граф вызовов, impact-анализ |
| **bsl-code-search** | `search_symbols`, `find_callers`, `get_module_ast` | tree-sitter символы, кто вызывает, AST модуля |
| **bsl-platform-context** | `search`, `getMember`, `getMembers`, `getConstructors`, `info` | API платформы 1С 8.3.27 (типы, методы, конструкторы) |
| **pdf-vector-graph** | `search_documents`, `ask_question` | RAG по документации 1С 8.3.27 (первоисточник) |
| **1c-debug-hmr** (Фаза 2.5 Runtime Trace, опц.) | `debug_health_check`, `debug_connect`, `debug_set_breakpoint`, `debug_get_breakpoints`, `debug_ping`, `debug_stack_trace`, `debug_variables`, `debug_evaluate`, `debug_step`, `debug_targets` | Live BP-trace для алгоритмов с ≥3 runtime-ветвлений |

**Скиллы этапа:** `analyze-1c-task-v2`, `1c-doc-research` (документация 8.3.27 — первоисточник), `architecture-research`.

## Этап 3 — Кодирование (`/implement-1c-task`, skill `implement-1c-task`)

**Основной write-path — `edt-mcp`** (чтение+запись кода/метаданных). `1c-mcp-crud` — живые данные.

| Группа | Инструменты | Назначение |
|---|---|---|
| **edt-mcp** ⭐ | `write_module_source`, `read_module_source`, `get_module_structure`, `read_method_source`, `add_metadata_attribute`, `revalidate_objects`, `update_database`, `get_project_errors`, `get_content_assist`, `validate_query`, `find_references`, `get_metadata_details`, `get_applications` | Запись BSL/XML, реквизиты, обновление БД, проверка ошибок ПОСЛЕ записи |
| **1c-mcp-crud** | `execute_code`, `execute_query`, `validate_query`, `get_object_by_link`, `find_references_to_object`, `post_document`, `create_object`, `update_object`, `mark_for_deletion` | Прогон SQL/кода на живой базе (ДО и ПОСЛЕ), подготовка/очистка тестовых данных |
| **bsl-debugger** | `bsl_analyze`, `bsl_execute` | Статический анализ (линтер) + проверка чистой логики (OneScript) |
| **bsl_lint.py** (скрипт) | `--format` форматер; диагностики | Предпочтительный статанализ (Этап 4), BSL-форматер |
| **bsl-semantic-search** (рефакторинг) | `bsl_rename_symbol`, `bsl_replace_method_body`, `bsl_safe_delete_symbol` | Путь `[REFACTOR]`-точек (Этап 3R) |
| **bsl-code-search** | `find_callers`, `get_module_ast` | Поиск вызовов изменённых методов |
| **bsl-platform-context** | `search`, `getMember`, `getMembers` | API платформы при написании кода |
| **1c-debug-hmr** (Этап 5.x Live BP-verification) | `debug_connect`, `debug_set_breakpoint`, `debug_break_on_next`, `debug_ping`, `debug_stack_trace`, `debug_variables`, `debug_evaluate`, `debug_step`, `debug_session_diff`, `debug_session_summary`, `debug_arm_warm_rphosts`, `debug_capture_mode` | BP-trace на каждой `[ADDED]`/`[MODIFIED]` точке + regression diff |

**Скиллы этапа:** `implement-1c-task`, `bsl-refactoring-workflow`, `bsl-symbol-editing`, `code-verify` (после правок).

**Обязательные циклы:** SQL → `validate_query` → `execute_query` → запись; запись → `get_project_errors`;
после всех правок → `bsl_analyze`/`bsl_lint.py` → `get_project_errors` → `execute_query` (результат).

## Этап 4 — Тестирование (`/write-1c-tests` + `/run-1c-tests`, skill `va-bdd-testing`)

**Основной инструмент анализа — `1c-mcp-crud`** (живая TestDB; золотое правило: всё проверяется на реальной базе).

| Группа | Инструменты | Назначение |
|---|---|---|
| **1c-mcp-crud** ⭐ | `get_form_structure`, `get_metadata`, `get_metadata_tree`, `execute_query`, `execute_code`, `get_access_rights`, `validate_query`, `find_references_to_object` | Анализ форм/объектов; **Stage 4a pre-check** тестовых данных; setup через `execute_code` |
| **edt-mcp** | `read_module_source` (Form.Module), `get_form_screenshot` | Анализ модулей форм, скриншот |
| **bsl-semantic-search** / **ast-grep-mcp** | поиск, call graph, AST | Анализ объектной модели (state machine, движения, триггеры) |
| **bsl-platform-context** | `search`, `getMember(s)` | API VA / платформы |
| **mcp-onec-test-runner** (YAxUnit/METR) | `run_all_tests`, `run_module_tests`, `build_project`, `check_syntax_edt`, `check_syntax_designer_modules`, `launch_app`, `dump_config` | Юнит-тесты YAxUnit, сборка, проверка синтаксиса |
| **run-bdd.ps1** (PowerShell/Bash) | `-Feature`, `-RunId`, `-OutputJson`, `-MaxRetries` | Запуск VA BDD пофайлово (см. [17.5](../17_ТЕСТИРОВАНИЕ_1С/17.5_КОМАНДЫ_ПАЙПЛАЙНА.md)) |
| **Read / Grep / Write** | — | `.feature`-файлы, `Form.xml`, `.run-state.json` |

**Скиллы этапа:** `va-bdd-testing` (v1.1, Stage 4a).

## Шаблон TOOL-PLAN.md (копировать в папку задачи)

```markdown
# TOOL-PLAN — <slug>

| Этап | Инструменты (план) | Quality |
|---|---|---|
| Планирование | 1c-mcp-crud (get_metadata*/execute_query), edt-mcp (read_*), bsl-semantic-search | _ |
| Дизайн | + bsl-platform-context, pdf-vector-graph (docs), 1c-debug-hmr (Runtime Trace при ≥3 ветвлений) | _ |
| Кодирование | edt-mcp (write_module_source/update_database/get_project_errors), 1c-mcp-crud (execute_*), bsl_lint.py, 1c-debug-hmr (BP-verify) | _ |
| Тестирование | 1c-mcp-crud (Stage 4a pre-check), run-bdd.ps1, mcp-onec-test-runner | _ |

Лог — авто `data/hook-invocations.jsonl` (run_id); отчёт — `tool_usage_report.py --run-id <id> --task-dir <папка>`.
Quality: ✓ / ⚠ / ✗ (авто из err% + ручная заметка).
```
