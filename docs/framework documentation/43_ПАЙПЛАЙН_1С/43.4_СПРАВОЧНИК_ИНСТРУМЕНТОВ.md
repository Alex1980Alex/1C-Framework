## Обязательное использование памяти (гл. 27) — recall → apply → capture

> **ОБЯЗАТЕЛЬНО для каждой 1С-задачи.** Память ([гл. 27 Unified Memory](../27_UNIFIED_MEMORY/27.1_Обзор.md))
> подключается не только пассивно (авто-surfacing `memory-first-hook`), но и **активно** — обязательным
> циклом **recall → apply → capture**. Цель: не повторять прошлые грабли + накапливать опыт по задачам 1С.

| Фаза | Действие (обязательно) | Инструмент |
|---|---|---|
| **Recall** — старт (Планирование) | Явно искать в памяти прошлый опыт по теме / JIRA / объектам: похожие задачи, известные грабли, правила заказчика, факты об объектах | `mcp__memory-orchestrator__unified_search` + `mcp__vector-memory__search_patterns` |
| Recall (авто, пассивно) | Surfacing top-K `.md`-памяти в контекст — **дополняет** явный recall, не заменяет | `memory-first-hook` (UserPromptSubmit) |
| **Apply** — Дизайн / Кодирование | Учесть найденный паттерн/правило в `ANALYSIS-REPORT` и в коде | `mcp__vector-memory__apply_pattern` / `get_pattern` |
| **Capture** — после verify PASS (Тестирование) | Зафиксировать переиспользуемый приём в карантин (pending) | `mcp__skill-learning__capture_pattern` (уже в протоколе [code-verify](../../../.claude/skills/code-verify/SKILL.md)) |
| Capture — durable факт | Сохранить знание задачи + новое правило/грабли заказчика | `mcp__memory-orchestrator__route_and_save` + `.md`-память (`memory/<slug>.md` + указатель в `MEMORY.md`) |

**Минимальный обязательный минимум на задачу:** (1) `unified_search` по теме **в начале**; (2)
`capture_pattern` **после verify PASS** нетривиальной задачи; (3) при новом правиле/граблях заказчика —
запись в `.md`-память. Остальное (`apply_pattern`, `route_and_save`) — по релевантности находок.

> **Hard-enforcement (Stop-хук).** Минимум **принудителен**: Stop-хук
> [`memory-protocol-stop.py`](../../../.claude/hooks/memory-protocol-stop.py) блокирует завершение, если в
> сессии была 1С-задача (pipeline `1С-задача (…)`), но в транскрипте нет **recall** (`unified_search` /
> `search_patterns`) ИЛИ **capture** (`capture_pattern` / `route_and_save` / запись в `memory/*.md`).
> Детект — по фактическим tool_use (не raw-text). Стоит в Stop-цепочке после `pipeline-protocol-stop`.
> Опт-аут (trivial / MCP-down): `MEMORY_PROTOCOL_DISABLE=1`.

Подробности слоёв и инструментов: [27.2 Оркестратор](../27_UNIFIED_MEMORY/27.2_Оркестратор.md),
[27.3 Memory-First Hook](../27_UNIFIED_MEMORY/27.3_Memory_First_Hook.md),
[27.7 MCP инструменты](../27_UNIFIED_MEMORY/27.7_MCP_инструменты.md).

## Карта хранилищ памяти и потоки в 1С-пайплайне (одна картинка)

Все блоки хранения памяти (гл. 27) и их **чтение (←R) / обновление (→W)** по этапам 1С-задачи. Федерацию
координирует **memory-orchestrator** (`unified_search` — чтение через RRF k=60; `route_and_save` /
`propagate_update` — запись/распространение). Полная карта федерации (вне 1С-контекста) —
[27.12 Карта систем памяти](../27_UNIFIED_MEMORY/27.12_Memory_Systems_Map.md).

```
ЭТАП →            Планирование     Дизайн      Кодирование    Тестирование    Stop (конец сессии)
ХРАНИЛИЩЕ
──────────────────────────────────────────────────────────────────────────────────────────────
.md память        ←R recall         ←R          ←R             ←R              →W правило/грабли
(memory/+MEMORY)    (hook + unified_search)                                      (durable feedback)
learned_patterns  ←R search_        ←R apply    ←R apply                        →W harvest (after confirm)
(Qdrant)             patterns
skill-learning                                  ←R arm ×0.7    →W capture_       →W review/confirm
pending (JSONL)                                                  pattern (PASS)
memory_ai.db      ←R surfacing                                                  →W session-memory-save
(episodic SQLite)
skill_library     ←R routing                                                   →W skills-harvester
(Qdrant)
wiki_pages_v1     ←R surfacing(RRF)                                             →W L2→L5 promotion
(Qdrant, L3)
graph             ←R bsl_call_graph / bsl_impact_analysis (анализ кода)         →W авто-reindex on commit
(call graph)
──────────────────────────────────────────────────────────────────────────────────────────────
   ▲ ОРКЕСТРАТОР memory-orchestrator: unified_search (R, RRF k=60) · route_and_save / propagate_update (W)
```

| Хранилище | Что хранит | Чтение (R) | Обновление (W) |
|---|---|---|---|
| **`.md` память** (`memory/` + `MEMORY.md`) | курируемые факты user / feedback / project / reference (вкл. `feedback_1c_*`) | recall: авто `memory-first-hook` + явный `unified_search` | новое правило/грабли заказчика → `.md` + указатель в `MEMORY.md` (ADR-011: read-time merge + ручной promote) |
| **`learned_patterns`** (Qdrant) | паттерны с decayed Beta(7,3)-confidence | `search_patterns` / `apply_pattern` | harvest после `confirm_pattern` (epoch.bump) |
| **skill-learning карантин** (pending JSONL) | приёмы на модерации | плечо `skill_learning` в memory-first-hook (вес ×0.7) | `capture_pattern` после verify PASS → pending |
| **`memory_ai.db`** (SQLite, episodic) | важные сообщения, сводки сессий | surfacing | `session-memory-save` (Stop) |
| **`skill_library`** (Qdrant) | скиллы | роутинг скиллов | `skills-harvester` (Stop) |
| **`wiki_pages_v1`** (Qdrant, L3) | канон wiki | surfacing RRF (memory-first 4-layer) | L2→L5 promotion (Stop hook) |
| **graph** (`cache/bsl_call_graph.db` / Neo4j / `graph_embeddings`) | граф вызовов BSL | `bsl_call_graph`, `bsl_impact_analysis` (Дизайн) | авто-reindex on commit |

**Итог по 1С-задаче:** в начале — **read** из всех хранилищ (recall: явный `unified_search` + пассивный
surfacing); по ходу — **apply** найденных паттернов в дизайн/код; в конце — **write**: `capture_pattern`
(→ pending), `session-memory-save` (→ episodic), `.md` при новом правиле, + авто-harvest/promote/reindex на
Stop/commit. Обновление хранилищ — **по необходимости** (нашёл новое/подтвердил приём/правило заказчика), а
не на каждом шаге.

## Обязательное использование системы скиллов (гл. 11) — активация → лог → оценка

> **ОБЯЗАТЕЛЬНО для каждой 1С-задачи.** Каждый этап ведётся через профильный **skill** (методику), а не
> «вручную». Уже **принудительно**: [`code-skill-enforcer`](../../../.claude/hooks/code-skill-enforcer.py)
> блокирует Write/Edit без `Skill()` (Level A–F), task-protocol требует SKILL CHECK, `skill-router`
> маршрутизирует промпт на нужный скилл. Полная система — [гл. 11](../11_СИСТЕМА_СКИЛЛОВ/11.1_Обзор.md).

| Этап | Обязательный skill (методика) |
|---|---|
| Планирование + Дизайн | **analyze-1c-task-v2** (+ `1c-doc-research` для документации 8.3.27, `architecture-research`) |
| Кодирование | **implement-1c-task** (+ `bsl-refactoring-workflow` / `bsl-symbol-editing` для `[REFACTOR]`); **code-verify** после правок |
| Тестирование | **va-bdd-testing** |
| Сквозные | `skill-router` (маршрут), `memory-unified`, `framework-patterns` |

**Логирование** (переиспользует существующее, не дублирует):
- [`posttooluse-skill-metrics.py`](../../../.claude/hooks/posttooluse-skill-metrics.py) → `data/skill-accuracy.jsonl` (+ SQLite через `db_writer.log_skill_usage`);
- `data/session-skills.json` — скиллы, активированные за сессию;
- `data/skill-router.log` / `data/skill-router-fp.jsonl` — решения роутера + ложные срабатывания.

**Оценка эффективности** (гл. [11.7 Мониторинг и метрики](../11_СИСТЕМА_СКИЛЛОВ/11.7_Мониторинг_и_метрики.md)):
- [`scripts/skill_system_acceptance.py`](../../../scripts/skill_system_acceptance.py) — приёмочный вердикт системы (`gate_representative`);
- [`scripts/eval-skill-router.py`](../../../scripts/eval-skill-router.py) — honest pooled `action_f1` роутера;
- [`skill-quality-monitor.py`](../../../.claude/hooks/skill-quality-monitor.py) (Stop) — детект деградации скилла;
- [`scripts/skill-enforcement-dashboard.py`](../../../scripts/skill-enforcement-dashboard.py) + `data/skill-health-report.md` — дашборд использования/здоровья.

**Связь:** skill-метрики (accuracy / health) **дополняют** tool-эффективность (раздел «Инструментирование» W) и
память (capture) — все три петли кормят `skill-learning` и корректировку плана следующих задач.

## Обязательный внешний анализ (Infostart + GitHub best-practices) — для 1С-задач

> **ОБЯЗАТЕЛЬНО на этапе Планирование/Дизайн** (в дополнение к первоисточнику — документации 1С 8.3.27):
> перед реализацией 1С-задачи проанализировать внешние источники. **Каждый факт — с атрибуцией** (правило
> skill [`1c-doc-research`](../../../.claude/skills/1c-doc-research/SKILL.md)); найденное — в кеш
> (knowledge-cache), чтобы переиспользовать в следующих задачах.

| Источник | Доверие | Когда | Инструмент |
|---|---|---|---|
| Документация 1С 8.3.27 | **первоисточник** | Планирование | `pdf-vector-graph` (RAG) + skill `1c-doc-research` |
| **Infostart** (infostart.ru) | **доверенный** (1С) | Планирование/Дизайн | `WebSearch` / `WebFetch` + `1c-doc-research` |
| **GitHub best-practices** | доп. (stars / freshness) | Дизайн | `WebSearch` / `WebFetch` + [`prework-github-bp`](../../../.claude/hooks/prework-github-bp.py) (cache-first) |
| its.1c.ru | доп. (1С) | по необходимости | `WebSearch` + `1c-doc-research` |
| Stack Overflow / контекст ошибки | доп. | при ошибках | [`prework-stackoverflow`](../../../.claude/hooks/prework-stackoverflow.py) / `WebSearch` |

**Механизмы (уже есть):**
- [`prework-github-bp.py`](../../../.claude/hooks/prework-github-bp.py) (UPS-воркер) — cache-first surfacing
  GitHub best-practices по теме промпта (фильтр stars / freshness ≤365d);
- skill [`1c-doc-research`](../../../.claude/skills/1c-doc-research/SKILL.md) — протокол: документация 8.3.27 —
  первоисточник, `infostart.ru` / `its.1c.ru` — дополнение, **атрибуция каждого факта**;
- [`knowledge-cache-reminder.py`](../../../.claude/hooks/knowledge-cache-reminder.py) — после
  `WebSearch`/`WebFetch` создаёт mandatory-задачу сохранить найденное в кеш (`architecture-research/cache/`).

**Минимум на 1С-задачу:** (1) документация 8.3.27 (первоисточник); (2) **Infostart** по теме задачи;
(3) **GitHub best-practices** по подходу/реализации. Найденное — закэшировать с атрибуцией.

> **Hard-enforcement (Stop-хук).** Принудительно: Stop-хук
> [`research-protocol-stop.py`](../../../.claude/hooks/research-protocol-stop.py) (в Stop-цепочке после
> `memory-protocol-stop`) блокирует завершение, если в сессии была 1С-задача (pipeline `1С-задача (…)`), но
> в транскрипте **нет ни одного `WebSearch`/`WebFetch`** (факт внешнего анализа). Детект — по фактическим
> tool_use (не raw-text). Конкретные Infostart/GitHub — в block-сообщении (литеральную строку не требуем —
> иначе ложный блок). Опт-аут (trivial-правка): `RESEARCH_PROTOCOL_DISABLE=1`.

**Связь:** найденные паттерны → `apply` в дизайн/код; переиспользуемое правило/приём → память (`capture`,
раздел «Обязательное использование памяти»).
