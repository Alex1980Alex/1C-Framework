# 43.5.1 · Блок ВХОД — сообщение в чате → «это 1С-задача?»

> **Детальный разбор блока 1/6** каскада детектора 1С. Обзорная карта всей цепочки —
> [43.5 Сквозная карта](43.5_СКВОЗНАЯ_КАРТА.md) (§0). Это «нулевой этап»: всё, что
> происходит **до** первой команды пайплайна. Задача блока — превратить произвольное
> чат-сообщение в три ответа: **(1) это 1С-задача? (2) какой сложности? (3) каким режимом вести?**
> Код входной точки — [`onec-task-input.py`](../../../.claude/hooks/onec-task-input.py);
> вся логика — мост [`pipeline_1c_bridge.py`](../../../.claude/hooks/shared/pipeline_1c_bridge.py)
> (best-effort, функции **никогда не кидают**).

## Схема

```
┌─ ВХОД · сообщение в ЧАТ → «это 1С-задача?» ────────────────────────────────┐
│ Три формы входа — распознаются ДО анализа содержимого:                     │
│                                                                            │
│   • свободный текст   «Доработать проведение…»     ← основной случай       │
│        нет «/», нет пути  →  полная цепочка ① → развилка → ② → ③           │
│   • /слэш-команда     /analyze-1c-task GKSTCPLK-2182                       │
│        early-return  →  маршрут ведёт preflight самой команды              │
│   • путь к папке ТЗ   configuration/<JIRA>/docs/…                          │
│        аргумент /run-1c-task  →  resolve_task_input (kind=folder)          │
└────────────────────────────────────────────────────────────────────────────┘
                    │  событие UserPromptSubmit
                    ▼
        onec-task-input.py   (advisory · таймаут 5s · НЕ блокирует)
```

## Подробно

Сообщение из чата приходит в одной из **трёх форм**. Две из них **самоописательны** и сразу
знают, что делать; третья требует разбора по содержимому — именно ради неё существует весь
дальнейший каскад (① → ② → ③).

| Форма входа | Как распознаётся | Куда уходит |
|---|---|---|
| **Свободный текст** (основной) | нет ведущего `/`, не путь к папке | **полная цепочка** `route_1c_task` (блоки ①→②→③) |
| **Слэш-команда** | ведущий `/` (`detect_slash_command`) | **early-return** ([onec-task-input.py:32](../../../.claude/hooks/onec-task-input.py)); маршрут ведёт preflight самой команды |
| **Путь к папке ТЗ** | обращение к ФС (`configuration/<JIRA>/docs/`) | аргумент `/run-1c-task` → `resolve_task_input` (kind=folder) |

**Асимметрия обработки.** Формы 2–3 — короткий путь: для слэша хук сразу делает `return None`
(дублировать рекомендацию не нужно — у команды свой preflight), путь к папке разбирается уже
внутри `/run-1c-task`. Полную цепочку «детект → сложность → режим» проходит **только свободный
текст** — остальное в ней не нуждается.

### Перехват: `onec-task-input.py` (UserPromptSubmit, advisory)

[`OnecTaskInput.execute`](../../../.claude/hooks/onec-task-input.py) на **каждое** сообщение:

1. **Слэш-команда?** → `detect_slash_command(prompt)` истинно → `return None`.
   *Простыми словами: вы сами начали с `/команды` — хук молчит, дальше ведёт preflight этой команды.*
2. **Иначе** → зовёт `route_1c_task(prompt)` и по полю `flow` инъектит **рекомендацию** в
   `systemMessage`. Хук **advisory** — ничего не блокирует, только подсказывает Claude маршрут.
   *Простыми словами: на обычное сообщение хук тихо прикидывает, не 1С-задача ли это, и если да —
   подсказывает режим; навязать ничего не может.*

Почему advisory, а не блокирующий: финальное решение «это 1С / каким потоком» — **за Claude**
(память [[feedback-1c-detection-judgment-mine]]); хук — подсказка, при сомнении Claude спрашивает.

## Кратко (TL;DR)

- **3 формы входа:** свободный текст · `/слэш-команда` · путь к папке ТЗ.
- **Только свободный текст** идёт в полную цепочку детекта; слэш = `return None` (early-return);
  путь = аргумент `/run-1c-task`.
- Хук **advisory** (UserPromptSubmit, 5s, не блокирует) — рекомендует маршрут, решение за Claude.

## Реальный пример

**Сообщение в чате:** `Доработать проведение документа Реализация`

1. **Форма** — нет ведущего `/`, не путь к ФС → **свободный текст** (основной случай).
2. `detect_slash_command(...)` → **ложно** → НЕ early-return.
3. → `route_1c_task("Доработать проведение документа Реализация")` → управление уходит в
   **блок ①** ([43.5.2](43.5.2_ПОИСК_ПО_ШАБЛОНАМ.md)).
4. Хук **advisory**: получит `flow` от каскада и вставит рекомендацию в `systemMessage` — Claude
   увидит подсказку, но решает сам.

**Контраст (форма 2):** `/analyze-1c-task GKSTCPLK-2182` → `detect_slash_command` истинно →
`return None`: хук молчит, маршрут ведёт preflight команды `/analyze-1c-task`. Каскад ①→②→③ **не
запускается** — он не нужен, команда уже знает, что делать.
