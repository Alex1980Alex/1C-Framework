# 43.5.2 · Блок ① ПОИСК ПО ШАБЛОНАМ — `classify_1c_task` (regex)

> **Блок 2/6** детектор-каскада. Обзор — [43.5 Сквозная карта](43.5_СКВОЗНАЯ_КАРТА.md) (§0.3).
> Сердце детектора: из **сырой строки** сообщения чистыми регэкспами получить
> `{is_1c, jira, ttype, ask, code}` — детерминированно, **<1 мс, офлайн, воспроизводимо**.
> Код: [`classify_1c_task`](../../../.claude/hooks/shared/pipeline_1c_bridge.py).

## Схема

```
┌─ ① ПОИСК ПО ШАБЛОНАМ · classify_1c_task (regex · <1мс · офлайн) ───────────┐
│ is_1c = TRUE, если ИСТИНЕН любой из 4 путей (короткое замыкание ∨):        │
│                                                                            │
│   1. JIRA-код   [A-Z]{2,}-\d+                      → confident             │
│   2. _1C_DEFINITIVE (гкс_ ∨ configuration/)        → confident, без глагола│
│   3. _1C_CODE  (Менеджер.Член · событие · ЕСТЬNULL) → confident, это КОД   │
│   4. (_1C_SIGNAL термин ∨ _1C_STRONG CamelCase) ∧ _TASK_VERB глагол        │
│                                                                            │
│ confident_1c = (confidence ≥ 0.7) = JIRA ∨ литеральный 1С-код (_1C_CODE) ∨ │
│   гкс_/configuration (_1C_DEFINITIVE) ∨ CamelCase-маркер (_1C_STRONG)      │
│      путь 4 без сильного маркера →  confident=FALSE →  ask_1c              │
└────────────────────────────────────────────────────────────────────────────┘
```

## Подробно

**Вход — сырая строка; ни LLM, ни NLP.** Детект сидит в `UserPromptSubmit`-хуке (таймаут 5 с на
**каждое** сообщение) — LLM-вызов стоил бы латентности и токенов на любой ввод. Цена выбора:
словарь **заземлён на ~35 реальных ТЗ** `configuration/<JIRA>/docs/` ([[project-1c-task-input-taxonomy]]),
не на догадку «как пишут про 1С».

**Четыре независимых пути к `is_1c=True`** (трёхуровневая логика по «силе» сигнала):

- **Пути 1–2 — определяющие.** JIRA-код или жёсткий маркер (`гкс_`, путь `configuration/`) → 1С
  **сразу**, таск-глагол не нужен.
- **Путь 3 — наличие 1С-кода (ключевой признак).** Литеральный BSL-синтаксис самодостаточен,
  **глагол НЕ требуется** и сразу `confident_1c=True` ([[feedback-1c-code-presence-key-signal]]):
  вызов менеджера (`Документы.X`), событие (`ПередЗаписью`), закрывающее слово (`КонецПроцедуры`),
  токен запроса (`ЕСТЬNULL`), БСП-вызов (`ОбщегоНазначения.`). Маркеры — `re.U` **без `re.I`**.
- **Путь 4 — по смыслу, связкой.** Доменный термин (`_1C_SIGNAL`) **или** форменный маркер
  (`_1C_STRONG`) засчитывается **только в паре с таск-глаголом** (`_TASK_VERB`). Один термин без
  действия («покажи справочник») — не задача, а вопрос.

**Словари** (тюнятся заземлением на реальные ТЗ):

| Группа | Роль | Примеры |
|---|---|---|
| `_1C_DEFINITIVE` | жёсткий маркер → 1С без глагола (путь 2) | `гкс_…`, `configuration/…` |
| `_1C_CODE` | BSL-синтаксис → 1С без глагола + confident (путь 3) | `Документы.X` · `ПередЗаписью` · `КонецЕсли` · `ЕСТЬNULL` · `СрезПоследних` · `ОбщегоНазначения.` |
| `_1C_SIGNAL` | доменный термин → 1С с глаголом (путь 4) | реквизит · проведени · `документ` · справочник · `регистр` · разгрузк · `проба` |
| `_1C_STRONG` | сильный маркер → 1С + confident (путь 4) | `гкс_` · `Документ\.` · CamelCase-кириллица `[а-яё][А-ЯЁ][а-яё]` |
| `_TASK_VERB` | активатор пути 4 | доработ · исправ · добав · создат · провед · настро · заблокир · учт |

**Почему высокий recall не шумит:** ``-границы (чтобы «ин**форм**ация» не матчила `форм`);
CamelCase строго `re.U` без `re.I` (иначе класс схлопывается в «любые 3 кириллицы»); ни один путь
не сработал → `is_1c=False` → хук **молчит** (`return None`).

**Детект ≠ уверенность.** Путь 4 через «голый» термин+глагол даёт `is_1c=True`, но
`confident_1c=False`: система не угадывает режим, а **спрашивает** ([43.5.3 РАЗВИЛКА](43.5.3_РАЗВИЛКА.md)).

## Кратко (TL;DR)

- `classify_1c_task` — **regex, <1мс, офлайн**, вход = сырая строка, выход `{is_1c, jira, ttype, ask, code, confidence}` (confidence ∈ {0.0, 0.5, 0.7, 0.9, 1.0} — калиброванный скор силы 1С-сигнала; на нём строится развилка). **Veto-иммунны ≥ 0.9** (JIRA/код/`гкс_`/`configuration/`); confidence 0.7 (CamelCase) и ниже — veto-able (см. [43.5.4](43.5.4_ДОСМОТР_ПО_СМЫСЛУ.md)).
- **4 пути** к `is_1c`: JIRA · `_1C_DEFINITIVE` · `_1C_CODE` (всё — без глагола) · термин+глагол.
- Высокий **recall**; `is_1c` ≠ `confident_1c` — уверенность решает «прогон или вопрос».

## Реальный пример

**Трасса A — JIRA:** `GKSTCPLK-2182 Доработать создание Направления на разгрузку…`
→ `_JIRA.search` → `GKSTCPLK-2182` → путь 1 → **`is_1c=True`**, `confident_1c=True` (глагол даже не
проверяется — короткое замыкание `∨`). `ttype=T1`.

**Трасса D — вставленный код БЕЗ глагола и БЕЗ `гкс_`:**
`РегистрыСведений.СостоянияРегистрации.СрезПоследних(&Дата)`
→ JIRA нет, `гкс_` нет, таск-глагола нет; но **`_1C_CODE`** ловит `Менеджер.Член`
(`РегистрыСведений.С…`) + токен `СрезПоследних` → путь 3 → **`is_1c=True`**, `confident_1c=True`
(код самодостаточен). Фикс 2026-06-17: раньше фрагмент BSL без глагола промахивался.
