# 43.5.4 · Блок ② ДОСМОТР ПО СМЫСЛУ — SetFit-гейт → TF-IDF

> **Блок 4/6** детектор-каскада. Обзор — [43.5 Сквозная карта](43.5_СКВОЗНАЯ_КАРТА.md) (§0.3).
> Второй шанс для входов, что regex (①) не распознал уверенно: семантический классификатор по
> **смыслу**, а не по шаблону. Включается только на ветке «нет» развилки (confidence < 0.7).
> Код: [`onec_setfit_gate.py`](../../../.claude/hooks/shared/onec_setfit_gate.py) +
> [`onec_semantic_fallback.py`](../../../.claude/hooks/shared/onec_semantic_fallback.py); решение — [ADR-025](../../../.claude/skills/architecture-research/adr/025-1c-detector-setfit-stage2a-scaffold.md).

## Схема

```
┌─ ② ДОСМОТР ПО СМЫСЛУ · только для неуверенных (confidence < 0.7) ──────────┐
│                                                                            │
│   SetFit-гейт (ST+LR, ВКЛ)  →  warm-serve HTTP ~25мс  →  prob ∈ [0,1]      │
│        │ сервис не поднят / нет модели / ошибка                            │
│        ▼                                                                   │
│   откат на TF-IDF (onec_semantic_fallback.semantic_sim)                    │
│                                                                            │
│   prob ≥ порог  →  ask_1c   (МЯГКИЙ сигнал: только вопрос)                 │
│   ( TEI откл. 023 · LLM откл. 024 · SetFit 025 ✔ )                         │
└────────────────────────────────────────────────────────────────────────────┘
```

## Подробно

Регэкспы ① ловят **форму** (есть ли 1С-маркер / код / термин+глагол), но не **смысл**. Near-domain
формулировки без явных маркеров (описательный баг-репорт «после приёмки ТС осталось
заблокированным») regex упускает. Слой ② досматривает такие входы семантически.

**Каскад внутри блока (`_semantic_signal`):**
1. **SetFit-гейт** (ADR-025, **включён** `ONEC_SETFIT_ENABLE=1`) — обучаемый классификатор
   `SentenceTransformer rubert-tiny2 + LogisticRegression` (backend ST+LR: пакет `setfit`
   несовместим с transformers 5.x — [[reference-setfit-transformers5-st-lr]]). Зовётся через
   **warm-serve** (долгоживущий CPU-сервис, **~25мс**; in-process было бы ~6с > таймаут хука —
   [`onec_setfit_serve.py`](../../../scripts/onec_setfit_serve.py)).
2. **Откат на TF-IDF** — если гейт спит / сервис не поднят / ошибка → `_serve_prob` отдаёт `None` →
   `semantic_sim` (bag-of-words косинус по опорным фразам). Каскад **не ломается** ни в одной точке.

**Результат:** интегрированный каскад (regex+SetFit) на 230-GT — `is_1c` F1 **0.88 → 0.97**,
Recall **0.81 → 0.98** (+16.5pp): SetFit поймал 22 из 25 hard-кейсов, что regex упускал, без потери
precision. Две прежние попытки на frozen-представлениях отклонены: TEI Qwen3 коллапс (ADR-023),
LLM-on-tail net-neutral (ADR-024).

**Инвариант безопасности.** SetFit (как и TF-IDF) — **МЯГКИЙ** сигнал: `prob ≥ порог` промоутит
вход лишь в **`ask_1c`** (вопрос), НИКОГДА в `confident`/`auto`. Ошибочный флип деградирует в
вопрос — blast-radius безопасен. `_semantic_signal` возвращает `(score, source, hit)`, в маршрут
добавлен ключ `semantic_source ∈ {setfit, tfidf, skipped}` для наблюдаемости.

## Кратко (TL;DR)

- Семантический досмотр **только** неуверенных входов (confidence < 0.7).
- Каскад: **SetFit** (ST+LR, warm-serve ~25мс) → откат **TF-IDF**; graceful в любой точке.
- `prob ≥ порог` → **`ask_1c`** (мягкий сигнал, только вопрос). Каскад F1 0.88→0.97 (ADR-025 ✔).

## Реальный пример

**Hard-1С, что regex упустил:** `после приёмки транспортное средство осталось заблокированным`
→ ① regex: нет JIRA/`гкс_`/кода; «приёмк»/«заблокир» есть, но без явного объекта → confidence < 0.7
→ **② SetFit** через warm-serve → `prob≈0.54 ≥ порог` → **`ask_1c`** (подтвердить «это 1С?»).
Без слоя ② это был бы `none` (ложно-отрицательный).

**Контраст (не-1С):** `как настроить redis кластер за час` → ② SetFit → `prob≈0.37 < порог` →
сигнала нет → `none` (молчит). Семантика корректно различила near-domain.
