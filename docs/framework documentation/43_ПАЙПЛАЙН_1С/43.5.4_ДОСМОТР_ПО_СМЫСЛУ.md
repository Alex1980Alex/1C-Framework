# 43.5.4 · Блок ② ДОСМОТР ПО СМЫСЛУ — SetFit-гейт → TF-IDF

> **Блок 4/6** детектор-каскада. Обзор — [43.5 Сквозная карта](43.5_СКВОЗНАЯ_КАРТА.md) (§0.3).
> Второй шанс для входов, что regex (①) не распознал уверенно: семантический классификатор по
> **смыслу**, а не по шаблону. Включается только на ветке «нет» развилки (confidence < 0.7).
> Код: [`onec_setfit_gate.py`](../../../.claude/hooks/shared/onec_setfit_gate.py) +
> [`onec_semantic_fallback.py`](../../../.claude/hooks/shared/onec_semantic_fallback.py); решение — [ADR-025](../../../.claude/skills/architecture-research/adr/025-1c-detector-setfit-stage2a-scaffold.md).

## Схема

```
┌─ ② ДОСМОТР ПО СМЫСЛУ · только для неуверенных (confidence < 0.7) ──────────┐
│                                                                            │
│   SetFit-гейт (ST+LR, opt-in ВЫКЛ по умолч.) → warm-serve HTTP ~6мс (прогр) │
│        │ ВЫКЛ / нет модели / сбой → откат TF-IDF (onec_semantic_fallback)  │
│        ▼                                                                   │
│   откат на TF-IDF (onec_semantic_fallback.semantic_sim)                    │
│                                                                            │
│   prob ≥ порог  →  ask_1c   (МЯГКИЙ сигнал: только вопрос)                 │
│   ( TEI откл. 023 · LLM откл. 024 · SetFit 025 ✔ )                         │
│                                                                            │
│   ─ veto НЕ-1С тех-контекста (Находка 2, уточнено C4) ────────────────    │
│   слабый сигнал (regex/семантика) + явный НЕ-1С маркер (FastAPI/Qdrant/    │
│   docker/эмбеддинг/…) → is_1c=False → none.                                │
│   Veto-ИММУННЫ ТОЛЬКО confidence ≥ 0.9: JIRA / литеральный код / гкс_ /    │
│   configuration. CamelCase-кириллица (confidence 0.7) — veto-able.          │
└────────────────────────────────────────────────────────────────────────────┘
```

## Подробно

Регэкспы ① ловят **форму** (есть ли 1С-маркер / код / термин+глагол), но не **смысл**. Near-domain
формулировки без явных маркеров (описательный баг-репорт «после приёмки ТС осталось
заблокированным») regex упускает. Слой ② досматривает такие входы семантически.

**Каскад внутри блока (`_semantic_signal`):**
1. **SetFit-гейт** (ADR-025) — обучаемый классификатор
   `SentenceTransformer rubert-tiny2 + LogisticRegression` (backend ST+LR: пакет `setfit`
   несовместим с transformers 5.x — [[reference-setfit-transformers5-st-lr]]). **Opt-in** (env
   `ONEC_SETFIT_ENABLE`, по умолчанию **ВЫКЛ**; нужна обученная модель). Выключен / нет модели /
   сбой → откат на TF-IDF (`onec_semantic_fallback`). По умолчанию каскад работает на TF-IDF.
   Включён → HTTP warm-serve `127.0.0.1:8077`, timeout `2.0s` (< 5s таймаута хука); прогретый
   ответ **~6мс**, холодный → авто-старт сервиса + откат на TF-IDF этот раз
   ([`onec_setfit_serve.py`](../../../scripts/onec_setfit_serve.py)).
2. **Откат на TF-IDF** — если гейт спит / сервис не поднят / ошибка → `_serve_prob` отдаёт `None` →
   `semantic_sim` (bag-of-words косинус по опорным фразам). Каскад **не ломается** ни в одной точке.

**Результат:** интегрированный каскад (regex+SetFit) на 230-GT — `is_1c` F1 **0.88 → 0.97**,
Recall **0.81 → 0.98** (+16.5pp): SetFit поймал 22 из 25 hard-кейсов, что regex упускал, без потери
precision. Две прежние попытки на frozen-представлениях отклонены: TEI Qwen3 коллапс (ADR-023),
LLM-on-tail net-neutral (ADR-024).

**Инвариант безопасности.** SetFit (как и TF-IDF) — **МЯГКИЙ** сигнал: `prob ≥ порог` промоутит
вход лишь в **`ask_1c`** (вопрос), НИКОГДА в `confident`/`auto`. Ошибочный флип деградирует в
вопрос — blast-radius безопасен. `_semantic_signal` возвращает `(score, source, hit)`, в маршрут
добавлен ключ `semantic_source ∈ {setfit, tfidf, skipped}` для наблюдаемости.

**Veto НЕ-1С тех-контекста (Находка 2, 2026-06-18; сужено C4).** Семантика поднимает *recall*; её
зеркало — слой *precision*: denylist [`_NON_1C_CONTEXT`](../../../.claude/hooks/shared/pipeline_1c_bridge.py)
высокоточных маркеров НЕ-1С разработки (FastAPI/Qdrant/pytest/эмбеддинг/docker/webhook/микросервис/…).
`_1C_SIGNAL` несёт полисемичные слова (обработк/отчёт/механизм/форма/обмен/регистр/профил) — на
русскоязычной разработке фреймворка они с глаголом давали ~80% FP. **Veto:** (regex ИЛИ семантика) +
явный НЕ-1С маркер → `is_1c=False` → `none` (молчим, а не шумный `ask_1c`).

**Veto-иммунитет (уточнение C4):** иммунны **только** входы с `confidence ≥ 0.9` — JIRA-код, литеральный
1С-код (`_1C_CODE`), `гкс_`, `configuration/`. Настоящая 1С-задача, упомянувшая инструмент фреймворка
(«доработать гкс_X, добавить в FastAPI»), защищена. **CamelCase-кириллица (`_1C_STRONG`, confidence 0.7)**
veto-иммунитета **не имеет** — не-1С тех-контекст её перевешивает. Пример: «функция
`ПолучитьЭмбеддинг` в langchain» → CamelCase → confident (0.7), но `langchain`/`эмбеддинг` → veto →
`none`. Намеренно исключены неоднозначные маркеры (очереди сообщений = реальный 1С-обмен, `mcp`, голый
`api`). Калибровка GT+holdout: **precision 0.86 → 0.97, recall 0.98 не упал**, ключ `non_1c_context` в
маршруте для наблюдаемости.

## Кратко (TL;DR)

- Семантический досмотр **только** неуверенных входов (confidence < 0.7).
- Каскад: **SetFit** (ST+LR, opt-in ВЫКЛ, warm-serve ~6мс прогретый) → откат **TF-IDF**; graceful в любой точке. По умолчанию работает TF-IDF.
- `prob ≥ порог` → **`ask_1c`** (мягкий сигнал, только вопрос). Каскад F1 0.88→0.97 (ADR-025 ✔).
- **Veto НЕ-1С тех-контекста** (зеркало precision): любой сигнал + FastAPI/Qdrant/docker/… → `none`;
  veto-иммунны **только confidence ≥ 0.9** (JIRA/код/`гкс_`/`configuration/`); CamelCase (0.7) — veto-able
  (Находка 2, уточнено C4 → precision 0.86→0.97, recall цел).

## Реальный пример

**Hard-1С, что regex упустил:** `после приёмки транспортное средство осталось заблокированным`
→ ① regex: нет JIRA/`гкс_`/кода; «приёмк»/«заблокир» есть, но без явного объекта → confidence < 0.7
→ **② SetFit** (если включён) через warm-serve → `prob≈0.54 ≥ порог` → **`ask_1c`**; иначе TF-IDF-откат (подтвердить «это 1С?»).
Без слоя ② это был бы `none` (ложно-отрицательный).

**Контраст (не-1С):** `как настроить redis кластер за час` → ② SetFit → `prob≈0.37 < порог` →
сигнала нет → `none` (молчит). Семантика корректно различила near-domain.

**Veto (Находка 2):** `Доработать обработку ошибок в API роутере FastAPI` → ① regex: «обработк»+«доработать»
дают слабый is_1c (0.5), но в тексте `FastAPI` → veto → `none` (молчим, а не шумный `ask_1c`).
Контраст: `доработать обработку гкс_ЛабораторныйАнализ с выгрузкой в postgres` → `гкс_` = confidence 0.9
→ veto НЕ применяется (реальная 1С-задача с упоминанием СУБД защищена).

**Veto + CamelCase (C4):** `функция ПолучитьЭмбеддинг в langchain` → ① `_1C_STRONG` CamelCase →
`confident_1c=True`, confidence 0.7; но `langchain`/`эмбеддинг` — НЕ-1С маркеры → veto **применяется**
(0.7 < 0.9, иммунитета нет) → `none`. Сравни: `ПолучитьЭмбеддинг` в prompt без НЕ-1С контекста → без veto
→ `ask_flow`/`auto` по сложности (действие названо).
