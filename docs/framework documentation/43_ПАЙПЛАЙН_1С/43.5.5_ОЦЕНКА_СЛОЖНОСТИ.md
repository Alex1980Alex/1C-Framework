# 43.5.5 · Блок ③ ОЦЕНКА СЛОЖНОСТИ — `estimate_effort`

> **Блок 5/6** детектор-каскада. Обзор — [43.5 Сквозная карта](43.5_СКВОЗНАЯ_КАРТА.md) (§0.4).
> Для уверенно-распознанной 1С-задачи прикидывает **трудозатраты** → банда (простая/средняя/
> сложная), которая в [РЕЖИМ](43.5.6_РЕЖИМ.md) выбирает поток (AUTO / спросить / гейт). Код:
> [`estimate_effort`](../../../.claude/hooks/shared/pipeline_1c_bridge.py#L355),
> config [`_EFFORT_CFG`](../../../.claude/hooks/shared/pipeline_1c_bridge.py#L330).

## Схема

```
┌─ ③ ОЦЕНКА СЛОЖНОСТИ · estimate_effort (эвристика трудозатрат) ─────────────┐
│ points = base(1) + Σ весов сигналов в тексте:                              │
│                                                                            │
│   modify +2 · heavy_obj +5 · cross +3 · multi +2 · folder +2               │
│   ttype_T1/T3 +1 · light −2 (ТОЛЬКО downgrade, при pos==0)                 │
│                                                                            │
│   points ≤ 2 → simple     3–5 → medium     ≥ 6 → complex                   │
└────────────────────────────────────────────────────────────────────────────┘
```

## Подробно

`estimate_effort` — **эвристика** (грубый оценщик, НЕ замена ревью). Веса и пороги вынесены в
config `_EFFORT_CFG` — тюнятся **без правки кода** (паттерн `a2_signals` из skill-router). Возврат
`{complexity, points, signals}`.

| Группа сигналов | Вес | Примеры ключей |
|---|---|---|
| `light` (косметика) | **−2** | опечатк · текст сообщен · наименован · переименов · комментар · заголовок |
| `modify` | **+2** | доработать · добавить реквизит/колонку/поле/форму · изменить алгоритм/запрос |
| `heavy_obj` | **+5** | новый/создать документ·справочник·регистр·отчёт·обработку · план обмена/видов |
| `cross` | **+3** | обмен данными · интеграц · RLS · права доступа · новую роль · подсистему · миграц |
| `multi` | **+2** | несколько · массов · по всем · пакетн · все документы |
| `folder` | **+2** | вход = готовая ТЗ-папка (`is_folder`) |
| `ttype_T1` / `ttype_T3` | **+1** | тип задачи (новое / «не учтено») |

**Расчёт:** `points = base(1) + Σ(modify, heavy_obj, cross, multi, folder, ttype)` → банды
`≤2 simple · 3–5 medium · ≥6 complex`.

**`light` — только downgrade, не counterweight.** Применяется лишь при `pos == 0` (нет позитивных
сигналов работы). Иначе имя-атрибута «Комментарий»/«Заголовок» в medium-задаче ложно занижало бы
её в simple. Это блок-специфичная тонкость, легко упускаемая при тюнинге весов.

> Детект (②) и оценка сложности (③) используют **разные словари**: «рефакторинг» есть в `cross`
> (вес сложности), но НЕ в `_TASK_VERB` (активатор детекта) — поэтому на чисто-английском
> «Отрефактори search manager» детектор молчит (③ даже не вызывается).

## Кратко (TL;DR)

- **Эвристика** трудозатрат: `points = base + Σ весов` → банды `≤2 / 3–5 / ≥6` (simple/medium/complex).
- Веса в config `_EFFORT_CFG`, тюнятся без кода; `heavy_obj` (+5) — самый тяжёлый сигнал.
- `light` (−2) **только downgrade** при `pos==0` — не топит реальные задачи именем атрибута.

## Реальный пример

**Средняя:** `GKSTCPLK-2182 Доработать создание Направления на разгрузку для заблокированных ТС`
→ «доработать» ∈ `modify` (+2) · `ttype_T1` (+1) → `points = 1+2+1 =` **4** → банда **medium** →
РЕЖИМ `ask_flow` (спросить: AUTO или гейт?).

**Сложная:** `Создать новый регистр накопления гкс_УчётРазгрузки и провести документ`
→ «новый регистр накопления» ∈ `heavy_obj` (+5) · `ttype_T1` (+1) → `points = 1+5+1 =` **7** →
банда **complex** → РЕЖИМ `gated` (`/analyze` → ревью → `/implement`).
