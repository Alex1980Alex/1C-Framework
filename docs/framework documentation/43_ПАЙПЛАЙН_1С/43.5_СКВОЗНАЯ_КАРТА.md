# 43.5 Сквозная карта: парадигма → команды → инструменты и системы (1С-задача)

> Сквозной top-down разрез решения 1С-задачи: **4-этапная парадигма** (ADR-017/018) → **специализированные
> команды Пайплайн 1С** → **инструменты и системы** (+ их обязательные enforcer) с **оценкой покрытия и
> пробелов**. Сводит воедино [43.1](43.1_ОБЗОР_И_ПАРАДИГМА.md) (парадигма), [43.2](43.2_КОМАНДЫ_И_РЕЖИМЫ.md)
> (команды), [43.3](43.3_МАРШРУТИЗАЦИЯ_ХУКИ_ИНСТРУМЕНТИРОВАНИЕ.md) + [43.4](43.4_СПРАВОЧНИК_ИНСТРУМЕНТОВ.md)
> (инструменты/системы). Состояние на 2026-06-15.

## Сквозная диаграмма (одна картинка)

```
ПАРАДИГМА (этап)        КОМАНДА 1С                 ОСНОВНЫЕ ИНСТРУМЕНТЫ                ENFORCER (Stop/гейт)
──────────────────────────────────────────────────────────────────────────────────────────────────────
1. Планирование ──┐
   архитектуры     ├─ /analyze-1c-task ──────► 1c-mcp-crud · edt-mcp ·            pipeline-protocol-stop
2. Дизайн          │     (Фазы 1-5)            bsl-semantic-search ·              (пайплайн заведён)
   реализации     ─┘                          bsl-platform-context ·             + approve-гейт G4
                        ▼ [approve-гейт G4]     pdf-vector-graph · 1c-debug-hmr    (pipeline-gate)
                                                (Runtime Trace 2.5)
3. Кодирование ──── /implement-1c-task ──────► edt-mcp(write) · 1c-mcp-crud ·     code-skill-enforcer
                        (Этапы 0-8)            bsl-debugger · bsl_lint.py ·       (Skill() до Write/Edit)
                                                1c-debug-hmr (Live BP-verify 5.x)
4. Тестирование ─── /write-1c-tests ─────────► 1c-mcp-crud (Stage 4a) ·          (зелёный .run-state →
                    /run-1c-tests              run-bdd.ps1 · mcp-onec-test-runner  этап 4 done)
──────────────────────────────────────────────────────────────────────────────────────────────────────
   AUTO: /run-1c-task = analyze → авто-approve → implement → test за один проход (без паузы)
──────────────────────────────────────────────────────────────────────────────────────────────────────
СКВОЗНЫЕ СИСТЕМЫ (поперёк ВСЕХ этапов) → ЕДИНЫЙ task-completion gate (один чеклист, без каскада):
   • Память (гл.27)       recall → apply → capture        ─┐
   • Внешний анализ        WebSearch (Infostart+GitHub)    ─┼→ onec-task-completion-stop
   • Система скиллов (гл.11)  Skill() на каждом этапе          │   (+ code-skill-enforcer: skill на Write)
   • Инструментирование (W)  TOOL-PLAN → лог → оценка        ─┘   (+ tool_usage_report — отчёт)
```

## Сквозные системы (поперёк всех этапов)

Четыре системы работают на каждом этапе и **принудительны** через свой Stop-enforcer (все с opt-out + graceful):

| Система | Что делает на задаче | Логирование | Оценка эффективности | Enforcer (opt-out) |
|---|---|---|---|---|
| **Память (гл. 27)** | recall (`unified_search`/`search_patterns`) → apply (`apply_pattern`) → capture (`capture_pattern`/`route_and_save`/`.md`) | `hook-invocations` / транскрипт; `learned_patterns`, `skill-learning` pending | `tool-effectiveness` + confidence Beta(7,3) | `onec-task-completion-stop` (единый, `ONEC_TASK_GATE_DISABLE=1`) |
| **Система скиллов (гл. 11)** | каждый этап через профильный `Skill()` (analyze/implement/va-bdd/code-verify) | `skill-accuracy.jsonl` (posttooluse-skill-metrics + db_writer), `session-skills.json`, `skill-router.log` | `skill_system_acceptance.py`, `eval-skill-router.py`, `skill-quality-monitor`, `skill-health-report.md` | `code-skill-enforcer` (Level A-F) |
| **Внешний анализ** | docs 8.3.27 (первоисточник) + **Infostart** (доверенный) + **GitHub best-practices** через `WebSearch`/`WebFetch` | `knowledge-cache` (`architecture-research/cache/`) после WebSearch | reuse кеша + атрибуция (1c-doc-research) | `onec-task-completion-stop` (единый, тот же gate) |
| **Инструментирование (W)** | TOOL-PLAN (план) → лог (`hook-invocations`) → оценка (`tool_usage_report.py`) → `TOOL-USAGE-REPORT.md` | `data/hook-invocations.jsonl` (`correlationid=run_id`) | `tool_usage_report.py` (err%/avg_ms ✓/⚠/✗) + `tool-effectiveness.jsonl` (`--rollup`) | — (отчёт; в AUTO — шаг оркестрации) |

Плюс **пайплайн-парадигма** сама принудительна: `pipeline-protocol-stop` (ADR-018) блокирует завершение,
если была правка без проводки через `pipeline/<slug>/.pipeline-state.json`.

## Оценка покрытия и пробелы (честно)

**Хорошо покрыто (✓):**
- **Анализ/Дизайн** — тройка live-данные (1c-mcp-crud) + код (edt-mcp) + семантика (bsl-semantic-search) + первоисточник-RAG (pdf-vector-graph) + опц. Runtime Trace (1c-debug-hmr); ревью закрыт approve-гейтом **G4**.
- **Кодирование** — write-path edt-mcp с обязательными циклами (`validate_query`→`execute_query`→write; write→`get_project_errors`), статанализ (bsl_lint/bsl_analyze), **Live BP-verification** каждой точки.
- **Тестирование** — VA BDD + **Stage 4a** pre-check данных (экономит ~95% на «нет данных») + retry/auto-fix + YAxUnit.
- **4 обязательные петли enforced** (пайплайн / память / внешний анализ / скиллы) — забыть любую нельзя без явного opt-out.

**Осталось by-design** (фикс = false-block / суть режима — обоснованно):
- **research-relevance (N7)** — засчитывается любой `WebSearch`/`WebFetch`; проверка релевантности Infostart/GitHub
  неизбежно даёт false-block (легитимный 1С-запрос находит Infostart без слова «infostart»). Симметрично recall.
- **AUTO авто-approve (N9 / G4)** — смысл AUTO-режима; компенсируется хард-правилом «AUTO ≠ игнор блокеров» +
  меткой `approved_by=auto`. Enforce ревью в AUTO противоречит режиму.
- **apply_pattern (H4)** — нет tool-сигнала «применил паттерн»; recall+capture обязательны, apply — по релевантности.
- **advance по имени файла (N12)** + **session_start / git-edge (N2 / N8)** — graceful best-effort.
- **W cross-task «корректировка плана»** — `tool-effectiveness.jsonl` отчётный; авто-петля обучения на нём — non-goal (нет потребителя).

**Открытый пункт:**
- **Сквозной прогон `/run-1c-task`** — нужен 1 живой e2e-прогон (приёмка, не код; кодовые риски низкие).

> **Детальный лог** закалки тонких мест **N1–N12** + закрытия пробелов **H1–H7** (вкл. единый task-completion
> gate, граф call-graph на commit, межсессионный gate) — в
> [roadmap 260614 §18](../../roadmap/260614_ROADMAP_1C_COMMANDS_4STAGE_ALIGNMENT.md)
> (umbrella `pipeline/impl-thin-spots-hardening/` + `impl-43-gaps-fixes/`).
