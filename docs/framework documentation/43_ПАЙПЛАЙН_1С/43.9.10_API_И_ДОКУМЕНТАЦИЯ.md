# 43.9.10 API платформы и документация 8.3.27

> **Тип:** авторитетная справка по платформе 1С:Предприятие 8.3.27 — типы/методы/конструкторы API и
> смысловые вопросы по механизмам. Глава каталога [43.9](43.9_ИНСТРУМЕНТЫ_ПО_ТИПАМ.md). Этапы: **2-3**.
> Внешний анализ (Infostart/GitHub) как **обязательный контур** — в [43.4](43.4_СПРАВОЧНИК_ИНСТРУМЕНТОВ.md);
> здесь — платформенная справка как **инструмент**.

## Назначение
Не гадать по training-памяти, а получить первоисточник: точная сигнатура метода платформы, возвращаемый тип,
конструкторы; «как работает механизм» по документации 8.3.27.

## Инструменты

| Функция | Сервер | Что даёт | Подводный камень |
|---|---|---|---|
| `search` / `getMember` / `getMembers` / `getConstructors` / `info` | bsl-platform-context | API 8.3.27: типы, методы, свойства, конструкторы | Java-jar + путь к платформе |
| `search_documents` / `ask_question` / `research` | pdf-vector-graph | RAG по документации 8.3.27 (смысловой вопрос) | cold-start ~мин ([[feedback-pdf-mcp-init-duration]]) |
| `get_platform_documentation` | edt-mcp | справка платформы в контексте EDT | — |
| `get_bsl_syntax_help` | 1c-mcp-crud | локальная справка по синтаксису BSL | без обращения к платформенному контексту |
| skill `1c-doc-research` | методика | протокол: доки 8.3.27 = первоисточник, Infostart/its.1c.ru = дополнение, **атрибуция** + кеш | каждый факт с атрибуцией |

## Выбор среди альтернатив

- **Точная сигнатура/тип метода платформы** → `bsl-platform-context` (`getMember`/`info`; живой прогон:
  `ПолучитьМакет` → `ПолучитьМакетОформления`, возвращает ТабличныйДокумент).
- **«Как работает механизм» (смысл)** → `pdf-vector-graph` (`ask_question`/`search_documents`) +
  оформление по `1c-doc-research`.
- **Быстрая синтакс-справка не выходя из ИБ** → `get_bsl_syntax_help` (1c-mcp-crud).
- **В контексте EDT** → `get_platform_documentation`.

> Документация 8.3.27 — **первоисточник**; внешние источники (Infostart/its.1c.ru/GitHub) — дополнение **с
> атрибуцией**, и это **обязательный** контур 1С-задачи (см. [43.4 «Внешний анализ»](43.4_СПРАВОЧНИК_ИНСТРУМЕНТОВ.md)).
> Найденное — в knowledge-cache (`knowledge-cache-reminder` после WebSearch/WebFetch).

## Когда применять
Дизайн/Кодирование — перед использованием незнакомого метода платформы (сигнатура/тип) и при вопросах по
механизмам (проведение, СКД, формы) — вместо догадки.
