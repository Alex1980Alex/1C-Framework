# 43.9.2 Данные и runtime живой ИБ

> **Тип:** работа с **живой информационной базой** — запросы, прогон BSL, чтение/запись данных, права, журнал.
> Глава каталога [43.9](43.9_ИНСТРУМЕНТЫ_ПО_ТИПАМ.md). Этапы: **1** (проверка данных), **3/4** (setup/verify
> на реальной базе). Основной сервер — **`1c-mcp-crud`** (HTTP к публикации 1С). Метаданные (структура) — в
> [43.9.1](43.9.1_МЕТАДАННЫЕ_И_ИНВЕНТАРЬ.md); деплой конфигурации — в [43.9.11](43.9.11_ДЕПЛОЙ_И_ИБ.md).

## Назначение
Получить/проверить **данные** и **поведение** на живой ИБ: SQL-запросы, серверный BSL (расчёты, рендер,
setup тестовых данных), навигация по ссылкам, эффективные права, журнал регистрации, CRUD объектов.

## Инструменты

| Функция | Сервер | Что делает | Подводный камень |
|---|---|---|---|
| `validate_query` | 1c-mcp-crud | синтаксис+семантика запроса **без** исполнения | всегда **перед** `execute_query` на проде |
| `execute_query` | 1c-mcp-crud | SQL к живой ИБ | без `ПЕРВЫЕ N`/`ГДЕ` — таймаут; ссылки = `{_objectRef…}` |
| `execute_code` | 1c-mcp-crud | серверный BSL: расчёты, рендер печати→PDF, setup данных | результат в переменную `Результат`; пишет в живую ИБ |
| `get_object_by_link` / `get_link_of_object` | 1c-mcp-crud | конвертация `{_objectRef}` ↔ навигационная ссылка | параметр `link` (не `navigation_link`) |
| `get_access_rights` | 1c-mcp-crud | права по ролям; **с `user_name`** — эффективные права пользователя | `user_name` = **логин ИБ** (не Наименование справочника), напр. `o.karankevich@sodru.com` |
| `get_event_log` | 1c-mcp-crud | журнал регистрации | параметры `limit`/`levels` (не `count`/`level`) |
| `post_document` / `create_object` / `update_object` / `mark_for_deletion` | 1c-mcp-crud | CRUD объектов/проведение | **только TestDB** или явное согласие; на проде — `execute_code` в транзакции |

## Выбор среди альтернатив

- **Чтение данных** → `execute_query` (не `execute_code` — проще, безопаснее). Сложный расчёт/рендер/побочный
  эффект → `execute_code`.
- **Запись** → в живую ИБ через `execute_code`/CRUD **только на TestDB** или с подтверждения; метаданные
  пишутся **не сюда**, а через [43.9.5](43.9.5_ЗАПИСЬ_И_РЕФАКТОРИНГ.md).
- **Права** → `get_access_rights` (с `user_name` для конкретного пользователя — логин ИБ достаётся через
  `ИдентификаторПользователяИБ` → `ПользователиИнформационнойБазы.НайтиПоУникальномуИдентификатору`).
- **Рендер печати для verify** → `execute_code` → `ТабДок.Записать(PDF)` → Read PDF ([[reference-1c-printform-render-verify]]).

## Обязательный цикл (Кодирование/Тестирование)
`validate_query` → `execute_query` (ДО правки, baseline) → … → `execute_query`/`execute_code` (ПОСЛЕ, verify).
Stage 4a (тесты): pre-check тестовых данных на живой TestDB перед сценарием.

## Когда применять
Планирование — проверить реальные данные/числа. Кодирование — baseline/после-правки прогон. Тестирование —
setup TestDB + runtime-verify (золотое правило: всё проверяется на реальной базе).
