# 43.9.3 Чтение и поиск кода

> **Тип:** найти и прочитать BSL-код (по смыслу / по символу / по тексту) + чтение исходников модулей и
> методов. Глава каталога [43.9](43.9_ИНСТРУМЕНТЫ_ПО_ТИПАМ.md). Этапы: **1-2** (найти эталон/понять код),
> **3** (контекст при правке). Граф вызовов/«кто кого зовёт» — отдельно в [43.9.4](43.9.4_ГРАФ_И_IMPACT.md).

## Назначение
Две связанные задачи: (а) **найти** нужный код в ~2k модулей (по смыслу, имени или тексту) и (б) **прочитать**
конкретный модуль/метод. На входе обычно описание («как это уже делали») или точное имя символа.

## Инструменты

| Функция | Сервер / тул | Что ищет/читает | Подводный камень |
|---|---|---|---|
| `bsl_search` / `bsl_hybrid_search` | bsl-semantic-search | **смысл**: эталонная реализация, похожий код | гибрид RRF (dense+bm25) |
| `bsl_similar` | bsl-semantic-search | похожие на заданный фрагмент | — |
| `bsl_coding_context` / `bsl_context` | bsl-semantic-search | контекст вокруг символа/темы | — |
| `search_symbols` / `get_module_ast` | bsl-code-search | **точные символы** (tree-sitter), AST модуля | нужен `/mcp reconnect` после правок; кириллица в regex — фикс 2026-06-21 ([[feedback-bsl-code-search-empty]]) |
| `search_code` | 1c-mcp-crud | текстовый поиск по BSL конфигурации | без LSP |
| `search_in_code` / `go_to_definition` / `get_symbol_info` | edt-mcp | поиск/переход/инфо по символу в EDT | снапшот EDT |
| `read_module_source` / `read_method_source` / `get_module_structure` / `list_modules` | edt-mcp | чтение модуля/метода/структуры | основной способ читать BSL из EDT |
| `Read` | нативный | прочитать `.bsl`-файл напрямую | путь от cwd; кириллица в пути — mojibake ([[feedback-cyrillic-path-bash]]) |
| `Grep` | нативный | литерал/regex по файлам | ASCII `\w`/`\b` не матчат кириллицу → `[\wА-Яа-яЁё]` |
| `ast-grep-mcp` | ast-grep-mcp | структурный поиск по AST BSL | — |
| serena (`find_symbol` и др.) | serena (LSP) | LSP-символы/навигация | ide-assistant контекст |
| `bsl_list_methods` | codepilot1c | методы модуля + сигнатуры + доки | хост плагина (`-32000` если выкл.) |

## Выбор среди альтернатив

- **Не знаешь имя (по смыслу)** → `bsl_search`/`bsl_hybrid_search` (живой прогон: «разгрузка заблок. ТС» →
  нужный метод, rel 1.123). Это самый частый старт «как это уже делали».
- **Знаешь имя символа** → `bsl-code-search` `search_symbols` (точно) или edt `go_to_definition`.
- **Литеральный текст** → `Grep` (быстро) / `search_code` (через ИБ).
- **Структурный паттерн** (форма синтаксиса) → `ast-grep` / serena.
- **Прочитать конкретный метод/модуль** → edt `read_method_source`/`read_module_source` (или `Read` файла).

## Когда применять
Планирование/Дизайн — найти эталон и понять существующую реализацию **до** написания своего кода (правило
analyze-1c-task: использовать готовое, следовать паттернам). Кодирование — контекст при правке.
