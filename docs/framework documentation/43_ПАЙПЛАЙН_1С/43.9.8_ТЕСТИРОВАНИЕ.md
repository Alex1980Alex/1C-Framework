# 43.9.8 Тестирование

> **Тип:** автоматические тесты конфигурации — приёмочные/UI (BDD) и модульные (YaXUnit). Глава каталога
> [43.9](43.9_ИНСТРУМЕНТЫ_ПО_ТИПАМ.md). Этап: **4 Тестирование**. Setup/verify данных на живой TestDB — в
> [43.9.2](43.9.2_ДАННЫЕ_И_RUNTIME.md); BP-отладка теста — в [43.9.7](43.9.7_ОТЛАДКА.md).

## Назначение
Проверить функционал автотестами: бизнес-сценарий через UI (Vanessa BDD) или модульную логику (YaXUnit), со
сборкой/проверкой синтаксиса и прогоном на TestDB.

## Инструменты

| Функция | Сервер / скрипт | Тип теста | Подводный камень |
|---|---|---|---|
| `run-bdd.ps1` (`-Feature`/`-RunId`/`-OutputJson`/`-MaxRetries`) | PowerShell + Vanessa Automation | **BDD/UI** (`.feature`) | пофайловый прогон с resume (`.run-state.json`); harness VA — [[reference-va-debug-attach]] |
| skill `va-bdd-testing` (v1.1) | методика | BDD | Stage 4a — **обяз. pre-check** тестовых данных |
| `run_all_tests` / `run_module_tests` | mcp-onec-test-runner | **YaXUnit** (юнит) | подключение к TestDB |
| `build_project` / `check_syntax_edt` / `check_syntax_designer_modules` / `check_syntax_designer_config` | mcp-onec-test-runner | сборка + проверка синтаксиса | перед прогоном |
| `launch_app` / `dump_config` | mcp-onec-test-runner | запуск приложения / выгрузка конфы | — |
| `run_yaxunit_tests` / `debug_yaxunit_tests` | edt-mcp | YaXUnit из EDT (+ отладка) | в связке с EDT launch |
| skill `yaxunit-unit-testing` + `/write-1c-unit-tests` → `/run-1c-unit-tests` | методика + команды | **YaXUnit** (юнит) | рукописные assert-тесты серверной логики; деплой расширения `UnitTests` (`LoadConfigFromFiles`+`UpdateDBCfg`); прогон `mcp-onec-test-runner`→JUnit→`.run-state.json` (см. [17.6](../17_ТЕСТИРОВАНИЕ_1С/17.6_НАПИСАНИЕ_YAXUNIT_ТЕСТОВ.md)) |
| `qa_generate` / `qa_plan_scenario` / `qa_run` / `qa_validate_feature` | codepilot1c | QA-контур: генерация / план сценария / прогон / валидация фичи | хост плагина (`-32000` если выкл.); альтернативный движок к VA BDD |

## Выбор среди альтернатив

- **Бизнес-сценарий / форма / цепочка процессов** → **VA BDD** (`run-bdd.ps1` + skill `va-bdd-testing`).
  Пайплайн `/write-1c-tests` → `/run-1c-tests` (цепной прогон с resume).
- **Модульная логика (функция/процедура)** → **YAxUnit**: методика `yaxunit-unit-testing` +
  `/write-1c-unit-tests` → `/run-1c-unit-tests` (прогон через `mcp-onec-test-runner`, или edt
  `run_yaxunit_tests` для связки с отладкой). Методика написания тестов — [17.6](../17_ТЕСТИРОВАНИЕ_1С/17.6_НАПИСАНИЕ_YAXUNIT_ТЕСТОВ.md).
- **QA-контур codepilot1c** (`qa_generate`/`qa_plan_scenario`/`qa_run`/`qa_validate_feature`) — альтернативный
  движок генерации/прогона сценариев (через хост плагина); основной приёмочный трек остаётся VA BDD.
- **Проверка синтаксиса/сборка перед тестом** → `mcp-onec-test-runner` `build_project`/`check_syntax_*`.
- **Данные для теста** → setup/verify на живой TestDB через [43.9.2](43.9.2_ДАННЫЕ_И_RUNTIME.md) (золотое
  правило: всё проверяется на реальной базе; Stage 4a pre-check обязателен).

## Когда применять
Тестирование: VA BDD для приёмки сценариев; YaXUnit для модульных инвариантов; перед прогоном — синтаксис/сборка;
после — verify данных на TestDB.
