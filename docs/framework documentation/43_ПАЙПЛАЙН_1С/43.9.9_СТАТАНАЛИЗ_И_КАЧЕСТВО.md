# 43.9.9 Статанализ и качество кода

> **Тип:** статическая проверка качества без исполнения — код-смелы, сложность, маркеры валидации,
> форматирование, профилирование. Глава каталога [43.9](43.9_ИНСТРУМЕНТЫ_ПО_ТИПАМ.md). Этапы: **3** (быстрый
> линт перед коммитом), **4** (глубокий аудит). Runtime-отладка — в [43.9.7](43.9.7_ОТЛАДКА.md).

## Назначение
Поймать дефекты/смелы/нарушения до прода: диагностики по всем `.bsl`, маркеры валидации EDT, форматирование под
стандарт, профилирование «узких мест».

## Инструменты

| Функция | Сервер / скрипт | Что даёт | Стоимость |
|---|---|---|---|
| `bsl_lint.py` (`--format`) ⭐ | скрипт (bsl-ls) | форматер + диагностики | **авто** (детачено на `.bsl` Write/Edit, ADR-036) |
| `bsl_analyze` | bsl-debugger | статический анализ модуля (OneScript) | быстро |
| `bsl_analyze_method` 🔒 | codepilot1c | сложность / unused-параметры / try-риски метода | быстро · 🔒 advisory-кандидат (ADR-035), `•` в onec-task-gate |
| `get_project_errors` / `get_problem_summary` / `get_markers` | edt-mcp | маркеры валидации по объекту/конфе | парный с `revalidate_objects` ([43.9.5](43.9.5_ЗАПИСЬ_И_РЕФАКТОРИНГ.md)) |
| `get_check_description` | edt-mcp | описание правила-диагностики | справочно |
| `start_profiling` / `stop_profiling` / `get_profiling_results` | edt-mcp | замер производительности | runtime-замер |
| `SonarQube BSL` + `run-sonar-analysis.ps1` | sonar-scanner | смелы/сложность/`ЕСТЬNULL`/утечки врем. хранилища по всей конфе (180 правил) | серверный скан (минуты) |
| `SonarQube MCP` (`sonar_mcp_launch.py`) | on-demand MCP (lazy-mcp кат. `code-quality`, ADR-042) | issues / quality-gate / rules / triage через MCP | запускается по требованию (не в корневом `.mcp.json`) |
| `sonar_rescan_verify.py` (mode=changed-lines) | скрипт | дельта-гейт: BLOCKER/CRITICAL по **изменённым строкам** (`git diff -w -U0`), не по всему файлу | пишет `onec-sonar-rescan-state.json`; выход из `onec-task-completion-stop` (ADR-037) |
| `sonar_issues_pull.py` (`--format worklist\|sarif\|both`) / `sonar_setup_quality_gate.py` / `sonar_setup_quality_profile.py` / `sonar_quality_gate_check.py` / `sonar_sources.py` | скрипты | worklist / **SARIF 2.1.0** issues · QG · профиль правил · hard-gate · источники | zero-dep; SARIF-контракт находок = R4 ADR-034 |

## Выбор среди альтернатив

- **Быстрый цикл (перед коммитом/после правки)** → `bsl_lint.py --format` + `get_project_errors` (маркеры EDT
  после записи). Сложность одного метода → `bsl_analyze_method`.
- **Глубокий аудит всей конфы** → `SonarQube` (`run-sonar-analysis.ps1`) — но **Sonar-баги фиксить только через
  `/fix-sonar-task`**, не ad-hoc (PATTERN 2.14, [ADR-033](../../../.claude/skills/architecture-research/adr/033-sonar-remediation-stage.md));
  scope-гейт: править только кастом (`гкс_*`), не вендорную БСП. QG-блокер по новому коду — `sonar_quality_gate_check.py`
  (opt-in `SONAR_QG_HARD`).
- **Производительность** → edt `*_profiling`.
- ⚠ `run-sonar-analysis.ps1` может вернуть `exit 255` в пост-шаге, но **анализ загружен** — статус по API
  (`/api/project_analyses`), не по exit-коду ([43.7 §SonarQube](43.7_АНАЛИЗ_ВСЕЙ_КОНФИГУРАЦИИ.md)).

## Когда применять
Кодирование — `bsl_lint.py`/`get_project_errors` после каждой правки (обяз. цикл). **Тестирование/завершение —
ОБЯЗАТЕЛЬНЫЙ Sonar re-scan изменённого/добавленного `.bsl`** (хард-гейт [ADR-037](../../../.claude/skills/architecture-research/adr/037-mandatory-sonar-rescan-changed-1c-code.md) в `onec-task-completion-stop`: дельта **0 BLOCKER/CRITICAL** по **изменённым строкам** — mode=changed-lines: пересечение issue-строк с `git diff -w -U0` изменённых `.bsl`, а не весь файл (`scripts/sonar_rescan_verify.py`, вырожденный new-code baseline не гейтит); Clean-as-You-Code на свои правки, default-ON; Sonar-down→skip, opt-out `ONEC_SONAR_GATE_DISABLE=1`). Полный аудит всей конфы (`run-sonar-analysis.ps1`) — по релизам / on-demand + dead-code ([43.9.4](43.9.4_ГРАФ_И_IMPACT.md)). Sonar-баги фиксить только через `/fix-sonar-task` (ADR-033).
