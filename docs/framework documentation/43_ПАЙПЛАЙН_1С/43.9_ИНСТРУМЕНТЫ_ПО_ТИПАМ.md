# 43.9 Инструменты по типам — выбор среди альтернатив

> **Глава-каталог инструментов 1С, сгруппированных по ТИПУ возможности** (что нужно сделать), а не по
> этапу или по серверу. Главная ценность — там, где одну задачу закрывает **не один, а несколько**
> инструментов: какой выбрать по умолчанию, чем отличаются, где у каждого подводный камень. Третья линза
> поверх [43.4 (по этапам, на задачу)](43.4_СПРАВОЧНИК_ИНСТРУМЕНТОВ.md) и
> [43.7 (анализ всей конфигурации, по слоям)](43.7_АНАЛИЗ_ВСЕЙ_КОНФИГУРАЦИИ.md). Оговорки — из реальных
> прогонов 2026-06-21/23 (см. 43.7) и памяти `feedback_*`/`reference_*`.

## Зачем отдельный слой

| Глава | Линза | Вопрос, на который отвечает |
|---|---|---|
| [43.4](43.4_СПРАВОЧНИК_ИНСТРУМЕНТОВ.md) | по **этапу** (на задачу) | «что взять в TOOL-PLAN на Планирование/Дизайн/Кодирование/Тестирование» |
| [43.7](43.7_АНАЛИЗ_ВСЕЙ_КОНФИГУРАЦИИ.md) | по **слою** (вся конфигурация) | «чем сделать массовый аудит всей конфы» |
| **43.9 (эта)** | по **типу возможности** | «**на эту операцию есть несколько тулов — каким и почему**» |

Многие операции (доступ к данным, поиск кода, отладка, формы/СКД, тестирование, API платформы)
покрываются **несколькими** инструментами с разными сильными/слабыми сторонами. Эта глава сводит
альтернативы в один экран и даёт правило выбора (default + когда переключаться).

## 1. Данные и метаданные (живая ИБ)

| Инструмент | Сильная сторона | Подводный камень | Когда брать |
|---|---|---|---|
| **`1c-mcp-crud`** ⭐ | живые данные + метаданные + код: `execute_query`/`execute_code`/`get_metadata*`/`get_form_structure`/`get_access_rights`/`find_references_to_object`/`get_event_log` | пишет в живую ИБ — осторожно с `create/update/post/mark_for_deletion` | **дефолт** для запросов, прав, runtime-прогона |
| **`edt-mcp`** | типизированная модель EDT: `get_metadata_details` (дети объекта), `find_references`, `get_method_call_hierarchy`, `get_symbol_info` | работает на in-memory снапшоте EDT — может отстать от диска ([[feedback-edt-mcp-stale-snapshot]]) | точные свойства объекта/ссылки/иерархия вызовов |
| **`codepilot1c`** | `scan_metadata_index`, `edt_metadata_details`, `bsl_list_methods` | MCP-хост плагина EDT (:8766) — `-32000` если выключен/токен разошёлся ([[reference-codepilot1c-mcp-host]]) | альт-ридер метаданных/методов, если EDT-MCP недоступен |

**Правило:** запросы/данные/права/код-прогон → `1c-mcp-crud`; «состав и свойства объекта» (реквизиты/ТЧ/формы)
→ `edt-mcp get_metadata_details` (надёжнее, чем `bsl_object_info`). `get_metadata_tree` (566 ОМ) ≠ FS-обход
(438 каталогов с кодом) — разные линзы, обе валидны.

## 2. Поиск кода (семантический и символьный)

| Инструмент | Что ищет | Подводный камень | Когда брать |
|---|---|---|---|
| **`bsl-semantic-search`** ⭐ | смысл: `bsl_search`/`bsl_hybrid_search` (эталон, похожее), `bsl_similar` | `bsl_object_info` капризен на `гкс_*` (`not found`) | «как это уже делали», поиск по описанию |
| **`bsl-code-search`** | точные символы: `search_symbols`, `find_callers`, `get_module_ast` (tree-sitter) | требует `/mcp reconnect` после правок; кириллица в regex — фикс 2026-06-21 ([[feedback-bsl-code-search-empty]]) | точное имя метода/символа, «кто вызывает» |
| **`Grep`** | литеральный текст/regex по файлам | ASCII `\w`/`\b` не матчат кириллицу — использовать `[\wА-Яа-яЁё]` | быстрый текстовый поиск, токены |
| **`ast-grep-mcp`** | структурный паттерн по AST BSL | — | поиск/замена по синтаксической форме |

**Правило:** не знаешь имя → `bsl_search` (смысл); знаешь имя/символ → `bsl-code-search`; литерал → `Grep`;
структурный рефактор-поиск → `ast-grep`.

## 3. Граф вызовов и impact-анализ

| Инструмент | Охват | Когда брать |
|---|---|---|
| **`bsl_impact_analysis`** (semantic-search) ⭐ | транзитивный «кто сломается» (d0/1/2) | **перед правкой любого экспортного метода** (живой прогон: 24 затронутых символа) |
| **`bsl_call_graph` / `bsl_dead_code`** | граф вызовов / мёртвый экспорт | анализ связности, cleanup (3596 кандидатов) |
| **`find_callers`** (bsl-code-search) | точные callers по имени | перед `[REFACTOR]`/удалением символа |
| **`build_call_graph.py` → `bsl_call_graph.db`** | граф всей конфы (~33k симв./80k вызовов) | массовая перестройка перед reindex |
| **`analyze_run.py --mode graph`** | авто-отчёт (dangling/orphan) | регулярный аудит (`data/reports/graph/`) |

## 4. Запись кода и метаданных

| Инструмент | Что пишет | Подводный камень | Когда брать |
|---|---|---|---|
| **`edt-mcp`** ⭐ | BSL (`write_module_source`), метаданные (`create_metadata`/`modify_metadata`), `update_database` | роли **не создаёт** (файлами); `.mxlx` **не компилирует** ([[feedback-edt-mcp-mxlx-not-compiled]]); снапшот может отстать | **дефолт write-path** для BSL/XML/реквизитов |
| **`Edit`** (нативный) | точечная правка `.bsl` на диске | EDT-снапшот → потом `revalidate`/`update_database` | хирургическая правка, когда EDT-write неудобен |
| **`bsl-symbol-editing`** (skill) | замена тела метода / safe-delete через нативный Edit | `bsl_replace_method_body`/`bsl_safe_delete_symbol` сервером **не экспонируются** | `[REFACTOR]`: тело/удаление |
| **`bsl_rename_symbol`** (semantic-search) | переименование символа (cross-file) | — | `[REFACTOR]`: rename |

**Правило:** BSL/метаданные → `edt-mcp`; rename символа → `bsl_rename_symbol`; тело/удаление → `bsl-symbol-editing`;
роли → **файлами** (.mdo + Rights.rights + регистрация в Configuration.mdo, [[project-1c-bsp-roles-workflow]]).

## 5. Отладка и runtime-трейс

| Инструмент | Тип | Подводный камень | Когда брать |
|---|---|---|---|
| **`1c-debug-hmr`** ⭐ | live RDBG + hot-reload + persistent session (`.active.json`) | alias принимается «молча» — верифицировать `rac infobase list` ([[feedback-1c-debug-hmr-alias-validation]]); HTTP-service spawn вне attach ([[feedback-1c-debug-hmr-recycle-scope]]) | **дефолт** live BP-trace (переживает правки wrapper'а) |
| **`1c-debug`** | live RDBG (без HMR) | пере-attach при правке wrapper'а | если HMR не нужен |
| **`bsl-debugger`** | OneScript, статика (без живой 1С) | не runtime живой ИБ | проверка чистой логики/линт |
| **`edt-mcp`** (debug) | через EDT launch (`debug_launch`, `set_breakpoint`, `run_yaxunit_tests`) | поднимает клиент из EDT | отладка в связке с EDT-запуском |

**Правило:** живой BP-trace 1С → `1c-debug-hmr` (для 1С-задач де-факто обязателен,
[[feedback-live-bp-trace-mandatory]]); 1550 — HTTP-порт ([[feedback-1c-debug-url-protocol]]).

## 6. Формы / СКД / макеты (UI-артефакты)

| Инструмент | Read | Write (offline) | Подводный камень |
|---|---|---|---|
| **`cc-1c-skills`** ⭐ (offline) | `form-info`/`skd-info`/`mxl-info`/`meta-info`/`role-info` | **`mxl-compile`/`decompile` round-trip, `skd-edit` (25 ops)** | per-object процесс — дорого на масштабе; вендорён (ADR-031) |
| **`codepilot1c`** | `inspect_form_layout` (отлично) | form-write | `inspect_template` не читает `.mxlx`; `dcs_manage` read сломан ([[reference-codepilot1c-form-template-dcs-tools]]) |
| **`edt-mcp`** | `get_form_layout_snapshot` ⚠ JVM-флаг, `get_form_screenshot` | — | bounds только при `nativeFormLayoutRender=FALSE` ([[feedback-edt-mcp-form-bounds-render-flag]]); `.mxlx` не компилирует |

**Правило:** структуру формы — `codepilot1c inspect_form_layout` / `edt-mcp`; **правку `.mxl/.mxlx/.dcs`** —
**`cc-1c-skills`** (единственный надёжный offline round-trip); рендер-verify печати → `execute_code` →
PDF → Read ([[reference-1c-printform-render-verify]]).

## 9. Статанализ и качество

| Инструмент | Охват | Стоимость | Когда брать |
|---|---|---|---|
| **`bsl_lint.py`** ⭐ | BSL-форматер (`--format`) + диагностики | мгновенно | перед коммитом/диагностикой |
| **`bsl-debugger` `bsl_analyze`** | статический анализ модуля | быстро | проверка чистой логики |
| **`bsl_analyze_method`** (codepilot1c) | сложность/unused/try-риски метода | быстро | ревью крупного/изменённого метода |
| **`ast-grep-mcp`** | структурный поиск/замена по AST | быстро | массовые однотипные правки |
| **`SonarQube BSL`** | smells/сложность/`ЕСТЬNULL`/утечки врем. хранилища по всей конфе (180 правил) | серверный скан (минуты) | глубокий аудит по релизам; remediation `/fix-sonar-task` |

**Правило:** быстрый цикл → `bsl_lint.py`/`bsl_analyze`; глубокий аудит → `SonarQube` (но Sonar-баги фиксить
**только** через `/fix-sonar-task`, не ad-hoc — [43.7 §remediation](43.7_АНАЛИЗ_ВСЕЙ_КОНФИГУРАЦИИ.md), [ADR-033]).

## Как выбрать (сводка-решение)

1. **Нужны данные/прогон/права** → `1c-mcp-crud`. Свойства объекта → `edt-mcp get_metadata_details`.
2. **Ищешь код:** по смыслу → `bsl_search`; по имени → `bsl-code-search`; литерал → `Grep`.
3. **Меняешь экспортный метод** → сперва `bsl_impact_analysis` (кто сломается).
4. **Пишешь BSL/метаданные** → `edt-mcp`; rename → `bsl_rename_symbol`; роли → файлами.
5. **Отлаживаешь живую логику** → `1c-debug-hmr` (BP/variables/evaluate).
6. **Правишь форму/СКД/макет** → структура: codepilot/edt; **offline-правка**: `cc-1c-skills`.
7. **Тестируешь** → сценарий: VA BDD; модуль: YaXUnit; данные: на живой TestDB.
8. **Вопрос по платформе** → API: `bsl-platform-context`; механизм: `pdf-vector-graph` + `1c-doc-research`.
9. **Качество** → быстро: `bsl_lint.py`; глубоко: `SonarQube` (фикс через `/fix-sonar-task`).
10. **Применить в ИБ** → `edt-mcp update_database` (+ обновить поставляемые профили при правке прав).

> Принцип (как в [43.4](43.4_СПРАВОЧНИК_ИНСТРУМЕНТОВ.md)/[43.7](43.7_АНАЛИЗ_ВСЕЙ_КОНФИГУРАЦИИ.md)):
> это **toolbox-каталог**, а не обязательный список. Обязательный минимум на 1С-задачу (память
> recall→capture · скилл-методика · внешний анализ Infostart/GitHub · циклы
> `validate_query`→`execute_query`→`get_project_errors`) принуждается хуками
> (`onec-task-completion-stop`, `code-skill-enforcer`, `pipeline-gate`, `pipeline-protocol-stop`) — см.
> [43.4](43.4_СПРАВОЧНИК_ИНСТРУМЕНТОВ.md). Здесь — **как выбрать среди альтернатив**, когда инструмент не один.
