# 43.9 Инструменты по типам — индекс

> **Каталог инструментов 1С-пайплайна, разнесённый по ТИПУ возможности** — по главе на тип (43.9.1–43.9.12).
> Правило: каждая функция/тул/скрипт приписана **ровно к одной** главе (**непересечение**); мульти-серверные
> инструменты (`edt-mcp`, `1c-mcp-crud`) распределены **по функциям** (напр. `write_module_source`→43.9.5,
> `update_database`→43.9.11, `debug_*`→43.9.7). Третья линза поверх [43.4 (по этапам, на задачу)](43.4_СПРАВОЧНИК_ИНСТРУМЕНТОВ.md)
> и [43.7 (анализ всей конфигурации, по слоям)](43.7_АНАЛИЗ_ВСЕЙ_КОНФИГУРАЦИИ.md).

## Обязательность high-leverage инструментов (ADR-036)

Часть инструментов промоутнута из advisory в **условно-обязательные** ([ADR-036](../../../.claude/skills/architecture-research/adr/036-promote-high-leverage-1c-tools-variant-a.md), вариант A):

| `find_callers`/`bsl_call_graph` | [43.9.4](43.9.4_ГРАФ_И_IMPACT.md) | **advisory** (`•`, перед `[REFACTOR]`) | — |

(прежнее поведение). Per-task escape для trivial: `ONEC_TOOLGATE_HARD_DISABLE=1`.

**T3–T4 advisory-кандидаты** (ADR-035, уровни «T3 — conditional, applies-when» и «T4 — recommended/passive»;
сюрфейсятся `•` в gate + измерительный лог `onec-toolgate-events.jsonl`, **НЕ блок** — копят follow_rate перед
решением о промоуте): `get_form_screenshot` ([43.9.6](43.9.6_ФОРМЫ_СКД_МАКЕТЫ.md), T3), `bsl_analyze_method`
([43.9.9](43.9.9_СТАТАНАЛИЗ_И_КАЧЕСТВО.md), T3), `bsl-platform-context`/`pdf-vector-graph`
([43.9.10](43.9.10_API_И_ДОКУМЕНТАЦИЯ.md), T4). (`find_callers`/`bsl_call_graph` — **не дублируем**: их диспозиция

## Валидатор presence_rate по всему каталогу

[`scripts/onec_pipeline_tool_validation.py`](../../../scripts/onec_pipeline_tool_validation.py) считает
**presence_rate** (доля 1С-сессий, где тул использован) для **всех** инструментов каталога 43.9 по
`data/hook-invocations.jsonl` (1С-сессия = где использован ≥1 инструмент пайплайна), группирует по 12 типам,
выдаёт per-category coverage + вердикт adoption (`heavy`≥0.5 / `occasional` / `unused`) + observed-вне-каталога
пробелы. Карта **адопции** (кто реально используется), сигнал к рассмотрению промоута — **не** мерило
безопасности hard (survivorship). Запуск: `python scripts/onec_pipeline_tool_validation.py [--json] [--window-days N] [--category 43.9.N]`.
(Узкий T1/T2 валидатор advisory-кандидатов ADR-035 — [`scripts/onec_toolgate_validation.py`](../../../scripts/onec_toolgate_validation.py).)

### Два валидатора — почему раздельно (не сливать)

Это два инструмента под РАЗНЫЕ вопросы (разный источник / знаменатель / окно / цель); слияние смешало бы
task- и session-метрики и governance- с adoption-целью:

| Ось | `onec_toolgate_validation.py` (узкий) | `onec_pipeline_tool_validation.py` (широкий) |
|---|---|---|
| Источник | `onec-toolgate-events.jsonl` (per-1С-**задача**, курируемые сигналы) | `hook-invocations.jsonl` (per-call, **все** тулы) |
| Знаменатель | 1С-**задача** (точно — по факту срабатывания gate) | 1С-**сессия** (эвристика: ≥1 инструмент пайплайна) |
| Охват | 3–7 advisory-кандидатов (T1/T2 ADR-035) | 113 тулов / 12 категорий |
| Окно | **фиксированное** (06-22→07-06, ADR-035 Фаза 1) | скользящее `--window-days` |
| Вердикт | `promote-candidate`/`keep-advisory`/`insufficient` (governance-решение) | `heavy`/`occasional`/`unused` + coverage + пробелы |
| Назначение | **РЕШЕНИЕ** о промоуте конкретных тулов в hard | **дашборд адопции** всего каталога |

**Решение: держать раздельно.** Дублирование минимально (общее — `acceptance_common` + сама идея presence_rate;
каталоги разного масштаба) → DRY-выигрыш от слияния ~нулевой, а ясность пострадала бы (задача vs сессия,
governance vs adoption). Точность узкого (per-задача, по факту завершения gate) при слиянии деградировала бы до
per-сессия. При нужде **единого входа** — тонкий диспетчер `{gate|catalog}`, зовущий оба, без слияния логики.

## Принцип (как и в 43.4/43.7)

Это **toolbox-каталог**, а не перечень обязательного. Обязательный минимум на 1С-задачу
(память · скилл-методика · внешний анализ · циклы `validate_query`→`execute_query`→`get_project_errors`)
принуждается хуками (`onec-task-completion-stop`, `code-skill-enforcer`, `pipeline-gate`,
`pipeline-protocol-stop`) — см. [43.4](43.4_СПРАВОЧНИК_ИНСТРУМЕНТОВ.md). Здесь — **как выбрать среди
альтернатив, когда инструмент не один**. Оговорки в главах — из реальных прогонов
([43.7](43.7_АНАЛИЗ_ВСЕЙ_КОНФИГУРАЦИИ.md)) и памяти `feedback_*`/`reference_*`.
