## Контекст

`prework-github-bp` — Pre-Work worker (UserPromptSubmit через `prework_dispatcher`, §14.4 Option B):
перед задачей фаззи-матчит промпт к темам в кеше `architecture-research/cache` с GitHub-контентом
(`github_repos_count > 0`), фильтрует по свежести (`last_verified` ≤ 365 дн.) и отдаёт top-K.

## Что изменено (ADR-039 V1)

| Было | Стало |
|---|---|
| Сортировка **только по rapidfuzz-relevance** | Блендинг **relevance × engagement** через `rank_items` |
| `github_repos_count` — **декоративный** (только в `body`) | `github_repos_count + sources_count` = сигнал engagement в ранжировании |
| Токенизация одного промпта | `expand_queries(prompt)` → расширенный набор токенов (recall) |

```python
# было: scored.sort(key=lambda x: relevance, reverse=True)
# стало:
candidates.append({"topic": t, "relevance": score / 100.0,
                   "engagement": repos_count + sources_count})
ranked = rank_items(candidates)            # blended = 0.7·relevance + 0.3·log-norm(engagement)
```

Сохранено без изменений: фильтры `_has_github_signal` / `_is_fresh`, порог `MIN_SCORE=60`, `TOP_K=3`,
форма item `{title, body, score}` (поле `score` теперь = blended).

## Graceful fallback

Импорт модуля обёрнут в `try/except`: при недоступности `shared.engagement_rank` worker
откатывается на relevance-only (== прежнее поведение). `sys.path.insert(0, hooks_dir)` безопасен —
worker импортирует только `shared.*` (без `memory.*`), нет коллизии путей.

## Проверка

- Юнит: `tests/unit/test_engagement_rank.py` (8 — порог, не-мутация входа, engagement меняет порядок).
- Smoke интеграции: два одинаково-релевантных топика (engagement 50 vs 5) → топик с engagement=50
  встаёт первым (blended 1.0 vs 0.837). Раньше (relevance-only) были неразличимы.
- code-verify reviewer: PASS (behavior-preservation + quality, 16/16).

## Эффект

Перед каждой задачей всплывают не просто «совпавшие по названию» GitHub-исследования, а **наиболее
проверенные сообществом** (по числу repos/sources) — выше сигнал-к-шуму в авто-контексте.
