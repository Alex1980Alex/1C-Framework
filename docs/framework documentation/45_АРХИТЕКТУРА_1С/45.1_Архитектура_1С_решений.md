## Зачем глава

При каждой 1С-задаче нужен **явный архитектурный шаг** (а не неявный внутри анализа): ПЕРЕД написанием
BSL зафиксировать арх-решение — как менять код, какая объектная модель, какая модель процесса, какие
стандарты. Раньше это было размазано по `analyze-1c-task`/`bsl-development`/ADR; теперь сведено в скилл
`1c-solution-architecture` + эту главу. Запускается на **Шаге 2 (Дизайн)** пайплайна.

## 1. Decision-tree: расширение ↔ изменение типовой (главное решение)

```
Доработка типовой (ERP/УТ/БП)?
├─ Можно расширением? (новый функционал · перехват метода БСП · +реквизит · +форма)
│   └─ ДА → РАСШИРЕНИЕ  (&Вместо/&Перед/&После/&ИзменениеИКонтроль, заимствование объекта)
│           обновляемость сохранена; типовая НЕ снята с поддержки
├─ Нужна глубокая правка алгоритма, невозможная расширением?
│   └─ ДА → изменение типовой (СНЯТИЕ С ПОДДЕРЖКИ) — крайняя мера
│           цена = ручное сравнение/объединение при КАЖДОМ обновлении
└─ Автономный модуль?
    └─ отдельная подсистема/конфигурация + обмен (РИБ/КД/RMQ)
```
Правило: **«сначала расширение, типовую трогать в последнюю очередь»** [its.1c.ru гл.34 «Расширение конфигурации»; its.1c.ru/db/pubextensions].

## 2. Матрица выбора регистра (объектная модель)

| Нужно | Объект | Признак |
|---|---|---|
| Остатки/обороты (кол-во, сумма) | **Регистр накопления** | склад, взаиморасчёты |
| Значение атрибута на дату | **Регистр сведений** (периодич.) | цены, курсы, статусы во времени |
| Бух.проводки (Дт/Кт) | **Регистр бухгалтерии** | план счетов |
| Периодические расчёты | **Регистр расчёта** | зарплата |
| Факт-событие | **Документ** + движения | первичка |
| НСИ/классификатор | **Справочник** | номенклатура, контрагенты |

Проверки: проведение **идемпотентно**; периодический РС, подчинённый регистратору, — НЕ «Месяц»
(коллизия ключа → «По позиции регистратора»); производительность = часть архитектуры (запросы не в
цикле, индексы, ВТ вместо соединения с виртуальной таблицей).

## 3. Моделирование бизнес-процесса

| Сложность | Модель | Объекты |
|---|---|---|
| Формализованный workflow с маршрутизацией | **штатный БП** | Бизнес-процесс + Карта маршрута + Задача |
| Лёгкая статусная модель | **состояния** | РС/реквизит состояния + переходы |
| Межсистемный процесс | **интеграция** | обмены РИБ/КД, RMQ, 1С:ДО |

## 4. Чек-лист стандартов (арх-гигиена)

- [ ] БСП вместо велосипеда (`ОбщегоНазначения.*`, `ОбработкаОшибок.*`, права через **поставляемые профили**).
- [ ] Реквизит — `ОбщегоНазначения.ЗначениеРеквизитаОбъекта` (не `Ссылка.Реквизит`, особ. в циклах).
- [ ] Запросы: не в цикле; без соединения с виртуальной таблицей (материализация во ВТ + индекс).
- [ ] Управляемые формы (8.3), зарезервированные имена; `СтрШаблон` вместо конкатенации.
- [ ] Изменённый BSL → SonarQube «1C BSL Way» дельта = 0 BLOCKER/CRITICAL (ADR-037).

## Выход (артефакт арх-шага)

В ANALYSIS-REPORT / ADR: **(1)** способ изменения кода (расширение/типовая/обмен) · **(2)** объектная
модель (объекты/регистры) · **(3)** модель процесса (если есть) · **(4)** отметка по чек-листу стандартов.

## Где взять актуальную информацию

Эталон — **its.1c.ru** (приоритет 1, см. [1c-doc-research]); практику — Infostart. Для свежего/доверенного
