# 46.2 Classify-And-Act

> Гл. [46 Паттерны оркестрации](46.1_Обзор.md)

## Схема
```
prompt → [классификатор] ─┬─ класс A → agent_A
                          └─ класс B → agent_B
```

## Суть и когда
Вход сначала **классифицируется**, затем направляется к **специализированному** агенту/ветке. Применять,
когда задачи разнородны и для каждого типа есть свой оптимальный обработчик (не гонять всё через один
универсальный промпт). Дёшево, детерминированно, легко расширять новым классом.

## Реализация в Claude Code
- **Субагент-классификатор** (или дешёвая LLM) возвращает метку → диспетчеризация.
- **Agent tool сам по себе** — classify-and-act: подбирает субагента по полю `description` (авто-выбор по намерению).
- **Hook-уровень:** UserPromptSubmit-хук классифицирует промпт и инъектит маршрут (наш `skill-router`).

## Workflow-пример
```js
const cls = await agent(`Classify task type → one word: bug|feature|refactor: ${args.task}`)
if (cls.includes('bug'))      return agent('Fix the bug...', {agentType: 'implementer'})
if (cls.includes('refactor')) return agent('Refactor...', {agentType: 'implementer'})
return agent('Design the feature...', {agentType: 'Plan'})
```

## Реальный пример в нашем фреймворке
- **`route_1c_task`** ([`shared/pipeline_1c_bridge.py`](../../../.claude/hooks/shared/pipeline_1c_bridge.py)):
  `classify_1c_task` (1С-тип) + `estimate_effort` → flow: простая→`/run-1c-task` (auto), средняя→спросить,
  сложная→гейтованный `/analyze`+`/implement`. Классический classify-and-act на входе 1С-задачи.
- **`skill-router.py`** — классифицирует промпт → bundle → активирует профильный скилл.

## Подводные камни
- Неуверенная классификация → **деградировать в вопрос** (`ask`), а не в неверную ветку (наш инвариант:
  «сомнение в 1С/потоке → спросить»). Классификатор-FP дороже, если ветка короткозамыкает на авто-действие.
