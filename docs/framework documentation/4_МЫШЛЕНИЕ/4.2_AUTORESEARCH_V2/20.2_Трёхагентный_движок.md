# 20.2 Трёхагентный движок

## Почему три агента

В AutoResearch v1 использовался один агент, который одновременно писал код и проверял результат. Это приводило к субъективной оценке: разработчик склонен считать своё решение правильным.

В v2 применено строгое разделение обязанностей:
- Кто пишет код — не проверяет его качество
- Кто проверяет — не имеет права вносить изменения
- Comparator выступает независимым арбитром и не знает, какая версия является "текущей"

Это обеспечивает объективность оценки и предотвращает "самоутверждение" ошибочных решений.

---

## Executor (Agent 1) — ДЕЛАЕТ

**Роль:** Внесение атомарных изменений в код.

**Инструменты:** Read, Write, Edit, Bash (build/run), Git (commit/diff), MCP tools.

**Ограничения:**
- Не запускает тесты
- Не оценивает свой код
- Не выносит verdict

### Протокол

1. Читает `autoresearch.md` — понимает контекст, dead ends, next ideas
2. Выполняет `git log --oneline -5` — анализирует последние изменения
3. Выбирает ОДНО изменение (не из Dead Ends)
4. Вносит атомарное изменение в scope
5. Выполняет `git commit -m "[AR-{iter}] описание"`
6. Выводит описание в 1 предложении

### Промпт (шаблон)

```
You are EXECUTOR in AutoResearch v2. Iteration {i} of {max}.
Domain: {domain}. Scope: {scope}.

INSTRUCTIONS:
1. Read autoresearch.md for context
2. Check git log --oneline -5
3. Make ONE atomic change
   Hint: {recipe.ExecutorHint}
4. Git commit: git add -A && git commit -m "[AR-{i}] description"
5. Do NOT run tests or verify
6. Output what you changed in 1 sentence

RULES:
- ONE change only
- Only modify files in scope
- Check Dead Ends - do NOT retry them
- Commit BEFORE verification
```

## Reviewer (Agent 2) — ПРОВЕРЯЕТ

**Роль:** Оценка качества изменений и вынесение вердикта.

**Инструменты:** Read (read-only), Bash (тесты/метрики), Git (diff/log), Grep.

**Ограничения:**
- Не пишет код
- Не коммитит (кроме `git revert`)

### Протокол

1. `git diff HEAD~1 --stat` — анализ изменений
2. Запускает verify command → получает метрику
3. Запускает test command → pass/fail
4. Проверяет: файлы вне scope не затронуты?
5. Сравнивает с предыдущим best

### Обязательный формат вывода

```
METRIC: <число>
TESTS: PASS или FAIL
VERDICT: KEEP или REVERT или FIX или SKIP
REASON: <1 предложение>
```

### Логика вердиктов

| Verdict | Условие | Действие |
|---------|---------|----------|
| KEEP | Метрика улучшилась И тесты OK | Оставить коммит |
| REVERT | Метрика ухудшилась ИЛИ тесты fail | `git revert HEAD --no-edit` |
| FIX | Тесты fail, но идея хорошая | Executor получает 1 попытку на исправление |
| SKIP | Метрика не изменилась | Revert для чистоты истории |

Reviewer обновляет `autoresearch.md`:
- History table — добавляет запись о текущей итерации
- Dead Ends — добавляет если REVERT (чтобы Executor не повторял)
- Current Best — обновляет если KEEP

### Промпт (шаблон)

```
You are REVIEWER in AutoResearch v2. Iteration {i}.
Domain: {domain}. Direction: {direction} is better.

INSTRUCTIONS:
1. Run: git diff HEAD~1 --stat
2. Run verify command: {recipe.Verify}
3. Run test command: {recipe.Test}
4. Check: files outside scope modified?
5. Compare metric with previous best: {bestMetric}

OUTPUT (mandatory format):
METRIC: <number>
TESTS: PASS or FAIL
VERDICT: KEEP or REVERT or FIX or SKIP
REASON: <1 sentence>

6. If VERDICT is REVERT or SKIP: execute git revert HEAD --no-edit
7. Update autoresearch.md: History, Dead Ends, Current Best

RULES:
- Do NOT write code. Do NOT make changes beyond revert.
- Be objective: only numbers decide the verdict.
- KEEP only if metric improved AND tests pass AND no out-of-scope changes.
```

## Comparator (Agent 3) — СРАВНИВАЕТ

**Роль:** Независимое слепое сравнение baseline и текущей версии.

**Инструменты:** Read (read-only), Bash (benchmark), Git (diff/log).

**Частота запуска:** Каждые N итераций (по умолчанию 5, настраивается `-CompareEvery`).

### Протокол

1. Читает текущий код в scope
2. `git diff {baseline_commit} HEAD` — все изменения с baseline
3. Оценивает ОБЕ версии по критериям:
   - Code quality (1-10)
   - Readability (1-10)
   - Complexity (1-10, чем ниже, тем лучше)
4. Выводит JSON:
   ```json
   {
     "winner": "A or B",
     "quality_A": 7,
     "quality_B": 8,
     "readability_A": 6,
     "readability_B": 7,
     "complexity_A": 5,
     "complexity_B": 4,
     "notes": "Version B has cleaner abstractions"
   }
   ```
   где A = baseline, B = current
5. Добавляет в `autoresearch.md` секцию `## Comparator Reviews`

**Важно:** Comparator не знает, какая версия "текущая" — слепое сравнение обеспечивает объективность.

## Реализация через claude -p

Скрипт `autoresearch.ps1` вызывает каждого агента последовательно:

```
Iteration i:
  1. $commitBefore = git rev-parse --short HEAD
  2. claude -p $ExecutorPrompt --dangerously-skip-permissions → logs/executor_{i}.txt
  3. $commitAfter = git rev-parse --short HEAD
     Если commit не изменился → SKIP (Executor не сделал коммит)

  4. claude -p $ReviewerPrompt --dangerously-skip-permissions → logs/reviewer_{i}.txt
  5. Parse: METRIC, TESTS, VERDICT, REASON из вывода Reviewer
  6. Apply verdict logic (update bestMetric, plateauCount)

  7. Каждые N итераций:
     claude -p $ComparatorPrompt --dangerously-skip-permissions → logs/comparator_{i}.txt

  8. Log to JSONL + TSV
  9. Update autoresearch.md state (Domain, Iteration, BestMetric, Plateau, Target)
```

### Структура логов

Каждый вызов агента сохраняется в отдельный файл для аудита и отладки:

```
{session}/logs/
  executor_1.txt      # Вывод Executor итерации 1
  executor_2.txt
  reviewer_1.txt      # Вывод Reviewer итерации 1
  reviewer_2.txt
  comparator_5.txt    # Вывод Comparator (каждые 5 итераций)
  comparator_10.txt
```

### Парсинг вывода Reviewer

Скрипт извлекает вердикт и метрику из текстового вывода:

```powershell
# Verdict: поиск в JSON или plain text
if ($text -match '"verdict"\s*:\s*"(KEEP|REVERT|FIX|SKIP)"') { $Matches[1] }
if ($text -match 'VERDICT:\s*(KEEP|REVERT|FIX|SKIP)')        { $Matches[1] }

# Metric: три fallback-паттерна
if ($text -match 'METRIC:\s*([\d.]+)')          { $Matches[1] }
if ($text -match '"metric_after"\s*:\s*([\d.]+)') { $Matches[1] }
if ($text -match 'F1[\s:=]+([\d.]+)')           { $Matches[1] }
```

## Альтернатива: Subagent внутри сессии

Для интерактивного режима (`/autoresearch`) можно использовать Agent() tool вместо headless mode:

```
Agent(
  prompt: "Ты REVIEWER. Проверь git diff HEAD~1. Запусти тесты. Выведи VERDICT.",
  subagent_type: "general"
)
```

**Преимущества:**
- Не требует отдельного процесса
- Быстрее в интерактивном режиме
- Общий доступ к MCP tools

**Недостатки:**
- Менее изолировано — общий контекст может влиять на объективность
- Не подходит для ночных автономных циклов
