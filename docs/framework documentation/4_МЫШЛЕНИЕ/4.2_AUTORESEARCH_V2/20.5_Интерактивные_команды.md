# 20.5 Интерактивные команды

AutoResearch v2 предоставляет три slash-команды для использования в интерактивном режиме Claude Code. Каждая команда ориентирована на конкретный сценарий работы: от быстрого улучшения метрик до полного планирования эксперимента и security-аудита.

---

## /autoresearch — Основная команда

Базовая команда для запуска цикла улучшения в интерактивном режиме. Пользователь описывает цель, Claude выполняет анализ и предлагает план действий.

### Рабочий процесс

После ввода команды Claude выполняет последовательность шагов:

1. **ANALYZE** — анализ текущего состояния: сбор метрик, подсчёт FP/FN, определение scope
2. **RECIPE** — определение параметров эксперимента: домен, инструменты, метрика, команда верификации
3. **Создание директории** — формирование `data/autoresearch/{idea}/` с артефактами
4. **Предложение запуска** — вывод команды для `autoresearch.ps1` или выполнение итераций в текущей сессии

### Пример использования

```
> /autoresearch
> Улучши F1 skill router до 0.85

Claude:
1. ANALYZE: текущий F1 = 0.6651, 81 FP, 13 FN
2. RECIPE: домен "skills", verify = eval-skill-router.py
3. Создал data/autoresearch/skill-f1-20260320/
4. Предлагаю запуск: .\scripts\autoresearch.ps1 -Domain skills -Target 0.85
```

### Создаваемые артефакты

| Файл | Назначение |
|------|------------|
| `autoresearch.md` | Живой документ с ходом эксперимента |
| `autoresearch.jsonl` | Структурированный лог всех итераций |

## /autoresearch:plan — Интерактивный Wizard

Команда запускает пошаговый мастер для создания полного custom-рецепта эксперимента. Wizard проводит пользователя через 5 ворот (Gates) с валидацией на каждом этапе.

### Gate 1: SCOPE — Определение области

```
Какие файлы/директории в scope? (glob pattern)
> src/api/**/*.py
```

**Валидация:** паттерн должен соответствовать минимум одному файлу в проекте.

### Gate 2: METRIC — Команда измерения

```
Команда, которая выводит числовую метрику:
> pytest tests/api/ --benchmark-json=bench.json | jq '.benchmarks[].stats.mean'
```

**Валидация:** команда должна выводить числовое значение.

### Gate 3: DIRECTION — Направление оптимизации

```
Метрика должна расти или уменьшаться?
> lower is better
```

**Допустимые значения:** `higher is better` или `lower is better`

### Gate 4: VERIFY — Команда проверки

```
Как проверить что ничего не сломалось?
> pytest tests/ -q
```

**Валидация:** команда должна завершаться с exit code 0.

### Gate 5: BASELINE — Замер и целевое значение

```
Измеряю текущее значение... Baseline: 142ms
Целевое значение? (необязательно)
> < 100ms
```

### Структура выходных артефактов

```
data/autoresearch/{idea-name}-{date}/
├── autoresearch.md      # Живой документ с планом
├── executor-prompt.md   # Промпт для Executor
├── reviewer-prompt.md   # Промпт для Reviewer
└── run.bat              # Команда запуска
```

### Шаблон autoresearch.md

```markdown
# AutoResearch Session: {название}

## Goal
{описание цели}

## Scope
{glob pattern}

## Metric
`{verify command}`
Direction: {higher|lower} is better

## Baseline
{значение} (measured {дата})

## Target
{целевое значение}

## Current Best
{значение} (iteration N, commit hash)

## History
| Iter | Change | Before | After | Verdict | Why |
|------|--------|--------|-------|---------|-----|

## Dead Ends (don't retry)

## Next Ideas

## Comparator Reviews
```

## /autoresearch:security — STRIDE + OWASP аудит

Специальная команда для проведения security-аудита в READ-ONLY режиме. Итерации представляют собой анализ различных attack vectors, а не исправление кода.

### Категории STRIDE

| Категория | Описание |
|-----------|----------|
| **Spoofing** | Подмена идентичности пользователя или сервиса |
| **Tampering** | Несанкционированная модификация данных |
| **Repudiation** | Возможность отказа от выполненных действий |
| **Information Disclosure** | Утечка конфиденциальной информации |
| **Denial of Service** | Нарушение доступности сервиса |
| **Elevation of Privilege** | Несанкционированное повышение привилегий |

### Пример использования

```
> /autoresearch:security
> Проведи security audit src/ по OWASP Top 10

Claude:
1. Создаёт план из 6 STRIDE категорий
2. Каждая итерация — анализ одной категории
3. Формирует findings.md с описанием уязвимостей
4. НЕ модифицирует код
```

### Важные ограничения

- Команда работает исключительно в режиме чтения
- Код не модифицируется ни на одной итерации
- Результаты фиксируются в `findings.md` с классификацией по критичности
- Каждая уязвимость содержит: описание, вектор атаки, потенциальный ущерб, рекомендации
