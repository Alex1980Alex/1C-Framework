# 20.6 Persistence и логирование

AutoResearch v2 обеспечивает сохранение полного состояния между сессиями через систему из трёх файлов данных и CLI-инструмента для визуализации. Это гарантирует, что длительные исследования можно прерывать и возобновлять без потери контекста, а результаты поддаются машинному анализу.

## Три формата данных

Система использует три различных формата для разных целей:

1. **autoresearch.md** — живой документ в формате Markdown. Хранит текущее состояние сессии, читается человеком и редактируется при необходимости.
2. **autoresearch.jsonl** — полный лог экспериментов в формате JSON Lines. Каждая строка представляет одну итерацию. Предназначен для машинной обработки и автоматизации.
3. **autoresearch-results.tsv** — компактная таблица с табличным разделением. Оптимизирована для импорта в Excel, Google Sheets или BI-системы.

## autoresearch.md — Живой документ

Этот файл служит точкой входа при перезапуске сессии. Скрипт обновляет его после каждой итерации.

### Шаблон для встроенных доменов

```markdown
# AutoResearch Session
Domain: skill-health
Iteration: 7
BestMetric: 0.7443
Plateau: 2
Target:
BaselineCommit: abc1234
Updated: 2026-03-16T22:30:00
```

При перезапуске скрипт извлекает значения полей `Iteration`, `BestMetric`, `Plateau` и `BaselineCommit`, чтобы продолжить с прерванного места. Это обеспечивает бесшовное возобновление работы.

### Расширенный шаблон для custom идей

При запуске через команду `/autoresearch:plan` файл содержит дополнительные секции:

- **Goal** — формулировка цели исследования
- **Scope** — область применимости (glob pattern)
- **Metric** — команда верификации и направление оптимизации
- **Baseline** и **Target** — начальное и целевое значения метрики
- **History table** — таблица истории изменений
- **Dead Ends** — тупиковые ветки исследования (не повторять)
- **Next Ideas** — очередь идей для проверки
- **Comparator Reviews** — результаты слепого A/B сравнения

## autoresearch.jsonl — Лог экспериментов

Формат JSON Lines позволяет добавлять записи без перезаписи всего файла. Каждая строка — независимый JSON-объект.

### Пример записей

```json
{"iter":1,"ts":"2026-03-16T21:00:00Z","domain":"skill-health","commit":"abc1234","change":"Added weighted_keywords","metric_before":0.72,"metric_after":0.73,"delta":0.01,"tests_pass":true,"verdict":"KEEP","reviewer_reason":"F1 improved"}
{"iter":2,"ts":"2026-03-16T21:05:00Z","domain":"skill-health","commit":"def5678","change":"Removed generic triggers","metric_before":0.73,"metric_after":0.71,"delta":-0.02,"tests_pass":true,"verdict":"REVERT","reviewer_reason":"F1 decreased"}
```

### Структура полей

| Поле | Тип | Описание |
|------|-----|----------|
| iter | integer | Номер итерации |
| ts | string | ISO 8601 timestamp |
| domain | string | Идентификатор домена |
| commit | string | Git commit hash |
| change | string | Описание внесённых изменений |
| metric_before | float | Значение метрики до изменения |
| metric_after | float | Значение метрики после изменения |
| delta | float | Разница (after - before) |
| tests_pass | boolean | Прошли ли тесты |
| verdict | string | Решение: KEEP, REVERT, FIX, SKIP |
| reviewer_reason | string | Обоснование решения |

## autoresearch-results.tsv — Компактная таблица

Табличный формат с заголовком, создаваемым автоматически при первом запуске.

### Колонки

```
iteration  timestamp  commit  change  metric_before  metric_after  delta  tests  verdict  reason
```

Формат оптимизирован для быстрого импорта в табличные процессоры и построения сводных графиков.

## Структура директории сессии

### Для встроенных доменов

```
data/autoresearch/
├── autoresearch.md
├── autoresearch.jsonl
├── autoresearch-results.tsv
└── logs/
    ├── executor_1.txt
    ├── executor_2.txt
    ├── reviewer_1.txt
    ├── reviewer_2.txt
    ├── comparator_5.txt
    └── ...
```

### Для custom идей

```
data/autoresearch/{idea-name}-{date}/
├── autoresearch.md
├── autoresearch.jsonl
├── autoresearch-results.tsv
├── executor-prompt.md
├── reviewer-prompt.md
├── run.bat
└── logs/
```

Директория `logs/` содержит детальные логи работы каждого агента на каждой итерации. Файлы именуются по шаблону `{agent}_{iteration}.txt`.

## Dashboard — autoresearch-dashboard.py

CLI-инструмент для визуализации прогресса исследования. Поддерживает два режима вывода: ASCII-графику для терминала и JSON для интеграций.

### Запуск

```bash
python scripts/autoresearch-dashboard.py                      # data/ по умолчанию
python scripts/autoresearch-dashboard.py data/autoresearch/   # конкретная сессия
python scripts/autoresearch-dashboard.py --json               # JSON вывод
```

### ASCII вывод

```
AutoResearch: skill-health
==================================================
Iterations: 7 | Kept: 4 | Reverted: 2 | Skipped: 1
Best: 0.7443 | Target: N/A | Plateau: 2 | Status: ACTIVE

Metric progression (7 points):
    1 | 0.7200 ##########
    2 | 0.7224 ###########
    3 | 0.7100 ########
    4 | 0.7350 ##############
    5 | 0.7443 ################ <-- best
    6 | 0.7300 #############
    7 | 0.7443 ################

Top improvements:
  +0.0150  iter 4: Added weighted_keywords to framework bundle
  +0.0093  iter 5: Refined bsl-development negative markers
```

### JSON вывод

При использовании флага `--json` возвращается объект со следующими полями: `domain`, `iteration`, `best_metric`, `target`, `plateau`, `total_entries`, `kept`, `reverted`, `skipped`, `metric_history`.

### Поддерживаемые структуры

Dashboard автоматически определяет структуру хранения:
- **Flat layout:** `data/autoresearch.jsonl`
- **Nested layout:** `data/autoresearch/{idea}/autoresearch.jsonl`

Это позволяет использовать один инструмент для анализа как встроенных доменов, так и пользовательских исследований.
