# 20.7 Eval система

## Обзор

AutoResearch v2 включает специализированную систему оценки качества для верификации корректности работы модулей trigger detection и domain classification. Скрипт `eval-autoresearch.py` автоматизирует процесс проверки двух ключевых метрик:

1. **Trigger accuracy** — оценка того, насколько корректно система определяет, подходит ли входящая задача под критерии запуска автономного исследовательского цикла.
2. **Domain detection** — оценка точности классификации задачи по доменам (skills, python-quality, security и другим).

Это позволяет контролировать качество работы системы при внесении изменений в логику определения триггеров и доменов.

## Запуск

```bash
# Базовый запуск с выводом сводной статистики
python scripts/eval-autoresearch.py

# Запуск с детальным выводом информации по каждому промпту
python scripts/eval-autoresearch.py --verbose
```

Результаты автоматически сохраняются в файл `data/eval/autoresearch/eval_results.json`.

## Набор данных

Набор данных состоит из 20 промптов в файле `data/eval/autoresearch/eval_prompts.json`. Набор сбалансирован:

- **10 положительных примеров** (`should_trigger=true`) с полем `expected_domain`
- **10 отрицательных примеров** (`should_trigger=false`) с причиной, почему не должно триггериться

| Промпт | Ожидаемый домен |
|--------|-----------------|
| "Уменьши количество ошибок ruff в src/" | `python-quality` |
| "Оптимизируй время ответа API до 100ms" | `python-performance` |
| "Повысь покрытие тестами до 80%" | `tests` |

| "Запусти автономный цикл улучшения BSL кода" | `bsl` |
| "Улучши F1 skill router до 0.85" | `skills` |

### Примеры отрицательных промптов

| Промпт | Причина |
|--------|---------|

| "Объясни как работает RAG pipeline" | explanation, not optimization |
| "Переименуй переменную foo в bar" | trivial refactor |

## Trigger Detection

Функция `should_trigger(prompt)` отвечает за определение необходимости запуска автономного цикла. Она использует взвешенную систему ключевых слов.

### Ключевые слова

- **TRIGGER_KEYWORDS** (25+ слов): `autoresearch`, `автономный цикл`, `улучши`, `оптимизируй`, `уменьши`, `повысь покрытие`, `ускорь`, `reduce errors`, `improve`, `optimize`, `benchmark`, `measure and improve`, `keep/revert`, `автоисследование`, `итеративно`, `security audit`, `docstring`, `покрытие тестами`.
- **NEGATIVE_KEYWORDS**: `исправь`, `fix`, `покажи`, `объясни`, `создай`, `напиши`, `git`, `commit`, `расскажи`, `настрой`, `переименуй`.

### Логика принятия решения

1. `pos_score >= 2` — активировать триггер
2. `pos_score >= 1` И `neg_score == 0` — активировать триггер
3. В остальных случаях — не активировать

## Domain Detection

Функция `detect_domain(prompt)` выполняет классификацию задачи методом сопоставления ключевых слов по 9 доменам:

| Домен | Ключевые слова |
|-------|----------------|
| `python-quality` | ruff, mypy, lint, ошибок, errors, quality |
| `python-performance` | время ответа, response time, performance, benchmark, ускорь, latency |
| `bsl` | bsl, 1с код, bsl_analyze |
| `skills` | skill, скилл, f1, router, description |
| `docs` | docstring, документация, documentation, interrogate |
| `hooks` | хук, hook, eval-hooks |
| `security` | security, owasp, stride, bandit, audit, уязвимост |
| `tests` | тест, test, coverage, покрытие, pytest |
| `1c-study` | конфигурац, 1с, изучи конфигурац, get_metadata |

Домен определяется по максимальному количеству совпавших ключевых слов.

## Метрики

Для оценки качества используются стандартные метрики бинарной классификации:

- **TP** (True Positives), **FP** (False Positives), **TN** (True Negatives), **FN** (False Negatives)
- **Precision** = TP / (TP + FP)
- **Recall** = TP / (TP + FN)
- **F1** = 2 * Precision * Recall / (Precision + Recall)
- **Accuracy** = (TP + TN) / Total
- **Domain Accuracy** = Correct / Total (рассчитывается только для True Positives)

## Pass/Fail критерии

- **PASS:** `F1 >= 0.9` И `domain_accuracy >= 0.85`
- **NEEDS IMPROVEMENT:** если условия выше не выполнены

**Текущий результат:** F1 = 1.0, domain_accuracy = 1.0, STATUS: PASS.

## Расширение набора данных

Для добавления новых тестовых случаев отредактируйте файл `data/eval/autoresearch/eval_prompts.json`:

```json
{"id": 21, "prompt": "Новый промпт для тестирования", "should_trigger": true, "expected_domain": "python-quality", "expected_tools": ["ruff"]}
```

Для отрицательных примеров `should_trigger` устанавливается в `false`, поле `expected_domain` опускается. Рекомендуется поддерживать баланс между положительными и отрицательными примерами.
