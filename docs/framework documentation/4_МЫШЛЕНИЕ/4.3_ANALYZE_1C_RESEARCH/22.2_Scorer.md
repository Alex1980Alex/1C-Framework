# 22.2 Scorer — метрика качества анализа

## Назначение

Скрипт `score-analysis-report.py` парсит ANALYSIS-REPORT.md и вычисляет Structured Quality Score (0-100). Выявляет конкретные пробелы (gaps) для итеративного улучшения.

## Методология расчёта

Итоговая оценка — взвешенная сумма пяти компонентов:

| Компонент | Вес | Формула | Источник |
|-----------|-----|---------|----------|
| Requirements coverage | 30% | `covered_refs / total_requirements` | Маркеры `[REQ-N]` |
| Fields verified | 25% | `verified / (verified + unverified)` | `✓ get_metadata` / `✗ не проверено` |
| Patterns found | 20% | `patterns / modification_points` | `✓ pattern` |
| SQL validated | 15% | `validated / sql_queries` | `✓ execute_query` |
| Open questions | 10% | `1 - open/(open+3)` | Секция 6 |

Каждый компонент ограничен своим максимальным весом. При отсутствии элемента (нет SQL, нет полей) компонент получает полный балл.

## Маркеры

Scorer ищет следующие маркеры в тексте отчёта:

- `✓ get_metadata` — поле проверено через MCP
- `✗ не проверено` — поле не проверено (gap)
- `✓ pattern` — найден образец из конфигурации
- `✓ execute_query` — SQL валидирован на реальных данных
- `[REQ-N]` — привязка точки модификации к требованию N

## Tolerant Parser

Для поддержки нестандартных форматов парсер распознаёт:

**Секции заголовков:**
- `### 1.1 Требования` (стандарт)
- `## Фаза 1: Требования` (GKSTCPLK-2215)
- `## Описание проблемы`, `## Найденные баги` (нестандарт)

**Формат требований:**
- Нумерованные: `1. текст`
- Маркированные: `- текст`
- Табличные: `| N | текст |`
- Заголовки багов: `### Баг N:`, `### BUG #N`

**Точки модификации:**
- Заголовки: `### Точка модификации N:`
- Таблицы: `| N | файл | строка | действие |`

## CLI

```bash
python scripts/score-analysis-report.py path/to/ANALYSIS-REPORT.md
```

## Формат вывода

```
METRIC: 85
BREAKDOWN: req=24/30 fields=25/25 patterns=16/20 sql=12/15 questions=8/10
GAPS: [{"type":"pattern_missing","detail":"2 modification point(s) without pattern from config"}]
```

Формат парсится Reviewer промптом через regex `METRIC:\s*(\d+)`.

## Edge Cases

| Сценарий | Score | Причина |
|----------|-------|---------|
| Пустой отчёт | 70 | 0 req + full fields/patterns/sql/questions |
| Идеальный отчёт | 100 | Все маркеры на месте |
| Без SQL | sql=15/15 | Нечего проверять = полный балл |
| Без полей | fields=25/25 | Нет ✓/✗ маркеров = полный балл |
