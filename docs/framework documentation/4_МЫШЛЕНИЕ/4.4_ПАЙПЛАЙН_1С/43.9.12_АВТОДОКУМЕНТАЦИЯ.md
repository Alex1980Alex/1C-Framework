# 43.9.12 Автодокументация и кодогенерация

> **Тип:** авто-генерация артефактов из кода — документация, ревью, тест-план, граф зависимостей, inline-доки.
> Глава каталога [43.9](43.9_ИНСТРУМЕНТЫ_ПО_ТИПАМ.md). Этапы: **2-4** (документирование, ревью, план тестов).
> Единственный профильный сервер — **`auto-documenter`** (Node, делегирует генерацию на Z.AI/GLM).

## Назначение
Сократить рутину документирования/ревью: по модулю получить human-readable документацию, авто-ревью,
черновой тест-план, граф зависимостей, inline-комментарии — генерацией, не вручную.

## Инструменты

| Функция | Сервер | Что генерит | Подводный камень |
|---|---|---|---|
| `generate_documentation` | auto-documenter | документация по модулю/объекту | делегирует на внешний LLM (Z.AI/GLM) — нужен ключ |
| `autoreview` | auto-documenter | авто-ревью кода | черновик — не заменяет `code-verify` |
| `autotestplan` | auto-documenter | черновой план тестов | вход для [43.9.8](43.9.8_ТЕСТИРОВАНИЕ.md) |
| `generate_dependency_graph` | auto-documenter | граф зависимостей модуля | визуализация (≠ call-graph из [43.9.4](43.9.4_ГРАФ_И_IMPACT.md)) |
| `generate_inline_docs` | auto-documenter | inline-комментарии/docstring | проверять корректность вставок |

## Выбор среди альтернатив
Альтернатив внутри типа нет (один сервер). Граничные случаи:
- **Документация по модулю** → `generate_documentation`; **inline-доки** → `generate_inline_docs`.
- **Черновое ревью** → `autoreview`, но финальная верификация правок — всё равно skill `code-verify`
  (автодок-ревью = черновик).
- **План тестов** → `autotestplan` → доводится в [43.9.8 Тестирование](43.9.8_ТЕСТИРОВАНИЕ.md).
- **Граф зависимостей** (модуль) ≠ **call-graph/impact** (символы) — последнее в [43.9.4](43.9.4_ГРАФ_И_IMPACT.md).

> Кодогенерация-смежное: edt `translate_configuration`/`generate_translation_strings` (локализация строк) —
> операционно близко, но это деплой-вспомогательное; основной арсенал типа = `auto-documenter`.

## Когда применять
Дизайн/Кодирование — документация/inline-доки нового кода. Тестирование — черновой тест-план/ревью как
ускоритель (с последующей верификацией `code-verify`).
