# 43.9.1 Метаданные и инвентарь

> **Тип:** read-only получение состава конфигурации, структуры объектов и связей между объектами. Глава
> каталога [43.9](43.9_ИНСТРУМЕНТЫ_ПО_ТИПАМ.md). Этапы: **1 Планирование** (инвентарь/объекты), **2 Дизайн**
> (структура целевого объекта). Чтение **кода** модулей — в [43.9.3](43.9.3_ЧТЕНИЕ_И_ПОИСК_КОДА.md); граф
> вызовов символов — в [43.9.4](43.9.4_ГРАФ_И_IMPACT.md).

## Назначение
Ответить на «что есть в конфигурации» и «как устроен объект»: список/дерево объектов, реквизиты/ТЧ/формы/движения,
права, где объект используется. Инвентарь — фундамент Планирования (оценка масштаба, delta-spec `[ADDED]`/`[MODIFIED]`).

## Инструменты

| Функция | Сервер / CLI | Что даёт | Подводный камень |
|---|---|---|---|
| `get_metadata_tree` | 1c-mcp-crud | полное дерево всех типов объектов | большой ответ — для инвентаря, не для одного объекта |
| `list_metadata_objects` | 1c-mcp-crud | список объектов одного типа (`metaType`) | англ. enum типа |
| `get_metadata` | 1c-mcp-crud | короткие реквизиты объекта | — |
| `get_metadata_structure` | 1c-mcp-crud | расширенная структура (реквизиты, ТЧ, измерения/ресурсы, формы) | `metaType` (англ.) + `name` |
| `get_metadata_objects` / `get_metadata_details` | edt-mcp | состав + свойства + **дети** объекта (типизированная модель EDT) | снапшот EDT может отстать ([[feedback-edt-mcp-stale-snapshot]]) |
| `get_configuration_properties` / `list_subsystems` / `get_subsystem_content` | edt-mcp | свойства конфигурации, состав подсистем | — |
| `get_objects_by_tags` / `get_tags` | edt-mcp | объекты по тегам | — |
| `scan_metadata_index` | codepilot1c | индекс объектов + фильтры по маске | только у codepilot1c (у edt-mcp такого тула нет); `-32000` если хост плагина выключен ([[reference-codepilot1c-mcp-host]]) |
| `find_references_to_object` | 1c-mcp-crud | где **объект** используется (документы/регистры/…) | `search_scope` — **англ.** enum; формат `{_objectRef…}` |
| `find_references` | edt-mcp | ссылки на объект/символ в EDT | — |
| `meta-info` / `cf-info` / `role-info` / `subsystem-info` | cc-1c-skills (offline) | состав/счётчики/права по файлам, **скриптуемо** в батч | per-object процесс — дорого на масштабе (ADR-031) |

## Выбор среди альтернатив

- **Инвентарь всей конфы** → `get_metadata_tree` (живая) или `cf-info` (offline). Срезы расходятся by design:
  `get_metadata_tree` (все зарегистрированные ОМ, вкл. без кода) ≠ FS-обход `src/` (каталоги с кодом) — обе валидны.
- **Свойства/состав одного объекта** → `edt-mcp get_metadata_details` (надёжнее, чем `bsl_object_info` из
  [43.9.4](43.9.4_ГРАФ_И_IMPACT.md), который капризен на `гкс_*`). Для живой проверки имён полей запроса —
  `get_metadata_structure` (1c-mcp-crud).
- **Где используется объект** → `find_references_to_object` (1c-mcp-crud, по данным) либо `find_references` (edt).
- **Оффлайн/батч/CI** → cc-1c-skills `*-info` (без живой ИБ/EDT).

## Когда применять
Планирование: оценка масштаба + delta-spec классификация (`get_metadata` → найден/не найден). Дизайн: точная
структура целевого объекта (реквизиты/ТЧ/измерения) перед написанием запросов/движений.
