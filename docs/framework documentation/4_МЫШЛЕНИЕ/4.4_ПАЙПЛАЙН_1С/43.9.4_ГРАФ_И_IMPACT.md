# 43.9.4 Граф вызовов и impact-анализ

> **Тип:** связи между символами кода — кто кого вызывает, что сломается при правке, мёртвый код. Глава
> каталога [43.9](43.9_ИНСТРУМЕНТЫ_ПО_ТИПАМ.md). Этапы: **1-2** (impact до правки), **3** (полнота рефактора),
> **4** (аудит dead-code). Поиск/чтение кода — в [43.9.3](43.9.3_ЧТЕНИЕ_И_ПОИСК_КОДА.md); ссылки на **объект
> метаданных** — в [43.9.1](43.9.1_МЕТАДАННЫЕ_И_ИНВЕНТАРЬ.md).

## Назначение
Построить карту регрессий **до** правки и обеспечить полноту изменений: транзитивный impact экспортного
метода, список вызывающих, иерархия вызовов, мёртвый экспорт, статистика индекса/графа.

## Инструменты

| Функция | Сервер / скрипт | Что даёт | Подводный камень |
|---|---|---|---|
| `bsl_impact_analysis` ⭐ | bsl-semantic-search | транзитивный «кто сломается» (d0/1/2) | живой прогон: `ПолучитьПоРегистрации` → 24 затронутых символа |
| `bsl_call_graph` | bsl-semantic-search | граф вызовов вокруг символа | — |
| `bsl_dead_code` | bsl-semantic-search | мёртвый экспорт по всей конфе | живой прогон: 3596 кандидатов |
| `bsl_stats` | bsl-semantic-search | размер/состояние индекса кода | `bsl_code_v4_late`, 4096d, ~37.7k точек |
| `bsl_object_info` | bsl-semantic-search | объект + граф-статы | резолв по имени папки капризен (`not found` на `гкс_*`) → для свойств брать [43.9.1](43.9.1_МЕТАДАННЫЕ_И_ИНВЕНТАРЬ.md) `get_metadata_details` |
| `find_callers` | bsl-code-search | точные вызывающие по имени метода | нужен `/mcp reconnect` после правок |
| `get_method_call_hierarchy` | edt-mcp | иерархия вызовов метода | снапшот EDT |
| `build_call_graph.py` → `bsl_call_graph.db` | скрипт | граф всей конфы (~33k символов / 80k вызовов / 2k модулей) + детектор dangling | гонять **перед** reindex |
| `analyze_run.py --mode graph` | скрипт | авто-отчёт по графу (dangling/orphan) `--source sqlite\|neo4j\|qdrant_graph` | результат в `data/reports/graph/` |

## Выбор среди альтернатив

- **«Что сломается, если правлю экспортный метод»** → `bsl_impact_analysis` (транзитивно, семантически). Это
  топ-1 «дёшево и сильно» — перед любой правкой экспортного метода. **🔒 conditional-hard** при
  `ONEC_TOOLGATE_HARD=1` (требуется на 1С-задаче с правкой кода; [ADR-036](../../../../.claude/skills/architecture-research/adr/036-promote-high-leverage-1c-tools-variant-a.md)).
  `find_callers`/`bsl_call_graph` — **advisory** (`•`) перед `[REFACTOR]`.
- **«Кто конкретно вызывает этот метод»** (для `[REFACTOR]`/удаления) → `find_callers` (точно по имени) либо
  edt `get_method_call_hierarchy`.
- **Массовый граф / dangling / orphan по всей конфе** → `build_call_graph.py` + `analyze_run.py --mode graph`
  (см. [43.7 §граф](43.7_АНАЛИЗ_ВСЕЙ_КОНФИГУРАЦИИ.md)).
- **Мёртвый код перед cleanup** → `bsl_dead_code`.

## Когда применять
Планирование/Дизайн — impact перед правкой (предотвращение «починил A — сломал B»). Кодирование — полнота
охвата при rename/удалении символа (см. [43.9.5](43.9.5_ЗАПИСЬ_И_РЕФАКТОРИНГ.md)). Тестирование — аудит мёртвого
кода/целостности графа.
