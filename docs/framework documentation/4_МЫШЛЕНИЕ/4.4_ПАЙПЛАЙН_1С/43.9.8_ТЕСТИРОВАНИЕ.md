# 43.9.8 Тестирование

> **Тип:** автоматические тесты конфигурации — приёмочные/UI (BDD) и модульные (YaXUnit). Глава каталога
> [43.9](43.9_ИНСТРУМЕНТЫ_ПО_ТИПАМ.md). Этап: **4 Тестирование**. Setup/verify данных на живой TestDB — в
> [43.9.2](43.9.2_ДАННЫЕ_И_RUNTIME.md); BP-отладка теста — в [43.9.7](43.9.7_ОТЛАДКА.md).

## Назначение
Проверить функционал автотестами: бизнес-сценарий через UI (Vanessa BDD) или модульную логику (YaXUnit), со
сборкой/проверкой синтаксиса и прогоном на TestDB.

## Выбор среди альтернатив

- **Бизнес-сценарий / форма / цепочка процессов** → **VA BDD** (`run-bdd.ps1` + skill `va-bdd-testing`).
  Пайплайн `/write-1c-tests` → `/run-1c-tests` (цепной прогон с resume).
- **Модульная логика (функция/процедура)** → **YAxUnit**: методика `yaxunit-unit-testing` +
  `/write-1c-unit-tests` → `/run-1c-unit-tests` (прогон через `mcp-onec-test-runner`, или edt
  `run_yaxunit_tests` для связки с отладкой). Методика написания тестов — [17.6](../../7_ПРОВЕРКА/7.4_ТЕСТИРОВАНИЕ_1С/17.6_НАПИСАНИЕ_YAXUNIT_ТЕСТОВ.md).
- **QA-контур codepilot1c / BDD-через-MCP** (`qa_inspect`→`qa_plan_scenario`→`qa_generate`→`qa_validate_feature`→`qa_run`)
  — MCP-native движок генерации/прогона сценариев через хост EDT-плагина. **Проверен рабочим** (MFM
  смоук junit 1/0/0). ⚠ **Рабочий только binary-путь** — EDT-runtime путь (`use_runtime=true`) сломан
  на EDT 2025.2.6 (метода `getThickClientInfo` в API нет — апстрим-баг плагина). Ключи qa-config.json:
  `edt.use_runtime=false`, `platform.bin_path=…\bin\1cv8c.exe` (**exe, не каталог**),
  `test_manager`/`test_clients[].ib_connection` с `Usr=`; `.epf` из git LFS (`git lfs pull`);
  `status:infra_error` при exit 0 **ложный** — истина в `junit/junit.xml`; зависшие клиенты съедают
  слоты dev-лицензии (`rac session terminate`). Полный рецепт — [[reference-codepilot1c-qa-run-binary-path]].
  Основной приёмочный трек по-прежнему VA BDD; qa_* — равноценный MCP-раннер.
- **Проверка синтаксиса/сборка перед тестом** → `mcp-onec-test-runner` `build_project`/`check_syntax_*`.
- **Данные для теста** → setup/verify на живой TestDB через [43.9.2](43.9.2_ДАННЫЕ_И_RUNTIME.md) (золотое
  правило: всё проверяется на реальной базе; Stage 4a pre-check обязателен).

## Когда применять
Тестирование: VA BDD для приёмки сценариев; YaXUnit для модульных инвариантов; перед прогоном — синтаксис/сборка;
после — verify данных на TestDB.
