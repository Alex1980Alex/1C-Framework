# 43.9.9 Статанализ и качество кода

> **Тип:** статическая проверка качества без исполнения — код-смелы, сложность, маркеры валидации,
> форматирование, профилирование. Глава каталога [43.9](43.9_ИНСТРУМЕНТЫ_ПО_ТИПАМ.md). Этапы: **3** (быстрый
> линт перед коммитом), **4** (глубокий аудит). Runtime-отладка — в [43.9.7](43.9.7_ОТЛАДКА.md).

## Назначение
Поймать дефекты/смелы/нарушения до прода: диагностики по всем `.bsl`, маркеры валидации EDT, форматирование под
стандарт, профилирование «узких мест».

## Выбор среди альтернатив

- **Быстрый цикл (перед коммитом/после правки)** → `bsl_lint.py --format` + `get_project_errors` (маркеры EDT
  после записи). Сложность одного метода → `bsl_analyze_method`.
- **Глубокий аудит всей конфы** → `SonarQube` (`run-sonar-analysis.ps1`) — но **Sonar-баги фиксить только через
  `/fix-sonar-task`**, не ad-hoc (PATTERN 2.14, [ADR-033](../../../../.claude/skills/architecture-research/adr/033-sonar-remediation-stage.md));
  scope-гейт: править только кастом (`гкс_*`), не вендорную БСП. QG-блокер по новому коду — `sonar_quality_gate_check.py`
  (opt-in `SONAR_QG_HARD`).
- **Производительность** → edt `*_profiling`.
- ⚠ `run-sonar-analysis.ps1` может вернуть `exit 255` в пост-шаге, но **анализ загружен** — статус по API
  (`/api/project_analyses`), не по exit-коду ([43.7 §SonarQube](43.7_АНАЛИЗ_ВСЕЙ_КОНФИГУРАЦИИ.md)).

## Python-слой `src/bsl/sonar/` (вторичный путь)

Помимо продакшн-контура (ps1 + `scripts/sonar_*.py`) в репо живёт самостоятельный Python-пакет
[`src/bsl/sonar/`](../../../../src/bsl/sonar/cli.py) — тонкая обёртка вокруг `sonar-scanner` с собственным
конфигом. Используется точечно (в первую очередь как **реестр версии BSL-плагина**), гейт `onec-task-completion-stop`
на него **не завязан**.

| Класс / модуль | Роль |
|---|---|
| `SonarQubeConfig` ([`config_manager.py`](../../../../src/bsl/sonar/config_manager.py)) | pydantic-модель: `host`, `token`, `project_key`, `sources`, `bsl_plugin_version` (пин bundled `tools/sonar-bsl-plugin.jar`, **1.18.1** на SonarQube CB 26.x), `quality_profile`, `sonar_scanner_path`; property `api_url` |
| `ConfigManager` (там же) | загрузка `data/sonar_config.json` с фолбэком на дефолты (файла в репо нет → работает на дефолтах) |
| `BSLRule` / `RulesManager` ([`rules_manager.py`](../../../../src/bsl/sonar/rules_manager.py)) | описание правила BSL (`key`, `name`, `severity`, `description`, `tags`) и реестр правил для вывода/фильтрации по тегу |
| `Issue` / `AnalysisReport` / `ReportGenerator` ([`report_generator.py`](../../../../src/bsl/sonar/report_generator.py)) | находка, агрегированный отчёт анализа и его рендер |
| CLI ([`cli.py`](../../../../src/bsl/sonar/cli.py)) | `python -m src.bsl.sonar.cli analyze --path <путь> [--output report.md]` (запуск сканера subprocess'ом, токен маскируется в логе) · `rules [--tag <tag>]` · `config [--show]`. ⚠ `--path` обязателен, позиционного аргумента нет |

⚠ **Что выбирать:** обязательный гейт изменённого кода и все операции по задачам — только продакшн-путь
(`run-sonar-analysis.ps1` + `sonar_rescan_verify.py`, таблица выше). Python-слой — для локальных ad-hoc прогонов
и как единственное место, где версия плагина зафиксирована в коде ([ADR-020](../../../../.claude/skills/architecture-research/adr/020-phase9-1c-tooling-adoption-verified.md),
[ADR-021](../../../../.claude/skills/architecture-research/adr/021-sonar-qa-gate-ci-production-wiring.md)).

## Операционные ловушки SQ-контура (roadmap 260706)

Инциденты live-прогона гейта → правила (детали: [roadmap 260706](../../../../docs/roadmap/260706_ROADMAP_SONARQUBE_SCAN_RELIABILITY.md), [[reference-sonar-changed-lines-gate]]):

- **I1 — НЕ редиректить stderr `run-sonar-analysis.ps1`** (`*>&1`/`2>&1` при вызове): PS 5.1 оборачивает stderr нативного java в `NativeCommandError`, под `$ErrorActionPreference="Stop"` скрипт падает на первом же не-фатальном варнинге сенсора. Нужен лог — параметр **`-LogFile <path>`** (скрипт сам пишет UTF-8, native-safe; P1.2). PS-`>` дал бы UTF-16 (I2).
- **I3 — запуск ТОЛЬКО из корня репо** (или полным путём): якорь корня = `$PSScriptRoot\..`, НЕ cwd-зависимый `git rev-parse` (из сабмодуля возвращал корень сабмодуля → `.env`/скрипты не найдены → тихий **exit 0 БЕЗ скана**). Нет токена / пустые sources / упавший helper → **FATAL exit 2** (не 0); сервер down → `SCAN-SKIPPED` exit 0.
- **I4 — CE асинхронен**: exit 0 сканера ≠ анализ готов (Compute Engine дописывает минуты). ps1 сам ждёт финализацию по `.scannerwork/report-task.txt` → `api/ce/task` (P1.1); `sonar_rescan_verify.py --wait-ce` (P0.1) — страховка ручных прогонов; freshness = max(`api/project_analyses`, `api/project_branches/list`). До фикса verify давал **ложный `scan_stale`** сразу после скана.
- **I5 — диагностика по файлу** без ручного curl с кириллическим ключом: **`sonar_rescan_verify.py --show-file <rel>`** → `component_key` + unresolved issues (line/severity/rule/message; P1.3).
- **Вырожденный new-code baseline** (первый скан проекта → все легаси-issue «новые» → QG=ERROR-шум soft): **`sonar_set_new_code_baseline.py --to-latest-before <ISO>`** / `--analysis-id <UUID>` (`SPECIFIC_ANALYSIS` **branch-level**; project-level `set` = тихий no-op → проверять `--show`; value = ПОЛНЫЙ UUID; P2.2). Дельта-гейт `changed-lines` от baseline независим (гейтит по diff-строкам), но baseline убирает QG-шум.
- **ps1 = UTF-8 с BOM** ([[feedback-ps1-utf8-bom-smart-quotes]]): без BOM PS 5.1 читает как cp1251, «—»/«ёлочки» в двойной строке → `”` (валидный делимитер) → parse error «Missing closing '}'». Тест-инвариант `test_run_sonar_ps1_has_utf8_bom`.

## Когда применять
Кодирование — `bsl_lint.py`/`get_project_errors` после каждой правки (обяз. цикл). **Тестирование/завершение —
ОБЯЗАТЕЛЬНЫЙ Sonar re-scan изменённого/добавленного `.bsl`** (хард-гейт [ADR-037](../../../../.claude/skills/architecture-research/adr/037-mandatory-sonar-rescan-changed-1c-code.md) в `onec-task-completion-stop`: дельта **0 BLOCKER/CRITICAL** по **изменённым строкам** — mode=changed-lines: пересечение issue-строк с `git diff -w -U0` изменённых `.bsl`, а не весь файл (`scripts/sonar_rescan_verify.py`, вырожденный new-code baseline не гейтит); Clean-as-You-Code на свои правки, default-ON; Sonar-down→skip, opt-out `ONEC_SONAR_GATE_DISABLE=1`). Полный аудит всей конфы (`run-sonar-analysis.ps1`) — по релизам / on-demand + dead-code ([43.9.4](43.9.4_ГРАФ_И_IMPACT.md)). Sonar-баги фиксить только через `/fix-sonar-task` (ADR-033).
