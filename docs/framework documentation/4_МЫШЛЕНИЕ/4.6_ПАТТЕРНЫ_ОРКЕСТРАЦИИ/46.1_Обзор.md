# 46.1 Обзор — паттерны мульти-агентной оркестрации

> **Статус:** актуально на 2026-07-05 (аудит 260704). Методологическая глава; проверяй датированные ссылки при использовании.

> **Версия:** 1.0 | **Дата:** 2026-06-25 | **Статус:** ACTIVE
> **Контекст:** 6 паттернов оркестрации агентов и их реализация в Claude Code (субагенты + Workflow + hooks + agent-loop).

## Что это

Шесть переиспользуемых **паттернов оркестрации** нескольких агентов (субагентов) для решения задач, которые
один проход не вытягивает — нужны охват (декомпозиция+параллель), уверенность (независимые перспективы +
состязательная проверка) или масштаб (одна задача не помещается в контекст).

| # | Паттерн | Суть | Глава |
|---|---|---|---|
| 1 | **Classify-And-Act** | классифицировать вход → роутить к специализированному агенту | [46.2](46.2_Classify_And_Act.md) |
| 2 | **Fanout-And-Synthesize** | веер параллельных агентов → синтез | [46.3](46.3_Fanout_And_Synthesize.md) |
| 3 | **Adversarial Verification** | находку проверяют агенты-скептики (опровергнуть) | [46.4](46.4_Adversarial_Verification.md) |
| 4 | **Generate-And-Filter** | сгенерировать много кандидатов → отфильтровать | [46.5](46.5_Generate_And_Filter.md) |
| 5 | **Tournament** | N независимых попыток → судьи → победитель | [46.6](46.6_Tournament.md) |
| 6 | **Loop Until Done** | итеративный цикл агента до терминального условия | [46.7](46.7_Loop_Until_Done.md) |

## Какой паттерн когда выбирать

```
Задача →
├─ вход разнородный, для каждого типа — свой обработчик?      → Classify-And-Act     (46.2)
├─ разложима на N независимых подзадач (нужен охват/скорость)? → Fanout-And-Synthesize (46.3)
├─ есть находка/решение, цена ошибки высока (plausible≠верно)? → Adversarial Verification (46.4)
├─ генерация дёшева, много шума → нужен массовый отсев?       → Generate-And-Filter   (46.5)
├─ широкая развилка, несколько подходов → выбрать лучший?     → Tournament            (46.6)
└─ объём результата неизвестен / доводка до условия?          → Loop Until Done       (46.7)
```

**Сигнал в формулировке → паттерн:**
| Сигнал | Паттерн |
|---|---|
| «разные типы входа», «смотря что пришло» | **Classify-And-Act** |
| «покрой всё», «быстро», «по разделу на агента» | **Fanout-And-Synthesize** |
| «убедись», «не ошибись», «проверь находки» | **Adversarial Verification** |
| «много кандидатов», «отсей лишнее», «top-N» | **Generate-And-Filter** |
| «сравни подходы», «выбери из вариантов» | **Tournament** |
| «пока не готово», «итеративно», «неизвестно сколько» | **Loop Until Done** |

**Ось выбора (одной фразой):** охват → *Fanout*; уверенность → *Adversarial* / *Tournament*; отсев шума →
*Generate-Filter*; маршрутизация → *Classify*; неизвестный объём/доводка → *Loop*.

**Композиция (паттерны сочетаются, не взаимоисключающи).** Типичный сильный конвейер:
```
Classify-And-Act (роут) → Fanout-And-Synthesize (охват) → Adversarial Verification (проверка каждой находки)
                        → Loop Until Done (пока не сойдётся; K пустых раундов = стоп)
```
`Generate-And-Filter` и `Tournament` встраиваются на стадии генерации внутри веера. Пример из сессии 2026-06-25:
fanout (its-researcher ×3) + adversarial-verify (code-verify) + generate-filter (ecosystem_scan) в одном потоке работ.

**Расширенные паттерны** (Multi-modal sweep · Pipeline без барьера · Perspective-diverse verify · Completeness
critic · Evaluator-optimizer · Agent teams · Loop-variants) — варианты/надстройки над базовыми 6, разобраны в
[46.8 Дополнительные паттерны](46.8_Дополнительные_паттерны.md).

## 4 примитива Claude Code (на чём всё строится)

| Примитив | Роль | Где |
|---|---|---|
| **Субагент** | рабочая единица (свой контекст, инструменты, модель) | Agent tool / Agent SDK `AgentDefinition`; `SubagentStart`-хук ловит спавн [code.claude.com/docs/en/hooks] |
| **Workflow** | детерминированный оркестратор (parallel / pipeline / циклы / условия) | Workflow tool; «custom subagents — the worker primitive workflows orchestrate» [code.claude.com/docs/en/workflows] |
| **Hooks** | гейты/верификация: callback → decision (`{}`=allow, deny=блок) | [code.claude.com/docs/en/agent-sdk/claude-code-features] |
| **Agent-loop** | условие останова цикла (`max_turns`/`max_budget_usd`) | [code.claude.com/docs/en/agent-sdk/agent-loop] |

## Как читать главу
Каждая подглава: **схема** (как на видео) → **когда применять** → **реализация в Claude Code** →
**Workflow-пример** (исполнимый JS) → **реальный пример в нашем фреймворке** → **подводные камни**.

Большинство паттернов **уже применяются** в проекте (примеры в подглавах; 4 из 6 — вживую в сессии 2026-06-25:
fanout-synthesize, adversarial-verify, generate-filter, loop-until-done).
