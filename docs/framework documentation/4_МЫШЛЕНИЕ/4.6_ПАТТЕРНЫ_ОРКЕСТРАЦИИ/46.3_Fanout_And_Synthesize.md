# 46.3 Fanout-And-Synthesize

> **Статус:** актуально на 2026-07-05 (аудит 260704). Методологическая глава; проверяй датированные ссылки при использовании.

> Гл. [46 Паттерны оркестрации](46.1_Обзор.md)

## Схема
```
prompt ─┬─ agent_1 ─┐
        ├─ agent_2 ─┼─ [синтез] → результат
        └─ agent_3 ─┘
```

## Суть и когда
**Веер** параллельных агентов (каждый — свой кусок/перспектива) → **синтез** в один ответ. Применять для
охвата: разложить тему на N подтем и закрыть их одновременно; собрать базу знаний; обработать N независимых
элементов. Выигрыш: wall-clock (параллель) + изоляция контекста (тяжёлое сырьё дистиллируется в субагентах).

## Реализация в Claude Code
- Несколько **субагентов в ОДНОМ сообщении** (Agent tool ×N) → запускаются конкурентно → оркестратор агрегирует.
- **Workflow `parallel([...])`** — барьер: дождаться всех; либо `pipeline()` без барьера.
- Кап конкурентности (cpu-2, ≤16); ToS/ресурсы — держать батч умеренным.

## Workflow-пример
```js
const dims = ['security','performance','correctness']
const findings = await parallel(dims.map(d => () =>
  agent(`Review the diff for ${d} issues`, {schema: FINDINGS})))
return synthesize(findings.filter(Boolean).flatMap(r => r.items))
```

## Подводные камни
- **Барьер `parallel` тратит wall-clock** на ожидание самого медленного — если стадии независимы, бери
  `pipeline()` (без барьера). `.filter(Boolean)` — упавший агент возвращает `null`, не роняет батч.
