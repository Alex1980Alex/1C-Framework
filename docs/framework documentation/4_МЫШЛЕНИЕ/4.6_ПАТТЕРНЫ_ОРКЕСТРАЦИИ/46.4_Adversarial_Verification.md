# 46.4 Adversarial Verification

> **Статус:** актуально на 2026-07-05 (аудит 260704). Методологическая глава; проверяй датированные ссылки при использовании.

> Гл. [46 Паттерны оркестрации](46.1_Обзор.md)

## Схема
```
prompt → находки ─┬─ verifier_1 (опровергни!) ─┐
                  ├─ verifier_2 (опровергни!) ─┼─ majority-refute → выкинуть
                  └─ verifier_3 (опровергни!) ─┘   иначе → подтверждено
```

## Суть и когда
Находку/решение проверяют **независимые агенты-скептики**, цель которых — **опровергнуть** (а не подтвердить).
Если большинство опровергло — отбросить. Применять, когда «правдоподобно, но может быть неверно» дорого
(баги-фантомы, ложные срабатывания). Убирает plausible-but-wrong результаты.

## Реализация в Claude Code
- **Reviewer-субагент** с промптом «попробуй опровергнуть; по умолчанию refuted=true при сомнении».
- **Перспективно-разнообразная** проверка: разные линзы (correctness / security / repro) ловят разные провалы.
- **Hook-гейт:** Stop-хук блокирует завершение, пока проверка не пройдена (decision=deny).

## Workflow-пример
```js
const votes = await parallel(Array.from({length: 3}, () => () =>
  agent(`Try to REFUTE: "${claim}". Default refuted=true if uncertain.`, {schema: VERDICT})))
const survives = votes.filter(Boolean).filter(v => !v.refuted).length >= 2
```

## Реальный пример в нашем фреймворке
- **`code-verify`** (скилл) — reviewer-субагент в 4 режимах (knowledge/behavior/bug-fix/quality) с маркером
  `[CODE-VERIFY-PASS]`/`[CODE-VERIFY-FAIL]`; при FAIL — Ralph-Wiggum итерации. Применялся ~6× на момент написания
  (см. штамп) (its_fetch, onec_search authority×recency, cc_docs_search и т.д.).
- **`onec-task-completion-stop`** — Stop-гейт 1С-задачи (recall/capture/research/sonar): decision=deny пока не закрыто.

## Подводные камни
- Скептик должен быть **настроен опровергать** (иначе подтверждает всё). Несколько **разных линз** > N
  одинаковых рефьютеров. Не зацикливаться: после K итераций — manual review.
