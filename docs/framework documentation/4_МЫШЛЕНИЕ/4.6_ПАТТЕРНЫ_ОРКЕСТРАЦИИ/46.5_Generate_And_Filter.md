# 46.5 Generate-And-Filter

> **Статус:** актуально на 2026-07-05 (аудит 260704). Методологическая глава; проверяй датированные ссылки при использовании.

> Гл. [46 Паттерны оркестрации](46.1_Обзор.md)

## Схема
```
prompt → [генератор: много кандидатов] → [фильтр: предикат/судья] → оставшееся
```

## Суть и когда
Сгенерировать **много** кандидатов, затем **отфильтровать** по предикату/оценке. Применять, когда генерация
дешёвая, а бóльшая часть вывода — шум: проще нагенерить с запасом и отсеять, чем выверять каждый на лету.

## Реализация в Claude Code
- **Генератор** (агент или CLI-источник) → стадия-**фильтр** (детерминированный предикат ИЛИ judge-агент).
- **Workflow `pipeline(items, generate, filter)`** или `parallel(gen).filter(predicate)`.
- Порог фильтра — тюнингуемый; **логировать отброшенное** (иначе «покрыли всё» читается ложно).

## Workflow-пример
```js
const cands = await agent('Предложи 10 вариантов имени для модуля', {schema: NAMES})
const kept = cands.names.filter(n => /^[A-ZА-Я]/.test(n) && n.length <= 25)   // детерминированный фильтр
// либо judge-фильтр:
const judged = await parallel(kept.map(n => () => agent(`Оцени имя "${n}" 1-5`, {schema: SCORE})))
return kept.filter((_, i) => (judged[i]?.score ?? 0) >= 4)
```

## Подводные камни
- **Тихий кап = ложное «покрыли всё»**: если режешь top-N / сэмплируешь — `log()` что отброшено.
- Порог фильтра калибровать на данных (наш кейс: 0.3 пропускал шум → 0.5).
