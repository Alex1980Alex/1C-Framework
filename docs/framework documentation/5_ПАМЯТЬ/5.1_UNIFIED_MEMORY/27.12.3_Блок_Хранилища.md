## 1. `memory-ai` (EPISODIC) — SQLite `data/memory_ai.db`

**Код:** [server.py](../../../../src/memory/ai_memory/server.py). Путь — project-local, `ensure_db()` создаёт БД при импорте модуля. Единственная таблица — `important_messages`:

| Колонка | Тип | Default | Назначение |
|---|---|---|---|
| `id` | TEXT PK | `uuid4()` | идентификатор сообщения |
| `content` | TEXT NOT NULL | — | текст факта/сообщения |
| `importance` | REAL | 0.5 (DDL) / **0.7** (tool-default при save) | важность 0.0–1.0 |
| `category` | TEXT | `'general'` | свободная категория |
| `tags` | TEXT | — | JSON-массив строк |
| `created_at` / `updated_at` | TEXT | — | ISO-8601 |
| `metadata` | TEXT | — | JSON-объект (при save пишется `{}`) |

**Индексы:** `idx_importance` (importance DESC), `idx_category`, `idx_created` (created_at DESC) — под сортировку чтения `ORDER BY importance DESC, created_at DESC`.

- **Пишут:** MCP `save_important_message`; Stop-хук `session-memory-save` (итоги сессии); `MemoryRouter._save_to_target` (episodic-маршрут); миграции (LIGHT-записи → `learned_patterns`, см. [27.12 §9](27.12_Memory_Systems_Map.md)).
- **Читают:** MCP `get_important_messages` (фильтр `min_importance`, default 0.5, + `category`), `search_messages` (substring `LIKE %query%` по `content` И `tags` — лексический, не семантический), `get_categories` (GROUP BY + AVG); федеративный `AiMemoryAdapter` (rerank 0.5·match + 0.5·`effective_importance`, [27.12 §5](27.12_Memory_Systems_Map.md); ранжирование по decay-corrected весу — см. ниже).
- **Особенности:** дедупа в server-коде **нет** (каждый save — новый uuid4); удаление только явным `delete_message` ИЛИ archive-job (см. retention ниже). ⚠ Колонки `content_hash` в DDL **нет** — дедуп-контракт §26 ([27.12 §11.2](27.12_Memory_Systems_Map.md)) реализуется на уровне MemoryCube-проекции, а не схемы таблицы.

**Retention (roadmap 260612 P3, [retention.py](../../../../src/memory/ai_memory/retention.py)):** classic TTL отсутствует, но есть lazy importance-decay + age-archive — тот же инвариант, что у §22 lazy decay-on-read (confidence).

| Механизм | Формула/порог | Категории | Где применяется |
|---|---|---|---|
| **Importance-decay** (read-time, ленивый) | `effective_importance()`: экспоненциальный decay, `HALF_LIFE_DAYS=90` — importance халвится каждые 90д ([retention.py:24,44-54](../../../../src/memory/ai_memory/retention.py#L24)) | только `DECAY_CATEGORIES={"session_summary","general"}` ([retention.py:21](../../../../src/memory/ai_memory/retention.py#L21)); curated-категории (`decision`/`preference`/`feedback` и пр.) — инвариант, не затухают | `AiMemoryAdapter.search` ранжирует по effective, не stored importance ([memory_orchestrator.py:210,242](../../../../src/memory/orchestrator/memory_orchestrator.py#L210)) |
| **Age-archive** (maintenance job) | `should_archive()`: decayable-строка старше `ARCHIVE_AFTER_DAYS=90` И `importance < ARCHIVE_IMPORTANCE_BELOW=0.8` → invalidate-stamp `metadata.archived_at` (не delete) ([retention.py:28-29,62-71](../../../../src/memory/ai_memory/retention.py#L28)) | те же `DECAY_CATEGORIES` | job `run_archive_episodic` в каденсе `scripts/memory_maintenance.py` (`archive_episodic`); архивные строки невидимы читателям через `is_archived()` |

Stored `importance` в БД статичен (write-time значение не меняется) — decay считается на чтении, дважды не персистится.

## 2. `vector-memory` (SEMANTIC) — Qdrant `learned_patterns` 4096d

**Код:** [server.py](../../../../src/memory/vector_memory/server.py), [models.py](../../../../src/memory/vector_memory/models.py), [confidence.py](../../../../src/memory/vector_memory/confidence.py). Qdrant `http://localhost:6333` (gRPC 6334, `prefer_grpc=True`), коллекция `learned_patterns` (env `LEARNING_COLLECTION_NAME`), `VECTOR_SIZE=4096` (env `LEARNING_VECTOR_SIZE`; Qwen3-Embedding-8B через TEI).

**Вектор:** один **безымянный** dense-вектор, COSINE, 4096d. ⚠ Named vectors (как у `bsl_code_v4_late` `{dense, bm25}`) здесь **не используются** — `_ensure_collection` создаёт plain `VectorParams`. ⚠ Docstring `_ensure_collection` всё ещё говорит «cosine 1024d» — stale-комментарий, фактический размер берётся из `VECTOR_SIZE=4096`. Embed-текст = `f"{name}: {content}"`.

**Payload** (полный список из `_pattern_to_payload`, модель [`LearnedPattern`](../../../../src/memory/vector_memory/models.py)):

| Поле | Тип | Назначение |
|---|---|---|
| `pattern_id` | str | дублирует point-id |
| `pattern_type` | enum (6) | `code-convention` · `workflow-pattern` · `debugging-heuristic` · `architectural-principle` · `project-structure` · `bsl-pattern` |
| `name` / `description` / `content` | str | содержимое паттерна (`.md`-файла нет — контент в payload) |
| `confidence` | float | производная Beta(7+succ, 3+fail); при save = prior **0.70**, advisory-аргумент игнорируется |
| `succ` / `fail` | float | sufficient statistics §22 (decayed-счётчики успехов/провалов) |
| `last_decay_at` | ISO/null | момент последнего decay счётчиков (lazy decay-on-read отсчитывается от него) |
| `expired_at` | ISO/null | **архив** (invalidate-not-delete §22 P3); `apply` ставит `None` = revive |
| `decay_rate` | float | per-pattern, default 0.05; эффективная = `stability_adjusted_rate` (FSRS-lite) |
| `application_count` / `last_applied` | int / ISO | монотонный счётчик применений + время |
| `evidence_sources` | list[dict] | [`EvidenceSource`](../../../../src/memory/vector_memory/models.py): `source_type` (`file`/`commit`/`conversation`/`tool-use`), `reference`, `weight`, `timestamp`, `metadata` |
| `created_at` / `updated_at` / `version` / `tags` / `metadata` | — | служебные; `content_hash` приезжает в payload через harvester/MemoryCube (§26) |

**Payload-индексы:** `pattern_type` (KEYWORD), `confidence` (FLOAT), `tags` (KEYWORD).

- **Пишут:** MCP `save_pattern` (point-id = **`uuid4()`**); харвестеры `patterns-harvester`/`skills-harvester` через ingest — point-id = **детерминированный UUID5(content_hash)** → повторный harvest того же факта = тот же id = идемпотентный `dup` ([27.12 §10.1](27.12_Memory_Systems_Map.md)); `apply_pattern`/`reinforce`/`decay_confidence` мутируют payload через `set_payload`.
- **Читают:** `search_patterns` (семантика × effective-confidence; server-side Range-префильтр по `confidence` **намеренно отсутствует** — stored-значение может быть ниже effective, фильтр клиентский), `list_patterns` (scroll без эмбеддинга — работает при TEI cold-start), `get_pattern`; surfacing-хук `memory-first-hook` (плечи `pattern_dense`/`pattern_lexical`).
- **Особенности:** архивные (`expired_at`≠null) исключаются из поиска (override `MEMORY_INCLUDE_ARCHIVED=1`); decay-sweep архивирует по `should_archive` (eff < 0.40, либо idle > 180д ∧ eff < 0.75 ∧ не invariant; invariant-типы `architectural-principle`/`bsl-pattern` от staleness освобождены) **и обратно ре-вайвит**, если счётчики отдекеились выше порогов. ⚠ Описание tool `decay_confidence` («below threshold are **deleted**») — drift: код **никогда не hard-delete'ит**, только `expired_at`. Каждая мутация — `epoch.bump()` (инвалидация surfacing-кэша §24) + fail-soft `_log_lifecycle`. `apply_pattern` дополнительно гонит каскад `_cascade_confidence` на соседей по LinkRegistry (depth-1, ≤10 узлов, gated `MEMORY_APPLY_CASCADE_DISABLE=1`).

## 3. `skill-learning` (LEARNING) — JSONL `data/skill_learning/`

**Код:** [server.py](../../../../src/memory/skill_learning/server.py). Четыре файла:

| Файл | Роль |
|---|---|
| `pending_patterns.jsonl` | захваченные, ждут подтверждения |
| `patterns.jsonl` | подтверждённые (saved) |
| `rejected_patterns.jsonl` | отклонённые |
| `learning_stats.json` | агрегаты: `total_patterns`, `by_type`, `by_confidence` (high ≥0.7 / medium ≥0.4 / low) |

**Поля JSONL-записи** (`handle_capture_pattern`): `pattern_id` (uuid4), `pattern_type`, `name`, `content`, `description`, `confidence` (default 0.7), `tags`, `evidence_sources`, `metadata`, `application_count`/`success_count`/`failure_count` (init 0), `created_at`/`updated_at` (ISO), `version` (1), `archived` (false); у отклонённых добавляется `rejected_at`.

**Жизненный цикл статусов:** `capture_pattern(require_confirmation=True)` → append в pending; `=False` → сразу в saved (+stats). `confirm_pattern` → append в saved + **полная перезапись** pending без записи; `reject_pattern` → append в rejected + перезапись pending. Т.е. статус = **в каком файле лежит запись**, отдельного поля статуса нет.

- **Пишут:** MCP `capture_pattern`/`batch_capture`/`confirm_pattern`/`reject_pattern`; `MemoryRouter` (learning-маршрут).
- **Читают:** `get_pending_patterns` (limit, default 10), `get_learning_stats` (+`pending_count`), федеративный `SkillLearningAdapter` (keyword-overlap).
- **Особенности:** дедупа и TTL нет; лимитов размера нет; append-only кроме перезаписи pending. Контент подтверждённого паттерна дальше промоутится в `vector-memory` (роль «приёмной» перед Qdrant).

## 4. `pdf-docs` (DOCS) — production Qdrant-коллекции `pdf_framework`

**Актуальное состояние (260612 pdf-docs full verification):** блок pdf-docs = production-коллекции
`pdf_documents` (830 pts) и `wiki_pages_v1` (3 073 pts), обе alias → `*_mrl_1024`
(Qwen3 MRL 1024d + SQ int8), плюс канонические re-embed источники `*_4096_backup`
(политика — skill `qdrant-operations`). Доступ — через `pdf-vector-graph` MCP
(`search_documents`/`ask_question`/`research`) и читателей `docs-change-enforcer` /
wiki-pipeline `HybridSearchService`. Писатели: `index_pdf` pipeline, `eval_hermes_phase4.py
index-wiki`, миграционные/golden-append скрипты.

**`DocsRagSearchAdapter` РЕТИРОВАН 2026-06-12** (roadmap
[260612 pdf-docs P0.1 / D1](../../../roadmap/260612_ROADMAP_PDF_DOCS_FULL_VERIFICATION.md)) в
[scripts/attic/docs_rag.py](../../../../scripts/attic/docs_rag.py): контур был мёртв с рождения
(default `chunks_db_path=""`, Qdrant-коллекция `docs_chunks` никогда не существовала,
эмбеддер заимствован у vector_memory 4096d против собственного дизайна, `_vector_search`
глотал все ошибки), жил только в integration-тестах. Production-RAG документации уже
полностью закрыт `pdf_framework` — дублирующая SQLite-вселенная не нужна.

**ADR P0.4 (D4-фиксация, 2026-06-12): PDF_DOCS в governance = осознанный `unsupported_source`.**
`_get_entity` / TTL / versioning оркестратора НЕ поддерживают `SourceServer.PDF_DOCS` —
это решение, а не дыра: документация **immutable со стороны памяти** (точки создаются
только индексационным pipeline, память их не мутирует → нечего версионировать, TTL
управляется reindex-каденсом, не ledger'ом). Honest-ответ `unsupported_source` корректен.
`create_doc_id()` / `MemoryType.DOCUMENTATION` остаются в `unified_id.py` для D2-решения
(docs-плечо `unified_search` — см. P2 роадмапа 260612).

## 5. `LinkRegistry` — SQLite `data/link_registry.db` (связи, не контент)

**Код:** [link_registry.py](../../../../src/memory/orchestrator/link_registry.py). Default-путь — `data/link_registry.db`; `SCHEMA_VERSION=1`. Четыре таблицы:

| Таблица | Колонки | Назначение |
|---|---|---|
| `entity_links` | `link_id` TEXT PK · `source_id` · `target_id` · `link_type` (CHECK по 8 значениям) · `strength` REAL default 0.8 (CHECK 0..1) · `created_at` · `created_by` ('system') · `metadata` JSON · `bidirectional` INT (0) · `expires_at` | сами связи; 7 индексов (source/target/type/strength/source_type/target_type/created) |
| `link_history` | `history_id` PK · `link_id` · `action` (create/update/delete) · `old_strength`/`new_strength` · `changed_at`/`changed_by`/`reason` | audit-trail каждой мутации; 2 индекса |
| `link_stats` | `entity_id` PK · `outgoing_count` · `incoming_count` · `avg_strength` · `last_updated` | денормализованные счётчики, пересчёт при каждом CRUD |
| `schema_info` | `key`/`value` | версия схемы |

**LinkType (8, после ADR-L1 260612 — `based_on`/`graph_node` ретированы):** авто `mirrors` · `derives_from` · `session_context` · `promoted_to`; ручные `supports` · `contradicts` · `extends` · `superseded_by` — enum в коде и CHECK в DDL продублированы.

- **Пишут:** оркестратор (cross-link `session_context` strength 0.7 при мульти-store save), MCP `create_link`, миграции (`PROMOTED_TO`/`MIRRORS`/`SUPERSEDED_BY`). `create_link` **запрещает дубль** тройки (source, target, type) — ValueError; self-link запрещён в `__post_init__`; `create_links_batch` молча скипает `IntegrityError`.
- **Читают:** `get_links_from/to`, BFS `get_related_entities` (default `max_depth=2`, `min_strength=0.5`, `effective_strength = strength × 0.9^(depth-1)`), `find_path`; `LinkEnricher` федеративного поиска; каскад `_cascade_confidence` vector-memory (forward-типы SUPPORTS/EXTENDS/BASED_ON/DERIVES_FROM).
- **TTL:** per-link `expires_at` + `cleanup_expired()` (hard-delete просроченных); `vacuum()`/`export()`/`import_links()` для обслуживания. Соединение — короткоживущее per-операция (contextmanager), WAL не включён.

## 7. Типичные сбои и диагностика

| Сбой | Поведение в коде | Диагностика |
|---|---|---|
| **Qdrant down** | vector-memory: все handlers обёрнуты в `call_tool` try/except → MCP вернёт `Error: ...` текстом, сервер не падает; `health_check` → `{"qdrant": false, "error": ...}`. pdf-docs: `pdf-vector-graph` MCP отдаёт честную ошибку tool'а (S1-S3 warmup в server.py) | `mcp__vector-memory__health_check` (qdrant/collection/count); `list_patterns` работает и при TEI cold-start (без эмбеддинга) |
| **Embedding-провайдер down** | `_get_embedding` → **RuntimeError** (search/save ломаются осознанно); hash-fallback только opt-in `MEMORY_VECTOR_ALLOW_HASH_FALLBACK=1` с WARN на каждый вызов (псевдо-векторы = бессмысленный поиск, roadmap 260509 §4.3) | stderr-лог `vector-memory`; `[HASH-FALLBACK]` в логах = деградация |
| **SQLite lock** | memory-ai: короткие транзакции через `with sqlite3.connect(...)`, но **без WAL и timeout** — конкурентная запись может дать `database is locked`; link_registry: connection-per-операция, тоже без WAL | повторить операцию; для memory-ai/link_registry конкурентных писателей мало (MCP stdio — один процесс) |
| **Коррупция JSONL** | skill-learning `_read_jsonl`: битая строка → `json.JSONDecodeError → continue` (тихо отбрасывается, остальные читаются) | `health_check` skill-learning (pending/saved/rejected counts); расхождение count vs `wc -l` файла = битые строки |
| **Перезапись pending** | `confirm`/`reject` делают полный rewrite `pending_patterns.jsonl` — без атомарного `os.replace` (краш в момент записи теоретически теряет pending) | бэкап каталога `data/skill_learning/` перед массовыми confirm |
| **Stale MCP-код** | мутации payload — на стороне MCP-процесса: правки `src/memory/vector_memory/*` требуют `/mcp reconnect`; `server_start`-событие в lifecycle-логе (с pid) делает перезагрузку наблюдаемой | `confidence-lifecycle.log` — pid/время `server_start` |
| **Каскад/трейс-логирование** | `_log_lifecycle`, `_cascade_confidence`, `write_trace` — все fail-soft (`except: pass`): сбой observability никогда не ломает handler | `scripts/memory_observability_query.py --view fact-trace --key <pattern_id>` |
