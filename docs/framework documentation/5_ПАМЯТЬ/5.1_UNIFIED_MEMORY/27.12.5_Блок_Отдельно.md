# 27.12.5 Блок «ОТДЕЛЬНО» — курируемый .md-слой и Event Store

> Детализация блока **«ОТДЕЛЬНО (не через оркестратор)»** мастер-схемы [27.12 §10](27.12_Memory_Systems_Map.md): две системы, которые живут вне маршрутизации/federated-поиска оркестратора — **курируемая память** (ручные `.md`-файлы, читаются только хуком) и **Event Store** (журнал событий памяти: hot JSONL + cold SQLite, pub/sub + replay). Все факты — из кода `memory-first-hook.py`, `feedback_draft.py`, `pattern_harvest.py` и `src/memory/infrastructure/`.

```text
  ╔══════════════════════════════════════════════════════════════════════════╗
  ║  ОТДЕЛЬНО (не через оркестратор):                                          ║
  ║   • Курируемая память: MEMORY.md + memory/*.md  ← РУЧНОЙ слой, .md-файлы   ║
  ║       читается только memory-first-hook (layer 'md')                       ║
  ║   • Event Store: events.jsonl (hot) + events.db (cold) — pub/sub + replay  ║
  ╚══════════════════════════════════════════════════════════════════════════╝
```

## Часть 1. Курируемая память — ручной `.md`-слой

### 1.1 Каталог и формат файла

Физически слой лежит **вне репозитория**: `~/.claude/projects/C--1--Framework/memory/` (override — env `CLAUDE_MEMORY_DIR`, см. [memory-first-hook.py](../../../../.claude/hooks/memory-first-hook.py), константа `MEMORY_DIR`). Состав:

- **`MEMORY.md`** — человекочитаемый индекс: одна строка-аннотация на запись со ссылкой на файл. Хук его **пропускает** при поиске (`if md_file.name == "MEMORY.md": continue` в `load_all_memories()`), т.е. индекс — для человека и автозагрузки контекста Claude Code, не для скоринга.
- **`memory/*.md`** — записи с YAML-frontmatter:

```markdown
---
name: feedback-bsl-sparse-bm25-dominance
description: "anchor benchmark: dense 17% Hit@10, BM25 90% — hybrid mandatory"
metadata:
  type: feedback        # user | feedback | project | reference
---
Тело записи. Wikilinks [[feedback-mrl-content-matters]] связывают записи между собой.
```

Парсер хука (`parse_frontmatter()`) — наивный, построчный: `content.split("---", 2)`, из frontmatter извлекаются только ключи `name` / `description` / `type` через `partition(":")`. Строка `  type: feedback` внутри блока `metadata:` тоже матчится (парсер не различает вложенность) — поэтому `metadata.type` фактически читается. Типы по конвенции именования файлов: `feedback_*` (правила/уроки), `project_*` (контекст проекта), `reference_*` (справочные рецепты), `user` (предпочтения).

### 1.2 Путь данных: человек → файл; авто-захват только в черновики

Слой — **единственный в системе с ручной записью**. Авто-pipeline сюда не пишет; он пишет **черновики** в `data/memory_drafts/`:

```text
  user prompt ──► userpromptsubmit-feedback-detector (UserPromptSubmit)
                  │  detect_feedback(): _RULE_PATTERNS (10 regex RU/EN:
                  │  «вместо X используй», «не делай», «use X instead of Y»…)
                  │  + обязательный _CODE_TOKEN (dotted-call / `код` / БСП-лексика)
                  ▼
        data/memory_drafts/{ts}_{sha1(norm_prompt)[:12]}.md   (status: pending)
                  │            dedup по key в имени файла — повторный prompt = silent skip
                  ▼
  Stop ──► stop-feedback-draft-aggregator: напоминание о pending-черновиках (cap 5)
                  │
        ┌─────────┴──────────────────────────────────────────────┐
        ▼ ПОДТВЕРЖДЕНИЕ (человек/ассистент вручную)              ▼ status: confirmed
  memory/feedback_<slug>.md + строка в MEMORY.md      pattern_harvest.py (Stop) →
  (= попадание в курируемый слой)                     upsert в learned_patterns (Qdrant),
                                                      НЕ в курируемый слой
```

Детектор — [userpromptsubmit-feedback-detector.py](../../../../.claude/hooks/userpromptsubmit-feedback-detector.py) + [shared/feedback_draft.py](../../../../.claude/hooks/shared/feedback_draft.py) (шаблон черновика с `metadata.status: pending` и плейсхолдерами `<…>`); напоминание — [stop-feedback-draft-aggregator.py](../../../../.claude/hooks/stop-feedback-draft-aggregator.py); opt-out обоих — `FEEDBACK_DRAFT_DISABLE=1`. Promote подтверждённого черновика двунаправленный: в курируемый слой переносит **человек**, а [shared/pattern_harvest.py](../../../../.claude/hooks/shared/pattern_harvest.py) (§26 P1) дополнительно майнит черновики с `metadata.status: confirmed/approved` и заполненными плейсхолдерами в семантический store `learned_patterns` — с явной оговоркой в docstring: «curated `MEMORY.md` layer stays manual per §26 §6».

> **Восстановлено (2026-06-10, roadmap 260609 P2.2):** «L5 drafts promote» в `session-memory-save.py` снова живой — `try_promote_patterns()` делегирует канонический `export_graph_to_wiki promote-patterns` (тот же промоут-job, что §26 P4 cadence; opportunistic per-session, opt-out `SESSION_MEMORY_NO_PROMOTE=1`), `save_to_wiki_log()` пишет в `docs/wiki/log.md`. Стабы пост-PR#2 устранены.

### 1.3 Чтение: слой `md` в memory-first-hook

Единственный читатель — [memory-first-hook.py](../../../../.claude/hooks/memory-first-hook.py) (UserPromptSubmit), слой `md` из 4-слойного federated recall (`LAYER_WEIGHTS`: sqlite 0.30, qdrant 0.35, **md 0.15**, wiki 0.20):

1. `load_all_memories()` — читает все `*.md` каталога (кроме `MEMORY.md`), парсит frontmatter, токенизирует `name` / `description` / `body[:2000]` (только первые 2000 символов тела!).
2. Токенизация (`tokenize()`): regex `[a-zA-Zа-яА-ЯёЁ0-9_\-]+`, lowercase, токены ≥2 символов, русский суффиксный стеммер (37 суффиксов: `-ами/-ого/-ать/…` → обрезка при остатке ≥3).
3. Скоринг (`score_memory()`) — взвешенный token-overlap **name×3 / description×2 / body×1**:

```text
weighted        = |Q∩name|·3 + |Q∩desc|·2 + |Q∩body|·1
query_coverage  = |Q∩(name∪desc∪body)| / |Q|
memory_density  = min(weighted / (|Q|·3), 1.0)
score           = 0.7·query_coverage + 0.3·memory_density
```

4. Пороги/бюджеты: `SCORE_THRESHOLD = 0.3` (ниже — запись не всплывает), `MD_TIMEOUT = 0.5s` на слой (при превышении остаток файлов не сканируется), top-10 со слоя → кросс-слойный `rrf_merge(k=60)` → top-5 (`MAX_RESULTS`) → инъекция в stdout. Общие гейты хука: prompt ≥20 символов, не слэш-команда, cooldown 30s, execution-cache (§24) по `hash(query_tokens)`+confidence-epoch.

### 1.4 Почему слой НЕ подключён к оркестратору

Изоляция — осознанная (27.12 §9: «курируемый слой живёт в стороне»). Курируемая память — это **vetted ручное знание** с гарантией «написано/подтверждено человеком». Подключение к `route_and_save` сломало бы гарантию: авто-классификатор с порогом 0.30 начал бы писать сюда непроверенный контент, и слой деградировал бы до ещё одного авто-store. Поэтому: запись — только человек (авто-захват упирается в draft-карантин `data/memory_drafts/` с обязательным подтверждением), чтение — только лёгкий token-overlap в хуке (без эмбеддингов: файлы маленькие, их ~50, лексический поиск по `name×3` достаточен и укладывается в 0.5s). `unified_search` оркестратора по этому слою **не ищет** — адаптера нет.

## Часть 2. Event Store + EventBus — журнал и шина событий памяти

### 2.1 Событие и envelope

Единица — dataclass `Event` ([event_bus.py](../../../../src/memory/infrastructure/event_bus.py)): `{event_id: uuid4, event_type: "memory.save" (dotted), data: dict, timestamp: UTC, source}`. В `events.jsonl` сериализуется плоским JSON-объектом с ISO-timestamp (`EventStore._serialize_event`).

Отдельная сущность — [event_envelope.py](../../../../src/memory/infrastructure/event_envelope.py) (§27 P3): **reader-adapter** для observability-sink'ов, НЕ для `events.jsonl`. `normalize(source, raw)` проецирует записи 10 разноформатных JSONL-логов (`CACHE_LOGS`: lifecycle/surfacing/ingestion/routing/read/propagation/circuit/metrics/maintenance + `data/services/audit.jsonl`) в один канонический CloudEvents-style конверт с фиксированным ядром `CORE_KEYS` (`ts/source/type/correlation_id/content_hash/pattern_id/store/action/outcome/latency_ms/success`) — стабильная схема для DuckDB `union_by_name`. `make_envelope()` — forward-helper для новых писателей (CloudEvents v1.0: `specversion/id/source/type/time` + `correlation_id/causation_id/content_hash`). `known_sinks(project_root)` — авторитетный expected-set для freshness/regression-детектора отчёта §27. On-disk форматы legacy-sink'ов не мигрируются — нормализация на чтении. **Metadata-only**: тела промптов/паттернов в конверт не проецируются.

### 2.2 EventBus — pub/sub ([event_bus.py](../../../../src/memory/infrastructure/event_bus.py))

Singleton (`get_event_bus()`), async, in-memory:

- **publish(event_type, data, source)** → событие в `_dispatch_queue`, фоновый `_dispatch_loop` (`asyncio.Task`) фанаутит по подписчикам; останов — sentinel `__shutdown__`.
- **subscribe(pattern)** → `Subscription` с собственной bounded `asyncio.Queue` (`max_queue_size=1000`). Wildcard-матчинг по dot-сегментам: `*` = ровно один сегмент, `**` = ноль и более (`memory.*` ловит `memory.save`, но не `memory.pattern.apply`; `memory.**` — оба).
- **Backpressure**: при `QueueFull` выбрасывается **старейшее** событие из очереди подписчика, новое кладётся, `dropped_count++` — медленный подписчик теряет хвост истории, но не блокирует шину.
- Лимиты: `max_subscribers=100` (RuntimeError при превышении), `dispatch_timeout=5.0s` на graceful stop. `get_stats()` → `{published_count, subscriber_count, dropped_count}`.

### 2.3 EventStore — hot JSONL + cold SQLite ([event_store.py](../../../../src/memory/infrastructure/event_store.py))

Двухслойная персистентность; пути прошиваются оркестратором ([memory_orchestrator.py](../../../../src/memory/orchestrator/memory_orchestrator.py)): hot `data/events.jsonl`, cold `data/events.db`.

| Аспект | Hot (`events.jsonl`) | Cold (`events.db`) |
|---|---|---|
| Запись | `append()` — построчный JSONL (быстрый append) | батч `INSERT OR IGNORE` при flush |
| Схема | плоский JSON | таблица `events(event_id PK, event_type, data, timestamp, source)`, WAL, индексы по `event_type` и `timestamp` |
| Ротация | очищается при flush (`_clear_jsonl`) | накапливается бессрочно |

**Ротация hot→cold** (а не size-rotation): авто-flush при `auto_flush_threshold=500` событий в hot-буфере **или** периодически каждые `flush_interval=60s` (фоновый таск), плюс финальный flush на `stop()`. `INSERT OR IGNORE` по `event_id` = идемпотентность при повторном flush. ⚠ Поле конфига `max_hot_buffer_mb=10.0` объявлено, но в коде **нигде не используется** (нет MB-ограничителя — расхождение config-vs-code).

**Чтение**: `query(event_type, start, end, limit=100)` — сначала cold (SQL), затем добор из hot (построчный фильтр), merge + sort по timestamp. **Replay**: `replay(event_type, start, callback)` — прогоняет до 100 000 событий через callback (sync или coroutine — `iscoroutine` + await), возвращает count; `callback=None` → 0. `get_stats()` → `{total_events, hot_buffer_size, cold_storage_size}`.

### 2.4 SubscriptionManager — heartbeat подписок ([subscription_manager.py](../../../../src/memory/infrastructure/subscription_manager.py))

Обёртка над EventBus для polling-клиентов (MCP — stateless-вызовы, push невозможен): `ManagedSubscription` = bus-подписка + `client_id`, `last_heartbeat`, `delivered_count`, metadata. Лимит `max_subscriptions_per_client=10`. Фоновый cleanup-loop (каждые `heartbeat_interval=30s`) удаляет подписки с `heartbeat_age > stale_timeout=120s` — клиент обязан периодически слать heartbeat, иначе подписка тихо умирает (счётчик `total_stale_cleaned` в `get_stats()`). `get_events(subscription_id, max_events=10)` — неблокирующий drain очереди (`get_nowait`).

### 2.5 MCP-инструменты realtime (P3, сервер `memory-orchestrator`)

8 tools поверх связки EventBus + EventStore + SubscriptionManager ([memory_orchestrator.py](../../../../src/memory/orchestrator/memory_orchestrator.py), §«Realtime tools»):

| Tool | Что делает |
|---|---|
| `memory_subscribe(client_id, pattern)` | создать managed-подписку (wildcard) |
| `memory_unsubscribe(subscription_id)` | снять подписку |
| `memory_publish(event_type, data, source)` | **dual-write**: bus.publish + store.append (персистентно) |
| `memory_get_events(subscription_id, max_events)` | poll очереди подписки |
| `memory_replay(event_type, start, limit)` | выборка из persistent storage (через `query`) |
| `memory_event_history(event_type, start, end, limit)` | то же + фильтр `end` |
| `memory_event_stats()` | stats шины + store + подписок одним вызовом |
| `memory_subscription_health(subscription_id?)` | с id = **heartbeat**, без = список всех подписок |

> ⚠ Уточнение к «не через оркестратор» из 27.12 §10: EventBus/EventStore **инициализируются процессом memory-orchestrator** и его внутренние события (`memory.save` из write-потока §4) идут через них. «Отдельно» в схеме означает: это **не контент-store** — Router не маршрутизирует в него записи, `unified_search` по нему не ищет; это инфраструктурный журнал *поверх* потоков, а не пятое хранилище.

## Сводка двух систем

| | Курируемая память | Event Store |
|---|---|---|
| Назначение | vetted ручное знание (правила, feedback, справки) | журнал событий памяти (pub/sub, replay, аудит потоков) |
| Носитель | `.md`-файлы `~/.claude/projects/C--1--Framework/memory/` + индекс `MEMORY.md` | `data/events.jsonl` (hot) + `data/events.db` (cold SQLite WAL) |
| Запись | **человек** / подтверждение черновика; авто — только в `data/memory_drafts/` (status pending) | авто: bus.publish / `memory_publish` (dual-write); flush ≥500 событий или 60s |
| Чтение | только `memory-first-hook` слой `md` (token-overlap name×3/desc×2/body×1, порог 0.3, вес 0.15 в RRF) | `memory_get_events` (live poll) / `memory_replay` / `memory_event_history` |
| Связь с оркестратором | **никакой** (нет адаптера, Router не пишет) | инициализируется им, но не участвует в route/search как store |
| Дедуп/идемпотентность | sha1(norm_prompt)[:12] в имени черновика | `event_id` PK + `INSERT OR IGNORE` |
| Время жизни | вечное, до ручного удаления | hot — до flush; cold — бессрочно |

## Типичные сбои и диагностика

- **Запись из `memory/*.md` не всплывает в хуке.** Проверить: score < 0.3 (стеммер режет только русские суффиксы — англ. словоформы должны совпадать буквально); искомые слова глубже 2000-го символа тела (`body[:2000]`); каталог большой и `MD_TIMEOUT=0.5s` срезал хвост glob'а; cooldown 30s; контент в `MEMORY.md` (индекс не сканируется — аннотация должна жить в самом файле записи). Трасса: `.claude/cache/memory-first-surfacing.log`, поле `layers.md`.
- **Черновик завис в `data/memory_drafts/`.** Это норма draft-mode: без ручного `status: confirmed` + заполнения плейсхолдеров `<…>` он не уходит ни в курируемый слой, ни в `learned_patterns` (`_PLACEHOLDER_RE` в `pattern_harvest.py` отбраковывает). Stop-хук напоминает (cap 5). Детектор молчит → проверить `FEEDBACK_DRAFT_DISABLE` и наличие code-токена в prompt'е (`_CODE_TOKEN` обязателен).
- **`events.jsonl` растёт и не очищается.** Flush делает только живой процесс memory-orchestrator; если MCP-сервер не запущен (или держит старый код — `/mcp reconnect`), hot-буфер копится. На старте `_count_hot_buffer()` подхватит накопленное, flush уйдёт по порогу/таймеру.
- **Подписка перестала отдавать события.** (а) heartbeat не слался >120s → stale-cleanup удалил её (`KeyError: Unknown subscription` из `memory_get_events`; смотреть `total_stale_cleaned` в `memory_event_stats`); (б) очередь переполнилась (1000) → drop-oldest, растёт `dropped_count` — забирать чаще.
- **`memory_replay` пуст.** События, опубликованные напрямую в bus (мимо `memory_publish`/`store.append`), не персистируются — шина in-memory; replay видит только то, что дошло до EventStore.
- **Конверты §27 «разъехались» со sink'ами.** Новый лог не виден в DuckDB-отчёте → он не зарегистрирован в `CACHE_LOGS` (`event_envelope.py`) — это единственный source of truth для expected-set.
- **Синк помечен `quiet`, а не `stale`.** Так и надо: он в `EVENT_DRIVEN_SOURCES` (`event_envelope.py`) — `propagation`/`circuit`/`links` пишут только по событию, планового писателя у них нет, поэтому молчание не регрессия (у `circuit` оно означает «ни один breaker не сработал»). Проверять надо, происходило ли САМО событие, а не давность записи. Молчание планового синка (`lifecycle`/`surfacing`/`ingestion`/`metrics`/`maintenance`) по-прежнему даёт `stale` + маркер `[REGRESSION]`. Разбор — 27.13, запись 2026-07-25.
