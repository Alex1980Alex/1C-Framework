# 27.2 Оркестратор памяти

Оркестратор — центральный координатор Unified Memory System. Он маршрутизирует данные между тремя бэкендами (AI Memory, Vector Memory, Skill Learning), управляет графом связей и выполняет федеративный поиск с агрегацией результатов.

Реализация: [`src/memory/orchestrator/`](../../../../src/memory/orchestrator/) — 8 модулей, 8 Core MCP tools + 25 дополнительных (P3+P4).

---

### MemoryCube

`MemoryCube` — унифицированный контейнер данных, независимый от целевого бэкенда. Используется для передачи записей между компонентами до конвертации в специфичный формат хранилища.

**Структура полей** (`orchestrator/memcube.py`):

| Секция | Поле | Тип | Описание |
|---|---|---|---|
| Identity | `cube_id` | `str` | UUIDv4 |
| | `content_type` | `ContentType` | fact/preference/rule/skill/code/observation/wiki |
| | `source` | `SourceServer` | Целевая подсистема-хранилище |
| | `content` | `str` | Основной текст записи |
| | `content_hash` | `str` | sha256(content)[:16] — dedup-ключ |
| Scoring | `confidence` | `float` | 0.0 — 1.0 |
| | `importance` | `float` | 0.0 — 0.95 |
| Temporal | `created_at` | `datetime` | Создание |
| | `updated_at` | `datetime` | Последнее обновление |
| | `expires_at` | `datetime \| None` | Опциональный TTL |
| Observations | `tags` | `list[str]` | Семантические теги |
| | `metadata` | `dict` | Произвольные метаданные |

**ContentType enum:**

```python
class ContentType(str, Enum):
    FACT = "fact"
    PREFERENCE = "preference"
    RULE = "rule"
    SKILL = "skill"
    CODE = "code"
    OBSERVATION = "observation"
    WIKI = "wiki"
```

**Конвертеры** в формат бэкендов:

- `to_ai_memory_row()` — запись для SQLite (`important_messages` таблица)
- `to_vector_memory_payload()` — Qdrant payload + вектор эмбеддингов
- `to_skill_learning_record()` — JSONL-запись с confidence и tags

### Memory Router

Модуль классификации и автоматической маршрутизации (`orchestrator/memory_router.py`). Определяет тип контента и выбирает целевой бэкенд 4-фазным конвейером (regex-classifier → детерминированные правила → keyword scoring → пороги).

Канонические сигналы, пороги и таблица `CONTENT_TYPE_TARGETS` — см. [27.12.2 Блок Координация §1](27.12.2_Блок_Координация.md).

**ClassificationResult:**

```python
@dataclass
class ClassificationResult:
    content_type: ContentType
    confidence: float       # 0.0 - 1.0
    signals: list[str]      # Совпавшие паттерны
```

Публичный API: `classify_content(text: str) -> ClassificationResult` — можно использовать из внешних компонентов.

### Link Registry

Граф связей на SQLite adjacency list (`orchestrator/link_registry.py`). Индексы на `entity_links`: одиночные `source_id`, `target_id`, `link_type`, `strength`, `created_at` + составные `(source_id, link_type)` и `(target_id, link_type)`.

8 типов связей (`LinkType`) — канонический список, семантика и BFS-параметры см. [27.12.2 Блок Координация §3](27.12.2_Блок_Координация.md).

API: `create_link(source_id, target_id, link_type, strength=0.8, metadata=None, created_by="system", bidirectional=False, expires_at=None)`, `get_related_entities(...)` (BFS-обход по глубине).

`get_related_entities` возвращает список **`RelatedEntity`** — результат обхода графа: `entity_id`,
`link_path` (цепочка **идентификаторов рёбер** `link_id`, пройденных до узла), `total_strength`
(произведение `strength` по пути), `depth`, `link_types`. Property `effective_strength` = `total_strength`
с затуханием по глубине (`0.9^(depth-1)`) — именно она ранжирует выдачу, а не сырое произведение.

### Unified Search (RRF)

Федеративный поиск через Reciprocal Rank Fusion (`orchestrator/unified_search.py`) — параллельный опрос адаптеров, слияние рангов, дедуп, rerank.

Канонические формула RRF, k-параметр, веса blend и boost-коэффициенты — см. [27.12.2 Блок Координация §2](27.12.2_Блок_Координация.md).

**Пример использования:**

```python
from memory.orchestrator.unified_search import federated_search, SearchOptions
from memory.orchestrator.unified_id import SourceServer

result = await federated_search(
    query="конфигурация circuit breaker",
    sources=[SourceServer.MEMORY_AI, SourceServer.VECTOR_MEMORY],
    limit=10,
    search_options=SearchOptions(
        rrf_enabled=True,
        rrf_k=60,
        rrf_source_weights={"memory-ai": 1.0, "vector-memory": 0.8},  # опционально; по умолчанию None → все веса 1.0
    ),
)

for r in result.results:
    print(r.unified_id, r.final_score, r.source.value)
```

Требует предварительной регистрации адаптеров через `UnifiedSearchEngine.register_adapter()` (делается один раз оркестратором при старте; см. `get_search_engine()`).

**Модель выдачи.** Элемент результата — **`SearchResultItem`**: `unified_id`, `source` (`SourceServer`),
`memory_type`, `content` + опциональные `title`/`snippet`, три оценки (`raw_score` от источника →
`normalized_score` после нормализации → `final_score` после RRF/boost — сортировка идёт по последней),
`created_at`/`updated_at`, `tags`, `metadata`, `duplicate_sources` (**имена источников** схлопнутых дублей — `source.value`, напр. `["memory-ai"]`) и
`linked_entities` — список **`LinkedEntity`** (`target_id`, `link_type`, `strength`, `direction`:
`outgoing`/`incoming`), подмешиваемых из Link Registry.

### Propagation Engine

BFS-пропагация изменений confidence через граф связей (`orchestrator/propagation_engine.py`). Заменил Neo4j на SQL через `LinkRegistry`; защищён rate-limiting и circuit breaker от лавинообразных каскадов.

Канонические формулы затухания (`time_decay`/`distance_decay`), лимиты `PropagationConfig` и режим работы оркестратора (sync без дедупа) — см. [27.12.2 Блок Координация §4](27.12.2_Блок_Координация.md).

---

### Hybrid Search

Поверх federated — гибридный поиск BM25 + dense с RRF (`orchestrator/search/hybrid_search.py`).

- `BM25Index` — in-memory, BSL-aware токенизация, стоп-слова (ru + en)
- `HybridSearchService` — sparse + injectable dense, RRF + weighted fusion
- Конфигурация: `SparseConfig` (k1, b), `HybridSearchConfig` (веса, fusion method)

См. подробности в [27.5 Поиск и сервисы](27.5_Поиск_и_сервисы.md).

---

### BSL Scorer

Reranker для BSL-кода (`orchestrator/search/bsl_scorer.py`):

- Определение типа объекта через `BSLObjectType` (модуль, процедура, функция, метод формы, запрос)
- Извлечение символов через `BSLSymbolType`
- `BSLAnalysisResult` агрегирует оценки
- `BSLScoreResult` возвращает reranked-позиции

Применяется поверх первичной выборки из Hybrid Search для повышения релевантности BSL-запросов.
