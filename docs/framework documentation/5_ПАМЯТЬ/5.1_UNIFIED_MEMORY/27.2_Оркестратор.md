# 27.2 Оркестратор памяти

Оркестратор — центральный координатор Unified Memory System. Он маршрутизирует данные между тремя бэкендами (AI Memory, Vector Memory, Skill Learning), управляет графом связей и выполняет федеративный поиск с агрегацией результатов.

Реализация: [`src/memory/orchestrator/`](src/memory/orchestrator/) — 8 модулей, 8 Core MCP tools + 25 дополнительных (P3+P4).

---

### MemoryCube

`MemoryCube` — унифицированный контейнер данных, независимый от целевого бэкенда. Используется для передачи записей между компонентами до конвертации в специфичный формат хранилища.

**Структура полей** (`orchestrator/memcube.py`):

| Секция | Поле | Тип | Описание |
|---|---|---|---|
| Identity | `id` | `str` | UnifiedID — `{type}:{source}:{uuid}` |
| | `content_type` | `ContentType` | fact/preference/rule/skill/code/observation |
| | `source` | `str` | Источник: session, skill, system, import |
| | `content` | `str` | Основной текст записи |
| Scoring | `confidence` | `float` | 0.0 — 1.0 |
| | `quality_score` | `float` | Внутренний показатель качества |
| | `importance` | `float` | 0.0 — 0.95 |
| | `access_count` | `int` | Трекинг использований |
| Temporal | `created_at` | `datetime` | Создание |
| | `updated_at` | `datetime` | Последнее обновление |
| | `last_accessed` | `datetime` | Последнее чтение |
| Observations | `tags` | `list[str]` | Семантические теги |
| | `metadata` | `dict` | Произвольные метаданные |

**ContentType enum:**

```python
class ContentType(str, Enum):
    FACT = "fact"
    PREFERENCE = "preference"
    RULE = "rule"
    SKILL = "skill"
    CODE = "code"
    OBSERVATION = "observation"
```

**Конвертеры** в формат бэкендов:

- `to_ai_memory_row()` — запись для SQLite (`important_messages` таблица)
- `to_vector_memory_payload()` — Qdrant payload + вектор эмбеддингов
- `to_skill_learning_record()` — JSONL-запись с confidence и tags

### Memory Router

Модуль классификации и автоматической маршрутизации (`orchestrator/memory_router.py`). Использует regex-based middleware на фазе 0 в `route()` для определения типа контента до выбора backend'а.

**Правила маршрутизации** (стратегия по умолчанию):

| ContentType | Целевой бэкенд | Сигналы (примеры) |
|---|---|---|
| FACT | ai_memory | "X равно Y", "согласно", "установлено что" |
| PREFERENCE | ai_memory | "предпочитаю", "люблю", "предпочтение" |
| RULE | vector_memory | "всегда", "никогда", "обязательно", "запрещено" |
| SKILL | skill_learning | "навык", "процедура", "алгоритм" |
| CODE | vector_memory | наличие `def `, `class `, `function`, `import` |
| OBSERVATION | ai_memory | fallback по умолчанию |

> Источник правды: `CONTENT_TYPE_TARGETS` в [memory_router.py:267](src/memory/orchestrator/memory_router.py#L267). RULE/CODE → `vector_memory` (семантический поиск по паттернам), FACT/PREFERENCE/OBSERVATION → `ai_memory` (SQLite с категориями/FTS).

**ClassificationResult:**

```python
@dataclass
class ClassificationResult:
    content_type: ContentType
    confidence: float       # 0.0 - 1.0
    signals: list[str]      # Совпавшие паттерны
```

Публичный API: `classify_content(text: str) -> ClassificationResult` — можно использовать из внешних компонентов.

### Link Registry

Граф связей на SQLite adjacency list (`orchestrator/link_registry.py`). Индексы на `source_id`, `target_id`, `relation_type`.

**6 типов связей:**

| Тип | Описание |
|---|---|
| `based_on` | Запись построена на основе другой (паттерн на основе документации) |
| `supports` | Запись подтверждает/подкрепляет другую |
| `contradicts` | Записи противоречат друг другу |
| `extends` | Расширение или дополнение существующей записи |
| `derives_from` | Факт выведен из другого факта |
| `session_context` | Связь в рамках одной сессии |

API: `create_link(source_id, target_id, relation_type, metadata)`, `get_related(node_id, types=[...], depth=1)`, `get_neighbors(node_id)`.

### Unified Search (RRF)

Федеративный поиск через Reciprocal Rank Fusion (`orchestrator/unified_search.py`).

**Формула RRF:**

```
RRF(D) = Σ_s  source_weight_s × (1 / (k + rank_s(D)))

Итог: score(D) = 0.60 × normalize(RRF(D)) + 0.40 × quality_signal(D)

Параметры (SearchOptions):
  k = 60                       (k-parameter, сглаживание)
  rrf_enabled = True           (toggle, fallback: legacy ScoreNormalizer)
  rrf_source_weights = {
      "ai_memory": 1.0,
      "vector_memory": 0.9,
      "skill_learning": 0.7,
  }
```

**RRFMerger** нормализует score'ы к шкале `[0, 1]` после суммирования.

**Пример использования:**

```python
from memory.orchestrator.unified_search import UnifiedSearch, SearchOptions

search = UnifiedSearch(orchestrator=orc)
results = await search.query(
    text="конфигурация circuit breaker",
    options=SearchOptions(
        limit=10,
        rrf_enabled=True,
        rrf_k=60,
        rrf_source_weights={"ai_memory": 1.0, "vector_memory": 0.8},
    ),
)

for r in results:
    print(r.unified_id, r.score, r.source_backend)
```

### Propagation Engine

BFS-пропагация изменений confidence через граф связей (`orchestrator/propagation_engine.py`). Заменил Neo4j на SQL через `LinkRegistry`.

**Затухание:**

```
new_confidence = old_confidence
               × time_decay(Δt)
               × distance_decay(depth)
               × sign(relation_type)

time_decay(Δt)      = exp(-λ_time × Δt_days)
distance_decay(d)   = 1 / (1 + depth × α)
sign(contradicts)   = -1
sign(supports|extends|based_on|derives_from) = +1
```

**Rate limiting** (конфигурируется):

| Параметр | Дефолт | Назначение |
|---|---|---|
| `max_depth` | 3 | Максимальная глубина BFS |
| `max_entities` | 100 | Сущностей за один запуск |
| `delta_threshold` | 0.01 | Минимальное изменение для продолжения |
| `rate_limit_per_hour` | 60 | Защита от каскадов |

Background dispatch через `asyncio.create_task`, не блокирует основные операции.

### Hybrid Search

Поверх federated — гибридный поиск BM25 + dense с RRF (`orchestrator/search/hybrid_search.py`).

- `BM25Index` — in-memory, BSL-aware токенизация, стоп-слова (ru + en)
- `HybridSearchService` — sparse + injectable dense, RRF + weighted fusion
- Конфигурация: `SparseConfig` (k1, b), `HybridSearchConfig` (веса, fusion method)

См. подробности в [27.5 Поиск и сервисы](27.5_Поиск_и_сервисы.md).

### BSL Scorer

Reranker для BSL-кода (`orchestrator/search/bsl_scorer.py`):

- Определение типа объекта через `BSLObjectType` (модуль, процедура, функция, метод формы, запрос)
- Извлечение символов через `BSLSymbolType`
- `BSLAnalysisResult` агрегирует оценки
- `BSLScoreResult` возвращает reranked-позиции

Применяется поверх первичной выборки из Hybrid Search для повышения релевантности BSL-запросов.
