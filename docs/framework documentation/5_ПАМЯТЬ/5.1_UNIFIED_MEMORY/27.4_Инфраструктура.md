# 27.4 Инфраструктура

Слой инфраструктуры [`src/memory/infrastructure/`](src/memory/infrastructure/) предоставляет переиспользуемые примитивы для resilience, кэширования, метрик и событийной модели. Внешние зависимости (Redis, Prometheus) заменены in-process решениями на базе asyncio и стандартной библиотеки.

---

## Resilience

Примитивы для обработки сбоев при взаимодействии с внешними системами.

### Retry + Backoff

Декоратор retry (фаза P0, [`retry.py`](src/memory/infrastructure/retry.py)) с экспоненциальной задержкой и jitter'ом.

```python
from memory.infrastructure.retry import retry

@retry(max_attempts=3, base_delay=0.5, max_delay=10.0,
       exceptions=(ConnectionError, TimeoutError))
async def fetch_external_data(url: str) -> dict:
    ...
```

### Timeout

Обёртки для ограничения времени выполнения async операций (фаза P0, [`timeout.py`](src/memory/infrastructure/timeout.py)).

```python
from memory.infrastructure.timeout import timeout

@timeout(seconds=5.0)
async def slow_query():
    ...
```

### Circuit Breaker

Паттерн "предохранитель" с 3 состояниями (фаза P1, [`circuit_breaker.py`](src/memory/infrastructure/circuit_breaker.py)). Переиспользован из `src/shared/llm_rotation/circuit_breaker.py`, убрана Redis-зависимость.

**Состояния:**

| State | Условие входа | Поведение |
|---|---|---|
| `Closed` | Штатная работа | Запросы пропускаются. При `failure_threshold` подряд — переход в `Open` |
| `Open` | Превышен порог ошибок | Все запросы отклоняются немедленно. Через `reset_timeout` → `HalfOpen` |
| `HalfOpen` | Таймаут истёк | Пропускается 1 тестовый запрос. Успех → `Closed`, ошибка → `Open` |

**CircuitBreakerRegistry** — управление несколькими CB (например, отдельный CB на каждый внешний сервис):

```python
from memory.infrastructure.circuit_breaker import CircuitBreakerRegistry

registry = CircuitBreakerRegistry()
cb = registry.get_or_create("qdrant", failure_threshold=5, reset_timeout=30)

if cb.is_open:
    raise ServiceUnavailableError()
try:
    result = await external_call()
    cb.record_success()
except Exception:
    cb.record_failure()
    raise
```

## Кэширование и метрики

### LRU Cache

In-process LRU-кэш (фаза P2, [`cache.py`](src/memory/infrastructure/cache.py)) на `OrderedDict` с TTL и лимитом размера. **Замена Redis** для single-process сценариев.

```python
from memory.infrastructure.cache import LRUCache

cache = LRUCache(max_size=1000, default_ttl=300)  # 1000 записей, 5 минут
await cache.set("key", value)
data = await cache.get("key")
print(cache.stats())   # hits, misses, evictions, size
```

### Metrics Collector

Счётчики/gauges/таймеры в памяти (фаза P2, [`metrics.py`](src/memory/infrastructure/metrics.py)). **Замена Prometheus**, экспорт в JSON.

```python
from memory.infrastructure.metrics import get_metrics

m = get_metrics()
m.increment("search.requests_total", labels={"backend": "qdrant"})
m.gauge("cache.size", 1024)
with m.timer("search.duration_seconds"):
    await search_call()

m.export_json()   # Выгрузка для лога/дашборда
```

Глобальный singleton `get_metrics()` — единая точка для всех подсистем.

## Realtime

Каноническое описание EventBus/EventStore/SubscriptionManager (API, wildcard-матчинг, hot/cold ротация, heartbeat) — см. [27.12.5 Блок Отдельно](27.12.5_Блок_Отдельно.md), часть 2 «Event Store + EventBus». Кратко: `EventBus` ([`event_bus.py`](src/memory/infrastructure/event_bus.py)) — async pub/sub на `asyncio.Queue` с wildcard-подписками и drop-oldest backpressure; `EventStore` ([`event_store.py`](src/memory/infrastructure/event_store.py)) — JSONL hot buffer + SQLite WAL cold storage; `SubscriptionManager` ([`subscription_manager.py`](src/memory/infrastructure/subscription_manager.py)) — heartbeat-трекинг подписок для polling-клиентов (MCP).

Рантайм-статистика шины — датакласс **`EventBusStats`** (`published_count`, `subscriber_count`, `dropped_count`);
ненулевой `dropped_count` = сработал drop-oldest backpressure (подписчик не успевает разбирать очередь).

### ConflictResolver

Разрешение конфликтов при конкурентных обновлениях (фаза P3, [`conflict_resolver.py`](src/memory/infrastructure/conflict_resolver.py)). 4 стратегии с field-level разрешением.

Значения перечисления **`ConflictStrategy`** (4 стратегии, field-level разрешение):

| Стратегия | Описание | Использование |
|---|---|---|
| `LAST_WRITE_WINS` | побеждает запись с максимальным timestamp | Простые счётчики, гауджи |
| `SOURCE_PRIORITY` | приоритет источника (ranked ordering) | `["system", "user", "auto"]` — индекс = ранг |
| `MERGE_FIELDS` | объединение непересекающихся полей; в пересечении **безусловно побеждает `incoming`** (timestamps и `source_priorities` НЕ учитываются), каждое расхождение пишется в `conflicts` | Обогащение записей |
| `MANUAL` | конфликт сохраняется для ручного разбора (`resolved=False`) | Критичные данные |

Модели результата: **`ConflictRecord`** — один field-level конфликт (`entity_id`, `field_name`,
`current_value`/`incoming_value`, парные `*_timestamp` и `*_source`); **`ConflictResult`** — итог
(`resolved`, `strategy_used`, `resolved_value`, список `conflicts`, `metadata`).

Служебные ключи входных словарей: `_entity_id`, `_timestamp`, `_source` — они **переносятся в результат**,
а не отбрасываются: при `MERGE_FIELDS` — из `incoming` (если он их несёт), при `LAST_WRITE_WINS`/`SOURCE_PRIORITY` —
от победившей стороны; при `MANUAL` результата нет вовсе (`resolved_value=None`).

⚠ `resolved` означает «разрешено без расхождений» (`len(conflicts) == 0`), а не «слияние выполнено»:
при MERGE_FIELDS с **расходящимися** значениями пересекающихся полей результат всегда `resolved=False`
+ непустой `conflicts` (совпадающие значения конфликта не создают).
`source_priorities` работает только в стратегии `SOURCE_PRIORITY`.

```python
from memory.infrastructure.conflict_resolver import ConflictResolver, ConflictStrategy

resolver = ConflictResolver(default_strategy=ConflictStrategy.MERGE_FIELDS)
result = resolver.resolve(
    current={"name": "Alice", "age": 30, "_source": "user"},
    incoming={"age": 31, "city": "Moscow", "_source": "system"},
)
# result.resolved          -> False  (поле "age" разошлось)
# result.resolved_value    -> {"name": "Alice", "age": 31, "_source": "system", "city": "Moscow"}
# result.conflicts         -> [ConflictRecord(field_name="age", current_value=30, incoming_value=31, ...)]
# result.metadata          -> {"entity_id": "unknown", "conflict_count": 1}
```

## Стратегия замещения внешних зависимостей

| Компонент | Было | Стало | Обоснование |
|---|---|---|---|
| Time-series | TimescaleDB hypertable | SQLite WAL | Нет инфраструктуры, проще деплой, single-process |
| Граф | Neo4j | SQLite adjacency list | SQL через LinkRegistry достаточен, pure-Python алгоритмы |
| Кэш/очереди | Redis | LRU Cache + asyncio.Queue | In-process, нулевая latency, нет TCP-overhead |
| Метрики | Prometheus exporter | in-memory counters/gauges | Нет Prometheus-инфраструктуры, JSON export в лог |
| Pub/Sub | Redis Streams | asyncio.Queue + EventBus | Внутрипроцессная шина, проще Wildcards |
