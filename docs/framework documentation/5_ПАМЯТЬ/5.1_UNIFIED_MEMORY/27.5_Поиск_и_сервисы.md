## Hybrid Search

Комбинация sparse (BM25) и dense (инжектируемый провайдер эмбеддингов) с RRF + weighted fusion ([`orchestrator/search/hybrid_search.py`](../../../../src/memory/orchestrator/search/hybrid_search.py)).

**Компоненты:**

- `BM25Index` — in-memory индекс с BSL-aware токенизацией, стоп-словами ru+en, настраиваемыми k1/b
- `HybridSearchService` — orchestrator sparse + dense, выбор стратегии fusion
- `SearchConfig`, `SparseConfig`, `HybridSearchConfig` — конфигурации ([`orchestrator/search/config.py`](../../../../src/memory/orchestrator/search/config.py): `FusionMethod`/`VectorType` enums, `SparseConfig` BM25-параметры, `HybridSearchConfig`, `BSLScorerConfig`)

```python
from memory.orchestrator.search.hybrid_search import (
    BM25Index, HybridSearchService, HybridSearchConfig,
)

bm25 = BM25Index(k1=1.5, b=0.75)
config = HybridSearchConfig(
    fusion_method="rrf",  # или "weighted"
    weights={"sparse": 0.6, "dense": 0.4},
)
service = HybridSearchService(sparse=bm25, dense=dense_provider, config=config)

results = await service.search(query="обработка документов", limit=10)
```

## BSL Scorer

Reranker для BSL-кода ([`orchestrator/search/bsl_scorer.py`](../../../../src/memory/orchestrator/search/bsl_scorer.py)).

**Возможности:**

- Определение типа объекта: `BSLObjectType` (модуль, процедура, функция, менеджер, форма, запрос)
- Извлечение символов: `BSLSymbolType` (идентификатор, ключевое слово, литерал)
- Агрегированный результат: `BSLAnalysisResult`, `BSLScoreResult`

```python
from memory.orchestrator.search.bsl_scorer import BSLScorer

scorer = BSLScorer()
ranked = scorer.rerank(
    query="Функция ОбработкаЗаказа",
    candidates=initial_results,
    boost_types=[BSLObjectType.FUNCTION, BSLObjectType.PROCEDURE],
)
```

Применяется поверх первичной выборки из Hybrid Search для повышения релевантности BSL-запросов.

## Audit Service

Append-only журнал событий на JSONL + in-memory buffer ([`ai_memory/services/audit_service.py`](../../../../src/memory/ai_memory/services/audit_service.py)).

| Характеристика | Значение |
|---|---|
| Хранилище | JSONL (одна запись — одна строка) |
| Буферизация | In-memory с periodic flush |
| Immediate persist | Для DELETE, ROLLBACK и других деструктивных действий |
| Deduplication | В `get_errors()` / `query()` |

```python
from memory.ai_memory.services.audit_service import AuditService

audit = AuditService(log_path="data/audit.jsonl")
await audit.log(action="CREATE", entity="memory", entity_id="mem_123",
                actor="system", metadata={"source": "api"})

# DELETE → immediate persist без буферизации
await audit.log(action="DELETE", entity="memory", entity_id="mem_456")

# Запрос с дедупликацией
entries = await audit.query(action="DELETE", deduplicate=True)
```

## Versioning Service

Полная история записей с diff и rollback ([`ai_memory/services/versioning_service.py`](../../../../src/memory/ai_memory/services/versioning_service.py)).

- Хранение: JSONL + in-memory cache под `asyncio.Lock`
- Diff между любыми двумя версиями
- Rollback к указанной версии
- Cleanup старых версий по политике (keep_last N)

```python
from memory.ai_memory.services.versioning_service import VersioningService

vs = VersioningService(storage_path="data/versions.jsonl")
v_id = await vs.create_version(entity_id="mem_123", data={"text": "v1"})

# История
history = await vs.get_history(entity_id="mem_123")

# Diff
delta = await vs.diff(entity_id="mem_123", from_version=1, to_version=3)

# Откат + cleanup
await vs.rollback(entity_id="mem_123", target_version=2)
await vs.cleanup(entity_id="mem_123", keep_last=10)
```

## TTL Service

Управление временем жизни записей с фоновым cleanup ([`ai_memory/services/ttl_service.py`](../../../../src/memory/ai_memory/services/ttl_service.py)).

Канонические пресеты `TTLPolicy` (секунды/сроки) и cleanup-интервал — см. [27.12.6 Блок Governance §1](27.12.6_Блок_Governance.md).

**API:**

```python
from memory.ai_memory.services.ttl_service import TTLService, TTLPolicy

ttl = TTLService(storage_path=Path("data/ttl.jsonl"), auto_cleanup_interval_seconds=3600)
entry = await ttl.register(entity_id="mem_123", policy=TTLPolicy.MEDIUM)
await ttl.extend_ttl(entity_id="mem_123", seconds=86400)
await ttl.record_access(entity_id="mem_123")   # Инкремент access_count
expired_ids = await ttl.cleanup_expired()
```

Background cleanup запускается через `asyncio.create_task` в `start_cleanup_task()`.

## ForgetGate Service

Селективное забывание с 4 стратегиями ([`vector_memory/services/forgetgate_service.py`](../../../../src/memory/vector_memory/services/forgetgate_service.py)). **SurpriseCalculator** оценивает новизну записи через IDF тегов (редкие теги → высокая неожиданность).

Канонические стратегии, пороги действий (`ForgetAction`) и веса composite-стратегии — см. [27.12.6 Блок Governance §6.1](27.12.6_Блок_Governance.md).

```python
from memory.vector_memory.services.forgetgate_service import (
    ForgetGateService, ForgetStrategy,
)

fg = ForgetGateService(strategy=ForgetStrategy.COMPOSITE)

# Dry run: только оценка, без изменений
actions = await fg.evaluate(memory_ids=["m1", "m2", "m3"], dry_run=True)

# Реальное применение
results = await fg.execute(actions, apply_callback=my_callback)
```

## Graph Algorithms

Pure-Python реализация без `networkx` ([`vector_memory/graph/algorithms.py`](../../../../src/memory/vector_memory/graph/algorithms.py)).

| Алгоритм | Назначение | Сложность |
|---|---|---|
| Dijkstra shortest path | Кратчайший путь между узлами | O(E + V log V) |
| PageRank | Важность узлов через случайное блуждание | O(iter × E) |
| Degree centrality | Важность по числу связей | O(V) |
| Connected components | Компоненты связности | O(V + E) |
| Label propagation | Кластеризация сообществ | O(iter × E) |

```python
from memory.vector_memory.graph.algorithms import GraphAlgorithms

algo = GraphAlgorithms(graph=my_graph)
path, distance = algo.dijkstra(source="n_a", target="n_b")
ranks = algo.pagerank(damping=0.85, iterations=100)
components = algo.connected_components()
communities = algo.label_propagation(max_iter=50)
```

## Relation Types

30 предопределённых типов связей ([`vector_memory/graph/relation_types.py`](../../../../src/memory/vector_memory/graph/relation_types.py)).

**Категории:**

| Категория | Примеры |
|---|---|
| Structural | `contains`, `depends_on`, `imports`, `inherits`, `composed_of` |
| Semantic | `similar_to`, `related_to`, `contradicts`, `extends`, `refines`, `synonym_of` |
| Temporal | `precedes`, `follows`, `concurrent_with`, `replaces`, `supersedes` |
| BSL-specific | `calls_function`, `uses_variable`, `modifies_form`, `queries_table`, `subscribes_to_event` |

**RelationRegistry** с индексами по source / target / type и auto-inverse:

```python
from memory.vector_memory.graph.relation_types import (
    RelationRegistry, RelationType,
)

registry = RelationRegistry()
registry.add_relation(
    source="module.orders",
    target="function.calc_total",
    relation_type=RelationType.CONTAINS,
)
# Автоматически создаётся обратная связь:
#   function.calc_total -[CONTAINED_BY]-> module.orders

outgoing = registry.get_by_source("module.orders")
incoming = registry.get_by_target("function.calc_total")
by_type  = registry.get_by_type(RelationType.DEPENDS_ON)
```
