## EventBus

Асинхронная pub/sub шина ([`infrastructure/event_bus.py`](src/memory/infrastructure/event_bus.py)) на `asyncio.Queue`. См. подробности в [27.4 Инфраструктура](27.4_Инфраструктура.md#realtime).

**Краткая справка:**

| Wildcard | Матчинг | Пример |
|---|---|---|
| `*` | один уровень | `memory.*` → `memory.created`, `memory.deleted` |
| `**` | ноль или более уровней | `memory.**` → `memory.node.child.updated` |
| точный | дословно | `memory.created` |

Backpressure: drop oldest при переполнении очереди подписчика. Singleton: `get_event_bus()` / `reset_event_bus()`.

## EventStore

Двухуровневое персистентное хранилище ([`infrastructure/event_store.py`](src/memory/infrastructure/event_store.py)):

- **Hot buffer (JSONL)** — быстрая append-запись, ~1ms на событие
- **Cold storage (SQLite WAL)** — индексированные запросы, long-term retention

**Механизмы сброса:**

| Механизм | Условие |
|---|---|
| Auto-flush | Достигнут threshold N записей в hot buffer |
| Periodic flush | Background-задача по таймеру |
| Manual flush | Вызов `store.flush()` перед shutdown |

**API:**

```python
store = EventStore(hot_path="events.jsonl", cold_db_path="events.db")
await store.initialize()

await store.append(event_type="memory.created", data={"id": "n1"})
events = await store.query(event_type="memory.*", start=t1, end=t2)

# Replay в callback (sync/async)
await store.replay(event_type="memory.**", callback=on_event, mode="async")
```

## ConflictResolver

4 стратегии разрешения конфликтов ([`infrastructure/conflict_resolver.py`](src/memory/infrastructure/conflict_resolver.py)).

| Стратегия | Алгоритм | Когда использовать |
|---|---|---|
| `LWW` | Побеждает запись с максимальным `timestamp` | Простые счётчики, gauges |
| `SOURCE_PRIORITY` | Ranked ordering источников | `[system < user < auto]` |
| `MERGE_FIELDS` | Field-level dict merge + LWW на конфликтах | Обогащение метаданных |
| `MANUAL` | Сохранение конфликта для разбора пользователем | Критичные данные |

**Field-level resolve** с детекцией конфликтов: каждое поле сравнивается отдельно, расхождения логируются.

## SubscriptionManager

In-memory управление подписками ([`infrastructure/subscription_manager.py`](src/memory/infrastructure/subscription_manager.py)) с heartbeat-трекингом.

**ManagedSubscription:** `subscription_id`, `client_id`, `pattern`, `last_heartbeat`, `events_buffer`.

| Метод | Назначение |
|---|---|
| `create(client_id, pattern)` | Создать подписку, вернуть `subscription_id` |
| `remove(subscription_id)` | Удалить подписку |
| `heartbeat(subscription_id)` | Обновить last_heartbeat |
| `get_events(subscription_id, limit)` | Забрать накопленные события |
| `list_subscriptions(client_id)` | Подписки клиента |

Per-client limits на число подписок. Stale-subscriptions удаляются автоматически при истечении heartbeat-таймаута.

## Интеграция с MemoryOrchestrator

EventBus и EventStore инициализируются в `MemoryOrchestrator.start()` и завершаются в `stop()`.

Внутренний helper `_emit_event()` выполняет fire-and-forget публикацию в bus и запись в store. Вызывается из `route_and_save()` и `create_link()`:

```python
class MemoryOrchestrator:
    async def start(self):
        self.event_bus = get_event_bus()
        await self.event_bus.start()
        self.event_store = EventStore(...)
        await self.event_store.initialize()

    def _emit_event(self, event_type: str, data: dict) -> None:
        # fire-and-forget: не блокирует write-операции
        asyncio.create_task(self.event_bus.publish(event_type, data))
        asyncio.create_task(self.event_store.append(event_type, data))

    async def route_and_save(self, content, ...):
        record_id = await self._save(content)
        self._emit_event("memory.saved", {"id": record_id, "type": ...})
        return record_id
```

Такой подход гарантирует минимальную задержку операций записи — публикация событий не блокирует основной путь.
