## vector-memory (8 tools)

Семантические паттерны в Qdrant коллекции `learned_patterns` (**4096d Qwen3-Embedding-8B** через TEI, не legacy 1024d E5 — Phase 8/9.1). Коллекция живая и растёт (**десятки паттернов**; фактическое число — прямой запрос к `learned_patterns` в Qdrant, не фиксируется в доке во избежание дрейфа). Паттерны хранятся в полной схеме (`pattern_id` + нормализованные поля); часть light-записей (`session_summary`) — episodic, намеренно не паттерны. Дедуп: content-hash + схлопывание семантических дублей кириллица/транслит (см. «Реализация» ниже).

| Tool | Аргументы | Возвращает |
|---|---|---|
| `save_pattern` | `pattern`, `confidence`, `metadata`, `tags` | `pattern_id`, статус |
| `search_patterns` | `query`, `confidence_min`, `limit`, `tags` | Массив паттернов с score |
| `apply_pattern` | `pattern_id`, `context`, `success` | Обновлённый `confidence`, счётчик применений |
| `get_pattern` | `pattern_id` | Полное описание паттерна |
| `delete_pattern` | `pattern_id` | Статус удаления |
| `decay_confidence` | `decay_rate`, `older_than_hours` | Количество обновлённых записей |
| `health_check` | — | Статус Qdrant, размер коллекции |
| `list_patterns` *(2026-06-02)* | `pattern_type?`, `min_confidence?`, `grep?`, `limit?`, `full?` | Просмотр **содержимого** паттернов без semantic-запроса (scroll-based, без embedding → нет cold-start) |

**Confidence system:** 0.0–1.0, **derived Beta(7,3) posterior** над time-decayed счётчиками succ/fail (prior → 0.70), НЕ legacy `confidence × exp(-0.05·days/30)`. Полный жизненный цикл (raise/decay/forget/revive, lazy decay-on-read, FSRS-lite) — [27.9 Confidence Lifecycle](27.9_Confidence_Lifecycle.md) / §22.

**Embedding fallback policy (roadmap 260509 §4.3, 2026-05-16):** все 7 инструментов требуют рабочий embedding provider (`pdf_framework.embeddings.get_embedding_engine`). При init failure `_get_embedding` **raises RuntimeError** по умолчанию — silent hash-based fallback (SHA-512 pseudo-vectors) более не активен, поскольку семантический поиск становился effectively random. Для offline/CI окружений где Qdrant + embedding model недоступны можно явно опт-инить legacy fallback через env `MEMORY_VECTOR_ALLOW_HASH_FALLBACK=1` — каждый embedding-вызов в этом режиме эмитит `[HASH-FALLBACK] ...` WARN log. Production deployments должны оставлять env пустым.

### Реализация (2026-06-01)

- **TEI-провайдер починен (фабрика).** `search_patterns`/`get_pattern`/`health_check` падали с `embedding provider unavailable`: фабрика `get_embedding_engine()` не имела ветки для провайдера `tei` (production-default Phase 8) → `ValueError: Unsupported embedding provider: tei`. Фикс: [`src/pdf_framework/embeddings/providers/tei.py`](../../../../src/pdf_framework/embeddings/providers/tei.py) `TEIEmbeddingEngine` (4096d Qwen3, QUERY_INSTRUCTION calibration как у hook'а, sub-batch ≤32) + ветка `tei` в фабрике. Чинит всех потребителей фабрики, не только MCP. ⚠ запущенный MCP-процесс требует `/mcp reconnect` ([[feedback-mcp-stale-code-reconnect]]). Verify: `search_patterns("RRF...")` → 4096d embed, корректные паттерны.
- **Дедуп коллекции.** [`scripts/dedupe_learned_patterns.py`](../../../../scripts/dedupe_learned_patterns.py) — content-hash дедуп (keep richest `pattern_id`-схему + oldest, sum succ/fail/application_count → recompute Beta(7,3) confidence) + opt-in exact-test-record removal. Dry-run by default, vector-inclusive атомарный backup перед delete (`data/memory/backups/`), `--restore` обратимость. Применено: **44→27** точек, `search_patterns` теперь без дублей (`calculate_rrf_score` ×4→1, `hybrid_rrf_search` ×3→1). 7 unit-тестов, code-verify PASS.
- **Просмотр содержимого (2026-06-02).** Два пути увидеть полный текст паттернов без semantic-запроса: CLI [`scripts/view_learned_patterns.py`](../../../../scripts/view_learned_patterns.py) (scroll + фильтры `--type`/`--min-confidence`/`--grep`/`--full`, читаемый Markdown-отчёт в UTF-8 → `data/reports/memory/learned_patterns_view.md`, `--stdout` через UTF-8-байты минуя cp1251-краш) + MCP-инструмент `list_patterns` (те же фильтры, scroll-based → без embedding cold-start, в отличие от `search_patterns`). Оба read-only, filter-эквивалентны, 5 unit-тестов, code-verify PASS. ⚠ MCP-инструмент требует `/mcp reconnect` после деплоя ([[feedback-mcp-stale-code-reconnect]]).
- **Нормализация light-записей (2026-06-02).** В коллекции было два payload-формата: **RICH** (`pattern_id` + полная схема LearnedPattern) и **LIGHT** (`original_id`/`category`/`importance` — мигрированные из memory-ai). При чтении через `_pattern_from_payload` light теряли `category` (→ default `code-convention`) и `importance` (→ default 0.5). [`scripts/normalize_light_patterns.py`](../../../../scripts/normalize_light_patterns.py) переписывает их в полную схему: `pattern_type` ← `CATEGORY_MAP[category]` (decision→architectural-principle, preference→workflow-pattern, bugfix→debugging-heuristic, reference/project→project-structure, feedback→workflow-pattern, implementation→code-convention), `confidence` ← `importance` (денорм), `tags` → реальный список, провенанс в `metadata`. **§22-честность:** по умолчанию `succ/fail=0` (без фабрикации evidence → effective стартует с prior 0.70); `--seed-importance N` опционально инжектит N синтетических наблюдений в пропорции importance. `session_summary` — episodic, не паттерн → **пропускается**. Dry-run by default, vector-inclusive backup, restorable. Применено: **16 нормализовано, 2 skipped**. 7 unit-тестов, code-verify PASS. ⚠ denorm `confidence` под §22 косметичен — ранжирование идёт по **effective** (из succ/fail). **Re-seed применён (`--seed-importance 5`, 2026-06-02):** importance теперь реально влияет на effective — спред `0.5→0.638 / 0.6→0.669 / 0.7→0.700 / 0.8→0.731` (был плоский 0.70). Слегка ниже теоретических из-за §22 lazy decay-on-read (счётчики `×exp(−0.05·Δdней/30)` при чтении, дрейф синтетического evidence к prior). Re-seed на уже-нормализованных записях требует restore бэкапа → renormalize (после нормализации `is_light=False`).

## Типовые сценарии

### 1. Federated search по всем подсистемам

```python
result = await mcp.call("memory-orchestrator", "unified_search", {
    "query": "настройка circuit breaker",
    "sources": ["ai_memory", "vector_memory", "skill_learning"],
    "limit": 10,
    "rrf_enabled": True
})
# result: агрегированные записи с source_backend и unified score
```

### 2. Сохранить факт с auto-classify

```python
result = await mcp.call("memory-orchestrator", "route_and_save", {
    "content": "Пользователь предпочитает PostgreSQL для production",
    "metadata": {"importance": 0.8, "session_id": "sess_001"}
})
# classifier определит PREFERENCE → маршрутизирует в ai_memory
```

### 3. Откатить версию записи

```python
# 1) история
history = await mcp.call("memory-orchestrator", "memory_version_history", {
    "entity_id": "mem_20260404_001", "limit": 5
})

# 2) diff между версиями 3 и 4
diff = await mcp.call("memory-orchestrator", "memory_version_compare", {
    "entity_id": "mem_20260404_001", "v1": 3, "v2": 4
})

# 3) откат
await mcp.call("memory-orchestrator", "memory_version_rollback", {
    "entity_id": "mem_20260404_001", "version": 3
})
```

### 4. Анализ графа связей

```python
# Контекст с соседями до depth=3
context = await mcp.call("memory-orchestrator", "get_full_context", {
    "entity_id": "skill:bsl-development", "depth": 3
})

# PageRank / communities для всего графа
analysis = await mcp.call("memory-orchestrator", "memory_graph_analyze", {
    "algorithm": "pagerank", "params": {"damping": 0.85, "iterations": 100}
})
```

### 5. Сессионный event replay

```python
# Подписка
sub = await mcp.call("memory-orchestrator", "memory_subscribe", {
    "pattern": "memory.**", "client_id": "agent_1"
})

# Забор накопленных событий
events = await mcp.call("memory-orchestrator", "memory_get_events", {
    "subscription_id": sub["subscription_id"], "limit": 50
})

# Replay за период
history = await mcp.call("memory-orchestrator", "memory_replay", {
    "event_type": "memory.saved",
    "from_ts": "2026-04-01T00:00:00Z",
    "to_ts":   "2026-04-04T23:59:59Z"
})
```
