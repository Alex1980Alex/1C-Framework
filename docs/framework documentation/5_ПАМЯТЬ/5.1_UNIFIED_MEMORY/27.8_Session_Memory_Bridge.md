# 27.8 Session Memory Bridge — автосохранение и federated recall

Фаза **P5** замыкает цикл памяти: Stop hook автоматически сохраняет контекст сессии в БД, а UserPromptSubmit hook ищет по всем источникам (SQLite + Qdrant + `.md`).

**Статус:** P5.1/P5.2/P5.4 DONE (2026-04-05); P5.3 Deferred Qdrant Indexing — **RETIRED 2026-06-12** (§26 Q1 ADR, см. ниже).

---

## Проблема

Текущая память работает **в одну сторону**:

- **Recall (P0.5):** `memory-first-hook` читает `.md` файлы → token overlap → stdout (ранее systemMessage, заменён 2026-04-05) ✅
- **Save:** Claude сам решает, когда записать в `.md` через `Write` tool ❌ (ненадёжно, забывает)

Результат: ценный контекст сессий (решения, ошибки, паттерны) **теряется** между сессиями.

---

## Решение: двухсторонний мост

- **SAVE (Stop hook)** автоматически извлекает контекст сессии и сохраняет в SQLite
- **RECALL (UserPromptSubmit hook)** ищет в SQLite FTS + Qdrant + `.md`, объединяет через RRF

---

## Архитектура

```
                SAVE (Stop hook)                            RECALL (UserPromptSubmit hook)
                =================                           ==============================

Session ends                                                User prompt arrives
      |                                                           |
      v                                                           v
SessionState + git diff                                    memory-first-hook
      |                                                           |
      v                                              +------------+-------------+
Extract: files changed, commits,                     |            |             |
skills, completed tasks                              v            v             v
      |                                      SQLite         Qdrant       .md files
      v                                    (token-overlap)  (semantic)   (+ wiki-stub)
      |                                      (0.30)         (0.35)       (0.15/0.20)
Format summary + calc importance                    |            |             |
      |                                             +------------+-------------+
      v                                                           |
SQLite INSERT (memory-ai)                                         v
 category = "session_summary"                               RRF merge (k=60)
 importance = 0.5-0.85 (auto)                                     |
 tags = extracted path tags                                       v
                                                       stdout (top-5 results)
                                                       with source attribution
```

## P5.1 Session Context Extractor (DONE)

**Файл:** [`.claude/hooks/session-memory-save.py`](.claude/hooks/session-memory-save.py)
**Триггер:** Stop hook (завершение сессии)
**Тесты:** 28 PASS (`tests/integration/test_memory_p5_session_save.py`)

### Источники данных

Все git-команды идут с префиксом `git -c core.quotepath=false` (кириллица в путях не эскейпится), `_run_git` timeout по умолчанию **2 s**, любой сбой → `[]`.

| Источник | Команда / файл | Что извлекает |
|---|---|---|
| Git changed | `git diff --name-only` | Изменённые файлы |
| Git staged | `git diff --cached --name-only` | Индексированные файлы |
| Git untracked | `git status --porcelain` (парсинг статус-кодов `??`/`A`/`M`/`AM`) | Новые/изменённые файлы |
| Git history | `git log --oneline --since='8 hours ago' --format=%s` (первые 5) | Коммиты за 8 часов |
| SessionState | `.claude/data/session-skills.json` | Активированные скиллы, session_id |
| Hook todos | `.claude/cache/hook-todos.json` | Завершённые задачи (`status == "completed"`) |

### Формат записи (SQLite)

```python
{
    "id": uuid4(),
    "content": (
        "Session 2026-04-04. Skills: memory-unified, framework-patterns. "
        "Changed 28 files. Commits: 3. Done: migrated P0-P4 Unified Memory."
    ),
    "importance": 0.78,                  # auto-calculated
    "category": "session_summary",
    "tags": '["memory","migration","P0-P4"]',
    "metadata": '{"session_id":"...","date":"2026-04-04","files":28,"commits":3}'
}
```

Хранилище: `data/memory_ai.db`, таблица `important_messages`, категория `session_summary`.

### Auto-importance формула

Каждое слагаемое **капается** по отдельности (`calculate_importance`):

```
importance = min(0.95,
    0.5
    + min(files   × 0.02, 0.20)     # изменённые файлы,   cap +0.20
    + min(commits × 0.05, 0.15)     # коммиты за 8 ч,     cap +0.15
    + min(skills  × 0.03, 0.10)     # активированные скиллы, cap +0.10
    + min(tasks   × 0.03, 0.10)     # завершённые задачи, cap +0.10
)
# base = 0.5; теоретический максимум суммы = 0.5+0.55 = 1.05 → срез на 0.95
```

### Auto-tagging правила

| Path pattern | Domain tag |
|---|---|
| `src/memory/` | memory |
| `src/bsl/` | bsl |
| `.claude/hooks/` | hooks |
| `.claude/skills/` | skills |
| `src/pdf_framework/` | pdf-framework |
| `tests/` | tests |
| `docs/` | docs |
| `tools/` | tools |

Базовые теги `{"session", <сегодня ISO-дата>}` + до 5 имён активированных скиллов + доменные теги по первому совпавшему path-префиксу. Максимум **10** тегов на запись (`sorted(tags)[:10]`).

### Meaningfulness gate

Перед сохранением `is_meaningful(ctx)` отсекает тривиальные сессии по **OR**-порогам: `files ≥ MIN_FILES=2` **или** `commits ≥ MIN_COMMITS=1` **или** `skills ≥ MIN_SKILLS=1`. Не прошло — `skipped-trivial`, запись не создаётся.

### Deduplication

- **Primary:** дедуп по `session_id` (если доступен в SessionState)
- **Fallback:** дедуп по `session_date` (если session_id null)
- **Механизм:** проверка `already_saved()` перед INSERT, пропуск при совпадении

### Timeout и graceful degradation

| Параметр | Значение |
|---|---|
| Timeout | 5 секунд (Stop hook constraint) |
| Graceful | `BaseHook.run()` → `exit(0)` при любой ошибке |
| Blocking | Не блокирует завершение сессии |
| Без LLM | Синхронные операции, без embedding |

**Отличие от плана:** JSONL append для skill-learning отложен — для session summaries достаточно SQLite (category=`session_summary`). Skill patterns нужны при EXECUTE-фазе, не при session save.

## P5.2 Federated Recall (DONE)

**Upgrade:** `memory-first-hook.py` — federated поиск вместо только `.md`.
**Файл:** [`.claude/hooks/memory-first-hook.py`](.claude/hooks/memory-first-hook.py)

> ⚠ Ниже — **актуальные** константы из кода (`LAYER_WEIGHTS`, `TOTAL_BUDGET`); первоначальный план P5.2 v2 имел 3 слоя с весами `0.40/0.35/0.25`. Полное описание read-пути — [27.3](27.3_Memory_First_Hook.md) и [27.12.4](27.12.4_Блок_Выход_Чтение.md).

### 4-layer архитектура (`LAYER_WEIGHTS`)

| Layer | Источник | Вес | Timeout | Обоснование |
|---|---|---|---|---|
| Layer 1 | SQLite `important_messages` (token-overlap, НЕ FTS) | 0.30 | 200 ms | Структурированные факты + tag-boost |
| Layer 2 | Qdrant semantic (`skill_library` + `learned_patterns`, hybrid RRF) | 0.35 | 2000 ms | Семантика + always-on lexical arms (опционально) |
| Layer 3 | `.md` files (`CLAUDE_MEMORY_DIR`) | 0.15 | 500 ms | Человекоредактируемые, всегда работает |
| Layer 4 | `search_wiki` (`docs/wiki/drafts/`) | 0.20 | 200 ms | **stub → `[]`** (реализация отложена) |

### Timeout budget (`TOTAL_BUDGET = 3.0 s`, hook hard-kill 5 s)

| Этап | Timeout | Fallback |
|---|---|---|
| SQLite | 200 ms | Skip layer |
| Qdrant (TEI+RRF) | 2000 ms | Skip layer / lexical-only |
| `.md` files | 500 ms | Skip layer |
| wiki (stub) | 200 ms | `[]` |

### RRF merge + source attribution

```
score(D) = Σ_layer  layer_weight × (1 / (k + rank_layer(D)))   k=60
```

В stdout каждый результат помечен источником:

```
[MEMORY CONTEXT] Top 5 results across 3 sources:

[SQLite|0.87] session_summary: "Migrated P0-P4 Unified Memory, 28 files, 3 commits"
[Qdrant|0.82] pattern: "BSL validation error handling"
[.md|0.74]    feedback: "Opus=Planner, Z.AI=Coder, never write code yourself"
[SQLite|0.69] preference: "Use PostgreSQL for production"
[Qdrant|0.61] pattern: "RRF fusion formula k=60"
```

### Embedding варианты для Qdrant

| Вариант | Latency | Сложность | Когда использовать |
|---|---|---|---|
| A: Pre-computed cache | <10 ms | SQLite таблица `query→vector` | Повторяющиеся запросы |
| B: Lightweight local model | ~100 ms | sentence-transformers локально | Всегда доступно |
| C: Skip Qdrant | 0 ms | Только SQLite + `.md` | Если модель/сервер недоступны |

## P5.3 Deferred Qdrant Indexing (RETIRED 2026-06-12)

> **ADR (roadmap 260612 P0.1):** контур ретирован в [`scripts/attic/deferred_qdrant_indexing.py`](../../../../scripts/attic/deferred_qdrant_indexing.py).
> Скрипт эмбеддил multilingual-E5 **1024d** и upsert'ил в `learned_patterns`, которая после
> Phase 8/9.1 — **4096d Qwen3**: запуск = dimension-mismatch или мусорные точки. Кроме того,
> эпизодика ≠ семантика (§26 Q1 ADR) — сanctioned-путь episodic→semantic теперь reflection
> (`scripts/reflect_memory.py`, §26 P2). Флаг `indexed_in_qdrant` приведён к реальности
> `scripts/memory_ai_backfill.py`: 18 точек живы (re-embedded 4096d при Qwen3-миграции,
> флаг сохранён), 15 мёртвых сброшены в 0. Новые строки в Qdrant не уходят — by design.

Исторический механизм (до ретирования): session summaries из P5.1 сохранялись в SQLite без embedding, P5.3 индексировал их в Qdrant партиями через CLI-скрипт (`--batch 25 -v`).

### Механизм

```
UserPromptSubmit hook:
  1. Recall (P5.2)
  2. Check: есть записи WHERE indexed_in_qdrant = 0?
  3. Если да → background task (threading, non-blocking):
     - batch до 10 записей
     - embedding через E5 local / FastEmbed
     - upsert в learned_patterns
     - UPDATE indexed_in_qdrant = 1
```

### Схема БД

```sql
ALTER TABLE important_messages
ADD COLUMN indexed_in_qdrant INTEGER DEFAULT 0;
```

## Прямой доступ к бэкендам (без MCP)

Хуки работают с бэкендами **напрямую**, без MCP-зависимостей — для скорости и независимости от запущенных серверов.

| Бэкенд | Путь | Способ записи из хука |
|---|---|---|
| SQLite (memory-ai) | `data/memory_ai.db` | `sqlite3.connect()` → `INSERT INTO important_messages` |
| JSONL (skill-learning) | `data/skill_learning/patterns.jsonl` | `json.dumps() + "\n"` → append |
| Qdrant (vector-memory) | `http://localhost:6333` | `qdrant_client.upsert()` (если доступен) |
| `.md` (auto-memory) | `~/.claude/projects/.../memory/` | Human-readable fallback |

**Преимущества:** нулевая зависимость от MCP серверов, прямое управление транзакциями, предсказуемая latency.

## Риски и митигации

| Риск | Вероятность | Митигация |
|---|---|---|
| Stop hook timeout (>5 s) для SQLite write | Низкая | SQLite WAL mode, pre-opened connection, короткие транзакции |
| Qdrant недоступен при recall | Средняя | Layer skip, `.md` fallback, auto-retry следующем запросе |
| Embedding latency в 2s budget | Средняя | Pre-computed cache (вариант A) или skip Qdrant (вариант C) |
| Дубликаты session summaries | Средняя | Dedup по `session_id` / `session_date` + content hash |
| SQLite lock contention (hook + MCP server) | Низкая | WAL mode, timeout 1s, retry с exponential backoff |
| Потеря контекста при crash | Низкая | SQLite ACID, WAL mode, atomic writes |
