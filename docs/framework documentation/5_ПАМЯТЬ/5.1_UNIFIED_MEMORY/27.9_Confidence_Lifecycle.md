# 27.9 Confidence Lifecycle — Auto-Raise & Auto-Decay (§22)

> **Статус:** P0–P4 DONE (2026-05-31, ADR-D4 accepted). Исследование (~20 репозиториев) + стратегия: [roadmap 260523 §22](../../../roadmap/260523_ROADMAP_FULL_DEV_LIFECYCLE_ANALYSIS.md).

## Проблема

L2-паттерны (`learned_patterns` в Qdrant) имели **наивный confidence**: `+0.02` при успехе, `−0.01` при провале. Это плоское накопление не отражало ни статистическую уверенность (5 успехов из 5 ≠ 50 из 50), ни забывание устаревших паттернов, ни разную скорость затухания «вечных» правил и одноразовых наблюдений.

## Решение: Beta-posterior над time-decayed счётчиками

Confidence теперь **производный** от Beta(7,3) posterior над затухающими счётчиками успехов/провалов. Чистые функции (без I/O) — [`src/memory/vector_memory/confidence.py`](../../../../src/memory/vector_memory/confidence.py).

### Формула

```
confidence = (PRIOR_SUCCESS + succ) / (PRIOR_SUCCESS + PRIOR_FAILURE + succ + fail)
           = (7 + succ) / (10 + succ + fail)
```

- **Prior Beta(7,3)** → стартовое значение **0.70** (read-time константа, не хранится).
- Хранятся **sufficient statistics**: `succ`, `fail` (float-счётчики), `last_decay_at`.
- `confidence` в payload — денормализованный кэш для Qdrant-фильтра; источник истины — счётчики.
- Без clamp: ratio всегда ∈ (0, 1).

### Жизненный цикл (raise → decay → forget → revive)

| Фаза | Механизм | Эффект |
|---|---|---|
| **Raise** (`apply_pattern`) | decay счётчиков `succ,fail *= exp(−rate·Δdays/30)` (floor <1e-6→0), затем `succ+=1` (success) / `fail+=1` (fail) | 5 чистых успехов: 0.70 → **0.80**; +1 провал → 0.75 |
| **Decay** (`decay_confidence` sweep) | затухают **счётчики**; confidence дрейфит к **prior 0.70**, НЕ к 0 | простой → де-промоушен, не обнуление |
| **Forget** (§22 P3) | invalidate-not-delete: флаг `expired_at` вместо удаления | паттерн скрыт из выдачи, но восстановим |
| **Revive** (§22 P3) | любой `apply` снимает `expired_at` | recurrence оживляет архивный паттерн |

### P2 — Lazy decay-on-read (`b05d1081d`)

`confidence.payload_effective_confidence()` пересчитывает confidence **при чтении** из хранимых счётчиков (без записи). Применяется в:
- `search_patterns` — drop server-prefilter + client-side фильтр/ранжирование по effective;
- `get_pattern` — отдаёт `effective_confidence`;
- `WikiPromoter` — gate на effective.

Результат: stale-паттерны ранжируются ниже **автоматически**, без фонового sweep'а.

### P4 — FSRS-lite stability (`942f55fa0`)

```
stability_adjusted_rate(base, application_count) = base / (1 + 0.3·ln(1 + count))
```

Established-паттерны (высокий lifetime `application_count`) затухают **медленнее** (use-modulated λ). Применён в `_resolve_state` (все decay-пути) + `decay_confidence` sweep. Без нового поля. Полная FSRS power-curve — deferred.

### P3 — Forgetting + revive (`2aa6fcb21`)

`confidence.should_archive(payload)` = одно из:
- **fail-breach:** `eff < 0.40` — применяется ко ВСЕМ типам, включая invariant (накопленные провалы → нет доверия);
- **staleness:** `idle > 180д AND eff < 0.75 AND NOT invariant` — время-архивация щадит вечные правила.

`is_invariant` = `architectural-principle` / `bsl-pattern` (вечные правила не архивируются по времени, только по провалам).

`decay_confidence` управляет `expired_at` в обе стороны: archive при `should_archive=True`, un-archive если архивный паттерн восстановил confidence. `WikiPromoter` пропускает archived.

### Legacy-миграция (lazy, on-read)

Точки без полей `succ`/`fail` мигрируются при первом чтении: `succ = conf·n, fail = (1−conf)·n` (n = `application_count`). Полное отсутствие полей → prior 0.70.

## Запись в Qdrant

[`src/memory/vector_memory/reinforce.py`](../../../../src/memory/vector_memory/reinforce.py):`reinforce_pattern()` — тонкая fail-soft обёртка над `apply_to_payload`: retrieve point → Beta-update → `set_payload`. Вся Qdrant-I/O изолирована здесь, математика — в `confidence.py`.

Stop-hook reinforcement loop — [`.claude/hooks/shared/pattern_reinforce.py`](../../../../.claude/hooks/shared/pattern_reinforce.py):`reinforce_session()`: на завершении сессии усиливает surfaced-паттерны по success-эвристике (commit OR task done), с per-session idempotency + per-pattern cooldown 6h + cap 50.

## Логирование жизненного цикла (§22.4)

Все confidence-мутации трассируются в `.claude/cache/confidence-lifecycle.log` (JSONL) через общий модуль [`src/memory/vector_memory/lifecycle_log.py`](../../../../src/memory/vector_memory/lifecycle_log.py):`log_event()`.

| Событие | Источник | Поля |
|---|---|---|
| `reinforce` | `reinforce.py` | pattern_id, success, old→new confidence, succ, fail, application_count |
| `reinforce_miss` | `reinforce.py` | pattern_id (point not found) |
| `reinforce_error` | `reinforce.py` | pattern_id, error (truncated 160) |
| `session` | Stop-hook `pattern_reinforce.py` | applied, skipped, errors, candidates |
| `session_error` | Stop-hook | error |
| `apply` / `decay_sweep` / `save` / `delete` | MCP `server.py` handlers | per-event метаданные |
| `server_start` | MCP `server.py` `main()` | pid, collection (делает `/mcp reconnect` наблюдаемым) |

Свойства: fail-soft (никогда не ломает confidence-write), atomic size-rotation (mkstemp+`os.replace`, cap 2MB tail-keep), buffered append, opt-out `CONFIDENCE_LOG_DISABLE=1`, метаданные-only (без тел паттернов). **MCP-side события требуют `/mcp reconnect`** (persistent stdio-процесс держит старый код).

Анализ: `tail` + построчный `json.loads`.

## Конфигурация

| Env | Default | Назначение |
