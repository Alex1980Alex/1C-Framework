# 32.3 Storage и формат

Wiki — plain markdown файлы с **обязательным YAML frontmatter**. Структура каталогов и формат строго определены через [`docs/wiki/SCHEMA.md`](../../../wiki/SCHEMA.md) — этот файл является **каноническим контрактом**. Pre-commit hook `kb-lint` валидирует соответствие на каждый commit.

## Реальный формат: MemoryCube.to_wiki_page()

Каждый markdown-файл **обязан** начинаться с frontmatter. Фактический контракт (не гипотетический) генерируется методом `MemoryCube.to_wiki_page()` ([`src/memory/orchestrator/memcube.py:247-301`](../../../../src/memory/orchestrator/memcube.py)) — сериализует `MemoryCube` (унифицированный контейнер памяти, `src/memory/orchestrator/memcube.py:37`) в YAML-frontmatter + markdown body.

Пример живого файла (`docs/wiki/entities/bsl.md`, entity-страница, без `status`):

```yaml
---
confidence: 1.0
content_type: wiki
created_at: '2026-04-21T01:05:00.883993'
importance: 0.5
memory_type: semantic
metadata:
  entity_id: 08e456c2-d3bf-576f-bcae-b6d134e581eb
  entity_type: CONCEPT
  source_document_id: 7787e37b244e72bc
source: memory-ai
tags:
- entity
- concept
title: BSL
unified_id: semantic:memory-ai:b7356877-0698-40cd-9e5f-117df1329d23
updated_at: '2026-04-21T01:05:00.883994'
version: 1
---
```

Пример draft-файла (`docs/wiki/drafts/unnamed-pattern.md`, **с** `status`, curation-marker `untagged` при отсутствии тэгов):

```yaml
---
confidence: 0.8122223722388641
content_hash: adeaa0efccecfc32
content_type: wiki
memory_type: wiki
source: obsidian-vault
tags: '["2026-04-04", "create-hook", "session", "tools"]'
title: unnamed-pattern
unified_id: wiki:obsidian-vault:cfa51279-eae3-400d-9cf6-a7bba495f793
version: 1
status: draft
---
```

### Field definitions (из `memcube.py:259-282`)

| Field | Type | Required | Назначение |
|---|---|---|---|
| `unified_id` | string `{memory_type}:{source}:{cube_id}` | всегда | Составной строковый ключ (**не UUID v7** — cube_id внутри обычно UUID4, но полное поле — составное); уникальный идентификатор |
| `memory_type` | enum (`episodic`/`semantic`/`learning`/`wiki`/…) | всегда | Target memory type подсистемы-источника |
| `content_type` | enum `ContentType` (`fact`/`preference`/`rule`/`skill`/`code`/`observation`/`wiki`) | всегда | Авто-классифицированный тип контента |
| `content_hash` | string | если задан | Хэш контента, используется для idempotent-skip при повторном экспорте |
| `source` | string (напр. `memory-ai`, `obsidian-vault`) | всегда | Подсистема-источник cube |
| `created_at` / `updated_at` | ISO 8601 | всегда | `updated_at` ≥ `created_at` |
| `confidence` | float [0.0, 1.0] | всегда | Threshold для promotion (`>=0.8`, см. 32.6) |
| `importance` | float [0.0, 1.0] | всегда | Вес для ranking |
| `version` | int | всегда | Версия cube |
| `status` | enum `draft`/`active`/`archived` | **только** если писатель явно передал `status=` (drafts/-writers с 2026-07-05; entities/-экспорт его не передаёт) | kb-lint required field — поэтому entities/ (без `status`) исключены из lint через `ignore_patterns` |
| `title` | string | если задан | Human title |
| `tags` | list[str] | если `status` передан ИЛИ есть непустые `self.tags` | Non-empty гарантирован для linted (status'ed) страниц — fallback `["untagged"]` |
| `expires_at` | ISO 8601 | если задан | TTL для эфемерных cube |
| `metadata` | dict | если непусто | Произвольные доп.поля (напр. `entity_id`, `entity_type`, `source_document_id` для entity-страниц) |

**Различие entities/ vs drafts/:** entity-экспорт (`WikiExporter.export_entity`, `src/pdf_framework/indexing/wiki_exporter.py:227` — `cube.to_wiki_page()` без аргумента `status`) не несёт `status`/гарантированных `tags` и **lint-ignored** (`entities/**` в `.kblintrc.yml`). Draft-писатели (`wiki_promoter.py:165`, `memory_orchestrator.py:~2033`) вызывают `to_wiki_page(status="draft")` — эти страницы **линтуются** kb-lint (required `status`+`tags`).

### Body sections (реальные, из `memcube.py:289-298`)

```markdown
## What

{self.what}

## Why

{self.why}

## Where

{self.where}

## Learned

{self.learned}

## Content

{self.content}
```

Каждая секция — опциональна (эмитится только если поле непусто). Легаси-контракт `## Properties / ## Source chunks / ## Connections` (из более раннего дизайна) **не соответствует** текущему коду — не использовать как reference.

## Naming rules

Из [SCHEMA.md](../../../wiki/SCHEMA.md) §«Naming Rules»:

1. **Format:** `lowercase-kebab-case.md`
2. **Maximum length:** 80 characters (excluding `.md`)
3. **Allowed:** lowercase letters (`a-z`), digits (`0-9`), hyphens (`-`)
4. **Prohibited:** spaces, underscores, special characters, uppercase
5. **No consecutive hyphens** (`foo--bar` → `foo-bar`)
6. **No leading/trailing hyphens**
7. **Cyrillic stems:** allowed только в hub pages (через kb-lint per-page exception); `entities/` slug'и должны быть ASCII

`WikiExporter._sanitize_filename()` implementation:

```python
@staticmethod
def _sanitize_filename(name: str) -> str:
    """Convert arbitrary entity name → safe filename slug."""
    s = name.lower()
    s = re.sub(r"[^a-z0-9]+", "-", s)        # non-alnum → hyphen
    s = re.sub(r"-+", "-", s)                # consecutive hyphens
    s = s.strip("-")                          # leading/trailing
    return s[:80] or "unnamed"
```

Тесты: `TestSanitizeFilename` (4 теста) покрывают basic, special chars, long names (>80), consecutive hyphens.

## Cross-reference syntax

### Wiki-links (Obsidian-compatible)

```markdown
См. [[provider-pattern]] для деталей.
Также: [[strategy-pattern|стратегии]].          ← с display text
```

Регулярка для парсинга (используется `ReverseSyncService._parse_wiki_page` и `WikiSearchIndexer._extract_searchable_text`):

```python
re.findall(r"\[\[([^\]|]+)(?:\|[^\]]+)?\]\]", body)
```

Захватывает только target (`provider-pattern`, `strategy-pattern`). Display text после `|` отбрасывается при извлечении relations, но используется при rendering для search/UI.

### Bidirectional linking rule

Из SCHEMA: «When Page A links to Page B, Page B must include Page A in `related`.»

Audit-paтерн (можно автоматизировать):

```bash
# Find all pages X linking to Y where Y doesn't link back to X
.venv/Scripts/python.exe scripts/kb_lint_ci.py 2>&1 | grep "Broken wiki-link\|orphan"
```

`_index.md` служит **central link registry** — все hub-страницы должны быть в нём перечислены.

### Markdown links (для внешних refs)

Для ссылок вне wiki — обычный markdown `[label](path)`:

```markdown
См. [CLAUDE.md](../../../../CLAUDE.md) §Memory для контекста.
Roadmap: [260514_ROADMAP_WIKI_PROMOTION_GAP.md](../../../roadmap/260514_ROADMAP_WIKI_PROMOTION_GAP.md).
```

`kb-lint` не валидирует внешние markdown links (только wiki-links). Битые внешние ссылки — отдельная проверка через `markdownlint-cli2` (другой pre-commit hook, scope `^docs/wiki/.*\.md$`).

## Page lifecycle (state machine)

```
   ┌────────┐     promote     ┌──────────┐    canonize    ┌──────────┐
   │ L2     │ ─────────────▶  │ L5 draft │ ────────────▶  │ L3       │
   │ pattern│  WikiPromoter   │ docs/    │  human review  │ active   │
   │ Qdrant │                 │ wiki/    │  + manual mv   │ entities/│
   └────────┘                 │ drafts/  │                └────┬─────┘
                              └──────────┘                      │
                                                                │ deprecate
                                                                │ (manual)
                                                                ▼
                                                          ┌──────────┐
                                                          │ archived │
                                                          │ archive/ │
                                                          │ <date>/  │
                                                          └──────────┘
```

| Transition | Trigger | Required action |
|---|---|---|
| L2 → L5 | `application_count ≥ 5 AND confidence ≥ 0.8` | Auto через `WikiPromoter.scan_and_promote()` (вызывается из Stop hook) |
| L5 → L3 | Human review | Manual: проверить frontmatter, наполнить body, `mv drafts/x.md entities/x.md`, set `status: active` |
| L3 → archived | Outdated / superseded | Manual: `mv entities/x.md archive/YYYY-MM/x.md`, set `status: archived`, оставить `superseded_by` ссылку в `related` |

Auto-archive (cron / age-based) — пока не реализован, см. roadmap gap в [chapter 32.6](32.6_L2_L5_Promotion.md).

## Размер и performance

| Параметр | Текущее значение | Лимит |
|---|---|---|
| Файлов в `entities/` | 2 822 | — (нет верхнего лимита, но `export-all` time scales linearly) |
| Файлов в `patterns/` | 28 | — |
| Средний размер entity page | ~2-4 KB | — |
| `log.md` length | ~80 KB | 500 lines (trimmed by `session-memory-save`) |
| `wiki_pages_v1` points | 3 073 | — (некоторые pages дают >1 chunk при индексации) |
| Reindex full wiki | ~3-5 min | — |

Performance критическая точка — `export_all()` last full run: linear scan через все entities + idempotent skip для unchanged. Idempotency проверяется через SHA1 hash frontmatter+body **до** записи, что устраняет filesystem churn.
