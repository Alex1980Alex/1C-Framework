# 32.3 Storage и формат

Wiki — plain markdown файлы с **обязательным YAML frontmatter**. Структура каталогов и формат строго определены через [`docs/wiki/SCHEMA.md`](../../../wiki/SCHEMA.md) — этот файл является **каноническим контрактом**. Pre-commit hook `kb-lint` валидирует соответствие на каждый commit.

## YAML Frontmatter contract

Каждый markdown-файл **обязан** начинаться с frontmatter:

```yaml
---
unified_id: 019e1e30-10a7-7db1-9226-669a6066e1cf      # UUID v7 (time-sortable)
status: active                                          # active | draft | archived
tags:                                                   # min 1, recommended 3-5
  - meta
  - overview
related:                                                # bidirectional wiki-links
  - '[[_index]]'
  - '[[SCHEMA]]'
created_at: 2026-04-20T10:00:00+00:00                   # ISO 8601 with timezone
updated_at: 2026-05-14T23:30:00+00:00                   # touched on each edit
confidence: 0.85                                        # float [0.0, 1.0]
promoted_from: <optional-l2-pattern-id>                 # если promoted из L2
sources:                                                # optional citations
  - '[CLAUDE.md](../../../../CLAUDE.md)'
title: Framework Overview                               # human-readable title
---
```

Полный список обязательных полей — [`docs/wiki/SCHEMA.md`](../../../wiki/SCHEMA.md) §«YAML Frontmatter Schema».

### Field definitions

| Field | Type | Required | Назначение |
|---|---|---|---|
| `unified_id` | UUID v7 string | yes | Уникальный идентификатор, time-sortable; используется в LinkRegistry и cross-system ссылках (см. chapter 27.2) |
| `status` | enum | yes | `draft` (work-in-progress), `active` (canonical, indexed), `archived` (out of search but preserved) |
| `tags` | list[str] | yes | Categorization tags; min 1, recommended 3-5; используются в kb-lint ignore filters и в поиске |
| `related` | list[str] | yes | Bidirectional wiki-links через `[[target]]` syntax; max 10 per page |
| `created_at` | ISO 8601 | yes | Timezone-aware datetime |
| `updated_at` | ISO 8601 | yes | Должен ≥ `created_at`; auto-touched в `WikiExporter` при перезаписи |
| `confidence` | float | yes | Range `0.0-1.0`. Threshold для promotion (`>=0.8`) и для retrieval ranking |
| `promoted_from` | string | no | L2 pattern ID если страница promoted'нута из vector memory |
| `sources` | list[str] | no | Citations в формате `[label](url)` |
| `title` | string | no | Human title (если отличается от filename slug); используется в search snippets |

### kb-lint enforcement

[`docs/wiki/.kblintrc.yml`](../../../wiki/.kblintrc.yml) определяет required fields и validation rules. Pre-commit hook вызывает [`scripts/kb_lint_ci.py`](../../../../scripts/kb_lint_ci.py) wrapper, который:

1. Reconfigures stdout encoding для UTF-8 на Windows (`sys.stdout.reconfigure(encoding='utf-8', errors='replace')`)
2. Monkey-patch `kb_lint.fixer.fix_filename_casing` для Cyrillic-safety (skip non-ASCII stems с warning)
3. Запускает kb-lint в `--ci` режиме (read-only check, без `--fix`)

Детали — [chapter 32.8 Pre-commit и качество](32.8_Pre_commit_и_качество.md).

## Naming rules

Из [SCHEMA.md](../../../wiki/SCHEMA.md) §«Naming Rules»:

1. **Format:** `lowercase-kebab-case.md`
2. **Maximum length:** 80 characters (excluding `.md`)
3. **Allowed:** lowercase letters (`a-z`), digits (`0-9`), hyphens (`-`)
4. **Prohibited:** spaces, underscores, special characters, uppercase
5. **No consecutive hyphens** (`foo--bar` → `foo-bar`)
6. **No leading/trailing hyphens**
7. **Cyrillic stems:** allowed только в hub pages (через kb-lint per-page exception); `entities/` slug'и должны быть ASCII

`WikiExporter._sanitize_filename()` implementation:

```python
@staticmethod
def _sanitize_filename(name: str) -> str:
    """Convert arbitrary entity name → safe filename slug."""
    s = name.lower()
    s = re.sub(r"[^a-z0-9]+", "-", s)        # non-alnum → hyphen
    s = re.sub(r"-+", "-", s)                # consecutive hyphens
    s = s.strip("-")                          # leading/trailing
    return s[:80] or "unnamed"
```

Тесты: `TestSanitizeFilename` (4 теста) покрывают basic, special chars, long names (>80), consecutive hyphens.

## Cross-reference syntax

### Wiki-links (Obsidian-compatible)

```markdown
См. [[provider-pattern]] для деталей.
Также: [[strategy-pattern|стратегии]].          ← с display text
```

Регулярка для парсинга (используется `ReverseSyncService._parse_wiki_page` и `WikiSearchIndexer._extract_searchable_text`):

```python
re.findall(r"\[\[([^\]|]+)(?:\|[^\]]+)?\]\]", body)
```

Захватывает только target (`provider-pattern`, `strategy-pattern`). Display text после `|` отбрасывается при извлечении relations, но используется при rendering для search/UI.

### Bidirectional linking rule

Из SCHEMA: «When Page A links to Page B, Page B must include Page A in `related`.»

Audit-paтерн (можно автоматизировать):

```bash
# Find all pages X linking to Y where Y doesn't link back to X
.venv/Scripts/python.exe scripts/kb_lint_ci.py 2>&1 | grep "Broken wiki-link\|orphan"
```

`_index.md` служит **central link registry** — все hub-страницы должны быть в нём перечислены.

### Markdown links (для внешних refs)

Для ссылок вне wiki — обычный markdown `[label](path)`:

```markdown
См. [CLAUDE.md](../../../../CLAUDE.md) §Memory для контекста.
Roadmap: [260514_ROADMAP_WIKI_PROMOTION_GAP.md](../../../roadmap/260514_ROADMAP_WIKI_PROMOTION_GAP.md).
```

`kb-lint` не валидирует внешние markdown links (только wiki-links). Битые внешние ссылки — отдельная проверка через `markdownlint-cli2` (другой pre-commit hook, scope `^docs/wiki/.*\.md$`).

## Page lifecycle (state machine)

```
   ┌────────┐     promote     ┌──────────┐    canonize    ┌──────────┐
   │ L2     │ ─────────────▶  │ L5 draft │ ────────────▶  │ L3       │
   │ pattern│  WikiPromoter   │ docs/    │  human review  │ active   │
   │ Qdrant │                 │ wiki/    │  + manual mv   │ entities/│
   └────────┘                 │ drafts/  │                └────┬─────┘
                              └──────────┘                      │
                                                                │ deprecate
                                                                │ (manual)
                                                                ▼
                                                          ┌──────────┐
                                                          │ archived │
                                                          │ archive/ │
                                                          │ <date>/  │
                                                          └──────────┘
```

| Transition | Trigger | Required action |
|---|---|---|
| L2 → L5 | `application_count ≥ 5 AND confidence ≥ 0.8` | Auto через `WikiPromoter.scan_and_promote()` (вызывается из Stop hook) |
| L5 → L3 | Human review | Manual: проверить frontmatter, наполнить body, `mv drafts/x.md entities/x.md`, set `status: active` |
| L3 → archived | Outdated / superseded | Manual: `mv entities/x.md archive/YYYY-MM/x.md`, set `status: archived`, оставить `superseded_by` ссылку в `related` |

Auto-archive (cron / age-based) — пока не реализован, см. roadmap gap в [chapter 32.6](32.6_L2_L5_Promotion.md).

## Размер и performance

| Параметр | Текущее значение | Лимит |
|---|---|---|
| Файлов в `entities/` | 2 822 | — (нет верхнего лимита, но `export-all` time scales linearly) |
| Файлов в `patterns/` | 28 | — |
| Средний размер entity page | ~2-4 KB | — |
| `log.md` length | ~80 KB | 500 lines (trimmed by `session-memory-save`) |
| `wiki_pages_v1` points | 3 073 | — (некоторые pages дают >1 chunk при индексации) |
| Reindex full wiki | ~3-5 min | — |

Performance критическая точка — `export_all()` last full run: linear scan через все entities + idempotent skip для unchanged. Idempotency проверяется через SHA1 hash frontmatter+body **до** записи, что устраняет filesystem churn.
