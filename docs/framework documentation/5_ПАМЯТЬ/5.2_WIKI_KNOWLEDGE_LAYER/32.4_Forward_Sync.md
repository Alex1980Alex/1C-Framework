# 32.4 Forward Sync — Graph → Wiki

Forward sync — это направление **GraphStore → docs/wiki/entities/**: каждая entity (Person, Concept, Technology, …) в knowledge graph должна иметь соответствующий markdown файл. Поддерживается тремя сервисами на разных временных горизонтах: `WikiExporter` (batch ad-hoc), `ForwardSyncService` (catch-up по timestamp), `IncrementalWikiSync` (event-driven realtime через EventBus).

## Три режима sync

| Режим | Когда | Trigger | Сервис |
|---|---|---|---|
| **Batch** | Initial export, manual re-sync | Manual CLI `python -m scripts.export_graph_to_wiki export-all` | `WikiExporter.export_all()` |
| **Catch-up** | После downtime, при startup, после миграций | Manual или start-up routine | `ForwardSyncService.sync_since(timestamp)` |
| **Event-driven** | Production runtime | `graph.*` events через EventBus | `IncrementalWikiSync._listen_loop()` |

В steady-state production обычно работает только event-driven; batch + catch-up — для recovery scenarios.

## Batch export workflow

### CLI

```bash
.venv/Scripts/python -m scripts.export_graph_to_wiki export-all \
    --output-dir docs/wiki/entities \
    --batch-size 50 \
    [--dry-run] \
    [--overwrite] \
    [--verbose]
```

Реализация: [`scripts/export_graph_to_wiki.py:cmd_export_all`](../../../../scripts/export_graph_to_wiki.py).

### Алгоритм

```python
async def cmd_export_all(args):
    store = await _get_graph_store()        # NetworkXGraphStore / Neo4j
    config = WikiExportConfig(
        output_dir=args.output_dir,
        batch_size=args.batch_size,
        dry_run=args.dry_run,
        overwrite=args.overwrite,
    )
    exporter = WikiExporter(store, config)
    result = await exporter.export_all()
    # result.exported_pages, .failed_pages, .total_entities, .errors
```

`WikiExporter.export_all()` итерирует entity_ids batch'ами, для каждой вызывает `export_entity(eid)`:

1. `graph_store.get_entity(eid)` → если `None`, skip
2. `graph_store.get_neighbors(eid, depth=1)` → SubGraph для frontmatter `related`
3. Build frontmatter (YAML) + body (markdown sections)
4. SHA1(frontmatter + body) compare с existing file
   - Match → skip (idempotent)
   - Mismatch или новый файл → `write_text(encoding="utf-8")`
5. Increment `exported_pages` counter (или `failed_pages` при exception)

`dry_run=True` логирует что было бы записано но не trogает диск.

### Frontmatter из Entity

```python
entity = await graph_store.get_entity(eid)
# entity.id, .name, .entity_type, .properties, .confidence, .source_chunk_ids

frontmatter = {
    "unified_id": entity.id,
    "status": "active",
    "tags": [entity.entity_type.lower(), *entity.properties.get("tags", [])],
    "related": [f"[[{_sanitize_filename(rel.target_name)}]]"
                for rel in neighbors[:config.max_relations_per_page]],
    "confidence": entity.confidence,
    "created_at": entity.properties.get("created_at", datetime.now().isoformat()),
    "updated_at": datetime.now().isoformat(),
    "source_pdf": entity.properties.get("source_document_id"),
    "title": entity.name,
}
```

### Body sections

```markdown
# {entity.name}

## Properties
| Key | Value |
|-----|-------|
| entity_type | {entity.entity_type} |
| source_document_id | {entity.properties.get('source_document_id')} |
| ... | ... |

## Source chunks (top N)
- chunk_id: {chunk_id_1} — {first 100 chars of chunk text}
- ...

## Connections
- [[{target_slug}]] — relation_type: {rel.relation_type}, confidence: {rel.confidence}
- ...
```

`source_chunk_limit` (default 5) ограничивает раздел Source chunks — иначе entity с тысячами chunks дал бы гигантскую страницу.

## Catch-up sync

`ForwardSyncService.sync_since(timestamp)` обновляет только те entities у которых `updated_at >= timestamp`. Полезен после downtime: пропустил события, но знаешь когда последний раз был online — фильтруешь по этому timestamp.

```python
fs = ForwardSyncService(graph_store, exporter)
result = await fs.sync_since(datetime(2026, 5, 14, 0, 0))
# result — список (entity_id, Path|Exception)
```

`sync_entity(entity_id)` — обёртка над `WikiExporter.export_entity` с retry-friendly интерфейсом (возвращает `Path | None`, не raise'ит на missing entity). Используется в `IncrementalWikiSync._sync_with_retry`.

## Event-driven sync (production runtime)

### Subscription

При запуске `IncrementalWikiSync.start()`:

```python
async def start(self):
    self._listener_task = asyncio.create_task(self._listen_loop())
    self._running = True

async def _listen_loop(self):
    async for event in self._event_bus.subscribe("graph.*"):
        try:
            await self.handle_event(event)
        except Exception as exc:
            logger.error("[INC-SYNC] Unhandled: %s", exc, exc_info=True)
```

EventBus реализован в [`src/memory/infrastructure/event_bus.py`](../../../../src/memory/infrastructure/event_bus.py). Topic pattern `graph.*` ловит все события графа.

### Event dispatch

```python
async def handle_event(self, event: GraphChangeEvent):
    if not self._running:
        return
    _metrics and _metrics.counter("wiki_sync_events_total")
    if not self._should_sync(event):
        return                                   # skip embedding_only updates

    if event.event_type in (GraphEventType.ENTITY_CREATED,
                            GraphEventType.ENTITY_UPDATED):
        await self._sync_with_retry(event.entity_id)
    elif event.event_type == GraphEventType.ENTITY_DELETED:
        await self._delete_wiki_page(event.entity_id)
    elif event.event_type in (GraphEventType.RELATION_ADDED,
                              GraphEventType.RELATION_REMOVED):
        for eid in event.affected_entity_ids:    # обе стороны связи
            await self._sync_with_retry(eid)
    elif event.event_type == GraphEventType.COMMUNITY_MERGED:
        for eid in event.affected_entity_ids:
            await self._sync_with_retry(eid)
```

### Retry policy (tenacity)

```python
async def _sync_with_retry(self, entity_id: str) -> None:
    try:
        async for attempt in AsyncRetrying(
            stop=stop_after_attempt(self._max_retries),       # default 5
            wait=wait_chain(*[wait_fixed(d) for d in self._BACKOFF_DELAYS]),
            retry=retry_if_exception_type(Exception),
            reraise=True,
            before_sleep=lambda state: logger.warning(
                "[INC-SYNC] Retry %d/%d for %s: %s",
                state.attempt_number, self._max_retries, entity_id,
                state.outcome.exception() if state.outcome else "<unknown>",
            ),
        ):
            with attempt:
                await self._forward_sync.sync_entity(entity_id)
        return
    except Exception:
        logger.error("[INC-SYNC] Failed after %d retries: %s",
                     self._max_retries, entity_id, exc_info=True)
        _metrics and _metrics.counter("wiki_sync_failures_total")
        await self._write_failed_event(entity_id, "retry_exhausted")
```

`_BACKOFF_DELAYS = [1, 2, 5, 10, 30]` (секунды) — exponential growth с плато на 30s. После 5 неудач entity отправляется в DLQ и метрика инкрементируется.

`reraise=True` важен — без него tenacity-обёртка проглатывала бы final exception, и пользовательский except не сработал бы. `before_sleep` callback логирует промежуточные неудачи, `exc_info=True` в финальном `logger.error` сохраняет stack final attempt'а (иначе он был бы потерян, см. comment в коде).

### Embedding-only filter

```python
def _should_sync(self, event: GraphChangeEvent) -> bool:
    meta = event.metadata or {}
    return meta.get("change_type") != "embedding_only"
```

Когда `IncrementalGraphUpdater` пересчитывает только эмбеддинг entity (без изменения properties или связей), он публикует `ENTITY_UPDATED` с `metadata={"change_type": "embedding_only"}`. Wiki frontmatter и body такой entity не меняются — sync бессмысленен. Этот фильтр предотвращает noise re-writes.

## Dead Letter Queue (DLQ)

После исчерпания retry → `_write_failed_event(entity_id, "retry_exhausted")`:

```python
async def _write_failed_event(self, entity_id: str, reason: str) -> None:
    self._failed_events_path.parent.mkdir(parents=True, exist_ok=True)
    entry = {
        "entity_id": entity_id,
        "reason": reason,
        "timestamp": datetime.now().isoformat(),
    }
    async with self._exporter._lock:
        with open(self._failed_events_path, "a", encoding="utf-8") as f:
            f.write(json.dumps(entry, ensure_ascii=False) + "\n")
    _metrics and _metrics.gauge("wiki_sync_dlq_size",
                                sum(1 for _ in open(self._failed_events_path, encoding="utf-8")))
```

**DLQ location** (default): `data/wiki_sync_dlq.jsonl`. Append-only, JSONL формат.

### DLQ recovery

На рестарте daemon обрабатывает DLQ до начала приёма новых событий:

```python
# Pseudocode внутри start()
if self._failed_events_path.exists():
    with open(self._failed_events_path, "r", encoding="utf-8") as f:
        for line in f:
            entry = json.loads(line)
            await self.handle_event(GraphChangeEvent(
                event_type=GraphEventType.ENTITY_UPDATED,
                entity_id=entry["entity_id"],
                timestamp=datetime.fromisoformat(entry["timestamp"]),
                affected_entity_ids=[entry["entity_id"]],
            ))
    self._failed_events_path.unlink()  # clear DLQ после успешного recovery
```

(Если recovery сам падает → DLQ растёт, нужно ручное вмешательство. Метрика `wiki_sync_dlq_size` мониторится через Prometheus.)

## Sync incremental daemon

CLI запуск:

```bash
.venv/Scripts/python -m scripts.export_graph_to_wiki sync-incremental [--verbose]
```

Реализация [`cmd_sync_incremental`](../../../../scripts/export_graph_to_wiki.py):

```python
async def cmd_sync_incremental(args):
    store = await _get_graph_store()
    config = WikiExportConfig(output_dir=Path("docs/wiki/entities"))
    exporter = WikiExporter(store, config)
    forward_sync = ForwardSyncService(store, exporter)
    inc_sync = IncrementalWikiSync(forward_sync, exporter)

    await inc_sync.start()
    print("Incremental sync started. Press Ctrl+C to stop.")
    try:
        await asyncio.Event().wait()    # block forever
    except KeyboardInterrupt:
        await inc_sync.stop()
    return 0
```

В production обычно запускается как systemd service / Docker container. Включает graceful shutdown через SIGINT/SIGTERM.

## Metrics (observability)

Если метрики настроены через [`src/pdf_framework/observability/`](../../../../src/pdf_framework/observability/), `IncrementalWikiSync` инкрементирует:

| Metric | Type | Что измеряет |
|---|---|---|
| `wiki_sync_events_total` | counter | Все обработанные events (включая filtered) |
| `wiki_sync_failures_total` | counter | Events failed after retry exhaustion |
| `wiki_sync_dlq_size` | gauge | Текущий размер DLQ |
| `wiki_sync_duration_seconds` | histogram | (планируется) per-event latency |

Если observability не настроена — graceful degradation: `_metrics` = `None`, операции skip'аются через `_metrics and _metrics.counter(...)`.

## Troubleshooting

| Симптом | Причина | Действие |
|---|---|---|
| `docs/wiki/entities/` пустой после `export-all` | GraphStore не инициализирован или пуст | `await store.initialize()`, проверить наличие PDF в index |
| Бесконечный retry на одной entity | Persistent exception в `sync_entity` (e.g., graph corruption) | Проверить `data/wiki_sync_dlq.jsonl`; вручную exclude entity или fix root cause |
| DLQ растёт | Daemon не справляется с потоком events | Проверить metrics, увеличить `_max_retries` или scale-out (multiple daemons на partitioned graph — future enhancement) |
| Стpраница не обновляется при изменении entity | `change_type == "embedding_only"` filter активен (это нормально) или event не публикуется | Проверить `IncrementalGraphUpdater` logs |
| Idempotency не работает (страница перезаписывается каждый export) | Frontmatter содержит timestamps (`updated_at: datetime.now()`) → hash отличается | Известный trade-off. Можно отключить timestamp обновление через `config.preserve_updated_at` (future) |
