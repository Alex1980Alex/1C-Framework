# 32.6 L2 → L5 Promotion — продвижение из vector memory в wiki drafts

Promotion — это **обратный путь к Forward Sync**: forward берёт canonical entity из графа и пишет в wiki; promotion наоборот берёт high-confidence pattern из vector memory `learned_patterns` Qdrant коллекции и **продвигает** в `docs/wiki/drafts/` для review и финальной канонизации в `docs/wiki/entities/`.

L5 = pending L3 candidates. После human review (или auto-canonization по дополнительным критериям) draft переходит в `entities/`.

## WikiPromoter algorithm

[`src/memory/librarian/wiki_promoter.py`](../../../../src/memory/librarian/wiki_promoter.py):

```python
async def scan_and_promote(self) -> list[str]:
    """Scan eligible patterns and create wiki drafts for new ones."""

    # 1. Scroll Qdrant с двойным фильтром
    candidates, _ = self.client.scroll(
        collection_name="learned_patterns",
        scroll_filter=Filter(
            must=[
                FieldCondition(key="confidence",
                              range=Range(gte=self.confidence_threshold)),
                FieldCondition(key="application_count",
                              range=Range(gte=self.usage_threshold)),
            ]
        ),
        with_payload=True,
        with_vectors=True,
        limit=100,
    )

    created: list[str] = []
    for point in candidates:
        payload = point.payload or {}

        # 2. Dedup: проверить cosine similarity с уже существующими wiki-pages
        vector = self._extract_vector(point, payload)
        existing = await self._dedup_check(vector, str(point.id))
        if existing is None:
            # 3. Create draft + log entry
            slug = await self._create_draft(payload)
            await self._publish_event("wiki.draft.created",
                                       {"slug": slug, "source_id": str(point.id)})
            created.append(slug)

    return created
```

### Dedup check

```python
async def _dedup_check(self, embedding, source_id):
    """Returns existing slug if too similar, else None."""
    if not embedding:
        return None
    results = self.client.query_points(
        collection_name="learned_patterns",
        query=embedding,
        limit=5,
        with_payload=True,
    )
    for scored in results.points:
        if str(scored.id) == source_id:
            continue                            # skip self
        if scored.score >= self.similarity_threshold:    # default 0.85
            payload = scored.payload or {}
            promoted = payload.get("promoted_to")        # уже promoted'нут?
            if promoted:
                return promoted
            slug = self._slugify(payload.get("name", "unnamed"))
            if (self.drafts_dir / f"{slug}.md").exists():
                return slug                     # уже есть draft с таким же контентом
    return None
```

Dedup использует тот же `learned_patterns` collection для сравнения (рассматривается каждая existing pattern как potential dup для new one). `similarity_threshold = 0.85` — высокий, избегает false-positive matches.

### Create draft

```python
async def _create_draft(self, candidate_payload: dict) -> str:
    name = candidate_payload.get("name", "unnamed-pattern")
    slug = self._slugify(name)

    cube = MemoryCube(
        content=candidate_payload.get("content", ""),
        content_type=ContentType.WIKI,
        memory_type=MemoryType.WIKI,
        source=SourceServer.OBSIDIAN_VAULT,
        title=name,
        confidence=candidate_payload.get("confidence", 0.8),
        tags=candidate_payload.get("tags", []),
        what=candidate_payload.get("description"),
    )

    self.drafts_dir.mkdir(parents=True, exist_ok=True)
    (self.drafts_dir / f"{slug}.md").write_text(
        cube.to_wiki_page(),
        encoding="utf-8",
    )
    self._append_log(slug, name, candidate_payload.get("confidence", 0.8))
    return slug
```

`MemoryCube.to_wiki_page()` — единая точка serialization L2 → L3. Гарантирует консистентный frontmatter shape.

### Slugify

```python
@staticmethod
def _slugify(name: str) -> str:
    return re.sub(r"[^a-z0-9-]", "",
                  name.lower().replace(" ", "-"))[:80] or "unnamed"
```

Простая версия `_sanitize_filename` без обработки consecutive hyphens — наследует от `WikiExporter` (для entities). Может отличаться slightly от exporter'а; обе версии безопасны для filesystem.

### Log entry

```python
def _append_log(self, slug, name, confidence):
    entry = (
        f"\n## {datetime.now().strftime('%Y-%m-%d')} — Auto-promoted: {name}\n\n"
        f"**Event:** L2 pattern promoted to wiki draft\n\n"
        f"- Pattern: `{name}` (confidence: {confidence:.2f})\n"
        f"- Draft: `docs/wiki/drafts/{slug}.md`\n\n"
        f"**Status:** Pending review\n\n---\n"
    )
    # Insert before "## Format Template" marker; trim to 500 lines
```

`log.md` накапливает chronology (max 500 lines, trimmed на каждый append). Это **audit trail** — кто и когда был promoted.

## Bayesian confidence update

`vector_memory/server.py:391 handle_apply_pattern` реализует простой Bayesian-like update:

```python
delta = 0.02 if success else -0.01
new_confidence = max(0.0, min(1.0, old_confidence + delta))
```

Это **не строгий Bayesian** (нет prior'а, нет likelihood модели), а простой running average с asymmetric step:

- **Success step (+0.02)** > **Failure step (-0.01)** — bias to «innocent until proven guilty» (одна ошибка не убивает хороший pattern, но повторные ошибки штрафуют)
- Clamp в `[0, 1]` гарантирует валидное значение для downstream filter'ов

**Time-to-threshold** при cold-start конкретного pattern'а:
- Starting confidence = 0.7 (typical для freshly captured pattern)
- Threshold = 0.8
- Delta = 0.1
- Required: `0.1 / 0.02 = 5` successful applications

**Time-to-promotion** (оба порога):
- confidence 0.7 → 0.8: 5 successes
- application_count 0 → 5: те же 5 calls
- → **Минимум 5 successful pattern applications** to promote

Это намеренный gate — отсеивает one-off patterns, требует repeated validation.

## Decay (counter-balance)

Patterns не только растут вверх — они **decay'ятся** со временем, если не применяются. Реализация — [`src/memory/librarian/wiki_decay.py`](../../../../src/memory/librarian/wiki_decay.py) `WikiDecayService` (добавлен 2026-05-14).

Алгоритм:

```python
days_idle = (now - max(decay_applied_at, last_applied, updated_at, created_at)).days
decay     = decay_rate * (days_idle / 30.0)         # monthly linear
new_conf  = max(min_confidence, old_conf - decay)
```

`decay_rate` — per-point payload field (default `0.05`/month). Timestamp source приоритет:

1. `decay_applied_at` (предыдущий decay run) — **критично**: без этого daily cron re-applied бы full elapsed delta каждый раз, fast-saturating до floor
2. `last_applied` (последний MCP apply)
3. `updated_at` / `created_at` (fallback)

CLI:

```bash
.venv/Scripts/python -m scripts.export_graph_to_wiki decay-confidence \
    [--min-confidence 0.0] [--dry-run]
```

Smoke 2026-05-14 на 44 точках `learned_patterns`: total=44, decayed=11, skipped=33 (11 points с `confidence` поле + давний `created_at` → decay applied).

Cadence: рекомендуется **monthly cron** или manual periodic run. НЕ wired в Stop hook (избегаем double-decay — apply_pattern уже даёт -0.01 при success=false, decay добавил бы шум).

## Field-name история

Pre-2026-05-14: WikiPromoter фильтровал по `usage_count`, который **никто никогда не писал**. Update side (`handle_apply_pattern`) пишет `application_count`. Field-name drift.

Closure 2026-05-14:

```diff
- FieldCondition(key="usage_count", range=Range(gte=self.usage_threshold)),
+ FieldCondition(key="application_count", range=Range(gte=self.usage_threshold)),
```

Constructor arg `usage_threshold` сохранён для back-compat со spec language. См. [roadmap 260514_ROADMAP_WIKI_PROMOTION_GAP.md](../../../roadmap/260514_ROADMAP_WIKI_PROMOTION_GAP.md) §Resolution.

## Stop hook wiring

[`.claude/hooks/session-memory-save.py`](../../../../.claude/hooks/session-memory-save.py):

```python
def try_promote_patterns() -> None:
    """L2→L5 promotion: scan learned_patterns, write drafts. Best-effort, non-blocking.

    Uses CLI defaults (confidence>=0.8, application_count>=5). Failures are swallowed —
    drafts/ is advisory state; missing run is acceptable. Disable with
    SESSION_MEMORY_NO_PROMOTE=1 (e.g. CI, dev with no Qdrant).
    """
    if os.environ.get("SESSION_MEMORY_NO_PROMOTE") == "1":
        return
    try:
        result = subprocess.run(
            [sys.executable, "-m", "scripts.export_graph_to_wiki", "promote-patterns"],
            capture_output=True, text=True,
            timeout=4,                         # leaves margin under 5s Stop-hook timeout
            cwd=str(PROJECT_ROOT),
            encoding="utf-8", errors="replace",
        )
        # success → CLI already wrote draft + log; nothing to do here
    except (subprocess.TimeoutExpired, OSError, FileNotFoundError):
        pass                                    # advisory; missing run is fine


class SessionMemorySave(BaseHook):
    def execute(self, inp):
        ctx = collect_context()
        if not is_meaningful(ctx):
            return None
        if already_saved(ctx["session_id"]):
            return None
        save_to_sqlite(ctx)
        save_to_wiki_log(ctx)
        try_promote_patterns()                  # ← new call
        return None
```

### Timeout reasoning

Hook docstring заявляет «Timeout: 5s». Subprocess `timeout=4` оставляет 1s margin для cleanup. Если Qdrant scroll + 100 candidates + dedup занимает > 4s — promotion skip'ается этой Stop event'ом, retry на следующем Stop'е. L5 drafts — advisory state, missing run acceptable.

### Opt-out

```bash
export SESSION_MEMORY_NO_PROMOTE=1    # CI environment, dev без Qdrant
```

Сценарии для opt-out:
- CI runners (нет running Qdrant)
- Локальная разработка, когда хочется быстрого Stop'а
- Testing infrastructure (избежать сайд-эффектов в test isolation)

Exit codes:
- `0` — successful run (с любым counter'ом promoted patterns, включая 0)
- `1` — total failure (Qdrant unreachable, etc.)
- `2` — bad arguments

«Promoted 0 patterns» — это **informational success**, не error. Exit 0 + сообщение в stderr.

Реализация: [`scripts/export_graph_to_wiki.py:cmd_promote_patterns`](../../../../scripts/export_graph_to_wiki.py).

## Manual promotion workflow

Когда WikiPromoter создал draft в `docs/wiki/drafts/<slug>.md`:

1. **Review draft** — открыть файл, проверить content, frontmatter, links
2. **Enhance content** — добавить examples, cross-refs, related sections
3. **Set `status: active`** — заменить `status: draft` в frontmatter
4. **Move** — `git mv docs/wiki/drafts/<slug>.md docs/wiki/entities/<slug>.md`
5. **Update related pages** — добавить bidirectional link в `[[<slug>]]` references
6. **Commit** — структурированный commit message
7. (Optional) Update `promoted_to` payload в `learned_patterns` — что зачастую делается через update_pattern MCP call

Auto-canonization (draft → active без human review) — НЕ implemented. Можно построить: e.g., если pattern reaches `confidence >= 0.95` AND `application_count >= 20` AND no human edit'ил draft за 30 дней → auto-move в entities/. Currently roadmap item.

**Cold start expectations**: после full session с активным pattern apply (через `vector_memory.apply_pattern` MCP calls с `success=true`):

- Каждый pattern → `+0.02 confidence`, `+1 application_count` per success
- 5 successful applications одного pattern'а с starting `confidence=0.7` → достижение порога (`confidence=0.8`, `application_count=5`)
- На следующий Stop event → `try_promote_patterns()` → создание draft

В реальных production sessions это занимает 1-5 дней работы (depending on session frequency и pattern reuse).
