# 32.6 L2 → L5 Promotion — продвижение из vector memory в wiki drafts

Promotion — это **обратный путь к Forward Sync**: forward берёт canonical entity из графа и пишет в wiki; promotion наоборот берёт high-confidence pattern из vector memory `learned_patterns` Qdrant коллекции и **продвигает** в `docs/wiki/drafts/` для review и финальной канонизации в `docs/wiki/entities/`.

L5 = pending L3 candidates. После human review (или auto-canonization по дополнительным критериям) draft переходит в `entities/`.

## Два писателя drafts/ (важно не путать)

`docs/wiki/drafts/` наполняют **ДВА независимых писателя**, оба через `MemoryCube.to_wiki_page(status="draft")`, но по разным триггерам:

1. **`WikiPromoter.scan_and_promote()`** (описан ниже) — периодический L2→L5 промоушен: сканирует `learned_patterns` по порогам `confidence≥0.8 & application_count≥5`, вызывается detached-subprocess'ом из `session-memory-save.py:try_promote_patterns()` на каждый Stop event. Batch, selective (eligible-only).
2. **`route_and_save` → `MemoryOrchestrator._save_to_target("wiki")`** ([`src/memory/orchestrator/memory_orchestrator.py:2013-2043`](../../../../src/memory/orchestrator/memory_orchestrator.py)) — **де-факто основной наполнитель**: прямая маршрутизация, срабатывает на КАЖДЫЙ save через `route_and_save`, когда роутер (`self._router.route(content, metadata)`, [`memory_orchestrator.py:596`](../../../../src/memory/orchestrator/memory_orchestrator.py)) относит content к target `"wiki"` — без порогов confidence/usage. Создаёт `MemoryCube` (`content_type=WIKI`, `source=OBSIDIAN_VAULT`, slug из `metadata["slug"]` или первых 40 символов content) → `to_wiki_page(status="draft")` → пишет `docs/wiki/drafts/{slug}.md` немедленно, синхронно внутри вызова.

Оба писателя используют один и тот же сериализатор (`MemoryCube.to_wiki_page`), поэтому drafts от обоих путей неотличимы по формату — различить можно только по `content_hash`/содержимому или по логам (`memory-routing.log` для route_and_save vs `session-promote.log` для WikiPromoter).

## WikiPromoter algorithm

[`src/memory/librarian/wiki_promoter.py`](../../../../src/memory/librarian/wiki_promoter.py):

```python
async def scan_and_promote(self) -> list[str]:
    """Scan eligible patterns and create wiki drafts for new ones."""

    # 1. Scroll Qdrant с двойным фильтром
    candidates, _ = self.client.scroll(
        collection_name="learned_patterns",
        scroll_filter=Filter(
            must=[
                FieldCondition(key="confidence",
                              range=Range(gte=self.confidence_threshold)),
                FieldCondition(key="application_count",
                              range=Range(gte=self.usage_threshold)),
            ]
        ),
        with_payload=True,
        with_vectors=True,
        limit=100,
    )

    created: list[str] = []
    for point in candidates:
        payload = point.payload or {}

        # 1b. F13: idempotency pre-filter — точка, уже несущая свой
        #     promoted_to, была promoted ранее; skip до дорогого vector dedup
        if payload.get("promoted_to"):
            continue

        # 2. Dedup: проверить cosine similarity с уже существующими wiki-pages
        vector = self._extract_vector(point, payload)
        existing = await self._dedup_check(vector, str(point.id))
        if existing is None:
            # 3. Create draft + log entry
            slug = await self._create_draft(payload)
            self._mark_promoted(str(point.id), slug)      # F13: stamp source point
            await self._publish_event("wiki.draft.created",
                                       {"slug": slug, "source_id": str(point.id)})
            created.append(slug)

    return created
```

### F13 идемпотентность (роадмап 260611 P3.2)

Promotion без маркера мог бы re-promote тот же pattern на каждом Stop-запуске (перезапись draft + повторный append в `log.md`). F13 закрывает это тремя точками:

1. **Pre-filter** — точка с уже выставленным `promoted_to` пропускается ДО дорогого vector dedup (см. пункт 1b выше)
2. **`_mark_promoted(source_point_id, slug)`** ([`wiki_promoter.py:95-112`](../../../../src/memory/librarian/wiki_promoter.py)) — best-effort `client.set_payload(..., payload={"promoted_to": slug})` на source-точке сразу после создания draft; ошибка записи маркера логируется, но не блокирует draft
3. **`_append_log` дедуп** ([`wiki_promoter.py:197-228`](../../../../src/memory/librarian/wiki_promoter.py)) — перед append проверяет `f"docs/wiki/drafts/{slug}.md" in content`; если путь уже упомянут в `log.md`, повторная запись пропускается (кроме редкого случая, когда упоминание было обрезано 500-строчным cap'ом)

### Dedup check

```python
async def _dedup_check(self, embedding, source_id):
    """Returns existing slug if too similar, else None."""
    if not embedding:
        return None
    results = self.client.query_points(
        collection_name="learned_patterns",
        query=embedding,
        limit=5,
        with_payload=True,
    )
    for scored in results.points:
        if str(scored.id) == source_id:
            continue                            # skip self
        if scored.score >= self.similarity_threshold:    # default 0.85
            payload = scored.payload or {}
            promoted = payload.get("promoted_to")        # уже promoted'нут?
            if promoted:
                return promoted
            slug = self._slugify(payload.get("name", "unnamed"))
            if (self.drafts_dir / f"{slug}.md").exists():
                return slug                     # уже есть draft с таким же контентом
    return None
```

Dedup использует тот же `learned_patterns` collection для сравнения (рассматривается каждая existing pattern как potential dup для new one). `similarity_threshold = 0.85` — высокий, избегает false-positive matches.

### Create draft

```python
async def _create_draft(self, candidate_payload: dict) -> str:
    name = candidate_payload.get("name", "unnamed-pattern")
    slug = self._slugify(name)

    cube = MemoryCube(
        content=candidate_payload.get("content", ""),
        content_type=ContentType.WIKI,
        memory_type=MemoryType.WIKI,
        source=SourceServer.OBSIDIAN_VAULT,
        title=name,
        confidence=candidate_payload.get("confidence", 0.8),
        tags=candidate_payload.get("tags", []),
        what=candidate_payload.get("description"),
    )

    self.drafts_dir.mkdir(parents=True, exist_ok=True)
    (self.drafts_dir / f"{slug}.md").write_text(
        cube.to_wiki_page(status="draft"),
        encoding="utf-8",
    )
    self._append_log(slug, name, candidate_payload.get("confidence", 0.8))
    return slug
```

`MemoryCube.to_wiki_page()` — единая точка serialization L2 → L3. Гарантирует консистентный frontmatter shape.

### Slugify

```python
@staticmethod
def _slugify(name: str) -> str:
    return re.sub(r"[^a-z0-9-]", "",
                  name.lower().replace(" ", "-"))[:80] or "unnamed"
```

Простая версия `_sanitize_filename` без обработки consecutive hyphens — наследует от `WikiExporter` (для entities). Может отличаться slightly от exporter'а; обе версии безопасны для filesystem.

## Confidence update — Beta(7,3) posterior (§22)

`handle_apply_pattern` делегирует математику в [`confidence.py:apply_to_payload`](../../../../src/memory/vector_memory/confidence.py) — единый источник §22. Это **настоящая Bayesian-модель**: паттерн хранит sufficient statistics `succ`/`fail`, а поле `confidence` — денормализованный кэш posterior mean:

```python
# 1. decay_counts: succ,fail ×= exp(-rate·Δdays/30)   (мультипликативный time-decay счётчиков)
# 2. succ += 1 (success)  |  fail += 1 (failure)
new_confidence = (PRIOR_SUCCESS + succ) / (PRIOR_SUCCESS + PRIOR_FAILURE + succ + fail)
#              = (7 + succ) / (10 + succ + fail)       Beta(7,3), prior mean = 0.70
```

- Prior **Beta(7,3)** → confidence нового паттерна (`succ=fail=0`) = **0.70**. Advisory-аргумент `confidence` при save игнорируется.
- Posterior mean всегда строго в (0, 1) — clamp не нужен, prior поглощает edge cases.
- Асимметрия «success не убивает / fail штрафует» заложена в prior 7:3, а не в асимметричном шаге дельты: один fail не убивает хороший паттерн, накопленные fail'ы штрафуют.

**Time-to-threshold** при cold-start конкретного pattern'а:
- Старт `derive_confidence(0,0) = 7/10 = 0.70`
- Threshold = 0.8
- `derive_confidence(n,0) = (7+n)/(10+n) ≥ 0.8` ⟹ `n ≥ 5` → 5 чистых успехов дают `12/15 = 0.80`

**Time-to-promotion** (оба порога):
- confidence 0.70 → 0.80: 5 успехов (по Beta-posterior, не по линейной дельте)
- application_count 0 → 5: те же 5 calls
- → **Минимум 5 successful pattern applications** to promote

Это намеренный gate — отсеивает one-off patterns, требует repeated validation. Полная §22-математика — [27.9](../5.1_UNIFIED_MEMORY/27.9_Confidence_Lifecycle.md) / [27.11](../5.1_UNIFIED_MEMORY/27.11_Pattern_Lifecycle.md).

## Decay (counter-balance) — две независимые модели

> **Важно: в системе два разных decay.**
> 1. **§22 count-decay** ([`confidence.py:decay_counts`](../../../../src/memory/vector_memory/confidence.py)) — основная модель: мультипликативно затухают Beta-счётчики `succ`/`fail` (`×= exp(-rate·Δdays/30)`, FSRS-lite: `rate = base/(1+0.3·ln(1+application_count))`), lazy decay-on-read, тянет confidence к prior 0.70. Это то, что применяется при каждом `apply_pattern`/чтении.
> 2. **WikiDecayService** (ниже) — отдельный **линейный** decay денорм-поля `confidence`, батч-cron. Ниже — про (2).

Patterns не только растут вверх — они **decay'ятся** со временем, если не применяются. Реализация — [`src/memory/librarian/wiki_decay.py`](../../../../src/memory/librarian/wiki_decay.py) `WikiDecayService` (добавлен 2026-05-14).

Алгоритм:

```python
days_idle = (now - <первый непустой из: decay_applied_at | last_applied | updated_at | created_at>).days  # coalesce, не max()
decay     = decay_rate * (days_idle / 30.0)         # monthly linear
new_conf  = max(min_confidence, old_conf - decay)
```

`decay_rate` — per-point payload field (default `0.05`/month). Timestamp source приоритет:

1. `decay_applied_at` (предыдущий decay run) — **критично**: без этого daily cron re-applied бы full elapsed delta каждый раз, fast-saturating до floor
2. `last_applied` (последний MCP apply)
3. `updated_at` / `created_at` (fallback)

CLI:

```bash
.venv/Scripts/python -m scripts.export_graph_to_wiki decay-confidence \
    [--min-confidence 0.0] [--dry-run]
```

Smoke 2026-05-14 на 44 точках `learned_patterns`: total=44, decayed=11, skipped=33 (11 points с `confidence` поле + давний `created_at` → decay applied).

Cadence: рекомендуется **monthly cron** или manual periodic run. НЕ wired в Stop hook (избегаем double-decay — §22 count-decay уже тянет Beta-счётчики к prior при простое/фейлах, линейный decay добавил бы шум поверх).

## Stop hook wiring

[`.claude/hooks/session-memory-save.py`](../../../../.claude/hooks/session-memory-save.py):

```python
def try_promote_patterns() -> None:
    """L2→L5 promotion: scan learned_patterns, write drafts. Best-effort, non-blocking.

    Uses CLI defaults (confidence>=0.8, application_count>=5). Failures are swallowed —
    drafts/ is advisory state; missing run is acceptable. Disable with
    SESSION_MEMORY_NO_PROMOTE=1 (e.g. CI, dev with no Qdrant).
    """
    if os.environ.get("SESSION_MEMORY_NO_PROMOTE") == "1":
        return
    creationflags = 0
    if sys.platform == "win32":
        creationflags = 0x00000008 | 0x08000000  # DETACHED_PROCESS | CREATE_NO_WINDOW
    try:
        log_path = PROJECT_ROOT / ".claude" / "cache" / "session-promote.log"
        log_fh = log_path.open("a", encoding="utf-8")
        try:
            subprocess.Popen(
                [sys.executable, "-m", "scripts.export_graph_to_wiki", "promote-patterns"],
                stdout=log_fh, stderr=log_fh,
                cwd=str(PROJECT_ROOT),
                creationflags=creationflags,
                close_fds=True,
            )
        finally:
            log_fh.close()          # родительская копия FD; child держит свою
    except Exception:
        pass                        # advisory; missing run is fine


class SessionMemorySave(BaseHook):
    def execute(self, inp):
        ctx = collect_context()
        if not is_meaningful(ctx):
            return None
        if already_saved(ctx["session_id"]):
            return None
        save_to_sqlite(ctx)
        save_to_wiki_log(ctx)
        try_promote_patterns()                  # ← new call
        return None
```

### Detached fire-and-forget (НЕ синхронный subprocess с timeout)

Реализация — **detached `subprocess.Popen`**, не `subprocess.run(..., timeout=...)`. Stop-хук не ждёт и не собирает результат child-процесса: promotion CLI (`WikiPromoter`) сам пишет draft + log, а stdout/stderr child'а редиректятся в `.claude/cache/session-promote.log` для диагностики. Это устраняет риск, который был бы у синхронного варианта — Qdrant scroll + 100 candidates + dedup, потенциально >5s Stop-hook budget — ценой того, что успех/неуспех запуска не виден в самом Stop-хуке (только в лог-файле). L5 drafts — advisory state, missing/delayed run acceptable.

### Opt-out

```bash
export SESSION_MEMORY_NO_PROMOTE=1    # CI environment, dev без Qdrant
```

Сценарии для opt-out:
- CI runners (нет running Qdrant)
- Локальная разработка, когда хочется быстрого Stop'а
- Testing infrastructure (избежать сайд-эффектов в test isolation)

## Manual promotion workflow

Когда WikiPromoter создал draft в `docs/wiki/drafts/<slug>.md`:

1. **Review draft** — открыть файл, проверить content, frontmatter, links
2. **Enhance content** — добавить examples, cross-refs, related sections
3. **Set `status: active`** — заменить `status: draft` в frontmatter
4. **Move** — `git mv docs/wiki/drafts/<slug>.md docs/wiki/entities/<slug>.md`
5. **Update related pages** — добавить bidirectional link в `[[<slug>]]` references
6. **Commit** — структурированный commit message
7. (Optional) Update `promoted_to` payload в `learned_patterns` — что зачастую делается через update_pattern MCP call

Auto-canonization (draft → active без human review) — НЕ implemented. Можно построить: e.g., если pattern reaches `confidence >= 0.95` AND `application_count >= 20` AND no human edit'ил draft за 30 дней → auto-move в entities/. Currently roadmap item.

**Cold start expectations**: после full session с активным pattern apply (через `vector_memory.apply_pattern` MCP calls с `success=true`):

- Каждый success → decay счётчиков, затем `succ += 1`, `application_count += 1`; confidence = `(7+succ)/(10+succ+fail)`
- 5 successful applications одного pattern'а со старта `confidence=0.70` → достижение порога (`confidence=(7+5)/15=0.80`, `application_count=5`)
- На следующий Stop event → `try_promote_patterns()` → создание draft

В реальных production sessions это занимает 1-5 дней работы (depending on session frequency и pattern reuse).
