# 32.7 Search интеграция

Wiki-страницы индексируются в отдельную Qdrant коллекцию `wiki_pages_v1` и используются как L3-слой в **memory-first-hook v3** (4-layer RRF) и через `LightRAGStrategy` поиска для GraphRAG-style retrieval'а. Это два разных потребителя — memory retrieval (context для Claude) vs. RAG retrieval (для агентов).

## Qdrant коллекция wiki_pages_v1

Snapshot 2026-05-14:

```json
{
  "name": "wiki_pages_v1",
  "status": "green",
  "points_count": 3073,
  "indexed_vectors_count": 2560,
  "vectors": {
    "size": 4096,
    "distance": "Cosine"
  },
  "shard_number": 1,
  "on_disk_payload": true
}
```

**Embedding model:** Qwen3-Embedding-8B через TEI Docker (`pdf-rag-tei`), 4096 dimensions, last-token pooling. Single dense vector layout (без sparse — BM25 на wiki делается через SQLite FTS5 как general scheme Phase 8, см. [chapter 31](../../2_КОНТЕКСТ/2.8_QWEN3_RETRIEVAL_PRODUCTION/31.1_Обзор.md)).

**Indexing source:** все `.md` файлы из `docs/wiki/entities/`, опционально `docs/wiki/patterns/` (через `wiki_dir` config). 2 822 entities → 3 073 points: некоторые большие страницы дают 2-3 chunks при splitting.

**Payload schema** (per point, verified live 2026-05-15):

```json
{
  "name": "константы",
  "entity_type": "",
  "text": "## What\n\nКонстанты\n\n## Why\n\nEntity of type CONCEPT extracted from 7787e37b244e72bc\n\n## Where\n\ndocs/wiki/entities/константы.md\n\n## Content\n\n...",
  "file_path": "docs\\wiki\\entities\\константы.md"
}
```

4 поля — минималистичная schema, генерируется `WikiSearchIndexer._extract_metadata(page)`:
- `name` — `page.stem` (filename без `.md`)
- `entity_type` — пустая строка для wiki pages (поле зарезервировано для будущей integration с graph entity types)
- `text` — searchable content из `_extract_searchable_text(page)` (frontmatter stripped, `[[link|display]]` resolved в display text)
- `file_path` — relative path к файлу для navigation back из search results (с Windows backslashes на Windows host)

**Note:** Frontmatter fields (unified_id, status, tags, confidence) **НЕ** копируются в payload. Если нужен доступ к ним из search-результата — придётся читать markdown файл по `file_path`. Future enhancement — обогатить indexer до full frontmatter copy в payload.

## WikiSearchIndexer

[`wiki_exporter.py:745`](../../../../src/pdf_framework/indexing/wiki_exporter.py#L745):

```python
class WikiSearchIndexer:
    def __init__(self,
                 hybrid_search: HybridSearchService,
                 wiki_dir: Path = Path("docs/wiki/entities")):
        self._hs = hybrid_search
        self._wiki_dir = wiki_dir

    async def index_all_pages(self) -> int:
        count = 0
        for page in self._wiki_dir.glob("*.md"):
            try:
                if await self.index_page(page):
                    count += 1
            except Exception as exc:
                logger.warning("[INDEX] Failed %s: %s", page.name, exc)
        return count

    async def index_page(self, page: Path) -> bool:
        text = self._extract_searchable_text(page)
        if not text.strip():
            return False
        metadata = self._extract_metadata(page)
        await self._hs.index_document(
            text=text,
            metadata=metadata,
            collection_name="wiki_pages_v1",
        )
        return True
```

### Searchable text extraction

```python
def _extract_searchable_text(self, page: Path) -> str:
    """Strip frontmatter, resolve wiki-links, normalize whitespace."""
    content = page.read_text(encoding="utf-8")

    # 1. Remove YAML frontmatter
    content = re.sub(r"^---\n.*?\n---\n?", "", content,
                     flags=re.DOTALL, count=1)

    # 2. Resolve [[target|display]] → display
    content = re.sub(r"\[\[([^\]|]+)\|([^\]]+)\]\]",
                     r"\2", content)

    # 3. Resolve [[target]] → target (без brackets)
    content = re.sub(r"\[\[([^\]]+)\]\]", r"\1", content)

    # 4. Normalize whitespace
    content = re.sub(r"\s+", " ", content).strip()

    return content
```

Frontmatter не индексируется (избегается noise от metadata). Wiki-links резолвятся в плоский текст — кросс-references становятся обычными словами для поиска.

### Metadata extraction (actual)

```python
def _extract_metadata(self, page: Path) -> dict:
    """Minimal payload: name + entity_type + file_path."""
    return {
        "name": page.stem,
        "entity_type": "",
        "file_path": str(page.relative_to(Path.cwd())),
    }
```

`text` field добавляется отдельно через `HybridSearchService.index_document(text=..., metadata={**meta, "text": text})` — оно становится searchable content.

### Потребитель 1: memory-first-hook (Claude context)

```
User prompt
    │
    ▼
[UserPromptSubmit hook]
memory-first-hook.py
    │
    ├─ Layer 1: SQLite memory_ai.db        (weight 0.30)
    │            "Recent session summaries"
    │
    ├─ Layer 2: Qdrant learned_patterns    (weight 0.35)
    │            "Learned patterns + skills"
    │            via TEI Qwen3 embedding
    │
    ├─ Layer 4: User .md files / MEMORY.md  (weight 0.15)
    │            "Cross-session preferences"
    │
    └─ Layer 3: Qdrant wiki_pages_v1        (weight 0.20)
                 "Canonical knowledge L3"
                 via TEI Qwen3 embedding
    │
    ▼ (RRF fusion на полученных Top-K из каждого слоя)
    ▼
RRF score: 1/(k+rank) * source_weight
    │
    ▼
systemMessage с Top-K cross-layer items
    │
    ▼
Claude в контексте видит relevant wiki knowledge
```

LAYER_WEIGHTS = {

### Потребитель 2: LightRAGStrategy (RAG agent search)

[`src/pdf_framework/search/strategies/graphrag_light.py:219`](../../../../src/pdf_framework/search/strategies/graphrag_light.py#L219):

```python
class LightRAGStrategy(SearchStrategy):
    async def search(self, query, k=5):
        # 1. Standard graph-RAG retrieval
        graph_results = await self._graph_search(query, k)

        # 2. Find canonical wiki pages для entities из results
        wiki_paths = []
        for ent in graph_results.entities:
            slug = WikiExporter._sanitize_filename(ent.name)
            wiki_path = Path("docs/wiki/entities") / f"{slug}.md"
            if wiki_path.exists():
                wiki_paths.append(str(wiki_path))

        # 3. Return ChunkResults + wiki_page_paths в metadata
        return SearchResponse(
            chunks=graph_results.chunks,
            metadata={
                "entities": graph_results.entities,
                "wiki_page_paths": wiki_paths,    # ← L3 canonical refs
            }
        )
```

Use case: agent получает не только raw chunks из PDF, но и pointers на canonical wiki pages для каждой entity (что они есть, где они задокументированы, какие у них links).

## Performance

| Operation | Time (current state) |
|---|---|
| Index all wiki pages (2 822 → 3 073 points) | ~3-5 min на TEI batch_size=32 (limit `MAX_CLIENT_BATCH_SIZE` Qwen3 TEI 1.7.2) |
| Single wiki page index | ~50-200ms (TEI embedding bottleneck) |
| `wiki_pages_v1` search query (top-5 dense) | ~10-30ms p95 (HNSW m=16, ef_construct=100, in-memory) |
| memory-first-hook full 4-layer query | ~300-500ms p95 (parallel async, capped by slowest layer) |

Bottleneck — TEI embedding latency при индексации. Search query — fast (HNSW).

## Reindex после миграции

Когда меняется embedding model (например, future Qwen4):

```bash
# 1. Backup existing collection
curl -X POST http://localhost:6333/collections/wiki_pages_v1/snapshots

# 2. Drop and recreate
curl -X DELETE http://localhost:6333/collections/wiki_pages_v1
# (HybridSearchService автоматически создаст с new model при первом index_document)

# 3. Reindex all wiki
.venv/Scripts/python -m scripts.export_graph_to_wiki index-search \
    --wiki-dir docs/wiki/entities
```

Auto-reindex on commit (post-commit git hook) для `framework_code_v1` есть, для wiki — нет (manual cadence acceptable, wiki меняется реже).
