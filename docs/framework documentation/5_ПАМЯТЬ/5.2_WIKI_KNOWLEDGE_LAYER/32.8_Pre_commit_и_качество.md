# 32.8 Pre-commit и качество

Wiki содержимое контролируется на каждый commit через **2 pre-commit hook'а** + 1 wrapper:

1. **markdownlint-cli2** — общая валидация markdown синтаксиса (taablesonon-canonical wiki tweaks)
2. **kb-lint** — проверка YAML frontmatter, wiki-link integrity, naming conventions
3. **`scripts/kb_lint_ci.py`** — wrapper над kb-lint 0.1.1 с двумя monkey-patch'ами для Windows + Cyrillic compatibility

Без этой chain wiki быстро дегенерирует в bit-rot: dead links, inconsistent frontmatter, encoding artifacts.

## Pre-commit конфиг

[`.pre-commit-config.yaml`](../../../../.pre-commit-config.yaml) (фрагмент про wiki):

```yaml
# markdownlint-cli2 — общая markdown валидация
- repo: https://github.com/DavidAnson/markdownlint-cli2
  rev: v0.22.0
  hooks:
    - id: markdownlint-cli2
      name: Markdown Lint (wiki)
      files: ^docs/wiki/.*\.md$

# kb-lint — wiki-specific validation
- repo: local
  hooks:
    - id: kb-lint
      name: KB Lint (wiki)
      entry: python scripts/kb_lint_ci.py
      language: system
      files: ^docs/wiki/.*\.md$
      pass_filenames: false
      args: ['--ci']
```

Оба hook'а scoped на `^docs/wiki/.*\.md$` — не triggered на изменения вне wiki.

## kb-lint: что валидирует

Конфигурация: [`docs/wiki/.kblintrc.yml`](../../../wiki/.kblintrc.yml).

| Проверка | Что |
|---|---|
| **frontmatter required fields** | `unified_id`, `status`, `tags`, `related`, `created_at`, `updated_at`, `confidence` должны присутствовать |
| **frontmatter types** | `confidence` — float [0,1], `status` — enum, `tags` — list, `unified_id` — UUID v7 формат |
| **dates parse** | `created_at`, `updated_at` — valid ISO 8601 |
| **naming** | lowercase kebab-case, max 80 chars, no leading/trailing hyphens |
| **wiki-link integrity** | `[[target]]` resolves to existing file (unless target wrapped в code block / disabled) |
| **bidirectional links** | Если A links to B, B должен иметь A в `related` |
| **orphan pages** | Pages с 0 incoming links — warning (не error) |
| **tags whitelist** | Optional: tags должны быть из known set |
| **structural** | Heading hierarchy (no H3 без H2 above), single H1 per page |

### Config location quirk

kb-lint 0.1.1 читает config из **`<wiki_path>/.kblintrc.yml`** или `<wiki_path>/pyproject.toml [tool.kb-lint]` — **НЕ из project-root**.

Каноническая локация: [`docs/wiki/.kblintrc.yml`](../../../wiki/.kblintrc.yml). Project-root `.kb-lint.toml` (если бы был) — dead config, kb-lint игнорирует. Это документировано в комментариях `.pre-commit-config.yaml` и в [chapter 09.14](../../7_ПРОВЕРКА/7.2_АДМИНИСТРИРОВАНИЕ/09.14_Pre_Commit_Hooks.md).

## Wrapper: scripts/kb_lint_ci.py

Wrapper необходим из-за **двух багов kb-lint 0.1.1 на Windows + Cyrillic KB**:

### Bug 1: UTF-8 stdout (Windows cp1251)

Upstream `rich.Console` (используется kb-lint для красивого вывода таблиц) пробует напечатать символы Unicode (`↔`, `✓`, `┌`) в Windows-консоль с charmap-encoding (cp1251 в России) и падает с `UnicodeEncodeError`.

**Fix:** wrapper reconfigure'ит stdout до импорта kb_lint:

```python
import sys

# Force UTF-8 stdout BEFORE kb_lint imports rich.Console
if hasattr(sys.stdout, "reconfigure"):
    sys.stdout.reconfigure(encoding="utf-8", errors="replace")

from kb_lint import cli      # safe to import now
```

`errors="replace"` гарантирует, что любой un-encodable символ заменится на `?`, а не упадёт.

### Bug 2: Cyrillic-stem rename (data loss risk)

`kb_lint.fixer.fix_filename_casing` использует regex:

```python
re.sub(r"[^a-z0-9]+", "-", stem.lower())
```

**ASCII-only character class** УНИЧТОЖАЕТ кириллицу и любые non-ASCII символы при `--fix`. Реальный инцидент **2026-05-13**: один запуск `kb-lint --fix docs/wiki/` переименовал/удалил **1 131 файл** и создал `docs/wiki/entities/.md` с пустым stem (`точек` → `-`-greedy → пусто).

**Fix:** wrapper monkey-patch'ит функцию:

```python
import kb_lint.fixer as fixer

_original_fix = fixer.fix_filename_casing

def _safe_fix_filename_casing(filename: str) -> str:
    stem, _, ext = filename.rpartition(".")
    if not stem.isascii():
        print(f"[wrapper] Skipping non-ASCII stem: {filename}", file=sys.stderr)
        return filename                         # leave unchanged
    return _original_fix(filename)

fixer.fix_filename_casing = _safe_fix_filename_casing
```

Production pre-commit вызывает только `--ci` режим, который НЕ дёргает `apply_fixes` — monkey-patch это **защита от ручного `python scripts/kb_lint_ci.py --fix`** запуска (e.g., developer запускает локально для cleanup).

## Запуск pre-commit

При обычном `git commit` запускается автоматически на staged `docs/wiki/**/*.md`:

```
$ git commit -m "docs(wiki): update overview"
...
Markdown Lint (wiki).....................................................Passed
KB Lint (wiki)...........................................................Passed
[branch abc1234] docs(wiki): update overview
```

При failure exit-code != 0 → commit заблокирован.

### Manual run

```bash
# Полная проверка docs/wiki/
.venv/Scripts/python scripts/kb_lint_ci.py

# Auto-fix safe issues (frontmatter ordering, ascii filenames только!)
.venv/Scripts/python scripts/kb_lint_ci.py --fix docs/wiki

# Show only ERROR-level (skip warnings)
.venv/Scripts/python scripts/kb_lint_ci.py | grep -E "^\│ E "
```

`scripts/kb_lint_ci.py --ci` (без path) — read-only check (no `--fix`), используется в pre-commit.

## Markdown Lint

Конфигурация: [`.markdownlint.yml`](../../../.markdownlint.yml) (project root). Стандартные rules:

- MD013 line length — disabled (long URLs and tables OK)
- MD033 inline HTML — disabled (use cases в kb-lint disable comments, HTML tables)
- MD041 first-line H1 — disabled (frontmatter сначала)
- остальные defaults

Triggered на `^docs/wiki/.*\.md$`. Параллельно с kb-lint.

## Common kb-lint issues и fixes

| Symptom | Cause | Fix |
|---|---|---|
| `Executable kb-lint not found` | Не установлен в `.venv` | `pip install kb-lint>=0.1.1` (уже в `pyproject.toml [project.optional-dependencies].dev`) |
| `UnicodeEncodeError '↔'` | Wrapper не вызван (прямой `kb-lint --ci`) | Использовать `python scripts/kb_lint_ci.py`, а не `kb-lint` напрямую |
| `yaml.constructor.ConstructorError 'found unhashable key'` | `{{placeholder}}` Mustache syntax в `templates/**.md` | Добавить `templates/**` в `ignore_patterns` в `.kblintrc.yml` |
| `Empty required field: unified_id` | Wiki page без `unified_id` в frontmatter | Сгенерировать UUID v7 через `scripts/patterns_fill_frontmatter.py` (utility script) |
| `Broken wiki-link: [[target]]` | `[[target]].md` не существует | Создать stub-page ИЛИ удалить ref ИЛИ `<!-- kb-lint-disable-next-line links -->` |
| `Broken wiki-link: []` (empty) | Literal `[[wiki-link]]` syntax demo в prose | Переписать чтобы не использовать `[[...]]` syntax в prose, или wrap в code-block-disabled context |
| `Invalid date format` | created_at: 'unknown' or invalid string | Provide valid ISO 8601 datetime |
| `Filename is not kebab-case: 'SCHEMA'` | Hub pages с uppercase (e.g., `SCHEMA.md`) | Existing convention для hub pages — per-file disable через `.kblintrc.yml` |

## kb-lint disable directives

В markdown теле можно отключить specific checks:

```markdown
<!-- kb-lint-disable-file links -->
<!-- All-page disable: for SCHEMA.md template syntax demos -->

<!-- kb-lint-disable-next-line links -->
See [[example-not-real-link]] for syntax demonstration only.

<!-- kb-lint-disable-line links -->
Inline disable on this same line: [[demo]]
```

Используется sparingly. Текущие use cases в repo:
- `SCHEMA.md` — `<!-- kb-lint-disable-file links -->` (содержит литеральные `[[wiki-link]]` syntax demos)

## CI integration

GitHub Actions workflow для CI runs (если настроен — см. `.github/workflows/`):

```yaml
- name: KB Lint
  run: |
    pip install kb-lint>=0.1.1
    python scripts/kb_lint_ci.py
```

Pre-commit hook покрывает локальные commits, CI workflow — pushed branches и PRs. Defense in depth.
