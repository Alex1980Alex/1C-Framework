# 32.8 Pre-commit и качество

Wiki содержимое контролируется на каждый commit через **2 pre-commit hook'а**:

1. **markdownlint-cli2** — общая валидация markdown синтаксиса, wiki-scoped конфиг
2. **kb-lint** (через wrapper `scripts/kb_lint_ci.py`) — YAML frontmatter, wiki-link integrity, structural checks

**Честная история проводки:** оба хука были описаны в этой главе, но **отсутствовали в `.pre-commit-config.yaml` до 2026-07-05** — wiki не гейтилась на commit вообще (аудит `docs/roadmap/260705_ROADMAP_MEMORY_DOCS_AUDIT.md` P0.1). Проводка восстановлена **вместе с фиксом писателей drafts** — `MemoryCube.to_wiki_page(status="draft")` (`src/memory/orchestrator/memcube.py:247`, писатели `wiki_promoter.py:165` и `memory_orchestrator.py:~2033`) стал эмитить непустой `tags` (fallback `["untagged"]`) и единственный trailing newline — без этого фикса восстановленный kb-lint сразу заблокировал бы существующие 11 drafts.

## Pre-commit конфиг (фактический фрагмент)

Реальный блок из [`.pre-commit-config.yaml`](../../../../.pre-commit-config.yaml):

```yaml
# markdownlint-cli2 — markdown validation, wiki-scoped (restored 2026-07-05,
# audit 260705 P0.1: the wiring documented in ch. 32.8 was missing — wiki was
# not gated on commit at all). entities/ excluded: 2800+ auto-generated
# LightRAG pages are data, not curated content (mirrors .kblintrc.yml).
- repo: https://github.com/DavidAnson/markdownlint-cli2
  rev: v0.18.1
  hooks:
    - id: markdownlint-cli2
      name: Markdown Lint (wiki)
      files: ^docs/wiki/.*\.md$
      exclude: ^docs/wiki/(entities/|log\.md)

# kb-lint — wiki frontmatter/structure validation (restored 2026-07-05, same
# P0.1). Wrapper defaults to `--ci docs/wiki` (bare --ci would lint from repo
# root!) and carries UTF-8 stdout + Cyrillic-rename + .gitignore-encoding
# safety patches. Draft writers emit `status: draft` since the same fix.
- repo: local
  hooks:
    - id: kb-lint
      name: KB Lint (wiki)
      entry: python scripts/kb_lint_ci.py
      language: system
      files: ^docs/wiki/.*\.md$
      pass_filenames: false
```

Оба hook'а scoped на `^docs/wiki/.*\.md$`; markdownlint дополнительно исключает `entities/` и `log.md` (auto-generated / append-only). kb-lint зовётся **без `pass_filenames`** и **без явных `args`** — wrapper сам подставляет `--ci docs/wiki`, если argv пуст (см. ниже).

## kb-lint: что валидирует

Конфигурация: [`docs/wiki/.kblintrc.yml`](../../../wiki/.kblintrc.yml) (актуальный контракт — сверено 2026-07-05):

| Параметр | Значение |
|---|---|
| `required_frontmatter` | `unified_id`, `status`, `tags`, `confidence` |
| `recommended_frontmatter` (не блокирует) | `related`, `created_at`, `updated_at`, `promoted_from` |
| `min_article_words` | 50 |
| `ignore_patterns` | `_templates/**`, `templates/**`, `archive/**`, **`entities/**`** (2800+ auto-generated LightRAG pages — данные, не курируемый контент), `.git/**`, `node_modules/**`, `.claude/**`, `src/**`, `tests/**`, `tools/**`, `scripts/**`, `features/**`, `data/**`, `build/**`, `tmp/**` |
| `checks` | `links`, `frontmatter`, `orphans`, `structure`, `consistency` |
| `severity_threshold` | `warning` |
| `recognized_directories` | `patterns`, `drafts`, `assets` |
| `allowed_confidence_levels` | текстовые бакеты `high`/`medium`/`low` **и** числовые строки `'0'`…`'1.0'` (шаг 0.1) — quoted как `str`, т.к. kb-lint 0.1.1 `frontmatter.py:99` делает `", ".join()` над списком и падает `TypeError` на `int`/`float` |

**Важно — `unified_id` НЕ требует формата UUID v7.** `.kblintrc.yml` проверяет только присутствие непустого поля; реальный формат, который эмитит `MemoryCube.to_wiki_page()`, — составной строковый ключ `{memory_type}:{source}:{cube_id}` (например `wiki:obsidian-vault:cfa51279-eae3-400d-9cf6-a7bba495f793`), не time-sortable UUID v7. Детали формата — [32.3 Storage и формат](32.3_Storage_и_формат.md).

`entities/**` в `ignore_patterns` означает, что kb-lint **не линтует** 2822 auto-export страницы — реальная поверхность enforcement — `drafts/`, `patterns/`, root hub-страницы.

### Config location quirk

kb-lint 0.1.1 читает config из **`<wiki_path>/.kblintrc.yml`** — **НЕ из project-root**. Каноническая локация: [`docs/wiki/.kblintrc.yml`](../../../wiki/.kblintrc.yml).

## Wrapper: scripts/kb_lint_ci.py

[`scripts/kb_lint_ci.py`](../../../../scripts/kb_lint_ci.py) — не просто encoding-фикс, а **три monkey-patch'а**, устанавливаемых до импорта `kb_lint.cli`:

### Патч 1: UTF-8 stdout (Windows cp1251)

`_reconfigure_utf8()` (`kb_lint_ci.py:32-40`) переключает `sys.stdout`/`sys.stderr` на `encoding="utf-8", errors="replace"` — иначе `rich.Console` падает `UnicodeEncodeError` на символах вроде `↔` в Windows-консоли с charmap-кодировкой.

### Патч 2: Cyrillic-safe filename rename

`_install_cyrillic_safety_patch()` (`kb_lint_ci.py:43-74`) подменяет `kb_lint.fixer.fix_filename_casing` — upstream-версия (`re.sub(r"[^a-z0-9]+", "-", stem.lower())`) уничтожает кириллицу при `--fix` (реальный инцидент: 1131 переименованный/удалённый файл, включая `entities/.md` с пустым stem). Патч делает no-op для любого non-ASCII stem, оставляя ASCII-стемы на upstream-реализации. Не активен в production pre-commit (`--ci` не вызывает `apply_fixes`), защищает только ручной `--fix`.

### Патч 3: `.gitignore`-encoding (новый, 2026-07-05)

`_install_ignore_spec_encoding_patch()` (`kb_lint_ci.py:77-104`) подменяет `kb_lint.scanner._build_ignore_spec` — upstream открывает `<wiki_path>/.gitignore` без явной кодировки (`scanner.py:39-44`), что на Windows/cp1251-локали крашится `UnicodeDecodeError` на любом UTF-8-содержимом **до сканирования хотя бы одной статьи**. Живой инцидент 2026-07-05: голый `--ci` (без явного `docs/wiki` пути) дефолтил `wiki_path` на **корень репозитория**, чей `.gitignore` с кириллическими комментариями убивал прогон на `scanner.py:41`. Патч читает `.gitignore` с `encoding="utf-8", errors="replace"`.

### Default path fallback

`kb_lint_ci.py:114-120` — если argv (после имени скрипта) пуст (ровно так вызывает pre-commit при `pass_filenames: false` без `args`), wrapper форсит `["--ci", "docs/wiki"]`. Без этого дефолта голый `--ci` линтил бы от корня репо (см. инцидент выше про `.gitignore`).

## Запуск pre-commit

При обычном `git commit` запускается автоматически на staged `docs/wiki/**/*.md`:

```
$ git commit -m "docs(wiki): update overview"
...
Markdown Lint (wiki).....................................................Passed
KB Lint (wiki)...........................................................Passed
[branch abc1234] docs(wiki): update overview
```

При failure exit-code != 0 → commit заблокирован.

### Manual run

```bash
# Полная проверка docs/wiki/ (тот же дефолт, что и pre-commit)
.venv/Scripts/python scripts/kb_lint_ci.py

# Явный путь / другие kb-lint флаги форвардятся как есть
.venv/Scripts/python scripts/kb_lint_ci.py --ci docs/wiki
.venv/Scripts/python scripts/kb_lint_ci.py --fix docs/wiki   # осторожно: см. Патч 2
```

## Markdown Lint (wiki-scoped конфиг)

Помимо корневого [`.markdownlint.jsonc`](../../../../.markdownlint.jsonc), с 2026-07-05 действует **wiki-scoped** [`docs/wiki/.markdownlint.jsonc`](../../../wiki/.markdownlint.jsonc), который `extends` корневой и дополнительно отключает правила, не гарантируемые машинно-сгенерированным контентом (drafts из `MemoryCube.to_wiki_page()`, LightRAG entity-экспорт):

```jsonc
{
  "extends": "../../.markdownlint.jsonc",
  "MD031": false, // blanks around fences — fences живут внутри stored payloads
  "MD012": false, // multiple blank lines — serialization artifact, harmless
  "MD022": false, // blanks around headings — тот же кейс, что MD031
  "MD034": false  // bare URLs — memory payloads несут raw ссылки рутинно
}
```

Triggered на `^docs/wiki/.*\.md$`, кроме `entities/` и `log.md` (см. exclude выше). Параллельно с kb-lint (kb-lint линтует `entities/**` тоже игнорирует через `.kblintrc.yml`).

## Common kb-lint issues и fixes

| Symptom | Cause | Fix |
|---|---|---|
| `Executable kb-lint not found` | Не установлен в `.venv` | `pip install kb-lint>=0.1.1` (dev-зависимость в `pyproject.toml`) |
| `UnicodeEncodeError '↔'` | Wrapper не вызван (прямой `kb-lint --ci`) | Использовать `python scripts/kb_lint_ci.py`, не `kb-lint` напрямую |
| `UnicodeDecodeError` на `.gitignore` | Голый `--ci` без пути линтит от корня репо | Не передавать `--ci` без пути вручную; wrapper дефолтит на `docs/wiki` |
| `Empty required field: unified_id/status/tags/confidence` | Wiki page без обязательного поля | Проверить писателя (`MemoryCube.to_wiki_page`) — required-набор см. `.kblintrc.yml` |
| `Broken wiki-link: [[target]]` | `[[target]].md` не существует | Создать stub-page ИЛИ удалить ref ИЛИ `<!-- kb-lint-disable-next-line links -->` |
| `Invalid date format` | `created_at`/`updated_at` не ISO 8601 | Provide valid ISO 8601 datetime |
| `Filename is not kebab-case` | Hub pages с uppercase (e.g., `SCHEMA.md`) | Per-file disable через `.kblintrc.yml`, если это намеренный hub |

## kb-lint disable directives

В markdown теле можно отключить specific checks:

```markdown
<!-- kb-lint-disable-file links -->
<!-- All-page disable: for SCHEMA.md template syntax demos -->

<!-- kb-lint-disable-next-line links -->
See [[example-not-real-link]] for syntax demonstration only.

<!-- kb-lint-disable-line links -->
Inline disable on this same line: [[demo]]
```

Используется sparingly. Текущий use case в repo:
- `SCHEMA.md` — `<!-- kb-lint-disable-file links -->` (содержит литеральные `[[wiki-link]]` syntax demos)
