## Что это

**Hermes / LLM Wiki** — инициатива по превращению PDF Framework из системы с **фрагментированной памятью** (4 подсистемы + 17 MCP-серверов + 75 skills, каждый со своим cache) в систему с **единым каноническим источником истины для знаний** в формате human-editable markdown в git.

Концепция основана на эссе Андрея Карпаты «LLM Wiki» (April 2026), где он предложил рассматривать знания LLM-агентов как обычную вики: иерархическую, git-versioned, immutable-by-design, с автоматической промоцией паттернов через confidence-decay.

В нашем фреймворке инициатива реализована в **7 фазах** (Ф0-Ф6), внедряющих **5-слойную модель памяти** с каноническим L3-слоем на markdown и derived L4-индексами в Qdrant/LightRAG.

## Бизнес-цель

> **Knowledge compound between sessions.** Каждая сессия обогащает wiki, каждый запрос использует накопленный опыт.

До инициативы каждая сессия фреймворка начиналась с нуля: memory из SQLite, паттерны из Qdrant, но никакого **накопления через сессии** не происходило. Confidence паттернов медленно decay'ил, но никогда не «графдуировался» в canonical wiki-страницы.

После Hermes:
1. **L2 → L3 промоция автомат** — паттерны с `confidence ≥ 0.8` и `application_count ≥ 5` промотируются в `docs/wiki/drafts/` через [`wiki_promoter.py`](../../../../src/memory/librarian/wiki_promoter.py).
2. **Git как версионирование знаний** — `git log docs/wiki/entities/X.md` показывает эволюцию понимания.
3. **Markdown как канонический источник** — Qdrant индексы становятся rebuildable cache. При повреждении (было на ChromaDB) — восстановление из wiki.
4. **Human-readable observability** — открыв `docs/wiki/` любой инженер видит «что знает фреймворк», без MCP-запроса.

## Мотивация — 5 проблем, которые решает

| # | Проблема (до) | Решение (после Hermes) |
|---|---|---|
| 1 | **Фрагментация знаний.** Факты живут в `memory_ai.db`, `learned_patterns`, `skill_library`, `experience_bank`, `MEMORY.md`, cache 11+ скиллов, `docs/architecture/`, `docs/roadmap/`. Дубликаты, противоречия. | `docs/wiki/` — единый L3 canonical store. Остальное — derived cache индексов или временный contextual state. |
| 2 | **Нет канонического источника.** Невозможно ответить «где живёт факт X?». При повреждении Qdrant теряются месяцы обучения. | Wiki в git — survivable. Qdrant — rebuildable. |
| 3 | **Knowledge compound не работает.** Паттерны умирают через confidence-decay, но никогда не graduate. | `wiki_promoter.py` промотирует с deduplication через `unified_search`, конфликты через `ConflictResolver`. |
| 4 | **Нет human-readable слоя.** Открыв Qdrant, невозможно понять «что знает фреймворк». | Markdown + Obsidian graph view → 604 .md в vault, 59 wiki-links. |
| 5 | **Git-history знаний отсутствует.** | Git diff/blame заменяют существующие `memory_version_*` tools для L3. |

## Ключевые принципы

**1. Markdown = источник истины.** Wiki-страницы в `docs/wiki/` — **canonical**. Qdrant-коллекции (`wiki_pages_v1`, `learned_patterns`, `skill_library`) — **rebuildable cache**. При повреждении индекса — пересборка из wiki через [`scripts/export_graph_to_wiki.py`](../../../../scripts/export_graph_to_wiki.py).

**2. Git = бесплатное versioning.** Wiki в git, `git log` / `git blame` заменяют необходимость в `memory_version_*` MCP tools для L3-слоя.

**3. Расширение, не переписывание.** Все 7 фаз построены на существующих компонентах: `MemoryCube`, `LinkRegistry`, `ConflictResolver`, `EventBus`, `PropagationEngine`, Phase 38 LightRAG, Phase 12.3 OAuth, `docs-change-tracker`, `HybridSearchService`. Новый код — ~1500-1800 LoC glue (фреймворк был на 85% готов после 5 проходов аудита).

**4. OSS-first.** Использует [Obsidian-MCP](https://github.com/MarkusPfundstein/mcp-obsidian) (3.3k⭐), [LightRAG](https://github.com/HKUDS/LightRAG) (33.1k⭐), [E2B code-interpreter](https://github.com/e2b-dev/code-interpreter), [LangSmith Sandboxes](https://www.langchain.com/blog/langsmith-sandboxes-generally-available) — production-tested, не наш велосипед.

**5. Brownfield-compatibility.** Существующие 4 memory subsystems (ai_memory, vector_memory, skill_learning, pdf_docs) работают без изменений. 26 тестов `test_memory_unified.py` + 288 тестов auth — должны оставаться зелёными.
