# 37.2 Архитектура 5-слойной памяти

> Главный архитектурный артефакт инициативы — иерархическая модель памяти L0-L4, где L3 (wiki) выступает каноническим источником истины, а L4 (Qdrant индексы) — rebuildable cache.

## Назначение каждого слоя

### L0 — Raw sources

**Содержание:** conversation transcripts, PDF binaries, git commit history, raw .md docs до миграции.

**Storage:** filesystem (`.claude/state/transcripts/`, `data/documents/`), git history.

**Properties:** immutable, ephemeral-ok (transcripts могут ротироваться), не индексируется напрямую.

**Use cases:** archive, audit trail, replay, source-of-truth для re-indexing.

### L1 — Episodic memory

**Содержание:** session summaries, important user messages, recent context (last 30-90 days).

**Storage:** SQLite `data/memory_ai.db`.

**Properties:** session-scoped, volatile (cleared via `cleanup_old_completed`), retrieved by recency + topic match.

**Хук:** [`session-memory-save.py`](../../../../.claude/hooks/session-memory-save.py) (Stop event) — capture session, save to SQLite, optionally trigger L2→L3 promotion via `try_promote_patterns()`.

**Tools:** `mcp__memory-ai__*` (search_messages, get_important_messages, save_important_message).

**RRF weight:** **0.30** в memory-first-hook v3.

### L2 — Semantic patterns

**Содержание:** Learned patterns с метаданными — confidence score, application count, last_applied, source (skill name / session id).

**Storage:**
- Qdrant collection `learned_patterns` (4096d Qwen3 эмбеддинги)
- JSONL log `data/skill_learning/` (incremental capture events)

**Properties:** confidence-weighted (Beta(7,3) posterior: `confidence = (7+succ)/(10+succ+fail)` над decayed счётчиками succ/fail — §22, [`confidence.py`](../../../../src/memory/vector_memory/confidence.py); prior mean 0.70), application_count incrementing per successful retrieve+apply, count-decay по времени отсутствия применения.

**Хук:** `mcp__skill-learning__capture_pattern` (явный вызов) + автоматический capture из Stop hook.

**Tools:** `mcp__vector-memory__*` (save_pattern, apply_pattern, search_patterns, decay_confidence).

**RRF weight:** **0.35** (доминирующий в hybrid search).

### L3 — Wiki (canonical)

**Содержание:** Promoted high-confidence knowledge — entities, concepts, procedures, patterns. Каждая страница — markdown с YAML frontmatter (unified_id, source, tags, related links).

**Storage:**
- `docs/wiki/` directory
- Sub-directories: `entities/`, `concepts/`, `procedures/`, `patterns/`, `auth/`, `drafts/`, `templates/`
- Plus migrated: `docs/architecture/*.md` (8 файлов с frontmatter), `docs/roadmap/`

**Properties:** **canonical** (источник истины), human-editable, git-versioned, Obsidian-compatible (graph view, [[wiki-links]]), kb-lint validated (pre-commit hook).

**Sub-layer L5 (drafts):** `docs/wiki/drafts/` — pending promotion candidates требующие human review. Считаются L3 в hybrid search (shared weight 0.20), но не считаются canonical для `entities/`.

**Хук:** [`docs-change-tracker.py`](../../../../.claude/hooks/docs-change-tracker.py) (PostToolUse on Write/Edit в docs/wiki/) — kb-lint validation + auto-index в `wiki_pages_v1`.

**Tools:** `mcp__obsidian-mcp__*` (read/write/search wiki через REST API plugin).

**RRF weight:** **0.20** (`LAYER_WEIGHTS["wiki"]` в `memory-first-hook.py`, узкий слой, высокая precision). **⚠ Честность:** в текущем коде `search_wiki()` — stub, всегда возвращает `[]` (полная реализация token-overlap по `docs/wiki/drafts/` + опциональный semantic через `wiki_pages_v1` отложена); слой участвует в RRF-формуле, но фактически не даёт хитов.

### L4 — Indexes (derived, rebuildable)

**Содержание:** Vector embeddings + entity graph для L3 wiki + L2 patterns + дополнительные коллекции framework_code, bsl_code, pdf_documents.

**Storage (Qdrant коллекции на 2026-05-15 после Phase 8+9.1):**

| Коллекция | Points | Dim | Источник |
|---|---|---|---|
| `bsl_code_v4_late` | 24 455 | 4096 | BSL methods (Late Chunking) |
| `bsl_code_v4` | 24 455 | 4096 | BSL methods (standard) |
| `framework_code_v1` | 21 277+ | 4096 | Python code (auto-reindex on commit) |
| `graph_embeddings` | 6 694 | 4096 | LightRAG entity nodes |
| `wiki_pages_v1` | **3 073** | **4096** | **L3 wiki pages** (NEW) |
| `pdf_documents` | 830 | 4096 | PDF chunks |
| `skill_library` | 80 | 4096 | 75 skills (Phase 9.1) |
| `learned_patterns` | 44 | 4096 | L2 patterns |
| `experience_embeddings` | 0 | 4096 | ready for auto-populate |
| `conversation_memory` | 0 | 4096 | ready for auto-populate |

**Embedding backend:** TEI HTTP service на Qwen3-Embedding-8B (см. [chapter 31](../../2_КОНТЕКСТ/2.8_QWEN3_RETRIEVAL_PRODUCTION/31.1_Обзор.md)).

**Properties:** **rebuildable** — можно полностью пересоздать из L0/L1/L3 через `scripts/reindex_*.py`. Auto-reindex on git commit для `framework_code_v1` и `bsl_code_v4*`.

**RRF weight в memory-first-hook.py:** этот широкий Indexes-тир (multi-collection, `unified_search`) **не является** 4-м взвешенным слоем хука — хук его не вызывает. Реальный 4-й слой `LAYER_WEIGHTS["md"] = 0.15` — token-overlap поиск по персональным `.md`-файлам памяти (`search_md()`, каталог `~/.claude/projects/<project>/memory/*.md`), контентно не связанный с этой Qdrant-таблицей.

## RRF Reciprocal Rank Fusion

[`memory-first-hook.py`](../../../../.claude/hooks/memory-first-hook.py) **синхронно** (без async/await, `BaseHook` — один процесс на UserPromptSubmit) вычисляет 4 слоя и сливает результаты через RRF (`LAYER_WEIGHTS`, строка ~102):

```
score(item) = Σ_layer (weight_layer × 1 / (k + rank_layer(item)))

где:
  weight_sqlite = 0.30  (L1, episodic)
  weight_qdrant = 0.35  (L2, semantic patterns) — dominant
  weight_wiki   = 0.20  (L3, wiki canonical — STUB, см. выше)
  weight_md     = 0.15  (L4, user .md memory files, narrow high-precision)
  k = 60  (RRF constant, dampens long tail)
```

**Поиск работает так (реально, без MCP-вызовов — прямые in-process функции):**

1. User submits prompt
2. memory-first-hook последовательно вызывает:
   - L1: `search_sqlite(query_tokens)` — прямой SQL SELECT по `data/memory_ai.db`
   - L2: `search_qdrant(query_tokens, prompt)` — гибридный RRF (TEI dense + lexical) по `skill_library`+`learned_patterns` через `qdrant_client`
   - L3: `search_wiki(query_tokens)` — **stub, всегда `[]`**
   - L4: `search_md(query_tokens)` — token-overlap по персональным `.md` файлам (`MEMORY_DIR`)
3. RRF fusion → top-`MAX_RESULTS` (5) items, инъекция через **stdout** (не `hookSpecificOutput`/`systemMessage`)
4. Claude отвечает с обогащённым контекстом

## Bidirectional sync между L3 и L4

```
                  Forward sync (L3 → L4)
            ┌────────────────────────────────┐
            │                                ▼
docs/wiki/entities/X.md          Qdrant wiki_pages_v1
            ▲                                │
            │                                │
            └────────────────────────────────┘
                  Reverse sync (L4 → L3)
                  (только entity graph, не embeddings)
```

**Forward sync (L3 → L4, через `wiki_exporter.py`):**

1. `IncrementalWikiSync` слушает events от `IncrementalGraphUpdater`
2. Affected entity → `WikiExporter.export_entity(entity_id)` → `MemoryCube.to_wiki_page()` → markdown
3. `docs-change-tracker` детектит новую/изменённую `.md` → запускает kb-lint + auto-index в Qdrant `wiki_pages_v1`

**Reverse sync (L3 → graph, через `ReverseSyncService` watchdog):**

1. Watchdog мониторит `docs/wiki/entities/<id>.md`
2. На Write event → `MemoryCube.from_wiki_page()` parse → diff с current graph state
3. Apply diff к LightRAG entity graph
4. DLQ (dead-letter queue) для failed parses

Подробности — [37.5 Write Path и Promotion](37.5_Write_Path_и_Promotion.md).

## L2 → L3 Promotion (auto-librarian)

[`wiki_promoter.py`](../../../../src/memory/librarian/wiki_promoter.py) — thin wrapper над существующими компонентами.

**Алгоритм:**

```python
async def scan_and_promote(confidence_threshold=0.8, usage_threshold=5):
    # 1. Query learned_patterns где confidence >= 0.8 AND application_count >= 5
    candidates = await vector_memory.search_patterns(
        filter={"confidence__gte": 0.8, "application_count__gte": 5}
    )

    for pattern in candidates:
        # 2. Deduplication через unified_search
        existing = await orchestrator.unified_search(
            query=pattern.content, targets=["wiki"], limit=3
        )
        if existing and existing[0].similarity >= 0.85:
            # 3. Conflict resolution
            resolved = await ConflictResolver.resolve(
                existing=existing[0], incoming=pattern,
                strategy=SOURCE_PRIORITY,
            )
            await link_registry.create_link(
                pattern.id, existing[0].id, type=LinkType.SUPERSEDED_BY
            )
            continue

        # 4. Promote: pattern → MemoryCube → markdown draft
        # (реальный код зовёт конструктор MemoryCube(content=..., title=..., ...);
        #  метода MemoryCube.from_pattern НЕ существует — см. wiki_promoter._create_draft)
        cube = MemoryCube(content=pattern.content, title=pattern.title,
                          content_type=ContentType.WIKI, confidence=pattern.confidence)
        draft_path = WIKI_DIR / "drafts" / f"{slugify(pattern.title)}.md"
        draft_path.write_text(cube.to_wiki_page(), encoding="utf-8")

        # 5. Link tracking
        await link_registry.create_link(
            pattern.id, draft_path.as_uri(), type=LinkType.PROMOTED_TO
        )

        # 6. Event for downstream (indexer, audit log)
        await event_bus.publish("wiki.promoted", {
            "pattern_id": pattern.id, "draft_path": str(draft_path),
        })
```

Trigger — после `session-memory-save.py:try_promote_patterns()` (subprocess timeout 4s, opt-out `SESSION_MEMORY_NO_PROMOTE=1`).

## Восстанавливаемость (resilience)

**Если потеряется Qdrant** (было на ChromaDB пару раз):

```bash
# Восстановить L4 индексы из L3 + git
python scripts/reindex_wiki.py                # wiki_pages_v1 из docs/wiki/
python scripts/reindex_framework_code.py     # framework_code_v1 из src/
python scripts/reindex_bsl.py --strategy=late # bsl_code_v4_late из BSL
python -m src.memory.skill_learning.replay   # learned_patterns из JSONL log
```

**Если потеряется L3 (`docs/wiki/`):**

```bash
# Восстановить из git
git checkout docs/wiki/

# Re-promote L2 → L3 (паттерны заново станут drafts)
python scripts/export_graph_to_wiki.py promote-patterns
```

**Если потеряются скиллы (`.claude/skills/`):**

```bash
git checkout .claude/skills/
# Re-index skill_library через session-memory-save.py
```

**Что НЕ восстановимо:**
- L0 transcripts (могут быть ротированы)
- L1 SQLite (если файл удалён + нет backup — потеряны session summaries)

L3 (markdown в git) — единственный слой который **survives любой data loss** в Qdrant/SQLite.
