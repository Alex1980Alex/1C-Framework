# 37.5 Write Path и Promotion — как знания попадают в L3

> **⚠ ARCHIVED-хроника (заморожена 2026-07-05, аудит 260705 R2).** Глава 5.3 (Hermes LLM Wiki) — историческая хроника инициативы. **Актуальное состояние wiki-слоя — глава 5.2 ([32.1 Обзор](../5.2_WIKI_KNOWLEDGE_LAYER/32.1_Обзор.md))**; при расхождении (в т.ч. нумерации слоёв) канон = 32.x. > При каждом Stop event происходит capture L1+L2, а periodic'но (после каждой N сессий) — L2 → L3 промоция. Reverse sync обеспечивает что edits в wiki синхронизируются с graph. **Актуальная детальная механика write-пути** — канон-главы [32.4 Forward Sync](../5.2_WIKI_KNOWLEDGE_LAYER/32.4_Forward_Sync.md), [32.5 Reverse Sync](../5.2_WIKI_KNOWLEDGE_LAYER/32.5_Reverse_Sync.md), [32.6 L2 → L5 Promotion](../5.2_WIKI_KNOWLEDGE_LAYER/32.6_L2_L5_Promotion.md). Ниже — краткая историческая схема pipeline (Hermes-эпоха, для контекста).

## Краткий pipeline (историческая схема)

```
Session ends → Stop hook fires
       │
       ├──► session-memory-save.py
       │       │
       │       ├──► save_session_to_sqlite(L1)
       │       │       └─ data/memory_ai.db
       │       │
       │       ├──► capture_patterns_to_qdrant(L2)
       │       │       └─ mcp__skill-learning__capture_pattern
       │       │       └─ Qdrant learned_patterns
       │       │
       │       └──► try_promote_patterns()        ←─── L2 → L3 trigger
       │               │ detached subprocess.Popen (fire-and-forget,
       │               │   лог .claude/cache/session-promote.log)
       │               │ opt-out SESSION_MEMORY_NO_PROMOTE=1
       │               │
       │               └──► python -m scripts.export_graph_to_wiki promote-patterns
       │                       │
       │                       └──► WikiPromoter.scan_and_promote()
       │                               │
       │                               ├──► filter: confidence>=0.8, application_count>=5
       │                               ├──► F13: skip если source-точка уже несёт promoted_to
       │                               ├──► dedup: cosine>=0.85 против learned_patterns
       │                               ├──► MemoryCube.to_wiki_page(status="draft")
       │                               ├──► write docs/wiki/drafts/<slug>.md
       │                               ├──► set_payload(promoted_to=slug) на source-точке (F13)
       │                               ├──► link_registry.create_link(PROMOTED_TO)
       │                               └──► event_bus.publish("wiki.draft.created")
       │
       └──► docs-change-tracker.py (PostToolUse on new .md в wiki)
               │
               └──► kb-lint validation + auto-index to Qdrant wiki_pages_v1
```

## L2 → L3 promotion (auto-librarian)

Trigger (`try_promote_patterns()` в Stop-хуке), полный `WikiPromoter.scan_and_promote()` алгоритм (scroll+filter → dedup cosine≥0.85 → `_create_draft` → log entry), Beta(7,3) confidence math и decay-модели, field-name history, CLI subcommand, manual promotion workflow — детально и **актуально** описаны в канон-главе **[32.6 L2 → L5 Promotion](../5.2_WIKI_KNOWLEDGE_LAYER/32.6_L2_L5_Promotion.md)** (эта глава заменяет устаревший pseudocode ранних версий этого документа, который описывал API, не совпадающий с реальным `wiki_promoter.py` — например, `ConflictResolver`/`vector_memory.search_patterns` в качестве промежуточного слоя не существуют в текущей реализации).

## Antipatterns

| Плохо | Почему | Как правильно |
|---|---|---|
| Прямой Write в `docs/wiki/entities/` без frontmatter | kb-lint падает, файл не индексируется | Используй template или `MemoryCube.to_wiki_page()` |
| `confidence_threshold=0.5` для промоции | Слишком много low-quality drafts в wiki | Default 0.8 — keep it |
| Игнорировать `wiki.promoted` events | Downstream consumers (indexer, audit) пропускают новые drafts | Subscribe через `event_bus.subscribe()` |
| Удалить draft без `SUPERSEDED_BY` link | Теряется audit trail откуда пришёл | Создать link через `link_registry` или mark deprecated |
