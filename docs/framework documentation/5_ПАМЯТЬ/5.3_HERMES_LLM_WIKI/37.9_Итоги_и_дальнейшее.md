## 23 deferred items — детальный breakdown

### Phase 2.1 — DSPy RAGAS eval (1 task)

**Что:** Eval-сравнение метрик до/после DSPy migration трио (grader/rewriter/hallucination_check).

**Почему отложено:**
- Требует `pip install dspy-ai` (не установлен в `.venv`)
- Требует benchmark dataset (RAGAS golden set)
- Unit-тесты 115 pass подтверждают отсутствие code-level регрессий — функционально работает

**Когда вернуться:** при первом case где DSPy migration вызывает функциональное сомнение, или при выделении дня на formal eval.

### Phase 3 — IncrementalGraphUpdater integration (1 task)

**Что:** Реэкспорт только affected entities из LightRAG через events.

**Почему отложено:** Блокирован Phase 4 wiki_exporter hookup — нужна интеграция между `IncrementalGraphUpdater` и `IncrementalWikiSync`, не landed.

**Workaround:** Bulk export через `scripts/export_graph_to_wiki.py export --all` работает (медленнее, но корректно).

**Когда вернуться:** при первом complaint о latency инкрементальной синхронизации.

### Phase 4 — PDF audit + eval + acceptance criteria (7 tasks)

**Что:**
- Аудит существующего Phase 38 на 3 тестовых PDF (baseline)
- Eval-регрессия GraphRAG suite
- 5 acceptance criteria (≥3 pages/PDF, ≥95% schema validation, ≥80% precision, `wiki_pages_v1` populated, ≥10% retrieval improvement)

**Почему отложено:** Требует:
- Реальный PDF prod run (data + время)
- Curated test set
- Metrics infrastructure setup

**Когда вернуться:** перед production launch для customer-facing PDFs.

### Phase 5 — Sandbox integration в research-skills (1 task)

**Что:** Подключить `select_backend()` в `architecture-research` / `tech-research` для исполнения prototype-кода.

**Почему отложено:** Skills сейчас не генерируют код для execution. Integration без реального usage — premature.

**Когда вернуться:** когда research-skill захочет valid'ировать API через mini-prototype (например, проверить что `tenacity` retry с конкретными params работает как ожидается).

## Что бы сделал по-другому

### Что прошло хорошо

1. **Brownfield principle.** Расширение существующих компонентов вместо переписывания сэкономило ~7000 LoC.
2. **OSS-first.** Obsidian-MCP, LightRAG, E2B, LangSmith Sandboxes — production-tested. Не наш велосипед.
3. **5 проходов аудита перед implementation** — обнаружили что фреймворк на 85% готов, изначальный roadmap (15-18 недель) сокращён до 3-4 недель.
4. **Atomic phases.** Каждая фаза независима — Ф5 и Ф6 параллелились, Ф3 не блокировала Ф4.
5. **Sprint 1+2 structure.** OAuth Sprint 1 (wrapper + audit + setup) → Sprint 2 (FastAPI router) — incremental rollout снижает риск.

### Что бы изменил

1. **Phase 4 acceptance criteria** должны были включать synthetic PDF eval, а не только real production PDFs. Сейчас они blocked на «real data» что отодвигает закрытие неопределённо.
2. **Ф6 §3.7 spec scope creep.** Изначальный roadmap указывал «3-4 недели» для OAuth, но фактически — 1 sprint Sprint 1 (2-3ч) + 1 Sprint 2 (3-4ч) = ~6-7ч активной работы. Roadmap audit pattern из memory `project_roadmap_audit_pattern.md` подтверждается: «260509 roadmap'ы переоценивают scope 1.5-3×».
3. **Sandbox integration в research-skills** — лучше landed бы вместе с F1/F2, чтобы dogfood'ить сразу.

### Уроки на будущее

- **Inventory audit перед execution = mandatory.** Найти что уже сделано до начала — экономит дни.
- **Architecture finding mid-implementation OK.** F5.2 архитектурный поворот (stdio not OAuth-applicable → reusable FastAPI router) сделан в процессе работы — это нормально для greenfield.
- **Auto-git-save может опередить parent commit.** Подтверждено в memory `feedback_auto_git_save_preempt.md`. Каждый Edit/Write автоматически коммитится; explicit commit может оказаться no-op.

## Метрики которые валидируют initiative ROI

После 3 месяцев production usage можно будет ответить:

- **Knowledge compound rate:** сколько новых wiki entries в месяц? Сколько L2→L3 promotions per week?
- **Recovery time:** при следующем Qdrant incident — сколько занимает rebuild из wiki?
- **Cross-session leverage:** % запросов где L3 wiki попадает в top-5 RRF results?
- **Wiki edits as canonical source:** сколько human edits в `docs/wiki/entities/` per week (signals adoption)?

Эти metrics определят, оправдала ли себя 5-слойная модель в production.
