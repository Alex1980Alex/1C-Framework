# 15.3 Code Review Enforcer — обязательный self-review

> PostToolUse хук: после КАЖДОГО Write/Edit кода — обязательная самопроверка.
> THOROUGH для production, BASIC для остального кода. Non-code файлы пропускаются.

---

## Обзор

Code Review Enforcer гарантирует, что ни одно изменение кода не останется без ревью — ни собственный код Opus, ни результаты ревью черновиков Z.AI.

```
Write/Edit файл → code-review-enforcer.py (PostToolUse)
                  │
                  ├─ file_path пустой? → пропуск
                  │
                  ├─ Расширение в _CODE_EXTENSIONS? ─ НЕТ → пропуск
                  │   (.py .js .ts .bsl .os .java .go .rs .rb .php
                  │    .c .cpp .h .hpp .sh .bash .ps1 .jsx .tsx)
                  │
                  ├─ Путь в _SKIP_PATTERNS? ─ ДА → пропуск
                  │   (.claude/cache/, .claude/data/, __pycache__,
                  │    node_modules/, .git/, data/*.json, data/*.db, .env)
                  │
                  ├─ Путь в _HARD_PATH_PATTERNS?
                  │   (src/, tools/, infra/, scripts/)
                  │   │
                  │   ├─ ДА → [CODE-REVIEW: THOROUGH]
                  │   │        5 чекпоинтов, 3-5 строк summary
                  │   │
                  │   └─ НЕТ → [CODE-REVIEW: BASIC]
                  │             2 чекпоинта, 1-2 строки
                  │
                  └─ Всегда continue=true (не блокирует, advisory)
```

---

## Два уровня ревью

### THOROUGH (production code)

Срабатывает для файлов в: `src/`, `tools/`, `infra/`, `scripts/`

Чеклист:
- [ ] **Logic correctness** — условия, циклы, возвраты
- [ ] **Edge cases** — None, empty, 0, граничные значения
- [ ] **Security** — injection, hardcoded secrets, input validation
- [ ] **Project patterns** — async-first, provider pattern
- [ ] **Error handling** — нет silent except

Пример output:
```
Wrote `parser.py:45-60`. Review:
- Logic: regex matches both EN/RU keywords — OK
- Edge: empty file returns [] — OK
- Security: no user input in regex — OK
- Patterns: BaseHook inheritance — OK
- Errors: BaseHook.run() wraps — OK
```

### BASIC (non-production code)

Срабатывает для всех остальных code-файлов (тесты, конфиги, скрипты вне `scripts/`).

Чеклист:
- [ ] **Logic correct?** Edge cases handled?
- [ ] **Naming consistent?** No copy-paste errors?

Пример output:
```
Edited `test_search.py`. Review: logic OK, assertions match expected.
```

---

## Что пропускается

| Категория | Примеры | Причина |
|-----------|---------|---------|
| Non-code файлы | `.md`, `.json`, `.yml`, `.toml`, `.env` | Не программный код |
| Cache/data | `.claude/cache/`, `.claude/data/`, `data/*.db` | Автогенерируемые |
| Build artifacts | `__pycache__`, `.pyc`, `node_modules/` | Не исходный код |
| Git | `.git/` | Системные файлы |

## Конфигурация

### Расширения кода (полный список)

```python
_CODE_EXTENSIONS = {
    ".py", ".js", ".ts", ".jsx", ".tsx",   # Python, JavaScript, TypeScript
    ".bsl", ".os",                          # 1С:Предприятие
    ".java", ".go", ".rs", ".rb", ".php",   # JVM, Go, Rust, Ruby, PHP
    ".c", ".cpp", ".h", ".hpp",             # C/C++
    ".sh", ".bash", ".ps1",                 # Shell, PowerShell
}
```

### Production пути

```python
_HARD_PATH_PATTERNS = [
    r"src/",       # Основной код фреймворка
    r"tools/",     # Инструменты (auto-documenter, bsl-debugger)
    r"infra/",     # Инфраструктура (lazy-mcp, docker)
    r"scripts/",   # Скрипты (eval, dashboard, ralph)
]
```

### Регистрация в settings.json

```json
{
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "Write|Edit",
        "hooks": [
          {
            "type": "command",
            "command": "D:/1С-Framework/.venv/Scripts/python.exe D:/1С-Framework/.claude/hooks/code-review-enforcer.py",
            "timeout": 3
          }
        ]
      }
    ]
  }
}
```
