# 21.1 LLM Rotation Service — обзор

> Мульти-провайдерный сервис для LLM-запросов с автоматической ротацией провайдеров, circuit breaker и бюджетным трекингом.

---

## Назначение

Сервис решает три задачи:

1. **Отказоустойчивость** — автоматический fallback при недоступности провайдера
2. **Экономия бюджета** — приоритизация дешёвых провайдеров, трекинг расходов
3. **Соблюдение лимитов** — rate limiting (RPM) и адаптивный скоринг

## Архитектура

```
┌─────────────────────────────────────────────────────────────┐
│                     LLMRotationService                      │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  complete(prompt, ...)                                      │
│      │                                                      │
│      ▼                                                      │
│  ┌───────────────────────────────────────────────────────┐  │
│  │  Phase 1: Force-Primary Retry                         │  │
│  │  ├── Попытка: primary provider (claude-cli-haiku)     │  │

│  │  └── Повтор: primary_max_retries раз                  │  │

│      │ (все попытки неудачны)                               │
│      ▼                                                      │
│  ┌───────────────────────────────────────────────────────┐  │
│  │  Phase 2: Fallback Rotation                           │  │
│  │  ├── Выбор: по приоритету + AdaptiveScorer            │  │
│  │  ├── Проверка: CircuitBreaker + ProviderRateLimiter   │  │
│  │  ├── Model-level failover (альтернативная модель)     │  │
│  │  └── Учёт: BudgetTracker                              │  │
│  └───────────────────────────────────────────────────────┘  │
│                                                             │
├─────────────────────────────────────────────────────────────┤
│  CircuitBreaker | BackoffStrategy | AdaptiveScorer          │
│  BudgetTracker  | ProviderRateLimiter                       │
└─────────────────────────────────────────────────────────────┘
```

## Провайдеры по умолчанию

`DEFAULT_PROVIDERS` (`service.py`) — ровно 4 провайдера, cleanup 2026-05-16 (roadmap 260509 §2.2) убрал устаревший набор из 7 HTTP-провайдеров (zai-glm5/zhipu/gemini/openrouter/mistral/ollama-cloud):

| # | Имя | Модель | Формат API | RPM | requires_key | Особенность |
|---|-----|--------|-----------|-----|---------------|-------------|
| 0 | claude-cli-haiku | haiku | claude-cli (subprocess) | -- (subscription quota) | нет | Основной (`primary_provider` default), самый быстрый CLI |
| 1 | claude-cli-sonnet | sonnet | claude-cli (subprocess) | -- (subscription quota) | нет | Выше качество, тот же CLI-канал |
| 2 | ollama-local | qwen2.5-coder:7b | ollama | -- | нет | Локальный offline, $0 |
| 3 | anthropic-sonnet | claude-sonnet-4-6 | anthropic | 50 | да (`ANTHROPIC_API_KEY`) | Paid-API escape hatch — пропускается, если ключ не задан |

> Сноска: в этом репо `.mcp.json` задаёт env `LLM_ROTATION_PRIMARY_PROVIDER=zai-glm5` (+ `DEEP_REASONING_MODEL=glm-5`), что переопределяет `primary_provider` для деплоя — но `zai-glm5` **не входит** в `DEFAULT_PROVIDERS` кода. Это рассинхрон деплой-конфига с дефолтами кода, а не дефолт самого сервиса.

## Двухфазный алгоритм complete()

### Phase 1: Force-Primary Retry

- Попытки выполнить запрос на основном провайдере (`primary_provider`)
- Количество повторов: `primary_max_retries=2`
- Задержка между попытками: экспоненциальный backoff с jitter
- При успехе — возврат результата, при неудаче — переход к Phase 2

### Phase 2: Fallback Rotation

- Перебор провайдеров по приоритету (от низкого индекса к высокому)
- Проверка состояния CircuitBreaker и лимитов ProviderRateLimiter
- **Model-level failover**: при transient error (timeout, 429, 5xx) попытка альтернативной модели того же провайдера
- Выбор провайдера с учётом AdaptiveScorer (история успехов/неудач)

### Auto-timeout

Таймаут выбирается автоматически по `max_tokens`:

| max_tokens | Таймаут |
|------------|---------|
| <= 1024 | 90s (`timeout`) |
| <= 3000 | 120s (`timeout_generation`) |
| > 3000 | 240s (`timeout_heavy`) |
