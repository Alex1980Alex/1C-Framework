# 21.2 Circuit Breaker

> Паттерн, предотвращающий каскадные сбои путём временной блокировки запросов к недоступному провайдеру.

---

## Паттерн Circuit Breaker

Circuit Breaker (автоматический выключатель) -- механизм защиты от повторных запросов к сервису, который временно недоступен. В контексте LLM API это критично: повторные запросы к упавшему провайдеру увеличивают latency и могут усугубить проблему (thundering herd).

Реализация: `src/shared/llm_rotation/circuit_breaker.py`.

## Три состояния

```
                  fail_threshold
            ┌──────────────────────┐
            │                      v
        ┌───────┐             ┌──────┐
        │CLOSED │             │ OPEN │
        └───────┘             └──────┘
            ^                     │
            │                     │ reset_timeout
            │ success_threshold   │
            │                     v
        ┌───────────┐        ┌─────────┐
        │  CLOSED   │<───────│HALF_OPEN│
        └───────────┘        └─────────┘
                                  │
                                  │ ошибка
                                  v
                             ┌──────┐
                             │ OPEN │
                             └──────┘
```

| Состояние | Поведение |
|-----------|-----------|
| **CLOSED** | Нормальная работа. Все запросы проходят. Счётчик ошибок сбрасывается при успехе. |
| **OPEN** | Провайдер заблокирован. Запросы отклоняются немедленно (fast fail) без обращения к API. |
| **HALF_OPEN** | Тестирование восстановления. Пропускается один probe-запрос для проверки доступности. |

**Переходы:**

- `CLOSED -> OPEN`: после `fail_threshold` последовательных ошибок
- `OPEN -> HALF_OPEN`: после `reset_timeout` секунд
- `HALF_OPEN -> CLOSED`: после `success_threshold` успешных probe-запросов
- `HALF_OPEN -> OPEN`: при любой ошибке во время probe

## API

### Конструктор

```python
CircuitBreaker(
    fail_threshold: int = 3,
    success_threshold: int = 1,
    reset_timeout: float = 60.0,
)
```

### Методы

| Метод | Описание |
|-------|----------|
| `can_execute() -> bool` | Проверяет, разрешён ли запрос. `True` в CLOSED и HALF_OPEN, `False` в OPEN (пока не истёк timeout). |
| `record_success()` | Регистрирует успешный запрос. В HALF_OPEN увеличивает счётчик probe. В CLOSED сбрасывает fail_count. |
| `record_failure()` | Регистрирует ошибку. При достижении порога -- переход в OPEN. В HALF_OPEN -- немедленно в OPEN. |
| `force_open(reset_timeout=None)` | Немедленный переход в OPEN. Используется при HTTP 429 (rate limit). Опционально переопределяет timeout. |
| `reset()` | Принудительный сброс в CLOSED. Обнуляет все счётчики. |

## Интеграция с ProviderState

Каждый провайдер имеет собственный экземпляр `CircuitBreaker`:

```python
ProviderState(
    config=cfg,
    circuit_breaker=CircuitBreaker(
        fail_threshold=settings.cb_fail_threshold,
        success_threshold=settings.cb_success_threshold,
        reset_timeout=settings.cb_reset_timeout,
    ),
)
```

**Взаимодействие:**

- `ProviderState.record_error()` -- при `429` вызывает `force_open(rate_limit_cooldown=60)`, иначе `record_failure()`
- `ProviderState.is_available()` -- делегирует на `circuit_breaker.can_execute()`

**Маппинг состояний CircuitState -> ProviderStatus:**

| CircuitState | ProviderStatus |
|--------------|----------------|
| CLOSED (fail_count=0) | HEALTHY |
| CLOSED (fail_count>0) | DEGRADED |
| OPEN | COOLDOWN |
| HALF_OPEN | DEGRADED |

## Конфигурация

| Параметр | Переменная окружения | Default | Описание |
|----------|---------------------|---------|----------|
| `cb_fail_threshold` | `LLM_ROTATION_CB_FAIL_THRESHOLD` | 3 | Ошибок для перехода в OPEN |
| `cb_success_threshold` | `LLM_ROTATION_CB_SUCCESS_THRESHOLD` | 1 | Успешных probe для CLOSED |
| `cb_reset_timeout` | `LLM_ROTATION_CB_RESET_TIMEOUT` | 60.0 | Время в OPEN (секунды) |

## Пример работы

Timeline с `fail_threshold=3`, `reset_timeout=60`:

```
t=0    запрос -> 200 OK                    [CLOSED, fail_count=0]
t=1    запрос -> 500 error                 [CLOSED, fail_count=1]
t=2    запрос -> 500 error                 [CLOSED, fail_count=2]
t=3    запрос -> 500 error                 [CLOSED -> OPEN, fail_count=3]
t=4    запрос -> rejected (fast fail)      [OPEN]
...    ...                                 [OPEN]
t=63   запрос -> rejected (fast fail)      [OPEN]
t=64   reset_timeout истёк                 [OPEN -> HALF_OPEN]
t=64   probe-запрос -> 200 OK              [HALF_OPEN -> CLOSED]
t=65   запрос -> 200 OK                    [CLOSED, fail_count=0]
```

При ошибке в HALF_OPEN цепь немедленно возвращается в OPEN с новым отсчётом `reset_timeout`.
