# 42.3 Запуск Monitor и примеры

Examples и cookbook для типовых watch-сценариев.

## Comprehensive CI watcher (current production version, 2026-05-26)

Priority-tagged + auto-cache integration. Replaces legacy version `bhlaxqp3s` / `bkozphbx9`. Spawn as `Monitor` tool в Claude session.

```bash
prev="" ; while true ; do {
  gh pr list --state open --json number,title,statusCheckRollup \
    --jq '.[] | . as $pr | (.statusCheckRollup[]? |
      select(.conclusion == "FAILURE" or .conclusion == "SUCCESS" or .conclusion == "TIMED_OUT" or .conclusion == "CANCELLED") |
      select(.name | test("YAxUnit|BSL Static|BDD Tests") | not) |
      "[P1-PR] PR#\($pr.number) [\($pr.title[:30])] \(.name|gsub(" *\\\\(.*\\\\)";""))=\(.conclusion)")' 2>/dev/null ;
  gh run list --limit 8 --json databaseId,workflowName,headBranch,conclusion --jq '.[] | select(.conclusion == "failure") |
    (if .headBranch == "master" then "[P0-master]"
     elif (.workflowName | test("Dependabot|dependabot")) then "[P2-dependabot]"
     elif (.workflowName | test("CodeQL|Security|security")) then "[P3-security]"
     else "[P1-PR]" end) + " RUN-FAIL[\(.workflowName)] \(.headBranch[:30]) id=\(.databaseId)"' 2>/dev/null ;
  gh pr list --state open --json number,title,reviewDecision \
    --jq '.[] | select(.reviewDecision != "" and .reviewDecision != null) | "[P1-PR] PR#\(.number) review=\(.reviewDecision)"' 2>/dev/null ;
  gh api repos/Alex1980Alex/1C-Framework/code-scanning/alerts --jq '.[]? | select(.state == "open" and .rule.severity == "error") | "[P3-security] CODEQL \(.rule.id) — \(.most_recent_instance.location.path)"' 2>/dev/null | head -3 ;
} | sort -u > /tmp/cur.txt 2>/dev/null ;
  new=$(comm -13 <(echo "$prev") /tmp/cur.txt | grep -vE "^$|node-version|cannot iterate|^null" || true) ;
  if [ -n "$new" ]; then
    echo "$new"
    # Auto-cache: invoke ci_failure_cache.py per RUN-FAIL line
    echo "$new" | grep -E "RUN-FAIL\[" | grep -oE "id=[0-9]+" | sed 's/id=//' | while read rid; do
      result=$(.venv/Scripts/python.exe scripts/ci_failure_cache.py --run-id "$rid" 2>/dev/null | tr -d '\n' | head -c 200)
      echo "  [auto-cache] run_id=$rid → $result"
    done
  fi ;
  prev=$(cat /tmp/cur.txt) ;
  sleep 20 ;
done
```

**Key changes vs legacy:**
- Priority prefix `[P0-master|P1-PR|P2-dependabot|P3-security]` для triage
- Auto-cache subprocess на каждый RUN-FAIL (no manual ci_failure_cache invocation needed)
- CodeQL filter ужесточён `severity=error` (low/medium/high — игнор)
- Polling 20s (был 15s) — баланс отзывчивости vs gh API rate
- **Live notifications poll** (added 2026-05-26 Phase 3): every 3 iter (~60s) `gh api notifications` → emit `[notif]` delta + `--log-event notification` auto-cache. Rate-limit aware (60s vs aggressive 20s). См. [42.4 §Generic Event Hashing](42.4_Failure_Caching.md#generic-event-hashing---log-event)

> **Note:** snippet выше показывает core watcher без notification poll-блока (для краткости). Production Monitor `bp06hbt02+` embed'ит дополнительный `iter % 3 == 0` блок с `gh api notifications --jq ...` + `comm -13` delta + `--log-event notification` invocation per new line. Полный production source — в `command:` поле live Monitor task (Bash: `gh api repos/.../actions/runs/<id>/logs` для retrieve).

## Простой PR-watcher (one PR)

```bash
prev="" ; while true ; do
  cur=$(gh pr view $PR --json statusCheckRollup --jq '.statusCheckRollup[] | "\(.name)=\(.conclusion)"' | sort -u) ;
  comm -13 <(echo "$prev") <(echo "$cur") ;
  prev="$cur" ;
  remain=$(echo "$cur" | grep -c "=$") ;
  [ "$remain" = "0" ] && echo "GATES COMPLETE" && break ;
  sleep 30 ;
done
```

## Запуск из Claude Code сессии

```
Monitor(
  description: "CI status changes",
  timeout_ms: 3600000,
  persistent: true,
  command: "<bash script выше>"
)
```

## Stop Monitor

```
TaskStop(task_id: "<monitor-task-id>")
```

Получить ID запущенного Monitor можно через result `Monitor()` invocation (returns `task_id`).

## Workflow

```
session start
  ↓
SessionStart hooks fire (ensure-docker / catchup / gh-notif-intake)
  ↓
manually spawn Monitor с command выше → returns task_id
  ↓
work; Monitor emit'ит delta lines в chat → Claude reacts:
  - on RUN-FAIL → auto-cache invoked (no manual action)
  - on [P0-master] failures → priority-flagged
  - on [P3-security] CodeQL → investigate
  - on review decisions → check PR comments
  ↓
TaskStop(task_id) перед session end ИЛИ Monitor умирает с сессией
```
