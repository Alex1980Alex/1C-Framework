# 42.5 GitHub Notifications Intake (SessionStart)

Auto-summarize unread GitHub notifications при старте Claude Code сессии.

## Зачем

Без этого хука пользователь должен **руками** открывать Gmail или GitHub UI чтобы увидеть что произошло пока сессия была offline (PR reviews, security alerts, CI fails, dependabot updates). Hook делает это автоматически и emit'ит inline systemMessage с приоритезированной сводкой.

## Компоненты

| File | Role |
|---|---|
| [`.claude/hooks/gh-notif-intake-on-start.py`](../../../../.claude/hooks/gh-notif-intake-on-start.py) | SessionStart hook, subprocess `gh api notifications` |
| [`.claude/hooks/shared/gh_notif_classifier.py`](../../../../.claude/hooks/shared/gh_notif_classifier.py) | Subject+reason → category + priority classifier |

## Pipeline

```
SessionStart event
  ↓
gh-notif-intake-on-start.py (≤8s timeout)
  ↓
subprocess: gh api notifications --jq '[.[] | {subject, type, reason}]'
  ↓ (4s timeout, graceful empty list on failure)
classify(subject, reason) → (category, priority) per notification
  ↓
summarize → {total, by_category, by_priority}
  ↓
emit systemMessage: "[GH-NOTIF] N unread (cat1=X, cat2=Y, ...)" + top-3 inline subjects
```

## Categories (priority order, first-match-wins)

| Category | Priority | Pattern | Example |
|---|---|---|---|
| `ci-fail` | P1 | `workflow run failed\|All jobs have failed\|Run failed` | "Python CI workflow run failed for fix/branch" |
| `security` | P0 | `security advisory\|vulnerab\|CodeQL` | "New security advisory CVE-..." |
| `pr-review` | P1 | `commented on\|approved\|requested changes\|review_requested` | "@gemini-code-assist commented on this pull request" |
| `merged` | P3 | `merged\|pull request closed` | "merged your pull request" |
| `dependabot` | P2 | `dependabot\|update .* requirement\|^bump .. from .. to ..` | "Bump tqdm from 4.65.0 to 4.67.3" |
| `other` | P3 | (fallback) | anything else |

**Order rationale:** CI failures take precedence over source — "Dependabot workflow run failed" → ci-fail/P1 (not dependabot/P2).

## Env vars

| Var | Default | Effect |
|---|---|---|
| `GH_NOTIF_INTAKE_DISABLE` | unset | Set `=1` to skip hook entirely |

## Smoke

```bash
echo '{"session_id":"test","hook_event_name":"SessionStart"}' | \
  .venv/Scripts/python.exe .claude/hooks/gh-notif-intake-on-start.py
```

Returns JSON with `systemMessage` field — concrete sample:

```json
{"continue": true, "systemMessage": "[GH-NOTIF] 50 unread (ci-fail=46, other=4)\n  • [P1 ci-fail] Python CI workflow run failed ...\n  • [P1 ci-fail] Claude Code workflow run failed ..."}
```

## Gaps closed

- **Off-session GitHub awareness:** previously required manual `gh notifications` / Gmail check.
- **Priority triage:** P0 security / P1 PR-review or CI-fail / P2 dependabot / P3 merged — emit shows breakdown.

## Limitations

- `gh api notifications` returns max 50 unread per page. For high-volume repos consider pagination (currently not implemented).
- Hook is session-bound (like all SessionStart hooks). Between sessions GitHub state still drifts — but next start catches up.
- Rate limits: gh CLI uses authenticated token, generous quota. Empty list returned on rate limit (graceful degradation).
