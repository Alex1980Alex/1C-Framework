# 50.2 Формат лога и логгеры

Единый структурный лог всех событий хуков и вызовов инструментов — `data/hook-invocations.jsonl` (JSONL, append-only, crash-safe). Одна строка = одно событие.

## Категории строк

Поле `category` разделяет источники. Потребители метрик считают вызовы инструментов ТОЛЬКО из канонических категорий:

| category | Кто пишет | Что означает |
|---|---|---|
| `tool_call` | [`tool-invocation-logger.py`](../../../../.claude/hooks/tool-invocation-logger.py) | канонический вызов **built-in**-инструмента (Read/Bash/Edit/Grep/Glob/Write/Task*/Skill/Agent/…) |
| `mcp_call` | [`mcp-invocation-logger.py`](../../../../.claude/hooks/mcp-invocation-logger.py) | канонический вызов **MCP**-инструмента (`mcp__<server>__<op>`) |
| `hook` | `BaseHook.run()` автолог | срабатывание энфорсера/хука (НЕ вызов тула) |
| `slash_run` | slash-command-tracker | жизненный цикл slash-команды (start/end) |
| `phase` | skill | маркер фазы скилла |

Канонические категории — единый источник `CANONICAL_CATEGORIES = ("mcp_call", "tool_call")` в [`scripts/tool_effectiveness.py`](../../../../scripts/tool_effectiveness.py); импортируется всеми потребителями (нет дрейфа литералов).

**Почему `hook` не считается вызовом тула:** до канонических логгеров один Bash-вызов давал N строк `category="hook"` (SearchOptimizer + ProcessGuard + … по каждому сматчившему хуку) → двойной счёт. Канонический логгер пишет РОВНО одну строку `tool_call`/`mcp_call` на вызов, а `BaseHook.run()` подавляет дубль-автолог `category="hook"` для того же mcp__-тула (`_NoAutoLog*` override).

## Схема строки

Строка — CloudEvents v1.0 конверт + W3C trace context + плоские поля обратной совместимости:

```json
{
  "ts": "2026-07-18T08:12:03.123456",
  "hook": "ToolInvocationLogger",
  "event": "PostToolUse",          // PreToolUse | PostToolUse | Stop | UserPromptSubmit
  "tool": "Bash",
  "elapsed_ms": 20,                 // время ХУКА, НЕ инструмента
  "duration_ms": 2057,              // 260718 H-P0.1: РЕАЛЬНАЯ длительность тула (только Post, только при наличии)
  "outcome": "allow",              // allow | block | message | error
  "session": "<session_id>",
  "run_id": "<uuid|>",             // корреляция со slash-командой
  "agent_id": "<subagent|>",       // атрибуция субагента (платформа шлёт с 2026-07)
  "category": "tool_call",
  "tool_call_id": "toolu_…",       // = gen_ai.tool.call.id — join-ключ Pre↔Post
  "success": true,
  "error_type": "",                 // низкокардинальная категория ошибки
  "args_hash": "ab12cd34ef56",     // sha1[:12] аргументов → детект retry (повтор идентичного)
  "gen_ai.tool.name": "Bash",      // OTel-алиасы (дословно дублируют плоские поля)
  "gen_ai.tool.call.id": "toolu_…",
  "error.type": "",
  "specversion": "1.0", "id": "<uuid>", "source": "claude-code-hooks",
  "type": "com.anthropic.claude.hook.PostToolUse", "time": "…",
  "correlationid": "<run_id|session>", "causationid": "",
  "traceparent": "00-<32hex>-<16hex>-01"
}
```

Значимые поля:

| Поле | Смысл |
|---|---|
| `tool_call_id` | стабильный join-ключ Pre↔Post (= `gen_ai.tool.call.id`, = нативный OTel `tool_use_id`). При отсутствии — FIFO по (session, tool, correlationid). |
| `duration_ms` | реальная длительность тула из PostToolUse-payload (H-P0.1). Пишется **только** при наличии → потребитель отличает «не было» от «0мс». Точнее пэйринга. |
| `elapsed_ms` | время работы САМОГО ХУКА (~20мс) — вводит в заблуждение как латентность тула; реальная латентность = `duration_ms` либо пара Pre→Post. |
| `args_hash` | фингерпринт аргументов (хеш, НЕ сырьё — пути/секреты не утекают). Тот же `args_hash` подряд = retry. |
| `success` / `error_type` | у MCP заполнены из ответа; у built-in консервативны (провал ловится непарным Pre — см. [50.3](50.3_Анализ_вердикты_действия.md)). |
| `gen_ai.*` алиасы | аддитивны, дословно дублируют плоские поля → будущий OTel-экспорт = переименование, jq/DuckDB-запросы целы. |

Опциональная JSON-Schema валидация: `CLAUDE_LOG_VALIDATE=1` (advisory, `.claude/schemas/events/hook-invocation.json`). Крипто-shred поля `error` per-session (opt-out `CLAUDE_LOG_NO_CRYPTO=1`).

## Логгеры

| Логгер | Событие | Роль |
|---|---|---|
| [`shared/invocation_logger.py`](../../../../.claude/hooks/shared/invocation_logger.py) | — | ядро: `log_invocation(...)` пишет строку; `extract_duration_ms(raw, event)` (H-P0.1, Post-only, отбраковка bool/neg/missing); каскадная ротация. |
| [`tool-invocation-logger.py`](../../../../.claude/hooks/tool-invocation-logger.py) | Pre/Post built-in | канонический `tool_call` (allowlist `BUILTIN_TOOLS`, no-op на mcp__/неизвестных). |
| [`mcp-invocation-logger.py`](../../../../.claude/hooks/mcp-invocation-logger.py) | Pre/Post `mcp__.*` | канонический `mcp_call` (matcher ловит ВСЕ MCP-серверы без per-server проводки). |
| `BaseHook.run()` (в [`base/protocol.py`](../../../../.claude/hooks/base/protocol.py)) | все | автолог `category="hook"` для энфорсеров; подавляет дубль mcp__ allow. |

Оба канонических логгера читают `duration_ms` из payload единым shared-helper `extract_duration_ms` (контракт извлечения не расходится) и пробрасывают в `log_invocation`.

## Ротация

`data/hook-invocations.jsonl` при превышении 10МБ ротируется каскадом `.1 → .2 → … → .N` (`HOOK_LOG_ARCHIVES=12` по умолчанию, ~120МБ ≈ 14 дней). Раньше держался только `.1` → окно 14д всегда было `window_incomplete` (лог покрывал ~2 дня). Ротация атомарна (`os.replace`, гонка параллельных процессов безопасна). Анализатор читает LOG + все архивы (`_all_logs`).

## Per-call логи MCP-серверов (второй источник истины)

Если stdio MCP-сервера падает ДО PostToolUse-хука, канонический `mcp_call` не запишется. Shared [`scripts/mcp_call_log.py`](../../../../scripts/mcp_call_log.py) (`log_mcp_call` + контекст `track_call`) даёт внутренний per-call лог сервера → `.claude/cache/mcp-<server>-calls.jsonl` (ротация 2МБ, fail-soft, opt-out `MCP_CALL_LOG_DISABLE=1`). Обёрнуты memory-orchestrator, 1c-mcp-crud (per-instance по `MCP_ONEC_URL`), vector-memory, skill-learning, memory-ai. ⚠ Правки MCP-серверного кода — рантайм после `/mcp reconnect`.

## Диагностический захват формы payload

Форма `tool_response` — контракт ПЛАТФОРМЫ (юнит-фикстура его не пинит). Gated-дамп в `tool-invocation-logger.py` (`TOOL_LOGGER_DEBUG_DUMP=1` или sentinel `.claude/cache/tool-response-dump.on`, cap 50) захватывает РЕАЛЬНУЮ форму первых N Post-вызовов → `.claude/cache/tool-response-shapes.jsonl`. Off by default. Именно этот дамп установил, что платформа не шлёт Post на провал built-in и что `duration_ms` присутствует.
