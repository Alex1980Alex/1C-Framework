# 50.4 Тяжёлый путь: OTel → Cross-check → Langfuse

Opt-in слой поверх лёгкого JSONL-контура: нативная телеметрия Claude Code как **независимый второй источник** для сверки честности + дашборды + LLM-judge. Реализация — roadmap [260718 OTel→Langfuse](../../../roadmap/260718_ROADMAP_OTEL_LANGFUSE_HEAVY_PATH.md) (H-P0..H-P4), [ADR-052](../../../../.claude/skills/architecture-research/adr/052-otel-langfuse-topology-retention-security.md).

## Зачем тяжёлый путь

Лёгкий контур честен, но с косвенными сигналами: провал built-in = непарный Pre (не различает тип провала, завышается обрывом сессии). Нативный OTel Claude Code даёт **прямые** `success`/`duration_ms`/`error_type` per-call — второй источник, которым можно СВЕРИТЬ честность лёгкого детектора (закрывает NB1-класс навсегда).

| Слепая зона лёгкого пути | Что даёт нативный OTel |
|---|---|
| провал = непарный Pre (косвенно) | событие `claude_code.tool_result`: прямые `success`/`error_type`/`duration_ms` |
| латентность из пары / `duration_ms` | спан `claude_code.tool.execution` + split «ожидание разрешения» vs исполнение |
| нет кросс-сессионной корреляции | Trace ID + `session.id`/`prompt.id`/`tool_use_id`; цепочка субагентов = один трейс |
| семантика («правильные аргументы») вне rule-слоя | LLM-judge (Argument Correctness / Task Completion) на сэмпле |

## Топология (fan-out через коллектор)

```
Claude Code (нативный OTLP, opt-in env в settings.local.json)
  │ http/protobuf → localhost:4318
  ▼
otel-collector (docker/docker-compose.otel-collector.yml)
  ├─ file/logs, file/traces → data/otel/*.jsonl   (кормит cross-check, БЕЗ Langfuse)
  ├─ debug                  → docker logs          (верификация эмиссии)
  └─ otlp_http → Langfuse /api/public/otel         (opt-in overlay, дашборды)
       ▼
Langfuse self-host (docker/docker-compose.langfuse.yml, 6 контейнеров)
```

У Claude Code ОДИН OTLP-endpoint → и файл-сырец, и Langfuse кормятся из **коллектора** (fan-out), а не двумя экспортами клиента. Включение эмиссии — [`scripts/otel/enable_claude_otel.py`](../../../../scripts/otel/enable_claude_otel.py) (`--console`/`--otlp`/`--disable`/`--status`, пишет в gitignored `settings.local.json`). Подробности нативного контракта (спаны/метрики/события) — [42.8](../7.10_MONITOR_CI/42.8_Claude_Code_OTel_Tool_Telemetry.md).

## Формат нативного сырца (⚠ коэрсинг обязателен)

File-exporter коллектора пишет OTLP-JSON. Ключевой сигнал — log-события `claude_code.tool_result` (плоские атрибуты `tool_name`/`tool_use_id`/`success`/`duration_ms`/`error_type`).

**⚠ Реальный Claude Code кодирует `success` и `duration_ms` как `stringValue`** (`"true"`/`"false"`, `"3879"`), НЕ `boolValue`/`intValue` (эмпирика 2026-07-18). Наивный парсинг (`bool("false")`==True) читал бы ВСЕ провалы как успех — NB1-класс на стороне OTel-парсинга. Парсер обязан коэрсить (`_coerce_bool`/`_coerce_int`). Отсутствие `success` НЕ трактуется как провал (иначе манфактурим FN).

## Cross-check (главная ценность) — `otel_crosscheck.py`

[`scripts/otel_crosscheck.py`](../../../../scripts/otel_crosscheck.py) джойнит нативный исход ↔ hook-вердикт по `tool_use_id` (native) == `tool_call_id` (hook) = `gen_ai.tool.call.id` (эмпирически 100% overlap):

| Метрика | Смысл |
|---|---|
| **FN** | native `success=false`, а hook счёл успехом → детектор **пропустил** провал |
| **FP** | hook пометил провал (непарный Pre), native `success=true` → **ложная тревога** |
| **TP** | оба согласны (провал) |
| `native_vs_direct` | \|native.duration_ms − hook.duration_ms\|: оба из одного поля → **≈0 валидирует захват H-P0.1** |
| `native_vs_paired` | \|native.duration_ms − (post−pre)\|: величина ошибки FIFO-пары |

Живой результат (2026-07-18): детектор unpaired-Pre согласован с native (**0 FN / 0 FP / 1 TP**); latency native↔hook-direct дельта **0мс** на 25 совпадений (H-P0.1 точен бит-в-бит), native↔пэйринг **max 9888мс** (ошибка пары, которую H-P0.1 убирает). Секция «OTel cross-check» рендерится в `_latest.md` (graceful — нет сырца → нет секции). Grace-период `in_flight` симметричен `completion_stats`.

## Langfuse self-host (H-P2, дашборды)

[`docker/docker-compose.langfuse.yml`](../../../../docker/docker-compose.langfuse.yml) — эталонный self-host (web + worker + Postgres + ClickHouse + Redis + MinIO), все порты на 127.0.0.1. Оркестратор [`scripts/otel/langfuse_up.py`](../../../../scripts/otel/langfuse_up.py):

```bash
.venv/Scripts/python.exe scripts/otel/langfuse_up.py up      # генерит секреты в .env.otel, up, health, fan-out коллектора
.venv/Scripts/python.exe scripts/otel/langfuse_up.py status  # health + контейнеры
.venv/Scripts/python.exe scripts/otel/langfuse_up.py down     # стоп (--volumes — снести данные)
```

UI: http://localhost:3000 (login из gitignored `.env.otel`). Коллектор пересоздаётся с overlay [`otel-collector-langfuse.yaml`](../../../../docker/otel-collector-langfuse.yaml) (fan-out на Langfuse, file-путь cross-check сохранён). **НЕ default** (RAM ~3ГБ, cross-check работает без Langfuse); `restart: unless-stopped` → переживает перезапуск. Инварианты безопасности (ADR-052): контент OFF по умолчанию (промпты/args/result = PII), секреты вне git, localhost-bind.

⚠ Операционка bring-up (живые грабли): init-email требует нормальный домен; ClickHouse host-порт 9000 конфликтует с SonarQube → ремап 9010; `otlphttp` → `otlp_http` (collector 0.154+).

## LLM-judge на сэмпле (H-P4, advisory)

[`scripts/tool_llm_judge.py`](../../../../scripts/tool_llm_judge.py) — семантический слой поверх rule-метрик: сэмпл 5-10% (все провалы + детерминированный хеш-сэмпл успехов) → рубрики Argument Correctness + Task Completion → судья через LLMRotationService (z.ai, token-economy) → jsonl + опц. Langfuse Scores. **Advisory-only** (вердикты rule-слоя не двигает), per-item изоляция (судья упал → status=error, прогон цел). Активация требует content-источник (`OTEL_LOG_TOOL_CONTENT=1` — PII, осознанно) либо явный jsonl; нет источника → no-op.
