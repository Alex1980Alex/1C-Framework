# 09.12 Async Patterns

> Roadmap reference: [260509_ROADMAP_CONSOLIDATED_BACKLOG.md §4.4](../../../../docs/roadmap/260509_ROADMAP_CONSOLIDATED_BACKLOG.md). Closed 2026-05-09.

PDF Framework — async-first (FastAPI, LangGraph, httpx). Но многие critical-path библиотеки (PyMuPDF, sentence-transformers, DSPy, sqlite3) **не предоставляют async API**. Эта глава фиксирует, когда `asyncio.to_thread` оправдан, а когда нужно native async.

## Decision tree

```
Нужен I/O или CPU-bound operation в async контексте?
  │
  ├── Есть native async API библиотеки? (httpx, asyncpg, aiosqlite, ...)
  │     │
  │     └── ДА → использовать native async, не to_thread
  │
  └── НЕТ — библиотека только sync (PyMuPDF, sentence-transformers, ...)?
        │
        └── ДА → asyncio.to_thread(sync_fn, ...) — корректный паттерн
```

## Когда `asyncio.to_thread` ОПРАВДАН

| Library | Тип | Файлы в проекте | Reason |
|---|---|---|---|
| **PyMuPDF** (`fitz`) | sync-only PDF parser | [`loaders/pdf/pymupdf_loader.py`](../../../../src/pdf_framework/loaders/pdf/pymupdf_loader.py), [`hybrid_loader.py`](../../../../src/pdf_framework/loaders/providers/hybrid_loader.py) | C-extension, нет async API |
| **Docling** | sync layout-aware parser | [`loaders/providers/docling_loader.py`](../../../../src/pdf_framework/loaders/providers/docling_loader.py) | sync-only |
| **sentence-transformers** | sync embeddings (CPU/GPU bound) | [`embeddings/providers/local.py`](../../../../src/pdf_framework/embeddings/providers/local.py), [`giga.py`](../../../../src/pdf_framework/embeddings/providers/giga.py) | model.encode() — sync |
| **DSPy** | sync prompt optimizer | [`prompts/signatures.py`](../../../../src/pdf_framework/prompts/signatures.py) | пока sync only (планы DSPy 3.0 — async) |
| **sqlite3** (stdlib) | sync DB driver | [`search/bm25_store.py`](../../../../src/pdf_framework/search/bm25_store.py), [`processing/section_summary.py`](../../../../src/pdf_framework/processing/section_summary.py) | aiosqlite — отдельный pkg, large refactor scope |

**Pattern (правильный):**
```python
async def embed_text(self, text: str) -> list[float]:
    """sentence-transformers — sync only; обёртка через to_thread."""
    return await asyncio.to_thread(self._embed_sync, text)
```

## Когда НУЖЕН native async (НЕ to_thread)

| Library | Async API | Используется в |
|---|---|---|
| **httpx** | `AsyncClient` | TEI embedder, BSL MCP HTTP transport, REST client (5 src files) |
| **anthropic** | `AsyncAnthropic` | LLM calls в agents/* |
| **redis (arq)** | `aioredis` встроен | [`api/routes/jobs.py`](../../../../src/api/routes/jobs.py) — async queue |
| **qdrant-client** | `AsyncQdrantClient` | [`vector_store/providers/qdrant.py`](../../../../src/pdf_framework/vector_store/providers/qdrant.py) |
| **neo4j** | `AsyncDriver` | [`graph_store/providers/neo4j.py`](../../../src/pdf_framework/graph_store/providers/neo4j.py) |

**Антипаттерн (НЕправильно):**
```python
# Плохо — оборачивать httpx sync API в to_thread
async def fetch(url):
    return await asyncio.to_thread(httpx.get, url)  # ❌

# Хорошо — использовать httpx.AsyncClient
async def fetch(url):
    async with httpx.AsyncClient() as client:
        return await client.get(url)  # ✓
```

Native async всегда предпочтительнее: меньше overhead (нет thread-pool roundtrip), лучше использует event loop, корректнее обрабатывает cancellation.

## `loop.run_in_executor` vs `asyncio.to_thread`

`asyncio.to_thread()` — wrapper над `run_in_executor(None, ...)` (Python 3.9+). Использует default ThreadPoolExecutor. Пример corner-case:

```python
# vision.py:185 — параллельный batch через run_in_executor
loop = asyncio.get_event_loop()
tasks = [loop.run_in_executor(None, self.describe, req) for req in requests]
results = await asyncio.gather(*tasks)
```

Эквивалентно (более идиоматично в новом коде):
```python
tasks = [asyncio.to_thread(self.describe, req) for req in requests]
results = await asyncio.gather(*tasks)
```

`run_in_executor` сохраняется в legacy кодах когда нужен **custom executor** (не default thread pool):
```python
custom_executor = ThreadPoolExecutor(max_workers=4)
result = await loop.run_in_executor(custom_executor, fn, *args)
```

## Migration roadmap (deferred)

| Library | Async alternative | Migration cost | ROI | Priority |
|---|---|---|---|---|
| sqlite3 | aiosqlite | High (3+ файла, schema changes) | Low (SQLite already fast) | Defer |
| PyMuPDF | — | N/A (no async API exists) | — | Never |
| sentence-transformers | — | N/A | — | Never |
| DSPy | DSPy 3.0 (planned) | Wait for upstream | Medium | Wait |
| **Qdrant (memory subsystem)** | `AsyncQdrantClient` | Medium (~half-day, 3 файла в `src/memory/`) | Medium (~6 call sites сейчас в `to_thread`; native async уменьшит thread pool overhead при concurrent pattern saves) | **Deferred follow-up** |

**Решение для PDF Framework (2026-05-09 → updated 2026-05-16 §4.4 closure):** не мигрировать в production-критичные пути. Существующие `to_thread` usage оправданы характером underlying libs. Documentation outliner — текущий гайд — фиксирует правильное использование. **Qdrant в `src/memory/`** — единственный realistic migration candidate (sync `QdrantClient` обёрнут в `to_thread` в 6+ местах, тогда как `src/pdf_framework/vector_store/providers/qdrant.py` уже использует `AsyncQdrantClient`). Не делается сейчас из-за: (1) cross-module touch (orchestrator + ai_memory/docs_rag + vector_memory MCP server), (2) необходимость атомарной замены factory `_get_qdrant()` без breaking back-compat для MCP-сервера, (3) low real-world QPS — memory subsystem не hot-path для thread pool contention. Активировать когда: реальное профилирование покажет thread pool насыщение, или planned API redesign даст естественный окно для смены factory.

## Async hooks (Claude Code `"async": true` flag, roadmap 260509 §4.9)

Claude Code v2.x поддерживает `"async": true` в hook command config — хук запускается в фоне без блокировки Claude. Trade-off:
- ✅ Не блокирует agent loop (UX gain ~3s на slow hooks)
- ❌ `decision`/`permissionDecision`/`continue` поля игнорируются (action уже завершён)
- ✅ Применимо только к `type: "command"`
- ❌ Stdout `systemMessage` тоже теряется (Claude уже двинулся дальше)

**Когда применять**: fire-and-forget хуки которые не должны менять behavior (логирование, telemetry, save-to-disk).

**Когда НЕ применять**: хуки которые инжектят контекст (`memory-first-hook` UserPromptSubmit с systemMessage инжекцией), блокирующие enforcer'ы (docs-change-enforcer, task-enforcer), фильтры/роутеры.

### Audit 2026-05-16 — applied to 2 hooks

§4.9.1 PostToolUse audit: **0 hooks** с p95 > 2000ms (самый медленный `PostToolUseAutoGitSave` p95=978ms — под порогом). Roadmap §4.9 был audit-stale в строгой PostToolUse-scope.

Шире: 3 hooks с p95 > 2s в других events:

| Event::Hook | p95 ms | Blocking? | `async: true` применён? |
|---|---|---|---|
| `UserPromptSubmit::auto-git-save-prompt` | 3900 | Никогда (header: «Always exit 0 (never block user prompt)») | ✅ Да (2026-05-16) |
| `Stop::SessionMemorySave` | 3187 | Никогда (header: «always allow stop (advisory, non-blocking)») | ✅ Да (2026-05-16) |
| `UserPromptSubmit::MemoryFirstHook` | 3332 | **Инжектит systemMessage** — блокировать нужно | ❌ Нельзя (потеряется инжекция) |

Result: 2 из 3 slow hooks стали async — Claude больше не ждёт ~3-6s после Stop / на UPS до запуска MemoryFirstHook. MemoryFirstHook остаётся sync — его purpose требует sync inject.

## Diagnostics

| Симптом | Причина | Решение |
|---|---|---|
| Event loop blocked > 100ms | Sync call в async coroutine без to_thread | Найти `for x in db.cursor.execute(...)` или `requests.get()` — обернуть в to_thread |
| Thread pool exhaustion (concurrent: max-workers exceeded) | Слишком много параллельных to_thread на default pool | Custom ThreadPoolExecutor через `run_in_executor` или ограничить concurrency через Semaphore |
| Cancellation не работает (await x.cancel() игнорируется) | Sync function не respects cancellation token | Native async обязателен (cancellation propagates через task tree); workaround — check внутри sync fn |
