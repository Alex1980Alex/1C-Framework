# 09.4.1 Langfuse

LLM observability platform — централизованный sink для всех LLM/RAG/tool spans фреймворка. Source of truth для production cost tracking и performance baseline.

**Назначение в стеке**: один из четырёх компонентов observability (см. [09.4 Мониторинг — Observability Stack](09.4_Мониторинг.md#observability-stack)). Покрывает то, что in-process `CostTracker` теряет при restart, и то, что Prometheus не видит — content-level (input/output текст), token usage, semantic span attribution.

**Полное описание (установка, конфигурация, credential resolution chain, usage patterns, wired call sites, what's tracked, smoke testing, diagnostics, scoring API, retention limits, roadmap status, файлы) — см. канон-главу [39 Langfuse](../7.7_LANGFUSE/39.1_Обзор.md):**

- [39.1 Обзор](../7.7_LANGFUSE/39.1_Обзор.md) — что это, use cases, точки интеграции, версия/phase
- [39.2 Детальная реализация](../7.7_LANGFUSE/39.2_Детальная_реализация.md) — `ObservabilitySettings`, `LangfuseCallbackHandler` (нативный v4-хендлер с 2026-07-04), `LangfuseTracer`, `langfuse_setup.py` singleton+helpers, integration points, trade-offs
- [39.3 Best practices](../7.7_LANGFUSE/39.3_Best_practices.md) — синтез из 15+ референсных GitHub-проектов
- [39.4 Дорожная карта](../7.7_LANGFUSE/39.4_Дорожная_карта.md) — P0-P3 backlog (async flush, RAGAS→score linkage, distributed trace_id, self-host, и т.д.)

Production runtime: SDK v4.6.1 (`langfuse>=4.0,<5.0`), нативный v4 `langfuse.langchain.CallbackHandler` (миграция с ручного v2-хендлера завершена 2026-07-04, см. 39.2/39.4 P0.4).

## Cost Baseline {#cost-baseline}

Production cost baseline извлекается через [`scripts/analyze_langfuse_cost.py`](../../../../scripts/analyze_langfuse_cost.py) (roadmap [260515 §5c.7](../../../roadmap/260515_ROADMAP_LANGFUSE_COST_BASELINE.md)). Источник истины — Langfuse Cloud (`/api/public/observations`, `/api/public/metrics`), НЕ in-process `CostTracker` (тот теряется при restart). Скрипт ходит за уже агрегированными данными, локально считает Top-N и by-strategy.

> Эта фича реализована и работает (P0.4/P0.7 закрыты) — в отличие от roadmap-статуса в [39.4 P2.2 Cost dashboards](../7.7_LANGFUSE/39.4_Дорожная_карта.md), который описывает ДОПОЛНИТЕЛЬНЫЕ Cloud-UI дашборды/алерты (ещё pending); экспорт+baseline-файл ниже — уже готовый локальный аналог.

### Запуск (default window = последние 7 закрытых дней, обходит ingestion-lag 15-30s)

```bash
.venv/Scripts/python scripts/analyze_langfuse_cost.py                     # md → docs/architecture/cost-baselines.md
.venv/Scripts/python scripts/analyze_langfuse_cost.py --output json       # JSON → stdout (для CI)
.venv/Scripts/python scripts/analyze_langfuse_cost.py --dry-run           # парсит + форматирует, файл НЕ пишется
.venv/Scripts/python scripts/analyze_langfuse_cost.py \
    --from-date 2026-05-08 --to-date 2026-05-14 --top-n 20                # custom window
```

### Что эмитится (5 секций в [`docs/architecture/cost-baselines.md`](../../../roadmap/260515_ROADMAP_LANGFUSE_COST_BASELINE.md))

1. **Top-N expensive observations** — cursor pagination через `client.api.observations.get_many(type="GENERATION")`, локальная агрегация по `obs.name`. Поля `cost_details.total` + `usage_details.total`. Определяет «где деньги уходят» — concentration analysis.
2. **Avg / P50 / P95 tokens per RAG call** — server-side `metrics.metrics()` с фильтром `name contains rag` (1 HTTP call вместо тысячи). Источник thresholds для §5c.6 dashboard alerts.
3. **Cost by strategy** — fetch_observations с `name="search.manager.search"`, локальная агрегация по `obs.input.strategy` (custom span-поле, Metrics API не группирует по input). Сравнивает vector / hybrid / graphrag / two_stage по effective cost.
4. **Cost by model** — `metrics.metrics()` с `dimensions=[providedModelName]`. Валидация delegation routing decisions (§4.5): доля Opus vs Sonnet vs Haiku.
5. **Daily run-rate** — локальная агрегация cost по `obs.start_time.date()` (Daily Metrics API не используется — pre-aggregated rollup может устареть; live agg более точен).

### Pre-req: pricing для локальных моделей

Автоматизировано через [`scripts/setup_langfuse_local_pricing.py`](../../../../scripts/setup_langfuse_local_pricing.py) — регистрирует все non-cloud модели (Z.AI GLM family, Ollama-local Qwen2.5/Llama, Qwen3-Embedding-8B, E5/nomic embeddings, BGE reranker, ColPali) с `input_price=0.0, output_price=0.0` через `client.api.models.create()`. Без этого `cost_details.total = null` и эти traces выпадают из секций 1/3/4/5 (daily run-rate занижается). Скрипт идемпотентный (list существующих → skip already-registered), run once после первой настройки Langfuse creds; повторный запуск безопасен. Cloud-модели (Anthropic claude-*) Langfuse ships pre-registered (158 моделей по умолчанию).

```bash
.venv/Scripts/python scripts/setup_langfuse_local_pricing.py --dry-run   # plan
.venv/Scripts/python scripts/setup_langfuse_local_pricing.py             # apply
```

### Retry

`tenacity` через `create_retry` (5 попыток, exp jitter 1-16s, 60s max-delay) на `TimeoutError`/`ConnectionError`. 401/403 → fail-fast с clear message в stderr.

### Auto-refresh

Cron-job [`.github/workflows/cost-baseline.yml`](../../../../.github/workflows/cost-baseline.yml) запускает скрипт по воскресеньям 09:00 UTC, создаёт PR с обновлённым baseline через `peter-evans/create-pull-request@v6`. Repo secrets: `LANGFUSE_PUBLIC_KEY` + `LANGFUSE_SECRET_KEY` (one-time setup в GitHub repo settings).

### Когда baseline ПУСТОЙ

Скрипт эмитит warning, файл не пишется (`n_observations == 0`). Это норма пока в Langfuse < 7 дней реальных запросов (§5c.5 closure = 2026-05-15, первый репрезентативный baseline — 2026-05-24+).

### Troubleshooting cost extraction

| Симптом | Причина | Что делать |
|---|---|---|
| `Langfuse not enabled or creds missing` | `OBSERVABILITY__LANGFUSE_PUBLIC_KEY` пустой | Проверить `.env` или repo secrets |
| `cost_details.total = null` для многих traces | Локальные модели без pricing | Запустить `setup_langfuse_local_pricing.py` |
| Total cost не совпадает с UI (±5%+) | Ingestion lag race или mismatch фильтров | Запустить с `to_date = yesterday` (closed window); проверить фильтр |
| Cron job падает в GitHub Actions | Secrets не настроены | `Settings → Secrets and variables → Actions` → добавить `LANGFUSE_PUBLIC_KEY` + `LANGFUSE_SECRET_KEY` |
| PR не создаётся при пустом отчёте | `n_obs == 0` блокирует write | Норма — скрипт не пишет файл, action не находит diff → no PR. Подождать накопления traffic |

## Retention и tier-specific лимиты

| Tier | Retention | Daily ingestion limit | Notes |
|---|---|---|---|
| Free | 30 days | 50,000 events | Достаточно для baseline collection, dashboard alerts ramp-up |
| Core | 90 days | 100,000 events | Минимум для §4.5 outcome corpus (требует 30 дней) |
| Pro | 1 year | 1M events | Production-grade |

Retention важно для §5c.9 Outcome corpus — JSONL экспорт через `client.api.observations.get_many` зависит от того что traces ещё не expired. Если у проекта retention < 30 дней — outcome corpus не сможет собрать репрезентативную выборку для §4.5 trained router.
