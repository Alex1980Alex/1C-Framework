# 09.4.1 Langfuse

LLM observability platform — централизованный sink для всех LLM/RAG/tool spans фреймворка. Source of truth для production cost tracking и performance baseline.

**Назначение в стеке**: один из четырёх компонентов observability (см. [09.4 Мониторинг — Observability Stack](09.4_Мониторинг.md#observability-stack)). Покрывает то, что in-process `CostTracker` теряет при restart, и то, что Prometheus не видит — content-level (input/output текст), token usage, semantic span attribution.

---

## Установка

```bash
pip install -e ".[langfuse]"
```

`[langfuse]` extra включает `langfuse>=2.0`. Без установки система работает в no-op режиме: `LangfuseCallbackHandler` автоматически выключается с warning в логе. Никаких runtime-исключений — graceful degradation.

Production runtime подтверждено на SDK v4.6.1. Минимальная поддерживаемая версия — `>=2.0`, но новые API surfaces (Metrics V2, Models pricing API) требуют `>=4.0`.

### Credential resolution chain

`LangfuseCallbackHandler._resolve_credentials` ходит по 4 источникам в порядке убывания приоритета:

| Приоритет | Источник | Когда использовать |
|---|---|---|
| 1 | explicit constructor kwargs | DI в unit-тестах, mock-инжекция |
| 2 | `settings.observability.langfuse_*` (canonical) | Production runtime, тестовые `.env` |
| 3 | `os.environ.LANGFUSE_*` (legacy single underscore) | Backwards-compat для старых интеграций |
| 4 | nothing | Handler disables itself + warning в лог |

> **Onboarding (2026-05-15, roadmap §3.4-ter):** placeholder env vars зафиксированы в [`.env.example`](../../../../.env.example) с `OBSERVABILITY__LANGFUSE_ENABLED=false` по умолчанию — fresh clone получает корректный reference set без необходимости читать roadmap для discovery нужных переменных. Активация Phase B — [ADR-010](../../../../docs/architecture/), roadmap §5c.

### Project-level setup в Langfuse Cloud

После регистрации в `cloud.langfuse.com` нужно один раз:

1. Создать project → получить `pk-lf-*` + `sk-lf-*`.
2. Settings → Retention: настроить retention period (free tier — 30 дней, paid — настраивается).
3. Settings → Models: cloud-модели (Anthropic claude-*) приходят pre-registered (158 моделей по умолчанию). Локальные — регистрируются через [`scripts/setup_langfuse_local_pricing.py`](../../../../scripts/setup_langfuse_local_pricing.py), см. [Cost Baseline](#cost-baseline) ниже.

## Использование

### Через middleware (рекомендуется)

```python
from src.pdf_framework.agents.rag.middleware import with_middleware

llm_traced = with_middleware(
    llm,
    enable_langfuse=True,
    user_id="user-123",
    session_id="session-abc",
)
```

`with_middleware` обвязывает LangChain `BaseLanguageModel`/`Runnable` и добавляет `LangfuseCallbackHandler` в `.callbacks`. Все события (`on_llm_start`, `on_llm_end`, `on_chain_start`, и т.д.) автоматически попадают в Langfuse как `generation` / `span` / `trace` объекты.

### Через central setup helper (для не-middleware кода)

```python
from src.pdf_framework.observability.langfuse_setup import (
    is_langfuse_enabled, build_langfuse_callback,
)

if is_langfuse_enabled():
    handler = build_langfuse_callback(user_id="u-1", session_id="s-1")
    if handler is not None:
        llm.callbacks = (llm.callbacks or []) + [handler]
```

`build_langfuse_callback()` возвращает `None` если:
1. `langfuse_enabled=False` в settings,
2. `langfuse` package не установлен,
3. credentials отсутствуют.

Никогда не raise. Defensive null-check — обязателен.

### Через `emit_observation()` для standalone хуков (2026-05-15, roadmap §5c.4)

Для Python-хуков Claude Code (memory-first-hook, session-memory-save, memory-sync), которые **не используют LangChain runtime**, добавлен второй entry point — прямая эмиссия одной observation через `langfuse.start_observation()` + `flush()`:

```python
from src.pdf_framework.observability.langfuse_setup import emit_observation

emit_observation(
    name="memory-first-recall",
    input={"prompt_len": len(prompt)},
    output={"layers": 4, "results": n_results, "latency_ms": dt_ms},
    session_id=event.get("session_id"),
    metadata={"hook": "memory-first", "event": "UserPromptSubmit"},
)
```

| Параметр | Тип | Назначение |
|---|---|---|
| `name` | `str` | Span name (используется как ключ агрегации в cost baseline Top-N) |
| `input` | `dict \| str` | Произвольный JSON. По соглашению — описание запроса (НЕ полный текст для крупных) |
| `output` | `dict \| str` | Результат + метаданные исполнения (status, latency, counts) |
| `session_id` | `str \| None` | Корреляция с Claude Code session — позволяет cross-hook трассировку |
| `metadata` | `dict` | Дополнительные tag-поля (hook, event type) |
| `flush` | `bool = True` | `True` для one-shot (Stop/UPS hooks); `False` для hot-path (search/tools) |

Pattern source: `doneyli/claude-code-langfuse-template` (Claude Code Stop hook reference impl), research cached в [`langfuse-standalone-spans-2026.md`](../../../../.claude/skills/architecture-research/cache/langfuse-standalone-spans-2026.md). Graceful: try/except оборачивает всё; ImportError / network / cred errors → debug log + return (никогда не raise). Opt-out: env `MEMORY_HOOK_NO_LANGFUSE=1`.

### Span lifecycle (упрощённо)

```
Producer (hook / tool / search) calls emit_observation(...)
  │
  ▼
_get_langfuse_client()  ← memoized singleton (module-level)
  │
  ├── client.start_observation(name=, input=, metadata=)
  │     → ObservationContext (id allocated, sent to background queue)
  │
  ├── ctx.update(output=, level=, status_message=)
  │     → enqueue update event
  │
  └── ctx.end()
       → enqueue end event
       │
       └── if flush=True: client.flush() blocks until queue empty
```

Без `flush=True` события уходят через background-thread queue Langfuse SDK — это значит на process exit (Stop hook, который sys.exit'ит) можно потерять trace. Поэтому one-shot хуки эмитят с `flush=True`, а hot-path callers (search/tools) — с `flush=False` для latency.

### Wired call sites (full §5c.4 + §5c.5 closure, 2026-05-15)

| Файл | Event | Span name | Status enum |
|---|---|---|---|
| [`session-memory-save.py`](../../../../.claude/hooks/session-memory-save.py) | Stop | `session-memory-save` | `skipped-trivial` / `skipped-duplicate` / `saved` |
| [`memory-first-hook.py`](../../../../.claude/hooks/memory-first-hook.py) | UserPromptSubmit | `memory-first-hook` | `skipped-trivial` / `skipped-cooldown` / `skipped-no-tokens` / `no-results` / `injected` (+ `layer_counts` + `duration_ms`) |
| [`memory-sync.py`](../../../../.claude/hooks/memory-sync.py) | Stop | `memory-sync` | `changes-detected` / `clean` |
| [`search/manager.py`](../../../../src/pdf_framework/search/manager.py) `SearchManager.search` | async | `search.manager.search` | `cache-hit` / `ok` (+ `strategy` + `k` + `duration_ms`, `flush=False`) |
| [`tools/retrieval/search_tool.py`](../../../../src/pdf_framework/tools/retrieval/search_tool.py) | @tool | `tool.search_documents` | `ok` / `error` (`flush=False`) |
| [`tools/graph_query/graph_tool.py`](../../../../src/pdf_framework/tools/graph_query/graph_tool.py) | @tool | `tool.query_knowledge_graph` | `ok` / `error` / `no-results` (+ `entities` + `relations`, `flush=False`) |
| [`tools/document/index_tool.py`](../../../../src/pdf_framework/tools/document/index_tool.py) | @tool | `tool.index_document` | `ok` / `error` (+ `chunks_stored` + `embeddings_computed`, `flush=False`) |

**Client singleton (perf):** `langfuse_setup._get_langfuse_client()` мемоизирует `Langfuse()` instance на уровне модуля. Без него каждый `emit_observation()` на hot-path search / tools создавал бы новый клиент → HTTP handshake overhead на каждый search. Init failure кешируется через `_LANGFUSE_CLIENT_INIT_FAILED` — нет retry storm'а при missing creds.

## Что трекается

`LangfuseCallbackHandler` подписан на LangChain `BaseCallbackHandler` events:

| Event | Что записывается |
|---|---|
| `on_llm_start` | Generation: prompts, user_id, session_id, model |
| `on_llm_end` | Generation: output_text, token usage (prompt/completion/total), model |
| `on_llm_error` | Generation с error metadata + status_message |
| `on_chain_start/end/error` | Span: chain name, input, output |
| `on_agent_action` | Span: tool name, tool input |
| `on_tool_start/end/error` | Span: tool execution + result |
| `on_retriever_start/end` | Span: retrieval query + retrieved docs |
| `ignore_chain/agent/retriever` | False — все callback'и активны |

Standalone `emit_observation` эмитит generation/span объекты вручную с указанными `name`/`input`/`output`/`metadata`.

## Diagnostics

| Симптом | Причина | Решение |
|---|---|---|
| `[LANGFUSE] langfuse not installed` warning | extra `[langfuse]` не установлен | `pip install -e ".[langfuse]"` |
| `[LANGFUSE] Missing credentials, disabling callback` | settings + env пусты | Проверить `.env` (см. Конфигурация выше) |
| Traces не появляются в Langfuse Cloud | `langfuse_enabled=False` или ключи неверны | Проверить `is_langfuse_enabled()` returns True; проверить ключи в Langfuse dashboard |
| `[LANGFUSE] Failed to start LLM trace: ...` | Network / Langfuse Cloud недоступен | Handler не падает (graceful), traces теряются. Проверить host/firewall |
| Traces появляются с задержкой 15-30 сек | Langfuse Cloud ingestion lag | Норма. Для weekly batch (`--to-date=yesterday`) — обходится автоматически. Для on-demand run — добавить `client.flush()` перед запросом |
| Cost в traces = null | Модель не зарегистрирована в Langfuse Models | Запустить [`scripts/setup_langfuse_local_pricing.py`](../../../../scripts/setup_langfuse_local_pricing.py) |
| 401/403 на API запросах | Creds expired / rotated | Перевыпустить ключи в Langfuse → обновить `.env` + repo secrets |
| 429 Too Many Requests | Cloud free-tier rate limit | tenacity retry уже встроен в `analyze_langfuse_cost.py`; для production middleware — рассмотреть paid plan |

## Cost Baseline {#cost-baseline}

Production cost baseline извлекается через [`scripts/analyze_langfuse_cost.py`](../../../../scripts/analyze_langfuse_cost.py) (roadmap [260515 §5c.7](../../../roadmap/260515_ROADMAP_LANGFUSE_COST_BASELINE.md)). Источник истины — Langfuse Cloud (`/api/public/observations`, `/api/public/metrics`), НЕ in-process `CostTracker` (тот теряется при restart). Скрипт ходит за уже агрегированными данными, локально считает Top-N и by-strategy.

### Запуск (default window = последние 7 закрытых дней, обходит ingestion-lag 15-30s)

```bash
.venv/Scripts/python scripts/analyze_langfuse_cost.py                     # md → docs/architecture/cost-baselines.md
.venv/Scripts/python scripts/analyze_langfuse_cost.py --output json       # JSON → stdout (для CI)
.venv/Scripts/python scripts/analyze_langfuse_cost.py --dry-run           # парсит + форматирует, файл НЕ пишется
.venv/Scripts/python scripts/analyze_langfuse_cost.py \
    --from-date 2026-05-08 --to-date 2026-05-14 --top-n 20                # custom window
```

### Что эмитится (5 секций в [`docs/architecture/cost-baselines.md`](../../../docs/architecture/cost-baselines.md))

1. **Top-N expensive observations** — cursor pagination через `client.api.observations.get_many(type="GENERATION")`, локальная агрегация по `obs.name`. Поля `cost_details.total` + `usage_details.total`. Определяет «где деньги уходят» — concentration analysis.
2. **Avg / P50 / P95 tokens per RAG call** — server-side `metrics.metrics()` с фильтром `name contains rag` (1 HTTP call вместо тысячи). Источник thresholds для §5c.6 dashboard alerts.
3. **Cost by strategy** — fetch_observations с `name="search.manager.search"`, локальная агрегация по `obs.input.strategy` (custom span-поле, Metrics API не группирует по input). Сравнивает vector / hybrid / graphrag / two_stage по effective cost.
4. **Cost by model** — `metrics.metrics()` с `dimensions=[providedModelName]`. Валидация delegation routing decisions (§4.5): доля Opus vs Sonnet vs Haiku.
5. **Daily run-rate** — локальная агрегация cost по `obs.start_time.date()` (Daily Metrics API не используется — pre-aggregated rollup может устареть; live agg более точен).

### Pre-req: pricing для локальных моделей

Автоматизировано через [`scripts/setup_langfuse_local_pricing.py`](../../../../scripts/setup_langfuse_local_pricing.py) — регистрирует все non-cloud модели (Z.AI GLM family, Ollama-local Qwen2.5/Llama, Qwen3-Embedding-8B, E5/nomic embeddings, BGE reranker, ColPali) с `input_price=0.0, output_price=0.0` через `client.api.models.create()`. Без этого `cost_details.total = null` и эти traces выпадают из секций 1/3/4/5 (daily run-rate занижается). Скрипт идемпотентный (list существующих → skip already-registered), run once после первой настройки Langfuse creds; повторный запуск безопасен. Cloud-модели (Anthropic claude-*) Langfuse ships pre-registered (158 моделей по умолчанию).

```bash
.venv/Scripts/python scripts/setup_langfuse_local_pricing.py --dry-run   # plan
.venv/Scripts/python scripts/setup_langfuse_local_pricing.py             # apply
```

### Retry

`tenacity` через `create_retry` (5 попыток, exp jitter 1-16s, 60s max-delay) на `TimeoutError`/`ConnectionError`. 401/403 → fail-fast с clear message в stderr.

### Auto-refresh

Cron-job [`.github/workflows/cost-baseline.yml`](../../../../.github/workflows/cost-baseline.yml) запускает скрипт по воскресеньям 09:00 UTC, создаёт PR с обновлённым baseline через `peter-evans/create-pull-request@v6`. Repo secrets: `LANGFUSE_PUBLIC_KEY` + `LANGFUSE_SECRET_KEY` (one-time setup в GitHub repo settings).

### Когда baseline ПУСТОЙ

Скрипт эмитит warning, файл не пишется (`n_observations == 0`). Это норма пока в Langfuse < 7 дней реальных запросов (§5c.5 closure = 2026-05-15, первый репрезентативный baseline — 2026-05-24+).

### Troubleshooting cost extraction

| Симптом | Причина | Что делать |
|---|---|---|
| `Langfuse not enabled or creds missing` | `OBSERVABILITY__LANGFUSE_PUBLIC_KEY` пустой | Проверить `.env` или repo secrets |
| `cost_details.total = null` для многих traces | Локальные модели без pricing | Запустить `setup_langfuse_local_pricing.py` |
| Total cost не совпадает с UI (±5%+) | Ingestion lag race или mismatch фильтров | Запустить с `to_date = yesterday` (closed window); проверить фильтр |
| Cron job падает в GitHub Actions | Secrets не настроены | `Settings → Secrets and variables → Actions` → добавить `LANGFUSE_PUBLIC_KEY` + `LANGFUSE_SECRET_KEY` |
| PR не создаётся при пустом отчёте | `n_obs == 0` блокирует write | Норма — скрипт не пишет файл, action не находит diff → no PR. Подождать накопления traffic |

Langfuse поддерживает scoring API для прикрепления качественных метрик к traces — это поле в roadmap §5c.8 Score collection wire-up:

```python
from src.pdf_framework.observability.langfuse_setup import _get_langfuse_client

client = _get_langfuse_client()
if client is not None:
    client.create_score(
        trace_id="abc-123",
        name="user-thumbs-up",
        value=1.0,  # 1.0 = positive, 0.0 = negative
        comment="Optional reason",
    )
```

UI-интеграция (👍/👎 кнопки в Web UI → backend call → `client.create_score`) — DEFERRED до §5c.8. Когда реализуется: scores корреляруются с feedback loop §3.5 и дают signal для §4.5 trained router.

## Retention и tier-specific лимиты

| Tier | Retention | Daily ingestion limit | Notes |
|---|---|---|---|
| Free | 30 days | 50,000 events | Достаточно для baseline collection, dashboard alerts ramp-up |
| Core | 90 days | 100,000 events | Минимум для §4.5 outcome corpus (требует 30 дней) |
| Pro | 1 year | 1M events | Production-grade |

Retention важно для §5c.9 Outcome corpus — JSONL экспорт через `client.api.observations.get_many` зависит от того что traces ещё не expired. Если у проекта retention < 30 дней — outcome corpus не сможет собрать репрезентативную выборку для §4.5 trained router.
