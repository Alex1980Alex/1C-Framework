# 09.4.2 Prometheus + Dashboards

Метрики времени исполнения, HTML дашборд для оперативного наблюдения, Prometheus exposition format для scraping в production-grade monitoring stack (Prometheus + Grafana + Alertmanager).

**Назначение в стеке**: дополняет [09.4.1 Langfuse](09.4.1_Langfuse.md) — Langfuse покрывает content-level (per-trace input/output/cost), Prometheus — aggregated counters + histograms (request volume, latency distribution, cache hit-rate). Разные questions, разные tools.

---

## Быстрый доступ к дашборду

Команда `dashboard` автоматически проверяет, запущен ли сервер, стартует его при необходимости и открывает браузер:

```bash
# Открыть HTML Dashboard (автозапуск сервера)
python -m src.cli.main dashboard

# На другом порту
python -m src.cli.main dashboard --port 9000

# Без открытия браузера (только запуск сервера)
python -m src.cli.main dashboard --no-browser
```

### Ручной запуск API-сервера

Если нужен только сервер без открытия браузера:

```bash
# Через CLI
python -m src.cli.main server --port 8000

# Через uvicorn напрямую
python -m uvicorn src.api.app:create_app --factory --host 0.0.0.0 --port 8000
```

### Перезапуск сервера

Команда `restart` находит процесс на порту, останавливает его и запускает новый экземпляр в фоне:

```bash
# Перезапуск на порту по умолчанию (8000)
python -m src.cli.main restart

# Перезапуск на другом порту
python -m src.cli.main restart --port 9000

# Принудительное завершение (без graceful shutdown)
python -m src.cli.main restart --force
```

| Опция | Описание | Default |
|---|---|---|
| `--host` | Хост сервера | `127.0.0.1` |
| `--port` | Порт сервера | `8000` |
| `--force`, `-f` | Завершить без ожидания graceful shutdown | `false` |

После запуска все `/metrics/*` эндпоинты доступны по адресу `http://localhost:8000`.

**Degraded mode:** Если Qdrant/Neo4j недоступны, сервер стартует в ограниченном режиме — метрики и health работают, search/index/chat вернут 500. Подробнее: [10.1 Частые ошибки](../7.3_УСТРАНЕНИЕ_НЕПОЛАДОК/10.1_Частые_ошибки.md#qdrant-не-доступен).

**Файлы:** [`src/api/app.py`](../../../../src/api/app.py) (фабрика `create_app`, degraded mode), [`src/api/routes/metrics.py`](../../../../src/api/routes/metrics.py) (эндпоинты), [`src/cli/main.py`](../../../../src/cli/main.py) (команда `dashboard`).

## HTML Dashboard

Визуальный дашборд системных метрик в браузере с автообновлением каждые 30 секунд.

**URL:** `http://localhost:8000/metrics/html`

### Секции дашборда

| Секция | Содержимое |
|---|---|
| **Key Metrics** | 6 карточек: Total Queries, Queries Today, Avg Latency, P95 Latency, Cache Hit Rate, Error Rate |
| **Cache Statistics** | Таблица: Embedding Cache, LLM Response Cache, Document Cache (hits, misses, hit rate с progress bar) |
| **Search Strategy Usage** | Таблица стратегий поиска с долей использования (%) |
| **Hook Invocations** | Таблица хуков: Count, Avg/P95 ms, Blocks, Errors |
| **Skill Activations** | Карточки: Activation Rate, Recommended, Activated, Prompt Detection, PostToolUse. Таблица скиллов с колонкой Source (цветные теги по источнику) |
| **Enforcement & Errors** | Total Blocks, Block Rate, последние ошибки |
| **Try It** | Интерактивный поиск/RAG-запрос прямо из дашборда |

### Как работает

1. `GET /metrics/html` вызывает `get_metrics()` — сбор метрик из 4 источников:
   - `MetricsCollector` — общие метрики (queries, latency, errors)
   - `EmbeddingCache` — кеш эмбеддингов (hits/misses)
   - `LLMCache` — кеш LLM-ответов (hits/misses)
   - `DocumentCache` — кеш документов (hits/stale)
2. Значения подставляются в HTML-шаблон через `string.Template`
3. JavaScript автоматически перезагружает страницу каждые 30 секунд

### Цветовая индикация

| Метрика | Зелёный | Жёлтый | Красный |
|---|---|---|---|
| Cache Hit Rate | > 50% | 20-50% | < 20% |
| Error Rate | < 1% | 1-5% | > 5% |

HTML Dashboard оптимизирован для **локальной разработки** и оперативного триажа. Для production observability — Prometheus + Grafana (см. ниже).

## Prometheus Metrics

```bash
# JSON метрики
curl http://localhost:8000/metrics/

# Prometheus exposition format (для scraping)
curl http://localhost:8000/metrics/prometheus

# HTML дашборд (в браузере)
http://localhost:8000/metrics/html
```

### Доступные метрики

| Метрика | Тип | Описание | Labels |
|---|---|---|---|
| `search_requests_total` | Counter | Общее число поисковых запросов | `strategy` |
| `search_latency_seconds` | Histogram | Задержка поиска (sec) | `strategy` |
| `index_chunks_total` | Counter | Проиндексированных чанков | — |
| `cache_hits_total` | Counter | Попаданий в кэш | `cache_type` (`embedding` / `llm` / `document`) |
| `cache_misses_total` | Counter | Промахов кэша | `cache_type` |
| `llm_tokens_total` | Counter | Использованных токенов LLM | `model`, `kind` (`prompt` / `completion`) |

Source: [`src/pdf_framework/observability/prometheus_metrics.py`](../../../../src/pdf_framework/observability/prometheus_metrics.py).

### Scraping config (prometheus.yml)

Пример конфигурации для production-grade scraping каждые 15 секунд:

```yaml
# /etc/prometheus/prometheus.yml
global:
  scrape_interval: 15s
  evaluation_interval: 15s

scrape_configs:
  - job_name: 'pdf-framework'
    metrics_path: '/metrics/prometheus'
    static_configs:
      - targets: ['localhost:8000']
        labels:
          service: 'rag'
          env: 'prod'

# Optional: alert rules file
rule_files:
  - '/etc/prometheus/rules/pdf-framework.yml'

alerting:
  alertmanagers:
    - static_configs:
        - targets: ['alertmanager:9093']
```

### Alert rules

Пороги — derived from cost baseline (см. [09.4.1 Cost Baseline](09.4.1_Langfuse.md#cost-baseline)) после ≥7 дней production traffic. До этого использовать дефолты как стартовую точку:

```yaml
# /etc/prometheus/rules/pdf-framework.yml
groups:
  - name: pdf-framework-availability
    interval: 30s
    rules:
      - alert: SearchErrorRateHigh
        expr: |
          (
            rate(search_requests_total{status="error"}[5m])
            / rate(search_requests_total[5m])
          ) > 0.05
        for: 5m
        labels:
          severity: warning
        annotations:
          summary: "Search error rate >5% over 5min"
          description: "{{ $value | humanizePercentage }} of search requests failed"

      - alert: SearchLatencyP95High
        expr: |
          histogram_quantile(0.95,
            rate(search_latency_seconds_bucket[5m])
          ) > 5
        for: 5m
        labels:
          severity: warning
        annotations:
          summary: "P95 latency >5s"
          description: "{{ $value }}s p95 — threshold 5s. Derive from cost baseline."

  - name: pdf-framework-cost
    interval: 60s
    rules:
      - alert: LLMTokenBurnUnusual
        # Trigger when daily token rate > 3x weekly average
        expr: |
          (
            rate(llm_tokens_total[1h])
            / rate(llm_tokens_total[7d])
          ) > 3
        for: 30m
        labels:
          severity: warning
        annotations:
          summary: "LLM token consumption 3x weekly average"
          description: "Investigate via Langfuse cost baseline"
```

### Grafana integration

Pre-built dashboards под этот set метрик пока не залиты в репо — quick-start через ручной import:

1. Установить Grafana, добавить Prometheus как data source (URL `http://prometheus:9090`).
2. Создать dashboard с panels:
   - **Request rate** — `sum(rate(search_requests_total[5m])) by (strategy)`
   - **Latency P50/P95/P99** — `histogram_quantile(0.50/0.95/0.99, rate(search_latency_seconds_bucket[5m]))`
   - **Cache hit rate** — `rate(cache_hits_total[5m]) / (rate(cache_hits_total[5m]) + rate(cache_misses_total[5m]))` by `cache_type`
   - **LLM token burn** — `sum(rate(llm_tokens_total[5m])) by (model, kind)`
3. Эти панели complementary к Langfuse UI: Prometheus показывает **rate over time**, Langfuse — **per-trace breakdown**.

Грубо: оператор смотрит **Grafana** для realtime triage, разработчик — **Langfuse** для post-hoc cost analysis.

## Интеграция с Cost Baseline

Pre-Prometheus alert thresholds (особенно `SearchLatencyP95High` и `LLMTokenBurnUnusual`) **должны** деривироваться из cost baseline после ≥7 дней production data:

| Alert | Поле в [`cost-baselines.md`](../../../roadmap/260515_ROADMAP_LANGFUSE_COST_BASELINE.md) | Формула |
|---|---|---|
| `SearchLatencyP95High` | (будущее поле в Cost Baseline §2) | `current P95 × 1.5` warning, `× 2` page |
| `LLMTokenBurnUnusual` | `cost_per_day_p95` из daily run-rate | `mean × 2` warning, `× 3` page |
| `SearchErrorRateHigh` | n/a (Prometheus-only) | Static 5% (не зависит от cost) |

Это unblock после §5c.7 closure (первый репрезентативный baseline = ~2026-05-24). До этого — статические дефолты выше.

## Все эндпоинты мониторинга

| Эндпоинт | Метод | Формат | Описание |
|---|---|---|---|
| `/metrics/` | GET | JSON | Все метрики (queries, cache, latency) |
| `/metrics/html` | GET | HTML | Визуальный дашборд с автообновлением |
| `/metrics/prometheus` | GET | Text | Prometheus exposition format |
| `/metrics/reset` | POST | JSON | Сброс дневных счётчиков |
| `/metrics/analytics` | GET | JSON | Аналитика: топ запросов, стратегии, hit rate |

### Analytics endpoint detail

Требует запущенного API-сервера.

```bash
curl http://localhost:8000/metrics/analytics
```

Возвращает:

- Топ запросов (top N by frequency)
- Распределение по стратегиям (counts + percentages)
- Средняя задержка по стратегиям
- Hit rate кэша (per-cache breakdown)

Полезно для оперативной аналитики без подключения внешнего Prometheus.
