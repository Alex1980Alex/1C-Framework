# 09.7 Система хуков Claude Code

> Автоматизация рабочего процесса через хуки — обработчики событий,
> срабатывающие на действия Claude Code (ввод пользователя, вызов инструментов, завершение сессии).
>
> **Полная документация системы скиллов:** [11. Система скиллов](../../9_НАВЫКИ/9.1_СИСТЕМА_СКИЛЛОВ/11.1_Обзор.md) — маршрутизатор, enforcement, каталог, мониторинг.

---

## Обзор

Хуки — это Python-скрипты, которые автоматически запускаются при определённых событиях Claude Code. Они получают JSON на stdin, выполняют логику и влияют на поведение Claude через stdout (systemMessage) или exit code (block/allow).

**Три типа событий:**

| Событие | Когда срабатывает | Пример использования |
|---------|-------------------|---------------------|
| **UserPromptSubmit** | Пользователь отправляет сообщение | Рекомендация скиллов, напоминания |
| **PreToolUse / PostToolUse** | До / после вызова инструмента (Write, Edit, Bash...) | Enforcement, логирование, автокоммит |
| **Stop** | Claude пытается завершить сессию | Блокировка при незавершённых задачах |

---

## Архитектура: три уровня

Хуки образуют трёхуровневую защиту, где каждый уровень работает на своём этапе:

```
┌──────────────────────────────────────────────────────────────┐
│  Уровень 1: ВВОД ПОЛЬЗОВАТЕЛЯ (UserPromptSubmit)            │
│                                                              │
│  skill-router.py          → рекомендация скиллов             │
│  skill-eval-enforcer-shell.py → принуждение к активации      │
│  auto-git-save-prompt.py  → напоминание о коммите            │
│                                                              │
│  Результат: systemMessage (советы Claude перед работой)      │
├──────────────────────────────────────────────────────────────┤
│  Уровень 2: ИНСТРУМЕНТЫ (PreToolUse / PostToolUse)           │
│                                                              │
│  PRE:  code-skill-enforcer.py → BLOCK без скилла             │
│  POST: posttooluse-auto-git-save.py → автокоммит            │
│  POST: posttooluse-quality-feedback.py → ruff-фидбек        │
│                                                              │
│  Результат: block (exit 2) или systemMessage                 │
├──────────────────────────────────────────────────────────────┤
│  Уровень 3: ЗАВЕРШЕНИЕ (Stop)                                │
│                                                              │
│  auto-git-save.py         → блокировка при uncommitted       │
│  git-commit-enforcer.py   → проверка git status              │
│  docs-change-enforcer.py  → проверка покрытия документацией  │
│  task-enforcer.py         → проверка pending задач           │
│  ralph_wiggum_stop.py     → контроль Ralph-итераций          │
│                                                              │
│  Результат: block (exit 2) или allow (exit 0)               │
└──────────────────────────────────────────────────────────────┘
```

> **89 зарегистрированных скриптов** в цепочках событий, **97 `.py`-файлов** в каталоге).
> Ниже — ключевые enforcer'ы; это не исчерпывающий список.

### UserPromptSubmit (при вводе пользователя)

| Хук | Назначение | Timeout |
|-----|-----------|---------|
| `skill-router.py` | Анализирует промпт, рекомендует скиллы из `skill-router-config.json` | 3s |

### PreToolUse (перед вызовом инструмента)

| Хук | Matcher | Назначение | Timeout |
|-----|---------|-----------|---------|
| `bsl-tool-router.py` | `Read\|Grep\|Glob` | Детектит BSL-сигналы (файл `.bsl`, ключевые слова, паттерны кода) и подсказывает стратегию поиска (`bsl_architecture`/`bsl_document_patterns`/`bsl_subsystem_analysis`) | 3s |
| `code-skill-enforcer.py` | `Write\|Edit\|Bash` | Блокирует код без активации скилла (уровни A-C) | 3s |
| `search-optimizer.py` | `Bash` | Advisory-подсказка оптимальных параметров при вызове search API (`strategy=hybrid, rerank=true, k=10`); никогда не блокирует | 3s |
| `process-guard.py` | `Bash\|PowerShell` | Защита демонов фреймворка (напр. `tei_keepalive`) от деструктивного process-control — блокирует `Stop-Process`/`taskkill`/`kill`/`pkill`/`killall` по protected-имени, pid из lock-файла или broad python-kill; opt-out `PROCESS_GUARD_DISABLE=1` | 3s |

> `tdd-guard.py` (matcher `Write\|Edit`) — opt-in advisory-нудж (ADR-015): при `TDD_GUARD_ENABLE=1`
> и правке `src/**.py` с новым def/class без соответствующего `tests/**/test_<mod>.py` эмитит
> system_message, **никогда не блокирует**. Включён **локально** через `settings.local.json`
> (`tdd-guard-validation-on-start.py` на SessionStart наблюдает окно валидации) — в team
> `settings.json` НЕ зарегистрирован. Принуждение к скиллам реализовано парой файлов:
> `skill-eval-enforcer.py` (python-логика) исполняется через зарегистрированную обёртку
> `skill-eval-enforcer-shell.py` (см. таблицу UserPromptSubmit выше; 100% activation

## Протокол взаимодействия

### Входные данные (stdin)

Хук получает JSON на stdin с информацией о событии:

```json
{
  "session_id": "abc-123",
  "tool_name": "Write",
  "tool_input": {
    "file_path": "/path/to/file.py",
    "content": "import langchain..."
  }
}
```

### Выходные данные (stdout + exit code)

| Exit code | Значение | Stdout |
|-----------|---------|--------|
| **0** | Разрешить (allow) | Текст → systemMessage для Claude |
| **2** | Заблокировать (block) | Текст → причина блокировки |

**Пример stdout (systemMessage):**
```
SKILL RECOMMENDATION: Активируй скилл 'langgraph-core' через Skill('langgraph-core')
```

**Пример stdout (block):**
```
BLOCKED: Код содержит StateGraph. Сначала активируй скилл 'langgraph-core'.
```

## BaseHook — базовый класс

Все хуки наследуют `BaseHook` из `.claude/hooks/base/base.py`:

```python
from base.base import BaseHook, HookInput, HookOutput

class MyHook(BaseHook):
    def process(self, inp: HookInput) -> HookOutput:
        # inp.tool_name — название инструмента
        # inp.tool_input — параметры инструмента
        # inp.detected_event — тип события

        out = HookOutput()
        out.system_message("Совет для Claude")
        return out
```

**Возможности BaseHook:**
- Автоматический парсинг stdin в `HookInput`
- UTF-8 safe flush (без падений на Windows cp1251)
- Таймер `elapsed_ms` для замеров latency
- Автологирование в `data/hook-invocations.jsonl`

**Файл:** `.claude/hooks/base/base.py`

## Invocation Logging (JSONL)

Каждый вызов хука записывается в `data/hook-invocations.jsonl`:

```json
{
  "ts": "2026-02-22T14:30:00.123456",
  "hook": "SkillRouter",
  "event": "UserPromptSubmit",
  "tool": null,
  "elapsed_ms": 45,
  "outcome": "message",
  "session": "abc123",
  "agent_id": null,
  "error": null
}
```

**Особенности:**
- Append-only формат (crash-safe)
- Автоматическая ротация при 10MB
- Поддержка `agent_id` для субагентов
- Overhead: 0-3ms на запись

**Файл:** `.claude/hooks/shared/invocation_logger.py`

## Защита от бесконечных циклов

### Проблема

Stop-хуки могут создавать бесконечный цикл:
```
ralph_wiggum_stop → изменяет .ralph_wiggum_count →
  git-commit-enforcer → видит изменение → блокирует →
    коммит → ralph снова...
```

### Решение

1. **`.gitignore`** — файлы `.ralph_*` исключены из git
2. **`auto-git-save.py`** — игнорирует `.ralph_active`, `.ralph_criteria.json`, `.ralph_wiggum_count`
3. **`docs-change-enforcer.py`** — пропускает `.ralph_` файлы
4. **`ralph_state.py`** — `stop_lock` предотвращает повторный вход

## IDE Filtering

Хук `skill-router.py` фильтрует IDE-события, чтобы не засорять рекомендации:

**Фильтруемые префиксы:**
```
<file_>        — открытие файла в IDE
<selection>    — выделение текста
<cursor>       — позиция курсора
<ide_opened_file> — событие VS Code
```

Также фильтруется любой текст, начинающийся с XML-тегов (эвристика).

## Субагенты

Субагенты (Task tool) используют отдельную конфигурацию хуков для предотвращения конфликтов:

**Файл:** `.claude/settings-subagent.json`

Отличия от основных настроек:
- Сокращённый набор хуков (только skill-router, invocation-logger)
- `disabledHooks` для потенциально зацикливающихся хуков
- Поле `agent_id` в логах для идентификации

```python
# Логирование с agent_id
from shared.invocation_logger import log_invocation

log_invocation(
    hook="agent:bsl-debugger",
    event="AgentStart",
    agent_id="sub-abc-789",
)
```

## OpenTelemetry Tracing

Для production-мониторинга доступен OTLP exporter:

```bash
# Console export (разработка)
export OTEL_EXPORTER_CONSOLE=true

# OTLP export (production)
export OTEL_EXPORTER_OTLP_ENDPOINT=http://localhost:4318/v1/traces
export OTEL_SERVICE_NAME=claude-hooks
```

```python
from shared.otel_exporter import HookTracer

tracer = HookTracer()
with tracer.span("SkillRouter", event="UserPromptSubmit"):
    # ... логика хука ...
    pass
```

**Поддерживаемые backends:** Console, SigNoz, Grafana Tempo, Jaeger, Langfuse.

**Файл:** `.claude/hooks/shared/otel_exporter.py`
