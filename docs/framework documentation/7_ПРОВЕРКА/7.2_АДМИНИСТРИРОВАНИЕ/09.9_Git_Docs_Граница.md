# Проверка связи изменений Git с документацией

Проверка использует Python 3.11+ и Git независимо от клиента агента. Она сопоставляет изменения кода с изменениями документации соответствующего раздела по закреплённым правилам; качество текста и авторство требуют отдельной оценки.

Для подготовки коммита проверяется выбранный индекс относительно HEAD. Для CI проверяется итоговый диапазон между явными base и head. Результаты JSON v1: PASS (rc0), FAIL (rc1), UNKNOWN (rc2); ошибка или неполный вход не считаются успехом.

Полные команды сборки, проверки манифеста, ручного запуска, установки последним в цепочку pre-commit и адресного возврата приведены в [инструкции Git/docs](../../../git-docs-boundary.md). При установке сохраняются прежние обработчики и их порядок; чужие ограничения не снимаются.

Доверие к проверяющему коду и SHA256 манифеста устанавливается отдельно до запуска. Проверка архива своей непроверенной копией не подтверждает bootstrap. Workflow запускается только для PR в квалифицированную доверенную ветку master: checker берётся из её base checkout, код PR не исполняется. Другие целевые ветки не квалифицированы и не запускают этот workflow; расширение требует отдельной приёмки доверия.

Пакет содержит CLI, правила, формат отчёта, Git-hook, CI workflow и проверки. Наличие workflow в ветке само по себе не подтверждает выполнение на GitHub runner или обязательность серверной проверки.

Remote bootstrap, PR BLOCK/PASS и серверная обязательность принимаются отдельно. Локальный запуск не подтверждает эти этапы или общую готовность внедрения.

При включении в существующий CI проверяйте новый код отдельно с правилами форматирования Ruff и строгой проверкой типов mypy проекта. Публичные функции описывают типы путей, Git-объектов, содержимого файлов и JSON-отчётов; аннотации не заменяют проверки входов во время исполнения. Форматирование и уточнение типов поставляются отдельной версией: её байты и манифест пересчитываются заново, а прежний архив сохраняется как исторический принятый выпуск. Прохождение этих проверок не удостоверяет выполнение workflow на runner или обязательность проверки в настройках сервера.
