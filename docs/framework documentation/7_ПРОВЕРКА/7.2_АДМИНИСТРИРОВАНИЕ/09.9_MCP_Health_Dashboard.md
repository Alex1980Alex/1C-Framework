# 09.9 Мониторинг здоровья MCP серверов

## Обзор

**MCP Health Monitor** — инструмент диагностики для мониторинга состояния 15+ MCP серверов в реальном времени. Отслеживает доступность, время отклика, количество инструментов и тип транспорта для каждого сервера.

## Назначение

MCP серверы — критичный компонент инфраструктуры. Отказ одного сервера может блокировать целые категории операций:
- **bsl-semantic-search** — поиск в коде
- **edt-mcp** — анализ структуры EDT проектов
- **glm-agent** — делегирование задач GLM-агентам
- **bsl-debugger** — отладка BSL кода

Health Monitor обнаруживает проблемы до того, как они повлияют на работу.

## Быстрый старт

```bash
# Проверка всех серверов (конфиг из .mcp.json)
python scripts/mcp_health_monitor.py

# Явно указать конфиг
python scripts/mcp_health_monitor.py .mcp.json
```

## Визуальные индикаторы

| Символ | Статус | Цвет | Значение |
|--------|--------|------|----------|
| OK | Доступен | Зелёный | Сервер отвечает и работает |
| ERR | Ошибка | Красный | Ошибка подключения |
| TMO | Таймаут | Жёлтый | Превышено 5 секунд |
| DIS | Отключён | Голубой | `"disabled": true` в конфиге |

## Стратегии проверки

### HTTP серверы

```
GET /health → HTTP 200
```

### Stdio серверы

```
1. Запустить процесс сервера
2. Отправить MCP initialize JSON-RPC
3. Прочитать ответ (capabilities, tools)
4. Завершить процесс
```

Обе стратегии: **таймаут 5 секунд**.

## Структура ServerHealth

```python
@dataclass
class ServerHealth:
    name: str           # Имя сервера
    status: str         # ok | error | timeout | disabled
    latency_ms: float   # Время отклика (мс)
    transport: str      # stdio | http
    last_check: str     # ISO 8601 timestamp
    error: str          # Текст ошибки
    tools_count: int    # Количество инструментов
```
