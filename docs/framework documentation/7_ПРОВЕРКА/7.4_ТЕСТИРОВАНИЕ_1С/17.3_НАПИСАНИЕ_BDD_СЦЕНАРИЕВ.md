# 17.3 Написание BDD-сценариев для 1С

Данный раздел описывает практические аспекты создания сценариев на языке Gherkin для проверки конфигураций 1С с использованием фреймворка Vanessa Automation.

## Формат feature-файла

Файлы сценариев (feature-файлы) должны строго соответствовать структуре Gherkin. Для корректной работы парсера и библиотек шагов на русском языке необходимо соблюдать следующие правила.

### Обязательные элементы

1.  **Директива языка**: Файл должен начинаться со строки `# language: ru`.
2.  **Контекст подключения**: Секция `Контекст` (Background) должна содержать шаг инициализации TestClient. Без этого сценарий не сможет взаимодействовать с тестируемым приложением.

**Базовый шаблон:**

```gherkin
# language: ru
Функционал: Название тестируемого функционала
    Контекст:
        Дано Я запускаю сценарий открытия TestClient или подключаю уже существующий

    @smoke @testclient
    Сценарий: Название конкретного тест-кейса
        # Шаги сценария...
```

### Теги

Рекомендуется использовать теги для классификации и фильтрации запуска тестов:
*   `@smoke` — для дымовых тестов.
*   `@testclient` — тесты, требующие запущенного клиентского приложения.
*   `@bdd` — общая метка для BDD-сценариев.
*   `@document` — тесты, связанные с документооборотом.

## Smoke-тест (рабочий пример)

Минимальный сценарий для проверки того, что инфраструктура тестирования работает корректно: TestClient запускается, и открывается главное окно конфигурации.

```gherkin
# language: ru
Функционал: Проверка подключения TestClient
    Контекст:
        Дано Я запускаю сценарий открытия TestClient или подключаю уже существующий

    @smoke @testclient
    Сценарий: Главное окно открывается
        Тогда открылось окно '*правление транспорто*'
```

**Разбор примера:**
*   Сценарий проверяет доступность интерфейса сразу после старта сессии.
*   Используется маска `*правление транспорто*`, чтобы игнорировать префиксы (например, "1С:Предприятие") и точное название конфигурации, если оно может меняться.
*   Среднее время выполнения: ~30 секунд (зависит от производительности сервера 1С).

## Работа с интерфейсом

При написании сценариев используются шаги взаимодействия с элементами формы 1С. Ниже приведены основные паттерны.

### Навигация и окна

*   **Открытие раздела навигации:**
    ```gherkin
    Когда В командном интерфейсе я выбираю "Склад и доставка"
    И В командном интерфейсе я выбираю "Документы"
    ```
*   **Проверка открытия окна:**
    Рекомендуется использовать символ подстановки `*`, чтобы тест не падал из-за изменения версии конфигурации в заголовке окна.
    ```gherkin
    Тогда открылось окно '*Справочник "Номенклатура*"'
    ```

### Действия в формах

*   **Нажатие кнопки:**
    Для надежности лучше обращаться к кнопке по ее имени (свойство "Имя" в конфигураторе), а не по заголовку.
    ```gherkin
    И я нажимаю на кнопку с именем 'Button0'
    ```
*   **Ввод текста:**
    ```gherkin
    И в поле "Наименование" я ввожу текст "Тестовое значение"
    ```

## Типичные ошибки

Ниже приведен список частых проблем при запуске сценариев и способы их решения.

| Ошибка / Симптом | Причина | Решение |
| :--- | :--- | :--- |
| **"Не найдена процедура или функция для выполнения шага"** | Текст шага не соответствует ни одному шагу из библиотеки Vanessa Automation. | Проверьте точное написание шага в справочнике шагов VA. Возможно, не хватает предлога или изменен регистр. |
| **"Окно с заголовком ... не найдено"** | Заголовок окна динамический или содержит лишние символы. | Используйте wildcard-паттерны (звездочку `*`) в начале и конце строки: `'*МояФорма*'`. |
| **"Недостаточно фактических параметров"** | Синтаксическая ошибка в вызове шага. | Проверьте параметры шага. Убедитесь, что кавычки закрыты, и переданы все необходимые аргументы. |
| **"PIDКлиентаТестирования: 0"** | TestClient не был запущен или не подключен. | 1. Проверьте порт (должен быть 1538). 2. Убедитесь, что настроена авто-аутентификация. |
| **Неправильный шаг подключения** | Используется специфичный шаг, требующий явного указания базы. | **Неверно:** `Допустим Я подключаю TestClient 'TestDB'`. **Верно:** `Дано Я запускаю сценарий открытия TestClient или подключаю уже существующий` |

## Расположение файлов

Соблюдение структуры каталогов важно для корректной работы скриптов запуска (`run-bdd.ps1`).

1.  **Исходные файлы (Репозиторий):**
    Разрабатываемые feature-файлы хранятся в директории фреймворка:
    `D:\1С-Framework\features\`

2.  **Рабочая директория (Execution):**
    При запуске тестов скрипт автоматически синхронизирует файлы в рабочую папку Vanessa Automation:
    `D:\va-test\features\`

### Правила именования

*   Один feature-файл должен описывать **один функционал** или одну группу связанных тестов.
*   Имена файлов должны быть понятными и отражать суть проверки.
    *   Пример: `smoke_testclient.feature`
    *   Пример: `bdd_document.feature`
