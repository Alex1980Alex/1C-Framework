# 30.1 Обзор: Эффективность команд, скиллов и MCP

> Кросс-обзор того, как в проекте настроена максимальная отдача от триады
> Hooks + Skills + MCP. Координация строится через 4-слойный router,
> enforcers, метрики и систему самообучения для делегирования.

---

## Проблема

Без координации триада даёт хаос. Скиллы не активируются при подходящих промптах, код пишется без ревью и проверки, кеш теряется, коммиты забываются. Результат — рост технического долга и перерасход токенов.

## 5 слоёв эффективности

```
1. МАРШРУТИЗАЦИЯ   (router 4 layers)        ← правильный скилл
2. ПРИНУЖДЕНИЕ     (pre/post/stop gates)    ← качество гарантировано
3. ИЗМЕРЕНИЕ       (accuracy + SQLite + UI) ← видимость системы
4. САМООБУЧЕНИЕ    (DelegationBandit)       ← адаптация
5. ДЕЛЕГИРОВАНИЕ   (Z.AI Coder + Opus PM)   ← экономия токенов
```

| Без слоя | С слоем |
|---|---|
| Скилл не находится, Claude пишет с нуля | Router находит релевантный bundle за O(1) |
| Код пишется без активации Skill() | PreToolUse enforcer блокирует Write до активации |
| Нет данных по активациям скиллов | JSONL + SQLite дают точную картину Source |
| Делегирование по жёстким правилам | LinUCB-бандит адаптируется к домену и типу задачи |
| Дорогая модель пишет бойлерплейт | Z.AI генерирует код, Opus проверяет |
