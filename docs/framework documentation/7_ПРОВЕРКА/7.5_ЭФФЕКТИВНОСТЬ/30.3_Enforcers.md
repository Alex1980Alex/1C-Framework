# 30.3 Enforcers — принуждение к качеству

> Два класса enforcer'ов: PreToolUse блокируют до действия,
> Stop блокируют завершение сессии. Цель — гарантировать
> соблюдение процессов и стандартов качества.

---

## Протокол блокировки

```
Hook читает stdin JSON → проверяет условие
  → OK:    exit(0), stdout пусто
  → BLOCK: exit(2), stderr с reason → Claude видит
           (PreToolUse: инструмент не выполняется)
           (Stop: сессия не завершается)
```

`reason` должен быть actionable — говорить КАК разблокироваться, а не только ЧТО не так.

## PreToolUse enforcers (5)

| Хук | Matcher | Блокировка | Bypass |
|---|---|---|---|
| `code-skill-enforcer.py` | Write\|Edit\|Bash | Write без Skill() | Skill() активация |
| `approval-gate.py` | Skill | `/implement-1c-task` без approved `.openspec.yaml` | `/opsx:approve` |
| `root-clutter-guard.py` | Write | `test_*` / `temp_*` / `debug_*` в корне | сохранить в `tests/` или `data/` |
| `z-ai-write-guard.py` | Write\|Edit | >15 строк кода без `llm_complete` в сессии | вызов `mcp__llm-rotation__llm_complete` |

Также пропускаются non-code расширения (`.md`, `.json`, `.yml`, …). **Исключение:** большие `.md` (>50 строк) вне `.claude/` НЕ exempt — документацию можно делегировать на Z.AI (см. `_LARGE_MD_THRESHOLD`).
>

| `bulk-action-guard.py` | Bash | `rm` 5+ файлов / `rm -rf` | Q5 подтверждение от пользователя |

## Stop enforcers (4)

| Хук | Блокировка | Bypass |
|---|---|---|
| `task-enforcer.py` | pending tasks в `.claude/cache/hook-todos.json` | выполнить задачу или пометить complete |
| `git-commit-enforcer.py` | незакоммиченные изменения | `git commit` |
| `docs-change-enforcer.py` | код изменён, docs не обновлены | обновить `docs/` (есть `SKIP_PATTERNS` для инфра-файлов) |
| `roadmap-progress-enforcer.py` | merge-milestone в сессии, но `docs/roadmap/` не тронут (**soft, block-once**) | обновить §18 Progress Log, или просто завершить снова (sentinel пропускает), или `ROADMAP_PROGRESS_NO_ENFORCE=1` |

`docs-change-enforcer.py` имеет existence filter: файлы, удалённые в пределах 6-часового окна `git log`, игнорируются — стрей-артефакты не блокируют завершение.

### `roadmap-progress-enforcer.py` — soft block-once

Реализует §19.3 P1 trigger-detection дорожной карты [`260523_ROADMAP_FULL_DEV_LIFECYCLE_ANALYSIS.md`](../../../roadmap/260523_ROADMAP_FULL_DEV_LIFECYCLE_ANALYSIS.md): закрывает gap, где обновление §18 Progress Log держалось только на memory-anchor `feedback_roadmap_progress_log_protocol`.

- **Детект milestone:** парсит transcript JSONL на Bash `tool_use` с `gh pr merge` / `git merge` (НЕ raw-text → чтение роадмапа, полного слова «MERGED», не даёт false-positive). Исключены `git merge-base`, `--abort`, `--quit`.
- **Soft = block-once per session:** при срабатывании блокирует Stop **один раз**, записывая sentinel в `.claude/cache/roadmap-progress-enforcer-state.json` (FIFO cap 200, atomic `os.replace`). Повторный Stop в той же сессии проходит → хук не deadlock'ит, если milestone не roadmap-worthy.
- **Не блокирует**, если `docs/roadmap/` уже изменён эту сессию (working tree + session-bounded `git log`, auto-save commits включены).
- **Дизайн-выбор precision-over-recall:** для soft-enforcer'а ложная блокировка хуже редкого пропуска (раздражает → отключат через opt-out). Поэтому regex ловит только две однозначные формы (`gh pr merge`, прямой `git merge X`). Редкий `-c`-префиксный мерж (`git -c merge.ff=false merge X`, где `git` не сразу за `merge`) **намеренно не покрыт** — расширение до `git.*merge` дало бы false-positive на `git log --grep merge` / `git config merge.tool`. **YAGNI:** если появится workflow, реально использующий `git -c merge.* merge`, — добавить точечный отдельный паттерн под него, а не расширять основной regex. Страховка для непокрытого случая — тот же memory-anchor.

## Как хуки добавляют задачи

```
reminder-хук ──[add_task()]──→ .claude/cache/hook-todos.json
                                    │
                              [Stop event]
                                    │
                                    ▼
                            task-enforcer.py
                              │         │
                         pending?    empty?
                              │         │
                          exit(2)    exit(0)
                          BLOCK      ALLOW
```

Reminder-хуки (`knowledge-cache-reminder`, `factory-enforcer`, `auto-git-save`, `docs-change-tracker`) добавляют задачи через `add_task()`. При попытке завершить сессию `task-enforcer.py` проверяет очередь. Незавершённые задачи блокируют выход.

Файл `hook-todos.json` защищён:
- **File lock**: Windows `msvcrt.locking()` / Unix `fcntl.flock()`
- **Atomic writes**: запись во временный файл + `os.replace()`
- **Cooldown**: повторная задача того же типа не добавляется чаще 5 минут

## Примеры блокировок

**Сценарий 1**: Claude вызывает `Write` без активации `Skill()`.
```
code-skill-enforcer: exit(2)
reason: "Активируйте релевантный скилл перед Write. Вызовите Skill('bsl-development') или Skill('learning-loop')."
```
→ Claude активирует скилл и повторяет Write.

**Сценарий 2**: Пользователь нажимает Stop, есть изменения.
```
git-commit-enforcer: exit(2)
reason: "Обнаружены незакоммиченные изменения (3 файла). Создайте коммит перед завершением."
```
→ Claude делает `git commit`.

**Сценарий 3**: Claude пишет 50 строк Python-кода напрямую.
```
z-ai-write-guard: exit(2)
reason: "Write содержит 50 строк кода, но llm_complete не вызывался. Делегируйте генерацию через Z.AI."
```
→ Claude вызывает `mcp__llm-rotation__llm_complete`, получает код, затем пишет.
