# 30.4 Метрики и самообучение

> Система собирает метрики активаций скиллов, маршрутизации и делегирования
> в трёх слоях (JSONL, SQLite, Dashboards) и автономно адаптируется
> через LinUCB-бандита для оптимизации решений.

---

## Слои измерения

```
┌──────────────────────────────────┐
│ 1. JSONL логи (append-only)      │  human-readable, git-friendly
├──────────────────────────────────┤
│ 2. SQLite (hook_metrics_db.py)   │  запросы, агрегация, p95
├──────────────────────────────────┤
│ 3. Dashboards (CLI + HTML + UI)  │  видимость для разработчика
└──────────────────────────────────┘
```

## skill-accuracy.jsonl

Per-prompt корреляция рекомендаций и активаций через `prompt_id`:

```
skill-router.py (recommend)  →  prompt_id  →  skill-usage-metrics.py / prompt-detection (activate)
                                    │
                           data/skill-accuracy.jsonl
                                    │
                            {ts, type, prompt_id, skills/skill, source}
```

Два источника активаций:

**PostToolUse:Skill** (`skill-usage-metrics.py`) — прямой источник. Фиксирует вызов инструмента `Skill()`. Имеет баг #6305 на Windows (не всегда срабатывает).

**Prompt-detection** (`skill-router.py:_detect_skill_activations`) — workaround. Парсит теги `<command-name>` из предыдущего turn сессии. Покрывает пропуски PostToolUse.

Формат записи:
```json
{"ts": "2026-04-23T12:34:56", "type": "recommend", "prompt_id": "a1b2c3d4", "skills": ["bsl-development", "1c-doc-research"], "prompt": "как написать обработку проведения"}
{"ts": "2026-04-23T12:35:02", "type": "activate", "prompt_id": "a1b2c3d4", "skill": "bsl-development", "source": "prompt-detection"}
```

## SQLite hook_metrics_db.py

Таблицы:

| Таблица | Колонки | Назначение |
|---|---|---|
| `hook_metrics` | name, exec_ms, status, ts | exec time, errors, p95_ms по каждому хуку |
| `skill_activations` | ts, skill, source, prompt_id | прямой лог активаций с источником |
| `skill_accuracy` | prompt_id, recommended, activated, match | корреляция рекомендаций и активаций |

Auto-migration: колонка `source` добавляется при первом запуске на старой схеме через `_migrate()`. Схема обновляется без ручного вмешательства.

API: `get_hook_metrics()`, `get_skill_metrics()` (incl. `by_source`), `get_accuracy_metrics()`, `get_enforcement_metrics()`, `get_error_log()`.

## DelegationBandit (LinUCB)

Автономная маршрутизация делегирования на Z.AI.

Параметры:
- **4 arm**: Soft / Medium / Hard / Never
- **6-dim context features**: content_type, domain, size, time-of-day, complexity, history
- **Pure numpy**, без внешних ML-зависимостей
- **State**: `data/delegation-bandit.pkl`

Warm-up этапы:

| Outcomes | Режим | Поведение |
|---|---|---|
| <20 | RULE_BASED | детерминированные правила по матрице content_type × size |
| 20–50 | HYBRID | правила + bandit взвешенно |
| >50 | AUTONOMOUS | полностью на bandit |

Интеграция:
- `delegation-outcome-tracker.py` — online update после каждого делегирования
- `z-ai-delegation-enforcer.py` — routing при `UserPromptSubmit`

CLI: `python -m src.shared.delegation_bandit dashboard` — текущее состояние бандита.

Текущий статус (2026-04): 544 outcomes trained, 89.2% delegation rate.

## delegation-outcomes.jsonl

TensorZero-совместимый формат:

```json
{
  "content_type": "code",
  "domain": "framework",
  "classification": "Hard",
  "context_features": [0.8, 0.2, 0.5, 0.1, 0.9, 0.3],
  "delegated": true,
  "outcome": "success"
}
```

Каждые 20 outcomes запускается learning loop: анализ → калибровка rule-based матрицы.
