# 30.5 Token Economy и MCP-экосистема

> Делегирование кодогенерации на Z.AI (правило >15 строк) +
> 21+ MCP-сервер в 4 профилях дают специализированные
> инструменты под конкретную задачу без перерасхода токенов.

---

## Правило делегирования >15 строк

```
Write/Edit код >15 строк
   │
   ├─ llm_complete вызван в сессии? → ALLOW (z-ai-write-guard exit 0)
   └─ Нет вызова?                   → BLOCK (exit 2, reason: «делегируй на Z.AI»)
```

Роли в системе:
- **Opus = Planner/Reviewer** — планирует архитектуру, ревьюит результат, пишет критичные места (security, сложная отладка)
- **Z.AI = Coder** — генерирует boilerplate, тесты, docs по спецификации

## Token Economy компоненты

| Компонент | Event | Назначение |
|---|---|---|
| `z-ai-delegation-enforcer.py` | UserPromptSubmit | сигналит Medium/Hard на делегируемых задачах |
| `z-ai-write-guard.py` | PreToolUse Write\|Edit | блокирует >15 строк без `llm_complete` |
| `delegation-outcome-tracker.py` | PreToolUse Write | пишет outcome в `delegation-outcomes.jsonl` |
| Skill `z-ai-delegation` | — | шаблоны Draft → Review |

Exempt для `z-ai-write-guard`:
- `.claude/` (настройки хуков и скиллов)
- `docs/` (кроме `data/analyze-1c-research/` — там enforced)
- Non-code файлы (`.json`, `.yaml`, `.txt`)
- `.md` файлы до 50 строк (кроме `data/analyze-1c-research/`)

## LLM Rotation v2.0

Архитектура с отказоустойчивостью (5 итераций, 101 тест):

```
┌─────────────────────────────────────────────┐
│ 5 провайдеров                                │
│ zai-glm5 (primary), gemini, openrouter,      │
│ ollama-local, ollama-cloud                   │
├─────────────────────────────────────────────┤
│ Circuit Breaker: Closed / Open / Half-Open   │
│ fail_threshold, reset_timeout, force_open 429│
├─────────────────────────────────────────────┤
│ BackoffStrategy: exponential + jitter + cap  │
│ + Retry-After header                         │
├─────────────────────────────────────────────┤
│ Health Check: background loop, auto-recovery │
├─────────────────────────────────────────────┤
│ Multi-level failover: model fallback внутри  │
│ провайдера на transient errors               │
├─────────────────────────────────────────────┤
│ AdaptiveScorer: quality + latency + cost     │
│ window_size=20, композитный score            │
├─────────────────────────────────────────────┤
│ BudgetTracker: дневной бюджет, alert 80%     │
└─────────────────────────────────────────────┘
```

Конфиг: 15 settings с префиксом `LLM_ROTATION_` (cb, backoff, health_check, adaptive, budget).

При all-providers-failed: `mcp__llm-rotation__llm_reset_provider` сбрасывает state.

## MCP профили

Конфигурации в `.mcp/`:

| Профиль | Содержание |
|---|---|
| `pdf.json` | Минимальный: `pdf-vector-graph` только |
| `bsl.json` | 1С + BSL: `1c-mcp-crud`, `bsl-semantic-search`, `bsl-platform-context`, `auto-documenter` |
| `full.json` | Всё: + `memory-orchestrator`, `serena`, `openspec-mcp` |
| `lazy-mcp.json` | Прокси: 22 on-demand серверов, 10 категорий |

Переключение профиля — через `.mcp.json` symlink или Claude Code CLI флаг.

## lazy-mcp — on-demand загрузка

11 категорий: git, web, files, docs, testing, debug, database, ml, security, cloud, misc.

Принцип: серверы стартуют только при вызове tool. Экономит память и токены — неактивные серверы не потребляют ресурсы.

```
Claude → lazy-mcp proxy ─[first call]─→ spawn target MCP server
                      │
                      └─[subsequent]──→ route to running server
```

Конфигурация: `.mcp/lazy-mcp.json`. Подробности в [главе 26](../../3_ИНСТРУМЕНТЫ/3.3_LAZY_MCP/26.1_Обзор.md).

## Экономика

Token savings (типичная сессия с 5 Write-операциями по 40 строк):

| Режим | Input tokens | Output tokens | Cost |
|---|---|---|---|
| Opus пишет сам | ~3k (context) | ~10k (5 × 2k) | $$$ |
| Z.AI Coder + Opus Review | ~3k (context) + ~5k (Z.AI output обратно на ревью) | ~2k (финальный Write) | $ |

Экономия ~70% при сопоставимом качестве (Opus проверяет каждый блок перед Write).
