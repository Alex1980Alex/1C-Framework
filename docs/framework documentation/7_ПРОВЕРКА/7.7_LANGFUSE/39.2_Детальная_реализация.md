## LangfuseCallbackHandler (LangChain layer)

[`callbacks/langfuse/langfuse_callback.py`](../../../../src/pdf_framework/callbacks/langfuse/langfuse_callback.py) — с **2026-07-04** субклассирует **нативный v4 LangChain-хендлер** `langfuse.langchain.CallbackHandler` (файл, `Version: 2.0.0`). Ранее это был ручной хендлер поверх `langchain_core.callbacks.BaseCallbackHandler`, вызывавший **v2**-методы `client.generation()` / `client.span()` — их нет на v4-клиенте (4.6.x), каждый вызов бросал `AttributeError`, который глотал broad `except` → трейсинг был молча мёртв. Нативный хендлер эмитит корректные v4 OTel-observations; креды прокидываются конструированием глобального `Langfuse`-клиента до `super().__init__` (нативный хендлер находит его через `get_client()`).

### Credentials resolution (4 шага)

`_resolve_credentials()`:
1. **Explicit args** из constructor (DI для тестов)
2. **pydantic-settings**: `get_settings().observability.langfuse_*` (canonical)
3. **os.environ**: `LANGFUSE_PUBLIC_KEY` / `LANGFUSE_SECRET_KEY` / `LANGFUSE_HOST` (legacy fallback)
4. **None** → handler self-disable с WARNING

Final host fallback: `https://cloud.langfuse.com`.

### Callback lifecycle

С миграцией на нативный v4-хендлер (2026-07-04) ручные `on_*`-методы **удалены** — `on_llm_start` / `on_chain_start` / `on_tool_start` / … теперь **наследуются** от `langfuse.langchain.CallbackHandler` и эмитят v4 OTel-observations с корректной вложенностью span. Per-trace `user_id` / `session_id` в v4 крепятся через runnable-config metadata (`langfuse_user_id` / `langfuse_session_id`).

Таблица ниже — **историческая** (ручной v2-хендлер до 2026-07-04, `client.generation()` / `client.span()` **больше не вызываются**):

| Метод (v2, удалён) | Langfuse object (v2) |
|-------|-----------------|
| `on_llm_start` | `client.generation(name="llm_call", input=prompts)` |
| `on_llm_end` | `client.generation(..., output, usage={input, output, total}, metadata={model})` |
| `on_llm_error` | `client.generation(level="ERROR", status_message=str(error))` |
| `on_chain_start` | `client.span(name=chain_name, input=inputs)` |
| `on_chain_end` | `client.span(..., output=outputs)` |
| `on_chain_error` | `client.span(level="ERROR")` |
| `on_tool_start` | `client.span(name=f"tool:{name}", input=inputs)` |
| `on_tool_end` | `client.span(..., output=str(outputs))` |
| `on_tool_error` | `client.span(level="ERROR")` |
| `ignore_*` properties | Управление skip для llm/chain/agent/retriever |

### Особенности

- **Graceful try/except** в каждом `on_*`. Любая ошибка → `logger.warning`, не propagat'ится в pipeline.
- **`client.flush()`** вызывается в конце каждого `on_*_end` → real-time visibility (trade-off с latency 50-200ms, см. roadmap P0.1).
- **`metadata`** прокидывает `user_id` + `session_id` во все observations.

## LangfuseTracer (generic tracer layer)

[`observability/tracer.py:243`](../../../../src/pdf_framework/observability/tracer.py#L243) — `LangfuseTracer(BaseTracer)`, НЕ LangChain callback, а абстрактный tracer для произвольных операций:

```python
def start_span(name, attributes) -> Span
def end_span(span, status, output, error) -> None
def flush() -> None

# Specialized:
def record_query(query, results, latency_ms, score, user_id)
def create_generation(name, model, prompt, completion, tokens_in, tokens_out, latency_ms)
```

Factory: `get_tracer("langfuse", **kwargs)` в [`tracer.py:676`](../../../../src/pdf_framework/observability/tracer.py#L676):

```python
from src.pdf_framework.observability.tracer import get_tracer

tracer = get_tracer("langfuse", enabled=True)
with tracer.span("search.hybrid", strategy="vector+bm25"):
    results = await search.run(query)
tracer.record_query(query, results, latency_ms=42, score=0.87)
```

## langfuse_setup.py (singleton + helpers)

[`observability/langfuse_setup.py`](../../../../src/pdf_framework/observability/langfuse_setup.py).

### `_get_langfuse_client()` — memoized singleton

Module-level state:
```python
_LANGFUSE_CLIENT: Any = None
_LANGFUSE_CLIENT_INIT_FAILED: bool = False
```

Init failure (ImportError / missing creds / network) → cached в `_INIT_FAILED=True`, no retry.

**Зачем**: hot-path `search/manager.py` + `tools/*` делают много observations. Per-call `Langfuse(...)` overhead ~500ms (HTTP discovery + auth).

### `is_langfuse_enabled()` — opt-out check

Проверяет:
1. `MEMORY_HOOK_NO_LANGFUSE=1` env (для standalone hooks)
2. `get_settings().observability.langfuse_enabled` (canonical config)

### `build_langfuse_callback(user_id, session_id)` — LangChain integration entry

Композирует:
- `is_langfuse_enabled()` check → None если disabled
- Import `LangfuseCallbackHandler` → None при ImportError
- Constructor → `handler`
- `handler._enabled` check → None если self-disable'ился

Caller pattern (тула / агент):
```python
from src.pdf_framework.observability.langfuse_setup import build_langfuse_callback

handler = build_langfuse_callback(user_id=ctx.user, session_id=ctx.session)
if handler is not None:
    llm.callbacks = (llm.callbacks or []) + [handler]
```

### `emit_observation()` — standalone hooks

Не-LangChain код (Stop-хуки, MCP-серверы, CLI):

```python
from src.pdf_framework.observability.langfuse_setup import emit_observation

emit_observation(
    name="memory-first-hook.search",
    input={"query": q},
    output={"hits": len(results)},
    session_id=session_id,
    user_id=user_id,
    metadata={"strategy": "hybrid"},
    flush=True,
)
```

Внутри:
- `is_langfuse_enabled()` check (short-circuit)
- `_get_langfuse_client()` (singleton)
- `client.start_observation(name, as_type="span", input=input)` (Langfuse v4 API)
- `span.update(output=output, metadata=meta)` finally `span.end()`
- `client.flush()` если `flush=True`
- Все exceptions swallowed → never raise

Pattern из `doneyli/claude-code-langfuse-template` (roadmap §5c.4).

## Integration points

### Search Manager

[`search/manager.py`](../../../../src/pdf_framework/search/manager.py) оборачивает каждую стратегию в Langfuse span:

```python
tracer = get_tracer("langfuse" if settings.observability.langfuse_enabled else "none")
with tracer.span(f"search.{strategy}", k=k, query_len=len(query)):
    results = await self._strategies[strategy].search(query, k=k)
tracer.record_query(query, results, latency_ms, score=None, user_id=ctx.user_id)
```

### Tools layer

[`tools/retrieval/search_tool.py`](../../../../src/pdf_framework/tools/retrieval/search_tool.py), [`document/index_tool.py`](../../../../src/pdf_framework/tools/document/index_tool.py), [`graph_query/graph_tool.py`](../../../../src/pdf_framework/tools/graph_query/graph_tool.py) — каждый tool через `build_langfuse_callback()` инъектит handler в свой LangChain `Tool`.

### Agents layer

[`agents/rag/middleware.py`](../../../../src/pdf_framework/agents/rag/middleware.py) — middleware для RAG-нод. На каждый node invocation добавляет Langfuse callback в `RunnableConfig`. Resulting trace tree:

```
trace: rag_invocation
  ├─ span: retrieve
  │   └─ span: search.hybrid (vector + bm25 + rrf)
  ├─ span: grade_documents (LLM)
  │   └─ generation: grader_llm (Claude Haiku)
  ├─ span: generate_answer
  │   └─ generation: answer_llm (Claude Opus)
  └─ span: hallucination_check
      └─ generation: check_llm (Claude Haiku)
```

## Trade-offs

| Решение | Pro | Con |
|---------|-----|-----|
| Sync `flush()` per span | Real-time UI | Latency overhead ~50-200ms |
| Singleton client | No per-call init | Process-level state, harder testing |
| Graceful no-op when disabled | Zero impact в dev | Дублирование callback-логики |
| Pydantic-settings + env fallback | Canonical config + backward compat | 4-step resolution — сложнее дебажить |

## Версии и совместимость

- **Langfuse SDK v4** (`langfuse>=4.0,<5.0` в `pyproject.toml`, установлен 4.6.x) — breaking change vs v2. На v4-клиенте нет `client.generation()` / `client.span()`; observations эмитятся через нативный LangChain-хендлер + `client.start_observation()` (в `emit_observation`)
- **LangChain 1.x post-split** — `langfuse>=4.0` required (issue #9758)
- **Unify DONE (2026-07-04)**: хендлер мигрирован на нативный v4 `langfuse.langchain.CallbackHandler`; ручные v2-методы удалены. Прежний mix v2-handler + v4-`emit_observation` устранён (roadmap P0.4 закрыт)
