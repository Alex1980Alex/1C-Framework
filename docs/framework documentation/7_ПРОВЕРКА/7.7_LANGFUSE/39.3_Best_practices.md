## Best practices (synthesis)

### 1. Initialize once, reuse client

Все Tier-1 примеры используют **singleton client**. Per-call `Langfuse(...)` overhead ~500ms. Наш `_get_langfuse_client()` ✓ соответствует pattern.

### 2. Graceful degradation

Все Tier-1 примеры — try/except + ImportError handling. Наш код это соблюдает (handler self-disable + try/except в каждом `on_*`). ✓

### 3. Decorator OR callback — не оба

Tier-2 проекты используют **либо** `@observe()` для custom кода **либо** `CallbackHandler` для LangChain. Mixing создаёт дубль-трейсы.

**Наш выбор**: callback для LangChain workflows, `emit_observation()` helper для standalone hooks (equivalent decorator). ✓

### 4. Use sessions для user grouping

Tier-2 пробрасывают `session_id` + `user_id` в `metadata`. Filter traces, per-user cost, replay user journey. Наш handler принимает `(user_id, session_id)` в constructor. ✓

### 5. Flush на process exit, не на каждый span

**Trade-off**: real-time UI vs latency (flush = HTTP call).

Best practice: flush async batches в background thread (SDK default), explicit flush только в `atexit`.

**Наш код**: flush на каждый `on_*_end` — **антипаттерн**, теряем 50-200ms на запрос. Phase 47 cleanup candidate (roadmap P0.1).

### 6. Score через `client.score()` для eval

Pattern из `evaluation_of_rag_with_ragas.ipynb`:

```python
trace_id = client.trace(name="rag-query", input=q).id
results = await retrieve_and_answer(q)
ragas_score = ragas_evaluate(query=q, answer=a, contexts=ctx)
client.score(trace_id=trace_id, name="faithfulness", value=ragas_score)
```

Наш `evaluation/ragas_adapter.py` **НЕ** пишет в Langfuse. Roadmap P0.2.

### 7. Prompt versioning через `langfuse.get_prompt()` (опц.)

Централизованное хранение промптов с A/B. Tier-2 используют для production rollout. У нас промпты в `src/pdf_framework/prompts/` — DSPy signatures, не Langfuse. Defer (vendor lock-in).

### 8. Sampling для cost control

В high-throughput setups (>100 req/s) full tracing дорого. Server-side sampling 1-5% production + 100% errors. У нас ~10 req/min — не нужно.

### 9. Self-host для compliance / data residency

Tier-1 рекомендует Kubernetes Helm chart для production self-host. Roadmap P2.1.

### 10. Cost dashboard через breakdown

Build cost-by-model / cost-by-session dashboards если все generations имеют корректный `model` field. У нас передаётся `response.llm_output.get("model", "unknown")` — ✓.

### 11. Tag traces with version/env

`metadata={"env": "prod", "version": git_sha}` — cross-version comparison после deploy. У нас этого нет. Roadmap P0.3.

### 12. Distributed tracing через trace_id propagation

Если pipeline проходит через несколько процессов — пробрасывать `langfuse_trace_id` через HTTP header / message queue metadata (Tier-2 `richardwadsworth/rag-pipeline-observability`). У нас monolithic — не критично.

### 13. Custom observation types для domain events

[`discussion #6970`](https://github.com/orgs/langfuse/discussions/6970) показывает custom типы (`"reranking"`, `"chunk_split"`, `"embedding_batch"`). У нас могли бы:
- BSL parser stages
- Graph builder phases
- Embedding batches

### 14. Mock client для tests

`LangfuseCallbackHandler` принимает explicit creds (DI) — ✓ testable. Roadmap P1.4 — добавить `tests/integration/test_langfuse.py`.

### 15. Monitor SDK errors отдельно

SDK сам может ронять (network, queue overflow). У нас `logger.warning(f"[LANGFUSE] ...")` с distinct prefix. ✓

## Антипаттерны в нашем коде

| Антипаттерн | Где | Почему плохо | Roadmap fix |
|-------------|-----|--------------|-------------|
| Sync flush per span | `on_*_end` | latency 50-200ms на каждом callback | P0.1 async flush |
| ~~Mixing v2/v4 API~~ (устранено 2026-07-04) | было: v2 `client.span()` в handler vs v4 `client.start_observation()` | breaking при SDK update | ✅ P0.4 DONE — handler на нативном v4 `langfuse.langchain.CallbackHandler` |
| No trace tagging by env/version | везде | hard сравнивать versions | P0.3 add metadata |
| No RAGAS → Langfuse score | `evaluation/ragas_adapter.py` | quality disconnected from traces | P0.2 linkage |
| Manual handler injection в каждый tool | `tools/*.py` | повтор кода | P1 middleware-decorator |

## Сравнение с альтернативами

| Tool | Pro | Con vs Langfuse |
|------|-----|-----------------|
| **LangSmith** | Native LangChain, нулевой setup | Paid, proprietary, lock-in |
| **Arize Phoenix** | OSS, OpenTelemetry-native | Меньше LLM-specific (sessions, scoring) |
| **W&B Prompts** | Strong ML pipeline | Heavy product, дорого |
| **OpenLLMetry** | OTEL standard, multi-backend | Только базовый tracing |
| **Helicone** | Proxy-based (no SDK) | Менее flexible, intermediate layer |

Langfuse выбран за: OSS, self-host option, LLM-specific UI, free tier.
