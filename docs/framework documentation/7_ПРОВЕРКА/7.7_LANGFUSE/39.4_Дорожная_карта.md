## P0 — closing visible gaps (~10ч)

### P0.1 — Async flush (~3ч)

**Проблема**: `client.flush()` в каждом `on_*_end` callback. Synchronous HTTP, +50-200ms latency на каждом callback. На 10-15 spans в RAG-агенте — overhead 1-3 сек.

**Fix**: убрать explicit flush из callbacks, полагаться на SDK async background thread. Final `flush()` только в `atexit.register()`.

**Эффект**: -50-200ms на каждый LLM-вызов.

### P0.2 — RAGAS → Langfuse score linkage (~4ч)

**Проблема**: `evaluation/ragas_adapter.py` вычисляет RAGAS metrics (faithfulness, answer_relevancy, context_precision), но они **не привязаны** к Langfuse traces.

**Fix**: после RAGAS-eval вызывать `langfuse_client.score(trace_id=..., name="faithfulness", value=...)`. Pattern из cookbook [`evaluation_of_rag_with_ragas.ipynb`](https://github.com/langfuse/langfuse-docs/blob/main/cookbook/evaluation_of_rag_with_ragas.ipynb).

**Эффект**: dashboards с recall@k/faithfulness per session, основа для production quality gating.

### P0.3 — Trace tagging by env/version/git_sha (~1ч)

**Проблема**: traces от dev/staging/prod невозможно distinguish.

**Fix**: в `build_langfuse_callback()` default `metadata={"env": $ENV, "git_sha": $GIT_SHA, "framework_version": "X.Y.Z"}`. Auto-detect.

### P0.4 — Unify v2/v4 API ✅ DONE (2026-07-04)

**Проблема (была)**: handler вызывал **v2** `client.generation()` / `client.span()` (которых нет на v4-клиенте → `AttributeError`, глотался `except` → трейсинг молча мёртв), `emit_observation()` использует v4 `client.start_observation()`.

**Выполнено**: handler мигрирован на нативный v4 `langfuse.langchain.CallbackHandler` (субкласс); ручные v2-методы удалены, observations эмитятся через нативный хендлер. См. [`langfuse_callback.py`](../../../../src/pdf_framework/callbacks/langfuse/langfuse_callback.py) (`Version: 2.0.0`).

## P1 — production hardening (~15ч)

### P1.1 — Custom observation types (~4ч)

Emit specialized observations для:
- `bsl_parser.parse_file` (per file)
- `graph_builder.extract_entities` (per chunk)
- `embedding.batch` (TEI/qwen3)
- `qdrant.upsert` (per batch)

Pattern: [discussion #6970](https://github.com/orgs/langfuse/discussions/6970).

### P1.2 — Distributed trace_id propagation (~6ч)

**Когда**: при multi-process / multi-machine deploy.

Пробрасывать `langfuse_trace_id` через HTTP X-Trace-Id, MCP message metadata, async job queue.

Pattern: [richardwadsworth/rag-pipeline-observability](https://github.com/richardwadsworth/rag-pipeline-observability).

### P1.3 — Prompt versioning через `langfuse.get_prompt()` (~5ч)

**Trade-off**: vendor lock-in vs централизованное storage. **Decision**: defer until clear non-developer prompt-editing need.

### P1.4 — Mock client tests (~2ч)

`tests/integration/test_langfuse.py` — mock `Langfuse` client. Verify lifecycle: init, callback dispatch, graceful degradation, flush.

## P2 — observability maturity (~25ч)

### P2.1 — Self-host Kubernetes (~1д)

**Когда**: compliance (data residency) или predictable cost.

Helm chart deployment, Postgres + ClickHouse, ingress, Vault secrets.

### P2.2 — Cost dashboards / alerts (~6ч)

В Langfuse Cloud build:
- Cost per model per day (Claude Opus vs Haiku vs GPT-4)
- Top 20 most expensive sessions
- p95 latency per agent node
- Error rate per tool

Slack webhooks при FAIL spike / cost threshold breach.

### P2.3 — Sampling (~4ч)

Server-side sampling 1-5% production + 100% errors. Сейчас не нужно (~10 req/min).

### P2.4 — Auto-cleanup старых traces (~3ч)

Только для self-host. Retention policy в Postgres. Cron `DELETE FROM traces WHERE created_at < now() - interval '90 days'`.

### P2.5 — Trace export для offline analysis (~8ч)

`Langfuse API → S3 → DuckDB/ClickHouse local` pipeline. Для year-over-year analytics без cloud retention limits.

## P3 — advanced (deferred)

### P3.1 — Migrate на OpenTelemetry standard

**Когда**: если потребуется vendor-neutral (mix Langfuse + Prometheus + Tempo).

**Trade-off**: универсальность vs потеря LLM-specific UI.

### P3.2 — LLM-as-judge auto-scoring

Background job → sampled traces → Haiku grading (`"answer faithful to context: yes/no"`) → `client.score()`. Cheap auto-quality monitoring (~6-8ч).

### P3.3 — Playground integration

Langfuse Playground UI для prompt-tuning. Zero code, требует team credentials access.

### P3.4 — Audit log для prod events

`audit.*` observations на каждый: user feedback, prompt change, model swap, config update. Compliance trail.
