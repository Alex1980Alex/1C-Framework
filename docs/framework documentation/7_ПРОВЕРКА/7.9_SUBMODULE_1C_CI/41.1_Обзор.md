# 41.1 Обзор — CI для submodule-репозиториев 1С

## Что это

Глава описывает паттерн **per-submodule CI** для 1С конфигураций, живущих в отдельных Git-репозиториях, подключённых к основному `1C-Framework` репозиторию как git submodules.

**Первая реализация (2026-05-24):** `IBTransportManagementDevelop-Configuration` (submodule path `ИБTransportManagementDevelop/Конфигурация/`).

## Зачем

В этом репо `1C-Framework` основная разработка — **Python** (RAG framework, MCP серверы, hooks). 1С код разрабатывается в **отдельных репозиториях** (submodules):

```
1C-Framework/                                    ← Python main repo
├── src/                                         ← Python code
├── .github/workflows/ci.yml                     ← Python CI
├── .github/workflows/ci-1c.yml                  ← main-repo 1С CI (self-hosted, 5 jobs)
└── ИБTransportManagementDevelop/Конфигурация/   ← submodule
    └── .github/workflows/ci.yml                 ← НОВОЕ: per-submodule 1С CI
```

**Ограничения main-repo `ci-1c.yml` (self-hosted):**
- Self-hosted runner only (`runs-on: [self-hosted, windows-11, 1c]`)
- Когда runner offline → jobs навсегда `QUEUED`
- Triggers на изменения в main repo, не отслеживает изменения внутри submodules
- Visual noise в PR checks даже если PR не трогает 1С

> Примечание: `ci-1c.yml` — **не** заброшенный legacy. Он активно развивается (5 job'ов: `bsl-analysis` с SonarQube QG, `yaxunit-tests`, `bdd-tests`, `coverage` с Coverage41C, `allure-report`) и остаётся основным 1С-CI для main repo. Per-submodule workflow — дополняющий паттерн для standalone-репозиториев конфигураций, а не замена.

**Решение — per-submodule CI:**
- Каждый 1С submodule имеет собственный `.github/workflows/ci.yml`
- BSL Static на **GitHub-hosted Linux** (always available, free)
- YAxUnit + BDD на self-hosted Windows
- Triggers только на изменения внутри submodule → нет шума для Python-only PR в main

## Четыре job'а в submodule workflow

| Job | Runner | Время | Что проверяет |
|-----|--------|-------|---------------|
| **bsl-static** | GitHub-hosted `ubuntu-latest` | ~2-3 мин | BSL Language Server — syntax, code smells, complexity |
| **yaxunit-tests** | self-hosted `windows-11, 1c` | ~10-15 мин | Unit тесты через 1С платформу + YAxUnit framework |
| **bdd-tests** | self-hosted `windows-11, 1c` | ~15-30 мин | E2E UI scenarios через VanessaAutomation |
| **pr-summary** | GitHub-hosted `ubuntu-latest` | ~10 сек | Aggregated PR comment с результатами |

## Преимущества per-submodule vs main-repo ci-1c.yml

| Аспект | Main-repo ci-1c.yml | Новый per-submodule |
|--------|------------------|---------------------|
| BSL Static без self-hosted runner | ❌ Нет | ✅ Да (Linux + JAR) |
| Triggers только на 1С изменения | ❌ Любой push в main | ✅ Только submodule |
| PR в main repo показывает 1С checks | ❌ Visual noise | ✅ Нет |
| Кеширование BSL LS JAR | ❌ Локально | ✅ GitHub Actions cache |
| Standalone 1С repos | ❌ Только monorepo | ✅ Self-contained |

## Применимость

Этот паттерн применим к 1С submodule-репозиторию который:
- Содержит 1С конфигурацию в EDT-формате (`src/` с CommonModules/, Catalogs/, etc.)
- Имеет dedicated GitHub repo
- Имеет (или планирует) BSL unit-тесты через YAxUnit
