# 41.3 Self-hosted runner setup

Пошаговый guide как настроить self-hosted GitHub Actions runner на Windows ПК с 1С:Предприятие для запуска YAxUnit + BDD jobs.

## Зачем self-hosted

YAxUnit и BDD jobs требуют:
- 1С:Предприятие 8.3.27+ Server / Thin Client / OneScript
- Windows OS (1С платформа Windows-only)
- Live infobase (для интеграционных тестов)

GitHub-hosted runners НЕ имеют 1С → нужен ваш ПК с runner агентом.

## Prerequisites

### Hardware/OS
- Windows 10/11 x64 (или Windows Server 2019+)
- Минимум 8GB RAM (1С + Java + runner процессы)
- 50GB свободного диска (1С + test infobase + cache)
- Постоянное интернет соединение (для polling GitHub Actions queue)

### Software (должно быть установлено заранее)

| Tool | Версия | Назначение | Установка |
|------|--------|------------|-----------|
| 1С:Предприятие | 8.3.27+ | Платформа для YAxUnit/BDD | `setup.exe` от 1С (требует лицензию) |
| OneScript | 1.9+ | Runtime для vrunner | https://oscript.io/ |
| vrunner | latest | CLI launcher для 1С | `opm install vrunner` |
| Git | 2.40+ | Checkout workflow | https://git-scm.com/ |
| Java (JDK) | 17+ | Опционально для local BSL Static тестов | https://adoptium.net/ |

**Проверка:**

```powershell
# 1С:Предприятие
Get-ChildItem "C:\Program Files\1cv8\*" | Select-Object -First 1

# OneScript
oscript -version

# vrunner
vrunner --help | Select-Object -First 5

# Java
java -version
```

## Шаг 1: Регистрация runner в GitHub

Перейдите в репо submodule:

```
https://github.com/Alex1980Alex/IBTransportManagementDevelop-Configuration
  → Settings (нужно admin access)
  → Actions
  → Runners
  → New self-hosted runner
  → Choose Windows x64
```

GitHub покажет команды установки. Выполните их в PowerShell как admin:

```powershell
# Создать рабочую директорию
mkdir C:\actions-runner
cd C:\actions-runner

# Скачать пакет (URL из GitHub UI — версия может отличаться)
Invoke-WebRequest -Uri https://github.com/actions/runner/releases/download/v2.319.1/actions-runner-win-x64-2.319.1.zip -OutFile actions-runner.zip

# Распаковать
Add-Type -AssemblyName System.IO.Compression.FileSystem
[System.IO.Compression.ZipFile]::ExtractToDirectory("$PWD/actions-runner.zip", "$PWD")

# Сконфигурировать с токеном из GitHub UI
./config.cmd --url https://github.com/Alex1980Alex/IBTransportManagementDevelop-Configuration --token <YOUR_TOKEN>
```

**Во время config:**
- Runner name: `WIN-1C-RUNNER-01` (или любое узнаваемое имя)
- Runner group: `default`
- **Labels** (КРИТИЧНО — должны точно соответствовать workflow): `windows-11,1c`
  - `self-hosted` добавляется автоматически
- Work folder: `_work` (default)

После config:

```powershell
# Запустить runner интерактивно (для тестирования)
./run.cmd

# Когда подтвердили работу — установить как Windows service
./svc.cmd install
./svc.cmd start
```

## Шаг 2: Verify runner online

GitHub repo → Settings → Actions → Runners:

```
WIN-1C-RUNNER-01    🟢 Idle    Labels: self-hosted, windows-11, 1c
```

Должно быть зелёный круг `Idle`. Если `Offline` — проверить service:

```powershell
Get-Service "actions.runner.Alex1980Alex-IBTransportManagementDevelop-Configuration.WIN-1C-RUNNER-01"
```

## Шаг 3: Подготовить runner environment

Workflow expects следующие пути (можно адаптировать env vars в ci.yml):

```yaml
env:
  VRUNNER_PATH: 'C:\Tools\OneScript\bin\vrunner.bat'
  TOOLS_PATH: 'D:\1C-FW\tools'
  IB_CONNECTION: '/SKOMPUTER\testdb1c'
```

**Проверить что эти пути существуют на runner machine:**

```powershell
Test-Path "C:\Tools\OneScript\bin\vrunner.bat"  # Должен быть True
Test-Path "D:\1C-FW\tools\vanessa\YAxUnit-25.12.cfe"  # YAxUnit framework
Test-Path "D:\1C-FW\tools\yaxunit.json"  # Конфиг YAxUnit
```

**Если пути отличаются** — отредактировать env в `.github/workflows/ci.yml` submodule репо.

## Шаг 4: Подготовить test infobase

Workflow подключается к `IB_CONNECTION: '/SKOMPUTER\testdb1c'` (SQL Server `SKOMPUTER`, база `testdb1c`).

**Если у вас другой setup:**

1. **File-based ИБ:** `IB_CONNECTION: 'F:\path\to\infobase'`
2. **Server-based на другом сервере:** `IB_CONNECTION: '/MYSERVER\dbname'`
3. **С указанием пользователя:** добавить `--db-user` flag в command

Test infobase должен:
- Иметь configuration загруженную (из submodule's `src/`)
- Иметь user (логин/пароль match secrets `USER_1C_LOGIN`/`USER_1C_PASS`)
- Иметь YAxUnit framework загруженный (`YAxUnit-25.12.cfe`)

## Шаг 5: Tests

Создать test PR в submodule репо:

```bash
cd "C:\1С-Framework\ИБTransportManagementDevelop\Конфигурация"
git checkout -b test-ci-setup
echo "# CI test trigger" > .ci-test
git add .ci-test
git commit -m "test: trigger CI workflow"
git push -u origin test-ci-setup
gh pr create --title "test: CI workflow trigger" --body "Triggering CI to verify runner setup"
```

Затем проверить:
1. GitHub UI → Actions → должен запуститься workflow
2. `bsl-static` — runs на Ubuntu, ~2-3 мин
3. `yaxunit-tests` — pickup self-hosted runner, ~10 мин
4. `bdd-tests` — same
5. `pr-summary` — посылает PR comment

## Maintenance

### Update runner

GitHub auto-updates runner agent (если разрешено в config). Manual update:

```powershell
cd C:\actions-runner
./svc.cmd stop
./config.cmd remove --token <REMOVE_TOKEN>
# Скачать новую версию + reconfigure
```

### Logs

```
C:\actions-runner\_diag\Runner_*.log  # Runner agent logs
C:\actions-runner\_diag\Worker_*.log  # Job execution logs
```

### Multiple runners

Можно установить **несколько runners** на одном ПК с разными именами:

```powershell
mkdir C:\actions-runner-02
cd C:\actions-runner-02
# ... повторить config с другим именем и token ...
```

Это позволяет parallel выполнение workflow (например 2 PR одновременно).

## Security considerations

См. [41.4 Secrets и безопасность](41.4_Secrets_и_безопасность.md):
- Runner имеет доступ к secrets через env vars
- Workflow code can read любые файлы на runner machine
- НЕ ставить runner на shared/общий PC
- НЕ давать runner access к production credentials
