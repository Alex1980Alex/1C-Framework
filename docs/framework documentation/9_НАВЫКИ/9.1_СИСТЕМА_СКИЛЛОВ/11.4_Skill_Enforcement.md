# 11.4 Skill Enforcement

> 6 уровней enforcement (A–F), Task Protocol, паттерны блокировки,
> Trust Scorer, Research Protocol.

---

## Обзор

Enforcement реализован двумя хуками:
- **Code Skill Enforcer** ([code-skill-enforcer.py](../../../../.claude/hooks/code-skill-enforcer.py)) — 6 уровней A-F
- **Task Protocol Enforcer** ([task-protocol-enforcer.py](../../../../.claude/hooks/task-protocol-enforcer.py)) — gate на Write/Edit

Оба работают через `PreToolUse` события (task-protocol-enforcer.py — только PreToolUse; code-skill-enforcer.py зарегистрирован ТОЛЬКО на PreToolUse — его PostToolUse-режим/`_handle_post` в коде есть, но не зарегистрирован в settings.json, см. ниже) и координируются через `SessionState`.

## Level B: Directory Rules (PRE)

Проверяет путь файла перед записью. Самый приоритетный уровень.

Конфигурация: `code-skill-patterns.json` → `directory_rules.mappings`

| Prefix | Required Skill | Label |
|--------|---------------|-------|
| `.claude/hooks/` | create-hook | Hook Development |
| `.claude/commands/` | claude-code-plugins | Slash Command Creation |
| `.claude/skills/` | doc-to-skill | Skill Creation |
| `src/agents/` | langgraph-core | LangGraph Agent Development |
| `src/graph_store/` | graph-operations | Graph Database Operations |
| `docker/` | deployment | Docker/Deployment |
| `.github/workflows/` | claude-code-github-actions | CI/CD Pipelines |
| `tests/` | evaluation-benchmark | Testing & Test Infrastructure |

**Всего:** 8 правил (все `skill` существуют в `.claude/skills/`)

**Алгоритм:**
1. Нормализовать путь (replace `\` → `/`, strip project root)
2. Проверить `normalized.startswith(prefix)` для каждого правила
3. Если скилл уже активирован (`SessionState.is_skill_activated`) → пропустить
4. Иначе → `BLOCK` с инструкцией `Skill('X')`

## Level A.1: Research Protocol Trigger (PRE, BLOCKING)

Для тем **без** dedicated скиллов (FastAPI, Redis, 1C Metadata и др.) — **блокирует** Write/Edit и инструктирует Claude вызвать `Skill('learning-loop')`.

**Блокирует** — `HookOutput().block(...)` с инструкцией запуска learning-loop.

Конфигурация: `code-skill-patterns.json` → `research_protocol.patterns`

| Pattern (regex) | Label | Domain |
|-----------------|-------|--------|
| `Redis\.\|from\s+redis\|aioredis` | Redis Caching | tech |
| `Справочник\s+\|Документ\s+\|Регистр\s+(накопления\|сведений)` | 1C Metadata Objects | 1c |
| `КомпоновкаДанных\|СхемаКомпоновки` | 1C Data Composition | 1c |
| `Dockerfile\|docker-compose\.yml\|FROM\s+\w+:` | Docker Configuration | devops |

**Всего:** 4 паттерна

> **Migration 2026-05-29.** `FastAPI\|APIRouter` и `pytest\.fixture\|@pytest\|conftest\.py` **удалены** из `research_protocol` и перенесены в Level A (`patterns.mappings`) → `framework-api` / `evaluation-benchmark`. Раньше они форсили `Skill('learning-loop')`, хотя профильные скиллы уже существовали (ложный learning-cycle). См. [Level A](#level-a-content-patterns-pre) и CLAUDE.md «Hooks Infrastructure».

**Алгоритм:**
1. Проверить `tool_name` in (Write, Edit)
2. Извлечь content; пропустить если < 30 символов
3. Проверить regex (compiled, IGNORECASE)
4. Пропустить если Level A уже нашёл совпадение (Level A приоритетнее)
5. Dedup: пропустить если `SessionState.is_skill_activated(f"learn:{label_key}")` (уже triggered)
6. При совпадении:
   - `SessionState.add_activated_skill(f"learn:{label_key}")` — dedup
   - `SessionState.set_pending_learn({label, domain, pattern})` — backup для Level F
   - `BLOCK` с инструкцией `Skill('learning-loop')`

**Dedup-механизм:**
```
Первый вызов (FastAPI detected):
  activated_skills: [..., "learn:fastapi-framework"]
  → BLOCK: "Run Skill('learning-loop')"

Повторный вызов (после learning-loop):
  is_skill_activated("learn:fastapi-framework") → True
  → return None (пропустить, не блокировать)
```

**Связь с Level F:** Level F служит advisory backup. Если A.1 block сработал (learn:X в activated_skills), Level F просто очищает `pending_learn`. Если A.1 был bypassed — Level F выдаёт advisory `system_message`.

**Тест:** `scripts/test-learn-cycle.py` (10 тестов, 27 assertions)

## Level C: Bash Commands (PRE)

Проверяет bash-команды перед выполнением.

| Pattern (regex) | Required Skill | Label |
|-----------------|---------------|-------|
| `docker\s+(compose\|build\|push\|tag)` | deployment | Docker Operations |
| `pytest\|coverage\.py\|tox` | evaluation-benchmark | Python Testing |

**Всего:** 2 правила

> **Phantom-skill cleanup (2026-05-14, commit `784e1a57b`).** Раньше таблица содержала 7 правил, из которых 4 указывали на skills, которых нет в `.claude/skills/`: `kubernetes`, `npm-publishing`, `code-quality`, `type-checking`. Эти rules срабатывали как hard-block на безобидные команды (например, `mypy --version` требовал phantom skill `type-checking`). Удалены полностью; 5 других правил redirected на существующие skills (см. commit message). Audit pattern для регрессий:
>
> ```bash
> python -c "import re,os;text=open('.claude/hooks/shared/code-skill-patterns.json',encoding='utf-8').read();[print(s) for s in re.findall(r'\"skill\":\\s*\"([^\"]+)\"',text) if not os.path.isdir(f'.claude/skills/{s}')]"
> ```
>
> должен вернуть пусто.

> **Phantom-guard на runtime (2026-06-12, roadmap [260612 Skill System](../../../roadmap/260612_ROADMAP_SKILL_SYSTEM_FULL_VERIFICATION.md) B2).** Ручной audit выше больше не единственная защита: `code-skill-enforcer._skill_exists()` проверяет наличие `.claude/skills/<skill>/SKILL.md` ПЕРЕД каждым блоком на всех трёх уровнях (A patterns / B directory_rules / C bash_rules). Маппинг на несуществующий скилл теперь даёт **честный non-blocking `CONFIG ERROR` systemMessage** (просьба починить `code-skill-patterns.json`) вместо неудовлетворимого блока «активируй Skill('фантом')» — deadlock-класс закрыт. Блок реального неактивированного скилла не изменён.

    "StateGraph",
    "invoke\\s*\\(",

  "must_not_contain": [
    "StateGraph\\s*\\(\\s*\\)",
    "node\\s*\\(\\s*\"\"",
    "edge\\s*\\(\\s*\\)"
  ],
  "error_message": "LangGraph agent missing required patterns..."
}
```

**Алгоритм:**
1. Проверить `tool_name` in (Write, Edit)
2. Проверить `file_pattern` regex match
3. Проверить что скилл в `activated_skills`
4. Для каждого `must_contain` — проверить наличие
5. Для каждого `must_not_contain` — проверить отсутствие
6. При нарушении → `system_message` (advisory, не block)

## Task Protocol

Независимый enforcer, работающий параллельно с уровнями A-F.

### Фазы протокола

```
┌──────┐    classify    ┌────────────┐   TaskCreate   ┌────────────┐
│ idle │───────────────>│ classified │──────────────>│ decomposed │
└──────┘                └────────────┘               └──────┬─────┘
                                │                          │
                                │          Skill()         │   Skill()
                                └────────────────┐         │
                                                 ▼         ▼
                                         ┌─────────────────────┐
                                         │   skill_checked     │
                                         │  [ALLOW Write/Edit] │
                                         └─────────────────────┘
```

| Переход | Кто выполняет | Механизм |
|---------|--------------|----------|
| idle → classified | skill-eval-enforcer-shell.py | `SessionState.set_task_classified(complexity)` |
| classified → decomposed | task-protocol-observer.py | `SessionState.record_decomposition()` при TaskCreate |
| * → skill_checked | task-protocol-observer.py | `SessionState.record_skill_checked()` при Skill() |
| * → idle | skill-eval-enforcer-shell.py | `SessionState.reset_task_protocol()` при новом промпте |

### Сообщения блокировки

В зависимости от текущей фазы, enforcer выдаёт контекстно-зависимую подсказку:

| Фаза | Подсказка |
|------|----------|
| `idle` | Classify → Search skills → TaskCreate → Retry |
| `classified` | Skills not checked! → Search skills → Skill() → Retry |
| `decomposed` | Decomposed but skills not checked! → Skill() → Retry |

### Исключения

Task Protocol Enforcer пропускает файлы в:
- `.claude/`, `docs/`, `data/`, `.github/` (каталоги)
- `.json`, `.toml`, `.yml`, `.env`, `.md`, `.txt` и др. (расширения)
- Dotfiles (начинаются с `.`)

## Trust Scorer

Модуль [trust_scorer.py](../../../../.claude/hooks/shared/trust_scorer.py) оценивает достоверность
информации из внешних источников.

### Источники и рубрики

| Источник | Trust Score | Критерии |
|----------|-----------|----------|
| **Context7** | 1.0 (всегда) | Официальная документация, всегда доверяем |
| **GitHub** | 0.0–1.0 | stars (30%), last_commit_days (25%), has_docs (25%), has_license (20%) |
| **StackOverflow** | 0.0–1.0 | is_accepted (40%), score (30%), recency_days (30%) |
| **Infostart** | 0.0–1.0 | rating (35%), downloads (35%), recency_days (30%) |

### Пороговые значения

**GitHub:**
- stars >= 100 → full credit
- last_commit_days <= 90 → full credit
- has_license in [MIT, Apache, BSD, ISC] → full credit

**StackOverflow:**
- is_accepted = true → full credit
- score >= 3 → full credit
- recency_days <= 365 → full credit

**Infostart:**
- rating >= 4.0 → full credit
- downloads >= 100 → full credit
- recency_days <= 730 → full credit

### Research Protocol (fallback)

Для доменов без dedicated скиллов — порядок источников:

| Домен | Порядок источников |
|-------|-------------------|
| **tech** | Context7 documentation → StackOverflow → GitHub repositories |
| **1c** | Infostart.ru publications → GitHub repositories → its.1c.ru |

## Как BLOCK работает

```python
# PreToolUse hook
return HookOutput().block(
    f"SKILL REQUIRED: '{label}' ({skill})\n"
    f"Detected pattern: {pattern}...\n\n"
    f"ACTIVATE THIS SKILL:\n"
    f"  Skill('{skill}')\n\n"
    f"Then retry your action."
)
```

1. `HookOutput.block()` устанавливает `{"continue": false, "decision": "block"}`
2. `emit()` записывает JSON в stdout
3. Hook завершается с exit code 2
4. Claude Code получает сообщение блокировки
5. Claude видит причину и инструкцию → вызывает `Skill('X')` → повторяет действие
