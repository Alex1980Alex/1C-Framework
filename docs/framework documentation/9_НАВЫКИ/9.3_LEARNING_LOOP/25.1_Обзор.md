# 25. Learning Loop — самообучающийся пайплайн

## 25.1 Обзор

**Learning Loop** — механизм самообучения Claude Code, который активируется, когда для выполнения задачи не хватает существующих навыков (skills). Система не просто ищет информацию — она преобразует полученные знания в формализованный, повторно используемый skill, который доступен всем последующим сессиям.

### Зачем нужен

Без Learning Loop знания о новой технологии живут только в текущем разговоре: после `/clear` или новой сессии Claude снова "не знает" про tenacity / DSPy / Qdrant и заново гуглит. Learning Loop **превращает разовое исследование в постоянный артефакт** (`SKILL.md` + `cache/`), снижая повторные затраты на FETCH с ~5-10K токенов до 0.

### Ключевое свойство — самоусиление

Каждый успешный прогон пайплайна создаёт новый skill. Будущие задачи по этой теме выполняются мгновенно, без повторного поиска. **База знаний растёт с каждой итерацией**:

```
Сессия 1:  SEARCH(tenacity) miss → FETCH (5K toks) → CREATE skill   [высокий cost]
Сессия 2:  SEARCH(tenacity) hit  → активация skill                    [нулевой cost]
Сессия N:  SEARCH(tenacity) hit  → паттерны в SKILL.md                [нулевой cost]
```

### Пайплайн (5 фаз)

```
┌─────────┐   ┌────────┐   ┌─────────┐   ┌────────┐   ┌────────┐
│ SEARCH  │──▶│ FETCH  │──▶│ EXECUTE │──▶│ VERIFY │──▶│ CREATE │
└─────────┘   └────────┘   └─────────┘   └────────┘   └────────┘
     │                                         │            │
     │ skill found ────────────────────────────┴───────────▶│
     │                                                      │
     └─ КОНЕЦ (skill уже существует)                       skill
                                                         сохранён
```

| Фаза | Цель | Артефакт |
|---|---|---|
| **SEARCH** | Найти существующий skill | hit / miss |
| **FETCH** | Собрать knowledge_block из 3+ trusted источников | KB (Markdown) |
| **EXECUTE** | Выполнить задачу с атрибуцией Source: | working code |
| **VERIFY** | Проверить соответствие KB через grep + reviewer-субагент | PASS / PARTIAL / FAIL |
| **CREATE** | Конвертировать KB + опыт в SKILL.md | новый skill |

Подробности фаз: [25.2 Пять фаз](25.2_Пять_фаз.md).

### Реализация

| Компонент | Назначение |
|---|---|
| **Субагент** [`learning-loop.md`](../../../../.claude/agents/learning-loop.md) | Изолированный контекст (Opus model) для FETCH+EXECUTE+VERIFY |
| **Скилл** [`learning-loop/SKILL.md`](../../../../.claude/skills/learning-loop/SKILL.md) | Пошаговая инструкция (5 фаз) автоинжектируется в субагент |
| **Триггер** `code-skill-enforcer` Level A.1 | Блокирует `Write` если в `.claude/skills/` нет skill для текущей технологии |
| **Verify mode** `knowledge-compliance` | code-verify в режиме knowledge-compliance проверяет атрибуцию Source: |

### Когда срабатывает

```
User: "Добавь retry с exponential backoff через tenacity"
        │
        ▼
PreToolUse:Write hook → code-skill-enforcer Level A
        │
        ▼
detect_pattern("tenacity") → ищет skill в .claude/skills/
        │
        ├── HIT → Skill('tenacity-retry') → Write разблокирован
        │
        └── MISS → BLOCK с сообщением "ACTIVATE: Skill('learning-loop')"
                                            │
                                            ▼
                              Subagent(learning-loop) запускается
                                  ↓ FETCH ↓ EXECUTE ↓ VERIFY ↓ CREATE
                                            ↓
                              Skill 'tenacity-retry' создан → user retry
```

### Связь с триадой Hook+Skill+MCP

Learning Loop живёт на уровне **2** триады (Skills) и расширяет её через автоматическое создание новых skills:

| Слой | Роль в Learning Loop |
|---|---|
| **Hook** (`code-skill-enforcer`) | Триггер запуска (PreToolUse:Write/Edit) |
| **Skill** (`learning-loop`) | Инструкция для субагента + результат CREATE-фазы |
| **MCP** (Context7, WebSearch) | Источники FETCH-фазы (tech-python домен) |

Подробнее: [13.1 Триада Hook+Skill+MCP](../9.2_ТРИАДА_HOOK_SKILL_MCP/13.1_Обзор.md).

### Когда НЕ нужен

| Ситуация | Почему | Что делать |
|---|---|---|
| Skill уже существует | SEARCH найдёт его | Пайплайн прерывается на фазе 1 |
| Domain Claude знает (стандарты Python) | Embedded знаний достаточно | Claude пишет напрямую |
| Одноразовый скрипт <30 строк | Overhead субагента не оправдан | Claude пишет напрямую |
| Architecture / security / debugging | Opus-домен (Never delegate) | Claude делает сам |

Подробнее: [25.6 Диагностика — когда не нужен](25.6_Диагностика.md).

### Source attribution и trust scoring

FETCH-фаза собирает knowledge из **минимум 3 разных источников** с trust-scoring через [`shared/trust_scorer.py`](../../../../.claude/hooks/shared/trust_scorer.py). Каждый источник попадает в knowledge_block с явным тегом и score (0.0-1.0):

| Источник | Trust default | Rubric (веса) |
|---|---|---|
| Context7 (MCP) | **1.0 fixed** | Structured official docs, always trusted |
| GitHub repo | 0.0-1.0 | stars 30% + recency 25% + has_docs 25% + permissive_license 20% |
| StackOverflow | 0.0-1.0 | is_accepted 40% + score 30% + recency 30% |
| Infostart (1С домен) | 0.0-1.0 | rating 35% + downloads 35% + recency 30% |
| Official docs (WebFetch) | 0.7 default | High by reputation (readthedocs, pypi, vendor sites) |

Источники с trust < 0.4 отбрасываются — это страховка от outdated SO-ответов 2015 года или брошенных GitHub-репо.

### Domain routing

Pipeline выбирает источники по домену задачи — keyword detection в первой реплике пользователя:

| Домен | Triggers | Primary sources |
|---|---|---|
| **tech-python** | `pip install`, `import`, имена Python-библиотек (tenacity, langchain, fastapi) | Context7 → SO → GitHub → readthedocs |
| **tech-other** | `npm`, `cargo`, `go get`, React, Docker, K8s | Context7 (когда есть) → official docs → SO → GitHub |
| **1c** | BSL, регистры, справочники, документы 1С, конфигуратор | Infostart.ru (rating ≥4.0) → its.1c.ru → GitHub 1C BSL → SO [1c] |

Полный routing-mechanism: [`learning-loop` skill — Фаза 2 FETCH](../../../../.claude/skills/learning-loop/SKILL.md).

### Антипаттерны

| Плохо | Почему | Как правильно |
|---|---|---|
| Сразу писать код без SEARCH | Может быть готовый skill | Всегда grep `.claude/skills/*/SKILL.md` сперва |
| FETCH из одного источника | Single point of failure | Минимум 3 источника + trust scoring |
| EXECUTE без `Source:` атрибуции | VERIFY не сможет проверить compliance | Требовать `Source: <секция KB>` в каждой функции |
| Пропустить VERIFY | Субагент мог использовать training data | code-verify mode=knowledge-compliance — обязательная фаза |
| Не запускать CREATE | Knowledge теряется при `/clear` | CREATE — обязательная финальная фаза |

### Метрики

Learning Loop отслеживается через существующую инфраструктуру [09.4 Мониторинг](../../7_ПРОВЕРКА/7.2_АДМИНИСТРИРОВАНИЕ/09.4_Мониторинг.md):

- `data/skill-router.log` — рекомендации learning-loop
- `data/skill-accuracy.jsonl` — корреляция recommend → activate (часто ли сработал MISS-блокировкой)
- `data/hook-invocations.jsonl` — `code-skill-enforcer` Level A.1 invocations + `run_id` для cross-hook trace
- `.claude/cache/hook-todos.json` — pending cache tasks (FETCH результаты ждут CREATE)
