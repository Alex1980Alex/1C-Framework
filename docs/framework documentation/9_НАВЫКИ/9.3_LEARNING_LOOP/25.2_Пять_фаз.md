# 25.2 Пять фаз пайплайна

## Фаза 1: SEARCH

**Цель:** проверить, существует ли уже skill для данной темы.

- `Grep` по `.claude/skills/*/SKILL.md` на совпадение с ключевыми словами
- Проверка `skill-router-config.json` на наличие зарегистрированного триггера
- **Если найден** → пайплайн прерывается, skill используется напрямую
- **Если не найден** → переход к FETCH

## Фаза 2: FETCH

**Цель:** собрать знания из 3+ независимых источников с оценкой доверия.

**Маршрутизация по домену:**

| Домен | Источники |
|-------|-----------|
| `tech-python` | Context7, StackOverflow, GitHub |
| `tech-other` | Official docs, StackOverflow, GitHub |
| `1c` | Infostart, its.1c.ru, GitHub |

**Оценка доверия:** `trust_scorer.py` (`.claude/hooks/shared/`) назначает вес каждому источнику:
- Context7 = 1.0 (всегда)
- SO accepted answer: `is_accepted` 40%, `score` 30%, `recency` 30%
- GitHub repo: `stars` 30%, `last_commit` 25%, `docs` 25%, `license` 20%

**Выход:** `knowledge_block` (KB) — структурированный блок знаний + marker patterns для VERIFY.

## Фаза 3: EXECUTE

**Цель:** написать код, используя **только** знания из KB.

**Требования:**
- Атрибуция источника обязательна в docstrings: `Source: [SO #12345 - accepted]`
- Async-first подход для I/O операций
- Pydantic v2 для валидации данных
- Паттерны НЕ из KB помечаются `Source: [own]` с обоснованием

## Фаза 4: VERIFY

**Цель:** подтвердить корректность кода. Выполняется **inline** (субагент не может породить суб-субагент).

**Три уровня проверки:**

| Уровень | Метод | Что проверяет |
|---------|-------|---------------|
| 1 | `Grep` markers | Marker patterns из KB присутствуют в коде |
| 2 | Self-review | API, параметры, anti-patterns, async |
| 3 | Verdict | PASS / PARTIAL / FAIL |

**Выход:** маркер `[CODE-VERIFY-PASS]` или `[CODE-VERIFY-FAIL]`.

При FAIL — retry (макс 2 раза) или Ralph Wiggum Loop.

**Два места VERIFY — не противоречие, а два уровня:**

| Где | Кто | Метод | Источник | Retry |
|---|---|---|---|---|
| Внутри субагента (это фаза 4) | Сам субагент `learning-loop` | inline Grep markers + self-review | [`agents/learning-loop.md`](../../../../.claude/agents/learning-loop.md) | макс 2 |
| После возврата субагента, в host | Главный Claude | `Skill('code-verify')` mode=`knowledge-compliance` | [`skills/learning-loop/SKILL.md`](../../../../.claude/skills/learning-loop/SKILL.md) | Ralph Wiggum, макс 3 |

Оба уровня обязательны: inline-проверка внутри субагента (запрет вложенных Subagent — см. [25.3](25.3_Архитектура_субагента.md)) + повторная host-level проверка через `code-verify` после возврата.

## Фаза 5: CREATE

**Цель:** сгенерировать `SKILL.md` и зарегистрировать в router.

**Чеклист качества skill'а:**
- [ ] ≤ 500 строк
- [ ] 5+ триггеров для маршрутизации (RU + EN)
- [ ] 3+ шаблона кода (copy-paste ready)
- [ ] 3+ анти-паттерна
- [ ] 1+ НЕ-redirect на смежный скилл
- [ ] Регистрация в `skill-router-config.json` (bundle)
- [ ] Триггеры уникальны (проверка grep)
