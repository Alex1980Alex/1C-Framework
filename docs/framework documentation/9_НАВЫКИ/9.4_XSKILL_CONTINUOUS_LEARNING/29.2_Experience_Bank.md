# 29.2 Experience Bank -- Накопление знаний (Phase 1-2)

## Формат Experience Record

Каждый инсайт хранится как JSON-объект в `experiences.jsonl`:

```json
{
  "experience_id": "exp-2026-04-08-161616",
  "trigger": {
    "task_type": "bsl-analysis",
    "keywords": ["BSL", "ast-grep", "structural"],
    "context_pattern": "Structural BSL search using ast-grep"
  },
  "insight": {
    "category": "tool_selection",
    "tool_preference": "mcp__ast-grep-mcp__ast_grep",
    "tool_avoided": "mcp__serena__find_symbol",
    "reason": "ast-grep 95% accuracy vs Serena 30-40% for BSL"
  },
  "evidence": {
    "success_count": 12,
    "failure_count": 3,
    "sessions_observed": 5,
    "last_observed": "2026-04-08T14:30:00Z"
  },
  "confidence": 0.8,
  "status": "confirmed",
  "source_model": "claude-opus"
}
```

**Категории инсайтов:** `tool_selection`, `parameter_tuning`, `workflow_order`, `error_avoidance`, `prompt_pattern`, `failure_pattern`, `performance_optimization`

**Типы задач:** `bsl-analysis`, `bsl-refactoring`, `bsl-debugging`, `documentation`, `code-review`, `code-generation`, `file-search`, `file-edit`, `git-operations`, `mcp-operations`, `query-execution`, `general`

**Статусы:** `candidate` -> `confirmed` -> `promoted` | `deprecated` | `conflicting`

## Phase 1: Experience Distillation

### Micro-Experience Capture (real-time)

**Файл:** `micro-experience-capture.py` -- PostToolUse hook

Срабатывает на каждый вызов инструмента. Детектирует паттерны в скользящем окне последних 10 вызовов:

- **Retry** -- тот же инструмент вызван повторно с другими параметрами
- **Tool switch** -- переключение с инструмента A на B для той же задачи (по совпадению path)
- **Success streak** -- 3+ успешных вызова одного инструмента подряд

Записывает в `pending-micro.jsonl` для batch-обработки.

### Batch Distillation (session-end)

**Файл:** `experience-distiller.py` -- PreCompact/Stop hook

Запускается при compact или завершении сессии. Анализирует все сырые данные сессии:

1. Парсит `auto-save-memory.jsonl` и `work-history.jsonl`
2. Группирует tool-use паттерны по task_type
3. Считает success/failure для каждого инструмента
4. Синтезирует Experience Records
5. Дедуплицирует с существующими
6. Записывает в `experiences.jsonl`

```bash
# Ручной запуск
python scripts/hooks/learning/experience-distiller.py --source compact
```

## Phase 2: Failure Capture

### Failure Detection (real-time)

**Файл:** `failure-capture.py` -- PostToolUse hook

Детектирует 7 типов неудач:

| Тип | Severity | Как детектируется |
|-----|----------|------------------|
| `tool_error` | moderate | error/exception/traceback в результате |
| `empty_result` | minor | "0 matches", "not found" в результате |
| `user_denied` | major | tool_denied в stdin |
| `tool_retry` | moderate | тот же tool + другие params в окне 3 вызовов |
| `approach_switch` | major | tool A -> tool B для того же path |
| `timeout` | moderate | таймаут инструмента |
| `wrong_result` | critical | пользователь поправил результат |

Записывает в `failures.jsonl` со sliding window state в `failure-state.json`.

### Contrastive Analysis

**Файл:** `contrastive-analyzer.py`

Сравнивает успехи и провалы для одного task_type:

```
bsl-analysis:
  SUCCESS: ast-grep (12 успехов, 3 провала) -> confidence 0.8
  FAILURE: serena  (5 успехов, 8 провалов)  -> confidence 0.38
  INSIGHT: "Для BSL structural search: ast-grep >> serena"
```

Запускается из `experience-distiller.py` после batch-дистилляции.

## Latency

Все PostToolUse хуки работают в hot path. Целевые latency:

| Хук | Target | Реальное |
|-----|--------|---------|
| `micro-experience-capture.py` | < 10ms | ~1ms |
| `failure-capture.py` | < 15ms | ~1ms |

Тяжелая обработка (distillation, contrastive) -- только на PreCompact/Stop.
