## Проблема

Experience Bank растет неограниченно: каждая сессия добавляет записи. Без consolidation:
- Дубликаты накапливаются (один и тот же инсайт записан 10 раз)
- Устаревшие записи отравляют retrieval
- Противоречия не разрешаются

## Pipeline

```
experience-consolidator.py
  1. Load experiences.jsonl
  2. TF-IDF cosine similarity matrix
  3. Find duplicate clusters (threshold=0.85)
  4. Merge: sum evidence, max confidence
  5. Detect conflicts (разные tools для одного task_type)
  6. Evict stale (>30 дней + confidence < 0.5)
  7. Archive evicted -> archive/evicted-TIMESTAMP.jsonl
  8. Re-index Qdrant
  9. Run knowledge-scorer
     |
     v
skill-promoter.py
  1. Filter: confidence >= 0.9 AND sessions >= 5 AND status=confirmed
  2. Match to existing SKILL.md by task_type + keywords
  3. Append "## Learned Experiences" section
  4. Or create new skill if no match
  5. Log to promotions.jsonl
```

## Semantic Deduplication

Использует TF-IDF (не Ollama) для скорости. Сравнивает `insight.reason` + `task_type` + `tool_preference`:

```python
# Два experience считаются дубликатами если:
# 1. Одна категория (tool_selection, workflow_order, ...)
# 2. Cosine similarity >= 0.85
```

При слиянии:
- Evidence суммируется (`success_count`, `failure_count`)
- Confidence = max из кластера
- `source_entries` объединяются (cap 20)
- `_merged_from` хранит ID поглощенных записей

## Conflict Resolution

Конфликт: два experience рекомендуют разные tools для одного `task_type + category` с высоким confidence (>= 0.7).

Пример конфликта:
```
bsl-analysis / tool_selection:
  exp-001: tool_preference=ast-grep, confidence=0.82
  exp-002: tool_preference=serena,   confidence=0.71
```

Оба сохраняются, но `status` меняется на `conflicting`. При retrieval инжектируется запись с наивысшим confidence.

## Stale Eviction

Запись считается stale если:
- `last_observed` > 30 дней назад
- `confidence` < 0.5

Stale записи перемещаются в `archive/evicted-YYYYMMDDTHHMMSS.jsonl` (не удаляются).

## Skill Promotion

Критерии промоции experience -> SKILL.md:

| Критерий | Порог |
|----------|-------|
| confidence | >= 0.9 |
| sessions_observed | >= 5 |
| status | "confirmed" |

Skill matching по `TASK_TYPE_SKILL_MAP`:
```python
"bsl-analysis" -> ["bsl-semantic-search-usage", "code-analysis-pipeline"]
"documentation" -> ["code-documentation-standard", "document-bsl"]
"code-review"  -> ["review-1c-code"]
```

Если нет подходящего skill -- создается новый `learned-{task_type}-{tool}/SKILL.md`.

```bash
# Статус
python consolidation-scheduler.py --status
# -> sessions_since_consolidation: 3, threshold: 5, next in: 2

# Slash command

```
