# AutoResearch: бесконечный цикл улучшений

**AutoResearch** — это open-source репозиторий Андрея Карпати (github.com/karpathy/autoresearch), выпущенный в марте 2026 года. Принцип: ИИ-агент автономно оптимизирует код бесконечным циклом «изменил → проверил → сохранил или откатил».

---

## Что это

Идея: дать ИИ-агенту реальную среду и позволить ему экспериментировать автономно всю ночь — изменять код, проверять результат за 5 минут, сохранять улучшения или откатывать провалы, и повторять.

Всё держится на одном правиле: у системы есть **одно число** (метрика), которое нужно улучшить. Если после изменения число стало лучше — изменение сохраняется через `git commit`. Если хуже — мгновенный `git revert`.

## Схема цикла

```
┌─────────────────────────────────────────┐
│         Человек задаёт цель             │
│  «Убрать все lint-ошибки в проекте»     │
└────────────────┬────────────────────────┘
                 │ (один раз)
                 ▼
┌─────────────────────────────────────────┐
│         1. Анализ                       │
│  Агент читает код + историю попыток     │◄──────────┐
└────────────────┬────────────────────────┘           │
                 │                                     │
                 ▼                                     │
┌─────────────────────────────────────────┐           │
│         2. Одно изменение               │           │
│  Правит конкретную проблему в коде      │           │
└────────────────┬────────────────────────┘           │
                 │                                     │
                 ▼                                     │  повтор
┌─────────────────────────────────────────┐           │  бесконечно
│         3. Сохранение в git             │           │
│  Коммит до проверки — для чистого отката│           │
└────────────────┬────────────────────────┘           │
                 │                                     │
                 ▼                                     │
┌─────────────────────────────────────────┐           │
│         4. Замер метрики                │           │
│  ruff check → было 47, стало 38        │           │
└────────────────┬────────────────────────┘           │
                 │                                     │
                 ▼                                     │
┌─────────────────────────────────────────┐           │
│         5. Стало лучше?                 │           │
│         38 < 47 → да!                   │           │
└───────┬─────────────────┬───────────────┘           │
        │                 │                            │
        ▼                 ▼                            │

        │                │                             │
        └────────────────┴─────────────────────────────┘
```

## Как читать схему (сверху вниз)

### Человек задаёт цель
Это единственное, что делаете вы. Один раз формулируете задачу («убрать lint-ошибки») и указываете метрику (число, которое нужно улучшить). Дальше вы не нужны — агент работает сам.

### Шаг 1 — Анализ
Агент открывает ваш код и читает лог всех прошлых попыток (файл `results.tsv`). Он видит: «На итерации 12 я пробовал заменить `==` на `is` — стало хуже, откатил». Поэтому он не повторяет ошибки и выбирает новую стратегию.

### Шаг 2 — Одно изменение
Агент делает ровно одну правку. Не десять, не пять — одну. Это критично: если сделать много изменений и метрика ухудшится, невозможно понять, какое именно навредило.

### Шаг 3 — Сохранение в git
Перед проверкой агент делает `git commit`. Зачем до, а не после? Чтобы при провале можно было мгновенно выполнить `git revert` и вернуться ровно к предыдущему рабочему состоянию. Это страховочная сетка всей системы.

### Шаг 4 — Замер метрики
Агент запускает команду проверки (например, `ruff check`). Получает одно число: было 47 ошибок, стало 38.

### Шаг 5 — Стало лучше?
Простое сравнение двух чисел:
- **38 < 47** → изменение сохраняется ✓ (левая ветка)
- **Число выросло или код сломался** → мгновенный откат через `git revert` ✗ (правая ветка)

### Возврат к шагу 1
Обе ветки ведут обратно к анализу. Неважно, было улучшение или откат — агент возвращается и начинает заново. Цикл крутится бесконечно, пока вы его не остановите через `Ctrl+C`.

## Результат

За ночь может пройти **50–100 итераций**. К утру вы открываете `results.tsv` и видите полную историю: что пробовал, что сработало, что нет — и код, который стал чище без единой минуты вашего времени.

## Три обязательных элемента

| Элемент | Что это | Пример |
|---------|---------|--------|
| **Метрика** | Одно число, которое нужно улучшить | Количество lint-ошибок Ruff |
| **Переменная** | Что агент имеет право менять | Файлы `.py` в папке `src/` |
| **Цикл обратной связи** | Команда, возвращающая метрику | `ruff check --output-format json` |

> Если эти три условия соблюдены, алгоритму неважно, оптимизирует он нейросеть или lint-ошибки — математика цикла идентична.

---

## Почему GPU не нужен

- **«Мозг» агента** (языковая модель Claude) работает в облаке Anthropic
- **На вашем компьютере** выполняются только лёгкие команды проверки: `ruff check`, `mypy`, `pylint`
- Эти команды работают за доли секунды на любом CPU
- Интернет-соединение — единственное техническое требование
