# Claude Code Skill Creator и обновление «Skills 2.0»

**3 марта 2026 года** Anthropic выпустила крупное обновление инструментария для работы со скиллами — официально оно называется *«Improving skill-creator: Test, measure, and refine Agent Skills»*. Обновление добавило систему оценки (evals), A/B-бенчмаркинг и автоматическую оптимизацию триггеров для скиллов Claude Code. Сообщество быстро окрестило это **«Skills 2.0»** (хотя сама Anthropic этот термин не использует). Суть изменений: скиллы превратились из статичных файлов-инструкций в тестируемые, измеримые и итеративно улучшаемые компоненты. Плагин Skill Creator, установленный уже более **50 000 раз**, доступен как плагин Claude Code и как отдельный репозиторий, и включает четыре компонуемых AI-агента для полного цикла разработки скиллов.

---

## Что такое Skill Creator и как его установить

**Skill Creator** — это верифицированный Anthropic плагин для Claude Code, представляющий собой полный набор инструментов для разработки, тестирования и итерации скиллов. Он размещён в двух официальных репозиториях на GitHub: `anthropics/skills` и `anthropics/claude-plugins-official`. На странице плагина `claude.com/plugins/skill-creator` зафиксировано **50 465 установок** по состоянию на середину марта 2026.

**Установка** выполняется через систему команд `/plugin` в Claude Code. Можно интерактивно просмотреть доступные плагины через `/plugin > Discover` и найти «skill-creator», либо установить напрямую из маркетплейса. Стандартный путь: добавить официальный маркетплейс Anthropic (`/plugin marketplace add anthropics/skills`), затем установить `/plugin install skill-creator`. После установки плагин вызывается командой `/skill-creator` с выбором режима.

Плагин работает в **четырёх режимах** — Create, Eval, Improve и Benchmark — и управляет **четырьмя компонуемыми агентами**:

- **Executor** — запускает скиллы на eval-промптах в чистом изолированном контексте
- **Grader** — оценивает выходные данные по заданным критериям и рубрикам
- **Comparator** — выполняет слепое A/B-сравнение между версиями скиллов (или скилл vs. базовая модель без скилла)
- **Analyzer** — синтезирует результаты и предлагает точечные улучшения

Сами скиллы следуют стандартизированной структуре папок с обязательным файлом `SKILL.md`, содержащим YAML-метаданные (name, description) и markdown-инструкции, плюс опциональные ресурсы в подпапках `scripts/`, `references/` и `assets/`.

**Области видимости (scope)** определяют, где хранятся скиллы и кому они доступны:

- **Персональный (user)** — `~/.claude/skills/`, доступен во всех проектах пользователя
- **Проектный (repo)** — `.claude/skills/` в корне проекта, расшаривается с командой через Git
- **Корпоративный (enterprise)** — управляется на уровне организации, имеет наивысший приоритет
- **Плагинный** — использует пространство имён `plugin-name:skill-name` для предотвращения конфликтов

Приоритет: enterprise > personal > project.

## Два типа скиллов и почему это важно

В блогпосте от 3 марта Anthropic формализовала критически важную таксономию, которую сообщество открывало органически. Скиллы теперь чётко делятся на две категории, и понимание разницы определяет долгосрочную отдачу.

### Capability Uplift Skills (скиллы повышения возможностей)

Помогают Claude делать то, что базовая модель либо не умеет, либо делает нестабильно. Каноничные примеры — собственные скиллы Anthropic для генерации документов: заполнение PDF-форм (особенно незаполняемых форм, требующих точного позиционирования по координатам), создание PowerPoint-презентаций и генерация Excel-файлов. Эти скиллы кодируют специализированные техники, превосходящие обычный промптинг.

Однако у них есть **встроенный срок годности**: по мере улучшения моделей разрыв в возможностях, который они закрывают, сужается. PDF-скилл Anthropic прошёл именно через этот цикл — evals выявили проблемы модели с незаполняемыми формами, команда исправила привязку текста к извлечённым координатам. Со временем будущая модель может справляться с этим нативно.

### Encoded Preference Skills (скиллы кодированных предпочтений / workflow-скиллы)

Документируют процессы, где Claude уже умеет выполнять каждый отдельный шаг, но скилл выстраивает их в последовательность согласно методологии команды — шаг A → B → C → D в определённом порядке с определёнными критериями. Примеры: проверка NDA по конкретному чеклисту компании, еженедельные статус-репорты с подтягиванием данных из MCP-интеграций, ревью безопасности PR по стандартам организации.

Эти скиллы **гораздо долговечнее** capability uplift, потому что кодируют институциональные знания, а не компенсируют ограничения модели. Множество аналитиков рекомендуют приоритизировать именно encoded preference скиллы для максимальной долгосрочной отдачи.

## Как работает система оценки и бенчмаркинга

Система оценки — центральный элемент обновления от 3 марта. До этого релиза у авторов скиллов — большинство из которых, как отмечает Anthropic, **являются предметными экспертами, а не инженерами** — не было системного способа узнать, работает ли скилл после обновления модели, триггерится ли когда нужно и действительно ли улучшился после правок.

### Процесс eval-прогона

1. Skill Creator генерирует набор из примерно **20 eval-запросов** — микс промптов, которые *должны* вызвать скилл, и промптов, которые *не должны*
2. Для каждого запроса автор определяет, как выглядит «хороший» результат
3. Система запускает несколько независимых агентов параллельно — каждый в **чистом изолированном контексте** с собственными метриками токенов и времени для предотвращения перекрёстного загрязнения
4. В примере из видео: **6 агентов = 3 тест-кейса × 2 условия** (со скиллом и без)

### Benchmark-режим

Предоставляет стандартизированную оценку по трём метрикам: **процент прохождения evals**, **затраченное время** и **потребление токенов**. Тесты сообщества показали существенный прирост эффективности: агенты со скиллами использовали **5 вызовов инструментов** против **12–24** у базовой модели, потребление токенов сокращалось с **37 000 до 21 000** за выполнение.

### Comparator-агенты

Многие обозреватели называют их самой мощной фичей. Они выполняют **слепое A/B-сравнение**: оценивают выходные данные, не зная, какой результат от скилловой версии, а какой от базовой (или альтернативной). Это устраняет субъективную предвзятость и выдаёт side-by-side отчёты с анализом дисперсии. Аналогия, которую часто проводят — A/B-тестирование превью на YouTube.

### Два назначения системы eval

- **Отлов регрессий** — когда обновление модели ухудшает работу связки «скилл + модель»
- **Обнаружение перерастания** — когда общие возможности модели продвинулись настолько, что скилл больше не нужен (особенно актуально для capability uplift скиллов)

## Trigger Tuning: оптимизация срабатывания скиллов

Постоянная проблема скиллов — ненадёжное срабатывание: скиллы либо вызываются, когда не нужно (ложные срабатывания), либо не вызываются, когда нужно (пропуски). Поле `description` в YAML-метаданных SKILL.md — **главный сигнал**, по которому Claude решает, вызывать ли скилл. Ранее настройка этого поля была скорее искусством, чем наукой.

Skill Creator теперь включает **оптимизацию описания**: система анализирует текущее описание на выборке промптов и предлагает правки для улучшения точности триггеров. Используется разбивка **60% обучающих / 40% тестовых** запросов, каждый запрос оценивается **3 раза** для статистической надёжности.

Anthropic сообщает, что этот процесс **улучшил триггеринг 5 из 6** их собственных публичных скиллов. Официальная рекомендация — делать описания скиллов намеренно «настойчивыми» (pushy), чтобы бороться с более частой проблемой недотриггеринга.

Технические детали: бюджет описания скилла масштабируется как **2% от контекстного окна** (с запасом в 16 000 символов). Архитектура прогрессивного раскрытия Claude означает, что при старте загружаются только имя и описание (~30–50 токенов на скилл), а полное тело SKILL.md подгружается по требованию — только когда скилл вызывается.

## Ultrathink: был убран, потом вернули по требованию пользователей

Ключевое слово `ultrathink` прошло через турбулентную историю. Изначально его обнаружило сообщество в середине 2025 года через анализ исходного кода — это было ключевое слово-препроцессор, которое устанавливало бюджет extended thinking на **максимум в 31 999 токенов**. Иерархия ключевых слов выглядела так: «think» запускал ~10 000 токенов, а «ultrathink» (а также «think harder», «think really hard» и т.д.) — полные 31 999.

Около **16 января 2026 года** Anthropic убрала ultrathink полностью. Обоснование: extended thinking теперь включён по умолчанию на максимальном бюджете, ключевое слово избыточно. Официальной заменой стала команда `/effort` (low/medium/high). Но сообщество воспротивилось — в Issue #19098 на GitHub была задокументирована **систематическая деградация качества** с момента замены явных триггеров на автоматическое мышление.

Anthropic прислушалась. В **v2.1.68 (около 4 марта 2026)** ultrathink был **возвращён** как per-turn ключевое слово, устанавливающее конкретный ход на «high effort». Это совпало с переходом Opus 4.6 на medium effort по умолчанию для подписчиков Max и Team. Важно: официальная документация скиллов теперь прямо указывает, что для включения extended thinking в скилле достаточно включить слово «ultrathink» в содержимое SKILL.md — авторы скиллов могут встраивать его прямо в инструкции для принудительного максимального рассуждения.

## Claude Code v2.1.7 — январский патч безопасности

Версия **2.1.7**, выпущенная **14 января 2026 года**, была патч-релизом с 15 изменениями — не связана с обновлением Skills 2.0 (которое вышло в начале марта). Ключевое добавление: **MCP tool search auto mode включён по умолчанию** — автоматически откладывает описания MCP-инструментов, когда они превышают 10% контекстного окна, обнаруживая их через MCPSearch tool. Релиз также закрыл **уязвимость безопасности**, при которой wildcard-правила разрешений могли совпадать с составными командами, содержащими операторы shell. Исправлены несколько Windows-специфичных багов (ложные ошибки модификации файлов от облачной синхронизации/антивируса, сбои bash с escape-символами в путях к временным директориям). Другие улучшения: настройка `showTurnDuration` для скрытия сообщений о длительности, инлайн-ответы агентов в уведомлениях о задачах, улучшенная отзывчивость терминала. На 14 марта 2026 Claude Code достиг **версии 2.1.76** (352 npm-версии всего).

## Заключение и практические рекомендации

Обновление Skill Creator от 3 марта 2026 представляет собой реальный сдвиг парадигмы в создании и поддержке поведений AI-агентов.

**Ключевые выводы:**

- Таксономия capability uplift vs. encoded preference даёт фреймворк для принятия решений, в какие скиллы инвестировать — encoded preference скиллы предлагают значительно лучшую долговечность
- Система eval и бенчмаркинга замыкает обратную связь, которая ранее отсутствовала, превращая разработку скиллов из непрозрачного искусства в измеримую инженерию
- Слепой A/B-компаратор — выдающаяся фича, обеспечивающая объективную оценку качества, доступную даже нетехническим авторам скиллов
- В сочетании с восстановленным ultrathink и экосистемой из **60 000+ опубликованных скиллов**, платформа скиллов Claude Code эволюционировала в «менеджер пакетов для агентных workflow»
- Конкурентное преимущество смещается от размера моделей к качеству тестирования и инфраструктуры скиллов
