## Фаза 5: Обновление 1c-mcp-crud до v1.5.0

**Цель:** Снизить потребление токенов на 30-60% и повысить безопасность данных через TOON-формат и анонимизацию.

**Основано на:** ROCTUP/1c-mcp-crud v1.5.0 ([GitHub](https://github.com/ROCTUP/1c-mcp-crud))

**Текущее состояние:** Подключён через `mcp-remote http://localhost:6003/mcp` (proxy-режим). Версия в MEMORY зафиксирована как v1.26.0, фактически на GitHub уже v1.5.0 с существенными улучшениями.

### Шаги

| Шаг | Действие | Результат |
|---|---|---|
| 5.1 | Скачать обновлённую обработку `MCP_Toolkit.epf` из `build/` v1.5.0 | Обновлённый .epf |
| 5.2 | Переключить на встроенный HTTP-сервер (NativeAPI MCPHttpTransport) | Прямое подключение без Python proxy |
| 5.3 | Обновить `.mcp.json`: заменить `mcp-remote` на прямой HTTP | `"url": "http://localhost:6003/mcp"` |
| 5.4 | Включить TOON-формат (`RESPONSE_FORMAT=toon`) | Экономия 30-60% токенов |
| 5.5 | Настроить анонимизацию через дерево полей в .epf | Безопасная передача ПДн в LLM |
| 5.6 | Тест: `execute_code` с клиентским контекстом | Проверка нового функционала v1.4+ |
| 5.7 | Тест: `submit_for_deanonymization` | Новый 9-й инструмент |
| 5.8 | Обновить MEMORY.md (версия, количество tools) | Актуальная документация |

### Ожидаемый эффект

- Экономия 30-60% токенов при передаче данных 1С в LLM (TOON-формат)
- Исключение промежуточного Docker-контейнера Python proxy
- Безопасная работа с персональными данными (анонимизация)
- 9 инструментов вместо 8

### Приоритет: P0 (критический) | Оценка: 1 день

## Фаза 6: tree-sitter-bsl для структурного поиска BSL

**Цель:** Добавить миллисекундный структурный поиск по BSL коду с пониманием синтаксиса (процедуры, функции, переменные, вызовы).

**Основано на:** hawkxtreme/mini-ai-1c — `mcp-1c-search` ([GitHub](https://github.com/hawkxtreme/mini-ai-1c)), грамматика от @alkoleft

**Текущее состояние:** Наш `bsl-semantic-search` использует Qdrant (семантический) + SQLite FTS5 (полнотекстовый). Нет понимания синтаксической структуры BSL — поиск работает по тексту, а не по символам.

### Шаги

| Шаг | Действие | Результат |
|---|---|---|
| 6.1 | Исследовать tree-sitter-bsl: API, формат AST, Node.js bindings | Техническое решение |
| 6.2 | Создать отдельный MCP-сервер `bsl-code-search` (Node.js) | Сервер с tree-sitter-bsl |
| 6.3 | Реализовать индексацию: сканирование `src/projects/` -> построение AST -> индекс символов | Индекс процедур/функций/переменных |
| 6.4 | Добавить MCP tool `search_symbols` (поиск по имени символа, 1-23мс) | Быстрый поиск процедур/функций |
| 6.5 | Добавить MCP tool `find_callers` (кто вызывает символ) | Граф вызовов через AST |
| 6.6 | Добавить MCP tool `get_module_ast` (структура модуля) | Дерево символов модуля |
| 6.7 | Интегрировать в `.mcp.json` и lazy-mcp registry | Доступность через MCP |
| 6.8 | Тест: сравнение скорости с текущим `bsl_search` | Бенчмарк |

### Ожидаемый эффект

- Поиск символов: 1-23мс (vs ~100мс текущий FTS5)
- Точный поиск по типу символа (только процедуры, только функции, только экспортные)
- AST-based граф вызовов (дополняет наш SQLite call_graph)

### Приоритет: P1 (высокий) | Оценка: 3 дня

## Фаза 7: MCP Resources и Prompts

**Цель:** Расширить MCP-интеграцию за пределы Tools — дать LLM статический контекст (Resources) и шаблоны взаимодействия (Prompts).

**Основано на:** vladimir-kharin/1c_mcp ([GitHub](https://github.com/vladimir-kharin/1c_mcp)) — единственный проект с полной поддержкой Resources + Prompts

**Текущее состояние:** Все наши 15+ MCP-серверов предоставляют только Tools. Resources и Prompts не используются, хотя MCP SDK их поддерживает.

### Шаги

| Шаг | Действие | Результат |
|---|---|---|
| 7.1 | Добавить Resources в `bsl-semantic-search`: `config://structure` — дерево метаданных | Статический контекст конфигурации |
| 7.2 | Добавить Resource: `standards://coding` — стандарты кодирования 1С (ITS) | Правила для code review |
| 7.3 | Добавить Resource: `templates://modules` — шаблоны типовых модулей BSL | Скелеты для генерации кода |
| 7.4 | Добавить Prompts: `generate_handler`, `refactor_module`, `review_code` | Шаблоны взаимодействия |
| 7.5 | Зарегистрировать Resources/Prompts в FastMCP (`@mcp.resource`, `@mcp.prompt`) | Обновлённый MCP сервер |
| 7.6 | Тест: Claude запрашивает Resource перед генерацией кода | Верификация workflow |

### Ожидаемый эффект

- LLM получает структуру конфигурации без вызова Tool (меньше latency)
- Стандартизация промптов для типовых задач (генерация, рефакторинг, ревью)
- Уменьшение количества tool calls для получения базового контекста

### Приоритет: P1 (высокий) | Оценка: 2 дня

## Фаза 10: Двухвекторный поиск BSL кода

| 10.2 | Создать миграцию: `bsl_code_v2` -> `bsl_code_v3` с двумя векторами | Новая коллекция |
| 10.3 | Обновить `scripts/reindex_bsl_qwen3.py`: генерировать оба вектора | Двойная эмбеддинг-генерация |
| 10.4 | Обновить `bsl_hybrid_search`: Prefetch по обоим векторам -> RRF fusion | Гибридный ранжировщик |
| 10.5 | A/B тестирование: single-vector vs dual-vector на `data/eval/bsl/bsl_eval_dataset.json` | Метрики precision/recall |
| 10.6 | При улучшении метрик: переключить production на `bsl_code_v3` | Деплой |

### Ожидаемый эффект

- Запрос "модуль менеджера справочника Контрагенты" найдёт точный модуль (по пути), а не семантически похожий
- Улучшение precision на 15-25% (по аналогии с Phase 3.5 для метаданных)
