**Симптом:** `create_project`/`delete_project` рвутся 60с-таймаутом, завершаясь асинхронно успешно (2 случая за сессию; память `reference-edt-mcp-refactor-async-timeout`).

### Б-2 ✅ Защита от осиротевшего `.git/index.lock` в auto-save

**Симптом:** 0-байтовый `index.lock` 4.5-часовой давности блокировал все коммиты main-репо.
**Сделано:** [`shared/auto_save_core.py`](../../.claude/hooks/shared/auto_save_core.py) `clear_stale_index_lock(root, max_age_sec=600)` + вызов step 0 в [`auto-git-save.py`](../../.claude/hooks/auto-git-save.py). 4 unit ([`test_auto_save_stale_lock.py`](../../tests/unit/test_auto_save_stale_lock.py)) + 7 amend-регресс зелёные.
**Остаточный риск (осознан):** критерий - возраст файла, не живость процесса; git не пишет PID в index.lock надёжно, а 10 минут на порядки больше любой легитимной git-операции - false-positive практически исключён. **Остаток → В-3** (тиражировать на 2 других хука трио).

### Б-3 ✅ Offline-fallback в `.epf` эмуляции прихода Warehouse

**Симптом:** демо-прогон обработки упирался в А-2 («прогон не выполнен»).
**Сделано:** `ЭмулироватьПриход` при недоступном Warehouse строит минимальную offline-структуру (вариант B §15: `{id, date, externalSampleTestResults:[]}` - для нового дока безопасна) и продолжает; лог явно говорит «ОФЛАЙН-режим». `.epf` пересобран в папку задачи (syntaxCheck passed). Логика эквивалентна live-проверенному held-job харнессу; GUI-смоук - руками (`ВнешниеОбработки.Создать` из HTTP-сервиса запрещён «Защитой от опасных действий»).

### Б-7 ⏳ Сериализатор MCP_Сервер: `ПеречислениеСсылка` роняет `execute_query`

**Симптом (живьём):** `{mcp_Сериализация.Модуль(142)}: Метод объекта не обнаружен (УникальныйИдентификатор)` на любом перечислении в выборке; обход - `ПРЕДСТАВЛЕНИЕ()` в каждом запросе.

**Корень (по исходнику `external/1c_mcp/src/1c_ext/CommonModules/mcp_Сериализация/Ext/Module.bsl`):** `ЭтоСсылка()` (:114-123) включает `Перечисления.ТипВсеСсылки()` (:118) → в `БезопасноеЗначение()` ссылочная ветка (:33-40) перехватывает перечисление раньше его собственной ветки (:92-97) → `ОписаниеОбъектаПоСсылке()` на :142 зовёт `Ссылка.УникальныйИдентификатор()`, которого у `ПеречислениеСсылка` нет.

**Патч (минимальный, в `ОписаниеОбъектаПоСсылке` - чинит все пути входа). Было (:140-144):**

```bsl
	Результат = Новый Структура;
	Результат.Вставить("_objectRef", Истина);
	Результат.Вставить("УникальныйИдентификатор", Строка(Ссылка.УникальныйИдентификатор()));
	Результат.Вставить("ТипОбъекта", ТипСсылки);
	Результат.Вставить("Представление", Строка(Ссылка));
```

**Стало:**

```bsl
	Результат = Новый Структура;
	Результат.Вставить("_objectRef", Истина);
	// PATCH 2026-07-24: у ПеречислениеСсылка нет метода УникальныйИдентификатор()
	// ("Метод объекта не обнаружен" на любом перечислении в выборке).
	// Для перечисления отдаём имя значения - оно и есть стабильный идентификатор.
	Если Перечисления.ТипВсеСсылки().СодержитТип(ТипЗнч(Ссылка)) Тогда
		Результат.Вставить("Имя", XMLСтрока(Ссылка));
	Иначе
		Результат.Вставить("УникальныйИдентификатор", Строка(Ссылка.УникальныйИдентификатор()));
	КонецЕсли;
	Результат.Вставить("ТипОбъекта", ТипСсылки);
	Результат.Вставить("Представление", Строка(Ссылка));
```

**Почему не в сабмодуль сразу:** `external/1c_mcp` - апстрим (прецедент 260713 P2.3: сабмодуль не трогаем); грязное дерево = та же WIP-болячка, что А-1. Маршрут: форк-коммит/PR в окне деплоя.
