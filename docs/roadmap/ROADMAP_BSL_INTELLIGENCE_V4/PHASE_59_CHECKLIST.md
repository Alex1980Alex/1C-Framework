# Чеклист готовности: Фаза 59 — AST-based BSL Indexing

**Приоритет:** CRITICAL | **Срок:** 3-5 дней | **Зависимости:** нет

## Предусловия
- [ ] tree-sitter-bsl WASM доступен (используется в auto-documenter)
- [ ] Определена стратегия миграции: новая коллекция `bsl_code_v3` или обновление `bsl_code_v2`
- [ ] Eval dataset (Фаза 58) готов для замера прироста recall
- [ ] Ресурсы Qdrant достаточны (рост с ~4K файловых до ~20K+ символьных векторов)

## Артефакты (файлы/код)
- [ ] `src/bsl/ast/parser.py` — обёртка tree-sitter-bsl для извлечения AST
- [ ] `src/bsl/ast/symbol.py` — dataclass BslSymbol (name, type, scope, line_range, module)
- [ ] `src/bsl/indexing/ast_indexer.py` — сервис: AST → символы → эмбеддинги → Qdrant
- [ ] `src/bsl/indexing/chunking.py` — стратегия разбиения тела метода (если > лимит токенов)
- [ ] Миграция Qdrant payload: `symbol_id`, `symbol_type`, `file_path`, `start_line`, `end_line`

## Метрики приёмки
- [ ] Recall@10 >= baseline + 44% (замер на eval dataset Фазы 58)
- [ ] Precision@5 >= 0.75
- [ ] Latency индексации: < 50ms на символ (парсинг + эмбеддинг)
- [ ] Гранулярность: 1 вектор = 1 символ (процедура/функция)
- [ ] Coverage: 100% экспортных процедур/функций извлечены и проиндексированы

## Интеграционные проверки
- [ ] Парсинг сложных конструкций BSL: `&НаКлиенте`, `&НаСервере`, вложенные функции
- [ ] Поиск по описанию: комментарий `// Блокировка ТС` находит соответствующий метод
- [ ] Обновление кода: перезапись файла удаляет старые векторы и создаёт новые (нет дублей)
- [ ] Файлы с синтаксическими ошибками не ломают индексацию (skip/fallback)

## Блокеры для следующих фаз
- [ ] Без символьного индекса блокируется Фаза 61 (Call Graph)
- [ ] Без `file_path` + `line_number` в payload блокируется Фаза 64 (MCP навигация)
- [ ] Без per-symbol эмбеддингов блокируется Фаза 63 (Contextual Search)
