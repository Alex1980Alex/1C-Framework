## Discovery Issue

**Title:** Proposal: add BSL (1C Enterprise) language support

**Body:**

### Summary

BSL is the programming language of 1C:Enterprise and OneScript — a business-app platform used heavily across the post-Soviet region and Europe. This proposal wraps https://github.com/1c-syntax/bsl-language-server (403⭐, MIT, Java 17) as a new `Language` adapter in multilspy.

### Motivation

- BSL codebases routinely exceed 2 000 modules; ERP configurations reach 10 000+.
- No LSP-based BSL tooling exists in the Python ecosystem today.
- We are building an LLM-driven refactoring orchestrator on top of multilspy, currently via a private fork using internal APIs.
- Upstream adoption lets downstream tools depend on `multilspy>=X.Y` instead of maintaining forks.
- Opens BSL to multilspy's existing semantic-tooling ecosystem (Serena et al.).

### Evidence

### Scope

Minimal additive change, matching the `eclipse_jdtls` / `kotlin_language_server` pattern.

- `Language.BSL = "bsl"` added to `multilspy_config.py`.
- Factory branch added to `language_server.py`.
- New package `language_servers/bsl_language_server/` with 4 files:
  - `bsl_language_server.py` — subclasses `LanguageServer`, launches `java -jar bsl-language-server.jar --lsp` as an argv list.
  - `runtime_dependencies.json` — pins BSL LS 0.22.0 with verified SHA256, downloads from GitHub releases on first use.
  - `initialize_params.json` — BSL-specific capabilities.
  - `__init__.py`.
- Three integration tests in `tests/multilspy/test_multilspy_bsl.py`, skipped when `java` is not on PATH.
- `.gitignore` entry for `bsl_language_server/static/` (matches other JAR-based adapters).

No changes to core / protocol / other adapters. Python-only, no C extensions, no new runtime deps.

### Non-goals

- `workspace/didChangeWorkspaceFolders` eager indexing — tracked separately upstream at `1c-syntax/bsl-language-server`. Current adapter uses per-document `didOpen`, same as Java / Kotlin.
- Diagnostics / code actions — `window/logMessage` and `publishDiagnostics` acknowledged but not surfaced.

### Prerequisites

- Java 17+ on PATH (BSL LS is a Spring Boot app built for JDK 17).
- First run downloads ~94 MB JAR; subsequent runs read from `static/<version>/`.

## Maintainer concerns to pre-address

| Concern | Preempt |
|---|---|
| Niche language | Additive only; no runtime cost if `Language.BSL` unused. |
| Large JAR download | Pattern already used by `eclipse_jdtls` (500 MB+), `kotlin` (~60 MB). SHA256 pinning added. |
| Java dependency | Same as `eclipse_jdtls`, `kotlin`. Test gated with `pytest.mark.skipif(shutil.which("java") is None)`. |
| Cyrillic in tests | Fixture uses Russian identifiers (`ПолучитьЗначение`) since BSL is a Cyrillic-native language. UTF-8 encoding explicit in `write_text`. |
| Per-document indexing limitation | Documented in the adapter module docstring; same behaviour as other non-workspace-aware language servers. |
