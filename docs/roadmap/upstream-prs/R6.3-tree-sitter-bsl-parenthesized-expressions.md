## Discovery Issue

**Title:** Fix: parenthesized expressions cause parse errors (14 errors on real BSL modules)

**Body:**

### Problem

BSL code with parenthesized expressions produces ERROR nodes in the parse tree. Examples:

```bsl
Результат = (А + Б) * В;
Если (Условие1) ИЛИ (Условие2) Тогда
    Результат = ((-1) * Значение);
КонецЕсли;
```

On a test corpus of 1,518 BSL lines from a real 1C configuration, this produces 14 parse errors (0.9% error rate).

### Root Cause

The grammar does not define a `parenthesized_expression` rule. The `expression` alternatives include `call_expression`, `property_access`, `unary_expression`, etc., but no rule for `(...)` grouping.

### Proposed Fix

Add `parenthesized_expression` as an expression alternative:

```diff
  conflicts: ($) => [],
+ conflicts: ($) => [
+   [$.execute_statement, $.parenthesized_expression],
+   [$.parenthesized_expression, $.arguments],
+ ],

  // in expression alternatives:
+       $.parenthesized_expression,

+     parenthesized_expression: ($) =>
+       seq('(', field('inner', $.expression), ')'),
```

### Evidence

- **Before:** 14 errors on 1,518 lines (0.9%)
- **After:** 0 errors (0.0%)
- **Corpus tests:** 27/27 pass (5 new tests added for: assignment, condition, nested, unary, double-parens)
