[ANALYSIS GKSTCPLK-2565] Доработать печатную форму ТТН Беларусь (документ гкс_РегистрацияНаПЛК).

Задача: на ПФ "ТТН (Беларусь)" и "ТТН (Беларусь) вертикально" реквизит "По доверенности ... выданной ____" должен заполняться Заказчиком перевозки из связанной Заявки на отгрузку (гкс_ЗаявкаНаОтгрузкуПродукции.ЗаказчикПеревозки), а не Контрагентом.

Архитектура печати: команды печати РегистрацииНаПЛК делегируются модулю локализации через гкс_ЛокализацияСервер.МодульЛокализации("гкс_РегистрацияНаПЛК") -> CommonModule.гкс_РегистрацияНаПЛКЛокализация_by. Менеджер печати ТТН = Обработка.гкс_ПечатьТТН_Беларусь; данные собирает гкс_РегистрацияНаПЛКЛокализация_by.ДанныеДляПечатнойФормыТТНБеларусь.

Ключевой факт: запрос шапки УЖЕ содержит колонку ЗаказчикПеревозкиНаименование (= ЗаявкаОтгрузки.ЗаказчикПеревозки.НаименованиеПолное, строка 235). Новый запрос/реквизит не нужен.

Точка правки: Обработка.гкс_ПечатьТТН_Беларусь.ManagerModule.ВывестиПодвал, строка 332: ОбластьМакета.Параметры.КонтрагентНаименование = ДанныеПечати.КонтрагентЗаказа. Параметр КонтрагентНаименование привязан к ячейке "выданной [КонтрагентНаименование]" области "Подвал" (горизонт. строки 32-47 / вертик. 32-43), рендерится только эта область.

Рекомендация: Вариант B (1 строка BSL) — заменить источник на ДанныеПечати.ЗаказчикПеревозкиНаименование, покрывает обе ориентации. Альтернатива A — переименовать токен в обоих .mxlx + удалить мёртвую строку 332. Открытый вопрос: фолбэк при пустом ЗаказчикПеревозки. Маршрут реализации: /implement-1c-task (нет новых объектов метаданных). Отчёт: ANALYSIS-REPORT.md в папке задачи.
