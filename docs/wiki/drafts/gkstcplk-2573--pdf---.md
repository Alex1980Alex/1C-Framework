## Content

GKSTCPLK-2573 (предпросмотр PDF на форме присоединённых файлов «Регистрация на ПЛК»). Целевой объект — вендорская форма Обработка.ИнтеграцияС1СДокументооборот.Форма.ПрисоединенныеФайлы (НЕ РаботаСФайлами и НЕ Catalogs.Файлы — у тех тоже есть ОбновитьПредпросмотр, но «Регистрация на ПЛК» идёт через интеграцию с 1С:ДО, подтверждено диалогом «Получение ссылки» = Обработка.ИнтеграцияС1СДокументооборот).

КЛЮЧЕВЫЕ НАХОДКИ для реализации:
1. Эта вендорская форма исторически кастомизируется ТОЛЬКО программно через #Область ИзменениеФормыГКС → гкс_ДобавитьИзменитьРеквизитыФормы() (ИзменитьРеквизиты(МассивРеквизитов)), вызывается из ПриСозданииНаСервере (стр.53-54). В Form.form НЕТ ни одного гкс_-элемента → правки делать программно (модуль-only), а не править Form.form. Это совпадает с формулировкой GKSTCPLK-2309 «доработка затронула только модули форм».
2. ПРОБЕЛ в «Код после» ТЗ: строка `ДокументPDFПредпросмотр = Новый ДокументPDF` выглядит локальной переменной, но чтобы PDF отрисовался в элементе ПолеПредпросмотраPDF — ДокументPDFПредпросмотр ДОЛЖЕН быть РЕКВИЗИТОМ ФОРМЫ типа ДокументPDF, а элемент ПолеПредпросмотраPDF (ВидПоляФормы.ПолеPDFДокумента) привязан к нему через ПутьКДанным. Иначе поле пустое.
3. Структура формы: Page СтраницаДокументооборотДоступен → UsualGroup ГруппаФайлыИПредпросмотр (united) → [Table Файлы | PictureField КартинкаПредпросмотра (dataPath=АдресДанныхФайла)]. Новый PDF-элемент — сиблинг КартинкаПредпросмотра (Элементы.КартинкаПредпросмотра.Родитель).
4. Платформа 8.3.27: ДокументPDF.Прочитать(Файл) подтверждён через bsl-platform-context; ПолеPDFДокумента распознан как элемент формы. НЕ подтверждено: точное enum-имя ВидПоляФормы.ПолеPDFДокумента и возможность программного создания PDF-поля через Элементы.Добавить — обязательная execute_code-проба ПЕРЕД реализацией (риск R-1). Fallback — правка Form.form (Подход A).
5. ДокументPDF.Прочитать загружает в память → «Код после» удаляет temp-файл сразу; проверить на большом многостраничном PDF (риск R-3).
