GKSTCPLK-2574 REQ-1 ПИВОТ (2026-06-30, заменяет ранний подписочный вариант): реквизит видимости ТипПредметаОповещения перенесён С ПОДПИСКИ гкс_ПодпискиНаРассылкиИОповещения НА САМ ШАБЛОН Справочник.ШаблоныСообщений. Причина пивота (решение пользователя): админ работает на ФОРМЕ ШАБЛОНА (Справочник.ШаблоныСообщений.Форма.ФормаЭлемента — где поле «Назначение»=ПолноеИмяТипаПараметраВводаНаОсновании), туда же логично класть «тип предмета» — настройка там, где работают.

Итоговый Вариант B (реализован, code-verify PASS):
1. [ADDED] Справочник.ШаблоныСообщений.ТипПредметаОповещения — Строка 250 (длина ОБЯЗАТЕЛЬНА: безлимит запрещён в условии сравнения запроса).
2. [MODIFIED] ШаблоныСообщенийСлужебный.ПодготовитьЗапросДляПолученияСпискаШаблонов (~:1054): ПРЯМОЕ «ИЛИ ШаблоныСообщений.ТипПредметаОповещения = &ПолноеИмяТипаПредмета» (без подзапроса — реквизит теперь на самом шаблоне; проще предыдущего ВладелецШаблона-В-подзапрос).
3. [MODIFIED] ШаблоныСообщений.ФормаЭлемента: поле ТипПредметаОповещения ниже Наименования (добавлено через codepilot1c mutate_form_model add_field → data_path=Объект.ТипПредметаОповещения, т.к. edt-mcp create_metadata НЕ умеет привязку Field к Объект.<реквизит> — только form-attribute-by-name/dynamic-list-column). В ПриСозданииНаСервере — список выбора: Элементы.ТипПредметаОповещения.РежимВыбораИзСписка=Истина + цикл Для Каждого ТипПредмета Из Метаданные.ОпределяемыеТипы.ПредметШаблонаСообщения.Тип.Типы() → СписокВыбора.Добавить(МетаданныеПредмета.ПолноеИмя(), .Представление()). Образец — существующий ПолноеИмяТипаПараметраВводаНаОсновании choice-list :20-24 той же формы.
