### 2.1 PM-SPEC INIT

**📄 Субагент:** `.claude/agents/development-pipeline/pm-spec-init.md`

#### Назначение

Инициализация контекста проекта, анализ задачи, поиск релевантных файлов.

#### Входные данные

| Параметр | Описание | Пример |
|----------|----------|--------|
| `PROJECT` | Имя или путь проекта | `251222_GKSTCPLK-1996` |

##### DependencyTracker

**Файл:** `development-pipeline/agents/project_manager/dependency_tracker.py`

**Функциональность:**

| Метод | Описание |
|-------|----------|
| `build_graph()` | Построение графа зависимостей |
| `validate_dependencies()` | Проверка валидности (детекция циклов) |
| `get_execution_order()` | Топологическая сортировка |

**Граф зависимостей:**
```python
class DependencyGraph:
    nodes: Set[str]           # task_ids
    edges: Dict[str, List[str]]      # task_id -> [dependent_task_ids]
    reverse_edges: Dict[str, List[str]]  # task_id -> [dependency_task_ids]
```

**Файл:** `development-pipeline/agents/project_manager/scheduler.py`

**Стратегии планирования:**

| Стратегия | Описание |

| `FIFO` | Первые вошли - первые вышли |
| `SHORTEST_FIRST` | Сначала короткие задачи |
| `CRITICAL_PATH` | Критический путь проекта |

**📄 Субагент:** `.claude/agents/development-pipeline/architect-design.md`

#### Входные данные

| Параметр | Описание |
|----------|----------|

| `spec.md` | Спецификация требований |

#### MCP инструменты

| Категория | Инструмент | Назначение |
|-----------|------------|------------|
| **PM-SPEC инструменты** | Все из INIT/SPEC | Анализ контекста |
| **Зависимости** | `mcp__serena__find_referencing_symbols` | Анализ связей |
| **Семантический поиск** | `mcp__bsl-semantic-search__search_bsl_code` | Поиск BSL кода |
| **Интеллектуальный поиск** | `mcp__bsl-semantic-search__intelligent_search` | Поиск с контекстом |
| **Глубокий анализ** | `mcp__deep-code-reasoning__escalate_analysis` | Глубокий анализ |
| **Генерация идей** | `mcp__llm-rotation__llm_complete` | LLM генерация |

#### Алгоритм работы

```
1. Анализ требований
   └─ Изучить spec.md → выделить технические требования

2. Исследование существующего кода
   ├─ Найти похожие реализации (semantic_search)
   ├─ Изучить паттерны (find_referencing_symbols)
   └─ Проанализировать зависимости

3. Проектирование решения
   ├─ Выбрать архитектурный подход
   ├─ Определить компоненты
   └─ Спланировать изменения

4. Оценка рисков
   ├─ Влияние на существующий код
   ├─ Производительность
   └─ Совместимость

5. Формирование design.md
```

### 3.3 BSL-DEBUGGER DEBUG

**📄 Субагент:** `.claude/agents/development-pipeline/bsl-debugger.md`

#### Назначение

Отладка runtime ошибок через протокол dbgs.

#### Входные данные

| Параметр | Описание |
|----------|----------|
| `PROJECT` | Имя или путь проекта |
| `SESSION_ID` | ID сессии |
| `ERROR_DESCRIPTION` | Описание ошибки |
| `ERROR_CONTEXT` | Контекст ошибки |
| `ERROR_FILE` | Файл с ошибкой |
| `ERROR_LINE` | Строка с ошибкой |

#### MCP инструменты

| Категория | Инструмент | Назначение |
|-----------|------------|------------|
| **Отладчик** | `connect_debugger` | Подключение к dbgs:// |
| **Отладчик** | `set_breakpoint` | Установка точки останова |
| **Отладчик** | `get_call_stack` | Стек вызовов |
| **Отладчик** | `evaluate_expression` | Вычисление выражения |
| **Отладчик** | `get_local_variables` | Локальные переменные |
| **Отладчик** | `step_over` | Шаг с обходом |
| **Отладчик** | `step_into` | Шаг с входом |
| **Отладчик** | `continue_execution` | Продолжить выполнение |
| **Анализ** | `mcp__ast-grep-mcp__ast_grep` | Структура кода |
| **Анализ** | `mcp__code-reasoning__code-reasoning` | Логика |
| **Чтение** | `Read` | Исходный код |

#### Типичные сценарии отладки

##### Деление на ноль
1. Найти делитель через `evaluate_expression`
2. Проследить откуда пришло нулевое значение

##### NullPointer (Неопределено)
1. Найти неинициализированную переменную
2. Проверить условия инициализации
