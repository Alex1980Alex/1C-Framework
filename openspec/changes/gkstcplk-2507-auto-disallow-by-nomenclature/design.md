# Design: GKSTCPLK-2507

> Companion to [proposal.md](proposal.md) и [tasks.md](tasks.md). Source ANALYSIS-REPORT см. в proposal.md.

## Архитектура решения

Решение строится по паттерну **«регистр-настройка → overlay в SQL движений»**, уже применённому в конфигурации для «зелёного коридора» (`гкс_НастройкиОтключенияВходногоКонтроляКачества`) и усиленного контроля (`гкс_НастройкиУсиленногоКонтроляКачества`).

Три компонента:

1. **Регистр-настройка** `гкс_НастройкиЗапретаВскрытияПоНоменклатуре` — декларативные правила автоустановки запретов. Owned бизнес-аналитиком через АРМ.
2. **SQL-overlay** в `Документы.гкс_РегистрацияНаПЛК.МодульМенеджера.ТекстЗапросаТаблицаСтатусыДопускаВагоновКВскрытию` — `ЛЕВОЕ СОЕДИНЕНИЕ` с регистром-настройкой во время формирования движений по `гкс_СтатусыДопускаВагоновКВскрытию`. Дефолтная ветка (Прет=Истина, остальные=Ложь) сохраняется при отсутствии правила; при наличии правила — `ВскрытиеЗапрещено=Истина` всегда.
3. **UI** — третья страница в `Группа Настройки` формы АРМ Приёмки По Качеству; CRUD над регистром-настройкой по образцу двух других вкладок.

Транзакционная семантика не меняется — движения формируются в тот же момент проведения, в том же регистре. Перепроведение применяет актуальные правила (overlay по текущему состоянию РС).
## Структура данных

### Новый РС `гкс_НастройкиЗапретаВскрытияПоНоменклатуре`

```
Измерения (mainFilter=true):
    Номенклатура       CatalogRef.Номенклатура              denyIncompleteValues
    ДопускКВскрытию    EnumRef.гкс_ДопускиКВскрытиюВагонов  denyIncompleteValues
    ДатаНачала         Date (Date-only)
Ресурс:
    Активен            Boolean
Реквизиты:
    ДатаОкончания      Date (Date-only)
    Комментарий        String(150)
    ДатаВремяИзменения Date
    Пользователь       CatalogRef.Пользователи
Формы: ФормаЗаписи, ФормаСписка
RLS: РазрешитьЧтениеИзменение ГДЕ ЗначениеРазрешено(Номенклатура)
```

### Связь с `гкс_СтатусыДопускаВагоновКВскрытию` (целевой регистр движений)

Существующая структура регистра-приёмника НЕ меняется. Изменение касается **только текста запроса**, который формирует движения при проведении документа. Ключ JOIN: `(Настройки.Номенклатура, Настройки.ДопускКВскрытию) = (НачальныеДопуски.Номенклатура, НачальныеДопуски.ДопускКВскрытию)` + `Настройки.Активен`.

### Новая ФО + Константа

`Constants.гкс_ИспользоватьАвтоустановкуЗапретаВскрытия (Boolean)` ↔ `FunctionalOption.гкс_ИспользоватьАвтоустановкуЗапретаВскрытия` — один-к-одному, по образцу `гкс_ИспользоватьОтключениеВходногоКонтроляКачества`. Используется для (a) видимости вкладки в АРМ, (b) опциональной guard'ы overlay в SQL.
## Поток управления при проведении

```
ОбработкаПроведения(Документ.гкс_РегистрацияНаПЛК)
  └── гкс_ПроведениеДокументов.ОбработкаПроведенияДокумента(...)
      └── ПолучениеДанныхДляПроведения вызывает МодульМенеджера.ПолучениеДанныхДляПроведения
          └── ТекстыЗапроса.Добавить(ТекстЗапросаТаблицаСтатусыДопускаВагоновКВскрытию(...))   ← MODIFIED
              ╞═ если ЭтоПриемкаЖДТранспорта(Документ) Или ЭтоПриемкаАвтоТранспорта(...)        ← MODIFIED (2bis)
              │   └── текст 2-го пакета содержит ЛЕВОЕ СОЕДИНЕНИЕ с новым РС                   ← MODIFIED (2)
              ╞═ запрос выполняется → ТаблицаДвижений
              └── движения по гкс_СтатусыДопускаВагоновКВскрытию записываются с overlay
```

**Семантика `ВскрытиеЗапрещено` после изменения:**

| Настройки.Номенклатура | ДопускКВскрытию = Претензионный | ВскрытиеЗапрещено | Комментарий |
|---|---|---|---|
| NULL (нет правила) | Истина | **Истина** | «Автоматически при создании регистрации на ПЛК» |
| NULL | Ложь | **Ложь** | «Автоматически при создании регистрации на ПЛК» |
| not NULL (есть правило) | Истина | **Истина** | «Автоматически по настройкам запрета вскрытия по номенклатуре» |
| not NULL | Ложь | **Истина** | «Автоматически по настройкам запрета вскрытия по номенклатуре» |

Существующее поведение полностью сохраняется при отсутствии правил (Row 1+2 = дефолт). Новая логика добавляет ветви Row 3+4.
## UI-интеграция в АРМ

`Обработка.гкс_АРМПриемкаПоКачеству.Форма.Форма` уже имеет pages-контейнер `ГруппаНастройки` с двумя страницами (Усиленный контроль + Отключение входного контроля) и общим handler'ом `ГруппаНастройкиПриСменеСтраницы`. Новая страница `ГруппаЗапретаВскрытияПоНоменклатуре` добавляется аддитивно:

```
ГруппаНастройки (Pages)
  ├── ГруппаУсиленныйКонтроль                  ← существует
  ├── ГруппаОтключенияВходногоКонтроля         ← существует (зелёный коридор)
  └── ГруппаЗапретаВскрытияПоНоменклатуре      ← NEW
       └── НастройкиЗапретаВскрытияПоНоменклатуре  (DynamicList реквизит)
            ├── Table с FormField'ами реквизитов и измерений нового РС
            └── <commandBar><СоздатьЗапретВскрытияПоНоменклатуре>
```

Обработчики Module.bsl (по образцу зелёного коридора) — см. секцию 6 в [tasks.md](tasks.md). Ключевая особенность: видимость новой страницы управляется ФО `гкс_ИспользоватьАвтоустановкуЗапретаВскрытия` через `Элементы.ГруппаЗапретаВскрытияПоНоменклатуре.Видимость = ПолучитьФункциональнуюОпцию(...);` в `УстановитьВидимостьДоступность`.

Право редактирования (CRUD команды) ограничивается ролью `гкс_НастройкаЗапретаВскрытияПоНоменклатуре` через `Пользователи.РолиДоступны(...)`. Пользователи без роли видят список read-only.
