## Requirements

### REQ-1: Регистр сведений настроек

- Имя: `гкс_НастройкиЗапретаВскрытияПоНоменклатуре`
- Синоним: «Настройки запрета вскрытия по номенклатуре»
- Comment: `GKSTCPLK-2507`
- Измерения: `Номенклатура` (`CatalogRef.Номенклатура`, mainFilter=true, denyIncompleteValues=true), `ДопускКВскрытию` (`EnumRef.гкс_ДопускиКВскрытиюВагонов`, mainFilter+deny), `ДатаНачала` (`Date`, mainFilter=true)
- Ресурс: `Активен` (`Boolean`)
- Реквизиты: `ДатаОкончания` (`Date`), `Комментарий` (`String(150)`), `ДатаВремяИзменения` (`Date`), `Пользователь` (`CatalogRef.Пользователи`)
- Формы: `ФормаЗаписи` (с `ПередЗаписью` заполняющим аудит-поля), `ФормаСписка` (с фильтрами по Номенклатуре + Активности)
- RLS: `РазрешитьЧтениеИзменение ГДЕ ЗначениеРазрешено(Номенклатура)`

### REQ-2: SQL-overlay движений по `гкс_СтатусыДопускаВагоновКВскрытию`

При проведении документа `гкс_РегистрацияНаПЛК` для каждой пары `(ТранспортноеСредство, ДопускКВскрытию)`:

- Если в `гкс_НастройкиЗапретаВскрытияПоНоменклатуре` существует **активная** запись с `Номенклатура = Регистрация.Номенклатура` и `ДопускКВскрытию = <текущий допуск>` — записать `ВскрытиеЗапрещено = Истина` и `Комментарий = "Автоматически по настройкам запрета вскрытия по номенклатуре"`.
- Иначе — сохранить существующее поведение: `ВскрытиеЗапрещено = (ДопускКВскрытию = Претензионный)`, `Комментарий = "Автоматически при создании регистрации на ПЛК"`.

### REQ-3: Распространение на типы перевозки

Логика движений в `гкс_СтатусыДопускаВагоновКВскрытию` (включая overlay из REQ-2) применяется к **ЖД И Авто** приёмке. Условие вызова `ТекстЗапросаТаблицаСтатусыДопускаВагоновКВскрытию` в общей логике проведения документа расширено с `ЭтоПриемкаЖДТранспорта(Документ)` на `ЭтоПриемкаЖДТранспорта(Документ) Или ЭтоПриемкаАвтоТранспорта(Документ)` (точная форма условия фиксируется на стадии apply после grep'а вспомогательных функций).

### REQ-4: Регрессия — пустые/неактивные настройки

При отсутствии активных записей в новом РС для пары `(Регистрация.Номенклатура × ДопускКВскрытию)` поведение проведения **полностью** идентично существующему: формируется по 4 записи на каждое ТС с `ВскрытиеЗапрещено = (ДопускКВскрытию = Претензионный)`. SQL-overlay через `ЛЕВОЕ СОЕДИНЕНИЕ` не дублирует строк и не теряет их.

### REQ-5: UI — третья вкладка в АРМ Приёмки По Качеству

В обработке `гкс_АРМПриемкаПоКачеству.Форма.Форма` в pages-контейнере `ГруппаНастройки` появляется третья страница `ГруппаЗапретаВскрытияПоНоменклатуре`:

- Содержит динсписок `НастройкиЗапретаВскрытияПоНоменклатуре` (`DynamicList(РегистрСведений.<новый>)`).
- Колонки: Номенклатура, ДопускКВскрытию, Активен, ДатаНачала, ДатаОкончания, Комментарий.
- Команда «Создать» открывает `РегистрСведений.гкс_НастройкиЗапретаВскрытияПоНоменклатуре.ФормаЗаписи`.
- Фильтр активности — общий для всех страниц `ГруппаНастройки` (через `ОтборАктивность` + `ПрименитьФильтрАктивностиДляАктивнойСтраницы`).
- Видимость страницы управляется ФО `гкс_ИспользоватьАвтоустановкуЗапретаВскрытия`.
- Доступность команд CRUD управляется ролью `гкс_НастройкаЗапретаВскрытияПоНоменклатуре` (без роли — TolkoProsmotr).

### REQ-6: Функциональная опция + Константа (kill switch)

`Constants.гкс_ИспользоватьАвтоустановкуЗапретаВскрытия (Boolean)` ↔ `FunctionalOption.гкс_ИспользоватьАвтоустановкуЗапретаВскрытия`. Когда константа = Ложь — новая вкладка в АРМ скрыта; опционально SQL-overlay в `ТекстЗапросаТаблицаСтатусыДопускаВагоновКВскрытию` оборачивается гардой `Если ПолучитьФункциональнуюОпцию("гкс_ИспользоватьАвтоустановкуЗапретаВскрытия") Тогда ... КонецЕсли;` для kill-switch'а на проде.

### REQ-7: Безопасность доступа

- Новая роль `гкс_НастройкаЗапретаВскрытияПоНоменклатуре` — права R/W/Add/Edit/Delete на новый РС по образцу `гкс_НастройкаУсиленногоКонтроля`.
- Существующие read-only роли (`гкс_БазовыеПраваУправлениеТранспортомНаПЛК`, `гкс_ТолькоПросмотрБезРЛС`) получают Read-доступ к новому РС.
- RLS регистра: `РазрешитьЧтениеИзменение ГДЕ ЗначениеРазрешено(Номенклатура)` — стандартный паттерн ограничения по номенклатуре в конфигурации.

### REQ-8: Аудит

При каждой записи в новый РС (через `ФормаЗаписи.ПередЗаписью`) обязательно заполняются:

- `ДатаВремяИзменения = ТекущаяДата()`
- `Пользователь = ПараметрыСеанса.ТекущийПользователь`

Эти поля доступны только на чтение и используются для разбора инцидентов («кто и когда создал/изменил правило»).
