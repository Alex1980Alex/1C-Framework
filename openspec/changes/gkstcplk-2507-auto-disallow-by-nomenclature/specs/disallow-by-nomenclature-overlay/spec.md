# Spec: disallow-by-nomenclature-overlay

**Change:** gkstcplk-2507-auto-disallow-by-nomenclature
**Phase:** 1 (single-phase)
**Profile:** onec-config
**JIRA:** GKSTCPLK-2507

## Контекст

При проведении документа `гкс_РегистрацияНаПЛК` в регистр `гкс_СтатусыДопускаВагоновКВскрытию` формируются по 4 записи на каждое ТС — по одной на каждое значение `Перечисление.гкс_ДопускиКВскрытиюВагонов` (Фитосанитарный, Фумигационный, Претензионный, Ветеринарный). Текущая SQL-логика в [`ТекстЗапросаТаблицаСтатусыДопускаВагоновКВскрытию` (ManagerModule.bsl:615-679)](../../../../ИБTransportManagementDevelop/Конфигурация/src/Documents/гкс_РегистрацияНаПЛК/ManagerModule.bsl#L615) жёстко присваивает `ВскрытиеЗапрещено = Истина` только для Претензионного.

Бизнес-цель: для рискованных номенклатур автоматически проставлять `ВскрытиеЗапрещено = Истина` для конфигурируемых видов допуска без ручного вмешательства оператора. Решение — overlay-паттерн через регистр-настройку и LEFT JOIN в SQL движений, по образцу зелёного коридора и усиленного контроля.

Подробности — в [proposal.md](../../proposal.md) и [design.md](../../design.md).

## ## ADDED REQ-1: РегистрСведений `гкс_НастройкиЗапретаВскрытияПоНоменклатуре`

**Файл:** `ИБTransportManagementDevelop/Конфигурация/src/InformationRegisters/гкс_НастройкиЗапретаВскрытияПоНоменклатуре/гкс_НастройкиЗапретаВскрытияПоНоменклатуре.mdo` (новый)

Новый регистр сведений настроек хранит правила автоустановки запретов вскрытия по номенклатуре. Имя `гкс_НастройкиЗапретаВскрытияПоНоменклатуре`, синоним «Настройки запрета вскрытия по номенклатуре», comment `GKSTCPLK-2507`. Periodicity: Independent (не подчинён регистратору, периодизация через измерение `ДатаНачала`).

**RFC 2119:** Конфигурация **MUST** содержать новый РС со структурой ниже. Каждое поле, помеченное `denyIncompleteValues=true`, **MUST** иметь непустое значение при записи.

### Объекты метаданных (новые)

| Категория | Имя | Тип | Атрибуты |
|---|---|---|---|
| Измерение | `Номенклатура` | `CatalogRef.Номенклатура` | mainFilter=true, denyIncompleteValues=true |
| Измерение | `ДопускКВскрытию` | `EnumRef.гкс_ДопускиКВскрытиюВагонов` | mainFilter=true, denyIncompleteValues=true |
| Измерение | `ДатаНачала` | `Date` (Date-only) | mainFilter=true |
| Ресурс | `Активен` | `Boolean` | — |
| Реквизит | `ДатаОкончания` | `Date` (Date-only) | пустая = бессрочно |
| Реквизит | `Комментарий` | `String(150)` | — |
| Реквизит | `ДатаВремяИзменения` | `Date` | аудит, заполняется в `ПередЗаписью` |
| Реквизит | `Пользователь` | `CatalogRef.Пользователи` | аудит, заполняется в `ПередЗаписью` |
| Форма | `ФормаЗаписи` | — | по образцу зелёного коридора |
| Форма | `ФормаСписка` | — | с фильтрами по Номенклатуре + Активности |

RLS-условие (`ManagerModule.ПриЗаполненииОграниченияДоступа`): `РазрешитьЧтениеИзменение ГДЕ ЗначениеРазрешено(Номенклатура)`.

#### Scenarios (Given/When/Then)

- **Given** новый РС зарегистрирован в конфигурации **When** оператор открывает `Формы.ФормаЗаписи` **Then** видны 8 полей (3 измерения + 1 ресурс + 4 реквизита), `ДатаВремяИзменения`/`Пользователь` read-only.
- **Given** оператор сохраняет запись без `Номенклатура` **When** срабатывает `denyIncompleteValues` **Then** платформа возвращает ошибку «Поле Номенклатура обязательно для заполнения», запись не сохранена.
- **Given** оператор сохраняет валидную запись **When** срабатывает `ПередЗаписью` **Then** `ДатаВремяИзменения = ТекущаяДата()`, `Пользователь = ПараметрыСеанса.ТекущийПользователь` (аудит).

## ## MODIFIED REQ-2: SQL-overlay движений по `гкс_СтатусыДопускаВагоновКВскрытию`

**Объект:** `Документ.гкс_РегистрацияНаПЛК`
**Модуль:** [`ManagerModule.bsl`](../../../../ИБTransportManagementDevelop/Конфигурация/src/Documents/гкс_РегистрацияНаПЛК/ManagerModule.bsl) (строки 615-679)
**Что меняется:** функция `ТекстЗапросаТаблицаСтатусыДопускаВагоновКВскрытию` — расширяется текст 2-го пакета: добавление `Регистрация.Номенклатура` во временную таблицу `ВТ_НачальныеДопуски`, добавление `ЛЕВОЕ СОЕДИНЕНИЕ` с новым РС, перевод `ВскрытиеЗапрещено` и `Комментарий` через `ВЫБОР КОГДА Настройки.Номенклатура ЕСТЬ NULL ТОГДА … ИНАЧЕ …`.
**Было:** `ВскрытиеЗапрещено = (ДопускКВскрытию = Претензионный)` жёстко, без учёта настроек.
**Стало:** при наличии активной записи в новом РС → `ВскрытиеЗапрещено = Истина` всегда; при отсутствии → старая логика.

**RFC 2119:** Реализация **MUST** изменить тело SQL-запроса согласно приведённой логике. Изменение **MUST** обеспечить регрессию-безопасность: при пустом РС количество и значения формируемых движений **MUST** быть идентичны исходным.

#### Scenarios (Given/When/Then)

- **Given** нет активных записей в новом РС для (Номенклатура × Допуск) **When** документ `гкс_РегистрацияНаПЛК` проведён **Then** в `гкс_СтатусыДопускаВагоновКВскрытию` записано 4 строки на ТС, `ВскрытиеЗапрещено = Истина` только для Претензионного (regress-safe).
- **Given** в РС есть активная запись (Номенклатура=Лен, Допуск=Фумигационный, Активен=Истина) **When** проведена регистрация с этой номенклатурой **Then** запись для Фумигационного имеет `ВскрытиеЗапрещено = Истина` и `Комментарий = "Автоматически по настройкам запрета вскрытия по номенклатуре"`; остальные 3 записи по дефолту.
- **Given** запись в РС деактивирована (`Активен = Ложь`) **When** регистрация перепроводится **Then** Фумигационный возвращается к дефолту `ВскрытиеЗапрещено = Ложь`.

## ## MODIFIED REQ-3: Расширение вызова на Авто-приёмку

**Объект:** `Документ.гкс_РегистрацияНаПЛК`
**Модуль:** [`ManagerModule.bsl`](../../../../ИБTransportManagementDevelop/Конфигурация/src/Documents/гкс_РегистрацияНаПЛК/ManagerModule.bsl) (строка ~51)
**Что меняется:** условие вызова `ТекстЗапросаТаблицаСтатусыДопускаВагоновКВскрытию` в общей логике формирования движений.
**Было:** `Если ЭтоПриемкаЖДТранспорта(Документ) Тогда ТекстЗапросаТаблицаСтатусыДопускаВагоновКВскрытию(...); КонецЕсли;` — только для ЖД.
**Стало:** `Если ЭтоПриемкаЖДТранспорта(Документ) Или ЭтоПриемкаАвтоТранспорта(Документ) Тогда ТекстЗапросаТаблицаСтатусыДопускаВагоновКВскрытию(...); КонецЕсли;` — для ЖД и Авто. Точная форма условия фиксируется на apply после grep'а вспомогательных функций.

**RFC 2119:** Реализация **MUST** обеспечить вызов функции формирования движений по `гкс_СтатусыДопускаВагоновКВскрытию` для обоих типов перевозок (ЖД и Авто). При отсутствии готовой функции-проверки `ЭтоПриемкаАвтоТранспорта` реализация **SHOULD** добавить такую функцию (или inline-условие на `Документ.ВидПеревозки`).

#### Scenarios (Given/When/Then)

- **Given** документ-регистрация с `ВидПеревозки = ЖДТранспорт` **When** документ проведён **Then** движения по `гкс_СтатусыДопускаВагоновКВскрытию` сформированы (как и было).
- **Given** документ с `ВидПеревозки = Автомобиль` **When** документ проведён **Then** движения тоже сформированы (новое поведение).

## ## ADDED REQ-4: UI — третья страница в АРМ Приёмки По Качеству

Добавляется новая страница `ГруппаЗапретаВскрытияПоНоменклатуре` в pages-контейнере `ГруппаНастройки` (рядом со страницами «Усиленный контроль» и «Отключение входного контроля»). **RFC 2119:** Реализация **MUST** добавить третью страницу в `ГруппаНастройки`; страница **MUST** содержать Table-элемент со списком записей нового РС, командой `СоздатьЗапретВскрытияПоНоменклатуре` и колонками для всех 8 полей РС.

### REQ-5: UI — третья вкладка в АРМ Приёмки По Качеству

В обработке `гкс_АРМПриемкаПоКачеству.Форма.Форма` в pages-контейнере `ГруппаНастройки` появляется третья страница `ГруппаЗапретаВскрытияПоНоменклатуре`:

- Содержит динсписок `НастройкиЗапретаВскрытияПоНоменклатуре` (`DynamicList(РегистрСведений.<новый>)`).
- Колонки: Номенклатура, ДопускКВскрытию, Активен, ДатаНачала, ДатаОкончания, Комментарий.
- Команда «Создать» открывает `РегистрСведений.гкс_НастройкиЗапретаВскрытияПоНоменклатуре.ФормаЗаписи`.
- Фильтр активности — общий для всех страниц `ГруппаНастройки` (через `ОтборАктивность` + `ПрименитьФильтрАктивностиДляАктивнойСтраницы`).
- Видимость страницы управляется ФО `гкс_ИспользоватьАвтоустановкуЗапретаВскрытия`.
- Доступность команд CRUD управляется ролью `гкс_НастройкаЗапретаВскрытияПоНоменклатуре` (без роли — TolkoProsmotr).

### REQ-6: Функциональная опция + Константа (kill switch)

`Constants.гкс_ИспользоватьАвтоустановкуЗапретаВскрытия (Boolean)` ↔ `FunctionalOption.гкс_ИспользоватьАвтоустановкуЗапретаВскрытия`. Когда константа = Ложь — новая вкладка в АРМ скрыта; опционально SQL-overlay в `ТекстЗапросаТаблицаСтатусыДопускаВагоновКВскрытию` оборачивается гардой `Если ПолучитьФункциональнуюОпцию("гкс_ИспользоватьАвтоустановкуЗапретаВскрытия") Тогда ... КонецЕсли;` для kill-switch'а на проде.

### REQ-7: Безопасность доступа

- Новая роль `гкс_НастройкаЗапретаВскрытияПоНоменклатуре` — права R/W/Add/Edit/Delete на новый РС по образцу `гкс_НастройкаУсиленногоКонтроля`.
- Существующие read-only роли (`гкс_БазовыеПраваУправлениеТранспортомНаПЛК`, `гкс_ТолькоПросмотрБезРЛС`) получают Read-доступ к новому РС.
- RLS регистра: `РазрешитьЧтениеИзменение ГДЕ ЗначениеРазрешено(Номенклатура)` — стандартный паттерн ограничения по номенклатуре в конфигурации.

### REQ-8: Аудит

При каждой записи в новый РС (через `ФормаЗаписи.ПередЗаписью`) обязательно заполняются:

- `ДатаВремяИзменения = ТекущаяДата()`
- `Пользователь = ПараметрыСеанса.ТекущийПользователь`

Эти поля доступны только на чтение и используются для разбора инцидентов («кто и когда создал/изменил правило»).
