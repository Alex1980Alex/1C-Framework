## Requirements

### REQ-1: Регистр сведений настроек

- Имя: `гкс_НастройкиЗапретаВскрытияПоНоменклатуре`
- Синоним: «Настройки запрета вскрытия по номенклатуре»
- Comment: `GKSTCPLK-2507`
- Измерения: `Номенклатура` (`CatalogRef.Номенклатура`, mainFilter=true, denyIncompleteValues=true), `ДопускКВскрытию` (`EnumRef.гкс_ДопускиКВскрытиюВагонов`, mainFilter+deny), `ДатаНачала` (`Date`, mainFilter=true)
- Ресурс: `Активен` (`Boolean`)
- Реквизиты: `ДатаОкончания` (`Date`), `Комментарий` (`String(150)`), `ДатаВремяИзменения` (`Date`), `Пользователь` (`CatalogRef.Пользователи`)
- Формы: `ФормаЗаписи` (с `ПередЗаписью` заполняющим аудит-поля), `ФормаСписка` (с фильтрами по Номенклатуре + Активности)
- RLS: `РазрешитьЧтениеИзменение ГДЕ ЗначениеРазрешено(Номенклатура)`

### REQ-2: SQL-overlay движений по `гкс_СтатусыДопускаВагоновКВскрытию`

При проведении документа `гкс_РегистрацияНаПЛК` для каждой пары `(ТранспортноеСредство, ДопускКВскрытию)`:

- Если в `гкс_НастройкиЗапретаВскрытияПоНоменклатуре` существует **активная** запись с `Номенклатура = Регистрация.Номенклатура` и `ДопускКВскрытию = <текущий допуск>` — записать `ВскрытиеЗапрещено = Истина` и `Комментарий = "Автоматически по настройкам запрета вскрытия по номенклатуре"`.
- Иначе — сохранить существующее поведение: `ВскрытиеЗапрещено = (ДопускКВскрытию = Претензионный)`, `Комментарий = "Автоматически при создании регистрации на ПЛК"`.

### REQ-3: Распространение на типы перевозки

Логика движений в `гкс_СтатусыДопускаВагоновКВскрытию` (включая overlay из REQ-2) применяется к **ЖД И Авто** приёмке. Условие вызова `ТекстЗапросаТаблицаСтатусыДопускаВагоновКВскрытию` в общей логике проведения документа расширено с `ЭтоПриемкаЖДТранспорта(Документ)` на `ЭтоПриемкаЖДТранспорта(Документ) Или ЭтоПриемкаАвтоТранспорта(Документ)` (точная форма условия фиксируется на стадии apply после grep'а вспомогательных функций).
