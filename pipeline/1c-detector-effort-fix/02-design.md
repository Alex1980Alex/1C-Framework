# 02 — Дизайн: фикс детектора 1С (оценка трудозатрат)

## Решение 1 — Находка 1: группа `develop` (НЕ изменение модели подсчёта)

**Почему не правим `modify`/счётчик:** существующий тест `test_route_medium_ask_flow` кодирует
«доработать обработку + добавить колонку» (2 modify-хита) = **medium**. Любой мульти-подсчёт `modify`
или добавление туда `создать` сломает это и `test_estimate_effort_folder_bump`. Поэтому добавляем
**отдельную группу `develop`** (вес `+2`, как `modify`, считается один раз) — аддитивно, минимальный
регресс-риск.

```
weights += {"develop": 2}
signals["develop"] = ["разработать", "реализовать", "печатн", "механизм", "функционал",
                      "новую форм", "новая форма"]
signals["cross"]  += ["настроить обмен", "обмен с баз", "обмен между"]   # интеграция помимо «обмен данны»
```

`develop` включается в цикл групп `for group in ("modify","heavy_obj","cross","multi","develop")`.

**Эффект (single-count, +2):**
| вход (с JIRA → confident) | было | стало |
|---|---|---|
| Создать новую печатную форму Акт забраковки | simple/auto | medium/ask_flow |
| Разработать печатную форму Ярлык пробы | simple/auto | medium/ask_flow |
| Разработать механизм приёмки авто | simple/auto | medium/ask_flow |
| Настроить обмен с базой УТ Инфида | simple/auto | medium/ask_flow |
| Реализовать функционал по внесению данных в документ | simple/auto | medium/ask_flow |
| Реализовать обмен данными + новую роль + рефакторинг подсистемы | medium | complex/gated (develop+cross) |

**Инвариант сохранён:** `test_route_simple_auto` («исправить опечатку в наименовании») не содержит
develop-слов → остаётся simple/auto (truly-cosmetic путь жив). `test_route_complex_gated` остаётся complex.

**Цель — НЕ авто-прогон.** `medium → ask_flow` («спросить AUTO или гейт») — достаточно: substantial-задача
больше не запускается без участия пользователя. Лексически отличить «разработать НОВУЮ ПФ» от «доработать ПФ»
нельзя, поэтому единый `+2` → medium как безопасный пол.

## Решение 2 — Находка 3: метрика complexity-band в eval

- Добавить в `data/1c-detector-ground-truth.json` поле `"complexity": "simple|medium|complex"`
  на 35 строк с `route_class=confident` (только там ветка сложности достижима).
- В `evaluate()` собрать band-точность по подмножеству строк, где `gt.complexity` задан И `pred` confident:
  `complexity_band: {accuracy, confusion, auto_misroutes}`.
  `auto_misroutes` = число строк, где gt.complexity ∈ {medium,complex}, а `flow=auto` (опасный мисроут).
- Печатать секцию в человеко-отчёте; в `--json` — ключ `complexity_band`.
- Метрика **диагностическая** (как и весь eval): детектор не учится на GT.
