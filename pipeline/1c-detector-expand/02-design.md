# 02 — Дизайн: code-presence path + расширение словарей детектора 1С

## Проблема (фидбэк пользователя)
Прежняя формулировка «наличие кода = вторичный сигнал» ошибочна. Грунт по реальным ТЗ
(`configuration/260304…/docs`, свод субагента + recall памяти): **285 fenced BSL/SQL-блоков в 46
файлах, 436 BSL-токенов в 40+ файлах** — литеральный код встречается в ТЗ/диалогах/отчётах массово.
В текущей логике `_1C_STRONG` (CamelCase/объект.точка) даёт is_1c ТОЛЬКО в паре с таск-глаголом —
значит вставленный фрагмент кода без «глагола» не распознаётся. Это и есть пробел.

## Решение

### A. Новый самостоятельный путь — `_1C_CODE` (наличие кода ⇒ 1С, БЕЗ глагола)
Высокоточные **синтаксические** маркеры BSL/запросов (case-sensitive, `re.U` без `re.I` — иначе
prose-слова зашумят). Состав (grounded):
- **Менеджер.Член** ед./мн.ч.: `Документы.`, `РегистрыСведений.`, `Перечисления.`, `Справочники.`, …
  с member-guard `\.(?:[А-ЯЁ]|гкс_)` (отсекает prose «Документ. Затем…»). **Главный промах** —
  мн.число менеджеров (раньше ловился только ед. `Документ.`).
- **Типы-ссылки**: `СправочникСсылка.`, `ДокументСсылка.`, `ПеречислениеСсылка.`
- **Событийные сигнатуры**: `ПередЗаписью|ПриЗаписи|ОбработкаПроведения|ОбработкаПроверкиЗаполнения|
  ПриСозданииНаСервере|ОбработкаЗаполнения`; `ОбменДанными.Загрузка`.
- **Закрывающие BSL-кейворды** (не бывают в обычной речи): `КонецПроцедуры|КонецФункции|КонецЕсли|
  КонецЦикла|КонецПопытки|ВызватьИсключение|…Транзакции`.
- **Язык запросов** (однозначные): `СГРУППИРОВАТЬ ПО|ОБЪЕДИНИТЬ ВСЕ|ЕСТЬNULL|ВЫРАЗИТЬ(|СрезПоследних`.
- **БСП/конструкторы/модули**: `ОбщегоНазначения.|ОбработкаОшибок.|УправлениеДоступом.`,
  `Новый (Структура|Массив|ТаблицаЗначений|…)`, `СтрШаблон(|НСтр(`, `ManagerModule|ObjectModule|
  RecordSetModule`, `.bsl|.mdo`, `Метаданные()`.

`is_1c = jira ∨ _1C_DEFINITIVE ∨ _1C_CODE ∨ ((_1C_SIGNAL ∨ _1C_STRONG) ∧ verb)`
`confident_1c = jira ∨ _1C_STRONG ∨ _1C_CODE`   (код — сильный маркер ⇒ маршрут по сложности)

### B. Расширение доменной лексики `_1C_SIGNAL` (второй класс — чат-транскрипты почти без кода)
+ бизнес-домен (предметная область приёмки/качества/транспорта, grounded на ТЗ+диалогах):
разгрузк, отгрузк, приёмк/приемк, лабораторн, блокировк/заблокир/разблокир, композит, накладн,
удостоверени, синхронизаци, рассылк, усиленн контрол, проба (anchored), + узкие аббревиатуры с `\b`
(НнР, ПЛК, ФНП, ИАС, ЛА, ЗПП, ТТН). Generic-слова (качество/контроль) НЕ берём bare — высокий FP.

### C. Расширение глаголов `_TASK_VERB` (фигурируют только в паре с сигналом ⇒ низкий FP)
+ перепровест, перезаполн, зарегистрир, синхронизир, заблокир/разблокир, принят, провер,
рассчита, вывест/вывод, выгруз, загруз, активир, внес/внесени, отмен, `\bформирован`.

## Инвариант безопасности (сохраняется)
- `_1C_CODE` = только **синтаксис кода**, НЕ голый CamelCase/доменное слово → негативы
  `«что такое ТабличныйДокумент»` (CamelCase без глагола) и `«исправить при проведении»`
  (домен+глагол, нет strong/кода → `ask_1c`) **не ломаются**.
- Доменные FP (разгрузка/приёмка в не-1С тексте) деградируют в `ask_1c` (вопрос), не в авто-прогон.
- `estimate_effort` НЕ трогаем (свой словарь) → effort-тесты целы.

## Тест-план
Расширить `tests/unit/test_pipeline_1c_bridge.py`: code-path без глагола (manager.член / event /
closer / query) ⇒ is_1c+confident; новые домен-термины+глагол ⇒ is_1c; новые глаголы; **регресс
негативов** (CamelCase без глагола, RAG, python, prose «Документ. Это важно»). + полный прогон `-m unit`.
