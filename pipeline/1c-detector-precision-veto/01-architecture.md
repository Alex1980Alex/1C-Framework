# 01 — Планирование: Находка 2 (precision детектора 1С)

## Проблема
`route_1c_task` даёт ~80% FP на русскоязычной разработке фреймворка: `_1C_SIGNAL` содержит общие
слова (`обработк/отчёт/механизм/форма/обмен/регистр/профил`), которые в паре с таск-глаголом дают
is_1c=True. Blast-radius ограничен `ask_1c` (инвариант безопасности), но это шум на основном потоке.

## Почему НЕЛЬЗЯ просто убрать слова из `_1C_SIGNAL`
Эти же слова — легитимные 1С-домен-термины. Их удаление обрушит recall на реальных 1С-задачах
(«доработать **обработку** проведения», «**отчёт** по движениям»). Подтверждено: GT-позитивы массово
используют именно эти слова.

## Решение: слой негативной улики (veto), НЕ удаление сигналов
Высокоточный denylist НЕ-1С тех-контекста (FastAPI/Qdrant/pytest/эмбеддинг/docker/...) ветирует
**только слабый** 1С-сигнал (regex domain-word ИЛИ семантика, confidence < 0.7). Confident-путь
(JIRA / BSL-код / гкс_/configuration / CamelCase-объект) **никогда не ветируется** — реальная 1С-задача,
упоминающая тех-слово, защищена. Веток слабый-сигнал → `none` (молчим) вместо `ask_1c` (шумим).

## Калибровка (эмпирическая, на расширенном GT) — выполнена в scouting
- denylist v1: **0 потерь recall** (134 позитива), **18 FP подавлено** (16 framework-dev-neg + 2 near-domain GT).
- Holdout (свежие, НЕ в GT): **0/8** остаточных FP на framework-dev; **0** recall-потерь от veto на 6 свежих 1С
  (1 FN «права доступа для роли» — пред-существующий, `veto=False`, относится к Находке 8, вне scope).

## Инвариант безопасности (исключения из veto)
1. JIRA / definitive (гкс_/configuration) / BSL-код / `_1C_STRONG` (CamelCase-кириллица, Объект.точка) → confident → НЕ ветируется.
2. Denylist исключает неоднозначные слова: `rmq/rabbitmq/kafka` (реальный 1С-обмен), `mcp` (1c-mcp), голый `api`/`база данных`.
3. Veto только в `route_1c_task` (политика маршрута); `classify_1c_task` остаётся чистым regex-детектором.

## Файлы
- `.claude/hooks/shared/pipeline_1c_bridge.py` — `_NON_1C_CONTEXT` regex + `_has_non_1c_context()` + veto в `route_1c_task` + ключ `non_1c_context`.
- `tests/unit/test_pipeline_1c_bridge.py` — veto framework-dev → none; confident-с-тех-словом НЕ ветируется; recall-инвариант.
- (eval уже меряет is_1c P/R → precision-выигрыш виден автоматически.)

## Критерий приёмки
- is_1c precision на полном GT растёт (0.86 → ~0.99); **recall не падает** (≥0.978).
- Confident-задачи с тех-словом не ветируются; framework-dev → flow=none.
- Существующие тесты зелёные; code-verify PASS.
