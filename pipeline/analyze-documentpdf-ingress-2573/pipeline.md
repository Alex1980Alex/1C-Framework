# Pipeline — Анализ: ДокументPDF чтение из Потока vs temp-файл (GKSTCPLK-2573)

Тип: trivial (исследование/советная задача — без правок конфигурации 1С).

## 1. План (Планирование)
Предложение пользователя: заменить запись PDF во временный файл на
`ПолучитьИзВременногоХранилища` → `ДвоичныеДанные.ОткрытьПотокДляЧтения()` →
`ДокументPDFПросмотрОкно.Прочитать(Поток)` → `Показать()`. Цель — проверить жизнеспособность
ухода от temp-файла на клиентском пути просмотра.

## 2. Дизайн
Метод проверки: (а) контракт платформы через `bsl-platform-context`; (б) живой
`execute_code`-тест на заведомо валидном PDF (сервер) — файловая и бинарная перегрузки +
факт блокировки файла; (в) внешняя корроборация (infostart, именно клиентский путь
`Показать()`). Сервер-крашащую перегрузку `Прочитать(Поток)` намеренно НЕ триггерить.

## 3. Реализация
Артефакты знаний (не код конфигурации): cache-топик
`.claude/skills/1c-doc-research/cache/documentpdf-prochitat-ingress.md` + обновление памяти
`feedback-1c-documentpdf-read-server-file-only` (подтверждение на .1936 + клиентский вывод).

## 4. Тест (Верификация)
Живой `execute_code` на 8.3.27.1936: `Прочитать(ИмяФайла)`=OK (1 стр.);
`Прочитать(ДвоичныеДанные)`=«Неправильный заголовок PDF файла» на ТЕХ ЖЕ байтах;
`УдалитьФайлы` при живом объекте=«файл занят другим процессом».
**Вывод:** предложение отклонено — не-файловый ingress нерабочий, и `Показать()` требует
temp-файл на обоих тирах (корроборировано infostart 2400974). Рекомендация: оставить
`Записать(temp)`→`Прочитать(ИмяФайла)`→`Показать()` + отложенная очистка temp.
