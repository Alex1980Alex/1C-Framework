# 02 — Дизайн: структура дорожной карты 260703

**Артефакт-результат:** `docs/roadmap/260703_ROADMAP_CH43_1C_PIPELINE_AUDIT.md`

## Принципы

1. Ошибки (док≠код) — только подтверждённые аудитом с `file:line`; каждая с фиксом и приоритетом.
2. Улучшения — каждое обязано ссылаться на факт GitHub-исследования ([web]) или локальный
   опыт ([exp]/[docs]); без атрибуции пункт не входит.
3. Не дублировать живые roadmap'ы (260614 §18) и ADR (034/035/037/041) — ссылаться.
4. Формат по образцу 260614: контекст → находки → фазы → риски → acceptance → §18 progress log.

## Секции

- §1 Контекст и метод (что аудировано, чем: 4 субагента + ecosystem_scan + кеш)
- §2 Сводка находок аудита: A. Ошибки док≠код · B. Внутренние противоречия ·
  C. Устаревшее/пробелы · D. Хрупкие места архитектуры
- §3 GitHub-исследование: сводные паттерны лидеров + вывод «что применимо к гл. 43»
- §4 Дорожная карта: P0 (исправление ошибок доков/кода) → P1 (консистентность/наблюдаемость)
  → P2 (улучшения по паттернам лидеров) → P3 (стратегические). Каждый пункт: задача,
  файлы, критерий приёмки, оценка, риск, атрибуция.
- §5 Риски и границы
- §6 Acceptance всего roadmap
- §18 Progress log (протокол feedback-roadmap-progress-log-protocol)

## Гейт-критерии перед публикацией

- Все P0-пункты трассируются к конкретной находке аудита (id F-xx).
- Все P2/P3-пункты трассируются к источнику исследования.
- Ссылки кликабельные (Output Rules CLAUDE.md).
