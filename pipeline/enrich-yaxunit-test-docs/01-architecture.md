# 01 — Анализ: рек.3 (YAxUnit-смоук) + gap-анализ доков/скилла vs ground truth

> Задача (мандат 2026-07-19): (1) проанализировать реализацию рек.3; (2) обогатить скиллы работы
> с тестами данными GitHub/интернета; (3) проверить документацию, при неполноте — дополнить.
> Ground truth = вендоренный исходник YAxUnit v24.x в `src/bsl/exts/YAXUNIT/CommonModules/`
> (BIA-Technologies, Apache-2.0) + 3 реальных задеплоенных тест-модуля в `src/bsl/exts/UnitTests/`.

## Part A. Что реализовано (рек.3, 2026-07-19) — «YAxUnit-смоук серверной логики»

Advisory-петля (НИКОГДА не блок), проведённая тремя точками:

1. **Детект сигнала** — [`onec-task-completion-stop.py:141-149`](../../.claude/hooks/onec-task-completion-stop.py)
   `_YAXUNIT_SMOKE_TOOLS = {run_all_tests, run_module_tests}` — ЕДИНСТВЕННЫЙ маршрут
   `mcp-onec-test-runner` (НЕ `edt/codepilot run_yaxunit_tests`-дубли, НЕ BDD). Сигнал
   `yaxunit_smoke` детектится по фактическому `tool_use` в транскрипте (Тир-3).
2. **Applicable-знаменатель** — `yaxunit_applicable = _impact_applicable()` =
   [`onec_change_scope.edits_exported_method`](../../.claude/hooks/shared/onec_change_scope.py).
   Тот же сигнал, что для impact-чека (T1): правка/добавление ЭКСПОРТНОГО серверного метода.
   Логика: YAxUnit зовёт только экспортные методы → экспортная поверхность = тестируемый
   инвариант. impact = pre-change «кто сломается», yaxunit-смоук = post-change «инвариант держится».
   git-diff дорог → считается ОДИН раз, пишется в оба ключа (`impact_applicable`+`yaxunit_applicable`).
3. **Сюрфейс + метрика**:
   - `•`-буллет в block-сообщении ([`onec-task-completion-stop.py:572`](../../.claude/hooks/onec-task-completion-stop.py)) + строка в advisory-таблице (`:395`) + LOOPS.md.
   - Событие пишется в `.claude/cache/onec-toolgate-events.jsonl` на КАЖДОЙ 1С-задаче.
   - Валидатор [`onec_toolgate_validation.py:97-107`](../../scripts/onec_toolgate_validation.py):
     `yaxunit_rate_on_applicable` = presence смоука ТОЛЬКО на задачах с правкой экспортного метода
     (честный знаменатель, старые записи без поля исключены).
   - Прогон пишет `.run-state.json` → авто-Этап-4 (`advance_test_done`, F-1.6), иначе секция
     live-данных (ADR-050).

**Вывод по A:** реализация корректна и следует лестнице advisory→замер→hard (ADR-035). Ядро
кода трогать НЕ нужно. Слабое место — НЕ в гейте, а в **методичке/скилле, которые агент читает,
когда решает написать смоук**: если скилл диктует несуществующий API, смоук либо не напишется,
либо упадёт «Метод не найден». Значит обогащение доков/скилла = прямое усиление рек.3.

## Part B. Ground truth API (вендоренный YAxUnit v24.x) — авторитетно

Извлечено из исходника (Экспорт-сигнатуры) + 3 реальных прогнанных теста.

**Регистрация — `ЮТТесты`** (`ЮТТесты/Ext/Module.bsl`):
- `ДобавитьСерверныйТест(ИмяТестовогоМетода, ПредставлениеТеста="", ТегиСтрокой="")` — 3 арг.
- `ДобавитьКлиентскийТест(Имя, Представление="", Теги="")`
- `ДобавитьТест(Имя, Представление="", ТегиСтрокой="", Контексты=Неопределено)` — generic, параметризация через `Контексты`.
- `ДобавитьТестовыйНабор(Имя, ТегиСтрокой="")` — набор.
- Флюент-модификаторы (chain на результат добавления): `.ВТранзакции(=Истина)`,
  `.УдалениеТестовыхДанных(=Истина)`, `.Перед(...)`, `.После(...)`, `.Тег(...)`,
  `.НастройкаИсполнения(Имя, Значение)`, `.Представление(...)`, `.ЗависитОт()`,
  `.СвойствоОтчета(...)`, `.СвойстваОтчета(...)`.

**Утверждения — `ЮТест.ОжидаетЧто(Значение, Сообщение="").<Матчер>()`** (`ЮТУтверждения/Ext/Module.bsl`):
- Равенство/сравнение: `Равно НеРавно Больше БольшеИлиРавно Меньше МеньшеИлиРавно`.
- Диапазоны: `МеждуВключаяГраницы МеждуИсключаяГраницы МеждуВключаяНачалоГраницы МеждуВключаяОкончаниеГраницы`.
- Заполненность: `Заполнено НеЗаполнено`.
- Тип: `ИмеетТип НеИмеетТип` — принимают **`Строка | Тип | ОписаниеТипов`** (т.е. и `ИмеетТип("Структура")`, и `ИмеетТип(Тип("Структура"))` валидны — подтверждено doc-коммент `ЮТУтверждения:437`).
- Булево: `ЭтоИстина ЭтоНеИстина ЭтоЛожь ЭтоНеЛожь`.
- Существование: `Существует НеСуществует ЭтоНеопределено ЭтоНеНеопределено ЭтоNull ЭтоНеNull`.
- Строки/коллекции: `Содержит НеСодержит СодержитСтрокуПоШаблону НеСодержитСтрокуПоШаблону НачинаетсяС ЗаканчиваетсяНа ВСписке`.
- Длина: `ИмеетДлину ИмеетДлинуБольше ИмеетДлинуМеньше НеИмеетДлину`.
- Свойства/элементы: `Свойство НетСвойства ИмеетСвойство НеИмеетСвойства ИмеетСвойстваРавные Элемент Объект ИмеющееПредставление`.
- Методы/исключения: `Метод(Имя, Параметры) ИмеетМетод ВыбрасываетИсключение(ОжидаемоеЗначение,...) НеВыбрасываетИсключение`.
- Предикаты/коллекции: `СоответствуетПредикату КаждыйЭлементСоответствуетПредикату ЛюбойЭлементСоответствуетПредикату КаждыйЭлементСодержитСвойство[СоЗначением] ЛюбойЭлементСодержитСвойство[СоЗначением]`.

**Точка входа — `ЮТест`** (`ЮТест/Ext/Module.bsl`), помимо `ОжидаетЧто`:
- `ОжидаетЧтоТаблицаБазы(ИмяТаблицы, Сообщение="")` → `ЮТУтвержденияИБ`.
- `Данные()` → фабрика фикстур `ЮТТестовыеДанные`.
- `Предикат(Условия)` → `ЮТПредикаты` (для проверки коллекций/движений).
- `Варианты(Реквизиты)` → data-driven прогон.
- `Контекст() / КонтекстТеста() / КонтекстТестовогоНабора() / КонтекстМодуля()` — общий стейт (для setup/teardown).
- **`Пропустить(Сообщение)`** — штатный SKIP теста (в реальном `гкс_РассылкиИОповещенияТест`
  автор НЕ знал про него и вручную писал `ОжидаетЧто(Истина,...).Равно(Истина); Возврат;` — это надо в скилл).
- `Упал(Сообщение, Факт, Ожид)` — явное падение.
- `Пауза ВывестиВКонсоль ДобавитьСообщение ДобавитьПредупреждение Окружение Зависимость`.

**БД-утверждения — `ЮТУтвержденияИБ`** (`ЮТест.ОжидаетЧтоТаблицаБазы(...)...`):
`СодержитЗаписи(Предикат) НеСодержитЗаписи СодержитЗаписиСНаименованием СодержитЗаписиСКодом
СодержитЗаписиСНомером СодержитТолькоОднуЗапись СодержитНесколькоЗаписей(N,...)` (+ Не-варианты).

**Мокирование — `Мокито`** (`Мокито/Ext/Module.bsl` + `МокитоОбучение` + `МокитоПроверки`):
- Поток: `Обучение → Прогон → (вызов кода) → Проверить`.
- `Мокито.Обучение(Объект, СброситьСтарыеНастройки=Истина)` → `МокитоОбучение`.
- Цепочка обучения: `.Наблюдать(Метод, Параметры)` (spy) / `.Когда(Метод, Параметры)` (stub-условие,
  алиас Наблюдать) → `.Вернуть(Результат)` / `.ВыброситьИсключение(Текст)` / `.Пропустить()` / `.ВыполнитьМетод()`.
  Два способа задать метод: `.Когда("ИмяМетода", Мокито.МассивПараметров(...))` ИЛИ `.Когда(Объект.ИмяМетода(...))`.
- **`Мокито.Прогон()` — ОБЯЗАТЕЛЕН** между обучением и вызовом тестируемого кода (переключает режим).
- Маски параметров: `Мокито.ЛюбойПараметр() ЧисловойПараметр() СтроковыйПараметр() ТипизированныйПараметр(Тип) МассивПараметров(...) ПараметрПоУмолчанию()`.
- Проверка: `Мокито.Проверить(Объект, Описание).КоличествоВызовов(Метод, Параметры).Равно(N)` (+ `.Больше .Меньше .Заполнено .Пусто`); `.Вызовы(...)`.
- **Ключевое ограничение (из doc-коммента `Мокито:29-47`):** мокнуть можно ТОЛЬКО метод, обёрнутый
  в расширении аннотацией `&Вместо("Метод")` + `МокитоПерехват.АнализВызова(...)`. Произвольный
  метод типовой без обвязки замокать НЕЛЬЗЯ. Ни один док этого не упоминает.

**Дискавери тест-модулей (подтверждено в этом проекте):** регистрация в подсистеме
`ЮТТ_ЮТПодключаемыеМодули → Модульные`, `<Content>` = `CommonModule.<ИмяМодуля>`
(`Модульные.xml:18-22`). Реальные модули: `ЮТТПримерТест`, `гкс_РассылкиИОповещенияТест`,
`гкс_ОбщегоНазначенияТест` — **префикс `ЮТТ` для МОДУЛЕЙ НЕ требуется** (`гкс_` работает). `ЮТТ` — имя подсистемы, не модулей.

**Дымовые тесты YAxUnit — `ЮТДымовыеТесты`** (НЕ путать с рек.3-«смоук»): встроенный набор,
компилирующий/метаданные-проверяющий всю конфу (`ИспользоватьДымовыеТесты() ПараметрыДымовыхТестов()
ИсключитьТест(...)`). рек.3-«смоук» = быстрый unit-прогон после правки, а НЕ этот встроенный ЮТДымовыеТесты.
