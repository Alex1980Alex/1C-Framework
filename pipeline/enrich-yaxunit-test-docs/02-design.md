# 02 — Дизайн: правки доков/скилла YAxUnit (correction-спек + enrichment-слоты)

> Основано на 01-architecture.md (gap-анализ). Два слоя: **(A) коррекции API** (100% ground truth,
> research-независимы) и **(B) обогащение** (из 3 research-агентов: GitHub/CI/coverage + официальные
> доки + Infostart-практики). A делается сразу; B фолдится по возврату агентов.

## Принципы

1. **Ground truth первичен**: каждый API-факт сверен с `src/bsl/exts/YAXUNIT/CommonModules/`.
   Research не может переопределить исходник — только добавить контекст (CI, сравнения, практики).
2. **Хирургические правки** (Edit по конкретным неверным местам), не переписывание файлов целиком.
   Сохранить структуру, тон, длину-бюджет скилла (BODY500 lint).
3. **Согласованность 3 файлов**: одинаковый корректный API в SKILL.md, 17.6, write-1c-unit-tests.md.
4. **Ядро рек.3 (код гейта) НЕ трогаем** — оно корректно. Трогаем только то, что агент читает,
   когда пишет смоук.

## Слой A — коррекции API (спека, дословно)

### A1. Мокито (все 3 файла) — заменить галлюцинацию на ground truth

НЕВЕРНО (текущее): `Мокито.Создать()` · `Мокито.Обучить(Мок,"М",Мокито.Параметры().Любой()).Вернуть()`
· `Мокито.Проверить(Мок).ВызванМетод(...).КоличествоРаз()` · `Мокито.Обучить(Модуль,"М")` (17.6).

ВЕРНО (эталон-блок для вставки):
```bsl
// 1. Обучение: подменить поведение метода ОБЪЕКТА/МОДУЛЯ (не «мок-объект»)
Мокито.Обучение(МодульИлиОбъект)
    .Когда("ИмяМетода", Мокито.МассивПараметров(Арг1))   // условие: метод + маска параметров
    .Вернуть(ПодменныйРезультат);                         // реакция: вернуть / ВыброситьИсключение(Текст) / Пропустить() / ВыполнитьМетод()
// 2. Перевести в режим прогона — ОБЯЗАТЕЛЬНО перед вызовом тестируемого кода
Мокито.Прогон();
// 3. ... вызвать тестируемый код ...
// 4. Проверить статистику вызовов
Мокито.Проверить(МодульИлиОбъект).КоличествоВызовов("ИмяМетода").Равно(1);
```
+ **Критическая нота (нет ни в одном доке):** мокнуть можно ТОЛЬКО метод, обёрнутый в расширении
`&Вместо("Метод")` + `МокитоПерехват.АнализВызова(...)`. Произвольный метод типовой без обвязки —
НЕЛЬЗЯ. Альтернатива изоляции: инъекция зависимости параметром вызывающего (Шаблон implement Э5.x) /
переопределяемые модули / `ЮТест.Данные()`. Маски: `Мокито.ЛюбойПараметр()/ЧисловойПараметр()/
СтроковыйПараметр()/ТипизированныйПараметр(Тип)`.

### A2. Исключения — `ОжидаетВыброс` НЕ существует

НЕВЕРНО: `ЮТест.ОжидаетВыброс("текст");` (SKILL 3.1/5, write-cmd 89/138/210).
ВЕРНО:
```bsl
// на значении-замыкании метода:
ЮТест.ОжидаетЧто(Объект, "Без прав — ошибка")
    .Метод("Записать", ЮТМетоды.МассивПараметров(РежимЗаписи.Запись))
    .ВыбрасываетИсключение();
// или через Мокито-обучение .ВыброситьИсключение(Текст) + прямой вызов в Попытке
```

### A3. Регистрация теста — 3-арг + нет `СКонтекстом`

- `ДобавитьСерверныйТест(Имя)` → `ДобавитьСерверныйТест(Имя, "человекочитаемое описание")`
  (реальные тесты всегда с описанием; 3-й арг `ТегиСтрокой` опционален).
- Удалить `ЮТТесты.ДобавитьСерверныйТестСКонтекстом(...)` (не существует) → параметризация через
  `ЮТест.Варианты(...)` + `ДобавитьТест(...).СПараметрами(...)` (слой B).

### A4. Несуществующие матчеры/хелперы

- SKILL «ЮТУтверждения — расширенные»: `ПроверитьТип/ПроверитьСвойство/ПроверитьСвойствоТип/
  ПроверитьКолонку` — **удалить** (не существуют). Заменить на реальные: `.ИмеетТип(...) /
  .ИмеетСвойство(...) / .Свойство("Имя").Равно(...) / .КаждыйЭлементСодержитСвойство(...)`.
- `.НеПуста()` → `.ИмеетДлинуБольше(0)` (или `.Заполнено()` для значения).
- `.ИмеетТип("Строка")` — оставить как есть, ДОБАВИТЬ ноту «принимает Строка|Тип|ОписаниеТипов»
  (обе формы валидны).

### A5. Дискавери — регистрация в подсистеме `Модульные` ОБЯЗАТЕЛЬНА

НЕВЕРНО: SKILL Фаза 4 «Автоматически, ничего делать не нужно»; write-cmd 263-273 «дискавери
подхватит автоматически»/`ЮТТесты.ДобавитьМодуль` (фантом); 17.6 §5 «имя ДОЛЖНО начинаться с ЮТТ».
ВЕРНО: тест-модуль надо ЗАРЕГИСТРИРОВАТЬ в подсистеме `ЮТТ_ЮТПодключаемыеМодули → Модульные`,
`<Content>` += `<xr:Item xsi:type="xr:MDObjectRef">CommonModule.<ИмяМодуля></xr:Item>`
(`Модульные.xml`). Имя модуля — ЛЮБОЕ (`гкс_…Тест` работает; ЮТТ — имя подсистемы, не модулей).
Через EDT: добавить модуль в состав подсистемы «Модульные». Без регистрации `run_all_tests` не видит.

### A6. Мелочи (🟢)

- 17.6 §4: убрать `.СПараметромОкружения(...)` и `.ВыполнитьНоваяПопытка()` (не существуют);

- 17.6 §3 БД: `.СодержитЗаписьСПолями(Структура)` → `.СодержитЗаписи(ЮТест.Предикат(Новый Структура(...)))`
  (+ `.СодержитЗаписиСКодом/СНаименованием/СНомером`).
- Платформа/ONEC_TEST_CONN: снять хардкод `8.3.27.1936` → «версия из установленной платформы»;
  ONEC_TEST_CONN — «значение из `.env` (File-база / серверная)».

## Слой B — обогащение (слоты; заполнить из research-агентов)

- **B1. `ЮТест.Пропустить(Сообщение)`** — штатный conditional-skip (вместо ручного
  `ОжидаетЧто(Истина).Равно(Истина);Возврат;` из реального теста). В SKILL + 17.6.
- **B2. Data-driven** `ЮТест.Варианты("а,б").Добавить(...)` + `ДобавитьТест(...).СПараметрами(...)`
  — полный пример (из research-агента §официальные доки).
- **B3. Теги + фильтрация** `.Тег(...)` / `ТегиСтрокой` + config.json `filter`.
- **B4. Lifecycle-события** (`ПередКаждымТестом`/`ПослеКаждогоТеста`/…) — как объявляются (research).
- **B5. БД-утверждения** `ОжидаетЧтоТаблицаБазы` — блок в SKILL (сейчас только в 17.6, с ошибкой).
- **B6. CI/раннеры** — vrunner/vanessa-runner + GitHub Actions/GitLab + Coverage41C (17.6 новая секция).
- **B7. Живые грабли** (Infostart): безопасный режим, /TESTMANAGER, изоляция — усилить 17.6 §7.
- **B8. Нота рек.3** — во всех: «смоук applicable при правке ЭКСПОРТНОГО серверного метода
  (`edits_exported_method`); маршрут `mcp-onec-test-runner run_module_tests/run_all_tests`; advisory».

## Верификация (Stage 4)

1. Пост-правка: grep галлюцинированных токенов в 3 файлах → 0 (кроме pipeline-артефактов).
2. Каждый исправленный вызов сверить с исходником (`ЮТест`/`ЮТУтверждения`/`ЮТТесты`/`Мокито`).
3. `lint_skills.py` на SKILL.md (BODY500/deadlinks) — не ухудшить.
4. code-verify (read-only ревьюер) — сверка правок vs ground truth.
5. Обновить CLAUDE.md-строку рек.3 (пункт «методика приведена к API») при необходимости.

## Решение по approve

Слой A — детерминированные фактические исправления (галлюцинированный API → реальный),
одобряю как автор (обоснование в 01/02). Слой B — аддитивен, риск-нейтрален (новые секции).
