# 01 — Планирование: resume крашнувшегося реиндекса ERP

## Проблема
Полный реиндекс `external/1c-reference-src/erp` (26207 .bsl → Qdrant `bsl_code_erp_ref`, qwen3-st 4096d) упал в 11:00:34 на ~8.5k файлов без `run_end`. Диагноз: CUDA OOM на RTX 3090 24GB — RSS стабилен (1.7GB), VRAM полз к потолку (24.2GB) = рост CUDA-кэша, не утечка Python. TEI-контейнер не запущен → контеншена не было.

## Цель
Дописать остаток без потери записанного (161k чанков, коллекция green) и без повторного эмбеддинга готовых файлов.

## Ограничения
- `--paths` режим читает argv → ~17k путей не влезут в командную строку Windows.
- Нужна перезапускаемость (возможен повторный OOM).
- Поведение при невыставленном флаге — побитово прежнее.

## Решение (выбор пользователя — вариант 2)
Idempotent resume через diff payload-ключей из самого store + митигация VRAM.
