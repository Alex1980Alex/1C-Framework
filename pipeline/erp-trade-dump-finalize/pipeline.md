# Pipeline: erp-trade-dump-finalize (trivial)

**Задача:** снять зависший `.git/index.lock` в корне фреймворка и дозакоммитить хвост
дампа эталонной конфигурации ERP в отдельном reference-репозитории.

Характер работы — операционный (git / housekeeping), правок исходного кода фреймворка нет.

## 1. План
- Проверить статус фонового агента `blmvz69pg` («ERP git-репо загрузился?») — в трекере отсутствует.
- Определить фактическое состояние на диске: каталог дампа, наличие активной выгрузки, lock-файлы.
- Закрыть два пункта: (1) снять мёртвый lock, (2) дозакоммитить незакоммиченный хвост дампа.

## 2. Дизайн
- `erp` и `trade` — **отдельные** git-репозитории (`external/1c-reference-src/{erp,trade}`),
  gitignored в корне (`.gitignore:159`), не сабмодули, у каждого свой `.git`, remote не задан.
- Операции выполнять **внутри их каталогов** (`git -C ...`), корневой репо не затрагивать.
- Lock снимать только при подтверждении: 0 байт, нет активных git-процессов, не пересоздаётся.
- Коммитить только при завершённой выгрузке (нет живого `DumpConfigToFiles`, каталог не пишется).
  Хвост должен быть аддитивным (без удалений файлов) — иначе это другой/неполный дамп, не коммитить.

## 3. Реализация
- Снят `C:/1С-Framework/.git/index.lock` (0 байт, от 18:47, владельца нет) — не вернулся, git разблокирован.
- Подтверждено завершение выгрузки: mtime каталога erp 19:25 (>1ч назад), живого процесса нет
  (`1cv8.exe` PID 4716 — это EDT-агент по другой ИБ, не дамп).
- Хвост дампа в `erp`: 88 новых разделов метаданных + 2 modified, 0 удалений → закоммичен
  (`2b4575868`, 971 файл). `trade` уже был чист (`9d769ac05`).

## 4. Тест
- `git status --porcelain` в обоих reference-репо → 0 (дерево чистое).
- Корневой репо: `git status` работает, lock отсутствует, рабочее состояние = исходное
  (`M .gitignore`, `?? scripts/dump_reference_config.ps1`).
- Память: записан факт о standalone-репозиториях ([[project-1c-reference-src-repos]]).
