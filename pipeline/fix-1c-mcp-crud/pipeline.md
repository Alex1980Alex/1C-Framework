# Пайплайн: fix-1c-mcp-crud

Восстановление MCP-сервера `1c-mcp-crud` + очистка диагностики из локальной истории.
База: ИБTransportManagementDevelop (УправлениеТранспортомНаПЛК), DESKTOP-TNU600C.

## 1. План
Исходный запрос — выдать `o.karankevich@sodru.com` административные права. По ходу выяснилось,
что MCP-сервер `1c-mcp-crud` в статусе **failed** (HTTP-сервис 1С отвечал `500` на все эндпоинты,
включая `/health`). Приоритет сместился на починку сервера. Задачу выдачи прав пользователь
впоследствии **снял** (зашли под учёткой с нужными правами).

## 2. Дизайн
Диагностика: авторизация проходит (пароль восстановлен пользователем), но сам HTTP-сервис падает →
причина на стороне 1С. Гипотеза: расширение `MCP_Сервер` присутствует, но его конфигурация
**не применена к БД** (правки в Конфигураторе без «Обновить конфигурацию БД»). Решение —
перезалить расширение из рабочей копии и выполнить обновление БД расширения; полную 19-инструментную
версию взять из дампа самой базы (копия в `external/1c_mcp/build` оказалась устаревшей, 2 инструмента).

## 3. Реализация
- Подключение через служебный Python-клиент сервиса 1С (MCP не был зарегистрирован в сессии).
- Учётка с правами конфигурирования: `a.terletskiy@sodru.com` (ПолныеПрава).
- `DumpCfg` (дамп текущего расширения 70 KB) → `LoadCfg` → `UpdateDBCfg -Extension MCP_Сервер`.
- HTTP-сервис ожил: `/health` = ok, `tools/list` = 19 инструментов.
- Выдача админ-прав `o.karankevich` — отменена по решению пользователя.
- Уборка: диагностический helper и временные файлы удалены из рабочего дерева и из неопубликованной
  локальной истории (filter-branch по `origin/master..HEAD`, surgical), `.tmp_onec/` внесён в `.gitignore`,
  backup-ветка `backup-before-purge` оставлена как страховка.

## 4. Тест
- 15 read/analysis инструментов прогнаны вживую — все работают (запрос, BSL, метаданные, формы,
  права, журнал, навигационные ссылки, поиск ссылок, поиск по метаданным, справка BSL).
- 4 write-инструмента (create/update/post/mark_for_deletion) доступны, намеренно не запускались
  (общая база).
- Очистка истории проверена: `diff backup-before-purge..HEAD` = удаление ровно 5 файлов, контент и
  изменения сабмодулей не затронуты; пароль отсутствует в неопубликованной истории.
