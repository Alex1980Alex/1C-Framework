# Организация не заполняется у эмулируемых Разнарядок

## Симптом

Прогон `гкс_ЭмуляцияОбменаCRM.epf` в другой базе, сценарий S5 («CRM убрала 1-ю строку,
но по ней была отгрузка»): заказ создан, **отгрузка не создана**.

```
Не удалось выполнить конвертацию в объект формата "Документ.РазнарядкаЭкспедиторов":
  ->КлючевыеСвойства
    ->Организация - не заполнено обязательное поле.
ПОД/ПКО: Документ_РазнарядкаЭкспедиторов_Отправка
Объект: Разнарядка экспедиторов 0000-00001 от 01.07.2027
```

## Корень

`СоздатьОтгрузку` создавала Разнарядку экспедитора, заполняя **только Дата и Комментарий**:

```bsl
РазнарядкаЭкспедитора = Документы.гкс_РазнарядкаЭкспедитора.СоздатьДокумент();
РазнарядкаЭкспедитора.Дата = ДатаОтгрузки;
РазнарядкаЭкспедитора.Комментарий = КомментарийЦепочки(Сценарий.Имя);
РазнарядкаЭкспедитора.Записать(РежимЗаписиДокумента.Запись);
```

Организация не заполнялась никогда — и это было сделано **осознанно**: комментарий на
строке 447 прямо говорит «Разнарядки достаточно ЗАПИСАТЬ: запрос читает их табличные
части, проведение им не нужно». Разнарядка нужна была лишь звеном для соединения по паре
(РазнарядкаНаОтгрузку, РазнарядкаЭкспедиторов), поэтому её собрали минимально.

У документа `гкс_РазнарядкаЭкспедитора` реквизит `Организация` **есть** (первый в .mdo).

## Почему прошло молча

`Записать(РежимЗаписиДокумента.Запись)` **не вызывает `ПроверитьЗаполнение()`** — проверка
отрабатывает при интерактивной записи и при проведении. Заведомо неполный документ
записался без возражений.

## Почему ломается только в другой базе

Там **включён обмен EnterpriseData (Отправка)**. Запись Разнарядки регистрирует её на узле
обмена → конвертация в формат `Документ.РазнарядкаЭкспедиторов` через ПКО
`Документ_РазнарядкаЭкспедиторов_Отправка` → формат требует `КлючевыеСвойства.Организация`
→ пусто → ошибка.

В исходной базе узла обмена нет, конвертировать документ никто не пытался, и дыра
оставалась невидимой. **База ни при чём** — она впервые предъявила к документу требования
бизнес-объекта, а не «звена для запроса». Косвенное подтверждение: номер в ошибке
`0000-00001` — первая Разнарядка в базе.

## Второе звено (тот же дефект, ещё не выстреливший)

`гкс_РазнарядкаНаОтгрузку` создавалась **ровно так же минимально**, и Организация у неё
тоже есть (плюс отдельная `ОрганизацияПродавец`). Если её ПКО в обмене — упала бы следующей.

## Источник значения

`Сценарий.Заказ` имеет тип `ДокументСсылка.гкс_ЗаявкаНаОтгрузку` (строка 38), Организация у
него есть — именно из неё эмуляция строит `OurCompany` для CRM-сообщения (строки 156, 733).
Читаем через БСП `ОбщегоНазначения.ЗначениеРеквизитаОбъекта` — модуль уже так делает (175).

## Класс дефекта

«Минимальный объект, валидный для своего запроса, но невалидный как бизнес-объект». Любая
база с активным обменом его отвергнет. Родственно [[reference-cadence-dry-run-silent-noop]]:
путь отрабатывает без ошибки и не делает того, что от него ждут.

## Открытый вопрос

Ошибка перечислила только Организацию, но конвертация могла остановиться на первом
незаполненном обязательном поле формата. Следующее поле выявится только прогоном в базе
с обменом — у меня такой базы нет.
