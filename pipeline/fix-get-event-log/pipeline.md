# Пайплайн: фикс get_event_log в MCP-расширении ERP

**Slug:** fix-get-event-log · **Тип:** trivial (один обработчик, 2-строчный фикс) · **Дата:** 2026-06-19

## 1. Планирование

**Задача:** инструмент `get_event_log` профиля `1c-mcp-crud-erp` всегда возвращает `success:true, data:[], count:0`, хотя в журнале регистрации ERP-базы есть события (подтверждено `execute_code` → 145 588 записей в окне).

**Граница:** баг на стороне 1С (Python-прокси `external/1c_mcp` — чистый JSON-RPC форвардер, логики инструментов нет). Источник задеплоенной сборки — бинарь `C:\Users\Tech. Boutique\Documents\MCP_Сервер.cfe` (в репо отсутствует; репо/submodule = старая 3-обработковая версия).

## 2. Дизайн

**Корень (по выгруженному из .cfe BSL):** обработка `mcp_ИнструментАдминистрирование`, функция `ПолучитьЖурналРегистрации`:
- **B (главный):** в цикле сбора строк отсутствует `Записи.Добавить(Запись);` → результирующий массив всегда пуст → `count:0` при любом отборе.
- **A (вторичный):** `Лимит` передан 5-м позиционным параметром `ВыгрузитьЖурналРегистрации` вместо корректной позиции.

**Способ правки без EDT:** `onec_dtools` для инспекции контейнера; сборка через `1cv8 DESIGNER` (scratch-ИБ → LoadCfg orig → DumpConfigToFiles → патч .bsl → LoadConfigFromFiles → DumpCfg fixed.cfe). **Деплой:** `DESIGNER /S DESKTOP-TNU600C\Enterprise20_2_5_27_52 /N Admin /P "" /LoadCfg fixed.cfe -Extension MCP_Сервер` + `/UpdateDBCfg -Extension`.

## 3. Реализация

- Пропатчен `ПолучитьЖурналРегистрации`: добавлена `Записи.Добавить(Запись);`, `Лимит` → 3-й параметр.
- Собран `MCP_Сервер_FIXED.cfe` (71 461 б). Верификация распаковкой: обе правки внутри, контейнер валиден.
- Применено в живую ERP-базу: `LoadCfg` (exit 0) + `UpdateDBCfg -Extension` (exit 0).
