# Правка вне репозитория не является «правкой кода» (pipeline-protocol)

## Проблема (наблюдена живьём 2026-07-26)

Сессия чистой верификации LLM Rotation: правок в репозитории **ноль** (`git status` пуст), единственные `Write` — записи памяти в `C:\Users\...\.claude\projects\...\memory\`, то есть **вне корня проекта**. `pipeline-protocol` заблокировал завершение с «правки кода без пайплайна».

Механика: `_session_writes_and_start` считает правкой canonical Pre-запись `Write`/`Edit` из `hook-invocations.jsonl`. Git-fallback молчал (дерево чистое) — сработала ветка hook-лога.

## Почему это надо чинить, а не терпеть

Сохранение памяти — **обязательная часть протокола** (capture-петля 1С-гейта, `feedback-proactive-memory-save`). Добросовестное исполнение одного правила штатно нарушает другое: любая исследовательская сессия с записью выводов упирается в блок и вынуждает заводить пайплайн-пустышку. Это обесценивает артефакты ровно так, как гейт и призван предотвращать.

## Ключевое ограничение, найденное при разборе (опровергает исходный план)

Вчерашняя формулировка лечения — «фильтровать по `Path.is_relative_to(repo_root)` в предикате» — **неосуществима**: в записи лога **пути нет**. Логгер намеренно хеширует аргументы (`_args_fingerprint`: «хешируем, НЕ логируем сырьё (пути/секреты не утекают)»), `args_hash` необратим, а в наблюдённых записях ещё и пуст.

Отсюда развилка:

| вариант | вердикт |
|---|---|
| A. Писать путь в лог | **Нет.** Ломает осознанный контракт приватности ради одного предиката |
| B. Считать «git чист ⇒ правок не было» | **Нет, опасно.** `auto-git-save` коммитит по ходу сессии → дерево чисто и при реальных правках кода. Гейт бы ослаб |
| C. Один бит `in_repo` в canonical-записи | **Да.** Не раскрывает ни имени, ни каталога; потребитель получает ровно то, что нужно для решения |

## Границы

- Бит вычисляется только там, где у вызова есть файловая цель (`file_path`/`notebook_path`); у `Bash`/`Read` ключа не будет вовсе — не null-шум (паттерн `duration_ms`).
- **Fail-closed:** отсутствие ключа (старые записи, чужой логгер, ошибка резолва) ⇒ считаем правкой, как раньше. Пробел в телеметрии не должен ослаблять гейт.
- Запись вне репо **не расходует** парную block-запись (вычет `blocked`, N-P4.3) — это независимые причины «правки не было».
