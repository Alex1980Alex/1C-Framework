# fix-zai-guard-test-isolation — компактный пайплайн (trivial, 2 файла)

## 1. План / верификация находки

По запросу пользователя проверены 4 утверждения о правке z-ai-write-guard (из другой сессии): (1) `"pipeline/"` в `_EXEMPT_PREFIXES` снимал гард с infra/pipeline/**/*.py — **подтверждено историей**: добавлен в `0d85a3db2`, удалён в `0e11398f7` (тот же цикл после FAIL ревьюера); blast radius — **133** tracked .py (не «~800»); (2) для ADR-018-артефактов запись недостижима (`.md` уходит в `_SKIP_EXTENSIONS` раньше) — подтверждено, задокументировано NB в коде; (3) «тесты скипаются в CI (.venv-путь)» — **уже исправлено** в `0e11398f7`: `sys.executable` + `pytest.mark.unit`; (4) «тот же класс дефекта» — да, и в исправленных тестах остался residual.

## 2. Дизайн / residual-находка моей проверки

Изоляция тестов была **фикцией**: экспортировалась `CLAUDE_SESSION_STATE_PATH` (не читает никто; реальная — `SESSION_STATE_PATH`, и ждёт КАТАЛОГ, а тест передавал файл) + мёртвый для этого хука `CLAUDE_CACHE_DIR`. Решающий эксперимент: probe с `SESSION_STATE_PATH=tmp(+делегирование)` → ALLOW; с тестовой переменной → BLOCK (хук читал живой state). Зелёность тестов держалась на случайном отсутствии `llm_delegation_count` в живой сессии — один реальный `llm_complete` красил бы позитивные ассерты.

## 3. Реализация

`_blocked()`: env → `SESSION_STATE_PATH: str(tmp_path)` (каталог), мёртвые переменные убраны, докстринг переписан честно (+ зафиксирован принятый residual: `is_provider_down` читает живой `data/llm-rotation-*.jsonl`, env-override нет). Новый пин `test_session_isolation_actually_isolates` (state с `llm_delegation_count=1` в tmp → гард обязан ПРОПУСТИТЬ; красный на версии с мёртвой переменной — доказано экспериментом). Хук: только докстринг-дрейф flow-шага 4 (перечислял `pipeline/` в exempt — противоречил NB).
