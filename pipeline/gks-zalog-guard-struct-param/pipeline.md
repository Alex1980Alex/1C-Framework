# Pipeline: gks-zalog-guard-struct-param

Задача: перевести `НайтиПротоколНаПериод` (РС `гкс_ЗалоговыеЦены`) с 5 позиционных параметров на один структурный `ПараметрыПоиска`.
Источник: задача из чата. Тип: refactor (behavior-preserving). Сложность: medium (2 файла, 1 вызов).

## 1. Анализ / Планирование
- Функция-guard принимала `(ТочкаМаршрута, Номенклатура, ВидЗалоговойЦены, НаДату, ТекущийРегистратор)`.
- Единственный вызов — `Documents/гкс_УстановкаЗалоговыхЦен/ObjectModule.ПроверитьЕдинственностьПротоколаЗаМесяц`.

## 2. Дизайн (approved)
- Сигнатура → `НайтиПротоколНаПериод(ПараметрыПоиска)`; поля читаются как `ПараметрыПоиска.<Поле>`.
- Имена полей структуры = прежние имена параметров (побуквенно) → отображение значений 1:1.
- Вызывающий собирает `Новый Структура` + `Вставить` 5 полей; структура строится внутри цикла (свежий экземпляр на итерацию).

## 3. Реализация
- `ManagerModule.bsl`: сигнатура `(ПараметрыПоиска)`, doc-комментарий описывает структуру, 5× `УстановитьПараметр` читают `ПараметрыПоиска.<Поле>`; текст запроса не тронут.
- `ObjectModule.bsl`: перед вызовом строится `ПараметрыПоиска` (ТочкаМаршрута, Номенклатура=СтрокаТоваров.Номенклатура, ВидЗалоговойЦены, НаДату=Дата, ТекущийРегистратор=Ссылка), вызов `(ПараметрыПоиска)`.

## 4. Тестирование / Верификация
- code-verify (behavior-preservation) — **PASS**: имена полей при записи/чтении идентичны, 5 значений отображены 1:1 со старым позиционным вызовом, запрос/параметры/возврат неизменны, окружающая логика сохранена.
- Grep: ровно 1 определение + 1 вызов (новой формы), осиротевших старых вызовов нет.
- Применение в рабочей ИБ: «Обновить конфигурацию БД».
