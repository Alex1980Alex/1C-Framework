### Доработка 2026-07-16: пошаговый режим

Причина: оба прихода выполнялись одним кликом, промежуточное состояние (заказ после ПЕРВОГО прихода)
посмотреть было негде.

- Колонки `Пометка` (Булево), `Факт1` (результат шага 1), `Состояние` (пусто / «шаг 1 сделан» / «шаг 2 сделан»).
- Две кнопки: **«Шаг 1: создать заказ»** и **«Шаг 2: ре-обмен и проверка»**. Работают только по помеченным строкам.
- `Ожидание` проверяется ТОЛЬКО на шаге 2 (на первом приходе нумерация тривиальна - по порядку строк CRM).
- Гейт: шаг 2 без шага 1 -> строка пропускается с предупреждением, новый заказ молча НЕ создаётся.
- Модуль объекта: `ВыполнитьСценарии` разбита на `ВыполнитьШаг1` / `ВыполнитьШаг2` + общая `ВыполнитьШаг`.
  CRMID заказа отдельно не хранится - это `Заказ.УникальныйИдентификатор()`.

### Почему цепочка обязательна, а не декоративна

`ИндЗаказа` попадает в движение **не из заказа**, а из `гкс_РазнарядкаНаОтгрузку.Состав` — соединением
по паре (`ТД.РазнарядкаНаОтгрузку`, `ТД.РазнарядкаЭкспедиторов`). Движения пишет только ТД с
`ВидОтправкиЖД = ДоставкаПромышленныхГрузов`. Обе детали — `гкс_ТранспортныйДокумент/ManagerModule.bsl`,
`ТекстЗапросагкс_ЛогистическийПотокДоставкаКлиентам` (стр. 1111-1225). Разнарядки достаточно **записать**:
запрос читает их табличные части.

Контекст базы: клиентской отгрузки в 260507 **не было ни разу** — все 12 проведённых ТД за 2022-2023
пишут в `гкс_ЛогистическийПотокДоставкаНаПЛК` (440 записей), это входящая доставка на ПЛК.

## Найденные дефекты правила (исправлены 2026-07-16)

1. **`ИМЕЮЩИЕ` было холостым.** ТД пишет `ФактТС = 1` **константой** (там же, стр. 1204), поэтому ветка
   `СУММА(ФактТС) <> 0` истинна для любого движения ТД. Код заявлял «план фактом не считаем», а считал.
   Доказано live: ТД без `ДатаПогрузки` (`ФактПеревозки` = 0, `ПланПеревозки` = 25.75, `ФактТС` = 1) —
   номер удержан, новым строкам роздано 3,4,5 вместо 2,3,4.
   Условие убрано, `НомераСФактомОтгрузки` → `НомераЗанятыеТранспортнымиДокументами`, комментарий исправлен.
   Поведение НЕ изменилось (оно и было «любой ТД») — изменилось то, что код теперь говорит правду.
   Обоснование удержания при нулевом факте: эталон `гкс_РазнарядкаНаОтгрузку/ManagerModule.bsl:395`
   связывает движение со строкой по `ИндЗаказа` — отданный номер перецепил бы старое движение на новую строку.
2. **Чтение без привилегированного режима.** Соседняя `ДанныеИдентификаторовСтрокЗаказов` его ставит, но
   режим снимается при выходе из процедуры (Руководство разработчика 8.3). Пользователь без прав не увидел бы
   чужую отгрузку и отдал её номер. Добавлен. Прецедент того же класса — GKSTCPLK-2656.
