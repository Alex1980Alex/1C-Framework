# Расширение 1С-детектора (recall) — Планирование

## Запрос пользователя
Расширить 1С-детектор (`classify_1c_task`), чтобы хук ловил больше формулировок 1С-задач из чата.
Правило (подтверждено): **решение «это 1С» — за Claude**; **сомнение → спросить**. Задачи 1С живут в
`C:\1С-Framework\configuration` — использовать для доп. анализа перед доработкой.

## Проблема (ревьюер прошлого среза)
`classify_1c_task._1C_SIGNAL` требует точку-нотацию (`Документ.`) / `гкс_` / узкий набор → фраза вроде
«доработать форму документа Расход» (косвенный падеж, без точки) НЕ ловится → хук молчит (recall-gap).

## Доп. анализ (заземление на configuration/, как просил пользователь)
`configuration/260304_GKSTCPLK-2182…/docs/` — ~35 РЕАЛЬНЫХ 1С-задач. Живой словарь из заголовков:
- **Глаголы:** Доработать, Восстановить, Описать, Исправить, Скорректировать, Разработать, Настроить,
  Создать, Добавить, Убрать, Устранить, Дополнить, Вернуть, Реализовать, Провести, Отобразить.
- **Термины:** Направление (документ), справочник, движения запасов, **АРМ**, **РС/РН/РМ**, печатная форма,
  механизм, обмен, Отчёт, профили доступа, обработка, документ, предопределённые элементы, вид допуска,
  «на форме», CamelCase-кириллица (РегистрацияНаПЛК, ОснованиеДляДвиженияЗапасов).
- **Сильный проектный маркер:** `гкс_`-префикс + путь `configuration/`.

Вывод: расширять надо И глаголы (`_TASK_VERB`), И термины (`_1C_SIGNAL`) — на реальном словаре, не гадая.

## Объём
`pipeline_1c_bridge.py` (`_TASK_VERB` + `_1C_SIGNAL` + `_1C_STRONG` += configuration-path) + тесты +
CLAUDE.md + память. Веса/маршрут (прошлый срез) не трогаю.
