# Расширение 1С-детектора (recall) — Кодирование

Реализовано в `pipeline_1c_bridge.py` (обратимо):

1. **`_TASK_VERB`** += восстанов, опис, коррект, разработ, убра, устран, дополн, сформир, отобра, вернут, удал, оптимизир, перенес, внедр (живой словарь configuration/.../docs).
2. **`_1C_DEFINITIVE`** (новый): `гкс_|[Cc]onfiguration[/\\]` — 1С даже БЕЗ таск-глагола.
3. **`_1C_SIGNAL`** расширен (+ \b-границы против substring-FP): печатн, \bформ[аеуы], \bдокумент, справочник, \bрегистр, обработк, \bотч[её]т, перечислени, \bконстант, макет, движени, табличн, подсистем, профил, механизм, \bобмен, предопредел, \bАРМ, \bРМ\b, \bРС\b, \bРН\b, план обмена/видов, бизнес-процесс, вид допуска, функционал, configuration-path.
4. **`_1C_STRONG`** += `[Cc]onfiguration[/\\]`, План\w*, БизнесПроцесс (CamelCase-кириллица уже была).
5. **`is_1c`** — двухуровнево: `JIRA OR _1C_DEFINITIVE OR ((_1C_SIGNAL OR _1C_STRONG) AND _TASK_VERB)`.
   CamelCase в `_1C_STRONG` (re.U, БЕЗ re.I — иначе hump-класс матчил бы любые 3 кириллицы).

**Безопасность:** term+verb без сильного маркера → `confident_1c=False` → route `ask_1c` (не авто-маршрут).
Recall↑, ложные → деградируют в вопрос (правило «сомнение→спросить»). Сильный маркер → confident → маршрут по сложности.

definitive без глагола; CamelCase-объект+глагол; не-1С-негатив вкл. «что такое ТабличныйДокумент»→False [нет глагола]).
