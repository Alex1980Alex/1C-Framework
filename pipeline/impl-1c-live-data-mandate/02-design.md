# 02 Дизайн

1. **Анализ:** Фаза 2.5 Runtime Trace - default-ON для задач с исполняемым BSL-кодом; `--trace` = форс,
   `--no-trace` = opt-out; SKIP только по 3 причинам (opt-out / нет кода / debug env down) с фиксацией в §10;
   критерий «≥3 ветвлений» переосмыслен как глубина step-трассировки. Правило 7: обязательная глава §10
   «Проверка на реальных данных» (база / таблица данных / сценарий / инструменты / результаты-вердикты;
   SKIP-вариант с [STATIC-ASSUMPTION]).
2. **Реализация/тестирование:** Этап 5.x - trigger на реальных данных (execute_query-кандидаты, параметры
   функциями вызывающего - Шаблон 7); Этап 6 - тест-план на реальных данных, идентификаторы фиксируются;
   Этап 7 - обязательная глава «Тестирование на реальных данных»; чеклист-пункт.
3. **Enforcement - advisory** через существующий lint_1c_artifacts (+2 core-секции, lenient regex вкл.
   «живых данных» и [STATIC-ASSUMPTION]); hard-гейт НЕ вводится (задачи без live-сценария; эскалация позже -
   паттерн ADR-035 Фазы 2). Пороги не ломают старые артефакты (8/9=89%, 5/6=83% ≥ 70%).
4. Доки: 43.1 (сквозной инвариант), 43.2 (обе команды); /run-1c-task наследует делегированием.

Отклонено: hard-Stop-гейт (дедлок-риск), отдельный файл-отчёт (глава дешевле), оставить opt-in (мандат).
Дизайн одобрен (auto): проведение прямого мандата пользователя, blast-radius - методики/доки/advisory-линт.
