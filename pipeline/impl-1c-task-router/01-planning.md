# Классификатор сложности + маршрутизация 1С-задачи — Планирование

## Запрос пользователя
При 1С-задаче из чата я должен сам: (1) понять 1С/не-1С (сомнение → спросить); (2) по классификатору
сложности (простая/средняя/сложная **через оценку трудозатрат**) выбрать поток — `/run-1c-task` (AUTO)
или гейтованный `/analyze`+`/implement`; сомнение в потоке → спросить.

## Решение маршрута (AskUserQuestion 2026-06-15)
**простая→AUTO, средняя→спросить, сложная→гейт.** Всегда: не-1С/сомнение-в-1С → спросить; сомнение-в-потоке → спросить.

## Что есть
- `classify_1c_task(prompt)` → `{is_1c, jira, ttype(T1/T2/T3), ask}` (V.6, есть).
- `onec-task-input.py` (UPS) — инъектит V.6-протокол при 1С-задаче из чата.
- `task-protocol` авто-классификатор trivial/medium/complex — **по числу файлов** (другой классификатор, для общего протокола; НЕ оценка трудозатрат 1С-задачи).

## Чего нет
- **Оценки трудозатрат 1С-задачи** (простая/средняя/сложная по содержанию ТЗ).
- **Маршрутизации по сложности** (какой поток запускать).

## Объём
2 функции в `pipeline_1c_bridge.py` (`estimate_effort` + `route_1c_task`) + правка `onec-task-input.py`
(сурфейсить маршрут) + тесты. Веса/пороги — config (тюнятся без правки кода, паттерн `a2_signals`).
