# 01 — Архитектура: P1 роадмапа 260716 (устойчивость оркестратора и каденса)

## Задача

Второй срез [260716](../../docs/roadmap/260716_ROADMAP_MEMORY_PAYLOAD_HARDENING.md).
P0 закрыл инцидент «одна битая точка валит инструмент» (коэрсер + толерантный read +
3 писателя + миграция). P1 закрывает то, что осталось: **потери и искажения на путях,
которые НЕ падают, а тихо врут** — теряют поля при merge, дилюируют скор пустыми
плечами, подменяют причину ошибки, расходятся в политике фильтрации между двумя
читателями одной коллекции.

Общая нить P0 и P1 одна: **никакой слой не должен молча деградировать**. P0 — про
вход (payload). P1 — про выход (результат, счётчик, причина, поле).

### M6 — находка: диагноз роадмапа неверен

Роадмап: «легаси TEXT-importance молча **выпадает** из `get_important_messages`
(SQLite type ordering: `TEXT >= 0.5` = false)».

Проверено на sqlite3 напрямую:

```
stored: ('a', 'high', 'text')      WHERE importance >= 0.5 -> MATCH
stored: ('b', 0.9,   'real')       WHERE importance >= 0.5 -> MATCH
ORDER BY importance DESC:  'критично' > 'high' > 0.9 > 0.8
```

В SQLite порядок классов хранения `NULL < REAL/INTEGER < TEXT < BLOB`, поэтому
TEXT **всегда больше** любого числа. Реальный дефект **противоположен** описанному:
легаси TEXT-importance не выпадает, а (а) проходит фильтр `>= min_importance`
**всегда**, независимо от смысла, и (б) в `ORDER BY importance DESC` встаёт **выше
любой** числовой — `'low'` обгоняет `0.99`. Это не «тихая потеря», а «тихий захват
топа». Живых TEXT-строк нет (0/154) → дефект латентный, но чинить надо в правильную
сторону.

## Инварианты (не нарушать)

1. **Изоляция ПЛЕЧА ≠ изоляция ТОЧКИ** (P0, F12). Инфра легла (TEI/Qdrant/breaker) →
   плечо в `sources_failed`. Одна нечитаемая точка → skip точки, плечо живо.
   P1 добавляет третий случай — **плечо отключено breaker'ом** — он относится к
   первому классу (честный `sources_failed`, не тихий ноль).
2. **`save_pattern` остаётся строгим** (fail-closed). P1 не «коэрсит везде».
3. **Дедуп никогда не рвёт ссылочную целостность.** Удаление точки, на которую
   есть рёбра, без re-point — запрещено. Канон, назначенный `cross_store_sync`,
   старше эвристики `pick_survivor`.
4. **Merge не теряет полей.** Каденс-джоб, перезаписывающий силос, обязан вернуть
   на диск всё, что прочитал, — включая то, чего его схема не знает.
5. Всё MCP-side → эффект только после `/mcp reconnect` ([[feedback-mcp-stale-code-reconnect]]).

## Ключевые архитектурные решения

**A1. P1.4 — общее ядро, не «подкрутить фильтр».** Роадмап допускает оба варианта.
Беру экспорт функции: два читателя одной коллекции с разной политикой — это и есть
корень M4, а не симптом. Косметическая правка фильтра оставит дубль, который разойдётся
снова.

**A2. P1.9 — seed выводится из prior, а не хардкодится.** `LEGACY_SEED_CONFIDENCE =
PRIOR_SUCCESS / (PRIOR_SUCCESS + PRIOR_FAILURE)`. Тогда «сев от дефолта не двигает
confidence» — свойство конструкции, а не совпадение чисел. Параметр
`default_confidence` удаляется: он существовал ровно из-за расщепления.

**A3. P1.3 — breaker проверяется ДО создания корутины** (`allow_request()`), не через
`call_async`. Иначе `wait_for(adapter.search(...))` закрывается непроверенным и
внутренняя корутина остаётся un-awaited (RuntimeWarning).

**A4. P1.7 — тул чинится, `--apply` на проде не запускается** в этом срезе. Задача P1 —
снять запрет, а не выполнить дедуп. Запуск — отдельное решение с бэкапом.

## Не-цели среза

- Запуск `dedupe --apply` на живой коллекции (A4).
- Разовая миграция колонки `importance` — мигрировать нечего (0 строк).
- LOW-хвост §3.3 — по мере касания.
