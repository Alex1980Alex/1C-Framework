# Пайплайн (trivial): Загрузка `mfm test.dt` в серверную ИБ

Операционная задача (администрирование сервера 1С), не правка кода проекта. Компактный trivial-формат по ADR-018.

## 1. План
Загрузить дамп `mfm test.dt` из Загрузки в серверную ИБ `Srvr="DESKTOP-TNU600C";Ref="260507_DEV_ATERLETSKIY_53196"`. «Загрузить дт» = `1cv8 DESIGNER /RestoreIB` (полная замена ИБ — данные + конфигурация).

## 2. Дизайн
- Версия Конфигуратора = версии активного кластера (`8.3.27.1936` x86, x64 2214 остановлена).
- Аутентификация `/N /P` (OS-аутентификация не проходит). Креды dev-баз: `a.terletskiy@sodru.com` / `Alex80Alex` (`.env`, `vrunner.json`).
- Монопольный доступ: запрет сеансов/регламентных через `rac`; зависшие фоновые задания снять рестартом службы (terminate/disconnect не берут).

## 3. Реализация
1. Файл найден: `…\Downloads\mfm test.dt` (172 МБ).
2. Поднят `ras` (1545); определён кластер `fb88a5c5…`, ИБ `07376da7…`.
3. `rac infobase update … --sessions-deny=on --scheduled-jobs-deny=on`; `session terminate`/`connection disconnect` не сняли зависшие фоновые задания.
4. Перезапуск службы «Агент сервера 1С:Предприятия 8.3» (через elevation/UAC) → ИБ освобождена.
5. `--sessions-deny=off` (пустить Конфигуратор), `--scheduled-jobs-deny=on` оставлен; запущен `/RestoreIB`.

## 4. Тест (верификация)
- Лог Конфигуратора: **«Загрузка информационной базы успешно завершена»** — успех.
- `rac session list` целевой ИБ = 0 сеансов на момент загрузки.
- Постусловие: восстановленная база `mfm test` несёт свой список пользователей → старые админ-креды к ней не подходят; снять `scheduled-jobs-deny` без админа новой базы нельзя. По решению пользователя регламентные задания оставлены отключёнными.
