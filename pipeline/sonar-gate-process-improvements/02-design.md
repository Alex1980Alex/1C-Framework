# 02 — Дизайн: 6 улучшений (одобрены пользователем «всё разом», 2026-07-03)

1. **verify независим от server-baseline**: `sonar_rescan_verify.py` гейтит BLOCKER/CRITICAL по
   пересечению issue-строк с `git diff -w -U0 HEAD` изменённых файлов (mode=changed-lines);
   вырожденный baseline (new≈total) детектится и репортится, но не гейтит.
2. **Починить new-code period на сервере**. План: NUMBER_OF_DAYS=30.
   **Отклонение (обоснованное):** проект впервые просканирован 2026-07-01 → 30-дневное окно ещё
   месяц считало бы весь легаси новым. Применено: branch-level `SPECIFIC_ANALYSIS` на пре-change
   анализ `8877ef63` (2026-07-02T21:39) — честный CaYC-baseline для легаси. Ключевое знание:
   SPECIFIC_ANALYSIS принимается ТОЛЬКО с `branch=`; project-level set → тихий 200 без эффекта.
3. **Обуздать bsl-format**: `_selective_format` — формат применяется только к строкам, изменённым
   vs HEAD (построчный difflib-мердж), EOL-стиль исходника сохраняется; `.gitattributes`
   (`*.bsl/xml/mdo text eol=crlf`, `* -text`) в сабмодуле SVETLY (index уже LF → без ренормализации).
4. **Правило батч-правок .bsl** одним вызовом/скриптом — в SKILL implement-1c-task (Этап 3) + память.
5. **Док-комментарии сразу** при добавлении методов — SKILL Этап 3 + чеклист завершения.
6. **Норма «один скан»**: все правки → формат → bsl_lint локально → один скан → один verify —
   SKILL шапка (Sonar-нота) + чеклист.

Бонус вне плана: fix `gate_policy._LOG_PATH` (абсолютный якорь от корня — мусор в сабмодулях),
per-file issues-запросы в verify (кириллический 500 починен в SQ CB 26.x → нет ES-усечения 10k).
