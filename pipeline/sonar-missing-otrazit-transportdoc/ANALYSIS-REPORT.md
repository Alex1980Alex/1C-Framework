# ANALYSIS-REPORT — Sonar BLOCKER: ОтразитьТранспортныйДокумент отсутствует

**Источник:** SonarQube BLOCKER `MissingCommonModuleMethod` (профиль «1C BSL Way»).
**Кластер (child-pipeline `sonar-missing-otrazit-transportdoc`):** один реальный баг.
**Через паттерн** `/fix-sonar-task` (ADR-033) → этап Планирование+Дизайн.

## 1. Задача (суть дефекта)
В форме документа `гкс_ТранспортныйДокумент.ФормаДокумента` (L77) вызывается
`гкс_ПриемкаНаПЛКСервер.ОтразитьТранспортныйДокумент(РегистрацияНаПЛК, Объект.Ссылка)`,
но метода `ОтразитьТранспортныйДокумент` **в общем модуле `гкс_ПриемкаНаПЛКСервер` нет** →
при выполнении ветки будет ошибка «Метод объекта не обнаружен».

Контекст вызова (L74-78):
```
РегистрацияНаПЛК = Документы.гкс_РегистрацияНаПЛК.РегистрацияНаПЛКПоПараметрам(ПараметрыПоиска);
Если ЗначениеЗаполнено(РегистрацияНаПЛК) Тогда
    гкс_ПриемкаНаПЛКСервер.ОтразитьТранспортныйДокумент(РегистрацияНаПЛК, Объект.Ссылка);
КонецЕсли;
```

## 3. Анализ механизма — доказательства корня
- **Метод отсутствует:** среди 27 экспортных/локальных методов `гкс_ПриемкаНаПЛКСервер` нет `ОтразитьТранспортныйДокумент`.
- **Не rename:** `git log -S ОтразитьТранспортныйДокумент -- <module>` → символ **никогда не присутствовал** в модуле (не переименование).
- **`ОтразитьДвижения` — НЕ цель:** единственный `Отраз*`-метод = `ОтразитьДвижения(ТаблицыДляДвижений, Движения, Отказ)` — generic-хелпер записи движений (3 параметра, вызывается как `гкс_ПроведениеДокументов.ОтразитьДвижения(...)` в 6+ местах). Семантика и арность **другие** (2 ссылки vs 3 параметра движений) → подмена была бы новым багом.
- **Нет кандидата под другим именем:** ни один из 27 методов не принимает `(РегистрацияНаПЛК, ТранспортныйДокумент)` и не «отражает транспортный документ» (методы про движения/регистрации/веса/роли/печать).
- **Вызов единственный и осмысленный:** `ОтразитьТранспортныйДокумент` встречается в конфигурации **только в этой форме**; вызов стоит внутри намеренной ветки (нашли РегистрациюНаПЛК → отразить транспортный документ против неё) → это **незаконченная фича**, а не очевидно мёртвый код.

## 4. Корень
**Реальный недостающий метод** (категория: real, не FP / не rename / не явная мёртвая ветка).
Разработчик написал вызов в расчёте на метод, который **не реализован** в `гкс_ПриемкаНаПЛКСервер`.

## 5. Доменный вопрос (approve-гейт G4 — нужно решение)
Что должен делать `ОтразитьТранспортныйДокумент(РегистрацияНаПЛК, ТранспортныйДокумент)`?
Это **бизнес-логика**, её нельзя выдумывать. Варианты:

- **(A) Реализовать метод** — если фича нужна. Требуется спецификация «отразить»: создать движения/связь
  «РегистрацияНаПЛК ↔ ТранспортныйДокумент», записать состояние регистрации, или что-то ещё? (тогда — какой
  регистр/реквизит/состояние).
- **(B) Удалить вызов** (L76-78) — если фича отменена/мертва. Риск: молча теряется задуманное поведение.
- **(C) Это другой существующий метод** — если разработчик ошибся именем (среди 27 кандидата под 2-арг.
  сигнатуру нет → маловероятно).

## 6. Рекомендация
Склоняюсь к **(A)** — окружающий код намеренный (поиск РегистрацииНаПЛК → условное отражение). Но без
описания «что значит отразить транспортный документ против регистрации» реализация = выдумывание бизнес-логики.
**Нужно подтверждение домена** (заказчик/аналитик): вариант + для (A) — целевой эффект (движения/состояние/связь).
