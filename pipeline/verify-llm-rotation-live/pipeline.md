# verify-llm-rotation-live

Задача: живая верификация LLM Rotation после `/mcp reconnect` (2026-07-26). Правок кода нет — только прогон и записи памяти.

## Что проверено (реальные вызовы, не синтетика)

| проверка | результат |
|---|---|
| `llm_route_explain` без модели | sonnet(force-primary) → haiku → ollama; `claude-cli-opus` в `unreachable` со skip «только по явному model» — анти-эскалация жива |
| `llm_route_explain model=opus` | младшие скипаются «не исполняет model=opus», opus переходит в `2-fallback` |
| `model="haiku"` | `claude-cli-haiku`/`claude-haiku-4-5`, 21.9с, `substituted:false` — строгий тир держится, primary скипнут |
| `llm_complete_batch` ×4 | `ok 4 / failed 0`, слоты выровнены по индексу, 28-56с |
| `model="opus"` | `claude-cli-opus`/`claude-opus-5`, 23.9с — explicit_only исполним |
| `model="gpt-4o"` | честный отказ с перечнем скипов и лечением, без тихой подмены |
| **`model=""`** | ушёл на sonnet, `requested_model:null` — блокирующая находка ревью (пустая строка пробивала анти-эскалацию на opus) закрыта |
| делегирование анализа `apply_queue_credit` | sonnet 28.2с, разбор верный по существу |

Побочное подтверждение правок ревью: в батче самый поздний слот дал **наименьшую** латентность (28.5с при гейте спавнов 3) — ожидание в очереди в `response_time` не попало (правка Н2). `avg_response_time` haiku 33.9с против порога `slow_call` 180с — конкурентность не деградирует.

## Находка

Делегат `claude-cli` **читает репозиторий**: ответ содержал довод из докстринга, не переданного в промпте; контрольный вопрос про число `def test_` в тест-файле дал `29` = факт `grep -c`. Следствие — вывод делегата не независим, для ревью/baseline это ложная валидация. Записано: [[reference-llm-rotation-delegate-reads-repo]], обновлён [[reference-llm-rotation-primary-env-override]].
