# Доработки Auto-Documenter для 1С:Предприятие

## Версия 2.6.0 (2025-11-27)

### Новые функции

#### 1. Интеллектуальный код-ревью BSL со стандартами 1С

**Файл:** `src/prompts/bsl-review-prompts.ts` (~350 строк)

**Описание:** Автоматический код-ревью BSL кода на основе официальных стандартов разработки 1С (СП 1С).

**Категории проверок:**
| Категория | Приоритет | Примеры проверок |
|-----------|-----------|------------------|
| 🔴 Безопасность | Критический | SQL-инъекции, привилегированный режим, права доступа |
| 🟠 Производительность | Важный | Запросы в циклах, N+1 проблема, блокировки |
| 🟡 Стандарты кода | Средний | Именование, структура модуля, длина процедур |
| 🟢 Транзакции | Важный | Сбалансированность, откат в исключении |
| ⚪ Обработка ошибок | Средний | Пустые блоки исключений, информативность |

**Проверки по типам модулей:**
- **Модуль объекта**: проверка обработчиков записи, проведения
- **Модуль менеджера**: API, кэширование, печатные формы
- **Модуль формы**: разделение клиент/сервер, временное хранилище
- **Общий модуль**: stateless, документирование экспортных процедур
- **Набор записей**: отборы, конфликты записи

**Использование:**
```bash
# Автоматически определяет BSL код и применяет специализированные промпты
mcp__auto-documenter__autoreview path="D:\\...\\src"

# Лог: [BSL Review] Detected BSL/1C code, using specialized review prompts
```

**Формат результата:**
```markdown
### Критические проблемы 🔴
- Строка 45: SQL-инъекция в динамическом запросе

### Важные замечания 🟠
- Строка 120: Запрос внутри цикла Для Каждого

### Рекомендации по улучшению 🟡
- Процедура ОбработатьДанные: рекомендуется разбить на меньшие процедуры

### Положительные моменты ✅
- Правильное использование транзакций
```

## Версия 2.5.0 (2025-11-27)

### Новые функции

#### 1. Автоматическое определение outputDir для 1С конфигураций

**Файл:** `src/index.ts`

**Описание:** При запуске документирования для 1С конфигураций система автоматически определяет выходную директорию `/docs` вместо создания файлов рядом с исходниками.

**Логика работы:**
```
Исходники: .../251118_GKSTCPLK-1872/src/
Документация: .../251118_GKSTCPLK-1872/docs/  ← автоматически
```

**Функции:**
- `is1CConfiguration(path)` - определяет 1С конфигурацию по:
  - Паттернам пути (`/configuration/`, `/CommonModules/`, `/Catalogs/`...)
  - Наличию папок метаданных
  - Наличию `.bsl` файлов

- `calculate1COutputDir(path)` - вычисляет путь к docs:
  - Если путь заканчивается на `/src` → создаёт `/docs` на том же уровне
  - Сохраняет структуру исходников

**Использование:**
```bash
# outputDir определяется автоматически для 1С
mcp__auto-documenter__generate_documentation path="D:\...\src"

# Лог: [1C Auto] Detected 1C configuration, outputDir set to: D:\...\docs
```

#### 2. Анализатор графа вызовов BSL

**Файл:** `src/analyzer/bsl-call-graph-analyzer.ts` (~600 строк)

**Описание:** Анализирует цепочки вызовов процедур и функций в BSL модулях с использованием tree-sitter AST.

**Возможности:**
- Парсинг всех процедур и функций модуля
- Определение точек входа (экспортируемых)
- Классификация типов вызовов:
  - `internal` - внутренние вызовы в модуле
  - `common_module` - вызовы общих модулей
  - `manager` - вызовы менеджеров объектов
  - `object_method` - методы объектов
  - `platform` - платформенные функции
  - `constructor` - конструкторы (Новый)

- Определение категорий объектов конфигурации:
  - Справочники, Документы, Регистры сведений
  - Регистры накопления, Обработки, Отчёты и др.

**Интерфейсы:**
```typescript
interface ModuleCallGraph {
  filePath?: string;
  procedures: Map<string, ProcedureCallInfo>;
  allCalls: CallInfo[];
  entryPoints: string[];           // Экспортируемые процедуры
  usedCommonModules: Set<string>;  // Используемые общие модули
  usedConfigObjects: Map<ConfigObjectCategory, Set<string>>;
}
```

**Результат в документации:**
```markdown
### Цепочки вызовов
```
ГлавнаяПроцедура()
├── ПодготовитьДанные()
│   └── ПроверитьПараметры()
├── ВыполнитьОбработку()
│   ├── ОбщийМодуль.Функция()
│   └── ЗаписатьРезультат()
└── ОповеститьПользователя()
```
```

#### 3. Русскоязычные промпты для BSL

**Файл:** `src/prompt-config.ts`

**Описание:** Специализированные промпты на русском языке для документирования кода 1С.

**Промпты:**
- `bslDocumentationPrompts.systemPrompt` - базовый промпт для BSL
- `bslDocumentationPrompts.topLevelPrompt` - для корневой директории конфигурации
- `bslDocumentationPrompts.withChildrenPrompt` - для директорий с дочерними объектами
- `bslCrossReferencePrompt` - анализ связей между объектами
- `bslCallGraphPrompt` - форматирование графа вызовов

**Формат связей:**
```markdown
## Связи с объектами конфигурации

### Использует
- Справочник.Контрагенты - получение данных контрагента
- РегистрСведений.ЦеныНоменклатуры - чтение актуальных цен

### Изменяет
- РегистрНакопления.ОстаткиТоваров - движения по товарам

### Вызывает
- ОбщийМодуль.РаботаСКонтрагентами.ПолучитьОсновнойДоговор()
```

#### 4. Контекстно-зависимые промпты для типов модулей

**Файл:** `src/prompts/bsl-context-prompts.ts`

**Описание:** Специализированные инструкции для каждого типа модуля 1С.

**Поддерживаемые типы:**
| Тип модуля | Особенности документирования |
|------------|------------------------------|
| `OBJECT_MODULE` | Обработчики событий, проверки, изменение данных |
| `MANAGER_MODULE` | API объекта, параметры поиска, формат возврата |
| `FORM_MODULE` | Директивы компиляции, элементы формы |
| `COMMON_MODULE` | Публичный API, контекст выполнения |
| `RECORDSET_MODULE` | Измерения, ресурсы, целостность данных |
| `COMMAND_MODULE` | Параметры команды, контекст вызова |

#### 5. Inline документация для BSL

**Файл:** `src/tools/inline-docs-tool.ts`, `src/prompts/inline-docs-prompts.ts`

**Описание:** Генерация комментариев в коде BSL по стандартам 1С.

**Формат комментариев:**
```bsl
// Получает основные данные контрагента для заполнения документов
//
// Параметры:
//   Контрагент - СправочникСсылка.Контрагенты - Ссылка на контрагента
//   ДатаПолучения - Дата - Дата актуальности данных (по умолчанию текущая)
//
// Возвращаемое значение:
//   Структура - Ключи: ИНН, КПП, НаименованиеПолное, ОсновнойДоговор
//
// Пример:
//   ДанныеКонтрагента = ПолучитьДанныеКонтрагента(Документ.Контрагент);
//
Функция ПолучитьДанныеКонтрагента(Контрагент, ДатаПолучения = Неопределено) Экспорт
```

### Инструменты MCP

#### generate_documentation
Создаёт файлы `documentation.md` с описанием модулей.

```bash
mcp__auto-documenter__generate_documentation path="D:\...\src"
```

**Результат для 1С:**
- Автоматически сохраняет в `/docs`
- Русскоязычная документация
- Граф вызовов
- Связи с объектами конфигурации

#### generate_inline_docs
Добавляет комментарии в код BSL.

```bash
mcp__auto-documenter__generate_inline_docs path="D:\...\src"
```

**Результат:**
- Модифицирует `.bsl` файлы
- Комментарии по стандартам 1С
- Описание параметров и возвращаемых значений

#### autoreview
Код-ревью с фокусом на проблемы 1С.

```bash
mcp__auto-documenter__autoreview path="D:\...\src"
```

#### autotestplan
План тестирования для кода 1С.

```bash
mcp__auto-documenter__autotestplan path="D:\...\src"
```
