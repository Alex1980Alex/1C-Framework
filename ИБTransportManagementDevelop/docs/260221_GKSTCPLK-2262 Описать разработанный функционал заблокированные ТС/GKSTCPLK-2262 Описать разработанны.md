# Подсистема «Усиленный контроль качества. Заблокированные ТС»

## Назначение

Подсистема реализует механизм усиленного контроля качества при приёмке транспортных средств на приёмно-лабораторных контрольных комплексах (ПЛК).

При получении неудовлетворительных результатов лабораторного анализа по одному ТС система автоматически блокирует последующие ТС того же контрагента (поставщика) и номенклатуры для принудительного прохождения дополнительных проверок перед разгрузкой.

Подсистема включается функциональными опциями:
- **гкс_ИспользоватьУсиленныйКонтрольКачества** — управляет видимостью всех объектов подсистемы
- **гкс_ИспользоватьЗаблокированныеТС** — управляет отображением информации о блокировках в АРМе

## Типы усиленного контроля

Подсистема поддерживает три типа контроля, определяемых перечислением `гкс_ТипыУсиленногоКонтроляКачества`:

### Первое ТС

Результат лабораторного анализа первого ТС контрагента за производственные сутки распространяется на все последующие ТС этого контрагента по данной номенклатуре. Если качество первого ТС не принято — все следующие ТС блокируются до получения результата.

### Группы ТС

ТС группируются по N штук (количество задаётся в настройках). Результат лабораторного анализа одного ТС из группы распространяется на остальных участников группы. Группы связаны последовательно через реквизит «ПредыдущаяГруппа» справочника `гкс_ГруппыТС` — разблокировка передаётся строго по цепочке.

### Каждое ТС

Индивидуальная проверка каждого ТС. Этот тип возникает автоматически при эскалации: если качество первого ТС или группы не принято, система переключает правило на «Каждое ТС» на срок, заданный константой `гкс_СрокУстановкиПравилКаждоеТС`.

## Бизнес-процесс

### Цепочка данных: от регистрации ТС до блокировки

#### Этап 1. Регистрация ТС на ПЛК

При проведении документа `гкс_РегистрацияНаПЛК` система:

1. Записывает ТС в регистр сведений `гкс_ТранспортныеСредстваПоставщикаУсиленногоКонтроля` с признаком «ЭтоПервоеТС».
2. Подбирает подходящие правила из регистра сведений `гкс_НастройкиУсиленногоКонтроляКачества` по комбинации: вид перевозки, точка маршрута, номенклатура, показатель, контрагент.
3. Записывает применённые правила в регистр сведений `гкс_ПравилаУсиленногоКонтроляПоРегистрации`.
4. Записывает показатели контроля в регистр сведений `гкс_ПоказателиУсиленногоКонтроляПоРегистрации`.
5. Если ТС не первое у контрагента — определяет группу через справочник `гкс_ГруппыТС` и записывает привязку в регистр сведений `гкс_СоставГруппТранспорта`.

#### Этап 2. Лабораторный анализ — создание блокировок

При проведении документа `гкс_ЛабораторныйАнализ` срабатывают два независимых механизма:

**Механизм 1 — обработка текущей регистрации:** оценивает качество текущего ТС, определяет статус (Качество принято / Качество не принято / Результаты проб получены).

**Механизм 2 — обработка заблокированных ТС:** проверяет, является ли текущий лабораторный анализ блокирующим для других ТС. Если да — создаёт или обновляет записи блокировки.

Записи блокировки создаются по **двухканальной модели**:

- **Канал «Первое ТС»** — в измерение «БлокирующаяРегистрация» записывается ссылка на документ регистрации первого ТС контрагента.
- **Канал «Группа ТС»** — в измерение «БлокирующаяГруппаТС» записывается ссылка на элемент справочника `гкс_ГруппыТС`.

Каналы взаимоисключающие: одна запись блокируется либо регистрацией, либо группой.

#### Этап 3. Проверка блокировки при создании направления на разгрузку

Перед формированием документа `гкс_НаправлениеНаРазгрузку` выполняется трёхуровневая проверка:

| Уровень | Условие | Действие |
|---------|---------|----------|
| **Блокировка** | Качество не принято **и** единичный анализ по усиленному контролю не выполнен | Создание направления на разгрузку запрещено |
| **Предупреждение** | Результаты проб получены **или** качество не принято, но единичный анализ выполнен | Пользователю выводится предупреждение с возможностью продолжить |
| **Разрешено** | Нет активных блокировок или все разблокированы | Направление на разгрузку создаётся без ограничений |

Критерий перехода от блокировки к предупреждению — **наличие** выполненного единичного анализа, а не его результат. Даже при отрицательном результате единичного анализа пользователь может принять качество вручную через направление на разгрузку.

#### Этап 4. Разблокировка

При проведении документа `гкс_НаправлениеНаРазгрузку` с принятием качества в регистре сведений `гкс_ЗаблокированныеРегистрацииУсиленныйКонтроль` устанавливается ресурс `Разблокировано = Истина`.

### Эскалация правил

При отклонении качества (состояние «Качество не принято») на первом ТС или в группе система автоматически:

1. Находит все правила типа «Первое ТС» и «Группы ТС» для данного контрагента и номенклатуры.
2. Меняет тип правила на «Каждое ТС».
3. Устанавливает дату окончания действия правила = текущая дата + срок из константы `гкс_СрокУстановкиПравилКаждоеТС`.

После эскалации все последующие ТС данного контрагента по данной номенклатуре проверяются индивидуально.

### Каскадная разблокировка групп

Группы ТС связаны последовательно. Разблокировка передаётся строго по цепочке:

```
Первое ТС → Группа 1 → Группа 2 → Группа 3 → ...
```

Первое ТС не может напрямую разблокировать группу 2. Каждое звено цепочки зависит только от непосредственно предыдущего.

## Две цепочки обработки качества

При работе с лабораторными анализами подсистема разделяет обработку на две независимые цепочки:

| Цепочка | Какие показатели анализируются | Назначение |
|---------|-------------------------------|------------|
| **Приёмка** | Все показатели из табличной части «Качественные показатели» документа «Лабораторный анализ» | Определение общего статуса качества ТС |
| **Заблокированные ТС** | Только показатели с признаком «УсиленныйКонтроль = Истина» | Разблокировка конкретного показателя или создание индивидуальных показателей для заблокированного ТС |

Если входной контроль (обычные показатели) не пройден, усиленный контроль не имеет смысла — ТС отклоняется на этапе приёмки. Состояние качества для композитных показателей устанавливается в «Пробы не требуются».

## Работа пользователя в АРМе

### Жизненный цикл ТС

АРМ «гкс_ПриемкаТранспорта» реализует машину состояний с 13 состояниями. Основные этапы, связанные с блокировками:

```
Въезд → Номер пробы → Принять пробы → Анализ → [Проверка блокировки] → На разгрузку → Разгрузка → Выезд
```

### Точки влияния блокировки

**1. Результаты лабораторного анализа (кнопка «Анализ»)**

При проведении лабораторного анализа из АРМа система создаёт записи блокировки для последующих ТС контрагента. В таблице АРМа у заблокированных ТС в колонке «УК» появляется иконка предупреждения.

**2. Создание направления на разгрузку (кнопка «На разгрузку»)**

При нажатии выполняется проверка наличия активных блокировок:
- **Блокировка** — кнопка недоступна, пользователь видит сообщение о необходимости выполнить анализ по усиленному контролю.
- **Предупреждение** — пользователю задаётся вопрос «ТС заблокировано. Продолжить создание направления на разгрузку?»
- **Разрешено** — открывается форма направления на разгрузку.

Для групповой обработки нескольких регистраций используется форма «ГрупповоеНаправлениеНаРазгрузку».

**3. Отображение причины блокировки (панель «Детали»)**

При выборе строки в таблице регистраций в панели деталей отображается:
- Причина блокировки (красный текст).
- Гиперссылка на блокирующий документ «Лабораторный анализ» (открывается по клику).

Элементы блокировки создаются программно при открытии формы, управляются функциональной опцией `гкс_ИспользоватьЗаблокированныеТС`.

**4. Пропуск входного контроля**

Для ЖД перевозок доступна кнопка «Пропустить контроль качества»:
- Видимость: функциональная опция `гкс_ИспользоватьОтключениеВходногоКонтроляКачества`.
- Доступность: роль `гкс_ПриемкаТранспортаБезВходногоКонтроля_ДобавлениеИзменение`.
- Действие: создаётся запись в регистре сведений `гкс_ПриемкаТранспортаБезВходногоКонтроля` и автоматически формируется направление на разгрузку.

## Схема движения данных по регистру сведений

### Операции над регистром сведений «гкс_ЗаблокированныеРегистрацииУсиленныйКонтроль»

| Операция | Инициатор | Условие |
|----------|-----------|---------|
| **Создание записи** | Проведение документа «Лабораторный анализ» | Результат анализа отклоняется по правилам усиленного контроля |
| **Обновление состояния** | Проведение последующих лабораторных анализов | Новые результаты меняют значение ресурса «БлокирующееСостояниеКачества» |
| **Разблокировка** | Проведение документа «Направление на разгрузку» | Качество принято — ресурс «Разблокировано» устанавливается в Истина |
| **Чтение (пакетное)** | АРМ «Приёмка транспорта» | Отображение списка ТС с информацией о блокировках |
| **Чтение (проверка)** | Форма направления на разгрузку / АРМ | Проверка наличия активных блокировок перед созданием документа |

### Граф вызовов

```
Документ «Лабораторный анализ» (модуль объекта, при проведении)
  └─ Общий модуль гкс_ВходнойКонтрольКачества
       ├─ Чтение: РС гкс_НастройкиУсиленногоКонтроляКачества
       ├─ Чтение/Запись: РС гкс_ПоказателиУсиленногоКонтроляПоРегистрации
       └─ Запись: РС гкс_ЗаблокированныеРегистрацииУсиленныйКонтроль

Документ «Направление на разгрузку» (модуль объекта, при проведении)
  └─ Общий модуль гкс_ВходнойКонтрольКачества
       └─ Запись: РС гкс_ЗаблокированныеРегистрацииУсиленныйКонтроль
            (Разблокировано = Истина)

Документ «Регистрация на ПЛК» (модуль объекта, при проведении)
  └─ Общий модуль гкс_ВходнойКонтрольКачества
       ├─ Запись: РС гкс_ТранспортныеСредстваПоставщикаУсиленногоКонтроля
       ├─ Запись: РС гкс_ПоказателиУсиленногоКонтроляПоРегистрации
       ├─ Запись: РС гкс_ПравилаУсиленногоКонтроляПоРегистрации
       └─ Справочник гкс_ГруппыТС + РС гкс_СоставГруппТранспорта
```
