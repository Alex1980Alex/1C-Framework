## 1. Описание задачи

### 1.1 Требования (3 пункта)

| #   | Сценарий ЛА                                                                 | Условие создания НаправленияНаРазгрузку                                                                                          |
| --- | --------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| 1   | ЛА приёмка на ТС                                                            | Если регистрация **НЕ** заблокировалась по правилу Первого ТС или Группы ТС → создать автоматически                              |
| 2   | ЛА промежуточного композита на группу **ИЛИ** ЛА приёмка первого ТС (по УК) | Если качество принято по УК для **ВСЕХ** заблокированных ТС, у которых итоговое качество принято → создать (если ещё не создано) |
| 3   | ЛА единичный / промежуточный композит по УК                                 | Если регистрация **разблокирована** И итоговое качество **принято** → создать                                                    |

**БЕЗ ФО «Заблокированные ТС»:** принцип создания Направления на разгрузку должен оставаться прежним.

### 1.2 Суть проблемы

**Что сейчас (верифицировано по коду):**

В модуле объекта `гкс_ЛабораторныйАнализ` уже частично реализована логика для заблокированных ТС:
- Есть процедура `СформироватьВспомогательныеДанныеДляЗаблокированныхТС` (строка 674), которая вызывает `ЗаписатьСостоянияРегистрацииЗаблокированныхТС` и `СформироватьНаправленияНаРазгрузкуДляРазблокированныхТС`
- Есть проверка `РегистрацияЗаблокированаДляРазгрузки()` (строка 717) в `СформироватьНаправлениеНаРазгрузкуПриНеобходимости`

**Однако** обнаружена **критическая проблема**: функция `РегистрацияЗаблокированаДляРазгрузки()` использует **модульную переменную** `гкс_ДокументРегистрации` (текущего ЛА), а НЕ параметр `ДокументРегистрации`, переданный в процедуру. Это означает, что когда `СформироватьНаправленияНаРазгрузкуДляРазблокированныхТС` итерирует по разблокированным ТС — проверка блокировки идёт по текущему ЛА, а не по конкретному ТС из таблицы. В результате если текущее ЛА связано с заблокированной регистрацией, то создание направлений для **всех** разблокированных ТС тоже блокируется.

### 1.3 Ключевая подсказка из ТЗ

> Для отработки вычисления в ЛА заблокированных ТС при проведении ЛА создана процедура `СформироватьСостоянияРегистацииДляЗаблокированныхТС()`. Опираться на неё для дальнейших доработок.

**В коде:** `СформироватьВспомогательныеДанныеДляЗаблокированныхТС()` (строка 674 ObjectModule.bsl).

### 3.2 Процедура `СформироватьНаправлениеНаРазгрузкуПриНеобходимости` (строки 598-622)

```bsl
Процедура СформироватьНаправлениеНаРазгрузкуПриНеобходимости(
    ДокументРегистрации, ЛабораторныйАнализ, ДатаАнализа, ДопПараметры = Неопределено)

    // Guard 1: параметры назначения и разрешение
    Если ДопПараметры <> Неопределено И Не НазначатьНаСкладыПоПараметрам(...)
        Или Не гкс_ПриемкаТранспорта.НаправлятьНаРазгрузкуРазрешение(ДокументРегистрации) Тогда
        Возврат;
    КонецЕсли;

    // Guard 2: ⚠️ БЛОКИРОВКА — использует МОДУЛЬНУЮ переменную гкс_ДокументРегистрации
    Если РегистрацияЗаблокированаДляРазгрузки() Тогда
        "Направление на разгрузку не сформировано: регистрация заблокирована по УК"
        Возврат;
    КонецЕсли;

    // Создание НаправленияНаРазгрузку
    гкс_ПриемкаТранспорта.СформироватьНаправлениеНаРазгрузку(ДатаАнализа, ДокументРегистрации, ЛабАнализ);
КонецПроцедуры
```

### 3.3 Функция `РегистрацияЗаблокированаДляРазгрузки()` (строки 717-722) — КОРЕНЬ ПРОБЛЕМЫ

```bsl

    Возврат
        ТребуетсяЗаблокированныеТСЛабАнализа()
        И гкс_ВходнойКонтрольКачества.ПроверитьБлокированиеТранспортногоСредстваДляРазгрузки(
            гкс_ДокументРегистрации);   // ← МОДУЛЬНАЯ ПЕРЕМЕННАЯ ТЕКУЩЕГО ЛА!
```

**Проблема:** При вызове из цикла `СформироватьНаправленияНаРазгрузкуДляРазблокированныхТС` параметр `ДокументРегистрации` — это регистрация из таблицы (разблокированная), но `РегистрацияЗаблокированаДляРазгрузки()` проверяет `гкс_ДокументРегистрации` (текущий ЛА) → если текущая заблокирована, ВСЕ направления из цикла тоже блокируются.

## 4. План изменений

### Точка модификации 1: `СформироватьНаправлениеНаРазгрузкуПриНеобходимости` (строки 598-622)

**Файл:** `src/Documents/гкс_ЛабораторныйАнализ/Ext/ObjectModule.bsl`
**Тип:** Модификация
**Связь с требованиями:** 1, 2, 3

**Проблема:** Проверка `РегистрацияЗаблокированаДляРазгрузки()` использует модульную переменную → блокирует создание направлений для разблокированных ТС из цикла.

**Решение (рекомендуемый вариант А):** Добавить параметр `ПропуститьПроверкуБлокировки = Ложь`:

```bsl
Процедура СформироватьНаправлениеНаРазгрузкуПриНеобходимости(
    ДокументРегистрации, ЛабАнализ, ДатаАнализа,
    ДопПараметры = Неопределено, ПропуститьПроверкуБлокировки = Ложь)

    // Guard 1: без изменений
    Если ДопПараметры <> Неопределено И Не НазначатьНаСкладыПоПараметрам(...)
        Или Не гкс_ПриемкаТранспорта.НаправлятьНаРазгрузкуРазрешение(ДокументРегистрации) Тогда
        Возврат;
    КонецЕсли;

    // Guard 2: GKSTCPLK-2182 — пропуск проверки для разблокированных ТС
    Если Не ПропуститьПроверкуБлокировки
        И РегистрацияЗаблокированаДляРазгрузки() Тогда
        ... сообщение + возврат
    КонецЕсли;

    // Создание: без изменений
    гкс_ПриемкаТранспорта.СформироватьНаправлениеНаРазгрузку(...);
КонецПроцедуры
```

**Обоснование:** Минимальная модификация сигнатуры. Существующие вызовы (из `гкс_Взвешивание`, `гкс_СРПВРегистрацияОперацииСВагоном`, и текущий из ОбработкаПроведения строка 161) не передают новый параметр → значение по умолчанию `Ложь` → поведение не меняется.

## 10. Детальный анализ Пункта 1: Алгоритм блокировки и создание направления на разгрузку

> **Требование 1:** При проведении ЛА приёмка на ТС, если регистрация **НЕ** заблокировалась по правилу Первого ТС или Группы ТС, то автоматически создаём направление на разгрузку.

### 10.1 Алгоритм записи в регистр блокировки (Write Path)

**Модуль:** `гкс_ВходнойКонтрольКачества` → `ЗаполнитьЗаблокированныеРегистрацииУсиленныйКонтроль`
**Регистр:** `РС гкс_ЗаблокированныеРегистрацииУсиленныйКонтроль`

#### Шаг 1: Запрос связанных регистраций

Процедура выполняет запрос `ТекстЗапросаЗаблокированныхРегистрацийУК()`, который возвращает все регистрации, связанные с текущей (по поставщику, виду продукции и т.п.), и тип входного контроля для каждой.

#### Шаг 2: Цикл по результатам и применение правил

```
Для каждой строки результата запроса:
│
├─ Если ТипВходногоКонтроля = "КаждоеТС" → ПРОПУСК (Продолжить)
│   (для типа "каждое ТС" блокировка не применяется)
│
├─ Если ТипВходногоКонтроля = "ПервоеТС" → ПРАВИЛО "Первое ТС":
│   └─ ЗаписатьБлокировкуТС(ДокументРегистрации, ДокументРегистрацииПервоеТС, Показатель)
│       → Создаёт запись в регистре:
│         ДокументРегистрации = текущая регистрация
│         ДокументРегистрацииПервоеТС = регистрация первого ТС
│         Разблокировано = Ложь
│
├─ Если ТипВходногоКонтроля = "ГруппаТС" → ПРАВИЛО "Группа ТС":
│   └─ ЗаписатьБлокировкуГруппыТС(ДокументРегистрации, ...)
│       → Создаёт записи для всех ТС в группе
│         Разблокировано = Ложь
│
└─ После каждой уникальной регистрации:
    └─ ОбновитьЗаблокированныеТСПриЗавершенииЛА(...)
        → Обновляет статусы при завершении ЛА (может установить Разблокировано = Истина)
```

#### Шаг 3: Результат

В регистре `гкс_ЗаблокированныеРегистрацииУсиленныйКонтроль` хранятся записи:
- `ДокументРегистрации` — заблокированная регистрация
- `ДокументРегистрацииПервоеТС` — регистрация, по которой определена блокировка
- `Показатель` — показатель качества
- `Разблокировано` — флаг (`Ложь` = заблокировано, `Истина` = разблокировано)

### 10.2 Алгоритм чтения из регистра блокировки (Read Path)

**Модуль:** `гкс_ВходнойКонтрольКачества` → `ПроверитьБлокированиеТранспортногоСредстваДляРазгрузки`
**Вызывается из:** `гкс_ЛабораторныйАнализ.ObjectModule.bsl` → `РегистрацияЗаблокированаДляРазгрузки()` (строка 722)

#### SQL-запрос проверки:

```sql
ВЫБРАТЬ ПЕРВЫЕ 1
    ЗаблокированныеТС.ДокументРегистрации
ИЗ
    РегистрСведений.гкс_ЗаблокированныеРегистрацииУсиленныйКонтроль КАК ЗаблокированныеТС
ГДЕ
    ЗаблокированныеТС.ДокументРегистрации = &ДокументРегистрации
    И НЕ ЗаблокированныеТС.Разблокировано
```

#### Логика:
- Ищет ХОТЯ БЫ ОДНУ запись, где `Разблокировано = Ложь`
- Если запись найдена → `Истина` (регистрация заблокирована)
- Если записей нет ИЛИ все записи имеют `Разблокировано = Истина` → `Ложь` (регистрация не заблокирована: либо не попадала под блокировку, либо была разблокирована)

### 11.6 Что именно изменено для Пункта 2

| Файл:строка              | Изменение                                                                                     | Назначение                                          |

**Одна строка.** Вся остальная цепочка (шаги 1–3) **уже существовала** в коде до изменений.

### 11.7 Почему нужен пропуск проверки

Без флага `Истина` внутри `СформироватьНаправлениеНаРазгрузкуПриНеобходимости` вызывалась бы:

```bsl
РегистрацияЗаблокированаДляРазгрузки()
    → ПроверитьБлокирование...(гкс_ДокументРегистрации)
                                ^^^^^^^^^^^^^^^^^^^^^^^^
                                модульная переменная = регистрация ТЕКУЩЕГО ЛА
```

Но в цикле мы создаём направления для **других** документов регистрации (`СтрокаДанные.ДокументРегистрации`). Функция проверяла бы блокировку не того документа.

Кроме того, повторная проверка **избыточна**: данные в таблице `ДанныеДляРазгрузкиРазблокированныхТС` уже отфильтрованы SQL-пакетом `ЗаблокированныеТСКачествоПринято` — содержат только разблокированные ТС с принятым качеством.

```
├─ [Обычный путь] СформироватьНаправлениеНаРазгрузкуПриНеобходимости(гкс_ДокументРегистрации, ...)
│   └─ РегистрацияЗаблокированаДляРазгрузки() → проверка текущего ЛА (Пункт 1)
│
└─ [Путь заблокированных ТС]
    ├─ ТребуетсяЗаблокированныеТСЛабАнализа() → Истина (ФО ВКЛ, УК, ПромежуточныйКомпозит)
    │
    └─ СформироватьВспомогательныеДанныеДляЗаблокированныхТС()
        │
        ├─ ЭтоЛабАнализДляЗаблокированныхТС() → Истина (ПромежуточныйКомпозит + ФормированиеНомераПроб)
        │
        ├─ ЗаписатьСостоянияРегистрацииЗаблокированныхТС(Ссылка, гкс_ДокументРегистрации, ТаблицаРезультат)
        │   └─ SQL пакет "ЗаблокированныеТСКачествоПринято"
        │       → Результат: таблица с N строками (разблокированные ТС, качество принято)
        │       → Пример:
        │         | ДокументРегистрации | ЛабораторныйАнализ | Дата       |
        │         | Регистрация-005     | ЛА-010             | 04.03.2026 |
        │         | Регистрация-008     | ЛА-012             | 04.03.2026 |
        │
        └─ СформироватьНаправленияНаРазгрузкуДляРазблокированныхТС(Таблица)
            │
            ├─ Итерация 1: СтрокаДанные = {Регистрация-005, ЛА-010, ...}
            │   └─ СформироватьНаправлениеНаРазгрузкуПриНеобходимости(
            │       Регистрация-005, ЛА-010, Дата, , Истина)
            │       │
            │       ├─ Не Истина И ... = Ложь → проверка блокировки ПРОПУЩЕНА
            │       └─ гкс_ПриемкаТранспорта.СформироватьНаправлениеНаРазгрузку(...)
            │           → ✅ Направление создано для Регистрация-005
            │
            └─ Итерация 2: СтрокаДанные = {Регистрация-008, ЛА-012, ...}
                └─ ... аналогично → ✅ Направление создано для Регистрация-008
```

### 11.9 Условие «если ещё не создано»

Проверка дублирования выполняется **внутри** `гкс_ПриемкаТранспорта.СформироватьНаправлениеНаРазгрузку(...)` — там вызывается `ПолучитьПоРегистрации()`, которая проверяет, существует ли уже направление для данного `ДокументРегистрации`. Если направление уже есть — повторное не создаётся. Этот механизм существовал до изменений GKSTCPLK-2182.

## 12. Детальный анализ Пункта 3: Единичный ЛА по УК

> **Требование 3:** ЛА единичный / промежуточный композит по УК — если регистрация **разблокирована** и итоговое качество **принято** → создать направление на разгрузку.

### 12.1 Суть вопроса

«Единичный ЛА» — это ЛА (приёмка или промежуточный композит), у которого `ДокументРегистрации = РегистрацияНаПЛК` (не `ФормированиеНомераПробы`).

Первоначально предполагалось, что для единичного ЛА нужно открыть gate-функцию `ЭтоЛабАнализДляЗаблокированныхТС()`. Однако при анализе SQL-запроса выяснилось, что это **не нужно**.

### 12.2 Почему изменение gate не требуется

Gate-функция `ЭтоЛабАнализДляЗаблокированныхТС()` (строка 710) открывает путь к SQL-запросу `ТекстЗапросаСостоянияРегистрацииЗаблокированныхТС` (CommonModules/гкс_ВходнойКонтрольКачества, строка 730).

**Пакет 1 SQL-запроса** (`ЗаблокированныеТС`, строки 744-766) состоит из двух частей через `ОБЪЕДИНИТЬ ВСЕ`:

**Часть 1** (строки 744-751):
```sql
ВЫБРАТЬ ДокументРегистрации
ПОМЕСТИТЬ ЗаблокированныеТС
ИЗ РегистрСведений.гкс_ЗаблокированныеРегистрацииУсиленныйКонтроль
ГДЕ БлокирующаяРегистрация = &ДокументРегистрации
    И НЕ Разблокировано
```
Ищет регистрации, заблокированные **ТЕКУЩЕЙ** регистрацией (`БлокирующаяРегистрация = &ДокументРегистрации`).

**Часть 2** (строки 753-766):
```sql
ВЫБРАТЬ ЗаблокированныеРегистрацииУК.ДокументРегистрации
ИЗ Документ.гкс_ФормированиеНомераПробы.СписокРегистраций
    ... СОЕДИНЕНИЕ ... гкс_ЗаблокированныеРегистрацииУсиленныйКонтроль
ГДЕ РегистрацииФПН.Ссылка = &ДокументРегистрации
    И НЕ Разблокировано
```
Ищет через `ФормированиеНомераПробы` — только если `&ДокументРегистрации` является `ФормированиеНомераПробы`.

**Для единичного ЛА** (`ДокументРегистрации = РегистрацияНаПЛК`):

| Часть SQL | Условие                                                | Результат                                                                                 |
| --------- | ------------------------------------------------------ | ----------------------------------------------------------------------------------------- |
| Часть 1   | `БлокирующаяРегистрация = РегистрацияНаПЛК_единичного` | **Пусто** — единичный ЛА (не первая регистрация) **не является** блокирующей регистрацией |
| Часть 2   | `РегистрацииФПН.Ссылка = РегистрацияНаПЛК`             | **Пусто** — `РегистрацияНаПЛК ≠ ФормированиеНомераПробы`                                  |

→ Таблица `ЗаблокированныеТС` **пуста** → все последующие пакеты пусты → `ДанныеДляРазгрузкиРазблокированныхТС` **пуста** → цикл создания направлений не выполняется.

**Вывод:** Даже если gate открыт для единичного ЛА, SQL-запрос не возвращает данных. Изменение gate **бесполезно**.

### 12.3 Как единичный ЛА обрабатывается через обычный путь (Пункт 1)

Направление для единичного ЛА создаётся через **обычный путь** — `СформироватьНаправлениеНаРазгрузкуПриНеобходимости()`:

```
ОбработкаПроведения
│
├─ ЛА = единичный (приёмка или промежуточный композит), ФО ВКЛ, Статус = Выполнен
│   ДокументРегистрации = РегистрацияНаПЛК
│
└─ СформироватьНаправлениеНаРазгрузкуПриНеобходимости(гкс_ДокументРегистрации, ..., ПропуститьПроверкуБлокировки=Ложь)
    │
    ├─ Не Ложь И РегистрацияЗаблокированаДляРазгрузки() = ?
    │   │
    │   └─ ПроверитьБлокированиеТранспортногоСредстваДляРазгрузки(гкс_ДокументРегистрации)
    │       SQL: WHERE ДокументРегистрации = текущий И НЕ Разблокировано
    │       │
    │       ├─ Если Разблокировано = Истина (или нет записи) → Ложь
    │       │   → Guard: Истина И Ложь = Ложь → НЕ выходим
    │       │   → Направление СОЗДАЁТСЯ ✅
    │       │
    │       └─ Если НЕ Разблокировано → Истина
    │           → Guard: Истина И Истина = Истина → ВЫХОД (Возврат)
    │           → Направление НЕ создаётся (корректно — ТС заблокировано) ✅
```

### 12.4 Итоговый статус Пункта 3

**Изменение gate-функции `ЭтоЛабАнализДляЗаблокированныхТС()` НЕ требуется.**

Функция оставлена без изменений (оригинальный код):

```bsl
Функция ЭтоЛабАнализДляЗаблокированныхТС()
    Возврат
        Перечисления.гкс_НазначенияИспользованияКачества.ЭтоПриемка(гкс_НазначениеИспользованияКачества)
        И гкс_ВходнойКонтрольКачества.ЭтоПерваяРегистрацияТСПоставщика(гкс_ДокументРегистрации)
        ИЛИ Перечисления.гкс_НазначенияИспользованияКачества.ЭтоПромежуточныйКомпозит(гкс_НазначениеИспользованияКачества)
        И ЭтоФормированиеНомераПроб(гкс_ДокументРегистрации);
КонецФункции
```

Единичный ЛА (приёмка или промежуточный композит) обрабатывается через **обычный путь** (Пункт 1): если регистрация разблокирована → `РегистрацияЗаблокированаДляРазгрузки()` возвращает `Ложь` → направление создаётся.

### 12.5 Связь Пунктов 1 и 2

| Пункт | Что обеспечивает                                                                             | Точка изменения                                               |
| ----- | -------------------------------------------------------------------------------------------- | ------------------------------------------------------------- |
| 1     | Обычный путь: проверка блокировки + создание направления для текущего ЛА (включая единичные) | Параметр `ПропуститьПроверкуБлокировки` (строка 599, 606-608) |
| 2     | Цикл разблокированных ТС: пропуск повторной проверки для ТС из SQL-выборки                   | `, Истина` в вызове (строка 701-704)                          |

Пункт 1 обеспечивает обычный путь для ВСЕХ типов ЛА (включая единичные). Пункт 2 обеспечивает создание направлений для ТС, которые были разблокированы после блокировки первым ТС или группой.

### 12.6 Проверка блокировки единичного ЛА по УК (упрощение)

#### Изменения

Пункт 3 (проверка «разблокирована, но качество не принято») **удалён** — избыточная логика.
Достаточно проверки наличия заблокированных регистраций (Пункт 1).

**Удалено:**
- Функция `РегистрацияРазблокированаБезПринятогоКачества` (`гкс_ВходнойКонтрольКачества`) — удалена полностью
- Блок «Пункт 3» в `СформироватьНаправлениеНаРазгрузкуПриНеобходимости` (`ObjectModule.bsl`) — удалён

**Изменено:**
- `ПолучитьДанныеБлокировкиЕдиничногоЛА` — `ЛЕВОЕ СОЕДИНЕНИЕ` заменено на `ВНУТРЕННЕЕ СОЕДИНЕНИЕ` с `гкс_ЗаблокированныеРегистрацииУсиленныйКонтроль`. Теперь возвращает только строки, где **есть** запись о блокировке.

#### Итоговая логика нормального пути

```
СформироватьНаправлениеНаРазгрузкуПриНеобходимости:
  1. [существующее] складские параметры + НаправлятьНаРазгрузкуРазрешение
  2. [Пункт 1] если заблокирована → Возврат
  3. → создаёт направление
```

#### Проверочный запрос

`гкс_ВходнойКонтрольКачества.ПолучитьДанныеБлокировкиЕдиничногоЛА(ДокументРегистрации)`:

```sql
ВЫБРАТЬ РАЗЛИЧНЫЕ
    ПоказателиУК.ДокументРегистрации,
    Заблокированные.ДокументРегистрации КАК ЗаблокированнаяДокументРегистрации,
    Заблокированные.БлокирующееСостояниеКачества,
    Заблокированные.Разблокировано,
    Заблокированные.БлокирующаяРегистрация
ИЗ
    гкс_ПоказателиУсиленногоКонтроляПоРегистрации КАК ПоказателиУК
    ВНУТРЕННЕЕ СОЕДИНЕНИЕ гкс_ЗаблокированныеРегистрацииУсиленныйКонтроль КАК Заблокированные
        ПО ПоказателиУК.ДокументРегистрации = Заблокированные.ДокументРегистрации
            И ПоказателиУК.Показатель = Заблокированные.Показатель
ГДЕ
    ПоказателиУК.ДокументРегистрации = &ДокументРегистрации
    И ПоказателиУК.НазначениеИспользования = ПромежуточныйКомпозит
    И ПоказателиУК.ТипПробы = Единичная
```

**Логика:** INNER JOIN возвращает только показатели, для которых **существует** запись блокировки в `гкс_ЗаблокированныеРегистрацииУсиленныйКонтроль`. Пустой результат означает — регистрация не была заблокирована. Колонка `Разблокировано` показывает текущий статус.
