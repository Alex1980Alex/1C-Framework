# GKSTCPLK-2182 -- Дорожная карта подготовки тестовых данных

**Дата:** 2026-03-10
**База:** TestDB (localhost)
**Цель:** Создать НОВЫЕ цепочки документов для тестирования создания НР для заблокированных ТС

---

## Почему нужны новые цепочки

Старые тестовые регистрации (КАУТ-0009175..0009180) **непригодны** для тестирования создания НР:

| Проблема | Суть | Последствие |
|----------|------|-------------|
| 28 старых НР | Все 12 тестовых регистраций уже имеют НР от 2023-2025 | `ПолучитьПоРегистрации` возвращает их -> новые НР не создаются |
| Удаление невозможно | `ОтменаПроведения` блокируется связанными документами | Помечены на удаление, но запрос всё равно находит |
| Баг ПолучитьПоРегистрации | Запрос не фильтрует по `ПометкаУдаления` | Даже удалённые НР блокируют создание новых |

**Решение:** Создать свежие цепочки документов с нуля + исправить баг в коде.

**Исправленный запрос (добавить строку):**
```sql
ВЫБРАТЬ РАЗРЕШЕННЫЕ
```

### 0.2 Баг: X <> X в ЗаписатьСостоянияРегистрацииЗаблокированныхТС

**Файл:** `ОбщиеМодули / гкс_ВходнойКонтрольКачества / Ext / Module.bsl`
**Строка:** ~867

**Текущий код (НЕПРАВИЛЬНО):**
```sql
ГДЕ СостоянияРегистрацииПоЗаблокированнымТС.СостояниеРегистрации
    <> СостоянияРегистрацииПоЗаблокированнымТС.СостояниеРегистрации
```

**Исправленный код:**
```sql
ГДЕ СостоянияРегистрацииПоЗаблокированнымТС.СостояниеРегистрации
```

- [ ] Исправлено в Конфигураторе
- [ ] Обновлена БД (F7)

### 0.3 Настройки усиленного контроля (РС гкс_НастройкиУсиленногоКонтроляКачества)

**Где:** 1С:Предприятие -> Все функции -> РегистрСведений `гкс_НастройкиУсиленногоКонтроляКачества`

Для работы механизма блокировки нужны **правила УК**, привязанные к тому же поставщику, номенклатуре и точке маршрута, что и тестовые регистрации.

| # | ТипВходногоКонтроля | Показатель | Поставщик | КоличествоТС | Статус |
|---|---------------------|-----------|-----------|--------------|--------|
| ПР-1 | **Первое ТС** | ГМО | Китаевка ООО | 1 | Активен=Да |
| ПР-2 | **Группы ТС** | ГМО | Китаевка ООО | 3 | Активен=Да |

#### Если правил нет — создать

**Правило ПР-1 "Первое ТС":**

| Измерение/Ресурс | Значение |
|-------------------|----------|
| ВидПеревозки | Автомобиль |
| ТочкаМаршрута | ПЛК Курск |
| Номенклатура | Соевые бобы (Россия), не ГМО |
| Показатель | ГМО (из справочника `гкс_ПоказателиКачестваWarehouse`) |
| Поставщик | **Китаевка ООО** |
| ТипВходногоКонтроля | **Первое ТС** |
| КоличествоТС | **1** |
| Активен | Да |
| ДатаНачала | 01.03.2026 (или раньше) |
| ДатаОкончания | 31.12.2026 (или пусто) |

**Правило ПР-2 "Группы ТС":**

| Измерение/Ресурс | Значение |
|-------------------|----------|
| ВидПеревозки | Автомобиль |
| ТочкаМаршрута | ПЛК Курск |
| Номенклатура | Соевые бобы (Россия), не ГМО |

**Без этих правил блокировки НЕ создадутся!**

- [ ] Правило "Первое ТС" (ПР-1) существует и активно
- [ ] Правило "Группы ТС" (ПР-2) существует и активно
- [ ] Поставщик в правилах = Китаевка ООО (совпадает с Фазой 1)

## ФАЗА 6: Разблокировка и создание НР (тест П.2)

### Зачем

Проверить, что при проведении ЛА на Первое ТС (с принятым качеством), заблокированные регистрации разблокируются и для них создаются НР.

### Что происходит при проведении ЛА на Первое ТС (Р6):

```
ОбработкаПроведения ЛА (Р6)
├─ СформироватьВспомогательныеДанныеДляЗаблокированныхТС()
│   ├─ ЭтоЛабАнализДляЗаблокированныхТС() = Истина
│   │   (Назначение=Приемка И ЭтоПерваяРегистрацияТСПоставщика)
│   ├─ ЗаписатьСостоянияРегистрацииЗаблокированныхТС()
│   │   → Заполняет ДанныеДляРазгрузкиРазблокированныхТС
│   ├─ СформироватьНаправленияНаРазгрузкуДляРазблокированныхТС()
│   │   → Для каждой строки вызывает:
│   │     СформироватьНаправлениеНаРазгрузкуПриНеобходимости(
│   │       ..., ПропуститьПроверкуБлокировки = Истина)
│   │   → Которая вызывает гкс_ПриемкаТранспорта.СформироватьНаправлениеНаРазгрузку()
│   │   → Которая создаёт НР
│   └─ ЗаполнитьЗаблокированныеРегистрацииУсиленныйКонтроль()
│       → Устанавливает Разблокировано = Истина
└─ ОбновитьНаправлениеНаРазгрузку()
    → Для самой Р6 тоже создаёт НР (если качество принято)
```

### Шаг 6.1: Перепровести ЛА для Р6

1. Открыть ЛА для Р6

**Что должно произойти автоматически:**
- Система видит что Р6 = Первое ТС (`ЭтоПерваяРегистрацияТСПоставщика`)
- Анализирует качество всех заблокированных ТС (Р1-Р5)

- Устанавливает `Разблокировано = Истина` в РС блокировок

## Возможные проблемы и решения

### Проблема: ЛА не проводится / ошибка при проведении

**Причина:** Незаполненные обязательные реквизиты.
**Решение:** Проверить заполнение всех реквизитов шапки + ТЧ КачественныеПоказатели.

### Проблема: Блокировки не создаются (0 записей в РС)

**Чеклист:**
1. ФО `гкс_ИспользоватьЗаблокированныеТС` = Да?
2. ФО `гкс_ИспользоватьУсиленныйКонтрольКачества` = Да?
3. ТипРегистрации = Приемка на регистрации?
4. Статус ЛА = Выполнен?
5. Назначение = Приемка?
6. Показатель ГМО есть в ТЧ?
7. Правило УК для Китаевка ООО + ГМО существует и активно?

### Проблема: НР не создаётся при разблокировке

**Чеклист:**
1. Баг 0.1 исправлен? (ПолучитьПоРегистрации фильтрует удалённые?)
2. НормативнаяСертификация заполнена в ЛА?
3. ЛА для Р6 — именно "Первое ТС"? (проверить РС ТранспортныеСредства)
4. `ЭтоЛабАнализДляЗаблокированныхТС()` возвращает Истина?

### Проблема: НР создан но "кривой" (без СлужебнаяНоменклатура)

**Причина:** НормативнаяСертификация пуста -> СлужебнаяНоменклатура не определяется.
**Решение:** Убедиться что НормативнаяСертификация заполнена в Фазе 3.
