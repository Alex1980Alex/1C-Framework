## Пункты ТЗ (дословно)

> **Преамбула:** Как сейчас При проведении Лаб. анализа, если качество принято, то создается Направление на разгрузку. БЕЗ включенной ФО Заблокированных ТС принцип создания Направления на разгрузку должен оставаться тот же.

> **П.1:** При проведении ЛА приемка на ТС, если регистрация не заблокировалась по правилу Первого ТС или Группы ТС, то автоматом создаем направление на разгрузку

> **П.2:** При проведении ЛА промежуточного композита на группу или ЛА приемка первого ТС(по УК), если Качество принято по УК для всех заблокированных ТС у которых итоговое качество принято формируем Направление на разгрузку, если оно еще не создано.

> **П.3:** При проведении ЛА единичный / промежуточной композит по УК, если Регистрация разблокирована и итоговое Качество принято

> **Примечание:** Для отработки вычисления в ЛА заблокированных ТС при проведении ЛА создана процедура СформироватьСостоянияРегистацииДляЗаблокированныхТС(). Опираться на нее для дальнейших доработок.

### Условие: ЭтоЛабАнализДляЗаблокированныхТС() [стр. 723-729]

Возвращает Истина если выполнено ОДНО из:
1. **Назначение = Приемка** И **ЭтоПерваяРегистрацияТСПоставщика** (первое ТС по УК)

### Полная цепочка создания блокировок (подтверждено тестами 10.03.2026)

**Этап 1: Регистрация ТС при проведении ФНП**
1. ФНП.ПередЗаписью → `ЗарегистрироватьТранспортноеСредствоДляУсиленногоКонтроля(Отказ, РежимЗаписи)` [стр. 300-315]
2. **Условие**: `ТребуетсяРегистрацияДляУсиленногоКонтроля()` [стр. 329-340] = `ТипПробы = Единичная И ТипРегистрации = Приемка`
3. Если условие выполнено → вызывает `гкс_ВходнойКонтрольКачества.ЗарегистрироватьТранспортноеСредствоДляУсиленногоКонтроля(ДокументРегистрации, МестнаяДата)` [стр. 8-60]
4. Результат: запись в **РС гкс_ТранспортныеСредстваПоставщикаУсиленногоКонтроля** с флагом `ЭтоПервоеТС`

**Этап 2: Создание блокировок при проведении ЛА**
1. ЛА.ОбработкаПроведения → `ЗаполнитьРегистрЗаблокированныеРегистрацииПЛК(Отказ)` [стр. 548-559]
2. **Guard**: `ТребуетсяЗаблокированныеТСЛабАнализа()` [стр. 671-680]
3. Guard проверяет: `ПолучитьФункциональнуюОпцию("гкс_ИспользоватьЗаблокированныеТС") И ТребуетсяУсиленныйКонтрольЛабАнализа()`
4. **`ТребуетсяУсиленныйКонтрольЛабАнализа()`** [стр. 657-664] = `ФО ВКЛ И **Статус = Выполнен** И ЭтоПриемкаПромежуточныйКомпозит()`
5. Если всё выполнено → создаёт записи в РС блокировок

### Как записи попадают в РС блокировок

1. При проведении ЛА вызывается `ЗаполнитьРегистрЗаблокированныеРегистрацииПЛК()`
2. Процедура проверяет правила УК из `гкс_НастройкиУсиленногоКонтроляКачества`
3. Если ТС попадает под правило (Первое ТС / Группа ТС) -- создаёт запись в РС:
   - ДокументРегистрации = текущая регистрация
   - Показатель = показатель из правила
   - БлокирующаяРегистрация / БлокирующаяГруппаТС = по типу правила
   - Разблокировано = Ложь
4. **Записи НЕ создаются вручную** -- только механизмом проведения ЛА

### Порядок разблокировки

1. ЛА проводится с `Назначение = ПромежуточныйКомпозит` (на группу) или `Приёмка первого ТС`
2. `СформироватьВспомогательныеДанныеДляЗаблокированныхТС()` анализирует качество
3. Если качество принято -- устанавливает `Разблокировано = Истина`

## Обнаруженные особенности COM/OneScript

| Проблема | Решение |
|----------|---------|
| `Строка()` на ссылочном объекте → "COMОбъект" | Использовать `.Наименование` для справочников |
| `Строка()` на перечислении → "COMОбъект" | Использовать `ПРЕДСТАВЛЕНИЕ()` в запросах |
| Модуль с `ВнешнееСоединение=Нет` невидим через COM | Включить флаг в конфигураторе → Обновить БД |
| `Соединение.NewObject("Дата", 2026, 3, 10)` → ошибка параметров | COM Date constructor не поддерживает 3 параметра из OneScript |
| `Функция` внутри исполняемого кода → ошибка `Ожидается EndOfText` | OneScript не поддерживает inline функции — только верхний уровень |
| Поля ЛА с префиксом `гкс_` | `гкс_ДокументРегистрации`, `гкс_НазначениеИспользованияКачества`, `гкс_ВидПеревозки` |
| Справочник показателей | `гкс_ПоказателиКачестваWarehouse` (НЕ `ПоказателиКачества`) |
| `БлокирующаяРегистрация.Номер` → "COMОбъект" для некоторых записей | Вероятно, ссылка на ГруппуТС вместо регистрации |
| `ДополнительныеСвойства` документа = COMОбъект через COM | Стандартное свойство платформы (Соответствие), но OneScript видит как COMОбъект. Присвоение `NewObject("Соответствие")` не помогает — серверный код падает на итерации. **БЛОКЕР для проведения КАУТ-009275** |
| LEFT JOIN с NULL → "COMОбъект" | COM не возвращает NULL для пустых ссылок — всё выглядит как COMОбъект. Решение: INNER JOIN + NOT IN subquery |

### Анализ ошибки ДополнительныеСвойства (строка 602 МодульОбъекта)

**Диагноз:** `ДополнительныеСвойства` документа — стандартное свойство платформы 1С (Соответствие). Присвоение нового Соответствия через COM не помогает — серверный код, вероятно, использует внутреннее состояние, которое COM не контролирует.
