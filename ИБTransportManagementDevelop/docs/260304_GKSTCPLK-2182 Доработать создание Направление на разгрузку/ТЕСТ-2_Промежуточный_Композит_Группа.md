# ТЕСТ-2: ЛА Промежуточный композит / Первый ТС по УК — разблокированные ТС

**Дата:** 2026-03-12
**База:** Srvr="KOMPUTER";Ref="TestDB"
**Требование п.2:** При проведении ЛА промежуточного композита на группу или ЛА приемка первого ТС (по УК), если Качество принято по УК для всех заблокированных ТС у которых итоговое качество принято — формируем Направление на разгрузку, если оно ещё не создано.

## Предусловия

| Параметр | Значение |
|---|---|
| ФО `гкс_ИспользоватьЗаблокированныеТС` | Должна быть **ВКЛЮЧЕНА** |
| ФО `гкс_ИспользоватьУсиленныйКонтрольКачества` | Должна быть **ВКЛЮЧЕНА** |

## Логика (из кода)

```
ОбработкаПроведения
  → СформироватьВспомогательныеДанныеДляЗаблокированныхТС(Отказ)
    → Guard: ТребуетсяЗаблокированныеТСЛабАнализа() = Истина
    → ЭтоЛабАнализДляЗаблокированныхТС():
        (ЭтоПриемка И ЭтоПерваяРегистрацияТСПоставщика)        ← первый ТС по УК
        ИЛИ (ЭтоПромежуточныйКомпозит И ЭтоФормированиеНомераПроб)  ← промеж. композит на группу
    → гкс_ВходнойКонтрольКачества.ЗаписатьСостоянияРегистрацииЗаблокированныхТС()
      → наполняет ДанныеДляРазгрузкиРазблокированныхТС (ТаблицаЗначений)
    → СформироватьНаправленияНаРазгрузкуДляРазблокированныхТС()
      → Цикл по ДанныеДляРазгрузки:
        → СформироватьНаправлениеНаРазгрузкуПриНеобходимости(
            СтрокаДанные.ДокументРегистрации, ..., , Истина)  ← ПропуститьПроверкуБлокировки
          → Guard блокировки ПРОПУЩЕН (Истина)
          → Guard РегистрацияРазблокированаБезПринятогоКачества ПРОПУЩЕН (Истина)
          → СформироватьНаправлениеНаРазгрузку() — СОЗДАНИЕ НР
```

## Анализ процедуры `ЗаписатьСостоянияРегистрацииЗаблокированныхТС`

### Общая информация

**Файл:** `src/CommonModules/гкс_ВходнойКонтрольКачества/Ext/Module.bsl`, строка 626

**Сигнатура:**
```bsl
Процедура ЗаписатьСостоянияРегистрацииЗаблокированныхТС(
    ЛабораторныйАнализ,        // ссылка на текущий проводимый ЛА
    ДокументРегистрации,        // регистрация текущего ЛА (первый ТС или ФНП группы)
    ДанныеДляРазгрузкиРазблокированныхТС  // выходной параметр — ТаблицаЗначений
) Экспорт
```

**Параметры запроса:**
- `&ЛабораторныйАнализ` — ссылка на текущий ЛА
- `&ДокументРегистрации` — регистрация текущего ЛА (первый ТС или ФНП)
- `&Пользователь` — текущий пользователь
- `&СписокСостоянийКачества` — [КачествоНеПринято, РезультатыПробПолучены, КачествоПринято]
- `&КомментарийЗаблокированныеТС` — "Лабораторный анализ по заблокированным ТС"

Запрос — пакетный, 9 временных таблиц. Два выходных результата:
- `СостонияРегистрацииТаблицаДвижений` → передаётся в `ЗаписатьДанныеПоРегистрацииНаПЛК()` (запись движений)
- `ЗаблокированныеТСКачествоПринято` → возвращается через параметр `ДанныеДляРазгрузкиРазблокированныхТС`

### Пошаговый разбор пакетного запроса (9 таблиц)

#### Таблица 1: `ЗаблокированныеТС` — найти ВСЕ заблокированные ТС текущего ЛА

Два ОБЪЕДИНИТЬ:

**Часть А — по правилу Первого ТС** (строки 918-925):
```sql
ВЫБРАТЬ ДокументРегистрации
ПОМЕСТИТЬ ЗаблокированныеТС
ИЗ гкс_ЗаблокированныеРегистрацииУсиленныйКонтроль
ГДЕ БлокирующаяРегистрация = &ДокументРегистрации  -- я первый ТС, кого я заблокировал?
  И НЕ Разблокировано                               -- только ещё заблокированные
```

Смысл: «Я — первый ТС поставщика. Ищу все регистрации, которые я заблокировал и которые ещё НЕ разблокированы.»

**Часть Б — по правилу Группы ТС** (строки 929-939):
```sql
ОБЪЕДИНИТЬ ВСЕ
ВЫБРАТЬ ДокументРегистрации
ИЗ ФормированиеНомераПробы.СписокРегистраций   -- регистрации из ФНП
  СОЕДИНЕНИЕ СоставГруппТранспорта             -- находим группу ТС по регистрации
  СОЕДИНЕНИЕ ЗаблокированныеРегистрации        -- кто заблокирован этой группой
ГДЕ ФНП.Ссылка = &ДокументРегистрации          -- текущий ЛА = промеж. композит на группу
  И НЕ Разблокировано
```

Смысл: «Я — промежуточный композит на группу. Через ФНП нахожу свою группу ТС. По группе ищу заблокированных, ещё не разблокированных.»

**Результат:** список `ДокументРегистрации` — все ТС, заблокированные текущим первым ТС или группой.

#### Таблица 2: `ПоказателиЗаблокированныхТС` — собрать показатели качества

Два ОБЪЕДИНИТЬ:

**Часть А** (строки 943-953): фактические показатели **приёмки** заблокированных ТС
```sql
ВЫБРАТЬ ДокументРегистрации, Показатель, СоответствуетНормативу, ОтклонятьКачество
ПОМЕСТИТЬ ПоказателиЗаблокированныхТС
ИЗ гкс_ФактическиеПоказателиКачества
  СОЕДИНЕНИЕ ЗаблокированныеТС
ГДЕ НазначениеИспользованияКачества = Приемка
```

Смысл: «Берём результаты приёмочных анализов для каждого заблокированного ТС»

**Часть Б** (строки 957-966): показатели **текущего ЛА** с флагом УсиленныйКонтроль
```sql
ОБЪЕДИНИТЬ ВСЕ
ВЫБРАТЬ ДокументРегистрации, Показатель, СоответствуетНормативу, ОтклонятьКачество
ИЗ гкс_ФактическиеПоказателиКачества
  СОЕДИНЕНИЕ ЗаблокированныеТС
ГДЕ УсиленныйКонтроль = Истина
  И Регистратор = &ЛабораторныйАнализ  -- показатели именно текущего ЛА
```

Смысл: «Добавляем результаты текущего промежуточного композита (который сейчас проводится)»

**Результат:** все показатели (Показатель, СоответствуетНормативу, ОтклонятьКачество) по каждому заблокированному ТС — как от его приёмки, так и от текущего ЛА.

#### Таблица 3: `КачествоПоЗаблокированнымТС` — итоговое качество каждого ТС

```sql
ВЫБРАТЬ
  МИНИМУМ(СоответствуетНормативу) КАК СоответствуетНормативу,
  МАКСИМУМ(ОтклонятьКачество) КАК ОтклонятьКачество,
  ДокументРегистрации
ПОМЕСТИТЬ КачествоПоЗаблокированнымТС
ИЗ ПоказателиЗаблокированныхТС
СГРУППИРОВАТЬ ПО ДокументРегистрации
```

Смысл:
- `МИНИМУМ(СоответствуетНормативу)` — если хоть один показатель НЕ соответствует → итог = `Ложь`
- `МАКСИМУМ(ОтклонятьКачество)` — если хоть один показатель отклоняет → итог = `Истина`

**Результат:** одна строка на каждое заблокированное ТС с итоговым качеством.

#### Таблица 4: `ДанныеЛабАнализа` — реквизиты текущего ЛА

```sql
ВЫБРАТЬ Период, ТочкаМаршрута, МестнаяДата, ВидПеревозки
ПОМЕСТИТЬ ДанныеЛабАнализа
ИЗ гкс_ЛабораторныйАнализ
ГДЕ Ссылка = &ЛабораторныйАнализ
```

Смысл: вспомогательные данные для записи движений по регистру состояний.

#### Таблица 5: `ТекущиеСостоянияРегистраций` — текущее состояние каждого заблокированного ТС

```sql
ВЫБРАТЬ ДокументРегистрации, Состояние
ПОМЕСТИТЬ ТекущиеСостоянияРегистраций
ИЗ гкс_СостоянияРегистрации.СрезПоследних(
    , ДокументРегистрации В (ВЫБРАТЬ ДокументРегистрации ИЗ ЗаблокированныеТС))
ГДЕ Состояние В (&СписокСостоянийКачества)  -- КачествоНеПринято, РезультатыПробПолучены, КачествоПринято
```

Смысл: «Какое состояние сейчас записано в регистре для каждого заблокированного ТС?» Нужно, чтобы не записывать повторно, если состояние не изменилось.

#### Таблица 6: `СостоянияРегистрацииПоЗаблокированнымТС` — вычислить НОВОЕ состояние

```sql
ВЫБРАТЬ
  ВЫБОР
    КОГДА ОтклонятьКачество      → КачествоНеПринято
    КОГДА НЕ СоответствуетНормативу → РезультатыПробПолучены
    ИНАЧЕ                          → КачествоПринято
  КОНЕЦ КАК СостояниеРегистрации,
  ДокументРегистрации
ПОМЕСТИТЬ СостоянияРегистрацииПоЗаблокированнымТС
ИЗ КачествоПоЗаблокированнымТС
```

Смысл: преобразование агрегированных показателей (Таблица 3) в конечное состояние регистрации:
- Есть «отклонять» → **КачествоНеПринято**
- Нет «отклонять», но не соответствует → **РезультатыПробПолучены**
- Всё ОК → **КачествоПринято**

#### Таблица 7: `СостоянияРегистрацииИтог` — только ИЗМЕНИВШИЕСЯ состояния

```sql
ВЫБРАТЬ ДокументРегистрации, Состояние
ПОМЕСТИТЬ СостоянияРегистрацииИтог
ИЗ СостоянияРегистрацииПоЗаблокированнымТС       -- новое состояние
  СОЕДИНЕНИЕ ТекущиеСостоянияРегистраций           -- текущее состояние
ГДЕ ТекущееСостояние <> НовоеСостояние             -- только если изменилось
```

Смысл: оптимизация — не пишем в регистр, если состояние не поменялось.

#### Таблица 8: `СостонияРегистрацииТаблицаДвижений` — данные для записи в регистр

```sql
ВЫБРАТЬ ДокументРегистрации, Состояние, Период, ТочкаМаршрута,
       МестнаяДата, ВидПеревозки, ТипРегистрации, ТранспортноеСредство,
       &Пользователь, &КомментарийЗаблокированныеТС
ИЗ СостоянияРегистрацииИтог
  СОЕДИНЕНИЕ РегистрацияНаПЛК  -- для ТипРегистрации, ТранспортноеСредство
  , ДанныеЛабАнализа           -- для периода, точки маршрута
```

**ВЫХОД №1:** передаётся в `ЗаписатьДанныеПоРегистрацииНаПЛК()` — запись движений в регистр `гкс_СостоянияРегистрации`.

#### Таблица 9: `ЗаблокированныеТСКачествоПринято` — данные для создания НР

```sql
ВЫБРАТЬ ДокументРегистрации, ЛабораторныйАнализ.Ссылка, ЛабораторныйАнализ.Дата
ИЗ СостоянияРегистрацииПоЗаблокированнымТС
  СОЕДИНЕНИЕ гкс_ЛабораторныйАнализ                      -- ищем ЛА Приёмка по этой регистрации
    ПО ДокументРегистрации = ЛА.гкс_ДокументРегистрации
    И ЛА.Назначение = Приемка
    И ЛА.Статус = Выполнен
    И ЛА.Проведен
  ЛЕВОЕ СОЕДИНЕНИЕ гкс_НаправлениеНаРазгрузку             -- проверяем нет ли уже НР
    ПО ДокументРегистрации = НР.ДокументРегистрации
    И НР.Проведен
ГДЕ НР.Ссылка ЕСТЬ NULL                                   -- НР ещё НЕ создан
  И СостояниеРегистрации = КачествоПринято                 -- итоговое качество ПРИНЯТО
```

**ВЫХОД №2:** возвращается через параметр `ДанныеДляРазгрузкиРазблокированныхТС`.

Условия попадания строки в результат:
1. Итоговое качество = **КачествоПринято** (все показатели в норме)
2. НР по этой регистрации ещё **НЕ существует** (LEFT JOIN + IS NULL)
3. Есть **проведённый ЛА Приёмка** со статусом Выполнен по данной регистрации

### Общая схема потока данных

```
ЗаблокированныеТС (кого я заблокировал? — по первому ТС или по группе)
    ↓
ПоказателиЗаблокированныхТС (какие результаты анализов? — приёмка + текущий ЛА)
    ↓
КачествоПоЗаблокированнымТС (агрегация МИНИМУМ/МАКСИМУМ по каждому ТС)
    ↓
СостоянияРегистрацииПоЗаблокированнымТС (→ КачествоПринято / НеПринято / РезультатыПолучены)
    ↓
    ├─→ СостоянияРегистрацииИтог (только изменившиеся)
    │     ↓
    │   ТаблицаДвижений → ЗаписатьДанныеПоРегистрацииНаПЛК() → ЗАПИСЬ в регистр состояний
    │
    └─→ ЗаблокированныеТСКачествоПринято (Качество=Принято И НР не существует)
          ↓
        ДанныеДляРазгрузкиРазблокированныхТС → СформироватьНаправленияНаРазгрузкуДляРазблокированныхТС()
          ↓
        Цикл: СформироватьНаправлениеНаРазгрузкуПриНеобходимости(..., , Истина) → СОЗДАНИЕ НР
```

### Пример прохождения на реальных данных

**Сценарий:** Проводится ЛА СоУТ-000053 (ПромежуточныйКомпозит) по регистрации СоУТ-0000044 (первый ТС).

1. **ЗаблокированныеТС**: Часть А находит СоУТ-0000045 (`БлокирующаяРегистрация = СоУТ-0000044`, `Разблокировано = Ложь`)
2. **ПоказателиЗаблокированныхТС**: берёт показатели приёмки СоУТ-0000045 + показатели текущего ЛА СоУТ-000053 (флаг УсиленныйКонтроль)
3. **КачествоПоЗаблокированнымТС**: `МИНИМУМ(СоответствуетНормативу)`, `МАКСИМУМ(ОтклонятьКачество)` по СоУТ-0000045
4. **СостоянияРегистрации**: допустим ОтклонятьКачество = Истина → `КачествоНеПринято`
5. **ЗаблокированныеТСКачествоПринято**: СостояниеРегистрации = КачествоНеПринято ≠ КачествоПринято → **строка НЕ попадает** → НР НЕ создаётся

Если бы все показатели были в норме → СостояниеРегистрации = КачествоПринято → строка попала бы в результат → НР создаётся.

| Показатель | Правильный UUID (из нормативов) | Неправильный UUID (тестовый дубль) |

INNER JOIN в запросе `ТекстЗапросаСлужебнаяНоменклатураДляФормированияНаправленияНаРагрузку` (строка 1757: `РезультатыНормативнойСертификацииНоменклатуры.ПоказательАнализа = ВТ_КачественныеПоказатели.ПоказательАнализа`) не срабатывал.

#### Проблема 9.1. Нет документов `гкс_ФормированиеНомераПробы` (ФНП)

РегистрацияНаПЛК → ФНП → ЛА → НР

**Эталон (СоУТ-0000043):** имеет 2 ФНП (УТ-00000050, УТ-00000051), оба с ТипПробы = Единичная.
