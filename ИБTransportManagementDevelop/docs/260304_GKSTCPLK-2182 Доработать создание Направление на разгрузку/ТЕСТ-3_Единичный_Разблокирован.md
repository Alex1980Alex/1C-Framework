## Логика (из кода)

Этот сценарий обрабатывается через новую проверку `РегистрацияРазблокированаБезПринятогоКачества()` в `СформироватьНаправлениеНаРазгрузкуПриНеобходимости()`:

```
СформироватьНаправлениеНаРазгрузкуПриНеобходимости(ДокументРегистрации, ...)
  → Guard 1: НаправлятьНаРазгрузкуРазрешение()
  → Guard 2: РегистрацияЗаблокированаДляРазгрузки()
    → Если текущий ЛА заблокирован → Возврат (НР не создаём)
  → Guard 3 (НОВЫЙ): РегистрацияРазблокированаБезПринятогоКачества(ДокументРегистрации)
    Запрос к гкс_ПоказателиУсиленногоКонтроляПоРегистрации
      СОЕДИНЕНИЕ гкс_ЗаблокированныеРегистрацииУсиленныйКонтроль
    ГДЕ НазначениеИспользования = ПромежуточныйКомпозит
      И ТипПробы = Единичная
      И Разблокировано = Ложь
    → Если есть такие записи → Возврат (качество ещё не принято по всем единичным)
  → СформироватьНаправлениеНаРазгрузку() — СОЗДАНИЕ НР
```

**Суть:** Единичный ЛА по УК проходит через основной вызов из `ОбработкаПроведения` (строка 161), а НЕ через цикл разблокированных. Новая проверка Guard 3 блокирует создание НР если по данной регистрации есть ещё не разблокированные записи с единичными пробами.

## Особенности реализации

1. **Guard 3 (`РегистрацияРазблокированаБезПринятогоКачества`)** — новая функция в `гкс_ВходнойКонтрольКачества`:
   - Проверяет только записи с `НазначениеИспользования = ПромежуточныйКомпозит` и `ТипПробы = Единичная`
   - Если хотя бы одна запись `Разблокировано = Ложь` → блокирует создание НР
   - Если все разблокированы → пропускает

2. **Разница с Guard 2**: Guard 2 проверяет модульную переменную `гкс_ДокументРегистрации` (текущий ЛА). Guard 3 проверяет переданный параметр `ДокументРегистрации` по запросу к регистрам.

3. **Флаг `ПропуститьПроверкуБлокировки = Истина`**: при вызове из цикла разблокированных ТС (Тест-2) оба Guard-а 2 и 3 пропускаются — данные уже проверены в `ЗаписатьСостоянияРегистрацииЗаблокированныхТС`.
