# ANALYSIS-REPORT: Заблокированные ТС по правилу Первого ТС (подзадача 5)

## Описание проблемы

При интерактивном создании "Направления на разгрузку" для заблокированного ТС (по правилу "Первое ТС") система не видит, что сделан единичный/промежуточный композит анализ, и не даёт создать документ. Дополнительно возникает runtime-ошибка при проведении ЛабораторногоАнализа.

## Найденные баги

### BUG #1 (CRITICAL): Неверный параметр в `РазблокироватьРегистрациюНаПЛК`

**Файл**: `src/Documents/гкс_ЛабораторныйАнализ/Ext/ObjectModule.bsl:778` ✓ get_metadata

**Суть**: Функция `РазблокироватьРегистрациюНаПЛК()` передаёт `гкс_ДокументРегистрации` (тип `ДокументСсылка.гкс_РегистрацияНаПЛК`) в метод `ЭтоПромежуточныйКомпозит()`, который ожидает `ПеречислениеСсылка.гкс_НазначенияИспользованияКачества`.

**Было**:
```bsl
И Перечисления.гкс_НазначенияИспользованияКачества.ЭтоПромежуточныйКомпозит(гкс_ДокументРегистрации);
```

**Стало**:
```bsl
И Перечисления.гкс_НазначенияИспользованияКачества.ЭтоПромежуточныйКомпозит(гкс_НазначениеИспользованияКачества);
```

**Последствия бага**: Сравнение ссылки на документ с перечислением ВСЕГДА возвращает `Ложь`. Функция `РазблокироватьРегистрациюНаПЛК()` никогда не возвращает `Истина`, поэтому `ОбновитьБлокировкуТекущейРегистрации()` никогда не вызывается при проведении промежуточного композита. Записи блокировки в РС `гкс_ЗаблокированныеРегистрацииУсиленныйКонтроль` не обновляются, ТС остаётся заблокированным навсегда.

**Цепочка вызовов**:
1. `ОбработкаПроведения` (ObjectModule:152) → `гкс_ПроведениеДокументов.ОбработкаПроведенияДокумента`
2. → `ЗаполнитьРегистрЗаблокированныеРегистрацииПЛК` (ObjectModule:548)
3. → `РазблокироватьРегистрациюНаПЛК()` (ObjectModule:773) — **возвращает Ложь из-за бага**
4. → `ОбновитьБлокировкуТекущейРегистрации` (ObjectModule:555) — **никогда не вызывается**

**Статус**: ИСПРАВЛЕНО

### BUG #2 (RUNTIME): Поле не найдено "ВТ_ВсеПоказатели.УчитыватьОтклонение"

**Файл**: `src/Documents/гкс_ЛабораторныйАнализ/Ext/ManagerModule.bsl`

**Ошибка при проведении**:
```
{(29, 21)}: Поле не найдено "ВТ_ВсеПоказатели.УчитыватьОтклонение"
```

**Анализ**: Поле `УчитыватьОтклонение` добавлено в рамках задачи GKSTCPLK-2182 в три места:
1. `ТекстЗапросаРасчетаСостоянияЛабАнализаЗаблокированныеТС()` (строка 597) — создание `ВТ_ВсеПоказатели` для ветки заблокированных ТС
2. `ТекстЗапросаРасчетаСостоянияЛабАнализа()` (строка 700) — создание `ВТ_ВсеПоказатели` для обычной ветки
3. `ТекстЗапросаВТПоказателиНеСоответствующиеНормативу()` (строка 913) — ссылка на `ВТ_ВсеПоказатели.УчитыватьОтклонение`

**Код в репозитории корректен** — все три изменения согласованы. Ошибка возникает на сервере из-за **неполного развёртывания**: ссылка на поле (п.3) была развёрнута, а создание поля в запросе (п.1 или п.2) — нет.

**Механизм ошибки**:
- `РассчитатьСостояниеЛабАнализа()` (строка 502) создаёт `ВТ_ВсеПоказатели` через `Запрос.Выполнить()` — таблица сохраняется в `МенеджерВременныхТаблиц` (строка 477)
- Пакетный запрос (строка 1436 `гкс_ПроведениеДокументов`) ссылается на `ВТ_ВсеПоказатели.УчитыватьОтклонение`
- Если на сервере старая версия создающего запроса (без `УчитыватьОтклонение`), а новая версия ссылающегося запроса — ошибка

**Решение**: Развернуть ВСЕ изменения `ManagerModule.bsl` целиком. Код в репозитории исправен.

**Статус**: ПРОБЛЕМА РАЗВЁРТЫВАНИЯ (код в репо корректен)

### Открытый вопрос: фильтр в `ПроверитьБлокировкуДляСозданияНнР`

**Файл**: `src/CommonModules/гкс_ВходнойКонтрольКачества/Ext/Module.bsl:2183`

Временная таблица `ВТ_КомпозитПоПоказателям` фильтрует записи по условию `СостояниеКачества = КачествоПринято`. Если результат анализа заблокированного ТС — не `КачествоПринято` (а, например, `РезультатыПробПолучены`), то композит не будет найден в таблице и система не даст создать НнР.

**Вопрос бизнесу**: Достаточно ли факта наличия анализа для разблокировки, или обязательно `КачествоПринято`?
