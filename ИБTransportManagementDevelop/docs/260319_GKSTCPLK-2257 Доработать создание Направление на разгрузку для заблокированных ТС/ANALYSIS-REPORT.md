# GKSTCPLK-2257 Доработать создание Направление на разгрузку для заблокированных ТС

## 1. Описание задачи

### 1.1 Требования

При включённой ФО `гкс_ИспользоватьЗаблокированныеТС` формирование документа «Направление на разгрузку» (НнР) должно работать по следующим правилам:

1. **БЕЗ ФО** — поведение не меняется (как сейчас)
2. **ЛА Приемка на ТС** — если регистрация НЕ заблокировалась по правилу Первого ТС или Группы ТС → автоматом создаём НнР
3. **ЛА промежуточного композита на группу / ЛА приемка первого ТС (по УК)** — если качество принято по УК для всех заблокированных ТС, у которых итоговое качество принято → формируем НнР (если ещё не создано)
4. **ЛА единичный / промежуточный композит по УК** — если регистрация разблокирована И итоговое качество принято → формируем НнР

### 1.2 Суть проблемы

Текущая логика `СформироватьНаправлениеНаРазгрузкуПриНеобходимости` (ObjectModule, стр. 630-654) **всегда** блокирует создание НнР для заблокированных ТС через проверку `РегистрацияЗаблокированаДляРазгрузки()` (стр. 637). Даже когда `СформироватьВспомогательныеДанныеДляЗаблокированныхТС` (стр. 706) определила, что качество принято и ТС должен быть разблокирован, вызов `СформироватьНаправленияНаРазгрузкуДляРазблокированныхТС` → `СформироватьНаправлениеНаРазгрузкуПриНеобходимости` снова натыкается на эту проверку.

### 3.2 Корневая причина

`СформироватьНаправлениеНаРазгрузкуПриНеобходимости` (стр. 637) вызывает `РегистрацияЗаблокированаДляРазгрузки()`, которая запрашивает `гкс_ЗаблокированныеРегистрацииУсиленныйКонтроль` с условием `НЕ Разблокировано`. Для заблокированных ТС, у которых качество принято (из запроса `ЗаблокированныеТСКачествоПринято`), эта проверка **всегда возвращает Истина**, потому что:

1. `ЗаписатьСостоянияРегистрацииЗаблокированныхТС` записывает **состояния регистрации**, но **не разблокирует** записи в регистре `гкс_ЗаблокированныеРегистрацииУсиленныйКонтроль`
2. Разблокировка происходит **позже** в `ЗаполнитьЗаблокированныеРегистрацииУсиленныйКонтроль` (стр. 720), но к этому моменту `СформироватьНаправленияНаРазгрузкуДляРазблокированныхТС` уже завершилась

### 3.3 Найденные паттерны в конфигурации

- Запрос `ЗаблокированныеТСКачествоПринято` (стр. 1270-1287) уже корректно отбирает ТС с `СостояниеРегистрации = КачествоПринято` и без существующего НнР (`НаправлениеНаРазгрузку.Ссылка ЕСТЬ NULL`)
- Процедура `СформироватьНаправленияНаРазгрузкуДляРазблокированныхТС` (стр. 725) уже содержит цикл для создания НнР по данным из запроса
- `гкс_ПриемкаТранспорта.СформироватьНаправлениеНаРазгрузку` (стр. 1232) — штатная процедура создания НнР, проверяет `ПолучитьПоРегистрации` (не создаёт дубли)

## 4. План изменений

### Точка модификации 1: Пропускать проверку блокировки для разблокированных ТС

- **Файл**: `Documents/гкс_ЛабораторныйАнализ/Ext/ObjectModule.bsl`
- **Метод**: `СформироватьНаправленияНаРазгрузкуДляРазблокированныхТС` (стр. 725-735)
- **Действие**: вызывать `гкс_ПриемкаТранспорта.СформироватьНаправлениеНаРазгрузку` напрямую, минуя проверку `РегистрацияЗаблокированаДляРазгрузки`
- **Образец**: `СформироватьНаправлениеНаРазгрузкуПриНеобходимости` (стр. 652) — вызывает `гкс_ПриемкаТранспорта.СформироватьНаправлениеНаРазгрузку`
- **Код**:
```bsl
// Было (стр. 725-735):
Процедура СформироватьНаправленияНаРазгрузкуДляРазблокированныхТС(ДанныеДляРазгрузкиРазблокированныхТС)

    // Формируем направления для разгрузки для тех заблокированных ТС, у которых состоние регистрации = Качество принято
    Для каждого СтрокаДанные из ДанныеДляРазгрузкиРазблокированныхТС цикл

        СформироватьНаправлениеНаРазгрузкуПриНеобходимости(
            СтрокаДанные.ДокументРегистрации, СтрокаДанные.ЛабораторныйАнализ, СтрокаДанные.Дата);

    КонецЦикла;

КонецПроцедуры

// Стало:
Процедура СформироватьНаправленияНаРазгрузкуДляРазблокированныхТС(ДанныеДляРазгрузкиРазблокированныхТС)

    // GKSTCPLK-2257: Формируем направления для разгрузки разблокированных ТС.
    // Проверка РегистрацияЗаблокированаДляРазгрузки не нужна —
    // данные уже отфильтрованы запросом (качество принято, НнР нет).
    Для каждого СтрокаДанные из ДанныеДляРазгрузкиРазблокированныхТС Цикл

        Если Не гкс_ПриемкаТранспорта.НаправлятьНаРазгрузкуРазрешение(СтрокаДанные.ДокументРегистрации) Тогда
            Продолжить;
        КонецЕсли;

        гкс_ПриемкаТранспорта.СформироватьНаправлениеНаРазгрузку(
            СтрокаДанные.Дата, СтрокаДанные.ДокументРегистрации, СтрокаДанные.ЛабораторныйАнализ);

    КонецЦикла;

КонецПроцедуры
```
- **Эффект**: для ТС из `ДанныеДляРазгрузкиРазблокированныхТС` (запрос уже гарантирует КачествоПринято + нет НнР) создаётся НнР напрямую, без ложной проверки блокировки

## 5. Чек-лист верификации

- [ ] Без ФО `гкс_ИспользоватьЗаблокированныеТС` — поведение не изменилось
- [ ] ЛА Приемка, ТС не заблокировалось → НнР создаётся автоматически (как раньше, стр. 155-156)
- [ ] ЛА Приемка, ТС заблокировалось → НнР **не** создаётся (стр. 637, `РегистрацияЗаблокированаДляРазгрузки`)
- [ ] ЛА промежуточного композита/первого ТС → для разблокированных ТС с КачествоПринято → НнР создаётся
- [ ] НнР не дублируется (запрос `ЗаблокированныеТСКачествоПринято` фильтрует `НнР.Ссылка ЕСТЬ NULL` + `ПолучитьПоРегистрации` в `СформироватьНаправлениеНаРазгрузку`)
- [ ] `НаправлятьНаРазгрузкуРазрешение` проверяется для каждого ТС

## 6. Риски и открытые вопросы

1. **Проверка `НазначатьНаСкладыПоПараметрам`**: в текущем коде `СформироватьНаправлениеНаРазгрузкуПриНеобходимости` (стр. 632) проверяет `НазначатьНаСкладыПоПараметрам(ДопПараметры)`. При вызове из `СформироватьНаправленияНаРазгрузкуДляРазблокированныхТС` `ДопПараметры = Неопределено`, поэтому эта проверка не срабатывает. В новом коде это поведение сохранено
2. **Взаимодействие с табло/кверион**: на скриншотах ТЗ помечено `??? Взаимодействие с кверион/табло` — требует уточнения (не влияет на создание НнР)
3. **Ограничение из ТЗ**: «Требуется доработка с переходом на новый регистр По Фактическим пробам» — упомянуто в таблице для сценариев КачествоПринято УК. Это может быть отдельная задача

## 7. Тест-план

### Сценарий 1: Без ФО (регрессия)
1. Отключить ФО `гкс_ИспользоватьЗаблокированныеТС`
2. Создать регистрацию → ФНП → ЛА Приемка (Качество принято)
3. Проверить: НнР создался автоматически

### Сценарий 2: С ФО, ТС не заблокировалось
1. Включить ФО
2. Регистрация → ФНП → ЛА Приемка (Качество принято), правило УК не подобралось
3. Проверить: НнР создался автоматически

### Сценарий 3: С ФО, ТС заблокировалось, затем качество принято по УК
1. Включить ФО
2. Регистрация 1 (первое ТС) → ФНП → ЛА Приемка → заблокировалось
3. НнР **не** создался
4. Регистрация 2 (группа) → ФНП → ЛА промежуточного композита → качество принято
5. Проверить: НнР создался для регистрации 1

### Сценарий 4: С ФО, ТС заблокировалось, качество НЕ принято
1. Тот же flow, но ЛА промежуточного композита → качество не принято
2. Проверить: НнР **не** создался

## 8. Резюме

**Причина**: `СформироватьНаправленияНаРазгрузкуДляРазблокированныхТС` вызывает `СформироватьНаправлениеНаРазгрузкуПриНеобходимости`, которая повторно проверяет блокировку — а ТС ещё не разблокировано в регистре на момент вызова.

**Решение**: 1 точка модификации — вызывать `гкс_ПриемкаТранспорта.СформироватьНаправлениеНаРазгрузку` напрямую для ТС из таблицы `ДанныеДляРазгрузкиРазблокированныхТС` (данные уже отфильтрованы запросом: КачествоПринято + нет НнР).

**Объём**: ~10 строк изменения в 1 процедуре 1 файла.
**Риск**: низкий — запрос `ЗаблокированныеТСКачествоПринято` гарантирует корректность отбора, дублирование НнР защищено через `ПолучитьПоРегистрации`.
