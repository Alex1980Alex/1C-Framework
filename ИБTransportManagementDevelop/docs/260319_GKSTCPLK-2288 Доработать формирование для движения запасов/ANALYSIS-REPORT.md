# GKSTCPLK-2288 Доработать формирование для движения запасов

## 1. Описание задачи

### 1.1 Требования
Документ «Основание для движения запасов» помечен на удаление. При попытке системой
перезаполнить и перепровести — ошибка выполнения.

### 1.2 Суть проблемы
Запрос `ПолучитьПоРегистрации` (ManagerModule, стр. 103-128) находит документ по регистрации
**без проверки** `ПометкаУдаления`. Если документ помечен на удаление, вызывающий код пытается
его перезаполнить и провести → ошибка платформы.

## 2. Задействованные объекты конфигурации

### 2.1 Основные объекты (требуют изменения)
- `Документ.гкс_ОснованиеДляДвиженияЗапасов.ManagerModule` — 3 запроса без проверки ПометкаУдаления

### 2.2 Объекты-источники (вызывающий код, только чтение)
- `Обработка.гкс_ПриемкаТранспорта.ObjectModule` — вызывает `СформироватьДокументПоНеобходимости`
- `Документ.гкс_Взвешивание.ObjectModule` — вызывает `АктуализироватьДокументДвиженияЗапасов`
- `Документ.гкс_СРПВПеревеска.ObjectModule` — вызывает `СформироватьДокументПоНеобходимости`

## 3. Детальный анализ

### 3.1 Корневая причина

Функция `ПолучитьПоРегистрации` (стр. 107-112):
```bsl
ВЫБРАТЬ РАЗРЕШЕННЫЕ ПЕРВЫЕ 1
    ОснованиеДляДвиженияЗапасов.Ссылка КАК ДокументСсылка
ИЗ
    Документ.гкс_ОснованиеДляДвиженияЗапасов КАК ОснованиеДляДвиженияЗапасов
ГДЕ
    ОснованиеДляДвиженияЗапасов.Регистрация = &Регистрация
```
Нет условия `И НЕ ОснованиеДляДвиженияЗапасов.ПометкаУдаления`.

### 3.2 Затронутые цепочки вызовов

**Цепочка 1**: `СформироватьДокументПоНеобходимости` (стр. 38-63)
- Вызывает `ПолучитьПоРегистрации` → получает помеченный на удаление документ
- `ПолучитьОбъект()` → `Заполнить()` → `СохранитьДокумент(, , Проводить=Истина)` → ОШИБКА
- Вызывается из: `гкс_ПриемкаТранспорта`, `гкс_СРПВПеревеска`

**Цепочка 2**: `АктуализироватьДокументДвиженияЗапасов` (стр. 72-93)
- Вызывает `ПолучитьПоРегистрации` → получает помеченный на удаление документ
- `ПолучитьОбъект()` → обновляет веса → `СохранитьДокумент(, , Проведен)` → ОШИБКА
- Вызывается из: `гкс_Взвешивание.ПриЗаписи`

**Цепочка 3**: `ДокументыОснованияДляДвиженияЗапасовПоКомпозитномуЛабораторномуАнализу` (стр. 235-274)
- Вызывает `ПолучитьПоРегистрации` → включает помеченный документ в массив
- `ПерезаполнитьОснованиеДвиженияЗапасовКомпозит` → `ПолучитьОбъект()` → `ПерезаполнитьПоЛабАнализу` → ОШИБКА

**Цепочка 4**: `ДокументыОснованияДляДвиженияЗапасовПоФормированиюНомераПроб` (стр. 138-165)
- Самостоятельный запрос без проверки ПометкаУдаления (стр. 142-150)
- Есть `ОснованиеДляДвиженияЗапасов.Проведен` — частично защищает (снятый с проведения не попадёт),
  но если документ помечен на удаление и ещё проведён — попадёт

### 3.3 Найденные паттерны в конфигурации
Во всём модуле `гкс_ОснованиеДляДвиженияЗапасов.ManagerModule` **нет ни одной** проверки
`ПометкаУдаления` (0 совпадений по поиску). Это системный пропуск.

## 4. План изменений

### Точка модификации 1: ПолучитьПоРегистрации — добавить фильтр ПометкаУдаления

- **Файл**: `Documents/гкс_ОснованиеДляДвиженияЗапасов/ManagerModule.bsl`
- **Строка**: 112 (после `ОснованиеДляДвиженияЗапасов.Регистрация = &Регистрация`)
- **Действие**: добавить условие
- **Код**:
```bsl
// Было:
"ВЫБРАТЬ РАЗРЕШЕННЫЕ ПЕРВЫЕ 1
|	ОснованиеДляДвиженияЗапасов.Ссылка КАК ДокументСсылка
|ИЗ
|	Документ.гкс_ОснованиеДляДвиженияЗапасов КАК ОснованиеДляДвиженияЗапасов
|ГДЕ
|	ОснованиеДляДвиженияЗапасов.Регистрация = &Регистрация";

// Стало:
"ВЫБРАТЬ РАЗРЕШЕННЫЕ ПЕРВЫЕ 1
|	ОснованиеДляДвиженияЗапасов.Ссылка КАК ДокументСсылка
|ИЗ
|	Документ.гкс_ОснованиеДляДвиженияЗапасов КАК ОснованиеДляДвиженияЗапасов
|ГДЕ
|	ОснованиеДляДвиженияЗапасов.Регистрация = &Регистрация
|	И НЕ ОснованиеДляДвиженияЗапасов.ПометкаУдаления";
```
- **Эффект**: исправляет цепочки 1, 2, 3 одним изменением (все используют `ПолучитьПоРегистрации`)

### Точка модификации 2: ДокументыОснованияДляДвиженияЗапасовПоФормированиюНомераПроб — добавить фильтр

- **Файл**: `Documents/гкс_ОснованиеДляДвиженияЗапасов/ManagerModule.bsl`
- **Строка**: 148 (после `ОснованиеДляДвиженияЗапасов.Проведен`)
- **Действие**: добавить условие
- **Код**:
```bsl
// Было:
|		ПО ФормированиеНомераПробыСписокРегистраций.ДокументРегистрации = ОснованиеДляДвиженияЗапасов.Регистрация
|			И (ОснованиеДляДвиженияЗапасов.Проведен)

// Стало:
|		ПО ФормированиеНомераПробыСписокРегистраций.ДокументРегистрации = ОснованиеДляДвиженияЗапасов.Регистрация
|			И (ОснованиеДляДвиженияЗапасов.Проведен)
|			И (НЕ ОснованиеДляДвиженияЗапасов.ПометкаУдаления)
```
- **Эффект**: исправляет цепочку 4 (самостоятельный запрос, не использует `ПолучитьПоРегистрации`)

### Порядок выполнения
1. Точка 1 — основной фикс (покрывает 3 из 4 цепочек)
2. Точка 2 — дополнительный фикс (покрывает 4-ю цепочку)
Точки независимы, можно применять в любом порядке.

## 5. Чек-лист верификации

- [ ] `ПолучитьПоРегистрации` не возвращает помеченные на удаление документы
- [ ] `СформироватьДокументПоНеобходимости` создаёт НОВЫЙ документ если существующий помечен на удаление
- [ ] `АктуализироватьДокументДвиженияЗапасов` пропускает помеченные на удаление (Возврат на стр. 77)
- [ ] `ДокументыОснованияДляДвиженияЗапасовПоФормированиюНомераПроб` не включает помеченные
- [ ] Нет регрессии: непомеченные документы обрабатываются как раньше

## 6. Риски и открытые вопросы

1. **Дубли**: если документ помечен на удаление и вызывается `СформироватьДокументПоНеобходимости`,
   будет создан НОВЫЙ документ (старый перестанет находиться). Это корректное поведение —
   помеченный на удаление документ не должен использоваться.

2. **Данные**: на момент анализа в тестовой базе нет документов с ПометкаУдаления=Истина.
   Проблема воспроизводится на БАТМ (Белагротерминал) — скриншот с БАТМ-0025430.

## 7. Тест-план

1. Создать регистрацию на ПЛК, сформировать Основание для движения запасов
2. Пометить Основание для движения запасов на удаление
3. Вызвать перезаполнение через АРМ Приёмка транспорта → ошибки быть не должно
4. Проверить что создался новый документ Основание для движения запасов (не помеченный)
5. Провести взвешивание → `АктуализироватьДокументДвиженияЗапасов` не должен падать

## 8. Резюме

**Причина**: запрос `ПолучитьПоРегистрации` не фильтрует помеченные на удаление документы.
**Решение**: 2 точки модификации — добавить `И НЕ ПометкаУдаления` в 2 запроса.
**Объём**: 2 строки кода в 1 файле.
**Риск**: минимальный — стандартная проверка, нет изменения логики.
