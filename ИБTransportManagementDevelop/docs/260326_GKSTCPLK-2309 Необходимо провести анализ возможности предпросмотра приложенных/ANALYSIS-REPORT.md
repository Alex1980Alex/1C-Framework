# GKSTCPLK-2309 Анализ возможности предпросмотра PDF-файлов в документе "Регистрация на ПЛК"

## 1. Описание задачи

### 1.1 Требования
- [REQ-1] Проанализировать возможность предварительного просмотра PDF-документов на форме присоединённых файлов
- [REQ-2] PDF-файлы загружаются через интеграцию с 1С:Документооборотом
- [REQ-3] Предпросмотр должен работать на стандартной форме "Присоединённые файлы"

### 1.2 Суть проблемы
При выборе PDF-файла в списке присоединённых файлов документа "Регистрация на ПЛК" в области предпросмотра отображается сообщение:
> "Предпросмотр файлов этого типа не поддерживается."

Это системное сообщение формируется в процедуре `ОбновитьПредпросмотр()` формы `Обработка.ИнтеграцияС1СДокументооборот.Форма.ПрисоединенныеФайлы` (строка 1067 модуля формы).

## 3. Детальный анализ механизма

### 3.1 Текущая архитектура предпросмотра

Механизм предпросмотра построен на **трёх компонентах**:

1. **Список поддерживаемых расширений** (`РаботаСФайламиСлужебный.СписокРасширенийДляПредпросмотра()`, строка 1526):
   ```
   bmp, emf, gif, ico, icon, jpg, jpeg, png, tiff, tif, wmf
   ```
   Только форматы изображений. PDF **отсутствует**.

2. **Элемент формы `PictureField`** (ПолеКартинки) с именем `КартинкаПредпросмотра` (Form.xml, строка 738):
   - Тип: `PictureField` — может отображать **ТОЛЬКО растровые/векторные изображения**
   - Привязан к реквизиту `АдресДанныхФайла` (строка адреса во временном хранилище)
   - **PDF не является форматом изображения** — PictureField его не отобразит

3. **Процедура `ОбновитьПредпросмотр()`** (строка 1048 модуля формы):
   - Проверяет расширение файла по списку поддерживаемых
   - Если расширение в списке → получает двоичные данные из ДО через `ПолучитьФайлИПоместитьВХранилище()` → отображает в PictureField
   - Если НЕ в списке → показывает "Предпросмотр файлов этого типа не поддерживается"

### 3.2 Сравнение с формой БСП "РаботаСФайлами"

Стандартная форма БСП (`Обработка.РаботаСФайлами.Форма.ПрисоединенныеФайлы`) использует **идентичный механизм**:
- Тот же `PictureField` для предпросмотра (`АдресДанныхФайла`, Form.xml строка 1239)
- Тот же список расширений из `РаботаСФайламиСлужебный.СписокРасширенийДляПредпросмотра()`
- Тот же подход: PDF не поддерживается и в стандартной форме БСП

**Вывод**: это не баг конфигурации, а **архитектурное ограничение платформы 1С:Предприятие**.

### 3.3 Ограничения платформы 1С:Предприятие 8.3.27

| Элемент управления | Поддержка PDF | Примечание |
|---------------------|--------------|------------|
| `PictureField` (ПолеКартинки) | НЕТ | Только форматы из перечисления `ФорматКартинки`: BMP, EMF, GIF, ICO, JPEG, PNG, TIFF, WMF |
| `HTMLDocumentField` (ПолеHTMLДокумента) | Частично | Использует встроенный браузер: IE (MSHTML) на Windows. IE не рендерит PDF inline без плагинов. В веб-клиенте — зависит от браузера пользователя |
| `TextDocumentField` (ПолеТекстовогоДокумента) | НЕТ | Только текстовые файлы |
| `SpreadsheetDocumentField` (ПолеТабличногоДокумента) | НЕТ | Только табличные документы 1С |

**Платформа 1С:Предприятие не имеет встроенного рендерера PDF.**

## 4. Анализ возможных подходов

### Подход 1: Конвертация PDF → изображение на сервере (РЕКОМЕНДУЕМЫЙ)

**Описание**: На сервере 1С конвертировать первую страницу PDF в формат PNG/JPG, отображать в существующем `PictureField`.

**Плюсы**:
- Работает с существующим элементом `PictureField` — минимум изменений формы
- Работает во всех типах клиентов (толстый, тонкий, веб)
- Не требует изменений стандартных модулей БСП

**Минусы**:
- Требует внешний инструмент на сервере (Ghostscript, ImageMagick, LibreOffice)
- Отображает только первую страницу
- Нагрузка на сервер при конвертации
- Зависимость от установки стороннего ПО на сервере

**Сложность**: Средняя. Требует:
1. Установка Ghostscript или LibreOffice на сервер
2. Серверная процедура для конвертации PDF → PNG
3. Модификация `ОбновитьПредпросмотр()` — добавить ветку для PDF с конвертацией
4. Добавить "pdf" в список расширений или в отдельную проверку

### Подход 2: ПолеHTMLДокумента + PDF.js (JavaScript рендерер)

**Описание**: Заменить `PictureField` на `HTMLDocumentField`, использовать библиотеку PDF.js (Mozilla) для рендеринга PDF в HTML Canvas.

**Плюсы**:
- Полноценный предпросмотр с навигацией по страницам
- Не требует серверного ПО

**Минусы**:
- `HTMLDocumentField` в толстом/тонком клиенте на Windows использует IE (MSHTML), который **не поддерживает** современный JavaScript (ES6+) для PDF.js
- Сломает предпросмотр изображений — нужно два элемента или переключение
- В веб-клиенте зависит от браузера
- Высокая сложность реализации

**Сложность**: Высокая. **Не рекомендуется** из-за ограничений IE-движка в 1С.

### Подход 3: Открытие PDF во внешнем приложении (УЖЕ РЕАЛИЗОВАНО)

**Описание**: Кнопка "Просмотреть" уже существует на форме — вызывает `ИнтеграцияС1СДокументооборотКлиент.ОткрытьФайл()`, который скачивает файл из ДО и открывает его в системной программе для PDF.

**Плюсы**:
- Уже работает
- Полноценный просмотр в Adobe Reader / Foxit / встроенном viewer
- Нулевая сложность

**Минусы**:
- Не inline-предпросмотр (открывается в отдельном окне)
- Требуется установленный PDF-viewer на клиенте
- Каждый раз скачивает файл из ДО

**Сложность**: Нулевая — уже реализовано.

### Подход 4: Конвертация PDF → изображение через внешнюю обработку OneScript

**Описание**: Использовать OneScript + библиотеку конвертации на сервере.

**Плюсы**:
- OneScript (2.0.0) уже установлен на сервере (`C:\Tools\OneScript\bin\oscript.exe`)
- Не требует дополнительного ПО если использовать .NET-обёртку

**Минусы**:
- Сложность интеграции
- Нет готовой библиотеки в OneScript для PDF

**Сложность**: Высокая. Не рекомендуется.

### Подход 5: Улучшение UX без предпросмотра PDF

**Описание**: Вместо реального предпросмотра PDF показывать информативное сообщение + кнопку быстрого просмотра.

**Плюсы**:
- Простая реализация
- Не требует серверного ПО
- Работает во всех клиентах

**Минусы**:
- Не настоящий предпросмотр

**Реализация**: В процедуре `ОбновитьПредпросмотр()` для PDF-файлов показывать текст:
```
"Для просмотра PDF нажмите 'Просмотреть' или дважды кликните по файлу."
```
Или добавить иконку PDF-файла с кнопкой быстрого открытия.

**Сложность**: Низкая.

### Подход 6: Нативный ДокументPDF.Показать() (отдельное окно)

**Описание**: Использование встроенного объекта платформы `ДокументPDF` (доступен с 8.3.21). Вызов `Прочитать()` + `Показать()` открывает PDF во встроенном окне платформы.

**Проверено через bsl-platform-context (2026-03-30)**:
- `ДокументPDF`: методы `Прочитать()`, `Показать()`, `КоличествоСтраниц()`, свойство `Страницы` (КоллекцияСтраницPDF)
- `СтраницаPDF`: **только** свойства геометрии (Высота, Ширина, Номер, Ориентация, Поля) — **НЕТ метода конвертации в картинку**
- `ЧтениеPDF`: `Открыть()`, получение подписей/вложений — **НЕТ рендеринга**

**Вывод**: `Показать()` открывает PDF в **отдельном окне**, НЕ встраивает в `PictureField`. Нативной конвертации PDF -> картинка в платформе **НЕТ**.

**Плюсы**:
- Не требует внешних компонент или ПО на сервере
- 2-3 строки кода на клиенте
- Полноценный просмотр всех страниц

**Минусы**:
- НЕ inline-предпросмотр — открывается в отдельном окне
- Не соответствует UX-требованию (предпросмотр на форме)

**Сложность**: Очень низкая (2-3 строки).
**Вердикт**: Не подходит для inline-предпросмотра. Фактически аналогичен Подходу 3 (уже реализовано).

## 6. Риски и открытые вопросы

### Риски
1. **Подход 1 (конвертация)**: Ghostscript/LibreOffice — лицензионные ограничения, требует согласования установки на production-сервер
2. **Подход 2 (PDF.js)**: IE-движок в 1С не поддерживает ES6+ — PDF.js работать не будет в толстом/тонком клиенте
3. **Любой подход с модификацией формы ДО**: Форма `Обработка.ИнтеграцияС1СДокументооборот.Форма.ПрисоединенныеФайлы` — это типовой объект подсистемы интеграции с ДО. Изменения будут потеряны при обновлении подсистемы

### Открытые вопросы
1. Какой тип клиента используют пользователи (толстый/тонкий/веб)? — влияет на выбор подхода
2. Установлен ли Ghostscript или LibreOffice на сервере приложений?
3. Допустимо ли модифицировать типовую форму подсистемы ДО (риск при обновлении)?
4. Достаточно ли предпросмотра первой страницы PDF, или нужна навигация по страницам?
5. Рассматривается ли вариант создания отдельной кастомной формы (`гкс_ПрисоединенныеФайлыСпискаВладельцев` — уже существует) вместо модификации типовой?

## 7. Рекомендация

### Вердикт: Предпросмотр PDF на форме 1С средствами платформы **невозможен** без серверной конвертации

Платформа 1С:Предприятие 8.3.27 не содержит встроенного рендерера PDF. Элемент `PictureField` поддерживает только растровые/векторные изображения. `HTMLDocumentField` использует IE-движок, не способный отображать PDF inline.

### Рекомендуемый план действий

**Этап 1 (без разработки)**: Проинформировать пользователей о кнопке "Просмотреть", которая уже работает и открывает PDF во внешнем приложении.

**Этап 2 (при необходимости, оценка 8-16 часов)**:
- Установить Ghostscript на сервер приложений
- В расширении создать переопределение процедуры `ОбновитьПредпросмотр()` для формы ДО
- Для PDF-файлов: получить данные из ДО → конвертировать первую страницу в PNG через Ghostscript → отобразить в PictureField
- Предпросмотр будет показывать только первую страницу; для полного просмотра — кнопка "Просмотреть"

**Этап 3 (опционально)**: Если нужна кастомная форма с расширенным предпросмотром — использовать уже существующую форму `гкс_ПрисоединенныеФайлыСпискаВладельцев` как основу.

## 8. Опыт реальной интеграции: сложности и решения

### 8.1 Выбор редакции библиотеки интеграции (БИД)

**Проблема:** Существуют две редакции — БИД ред. 1.1 и БИД ред. 3. Какую ставить?

**Как определили:** В модуле `ОбновлениеИнформационнойБазыБИД` нашли обработчики обновления с версиями `1.1.6.1`, `1.1.8.4`, `1.1.12.2` — все в диапазоне 1.1.x.x. Значит в конфигурации уже стоит **ред. 1.1**, обновляем только её.

**Грабли:** На releases.1c.ru рядом лежит "Документооборот ПРОФ, ред. 3.0" — он **НЕ совместим** с БИД 1.1. ДО ред. 3.0 требует БИД ред. 3 (другой API, другой web-сервис). Нужен **ДО КОРП ред. 2.1**.

**Решение:** Скачали БИД 1.1.18.7 (обновление с 1.1.12.2) и ДО КОРП 2.1.37.5.

**Как решить в будущем:** Всегда проверяй версию БИД по модулю `ОбновлениеИнформационнойБазыБИД` → обработчики `ПерейтиНаВерсию_X_X_X_X`. Первые две цифры = редакция. БИД 1.1 → ДО 2.x, БИД 3 → ДО 3.x.

### 8.2 Развёртывание базы 1С:Документооборот

**Проблема:** БИД — это только клиентский код интеграции (аналог драйвера). Для работы нужен сам 1С:Документооборот — отдельная конфигурация, отдельная база, отдельная лицензия.

**Что сделали:**
1. Создали серверную ИБ: `1cv8.exe CREATEINFOBASE "Srvr=KOMPUTER;Ref=DocFlow;DBMS=MSSQLServer;DBSrvr=localhost;DB=docflow;DBUID=sa;DBPwd=...;CrSQLDB=Y"`
2. Загрузили конфигурацию: `1cv8.exe DESIGNER /S KOMPUTER\DocFlow /LoadCfg 1Cv8.cf`
3. Обновили БД: `1cv8.exe DESIGNER /S KOMPUTER\DocFlow /UpdateDBCfg`
4. Опубликовали на IIS: `webinst.exe -publish -iis -wsdir DocFlow -dir C:\inetpub\wwwroot\DocFlow -connstr "Srvr=KOMPUTER;Ref=DocFlow;"`

**Грабли:**
- Конфигуратор (`1cv8.exe DESIGNER`) зависает при пакетном запуске — показывает GUI-диалоги лицензии. Команды `/LoadCfg` и `/UpdateDBCfg` отработали, а `/Execute` и `/PublishInfoBase` — нет.
- Публикация через `webinst.exe` требует прав администратора. Без elevation — "Отказано в доступе".
- Ручное создание `default.vrd` + копирование `wsisapi.dll` недостаточно — IIS не настраивает ISAPI handler mapping. Только `webinst.exe` делает это корректно.

**Как решить в будущем:** Для пакетного развёртывания ДО: (1) `CREATEINFOBASE` работает надёжно, (2) `/LoadCfg` + `/UpdateDBCfg` работают, (3) публикацию делать только через `webinst.exe` с elevation, не вручную.

### 8.3 Аутентификация web-сервиса DMService

**Проблема:** После создания базы ДО web-сервис `DMService?wsdl` возвращал 402 "Неверно указан пользователь или пароль".

**Причина:** При первоначальной настройке ДО пользователь `Администратор` был создан **без флага "Аутентификация 1С:Предприятия"**. Web-сервис использует именно этот тип аутентификации (Basic Auth → 1С аутентификация). Без флага — любой пароль отклоняется.

**Дополнительная проблема:** Множество попыток ввода пароля заблокировали учётную запись ("Превышено допустимое количество ошибок при вводе"). Пришлось удалить пользователей через SQL (`DELETE FROM v8users`) и создать заново.

**Решение:** При создании пользователя в ДО обязательно установить:
- Аутентификация 1С:Предприятия = Да
- Пароль задать явно
- Роли: Полные права

**Как решить в будущем:** При создании пользователя ДО для web-сервисной интеграции **всегда** проверяй флаг "Аутентификация 1С:Предприятия". Если учётка заблокирована — удали через SQL `DELETE FROM v8users WHERE Name = 'Администратор'` в базе ДО и создай заново.

### 8.4 Корневая папка файлов

**Проблема:** При добавлении файла из TestDB ошибка: `Новый УникальныйИдентификатор(ИдентификаторКорневойПапки)` — "Недопустимое значение параметра".

**Причина:** В TestDB есть кастомная константа `ИдентификаторКорневойПапкиФайлов1СДокументооборот` (добавлена в доработке GMFM-77). Она хранит UUID папки в ДО, куда складываются файлы. В свежей базе ДО константа пустая → конструктор `УникальныйИдентификатор("")` падает.

**Решение:** Через DMService получили список папок (`DMGetObjectListRequest`, type=`DMFileFolder`), нашли папку "Входящие файлы" (ID `1bd7da21-...`), записали её UUID в константу.

**Как решить в будущем:** После развёртывания ДО: (1) открыть ДО в 1С:Предприятие, пройти мастер начальной настройки — он создаст папки, (2) через DMService получить ID нужной папки (`execute` запрос с type=`DMFileFolder`), (3) записать ID в константу `ИдентификаторКорневойПапкиФайлов1СДокументооборот`.

### 8.5 Настройка подключения в TestDB

**Что нужно заполнить в TestDB:**

| Константа / Настройка | Значение | Где заполнять |
|----------------------|----------|---------------|
| `АдресВебСервиса1СДокументооборот` | `http://KOMPUTER/DocFlow/` | Код: `Константы.АдресВебСервиса1СДокументооборот.Установить(...)` |
| `ИдентификаторКорневойПапкиФайлов1СДокументооборот` | UUID папки из ДО | Код: `Константы.Идентификатор...Установить(...)` |
| Имя пользователя ДО | `Администратор` | Форма "Настроить доступ" (ПрисоединенныеФайлы) |
| Пароль ДО | `1980` | Форма "Настроить доступ" — сохраняется в параметрах сеанса текущего пользователя |

**Важно:** Пароль хранится в параметрах сеанса **привязанных к пользователю**. Каждый пользователь TestDB должен один раз ввести логин/пароль ДО через "Настроить доступ".
