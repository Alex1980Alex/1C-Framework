# Анализ GKSTCPLK-2341: Исправить ошибки сформировать Направление на разгрузку с ручным принятием качества

**Дата:** 2026-04-03
**Задача:** ТС заблокировано предыдущей группой, в АРМ только знак УК. Пользователь может сформировать Направление на разгрузку с ручным принятием качества. Должно быть предупреждение что ТС заблокировано до получения результата по усиленному контролю.
**Вердикт:** ОШИБКА ПОДТВЕРЖДЕНА

---

## 1. Описание проблемы

ТС заблокировано в регистре `гкс_ЗаблокированныеРегистрацииУсиленныйКонтроль`, но пользователь может создать Направление на разгрузку (НР) с ручным принятием качества **без предупреждения**. При проведении НР с `ПринятьКачество = Истина` блокировка снимается.

---

## 2. Корневая причина

### Ресурс `БлокирующееСостояниеКачества` = `ПустаяСсылка()`

**Метаданные регистра `гкс_ЗаблокированныеРегистрацииУсиленныйКонтроль`:**

| Элемент | Тип | Описание |
|---------|-----|----------|
| **Измерения:** | | |
| ДокументРегистрации | ДокументСсылка.гкс_РегистрацияНаПЛК | Документ регистрации |
| Показатель | СправочникСсылка.гкс_ПоказателиАнализовНоменклатуры | Показатель |
| БлокирующаяРегистрация | ДокументСсылка.гкс_РегистрацияНаПЛК | Блокирующая регистрация |
| БлокирующаяГруппаТС | СправочникСсылка.гкс_ГруппыТС | Блокирующая группа ТС |
| **Ресурсы:** | | |
| БлокирующееСостояниеКачества | ПеречислениеСсылка.гкс_СостоянияКачества | Блокирующее состояние качества |
| Разблокировано | Булево | Разблокировано |

**Данные в базе TestDB:** Все 14 заблокированных записей имеют `БлокирующееСостояниеКачества = ПустаяСсылка()` (пустая ссылка перечисления). Это **ресурс** (не измерение), и при первичной записи в регистр он явно заполняется значением `Перечисления.гкс_СостоянияКачества.ПустаяСсылка()` — состояние качества обновляется позже через `ОбновитьСостояниеБлокировки()`.

### Функция `ПроверитьБлокировкуДляСозданияНнР` не обрабатывает пустую ссылку

**Файл:** `CommonModules/гкс_ВходнойКонтрольКачества/Ext/Module.bsl`

Функция `ПроверитьБлокировкуДляСозданияНнР` (строки 3087-3188) выполняет **пакетный запрос** из двух частей:

1. **Пакет 1** (строки 3105-3117): собирает во временную таблицу `ВТ_КомпозитПоПоказателям` показатели, по которым сделан промежуточный композит ЛА.
2. **Пакет 2** (строки 3120-3135): LEFT JOIN блокирующих записей к ВТ, формирует поля `БлокирующееСостояниеКачества` и `КомпозитСделан`.

Затем **программный обход** результата запроса (строки 3156-3183) определяет итог по **комбинации** двух полей:

```bsl
// Строка 3158 — блокировка: КачествоНеПринято БЕЗ композита
Если Выборка.БлокирующееСостояниеКачества = Перечисления.гкс_СостоянияКачества.КачествоНеПринято
    И НЕ Выборка.КомпозитСделан Тогда
    Результат.ЕстьБлокировка = Истина;    // → создание НР запрещено
    Прервать;

// Строка 3170 — предупреждение: (КачествоНеПринято ИЛИ РезультатыПробПолучены) С композитом
ИначеЕсли Выборка.КомпозитСделан
    И (Выборка.БлокирующееСостояниеКачества = Перечисления.гкс_СостоянияКачества.КачествоНеПринято
        ИЛИ Выборка.БлокирующееСостояниеКачества = Перечисления.гкс_СостоянияКачества.РезультатыПробПолучены) Тогда
    Результат.ЕстьПредупреждение = Истина; // → предупреждение, создание разрешено
    Прервать;
КонецЕсли;
```

**Матрица решений функции:**

| `БлокирующееСостояниеКачества` | `КомпозитСделан` | Результат |
|---|---|---|
| `КачествоНеПринято` | `Ложь` | `ЕстьБлокировка = Истина` (запрет) |
| `КачествоНеПринято` | `Истина` | `ЕстьПредупреждение = Истина` |
| `РезультатыПробПолучены` | `Истина` | `ЕстьПредупреждение = Истина` |
| `РезультатыПробПолучены` | `Ложь` | **Ничего** (пропуск) |
| `ПустаяСсылка()` | Любое | **Ничего** (пропуск) |

**Когда `БлокирующееСостояниеКачества = ПустаяСсылка()`** — НИ ОДНО условие не выполняется:
- `ЕстьБлокировка = Ложь` (нет запрета)
- `ЕстьПредупреждение = Ложь` (нет предупреждения)
- Результат: НР создаётся без каких-либо уведомлений

> **Примечание:** В 1С `ПустаяСсылка()` перечисления — это не `NULL` и не `Неопределено`. Это пустая ссылка типа `ПеречислениеСсылка.гкс_СостоянияКачества`, которая не равна ни одному значению перечисления.

### Почему функция `ПроверитьБлокированиеТранспортногоСредстваДляРазгрузки` работает корректно

Эта функция (строка 3002-3020) проверяет **только факт наличия незаблокированной записи**:

```bsl
ВЫБРАТЬ ПЕРВЫЕ 1
    Заблокированные.ДокументРегистрации КАК ДокументРегистрации
ИЗ
    РегистрСведений.гкс_ЗаблокированныеРегистрацииУсиленныйКонтроль КАК Заблокированные
ГДЕ
    Заблокированные.ДокументРегистрации = &ДокументРегистрации
    И НЕ Заблокированные.Разблокировано
```

Она НЕ проверяет `БлокирующееСостояниеКачества` — просто проверяет наличие записи. Поэтому корректно определяет блокировку.

## 3. Точки создания Направления на разгрузку

### Точка 1: Форма документа НР (частичная защита)

**Файл:** `Documents/гкс_НаправлениеНаРазгрузку/Forms/ФормаДокумента/Ext/Form/Module.bsl`

- `ИнициализироватьРеквизитыФормы()` (строка 288-309): вызывает `ТранспортноеСредствоЗаблокировано()`
- `ТранспортноеСредствоЗаблокировано()` (строка 432-439): вызывает `ПроверитьБлокированиеТранспортногоСредстваДляРазгрузки` → корректно определяет блокировку

**Механизм:** при обнаружении блокировки устанавливается реквизит формы `КачествоНеПринято = Истина` и заполняется `ПричинаКачествоНеПринято` (строки 294-296). Этот реквизит влияет на отображение формы — пользователь видит причину блокировки. Однако форма **не запрещает** создание документа — она информирует пользователя, который может продолжить с `ПринятьКачество = Истина`.

Дополнительно форма проверяет `ТекущийКомпозитныйАнализНеПройденПоКачеству` (строки 297-301) как второй уровень проверки.

**Статус:** Блокировка обнаруживается, но не предотвращается. Пользователь видит информацию о блокировке, но может проигнорировать.

### Точка 2: АРМ Приёмка — единичное создание (БАГ)

**Файл:** `DataProcessors/гкс_ПриемкаТранспорта/Forms/ОсновнаяФорма/Ext/Form/Module.bsl` (строки 382-407)

Вызывает `гкс_ПриемкаТранспортаВызовСервера.ПроверитьБлокировкуДляСозданияНнР` (строка 382) → при `ПустаяСсылка()` возвращает `{ЕстьБлокировка: Ложь, ЕстьПредупреждение: Ложь}` → НР создаётся без предупреждения.

Код формы корректно обрабатывает **оба** флага (строки 385-407):
- `ЕстьБлокировка` → сообщение пользователю, создание запрещено
- `ЕстьПредупреждение` ИЛИ `ТекущийКомпозитныйАнализНеПройденПоКачеству` → вопрос Да/Нет пользователю

Проблема именно в функции `ПроверитьБлокировкуДляСозданияНнР`, которая не распознаёт пустую ссылку.

**Статус:** БАГ — блокировка НЕ обнаруживается.

### Точка 3: АРМ Приёмка — групповое создание (БАГ)

**Файл:** `DataProcessors/гкс_ПриемкаТранспорта/Ext/ManagerModule.bsl` (строка 126)

Вызывает `гкс_ВходнойКонтрольКачества.ПроверитьБлокировкуДляСозданияНнР` (строки 137-138) → при `ПустаяСсылка()` возвращает `{ЕстьБлокировка: Ложь}` → молчаливое продолжение.

**Дополнительная проблема:** Функция `ГрупповоеНаправлениеНаРазгрузку` проверяет только `ЕстьБлокировка` (строки 139-141), но **не проверяет** `ЕстьПредупреждение` — предупреждения silently игнорируются даже для ненулевых значений `БлокирующееСостояниеКачества`.

> **Вопрос для уточнения:** Игнорирование `ЕстьПредупреждение` в пакетной операции может быть **осознанным дизайном** (в групповой операции нет интерактивного диалога). Необходимо уточнить у аналитика/заказчика, должна ли групповая операция пропускать регистрации с предупреждением или нет.

**Статус:** БАГ — блокировка НЕ обнаруживается. Отсутствие проверки `ЕстьПредупреждение` — потенциальный баг (требует уточнения).

### Точка 4: Программное создание через менеджер (БАГ)

**Файл:** `Documents/гкс_НаправлениеНаРазгрузку/Ext/ManagerModule.bsl`

- `СоздатьДокументНаОсновании()` (строка 82): **нет проверки** блокировки
- `СоздатьИзменитьИзАРМПриемки()` (строка 114): **нет проверки** блокировки

**Статус:** БАГ — нет вообще никакой проверки.

### Точка 5: Проведение НР — снимает блокировку

**Файл:** `Documents/гкс_НаправлениеНаРазгрузку/Ext/ObjectModule.bsl`

- `ОбработкаПроведения()` (строки 94-103): при `ПринятьКачество = Истина` И `НЕ Отказ` вызывает `РазблокироватьТСПриПринятииКачества(ДокументРегистрации)` (строки 99-101)
- `РазблокироватьТСПриПринятииКачества()` (строки 3196-3241 в `гкс_ВходнойКонтрольКачества`): находит все незаблокированные записи по регистрации, устанавливает `Разблокировано = Истина` для каждой записи через набор записей

**Статус:** Работает корректно (разблокировка при принятии качества — целевое поведение).

## 5. Варианты исправления

### Вариант A: Исправить функцию `ПроверитьБлокировкуДляСозданияНнР`

Добавить обработку пустой ссылки в программном обходе результата запроса (строки 3156-3183). Пустая ссылка перечисления означает, что анализ ещё не завершён — следует считать это предупреждением:

```bsl
// Добавить ПЕРЕД существующими условиями в цикле обхода (строка 3157):
Если НЕ ЗначениеЗаполнено(Выборка.БлокирующееСостояниеКачества) Тогда
    // Анализ ещё не завершён — ПустаяСсылка() = предупреждение
    Результат.ЕстьПредупреждение = Истина;
    Результат.ТекстСообщения = НСтр(
        "ru = 'Транспортное средство заблокировано по усиленному контролю.
        |Результаты анализа ещё не получены. Продолжить создание направления на разгрузку?'");
    Прервать;
ИначеЕсли ...  // существующие условия
```

> **Важно:** В 1С `ПустаяСсылка()` перечисления — это **не** `NULL` и **не** `Неопределено`. Проверка через `= НЕОПРЕДЕЛЕНО` в запросе **не сработает**. Корректные варианты:
> - В BSL-коде: `НЕ ЗначениеЗаполнено(Выборка.БлокирующееСостояниеКачества)`
> - В запросе: `= ЗНАЧЕНИЕ(Перечисление.гкс_СостоянияКачества.ПустаяСсылка)`

**Плюсы:** Минимальные изменения, единая точка исправления.
**Минусы:** Не решает проблему с программным созданием (точка 4).

### Вариант B: Заменить `ПроверитьБлокировкуДляСозданияНнР` на `ПроверитьБлокированиеТранспортногоСредстваДляРазгрузки`

Во всех точках вызова (АРМ) использовать простую проверку из формы НР.

**Плюсы:** Простая, проверенная логика.
**Минусы:** Теряется гранулярность (различие блокировка/предупреждение).

### Вариант C: Комбинированный (рекомендуемый)

1. Исправить `ПроверитьБлокировкуДляСозданияНнР` — добавить обработку `ПустаяСсылка()` (Вариант A)
2. Добавить проверку в `СоздатьДокументНаОсновании()` и `СоздатьИзменитьИзАРМПриемки()` (Точка 4)
3. Исправить `ГрупповоеНаправлениеНаРазгрузку` — проверять `ЕстьПредупреждение` в дополнение к `ЕстьБлокировка` (после уточнения требований — см. Точка 3)

## 6. Рекомендация

**Вариант C** — наиболее полное исправление, устраняющее все четыре точки проникновения ошибки.

### Причина пустой ссылки в `БлокирующееСостояниеКачества`

**Файл:** `InformationRegisters/гкс_ЗаблокированныеРегистрацииУсиленныйКонтроль/Ext/ManagerModule.bsl`

Функция `ЗаписатьБлокировкуТС` (строка 14) — блокировка по правилу "Первое ТС":
```bsl
// Строки 16-18 — передаётся ПустаяСсылка() перечисления
ДобавитьЗаписьБлокировки(ДокументРегистрации, Показатель, БлокирующаяРегистрация,
    Справочники.гкс_ГруппыТС.ПустаяСсылка(),
    Перечисления.гкс_СостоянияКачества.ПустаяСсылка());  // ← пустая ссылка!
```

Функция `ЗаписатьБлокировкуГруппыТС` (строка 36) — блокировка по правилу "Группа ТС":
```bsl
// Строки 39, 44, 47 — ПустоеСостояниеКачества = ПустаяСсылка()
ПустоеСостояниеКачества = Перечисления.гкс_СостоянияКачества.ПустаяСсылка();
...
ДобавитьЗаписьБлокировки(..., ПустоеСостояниеКачества);  // ← пустая ссылка!
```

**Жизненный цикл поля `БлокирующееСостояниеКачества`:**

1. **Создание блокировки** → `ПустаяСсылка()` (анализ ещё не начат)
2. **Получение результатов** → `ОбновитьСостояниеБлокировки()` (строка 67) заполняет значение:
   - `КачествоПринято` → `Разблокировано = Истина` (разблокировка)
   - `КачествоНеПринято` или `РезультатыПробПолучены` → записывает в `БлокирующееСостояниеКачества`
3. **Альтернативный путь** → `ЗаписатьБлокировкуСОтказомКачества()` (строка 106) — блокировка сразу с заполненным состоянием

**Вывод:** Обе основные функции записи блокировки передают `ПустаяСсылка()` перечисления. Это **не `NULL`** в терминах запросов 1С, а пустая ссылка типа `ПеречислениеСсылка.гкс_СостоянияКачества`. Состояние качества заполняется позже — **только** при получении результата анализа.

**Таким образом:** На момент создания НР (до завершения анализа) — состояние качества ещё не заполнено → `ПустаяСсылка()` → функция `ПроверитьБлокировкуДляСозданияНнР` не видит блокировку.

### Дополнительная проблема: `ГруппаТСТребуетБлокировки` (строки 156-163)

**Файл:** `InformationRegisters/гкс_ЗаблокированныеРегистрацииУсиленныйКонтроль/Ext/ManagerModule.bsl`

```bsl
Возврат ЗначениеЗаполнено(БлокирующаяГруппаТС)
    И Не АнализГруппыЗавершен
    И (СостояниеКачестваГруппы <> Перечисления.гкс_СостоянияКачества.КачествоНеПринято
    Или СостояниеКачестваГруппы <> Перечисления.гкс_СостоянияКачества.РезультатыПробПолучены);
```

**Логическая ошибка:** Условие `X <> A ИЛИ X <> B` **всегда `Истина`** для любого X, когда A <> B. Доказательство:
- Если X = A → первая часть `Ложь`, но вторая `Истина` (т.к. A <> B) → итог `Истина`
- Если X = B → первая часть `Истина` → итог `Истина`
- Если X = иное → обе части `Истина` → итог `Истина`

Третье условие в выражении фактически **не фильтрует ничего** — блокировка создаётся для любого незаполненного состояния, даже когда `СостояниеКачестваГруппы` уже `КачествоНеПринято` или `РезультатыПробПолучены`.

**Вероятное исправление:** `Или` → `И` (блокировка нужна если состояние не равно **ни одному** из конечных):
```bsl
    И (СостояниеКачестваГруппы <> Перечисления.гкс_СостоянияКачества.КачествоНеПринято
    И СостояниеКачестваГруппы <> Перечисления.гкс_СостоянияКачества.РезультатыПробПолучены);
```

**Статус:** Отдельная ошибка, не связанная с GKSTCPLK-2341 напрямую. Влияет на избыточное создание записей блокировки.
