# ANALYSIS-REPORT: GKSTCPLK-2307

## 1. Описание задачи

### 1.1 Требования
- **[REQ-1]** Профиль «Менеджер по закупкам» — убрать доступ на создание Графиков и Записей в очередь (переезд на Регонлайн)
- **[REQ-2]** Все профили кроме «Администратор» — убрать создание документов Графиков/Очередей (только чтение)
- **[REQ-3]** Профиль «Администратор» — оставить полные права (через роль ПолныеПрава)
- **[REQ-4]** Профиль «Менеджер по закупкам» — добавить чтение отчётов Лаборатории (Входной контроль сырья, выгрузка Excel)
- **[REQ-5]** Профиль «Менеджер по закупкам» — чтение отчётов ЭО: Анализ предварительной записи, Контроль заезда по ЭО

### 1.2 Суть проблемы
Функционал создания Графиков и Записей в очередь мигрирует на сторону сервиса **Регонлайн**. Ранее графики открывались в 1С → отправлялись в Регонлайн → поставщики брали талончики. Теперь открытие очередей и запись поставщиков происходит на стороне Регонлайна, а данные **приходят в 1С документами** через интеграцию. Пользователям 1С необходимо оставить только **просмотр** (убрать **интерактивное** создание). Дополнительно — расширить права профиля «Менеджер по закупкам» для просмотра отчётов Лаборатории и ЭО.

> **Источник**: стенограмма рабочей встречи (Диалог Оптимизация роли.md)
> Задача — часть более широкой инициативы по постепенной очистке прав доступа: «у очень многих полные права, потихоньку будем клепать задачи».

## 3. Детальный анализ механизма

### 3.1 Механизм профилей доступа

> **⚠️ КРИТИЧЕСКАЯ КОРРЕКТИРОВКА (2026-03-31):** Профили являются **поставляемыми** (supplied) — определены программно в BSL-коде. Изменения через GUI **будут перезаписаны** при следующем обновлении ИБ или восстановлении начального заполнения.

Управление правами осуществляется через `Справочник.ПрофилиГруппДоступа`, ТЧ `Роли` (ссылки на `СправочникСсылка.ИдентификаторыОбъектовМетаданных`).

**Механизм поставляемых профилей БСП:**
1. Точка входа: `УправлениеДоступомПереопределяемый.ПриЗаполненииПоставляемыхПрофилейГруппДоступа()` → делегирует в `гкс_УправлениеДоступом.ПриЗаполненииПоставляемыхПрофилейГруппДоступа()` (стр. 77)
2. Вызывается `ЗаполнитьПоставляемыеПрофилиГруппДоступа()` (стр. 218) — добавляет 17 профилей
3. Каждый профиль описан функцией `ОписаниеПрофиля*()`, которая формирует структуру через `УправлениеДоступом.НовоеОписаниеПрофиляГруппДоступа()` и наполняет массив `ОписаниеПрофиля.Роли`
4. Роли добавляются вспомогательными процедурами `ДополнитьПрофиль*()` — модульная композиция
5. При обновлении ИБ БСП **перезаписывает** ТЧ `Роли` справочника из кода → GUI-изменения теряются

**Файл реализации:** `CommonModules/гкс_УправлениеДоступом/Module.bsl` (1222 строки, 59 методов)

**Метод `ЗаменитьРолиВПрофилях`** (БСП, стр. 1778) — НЕ подходит для наших профилей: запрос явно **пропускает** поставляемые профили (`ИдентификаторПоставляемыхДанных = ПустойИдентификатор ИЛИ ПоставляемыйПрофильИзменен`). ✓ verified
