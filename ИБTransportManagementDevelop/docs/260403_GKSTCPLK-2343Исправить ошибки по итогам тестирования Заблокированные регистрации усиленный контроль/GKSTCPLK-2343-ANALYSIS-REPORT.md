## 1. Описание задачи

### 1.1 Требования

Ошибки выявлены при тестировании сценария:
- 1 ТС = "Качество принято"
- 2 ТС — входной контроль готов **до** получения результатов 1 ТС
- По регистрам 2 ТС проходит как заблокированное

**Проблема 1:** В АРМ Приёмка (список регистраций) **нет визуального признака блокировки** для 2 ТС. Видна только пиктограмма УК (жёлтый кружок), но нет знака восклицания (блокировка).

**Проблема 2:** При создании НР из АРМ для заблокированного ТС — **Силос НЕ назначается автоматически**. Форма НР открывается с пустыми полями Склад и ЯмаРазгрузки.

### 1.2 Суть проблемы

| Что сейчас | Что должно быть |
|------------|-----------------|
| Список АРМ не показывает знак блокировки для заблокированного ТС | Иконка `!` (AppearanceExclamationMarkIcon) видна в колонке `Заблокировано` |
| НР из АРМ создаётся без силоса | Силос определяется автоматически при открытии формы НР |

## 3. Детальный анализ механизма

### 3.1 Проблема 1: Колонка блокировки в списке АРМ

#### Как формируется признак блокировки в списке

**Form.xml**, строки 2730-2738 — временная таблица `ВТ_ЗаблокированныеТС`:

```sql
ВЫБРАТЬ
    ЗаблокированныеРегистрацииУК.ДокументРегистрации КАК ДокументРегистрации,
    МАКСИМУМ(НЕ ЗаблокированныеРегистрацииУК.Разблокировано) КАК Заблокирована
ПОМЕСТИТЬ ВТ_ЗаблокированныеТС
ИЗ
    РегистрСведений.гкс_ЗаблокированныеРегистрацииУсиленныйКонтроль КАК ЗаблокированныеРегистрацииУК
СГРУППИРОВАТЬ ПО
    ЗаблокированныеРегистрацииУК.ДокументРегистрации
```

Далее LEFT JOIN к основному списку (строка 2931-2932):
```sql
ЛЕВОЕ СОЕДИНЕНИЕ ВТ_ЗаблокированныеТС КАК ВТ_ЗаблокированныеТС
    ПО АРМПриемкиНаПЛКСписокРегистраций.ДокументРегистрации = ВТ_ЗаблокированныеТС.ДокументРегистрации
```

Поле в SELECT (строка 2909):
```sql
ЕСТЬNULL(ВТ_ЗаблокированныеТС.Заблокирована, ЛОЖЬ) КАК Заблокировано
```

Колонка `СписокРегистрацииЗаблокировано` (Form.xml, строки 1108-1122):
- Тип: PictureField
- Пиктограмма: `StdPicture.AppearanceExclamationMarkIcon`
- DataPath: `СписокРегистрации.Заблокировано`

Видимость (Module.bsl, строки 1205-1206):
```bsl
Элементы.СписокРегистрацииЗаблокировано.Видимость
    = ПолучитьФункциональнуюОпцию("гкс_ИспользоватьЗаблокированныеТС");
```

#### Анализ

Запрос `ВТ_ЗаблокированныеТС` **не имеет WHERE** — берёт ВСЕ записи регистра. Если в регистре есть запись с `Разблокировано = Ложь` для данной регистрации, `МАКСИМУМ(НЕ Ложь) = Истина` → иконка `!` должна отображаться.

При этом деталь-панель (функция `ЗаполнитьИнформациюОБлокировке`, строки 3978-3996) **показывает** блокировку корректно — она вызывает `ПолучитьПричинуБлокировкиДляДеталей` (строки 2133-2178), которая тоже проверяет `НЕ Разблокировано`.

#### Вероятная причина

Список формируется **при открытии формы** (DynamicDataRead = false, строка 2729). Если запись блокировки в регистре появляется **после** загрузки списка — данные устаревают. Деталь-панель выполняет запрос **при каждом клике** на строку, поэтому видит актуальные данные.

**Рекомендация:** Необходимо проверить в тестовой среде:
1. Была ли запись в регистре на момент открытия АРМ (или появилась позже)
2. Обновлялся ли список после создания записи блокировки
3. Позиция и видимость колонки `СписокРегистрацииЗаблокировано` в форме

> **Если данные были актуальны на момент загрузки** — запрос корректен и причина в отображении. Если данных не было — это не баг кода, а ожидаемое поведение, которому нужна кнопка "Обновить" или автообновление.

### 3.2 Проблема 2: Силос не назначается при создании НР из АРМ

#### Алгоритм назначения силоса

**Module.bsl**, функция `СтруктураЗаполненияДанныхНаправлениеНаРазгрузку` (строки 3785-3831):

```
ШАГ 1 (строки 3798-3803):
    Если Состояние ∈ {ВзвешенТара, КачествоПринято}
        И НЕ ПропуститьИнициализациюМестаРазгрузки
    Тогда
        Склад ← ТекущиеДанные.СкладПлан         // ← из списка АРМ!
        ЯмаРазгрузки ← ТекущиеДанные.ЯмаРазгрузки  // ← из списка АРМ!

ШАГ 2 (строки 3805-3806):
    СлужебнаяНоменклатура ← СлужебнаяНоменклатураДляФормированияНаправленияНаРагрузку(
        ТекущиеДанные.ДокументРегистрацииАнализов)

ШАГ 3 (строки 3814-3821):
    Если СлужебнаяНоменклатура заполнена
        И НЕ ПропуститьИнициализациюМестаРазгрузки
    Тогда
        ЯмаСилосРазгрузки ← ЯмаСилосРазгрузки(ТочкаМаршрута, ВидПеревозки,
            Номенклатура, СлужебнаяНоменклатура)     // ← динамическое определение!
        Склад ← ЯмаСилосРазгрузки.Силос              // перезаписывает ШАГ 1
        ЯмаРазгрузки ← ЯмаСилосРазгрузки.ЯмаРазгрузки
```

#### Допустимые состояния для назначения силоса

Функция `СостоянияПриемкиДляРазгрузки` (строки 3119-3126):
```bsl
Состояния = Новый Массив;
Состояния.Добавить(Перечисления.гкс_СостоянияРегистрации.ВзвешенТара);
Состояния.Добавить(Перечисления.гкс_СостоянияРегистрации.КачествоПринято);
```

#### Источник данных `СкладПлан` в списке

**Form.xml**, строка 2891: `АРМПриемкиНаПЛКСписокРегистраций.СкладПлан КАК СкладПлан` — берётся напрямую из источника данных АРМ.

#### Корневая причина

Для заблокированного ТС (2 ТС) в списке АРМ:

1. **ШАГ 1:** Состояние = "Качество принято" → условие выполняется. Но `ТекущиеДанные.СкладПлан` **пуст** — плановый силос не был определён для этого ТС, т.к. автоматическое создание НР не произошло из-за блокировки.

2. **ШАГ 2:** `СлужебнаяНоменклатура` не найдена — документ ЛА заблокированного ТС мог не пройти полный цикл (нет связи ФНП→ЛА для определения служебной номенклатуры).

3. **ШАГ 3:** Не выполняется (нет `СлужебнаяНоменклатура`).

**Итог:** `Склад = ПустаяСсылка()`, `ЯмаРазгрузки = ПустаяСсылка()` → НР открывается без силоса.

#### Сравнение: автоматический путь

Функция `СформироватьНаправлениеНаРазгрузку` (строки 1234-1298 в `гкс_ПриемкаТранспорта/Module.bsl`) **всегда** определяет силос динамически через `ЯмаСилосРазгрузки()`, используя `СлужебнаяНоменклатура` от ЛА. Этот путь не зависит от данных списка.
