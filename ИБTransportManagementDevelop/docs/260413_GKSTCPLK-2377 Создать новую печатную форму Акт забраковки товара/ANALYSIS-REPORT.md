# GKSTCPLK-2377 Создать новую печатную форму «Акт забраковки товара»

## 1. Описание задачи

### 1.1 Требования

- **[REQ-1]** Создать новую печатную форму «Акт забраковки товара» в документе `гкс_ЛабораторныйАнализ`.
- **[REQ-2]** За образец взять существующий макет «Акт забраковки партии» (`ПФ_MXL_АктЗабраковкиПартии_ru`).
- **[REQ-3]** На скриншоте (260413_GKSTCPLK-2377) выделены 5 текстовых блоков, которые должны быть изменены в новом макете:
  1. Заголовок: «забраковки и возврата **сырья**» → «забраковки и возврата **товара**».
  2. «Наименование вида **сырья**:» → «Наименование вида **товара**:».
  3. «**Партия масличного сырья** забракована и подлежит возврату грузоотправителю в связи с:» → «**Товар** забракован и подлежит возврату грузоотправителю в связи с:».
  4. «- обнаружением **вредителей** ГОСТ 10853-88» → «- обнаружением ГОСТ 10853-88 **зараженности**».
  5. «- несоответствием **контрактных условий**» → «- несоответствием **по качественным показателям**».
- **[REQ-4]** Блок «Основание: Идентификационный номер пробы № [НомерПробы]...» уже присутствует в актуальной версии исходного макета (`Template.xml:1618`) — изменение не требуется. Выделение на скриншоте описывает текущее состояние.
- **[REQ-5]** Новая команда печати должна быть доступна из формы приёмки транспорта (`Обработка.гкс_ПриемкаТранспорта.Форма.ОсновнаяФорма`), как это реализовано для команды «Акт забраковки».
- **[REQ-6]** Источник данных и настройки печати переиспользуются — расширения запроса и формы настроек не требуются.

### 1.2 Суть проблемы

В конфигурации есть единственный макет «Акт забраковки партии», который исторически оформлялся на масличное сырьё. Требуется аналогичная печатная форма с формулировками, применимыми к **товару** (обобщённый случай), чтобы лаборатория могла печатать её для не-масличных/неопределённых видов ТМЦ. Логика отбора данных и вывод одинаковы — меняются только текстовые константы макета.

## 6. Риски и открытые вопросы

1. **Риск: uuid-коллизия.** Повторное использование uuid от «партии» сломает метаданные. **Митигация:** сгенерировать новый (`[guid]::NewGuid()` / `uuidgen`).
2. **Риск: Form.xml id-коллизия.** Числа 916-918 заняты — перепроверить перед коммитом (`grep -oE 'id="[0-9]+"'`). **Митигация:** повторная проверка перед EDT-импортом.
3. **Вопрос:** Нужно ли в настройках печати чек-боксом выбирать «партия vs товар», или это разные кнопки меню?
   **Ответ по коду:** существующая реализация — отдельная кнопка для каждого макета (см. команды `КомандаПечатьАктОтбораПроб`, `КомандаПечатьАктОтбораПробЭкспресс`, `КомандаПечатьАктЗабраковкиПартии`). Следуем паттерну — отдельная кнопка.
4. **Вопрос:** Нужна ли локализация на английский (`_en`)? **Ответ по коду:** у «партии» нет `_en`-версии, только `_ru`. Делаем аналогично — только русский. Если позже потребуется — создать `ПФ_MXL_АктЗабраковкиТовара_en`.
5. **Вопрос:** Доступность команды по правам. Существующая `КомандаПечатьАктЗабраковкиПартии` не имеет отдельных ролей — все пользователи, видящие документ, видят кнопку. Новая команда наследует ту же модель.
6. **Открытый вопрос:** нужно ли в `Документ.гкс_ЛабораторныйАнализ.Форма.ФормаДокумента` (если есть меню печати из самого документа) также добавить команду? **Проверка:** grep не нашёл вызовов `АктЗабраковкиПартии` в форме документа — только в форме приёмки транспорта. Значит изменение формы документа **не требуется**.
