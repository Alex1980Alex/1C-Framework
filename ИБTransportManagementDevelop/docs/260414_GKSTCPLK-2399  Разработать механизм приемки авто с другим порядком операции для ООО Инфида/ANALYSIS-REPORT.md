# GKSTCPLK-2399 Разработать механизм приемки авто с другим порядком операции для ООО Инфида

## 1. Описание задачи

### 1.1 Требования

**[REQ-1]** Разработать константу (функциональную опцию) `гкс_РазрешитьВходнойКонтрольДоВзвешиванияАвто`
(тип Булево) по аналогии с уже существующей `гкс_РазрешитьВходнойКонтрольДоВзвешиванияЖД`.
Синоним: «Разрешить входной контроль до взвешивания (авто транспорт)».

**[REQ-2]** Разместить новую константу на общей форме `гкс_ОсновныеНастройки` в группе «Общие настройки»,
рядом с существующей «Разрешить входной контроль до взвешивания (ЖД транспорт)».

**[REQ-3]** Реализовать альтернативный порядок операций приёмки автотранспорта при включённой опции:
1. Регистрация транспорта → 2. **Лабораторный анализ** → 3. **Взвешивание** →
4. Распределение по силосам → 5. Взвешивание тары.
(Стандартный порядок: Регистрация → Взвешивание → Лаб. анализ → Силосы → Тара.)

**[REQ-4]** Выдать права на чтение/просмотр новой константы роли
`гкс_БазовыеПраваУправлениеТранспортомНаПЛК` и права чтения/записи роли `гкс_БазовыеПраваАналитика`
(по аналогии с правами на ЖД-константу).

**[REQ-5]** Включить константу в состав подсистемы `гкс_ФункциональныеСодружество.ПриемкаТранспорта`.

### 1.2 Scope / вне scope

**В scope:**
- Новая константа, её появление на форме настроек, права ролей, состав подсистемы.
- Расширение одной ключевой серверной функции принятия решения.

**Вне scope:**
- Переписывание АРМа приёмки транспорта — он УЖЕ параметризован и автоматически
  подхватит новый порядок (см. секцию 3.1).
- Переписывание документа `гкс_Взвешивание` — его обработчик уже использует параметризованную функцию.
- Изменение бизнес-логики формирования направления на разгрузку.

### 1.3 Суть проблемы

На конфигурации УТЭ уже реализован механизм «входной контроль до взвешивания» для ЖД транспорта.
Вся «плотная» логика (видимость кнопок в АРМ приёмки, расширение списка допустимых состояний для
отбора проб, автоформирование направления на разгрузку в модуле взвешивания) уже построена
через **одну параметризованную функцию-предикат** `гкс_ПриемкаТранспорта.РазрешитьВходнойКонтрольДоВзвешивания(ТипРегистрации, ВидПеревозки)`.

Функция принимает `ВидПеревозки` как параметр, но в текущем теле **жёстко проверяет только ЖД-ветку**.
Все вызывающие модули уже передают правильные типы перевозок (в т.ч. авто) — поэтому задача
сводится к минимальному расширению: добавить новую константу и развилку по типу перевозки внутри функции.

## 3. Детальный анализ механизма

### 3.1 Найденные паттерны в конфигурации ✓ pattern

**Паттерн 1 — параметризованная функция-предикат**. Ключевая функция уже принимает `ВидПеревозки` как параметр,
но внутри использует `ЭтоЖДПеревозка`. Это идеальная точка для расширения через `ИначеЕсли` с `ЭтоАвтоПеревозка`.
Источник: `CommonModule.гкс_ПриемкаТранспорта`, строки 1143–1152.

**Паттерн 2 — wrapper-функция с извлечением реквизитов**. Есть отдельная функция
`РазрешитьВходнойКонтрольДоВзвешиванияПоРегистрации(ДокументРегистрации)`, которая через
`ОбщегоНазначения.ЗначенияРеквизитовОбъекта` получает `ТипРегистрации, ВидПеревозки` и вызывает основную функцию.
Никаких изменений не требует — работает «из коробки» для любого типа перевозки.
Источник: `CommonModule.гкс_ПриемкаТранспорта`, строки 1102–1109.

**Паттерн 3 — реактивный реквизит формы**. Поле формы `РазрешитьВходнойКонтрольДоВзвешивания` пересчитывается
в процедуре `ИнициализироватьРеквизитыПриемкиЖД`. Эта процедура уже вызывается и из `ПриСозданииНаСервере` (строка 968),
и из обработчиков изменения `ВидПеревозкиПриИзменении` (3239) и `ТипРегистрацииПриИзменении` (3253).
Имя процедуры — misnomer (исторически): тело универсально, новое переименование **не требуется функционально**,
но рекомендуется косметически (см. п. 4, точка 8 — опционально).
Источник: `DataProcessor.гкс_ПриемкаТранспорта.Form.ОсновнаяФорма.Module`, строки 1068–1074.

**Паттерн 4 — CheckBoxField через НаборКонстант**. Форма `гкс_ОсновныеНастройки` имеет
основной реквизит `НаборКонстант` типа `ConstantsSet`. Чекбокс добавляется как `<CheckBoxField>` с
`<DataPath>НаборКонстант.{имя_константы}</DataPath>` — **декларативных изменений состава реквизитов не нужно**.
Источник: `CommonForm.гкс_ОсновныеНастройки.Form.xml`, строки 165–170, 435–443.

**Паттерн 5 — наличие enum-предиката для Авто**. В `Enum.гкс_ТипыТранспортныхСредствДоставки.ManagerModule`
уже есть экспортная функция `ЭтоАвтоПеревозка(Значение)` (строка 25–27, возвращает `Автомобиль = Значение`).
Использование гарантирует единообразие с ЖД-веткой.
Источник: `Enum.гкс_ТипыТранспортныхСредствДоставки.ManagerModule`, строки 13–27.

### 3.2 Логика решения

Минимально-инвазивная стратегия: **одна новая константа + одна развилка в одной функции**.

Вся остальная логика (форма АРМа, документ взвешивания, LIMS-интеграция) **уже параметризована**
по `ВидПеревозки` и будет автоматически переключаться через ту же функцию.

### 3.3 Псевдо-код расширения функции

```bsl
Функция РазрешитьВходнойКонтрольДоВзвешивания(ТипРегистрации, ВидПеревозки) Экспорт

    УстановитьПривилегированныйРежим(Истина);

    Если ТипРегистрации <> Перечисления.гкс_ТипРегистрации.Приемка Тогда
        Возврат Ложь;
    КонецЕсли;

    ТипыТС = Перечисления.гкс_ТипыТранспортныхСредствДоставки;

    Если ТипыТС.ЭтоЖДПеревозка(ВидПеревозки) Тогда
        Возврат Константы.гкс_РазрешитьВходнойКонтрольДоВзвешиванияЖД.Получить();
    ИначеЕсли ТипыТС.ЭтоАвтоПеревозка(ВидПеревозки) Тогда                   // GKSTCPLK-2399
        Возврат Константы.гкс_РазрешитьВходнойКонтрольДоВзвешиванияАвто.Получить(); // GKSTCPLK-2399
    КонецЕсли;

    Возврат Ложь;

КонецФункции
```

### 3.4 Обработка граничных условий

- **Только Приемка.** Функция возвращает `Ложь` для любого `ТипРегистрации ≠ Приемка` (поведение сохранено).
- **Неизвестный тип перевозки.** `Ложь` (поведение сохранено, финальный `Возврат Ложь`).
- **Константа пустая** (не установлена админом). Платформа возвращает `Ложь` для Boolean-константы по умолчанию.
- **Смена `ВидПеревозки` в АРМе.** Обработчик `ВидПеревозкиПриИзмененииНаСервере` уже перевычисляет реквизит
  формы через `ИнициализироватьРеквизитыПриемкиЖД` (строка 3239). Проблем со сменой ЖД↔Авто не будет.
- **Статусные иконки** (отдельно упомянуто в рабочем созвоне). Активные иконки в АРМе зависят от связки
  `РазрешитьВходнойКонтрольДоВзвешивания + Состояние`. Текущая логика (строки 920, 1813, 1821) корректно
  активирует кнопки «Вес на въезде» и «Номер пробы» в статусе `Прибыл`, когда опция включена — для авто
  это даст корректный ранний доступ к отбору проб до взвешивания. **Отдельного кода под авто писать не требуется.**

### 3.5 SQL-запросы

**SQL-запросов в рамках задачи нет.** Все операции — работа с константой и перечислением,
через `Константы.X.Получить()` и предикаты enum. Валидация через execute_query не требуется.

## 6. Риски и открытые вопросы

### Риски

1. **Статусные переходы автотранспорта отличаются от ЖД.** В АРМе логика состояний уже работает через
   параметр `РазрешитьВходнойКонтрольДоВзвешивания`, но тестировать нужно именно сценарий
   «авто + включена константа». В созвоне предупреждали: «нужно быть очень аккуратно со статусами,
   потому что эта обработка, она как бы активные иконки становятся в зависимости от статусов».
   **Митигация:** обязательный ручной прогон в `testdb1c` (п. 7), особенно переход из `Прибыл` → `ПробыВзяты`.

2. **Документ `гкс_Взвешивание`** автоформирует `НаправлениеНаРазгрузку` при входе на въезд, если
   `РазрешитьВходнойКонтрольДоВзвешивания = Истина` (ObjectModule строки 273–280). Для авто это поведение
   **заработает автоматически** — нужно убедиться, что документ «Направление на разгрузку» формируется корректно
   (ожидается корректно, т.к. функция `ОпределитьЛабораторныйАнализ` уже универсальна).
   **Митигация:** прогон полной цепочки авто-приёмки с включённой константой.

3. **LIMS-интеграция** (`гкс_ИнтеграцияЛИМССервер`, строки 300–305) установит даты анализа для статуса
   `ПробыВзяты` без требования `ГотовКОтборуПроб` — это ожидаемое поведение «входной контроль до взвешивания».
   Если у Инфиды LIMS не используется — риск отсутствует; если используется — требуется функциональное тестирование.

4. **Одновременное включение ЖД и Авто.** Администратор может включить обе галочки — поведение должно быть
   согласованным (каждый тип перевозки независимо). В псевдо-коде это обеспечено раздельными ветками `Если/ИначеЕсли`.

## 9. Резюме

Задача имеет **исключительно благоприятную архитектуру** для минимальной реализации:
- вся «тяжёлая» логика цепочки приёмки уже инкапсулирована в одну параметризованную серверную функцию;
