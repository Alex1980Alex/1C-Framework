**Корень проблемы:**

На строке 301 запрос пытается получить `НомерПробы` напрямую из `ДокументФормированиеНомераПробы`:

```bsl
ВТ_ПервичныеДанные.ДокументФормированиеНомераПробы.НомерПробы КАК НомерПробы
```

Но в пакете `ВТ_ПервичныеДанные` (строки 271-287):
- `ДокументФормированиеНомераПробы` — это алиас для `РегистрСведенийКомпозитныеПробы.КомпозитнаяПроба` (тип `Документ.гкс_ФормированиеНомераПробы`)
- **Нет JOIN к справочнику `гкс_НомерПробы`** для получения кода пробы
- Поэтому поле `НомерПробы` недоступно в пакете `ВТ_ПервичныеДанные`

### 3.3 Почему на закладке "по УК" работает

В запросе для "Усиленный контроль" (`ТекстЗапросаДанныеДляУсиленногоКонтроля`, строки 321+) есть правильный JOIN:

```bsl
ВЫБРАТЬ РАЗРЕШЕННЫЕ
	...
	ЕСТЬNULL(СправочникНомераПроб.Код, """") КАК НомерПробы,
	...
ПОМЕСТИТЬ ВТ_КомпозитныеПробы
ИЗ
	РегистрСведений.гкс_КомпозитныеПробы КАК КомпозитныеПробы
		ВНУТРЕННЕЕ СОЕДИНЕНИЕ ВТ_Регистрации КАК ВТ_Регистрации
		ПО ВТ_Регистрации.ДокументРегистрации = КомпозитныеПробы.ДокументРегистрации
		ВНУТРЕННЕЕ СОЕДИНЕНИЕ Документ.гкс_ФормированиеНомераПробы КАК ДокументФНП
			ЛЕВОЕ СОЕДИНЕНИЕ Справочник.гкс_НомерПробы КАК СправочникНомераПроб  ← ✅ ПРАВИЛЬНЫЙ JOIN
			ПО ДокументФНП.НомерПробы = СправочникНомераПроб.Ссылка
		ПО КомпозитныеПробы.КомпозитнаяПроба = ДокументФНП.Ссылка
```

Этот JOIN получает `Код` из справочника `гкс_НомерПробы`, который и отображается как номер пробы.
