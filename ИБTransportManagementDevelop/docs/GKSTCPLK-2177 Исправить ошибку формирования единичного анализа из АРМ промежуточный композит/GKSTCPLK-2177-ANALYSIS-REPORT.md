## 1. Описание задачи

### 1.1 Требования

1. При формировании промежуточного композита для ТС из закладки "УК для ТС" в АРМ Промежуточный композит должен создаваться как ФНП (единичная), так и ЛА (лабораторный анализ).

### 1.2 Суть проблемы

**Что сейчас:** Из АРМ Промежуточный композит, закладка "УК для ТС", при формировании промежуточного композита для ТС создаётся ФНП с типом "единичная", но **не создаётся** лабораторный анализ.

**Что должно быть:** При формировании единичной пробы из "УК для ТС" должен автоматически создаваться как ФНП, так и связанный ЛА с `НазначениеИспользования = ПромежуточныйКомпозит`.

### 1.3 Сценарий воспроизведения

1. ТС-1 зарегистрировано → ЛА Приёмка → качество НЕ принято → усиленный контроль
2. ТС-2 зарегистрировано → группа из ТС-1 и ТС-2
3. Из закладки "Усиленный контроль" (группа) → формируется **композитная** ФНП (группа) → ЛА создаётся с `НазначениеИспользования = ПромежуточныйКомпозит`
4. Из закладки "УК для ТС" (индивидуально) → формируется **единичная** ФНП для ТС-1 → ЛА **НЕ создаётся** (баг)

### 3.2 Корневая причина (Root Cause)

**Файл:** `CommonModules/гкс_ПриемкаТранспорта/Ext/Module.bsl`
**Функция:** `ОпределитьЛабораторныйАнализ()` (строка 495)
**Строки:** 541-546 (ветка `ПроверкаДляПромежуточногоКомпозита`) + запрос 2117-2131

Запрос `ТекстЗапросаЛабАнализЧерезСопоставление()` (строка 2117) ищет существующий ЛА через цепочку:

```sql
ФНП.СписокРегистраций (ДокументРегистрации = &ДокументРегистрации)
  → INNER JOIN РС.гкс_СопоставлениеФНПЛабАнализа (ФНП = ФормированиеНомераПробы)
  → INNER JOIN Документ.гкс_ЛабораторныйАнализ (ЛА = ЛабораторныйАнализ)
WHERE
  НазначениеИспользования = ПромежуточныйКомпозит
  AND NOT ПометкаУдаления
```

**Проблема:** Запрос не фильтрует по `ТипПробы` ФНП/сопоставления. Он ищет ВСЕ ФНП, содержащие данную регистрацию в `СписокРегистраций`, включая **групповые композитные** ФНП.

**Сценарий ошибки:**

| Шаг | Действие                   | ФНП               | ТипПробы        | ЛА НазначениеИспользования        |
| --- | -------------------------- | ----------------- | --------------- | --------------------------------- |
| 1   | Приёмка ТС-1               | ФНП_единичная_1   | Единичная       | Приемка                           |
| 2   | Групповой УК (ТС-1 + ТС-2) | ФНП_композитная_1 | **Композитная** | **ПромежуточныйКомпозит**         |
| 3   | Единичный УК для ТС-1      | ФНП_единичная_2   | Единичная       | должен быть ПромежуточныйКомпозит |

На шаге 3 запрос ищет: "есть ли ЛА с `ПромежуточныйКомпозит` для регистрации ТС-1?"
- Находит: ФНП_композитная_1 (содержит ТС-1 в `СписокРегистраций`) → ЛА с `ПромежуточныйКомпозит`
- Результат: **"ЛА уже существует" → новый ЛА НЕ создаётся**

Это ложное срабатывание: найденный ЛА принадлежит **групповой** пробе, а не единичной.

### 3.3 Структура РС гкс_СопоставлениеФНПЛабАнализа

| Вид       | Имя                     | Тип                                                    | Индексирован    |
| --------- | ----------------------- | ------------------------------------------------------ | --------------- |
| Измерение | ФормированиеНомераПробы | ДокументСсылка.гкс_ФормированиеНомераПробы             | Основной фильтр |
| Ресурс    | ЛабораторныйАнализ      | ДокументСсылка.гкс_ЛабораторныйАнализ                  | Да (Index)      |
| Ресурс    | **ТипПробы**            | ПеречислениеСсылка.гкс_ТипыПроб                        | Нет             |
| Ресурс    | НазначениеИспользования | ПеречислениеСсылка.гкс_НазначенияИспользованияКачества | Нет             |
| Ресурс    | УсиленныйКонтроль       | Булево                                                 | Нет             |

Ресурс `ТипПробы` уже содержит информацию о типе пробы (Единичная/Композитная) для каждой записи сопоставления. Его можно использовать в условии фильтрации запроса.

## 6. Риски и открытые вопросы

### Риски

1. **Низкий риск.** Ресурс `ТипПробы` не индексирован (Indexing=DontIndex). Для небольшого регистра это не критично для производительности.

2. **Низкий риск.** Если существуют записи сопоставления с пустым `ТипПробы` (от первоначального заполнения или ручных корректировок), условие `ТипПробы = Единичная` не найдёт их. Однако пустой `ТипПробы` не должен встречаться в корректных данных.

### Открытые вопросы

## 7. Тест-план

### Позитивные сценарии

1. **Единичная проба из "УК для ТС" — основной сценарий**
   - Предусловие: ТС зарегистрировано, ЛА Приёмка → качество не принято, ТС в составе композитной пробы (групповой ЛА с ПромежуточныйКомпозит уже существует)
   - Действие: Из АРМ → "УК для ТС" → сформировать промежуточный композит
   - Ожидание: Создаётся ФНП (единичная) И ЛА с НазначениеИспользования = ПромежуточныйКомпозит

2. **Композитная проба из "Усиленный контроль" — регрессия**
   - Предусловие: группа из нескольких ТС в усиленном контроле
   - Действие: Из АРМ → "Усиленный контроль" → сформировать промежуточный композит
   - Ожидание: Создаётся ФНП (композитная) И ЛА с НазначениеИспользования = ПромежуточныйКомпозит

3. **Обычный промежуточный композит — регрессия**
   - Действие: Из АРМ → обычная закладка → сформировать промежуточный композит
   - Ожидание: Создаётся ФНП И ЛА с НазначениеИспользования = ДополнительныйАнализ

### Негативные сценарии

4. **Повторное создание единичной пробы**
   - Предусловие: единичная ФНП и ЛА для "УК для ТС" уже созданы
   - Действие: Попытка повторного формирования промежуточного композита для того же ТС
   - Ожидание: Повторный ЛА НЕ создаётся (существующий единичный найден)

### Граничные условия

5. **Без группового УК — чистый сценарий**
   - Предусловие: ТС в усиленном контроле, но БЕЗ предшествующей групповой пробы
   - Действие: Из "УК для ТС" → сформировать промежуточный композит
   - Ожидание: ФНП и ЛА создаются корректно

## 8. Резюме

### Суть задачи
При формировании единичной пробы из закладки "УК для ТС" в АРМ Промежуточный композит создаётся ФНП, но не создаётся лабораторный анализ. Причина — запрос проверки существования ЛА не различает групповые (композитные) и индивидуальные (единичные) пробы, находит уже существующий групповой ЛА и ошибочно считает, что индивидуальный ЛА уже создан.

### Что нужно сделать
Добавить фильтр `ТипПробы = Единичная` в запрос поиска существующего ЛА для ветки "промежуточный композит". Изменения в одном файле: `гкс_ПриемкаТранспорта` (общий модуль), 3 точки модификации.

### Краткое резюме

**Корневая причина:** Запрос `ТекстЗапросаЛабАнализЧерезСопоставление()` в функции `ОпределитьЛабораторныйАнализ` (`гкс_ПриемкаТранспорта:495`) ищет существующий ЛА через `ФНП.СписокРегистраций`, но не фильтрует по `ТипПробы` (Единичная vs Композитная).

**Сценарий ошибки:** Когда ТС входит в групповую композитную ФНП (с ЛА `ПромежуточныйКомпозит`), а затем для этого же ТС создаётся единичная ФНП из "УК для ТС" — запрос находит групповой ЛА и ошибочно считает, что индивидуальный ЛА уже существует.

**Исправление:** 3 точки модификации в одном файле `CommonModules/гкс_ПриемкаТранспорта/Ext/Module.bsl`:

1. Добавить плейсхолдер `&ТекстУсловияПоТипуПробы` в оба шаблона запросов (строки 2131, 2153)
2. В ветке `ПроверкаДляПромежуточногоКомпозита` (строка 546) — установить `ТипПробы = Единичная`
3. Добавить `СтрЗаменить` для подстановки (после строки 558)
