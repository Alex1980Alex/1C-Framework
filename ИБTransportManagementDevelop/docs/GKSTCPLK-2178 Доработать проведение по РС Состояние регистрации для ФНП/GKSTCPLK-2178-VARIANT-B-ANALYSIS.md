# GKSTCPLK-2178 Углублённый анализ Варианта Б

## Детальный аналитический отчёт

**Дата:** 2026-03-05
**Проект:** 260304_GKSTCPLK-2182 Доработать создание Направление на разгрузку для заблокированных ТС
**Задача:** Исключить движения по РС `гкс_СостоянияРегистрации` ТОЛЬКО для единичных ФНП по УК (усиленный контроль), созданных из АРМ "Композитные пробы"

---

## 1. Постановка задачи Варианта Б

### 1.1 Требование

> При проведении документа "Формирование номера пробы" (ФНП), созданного из АРМ "Композитные пробы" для единичного ТС по УК (усиленный контроль) — **НЕ делать** движения по РС `гкс_СостоянияРегистрации`

### 1.2 Отличие от Варианта А

| Вариант | Фильтр | Что исключается |
|---------|--------|-----------------|
| **А** | Регистрация входит в композитную пробу | **ВСЕ** единичные ФНП для регистраций из композитных |
| **Б** | Регистрация в композитной + ФНП по УК | **ТОЛЬКО** единичные ФНП по усиленному контролю в композитных |

**Бизнес-смысл Варианта Б:** Если существуют единичные пробы в составе композитных, которые **НЕ** по УК — они ДОЛЖНЫ менять состояние регистрации на "ВзятыПробы".

### 2.2 Источник 1: РС `гкс_СопоставлениеФНПЛабАнализа` (из оригинального анализа)

**Структура:**
- Измерения: `ФормированиеНомераПробы`, `ЛабораторныйАнализ`
- Ресурсы: `ТипПробы`, `НазначениеИспользования`, `УсиленныйКонтроль` (Булево)

**Проблема:** Запись создаётся **ПОСЛЕ** формирования движений (ObjectModule.bsl:52).

**Вывод:** НЕ подходит для использования в запросе `ТекстЗапросаТаблицаСостояниеРегистрации`.

### 2.3 Источник 2: РС `гкс_ПоказателиУсиленногоКонтроляПоРегистрации` (НОВЫЙ)

**Структура:**
- Измерения:
  - `ДокументРегистрации` (ДокументСсылка.гкс_РегистрацияНаПЛК)
  - `Показатель` (СправочникСсылка.гкс_ПоказателиАнализовНоменклатуры)
  - `ЛабораторныйАнализ` (ДокументСсылка.гкс_ЛабораторныйАнализ) — **может быть пустым!**
  - `НазначениеИспользования` (Перечисление)
  - `ТипПробы` (Перечисление)
- Ресурсы: `СостояниеКачества`, `ЗначениеПоказателяМин`, `ЗначениеПоказателяМакс`, `Базис`

**Когда создаётся:** В `ПередЗаписью` через `ЗарегистрироватьТранспортноеСредствоДляУсиленногоКонтроля()` (ObjectModule.bsl:25).

**Ключевое преимущество:** Запись существует **ДО** формирования движений!

**Нюанс:** На момент проведения поле `ЛабораторныйАнализ` может быть пустым (заполняется позже при создании ЛабАнализа). Но для определения факта УК это не критично — достаточно наличия записи.

### 2.4 Источник 3: РС `гкс_ЗаблокированныеРегистрацииУсиленныйКонтроль`

**Структура:**
- Измерения: `ДокументРегистрации`, `Показатель`, `БлокирующаяРегистрация`, `БлокирующаяГруппаТС`
- Ресурсы: `БлокирующееСостояниеКачества`, `Разблокировано`

**Когда используется:** Заполняется при проведении ЛабораторногоАнализа (позже).

**Вывод:** НЕ подходит для использования при проведении ФНП.

## 3. Альтернативные реализации Варианта Б

### 3.1 Вариант Б-1: Оригинальный (через `СопоставлениеФНПЛабАнализа`)

**Требует рефакторинга `ОбработкаПроведения`:** Переместить `ЗаписатьСопоставлениеФНПИЛабАнализа()` ДО `ОбработкаПроведенияДокумента()`.

**Проблемы:**
1. `ЗаписатьСопоставлениеФНПИЛабАнализа()` требует созданный `ЛабораторныйАнализ`
2. `ЛабораторныйАнализ` создаётся в `СформироватьЛабораторныйАнализПоНеобходимости()`
3. Эта функция вызывается ПОСЛЕ проведения (нужны данные из движений)

**Вывод:** Сложный рефакторинг, высокий риск побочных эффектов.

---

### 3.2 Вариант Б-2: Альтернативный (через `ПоказателиУсиленногоКонтроляПоРегистрации`) ⭐

**Идея:** Использовать РС `гкс_ПоказателиУсиленногоКонтроляПоРегистрации`, который создаётся в `ПередЗаписью` (ДО проведения).

**Логика:**
1. Проверяем: есть ли запись в `гкс_ПоказателиУсиленногоКонтроляПоРегистрации` для данного `ДокументРегистрации`?
2. Проверяем: входит ли `ДокументРегистрации` в композитную пробу (`гкс_КомпозитныеПробы`)?
3. Если ОБА условия истинны → НЕ формировать движение по `СостоянияРегистрации`

**Полный код функции:**
```bsl
Функция ТекстЗапросаТаблицаСостояниеРегистрации(ТекстыЗапроса, Регистры)

	ИмяРегистра = "гкс_СостоянияРегистрации";

	Если НЕ гкс_ПроведениеДокументов.ТребуетсяТаблицаДляДвижений(ИмяРегистра, Регистры) Тогда
		Возврат "";
	КонецЕсли;

	ТекстЗапроса =
	"ВЫБРАТЬ РАЗЛИЧНЫЕ
	|	ФормированиеНомераПробы.Дата КАК Период,
	|	ФормированиеНомераПробы.ТочкаМаршрута КАК ТочкаМаршрута,
	|	ФормированиеНомераПробы.Ссылка КАК Регистратор,
	|	ФормированиеНомераПробыТЧ.ДокументРегистрации КАК ДокументРегистрации,
	|	&Пользователь КАК Пользователь,
	|	Регистрация.ТранспортноеСредство КАК ТранспортноеСредство,
	|	ЗНАЧЕНИЕ(Перечисление.гкс_СостоянияРегистрации.ВзятыПробы) КАК Состояние,
	|	Регистрация.ТипРегистрации КАК ТипРегистрации,
	|	Регистрация.ВидПеревозки КАК ВидПеревозки,
	|	ФормированиеНомераПробы.МестнаяДата КАК МестнаяДата
	|ИЗ
	|	Документ.гкс_ФормированиеНомераПробы.СписокРегистраций КАК ФормированиеНомераПробыТЧ
	|		ВНУТРЕННЕЕ СОЕДИНЕНИЕ Документ.гкс_ФормированиеНомераПробы КАК ФормированиеНомераПробы
	|		ПО ФормированиеНомераПробыТЧ.Ссылка = ФормированиеНомераПробы.Ссылка
	|		ВНУТРЕННЕЕ СОЕДИНЕНИЕ Документ.гкс_РегистрацияНаПЛК КАК Регистрация
	|		ПО ФормированиеНомераПробыТЧ.ДокументРегистрации = Регистрация.Ссылка
	|		// Гкс+[GKSTCPLK-2178] Проверка: регистрация входит в композитную пробу
	|		ЛЕВОЕ СОЕДИНЕНИЕ РегистрСведений.гкс_КомпозитныеПробы КАК КомпозитныеПробы
	|		ПО ФормированиеНомераПробыТЧ.ДокументРегистрации = КомпозитныеПробы.ДокументРегистрации
	|		// Гкс+[GKSTCPLK-2178] Проверка: регистрация под усиленным контролем
	|		ЛЕВОЕ СОЕДИНЕНИЕ РегистрСведений.гкс_ПоказателиУсиленногоКонтроляПоРегистрации КАК ПоказателиУК
	|		ПО ФормированиеНомераПробыТЧ.ДокументРегистрации = ПоказателиУК.ДокументРегистрации
	|ГДЕ
	|	ФормированиеНомераПробыТЧ.Ссылка = &Ссылка
	|	И ФормированиеНомераПробыТЧ.ДокументРегистрации ССЫЛКА Документ.гкс_РегистрацияНаПЛК
	|	// Гкс+[GKSTCPLK-2178] Исключить: регистрация в композитной + под УК
	|	И НЕ (КомпозитныеПробы.ДокументРегистрации ЕСТЬ НЕ NULL
	|		И ПоказателиУК.ДокументРегистрации ЕСТЬ НЕ NULL)"
	;

	ТекстыЗапроса.Добавить(ТекстЗапроса, ИмяРегистра);

	Возврат ТекстЗапроса;

КонецФункции
```

**Ключевые отличия от оригинального Варианта Б:**
1. Используется `РАЗЛИЧНЫЕ` — для исключения дубликатов при множественных записях в РС
2. JOIN к `гкс_ПоказателиУсиленногоКонтроляПоРегистрации` вместо `гкс_СопоставлениеФНПЛабАнализа`
3. Условие: `КомпозитныеПробы.ДокументРегистрации ЕСТЬ НЕ NULL И ПоказателиУК.ДокументРегистрации ЕСТЬ НЕ NULL`

---

### 3.3 Вариант Б-3: Через параметр ДопПараметры (программный подход)

**Идея:** Передать признак УК через `ДопПараметры.ДополнительныеСвойства` в запрос.

**Требует изменений:**
1. В `ПередЗаписью` или `ОбработкаПроведения` определить признак УК
2. Передать его в `ДопПараметры.ДополнительныеСвойства.ЭтоУсиленныйКонтроль`
3. Использовать параметр `&ЭтоУсиленныйКонтроль` в запросе

**Проблемы:**
1. Признак УК определяется **для регистрации**, а не для всего ФНП
2. В ФНП может быть несколько регистраций с разными признаками УК
3. Сложнее реализовать корректно

**Вывод:** Не рекомендуется.

### 4.1 Анализ побочных эффектов

**Вариант А:**
- ❌ Единичные пробы в композитных БЕЗ УК тоже НЕ будут менять состояние
- ✅ Если таких проб нет в бизнес-процессе — проблем нет

**Вариант Б-2:**
- ✅ Исключаются ТОЛЬКО единичные пробы по УК в композитных
- ✅ Единичные пробы в композитных БЕЗ УК продолжат менять состояние
- ⚠️ Зависит от корректности заполнения РС `ПоказателиУсиленногоКонтроляПоРегистрации`

### 4.2 Анализ производительности

**Запрос Варианта Б-2 добавляет:**
- 1 дополнительный LEFT JOIN к РС `ПоказателиУсиленногоКонтроляПоРегистрации`
- Измерение `ДокументРегистрации` проиндексировано (MainFilter = true)
- Ожидаемое влияние на производительность: минимальное

## 5. Рекомендации

### 5.1 Когда выбирать Вариант А

- Если в бизнес-процессе **НЕТ** единичных проб в композитных, которые должны менять состояние
- Если нужна **максимальная простота** и надёжность
- Если сроки реализации критичны

### 5.2 Когда выбирать Вариант Б-2 ⭐

- Если в бизнес-процессе **ЕСТЬ** единичные пробы в композитных БЕЗ УК, которые должны менять состояние
- Если требуется **точечное исправление** без затрагивания других сценариев
- Если есть уверенность в корректности данных в РС `ПоказателиУсиленногоКонтроляПоРегистрации`

### 5.3 НЕ рекомендуется

- ❌ **Вариант Б-1** (оригинальный через `СопоставлениеФНПЛабАнализа`) — требует сложного рефакторинга

## 6. Чек-лист верификации для Варианта Б-2

- [ ] **Точка модификации 1:** LEFT JOIN к `гкс_КомпозитныеПробы` корректно находит регистрации в композитных
- [ ] **Точка модификации 2:** LEFT JOIN к `гкс_ПоказателиУсиленногоКонтроляПоРегистрации` корректно находит регистрации под УК
- [ ] **Условие-исключение:** `НЕ (КомпозитныеПробы.ДокументРегистрации ЕСТЬ НЕ NULL И ПоказателиУК.ДокументРегистрации ЕСТЬ НЕ NULL)` работает корректно
- [ ] **Обратная совместимость:** Обычные единичные пробы (не в композитных, не под УК) продолжают менять состояние
- [ ] **Дубликаты:** `РАЗЛИЧНЫЕ` исключает дубликаты при множественных записях в РС
- [ ] **Побочные эффекты:** Единичные пробы в композитных БЕЗ УК продолжают менять состояние

## 7. Тест-план для Варианта Б-2

### Позитивные сценарии
- [ ] ФНП для регистрации в композитной + под УК → движение НЕ формируется
- [ ] ФНП для регистрации в композитной + БЕЗ УК → движение формируется (отличие от Варианта А!)
- [ ] ФНП для регистрации НЕ в композитной + под УК → движение формируется
- [ ] ФНП для регистрации НЕ в композитной + БЕЗ УК → движение формируется
- [ ] Композитная проба → движение по `гкс_КомпозитныеПробы` формируется

### Негативные / граничные сценарии
- [ ] ФНП с пустым `СписокРегистраций` → проведение без ошибок
- [ ] ФНП с несколькими регистрациями (часть в композитных, часть нет) → корректная фильтрация
- [ ] Перепроведение ФНП → старые движения удалены, новые по актуальным условиям
- [ ] Отмена проведения → движения корректно удалены
