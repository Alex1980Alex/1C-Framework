# GKSTCPLK-2178 Вариант Б-Param: Реализация через параметр

## Аналитический отчёт

**Дата:** 2026-03-05
**Проект:** 260304_GKSTCPLK-2182
**Задача:** Исключить движения по РС `гкс_СостоянияРегистрации` для единичных ФНП по УК через параметр (вместо LEFT JOIN в запросе)

---

## 1. Суть подхода

Вместо модификации SQL-запроса с LEFT JOIN к двум регистрам сведений — передавать **параметр-флаг** из АРМ Приёмка при создании ФНП. Если параметр установлен — полностью пропустить формирование движений по РС `гкс_СостоянияРегистрации`.

### 1.1 Сравнение с текущей реализацией (Вариант Б-2, через запрос)

| Критерий | Б-2 (LEFT JOIN) | Б-Param (параметр) |
|----------|-----------------|---------------------|
| **Сложность запроса** | +2 LEFT JOIN, +1 условие ГДЕ | Запрос без изменений |
| **Точка принятия решения** | В запросе (данные) | В бизнес-логике (параметр) |
| **Производительность** | Минимальное влияние | Без влияния (запрос не вызывается) |
| **Точки модификации** | 1 функция | 4 точки (см. ниже) |
| **Прозрачность** | Логика скрыта в запросе | Явный параметр — легко отладить |
| **Расширяемость** | Нужен рефакторинг запроса | Добавить условие в ARM |
| **Перепроведение** | Работает (данные в РС) | ⚠️ Не работает (параметр не сохраняется) |

### 3.2 Точка 2: СоздатьНовыйДокумент — пробросить параметр

**Файл:** `src/Documents/гкс_ФормированиеНомераПробы/Ext/ManagerModule.bsl`
**Функция:** `СоздатьНовыйДокумент` (строки 401-410)

**Текущий код:**
```bsl

    УстановитьПривилегированныйРежим(Истина);
    НовыйДокумент = СоздатьДокумент();
    НовыйДокумент.Заполнить(ДанныеЗаполнения);
    НовыйДокумент.Записать(РежимЗаписиДокумента.Проведение);
КонецПроцедуры
```

**Предлагаемое изменение:**
```bsl
Процедура СоздатьНовыйДокумент(ДанныеЗаполнения) Экспорт
    УстановитьПривилегированныйРежим(Истина);
    НовыйДокумент = СоздатьДокумент();
    НовыйДокумент.Заполнить(ДанныеЗаполнения);
    // Гкс+[GKSTCPLK-2178] Передать параметр пропуска проводки по СостоянияРегистрации
    НеПроводитьПоСостояниюРегистрации = Ложь;
    Если ТипЗнч(ДанныеЗаполнения) = Тип("Структура") Тогда
        ДанныеЗаполнения.Свойство("НеПроводитьПоСостояниюРегистрации",
            НеПроводитьПоСостояниюРегистрации);
    КонецЕсли;
    Если НеПроводитьПоСостояниюРегистрации Тогда
        НовыйДокумент.ДополнительныеСвойства.Вставить(
            "НеПроводитьПоСостояниюРегистрации", Истина);
    КонецЕсли;
    НовыйДокумент.Записать(РежимЗаписиДокумента.Проведение);
КонецПроцедуры
```

**Почему здесь, а не в ОбработкаЗаполнения:**
- `ОбработкаЗаполнения` вызывает `ЗаполнитьЗначенияСвойств(ЭтотОбъект, ДанныеЗаполнения)` — попытается записать `НеПроводитьПоСостояниюРегистрации` как реквизит документа (такого нет) → будет проигнорирован
- `СоздатьНовыйДокумент` — единственная точка между `Заполнить()` и `Записать()`, где можно установить `ДополнительныеСвойства`

## 4. Критический момент: перепроведение

### ⚠️ Проблема

Параметр `НеПроводитьПоСостояниюРегистрации` передаётся через `ДополнительныеСвойства` — он существует **только в момент первичного создания** документа из АРМ Приёмка. При **перепроведении** (из формы документа, через обработку, при обновлении конфигурации) этого параметра не будет → движение будет сформировано.

### Варианты решения проблемы перепроведения

**Вариант А: Определять параметр в ОбработкаПроведения (рекомендуется)**

Вместо пробрасывания из ARM — определять условие непосредственно в `ОбработкаПроведения`:

```bsl
Процедура ОбработкаПроведения(Отказ, РежимПроведения)
    ДопПараметры = гкс_ПроведениеДокументов.ДопПараметрыИнициализироватьДанныеДокументаДляПроведения();
    ДопПараметры.ДополнительныеСвойства = Новый Структура;
    ЗаполнитьДопПараметры(ДопПараметры, "ТипПробы", ТипПробы);
    // Гкс+[GKSTCPLK-2178] Определить: нужна ли проводка по СостоянияРегистрации
    // Проверяем для каждой регистрации: если в композитной + под УК → пропускаем
    Если ТипПробы = Перечисления.гкс_ТипыПроб.Единичная Тогда
        ДокументРегистрации = ПолучитьДокументРегистрации();
        НеПроводитьПоСостояниюРегистрации =
            ЕстьПоказателиУсиленногоКонтроля(ДокументРегистрации)
            И ТСВходитВКомпозитнуюПробу(ДокументРегистрации);
        Если НеПроводитьПоСостояниюРегистрации Тогда
            ЗаполнитьДопПараметры(ДопПараметры,
                "НеПроводитьПоСостояниюРегистрации", Истина);
        КонецЕсли;
    КонецЕсли;
    гкс_ПроведениеДокументов.ОбработкаПроведенияДокумента(ЭтотОбъект, Отказ, ДопПараметры);
    ...
```

**Плюсы:** Работает и при первичном проведении, и при перепроведении.
**Минусы:** Нужна дополнительная функция `ТСВходитВКомпозитнуюПробу()`.

**Вариант Б: Сохранять признак в реквизите документа**

Добавить булевый реквизит `НеПроводитьПоСостояниюРегистрации` в метаданные документа `гкс_ФормированиеНомераПробы`. Устанавливать при создании. Читать при проведении.

**Плюсы:** Надёжно сохраняется, работает при перепроведении.
**Минусы:** Изменение метаданных документа (добавление реквизита).

### 5.2 Новая функция ТСВходитВКомпозитнуюПробу

**Файл:** `src/Documents/гкс_ФормированиеНомераПробы/Ext/ObjectModule.bsl`

```bsl
// Гкс+[GKSTCPLK-2178] Проверяет, входит ли документ регистрации в композитную пробу.
//
// Параметры:
//  ДокументРегистрации - ДокументСсылка.гкс_РегистрацияНаПЛК
//
// Возвращаемое значение:
//  Булево - Истина, если регистрация входит в композитную пробу
Функция ТСВходитВКомпозитнуюПробу(ДокументРегистрации)

    Если НЕ ЗначениеЗаполнено(ДокументРегистрации) Тогда
```

## 6. Сравнение итоговых вариантов

| Критерий | Б-2 (LEFT JOIN) | Б-Param (рекоменд.) |
|----------|-----------------|----------------------|
| **Запрос** | +2 LEFT JOIN | Без изменений |
| **Перепроведение** | ✅ Работает | ✅ Работает (определяется в ОбработкаПроведения) |
| **Дополнительный запрос** | Нет | 1 запрос `ВЫБРАТЬ ПЕРВЫЕ 1` к КомпозитныеПробы |
| **Производительность** | 2 LEFT JOIN в основном запросе | 1 лёгкий ВЫБРАТЬ ПЕРВЫЕ 1 + 1 существующая проверка |
| **Читаемость** | Условие в ГДЕ запроса | Явная бизнес-логика в ОбработкаПроведения |
| **Точки модификации** | 1 функция запроса | ObjectModule + dispatch-код |
| **Откат** | Убрать JOIN из запроса | Убрать проверку из ОбработкаПроведения + dispatch |

## 7. Тест-план

### Позитивные сценарии
- [ ] ФНП единичная + регистрация в композитной + под УК → движение НЕ формируется
- [ ] ФНП единичная + регистрация в композитной + БЕЗ УК → движение формируется
- [ ] ФНП единичная + регистрация НЕ в композитной + под УК → движение формируется
- [ ] ФНП единичная + регистрация НЕ в композитной + БЕЗ УК → движение формируется
- [ ] ФНП композитная → движение по `гкс_КомпозитныеПробы` формируется (как раньше)

### Перепроведение
- [ ] Перепроведение ФНП (регистрация в композитной + под УК) → движение НЕ формируется
- [ ] Перепроведение ФНП (обычная регистрация) → движение формируется

### Граничные
- [ ] ФНП с пустым `СписокРегистраций` → проведение без ошибок
- [ ] Отмена проведения → движения удалены
