## 1. Описание задачи

### 1.1 Требования (1 пункт)

1. **Дополнить условие отображения признака "Принять качество"** в форме документа "Направление на разгрузку": помимо текущей проверки `СостояниеРегистрации <> КачествоПринято`, добавить проверку наличия записей в РС `гкс_ЗаблокированныеРегистрацииУсиленныйКонтроль` для данной регистрации с признаком `Разблокировано = Ложь`. [REQ-1]

### 1.2 Суть проблемы

**Что сейчас:** Признак "Принять качество" (и связанное поле "Комментарий") отображаются в форме "Направление на разгрузку" только когда `ПервичныйСтатус <> КачествоПринято`. Если качество было принято, но ТС заблокировано по усиленному контролю — чекбокс не показывается и пользователь не может вручную принять качество.

**Что должно быть:** Признак "Принять качество" отображается также если по данной регистрации есть хотя бы одна запись в РС "Заблокированные регистрации усиленный контроль" с `Разблокировано = Ложь`. Это позволит пользователю вручную принять качество для заблокированных ТС.

### 1.3 Связанные задачи

- GKSTCPLK-2182 — родительская задача по доработке создания Направления на разгрузку для заблокированных ТС
- ФО `гкс_ИспользоватьЗаблокированныеТС` — функциональная опция, контролирующая весь функционал блокировки ТС

## 3. Детальный анализ механизма

### 3.1 Модуль формы ФормаДокумента (Module.bsl)

#### Текущий алгоритм вычисления `КачествоНеПринято`

Реквизит формы `КачествоНеПринято` (Булево) вычисляется в процедуре `ИнициализироватьРеквизитыФормы()` (строки 288-298):

```bsl
// Строка 288
Процедура ИнициализироватьРеквизитыФормы()
    ПолучитьЗначенияРегистрации();
    Если ТипРегистрации = Перечисления.гкс_ТипРегистрации.Приемка Тогда
        КачествоНеПринято = Объект.ПервичныйСтатус <> Перечисления.гкс_СостоянияРегистрации.КачествоПринято;
    Иначе
        КачествоНеПринято = Ложь;
    КонецЕсли;
КонецПроцедуры
```

#### Использование `КачествоНеПринято` в форме

Реквизит используется в 3-х местах:

1. **Видимость элементов** — `УстановитьВидимостьДоступностьЭлементовФормы()` (строки 369-379):
   - `Элементы.ПринятьКачество.Видимость = КачествоНеПринято` (строка 373)
   - `Элементы.Комментарий.Видимость = КачествоНеПринято` (строка 374)
   - `Элементы.Склад.Видимость = Не КачествоНеПринято Или Объект.ПринятьКачество` (строка 375)
   - `Элементы.ЯмаРазгрузки.Видимость = Не КачествоНеПринято Или Объект.ПринятьКачество` (строка 376)

2. **Проверка заполнения** — `ОбработкаПроверкиЗаполненияНаСервере()` (строки 58-82):
   - Если `КачествоНеПринято И Не Объект.ПринятьКачество` → ошибка (строка 60)
   - Если `КачествоНеПринято И Не ЗначениеЗаполнено(Объект.Комментарий)` → ошибка (строка 65)

3. **Обработчик клиент** — `ПринятьКачествоПриИзменении()` (строка 150):
   - Переключение видимости склада и ямы разгрузки при изменении чекбокса

#### Вызов `ИнициализироватьРеквизитыФормы`

Вызывается один раз из `ПриСозданииНаСервере()` (строка 21). Это означает, что значение `КачествоНеПринято` вычисляется единожды при открытии формы.

### 3.2 Готовая функция проверки блокировки

В общем модуле `гкс_ВходнойКонтрольКачества` (строка 1862) уже есть экспортная функция:

```bsl
Функция ПроверитьБлокированиеТранспортногоСредстваДляРазгрузки(ДокументРегистрации) Экспорт
    Запрос = Новый Запрос;
    Запрос.Текст =
        "ВЫБРАТЬ ПЕРВЫЕ 1
        |   ЗаблокированныеТС.ДокументРегистрации
        |ИЗ
        |   РегистрСведений.гкс_ЗаблокированныеРегистрацииУсиленныйКонтроль
        |       КАК ЗаблокированныеТС
        |ГДЕ
        |   ЗаблокированныеТС.ДокументРегистрации = &ДокументРегистрации
        |   И НЕ ЗаблокированныеТС.Разблокировано";
    Запрос.УстановитьПараметр("ДокументРегистрации", ДокументРегистрации);
    Возврат НЕ Запрос.Выполнить().Пустой();
КонецФункции
```

Функция возвращает `Истина`, если есть хотя бы одна не разблокированная запись для данной регистрации. Это **точно** то условие, которое описано в ТЗ.

### 3.3 Паттерн использования ФО

Во всех местах конфигурации проверка ФО выполняется перед обращением к РС блокировок:

```bsl
Если Не ПолучитьФункциональнуюОпцию("гкс_ИспользоватьЗаблокированныеТС") Тогда
    Возврат; // или Возврат Ложь;
КонецЕсли;
```

Примеры: `гкс_ВходнойКонтрольКачества` строки 1989, 2077; `гкс_ЛабораторныйАнализ.ObjectModule` строка 674.

**Реализованный код (после рефакторинга GKSTCPLK-2182):**
```bsl
Процедура ИнициализироватьРеквизитыФормы()
    ПолучитьЗначенияРегистрации();
    Если ТипРегистрации = Перечисления.гкс_ТипРегистрации.Приемка Тогда
        КачествоНеПринято = Объект.ПервичныйСтатус <> Перечисления.гкс_СостоянияРегистрации.КачествоПринято;
        // GKSTCPLK-2181: Дополнительно показываем "Принять качество" для заблокированных ТС
        Если Не КачествоНеПринято Тогда
            КачествоНеПринято = ТранспортноеСредствоЗаблокировано(Объект.ДокументРегистрации);
        КонецЕсли;
    Иначе
        КачествоНеПринято = Ложь;
    КонецЕсли;
КонецПроцедуры

// GKSTCPLK-2182
&НаСервереБезКонтекста
Функция ТранспортноеСредствоЗаблокировано(ДокументРегистрации)

    Возврат ПолучитьФункциональнуюОпцию("гкс_ИспользоватьЗаблокированныеТС")
        И ЗначениеЗаполнено(ДокументРегистрации)
        И гкс_ВходнойКонтрольКачества
            .ПроверитьБлокированиеТранспортногоСредстваДляРазгрузки(ДокументРегистрации);

КонецФункции
```

**Логика изменения:**
1. Сначала вычисляется стандартное условие (`ПервичныйСтатус <> КачествоПринято`)
2. Если качество **уже принято** (`КачествоНеПринято = Ложь`), проверяем дополнительно через `ТранспортноеСредствоЗаблокировано()`:
   - Включена ли ФО `гкс_ИспользоватьЗаблокированныеТС`
   - Заполнен ли документ регистрации (защита от пустой ссылки)
   - Есть ли не разблокированные записи в РС
3. Если ТС заблокировано → `КачествоНеПринято = Истина` → показываем чекбокс

> **Рефакторинг (GKSTCPLK-2182):** Условие проверки блокировки вынесено в отдельную функцию `ТранспортноеСредствоЗаблокировано()` (`&НаСервереБезКонтекста`) для улучшения читаемости.

**Зависимости:** Нет зависимостей от других изменений. Единственная точка модификации.

## 7. Тест-план

### Позитивные сценарии

1. **ФО включена, ТС заблокировано, качество принято:**
   - Открыть "Направление на разгрузку" для регистрации с `ПервичныйСтатус = КачествоПринято`
   - В РС `гкс_ЗаблокированныеРегистрацииУсиленныйКонтроль` есть запись с `Разблокировано = Ложь`
   - **Ожидание:** Чекбокс "Принять качество" и поле "Комментарий" видимы

2. **ФО включена, ТС заблокировано, качество НЕ принято:**
   - Открыть форму с `ПервичныйСтатус <> КачествоПринято`
   - **Ожидание:** Чекбокс видим (как и раньше, по основному условию)

3. **Проведение с принятием качества:**
   - Установить чекбокс "Принять качество", заполнить комментарий
   - Провести документ
   - **Ожидание:** Документ проводится успешно

### Негативные сценарии

4. **ФО включена, ТС заблокировано, не отмечен чекбокс:**
   - Попытка провести без установки "Принять качество"
   - **Ожидание:** Ошибка "Необходимо Принять качество"

5. **ФО включена, ТС заблокировано, не заполнен комментарий:**
   - Установить чекбокс, но не заполнить комментарий
   - **Ожидание:** Ошибка "Необходимо заполнить комментарий"

### Граничные условия

6. **ФО выключена, ТС заблокировано:**
   - **Ожидание:** Чекбокс НЕ показывается (поведение как раньше)

7. **ФО включена, ТС НЕ заблокировано, качество принято:**
   - В РС нет записей или все `Разблокировано = Истина`
   - **Ожидание:** Чекбокс НЕ показывается

8. **ФО включена, пустой документ регистрации:**
   - Новый документ без заполненной регистрации
   - **Ожидание:** Чекбокс НЕ показывается, ошибок нет

## 8. Резюме

### Суть задачи

При открытии формы «Направление на разгрузку» для заблокированного ТС (по усиленному контролю) чекбокс «Принять качество» не показывается, если качество уже принято.
