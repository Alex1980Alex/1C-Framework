## 1. Описание задачи

### 1.1 Требования (3 пункта)

**Требование 1.** При проведении ЛА с НазначениеИспользования = Приемка и Статус = Выполнен:
- Если в регистре `гкс_ПоказателиУсиленногоКонтроляПоРегистрации` для данной регистрации есть записи с:
  - `НазначениеИспользования = ПромежуточныйКомпозит`
  - `ТипПробы = Композитная`
  - `СостояниеКачества = ПустаяСсылка` (не заполнено)
- И по результатам ЛА качество НЕ принято (показатель с `ОтклонятьКачество = Истина`)
- **Тогда:** проставить `СостояниеКачества = ПробыНеТребуются` для этих записей

**Требование 2.** При проведении ЛА первого ТС / группы ТС:
- Если среди заблокированных ТС есть такие, у которых входной контроль НЕ пройден (`СостояниеКачества = НеПринятоВходнойКонтроль`)
- **Тогда:** НЕ создавать новые записи в `ПоказателиУсиленногоКонтроляПоРегистрации` с типом `ПромежуточныйКомпозит / Единичная` для этих ТС

**Требование 3.** Проверить АРМ Промежуточный Композит / Усиленный Контроль:
- Убедиться, что анализы с `СостояниеКачества = ПробыНеТребуются` не отображаются в списке для формирования композита

### 1.2 Суть проблемы

**Что сейчас:** При проведении ЛА Приемка с результатом "Качество не принято" записи промежуточного композита / композитные в регистре ПоказателиУК остаются с пустым `СостояниеКачества`. Они появляются в АРМ как ожидающие формирования композита, хотя фактически композитный анализ для них не нужен. Для заблокированных ТС с непройденным входным контролем создаются лишние записи.

**Что должно быть:** Композитные записи получают статус "ПробыНеТребуются", исчезают из АРМ, не создаются лишние записи для ТС с непройденным входным контролем.

## 6. Чек-лист верификации

- [ ] **Требование 1** (Точки 1, 2)
  - При проведении ЛА Приемка/Выполнен с КачествоНеПринято — Композитные записи ПоказателиУК получают `ПробыНеТребуются`
- [ ] **Требование 2** (Точки 3, 4, 5)
  - При проведении ЛА первого ТС/группы — не создаются записи для заблокированных ТС с `НеПринятоВходнойКонтроль`
- [ ] **Требование 3** (без изменений кода)
  - АРМ фильтрует по `СостояниеКачества В (Пусто, ОтборПроб)` — записи с `ПробыНеТребуются` НЕ отображаются
- [ ] Побочные эффекты:
  - `ЗаполнитьРегистрПоказателейУсиленногоКонтроляЛабАнализом` вызывается при `ТребуетсяУсиленныйКонтрольЛабАнализа()` (строка 656) — нет побочных эффектов
  - `УстановитьПробыНеТребуютсяДляКомпозитных` устанавливает статус ТОЛЬКО для записей с пустым СостояниеКачества (строка 288: `Не ЗначениеЗаполнено(Запись.СостояниеКачества)`) — не затронет уже обработанные записи
- [ ] Обратная совместимость:
  - Если Композитных записей нет → `УстановитьПробыНеТребуютсяДляКомпозитных` ничего не сделает
  - Если `НеПринятоВходнойКонтроль` не встречается → `ЕстьНеПринятыйВходнойКонтроль` вернёт Ложь, поведение не изменится

## 7. Риски и открытые вопросы

### Решённый вопрос: Значение перечисления "Не требуется"

ТЗ: "Состояние качества - Не требуется". В перечислении `гкс_СостоянияКачества` (верифицировано через get_metadata) нет "НеТребуется", но есть `ПробыНеТребуются` ("Пробы не требуются").

**Решение:** Используем `ПробыНеТребуются` — оно уже применяется в аналогичном сценарии (`УстановитьПробыНеТребуютсяДляКомпозитных`, строка 289). Не требуется изменение метаданных.

### Решённый вопрос: ФормированиеНомераПробы (ФНП)

Поле `гкс_ДокументРегистрации` имеет составной тип: `ДокументСсылка.гкс_РегистрацияНаПЛК | ДокументСсылка.гкс_ФормированиеНомераПробы` (верифицировано через get_metadata). Записи в `ПоказателиУК` хранятся по каждой `РегистрацияНаПЛК`, а не по `ФормированиеНомераПробы`. Существующая логика в `ЗаполнитьРегистрПоказателейУсиленногоКонтроляЛабАнализом` (строки 84-101) разворачивает ФНП в список регистраций через `ОБЪЕДИНЕНИЕ ВСЕ`.

**Решение (подтверждено):** Новая процедура в Точке 2 использует тот же паттерн `ОБЪЕДИНЕНИЕ ВСЕ` — разворачивает ФНП в список `РегистрацияНаПЛК` из ТЧ `СписокРегистраций`, затем вызывает `УстановитьПробыНеТребуютсяДляКомпозитных` для каждой регистрации отдельно.

### Риск: Производительность

`ЕстьНеПринятыйВходнойКонтроль` выполняет запрос для каждого заблокированного ТС. При большом количестве блокировок (> 50) это может быть заметно. Оптимизация: можно передавать массив регистраций одним запросом, но для текущих объёмов (26 записей в ЗаблокированныеРегистрацииУК) это не критично.
