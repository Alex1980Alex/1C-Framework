# GKSTCPLK-2213 Исправить ошибку проверки блокировки в АРМ приемка

## Детальный аналитический отчёт

**Дата:** 2026-03-11
**Проект:** 260304_GKSTCPLK-2182 Доработать создание Направление на разгрузку для заблокированных ТС
**Статус:** Анализ завершён

---

## 1. Описание задачи

### 1.1 Требования

**Контекст:** АРМ Приемки. Правило "Первое ТС". ТС было заблокировано, затем разблокировано лабораторным анализом первого ТС. При нажатии кнопки "Направление на разгрузку" выдаётся сообщение, что ТС заблокировано. Но у регистрации статус "Разблокировано".

### 1.2 Суть проблемы

**Что сейчас:** Функция `ПроверитьБлокировкуДляСозданияНнР()` в общем модуле `гкс_ВходнойКонтрольКачества` (строка 2003) запрашивает записи из регистра `гкс_ЗаблокированныеРегистрацииУсиленныйКонтроль` **без фильтра** `И НЕ Разблокировано`. Поэтому разблокированные записи попадают в результат, и функция ошибочно показывает предупреждение "Транспортное средство заблокировано по усиленному контролю. Продолжить создание направления на разгрузку?"

**Что должно быть:** Разблокированные записи (`Разблокировано = Истина`) должны игнорироваться при проверке. Если все записи разблокированы — кнопка должна работать без предупреждений.

### 1.3 Корневая причина (Root Cause)

В запросе функции `ПроверитьБлокировкуДляСозданияНнР()` (строка 2050-2051) отсутствует условие `И НЕ ЗаблокированныеТС.Разблокировано` в блоке `ГДЕ` второго пакета запроса.

**Все остальные запросы** к этому регистру в модуле `гкс_ВходнойКонтрольКачества` корректно фильтруют по `Разблокировано`:
- Строка 755: `И НЕ ЗаблокированныеРегистрацииУсиленныйКонтроль.Разблокировано`
- Строка 769: `НЕ ЗаблокированныеРегистрацииУК.Разблокировано`
- Строка 1637: `И НЕ Заблокированные.Разблокировано`
- Строка 1680: `И НЕ Заблокированные.Разблокировано`
- Строка 1928: `И НЕ ЗаблокированныеТранспортныеСредства.Разблокировано`
- Строка 1956: `И НЕ ЗаблокированныеТранспортныеСредства.Разблокировано`
- Строка 2114: `И НЕ ЗаблокированныеТС.Разблокировано` (в `РазблокироватьТСПриПринятииКачества`)

Только в `ПроверитьБлокировкуДляСозданияНнР` этот фильтр пропущен.

## 3. Детальный анализ механизма

### 3.1 Цепочка вызовов при нажатии "На разгрузку"

```
Пользователь нажимает кнопку "На разгрузку"
  → РедактироватьНаправлениеНаРазгрузку()                   [Клиент, строка 372]
    → гкс_ПриемкаТранспортаВызовСервера
        .ПроверитьБлокировкуДляСозданияНнР(Регистрация)     [Сервер, строка 211]
      → гкс_ВходнойКонтрольКачества
          .ПроверитьБлокировкуДляСозданияНнР(Регистрация)   [Сервер, строка 2003]  *** ОШИБКА ЗДЕСЬ ***
    → Если ЕстьБлокировка → СообщитьПользователю() + Возврат  [строка 391-393]
    → Если ЕстьПредупреждение → ПоказатьВопрос()               [строка 394-399]
    → Иначе → ОткрытьФормуНаправленияНаРазгрузкуДляРегистрации()
```

### 3.2 Текущий SQL запроса (ошибочный)

```sql
-- Пакет 2 (строка 2037-2051)
ВЫБРАТЬ РАЗЛИЧНЫЕ
    ЗаблокированныеТС.БлокирующееСостояниеКачества,
    ЗаблокированныеТС.Показатель,
    ВЫБОР КОГДА ВТ_КомпозитПоПоказателям.ДокументРегистрации ЕСТЬ NULL
        ТОГДА ЛОЖЬ ИНАЧЕ ИСТИНА
    КОНЕЦ КАК КомпозитСделан
ИЗ
    РегистрСведений.гкс_ЗаблокированныеРегистрацииУсиленныйКонтроль КАК ЗаблокированныеТС
    ЛЕВОЕ СОЕДИНЕНИЕ ВТ_КомпозитПоПоказателям ...
ГДЕ
    ЗаблокированныеТС.ДокументРегистрации = &ДокументРегистрации
    -- !!! ОТСУТСТВУЕТ: И НЕ ЗаблокированныеТС.Разблокировано !!!
```

### 3.3 Логика обработки результата (строки 2058-2085)

1. Если результат запроса пуст → нет блокировки → `Возврат` (всё ОК)
2. Цикл по записям: если `КачествоНеПринято И НЕ КомпозитСделан` → `ЕстьБлокировка = Истина` (жёсткий блок)
3. Если `ЕстьБлокировка` → текст "заблокировано... Создание запрещено"
4. **Иначе** (записи есть, но нет КачествоНеПринято) → `ЕстьПредупреждение = Истина` → текст "заблокировано... Продолжить?"

### 3.4 Сценарий бага

1. ТС заблокировано по правилу "Первое ТС" → запись в регистре с `Разблокировано = Ложь`
2. ЛА первого ТС проходит → `Разблокировано = Истина` (вызов `РазблокироватьТСПриПринятииКачества`, строка 2097)
3. Пользователь нажимает "На разгрузку" → вызывается `ПроверитьБлокировкуДляСозданияНнР`
4. Запрос **без фильтра** по `Разблокировано` возвращает разблокированную запись
5. Результат не пуст → шаг 1 (строка 2058) не срабатывает
6. В цикле (строка 2065): `БлокирующееСостояниеКачества` у разблокированной записи не `КачествоНеПринято` → `ЕстьБлокировка` остаётся `Ложь`
7. Попадаем в `Иначе` (строка 2079) → `ЕстьПредупреждение = Истина`
8. На клиенте (строка 394) → показывается вопрос "Продолжить создание направления на разгрузку?"
9. Пользователь видит сообщение о блокировке, хотя ТС разблокировано

## 4. План изменений

### Точка модификации 1: Добавить фильтр `Разблокировано` в запрос

**Файл:** `CommonModules/гкс_ВходнойКонтрольКачества/Ext/Module.bsl`
**Функция:** `ПроверитьБлокировкуДляСозданияНнР()` (строка 2003)
**Строка:** 2051

**Действие:** Добавить условие `И НЕ ЗаблокированныеТС.Разблокировано` в `ГДЕ` второго пакета запроса.

**Было (строка 2050-2051):**
```sql
ГДЕ
    ЗаблокированныеТС.ДокументРегистрации = &ДокументРегистрации
```

**Стало:**
```sql
ГДЕ
    ЗаблокированныеТС.ДокументРегистрации = &ДокументРегистрации
    И НЕ ЗаблокированныеТС.Разблокировано
```

**Тип:** Исправление ошибки (bugfix)
**Зависимости:** Нет
**Побочные эффекты:** Нет. Фильтрация разблокированных записей — стандартный паттерн, используемый во всех остальных запросах к этому регистру в модуле.

### Порядок выполнения

1. Точка 1 — единственное изменение

## 7. Резюме

### Суть бага

Пропущен фильтр `И НЕ Разблокировано` в единственной функции проверки блокировки при создании НнР. Все остальные 7 запросов в модуле корректно фильтруют разблокированные записи.

### Исправление

Одна строка в SQL запросе: добавить `И НЕ ЗаблокированныеТС.Разблокировано` в WHERE-условие пакета 2 функции `ПроверитьБлокировкуДляСозданияНнР()`.
