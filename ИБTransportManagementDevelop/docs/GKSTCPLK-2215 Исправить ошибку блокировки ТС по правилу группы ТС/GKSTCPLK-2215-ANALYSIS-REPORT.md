# GKSTCPLK-2215 -- ANALYSIS REPORT

**Дата:** 2026-03-10
**Задача:** Исправить ошибку блокировки ТС по правилу группы ТС
**Статус:** Анализ завершён, 3 бага идентифицированы

## Фаза 1: Требования (из ТЗ)

### Баг 1: Второе ТС в группе 1 блокируется при проведении ЛА [REQ-1]
> Первое ТС прошло ЛА в статусе выполнен. Показатель ГМО по УК - качество принято.
> Второе ТС. Первое в 1-ой группе. При проведении ЛА второго ТС Заблокировалось. Чего не должно быть.

**Ожидание:** Если первое ТС уже получило "Качество принято" по УК, то второе ТС НЕ должно блокироваться.

### Баг 2: Группа 2 не разблокируется при проведении композита на Группу 1 [REQ-2]
> Вторая группа заблокирована первой группой (не сделан композит на Группу1).
> При проведении ЛА композит на первую группу с положительным качеством -- не разблокировалась 2 группа (должна разблокироваться).

**Ожидание:** При проведении ЛА промежуточного композита на группу 1 с качеством "принято", все ТС, заблокированные группой 1, должны разблокироваться.

### Баг 3: Группа 1 блокируется на первое ТС после композита [REQ-3]
> При проведении ЛА композит на первую группу с положительным качеством -- заблокировалась 1 группа на первое ТС (такого действия не должно быть).

**Ожидание:** Проведение композита на группу 1 НЕ должно создавать новые блокировки для ТС в группе 1.

## Фаза 3: Алгоритмический анализ -- 3 найденных бага

### БАГ #1 (КРИТИЧЕСКИЙ): Логическая ошибка `ИЛИ` вместо `И` в `ГруппаТСТребуетБлокировки`

**Файл:** `ManagerModule.bsl` РС `гкс_ЗаблокированныеРегистрацииУсиленныйКонтроль`, строки 133-140

**Текущий код:**
```bsl
Функция ГруппаТСТребуетБлокировки(БлокирующаяГруппаТС, АнализГруппыЗавершен, СостояниеКачестваГруппы)

    Возврат ЗначениеЗаполнено(БлокирующаяГруппаТС)
        И Не АнализГруппыЗавершен
        И (СостояниеКачестваГруппы <> Перечисления.гкс_СостоянияКачества.КачествоНеПринято
        Или СостояниеКачестваГруппы <> Перечисления.гкс_СостоянияКачества.РезультатыПробПолучены);

КонецФункции
```

**Проблема:** Условие `(X <> A ИЛИ X <> B)` **ВСЕГДА ИСТИНА** для любого X, потому что любое значение не равно хотя бы одному из двух. Третья строка условия полностью бесполезна -- функция работает как:
```
ЗначениеЗаполнено(БлокирующаяГруппаТС) И Не АнализГруппыЗавершен
```

**Влияние:** Состояние качества группы полностью игнорируется. Блокировка создаётся ВСЕГДА когда есть предыдущая группа и анализ не завершён, даже если результаты уже получены или качество уже не принято.

**Связь с багами ТЗ:** Влияет на все 3 бага -- неверная оценка необходимости блокировки по группе.

**Образец:** Аналогичная логика в `ПроверитьБлокировкуДляСозданияНнР` (гкс_ВходнойКонтрольКачества) ✓ pattern

**Исправление:** Заменить `Или` на `И`:
```bsl
И (СостояниеКачестваГруппы <> Перечисления.гкс_СостоянияКачества.КачествоНеПринято
И СостояниеКачестваГруппы <> Перечисления.гкс_СостоянияКачества.РезультатыПробПолучены);
```

После исправления:
- `КачествоНеПринято` → Ложь И Истина = **Ложь** (НЕ блокируем) -- корректно
- `РезультатыПробПолучены` → Истина И Ложь = **Ложь** (НЕ блокируем) -- корректно
- `КачествоПринято` → Истина И Истина = **Истина** (блокируем, анализ ещё в процессе) -- корректно
- `ПустаяСсылка()` → Истина И Истина = **Истина** (блокируем, результат ещё не получен) -- корректно

### БАГ #2 (КРИТИЧЕСКИЙ): Неиспользуемый параметр `СостояниеКачестваПервоеТС` в `ЗаписатьБлокировкуГруппыТС`

**Файл:** `ManagerModule.bsl` РС `гкс_ЗаблокированныеРегистрацииУсиленныйКонтроль`, строки 36-52

**Текущий код:**
```bsl
Процедура ЗаписатьБлокировкуГруппыТС(ДокументРегистрации, БлокирующаяРегистрация,
        СостояниеКачестваПервоеТС,                    // <-- ПЕРЕДАЁТСЯ, НО НИГДЕ НЕ ИСПОЛЬЗУЕТСЯ!
        БлокирующаяГруппаТС, АнализГруппыЗавершен,
        СостояниеКачестваГруппы, Показатель) Экспорт

    ПустоеСостояниеКачества = Перечисления.гкс_СостоянияКачества.ПустаяСсылка();

    Если ГруппаТСТребуетБлокировки(БлокирующаяГруппаТС, АнализГруппыЗавершен, СостояниеКачестваГруппы) Тогда
        // Блокировка по группе
        ДобавитьЗаписьБлокировки(ДокументРегистрации, Показатель,
            Документы.гкс_РегистрацияНаПЛК.ПустаяСсылка(), БлокирующаяГруппаТС,
            ПустоеСостояниеКачества);
    Иначе
        // БЕЗУСЛОВНАЯ блокировка по первому ТС -- НЕТ ПРОВЕРКИ СостояниеКачестваПервоеТС!
        ДобавитьЗаписьБлокировки(ДокументРегистрации, Показатель, БлокирующаяРегистрация,
            Справочники.гкс_ГруппыТС.ПустаяСсылка(), ПустоеСостояниеКачества);
    КонецЕсли;

КонецПроцедуры
```

**Проблема:** Ветка `Иначе` (когда группа НЕ требует блокировки -- нет предыдущей группы или анализ завершён) **безусловно** создаёт блокировку по первому ТС. Параметр `СостояниеКачестваПервоеТС` передаётся в процедуру, но не используется.

**Связь с багом ТЗ #1:** Второе ТС (первое в группе 1) блокируется по первому ТС, даже если первое ТС уже прошло ЛА с "Качество принято". Предыдущей группы нет → `ГруппаТСТребуетБлокировки = Ложь` → попадает в `Иначе` → безусловная блокировка.

**Связь с багом ТЗ #3:** При проведении композита на группу 1, `ЗаполнитьЗаблокированныеРегистрацииУсиленныйКонтроль` перевыполняется и создаёт НОВЫЕ блокировки по первому ТС для всех членов группы 1 (через ту же ветку `Иначе`).

**Образец:** Паттерн проверки перечисления из `ГруппаТСТребуетБлокировки` (тот же модуль) ✓ pattern

**Исправление:** Добавить проверку `СостояниеКачестваПервоеТС` в ветку `Иначе`:
```bsl
Иначе
    // Блокировка по первому ТС -- только если первое ТС ещё не прошло качество
    Если СостояниеКачестваПервоеТС <> Перечисления.гкс_СостоянияКачества.КачествоПринято Тогда
        ДобавитьЗаписьБлокировки(ДокументРегистрации, Показатель, БлокирующаяРегистрация,
            Справочники.гкс_ГруппыТС.ПустаяСсылка(), ПустоеСостояниеКачества);
    КонецЕсли;
КонецЕсли;
```

### БАГ #3 (СРЕДНИЙ): Контекст вызова `ОбновитьЗаблокированныеТСПриЗавершенииЛА` при проведении композита

**Файл:** `CommonModules/гкс_ВходнойКонтрольКачества/Ext/Module.bsl`, строки 181-252

**Проблема:** При проведении ЛА промежуточного композита вызывается:
1. `СформироватьВспомогательныеДанныеДляЗаблокированныхТС()` → записывает состояния + разблокирует
2. `ЗаполнитьЗаблокированныеРегистрацииУсиленныйКонтроль()` → **перевычисляет блокировки и вызывает `ОбновитьЗаблокированныеТСПриЗавершенииЛА`**

Порядок вызова в `СформироватьВспомогательныеДанныеДляЗаблокированныхТС` (ObjectModule.bsl, строки ~691-710):
```
1. ЗаписатьСостоянияРегистрацииЗаблокированныхТС()     → UNION-запрос находит заблокированные ТС
2. СформироватьНаправленияНаРазгрузкуДляРазблокированныхТС() → создаёт НР
3. ЗаполнитьЗаблокированныеРегистрацииУсиленныйКонтроль()   → ПЕРЕВЫЧИСЛЯЕТ блокировки
```

На шаге 3 запрос `ТекстЗапросаЗаблокированныхРегистрацийУК` возвращает ТС из группы 1 (они попадают под правило ГруппыТС), и код в строках 227-235 вызывает `ЗаписатьБлокировкуГруппыТС`. Из-за бага #2 (безусловная блокировка по первому ТС) создаются НОВЫЕ записи блокировки для группы 1 -- **даже после только что проведённого композита с принятым качеством**.

**Связь с багом ТЗ #3:** "заблокировалась 1 группа на первое ТС" -- именно этот механизм.

**Исправление:** Исправление бага #2 автоматически решит баг #3 -- если `СостояниеКачестваПервоеТС = КачествоПринято`, блокировка по первому ТС не будет создаваться.

### Дополнительно: Анализ разблокировки группы 2 (Баг ТЗ #2)

**Путь разблокировки группы:**

```
ОбработкаПроведения (ЛА промежуточного композита на группу 1)
├── СформироватьВспомогательныеДанныеДляЗаблокированныхТС()
│   ├── ЗаписатьСостоянияРегистрацииЗаблокированныхТС()
│   │   └── UNION-запрос: находит ТС группы 2 заблокированные по БлокирующаяГруппаТС = Группа1
│   │       через: ФНП.СписокРегистраций → СоставГруппТранспорта → ЗаблокированныеРегистрацииУК
│   └── СформироватьНаправленияНаРазгрузкуДляРазблокированныхТС()
└── ЗаполнитьЗаблокированныеРегистрацииУсиленныйКонтроль()
    └── ОбновитьЗаблокированныеТСПриЗавершенииЛА() [стр. 1402-1435]
        └── ОбновитьБлокировкуГруппаТС() [стр. 1563-1590]
            └── ОбновитьСостояниеБлокировки(ЗаблокированноеТС, ..., БлокирующаяГруппаТС)
                → если КачествоПринято → Разблокировано = Истина
```

Механизм разблокировки СУЩЕСТВУЕТ (`ОбновитьБлокировкуГруппаТС`, строка 1573-1574). Для его срабатывания нужно:

1. `ОбновитьЗаблокированныеТСПриЗавершенииЛА` получает данные из `ДанныеБлокировки.ГруппыПоРегистрациям` (строка 1453)
2. Список заблокированных групп формируется в `ПолучитьДанныеБлокировкиДляРегистраций` (пакетная предзагрузка)
3. Итерирует по `ЗаблокированныеГруппыТС` и вызывает `ОбновитьБлокировкуГруппаТС`

**Возможная причина бага #2:** `ПолучитьДанныеБлокировкиДляРегистраций` формирует данные по регистрациям из запроса `ТекстЗапросаЗаблокированныхРегистрацийУК`. Этот запрос возвращает ТС, попадающие под правила УК для **текущего** ЛА. При проведении композита на группу 1, запрос может НЕ возвращать ТС из группы 2 (они не связаны с текущим ФНП), и `ОбновитьЗаблокированныеТСПриЗавершенииЛА` не получает данных для их разблокировки.

**Требуется верификация:** Прочитать `ПолучитьДанныеБлокировкиДляРегистраций` (предзагрузка данных) и `ТекстЗапросаЗаблокированныхРегистрацийУК` (строки 1668-1862) чтобы подтвердить, что запрос НЕ включает ТС группы 2 при проведении композита на группу 1.

**Альтернативная гипотеза:** Разблокировка группы 2 должна происходить через `ЗаписатьСостоянияРегистрацииЗаблокированныхТС` (UNION-запрос), но этот запрос только записывает СОСТОЯНИЯ регистрации (в РС гкс_СостоянияРегистрации), а НЕ устанавливает `Разблокировано = Истина` в РС блокировок. Нужен дополнительный шаг.
