## 2. Три корневые причины

### BUG2-1: Запрос `ВТ_ПоказателиГруппа` ищет в НЕПРАВИЛЬНОМ направлении

**Запрос 2 пакета** (строки 1241-1258):

```sql
ВЫБРАТЬ
    ГруппыТС.ПредыдущаяГруппа КАК Группа,        -- берётся ПРЕДЫДУЩАЯ группа
    ПоказателиУсиленногоКонтроляПоРегистрации.Показатель
ПОМЕСТИТЬ ВТ_ПоказателиГруппа
ИЗ
    РегистрСведений.гкс_СоставГруппТранспорта
        ВНУТРЕННЕЕ СОЕДИНЕНИЕ Справочник.гкс_ГруппыТС
        ПО СоставГруппТранспорта.ГруппаТС = ГруппыТС.Ссылка
        ВНУТРЕННЕЕ СОЕДИНЕНИЕ ВТ_РегистрацииНаПЛК
        ...
ГДЕ
    ГруппыТС.ПредыдущаяГруппа <> ЗНАЧЕНИЕ(Справочник.гкс_ГруппыТС.ПустаяСсылка)
```

**Что происходило:**
1. `ВТ_РегистрацииНаПЛК` содержит КАУТ-0009170 (не-первое ТС)
2. КАУТ-0009170 входит в **Группу 1** (через `СоставГруппТранспорта`)
3. У Группы 1 `ПредыдущаяГруппа = ПустаяСсылка()` (она первая)
4. Условие `ПредыдущаяГруппа <> ПустаяСсылка()` **ОТСЕКАЕТ Группу 1**
5. **`ВТ_ПоказателиГруппа` = ПУСТО!**

**Логическая ошибка:**
```
СТАРЫЙ ЗАПРОС (неправильно):
  Регистрация (0009170) → Группа 1 → ПредыдущаяГруппа (ПУСТО) → ничего

НУЖНО (правильно):
  Регистрация (0009170) → Группа 1 → ГруппаТС = Группа 1
  → Ищем в РС блокировок: БлокирующаяГруппаТС = Группа 1 → КАУТ-0009172
```

### BUG2-2: Ключ `ГруппыПоРегистрациям` не совпадает

**Запрос 5 пакета** `ВТ_ЗаблокированныеГруппаТС` (строка 1288):

```sql
ЕСТЬNULL(ВТ_Заблокированные.БлокирующаяРегистрация,
    ЗНАЧЕНИЕ(Документ.гкс_РегистрацияНаПЛК.ПустаяСсылка)) КАК БлокирующаяРегистрация
```

**Проблема:** Для записей, заблокированных **группой** (не регистрацией), `БлокирующаяРегистрация = ПУСТО`. Fallback `ЕСТЬNULL → ПустаяСсылка` делает ключ = ПустаяСсылка. Но в цикле обработки ищется по `ДокументРегистрации` (КАУТ-0009170) → **ключ не совпадает**.

### BUG3: Преждевременный выход из `ПолучитьДанныеДляОбновленияБлокировки`

**Функция** (строка 1485-1487, до исправления):

```bsl
Если ЗаблокированныеТС = Неопределено ИЛИ ЗаблокированныеТС.Количество() = 0 Тогда
    Возврат Неопределено;  // ← выход, даже если есть ЗаблокированныеГруппыТС!
КонецЕсли;
```

**Проблема:** В сценарии с группами КАУТ-0009170 **никого не блокирует по регистрации** → `ЗаблокированныеТС = Неопределено`. Проверка возвращала `Неопределено`, полностью игнорируя данные `ЗаблокированныеГруппыТС`. Вызывающий код (строка 1427-1428) получал `Неопределено` → `Возврат` → **цикл обработки групп (строки 1445-1455) никогда не выполнялся**.

## 3. Решение (ПРИМЕНЕНО — 3 изменения)

### Изменение 1: ОБЪЕДИНИТЬ ВСЕ в `ВТ_ПоказателиГруппа` (строка 1260)

Старый запрос сохранён без изменений. Добавлен `ОБЪЕДИНИТЬ ВСЕ` с новым SELECT, который берёт `СоставГруппТранспорта.ГруппаТС` (текущую группу регистрации из композита):

```sql
-- Старый запрос (без изменений) — ищет ПредыдущаяГруппа
ВЫБРАТЬ
    ГруппыТС.ПредыдущаяГруппа КАК Группа,
    ПоказателиУсиленногоКонтроляПоРегистрации.Показатель
...
ГДЕ
    ГруппыТС.ПредыдущаяГруппа <> ЗНАЧЕНИЕ(Справочник.гкс_ГруппыТС.ПустаяСсылка)

// GKSTCPLK-2215: Разблокировка подчинённых групп
ОБЪЕДИНИТЬ ВСЕ

ВЫБРАТЬ
    СоставГруппТранспорта2.ГруппаТС КАК Группа,
    ПоказателиУК2.Показатель КАК Показатель
ИЗ
    РегистрСведений.гкс_СоставГруппТранспорта КАК СоставГруппТранспорта2
        ВНУТРЕННЕЕ СОЕДИНЕНИЕ гкс_ПоказателиУсиленногоКонтроляПоРегистрации КАК ПоказателиУК2
            ВНУТРЕННЕЕ СОЕДИНЕНИЕ ВТ_РегистрацииНаПЛК КАК ВТ_РегистрацииНаПЛК2
            ПО ВТ_РегистрацииНаПЛК2.ДокументРегистрации = ПоказателиУК2.ДокументРегистрации
        ПО СоставГруппТранспорта2.РегистрацияТранспорта = ПоказателиУК2.ДокументРегистрации
        И ПоказателиУК2.НазначениеИспользования = ЗНАЧЕНИЕ(...ПромежуточныйКомпозит)
        И ПоказателиУК2.ТипПробы = ЗНАЧЕНИЕ(...Композитная)
```

### Изменение 2: ЕСТЬNULL fallback на регистрацию из состава группы (строка 1304)

```sql
-- Было:
ЕСТЬNULL(ВТ_Заблокированные.БлокирующаяРегистрация,
    ЗНАЧЕНИЕ(Документ.гкс_РегистрацияНаПЛК.ПустаяСсылка)) КАК БлокирующаяРегистрация

-- Стало:
// GKSTCPLK-2215: fallback на регистрацию из состава группы вместо ПустаяСсылка
ЕСТЬNULL(ВТ_Заблокированные.БлокирующаяРегистрация,
    гкс_СоставГруппТранспорта.РегистрацияТранспорта) КАК БлокирующаяРегистрация
```

### Изменение 3: Проверка ТС ИЛИ групп в `ПолучитьДанныеДляОбновленияБлокировки` (строка 1485)

```bsl
-- Было:
Если ЗаблокированныеТС = Неопределено ИЛИ ЗаблокированныеТС.Количество() = 0 Тогда
    Возврат Неопределено;
КонецЕсли;

-- Стало:
// GKSTCPLK-2215: Проверяем наличие данных по ТС ИЛИ по группам (не только по ТС)
ЕстьЗаблокированныеТС = ЗаблокированныеТС <> Неопределено И ЗаблокированныеТС.Количество() > 0;
ЕстьЗаблокированныеГруппы = ЗаблокированныеГруппыТС <> Неопределено И ЗаблокированныеГруппыТС.Количество() > 0;

Если НЕ ЕстьЗаблокированныеТС И НЕ ЕстьЗаблокированныеГруппы Тогда
    Возврат Неопределено;
КонецЕсли;
```

| Группа 2 (ПредыдущаяГруппа=Группа 1) блокирует Группу 3 | Находит Группа 1 | Находит Группа 2 | Оба работают |
| Регистрация не в группе | 0 строк | 0 строк | Без изменений |
| Регистрация в группе, но группа никого не блокирует | Может найти | Находит группу, но `ВТ_ЗаблокированныеГруппаТС` пуст (INNER JOIN) | Ничего не делает |
| Есть ЗаблокированныеТС, нет групп | Работало | Работает | Без изменений |
| Есть группы, нет ЗаблокированныеТС | **Возврат Неопределено (BUG3)** | Проходит проверку | **Исправлено** |
| Нет ни ТС, ни групп | Возврат Неопределено | Возврат Неопределено | Без изменений |

## 6. Замечание (не связано с текущим багом)

Строки 1388-1389 используют `И` вместо `ИЛИ` в проверке дубликатов:
```bsl
Если БлокируюшаяГруппы["БлокирующаяГруппаТС"] <> БлокирующаяГруппаТС
    И БлокируюшаяГруппы["ЗаблокированноеТС"] <> ЗаблокированноеТС Тогда
```
При `И` запись добавляется только если **оба** поля отличаются. Если совпадает только одно поле (например, та же группа блокирует другое ТС) — запись НЕ добавится. Потенциальный баг при множественных блокировках. В текущем сценарии с одной записью блокировки не влияет.
