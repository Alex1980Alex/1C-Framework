## 2. Выявленные проблемы

### 2.1 КРИТИЧЕСКАЯ: Фантомные записи в регистре данных

**94 записи** в `гкс_ЭлектронныеТабло`, но настройки есть **только для 1 из 4 типов** табло.

| ВидТабло | Записей в данных | Настроек | RMQ отправляется? |
|----------|------------------|----------|-------------------|
| НеПрошедшиеРегистрацию | 1 рег. / 4 авто | 2 | ✅ ДА |
| НазначениеНаВыгрузку | 28 рег. / 24 авто | 0 | ❌ НЕТ (нет настроек) |
| НазначениеНаВесы | 60 рег. / 40 авто | 0 | ❌ НЕТ (нет настроек) |
| ОжиданияПроб | 5 рег. / 3 авто | 0 | ❌ НЕТ (нет настроек) |

**Причина:** До GKSTCPLK-2256 M-1 `ОбновитьТабло()` вызывался безусловно — записи создавались в регистре данных даже без настроек табло. После M-1 (проверка `СписокТабло.Количество() = 0`) новые записи не создаются, но **старые не очищены**.

**Следствие:** 93 из 94 записей — «мёртвые» данные, которые никогда не отправляются на физические табло.

### 2.2 НазначениеНаВесы — нулевые даты

60 записей с `ЗаписьВОчередь = 0001-01-01T00:00:00` — время записи в очередь не заполнено. Это значит, что поле `ЗаписьВОчередь` (измерение) заполнялось пустой датой при записи. Данные некорректны и не несут информации для отображения.

### 2.3 Отсутствие трекинга отправки

Подтверждено: ни регистр настроек (`гкс_НастройкаЭлектронногоТабло`), ни регистр данных (`гкс_ЭлектронныеТабло`) не содержат информации о дате/времени последней отправки сообщения.

## 3. Анализ пустых сообщений

### 3.1 Когда отправляются пустые сообщения

Пустое сообщение отправляется когда:
1. Смена состояния регистрации триггерит `СформироватьВариантыДляТабло()`
2. Для варианта найдены настройки в `гкс_НастройкаЭлектронногоТабло` (прошёл фильтр M-1)
3. Запрос `ПолучитьСписокРегистрацийДляТабло()` возвращает 0 строк (все машины уехали)
4. `НаборЗаписей.Записать(Истина)` — записывает пустой набор (удаляет данные из регистра)
5. `ОтправитьДанныеНаЭлектронноеТабло()` — формирует XDTO без DataTable → RMQ

### 3.2 Когда НЕ отправляются пустые сообщения

- Если нет настроек для данного варианта → GKSTCPLK-2256 M-1 пропускает (стр. 265-267)
- Если вид перевозки ≠ Автомобиль (стр. 115)
- Если `ИспользуетсяЭлектронноеТабло(ТочкаМаршрута) = Ложь` (стр. 116)
- Если `ИспользоватьЭлектронноеТабло` (функциональная опция) = Ложь (стр. 5-9)

### 3.3 Вывод

**На тестовой базе пустые сообщения НЕ являются проблемой:** всего 2 настройки, и только для типа "НеПрошедшиеРегистрацию". Пустые сообщения отправляются только при смене состояния авто, зарегистрированного на ПЛК Светлый.

**На продуктивной базе** картина может быть иной — нужно проверить количество настроек и частоту смен состояний.

## 6. Цепочка вызовов (из анализа кода)

### 6.1 Основной триггер (смена состояния регистрации)

```
гкс_СостоянияРегистрации.RecordSetModule:
  ПередЗаписью (стр. 12-22):
    → СформироватьВариантыДляТабло(ДокументРегистрации) (стр. 111-154)
      Условия: ВидПеревозки = Автомобиль И ИспользуетсяЭлектронноеТабло(ТочкаМаршрута)
      По состоянию формирует варианты:
        Прибыл → НазначениеНаВесы
        ВыгрузкаРазрешена → НазначениеНаВыгрузку + ОжиданияПроб
        КачествоНеПринято → ОжиданияПроб

  ПриЗаписи (стр. 24-51):
    → ЗарегистрироватьОбъектКОбменуСТабло(Отказ) (стр. 239-283)
      Для каждого варианта:
        → [GKSTCPLK-2256 M-1] ПолучитьНастройкиПоВидуТабло() → СписокТабло (стр. 262-264)
        → Если нет настроек → Продолжить (стр. 265-267)
        → ОбновитьТабло(ВидТабло, СтруктураПараметров, Отказ) (стр. 270)
        → Для каждого СтрокаТабло из СписокТабло (стр. 276-278):
            → ОтправитьДанныеНаЭлектронноеТабло(СтрокаТабло.Табло)
```

## 7. Рекомендации

### 7.1 Очистка фантомных записей

Перед или после внедрения GKSTCPLK-2340 рекомендуется очистить «мёртвые» записи в `гкс_ЭлектронныеТабло`. Запрос для определения записей без настроек:

```sql
ВЫБРАТЬ
    ЭлектронныеТабло.ВидТабло,
    КОЛИЧЕСТВО(*) КАК КолвоЗаписей
ИЗ
    РегистрСведений.гкс_ЭлектронныеТабло КАК ЭлектронныеТабло
        ЛЕВОЕ СОЕДИНЕНИЕ РегистрСведений.гкс_НастройкаЭлектронногоТабло КАК Настройки
        ПО ЭлектронныеТабло.ТочкаМаршрута = Настройки.ТочкаМаршрута
            И ЭлектронныеТабло.ВидТабло = Настройки.ВидТабло
ГДЕ
    Настройки.Табло ЕСТЬ NULL
СГРУППИРОВАТЬ ПО
    ЭлектронныеТабло.ВидТабло
```

### 7.2 Проверка на продуктивной базе

Тестовая база содержит минимум настроек (2 записи). На проде количество может быть значительно больше. Рекомендуется выполнить аналогичные запросы на продуктивной базе для оценки масштаба.

### 7.3 Анализ пустых сообщений — итоговое решение

Пустые сообщения **необходимы** — они очищают экран физического табло. Без них уехавшая машина продолжит отображаться. Оптимизация (пропуск повторных пустых) несёт риск зависания устаревших данных при потере RMQ-сообщения.
