## 8. БАГ #5 ПОДТВЕРЖДЁН: Дубликаты в НеПрошедшиеРегистрацию

| Авто | Кол-во записей | Номенклатура |
|------|---------------|-------------|
| **С712НВ39** | **7** | Пшеница продовольственная мягкая |
| С519ВЕ39 | 2 | Пшеница продовольственная мягкая |

**С712НВ39** повторяется 7 раз с одинаковой номенклатурой — это записи из электронной очереди с разным временем `ЗаписьВОчередь` (31.10.2025, каждые 12 минут с 09:24 до 11:24).

**Корневая причина**: Регламентное задание `гкс_ОбновлениеТаблоЭлектроннойОчереди` перезаписывает набор записей целиком, но если одно ТС имеет несколько записей в очереди с разным временем — каждая попадает как отдельная запись в регистр (ЗаписьВОчередь — измерение регистра).

## 9. НеПрошедшиеРегистрацию — ТС без документов регистрации

Запрос `Документ.гкс_РегистрацияНаПЛК` с фильтром по ТранспортноеСредство для 4 ключевых авто (С712НВ39, С519ВЕ39, О972ТТ39, Н291ХУ39) вернул **0 результатов** (нет проведённых документов регистрации с 30.10.2025).

Однако в электронной очереди `гкс_ОчередьПриемкиПЛК` для С519ВЕ39 найдено **20+ записей** с НачалоПериода до 06-07.11.2025, с РАЗНЫМИ номенклатурами (Пшеница и Соевые бобы).

**Вывод**: Эти ТС записались в очередь, но так и не прошли регистрацию. Регламентное задание продолжало показывать их на табло. С остановкой очереди (07.11.2025) обновление прекратилось, и последний снимок (31.10.2025) завис навсегда.

## 12. Запросы использованные для baseline

### Запрос 1: Настройки табло
```sql
ВЫБРАТЬ
    НастройкаТабло.ТочкаМаршрута.Наименование КАК ТочкаМаршрута,
    НастройкаТабло.ВидТабло,
    НастройкаТабло.Номенклатура.Наименование КАК Номенклатура,
    НастройкаТабло.Табло.Наименование КАК Табло,
    НастройкаТабло.ВидПеревозки
ИЗ
    РегистрСведений.гкс_НастройкаЭлектронногоТабло КАК НастройкаТабло
```

### Запрос 2: Содержимое регистра (сводка)
```sql
ВЫБРАТЬ
    Табло.ВидТабло,
    КОЛИЧЕСТВО(*) КАК КолЗаписей,
    МИНИМУМ(Табло.ЗаписьВОчередь) КАК МинДата,
    МАКСИМУМ(Табло.ЗаписьВОчередь) КАК МаксДата
ИЗ
    РегистрСведений.гкс_ЭлектронныеТабло КАК Табло
СГРУППИРОВАТЬ ПО Табло.ВидТабло
```

### Запрос 3: Зависшие НазначениеНаВесы с текущими состояниями
```sql
ВЫБРАТЬ
    Табло.Авто,
    ПРЕДСТАВЛЕНИЕ(Табло.ДокументРегистрации) КАК ДокументРегистрации,
    Табло.ВидТабло, Состояния.Состояние
ИЗ
    РегистрСведений.гкс_ЭлектронныеТабло КАК Табло
        ЛЕВОЕ СОЕДИНЕНИЕ РегистрСведений.гкс_СостоянияРегистрации.СрезПоследних КАК Состояния
        ПО Табло.ДокументРегистрации = Состояния.ДокументРегистрации
ГДЕ
    Табло.ВидТабло = ЗНАЧЕНИЕ(Перечисление.гкс_ВидыЭлектронныхТабло.НазначениеНаВесы)
```

### Запрос 4: Дубли в НеПрошедшиеРегистрацию
```sql
ВЫБРАТЬ
    Табло.Авто, КОЛИЧЕСТВО(*) КАК КолЗаписей
ИЗ
    РегистрСведений.гкс_ЭлектронныеТабло КАК Табло
ГДЕ
    Табло.ВидТабло = ЗНАЧЕНИЕ(Перечисление.гкс_ВидыЭлектронныхТабло.НеПрошедшиеРегистрацию)
СГРУППИРОВАТЬ ПО Табло.Авто
ИМЕЮЩИЕ КОЛИЧЕСТВО(*) > 1
```

### Запрос 5: Регистрации ТС из НеПрошедшиеРегистрацию
```sql
ВЫБРАТЬ
    Регистрация.ТранспортноеСредство.Наименование КАК Авто,
    ПРЕДСТАВЛЕНИЕ(Регистрация.Ссылка) КАК ДокРегистрации,
    Регистрация.Дата
ИЗ
    Документ.гкс_РегистрацияНаПЛК КАК Регистрация
ГДЕ
    Регистрация.ТранспортноеСредство.Наименование В("С712НВ39", "С519ВЕ39", "О972ТТ39", "Н291ХУ39")
    И Регистрация.Дата >= ДАТАВРЕМЯ(2025, 10, 30)
    И Регистрация.Проведен = ИСТИНА
-- Результат: 0 записей (ни одно ТС не зарегистрировано)
```
