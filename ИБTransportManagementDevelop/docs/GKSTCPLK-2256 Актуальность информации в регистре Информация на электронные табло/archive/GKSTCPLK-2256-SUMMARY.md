# GKSTCPLK-2256 -- Самари

## Суть проблемы

Данные на электронных табло ПЛК (Светлый, КАТ) **"зависают"** -- записи не удаляются из регистра `гкс_ЭлектронныеТабло` при прохождении ТС по маршруту. Корневая причина: запросы, формирующие данные для табло, не фильтруют по актуальному состоянию регистрации.

**Заказчик**: Новосельцева Надежда Октаевна (аналитик ГК "Содружество")

## Инфраструктура табло

- **Светлый**: 2 физических табло (НеПрошедшиеРегистрацию), IP 172.20.23.250 / 172.20.22.202
- **КАТ**: 4 табло "Назначение на выгрузку" + 4 табло "Ожидания проб"
- Все табло показывают по 3 строки

## 3 корневых причины (из кода)

| # | Причина | Где | Следствие |
|---|---------|-----|-----------|
| 1 | Нет фильтра `ГДЕ Состояние В(&СписокСостояний)` для НазначениеНаВесы | `гкс_ИнтеграцияСЭлектроннымТаблоСервер`, стр. 278-305 | ТС с любым статусом (Выгружен, Убыл) остаются на табло |
| 2 | Нет фильтра по `Номенклатура` в запросе отображения НеПрошедшиеРегистрацию | `гкс_ЭлектронныеТабло.ManagerModule`, стр. 44-62 | Табло с фильтром по номенклатуре показывает ВСЕ записи |
| 3 | Нет проверки факта регистрации в запросе электронной очереди | `гкс_СтатусыЗаписейВОчередиПриемкиПЛК.ManagerModule`, стр. 89-156 | Зарегистрированные ТС продолжают отображаться |

## 3 дополнительных проблемы (из диалога с заказчиком)

| # | Проблема | Суть | Приоритет |
|---|---------|------|-----------|
| 4 | Записи для ненастроенных видов табло | Генерируются записи для видов, у которых нет физического табло на площадке | Средний |
| 5 | Возможная потеря записей | `ПЕРВЫЕ 10` в запросе -- при > 10 ТС часть не попадёт на табло | Средний |
| 6 | Нет истории для расследования | Регистр -- транзитный кэш без журнала; невозможно понять, что было на табло | Низкий |

## 4 точки модификации

| # | Что делать | Файл | Приоритет | Объём |
|---|-----------|------|-----------|-------|
| 1 | Добавить `ГДЕ Состояние В(&СписокСостояний)` | `гкс_ИнтеграцияСЭлектроннымТаблоСервер/Module.bsl` | Критичный | ~3 строки |
| 2 | Добавить фильтр `Номенклатура = &Номенклатура` (с ПустаяСсылка) | `гкс_ЭлектронныеТабло/ManagerModule.bsl` | Критичный | ~3 строки |
| 3 | LEFT JOIN с регистрациями, исключить зарегистрированных | `гкс_СтатусыЗаписейВОчередиПриемкиПЛК/ManagerModule.bsl` | Важный | ~10 строк |
| 4 | Разделить набор записей по Номенклатуре (опционально) | `гкс_ИнтеграцияСЭлектроннымТаблоСервер/Module.bsl` | Низкий | ~5 строк |

**Порядок**: Точка 1 + 2 (параллельно) -> Точка 3 -> [Точка 4 опционально]

## Два пути обновления табло

- **Путь А** (событийный): `гкс_СостоянияРегистрации.ПриЗаписи()` -> `ОбновитьТабло()` -> RMQ. Виды: НазначениеНаВесы, НазначениеНаВыгрузку, ОжиданияПроб
- **Путь Б** (регламентный): задание `гкс_ОбновлениеТаблоЭлектроннойОчереди`. Вид: НеПрошедшиеРегистрацию

## Baseline (01.04.2026, testdb1c)

- **64 записи** НазначениеНаВесы — из них 58 зависших (90.6%), только 6 со статусом "Прибыл"; старейшие -- март 2025
- **5 ТС** с дублями номенклатуры (те же: А117СО62RUS, В008АН136RUS, Е212АВ46, ТЕСТОВЫЙАВТОМОБИЛЬ1, ТЕСТОВЫЙАВТОМОБИЛЬ2)
- **8 дублей** С111СС39 + **5 дублей** О412ТХ39 в НеПрошедшиеРегистрацию
- **Всего в регистре**: 113 записей (64+29+15+5), из них 98 (86.7%) — для ненастроенных видов табло

## Риски

1. Точка 2 может сломать единые табло без отбора -> митигация: `ИЛИ &Номенклатура = ПустаяСсылка`
2. Связь ОчередьПриемки <-> РегистрацияНаПЛК не очевидна -> нужна верификация по живой базе
3. После деплоя нужна очистка зависших записей (или дождаться цикла регламентного задания)

## Открытые вопросы

1. Как связаны `гкс_ОчередьПриемкиПЛК` и `гкс_РегистрацияНаПЛК`? (поле связи)
2. Есть ли табло НеПрошедшиеРегистрацию БЕЗ фильтра по номенклатуре?
3. Нужна ли одноразовая обработка очистки?
4. Бывает ли > 10 одновременных регистраций на одной точке маршрута? (потеря записей)
5. Нужен ли рефакторинг механизма? (заказчик допускает переписать)
6. testdb1c покрывает только Светлый -- нужна проверка КАТ (ПЛК Курск)

## Указания заказчика (из диалога)

1. **"Сначала разобраться с механизмом"** -- понять, как формируется регистр
2. **"КАТ -- интереснее"** -- на КАТе другие виды табло, более сложные сценарии
