  Шаг 3: Цикл по записям набора (стр. 124-147)

  Для Каждого РегистрСведенийЗапись Из ЭтотОбъект Цикл

  Для каждой записи набора:

  3.1 Получение текущего состояния (стр. 126)

  ТекущееСостояние = гкс_ПриемкаТранспорта.ТекущееСостояниеРегистрации(Док)

  Цепочка вызовов:
  гкс_ПриемкаТранспорта.ТекущееСостояниеРегистрации(Док)
    → РегистрыСведений.гкс_СостоянияРегистрации.ТекущееСостояниеПоРегистрации(Док)     ← БЕЗ даты!
      → ТекущиеДанныеСостоянияПоРегистрации(Док, Неопределено)
        → Запрос: СрезПоследних(NULL, ДокументРегистрации = Док)

  Критично: Дата = Неопределено → СрезПоследних без ограничения по дате → возвращает самое последнее состояние из всех периодов.

  Это отличается от СтароеСостояние (стр. 70), где Дата = Период → срез по конкретному периоду.

  3.2 Три независимых условия

  Запись.Состояние  = то, что ЗАПИСЫВАЕТСЯ (новое для данного периода)
  ТекущееСостояние  = то, что СЕЙЧАС В БАЗЕ (последнее по всем периодам)

  Условие 1 — Прибыл (стр. 128-132):
  Если Состояние = Прибыл ИЛИ ТекущееСостояние = Прибыл
  → ДобавитьВариантНазначениеНаВесы: ВидТабло = НазначениеНаВесы, СписокСостояний = [Прибыл]
  - Заполняет Номенклатуру из ДокументРегистрации.Номенклатура
  - Смысл: при статусе "Прибыл" ТС нужно показать на табло весов

  Условие 2 — ВыгрузкаРазрешена (стр. 134-138):
  Если ТекущееСостояние = ВыгрузкаРазрешена ИЛИ Состояние = ВыгрузкаРазрешена
  → ДобавитьВариантНазначениеНаВыгрузку: ВидТабло = НазначениеНаВыгрузку, СписокСостояний = [ВыгрузкаРазрешена]
  - Заполняет ЯмуРазгрузки (из ДопСвойств или из НаправлениеНаРазгрузку)
  - Также вызывает ДобавитьВариантОжиданияПроб внутри (стр. 180) — всегда добавляет парный вариант
  - Смысл: при выгрузке нужно обновить и табло выгрузки, и табло ожидания проб

  Условие 3 — КачествоНеПринято (стр. 140-146):
  Если (ТекущееСостояние = КачествоНеПринято И Состояние <> ВыгрузкаРазрешена)
      ИЛИ Состояние = КачествоНеПринято
  → ДобавитьВариантОжиданияПроб: ВидТабло = ОжиданияПроб, СписокСостояний = [ВыгрузкаРазрешена, КачествоНеПринято]
  - Заполняет Весы из документа взвешивания на въезде
  - Смысл: при отклонении качества ТС попадает в список ожидания пересдачи проб

  Шаг 4: Свёртка (стр. 149-150)

  СвернутьПо = "ТочкаМаршрута,Номенклатура,ТипРегистрации,ВидПеревозки,ВидТабло,СписокСостояний,ЯмаРазгрузки,Весы";
  ВариантыДляТабло.Свернуть(СвернутьПо, "");

  Удаляет дубли, если несколько записей в наборе сгенерировали одинаковые варианты. Суммируемых колонок нет (второй параметр пуст).

  B4. Состояние = Нейтральное, ТекущееСостояние = Нейтральное
  - Ничего — ни одно условие не срабатывает, табло не обновляется
  - Бизнес-смысл: переход между состояниями, не связанными с табло (например, «ВзятыПробы» → «РезультатыПробПолучены»)

  ---
  Общий принцип

  Условия проверяют и новое, и текущее состояние по одной причине:

  ┌──────────────────────┬──────────────────────────────────────────────────┐
  │     Направление      │                      Зачем                       │
  ├──────────────────────┼──────────────────────────────────────────────────┤
  │ Состояние = X        │ Вход в состояние → добавить ТС на табло          │
  ├──────────────────────┼──────────────────────────────────────────────────┤
  │ ТекущееСостояние = X │ Выход из состояния → убрать/обновить ТС на табло │
  └──────────────────────┴──────────────────────────────────────────────────┘

  Код не различает «добавить» и «убрать» — он просто пересчитывает данные табло через ОбновитьТабло. Поэтому вызов нужен в обоих направлениях.

  Потенциальная проблема: сценарий A9

  При Состояние = КачествоНеПринято, ТекущееСостояние = ВыгрузкаРазрешена:
  - Усл.2 добавляет ОжиданияПроб (из ДобавитьВариантНазначениеНаВыгрузку, стр. 180)
  - Усл.3 добавляет ОжиданияПроб ещё раз

  После Свернуть (стр. 150) — дубли не схлопнутся, т.к. СписокСостояний — это объект СписокЗначений, свёртка сравнивает по ссылке, а не по содержимому. Итого: ОбновитьТабло для
   «ОжиданияПроб» вызовется дважды — лишний вызов.

  В отличие от сценария A5, где это предотвращено исключением Состояние <> ВыгрузкаРазрешена.

  ---
  SUMMARY

  1. Что делает СформироватьВариантыДляТабло:
     Формирует таблицу вариантов обновления электронных табло при записи набора регистра гкс_СостоянияРегистрации.
     Вызывается в ПередЗаписью, результат передаётся через ДополнительныеСвойства в ПриЗаписи → ОбновитьТабло.

  2. Guard: только Автомобиль + ИспользуетсяЭлектронноеТабло(ТочкаМаршрута).

  3. Из 17 состояний перечисления только 3 влияют на табло:
     - Прибыл → табло «Назначение на весы»
     - ВыгрузкаРазрешена → табло «Назначение на выгрузку» + «Ожидания проб»
     - КачествоНеПринято → табло «Ожидания проб»
     Остальные 14 состояний — нейтральные (не триггерят условия напрямую).

  4. Три условия НЕЗАВИСИМЫЕ (Если, не ИначеЕсли) — могут сработать несколько на одну запись.
     Каждое проверяет ОБА значения: записываемое (Состояние) и текущее в базе (ТекущееСостояние).
     Причина: при ВХОДЕ в состояние — добавить ТС на табло, при ВЫХОДЕ — убрать.

  5. Два разных «текущих состояния» — корень расхождения:
     - СтароеСостояние = СрезПоследних(Период, Док) — по конкретному периоду, для ЕстьИзменениеСостояния
     - ТекущееСостояние = СрезПоследних(NULL, Док) — без даты, последнее по всем периодам, для условий табло
     При перезаписи того же периода: ЕстьИзменениеСостояния = Ложь, но ТекущееСостояние может отличаться.

  6. Подтверждённый кейс (отладка):
     Состояние = Прибыл, ТекущееСостояние = КачествоНеПринято → Усл.1 + Усл.3 → 2 варианта.

  7. Всего 16 комбинаций (4×4): 9 с триггерными состояниями (группа A), 4 с нейтральными (группа B),
     из них 1 пустая (Нейтральное × Нейтральное — табло не обновляется).

  8. Потенциальная проблема — сценарий A9 (КачествоНеПринято × ВыгрузкаРазрешена):
     Усл.2 и Усл.3 оба добавляют ОжиданияПроб. Свернуть не схлопнет (СписокЗначений — разные объекты).
     ОбновитьТабло вызовется дважды. В A5 (зеркальный) — защита есть (Состояние <> ВыгрузкаРазрешена).

  ---
  ВОЗМОЖНЫЕ ВАРИАНТЫ И ПРИЧИНЫ

  Код генерирует от 0 до 3 строк в таблице ВариантыДляТабло. Каждая строка = один вызов ОбновитьТабло.

  0 вариантов (табло не обновляется):
    - Нейтральное × Нейтральное (14 × 14 = 196 комбинаций)
      Переход не затрагивает ни одно табло. Пример: ВзятыПробы → РезультатыПробПолучены.

  1 вариант — НазначениеНаВесы:
    - Прибыл × Прибыл — перезапись того же состояния, просто обновить табло весов
    - Прибыл × Нейтральное — ТС прибыло, показать на весах
    - Нейтральное × Прибыл — ТС ушло с «прибыл», убрать с весов

  1 вариант — ОжиданияПроб:
    - КачествоНеПринято × КачествоНеПринято — перезапись, обновить табло проб
    - КачествоНеПринято × Нейтральное — качество отклонено, показать ожидание проб
    - Нейтральное × КачествоНеПринято — ушёл из «качество не принято», убрать с табло

  2 варианта — НазначениеНаВыгрузку + ОжиданияПроб (оба от Усл.2):
    - ВыгрузкаРазрешена × ВыгрузкаРазрешена — перезапись, обновить выгрузку + пробы
    - ВыгрузкаРазрешена × Нейтральное — разрешена выгрузка, показать на обоих табло
    - ВыгрузкаРазрешена × КачествоНеПринято — качество не приняли, но выгрузку разрешили.
      Обновить выгрузку + пробы. Усл.3 не дублирует (исключение Состояние <> ВыгрузкаРазрешена)
    - Нейтральное × ВыгрузкаРазрешена — ушёл из «выгрузка разрешена», убрать с обоих табло

  2 варианта — НазначениеНаВесы + ОжиданияПроб (Усл.1 + Усл.3):
    - Прибыл × КачествоНеПринято — ТС повторно прибыло после отклонения качества.
      Показать на весах + обновить ожидание проб
    - КачествоНеПринято × Прибыл — было «прибыл», качество отклонили.
      Убрать с весов + показать ожидание проб

  3 варианта — НазначениеНаВесы + НазначениеНаВыгрузку + ОжиданияПроб (Усл.1 + Усл.2):
    - Прибыл × ВыгрузкаРазрешена — аномалия: ТС вернулось на «прибыл» после разрешения выгрузки.
      Обновить все три табло
    - ВыгрузкаРазрешена × Прибыл — прибывшее ТС получило разрешение на выгрузку.
      Убрать с весов + показать на выгрузке + обновить ожидание проб

  3 варианта с ДУБЛЕМ — НазначениеНаВыгрузку + ОжиданияПроб ×2 (Усл.2 + Усл.3):
    - КачествоНеПринято × ВыгрузкаРазрешена — ПРОБЛЕМА:
      Усл.2 добавляет НаВыгрузку + ОжиданияПроб.
      Усл.3 добавляет ОжиданияПроб повторно.
      Свернуть не помогает (разные объекты СписокЗначений).
      Итого: ОбновитьТабло «ОжиданияПроб» вызовется дважды.
      В зеркальном A5 защита есть (Состояние <> ВыгрузкаРазрешена), здесь — нет.

  Почему именно так:

  1. ВХОД + ВЫХОД: каждое условие проверяет оба направления перехода.
     При входе в триггерное состояние — ТС ПОЯВЛЯЕТСЯ на табло.
     При выходе из триггерного состояния — ТС ИСЧЕЗАЕТ с табло.
     Код не различает эти операции — всегда полный пересчёт через ОбновитьТабло.

  2. ПАРНОСТЬ Усл.2: ВыгрузкаРазрешена всегда обновляет ДВА табло (выгрузку + пробы),
     потому что разрешение выгрузки влияет и на очередь выгрузки, и на список ожидания проб.
     Это единственное условие с «вложенным» вызовом (стр. 180).

  3. ИСКЛЮЧЕНИЕ в Усл.3: проверка Состояние <> ВыгрузкаРазрешена предотвращает дубль
     ОжиданияПроб в сценарии A5 (ВыгрузкаРазрешена × КачествоНеПринято).
     Но зеркальный сценарий A9 (КачествоНеПринято × ВыгрузкаРазрешена) НЕ защищён —
     исключение проверяет только записываемое Состояние, а не ТекущееСостояние.

  4. НЕЙТРАЛЬНЫЕ СОСТОЯНИЯ (14 из 17): не триггерят условия сами по себе,
     но если ТекущееСостояние триггерное — обновление всё равно происходит.
     Это нужно чтобы убрать ТС с табло при уходе из триггерного состояния.
