# GKSTCPLK-2256: Цепочка обновления электронных табло

## 1. Точка входа: запись состояния регистрации

```
УстановитьСостояниеРегистрации(ДанныеЗаписи)          // ManagerModule, стр. 35
  → ДобавитьЗапись(ДанныеЗаписи)                       // ManagerModule, стр. 24
    → ОбменДаннымиСлужебный.ДобавитьЗаписьВРегистрСведений()
      → НаборЗаписей.Записать()                         // Платформа вызывает события ↓
```

Также вызывается из:
- `гкс_ВходнойКонтрольКачества.ЗаписатьСостояниеРегистрации` (стр. 1095) — прямая запись набора
- `гкс_ПриемкаНаПЛКСервер` (стр. 105) — запись пустого набора (отмена)

## 2. ПередЗаписью (RecordSetModule, стр. 13-23)

```
ПередЗаписью(Отказ, Замещение)
│
├─ ЗаполнитьДополнительныеСвойстваПередЗаписью()      // стр. 58-89
│   ├─ ДокументРегистрации  ← Отбор.ДокументРегистрации.Значение
│   ├─ Номенклатура         ← реквизит документа регистрации
│   ├─ СтароеСостояние      ← ТекущееСостояниеПоРегистрации(Док, Период)
│   ├─ НовоеСостояние       ← Выгрузить()[0].Состояние
│   ├─ ТочкаМаршрута        ← Выгрузить()[0].ТочкаМаршрута
│   ├─ Период               ← Отбор.Период.Значение
│   └─ ЕстьИзменениеСостояния ← НовоеСостояние <> СтароеСостояние
│
└─ СформироватьВариантыДляТабло(ДокументРегистрации)   // стр. 111-154
    ├─ Проверка: ВидПеревозки = Автомобиль И ИспользуетсяЭлектронноеТабло
    ├─ Цикл по ЭтотОбъект → формирует ТаблицуЗначений вариантов
    ├─ Свернуть по ключевым полям
    └─ ДополнительныеСвойства.Вставить("ВариантыДляТабло", ...)
```

## 3. Логика формирования вариантов (стр. 124-147)

Для **каждой записи** в наборе проверяются **три независимых условия** (не ИначеЕсли!):

| Условие | Проверка | Процедура | ВидТабло |
|---------|----------|-----------|----------|
| 1 (стр. 128) | `Состояние = Прибыл` ИЛИ `ТекущееСостояние = Прибыл` | `ДобавитьВариантНазначениеНаВесы` | НазначениеНаВесы |
| 2 (стр. 134) | `ТекущееСостояние = ВыгрузкаРазрешена` ИЛИ `Состояние = ВыгрузкаРазрешена` | `ДобавитьВариантНазначениеНаВыгрузку` (+ внутри вызывает ОжиданияПроб) | НазначениеНаВыгрузку + ОжиданияПроб |
| 3 (стр. 140) | `(ТекущееСостояние = КачествоНеПринято` И `Состояние <> ВыгрузкаРазрешена)` ИЛИ `Состояние = КачествоНеПринято` | `ДобавитьВариантОжиданияПроб` | ОжиданияПроб |

**Ключевое**: `ТекущееСостояние` (стр. 126) получается через `гкс_ПриемкаТранспорта.ТекущееСостояниеРегистрации(Док)` — **без периода**, общее текущее состояние.

## 4. ПриЗаписи (RecordSetModule, стр. 25-52)

```
ПриЗаписи(Отказ, Замещение)
│
├─ Если ДополнительныеСвойства.Свойство("ВариантыДляТабло")
│   └─ ЗарегистрироватьОбъектКОбменуСТабло(Отказ)      // стр. 239
│       └─ Цикл по ВариантыДляТабло
│           └─ гкс_ИнтеграцияСЭлектроннымТаблоСервер.ОбновитьТабло(ВидТабло, Параметры, Отказ)
│
└─ Если ЕстьИзменениеСостояния И состояние в списке для Кверион
    └─ гкс_ИнтеграцияСКверионСервер.ВыгрузитьСообщениеВКверион(Параметры, Отказ)
```

## 5. Два вызова ОбновитьТабло — причина

Отладка подтвердила: **одна запись в наборе, два условия срабатывают одновременно**.

```
Состояние (записываемое)  = Прибыл
ТекущееСостояние (в базе)  = КачествоНеПринято
ЕстьИзменениеСостояния     = Ложь
```

| # | Условие | Результат | ВидТабло |
|---|---------|-----------|----------|
| [0] | Условие 1: `Прибыл = Прибыл` | TRUE | Назначение на весы |
| [1] | Условие 3: `КачествоНеПринято = КачествоНеПринято И Прибыл ≠ ВыгрузкаРазрешена` | TRUE | Ожидания проб |

При переходе из "Качество не принято" → "Прибыл" обновляются оба табло:
1. **Назначение на весы** — показать, что ТС прибыло
2. **Ожидания проб** — обновить/убрать неактуальную информацию

## 6. Расхождение: ЕстьИзменениеСостояния = Ложь

Два **разных метода** для получения "текущего" состояния:

| Переменная | Метод | Модуль | Параметры |
|------------|-------|--------|-----------|
| `СтароеСостояние` (стр. 70) | `ТекущееСостояниеПоРегистрации` | РегистрыСведений.гкс_СостоянияРегистрации | Док, **Период** |
| `ТекущееСостояние` (стр. 126) | `ТекущееСостояниеРегистрации` | гкс_ПриемкаТранспорта | Док (без периода) |

- `СтароеСостояние` по конкретному периоду = Прибыл → `ЕстьИзменениеСостояния = Ложь`
- `ТекущееСостояние` общее = КачествоНеПринято (более поздняя запись в регистре)

## 7. Второй источник: гкс_СтатусыЗаписейВОчередиПриемкиПЛК

Аналогичная логика обновления табло в `RecordSetModule` регистра `гкс_СтатусыЗаписейВОчередиПриемкиПЛК`:
- Формирует `ТаблицаВариантовТабло` и сворачивает (стр. 72-75)
- Вставляет в `ДополнительныеСвойства.ВариантыДляТабло` (стр. 75)
- Вызывает `гкс_ИнтеграцияСЭлектроннымТаблоСервер.ОбновитьТаблоДляЭлектроннойОчереди` (стр. 114)

## 8. Единственный вызов ОбновитьТабло

```
гкс_ИнтеграцияСЭлектроннымТаблоСервер.ОбновитьТабло(ВидТабло, СтруктураПараметров, Отказ)
```

Вызывается из одного места: `гкс_СостоянияРегистрации.ЗарегистрироватьОбъектКОбменуСТабло` (стр. 251).
