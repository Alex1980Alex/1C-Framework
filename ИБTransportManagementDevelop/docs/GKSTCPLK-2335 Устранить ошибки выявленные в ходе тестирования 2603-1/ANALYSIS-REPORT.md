# GKSTCPLK-2335 Устранить ошибки: запись УсиленныйКонтроль в РС СопоставлениеФНПЛабАнализа

## 1. Описание задачи

### 1.1 Требования
- [REQ-1] В РегистрСведений.гкс_СопоставлениеФНПЛабАнализа должен корректно записываться признак `УсиленныйКонтроль = Истина` при блокировке ТС по правилам "Группа ТС" и "Первое ТС"

### 1.2 Суть проблемы
При блокировке регистрации по правилу "Группа ТС" или "Первое ТС" в регистр `гкс_СопоставлениеФНПЛабАнализа` записывается `УсиленныйКонтроль = Ложь`, хотя проба относится к усиленному контролю.

**Верифицировано на данных**: все 20 записей регистра имеют `УК = false`, включая те, чьи регистрации заблокированы в `гкс_ЗаблокированныеРегистрацииУсиленныйКонтроль`.

### 3.2 Корневая причина (root cause)

**Несовпадение `НазначениеИспользования` между регистрами.**

Данные в `гкс_ПоказателиУсиленногоКонтроляПоРегистрации` для заблокированных ТС: ✓ execute_query

| Регистрация | Показатель | НазначениеИспользования | ТипПробы |
|---|---|---|---|
| ТМУТ-0000010 (заблокирована) | ГМО | **ПромежуточныйКомпозит** | Единичная |
| ТМУТ-0000011 (заблокирована) | ГМО | **ПромежуточныйКомпозит** | Единичная |
| ТМУТ-0000009 (блокирующая)   | ГМО | **Приемка** | Единичная |

Функция `ПоказателиУсиленногоКонтроля()` (гкс_РаботаСПоказателямиНоменклатуры:285) фильтрует:
```sql
ГДЕ ДокументРегистрации В (&ДокументыРегистрации)       -- ТМУТ-0000010
  И НазначениеИспользования = &НазначениеИспользования   -- Приемка
  И ТипПробы = &ТипПробы                                 -- Единичная
```

**Результат: пустой набор**, потому что для ТМУТ-0000010 запись с `Приемка + Единичная` **не существует** -- есть только `ПромежуточныйКомпозит + Единичная`.

Из-за этого:
1. `ЗаполнитьПоказателиДляИсследования` НЕ устанавливает флаг `УсиленныйКонтроль` на показателях ЛА
2. `ОпределитьУсиленныйКонтроль` проверяет показатели -> все без флага -> возвращает `Ложь`
3. Регистр `гкс_СопоставлениеФНПЛабАнализа` получает `УсиленныйКонтроль = Ложь`

### 3.3 Найденные паттерны в конфигурации

Функция `ЭтоЛабАнализДляЗаблокированныхТС` в `гкс_ВходнойКонтрольКачества` уже проверяет `гкс_ЗаблокированныеРегистрацииУсиленныйКонтроль` + `гкс_ПоказателиУсиленногоКонтроляПоРегистрации` через запрос -- это готовый паттерн проверки "участвует ли регистрация в усиленном контроле". ✓ pattern

## 9. Резюме

**Корневая причина**: несовпадение `НазначениеИспользования` между `гкс_ПоказателиУсиленногоКонтроляПоРегистрации` (записывает `ПромежуточныйКомпозит` для заблокированных ТС) и запросом в `ПоказателиУсиленногоКонтроля()` (фильтрует по `Приемка`).

**Решение**: модифицировать функцию `ОпределитьУсиленныйКонтроль` -- добавить fallback-проверку через `гкс_ЗаблокированныеРегистрацииУсиленныйКонтроль`, чтобы определять УК не только по флагам показателей, но и по факту блокировки регистрации.
