## Текущая логика функции (строка 70)

Функция `ОпределитьУсиленныйКонтроль()` работает в два этапа:

### Этап 1: Основная проверка — по показателям ЛА (строка 78-98)

Запрос к `Документ.гкс_ЛабораторныйАнализ.КачественныеПоказатели`:

```bsl
ВЫБРАТЬ
    ИСТИНА КАК УсиленныйКонтроль
ИЗ
    Документ.гкс_ЛабораторныйАнализ.КачественныеПоказатели КАК КачественныеПоказатели
ГДЕ
    КачественныеПоказатели.Ссылка = &ЛабораторныйАнализ
ИМЕЮЩИЕ
    КОЛИЧЕСТВО(*) > 0
    И КОЛИЧЕСТВО(*) = СУММА(ВЫБОР
        КОГДА КачественныеПоказатели.УсиленныйКонтроль = ИСТИНА
            ТОГДА 1
        ИНАЧЕ 0
    КОНЕЦ)
```

**Результат:** `Истина` только если **ВСЕ** показатели в табличной части имеют флаг `УсиленныйКонтроль = Истина`.
Если есть хотя бы один показатель без УК — результат `Ложь`.

### Этап 2: Fallback — по регистру заблокированных (строка 101, GKSTCPLK-2335)

```bsl
Возврат РегистрацияЗаблокированаДляУК(ЛабораторныйАнализ);
```

Проверяет регистр `гкс_ЗаблокированныеРегистрацииУсиленныйКонтроль` — если регистрация заблокирована
(по правилу «Группа ТС» или «Первое ТС») и не разблокирована, возвращает `Истина`.

## Жалоба тестировщика (Надежда)

При создании ЛА с формированием пробы: в табличной части 1 показатель ГМО (усиленный контроль) + остальные показатели промежуточного композита (без УК). Ожидала: `УсиленныйКонтроль = Истина`. Фактически: `УсиленныйКонтроль = Ложь`.

## Позиция разработчика (Алексей) — из аудиозаписи

### Признак `УсиленныйКонтроль` — атавизм

1. **Изначальная цель:** Разграничение промежуточных композитов (усиленный контроль) от дополнительных анализов в АРМах (Направление на разгрузку, ФНП, ЛА). Реквизит создавался когда назначение использования «Промежуточный композит» содержало смесь УК и вспомогательных анализов.

2. **Текущее состояние:** Разграничение сделано через отдельное назначение использования «Дополнительный анализ». Промежуточный композит теперь относится только к УК. Признак `УсиленныйКонтроль` больше не нужен для логики АРМов.

3. **Первоначальное заполнение (`ТекстЗапросаДанныхДляЗаполнения`):** Может ещё содержать старую логику вычисления УК, т.к. на момент заполнения разграничения не было.

### Цитаты из обсуждения

> «Этот признак он уже как атавизм. Надо сделать рефактор, потому что мы, в принципе, везде должны были перейти на анализ назначения использования»

> «Если в принципе в коде уже этот признак нигде не используется, то я бы предложила его выпилить, потому что у него была другая смысловая нагрузка, и сейчас, возможно, она не нужна»

> «Код при обновлении всё ещё может содержать именно такой поиск и обозначение усиленного контроля. Но если ты везде перешёл на назначение использования, то этот признак — атавизм»

---

## Решение

**Не исправлять логику функции**, а провести рефакторинг:

1. **Найти все использования** признака `УсиленныйКонтроль` из регистра `гкс_СопоставлениеФНПЛабАнализа` в коде
2. **Если нигде не используется** — выпилить реквизит (это не сверхзадача, ни на что не влияет)
3. **Перейти на определение УК через НазначениеИспользования** — если назначение = «Промежуточный композит» → УК, иначе → нет
4. **Проверить `ТекстЗапросаДанныхДляЗаполнения`** — старый код вычисления УК при обновлении
