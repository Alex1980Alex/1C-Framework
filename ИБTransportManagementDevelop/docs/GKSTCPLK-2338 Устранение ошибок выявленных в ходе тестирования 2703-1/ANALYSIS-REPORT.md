# GKSTCPLK-2338 Устранение ошибок: блокировка ТС по группе при КачествоНеПринято

## 1. Описание задачи

### 1.1 Требования

**[REQ-1]** При получении "Качество не принято" по 1-му ТС группы, все остальные ТС группы (у которых уже взяты пробы) должны быть заблокированы в регистре `гкс_ЗаблокированныеРегистрацииУсиленныйКонтроль`.

**[REQ-2]** Для заблокированных ТС промежуточный композит НЕ требуется — композитные записи (`ПромежуточныйКомпозит/Композитная`) должны быть помечены как "пробы не требуются".

**[REQ-3]** Для заблокированных ТС должны быть созданы НОВЫЕ записи в `гкс_ПоказателиУсиленногоКонтроляПоРегистрации` с типом пробы `Единичная` и назначением `ПромежуточныйКомпозит` — каждое ТС проверяется индивидуально.

**[REQ-4]** ТС остаются заблокированными до тех пор, пока по каждому не будет проведена индивидуальная проверка по усиленному контролю.

### 1.2 Суть проблемы

**Кейс:**
- Правило: Группа ТС
- ТС1 → въезд → номер пробы → принять пробу
- ТС2 → въезд → номер пробы → принять пробу
- ТС3 → въезд → номер пробы → принять пробу
- ТС1 НЕ прошло УК → "Качество не принято"

**Ожидание:** ТС2 и ТС3 заблокированы, композитная проба отменена, нужна единичная проба на каждое ТС.

**Факт:** ТС2 не попадает в заблокированные. Система ждёт промежуточный композит по группе.

**Корневая причина (Root Cause):** При проведении ЛА первого ТС с результатом КачествоНеПринято, процедура `ЗаполнитьЗаблокированныеРегистрацииУсиленныйКонтроль` не создаёт записи блокировки для остальных ТС группы, потому что:

1. **Проблема области видимости запроса**: Запрос `ТекстЗапросаЗаблокированныхРегистрацийУК()` (строка 2313) ограничивает `ВТ_РегистрацииНаПЛК` только регистрациями, привязанными к текущему ЛА через `СопоставлениеФНПЛабАнализа`. ТС2 и ТС3 имеют свои ФНП → не попадают в выборку.

2. **Проблема условия блокировки**: `ТребуетсяБлокировкаПервоеТС()` (строка 2825) блокирует ТОЛЬКО при `СостояниеКачества = ОтборПроб ИЛИ ПустаяСсылка()`. При проведении ЛА первого ТС, его состояние УЖЕ обновлено на КачествоНеПринято (этап 1 ОбработкаПроведения) → условие блокировки = ЛОЖЬ → блокировка не создаётся.

3. **`ОбновитьЗаблокированныеТСПриЗавершенииЛА`** может ОБНОВИТЬ существующие записи блокировки, но не может СОЗДАТЬ новые. Если записи не были созданы ранее → нечего обновлять.

### 3.2 Найденные паттерны в конфигурации ✓ pattern

**Паттерн блокировки при регистрации:**
- `ЗаписатьБлокировкуТС()` (ManagerModule гкс_ЗаблокированныеРегистрацииУсиленныйКонтроль) — создаёт запись блокировки по правилу "Первое ТС"
- `ЗаписатьБлокировкуГруппыТС()` — создаёт запись блокировки по правилу "Группа ТС"
- Оба вызывают `ДобавитьЗаписьБлокировки()` — универсальный метод записи

**Паттерн обновления при завершении ЛА:**
- `ОбновитьСостояниеБлокировки()` (ManagerModule) — обновляет РС:
  - КачествоПринято → Разблокировано = Истина
  - КачествоНеПринято/РПП → БлокирующееСостояниеКачества, Разблокировано = Ложь

**Паттерн "Сценарий B"** (строки 2002-2018 и 2047-2066):
- КачествоНеПринято → `УстановитьПробыНеТребуютсяДляКомпозитных()` + `ДобавитьПоказателиУКДляЗаблокированногоТС(Единичная)`
- Проверка `НеПрошелВходнойКонтроль` — если ТС уже не прошло ВК, не создавать дублирующие показатели

### Точка модификации 2: Расширить область видимости запроса [REQ-1]

**Файл:** `CommonModules/гкс_ВходнойКонтрольКачества/Ext/Module.bsl`
**Функция:** `ТекстЗапросаЗаблокированныхРегистрацийУК()` (строка 2313)
**Действие:** Расширить `ВТ_РегистрацииНаПЛК` чтобы включить ВСЕ регистрации того же поставщика/номенклатуры/производственных суток, а не только привязанные к текущему ЛА

**Проблема:** 2-й запрос пакета (строки 2334-2354) фильтрует через `СопоставлениеФНПЛабАнализа.ЛабораторныйАнализ = &ЛабораторныйАнализ`. Это возвращает только регистрации, привязанные к текущему ЛА через ФНП. ТС2 и ТС3 имеют свои ФНП и не попадают в выборку.

**Предлагаемое решение:** Добавить UNION в `ВТ_РегистрацииНаПЛК` для включения всех регистраций того же поставщика/номенклатуры/производственных суток:

```sql
-- Добавить в ВТ_РегистрацииНаПЛК (после существующего SELECT)
ОБЪЕДИНИТЬ ВСЕ

ВЫБРАТЬ
    ТранспортныеСредстваПоставщика.ДокументРегистрации
ИЗ
    РегистрСведений.гкс_ТранспортныеСредстваПоставщикаУсиленногоКонтроля КАК Источник
        ВНУТРЕННЕЕ СОЕДИНЕНИЕ РегистрСведений.гкс_ТранспортныеСредстваПоставщикаУсиленногоКонтроля
            КАК ТранспортныеСредстваПоставщика
        ПО Источник.Контрагент = ТранспортныеСредстваПоставщика.Контрагент
        И Источник.Номенклатура = ТранспортныеСредстваПоставщика.Номенклатура
        И Источник.ПроизводственныеСутки = ТранспортныеСредстваПоставщика.ПроизводственныеСутки
ГДЕ
    Источник.ДокументРегистрации = &ДокументРегистрации
```

**Образец:** Аналогичный подход используется в `ТекстЗапросаПолучитьДанныеЗаблокированныхРегистраций()` (строка 2615) и `ТекстЗапросаПолучитьДанныеБлокировкиДляРегистраций()` (строка 2685) — они находят ВСЕ ТС того же поставщика через самосоединение `гкс_ТранспортныеСредстваПоставщикаУсиленногоКонтроля`.

**Зависимости:** Точка модификации 1
**Риски:** Средние — расширяет объём данных в запросе. Требуется тщательное тестирование.
