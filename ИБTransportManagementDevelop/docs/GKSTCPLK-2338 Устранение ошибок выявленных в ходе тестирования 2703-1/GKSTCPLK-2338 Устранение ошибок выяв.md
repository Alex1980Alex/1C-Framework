GKSTCPLK-2338 Устранение ошибок выявленных в ходе тестирования 2703-1

Описание

кейс:

правило группа ТС
первое ТС - въезд - номер пробы - принять пробу
второе ТС - въезд - номер пробы - принять пробу
третье ТС - въезд - номер пробы - принять пробу

Первое ТС НЕ прошло УК по результатам лаб анализа входного контроля 2 ТС = Качество принято + учитываем результат по 1 ТС = итог "качество не принято". Но 2 ТС не попадает в заблокированные, и мы по 1 группе все еще ждем Промежуточный композит

ожидание: по тем ТС, по которым была взята проба до получения "Качество не принято" по 1ТС, уже не нужен промежуточный композит. ТС должны быть заблокированы до проверки каждого ТС по УК
если у нас 1 ТС не прошло УК, но есть уже запись в показателях по 2 ТС, нам нужна запись в регистре по заблокированным и новая запись в показателях что композитная проба не требуется, а нужна единичная

---

## Анализ задачи

### Правило: Группа ТС, усиленный контроль качества

**Предусловие:** Настроен усиленный контроль по правилу "Группа ТС" для показателя (например ГМО). Поставщик привозит несколько ТС одной номенклатуры за производственные сутки.

### Текущее поведение (до доработки)

Блокировка последующих ТС срабатывает только когда **последующее ТС проводит свой ЛА** и обнаруживает что первое ТС ещё в состоянии `ОтборПроб`. Обратного сценария нет — когда первое ТС проводит ЛА с `КачествоНеПринято`, последующие ТС не блокируются.

### Требуемое поведение

При проведении ЛА первого ТС с результатом `КачествоНеПринято`:
1. Все последующие ТС того же поставщика/номенклатуры/даты, которые ещё НЕ заблокированы → **создать запись блокировки**
2. Композитные записи (`ПромежуточныйКомпозит/Композитная`) последующих ТС → **пометить как "пробы не требуются"**
3. Для каждого заблокированного ТС → **создать запись единичной пробы** (`Единичная/ПромежуточныйКомпозит`)
4. ТС остаются заблокированными до индивидуальной проверки по УК

### Алгоритм доработки

```
При проведении ЛА (ОбработкаПроведения → СформироватьВспомогательныеДанныеДляЗаблокированныхТС
    → ЗаполнитьЗаблокированныеРегистрацииУсиленныйКонтроль):

1. Пакетный запрос ПолучитьДанныеБлокировкиДляРегистраций:
   - Существующие пакеты 0-8 (без изменений)
   - Новый пакет 9: LEFT JOIN ВТ_РегистрацииНаПЛК (последующие ТС)
     с РС гкс_ЗаблокированныеРегистрацииУсиленныйКонтроль
     → поле ДокументРегистрацииЗаблокирован = NULL если ТС ещё НЕ заблокировано

2. В цикле по ТаблицаРегистраций:
   ЕСЛИ ДанныеДляОтбора.ЭтоПервоеТС
      И СостояниеКачестваПервоеТС = КачествоНеПринято
      И есть НезаблокированныеПоследующиеТС:

      Для каждого незаблокированного последующего ТС:
        а) РС гкс_ЗаблокированныеРегистрацииУсиленныйКонтроль.ЗаписатьБлокировкуТС()
        б) РС гкс_ПоказателиУсиленногоКонтроляПоРегистрации.УстановитьПробыНеТребуютсяДляКомпозитных()
        в) РС гкс_ПоказателиУсиленногоКонтроляПоРегистрации.ДобавитьПоказателиУКДляЗаблокированногоТС(Единичная)
```

### Точки модификации

1. `ТекстЗапросаПолучитьДанныеБлокировкиДляРегистраций()` — добавлен пакет 9
2. `ПолучитьДанныеБлокировкиДляРегистраций()` — обработка пакета 9 → `НезаблокированныеПоследующиеТС`
3. `ЗаполнитьЗаблокированныеРегистрацииУсиленныйКонтроль()` — вызов внутри цикла
4. `ЗаблокироватьПоследующиеТСПриОтказеПервого()` — новая процедура (Сценарий B)
