# Coding Conventions — BSL/1С

## Именование объектов конфигурации

- **Префикс «гкс_»** для нетиповых объектов (CommonModules, Catalogs, Documents):
  `гкс_АсинхронныеСервисы`, `гкс_АРМКомпозитныеПробы`. Префикс отражает
  корпоративную принадлежность (Группа Компаний Содружество).
- **Камелкейс** для имён процедур/функций: `СформироватьНаправлениеНаРазгрузку`,
  `ПолучитьСтатусТС`.
- **Реквизиты табличных частей** — без подчёркиваний: `ВидТСАвто`,
  `ДатаПлановаяРазгрузки`, `НомерПломбы`.

## Модули и регионы

- Модули объектов и форм разделены на стандартные регионы:
  ```bsl
  #Область ОписаниеПеременных
  #Область ОбработчикиСобытийФормы
  #Область ОбработчикиКомандФормы
  #Область СлужебныеПроцедурыИФункции
  ```
- Серверные процедуры маркируются: `&НаСервере`, `&НаКлиентеНаСервереБезКонтекста`.

## Запросы

- Имена параметров запроса — латиница + камелкейс: `&НачалоПериода`, `&Организация`.
- При работе с объектными ссылками — выборка через временные таблицы,
  не через подзапросы (производительность).
- Виртуальные таблицы регистров остатков/оборотов — основной источник
  для отчётов (не выборка из таблицы движений напрямую).

## Обработка проведения

- Любой документ с движениями должен иметь:
  - `ПередЗаписью` — валидация
  - `ОбработкаПроведения` — формирование движений по регистрам
  - При отмене проведения — автоматическая очистка движений (стандарт)
- Контроль остатков — через метод `Запрос.ВыполнитьПакет()` с проверкой
  отрицательных остатков.

## События форм

- Используем расширенную модель событий 8.3 (управляемые формы):
  - `&НаСервере` для серверной обработки
  - `&НаКлиенте` для интерактивных действий
- Не использовать `Внимание()` / `Предупреждение()` без коллбэков
  (deprecated в 8.3+).

## Подсистема функциональных опций

- Включения функционала по фичам — через ФункциональныеОпции
  (`ИспользоватьЗаблокированныеТС`, `ИспользоватьКомпозитныеПробы`).
- Опции хранят значения в Константах или РегистрахСведений.

## RLS и роли

- Профили групп доступа — поставляемые из БСП (БиблиотекаСтандартныхПодсистем).
- Кастомные роли — с префиксом `гкс_`: `гкс_РольОператораПЛК`,
  `гкс_РольЛогиста`.
- RLS-шаблоны храним в подсистеме «УправлениеДоступом».

## БСП и совместимость

- Используем БиблиотекуСтандартныхПодсистем 3.1.x.
- Расширения (`*.cfe`) — отдельно, не сливаются с основной конфигурацией.
- При обновлении платформы фиксируем в `docs/<JIRA>/UPGRADE-NOTES.md`.

## Локализация

- Все наименования — на русском языке (русская локализация платформы).
- Сообщения пользователю — через `ОбщийМодуль.ВывестиСообщениеПользователю(...)`,
  не `Сообщить()` напрямую.

## Обработчики БСП

- Подписки на события (`EventSubscriptions`) — называются по схеме
  `<Объект><Событие>`: `гкс_ДокументПриЗаписи`,
  `гкс_СправочникПередУдалением`.

## Тестирование

- Юнит-тесты — через подсистему «ТестированиеXUnitFor1C» (если используется).
- Интеграционные/UI-тесты — через Vanessa Automation BDD.
- Pre-scenario TestDB check — обязательный (см. skill `va-bdd-testing` Stage 4a).
