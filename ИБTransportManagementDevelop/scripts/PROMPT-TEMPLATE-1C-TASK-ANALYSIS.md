# Универсальный шаблон промта: Анализ и декомпозиция задачи 1С

> **Версия:** 2.0 | **Дата:** 2026-01-29
> **Применимость:** Любая задача по доработке конфигурации 1С:Предприятие
> **Оптимизирован для:** Claude Code с MCP-инструментами (Serena, ast-grep, ripgrep, 1c-docs-rag)

---

## Когда использовать

Любая задача по конфигурации 1С:
- Доработка существующего функционала (изменение логики, расширение фильтров)
- Добавление нового функционала (новые колонки, закладки, кнопки, регистры)
- Исправление ошибок (неверное поведение, пропущенные условия)
- Рефакторинг (оптимизация запросов, реструктуризация модулей)

---

## Шаблон промта

```
### ЗАДАЧА
<путь_к_файлу_ТЗ>

### КОНФИГУРАЦИЯ
<путь_к_папке_src_конфигурации>

### ИНСТРУКЦИЯ

Выполни полный анализ задачи и сформируй детальный отчёт.

#### Фаза 1 — Понимание требований
- Прочитай ТЗ и выдели конкретные требования (пронумеруй)
- Сформулируй суть проблемы одним абзацем: что сейчас → что должно быть
- Если ТЗ неполное — зафиксируй допущения и открытые вопросы

#### Фаза 2 — Поиск объектов конфигурации
- Найди ВСЕ объекты конфигурации, задействованные в задаче
- Для каждого объекта определи: тип, файл, роль в задаче, нужны ли изменения
- Раздели на группы: требуют изменения / участвуют в цепочке / только чтение
- Построй таблицу объектов с колонками: #, Объект, Тип, Файл, Роль

#### Фаза 3 — Анализ механизма и алгоритма
- Для каждого объекта, требующего изменения:
  - Прочитай исходный код (функции, процедуры, запросы)
  - Опиши текущий алгоритм работы пошагово
  - Укажи конкретные строки кода, которые нужно менять
  - Объясни ПОЧЕМУ именно эти строки (причинно-следственная связь с требованием)
- Если есть цепочка вызовов — опиши полный путь выполнения (entry point → промежуточные вызовы → конечный результат)

#### Фаза 4 — План изменений (декомпозиция)
- Для каждого изменения укажи:
  - Файл и функция/процедура
  - Что именно менять (конкретные строки, SQL-выражения, параметры)
  - Тип изменения: добавление / модификация / удаление
  - Зависимости от других изменений (порядок выполнения)
- Если есть XML-изменения (Form.xml, метаданные) — опиши структуру

#### Фаза 5 — Верификация
- Проверь: покрыты ли ВСЕ требования из ТЗ?
- Проверь: нет ли побочных эффектов (другие формы/модули, использующие те же объекты)?
- Проверь: обратная совместимость (что будет если новые данные пустые)?
- Составь чек-лист проверки для реализации

### ФОРМАТ ОТЧЁТА

Markdown-файл со структурой:
1. Описание задачи (требования + суть проблемы)
2. Задействованные объекты конфигурации (таблицы по группам)
3. Детальный анализ механизма (по каждому объекту с кодом)
4. План изменений (пронумерованные точки модификации)
5. Чек-лист верификации
6. [Опционально] Риски и открытые вопросы

Отчёт сохрани в файл {TASK_ID}-ANALYSIS-REPORT.md в папке задачи.
```

## Краткая версия (быстрый запуск)

Минимальный промт, который даёт результат того же качества:

```
<путь_к_файлу_ТЗ>
<путь_к_папке_src>

Полный анализ задачи 1С:
1. Выдели требования из ТЗ, сформулируй суть (что сейчас → что должно быть)
2. Найди ВСЕ объекты конфигурации — раздели на: меняем / цепочка / только чтение
3. Прочитай код каждого изменяемого объекта, опиши алгоритм, укажи конкретные строки
4. План изменений: файл, функция, что менять, зависимости
5. Чек-лист: все требования покрыты? побочные эффекты? обратная совместимость?

Отчёт → {TASK_ID}-ANALYSIS-REPORT.md в папке задачи.
```

## Варианты расширения

### A. Если нужна только реализация (без анализа)

Добавить после основного промта:
```
После анализа — реализуй все изменения из плана.
Соблюдай существующий стиль кода. Не трогай функции, не связанные с задачей.
```

### B. Если есть готовый отчёт анализа

```
<путь_к_файлу_ТЗ>
<путь_к_папке_src>

Реализуй задачу на основании ТЗ и файла анализа {TASK_ID}-ANALYSIS-REPORT.md.
Следуй плану изменений из отчёта. После реализации пройди чек-лист из отчёта.
```

### C. Если задача типовая (есть PROMPT-TEMPLATE)

Использовать специализированный шаблон из папки docs/:
- `PROMPT-TEMPLATE-ADD-COLUMNS-TO-ARM.md` — добавление колонок из РС в ТЧ формы

## Почему этот шаблон работает

| Принцип | Как применён |
|---------|-------------|
| **Chain-of-Thought** | 5 фаз от понимания → поиск → анализ → план → верификация |
| **Structured Output** | Фиксированная структура отчёта из 6 секций |
| **Self-Verification** | Фаза 5 с явной проверкой полноты и побочных эффектов |
| **Specificity** | Конкретные инструкции: "таблица с колонками #, Объект, Тип, Файл, Роль" |
| **Decomposition** | Каждая фаза разбита на bullet-points с чёткими действиями |
| **Context grounding** | Пути к ТЗ и src привязывают к реальным файлам |
